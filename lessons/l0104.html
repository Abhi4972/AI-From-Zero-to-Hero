Why this came about

Before 2017, language models read text one word at a time (recurrent networks), which was slow to train and forgot long-range context. The 2017 paper "Attention Is All You Need" introduced the transformer, which lets every token look at every other token at once and trains in parallel on GPUs. That architecture made today's large language models possible, and its design still explains their limits: context length, memory and speed.

In plain words first
Every word looks at every other word

A transformer turns each token into a vector, then repeatedly lets every token look at the others and decide which ones matter for it (attention), mixing in their information. Many such layers build up meaning: which "it" refers to which noun, what a question is asking. To write, it predicts one next token at a time, and keeps the keys and values it already computed (the KV cache) so it does not redo work for earlier tokens. Most practical limits, such as context length, memory per request and speed, follow from this design.

The whole model in one picture

A decoder-only LLM turns token ids into vectors with an embedding table, passes them through a stack of identical blocks, and ends with an output head that turns the last vector into a score for every token in the vocabulary (the logits), then a softmax into probabilities. Each block has two sublayers, attention and a feed-forward network, and each one reads from and adds back to a running vector per token called the residual stream.

Inside the model, in code

You do not need to train models to build agents, but four mechanisms explain most of what you will see in production: why some languages cost more, why answers vary, why long prompts are slow to start, and why output tokens dominate latency. Each takes a few lines of NumPy.

Attention, and why the KV cache exists

A transformer's core operation is self-attention: each token builds a weighted mix of earlier tokens' information, weighted by how well its query matches their keys. A causal mask stops tokens from looking ahead.

def self_attention(x, Wq, Wk, Wv):
    """Scaled dot-product attention with a causal mask, for one head."""
    Q, K, V = x @ Wq, x @ Wk, x @ Wv
    scores = Q @ K.T / np.sqrt(K.shape[1])
    scores += np.triu(np.full(scores.shape, -1e9), k=1)          # token i cannot attend to tokens after i
    weights = np.exp(scores - scores.max(axis=1, keepdims=True))
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ V, weights, K, V

rng = np.random.default_rng(1)
d = 8
x = rng.normal(size=(5, d))                                       # 5 tokens, each an 8-number vector
Wq, Wk, Wv = (rng.normal(size=(d, d)) / np.sqrt(d) for _ in range(3))
out, weights, K, V = self_attention(x, Wq, Wk, Wv)
print(np.round(weights, 2))

# Generating token 6: with a KV cache we compute only the new token's query, key and value
new = rng.normal(size=(1, d))
q_new, k_new, v_new = new @ Wq, new @ Wk, new @ Wv
K_cached, V_cached = np.vstack([K, k_new]), np.vstack([V, v_new])
w = np.exp(q_new @ K_cached.T / np.sqrt(d)); w /= w.sum()
with_cache = w @ V_cached
full, *_ = self_attention(np.vstack([x, new]), Wq, Wk, Wv)
print("cached result equals full recomputation:", np.allclose(with_cache, full[-1]))

The zeros above the diagonal are the causal mask. The second print is the KV cache: keys and values of earlier tokens never change, so generating each new token needs only one new row instead of recomputing everything. It is why reading a long prompt (prefill, done once, in parallel) and writing the answer (decode, one token at a time) have very different speeds, and why prompt cachinglater · 11.23 across requests (Lesson 11.23) can skip prefill for a repeated prefix.

Attention: queries, keys and values

For each token, attention computes a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what do I pass on?"), each by multiplying the token's vector by a learned matrix. The score between two tokens is the dot product of one's query with the other's key; a softmax turns a row of scores into weights; the output is the weighted sum of values. Together this is scaled dot-product attention: softmax(Q Kᵀ / √d_k) V.

Why divide by √d_k? Dot products of random d-dimensional vectors have a spread that grows like √d, so in large dimensions the scores become huge, the softmax puts almost all its weight on one token, and gradients through it nearly vanish. Dividing keeps scores in a range where the softmax stays soft:

import numpy as np
rng = np.random.default_rng(0)

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

# Why attention divides by sqrt(d_k): dot products of random vectors grow with dimension
for d_k in [16, 128, 1024]:
    q = rng.normal(size=d_k)
    K = rng.normal(size=(50, d_k))
    raw = K @ q
    print(f"d_k={d_k:<5} score std {raw.std():5.1f}  | top weight unscaled {softmax(raw).max():.2f}"
          f"  scaled {softmax(raw / np.sqrt(d_k)).max():.2f}")
What you should see
d_k=16    score std   3.7  | top weight unscaled 0.77  scaled 0.11
d_k=128   score std   9.2  | top weight unscaled 0.71  scaled 0.08
d_k=1024  score std  34.4  | top weight unscaled 1.00  scaled 0.13

Without scaling, at d_k = 1024 attention collapses onto a single token (weight 1.00). With scaling it stays spread, so the model can learn which tokens matter.

Causal masking sets the scores for future tokens to minus infinity before the softmax, so each token sees only itself and earlier tokens; this is what lets one training pass learn to predict every next token at once. Multi-head attention runs several attentions in parallel, each in a smaller slice of the vector, so one head can track syntax while another tracks which entity "it" refers to; the heads' outputs are concatenated and mixed by an output matrix.

def multi_head_attention(X, Wq, Wk, Wv, Wo, n_heads):
    """X: (T, d_model). Each head attends in its own d_model/n_heads-dimensional subspace."""
    T, d = X.shape
    hd = d // n_heads
    split = lambda M: M.reshape(T, n_heads, hd).transpose(1, 0, 2)      # (heads, T, head_dim)
    Q, K, V = split(X @ Wq), split(X @ Wk), split(X @ Wv)
    scores = Q @ K.transpose(0, 2, 1) / np.sqrt(hd)                      # (heads, T, T)
    scores = scores + np.triu(np.full((T, T), -np.inf), k=1)             # causal mask: no peeking ahead
    weights = softmax(scores)
    heads = weights @ V                                                  # (heads, T, head_dim)
    concat = heads.transpose(1, 0, 2).reshape(T, d)                      # glue the heads back together
    return concat @ Wo, weights

T, d, H = 5, 16, 4
X = rng.normal(size=(T, d))
Wq, Wk, Wv, Wo = (rng.normal(size=(d, d)) / np.sqrt(d) for _ in range(4))
out, w = multi_head_attention(X, Wq, Wk, Wv, Wo, H)
print("output shape", out.shape, "| weights shape", w.shape)
print("head 0, token 2 attends to:", w[0, 2].round(2), "(zeros after position 2: the mask)")
print("each row sums to 1:", np.allclose(w.sum(-1), 1))

Four heads, each with its own 5 × 5 attention pattern, and the mask zeroes every weight on a future token.

Self-attention compares a sequence with itself; cross-attention uses queries from one sequence and keys and values from another (an encoder-decoder translator, or a speech model attending to audio). Attention's cost is the catch: every token is compared with every other, so compute and memory for the scores grow with the square of the sequence length, O(n²). Doubling the context quadruples that work, which is why long context is expensive and why the techniques below exist.

Positions: telling the model about word order

Attention by itself ignores order: shuffle the tokens and the weights shuffle with them. Positional encoding fixes that.

Method How it works Used by
Sinusoidal Add fixed sine and cosine waves of different frequencies to each embedding The original 2017 transformer
Learned absolute Learn one vector per position, up to a maximum length BERT, GPT-2
RoPE (rotary) Rotate each query and key by an angle proportional to its position; the dot product then depends only on the distance between tokens Llama, Mistral, Qwen, Gemma and most current open models
ALiBi Subtract a penalty from attention scores that grows with distance BLOOM, some MPT models 
import numpy as np
rng = np.random.default_rng(0)
def rope(x, pos, base=10000.0):
    """Rotary position embedding: rotate each pair of dimensions by an angle proportional to the position."""
    d = x.shape[-1]
    freqs = base ** (-np.arange(0, d, 2) / d)          # fast-turning pairs for local order, slow ones for long range
    ang = pos * freqs
    x1, x2 = x[0::2], x[1::2]
    out = np.empty_like(x)
    out[0::2] = x1 * np.cos(ang) - x2 * np.sin(ang)
    out[1::2] = x1 * np.sin(ang) + x2 * np.cos(ang)
    return out

q, k = rng.normal(size=64), rng.normal(size=64)
for qpos, kpos in [(5, 2), (105, 102), (1005, 1002), (5, 4)]:
    print(f"query at {qpos:>4}, key at {kpos:>4} (distance {qpos - kpos}): score {rope(q, qpos) @ rope(k, kpos):+.4f}")
What you should see
query at    5, key at    2 (distance 3): score -8.4462
query at  105, key at  102 (distance 3): score -8.4462
query at 1005, key at 1002 (distance 3): score -8.4462
query at    5, key at    4 (distance 1): score -8.5191

The same pair of vectors gives the same score at positions 5 and 2, 105 and 102, or 1005 and 1002: with RoPE, attention sees relative distance, not absolute position. That property is what context extension methods exploit: position interpolation, NTK-aware scaling and YaRN stretch the rotation frequencies so a model trained on 8,000 tokens can be fine-tuned to work at 128,000.

The rest of the block

  • Residual connections: each sublayer's output is added to its input (x = x + sublayer(x)). The stream carries information up through dozens of layers, and gradients flow straight back down it, which is what makes very deep networks trainable.
  • Normalization: LayerNorm rescales each token's vector to zero mean and unit variance; RMSNorm skips the centering and just divides by the root mean square, which is cheaper and works as well, so Llama-family models use it. Modern models apply it before each sublayer (pre-norm), which trains more stably than the original transformer's post-norm.
  • Feed-forward network (FFN): a two- or three-matrix network applied to each token separately, usually expanding the vector about 3.5 to 4 times. It holds about two-thirds of a dense model's parameters, and interpretability work suggests much factual recall happens here. Most current models use the gated SwiGLU form.
def layer_norm(x, eps=1e-5):                 # original transformer, BERT, GPT-2: centre, then scale
    return (x - x.mean(-1, keepdims=True)) / np.sqrt(x.var(-1, keepdims=True) + eps)

def rms_norm(x, eps=1e-5):                   # Llama, Mistral, Qwen: skip the centring, a little cheaper
    return x / np.sqrt((x ** 2).mean(-1, keepdims=True) + eps)

def swiglu_ffn(x, W_gate, W_up, W_down):     # the feed-forward network: expand, gate, project back
    gate = x @ W_gate
    return ((gate / (1 + np.exp(-gate))) * (x @ W_up)) @ W_down    # SiLU(gate) * up, then down

def block(x, p):
    """One pre-norm decoder block. The residual stream x is only ever ADDED to."""
    attn_out, _ = multi_head_attention(rms_norm(x), p["Wq"], p["Wk"], p["Wv"], p["Wo"], n_heads=4)
    x = x + attn_out                                        # residual connection 1
    x = x + swiglu_ffn(rms_norm(x), p["Wg"], p["Wu"], p["Wd"])  # residual connection 2
    return x

T, d, ff = 6, 16, 44
x = rng.normal(size=(T, d))
print("rms after rms_norm:", np.sqrt((rms_norm(x) ** 2).mean(-1)).round(3)[:3], "| mean after layer_norm:", layer_norm(x).mean(-1).round(3)[:3] + 0.0)
for i in range(4):
    p = {k: rng.normal(size=s) / np.sqrt(s[0]) * 0.5 for k, s in
         [("Wq", (d, d)), ("Wk", (d, d)), ("Wv", (d, d)), ("Wo", (d, d)), ("Wg", (d, ff)), ("Wu", (d, ff)), ("Wd", (ff, d))]}
    new = block(x, p)
    print(f"block {i + 1}: shape {new.shape}, update size relative to the stream {np.linalg.norm(new - x) / np.linalg.norm(x):.2f}")
    x = new
What you should see

Each block adds a modest update to the stream rather than replacing it, which is the residual design at work.

Counting parameters and the KV cache from a config

Every open model ships a config with a handful of numbers. From them you can work out the model's size and, more usefully for serving, how much memory each token of context costs.

cfg = dict(vocab=128_256, d_model=4096, layers=32, heads=32, kv_heads=8, ffn=14_336)   # Llama 3 8B

def count_params(c):
    hd = c["d_model"] // c["heads"]
    attn = c["d_model"] * c["d_model"] * 2 + c["d_model"] * c["kv_heads"] * hd * 2   # Wq, Wo + smaller Wk, Wv (GQA)
    ffn = 3 * c["d_model"] * c["ffn"]                                               # SwiGLU has three matrices
    norms = 2 * c["d_model"]
    per_layer = attn + ffn + norms
    embed = c["vocab"] * c["d_model"] * 2                                           # input embedding + output head
    return per_layer, per_layer * c["layers"], embed

per_layer, blocks, embed = count_params(cfg)
print(f"per layer {per_layer / 1e6:.0f}M | all layers {blocks / 1e9:.2f}B | embeddings {embed / 1e9:.2f}B "
      f"| total {(blocks + embed) / 1e9:.2f}B")

def kv_cache_gib(c, tokens, kv_heads=None, bytes_per=2):
    hd = c["d_model"] // c["heads"]
    per_token = 2 * c["layers"] * (kv_heads or c["kv_heads"]) * hd * bytes_per    # 2 = one key + one value
    return per_token, per_token * tokens / 2 ** 30

per_tok, _ = kv_cache_gib(cfg, 1)
print(f"KV cache per token: {per_tok // 1024} KiB")
for tokens in [8_192, 131_072]:
    print(f"{tokens:>7,} tokens: GQA (8 KV heads) {kv_cache_gib(cfg, tokens)[1]:5.1f} GiB | "
          f"full multi-head (32) {kv_cache_gib(cfg, tokens, kv_heads=32)[1]:5.1f} GiB | "
          f"multi-query (1) {kv_cache_gib(cfg, tokens, kv_heads=1)[1]:5.2f} GiB")
What you should see
per layer 218M | all layers 6.98B | embeddings 1.05B | total 8.03B
KV cache per token: 128 KiB
  8,192 tokens: GQA (8 KV heads)   1.0 GiB | full multi-head (32)   4.0 GiB | multi-query (1)  0.12 GiB

The count lands on Llama 3 8B's published size. The KV cache line is the one to remember for serving: 128 KiB per token means one 128,000-token conversation needs 16 GiB of GPU memory on top of the weights. Grouped-query attention (GQA) shares each key and value head among several query heads (here 4), cutting the cache by 4 times for a small quality cost; multi-query attention (MQA) shares one across all; DeepSeek's multi-head latent attention (MLA) compresses keys and values into a small latent vector instead.

Three families of transformers

Family Sees Trained to Examples Use it for
Encoder-only The whole input, both directions Fill in masked words (masked language modeling) BERT, RoBERTa, ModernBERT Embeddings, classifiers, rerankerslater · 5.38, named entity extraction
Decoder-only Only earlier tokens (causal) Predict the next token GPT, Llama, Claude, Gemini, Qwen Generation, chat, agents: today's LLMs
Encoder-decoder Encoder reads all input; decoder generates with cross-attention to it Map input to output (translation, denoising) Original transformer, T5, BART, Whisper Translation, summarization, speech recognition

Decoder-only won for general models because one simple objective scales to all of the web and every task can be phrased as "continue this text". Encoders remain the right tool for fast embedding and classification, which is why most rerankers and many embedding models in Lesson 14.71 are encoders.

Making attention affordable

Technique What it does Effect
KV cache Keep earlier tokens' keys and values instead of recomputing them (Lesson 7.21) Each new token costs one row, not the whole sequence
GQA / MQA / MLA Share or compress key and value heads 4 to 30 times smaller cache
FlashAttention Compute attention in tiles that fit in the GPU's fast on-chip memory, never writing the full n × n score matrix to slow memory Same exact result, several times faster and far less memory; standard in every serving engine
Sliding-window attention Each token attends only to the last few thousand tokens; stacked layers still pass information further Mistral 7B, Gemma's local layers
PagedAttentionlater · 14.137 Store the KV cache in fixed-size pages, like virtual memory Far more concurrent requests per GPU (vLLMlater · 3.25, Lesson 14.137)
Quantization Store weights or KV cache in 8 or 4 bits Half to a quarter of the memory (Lesson 14.137)

Long context has a quality limit as well as a cost: models use information at the start and end of a long prompt better than the middle ("lost in the middlelater · 11.27"), so retrieval and context engineeringlater · 11.27 (Lesson 11.27) still matter at a million tokens.

Mixture of experts

A mixture-of-experts (MoE) model replaces each feed-forward network with many smaller expert networks and a router that sends each token to only a few of them. The model has many parameters to store knowledge, but each token pays for only the experts it uses.

import numpy as np
rng = np.random.default_rng(0)
# Mixture of experts: a router picks the top 2 of 8 expert FFNs for each token
n_experts, top_k, d, T = 8, 2, 16, 12
W_router = rng.normal(size=(d, n_experts))
tokens = rng.normal(size=(T, d))
logits = tokens @ W_router
chosen = np.argsort(-logits, axis=1)[:, :top_k]
gates = np.take_along_axis(logits, chosen, 1)
gates = np.exp(gates) / np.exp(gates).sum(1, keepdims=True)     # mixing weights for the chosen two
print("token 0 -> experts", chosen[0], "with weights", gates[0].round(2))
load = np.bincount(chosen.ravel(), minlength=n_experts)
print("tokens per expert:", load, "<- uneven load is why MoE training adds a load-balancing loss")

# Active vs total parameters, Mixtral 8x7B style
shared, per_expert = 1.6e9, 5.64e9
print(f"total {(shared + 8 * per_expert) / 1e9:.1f}B parameters, active per token {(shared + 2 * per_expert) / 1e9:.1f}B")
What you should see
token 0 -> experts [1 4] with weights [0.89 0.11]
tokens per expert: [1 3 4 6 4 0 5 1] <- uneven load is why MoE training adds a load-balancing loss
total 46.7B parameters, active per token 12.9B

Mixtral 8x7B stores 46.7B parameters but runs about 12.9B per token; DeepSeek-V3 stores 671B and activates 37B. The catch: every expert must still sit in GPU memory, so MoE saves compute, not memory, and training needs a load-balancing loss so the router does not overload a few experts.

Beyond attention

State-space models (SSMs) such as Mamba process a sequence with a fixed-size running state instead of comparing every pair of tokens, so cost grows linearly with length and there is no growing KV cache. Pure SSMs are weaker at exact recall from far back in the context, so the practical trend is hybrids that interleave a few attention layers with many SSM or linear-attention layers (Jamba, IBM Granite 4, NVIDIA Nemotron-H). Diffusion language models generate by refining a whole block of tokens in parallel over several steps rather than one token at a time; they are fast but still a minority approach.

Research directions beyond next-token prediction

Everything in this course is built on transformers trained to predict the next token. Researchers are also pursuing other routes, and you will see these terms:

  • World models: models that learn to predict how an environment changes when you act in it (the next video frames of a game, a robot's surroundings), so that an agent can plan by imagining outcomes. Video-generation models are sometimes described this way.
  • JEPA (joint-embedding predictive architecture), championed by Yann LeCun: predict the representation of the missing part of an image or video instead of its pixels or tokens, on the argument that most detail is unpredictable and not worth modelling.
  • Neuro-symbolic systems: a neural model paired with a symbolic engine (a solver, a proof checker, a knowledge graphlater · 14.83) that guarantees correctness of the parts it handles. An LLM calling a calculator or a SQL engine is the everyday version (the Agents from first principles section).
  • Continual learning: models that keep learning after deployment without forgetting. Today's models are frozen; memory systems and retrieval (Lessons 14.64 and 14.65) are the practical substitute.

None of these has displaced the transformer language model in products. They matter as context for claims about what current models can and cannot do.

Decoding: from probabilities to text

Lesson 11.19 covered temperature, top-k and top-p sampling. The rest of the toolbox:

  • Greedy decoding takes the most likely token each step. Beam search keeps the best few partial sequences and can find a more likely whole answer; it suits translation and other tasks with one right output, and is rarely used for chat because it produces bland, repetitive text.
  • min-p keeps tokens whose probability is at least a fraction of the top token's, adapting to how confident the model is; popular with open models.
  • Repetition, frequency and presence penalties lower the scores of tokens already used.
  • Logprobs: most APIs can return each token's log-probability, useful for confidence scores, classification by comparing label probabilities, and spotting where an answer is shaky.
  • Constrained decodinglater · 11.21 masks every token that would break a grammar or JSON schema; it is how structured outputlater · 11.21 is guaranteed (Lesson 11.21).
import math
# A tiny "model": probability of the next word given the previous one
P = {"<s>": {"the": 0.5, "a": 0.4, "my": 0.1},
     "the": {"order": 0.4, "refund": 0.35, "box": 0.25},
     "a":   {"refund": 0.9, "box": 0.1},
     "my":  {"order": 1.0},
     "order": {"</s>": 1.0}, "refund": {"</s>": 1.0}, "box": {"</s>": 1.0}}

def greedy(start="<s>"):
    seq, lp = [start], 0.0
    while seq[-1] != "</s>":
        word, p = max(P[seq[-1]].items(), key=lambda kv: kv[1])   # always take the single best next word
        seq.append(word); lp += math.log(p)
    return seq[1:-1], math.exp(lp)

def beam(width=2, start="<s>"):
    beams = [([start], 0.0)]
    while not all(s[-1] == "</s>" for s, _ in beams):
        cand = []
        for s, lp in beams:
            if s[-1] == "</s>": cand.append((s, lp)); continue
            cand += [(s + [w], lp + math.log(p)) for w, p in P[s[-1]].items()]
        beams = sorted(cand, key=lambda c: -c[1])[:width]       # keep the best `width` partial answers
    s, lp = beams[0]
    return s[1:-1], math.exp(lp)

for name, (words, prob) in [("greedy", greedy()), ("beam 2", beam(2))]:
    print(f"{name}: {' '.join(words):<12} probability {prob:.2f}")
What you should see
greedy: the order    probability 0.20
beam 2: a refund     probability 0.36

Greedy grabs "the" (0.5) and ends at 0.20; beam search keeps "a" alive and finds "a refund" at 0.36.

Speculative decoding speeds up generation without changing the output: a small draft model guesses the next few tokens, the large model checks all of them in one forward pass, keeps the run it agrees with, and adds one token of its own. Because the big model's pass costs about the same for one token or five, every accepted guess is nearly free.

import numpy as np
rng = np.random.default_rng(0)
# Speculative decoding: a small draft model proposes k tokens, the big model checks them all in ONE pass
def expected_tokens_per_pass(alpha, k):
    """alpha = chance the big model accepts each draft token. Accepted run + one token from the big model."""
    return (1 - alpha ** (k + 1)) / (1 - alpha)

def simulate(alpha, k, passes=20000):
    total = 0
    for _ in range(passes):
        accepted = 0
        while accepted < k and rng.random() < alpha:
            accepted += 1
        total += accepted + 1                     # the big model always contributes one token itself
    return total / passes

for alpha in [0.6, 0.8, 0.9]:
    print(f"acceptance {alpha:.0%}, draft 4 tokens: {expected_tokens_per_pass(alpha, 4):.2f} tokens per big-model pass "
          f"(simulated {simulate(alpha, 4):.2f})")
What you should see
acceptance 60%, draft 4 tokens: 2.31 tokens per big-model pass (simulated 2.30)
acceptance 80%, draft 4 tokens: 3.36 tokens per big-model pass (simulated 3.38)
acceptance 90%, draft 4 tokens: 4.10 tokens per big-model pass (simulated 4.11)

At 80% acceptance each big-model pass yields over three tokens. Serving engines offer it as draft models, n-gram lookup from the prompt, or extra prediction heads (Medusa, EAGLE).

Multimodal models

A vision transformer (ViT) cuts an image into patches (16 × 16 pixels, say), embeds each patch like a token, and runs a transformer over them. CLIP trains an image encoder and a text encoder together so matching images and captions get similar vectors (contrastive learninglater · 14.71, the same idea as Lesson 3.22's embedding fine-tuning). Vision-language models such as Claude, GPT and Gemini feed image-patch embeddings into the language model alongside text tokens, which is why an image costs a predictable number of tokens. Audio works the same way with audio frames (Lesson 6.18).

Solutions

SolutionP1 · Quadratic attention

About four times: every token attends to every other, so the score matrix grows with the square of the length. This is why long contexts are expensive.

SolutionB1 · The mask prevents cheating

Each position can see future tokens, so predicting the next token becomes trivial and the model learns nothing useful for generation.

SolutionD1 · The KV cache

Caching keys and values of previous tokens, so each new token computes attention only for itself against the cache.

SolutionM1 · Heads

Multiple heads let the model attend to different relations in parallel; one head must mix them. Output shapes are the same.
