In plain words first
The idea in one line

Text alone is a clumsy control signal. ControlNet lets you clone a pretrained diffusion model and steer it with a depth map, pose skeleton, scribble, or edge image. LoRA lets you fine-tune a 2B-parameter model by training 10 million parameters. Together they made Stable Diffusion a controllable production tool.

Terms you'll hear
Term What people say What it actually means
ControlNet "Spatial control" Cloned encoder + zero-conv skips; reads a conditioning image.
Zero convolution "Starts as identity" 1×1 conv initialized to zero; ControlNet starts as no-op.
LoRA "Low-rank adapter" $W + BA$, $r \ll d$; 100x fewer params than a full fine-tune.
rank r "The knob" LoRA compression; 4-16 typical, 64+ for heavy personalization.
$\alpha$ "LoRA strength" Runtime scaling of the LoRA delta.
IP-Adapter "Reference image" Small image-conditioning adapter via CLIP-image tokens.
DreamBooth "Full subject fine-tune" Train the full model on ~30 images of a subject.
Textual Inversion "New token" Learn a new word embedding only; legacy, mostly replaced.

The problem

In plain words first

A text prompt cannot say exactly where things go in a picture, what pose a person is in, or what your product looks like. Three add-ons fix this without retraining the big model. ControlNet attaches a trainable copy of half of the diffusion network that reads an extra picture, such as an edge map, a depth map or a pose skeleton, and nudges the original network so the output follows its layout. LoRA teaches the model a new style or subject by learning a small "correction" to each weight matrix, stored as the product of two thin matrices, a few percent of the model's size. IP-Adapter lets a reference image act like part of the prompt. This lesson checks LoRA's arithmetic, opens a real LoRA file to see what it contains and what happens when it meets the wrong model, and builds ControlNet's zero-initialised branch on a real Stable Diffusion U-Net to show why training it starts safely. Nothing is trained.

A prompt like "a woman in a red dress walking a dog on a busy street" gives the model no information about where the dog is, what pose the woman is in, or the perspective of the street. Text pins down about 10% of what you need to specify an image. The rest is visual and cannot be described efficiently in words.

Training a new conditional model from scratch for every signal (pose, depth, canny, segmentation) is prohibitive. You want to keep the 2.6B-param SDXL backbone frozen, attach a small side-network that reads the conditioning, and have it nudge the backbone's intermediate features. That is ControlNet.

You also want to teach the model new concepts (your face, your product, your style) without retraining the full model. You want a 100x smaller delta. That is LoRA — low-rank adapters that plug into existing attention weights.

ControlNet + LoRA + text is the practitioner's toolkit: typical ComfyUI and diffusers workflows stack one or more LoRAs, a ControlNet or two, and sometimes an IP-Adapter on an SDXL, FLUX.1, FLUX.2 or Qwen-Image base.

The idea

Idea 1 · ControlNet (Zhang et al., 2023)

Take a pretrained SD. Clone the encoder half of the U-Net. Freeze the original. Train the clone to accept an extra conditioning input (edges, depth, pose). Connect the clone back to the decoder half of the original with zero-convolution skip connections (1×1 convs initialized to zero — start as a no-op, learn a delta).

SD U-Net decoder:   ... ← orig_enc_features + zero_conv(controlnet_enc(condition))

Zero-conv init means ControlNet starts as identity — no harm even before training. Train on 1M (prompt, condition, image) triples with the standard diffusion loss.

Per-modality ControlNets ship as side models: about 360M parameters for SD 1.5 (a copy of its encoder half) and about 1.2B for SDXL, with smaller distilled variants available. You can compose them at inference:

features += weight_a * control_a(depth) + weight_b * control_b(pose)

Idea 2 · LoRA (Hu et al., 2021)

For any linear layer W∈Rd×d in the model, freeze W and add a low-rank delta:

W′=W+ΔW,ΔW=BA,A∈Rr×d,B∈Rd×r

with r≪d. Rank 4-16 is standard for attention, rank 64-128 for heavy fine-tunes. Number of new parameters: 2⋅d⋅r instead of d2. For SDXL attention with d=640, r=16: 20k params per adapter instead of 410k — a 20x reduction. Across the whole model: a LoRA is usually 20-200MB vs the base 5GB.

At inference you can scale the LoRA: W′=W+α⋅BA. α=0.5-1.5 is normal. Multiple LoRAs stack additively (with the usual caveat that they interact in non-linear ways).

Idea 3 · IP-Adapter (Ye et al., 2023)

A tiny adapter that accepts an image as conditioning (alongside text). Uses the CLIP image encoder to produce image tokens, injects them into cross-attention alongside text tokens. ~20MB per base model. Lets you do "generate an image in the style of this reference" without a LoRA.

The same idea as a formula

LoRA. For a frozen weight W∈Rdout​×din​:

h=Wx+rα​BAx,A∈Rr×din​,B∈Rdout​×r

with r trainable directions (α/r is the usual scaling; the runtime "LoRA strength" multiplies it again). Trainable numbers: r(din​+dout​) instead of din​dout​. The change BA has rank at most r, and the best rank-r approximation of any needed change Δ is its truncated SVD (Eckart–Young), so LoRA can do no better than ∥Δ−Δr​∥.

Initialisation. A random, B=0. Then h=Wx at step 0, and with g=∂L/∂h:

∂B∂L​=g(Ax)⊤=0,∂A∂L​=B⊤gx⊤=0

B learns first; A starts moving once B=0.

ControlNet. With the frozen block F(⋅;Θ), its trainable copy Θc​ and zero-initialised 1×1 convolutions Z:

yc​=F(x;Θ)+Z(F(x+Z(c;Θz1​);Θc​);Θz2​)

At initialisation Z outputs zero, so yc​=F(x;Θ), while the gradient with respect to Z's weights is nonzero because its input is not zero.

IP-Adapter. Decoupled cross-attention: Attn(Q,Ktext​,Vtext​)+λAttn(Q,Kimg​,Vimg​), with new K, V projections for the reference image's CLIP tokens.

Worked example
LoRA sizes by hand
  • One attention projection in SD 1.5's first block: d=320, r=64: 64×(320+320)=40,960 numbers instead of 3202=102,400. At this rank and width the saving is only 2.5×; at d=1,280 it is 1,2802/(64×2,560)=10×.
  • SDXL attention, d=640, r=16: 16×1,280=20,480 against 409,600, 20 times fewer.
  • A whole LoRA: LCM-LoRA adapts 278 layers of SD 1.5 at rank 64, 67M numbers, 7.8% of the 860M-parameter U-Net (the run under "Use it"). Style LoRAs at rank 8–32 are a few percent of that.
  • Merging costs nothing at inference: W+rα​BA is one matrix the size of W.

ControlNet's size. It copies the encoder half of the U-Net plus small zero convolutions: about 360M parameters for SD 1.5's 860M U-Net. Each step with one ControlNet runs the U-Net plus that copy.

Check your mental model
  • ✗ "Zero-initialising a layer means it cannot learn."
    ✓ A zero output still receives gradients as long as its input is nonzero; only when both LoRA factors start at zero do the gradients vanish (Solution B1).
  • ✗ "Any LoRA works with any model of the same family name."
    ✓ It must match the exact layer names and shapes of the base it was trained on; SD 1.5, SDXL, SD3 and pruned derivatives differ.
  • ✗ "ControlNet retrains the diffusion model."
    ✓ The original weights stay frozen; only the copy and the zero convolutions train, so removing the ControlNet restores the original model exactly.

Step 1 · LoRA math

code/main.py simulates the two mechanisms on 1-D:

  1. LoRA. A pretrained linear layer W. Freeze it. Train a low-rank BA such that W+BA matches a target linear layer. Show that r=1 is enough to learn a rank-1 correction perfectly.

  2. ControlNet-lite. A "frozen base" predictor and a "side network" that reads an extra signal. The side network's output is gated by a learnable scalar initialized to zero (our version of zero-conv). Train and watch the gate ramp up.

def lora(W, A, B, x, alpha=1.0):
    # W is frozen; A, B are the trainable low-rank factors.
    return [W[i][j] * x[j] for i, j in ...] + alpha * (B @ (A @ x))

Step 2 · zero-init side network

import torch, torch.nn as nn
torch.manual_seed(0)
base, control_net = nn.Linear(8, 8), nn.Linear(8 + 2, 8)          # a frozen base layer and a side network
gate = nn.Parameter(torch.zeros(1))
x, condition = torch.randn(4, 8), torch.randn(4, 2)

side_out = control_net(torch.cat([x, condition], dim=1))
gated = gate * side_out  # gate initialized to 0
h = base(x) + gated
print("identical to base at step 0:", torch.equal(h, base(x)))
h.pow(2).sum().backward()
print(f"gradient for the gate: {gate.grad.item():+.3f} | for the side network: {control_net.weight.grad.norm():.3f}")

LoRA's arithmetic, checked

A 64×64 frozen layer whose needed change has rank 2: the best possible LoRA at ranks 1, 2 and 4 (truncated SVD), the gradients at initialisation, and merged against runtime adapters.

import torch
torch.manual_seed(0)
d = 64
W = torch.randn(d, d) / d ** 0.5                          # a "pretrained" layer, frozen
true_delta = torch.randn(d, 2) @ torch.randn(2, d) / d     # the change fine-tuning needs: rank 2

# 1. The best a rank-r LoRA can possibly do is the truncated SVD of the needed change (Eckart-Young).
U, S, Vh = torch.linalg.svd(true_delta)
print("singular values of the needed change:", " ".join(f"{s:.3f}" for s in S[:4].tolist()), "...")
for r in (1, 2, 4):
    B, A = U[:, :r] * S[:r], Vh[:r]                        # B (d x r), A (r x d)
    err = (true_delta - B @ A).norm() / true_delta.norm()
    print(f"rank {r}: {2 * d * r:>4} trainable numbers instead of {d * d}; best relative error {err:.4f}")

# 2. Why one factor starts at zero: the layer is unchanged at step 0, yet training can still move.
A = torch.randn(4, d, requires_grad=True) * 0.01; A.retain_grad()
B = torch.zeros(d, 4, requires_grad=True)
x, target = torch.randn(32, d), torch.randn(32, d)
y = x @ W.T + x @ (B @ A).T
print(f"\nat initialisation: max |LoRA layer - frozen layer| = {(y - x @ W.T).abs().max():.1e}")
((y - target) ** 2).mean().backward()
print(f"gradient norms: dL/dB {B.grad.norm():.4f} (nonzero, so B starts learning), dL/dA {A.grad.norm():.4f} (zero until B moves)")

# 3. Merging: W + alpha * B A as one matrix gives the same outputs as running the adapter separately.
B2, A2, alpha = torch.randn(d, 4) * 0.1, torch.randn(4, d) * 0.1, 0.8
runtime = x @ W.T + alpha * (x @ A2.T) @ B2.T
merged = x @ (W + alpha * B2 @ A2).T
print(f"\nmerged vs runtime adapter: max difference {(runtime - merged).abs().max():.1e}; "
      f"merged costs {d * d} multiply-adds per token, runtime adds {2 * d * 4}")

rank 2:  256 trainable numbers instead of 4096; best relative error 0.0000

Reading this output

The needed change has two nonzero singular values (1.04 and 0.83), so it is exactly rank 2. A rank-1 LoRA, 128 numbers, can at best capture the larger direction and leaves 63% of the change unexplained; rank 2 (256 numbers instead of 4,096) reproduces it exactly, and rank 4 adds nothing. That is Eckart–Young: LoRA's ceiling is set by how many directions the fine-tune really needs. At initialisation the LoRA layer equals the frozen layer to the last bit, yet the gradient for B is nonzero while that for A is exactly zero, as the formula box predicts. Merging W+αBA into one matrix matches the separate adapter to within rounding (10−6): a merged LoRA costs nothing at inference, an unmerged one adds 2dr multiply-adds per token but can be switched or rescaled per request.

ControlNet's branch on a real U-Net

BK-SDM-Tiny's U-Net (Lesson 8.7) with a ControlNet-style branch built the way the paper describes: a copy of the encoder half, a small convolutional encoder for the control image, and a zero-initialised 1×1 convolution on every skip connection. One forward and backward pass, no training.

import copy, torch, torch.nn as nn
from diffusers import UNet2DConditionModel

torch.manual_seed(0); torch.set_num_threads(2)
# ControlNet's construction on a real U-Net (BK-SDM-Tiny's, 323M parameters): clone the encoder half,
# give it a small encoder for the control image, and connect every clone output through a zero-initialised 1x1 conv.
unet = UNet2DConditionModel.from_pretrained("nota-ai/bk-sdm-tiny", subfolder="unet", variant="fp16", dtype=torch.float32).eval()
class ControlBranch(nn.Module):
    def __init__(self, unet):
        super().__init__()
        self.conv_in, self.time_proj, self.time_embedding = (copy.deepcopy(m) for m in (unet.conv_in, unet.time_proj, unet.time_embedding))
        self.down_blocks = copy.deepcopy(unet.down_blocks)                        # the trainable copy
        self.hint = nn.Sequential(nn.Conv2d(3, 16, 3, padding=1), nn.SiLU(), nn.Conv2d(16, 32, 3, 2, 1), nn.SiLU(),
                                  nn.Conv2d(32, 96, 3, 2, 1), nn.SiLU(), nn.Conv2d(96, 320, 3, 2, 1))   # 8x down to latent size
        chans = [320] + [b.resnets[-1].out_channels for b in unet.down_blocks for _ in range(len(b.resnets) + (b.downsamplers is not None))]
        self.zero = nn.ModuleList(nn.Conv2d(c, c, 1) for c in chans)
        for z in self.zero: nn.init.zeros_(z.weight); nn.init.zeros_(z.bias)
    def forward(self, z, t, text, control):
        emb = self.time_embedding(self.time_proj(t.flatten()).to(z.dtype))
        h = self.conv_in(z) + self.hint(control)                                   # the control image enters here
        res = [h]
        for block in self.down_blocks:
            h, outs = block(h, emb, encoder_hidden_states=text); res += list(outs)
        return [zc(r) for zc, r in zip(self.zero, res)], h

branch = ControlBranch(unet)
n = lambda m: sum(p.numel() for p in m.parameters()) / 1e6
print(f"U-Net {n(unet):.0f}M | control branch {n(branch):.0f}M (encoder copy {n(branch.down_blocks):.0f}M, "
      f"{len(branch.zero)} zero convs {n(branch.zero):.2f}M)")
z, t, text = torch.randn(1, 4, 32, 32), torch.tensor([500]), torch.randn(1, 77, 768)
control = torch.rand(1, 3, 256, 256)                                               # e.g. an edge map
with torch.no_grad():
    plain = unet(z, t, text).sample
res, bottom = branch(z, t, text, control)
out = unet(z, t, text, down_block_additional_residuals=res, mid_block_additional_residual=torch.zeros_like(bottom)).sample
print(f"step 0: max |U-Net with control - U-Net alone| = {(out - plain).abs().max():.1e} (the branch changes nothing yet)")
out.pow(2).mean().backward()
print(f"gradient reaching the zero convs: {sum(z.weight.grad.norm() for z in branch.zero):.3f}; "
      f"reaching the copied encoder: {sum(p.grad.norm() for p in branch.down_blocks.parameters() if p.grad is not None):.3f} "
      f"(zero until the zero convs move)")

Reading this output

The branch is 90M parameters: an 85M copy of BK-SDM-Tiny's encoder half, a small encoder for the control image, and six zero convolutions (2.8M), one per skip connection. With everything wired in, the U-Net's output with the branch is identical to its output alone (difference exactly 0): adding an untrained ControlNet cannot harm the model. Yet the gradient reaching the zero convolutions is clearly nonzero, because their inputs, the copied encoder's features, are not zero, while the copy itself receives no gradient yet, since everything it computes passes through the zero-weight convolutions. After the first update the zero convolutions open a little and gradient flows into the copy: training starts from exactly the pretrained model and moves away gradually, which is why ControlNets train stably on modest data.

Pitfalls

  • Over-scaling LoRAs. α=2 or α=3 is a common "make it stronger" hack that produces over-stylized / broken outputs. Keep α≤1.5.
  • ControlNet weight conflict. Using a Pose ControlNet at weight 1.0 and a Depth ControlNet at weight 1.0 usually overshoots. Sum of weights ≈ 1.0 is a safe default.
  • LoRA on the wrong base. A LoRA made for one base does not fit another: layer names and widths differ, and loaders either refuse (the run under "Use it" shows 120 mismatched tensors) or skip what does not match, silently doing less than you expect.
  • Textual Inversion drift. Tokens trained on one checkpoint drift badly on another. LoRA is more portable.
  • LoRA weight-merging and storage. You can bake a LoRA into the base model weights for faster inference (no runtime addition), but you lose the ability to scale α at runtime. Keep both versions.

Inside a real LoRA file

latent-consistency/lcm-lora-sdv1-5, the LoRA that turns SD 1.5 into a 4-step sampler: what it adapts, its rank, its size against the U-Net (counted on PyTorch's meta device), one layer's change, and what happens when it is loaded into a different model.

import collections, torch
from huggingface_hub import hf_hub_download
from safetensors.torch import load_file
from diffusers import UNet2DConditionModel, StableDiffusionPipeline

# LCM-LoRA for Stable Diffusion 1.5: a real LoRA that turns SD 1.5 into a 4-step sampler (Lesson 8.13's idea).
sd = load_file(hf_hub_download("latent-consistency/lcm-lora-sdv1-5", "pytorch_lora_weights.safetensors"))
downs = {k: v for k, v in sd.items() if k.endswith("lora_down.weight")}   # A matrices (kohya naming); lora_up = B
def kind(k):
    for key, name in (("attn1", "self-attention"), ("attn2", "cross-attention"), ("ff_net", "feed-forward"),
                      ("proj_", "attention in/out projection"), ("resnets", "ResNet conv"), ("time_emb", "time embedding")):
        if key in k: return name
    return "other (up/downsamplers, ...)"
kinds = collections.Counter(kind(k) for k in downs)
ranks = collections.Counter(v.shape[0] for v in downs.values())
n_lora = sum(v.numel() for k, v in sd.items() if not k.endswith(".alpha"))
print(f"{len(downs)} adapted layers, ranks {dict(ranks)}, {n_lora / 1e6:.1f}M numbers in the file")
print("adapted layers by type:", ", ".join(f"{k} {n}" for k, n in kinds.most_common()))

# The base it was made for: SD 1.5's U-Net, counted from its config without downloading the weights.
cfg = UNet2DConditionModel.load_config("stable-diffusion-v1-5/stable-diffusion-v1-5", subfolder="unet")
with torch.device("meta"):
    base = UNet2DConditionModel.from_config(cfg)
n_base = sum(p.numel() for p in base.parameters())
print(f"SD 1.5 U-Net: {n_base / 1e6:.0f}M parameters; the LoRA adds {n_lora / n_base:.1%} of that")

k = next(k for k in downs if "attn1_to_q" in k)
A = downs[k].float().flatten(1); B = sd[k.replace("lora_down", "lora_up")].float().flatten(1)
print(f"one layer, {k.split('.')[0][10:]}: B {tuple(B.shape)} @ A {tuple(A.shape)} = a {tuple((B @ A).shape)} change "
      f"of rank {torch.linalg.matrix_rank(B @ A).item()}, stored in {A.numel() + B.numel():,} numbers instead of {(B @ A).numel():,}")

# The same file on a different base: BK-SDM-Tiny is SD 1.4 with whole blocks removed, so block indices and widths shift.

                                               safety_checker=None, requires_safety_checker=False)

Break it on purpose

In a LoRA layer, initialise both factors to zero, A = 0 and B = 0, "to be safe". The layer still equals the frozen layer at step 0. What happens during training? (Solution B1.)

Industry practice
What's current (2024–2026)
  • LoRAs as the unit of customisation. Civitai and the Hugging Face Hub host LoRAs for SD 1.5, SDXL, FLUX.1, FLUX.2, Qwen-Image and Wan; diffusers' load_lora_weights and set_adapters, and ComfyUI's LoRA loaders, stack several with per-adapter strengths, and training scripts (kohya-ss, ai-toolkit, diffusers) produce them on a single GPU.
  • ControlNets for transformer models. FLUX.1 has official Canny and Depth control models and community ControlNet-Union models; Qwen-Image and SD3.5 ship ControlNets too. Instruction-based editors (FLUX.1 Kontext) now cover some tasks that needed a ControlNet.
  • Identity and style from a reference. IP-Adapter (including FaceID variants), InstantID, FLUX.1 Redux and FLUX.2's multi-reference input take reference images instead of a trained LoRA.

Recap
What to keep from this lesson
  • LoRA: W+rα​BA; r(din​+dout​) numbers; rank at most r; B=0 at start, A random.
  • A LoRA belongs to one base model's exact layers and widths.
  • ControlNet: frozen U-Net + trainable encoder copy + zero convolutions; identical to the base at step 0, yet trainable.
  • IP-Adapter: a reference image's tokens through extra cross-attention keys and values.
  • Serving: hot-swap LoRAs as small deltas; each ControlNet adds roughly half a U-Net per step.

Solutions

SolutionP1 · It fails

It fails: 120 of the LoRA's tensors have the wrong shape for BK-SDM-Tiny, and diffusers refuses to load it. Removing blocks shifted the numbering: BK-SDM-Tiny dropped Stable Diffusion's outermost stage, so a key such as up_blocks.1.attentions.0 now points to a block that works at 640 channels instead of 1,280. A LoRA is tied to the exact names and shapes of the network it was trained on. When names happen to match but meanings differ, a loader may also skip or misapply weights silently, which is worse than an error; this is why model hubs label every LoRA with its base model.

SolutionB1 · The layer never learns

With A=0 and B=0, both gradients vanish: ∂L/∂B=g(Ax)⊤=0 because Ax=0, and ∂L/∂A=B⊤gx⊤=0 because B=0. The optimiser receives zero for every LoRA parameter at every step, so the adapter stays at zero forever while the loss looks perfectly normal, since the frozen model still works. One factor must be nonzero to break the symmetry; the standard choice is A random and B=0, which keeps the layer unchanged at step 0 and still lets B learn, as the run after Step 2 shows. ControlNet's zero convolutions avoid the same trap because their inputs, the copied encoder's features, are nonzero.

Production note: LoRA swaps, ControlNet lanes, multi-tenant serving

A real text-to-image SaaS serves hundreds of LoRAs and a dozen ControlNets over the same base checkpoint. The serving problem looks a lot like LLM multi-tenancy (the production literature covers the LLM case under continuous batching and LoRAX / S-LoRA):

  • Hot-swap LoRAs, do not merge. Merging W′=W+α⋅B⋅A into the base removes the adapter's extra matrix multiplies (a modest per-step saving) but freezes α and the base. Keep LoRAs hot in VRAM as rank-r deltas; diffusers exposes pipe.load_lora_weights() + pipe.set_adapters([...], adapter_weights=[...]) for per-request activation. Swap cost is the 2 · d · r · num_layers weights — MB-scale, sub-second.
  • ControlNet as a second attention lane. The cloned encoder runs in parallel with the base. Two ControlNets at weight 1.0 each = two extra forward passes per step, not one merged pass. Activation memory grows with each one. Budget roughly 1.4–1.5× step cost per active ControlNet, since each runs a copy of the encoder half.
  • Quantized LoRAs too. If you quantized the base (see Lesson 8.7, Flux on 8GB), the LoRA delta also quantizes cleanly to 8-bit or 4-bit. QLoRA-style loading lets you stack 5-10 LoRAs on top of a 4-bit Flux base without blowing memory.

Flux-specific: Niels' Flux-on-8GB notebook quantizes the base to 4-bit; stacking a style LoRA (pipe.load_lora_weights("user/style-lora")) on that quantized base at weight_name="pytorch_lora_weights.safetensors" still works. This is a common recipe for serving FLUX-family LoRAs on small GPUs.
