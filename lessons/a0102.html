Terms you'll hear
Term What people say What it actually means
Vector "An arrow" An ordered list of numbers. In AI: a point in high-dimensional space.
Matrix "A table of numbers" A linear transformation. It maps vectors from one space to another.
Matrix multiply "Just multiply the numbers" Dot products between every row of the first matrix and every column of the second. Order matters.
Transpose "Flip it" Swap rows and columns. Turns an $m \times n$ matrix into $n \times m$. Critical in backpropagation.
Determinant "Some number from the matrix" Measures how much the matrix scales area (2D) or volume (3D). Zero means the transformation crushes a dimension.
Inverse "Undo the matrix" The matrix that reverses the transformation. Only exists when the determinant is not zero.
Identity matrix "The boring matrix" The matrix equivalent of multiplying by 1. Used in residual connections (ResNets).
Broadcasting "Magic shape fixing" Stretching a smaller array to match a larger one by repeating along missing dimensions.
Element-wise "Regular multiplication" Multiply matching positions. Both arrays must have the same shape (or be broadcastable).

The problem

In plain words first

A matrix is a grid of numbers with a shape, rows × columns. Two kinds of multiplication matter and are easy to mix up: element-wise (*) multiplies matching positions and needs equal shapes, while matrix multiplication (@) takes dot products of rows with columns and needs the inner sizes to match. Broadcasting lets NumPy and PyTorch combine arrays of different shapes by repeating the smaller one, which is convenient and occasionally a silent bug.

You want to build a neural network. You read the code and see this:

output = activation(weights @ input + bias)

That @ is matrix multiplication. The weights are a matrix. The input is a vector. If you do not know what those operations do, this line is magic. If you do know, it is the entire forward pass of a layer in three operations.

Every image your model processes is a matrix of pixel values. Every word embedding is a vector. Every layer of every neural network is a matrix transformation. You cannot build AI systems without being fluent in matrix operations the same way you cannot write code without understanding variables.

This lesson builds that fluency from scratch.

Idea 1 · Vectors: ordered lists of numbers

A vector is a list of numbers with a direction and magnitude. In AI, vectors represent data points, features, or parameters.

v = [3, 4]        -- a 2D vector
w = [1, 0, -2]    -- a 3D vector

A 2D vector [3, 4] points to coordinates (3, 4) on a plane. Its length (magnitude) is 5 (the 3-4-5 triangle).

Idea 2 · Matrices: grids of numbers

A matrix is a 2D grid. Rows and columns. An m×n matrix has m rows and n columns.

A=[14​25​36​]2x3 matrix (2 rows, 3 columns)

In neural networks, weight matrices transform input vectors into output vectors. A layer with 784 inputs and 128 outputs uses a 128x784 weight matrix.

Idea 3 · Why shapes matter

Matrix multiplication has a strict rule: (m x n) @ (n x p) = (m x p). The inner dimensions must match.

(128 x 784) @ (784 x 1) = (128 x 1)
  weights       input       output

Inner dimensions: 784 = 784  -- valid

If you get a shape mismatch error in PyTorch, this is why.

Idea 5 · Element-wise vs matrix multiplication

This distinction trips up beginners constantly.

Element-wise: multiply matching positions. Both matrices must be the same shape.

[13​24​]∗[57​68​]=[521​1232​]

Matrix multiplication: dot products of rows and columns. Inner dimensions must match.

[13​24​]@[57​68​]=[1⋅5+2⋅73⋅5+4⋅7​1⋅6+2⋅83⋅6+4⋅8​]=[1943​2250​]

Different operations, different results, different rules.

Check your mental model
  • ✗ "A @ B equals B @ A, like ordinary multiplication."
    ✓ Not in general. With the lesson's A and B, A @ B is [[19, 22], [43, 50]] and B @ A is [[23, 34], [31, 46]]. Order matters: apply B then A is a different transformation from A then B.
  • ✗ "A * B is matrix multiplication in NumPy."
    ✓ It is element-wise. Matrix multiplication is @ (or np.matmul). Both run without error on two square matrices, so the mistake is silent.
  • ✗ "The determinant is just a number to check before inverting."
    ✓ It is the factor by which the matrix scales areas (volumes in 3D). Zero means space is squashed flat, which is exactly why the matrix cannot be undone.

Idea 6 · Broadcasting

When you add a bias vector to a matrix of outputs, the shapes do not match. Broadcasting stretches the smaller array to fit.

| 1  2  3 |   +   [10, 20, 30]
| 4  5  6 |

Broadcasting stretches the vector across rows:

| 1  2  3 |   | 10  20  30 |   | 11  22  33 |
| 4  5  6 | + | 10  20  30 | = | 14  25  36 |

Every modern framework does this automatically. Understanding it prevents confusion when shapes seem wrong but the code runs.

The same idea as a formula

Matrix product. For A of shape m×n and B of shape n×p,

(AB)ij​=k=1∑n​Aik​Bkj​,AB has shape m×p

The inner sizes must match; the result keeps the outer ones. It costs m⋅n⋅p multiply-adds, 2mnp FLOPs. In general AB=BA, and (AB)⊤=B⊤A⊤.

Element-wise (Hadamard) product. (A⊙B)ij​=Aij​Bij​ needs equal shapes (after broadcasting) and costs mn multiplies.

Broadcasting. Line the shapes up from the right; each pair of sizes must be equal or one of them must be 1, and a size-1 axis is repeated to match. (32,128)+(128,) gives (32,128); (3,1)+(1,4) gives (3,4); (3,2)+(3,) fails.

A neural-network layer is one matrix product plus a broadcast add: for a batch X of shape B×din​ and weights W of shape dout​×din​ (PyTorch's convention), Y=XW⊤+b has shape B×dout​.

Worked example
Shapes and products by hand

A=(14​25​36​) (2×3), B=​101​011​​ (3×2).

  • AB is 2×2: row 1 is (1+0+3, 0+2+3)=(4,5); row 2 is (4+0+6, 0+5+6)=(10,11).
  • BA is 3×3: a different shape altogether, so AB=BA is not even a question of values.
  • A⊙B fails: 2×3 against 3×2.

A layer. MNIST images flattened to 784 numbers, a batch of 32, a hidden layer of 128: X is 32×784, W is 128×784, b has 128 entries. Y is 32×128, the layer has 784×128+128=100,480 parameters, and the forward pass costs 2×32×784×128≈6.4 million FLOPs.

Step 1 · Vector class

class Vector:
    def __init__(self, data):
        self.data = list(data)
        self.size = len(self.data)

    def __repr__(self):
        return f"Vector({self.data})"

    def __add__(self, other):
        return Vector([a + b for a, b in zip(self.data, other.data)])

    def __sub__(self, other):
        return Vector([a - b for a, b in zip(self.data, other.data)])

    def __mul__(self, scalar):
        return Vector([x * scalar for x in self.data])

    def dot(self, other):
        return sum(a * b for a, b in zip(self.data, other.data))

    def magnitude(self):
        return sum(x ** 2 for x in self.data) ** 0.5

Step 2 · Matrix class with core operations

class Matrix:
    def __init__(self, data):
        self.data = [list(row) for row in data]
        self.rows = len(self.data)
        self.cols = len(self.data[0])
        self.shape = (self.rows, self.cols)

    def __repr__(self):
        rows_str = "\n  ".join(str(row) for row in self.data)
        return f"Matrix({self.shape}):\n  {rows_str}"

    def __add__(self, other):
        return Matrix([
            [self.data[i][j] + other.data[i][j] for j in range(self.cols)]
            for i in range(self.rows)
        ])

    def __sub__(self, other):
        return Matrix([
            [self.data[i][j] - other.data[i][j] for j in range(self.cols)]
            for i in range(self.rows)
        ])

    def scalar_multiply(self, scalar):
        return Matrix([
            [self.data[i][j] * scalar for j in range(self.cols)]
            for i in range(self.rows)
        ])

    def element_wise_multiply(self, other):
        return Matrix([
            [self.data[i][j] * other.data[i][j] for j in range(self.cols)]
            for i in range(self.rows)
        ])

    def matmul(self, other):
        return Matrix([
            [
                sum(self.data[i][k] * other.data[k][j] for k in range(self.cols))
                for j in range(other.cols)
            ]
            for i in range(self.rows)
        ])

    def transpose(self):
        return Matrix([
            [self.data[j][i] for j in range(self.rows)]
            for i in range(self.cols)
        ])

    def determinant(self):
        if self.shape == (1, 1):
            return self.data[0][0]
        if self.shape == (2, 2):
            return self.data[0][0] * self.data[1][1] - self.data[0][1] * self.data[1][0]
        det = 0
        for j in range(self.cols):
            minor = Matrix([
                [self.data[i][k] for k in range(self.cols) if k != j]
                for i in range(1, self.rows)
            ])
            det += ((-1) ** j) * self.data[0][j] * minor.determinant()
        return det

    def inverse_2x2(self):
        det = self.determinant()
        if det == 0:
            raise ValueError("Matrix is singular, no inverse exists")
        return Matrix([
            [self.data[1][1] / det, -self.data[0][1] / det],
            [-self.data[1][0] / det, self.data[0][0] / det]
        ])

    @staticmethod
    def identity(n):
        return Matrix([
            [1 if i == j else 0 for j in range(n)]
            for i in range(n)
        ])

Step 4 · Connect to neural networks

import random

inputs = Matrix([[0.5], [0.8], [0.2]])
weights = Matrix([
    [random.uniform(-1, 1) for _ in range(3)]
    for _ in range(2)
])
bias = Matrix([[0.1], [0.1]])

def relu_matrix(m):
    return Matrix([[max(0, val) for val in row] for row in m.data])

pre_activation = weights.matmul(inputs) + bias
output = relu_matrix(pre_activation)

print(f"Input shape: {inputs.shape}")
print(f"Weight shape: {weights.shape}")
print(f"Output shape: {output.shape}")
print(f"Output: {output.data}")

Recap
What to keep from this lesson
  • Shapes first: (m × n) @ (n × p) = (m × p); the inner sizes must match.
  • * is element-wise, @ is matrix multiplication, and A @ B is usually not B @ A.
  • Transpose swaps rows and columns; the determinant is the area scale; a zero determinant means no inverse.
  • Broadcasting repeats size-1 dimensions; check result shapes when arrays of different ranks meet.

Solutions

SolutionP1 · Inner sizes

(2 × 3) @ (3 × 4) gives 2 × 4. (3 × 4) @ (2 × 3) fails: the inner sizes 4 and 2 differ. For W @ x with x of shape 784 × 1, W must be 128 × 784, so that (128 × 784) @ (784 × 1) = 128 × 1. PyTorch's nn.Linear(784, 128) stores its weight exactly that way, as (128, 784).

SolutionB1 · A perfect prediction with a large error

1.333... instead of 0. y - p broadcasts a (3, 1) column against a (3,) row into a (3, 3) table of every target minus every prediction, and the mean of its squares is 4/3. No error is raised. Flatten one side first (y.ravel() - p gives 0.0) and check .shape of anything you subtract in a loss.

Industry practice
What's current (2024–2026)
  • Lower-precision matrices. Training runs in BF16, Hopper GPUs added FP8 and Blackwell adds 4-bit formats (NVFP4, MXFP4) for matrix multiplication. OpenAI's open-weight gpt-oss models ship their mixture-of-experts weights in MXFP4, and DeepSeek-V3 was trained with FP8 matrix multiplications.
  • Libraries do the arithmetic. NumPy and PyTorch call BLAS libraries (OpenBLAS, MKL, Accelerate on Macs, cuBLAS on NVIDIA GPUs); writing loops yourself is for understanding, as in this lesson, not for speed.

Sources: gpt-oss model card, DeepSeek-V3 report, NVIDIA Blackwell, cuBLAS.

You are a math tutor who teaches linear algebra through geometric intuition. Your goal is to make matrix operations feel physical and visual, not abstract.

When explaining matrix concepts, follow these principles:

1. Start with geometry, not formulas. A matrix is a transformation that stretches, rotates, or squishes space. Show what happens to a unit square or unit vectors before writing any equations.

2. Connect every operation to neural networks. Do not teach math in isolation. After explaining what an operation does geometrically, immediately show where it appears in a real network.

3. Use concrete small examples. Work with 2x2 and 2x3 matrices so the student can verify by hand. Never jump to high dimensions before the low-dimensional case is solid.

4. Distinguish element-wise from matrix multiplication early and often. This is the most common source of bugs for beginners. Show both side by side with the same inputs so the difference is obvious.

5. Teach shapes as the primary debugging tool. Before computing anything, have the student predict the output shape. If they can predict shapes, they understand the operation.

When a student asks about a matrix operation, structure your response as:

- What it does geometrically (one sentence, with a visual if possible)
- The formula (compact, no unnecessary notation)
- A 2x2 or 2x3 worked example with actual numbers
- Where this shows up in neural networks (specific layer, specific step)
- A common mistake to watch for

Operations you should be prepared to explain:

- Addition: combining transformations, bias addition in networks
- Scalar multiplication: scaling gradients by learning rate
- Matrix multiplication: the core of every layer's forward pass
- Transpose: swapping input/output perspectives, used in backpropagation
- Determinant: measuring how much a transformation scales space, checking if inverse exists
- Inverse: undoing a transformation, solving linear systems
- Identity: the do-nothing transformation, residual connections
- Broadcasting: how bias vectors add to output matrices without explicit expansion

Avoid:
- Abstract proofs without geometric grounding
- Jumping to high dimensions before 2D/3D is clear
- Using "obvious" or "trivially" or "it can be shown that"

Explain the mechanismA colleague builds a dense layer that takes 784 inputs and gives 128 outputs. The first forward pass stops with a shape error. Which dimensions does the weight matrix need, and how do you read an error like this one?

Level 1 of 4 · about 5 minutes to answer well.

Short answer. The matrix is 128 by 784: one row for each output and one column for each input. A matrix product needs the inner sizes to agree, so a 128 by 784 matrix times a 784 by 1 input gives a 128 by 1 output. An error means the inner sizes differ, and the fix starts with the shapes of every operand written on paper.

The rule.

A product of an m by n matrix and an n by p matrix gives an m by p matrix. The inner sizes, both n, must agree. For the layer in the question:

(128 x 784) @ (784 x 1) = (128 x 1)
  weights       input       output

The rows of the weight matrix count the outputs. The columns count the inputs. Each output is the dot product of one weight row with the whole input vector.

The bias.

The bias holds one value for each output. Store it as a 128 by 1 column, as the lesson does, so that it adds to the 128 by 1 result element by element. A flat array of 128 values against a 128 by 1 column broadcasts to 128 by 128 with no error. When the layer runs on a batch, the bias has fewer dimensions than the output, and broadcasting repeats it across the batch. Broadcasting only stretches a dimension of size 1, so it never fixes a 784 against a 128.

How to read the error.

  1. Write the shape of every operand next to the operation.
  2. Find the operation whose inner sizes do not match. That is the broken line.
  3. Decide which side is wrong. A transposed weight matrix, an input stored as a row instead of a column, and a missing batch dimension each give a different pair of numbers in the message.

The lesson makes the same check for a two layer network: the first matrix is 4 by 3 and the second is 2 by 4, so a 3 by 1 input gives a 4 by 1 hidden vector and a 2 by 1 output.

Plausible wrong answers.

  • "The weight matrix is 784 by 128 because inputs come first." With a column input the matrix needs 128 rows and 784 columns. The order of the product decides which form is right, not the order in which you name the sizes.
  • "Shapes do not matter, the framework fixes them." Broadcasting repeats only a dimension of size 1. A 784 against a 128 inner size is an error, or a silent wrong result after a reshape.
  • "Transpose things until the code runs." A transpose that makes the code run can multiply the wrong pairs of numbers. Write the shapes down first and then change the one that is wrong.

Follow-ups an interviewer may ask.

  • (level 1) What shape does the bias have? Expected: one value for each output, so 128 values, stored as a 128 by 1 column so that it adds to each output column.
  • (level 2) A batch of inputs arrives as rows instead of columns. What changes? Expected: the order of the product changes, so the batch matrix times the transposed weight gives one output row for each input.
  • (level 2) Why does a transpose appear in the backward pass? Expected: the gradient for the input needs the weight matrix with its rows and columns swapped, so that the shapes agree in the reverse direction.
  • (level 3) How does broadcasting hide a shape bug? Expected: a dimension of size 1 is stretched to fit, so a wrong shape can run without an error and give wrong values. An assertion on the shape catches it.

Level 1 of 4 · about 5 minutes to answer well.

Short answer. The star multiplies matching positions, so the first print shows 5, 12, 21 and 32. The at sign forms dot products of rows with columns, so the second print shows 19, 22, 43 and 50. A layer uses the at sign, because every output must sum over every input.

Element-wise product.

Both arrays have the same shape, so the star pairs each cell with the cell at the same position:

1*5 = 5    2*6 = 12
3*7 = 21   4*8 = 32

The order of A and B does not change the result.

Matrix product.

The at sign calls the matmul method. Cell (i, j) of the result is the dot product of row i of A with column j of B:

1*5 + 2*7 = 19    1*6 + 2*8 = 22
3*5 + 4*7 = 43    3*6 + 4*8 = 50

The order matters. B times A gives other numbers. The inner sizes must agree, and the result has the rows of A and the columns of B.

Which one a layer uses.

A dense layer computes an activation of W times x plus b. Each output mixes all inputs with its own row of weights, which is the dot product inside a matrix product. The element-wise product appears in other places in training, for example when the learning rate scales a gradient, or when a mask zeroes some values. NumPy runs the matrix product with tuned BLAS routines written in C and Fortran, which the lesson measures as about 100 times faster than a Python loop over the same numbers.

Plausible wrong answers.

  • "Both print the same matrix, the star is another spelling of the at sign." The two operations follow different rules and give different numbers.
  • "The at sign is the element-wise product and the star is the matrix product." The at sign calls matmul, which forms dot products of rows and columns. The star works on matching positions.
  • "A dense layer multiplies each weight by its input, so it is element-wise." Each output also sums over all inputs. That sum is the dot product inside a matrix product.

Follow-ups an interviewer may ask.

  • (level 1) Does the order of A and B matter in each case? Expected: no for the element-wise product, yes for the matrix product.
  • (level 2) Which of the two operations does a learning rate step use? Expected: a scalar times the gradient, which is an element-wise scale.
  • (level 2) Why is the at sign so much faster than a loop in Python? Expected: it calls BLAS routines in C and Fortran. The lesson gives about 100 times.
  • (level 3) Someone writes the star for the layer and the code runs without an error. How is that possible? Expected: the shapes happened to be equal, so the element-wise product ran and gave wrong values with no error.
