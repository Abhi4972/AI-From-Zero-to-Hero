The problem

In plain words first

This capstone joins the phase together. A voice assistant listens to a microphone in 20 ms pieces, notices when someone starts and stops talking (voice activity detection), writes down what they said (speech recognition), decides what to do, possibly by calling a tool such as a timer or a weather service (an LLM with tool calling), says the answer (text-to-speech), and stops talking at once if the user interrupts. Each part was covered in an earlier lesson; the hard part is the joins: when exactly a turn starts and ends, how long each step may take, and what happens when one step is wrong. This lesson runs a complete assistant on this page with small open models on a CPU (WebRTC VAD, Whisper base.en, Qwen2.5-0.5B with tool calling, SpeechT5), feeds it spoken requests, and measures every stage. It also finds two real bugs along the way. Nothing is trained.

Build an end-to-end assistant:

  1. Captures mic input (16 kHz mono).
  2. Detects start/end of user speech.
  3. Transcribes streaming.
  4. Passes transcript to an LLM that can call tools (timer, weather, calendar).
  5. Streams LLM text to a TTS.
  6. Plays audio back to the user.
  7. Stops if the user interrupts mid-response.

Latency target: first TTS audio byte within 800 ms of the user finishing their utterance on a laptop CPU. Quality target: no missed words, no hallucinated subtitles on silence, no voice cloning leakage, no prompt injection success.

The idea

The same idea as a formula

Latency to first audio. From the end of the user's speech:

T=tend-of-turn​+tSTT​+tLLM(first sentence)​+ttools​+tTTS(first chunk)​+tnetwork​

tend-of-turn​ is a choice, the silence the system waits before deciding the user has finished; shorter waits answer faster and cut people off mid-sentence more often.

Turn detection as a small state machine. States idle → speaking → idle. Enter speaking after m consecutive speech frames (minimum speech duration 20m ms) and include the pre-roll; leave after s consecutive non-speech frames. With per-frame false-alarm probability p on noise, a single-frame trigger fires on noise at rate p per frame, while requiring m frames in a row lowers that to roughly pm (if frames were independent).

Barge-in delay = 20m ms of speech needed to trust the detection + the time to cancel playback, LLM and TTS. Larger m ignores coughs and background voices; smaller m stops faster.

Tool calling is a loop: the LLM emits a structured call (name,arguments) that matches a JSON schema, the runtime executes it, and the result is appended to the conversation as a tool message before the LLM continues. Each round trip adds an LLM call to T.

Worked example
A turn's budget by hand

Target. 800 ms to first audio. Spend it: end-of-turn wait 500 ms leaves 300 ms for everything else, so on a CPU this target is out of reach (the run under Step 5 measures several seconds). Typical production answers: a shorter end-of-turn wait with a turn-detection model, GPU or hosted STT, an LLM with fast first tokens, and TTS started on the first clause.

False triggers. If background noise makes a fresh VAD fire on 4 of the first 5 frames, a single-frame trigger starts a turn at once. Requiring 10 consecutive frames (200 ms) ignores that burst; the price is 200 ms of extra delay before a real turn is confirmed, recovered by the pre-roll so no audio is lost.

Barge-in. At 20 ms per frame, requiring 5 speech frames means the assistant keeps talking for at least 100 ms after the user starts, plus the time to stop playback.

Check your mental model
  • ✗ "VAD says speech, so a turn has started."
    ✓ A single frame is weak evidence; adaptive VADs also misfire while they learn the background. Require a minimum run of speech.
  • ✗ "The LLM's text can go straight to TTS."
    ✓ Text written for reading ("14°C", "5 min", markdown) must be normalised for speaking.
  • ✗ "Latency is the sum of model run times."
    ✓ The end-of-turn silence and every tool round trip count too, and on a CPU the models dominate.

Idea 1 · The seven components

  1. Audio capture. Mic → 16 kHz mono → 20 ms chunks. Usually sounddevice in Python or native AudioUnit/ALSA/WASAPI in production.
  2. VAD (Lesson 6.11). A common configuration: Silero VAD at threshold 0.5, minimum speech 250 ms, end-of-turn silence 500 ms. Signals "start" and "end."
  3. Streaming STT (Lessons 6.4–6.5). Whisper-streaming, Parakeet-TDT, or Deepgram Nova-3 (API). Partial + final transcripts.
  4. LLM with tool calling. A fast model from a major provider, or a local open model. JSON schema for tools. Stream tokens.
  5. Streaming TTS (Lesson 6.7). Kokoro-82M (small, fast, open) or a commercial streaming TTS such as Cartesia Sonic or ElevenLabs Flash. Start speaking at the first sentence or clause boundary instead of waiting for the full reply.
  6. Playback. Speaker out; opus-encode for low-bandwidth networks.
  7. Interruption handler. If VAD fires during TTS playback, stop playback, cancel LLM, restart STT.

Idea 2 · The three failure modes you will hit

  1. First-word clip. VAD starts a beat too late. User's "hey" is missing. Keep a pre-roll buffer (Step 2 does) and, with Silero, a slightly lower start threshold.
  2. Mid-response interrupt confusion. LLM keeps generating after user interrupts; assistant talks over user. Wire VAD → cancel-LLM.
  3. Silence hallucination. Whisper outputs "Thanks for watching" on the silent warm-up frames. Always VAD-gate.

Step 1 · mic capture with chunking (pseudocode)

import sounddevice as sd

def mic_stream(chunk_ms=20, sr=16000):
    q = queue.Queue()
    def cb(indata, frames, time, status):
        q.put(indata.copy().flatten())
    with sd.InputStream(channels=1, samplerate=sr, blocksize=int(sr * chunk_ms/1000), callback=cb):
        while True:
            yield q.get()

Not run here: this page has no microphone or sounddevice. The runs under Step 5 replay recordings as 20 ms frames, which is what the callback delivers.

Step 2 · VAD-gated turn capture

def capture_turn(stream, vad, pre_roll_ms=300, silence_ms=500):
    buf, pre, triggered = [], collections.deque(maxlen=pre_roll_ms // 20), False
    silent = 0
    for chunk in stream:
        pre.append(chunk)
        if vad(chunk):
            if not triggered:
                buf = list(pre)
                triggered = True
            buf.append(chunk)
            silent = 0
        elif triggered:
            silent += 20
            buf.append(chunk)
            if silent >= silence_ms:
                return b"".join(buf)

Step 3 · streaming STT → LLM → TTS

async def turn(audio_bytes):
    transcript = await stt.transcribe(audio_bytes)
    async for token in llm.stream(transcript):
        async for audio in tts.stream(token):
            await speaker.play(audio)

Step 4 · tool calling inside the LLM loop

async def llm_turn(user_text, tools, llm, tts):
    async for chunk in llm.stream(user_text, tools=tools):
        if chunk.type == "tool_call":
            result = dispatch(chunk.name, chunk.args)
            continue_streaming(result)
        if chunk.type == "text":

Step 5 · interruption handling

async def listen_while_speaking(mic, vad, speaker, tts_loop, new_turn):
    tts_task = asyncio.create_task(tts_loop())
    while True:
        chunk = await mic.get()
        if vad(chunk):
            tts_task.cancel()
            await speaker.stop()
            await new_turn()
            break

A complete assistant, on this page

Three requests spoken by SpeechT5 (as the "user", so no microphone is needed), placed in a quiet room with half a second of lead-in, replayed as 20 ms frames into Step 2's capture_turn with WebRTC's VAD, transcribed by Whisper base.en, answered by Qwen2.5-0.5B-Instruct with two tools (set_timer, and get_weather as a stub with no network), and spoken back by SpeechT5. Whisper then transcribes the spoken reply as a check. Every stage is timed; then the failed turn is diagnosed and fixed.

import collections, json, re, time                                  # Step 2's capture_turn needs collections
import numpy as np, torch, webrtcvad
from datasets import load_dataset
from transformers import (SpeechT5Processor, SpeechT5ForTextToSpeech, SpeechT5HifiGan, WhisperProcessor,
                          WhisperForConditionalGeneration, AutoTokenizer, AutoModelForCausalLM)

SR = 16000
# --- load every model once, before the first turn (cold starts are a pitfall) ---
tproc = SpeechT5Processor.from_pretrained("microsoft/speecht5_tts")
tts = SpeechT5ForTextToSpeech.from_pretrained("microsoft/speecht5_tts").eval()
vocoder = SpeechT5HifiGan.from_pretrained("microsoft/speecht5_hifigan").eval()
xv = load_dataset("Matthijs/cmu-arctic-xvectors", revision="refs/convert/parquet", split="validation")
names = [f.split("_arctic")[0].replace("cmu_us_", "") for f in xv["filename"]]
voice = {s: torch.tensor(xv[names.index(s)]["xvector"]).unsqueeze(0) for s in ["slt", "bdl"]}
wproc = WhisperProcessor.from_pretrained("openai/whisper-base.en")
stt = WhisperForConditionalGeneration.from_pretrained("openai/whisper-base.en").eval()
ltok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct", dtype=torch.float32).eval()

def speak(text, who="slt"):
    torch.manual_seed(0)
    with torch.no_grad():
        return tts.generate_speech(tproc(text=text, return_tensors="pt")["input_ids"], voice[who], vocoder=vocoder).numpy()
def transcribe(audio):
    with torch.no_grad():
        return wproc.batch_decode(stt.generate(wproc(audio, sampling_rate=SR, return_tensors="pt").input_features),
                                  skip_special_tokens=True)[0].strip()

# --- tools: JSON schemas the LLM sees, and the functions that run ---
TOOLS = [
    {"type": "function", "function": {"name": "set_timer", "description": "Start a countdown timer.",
     "parameters": {"type": "object", "properties": {"seconds": {"type": "integer", "description": "Length in seconds"}},
                    "required": ["seconds"]}}},
    {"type": "function", "function": {"name": "get_weather", "description": "Current weather for a city.",
     "parameters": {"type": "object", "properties": {"location": {"type": "string"}}, "required": ["location"]}}},
]
def dispatch(name, args):
    if name == "set_timer":
        return {"ok": True, "seconds": int(args["seconds"])}
    if name == "get_weather":                                        # a stub: no network calls on this page
        return {"location": args["location"], "forecast": "light rain", "temperature_c": 14}
    return {"error": f"unknown tool {name}"}

def generate(messages, tools=None, max_new_tokens=80):
    ids = ltok.apply_chat_template(messages, tools=tools, add_generation_prompt=True, return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=max_new_tokens, do_sample=False)
    return ltok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()

def assistant(user_text):
    messages = [{"role": "system", "content": "You are a concise voice assistant. Answer in one short sentence."},
                {"role": "user", "content": user_text}]
    out = generate(messages, tools=TOOLS)
    calls = [json.loads(m) for m in re.findall(r"<tool_call>\s*(\{.*?\})\s*</tool_call>", out, re.S)]
    for call in calls:                                               # run each tool, feed the result back, ask again
        result = dispatch(call["name"], call.get("arguments", {}))
        messages += [{"role": "assistant", "content": "", "tool_calls": [{"type": "function", "function": call}]},
                     {"role": "tool", "content": json.dumps(result)}]
    reply = generate(messages, tools=TOOLS) if calls else out
    return calls, reply

# --- one full turn, from microphone frames to spoken reply ---
wvad = webrtcvad.Vad(2)
def vad(chunk_bytes):
    return wvad.is_speech(chunk_bytes, SR)
def mic(audio):                                                      # replay a recording as 20 ms frames of 16-bit PCM
    pcm = (np.clip(audio, -1, 1) * 32767).astype(np.int16)
    for i in range(0, len(pcm) - 320 + 1, 320):
        yield pcm[i:i + 320].tobytes()

rng = np.random.default_rng(0)
for request in ["Set a timer for five minutes.", "What is the weather like in Paris today?", "Tell me a short joke about cats."]:
    said = speak(request, "bdl")                                     # the "user", synthesised so the page needs no microphone
    room = np.concatenate([np.zeros(SR // 2), said, np.zeros(SR)]) + 0.002 * rng.standard_normal(len(said) + SR * 3 // 2)
    t = {}
    t0 = time.perf_counter()
    turn = capture_turn(mic(room.astype(np.float32)), vad)           # Step 2: VAD-gated capture with pre-roll
    audio = np.frombuffer(turn, dtype=np.int16).astype(np.float32) / 32768
    t["capture (incl. 500 ms end-of-turn silence)"] = 0.5            # the end-pointing wait, in real time
    t1 = time.perf_counter(); text = transcribe(audio); t["speech to text"] = time.perf_counter() - t1
    t1 = time.perf_counter(); calls, reply = assistant(text); t["LLM incl. tool calls"] = time.perf_counter() - t1
    t1 = time.perf_counter(); first = re.split(r"(?<=[.!?])\s+", reply)[0]; spoken = speak(first)
    t["TTS, first sentence"] = time.perf_counter() - t1
    print(f"user said: {request!r}\n  captured {len(audio) / SR:.2f} s; heard {text!r}")
    print(f"  tool calls: {calls}\n  reply: {reply!r}\n  reply as heard by Whisper: {transcribe(spoken)!r}")
    print("  latency: " + ", ".join(f"{k} {v * 1000:.0f} ms" for k, v in t.items()) + f"; total {sum(t.values()) * 1000:.0f} ms\n")

# Fix: require ~200 ms of consecutive speech before a turn starts (and warm the VAD up on background audio).
def capture_turn_min(stream, vad, pre_roll_ms=300, silence_ms=500, min_speech_ms=200):
    pre, buf, run, silent, triggered = collections.deque(maxlen=pre_roll_ms // 20), [], 0, 0, False
    for chunk in stream:
        pre.append(chunk); speech = vad(chunk)
        if not triggered:
            run = run + 1 if speech else 0
            if run * 20 >= min_speech_ms:                            # enough speech in a row: start the turn
                buf, triggered = list(pre), True
            continue
        buf.append(chunk); silent = 0 if speech else silent + 20
        if silent >= silence_ms:
            return b"".join(buf)

The first request fails before any model runs. Step 2's capture_turn returns 0.60 s of audio and Whisper hears "So"; the assistant then answers a question nobody asked. The diagnostic line shows why: a fresh WebRTC VAD flags the first 4 frames of background noise as speech while it adapts to the room; capture_turn starts a turn on the first speech frame, sees 500 ms of silence, and ends the "turn" before the user has said a word. Barge-in, timed

The assistant "plays" 3 s of reply in real-time 20 ms chunks while the microphone task listens; the user starts saying "Wait, stop" after 1 s. Playback stops once the VAD has seen 1, 5 or 15 speech frames in a row. Each run uses a fresh VAD warmed up on 1 s of background noise.

import asyncio

# Barge-in: the assistant is "speaking" (playing 20 ms chunks in real time) when the user starts talking.
def fresh_warm_vad():
    global wvad
    wvad = webrtcvad.Vad(2)                                            # WebRTC's VAD adapts to the background:
    for f in mic((0.002 * np.random.default_rng(2).standard_normal(SR)).astype(np.float32)):
        vad(f)                                                         # warm it up on 1 s of background noise
async def barge_in_demo(user_starts_s=1.0, need_frames=5):
    fresh_warm_vad()
    stop = asyncio.Event(); log = {}
    async def playback(n_chunks=150):                                  # 3 s of reply audio
        for i in range(n_chunks):
            if stop.is_set():
                log["stopped_at"] = time.perf_counter(); return
            await asyncio.sleep(0.02)                                  # the sound card consumes one 20 ms chunk
        log["finished"] = True
    async def microphone():
        frames = mic(np.concatenate([0.002 * np.random.default_rng(1).standard_normal(int(user_starts_s * SR)), speak("Wait, stop.", "bdl")]).astype(np.float32))
        run = 0
        for i, f in enumerate(frames):
            await asyncio.sleep(0.02)                                  # frames arrive in real time
            if i * 0.02 >= user_starts_s and "speech_onset" not in log:
                log["speech_onset"] = time.perf_counter()
            run = run + 1 if vad(f) else 0
            if run >= need_frames:                                     # require 100 ms of speech: no stopping on a cough
                log["detected"] = time.perf_counter(); stop.set(); return
    await asyncio.gather(playback(), microphone())
    return log

for need in [1, 5, 15]:
    log = asyncio.run(barge_in_demo(need_frames=need))
    if "speech_onset" not in log:
        print(f"stop after {need:2d} speech frames: stopped BEFORE the user spoke (a false barge-in on noise)")
    else:
        print(f"stop after {need:2d} speech frames: assistant stopped "
              f"{(log['stopped_at'] - log['speech_onset']) * 1000:4.0f} ms after the user started talking")

Reading this output

With a 1-frame rule the assistant stops 41 ms after the user starts, with 5 frames 122 ms, with 15 frames 324 ms: each extra frame costs about 20 ms. The 1-frame rule is fastest and also the one that stops for every cough, door or background voice; 5 frames (100 ms) is a common compromise. While building this demo, reusing one VAD across runs produced false barge-ins: after hearing speech, the VAD's adapted state flagged the next run's background noise as speech. Reset or re-warm adaptive components at session boundaries.

Break it on purpose

Make the end-of-turn silence shorter: call capture_turn_min(..., silence_ms=100) on the timer request, then silence_ms=20 (a single silent frame). What does Whisper hear each time, and why would a real user notice long before 20 ms? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Frameworks, not hand-wired loops. LiveKit Agents and Pipecat provide the turn state machine, interruption handling, tool calling and streaming plumbing; teams plug in their choice of STT, LLM and TTS.
  • Turn detection models. Both frameworks offer small models that judge from the words (and in some cases the audio) whether the user has finished, so the assistant can reply after a short pause when a sentence is complete and wait longer when it is not.
  • Speech-to-speech as an alternative. OpenAI's Realtime API and Gemini's Live API replace STT + LLM + TTS with one streaming model; the cascade remains common because each part can be chosen, tested and logged on its own (Lesson 6.15).

Sources: LiveKit Agents, Pipecat, OpenAI Realtime API, Qwen2.5 function calling, WebRTC VAD (py-webrtcvad).

Pitfalls

  • Logging PII forever. Full-turn audio is personal data in most jurisdictions. Set a short retention period, encrypt at rest, and get consent where the law requires it.
  • No barge-in. Users will interrupt. Your assistant must stop talking.
  • TTS that blocks. Synchronous TTS blocks the event loop. Use async or a separate thread.
  • No tool-call error handling. Tools fail. LLM must get back the error + retry once, then gracefully degrade.
  • Overzealous hallucination filters. Over-filter and the assistant repeats "I can't help with that." Under-filter and it says anything. Calibrate on a held-out set.
  • No wake-word option. Always-listening is a privacy liability. Add a wake-word gate (Porcupine or openWakeWord).
Recap
What to keep from this lesson
  • Pipeline: capture → VAD/turn detection → STT → LLM with tools → TTS → playback, with barge-in cancelling the tail.
  • Start a turn only after a minimum run of speech, keep a pre-roll, and warm up or reset adaptive VADs.
  • Normalise LLM text for speech before TTS; start speaking at the first sentence.
  • Measure every stage per turn; on a CPU the LLM and TTS dominate, and the end-of-turn wait is a budget item you choose.
  • Barge-in delay is frames-to-confirm × 20 ms plus cancellation; trade it against false stops.

Solutions

SolutionP1 · The first one, before any model runs

The timer request fails at turn capture: a fresh VAD fires on the first frames of room noise, the capture function treats that as a turn, and after 500 ms of "silence" it hands 0.6 s of noise to Whisper ("So"). Most people expect the 0.5B LLM to be the weak link; it handled both tool calls correctly. The weather reply has a smaller failure at the very end (TTS reading "14°C").

SolutionB1 · Cut off mid-sentence

At 100 ms the whole sentence is still captured (1.74 s, "Set a timer for five minutes."): synthetic speech has no hesitations. At 20 ms, one silent frame ends the turn and Whisper hears "set a timer for"; the assistant would ask for a duration, or guess. Real people pause mid-sentence to think, much longer than 100 ms, so production systems wait several hundred milliseconds or use a turn-detection model that recognises an unfinished sentence.
