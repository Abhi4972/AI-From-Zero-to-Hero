In plain words first
The idea in one line

A loop that does not measure is a loop that lies. This lesson builds the training loop that drives the GPT model: AdamW with weight decay split, a warmup plus cosine learning rate schedule, a calc_loss_batch helper, an evaluate_model pass on held out data, a generate_and_print_sample qualitative probe every K steps, and a JSONL log of losses you can plot after. The same skeleton trains every decoder LLM you will ever build.

Terms you'll hear
Term What people say What it actually means
Loss alignment "Shift by one" Input tokens at positions 0..T-1, target tokens at positions 1..T; cross entropy is computed on flattened shapes
Decay split "Two groups" AdamW receives matrix shaped tensors with weight decay and scale or bias tensors with none
Warmup "Ramp" The learning rate climbs from zero to its target over a fixed number of steps so the optimizer state can populate
Eval batches "Held out batches" A fixed slice of the validation token tensor, sliced once at script start, used identically every probe
Qualitative probe "Sample print" A short generation from a fixed prompt printed every K steps to catch failure modes loss alone hides

The problem

A training script that prints the loss but does nothing else fails three ways. It cannot tell you if the loss is decreasing for the right reason (the model could overfit the training set and never learn). It cannot tell you if a divergence is starting (the loss can spike for one step and recover, or one step and crash). It cannot tell you what the model has learned (loss is a scalar; a generated sample is a paragraph). All three failures hide unless the loop measures.

The loop in this lesson measures three ways. Loss on the training batch every step. Loss on a held out batch every K steps. A generated continuation from a fixed prompt every K steps. The training log lands in JSONL so the artifact is the loop's testimony.

The idea

The two non-obvious pieces are the loss alignment and the AdamW decay split.

Idea 1 · Loss alignment

The model predicts the next token at every position. If the input batch is tokens [t0, t1, t2, t3], the target batch must be [t1, t2, t3, t4]. Cross entropy is computed on the flat shape (batch * seq, vocab) against the flat target (batch * seq,). Forget the shift and you train the model to predict itself, which converges to zero loss while learning nothing useful.

Idea 2 · AdamW decay split

Weight decay regularizes weight tensors but not normalization scales or biases. Putting decay on the LayerNorm scale slowly drives the scale to zero and breaks normalization. Putting decay on a bias is mathematically harmless but a waste of cycles. The standard split is: matrix shaped tensors (linear weights, embedding tables) get decay, anything that looks like a scale or shift does not.

Idea 3 · Warmup plus cosine schedule

Warmup ramps the learning rate from zero to the target over a few hundred steps so the optimizer state has time to populate. Cosine decay drops the learning rate back toward zero over the remaining steps so the final phase fine tunes the weights at a small step size. The combination is the most common schedule in open weights LLM training because it removes most of the brittle moments in the first thousand steps and the last thousand steps.

Idea 4 · Held out evaluation

evaluate_model runs a fixed number of batches from the validation split, accumulates loss, divides by the batch count, and returns. No gradient. No dropout. The number is reproducible across runs given the same seed and the same split. Reporting the held out loss next to the training loss is how you spot overfitting.

Idea 5 · Qualitative sampling as an early signal

A model whose training loss drops nicely but whose generated samples are all the same token is broken. A model whose loss curve looks flat but whose generated samples sharpen into coherent words is learning. The qualitative probe runs faster than reading the full curve and catches modes the scalar misses.

Build it

code/main.py implements:

  • make_batches(token_ids, batch_size, context_length) which slices a long token tensor into input and target pairs.
  • calc_loss_batch(model, inputs, targets) which forwards, flattens, and returns the scalar cross entropy.
  • evaluate_model(model, val_loader, max_batches) which iterates a fixed number of validation batches with no grad and returns the mean loss.
  • generate_and_print_sample(model, prompt, max_new_tokens) which runs the lesson 35 generation function on a fixed prompt and prints the result.
  • build_param_groups(model, weight_decay) which produces the two-group AdamW parameter list.
  • cosine_with_warmup(step, warmup_steps, total_steps, max_lr, min_lr) which returns the LR at a given step.
  • train(...) which runs the loop, persists outputs/losses.jsonl, and prints the eval loss and a sample every eval_every steps.
  • A demo that trains a tiny model on synthetic data for a small number of steps, writes a JSONL log, and prints the eval loss and a sample at the probe points. The demo runs in well under a minute on CPU.

Run it:

python3 code/main.py

Output: per step loss line, eval loss every probe step, a generated sample every probe step, and a final outputs/losses.jsonl you can load with json.loads per line.

Production patterns in the wild

Three patterns turn the textbook loop into something you can leave running overnight.

Gradient norm clipping is non negotiable. A bad batch (anomalous data, an LR spike, a numerical edge case) produces a huge gradient that wipes out hours of training. torch.nn.utils.clip_grad_norm_(params, max_norm=1.0) after backward and before step keeps the optimizer in a safe range. The clipping value is a free parameter; one is the default that survives most setups.

Resumable JSONL logging, not pickled state. Per step loss records as {"step": int, "train_loss": float, "lr": float} lines in JSONL are durable: any crash leaves a readable artifact, you can grep, you can plot with thirty lines of Python, and you can resume training by reading the last step. Pickled state ties you to the exact module layout that produced the file, which is brittle across refactors.

Eval batches drawn from a fixed slice. The validation tokens get sliced into batches at script start, not on the fly. Reproducibility depends on the eval batches being identical from run to run; otherwise comparing eval loss between two runs measures the batch shuffle as much as the model.

Use it: the same idea with real libraries

  • The loop in this lesson is the same skeleton that trains a 124M model on real data. Swap the synthetic token tensor for a datasets-style loader and the loop runs unchanged.
  • The JSONL log is the deliverable that turns a training run into evidence. The next lesson uses one to compare a freshly trained checkpoint with a pretrained one.
  • The qualitative sample probe is the catch-all that scalar loss cannot replace.

Questions from real AI engineering interviews that this lesson prepares you for. Answer out loud first, then open the worked answer.

Read the codeA hand-written optimizer step is labeled AdamW. Review it: python def adam_step(params, grad, m, v, t, lr, beta1, beta2, eps, weight_decay): grad = grad + weight_decay * params m = beta1 * m + (1 - beta1) * grad v = beta2 * v + (1 - beta2) * grad * grad m_hat = m / (1 - beta1 ** t) v_hat = v / (1 - beta2 ** t) return params - lr * m_hat / (np.sqrt(v_hat) + eps), m, v Is this AdamW? What changes, and why does it matter for a language model?

Level 2 of 4 · about 10 minutes to answer well.

Short answer. No, this is Adam with an L2 penalty folded into the gradient. AdamW applies the decay directly to the parameters, scaled by the learning rate, outside the adaptive step. When the penalty goes through the gradient it is divided by the second-moment estimate, so parameters with large gradients get almost no decay and the regularization becomes uneven across the model.

The corrected step.

def adam_step(params, grad, m, v, t, lr, beta1, beta2, eps, weight_decay):
    m = beta1 * m + (1 - beta1) * grad
    v = beta2 * v + (1 - beta2) * grad * grad
    m_hat = m / (1 - beta1 ** t)
    v_hat = v / (1 - beta2 ** t)
    new = params - lr * (m_hat / (np.sqrt(v_hat) + eps) + weight_decay * params)
    return new, m, v

The decay term is added to the update, not to the gradient. It never passes through the moment estimates.

What the difference changes.

Adam normalizes every coordinate by its running gradient magnitude. A penalty that enters as part of the gradient is normalized too, so a weight with a large, noisy gradient is barely decayed while a weight with a tiny gradient is decayed hard. Decoupled decay shrinks every weight by the same fraction per step, which is what the regularizer was meant to do. Language model recipes use the decoupled form, and the loop in the training lesson builds its parameter groups around it.

Three more details the practice pins.

  • The step counter starts at one. With t = 0 the bias correction divides by zero, and with t + 1 the first step acts as the second.
  • Epsilon sits outside the square root. Inside it, tiny gradients give a much smaller step than intended.
  • The function returns new state arrays. Updating m and v in place changes the caller's state and breaks checkpoint resume.

Where the decay should not go.

Even with the correct form, the decay belongs on matrix-shaped weights only. Normalization scales and biases get no decay, which is the subject of the parameter group split.

Plausible wrong answers.

  • "L2 and weight decay are the same thing." They coincide for plain gradient descent, not for an adaptive optimizer that normalizes the gradient.
  • "Put epsilon inside the square root for stability." It changes the step size for small gradients; the reference form adds it after the root.
  • "Start the step counter at zero like an index." The bias correction then divides by zero on the first step.

Follow-ups an interviewer may ask.

  • (level 2) What does the bias correction fix in the first steps? Expected: the moment estimates start at zero and are biased low early; dividing by 1 - beta**t rescales them.
  • (level 2) Why return new arrays instead of updating in place? Expected: a pure function keeps the caller's state intact, so a step can be retried or compared and a checkpoint stays consistent.
  • (level 3) How does the learning rate schedule interact with decoupled decay? Expected: the decay is multiplied by the current learning rate, so warmup and cosine decay also scale the regularization over training.

Where it is taught. The training loop lesson configures AdamW with its decay split, the cosine schedule lesson pairs it with warmup and decay, and the Adam practice checks the decoupled form.

Take-homeWrite a training loop for a table of next-character logits: one row per context character, one column per next character. Train it with gradient descent on a text, under a fixed step budget and a seeded generator, until its held-out NLL is lower than a model that ignores the context. Tell me what the held-out check must look like for the comparison to mean anything.

Level 3 of 4 · about 30 minutes to answer well.

Short answer. Build the pairs so that the current character is the context and the following character is the target, compute the log-softmax over each row, and descend the mean of the negative target log-probabilities over the training pairs within the step budget. The held-out check scores a fixed split that training never saw, with the same loss definition for the bigram and the unigram baseline, and the model only passes when its held-out value is lower than the baseline's. Reproducibility comes from drawing the initial table from the generator that the caller passes, not from a global one.

The model and the loop.

def train(text, rng, steps, lr):
    pairs = [(ord(a), ord(b)) for a, b in zip(text, text[1:])]
    W = rng.normal(0, 1, (V, V))
    for _ in range(steps):
        logits = W[[a for a, _ in pairs]]
        logp = log_softmax(logits)
        grad = softmax(logits)
        grad[np.arange(len(pairs)), [b for _, b in pairs]] -= 1
        gW = np.zeros_like(W)
        np.add.at(gW, [a for a, _ in pairs], grad / len(pairs))
        W = W - lr * gW
    return W


def next_log_probs(W, context):
    return log_softmax(W[context])

The pair direction is the whole model: context first, target second. Reversing them trains a model that predicts the previous character, and counting each next character as its own context trains nothing about what follows what.

The gradient sign.

The update subtracts the gradient. Adding it climbs the loss, which is visible on the first evaluation, and is the first mutant the practice checks.

The held-out check.

The loop lesson's rule is that evaluation runs on a fixed held-out slice with no gradient, and the number must be comparable across runs. For this task that means three things. The split is fixed before training and never touched by the loop. The unigram baseline, which assigns each character its frequency in the training text regardless of context, is scored on the same held-out characters with the same loss definition. The bigram passes only when its held-out value is strictly lower. A model that wins on the training text and not on the held-out text has memorized the training text.

The budget.

A step budget is part of the contract. A loop that runs more steps than the budget may reach the target but fails the task, and in a real run it is the difference between a planned job and an overrun.

Plausible wrong answers.

  • "Evaluate on the training text to save time." The comparison then measures memorization and the baseline comparison means nothing.
  • "Draw the initial table from the global random state." Two runs with one seed then differ, and the test for reproducibility fails.
  • "Train until the loss stops improving." The budget is part of the contract and an open-ended loop hides a slow or stuck run.

Follow-ups an interviewer may ask.

  • (level 3) Why return log-probabilities and not raw logits from the scoring function? Expected: the loss needs a normalized distribution per row; raw logits are not comparable across contexts.
  • (level 3) The model beats the baseline on training text and loses on held-out text. What happened? Expected: it memorized the training pairs; a held-out split exists to catch exactly that.
  • (level 4) How does this toy loop map onto the full training loop in the lesson? Expected: the pair construction is the shift-by-one, the row lookup is the forward, the held-out check is the fixed evaluation, and the budget is the step count of the schedule.

Where it is taught. The training loop lesson sets the rules for held-out evaluation and loss alignment, and the character bigram practice trains the smallest model under a step budget.

Read the codeA training run looks healthy for the first few thousand steps, then the loss starts to climb and samples degrade. The optimizer is built with one parameter group: python optimizer = AdamW(model.parameters(), lr=lr, weight_decay=weight_decay) Write the function that builds the parameter groups correctly and explain which tensors must be excluded from decay and why.

Level 3 of 4 · about 10 minutes to answer well.

Short answer. Decay belongs on matrix-shaped tensors, which are the linear weights and the embedding tables, and not on normalization scales or biases. A decayed LayerNorm scale drifts toward zero over thousands of steps until normalization stops working, which matches the late failure. Split the parameters by shape into a decay group and a no-decay group and pass both to the optimizer.

The split.

def build_param_groups(model, weight_decay):
    decay, no_decay = [], []
    for name, p in model.named_parameters():
        if not p.requires_grad:
            continue
        (decay if p.dim() >= 2 else no_decay).append(p)
    return [
        {"params": decay, "weight_decay": weight_decay},
        {"params": no_decay, "weight_decay": 0},
    ]

A two-dimensional or larger tensor is a weight matrix or an embedding table. A one-dimensional tensor is a scale or a shift, which includes LayerNorm parameters and every bias. The rule by dimension is simple and matches the standard recipe.

Why decay on a scale is harmful.

Weight decay pulls every decayed parameter toward zero on every step. A linear weight has gradient pressure in many directions and the pull acts as regularization. A LayerNorm scale has one job, to set the magnitude of the normalized activations, and a steady pull toward zero shrinks the residual stream of every block until the signal is too small for the layers that follow. The effect accumulates slowly, which is why the run looks fine at first.

Why decay on a bias is waste.

Decaying a bias is mathematically harmless but spends update cycles on a parameter that regularization does not need to control. The split excludes it along with the scales.

How to test the split.

A unit test can walk the named parameters and assert that each scale and bias landed in the no-decay group and each linear and embedding weight landed in the decay group. The loop lesson lists exactly this test as its first exercise.

Plausible wrong answers.

  • "Weight decay applies to all weights by definition." The standard recipe excludes normalization and bias tensors; applying it everywhere breaks normalization over time.
  • "Decide by parameter name, excluding anything called bias." Names vary across implementations; the dimension rule is robust.
  • "Lower the weight decay until the run is stable." A smaller value slows the drift but keeps the pull on the scales.

Follow-ups an interviewer may ask.

  • (level 3) The language model head is tied to the token embedding. Which group is it in, and how many times? Expected: once, in the decay group, because it is the same tensor as the embedding table.
  • (level 3) A model uses RMSNorm instead of LayerNorm. Does the rule change? Expected: no; the RMSNorm weight is one-dimensional and stays out of the decay group.
  • (level 4) Why does the problem appear late rather than at the start of training? Expected: the decay shrinks the scale by a small fraction per step, so the damage compounds over thousands of steps before the activations become too small.

Where it is taught. The training loop lesson defines the two-group AdamW split and the test for it, and the Adam practice implements the decoupled decay the groups feed into.

Read the codeTwo evaluation runs on the same checkpoint and the same fixed validation batches report different losses. The dropout layer is: python def dropout_forward(x, p, rng, training): mask = rng.random(x.shape) >= p if training: return x * mask / (1 - p), mask return x * (1 - p), mask Find every problem with the inference path and explain what the evaluation function expects.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. Inverted dropout scales the kept units during training so that inference is the identity, but this inference path multiplies the input by one minus p, which belongs to the non-inverted form and shrinks every activation. It also draws from the generator in inference mode, which changes every later random number in the run, such as the next training mask and the next probe sample. Inference must return the input unchanged and must not touch the generator.

The two bugs.

  1. Scaling at inference. With inverted dropout the division by one minus p happens in training, so the expected activation already matches the no-dropout value. Scaling again at inference halves the signal at a rate of one half and damages every layer that follows.
  2. Drawing at inference. The mask is sampled before the branch. Evaluation consumes random numbers, so the generation sample after the probe, and any later training step, sees a different stream than a run without the probe.

The fix.

def dropout_forward(x, p, rng, training):
    if not training:
        return x.copy(), np.ones(x.shape, dtype=bool)
    mask = rng.random(x.shape) >= p
    return x * mask / (1 - p), mask

At inference the layer returns a copy of the input and a mask that is true everywhere, and it does not draw. Keep an entry when the random number is at or above p, so the complement rule is right, and divide the kept entries by one minus p. The backward pass multiplies the incoming gradient by the same mask and divides by the same factor.

What evaluation expects.

The training loop's evaluation function runs a fixed number of validation batches with no gradient and no dropout, and the number must be reproducible across runs given the same seed and split. Any randomness inside the model during that pass breaks the comparison between two runs, because the difference measures the random stream rather than the model. The assembly lesson's model has an embedding dropout of 0.1, so this layer sits in the path of every evaluation.

Plausible wrong answers.

  • "Scale down at inference as the original dropout paper did." That form skips the scaling in training; mixing the two forms shrinks the activations.
  • "Re-seed the generator before every evaluation." It hides the extra draws but still changes the training stream afterwards; the inference path should not draw at all.
  • "Keep an entry when the random number is below p." That keeps a fraction p and drops the rest, the complement of the intended mask.

Follow-ups an interviewer may ask.

  • (level 2) Why divide by one minus p during training at all? Expected: so the expected value of each activation is the same with and without the mask, which makes inference the identity.
  • (level 2) Why must the backward pass use the same mask? Expected: the gradient must flow only through the units that were kept, with the same scale, otherwise the gradient does not match the forward computation.
  • (level 3) The evaluation is reproducible but still differs from a run that skipped the probe. What else draws? Expected: the sampled generation at the probe step consumes draws from the shared generator; give the probe its own generator.

Where it is taught. The training loop lesson requires that evaluation skip gradients and dropout, the GPT assembly lesson places the embedding dropout, and the inverted dropout practice checks the identity at inference.

Read the codeA colleague reports that their language model reaches a loss near zero very early in training, and the generated samples are garbage. The batch code is: python def calc_loss_batch(model, tokens): logits = model(tokens) return cross_entropy(logits.reshape(-1, logits.shape[-1]), tokens.reshape(-1)) What went wrong, and what does the correct version look like?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. The targets are the inputs, so the model learns to predict the token it was just given, which is trivial and converges to zero loss while learning nothing. The target at position t must be the input at position t + 1. Slice the inputs to drop the last token and the targets to drop the first, then flatten both to batch times time by vocabulary and batch times time.

The alignment.

For input tokens t0, t1, t2, t3 the targets are t1, t2, t3, t4. Every position predicts the next token, which is why one training example covers the context length plus one raw id. The batch maker produces the two tensors already shifted, or the loss function shifts them:

def calc_loss_batch(model, inputs, targets):
    logits = model(inputs)
    V = logits.shape[-1]
    return cross_entropy(logits.reshape(-1, V), targets.reshape(-1))

with inputs = window[:-1] and targets = window[1:].

Why the flatten.

Cross-entropy takes a matrix of rows by classes and a vector of class ids. Flattening batch and time into one axis turns the three-dimensional logits into that matrix and the two-dimensional targets into that vector, and the mean over rows is the mean over every predicted position. Flattening is not the bug; the missing shift is.

Why the symptom is a near-zero loss.

Predicting the current token from the current token needs only an identity through the embedding and the output head, which a tied head gives for free. The loss collapses, the eval loss collapses too, and only the qualitative sample shows that nothing was learned. That is why the training loop prints a generated continuation at every probe step and not only the two losses.

The numeric side.

The practice task also checks that the cross-entropy is computed from a shifted softmax, so that large logits do not overflow, and that the loss is the mean over examples rather than the sum.

Plausible wrong answers.

  • "The learning rate is too high." A high learning rate diverges or oscillates; a collapse to zero loss points at a leak in the objective.
  • "Flattening mixes the batch and time axes." The flatten is required; the rows are independent predictions and their order does not matter to the mean.
  • "The model overfits the training set." Overfitting shows a gap between training and validation loss; here both collapse.

Follow-ups an interviewer may ask.

  • (level 2) Which signal in the training loop catches this bug first? Expected: the generated sample at the probe step; both losses look excellent.
  • (level 2) The validation loss is also near zero. Why does held-out data not catch it? Expected: the target leak is in the loss definition, which is the same on both splits.
  • (level 3) How does the sliding-window dataset avoid this at the source? Expected: it returns a window of context length plus one and splits it into input and target in the dataset itself, so the loop never sees unshifted pairs.
  • (level 3) Your supervised fine-tuning data masks the instruction tokens. Where does the mask go relative to the shift? Expected: after the shift, so the ignored positions line up with the shifted targets.

Where it is taught. The training loop lesson explains the loss alignment and the qualitative probe, and the softmax and cross-entropy practice checks the batched loss.
