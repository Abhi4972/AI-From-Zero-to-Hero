Why this came about

Debugging AI systems required seeing every model call and tool step, which logs did not show. LLM observability tools (2023 onward) adapted distributed tracing, and OpenTelemetry added conventions for generative AI.

In plain words first
A flight recorder for every run

You cannot fix what you cannot see. Observability for agents means recording each run as a trace: every model call with its inputs, outputs, tokens and timing, every tool call and its result, linked to the user, prompt version and model. Metrics and alerts are built on top: error rates, latency, cost, tool failures, loops. Sensitive data must be kept out of traces or masked.

Logs, traces, metrics, and what is different for agents

Signal Answers Agent-specific content
Traces What happened in this run, step by step, and how long each step took? Model calls, tool calls, retrieval, guardrail decisions, handoffs, approvals
Metrics How is the system doing overall? Tokens and cost per run, tool error rate, steps per run, escalation rate, judge scores
Logs What exactly was said and decided? Prompts and responses (redacted), tool arguments and results, policy blocks
Feedback and evals Was the outcome good? Thumbs, corrections, resolution outcome, online judge scores

For agents, the trace is the primary unit: almost every question ("why did it refund that order?", "why was this run slow?", "why did cost spike?") starts from one.

Step 1 · Instrument with OpenTelemetry

Framework integrations (Lesson 14.118's tracing, Strands, ADK, MAF, LangSmith, MLflow autolog) produce spans for you. Underneath, the vendor-neutral standard is OpenTelemetry. Here is the shape of a well-instrumented agent, written by hand so you see every attribute:

import json
from mockllm import start
from openai import OpenAI
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor
from opentelemetry.sdk.trace.export.in_memory_span_exporter import InMemorySpanExporter
from opentelemetry.sdk.resources import Resource

exporter = InMemorySpanExporter()                          # in production: an OTLP exporter to your collector
provider = TracerProvider(resource=Resource.create({"service.name": "shopkart-support", "deployment.environment": "dev"}))
provider.add_span_processor(SimpleSpanProcessor(exporter))
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("shopkart.agent")

client = OpenAI(base_url=start(), api_key="mock")
ORDERS = {"A-1001": "shipped"}
TOOLS = [{"type": "function", "function": {"name": "get_order_status", "description": "Order status",
          "parameters": {"type": "object", "properties": {"order_id": {"type": "string"}}, "required": ["order_id"]}}}]

def chat(messages):
    with tracer.start_as_current_span("chat mock-model") as span:          # GenAI convention: "{operation} {model}"
        span.set_attribute("gen_ai.operation.name", "chat")
        span.set_attribute("gen_ai.provider.name", "openai")
        span.set_attribute("gen_ai.request.model", "mock-model")
        r = client.chat.completions.create(model="mock-model", messages=messages, tools=TOOLS)
        span.set_attribute("gen_ai.response.finish_reasons", [r.choices[0].finish_reason])
        span.set_attribute("gen_ai.usage.input_tokens", r.usage.prompt_tokens)
        span.set_attribute("gen_ai.usage.output_tokens", r.usage.completion_tokens)
        return r.choices[0].message

def run_tool(name, args):
    with tracer.start_as_current_span(f"execute_tool {name}") as span:
        span.set_attribute("gen_ai.operation.name", "execute_tool")
        span.set_attribute("gen_ai.tool.name", name)
        return f"{args['order_id']} is {ORDERS.get(args['order_id'], 'not found')}"

def invoke_agent(question: str, user_id: str) -> str:
    with tracer.start_as_current_span("invoke_agent shopkart-support") as span:
        span.set_attribute("gen_ai.operation.name", "invoke_agent")
        span.set_attribute("gen_ai.agent.name", "shopkart-support")
        span.set_attribute("enduser.id", user_id)                          # a pseudonymous ID, not an email
        messages = [{"role": "user", "content": question}]
        for _ in range(5):
            msg = chat(messages)
            if not msg.tool_calls:
                return msg.content
            messages.append(msg.model_dump(exclude_none=True))
            for call in msg.tool_calls:
                result = run_tool(call.function.name, json.loads(call.function.arguments))
                messages.append({"role": "tool", "tool_call_id": call.id, "content": result})

print(invoke_agent("Where is A-1001?", user_id="u-8f3a"))
spans = exporter.get_finished_spans()
root = next(s for s in spans if s.parent is None)
for s in sorted(spans, key=lambda s: s.start_time):
    depth = 0 if s.parent is None else 1
    tokens = s.attributes.get("gen_ai.usage.input_tokens")
    print("  " * depth + f"{s.name:32}" + (f"  in={tokens}" if tokens else ""))
print("same trace:", all(s.context.trace_id == root.context.trace_id for s in spans))
What you should see
Here is what I found: A-1001 is shipped
invoke_agent shopkart-support
  chat mock-model                   in=50
  execute_tool get_order_status
  chat mock-model                   in=50
same trace: True

One trace, one root span per agent run, a child per model call and tool call, token counts on each model span. Replace InMemorySpanExporter with an OTLP exporter and the same spans appear in any backend. Prompt and response text are left out on purpose: the conventions make content capture opt-in.

Step 2 · What to log, and what not to

Decision Recommendation
Content capture Capture prompts and responses where you need them for debugging and evals, with PII redaction before storage (Lesson 15.23), restricted access and an audit trail
Identifiers Pseudonymous user and tenant IDs on every span; never emails, phone numbers or names as attributes
Sampling Keep 100% of errors, blocked requests, negative feedback and slow or expensive runs; sample the rest (for example 10%)
Retention Short for full content (for example 30 days), longer for metrics and redacted metadata; align with privacy law and contracts
Correlation Put the trace ID in every log line and in your support tickets, so "this customer had a bad answer" leads to one trace
Cost attribution Tag spans with team, app, feature and model, so costs roll up (Lesson 14.142)
Erasure Make traces deletable by user ID; tracing stores are personal-data stores (Lesson 15.26)

Three of those rows in code. First, content capture that is off by default and redacted when on. The environment variable is the one OpenTelemetry's GenAI instrumentations use:

import os, re

PII = [(re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+"), "<EMAIL>"), (re.compile(r"(?<!\d)[6-9]\d{9}(?!\d)"), "<PHONE>"),
       (re.compile(r"\b(?:\d[ -]?){13,16}\b"), "<CARD>")]
CAPTURE_CONTENT = os.environ.get("OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT", "false") == "true"

def redact(text: str) -> str:
    for pattern, label in PII:
        text = pattern.sub(label, text)
    return text

def record_messages(span, messages: list[dict]) -> None:
    """Content goes on spans only when capture is switched on, and only after redaction."""
    if not CAPTURE_CONTENT:
        span.set_attribute("app.input.message_count", len(messages))
        return
    safe = [{"role": m["role"], "content": redact(m["content"])} for m in messages]
    span.set_attribute("gen_ai.input.messages", json.dumps(safe))

msgs = [{"role": "user", "content": "Cancel A-1002, I'm ravi@gmail.com, card 4111 1111 1111 1111, call 9876543210"}]
for capture in (False, True):
    CAPTURE_CONTENT = capture
    with tracer.start_as_current_span("chat mock-model") as span:
        record_messages(span, msgs)
    attrs = dict(exporter.get_finished_spans()[-1].attributes)
    print(f"capture={capture}:", attrs)
What you should see
capture=False: {'app.input.message_count': 1}
capture=True: {'gen_ai.input.messages': '[{"role": "user", "content": "Cancel A-1002, I\'m <EMAIL>, card <CARD>, call <PHONE>"}]'}

Redact before the attribute is set, not in the backend: once raw text leaves the process it is in your collector, your vendor and their backups. Regexes catch the obvious formats; for names and addresses, run a recognizer such as Presidio (Lesson 15.23) in the collector or the instrumentation.

Second, tail-based sampling: decide whether to keep a trace after it finishes, when you know whether it was interesting. (Head-based sampling decides at the start, so it drops errors as readily as successes.)

import random
from dataclasses import dataclass

@dataclass
class FinishedRun:
    trace_id: int
    error: bool
    feedback: int | None          # 1 thumbs up, 0 thumbs down, None no feedback
    blocked: bool                 # a guardrail fired
    cost_usd: float
    latency_s: float

def keep(run: FinishedRun, base_rate: float = 0.10) -> tuple[bool, str]:
    """Tail-based sampling: decide after the run, when you know whether it was interesting."""
    if run.error:            return True, "error"
    if run.blocked:          return True, "guardrail"
    if run.feedback == 0:    return True, "negative feedback"
    if run.cost_usd > 0.50:  return True, "expensive"
    if run.latency_s > 20:   return True, "slow"
    sampled = (run.trace_id % 10_000) / 10_000 < base_rate          # deterministic per trace ID
    return sampled, "sampled" if sampled else "dropped"

random.seed(3)
runs = [FinishedRun(trace_id=random.getrandbits(64), error=random.random() < 0.02, feedback=random.choice([1, 1, 1, 0, None, None]),
                    blocked=random.random() < 0.01, cost_usd=random.lognormvariate(-3.5, 0.8),
                    latency_s=random.lognormvariate(1.5, 0.5)) for _ in range(10_000)]
reasons = {}
for r in runs:
    kept, why = keep(r)
    reasons[why] = reasons.get(why, 0) + 1
kept_total = sum(v for k, v in reasons.items() if k != "dropped")
print({k: reasons[k] for k in sorted(reasons)})
print(f"kept {kept_total} of {len(runs)} traces ({kept_total / len(runs):.0%})")
What you should see
{'dropped': 7245, 'error': 212, 'expensive': 1, 'guardrail': 93, 'negative feedback': 1616, 'sampled': 821, 'slow': 12}
kept 2755 of 10000 traces (28%)

Every error, block, complaint and outlier was kept, plus a 10% random sample of the ordinary runs for baselines. The OpenTelemetry Collector's tail_sampling processor implements the same rules as configuration; most LLM observability vendors offer equivalent filters at ingestion.

Third, correlation: put the trace ID on every log line, so a log entry, a support ticket or an alert leads to exactly one trace:

import logging, sys
from opentelemetry.trace import format_trace_id

class TraceIdFilter(logging.Filter):
    """Stamp the current trace ID on every log line, so a log leads straight to its trace."""
    def filter(self, record: logging.LogRecord) -> bool:
        ctx = trace.get_current_span().get_span_context()
        record.trace_id = format_trace_id(ctx.trace_id) if ctx.is_valid else "-"
        return True

handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(logging.Formatter("%(levelname)s trace=%(trace_id).8s… %(message)s"))
handler.addFilter(TraceIdFilter())
log = logging.getLogger("shopkart")
log.addHandler(handler); log.setLevel(logging.INFO); log.propagate = False

log.info("starting up")
with tracer.start_as_current_span("invoke_agent shopkart-support") as span:
    log.warning("tool get_order_status timed out, retrying")
    current = format_trace_id(span.get_span_context().trace_id)
print("log line carries this span's trace ID:", exporter.get_finished_spans()[-1].context.trace_id == int(current, 16))
What you should see
INFO trace=-… starting up
WARNING trace=6448d228… tool get_order_status timed out, retrying
log line carries this span's trace ID: True

Your trace ID will differ. OpenTelemetry's logging instrumentation (opentelemetry-instrumentation-logging) adds the same fields automatically and can ship the logs over OTLP next to the traces.

Step 3 · Dashboards and alerts that matter

Watch Why Alert when
Error rate (model, tool, guardrail blocks) Outages and broken tools Above the SLO for 10 minutes
p50 and p95 latency, time to first token User experience p95 above the latency budget
Steps and tool calls per run Loops, confused agents p95 doubles versus last week
Tokens and cost per run, per tenant Runaway cost, abuse Daily spend above forecast; any single run above a ceiling

Define SLOs for the agent (for example "99% of runs complete without error; 95% under 15 seconds"), and treat quality like availability: a release that drops the online judge score is an incident.

The numbers on those dashboards come from the traces. Here they are computed from the 10,000 runs above, followed by the alerting method most SRE teams now use, error-budget burn rate: alert when the rate of failures would exhaust the month's allowance much too fast, checked over a long and a short window together so one bad minute does not page anyone:

import statistics

def percentile(values: list[float], p: float) -> float:
    s = sorted(values)
    return s[min(len(s) - 1, int(p / 100 * len(s)))]

steps = [3 if r.latency_s < 6 else 7 for r in runs]                     # stand-in: slow runs take more steps
print(f"latency p50 {percentile([r.latency_s for r in runs], 50):.1f} s, p95 {percentile([r.latency_s for r in runs], 95):.1f} s")
print(f"cost per run mean ${statistics.mean(r.cost_usd for r in runs):.3f}, p95 ${percentile([r.cost_usd for r in runs], 95):.3f}")
print(f"steps per run p95 {percentile(steps, 95)}, error rate {sum(r.error for r in runs) / len(runs):.2%}")

# Error-budget burn rate: how fast are we spending the SLO's allowed failures?
SLO = 0.99                                            # 99% of runs succeed over 30 days
def burn_rate(errors: int, total: int) -> float:
    return (errors / total) / (1 - SLO)               # 1.0 = spending the budget exactly on schedule

windows = {"last 1 h": (230, 1_200), "last 6 h": (520, 7_000), "last 3 d": (900, 80_000)}
for name, (errors, total) in windows.items():
    print(f"{name:9} burn rate {burn_rate(errors, total):4.1f}")
fast = burn_rate(*windows["last 1 h"]) > 14.4 and burn_rate(*windows["last 6 h"]) > 6
print("page the on-call:", fast)
What you should see
latency p50 4.5 s, p95 10.2 s
cost per run mean $0.041, p95 $0.109
steps per run p95 7, error rate 2.12%
last 1 h  burn rate 19.2
last 6 h  burn rate  7.4
last 3 d  burn rate  1.1
page the on-call: True

A burn rate of 19 means the last hour consumed error budget nineteen times faster than the SLO allows; sustained, the month's budget would be gone in under two days. The thresholds (14.4 over one hour, 6 over six hours) come from Google's SRE workbook. Apply the same method to quality: define an SLO on the online judge's pass rate, and burn alerts catch a bad prompt release within the hour.

Aggregates like these should be emitted as metrics rather than recomputed from traces, because metrics are cheap to store for months and are never sampled. The GenAI semantic conventions define the standard instruments:

from opentelemetry import metrics
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import InMemoryMetricReader

reader = InMemoryMetricReader()                       # in production: a periodic OTLP exporter
metrics.set_meter_provider(MeterProvider(metric_readers=[reader]))
meter = metrics.get_meter("shopkart.agent")
token_usage = meter.create_histogram("gen_ai.client.token.usage", unit="{token}",
                                     description="Tokens used per model call")
duration = meter.create_histogram("gen_ai.client.operation.duration", unit="s")

for model, tin, tout, secs in [("small-model", 900, 120, 0.8), ("small-model", 1100, 90, 0.7), ("strong-model", 6200, 400, 3.9)]:
    attrs = {"gen_ai.operation.name": "chat", "gen_ai.request.model": model, "app.team": "support"}
    token_usage.record(tin, {**attrs, "gen_ai.token.type": "input"})
    token_usage.record(tout, {**attrs, "gen_ai.token.type": "output"})
    duration.record(secs, attrs)

for metric in reader.get_metrics_data().resource_metrics[0].scope_metrics[0].metrics:
    for point in sorted(metric.data.data_points, key=lambda p: sorted(p.attributes.items())):
        a = point.attributes
        label = f"{a['gen_ai.request.model']} {a.get('gen_ai.token.type', '')}".strip()
        print(f"{metric.name:32} {label:20} count={point.count} sum={point.sum:g}")

Histograms give you counts, sums and buckets per attribute combination, which is enough for tokens per model, cost per team (multiply by price), and latency percentiles, in Prometheus, CloudWatch, Azure Monitor or any OTLP backend. Keep attribute values low-cardinality: team, model and operation, never user IDs, or the metric store will explode.

In production
Observability gaps teams discover too late
  • Traces without inputs: content capture was off, so a complaint cannot be reproduced. Capture redacted content for a sample and for every error or thumbs-down.
  • No link from feedback to trace: thumbs-down events land in a product database with no trace ID. Put the trace ID in the UI event.
  • Cost by model, not by feature: finance sees one large bill. Tag every call with team, feature and tenant at the gateway.
  • Averages on dashboards: p95 latency and cost per run hide behind means. Chart percentiles and the most expensive runs.
  • Quality not monitored at all: errors and latency look fine while answers get worse after a model update. Run online judges on sampled traffic and alert on drops (Lesson 14.143).

Exercises

Predict before you run

A trace for one conversation has spans for model calls, tool calls and retrieval. Which attribute on every span lets you find all traces for one customer complaint? (Solution P1.)

Break it on purpose

Log full prompts and responses for every call, including customer messages, forever. What problems follow? (Solution B1.)

Debugging exercise

Make it your own

Solutions

SolutionP1 · Correlation IDs

A conversation or session ID (and user ID, where permitted) propagated to every span. Without it, traces cannot be joined to complaints.

SolutionB1 · Logging and privacy

Personal data accumulates without retention limits, increasing breach impact and violating data rules. Redact, sample, and set retention.

SolutionD1 · Measure what users feel

Users feel time per turn (several calls) and time to first token, and tails, not average per call. Add per-turn and p95 or p99 metrics.

SolutionM1 · Minimum telemetry

Spans for each turn, model call, tool call and retrieval, with conversation ID, model, tokens, cost, latency, errors; metrics for p95 turn time, error rate, cost per conversation, fallback rate; alerts on SLO burn.

Explain the mechanismWhat should you observe in an LLM application?

Worked answer. Traces of each request through model, retrieval and tool calls, with tokens, cost, latency and errors; prompt and model versions; quality signals (sampled evals, feedback, handoffs); and business outcomes. Use standards such as OpenTelemetry's generative AI conventions so tools interoperate, and protect personal data.

A plausible wrong answer. "Logs are enough." Without traces, multi-step behavior is unreadable.

Follow-ups. What are OpenTelemetry's GenAI semantic conventions?

Debug a failureTraces are missing tool spans for one framework. What do you check?

Worked answer. Whether that framework's instrumentation is installed, whether context propagates across async boundaries or threads, and whether tools run in another process without trace headers.

A plausible wrong answer. "The framework does not support tracing." Usually instrumentation is missing.

Follow-ups. How would you test tracing in CI?

Defend a designA specialized LLM observability tool or your existing APM?

Worked answer. An LLM tool for prompt, eval and trace features, exported to or alongside your APM for infrastructure and alerting. OpenTelemetry keeps you portable between them.

A plausible wrong answer. "One tool for everything." Use what fits, connected by standards.
