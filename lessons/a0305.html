In plain words first
The idea in one line

Your network makes a prediction. The ground truth says otherwise. How wrong is it? That number is the loss. Pick the wrong loss function and your model optimizes for the wrong thing entirely.

Terms you'll hear
Term What people say What it actually means
Loss function "How wrong the model is" A differentiable function mapping predictions and targets to a scalar that the optimizer minimizes
MSE "Average squared error" Mean of squared differences between predictions and targets; penalizes large errors quadratically
Cross-entropy "The classification loss" Measures divergence between predicted probability distribution and true distribution using $-\log(p)$
Binary cross-entropy "BCE" Cross-entropy for two classes: $-(y \log(p) + (1-y) \log(1-p))$
Label smoothing "Softening the targets" Replacing hard 0/1 targets with soft values (e.g., 0.1/0.9) to prevent overconfidence and improve generalization
Contrastive loss "Pull together, push apart" A loss that learns representations by making similar pairs close and dissimilar pairs far in embedding space
InfoNCE "The CLIP/SimCLR loss" Normalized temperature-scaled cross-entropy over similarity scores; treats contrastive learning as classification
Focal loss "The imbalanced data fix" Cross-entropy weighted by $(1-p_t)^\gamma$ to down-weight easy examples and focus on hard ones
Triplet loss "Anchor-positive-negative" Pushes anchor closer to positive than negative by at least a margin in embedding space
Temperature "Sharpness knob" A scalar divisor on logits/similarities that controls how peaked the resulting distribution is; lower = sharper

The problem

In plain words first

The loss is the single number the optimiser makes smaller, so it defines what "better" means. For predicting numbers, mean squared error punishes big misses heavily. For predicting classes, cross-entropy scores the probability given to the right answer, and its gradient stays strong exactly when the model is confidently wrong. For learning embeddings without labels, contrastive losses pull matching pairs together and push the rest apart. Change the loss and you change what the model learns.

A classifier that predicts 0.5 for everything scores an MSE of 0.25 on balanced classes, the best that any guess blind to the input can do. That is low-looking loss from a useless model, and the warning sign this lesson starts from.

The loss function is the only thing your model actually optimizes. Not accuracy. Not F1 score. Not whatever metric you report to your manager. The optimizer takes the gradient of the loss function and adjusts weights to make that number smaller. If the loss function doesn't capture what you care about, the model will find the mathematically cheapest way to satisfy it, and that way is almost never what you wanted.

Here is a concrete example. You have a binary classification task. Two classes, 50/50 split. You use MSE as your loss. The model predicts 0.5 for every single input. The average MSE is 0.25, which is the minimum possible without actually learning anything. The model has zero discriminative ability but it has technically minimized your loss function. Switch to cross-entropy and the same model is forced to push predictions toward 0 or 1, because -log(0.5) = 0.693 is a terrible loss, while -log(0.99) = 0.01 rewards confident correct predictions. The choice of loss function is the difference between a model that learns and a model that games the metric.

It gets worse. In self-supervised learning, you don't even have labels. Contrastive loss defines the learning signal entirely: what counts as similar, what counts as different, and how hard the model should push them apart. Get contrastive loss wrong and your embeddings collapse to a single point -- every input maps to the same vector. Technically zero loss. Completely worthless.

Idea 1 · Mean Squared Error (MSE)

The default for regression. Compute the squared difference between prediction and target, average over all samples.

MSE=n1​∑(ypred​−ytrue​)2

Why squaring matters: it penalizes large errors quadratically. An error of 2 costs 4x as much as an error of 1. An error of 10 costs 100x. This makes MSE sensitive to outliers -- a single wildly wrong prediction dominates the loss.

Real numbers: if your model predicts housing prices and is off by $10,000 on most houses but off by $200,000 on one mansion, MSE will aggressively try to fix that one mansion, potentially hurting performance on the other 99 houses.

The gradient of MSE with respect to a prediction is:

∂ypred​∂MSE​=n2​(ypred​−ytrue​)

Linear in the error. Bigger errors get bigger gradients. This is a feature for regression (large errors need large corrections) and a bug for classification (you want to penalize confident wrong answers exponentially, not linearly).

Idea 2 · Cross-Entropy Loss

The loss function for classification. Rooted in information theory -- it measures the divergence between the predicted probability distribution and the true distribution.

Binary Cross-Entropy (BCE):

BCE=−(ylog(p)+(1−y)log(1−p))

Where y is the true label (0 or 1) and p is the predicted probability.

Why −log(p) works: when the true label is 1 and you predict p=0.99, the loss is −log(0.99)=0.01. When you predict p=0.01, the loss is −log(0.01)=4.6. That 460x difference is why cross-entropy works. It brutally punishes confident wrong predictions while barely penalizing confident correct ones.

The gradient tells the same story:

∂p∂BCE​=−py​+1−p1−y​

When y=1 and p is near zero, the gradient is −1/p which approaches negative infinity. The model gets an enormous signal to fix its mistake. When p is near 1, the gradient is tiny. Already correct, nothing to fix.

Categorical Cross-Entropy:

For multi-class classification with one-hot encoded targets.

CCE=−i∑​yi​log(pi​)

Only the true class contributes to the loss (because all other yi​ are zero). If there are 10 classes and the correct class gets probability 0.1 (random guessing), the loss is −log(0.1)=2.3. If the correct class gets probability 0.9, the loss is −log(0.9)=0.105. The model learns to concentrate probability mass on the right answer.

Idea 3 · Why MSE Fails for Classification

MSE gradients flatten when predictions are near 0 or 1 (due to sigmoid saturation). Cross-entropy gradients compensate for this -- the −log cancels the sigmoid's flat regions, giving strong gradients exactly where they are needed most.

Worked example
The gradient that reaches the logit

With a sigmoid output p=σ(z) and true label y=1, the gradient of each loss with respect to the logit z is:

Prediction p MSE: 2(p−y)p(1−p) Cross-entropy: p−y
0.6 (unsure, wrong side is close) −0.192 −0.40
0.01 (confidently wrong) −0.0196 −0.99

For the confidently wrong prediction, cross-entropy pushes about 50 times harder. The sigmoid's slope p(1−p) multiplies the MSE gradient and is almost zero at p=0.01; cross-entropy's 1/p cancels it exactly, leaving the clean p−y.

Check your mental model
  • ✗ "MSE makes a classifier predict 0.5 for everything."
    ✓ MSE on probabilities (the Brier score) is smallest when the model predicts the true probability for each input, just like cross-entropy. Its weakness is the gradient: it fades when the sigmoid saturates on a wrong answer. Step 6 shows MSE training fine on the circle data and then stalling from a bad start.
  • ✗ "Cross-entropy always drives predictions to exactly 0 or 1."
    ✓ Its minimum is also the true probability. It only heads for 0 and 1 when the training data can be separated perfectly, which is one reason label smoothing exists.
  • ✗ "Lower contrastive temperature is always better."
    ✓ A low temperature sharpens the softmax so much that only the hardest negatives matter, and training can become unstable; the best value depends on batch size and data.

Idea 4 · Label Smoothing

Standard one-hot labels say "this is 100% class 3 and 0% everything else." That's a strong claim. Label smoothing softens it:

smooth_label=(1−α)⋅one_hot+num_classesα​

With α=0.1 and 10 classes: instead of [0, 0, 1, 0, ...], the target becomes [0.01, 0.01, 0.91, 0.01, ...]. The model targets 0.91 instead of 1.0.

Why this works: a model trying to output exactly 1.0 through a softmax needs to push logits to infinity. This causes overconfidence, hurts generalization, and makes the model brittle to distribution shift. Label smoothing caps the target at 0.9 (with α=0.1), keeping logits in a reasonable range. Inception-v3 introduced it and the original Transformer used a smoothing of 0.1; large language models are usually pretrained without it.

Idea 5 · Contrastive Loss

No labels. No classes. Just pairs of inputs and the question: are these similar or different?

SimCLR-style contrastive loss (NT-Xent / InfoNCE):

Take one image. Create two augmented views of it (crop, rotate, color jitter). These are the "positive pair" -- they should have similar embeddings. Every other image in the batch forms a "negative pair" -- they should have different embeddings.

L=−log∑k​exp(sim(zi​,zk​)/τ)exp(sim(zi​,zj​)/τ)​

Where sim() is cosine similarity, zi​ and zj​ are the positive pair, the sum is over all negatives, and τ (temperature) controls how sharp the distribution is. Lower temperature = harder negatives = more aggressive separation.

Real numbers: batch size 256 means 255 negatives per positive pair. Temperature τ=0.07 (the value MoCo uses and CLIP starts from; SimCLR reported 0.1 as best on ImageNet and 0.5 on CIFAR-10). The loss looks like a softmax over similarities -- it wants the positive pair's similarity to be highest among all 256 options.

Triplet Loss:

Takes three inputs: anchor, positive (same class), negative (different class).

L=max(0,d(anchor,positive)−d(anchor,negative)+margin)

The margin (typically 0.2-1.0) enforces a minimum gap between positive and negative distances. If the negative is already far enough away, the loss is zero -- no gradient, no update. This makes training efficient but requires careful triplet mining (choosing hard negatives that are close to the anchor).

Worked example
InfoNCE at three temperatures

An anchor has cosine similarity 0.9 with its positive and 0.1, 0.0 and −0.2 with three negatives. Divide each by τ, apply softmax, and take −log of the positive's share:

τ Positive's share of the softmax Loss
0.07 0.99999 0.00001
0.5 0.677 0.391
1.0 0.457 0.783

At τ=0.07 this anchor is already "solved" and contributes almost nothing; the gradient goes to anchors whose negatives are still close. At τ=1 the same gaps barely register. Temperature decides how picky the loss is.

Idea 6 · Focal Loss

For imbalanced datasets. Standard cross-entropy treats all correctly classified examples equally. Focal loss down-weights easy examples:

FL=−α(1−pt​)γlog(pt​)

Where pt​ is the predicted probability of the true class and γ controls the focusing. With γ=0, this is standard cross-entropy. With γ=2 (the default):

  • Easy example (pt​=0.9): weight =(0.1)2=0.01. Effectively ignored.
  • Hard example (pt​=0.1): weight =(0.9)2=0.81. Full gradient signal.

Focal loss was introduced by Lin et al. for object detection, where 99% of candidate regions are background (easy negatives). Without focal loss, the model drowns in easy background examples and never learns to detect objects. With it, the model focuses its capacity on the hard, ambiguous cases that matter.

Idea 8 · Loss Landscape

The same idea as a formula

Regression. MSE=n1​∑(y^​i​−yi​)2 is the negative log-likelihood of Gaussian noise (up to constants); MAE=n1​∑∣y^​i​−yi​∣ corresponds to Laplace noise and is less sensitive to outliers; Huber is quadratic near 0 and linear beyond a threshold.

Classification. Cross-entropy with probabilities p=softmax(z) and true class y is −logpy​, the negative log-likelihood of a categorical distribution; for one sigmoid output it is −[ylogp+(1−y)log(1−p)]. Its gradient with respect to the logits is p−onehot(y), bounded and largest when the model is most wrong.

Label smoothing with ε and K classes trains against (1−ε)onehot(y)+ε/K: the optimum logits are then finite, which reduces over-confidence.

Focal loss down-weights easy examples: −(1−pt​)γlogpt​, with pt​ the probability of the true class; γ=2 cuts the loss of a pt​=0.9 example by a factor of 100.

Contrastive (InfoNCE). For an anchor with similarity s+​ to its positive and sj​ to all candidates,

L=−log∑j​esj​/τes+​/τ​

a cross-entropy whose "classes" are the candidates; the temperature τ sets how sharply hard negatives are penalised. CLIP and sentence-embedding models train with it.

Step 1 · MSE and Its Gradient

def mse(predictions, targets):
    n = len(predictions)
    total = 0.0
    for p, t in zip(predictions, targets):
        total += (p - t) ** 2
    return total / n

def mse_gradient(predictions, targets):
    n = len(predictions)
    grads = []
    for p, t in zip(predictions, targets):
        grads.append(2.0 * (p - t) / n)
    return grads

Step 2 · Binary Cross-Entropy

The log(0) problem is real. If the model predicts exactly 0 for a positive example, log(0)=−∞. Clipping prevents this.

import math

def binary_cross_entropy(predictions, targets, eps=1e-15):
    n = len(predictions)
    total = 0.0
    for p, t in zip(predictions, targets):
        p_clipped = max(eps, min(1 - eps, p))
        total += -(t * math.log(p_clipped) + (1 - t) * math.log(1 - p_clipped))
    return total / n

def bce_gradient(predictions, targets, eps=1e-15):
    grads = []
    for p, t in zip(predictions, targets):
        p_clipped = max(eps, min(1 - eps, p))
        grads.append(-(t / p_clipped) + (1 - t) / (1 - p_clipped))
    return grads

Step 3 · Categorical Cross-Entropy with Softmax

Softmax converts raw logits to probabilities. Then we compute the cross-entropy against one-hot targets.

def softmax(logits):
    max_val = max(logits)
    exps = [math.exp(x - max_val) for x in logits]
    total = sum(exps)
    return [e / total for e in exps]

def categorical_cross_entropy(logits, target_index, eps=1e-15):
    probs = softmax(logits)
    p = max(eps, probs[target_index])
    return -math.log(p)

def cce_gradient(logits, target_index):
    probs = softmax(logits)
    grads = list(probs)
    grads[target_index] -= 1.0
    return grads

The gradient of softmax + cross-entropy simplifies beautifully: it's just (predicted probability - 1) for the true class, and (predicted probability) for all other classes. This elegant simplification is not a coincidence -- it's why softmax and cross-entropy are paired.

Step 4 · Label Smoothing

def label_smoothed_cce(logits, target_index, num_classes, alpha=0.1, eps=1e-15):
    probs = softmax(logits)
    loss = 0.0
    for i in range(num_classes):
        if i == target_index:
            smooth_target = 1.0 - alpha + alpha / num_classes
        else:
            smooth_target = alpha / num_classes
        p = max(eps, probs[i])
        loss += -smooth_target * math.log(p)
    return loss

Step 5 · Contrastive Loss (Simplified InfoNCE)

def cosine_similarity(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = math.sqrt(sum(x * x for x in a))
    norm_b = math.sqrt(sum(x * x for x in b))
    if norm_a < 1e-10 or norm_b < 1e-10:
        return 0.0
    return dot / (norm_a * norm_b)

def contrastive_loss(anchor, positive, negatives, temperature=0.07):
    sim_pos = cosine_similarity(anchor, positive) / temperature
    sim_negs = [cosine_similarity(anchor, neg) / temperature for neg in negatives]

    max_sim = max(sim_pos, max(sim_negs)) if sim_negs else sim_pos
    exp_pos = math.exp(sim_pos - max_sim)
    exp_negs = [math.exp(s - max_sim) for s in sim_negs]
    total_exp = exp_pos + sum(exp_negs)

    return -math.log(max(1e-15, exp_pos / total_exp))

Step 6 · MSE vs Cross-Entropy on Classification

Train the same network from lesson 04 (circle dataset) with both loss functions. Watch cross-entropy converge faster.

import random

def sigmoid(x):
    x = max(-500, min(500, x))
    return 1.0 / (1.0 + math.exp(-x))

def make_circle_data(n=200, seed=42):
    random.seed(seed)
    data = []
    for _ in range(n):
        x = random.uniform(-2, 2)
        y = random.uniform(-2, 2)
        label = 1.0 if x * x + y * y < 1.5 else 0.0
        data.append(([x, y], label))
    return data


class LossComparisonNetwork:
    def __init__(self, loss_type="bce", hidden_size=8, lr=0.1):
        random.seed(0)
        self.loss_type = loss_type
        self.lr = lr
        self.hidden_size = hidden_size

        self.w1 = [[random.gauss(0, 0.5) for _ in range(2)] for _ in range(hidden_size)]
        self.b1 = [0.0] * hidden_size
        self.w2 = [random.gauss(0, 0.5) for _ in range(hidden_size)]
        self.b2 = 0.0

    def forward(self, x):
        self.x = x
        self.z1 = []
        self.h = []
        for i in range(self.hidden_size):
            z = self.w1[i][0] * x[0] + self.w1[i][1] * x[1] + self.b1[i]
            self.z1.append(z)
            self.h.append(max(0.0, z))

        self.z2 = sum(self.w2[i] * self.h[i] for i in range(self.hidden_size)) + self.b2
        self.out = sigmoid(self.z2)
        return self.out

    def backward(self, target):
        if self.loss_type == "mse":
            d_loss = 2.0 * (self.out - target)
        else:
            eps = 1e-15
            p = max(eps, min(1 - eps, self.out))
            d_loss = -(target / p) + (1 - target) / (1 - p)

        d_sigmoid = self.out * (1 - self.out)
        d_out = d_loss * d_sigmoid

        for i in range(self.hidden_size):
            d_relu = 1.0 if self.z1[i] > 0 else 0.0
            d_h = d_out * self.w2[i] * d_relu
            self.w2[i] -= self.lr * d_out * self.h[i]
            for j in range(2):
                self.w1[i][j] -= self.lr * d_h * self.x[j]
            self.b1[i] -= self.lr * d_h
        self.b2 -= self.lr * d_out

    def compute_loss(self, pred, target):
        if self.loss_type == "mse":
            return (pred - target) ** 2
        else:
            eps = 1e-15
            p = max(eps, min(1 - eps, pred))
            return -(target * math.log(p) + (1 - target) * math.log(1 - p))

    def train(self, data, epochs=200):
        losses = []
        for epoch in range(epochs):
            total_loss = 0.0
            correct = 0
            for x, y in data:
                pred = self.forward(x)
                self.backward(y)
                total_loss += self.compute_loss(pred, y)
                if (pred >= 0.5) == (y >= 0.5):
                    correct += 1
            avg_loss = total_loss / len(data)
            accuracy = correct / len(data) * 100
            losses.append((avg_loss, accuracy))
            if epoch % 50 == 0 or epoch == epochs - 1:
                print(f"    Epoch {epoch:3d}: loss={avg_loss:.4f}, accuracy={accuracy:.1f}%")
        return losses

Recap
What to keep from this lesson
  • The loss is what the optimiser actually minimises; pick it to match the task.
  • MSE for regression; cross-entropy for classes, computed from logits for stability.
  • With a sigmoid or softmax output, cross-entropy's gradient on the logit is simply p−y, strong when confidently wrong.
  • Label smoothing softens one-hot targets; focal loss down-weights easy examples.
  • Contrastive losses (InfoNCE, triplet) learn embeddings from pairs; temperature sets how picky they are.

Solutions

SolutionP1 · About the same, from a neutral start

Cross-entropy wins by one epoch: it reaches 90% at epoch 3 and MSE at epoch 4, and both end at 99%. Near p=0.5 the sigmoid's slope is at its largest, p(1−p)=0.25, so the MSE gradient 2(p−y)p(1−p) is only about half the cross-entropy gradient p−y, not fifty times smaller. The large gap of the worked example appears only when predictions start confidently wrong, which is what B1 sets up.

SolutionB1 · MSE stalls, cross-entropy recovers

With MSE the accuracy sits at 71.5 percent, the share of points outside the circle, for about the first 50 epochs (68.5 percent at epoch 50) and only reaches 97 percent by epoch 100. With cross-entropy it is 91 percent by epoch 10. Every prediction starts near 0, where the sigmoid is flat, so MSE's gradient is multiplied by almost zero; cross-entropy's gradient on the logit is p−y≈−1 for every positive example, full strength.

Focal loss is cross-entropy with a weight that makes easy examples count less. A detector sees many easy background regions and few objects. With plain cross-entropy, the easy examples give most of the loss. Focal loss multiplies each term by (1−pt​)γ, so the model learns more from the hard examples.

Task

Write three functions.

  1. binary_focal_loss(logits, targets, gamma, alpha) returns the mean binary focal loss.
  2. binary_focal_grad(logits, targets, gamma, alpha) returns the gradient of that mean loss with respect to the logits.
  3. focal_loss(logits, targets, gamma, alpha) returns the mean multi-class focal loss.

For one example, pt​ is the predicted probability of the true class and

FL(pt​)=−αt​(1−pt​)γlogpt​.

In the binary case, the logit is x and the target is y∈{0,1}. Then pt​=σ(x) when y=1 and pt​=1−σ(x) when y=0, with σ(x)=1/(1+e−x). With a float alpha, αt​=α when y=1 and αt​=1−α when y=0.

In the multi-class case, pt​ is the softmax probability of the target class over the row of logits. With an array alpha of size C, αt​ is alpha[target].

When alpha is None, αt​=1. Each loss is the mean of FL over the batch. With γ=0 and no alpha, both losses are the ordinary cross-entropy.

Hint 1

Let s=x when y=1 and s=−x when y=0. Then pt​=σ(s) in both cases, and one formula covers every example.

Hint 2

Reference solution and notes
import numpy as np


def binary_parts(logits, targets, alpha):
    sign = 2.0 * np.asarray(targets, dtype=float) - 1.0
    s = sign * np.asarray(logits, dtype=float)
    log_pt = -np.logaddexp(0.0, -s)
    one_minus_pt = np.exp(-np.logaddexp(0.0, s))
    alpha_t = 1.0 if alpha is None else np.where(sign > 0, alpha, 1.0 - alpha)
    return sign, log_pt, one_minus_pt, alpha_t


def binary_focal_loss(logits, targets, gamma=2.0, alpha=None):
    _, log_pt, one_minus_pt, alpha_t = binary_parts(logits, targets, alpha)
    return float(np.mean(-alpha_t * one_minus_pt ** gamma * log_pt))


def binary_focal_grad(logits, targets, gamma=2.0, alpha=None):
    sign, log_pt, one_minus_pt, alpha_t = binary_parts(logits, targets, alpha)
    pt = np.exp(log_pt)
    d_s = alpha_t * one_minus_pt ** gamma * (gamma * pt * log_pt - one_minus_pt)
    return d_s * sign / sign.size


def focal_loss(logits, targets, gamma=2.0, alpha=None):
    logits = np.asarray(logits, dtype=float)
    shifted = logits - np.max(logits, axis=1, keepdims=True)
    log_probs = shifted - np.log(np.sum(np.exp(shifted), axis=1, keepdims=True))
    log_pt = log_probs[np.arange(logits.shape[0]), targets]
    alpha_t = 1.0 if alpha is None else np.asarray(alpha, dtype=float)[targets]
    return float(np.mean(-alpha_t * (1.0 - np.exp(log_pt)) ** gamma * log_pt))

Why the factor helps

An easy example has pt​ near 1, so (1−pt​)γ is near 0. With γ=2, an example with pt​=0.9 gives 100 times less loss than with cross-entropy. An example with pt​=0.1 keeps 81 percent of its loss. In a detector with thousands of easy background regions for each object, this change moves most of the gradient to the hard examples.

Alpha and gamma together

The paper uses γ=2 and α=0.25. It is a surprise that the best α gives the rare positive class a smaller weight. The factor (1−pt​)γ already removes most of the easy negatives, so the remaining negatives need a larger weight.

The numerical trap

logσ(x) with np.log(sigmoid(x)) gives minus infinity for x=−1000. The form with np.logaddexp gives exactly −1000. The same problem occurs for 1−pt​ when pt​ is near 1: compute it as σ(−s) and not as 1 - sigmoid(s).

Where this goes next

RetinaNet uses the binary form for each class and each anchor box. The paper also starts the bias of the last layer at −log((1−π)/π) with π=0.01, so that the first predictions are rare positives. The computer vision phase uses focal loss for detection.

A classifier gives one row of logits for each example. Softmax turns each row into probabilities. Cross-entropy measures how much probability the model gives to the correct class. Its gradient with respect to the logits is the signal that trains every classifier in the course.

Task

Write three functions.

  1. softmax(logits) returns the softmax of each row.
  2. cross_entropy(logits, targets) returns the mean cross-entropy loss over the batch.
  3. cross_entropy_grad(logits, targets) returns the gradient of that mean loss with respect to logits.

The softmax of a row z is pi​=ezi​/∑j​ezj​. The loss of one example with the correct class y is −logpy​. The batch loss is the mean of the example losses.

Large logits overflow np.exp. Your softmax must give correct probabilities for logits such as 1000.0.

Reference solution and notes
import numpy as np


def softmax(logits):
    shifted = logits - np.max(logits, axis=1, keepdims=True)
    exps = np.exp(shifted)
    return exps / np.sum(exps, axis=1, keepdims=True)


def cross_entropy(logits, targets):
    shifted = logits - np.max(logits, axis=1, keepdims=True)
    log_probs = shifted - np.log(np.sum(np.exp(shifted), axis=1, keepdims=True))
    rows = np.arange(logits.shape[0])
    return float(-np.mean(log_probs[rows, targets]))


def cross_entropy_grad(logits, targets):
    grad = softmax(logits)
    rows = np.arange(logits.shape[0])
    grad[rows, targets] -= 1.0
    return grad / logits.shape[0]

Why the shift works

For any constant c, ezi​−c/∑j​ezj​−c=ezi​/∑j​ezj​. With c=maxj​zj​, every exponent is 0 or less, so each term is in (0,1] and the sum is at least 1. Overflow cannot occur, and the sum is never 0.

Why log-softmax and not log of softmax

When the correct class has a probability below about 10−308, softmax rounds it to 0 and np.log returns minus infinity. The form zy​−c−log∑j​ezj​−c never computes that small number, so the loss stays finite. This is the log-sum-exp trick.

The gradient

The derivative of −logpy​ with respect to zi​ is pi​−[i=y]. The full Jacobian of softmax cancels out, which is why frameworks fuse softmax and cross-entropy into one operation. The lesson builds the same gradient for one example in cce_gradient.

Where this goes next

The same pattern returns in the attention lessons: attention weights are a softmax over each row of scores, with a mask applied before the shift.

Explain the mechanismA binary classifier trained with mean squared error on a balanced dataset settles on an output near 0.5 for every input. The loss is low and stable, and the optimizer reports no problem. Explain why the optimizer is content and which loss you switch to.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. With two classes split evenly, a constant output of 0.5 gives a squared error of 0.25 on every row, which the lesson calls the minimum MSE a model can reach without learning anything, and the sigmoid's flat regions give MSE almost no gradient near a confident wrong answer. Cross-entropy charges minus the log of the predicted probability of the true class: 0.693 for 0.5, 0.01 for 0.99 and 4.6 for 0.01, so it pushes each prediction toward its label. Switch to binary cross-entropy.

Why MSE is content.

MSE averages the squared gap between the prediction and the label. Its gradient with respect to a prediction is linear in the gap. The prediction passes through a sigmoid, whose derivative is p(1 - p) and is near zero when p is near 0 or 1. A confident wrong answer, p near 0 for a positive row, sits exactly where the sigmoid is flat, so the update is tiny. A model can lower the loss a little by moving everything toward the middle and then stop, because the gradient has little left to say.

Why cross-entropy is not.

Binary cross-entropy is minus y log p minus (1 - y) log (1 - p). Its derivative with respect to p is minus y over p plus (1 - y) over (1 - p). For a positive row with p near 0 that is about minus 1 over p, which grows without bound as p falls. The log undoes the sigmoid: the derivative of the loss with respect to the logit is the prediction minus the target, linear in the error and never flat. The lesson's scale: a right answer at 0.99 costs 0.01, a wrong answer at 0.01 costs 4.6, a ratio of about 460.

The multi-class version.

Categorical cross-entropy on a one-hot target reduces to minus the log of the probability of the true class. A random guess among 10 classes puts probability 0.1 there and costs 2.3; a probability of 0.9 costs 0.105. A loss stuck near 2.3 on a 10 class problem is the multi-class twin of the 0.5 symptom.

When the switch does not help.

The switch helps only when the inputs carry signal about the label. On balanced data with no predictive features, both losses are lowest at a constant 0.5, so cross-entropy settles there too. Check that a simple model beats the constant before you blame the loss.

Where MSE belongs.

Regression on real valued targets, where a linear gradient in the error is what you want. For targets with heavy outliers, MAE or a Huber loss are the lesson's alternatives.

Plausible wrong answers.

  • "Lower the learning rate so MSE converges properly." The 0.5 output is where MSE is content; a smaller step arrives there more slowly.
  • "MSE and cross-entropy have the same minimizer, so it does not matter." They agree only at a perfect fit. Away from it, MSE's gradient flattens where cross-entropy's grows.
  • "Use accuracy as the loss instead." Accuracy has no useful gradient; the optimizer needs a smooth loss.

Follow-ups an interviewer may ask.

  • (level 2) Write the derivative of binary cross-entropy with respect to p. Expected: minus y over p plus (1 - y) over (1 - p), which grows without bound when p is near 0 for a positive row.
  • (level 2) Why does a prediction of 0.5 cost 0.693 under cross-entropy? Expected: it is minus the natural log of 0.5.
  • (level 3) After the sigmoid, differentiate cross-entropy by the logit. What do you get? Expected: the prediction minus the target; the log cancels the sigmoid's derivative.
  • (level 3) When is MSE the right loss? Expected: regression on real valued targets; for heavy outliers, MAE or a Huber loss.

Then describe the gradient vector when the model is sure and right, and when it is sure and wrong.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. For softmax followed by cross-entropy on a one-hot target, the derivative of the loss with respect to logit i is the predicted probability of class i minus the target for class i. The function copies the probabilities and subtracts 1 at the true class, which is that vector. When the model is confident and right, every entry is near zero. When it is confident and wrong, the entry at the true class is near minus 1 and the entry at the class it chose is near plus 1.

Why the form is so simple.

The loss is minus the log of the probability of the true class, and that probability is exp of the true logit over the sum of exp of all logits. Differentiate with respect to logit i: the log of the denominator contributes plus p_i for every i, and the log of the numerator contributes minus 1 only for the true class. The softmax derivative on its own is a full matrix; combined with the log it collapses to p minus the one-hot target. The lesson's phrase is that softmax and cross-entropy are paired on purpose.

Reading the vector.

  • Confident right: p at the true class is near 1, so that entry is near 0, and every other p is near 0. Almost no update.
  • Confident wrong: p at the true class is near 0, so that entry is near minus 1; the chosen class has p near 1 and an entry near plus 1. A large update that lowers the chosen logit and raises the true one.
  • The entries sum to zero, because the probabilities sum to 1 and so does the one-hot target. That is a quick check for a hand-written version.

What the three lines rely on.

The softmax call must be the stable one, with the largest logit subtracted before the exponential, or large logits give inf. A framework fuses log-softmax and the negative log-likelihood into one loss that takes logits, for the same reason; the lesson's rule is to call that fused loss rather than a softmax followed by a separate log.

With label smoothing.

Replace the one-hot target by the smoothed vector: with alpha of 0.1 on ten classes the true class gets 0.91 and the others 0.01. The gradient is p minus that vector, so it reaches zero at 0.91, not at 1.0, which keeps the logits from running to infinity.

Plausible wrong answers.

  • "The gradient is minus 1 over p at the true class, like binary cross-entropy." That is the derivative with respect to the probability; through the softmax, the derivative with respect to the logit is p minus the target.
  • "Only the true class has a gradient, because only it appears in the loss." Every logit appears in the softmax denominator, so every logit receives its p as gradient.
  • "Divide by the number of classes." The gradient per sample is p minus the target; averaging over a batch divides by the batch size, not the class count.

Follow-ups an interviewer may ask.

  • (level 2) What does the gradient vector sum to? Expected: zero; the probabilities sum to 1 and the one-hot target sums to 1.
  • (level 2) Why pair softmax with cross-entropy rather than with squared error? Expected: the log undoes the exponential, so the gradient is linear in the error and never flattens.
  • (level 3) How does the gradient change with label smoothing of 0.1 on ten classes? Expected: the target becomes 0.91 at the true class and 0.01 elsewhere, so the gradient is p minus that vector and reaches zero at 0.91, not at 1.0.
  • (level 3) A framework offers a loss on logits and a loss on log probabilities. Which do you call? Expected: the one on logits, which fuses log-softmax and the negative log-likelihood in one numerically stable step.

The loss function maps predictions and targets to a single scalar that the optimizer minimizes via gradient descent. It must be differentiable so gradients can be computed.

Q2Why is cross-entropy preferred over MSE for classification tasks?

When a model confidently predicts the wrong class (p near 0 for true class), -log(p) produces a huge loss and strong gradient. MSE produces weak gradients in the same situation because sigmoid is flat near 0 and 1.

Q3What happens if you use MSE loss for binary classification?

With MSE on a balanced binary dataset, predicting 0.5 for every input gives MSE=0.25 -- the minimum achievable without discrimination. The model satisfies the loss without learning any useful patterns.

Q4What does label smoothing do and why is it useful?

Label smoothing changes targets from [0,0,1,0] to [0.025,0.025,0.925,0.025] (with alpha=0.1). This prevents the model from pushing logits to infinity to achieve hard targets, reducing overconfidence.

Q5In contrastive loss (InfoNCE), what role does the temperature parameter play?

Temperature divides the similarity scores before softmax. Lower temperature (e.g., 0.07) creates a sharper distribution where the model must clearly separate positives from negatives. Higher temperature is more forgiving.
