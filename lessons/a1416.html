In plain words first
The idea in one line

OpenAI Agents SDK is the lightweight multi-agent framework built on the Responses API. Five primitives: Agent, Handoff, Guardrail, Session, Tracing. Handoffs are tools named transfer_to_<agent>. Guardrails trip on input or output. Tracing is on by default.

Terms you'll hear
Term What people say What it actually means
Agent "LLM + instructions" Agent type in the SDK; owns tools and handoffs
Handoff "Transfer" Tool the model calls to delegate to another agent
Guardrail "Policy check" Validation on input / output / tool invocation
Tripwire "Guardrail trip" Exception raised when guardrail rejects
Session "History store" Conversation memory persisted between runs
Tracing "Spans" Built-in observability over LLM + tool + handoff + guardrail
Blocking guardrail "Sequential check" Guardrail runs first; no token waste on trip
Parallel guardrail "Concurrent check" Guardrail runs alongside; lower latency, wastes tokens on trip

The problem

In plain words first

The OpenAI Agents SDK is a small Python library for building agents out of five pieces. An agent is a model plus instructions and tools. A handoff lets one agent pass the conversation to another (a triage agent sends a billing question to the billing agent); to the model it looks like one more tool, called something like transfer_to_billing_agent. A guardrail is a check on the incoming request or the outgoing answer that can stop the run. A session remembers earlier turns of a conversation. Tracing records every model call, tool call, handoff and guardrail as a span you can inspect. This lesson builds these pieces in plain Python, then runs the real SDK against a small local model and watches where handoffs and guardrails work and where they fail.

Agents that cannot delegate cleanly end up stuffing everything into one prompt. Agents without guardrails ship PII, policy-violating output, or loop forever. OpenAI's SDK codifies the three primitives that make multi-agent work tractable.

Idea 1 · Five primitives

  1. Agent. LLM + instructions + tools + handoffs.
  2. Handoff. Delegation to another agent. Represented to the model as a tool named transfer_to_<agent_name>.
  3. Guardrail. Validation on input (first agent only), output (last agent only), or tool invocation (per function tool).
  4. Session. Automatic conversation history across turns.
  5. Tracing. Built-in spans for LLM generations, tool calls, handoffs, guardrails.

Idea 2 · Handoffs as tools

The model sees transfer_to_billing_agent in its tool list. Calling it signals the runtime to:

  1. Copy the conversation context (or collapse it via nest_handoff_history beta).
  2. Initialize the target agent with its instructions.
  3. Continue the run with the target agent.

This is the supervisor pattern (Lesson 14.13 / Lesson 14.28) productized.

Idea 3 · Guardrails

Three flavors:

  • Input guardrails. Run on the first agent's input. Reject unsafe or out-of-scope requests before any LLM call.
  • Output guardrails. Run on the last agent's output. Catch PII leaks, policy violations, malformed responses.
  • Tool guardrails. Run per-function-tool. Validate arguments, check permissions, audit execution.

Mode:

  • Parallel (default). Guardrail LLM runs alongside the main LLM. Lower tail latency. If tripped, the main LLM's work is discarded (token waste).
  • Blocking (run_in_parallel=False). Guardrail LLM runs first. If tripped, no tokens wasted on the main call.

Tripwires raise InputGuardrailTripwireTriggered / OutputGuardrailTripwireTriggered.

Idea 4 · Tracing

On by default. Every LLM generation, tool call, handoff, and guardrail emits a span. OPENAI_AGENTS_DISABLE_TRACING=1 opts out. add_trace_processor(processor) fans spans to your own backend alongside OpenAI's.

Idea 5 · Sessions

Session stores conversation history in a backend (SQLite, Redis, custom). Runner.run(agent, input, session=session) auto-loads and appends.

Idea 6 · Where this pattern goes wrong

  • Handoff drift. Agent A hands off to Agent B which hands back to Agent A. Add a hop counter.
  • Guardrail bypass. Tool guardrails only fire on function tools; built-in tools (file reader, web fetch) need separate policy.
  • Over-tracing. Sensitive content in spans. Pair with OTel GenAI content-capture rules (Lesson 14.23) — store externally, reference by ID.

The same idea as a formula

A handoff is a tool call that changes the agent. With agents A1​,…,Am​, each run step is

at​=πA(t)​(ht​),A(t+1)={Aj​A(t)​at​=transfer_to_Aj​otherwise​,
and the run ends when the current agent produces a final answer or t reaches max_turns.

Guardrails are predicates. An input guardrail gin​(x)∈{pass,trip} runs on the request; an output guardrail gout​(y) on the final answer. A trip raises an exception instead of returning y.

Parallel or blocking. If the guardrail takes tg​ and the first model call tm​, a blocking guardrail adds latency tg​ to every request, while a parallel one adds none but may waste the model call's tokens when it trips: on a trip rate r, about r⋅tm​ of compute per request.

Worked example
Reading the spans of the routed order question
  • The span list for "Where is my order A-1001?" in the second block has three generation spans: triage, then the orders agent twice (once to call the tool, once to answer).
  • Between them: one handoff span (triage to orders) and one function span (get_order_status). Two guardrail spans: the input check at the start and the output check at the end.
  • So one user question cost 3 model calls, 1 tool call and 2 guardrail checks. In the first block, the same question cost 1 model call and produced no answer at all.
  • With a card number in the request, the input guardrail trips on 16 digits and the run raises InputGuardrailTripwireTriggered; no generation span is recorded for it.
Check your mental model
  • ✗ "Listing handoffs makes the model use them."
    ✓ The model must choose the transfer tool; a weak model may never do so.
  • ✗ "Guardrails see only the new message."
    ✓ With a session the input can include earlier items; write the check for the shape it receives.
  • ✗ "Forcing a tool call is always safe."
    ✓ The model can invent a tool name, as the third request shows; the SDK rejects it with an error.
  • ✗ "Tracing is optional decoration."
    ✓ It is how you count calls, see handoffs and find where a run went wrong.

# The OpenAI Agents SDK (openai-agents 0.26) on a local model: Qwen2.5-0.5B-Instruct behind a small
# OpenAI-compatible server (the same one as lesson 14.15, started here). A triage agent with two handoffs,
# a function tool, an input guardrail and an output guardrail; spans go to a local trace processor.
import asyncio, json, os, pathlib, re, subprocess, sys, tempfile
work = pathlib.Path(tempfile.mkdtemp())
SERVER = r'''# qwen_server.py: Qwen2.5-0.5B-Instruct behind a minimal OpenAI-compatible /v1/chat/completions endpoint,
# so frameworks that speak that API can run on a local model. Greedy decoding; tool calls supported through
# the model's chat template (<tool_call> blocks become OpenAI tool_calls); tool_choice="required" is honoured by
# starting the reply inside a <tool_call> block. Stops by itself after LIFETIME s.
import json, os, re, sys, time, uuid, torch
from http.server import BaseHTTPRequestHandler, HTTPServer
os.environ.setdefault("HF_HUB_OFFLINE", "1")
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
M = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(M); llm = AutoModelForCausalLM.from_pretrained(M).eval()
LOG = os.environ.get("QWEN_LOG")
def text_of(content):
    return content if isinstance(content, str) else " ".join(p.get("text", "") for p in content or [])
def to_template(messages):
    out = []
    for m in messages:
        msg = {"role": m["role"], "content": text_of(m.get("content") or "")}
        if m.get("tool_calls"):
            msg["tool_calls"] = [{"type": "function", "function": {"name": c["function"]["name"],
                                  "arguments": json.loads(c["function"]["arguments"] or "{}")}} for c in m["tool_calls"]]
        out.append(msg)
    return out
def complete(req):
    tools = req.get("tools") or None
    ids = tok.apply_chat_template(to_template(req["messages"]), tools=tools, add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True)["input_ids"]
    forced = '<tool_call>\n{"name": "' if tools and req.get("tool_choice") == "required" else ""
    if forced:                                           # constrained start: the reply must be a tool call
        ids = torch.cat([ids, tok(forced, return_tensors="pt")["input_ids"]], dim=1)
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=int(req.get("max_tokens") or req.get("max_completion_tokens") or 256),
                           do_sample=False)
    text = forced + tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()
    calls = []
    for blob in re.findall(r"<tool_call>\s*(\{.*?\})\s*</tool_call>", text, re.S) if tools else []:
        try:
            d = json.loads(blob)
            calls.append({"id": "call_" + uuid.uuid4().hex[:8], "type": "function",
                          "function": {"name": d["name"], "arguments": json.dumps(d.get("arguments", {}))}})
        except (json.JSONDecodeError, KeyError):
            pass
    content = re.sub(r"<tool_call>.*?</tool_call>", "", text, flags=re.S).strip() if calls else text
    if LOG:
        with open(LOG, "a") as f:
            f.write(json.dumps({"prompt_tokens": ids.shape[1], "tools": len(tools or []), "tool_calls": [c["function"] for c in calls],
                                "content": content[:200]}) + "\n")
    msg = {"role": "assistant", "content": content or None}
    if calls:
        msg["tool_calls"] = calls
    return {"id": "chatcmpl-" + uuid.uuid4().hex[:8], "object": "chat.completion", "created": int(time.time()),
            "model": req.get("model", M), "choices": [{"index": 0, "message": msg,
            "finish_reason": "tool_calls" if calls else "stop"}],
            "usage": {"prompt_tokens": ids.shape[1], "completion_tokens": out.shape[1] - ids.shape[1],
                      "total_tokens": out.shape[1]}}
class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args):
        pass
    def do_GET(self):
        body = json.dumps({"object": "list", "data": [{"id": M, "object": "model"}]}).encode()
        self.send_response(200); self.send_header("Content-Type", "application/json"); self.end_headers(); self.wfile.write(body)
    def do_POST(self):
        req = json.loads(self.rfile.read(int(self.headers["Content-Length"])))
        body = json.dumps(complete(req)).encode()
        self.send_response(200); self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body))); self.end_headers(); self.wfile.write(body)
port, lifetime = int(sys.argv[1]), float(sys.argv[2])
srv = HTTPServer(("127.0.0.1", port), Handler); srv.timeout = 0.5
print("ready", flush=True)
deadline = time.time() + lifetime
while time.time() < deadline:                            # bounded: one request at a time until the deadline
    srv.handle_request()
'''
(work / "qwen_server.py").write_text(SERVER)
PORT = 8700 + os.getpid() % 100
server = subprocess.Popen([sys.executable, str(work / "qwen_server.py"), str(PORT), "900"],

assert server.stdout.readline().strip() == "ready"

                    set_trace_processors, ModelSettings)
from agents.tracing import TracingProcessor
set_default_openai_api("chat_completions")              # the local server speaks Chat Completions
class LocalSpans(TracingProcessor):
    """Collects span types instead of exporting them to OpenAI."""
    def __init__(self): self.spans = []
    def on_trace_start(self, trace): pass
    def on_trace_end(self, trace): pass
    def on_span_start(self, span): pass
    def on_span_end(self, span): self.spans.append(span.span_data.type)
    def shutdown(self): pass
    def force_flush(self): pass
SPANS = LocalSpans(); set_trace_processors([SPANS])
ORDERS = {"A-1001": "shipped on 20 Nov", "A-1002": "processing"}
@function_tool
def get_order_status(order_id: str) -> str:
    """Return the shipping status for an order ID such as A-1001."""
    return f"{order_id}: {ORDERS.get(order_id, 'not found')}"
@input_guardrail
async def no_card_numbers(ctx, agent, user_input):
    if isinstance(user_input, list):                    # with a session, the input includes earlier items
        user_input = next(i.get("content", "") for i in reversed(user_input) if i.get("role") == "user")
    digits = re.sub(r"\D", "", str(user_input))
    return GuardrailFunctionOutput(output_info={"digits": len(digits)}, tripwire_triggered=len(digits) >= 13)
@output_guardrail
async def no_promises(ctx, agent, output):
    bad = re.search(r"\b(guarantee|promise|refund(ed)? (today|now))\b", str(output), re.I)
    return GuardrailFunctionOutput(output_info={"match": bad.group(0) if bad else None}, tripwire_triggered=bool(bad))
MODEL = "qwen2.5-0.5b"; SETTINGS = ModelSettings(temperature=0)
orders = Agent(name="Orders agent", model=MODEL, model_settings=SETTINGS, tools=[get_order_status],
               instructions="You answer questions about orders. Use get_order_status, then answer in one sentence.",
               output_guardrails=[no_promises])
billing = Agent(name="Billing agent", model=MODEL, model_settings=SETTINGS, output_guardrails=[no_promises],
                instructions="You answer billing questions in one sentence. Never promise refunds.")
triage = Agent(name="Triage agent", model=MODEL, model_settings=SETTINGS, handoffs=[orders, billing],
               instructions="You route each message. For order or shipping questions call transfer_to_orders_agent. "
                            "For payment or invoice questions call transfer_to_billing_agent. Never answer yourself.",
               input_guardrails=[no_card_numbers])
REQUESTS = ["Where is my order A-1001?", "Why was I charged twice on my invoice?",
            "My card 4111 1111 1111 1111 was declined, can you retry it?"]
async def main():
    for text in REQUESTS:
        SPANS.spans.clear()
        try:
            r = await Runner.run(triage, text, max_turns=6)
            tools = [i.raw_item.name for i in r.new_items if i.type == "tool_call_item"]
            print(f"\n{text}\n  answered by: {r.last_agent.name}   tool calls: {tools}")
            print(f"  reply: {' '.join(str(r.final_output).split())[:150]}")
        except InputGuardrailTripwireTriggered as e:
            print(f"\n{text}\n  blocked by the input guardrail: {e.guardrail_result.output.output_info}")
        except OutputGuardrailTripwireTriggered as e:
            print(f"\n{text}\n  reply withheld by the output guardrail: {e.guardrail_result.output.output_info}")
        except Exception as e:
            print(f"\n{text}\n  run failed: {type(e).__name__}: {str(e)[:120]}")
        print(f"  spans: {SPANS.spans}")
asyncio.run(main())

Part 1 of 4 · GuardrailTripped, FunctionTool, Handoff, Agent, InputGuardrail, OutputGuardrail, Span

"""OpenAI Agents SDK-shaped runtime in stdlib.

Five primitives: Agent, FunctionTool, Handoff, Guardrail, Tracing.
Handoffs are tools named transfer_to_<agent>. Guardrails trip on input/output.
A span tree mirrors what the real SDK emits.
"""

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, Callable


class GuardrailTripped(Exception):
    def __init__(self, which: str, reason: str) -> None:
        super().__init__(f"{which}: {reason}")
        self.which = which
        self.reason = reason


@dataclass
class FunctionTool:
    name: str
    description: str
    fn: Callable[..., str]


@dataclass
class Handoff:
    target: "Agent"

    @property
    def tool_name(self) -> str:
        return f"transfer_to_{self.target.name}"


@dataclass
class Agent:
    name: str
    instructions: str
    policy: Callable[[str], dict[str, Any]]
    tools: list[FunctionTool] = field(default_factory=list)
    handoffs: list[Handoff] = field(default_factory=list)


@dataclass
class InputGuardrail:
    name: str
    check: Callable[[str], tuple[bool, str]]


@dataclass
class OutputGuardrail:
    name: str
    check: Callable[[str], tuple[bool, str]]


@dataclass
class Span:
    name: str
    attributes: dict[str, Any] = field(default_factory=dict)
    children: list["Span"] = field(default_factory=list)

Part 2 of 4 · Runner

@dataclass
class Runner:
    input_guardrails: list[InputGuardrail] = field(default_factory=list)
    output_guardrails: list[OutputGuardrail] = field(default_factory=list)
    max_hops: int = 3
    trace: Span = field(default_factory=lambda: Span(name="run"))

    def run(self, agent: Agent, user_input: str) -> str:
        for guard in self.input_guardrails:
            ok, reason = guard.check(user_input)
            span = Span(name=f"input_guardrail.{guard.name}",
                        attributes={"passed": ok, "reason": reason})
            self.trace.children.append(span)
            if not ok:
                raise GuardrailTripped("input", reason)

        current_agent = agent
        current_input = user_input
        final_output = ""
        for hop in range(self.max_hops):
            agent_span = Span(name=f"agent.{current_agent.name}",
                              attributes={"hop": hop,
                                          "instructions": current_agent.instructions[:40]})
            self.trace.children.append(agent_span)

            policy_output = current_agent.policy(current_input)
            kind = policy_output["kind"]

            if kind == "final":
                final_output = policy_output["text"]
                agent_span.children.append(
                    Span(name="llm_generation",
                         attributes={"output": final_output[:60]})
                )
                break
            if kind == "tool":
                tool_name = policy_output["tool"]
                args = policy_output.get("args", {})
                tool = next((t for t in current_agent.tools if t.name == tool_name),
                            None)
                if tool is None:
                    agent_span.children.append(
                        Span(name="tool_error",
                             attributes={"tool": tool_name,
                                         "reason": "unknown tool"})
                    )
                    final_output = f"error: unknown tool {tool_name}"
                    break
                result = tool.fn(**args)
                agent_span.children.append(
                    Span(name=f"tool.{tool_name}",
                         attributes={"args": args, "result": result[:40]})
                )
                current_input = f"tool {tool_name} returned: {result}"
                continue
            if kind == "handoff":
                target_name = policy_output["to"]
                handoff = next((h for h in current_agent.handoffs
                                if h.target.name == target_name), None)
                if handoff is None:
                    final_output = f"error: no handoff to {target_name}"
                    break
                agent_span.children.append(
                    Span(name=f"handoff.{handoff.tool_name}",
                         attributes={"from": current_agent.name,
                                     "to": target_name})
                )
                current_agent = handoff.target
                current_input = policy_output.get("input", current_input)
                continue
            final_output = f"error: unknown policy kind {kind}"
            break

        for guard in self.output_guardrails:
            ok, reason = guard.check(final_output)
            span = Span(name=f"output_guardrail.{guard.name}",
                        attributes={"passed": ok, "reason": reason})
            self.trace.children.append(span)
            if not ok:
                raise GuardrailTripped("output", reason)

        return final_output

Part 3 of 4 · _print_span, _triage_policy, _billing_policy, _support_policy, _pii_check, _length_check

def _print_span(span: Span, indent: int = 0) -> None:
    prefix = "  " * indent
    attrs = " ".join(f"{k}={v!r}" for k, v in span.attributes.items())
    print(f"{prefix}{span.name}  {attrs}")
    for child in span.children:
        _print_span(child, indent + 1)


def _triage_policy(user_input: str) -> dict[str, Any]:
    t = user_input.lower()
    if "refund" in t or "billing" in t or "invoice" in t:
        return {"kind": "handoff", "to": "billing", "input": user_input}
    if "error" in t or "crash" in t or "bug" in t:
        return {"kind": "handoff", "to": "support", "input": user_input}
    return {"kind": "final", "text": "i'm not sure how to help with that"}


def _billing_policy(user_input: str) -> dict[str, Any]:
    return {"kind": "final", "text": f"billing handled: {user_input[:40]}"}


def _support_policy(user_input: str) -> dict[str, Any]:
    return {"kind": "final", "text": f"support handled: {user_input[:40]}"}


def _pii_check(text: str) -> tuple[bool, str]:
    if "ssn" in text.lower():
        return False, "refuses to process social security numbers"
    return True, "ok"


def _length_check(text: str) -> tuple[bool, str]:
    return len(text) < 200, f"output {len(text)} chars"

        name="triage", instructions="route queries to the right specialist",
        policy=_triage_policy,

    )

    runner = Runner(
        input_guardrails=[InputGuardrail("pii_block", _pii_check)],
        output_guardrails=[OutputGuardrail("length_cap", _length_check)],

Industry practice
What's current (2024–2026)
  • OpenAI Agents SDK (Python and TypeScript) is OpenAI's production agent library, built on the Responses API; it also runs on any Chat Completions endpoint and, through LiteLLM, on other providers, as this lab shows with a local model.
  • Built-in features beyond this lab: tool guardrails, human approval for tools (needs_approval), MCP servers as tool sources, realtime voice agents, and several session backends (SQLite, Redis, SQLAlchemy, OpenAI Conversations).
  • Tracing goes to the OpenAI dashboard by default; trace processors export to Langfuse, LangSmith, Arize, Braintrust and others, or to your own code as here.
  • On your laptop: point the SDK at Ollama's or llama.cpp's OpenAI-compatible endpoint; a 7B to 8B model in 4-bit on the RTX 4060 uses handoffs without tool_choice tricks far more often than 0.5B does.

Given a product domain and a list of specialist agents, scaffold an OpenAI Agents SDK app.

Produce:

1. `Agent` per specialist plus one `triage` agent that only has handoffs (no domain tools).
2. `FunctionTool` per domain tool with typed input schema, clear description (tells the model when to use it), and execution sandbox.
3. `Handoff` from triage to each specialist. Verify tool names follow `transfer_to_<agent>` convention.
4. `InputGuardrail` for PII, policy, scope. Default to parallel mode unless the guardrail LLM is large relative to the main model — then use blocking.
5. `OutputGuardrail` for length, PII, policy. Always blocking on prod for safety-critical outputs.
6. Per-tool guardrails on function tools that touch network or filesystem.
7. `Session` store (SQLite default; Redis for prod).
8. `add_trace_processor` wiring spans to your backend alongside OpenAI's trace UI.

Hard rejects:

- Triage agents with domain tools. Triage handoffs only; mixing dilutes the router's decision.
- Guardrails that mutate the input/output. Guardrails approve or reject — they do not rewrite.
- Silent handoff loops. Require a hop counter (default max 3).

Refusal rules:

- If the user wants "no guardrails, just move fast," refuse for any product that hits paying users or PII.
- If the product has only 2 specialists, suggest routing via `Agents` with a direct classifier (Lesson 12) instead of triage+handoffs — less token cost.
- If tracing is disabled in prod, refuse to ship. Multi-step failures are un-debuggable without traces.

Output: `agents.py`, `tools.py`, `guardrails.py`, `app.py`, `README.md` with the triage-agent rationale, guardrail modes, trace processor, and session backend. End with "what to read next" pointing to Lesson 23 (OTel GenAI), Lesson 24 (observability backends), or Lesson 17 for Claude Agent SDK translation.

Solutions

SolutionP1 · The triage agent, with no tool call

The triage agent answers itself and no tool is called. The 0.5B model sees transfer_to_orders_agent among its tools and an instruction to use it, but replies in text instead, asking for details it already has. Handoffs only happen when the model chooses the transfer tool; with a weak model you either force tool use (second block), route in code, or use a stronger model.

SolutionB1 · The guardrail started reading history

With sessions, the input guardrail receives the conversation so far, not just the new message: earlier messages, tool calls, IDs and timestamps all go through str(user_input). Once a returning customer's history holds 13 digits in total (order numbers, amounts, dates), every new message trips the check, whatever it says. This lab hit exactly that before the fix.

Write guardrails against the input type the SDK actually passes (a string or a list of items) and check only the part you mean to check, here the latest user message. Test them with fixtures that include a session history, a message with numbers that are not card numbers, and a real card pattern (better: a Luhn check on digit runs rather than a digit count), and track the guardrail trip rate in production; a sudden rise is a bug, not an attack.
