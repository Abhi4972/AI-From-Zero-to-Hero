Why this came about

In 2003 Yoshua Bengio and colleagues replaced the n-gram count table with a neural network: look up a learned vector for each previous word, feed them through a hidden layer, and predict the next word. Because similar words get similar vectors, the network could make sensible predictions for word combinations it had never seen. Recurrent neural networks (RNNs), which read text one step at a time while carrying a memory, go back to the 1980s; the LSTM (Hochreiter and Schmidhuber, 1997) made that memory last longer. By 2015, LSTM language models led the field, Andrej Karpathy's blog post "The Unreasonable Effectiveness of Recurrent Neural Networks" generated fake Shakespeare with them, and Google Translate switched to LSTM networks in 2016. A year later the transformerlater · 7.19 replaced them.

In plain words first
From a lookup table to a pattern learner

The counting model of Lesson 5.34 is a giant lookup table: it only knows contexts it has seen. A neural model learns a small vector for every character (or word), and a function that turns the vectors of the recent context into a prediction. Contexts that are similar produce similar vectors, so the model can handle a context it has never met. A recurrent network goes one step further: instead of looking at a fixed window, it reads the text one character at a time and keeps a running summary, its hidden state, like a reader who remembers the gist of what came before.

Step 1 · Text as tensors

The same Tiny Shakespeare text as Lesson 5.34, turned into a tensor of character IDs:

import math
import time

import torch
from torch import nn
import torch.nn.functional as F

URL = "https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt"

Step 2 · A neural language model with a fixed window

The model looks at the previous 8 characters. Each is looked up in an embedding table (16 numbers per character), the 8 vectors are joined into one vector of 128 numbers, a hidden layer mixes them, and the output layer gives 65 scores, one per possible next character.

CTX = 8

class WindowLM(nn.Module):
    def __init__(self, vocab=V, dim=16, hidden=256):
        super().__init__()
        self.emb = nn.Embedding(vocab, dim)
        self.hidden = nn.Linear(CTX * dim, hidden)
        self.out = nn.Linear(hidden, vocab)

    def forward(self, x):                        # x: (batch, 8) character ids
        e = self.emb(x).flatten(1)               # (batch, 8, 16) -> (batch, 128): join the 8 vectors
        return self.out(torch.tanh(self.hidden(e)))   # (batch, 65) logits

def window_batch(ids, size, gen):
    starts = torch.randint(len(ids) - CTX, (size,), generator=gen)
    x = torch.stack([ids[i:i + CTX] for i in starts])      # 8 characters of context
    y = ids[starts + CTX]                                   # the character that came next
    return x, y

@torch.no_grad()
def window_val_loss(model):
    model.eval()
    windows = val_ids.unfold(0, CTX + 1, 1)[:50_000]        # 50,000 overlapping windows of 9 characters
    loss = F.cross_entropy(model(windows[:, :CTX]), windows[:, CTX]).item()
    model.train()
    return loss

torch.manual_seed(0)
mlp = WindowLM()
print("parameters:", sum(p.numel() for p in mlp.parameters()))
opt = torch.optim.AdamW(mlp.parameters(), lr=3e-3)
gen = torch.Generator().manual_seed(0)

for step in range(1, 4001):
    x, y = window_batch(train_ids, 256, gen)
    loss = F.cross_entropy(mlp(x), y)
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step in (1, 500, 1000, 2000, 4000):
        print(f"step {step:>4}  validation loss {window_val_loss(mlp):.3f}")

Step 3 · Recurrent networks: reading with a memory

A fixed window cannot use anything further back than 8 characters. A recurrent neural network (RNN) reads one character at a time and carries a hidden state, a vector that is updated at every step from the previous state and the new character:

h_t = tanh(W_x · x_t + W_h · h_{t−1} + b)

The same weights are used at every step, so the network can read text of any length.

Here is that update written out, for a hidden state of 4 numbers with random weights, just to see the state change as it reads:

torch.manual_seed(0)
W_x, W_h, b = torch.randn(4, V) * 0.5, torch.randn(4, 4) * 0.5, torch.zeros(4)
h = torch.zeros(4)                                     # the memory starts empty
for c in "to be":
    x = F.one_hot(torch.tensor(stoi[c]), V).float()    # the character as a one-hot vector
    h = torch.tanh(W_x @ x + W_h @ h + b)              # new memory = f(new input, old memory)
    print(f"read {c!r}: hidden state {h.numpy().round(2)}")
What you should see
read 't': hidden state [ 0.64 -0.2   0.32 -0.58]
read 'o': hidden state [-0.63 -0.35  0.49  0.92]
read ' ': hidden state [-0.5   0.46  0.38 -0.73]
read 'b': hidden state [0.66 0.49 0.64 0.77]
read 'e': hidden state [-0.77 -0.52 -0.82  0.27]

The state after "to be" depends on every character read so far, in order. Training adjusts W_x, W_h and b (with backpropagation through all the steps, called backpropagation through time) so that the state keeps whatever helps predict the next character.

Plain RNNs forget quickly: the gradient has to pass back through the same multiplication at every step, and it vanishes (or explodes) over long distances, the problem of Lesson 3.18 stretched along time. The LSTM ("long short-term memory") adds a separate memory cell and gates, small sigmoid layers that decide what to forget, what to write and what to read at each step. The cell can carry information over hundreds of steps. GRUs are a simpler variant. PyTorch provides both as single layers.

Step 4 · Training an LSTM language model

The model: an embedding table, one LSTM layer with a hidden state of 256 numbers, and an output layer. It is trained on chunks of 64 characters, predicting the next character at every position of each chunk at once:

T = 64                                             # characters per training chunk

class CharLSTM(nn.Module):
    def __init__(self, vocab=V, dim=32, hidden=256):
        super().__init__()
        self.emb = nn.Embedding(vocab, dim)
        self.rnn = nn.LSTM(dim, hidden, batch_first=True)
        self.out = nn.Linear(hidden, vocab)

    def forward(self, x, state=None):              # x: (batch, time) ids
        h, state = self.rnn(self.emb(x), state)    # h: (batch, time, hidden), one state per position
        return self.out(h), state                  # logits for the next character at every position

def chunk_batch(ids, size, gen):
    starts = torch.randint(len(ids) - T - 1, (size,), generator=gen)
    x = torch.stack([ids[i:i + T] for i in starts])
    y = torch.stack([ids[i + 1:i + T + 1] for i in starts])   # the same chunk shifted by one: next characters
    return x, y

@torch.no_grad()
def lstm_val_loss(model, n=100_000):
    model.eval()
    xs, ys = val_ids[:n].unsqueeze(0), val_ids[1:n + 1].unsqueeze(0)   # read 100,000 characters in one go
    logits, _ = model(xs)
    model.train()
    return F.cross_entropy(logits.reshape(-1, V), ys.reshape(-1)).item()

torch.manual_seed(0)
lstm = CharLSTM()
print("parameters:", sum(p.numel() for p in lstm.parameters()))
opt = torch.optim.AdamW(lstm.parameters(), lr=3e-3)
gen = torch.Generator().manual_seed(0)
start = time.time()
for step in range(1, 1001):
    x, y = chunk_batch(train_ids, 32, gen)
    logits, _ = lstm(x)
    loss = F.cross_entropy(logits.reshape(-1, V), y.reshape(-1))
    opt.zero_grad()
    loss.backward()
    nn.utils.clip_grad_norm_(lstm.parameters(), 1.0)       # RNNs need clipping (Lesson F4.4)
    opt.step()
    if step in (1, 250, 500, 1000):
        print(f"step {step:>4}  validation loss {lstm_val_loss(lstm):.3f}")
print("trained in under five minutes:", time.time() - start < 300)

Reading this code
  • y is x shifted one place to the left: at each of the 64 positions, the target is the character that comes next. One chunk gives 64 training examples, all computed in one forward pass. GPT trains exactly this way (Lesson 7.20).
  • logits.reshape(-1, V) flattens (batch, time, 65) into (batch × time, 65) rows, because cross_entropy expects one row per prediction.
  • Validation reads 100,000 characters as one long sequence, carrying the hidden state all the way: the LSTM can use context from much further back than 8 characters.
  • After 1,000 steps the validation loss is about 1.64, better than the best counting model (1.78) and the window network (1.86). Lesson 7.20's small transformer goes further still.

Step 5 · Writing with the LSTM

To generate, feed one character at a time, keep the hidden state between steps, and sample from the softmax:

@torch.no_grad()
def generate(model, start="ROMEO:\n", length=300, temperature=1.0, seed=0):
    torch.manual_seed(seed)
    model.eval()
    ids = torch.tensor([[stoi[c] for c in start]])
    logits, state = model(ids)                     # read the prompt, building up the memory
    out = start
    for _ in range(length):
        probs = F.softmax(logits[0, -1] / temperature, dim=-1)   # temperature: Lesson F2.3
        nxt = torch.multinomial(probs, 1)          # sample one character
        out += itos[int(nxt)]
        logits, state = model(nxt.view(1, 1), state)              # feed it back in, keep the memory
    model.train()
    return out

print(generate(lstm))

Step 6 · Why recurrent networks gave way to transformers

Weakness What happens What fixed it
One step at a time step 100 cannot start until step 99 is done, so training cannot use a GPU's parallelism across the sequence transformers process all positions at once (the Transformers, step by step section)
Memory through one vector everything read so far must squeeze into one fixed-size hidden state; details from far back fade attention lets each position look back at any earlier position directly (Lesson 5.36)
Long-range gradients even LSTMs struggle to learn dependencies over thousands of steps attention connects any two positions in one step

RNNs did not disappear entirely: newer designs called state-space modelslater · 7.24 (such as Mamba, 2023) revive the idea of a running state with clever tricks that allow parallel training, and some recent models mix them with attention. But since 2018 nearly every leading language model has been a transformer.

The same idea as a formula
  • window model: ŷ = softmax(W₂ tanh(W₁ [e(x_{t−8}); …; e(x_{t−1})] + b₁) + b₂)
  • simple RNN: h_t = tanh(W_x x_t + W_h h_{t−1} + b), ŷ_t = softmax(W_o h_t)
  • LSTM gates (σ is the sigmoid): forget f_t, input i_t and output o_t, each = σ(W [h_{t−1}; x_t] + b); cell c_t = f_t ⊙ c_{t−1} + i_t ⊙ tanh(W_c [h_{t−1}; x_t] + b_c); h_t = o_t ⊙ tanh(c_t)
  • training loss: average cross-entropy over every position of every chunk
Check your mental model
  • ✗ "A neural language model is a bigger lookup table."
    ✓ It is a function with far fewer parameters than a count table would need, and it gives sensible predictions for contexts it never saw.
  • ✗ "An RNN remembers everything it has read."
    ✓ Everything must fit in one fixed-size hidden state; older details fade. That bottleneck is what attention removes.
  • ✗ "RNNs are slow because they are big."
    ✓ They are slow to train because each step waits for the previous one, so the work along the sequence cannot be done in parallel.

Exercises

Predict before you run

Run generate(lstm, temperature=0.2). Will the text be more or less varied than with temperature 1.0, and what kind of words will dominate? (Solution P1.)

Make it your own

Change CTX in Step 2 from 8 to 3 and retrain the window model for 4,000 steps. Compare its validation loss with the 4-gram counting model of Lesson 5.34 (same 3 characters of context, about 1.78). Which wins, and why might counting do so well here? (Solution M1.)

Debugging exercise

A colleague's LSTM training loss reaches 0.9 while validation loss rises from 1.6 to 2.1. What is happening, and what would you try? (Solution D1.)

Solutions

SolutionP1 · Low temperature

Less varied. Dividing the logits by 0.2 sharpens the distribution (Lesson 1.25), so the model nearly always picks its top choice. Expect the most common short words ("the", "and", "I", "to") and phrases repeating in loops. Low temperature trades variety for safety; at 0 it becomes greedy decodinglater · 7.21 (Lesson 7.21).

SolutionM1 · A short window

With 3 characters of context, the network reaches a validation loss of about 1.92 after 4,000 steps, while the 4-gram counting model scores about 1.78: counting wins. With a short context there are few possible contexts (at most 65³ ≈ 275,000, and far fewer occur), and a million characters of training text covers most of them well, so counting is hard to beat. The network's advantage grows with context length, where counting runs out of data.

SolutionD1 · Training loss falls, validation loss rises

Overfitting: the model is memorising the training text (Lesson 2.26). Keep the checkpoint with the best validation loss (early stopping), add dropout between layers (nn.LSTM(..., dropout=0.2) with two or more layers, or an nn.Dropout before the output layer), use weight decay, or reduce the model size. With one million characters, models of a few million parameters overfit quickly.

Recap
  • A neural language model learns a vector per character or word and a function from the recent context to next-token probabilities; it generalises to contexts it never saw.
  • With the same context length, a small network beats counting by a wide margin because counting has no notion of similar contexts.
  • A recurrent network reads one step at a time, updating a hidden state with the same weights at every step; LSTMs add gates so memory lasts longer.
  • Training predicts the next character at every position of a chunk at once; generation samples one character at a time and feeds it back in.
  • RNNs are slow to train (sequential) and squeeze all memory into one vector; attention and transformers remove both limits.
