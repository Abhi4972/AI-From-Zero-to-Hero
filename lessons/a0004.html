In plain words first
The idea in one line

Every AI API works the same way: send a request, get a response. The details change, the pattern doesn't.

Terms you'll hear
Term What people say What it actually means
API key "Password for the API" A unique string that identifies your account and authorizes requests
Rate limit "They're throttling me" Maximum requests per minute/hour to prevent abuse and ensure fair usage
Token "A word" (in API context) A billing unit: input and output tokens are counted and charged separately
Streaming "Real-time responses" Getting the response word by word instead of waiting for the full response

The problem

In plain words first

A model API is a web address you send a request to. The request carries your API key, a secret string that says who is paying, and a JSON body that says which model to use and what to ask. The reply is JSON too. An SDK is a library that builds those requests for you; underneath, it is the same HTTP call.

Starting from Phase 11, you'll call LLM APIs (Anthropic, OpenAI, Google). In Phase 13-16 you'll build agents that use these APIs in loops. You need to know how API keys work, how to store them safely, and how to make your first API call.

The idea

Every API call has: 1. An endpoint (URL) 2. An API key (authentication) 3. A request body (what you want) 4. A response body (what you get back)

The same idea as a formula

Cost. Providers price per million tokens, separately for input (your prompt, including the conversation so far) and output (the reply):

cost=106Tin​pin​+Tout​pout​​

Output tokens usually cost 4 to 5 times more than input tokens, and in a chat every turn resends the history, so Tin​ grows with the conversation.

Rate limits. Many APIs enforce limits like a token bucket: a bucket holds at most C units and refills at r per second; each request takes units out. You can burst up to C at once, but over a long period you get at most r per second.

Retries. On a 429 Too Many Requests or a 5xx error, wait before retrying, doubling the wait each time up to a cap, and pick the actual wait at random ("full jitter"):

waitn​∼Uniform(0, min(cap, base⋅2n))

The randomness keeps many clients that failed together from retrying together.

How many requests are in flight. By Little's law, with λ requests per second each taking W seconds, on average L=λW are open at once.

Worked example
Budgeting a chatbot by hand

A support bot handles 20,000 conversations a month, each about 3,000 input tokens and 400 output tokens, on a model priced at 3 dollars per million input tokens and 15 per million output tokens (a common mid-tier price; check your provider's pricing page):

  • Input: 20,000×3,000=60 million tokens, at 3 dollars per million: 180 dollars.
  • Output: 20,000×400=8 million tokens, at 15 dollars per million: 120 dollars.
  • Total: 300 dollars a month. The output is 12% of the tokens but 40% of the bill.

With a limit of 50 requests per minute and replies that take 3 seconds, L=(50/60)×3=2.5 requests are open at once on average, so a client that allows 4 concurrent calls is enough.

Check your mental model
  • ✗ "It's fine to paste my key into the notebook for now."
    ✓ Notebooks and scripts get committed, shared and screenshotted. Keys leaked to GitHub are found by scanners within minutes. Keep them in environment variables or a git-ignored .env file.
  • ✗ "A token is a word."
    ✓ A token is a piece of text the model reads, often part of a word. You pay separately for input and output tokens.
  • ✗ "The SDK and the raw HTTP call can give different answers."
    ✓ The SDK sends the same HTTP request. The difference is convenience: retries, types, streaming helpers.

Step 1 · Store API keys safely

Never put API keys in code. Use environment variables.

export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."

Or use a .env file (add it to .gitignore):

ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...

Step 2 · First API call (Python)

import os

import anthropic

client = anthropic.Anthropic()

MODEL = os.environ.get("LLM_MODEL", "claude-sonnet-5")

response = client.messages.create(
    model=MODEL,
    max_tokens=256,
    messages=[{"role": "user", "content": "What is a neural network in one sentence?"}]
)

print(response.content[0].text)

LLM_MODEL selects the Anthropic model id, and the default is the un-dated Sonnet alias. Other providers (OpenAI, Google, and others) follow the same pattern of a key plus a model id, but each has its own SDK, endpoint, and request/response schema.

Watch out
Model names change

Model ids are retired and replaced every few months. In November 2026 the current Anthropic ids include claude-sonnet-5-5, claude-opus-5-5 and claude-haiku-5-5. If a call fails with a "model not found" error, check the provider's model list and set LLM_MODEL to a current id instead of editing the code.

Step 4 · Raw HTTP (no SDK)

import os
import urllib.request
import json

url = "https://api.anthropic.com/v1/messages"
headers = {
    "Content-Type": "application/json",
    "x-api-key": os.environ["ANTHROPIC_API_KEY"],
    "anthropic-version": "2023-06-01",
}
body = json.dumps({
    "model": os.environ.get("LLM_MODEL", "claude-sonnet-5"),
    "max_tokens": 256,
    "messages": [{"role": "user", "content": "What is a neural network in one sentence?"}],
}).encode()

req = urllib.request.Request(url, data=body, headers=headers, method="POST")
with urllib.request.urlopen(req) as resp:
    result = json.loads(resp.read())
    print(result["content"][0]["text"])

This is what the SDKs do under the hood. Understanding the raw HTTP call helps when debugging.

Recap
What to keep from this lesson
  • Every model API is an HTTPS POST with a key in a header and a JSON body; the reply is JSON.
  • Keys live in environment variables or a git-ignored .env, never in code.
  • SDKs wrap the same HTTP call and add retries, types and streaming.
  • Read the status code first: 401 key, 400 request, 429 rate limit, 5xx provider.
See it drawn
Backoff with jitter, simulated

The retry formula for one client, then 100 clients that all hit a rate limit at the same moment and retry with and without jitter, then the cost formula on the worked example's numbers.

import random
random.seed(0)
# Exponential backoff with "full jitter": wait a random time between 0 and min(cap, base·2^attempt).
base, cap = 0.5, 30.0
print("attempt  ceiling (s)  one client's wait (s)")
for attempt in range(8):
    ceiling = min(cap, base * 2 ** attempt)
    print(f"{attempt:>7}  {ceiling:>11.1f}  {random.uniform(0, ceiling):>21.2f}")
# Why jitter: 100 clients hit a rate limit at the same moment and all retry.
def peak(jitter, clients=100, attempt=3):
    waits = [random.uniform(0, base * 2 ** attempt) if jitter else base * 2 ** attempt for _ in range(clients)]
    buckets = {}
    for w in waits:
        buckets[round(w, 1)] = buckets.get(round(w, 1), 0) + 1
    return max(buckets.values())
print(f"busiest 0.1 s window on retry 3: {peak(False)} requests without jitter, {peak(True)} with full jitter")
# A month of a support chatbot: 20,000 conversations, 3,000 input and 400 output tokens each.
p_in, p_out = 3.00, 15.00          # dollars per million tokens (illustrative prices; check your provider's page)
cost = 20_000 * (3_000 * p_in + 400 * p_out) / 1e6
print(f"monthly cost at {p_in} and {p_out} dollars per million input and output tokens: {cost:,.0f} dollars")

Reading this output

The ceiling doubles from 0.5 s until it reaches the 30 s cap, and each actual wait is a random fraction of it. Without jitter all 100 clients wait exactly 4 s and come back in the same instant, hitting the limit again; with full jitter the busiest tenth of a second holds only a handful of them. The official Anthropic and OpenAI SDKs retry this way for you (their max_retries setting); write it yourself only when you call the HTTP API directly.

Solutions

SolutionP1 · A missing variable

os.environ["ANTHROPIC_API_KEY"] raises KeyError: 'ANTHROPIC_API_KEY', which stops the program at that line. os.environ.get(...) returns None and carries on, so the failure shows up later as a confusing 401 from the server. For required secrets, failing early with the KeyError is the better behaviour.

SolutionB1 · A wrong key

The SDK raises anthropic.AuthenticationError with status 401 and an authentication_error type in the body. It is raised by the client.messages.create(...) line, not by anthropic.Anthropic(): creating the client does not contact the server, so a bad key is only found on the first request.

Industry practice
What's current (2024–2026)
  • OpenAI's Responses API is the recommended interface for new projects; the older Assistants API was shut down on 26 August 2026. Chat Completions remains supported.
  • OpenAI-compatible endpoints everywhere. vLLM, SGLang, Ollama, and providers such as Google (Gemini) and many inference clouds accept the OpenAI request format, so one client library can switch providers by changing the base URL and key.
  • Keys as secrets, scoped and rotated. Providers offer project-scoped keys with spending limits; production code reads keys from a secret manager (AWS Secrets Manager, GCP Secret Manager, Vault) rather than .env files, and secret scanning on repositories catches leaked keys.
  • Tools through MCP. The Model Context Protocol is the common way to give models access to tools and data across Claude, ChatGPT, Gemini and IDEs.

Sources: Migrate to Responses, Assistants API deprecation, vLLM OpenAI-compatible server, Model Context Protocol.

You diagnose AI API errors. When someone shares an error, identify the cause and give the fix.

Common errors and fixes:

- **401 Unauthorized**: API key is wrong or missing. Check the environment variable is set and the key is valid.
- **403 Forbidden**: API key doesn't have permission for this endpoint or model.
- **429 Too Many Requests**: Rate limited. Wait and retry, or reduce request frequency.
- **400 Bad Request**: Request body is malformed. Check required fields, model name spelling, message format.
- **500/502/503**: Server-side issue. Wait a minute and retry.
- **Timeout**: Request took too long. Reduce max_tokens or use streaming.
- **Connection refused**: Wrong base URL or network issue. Check the endpoint URL.

Diagnostic steps:
1. Is the API key set? `echo $ANTHROPIC_API_KEY | head -c 10`
2. Is the key valid? Try a minimal request.
3. Is the request format correct? Compare to the docs.
4. Is there a network issue? `curl -I https://api.anthropic.com`
