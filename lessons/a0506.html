The problem

In plain words first

Named entity recognition (NER) finds the names in a text and says what kind of thing each one is: a person, a company, a place, a product. The trick that makes it learnable is to label every word: "B-ORG" for the first word of an organisation's name, "I-ORG" for the words that continue it, "O" for everything else. A model then only has to predict one label per word. This lesson climbs the ladder of models that do that, from a lookup list of known names, to a probabilistic model that counts label sequences, to a CRF that uses hand-made clues like capital letters, to BERT. Under "Use it" all of them run on the same standard news benchmark, so you can see exactly what each step bought, and a small modern model finds entity types you name on the spot.

"Apple sued Google over its iPhone search deal in the US." Five entities: Apple (ORG), Google (ORG), iPhone (PRODUCT), search deal (maybe), US (GPE). A good NER system extracts all of them with correct types. A bad one misses iPhone, confuses Apple the fruit with Apple the company, and labels "US" as a PERSON.

NER is the workhorse underneath every structured extraction pipeline. Resume parsing, compliance log scanning, medical record anonymization, search query understanding, grounding for chatbot responses, legal contract extraction. You never quite see it; you always depend on it.

This lesson walks the classical path (rule-based, HMM, CRF) into the modern one (BiLSTM-CRF, then transformers). Each step solves a specific limitation of the one before it. The pattern is the lesson.

The idea

BIO tagging (or BILOU) turns entity extraction into a sequence-labeling problem. Label each token with B-TYPE (beginning of entity), I-TYPE (inside entity), or O (outside any entity).

Apple    B-ORG
sued     O
Google   B-ORG
over     O
its      O
iPhone   B-PRODUCT
search   O
deal     O
in       O
the      O
US       B-GPE
.        O

Multi-token entities chain: New B-GPE, York I-GPE, City I-GPE. A model that understands BIO can extract arbitrary spans.

The architecture progression:

  • Rule-based. Regex + gazetteer lookups. High precision on known entities, zero coverage on new ones.
  • HMM. Hidden Markov Model. Emission probability of token given tag, transition probability of tag-to-tag. Viterbi decode. Trained on labeled data.
  • CRF. Conditional Random Field. Like HMM but discriminative, so you can mix arbitrary features (word shape, capitalization, neighboring words). Still a solid choice when labelled data is modest and inference must be cheap.
  • BiLSTM-CRF. Neural features instead of hand-crafted. LSTM reads the sentence both directions, CRF layer on top enforces consistent tag sequences.
  • Transformer-based. Fine-tune BERT with a token-classification head. Best accuracy. Most compute.

The same idea as a formula
HMM versus CRF

Both score a whole tag sequence y1:n​ for a sentence x1:n​, and both decode with Viterbi. They differ in what they model.

An HMM is generative: it models how the words and tags are produced together,

P(x,y)=t=1∏n​P(yt​∣yt−1​)P(xt​∣yt​)

Each word depends only on its own tag, so the model cannot use clues like "the next word is Inc." or "this word is capitalised" without breaking its own probability rules.

A linear-chain CRF is discriminative: it models only the tags given the words, using any features of the whole sentence,

P(y∣x)=Z(x)1​exp(t=1∑n​[θ⊤ϕ(yt​,x,t)+Ayt−1​,yt​​]),Z(x)=y′∑​exp(⋯)

Here ϕ is a feature vector (the dictionaries in to_features: word, shape, suffix, neighbours), θ their learned weights for each tag, and A a learned tag-to-tag transition matrix. Z(x) sums over every possible tag sequence; the forward algorithm computes it in O(nK2) time for K tags, the same dynamic programming as Viterbi with sums in place of maxima. Training maximises ∑logP(y∣x) minus the c1 (L1) and c2 (L2) penalties, a convex problem solved here with L-BFGS. Under "Use it" you can see the learned A: large negative weights wherever BIO forbids a move.

Step 1 · BIO tagging helpers

def spans_to_bio(tokens, spans):
    labels = ["O"] * len(tokens)
    for start, end, label in spans:
        labels[start] = f"B-{label}"
        for i in range(start + 1, end):
            labels[i] = f"I-{label}"
    return labels


def bio_to_spans(tokens, labels):
    spans = []
    current = None
    for i, label in enumerate(labels):
        if label.startswith("B-"):
            if current:
                spans.append(current)
            current = (i, i + 1, label[2:])
        elif label.startswith("I-") and current and current[2] == label[2:]:
            current = (current[0], i + 1, current[2])
        else:
            if current:
                spans.append(current)
                current = None
    if current:
        spans.append(current)
    return spans

Worked example
Scoring entities, not words

NER is scored on whole entities: a predicted span counts only if its start, end and type all match. Say the gold spans for the sentence above are (0,1,ORG) (2,3,ORG) (4,5,PRODUCT) and a model predicts (0,1,ORG) (2,3,ORG) (4,5,ORG) (6,7,LOC).

  • Correct: the two ORG spans, so tp=2.
  • Predicted but wrong: (4,5,ORG) (right span, wrong type) and (6,7,LOC), so fp=2.
  • Gold but missed: (4,5,PRODUCT), so fn=1.
  • Precision 2/4=0.50, recall 2/3=0.67, F1 =2⋅0.50⋅0.67/(0.50+0.67)=0.57.

A type error is punished twice, once as a false positive and once as a missed entity, even though the model found the right words. All the scores under "Use it" are computed this way, with the lesson's bio_to_spans.

Step 2 · hand-crafted features

For classical (non-neural) NER, features are the game. Useful ones:

def token_features(token, prev_token, next_token):
    return {
        "lower": token.lower(),
        "is_upper": token.isupper(),
        "is_title": token.istitle(),
        "has_digit": any(c.isdigit() for c in token),
        "suffix_3": token[-3:].lower(),
        "shape": word_shape(token),
        "prev_lower": prev_token.lower() if prev_token else "<BOS>",
        "next_lower": next_token.lower() if next_token else "<EOS>",
    }


def word_shape(word):
    out = []
    for c in word:
        if c.isupper():
            out.append("X")
        elif c.islower():
            out.append("x")
        elif c.isdigit():
            out.append("d")
        else:
            out.append(c)
    return "".join(out)

word_shape("iPhone") returns xXxxxx. word_shape("USA-2024") returns XXX-dddd. Capitalization patterns are high-signal for proper nouns.

Step 3 · a simple rule-based + dictionary baseline

ORG_GAZETTEER = {"Apple", "Google", "Microsoft", "OpenAI", "Meta", "Amazon", "Netflix"}
GPE_GAZETTEER = {"US", "USA", "UK", "India", "Germany", "France"}
PRODUCT_GAZETTEER = {"iPhone", "Android", "Windows", "ChatGPT", "Claude"}


def rule_based_ner(tokens):
    labels = []
    for token in tokens:
        if token in ORG_GAZETTEER:
            labels.append("B-ORG")
        elif token in GPE_GAZETTEER:
            labels.append("B-GPE")
        elif token in PRODUCT_GAZETTEER:
            labels.append("B-PRODUCT")
        else:
            labels.append("O")
    return labels

Production gazetteers have millions of entries scraped from Wikipedia and DBpedia. Coverage is good. Disambiguation (Apple the company vs the fruit) is terrible. That is why statistical models won.

Check your mental model
  • ✗ "A big enough list of names solves NER."
    ✓ Lists cannot handle names they lack (most names in tomorrow's news) or names that mean different things ("Jordan" the country, the river, the player). Under "Use it", a list of every entity in the training data finds only about half the test entities.
  • ✗ "Per-word accuracy is a good NER metric."
    ✓ Most words are O, so a model that tags everything O gets over 80% of words right and finds no entities. Score whole spans.
  • ✗ "BIO labels are independent decisions."
    ✓ They constrain each other: I-ORG can only follow B-ORG or I-ORG. Models that score the whole sequence (HMM, CRF) can learn that; a classifier that labels each word alone cannot.

Step 4 · the CRF step (sketch, not full impl)

Full CRF from scratch in 50 lines is not enlightening without the probability-theory foundations. Use sklearn-crfsuite instead:

import sklearn_crfsuite
import pyarrow.parquet as pq
from huggingface_hub import hf_hub_download

# CoNLL-2003: English Reuters news, 14,041 training sentences, four types (PER, ORG, LOC, MISC)
TAGS = ["O", "B-PER", "I-PER", "B-ORG", "I-ORG", "B-LOC", "I-LOC", "B-MISC", "I-MISC"]
conll = lambda split: pq.read_table(hf_hub_download("eriktks/conll2003", f"conll2003/{split}/0000.parquet",
                                                    repo_type="dataset", revision="refs/convert/parquet")).to_pydict()
conll_train, conll_test = conll("train"), conll("test")
sentences_tokenized = conll_train["tokens"]
bio_labels_train = [[TAGS[t] for t in s] for s in conll_train["ner_tags"]]

def to_features(tokens):
    out = []
    for i, tok in enumerate(tokens):
        prev = tokens[i - 1] if i > 0 else ""
        nxt = tokens[i + 1] if i + 1 < len(tokens) else ""
        out.append({
            "word.lower()": tok.lower(),
            "word.isupper()": tok.isupper(),
            "word.istitle()": tok.istitle(),
            "word.isdigit()": tok.isdigit(),
            "word.suffix3": tok[-3:].lower(),
            "word.shape": word_shape(tok),
            "prev.word.lower()": prev.lower(),
            "next.word.lower()": nxt.lower(),
            "BOS": i == 0,
            "EOS": i == len(tokens) - 1,
        })
    return out


crf = sklearn_crfsuite.CRF(algorithm="lbfgs", c1=0.1, c2=0.1, max_iterations=100, all_possible_transitions=True)
X_train = [to_features(s) for s in sentences_tokenized]
crf.fit(X_train, bio_labels_train)
print(f"trained on {len(X_train):,} sentences;", sentences_tokenized[0], bio_labels_train[0])

c1 and c2 are L1 and L2 regularization. all_possible_transitions=True lets the model learn illegal sequences (e.g., I-ORG after O) are unlikely, which is how a CRF enforces BIO consistency without you writing the constraint.

Step 5 · what a BiLSTM-CRF adds

Features become learned. Inputs: token embeddings (GloVe or fastText). LSTM reads left-to-right and right-to-left. Concatenated hidden states go through a CRF output layer. The CRF still enforces tag-sequence consistency; the LSTM replaces hand-crafted features with learned ones.

import torch
import torch.nn as nn


class BiLSTM_CRF_Head(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, n_labels):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, bidirectional=True, batch_first=True)
        self.fc = nn.Linear(hidden_dim * 2, n_labels)

    def forward(self, token_ids):
        e = self.embed(token_ids)
        h, _ = self.lstm(e)
        emissions = self.fc(h)
        return emissions

For the CRF layer, use torchcrf.CRF (pip install pytorch-crf). The gain over hand-crafted CRF is measurable but smaller than you expect unless you have tens of thousands of labeled sentences.

Four generations on one benchmark

Every model on the first 1,000 sentences of the CoNLL-2003 test set, scored on whole entities with the lesson's bio_to_spans. The gazetteer is every entity string seen in training, matched longest-first. The HMM is built here from counts, with Viterbi decoding and the word's word_shape standing in for words it never saw. The CRF is the one trained above. BERT is dslim/bert-base-NER, fine-tuned on CoNLL-2003's training set.

import time
import re
import numpy as np
import torch
import matplotlib.pyplot as plt
from collections import Counter, defaultdict
from transformers import AutoTokenizer, AutoModelForTokenClassification
torch.set_num_threads(2)

test_tokens = conll_test["tokens"][:1000]
test_gold = [[TAGS[t] for t in s] for s in conll_test["ner_tags"][:1000]]
train_spans = {(tuple(t[s:e]), lab) for t, y in zip(sentences_tokenized, bio_labels_train) for s, e, lab in bio_to_spans(t, y)}
seen_strings = {s for s, _ in train_spans}

def score(preds, subset=None):
    tp = fp = fn = 0
    for toks, g, p in zip(test_tokens, test_gold, preds):
        G, P = set(bio_to_spans(toks, g)), set(bio_to_spans(toks, p))
        if subset is not None:      # keep only gold spans whose text was / was not seen in training
            G = {x for x in G if (tuple(toks[x[0]:x[1]]) in seen_strings) == subset}
            P = {x for x in P if (tuple(toks[x[0]:x[1]]) in seen_strings) == subset}
        tp, fp, fn = tp + len(G & P), fp + len(P - G), fn + len(G - P)
    prec, rec = tp / max(tp + fp, 1), tp / max(tp + fn, 1)
    return prec, rec, 2 * prec * rec / max(prec + rec, 1e-9)

# 1. gazetteer: most frequent type for each entity string in training, longest match first
gaz = defaultdict(Counter)
for s, lab in train_spans:
    gaz[s][lab] += 1
gaz = {s: c.most_common(1)[0][0] for s, c in gaz.items()}
def gazetteer_tag(toks):
    labels, i = ["O"] * len(toks), 0
    while i < len(toks):
        for n in range(min(8, len(toks) - i), 0, -1):
            if tuple(toks[i:i + n]) in gaz:
                labels[i:i + n] = spans_to_bio(toks[i:i + n], [(0, n, gaz[tuple(toks[i:i + n])])]); i += n; break
        else:
            i += 1
    return labels

# 2. HMM: transition and emission counts, Viterbi decoding
K, ix = len(TAGS), {t: k for k, t in enumerate(TAGS)}
trans, start, tag_n = np.ones((K, K)), np.ones(K), np.zeros(K)
emit, word_n = defaultdict(lambda: np.zeros(K)), Counter(w for s in sentences_tokenized for w in s)
for toks, labs in zip(sentences_tokenized, bio_labels_train):
    k = [ix[l] for l in labs]; start[k[0]] += 1
    for a, b in zip(k, k[1:]):
        trans[a, b] += 1
    for w, a in zip(toks, k):
        emit[w][a] += 1; tag_n[a] += 1
short_shape = lambda w: re.sub(r"(.)\1+", r"\1", word_shape(w))       # "Xxxxx" -> "Xx", "dddd" -> "d"
rare_shape, rare_n = defaultdict(lambda: np.zeros(K)), np.zeros(K)       # unseen words behave like words seen once
for toks, labs in zip(sentences_tokenized, bio_labels_train):
    for w, l in zip(toks, labs):
        if word_n[w] == 1:
            rare_shape[short_shape(w)][ix[l]] += 1; rare_n[ix[l]] += 1
log_trans, log_start = np.log(trans / trans.sum(1, keepdims=True)), np.log(start / start.sum())
def log_emit(w):
    if w in emit:
        return np.log((emit[w] + 0.01) / (tag_n + 0.01 * len(emit)))
    return np.log((rare_n + 1) / (tag_n + K)) + np.log((rare_shape[short_shape(w)] + 0.1) / (rare_n + 0.1 * len(rare_shape)))
def viterbi(toks):
    best, back = log_start + log_emit(toks[0]), []
    for w in toks[1:]:
        cand = best[:, None] + log_trans
        back.append(cand.argmax(0)); best = cand.max(0) + log_emit(w)
    path = [int(best.argmax())]
    for b in reversed(back):
        path.append(int(b[path[-1]]))
    return [TAGS[k] for k in reversed(path)]

# 4. BERT fine-tuned on CoNLL-2003: label of each word's first sub-word
bert_tok = AutoTokenizer.from_pretrained("dslim/bert-base-NER")
bert = AutoModelForTokenClassification.from_pretrained("dslim/bert-base-NER").eval()
def bert_tag_all(sents, batch=64):
    out = []
    for i in range(0, len(sents), batch):
        enc = bert_tok(sents[i:i + batch], is_split_into_words=True, return_tensors="pt", padding=True, truncation=True)
        with torch.no_grad():
            ids = bert(**enc).logits.argmax(-1)
        for b, toks in enumerate(sents[i:i + batch]):
            labels, done = ["O"] * len(toks), set()
            for pos, w in enumerate(enc.word_ids(b)):
                if w is not None and w not in done:
                    done.add(w); labels[w] = bert.config.id2label[int(ids[b, pos])]
            out.append(labels)
    return out

results = {}
for name, tagger in [("gazetteer", lambda S: [gazetteer_tag(t) for t in S]), ("HMM", lambda S: [viterbi(t) for t in S]),
                     ("CRF", lambda S: crf.predict([to_features(t) for t in S])), ("BERT", bert_tag_all)]:
    t0 = time.time(); preds = tagger(test_tokens); ms = (time.time() - t0) / len(test_tokens) * 1000
    results[name] = (score(preds), score(preds, True), score(preds, False), ms)
n_seen = sum((tuple(t[s:e]) in seen_strings) for t, g in zip(test_tokens, test_gold) for s, e, _ in bio_to_spans(t, g))
n_all = sum(len(bio_to_spans(t, g)) for t, g in zip(test_tokens, test_gold))
print(f"{n_all} gold entities in 1,000 test sentences; {n_seen / n_all:.0%} of them appear verbatim in training")
print(f"{'':10s}{'precision':>10s}{'recall':>8s}{'F1':>7s}   F1 seen  F1 unseen   ms/sentence")
for name, ((p, r, f), seen, unseen, ms) in results.items():
    print(f"{name:10s}{p:10.1%}{r:8.1%}{f:7.1%}   {seen[2]:7.1%}  {unseen[2]:9.1%}   {ms:11.2f}")

fig, ax = plt.subplots(figsize=(6.5, 3.4))
x = np.arange(len(results))
ax.bar(x - 0.2, [v[1][2] for v in results.values()], 0.38, label="entity seen in training", color="#474d9a")
ax.bar(x + 0.2, [v[2][2] for v in results.values()], 0.38, label="new entity", color="#b24a1d")
ax.set_xticks(x, list(results)); ax.set_ylabel("entity F1"); ax.set_ylim(0, 1)
ax.legend(frameon=False, fontsize=8); ax.grid(axis="y", alpha=0.3)
ax.set_title("Each generation mostly improves on names it has never seen", fontsize=9)
plt.tight_layout(); plt.show()

Half the test entities (53%) appear verbatim in training, and that split explains the table. The gazetteer can only find names it already has, so its F1 on new entities is zero by construction and its recall is under half. The HMM, using only label-sequence counts and the shape of unknown words, jumps to about 79% overall; on names seen in training it is even slightly ahead of the CRF. The CRF's hand-made features (capitalisation, suffixes, neighbouring words) pay off where it matters, on new names (71% against 64%). BERT, which brings knowledge from pretraining on billions of words, reaches about 92% overall and 89% even on new names. Speed runs the other way: from a hundredth of a millisecond per sentence to about 45 ms on two CPU cores, thousands of times slower.

LLM-based NER (the 2026 option)

Zero-shot and few-shot NER, with LLMs or with small open-type models, is now a practical starting point. On a standard benchmark it usually scores below a fine-tuned model, but when labelled data is scarce or the entity types are new, it is often good enough, and it works on day one.

  • Zero-shot prompting. Give the LLM a list of entity types and an example schema. Ask for JSON output. Works out of the box; accuracy is moderate on novel domains.
  • Small open-type models (GLiNER). A ~200M-parameter encoder that takes the entity types as plain-text labels at inference time ("drug", "dose", "symptom") and runs on a CPU. GLiNER (NAACL 2024) and GLiNER2 (2025, which adds classification and structured extraction) are the usual middle ground between a fixed-type model and an LLM; one runs under "Use it".
  • Multi-stage prompting. Split the task: first extract candidate spans, then assign types and have the model check its own answers. FETA ("First Extract, Tag Afterwards", 2026) reports state-of-the-art biomedical NER this way with general-purpose LLMs.
  • Dynamic prompting with RAG. Retrieve the most similar labeled examples from a small annotated seed set for every inference call; build the few-shot prompt on the fly. On biomedical NER with GPT-4 and Llama 3, this raised average F1 by about 7% (5-shot) and 6% (10-shot) over a fixed set of examples (Ge et al., 2025).
  • Per-entity-type decomposition. For long documents, a single call that extracts all entity types at once loses recall as length grows. Run one extraction pass per entity type. Higher inference cost, substantially higher accuracy. This is the standard pattern for clinical notes and legal contracts.

A sensible starting point: try a zero-shot model first (GLiNER on a CPU, or an LLM with a JSON schema), score it on a hundred hand-labelled examples, and fine-tune only if that falls short. For high-volume, fixed-type extraction, a fine-tuned encoder like the BERT model under "Use it" is still faster, cheaper and usually more accurate.

Where classical NER still wins

Even with LLMs available, classical NER wins when:

  • Latency budget is under 50ms.
  • You have thousands of labeled examples and a fixed set of types, and need the highest accuracy per millisecond.
  • The domain has a stable ontology where a pretrained CRF or BiLSTM transfers well.
  • Regulatory constraints require an on-prem, non-generative model.

Where it falls apart

  • Domain shift. A model trained on news (CoNLL-2003) loses much of its accuracy on legal contracts, tweets or clinical notes, where both the names and the writing style differ. Fine-tune on your domain, or start from a zero-shot model.
  • Nested entities. "Bank of America Tower" is simultaneously an ORG and a FACILITY. Standard BIO cannot represent overlapping spans. You need nested NER (multi-pass or span-based models).
  • Long entities. "United States Federal Deposit Insurance Corporation." Token-level models sometimes split this. Use aggregation_strategy or post-process.
  • Sparse types. Medical NER labels like DRUG_BRAND, ADVERSE_EVENT, DOSE. General-purpose models have no idea. Scispacy and BioBERT are the starting points there.
Recap
What to keep from this lesson
  • BIO labels turn span extraction into one label per token; evaluate on whole spans with precision, recall and F1.
  • Gazetteers are precise but blind to new names; every learned model's real test is entities it never saw.
  • HMMs score whole label sequences; CRFs add arbitrary features and learn BIO constraints from data.
  • Fine-tuned BERT is the accuracy baseline for fixed types; its types are fixed by its training data.
  • Zero-shot models (GLiNER, LLMs with a schema) handle new types on day one; measure them before trusting them.
Industry practice
What's current (2024–2026)
  • Three production routes. Fine-tuned encoders (spaCy transformer pipelines, Hugging Face token classification) for high volume; GLiNER models that take entity types as text at run time for zero-shot extraction on CPUs; and LLMs with a JSON schema for complex or rare types.
  • PII detection. Microsoft Presidio combines NER models and rules to find and redact personal data, a common pre-processing step before sending text to an LLM.
  • Cloud APIs. AWS Comprehend, Azure AI Language and Google Cloud Natural Language provide managed NER with custom-entity training.

Solutions

SolutionP1 · About half

Recall is about 50% on the full test set (the run on the first 1,000 sentences shows the same pattern), and precision only about 70%. Many test entities are names that never appeared in training, and some known strings carry a different type in a new sentence: a city in one story is a sports team ("Chelsea", "Leeds") in the next. A list cannot see context, which is why statistical models won.

SolutionB1 · The entity silently disappears

bio_to_spans returns []. An I-ORG only extends a span that is already open; with no B-ORG before it, the function falls into the else branch and starts nothing, so a two-word organisation is dropped without any error. Other tools treat this case differently (seqeval by default starts a new entity at an orphan I-), so the same predictions can score differently depending on the scorer. The better fix is upstream: decode with a model that scores whole sequences, like the CRF, which learned large negative weights for O → I-X.
