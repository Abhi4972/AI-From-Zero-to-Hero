In plain words first
The idea in one line

An image is a grid of patches. A sentence is a grid of tokens. The same transformer eats both.

Terms you'll hear
Term What people say What it actually means
Patch "The vision-transformer token" Flat vector of pixel values for a P × P × C region of the image.
Patchify "Chop + flatten" Slice image into non-overlapping patches, flatten each to a vector.
[CLS] token "The image summary" Prepended learnable token; its final embedding is the image representation.
Inductive bias "What the model assumes" ViT has fewer priors than CNNs; needs more data to make up the gap.
DINOv2 "Self-supervised ViT" Trained without labels using image augmentation + momentum teacher. Best general image features in 2026.
SigLIP "CLIP's successor" ViT + text encoder trained with sigmoid contrastive loss; better than CLIP on matched compute.
Swin "Windowed ViT" Hierarchical ViT with local attention + shifted windows; sub-quadratic.
Register tokens "2023 trick" A few extra learnable tokens that soak up attention sinks; improves DINOv2 features.

The problem

In plain words first

A vision transformer treats a picture like a sentence. It cuts the image into small squares (patches), flattens each square's pixels into one long list of numbers, and multiplies that list by a learned matrix to get a vector, one "word" per patch. A learned summary vector is put in front, position information is added, and an ordinary transformer encoder, the same as BERT's, processes the sequence. Nothing in it knows that patches next to each other are neighbours; it has to learn that from data, which is why ViTs need large datasets or self-supervised pretraining. This lesson runs the lesson's patchify code, checks on a real ViT that "patchify plus one matrix" is exactly the convolution libraries use, counts where its 86 million parameters sit, classifies real photos, and shows what DINOv2's patch features have learned without any labels. Nothing is trained.

Before 2020, computer vision meant convolutions. Every SOTA on ImageNet, COCO, and detection benchmarks used a CNN backbone. Transformers were for language.

Dosovitskiy et al. (2020) — "An Image is Worth 16x16 Words" — showed you can drop the convolutions entirely. Slice an image into fixed-size patches, linearly project each patch into an embedding, feed the sequence to a vanilla transformer encoder. At sufficient scale (ImageNet-21k pretraining or bigger), ViT matches or beats ResNet-based models.

ViT was the start of a broader pattern in 2026: one architecture, many modalities. Whisper tokenizes audio. ViT tokenizes images. Action tokens for robotics. Pixel tokens for video. The transformer doesn't care — feed it a sequence and it learns.

By 2026, ViT and its descendants (DeiT, Swin, DINOv2, ViT-22B, SAM 3) own most of vision. CNNs still win on edge devices and latency-sensitive tasks. Everything else has a ViT somewhere in the stack.

The idea

Idea 1 · Step 1 — patchify

Split a H × W × C image into an N × (P·P·C) sequence of flat patches. Typical setup: 224 × 224 image, 16 × 16 patches → 196 patches of 768 values each.

image (224, 224, 3) → 14 × 14 grid of 16x16x3 patches → 196 vectors of length 768

Patch size is the lever. Smaller patches = more tokens, better resolution, quadratic attention cost. Larger patches = coarser, cheaper.

Idea 2 · Step 2 — linear embedding

A single learned matrix projects each flat patch to d_model. Equivalent to a convolution of kernel size P and stride P. In PyTorch this is literally nn.Conv2d(C, d_model, kernel_size=P, stride=P) — a 2-line implementation.

Idea 3 · Step 3 — prepend [CLS] token, add positional embeddings

  • Prepend a learnable [CLS] token. Its final hidden state is the image representation used for classification.
  • Add learnable positional embeddings (ViT-original) or sinusoidal 2D (later variants).
  • In 2024+ RoPE extended to 2D for position, sometimes without explicit embeddings.

Idea 4 · Step 4 — standard transformer encoder

Stack L blocks of LayerNorm → Self-Attention → + → LayerNorm → MLP → +. Identical to BERT. No vision-specific layers. This is the pedagogical punchline of the paper.

Idea 5 · Step 5 — head

For classification: take [CLS] hidden state → linear → softmax. For DINOv2 or SAM, discard [CLS], use the patch embeddings directly.

Idea 6 · Variants that mattered

Model Year Change
ViT 2020 The original. Fixed patch size, full global attention.
DeiT 2021 Distillation; trainable on ImageNet-1k only.
Swin 2021 Hierarchical with shifted windows. Fixed sub-quadratic cost.
DINOv2 2023 Self-supervised (no labels). Best general vision features.
ViT-22B 2023 22B params; scaling laws apply.
SigLIP 2023 ViT + language pair, sigmoid contrastive loss.
SAM 3 2025 Segment anything from text or examples; a ViT backbone plus promptable detector and mask decoder.

Idea 7 · Why it took a while

ViT needs a lot of data to match CNNs because it has none of the CNN inductive biases (translation invariance, locality). Without >100M labeled images or strong self-supervised pretraining, CNNs still win at matched compute. DeiT fixed this in 2021 with distillation tricks; DINOv2 fixed it permanently in 2023 with self-supervision.

The same idea as a formula

Patchify. An image of H×W pixels with C channels, cut into P×P patches, becomes

N=PH​⋅PW​ patches,xp​∈RP2C each (flattened in raster order)

Embed, add a class token and positions.

z0​=[xcls​; x1​E; x2​E; …; xN​E]+Epos​,E∈RP2C×D, Epos​∈R(N+1)×D

Multiplying each flattened patch by E is exactly a convolution with kernel size P and stride P whose D filters are the columns of E (the run under "Use it" checks it to 10−5).

Encode and classify. L pre-norm encoder blocks, the same as BERT's, then y^​=softmax(WLN(zLcls​)).

Cost. Attention is O(N2D) per layer and N grows with the square of resolution over patch size: doubling the resolution, or halving P, multiplies N by 4 and attention cost by 16.

Parameters. Per block 4D2 (attention) +8D2 (MLP of width 4D), plus biases and norms; ViT-Base (D=768, L=12) has $12 \times 12 \times 768^2 \approx 85$M in its blocks, and the patch embedding only $768 \times 768 \approx 0.6$M.

Missing priors. A convolution shares weights across positions and looks only locally, by construction. A ViT's attention can link any two patches from the first layer, and Epos​ starts random: locality must be learned from data, which is why ViTs need far more images, or self-supervised pretraining, to match CNNs.

Worked example
A ViT's input by hand

A 224×224 RGB image with P=16:

  • Grid 14×14, so N=196 patches, each 16×16×3=768 numbers.
  • With the class token the sequence has 197 vectors of width D=768 (ViT-Base).
  • Patch embedding: 768×768+768=590,592 parameters; position embeddings 197×768=151,296.
  • At P=14 (DINOv2, CLIP ViT-L) the grid is 16×16, N=256; at 448×448 with P=14 it is 32×32=1,024 patches, and attention costs (1024/256)2=16 times more than at 224.

Step 2 · patchify

def patchify(image, P):
    H = len(image)
    W = len(image[0])
    patches = []
    for i in range(0, H, P):
        for j in range(0, W, P):
            patch = []
            for di in range(P):
                for dj in range(P):
                    patch.extend(image[i + di][j + dj])
            patches.append(patch)
    return patches

Raster order: row-major across the grid. Every ViT uses this ordering.

Step 3 · linear embed

Multiply each flat patch by a random (patch_flat_size, d_model) matrix. Verify output shape is (N_patches + 1, d_model) after prepending [CLS].

Step 4 · count parameters for a realistic ViT

Print the param count for ViT-Base: 12 layers, 12 heads, d=768, patch=16. Compare to ResNet-50 (~25M). ViT-Base lands at ~86M. ViT-Large ~307M. ViT-Huge ~632M.

import pyarrow.parquet as pq
from PIL import Image

                          "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset")

with torch.no_grad():
    out = model(**inputs).last_hidden_state   # (1, 197, 768): [CLS] + 196 patches

DINOv2 embeddings are a common default for image features. Freeze the backbone, train a tiny head. Works for classification, retrieval, detection and depth. DINOv2's patch features are especially strong on dense tasks (segmentation, depth, correspondence), where CLIP-style image–text features are weaker; for anything involving text, CLIP or SigLIP features are the usual choice.

Patch-size picking. Many models use 16×16 (ViT-B/16, and SAM's encoder on 1024×1024 inputs); DINOv2, CLIP ViT-L and many very large models use 14×14; dense prediction benefits from smaller patches or higher input resolution, at quadratic attention cost.

Inside a real ViT-Base

Using the model and photo loaded above: the patch embedding recomputed as patchify plus one matrix, the parameters grouped by component, then the ImageNet-fine-tuned ViT-Base on six Imagenette photos.

import torch.nn.functional as F
from transformers import ViTForImageClassification

# 1. The patch embedding is a convolution with kernel = stride = 16, i.e. one matrix applied to each flat patch.
conv = model.embeddings.patch_embeddings.projection                  # Conv2d(3, 768, kernel_size=16, stride=16)
x = inputs.pixel_values
by_conv = conv(x).flatten(2).transpose(1, 2)                         # (1, 196, 768)
patches = F.unfold(x, kernel_size=16, stride=16).transpose(1, 2)     # (1, 196, 768): each row one flat 16x16x3 patch
by_matmul = patches @ conv.weight.reshape(768, -1).T + conv.bias
print(f"patchify + one matrix vs Conv2d: max difference {(by_conv - by_matmul).abs().max():.1e}")

# 2. Where ViT-Base's 86M parameters are.
groups = {}
for name, p in model.named_parameters():
    key = ("patch embedding" if "patch_embeddings" in name else "position embeddings + CLS" if "embeddings" in name else
           "attention" if "attn" in name or "attention" in name else "MLP" if "mlp" in name else
           "pooler" if "pooler" in name else "norms")
    groups[key] = groups.get(key, 0) + p.numel()
total = sum(groups.values())
for k, v in groups.items():
    print(f"  {k:26s} {v / 1e6:6.2f} M  {v / total:5.1%}")
print(f"  {'total':26s} {total / 1e6:6.2f} M")

# 3. The ImageNet-1k fine-tuned version classifies a few Imagenette photos.
clf = ViTForImageClassification.from_pretrained("google/vit-base-patch16-224").eval()
proc = ViTImageProcessor.from_pretrained("google/vit-base-patch16-224")
names = ["tench", "English springer", "cassette player", "chain saw", "church", "French horn", "garbage truck", "gas pump", "golf ball", "parachute"]
print("\ntrue class          top prediction (probability)")
for row in range(0, table.num_rows, table.num_rows // 6)[:6]:
    im = Image.open(io.BytesIO(table.column("image")[row].as_py()["bytes"])).convert("RGB")
    with torch.no_grad():
        p = clf(**proc(im, return_tensors="pt")).logits.softmax(-1)[0]
    print(f"{names[table.column('label')[row].as_py()]:18s}  {clf.config.id2label[int(p.argmax())][:40]} ({p.max():.2f})")

What self-supervised patch features know

DINOv2 (small, with register tokens) on four photos at 448×448, giving 32×32=1,024 patch vectors per image. For each image, PCA keeps the three main directions of variation among its patch vectors, displayed as red, green and blue.

Show the code that draws this 
import numpy as np
import matplotlib.pyplot as plt
from transformers import AutoImageProcessor, AutoModel

# DINOv2 (trained without labels): the patch tokens themselves, reduced to 3 numbers each with PCA and shown as colours.
repo = "facebook/dinov2-with-registers-small"
proc = AutoImageProcessor.from_pretrained(repo, size={"shortest_edge": 448}, crop_size={"height": 448, "width": 448})
dino = AutoModel.from_pretrained(repo).eval()
skip = 1 + dino.config.num_register_tokens                        # CLS + 4 register tokens come first
rows = (0, 1200, 3000, 3600)
feats, shown = [], []
for r in rows:
    im = Image.open(io.BytesIO(table.column("image")[r].as_py()["bytes"])).convert("RGB")
    enc = proc(im, return_tensors="pt")
    with torch.no_grad():
        feats.append(dino(**enc).last_hidden_state[0, skip:])        # 1024 patches = 32 x 32 grid of 14-pixel patches
    px = enc.pixel_values[0].numpy().transpose(1, 2, 0)
    shown.append(np.clip(px * np.array(proc.image_std) + np.array(proc.image_mean), 0, 1))
colours, shares = [], []
for f in feats:                                                       # PCA of each image's own 1024 patch vectors
    X = f.numpy() - f.numpy().mean(0)
    _, s, Vt = np.linalg.svd(X, full_matrices=False)
    P = X @ Vt[:3].T
    colours.append((P - P.min(0)) / (P.max(0) - P.min(0)))
    shares.append((s[:3] ** 2).sum() / (s ** 2).sum())
print("1024 patch vectors of size 384 per image; share of their variance in the first 3 principal components:",
      ", ".join(f"{v:.0%}" for v in shares))
fig, axes = plt.subplots(2, len(rows), figsize=(10, 5.2))
for k in range(len(rows)):
    axes[0, k].imshow(shown[k]); axes[1, k].imshow(colours[k].reshape(32, 32, 3))
for a in axes.ravel(): a.axis("off")
plt.suptitle("DINOv2 patch features, first three principal components as RGB per image", fontsize=10)
plt.tight_layout(); plt.show()

Reading this output

The colours follow the content, not the pixels. In the church photo the sky, the roof, the stone wall and the grass with gravestones each get their own colour; the golf balls are one colour and their printed labels another; the French horn's bell, tubing and the background separate, although bell and tubing are the same brass colour. Three components hold about half of the variance of the 384-number patch vectors. Nobody labelled sky or roof: DINOv2 learned these groupings by matching views of the same image (Lesson 4.17). This is why frozen DINOv2 features work so well for segmentation and depth with only a small trained head.

Break it on purpose

In patchify, flatten each patch column by column (image[i + di][j + dj] with the loops over di and dj swapped) while the pretrained embedding matrix expects row-major patches. Every shape is unchanged and the model still outputs a prediction. What happens, and why would the same bug be invisible when training a ViT from scratch? (Solution B1.)

Industry practice
What's current (2024–2026)
  • ViT backbones under most vision products. ViT vision towers feed the vision-language models (SigLIP in Gemma 3, CLIP-style encoders in Qwen2.5-VL and Llama 4), DINOv2 and DINOv3 provide frozen features for segmentation, depth and retrieval, and SAM 2 and SAM 3 segment with ViT encoders.
  • Registers and high resolution. Register tokens (DINOv2 with registers) remove attention artefacts in large ViTs; current models process variable resolutions and aspect ratios (NaViT-style packing, Qwen2-VL's dynamic resolution) instead of fixed 224×224 crops.
  • CNNs where latency rules. Mobile and embedded deployments still favour CNNs or hybrids (MobileNetV4, YOLO detectors) when milliseconds and power matter.

Sources: DINOv2, DINOv3, SigLIP 2, SAM 3, Vision Transformers Need Registers, Ultralytics YOLO.

Recap
What to keep from this lesson
  • Patchify an image into N=HW/P2 flat patches, embed each with one matrix (a stride-P convolution), add a class token and positions.
  • The rest is a standard transformer encoder; most parameters are in its MLPs.
  • Attention cost grows with N2: resolution and patch size are the main cost levers.
  • ViTs lack CNN priors, so they need large data or self-supervision; DINOv2's unlabeled features already separate objects and parts.

Given a vision task (classification / segmentation / detection / retrieval), image resolution, dataset size (labeled + unlabeled), and deployment target, output:

1. Backbone. One of: DINOv2 ViT-L/14 (default for retrieval/classification), SAM 3 encoder (segmentation), SigLIP (vision-language), ConvNeXt (latency-critical). One-sentence reason.
2. Patch size. 16 for standard classification at 224, 14 for DINOv2, 8 for dense prediction at high res. Flag sequence length `(H/P)^2 + 1` and attention cost `O(N^2)`.
3. Pretraining source. Checkpoint name. For small labeled sets (<10k): DINOv2 features frozen + linear probe. For >100k: fine-tune last blocks. State why.
4. Training recipe. Optimizer (AdamW), lr, augmentations (RandAug, MixUp, Random Erasing), label smoothing (0.1 typical), EMA.
5. Risk note. Data regime risk (too little data for full fine-tune), resolution mismatch (pretrain 224 → deploy 1024 without position interpolation), register-token absence (may hurt DINOv2 features).

Refuse to recommend training a ViT from scratch on less than 1M images — CNN baselines will win. Refuse to recommend patch size that yields sequence length > 4096 without explicit discussion of Flash Attention + hierarchical variants (Swin). Flag any deployment that changes input resolution without interpolating positional embeddings.

Solutions

SolutionP1 · The parts separate

They separate the scene's parts: sky, roof, wall and the grass with gravestones each come out in a distinct colour, with fairly sharp borders between them. Brightness alone would not do this (the roof and parts of the wall are similarly dark), and noise would show no regions at all. DINOv2 was trained only to give consistent features to different crops of the same image, and grouping patches by what they belong to turned out to be the best way to do that; the same PCA on the golf balls separates the balls from their labels.

SolutionB1 · Scrambled patches for a pretrained model

The pretrained embedding matrix E was learned for one pixel order. Flattening column-major transposes every patch, so each pixel is multiplied by the weight meant for a different pixel: the model sees every patch mirrored along its diagonal. A pretrained model's accuracy collapses, because none of its filters match. Training from scratch with the bug would work almost as well as without it, because E would simply learn the transposed filters: the order only has to be consistent between training and inference. That is why preprocessing code (pixel order, channel order, normalisation statistics) must be copied exactly from the model's own processor.
