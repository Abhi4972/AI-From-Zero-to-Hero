In plain words first
The idea in one line

WebArena tests web-agent capability across four self-hosted apps. OSWorld tests desktop-agent capability across Ubuntu, Windows, macOS. At release (2023–2024) both showed a big gap between best-in-class agents and humans. The gap is narrowing; the failure modes haven't changed.

The problem

In plain words first

A web agent operates a website the way a person does: it reads the page, clicks, types, and repeats until the task is done. A computer-use agent does the same on a whole desktop, from screenshots. WebArena and OSWorld are the standard tests. Their key design choice is execution-based evaluation: a task counts as done only if the application's state changed correctly (the order exists, the setting is saved), not because the agent or the page says so. They also count steps, because an agent that takes three times as many clicks as a person is slow and more likely to break something on the way. This lesson runs a small model as a web agent on a real page in a browser and grades it both ways.

Generalist agents can call tools. Can they drive a browser across 20 clicks to complete a shopping checkout? Can they configure a Linux box using only keyboard and mouse? These are the questions WebArena and OSWorld answer.

Idea 1 · WebArena (Zhou et al., ICLR 2024)

  • 812 long-horizon tasks across four self-hosted web apps: a shopping site, a forum, a GitLab-like dev tool, a business CMS.
  • Plus utilities: map, calculator, scratchpad.
  • Evaluation is execution-based via gym APIs — was the order placed, was the issue closed, was the CMS page updated?
  • At release: best GPT-4 agent hit 14.41% success vs human 78.24%.

The self-hosted framing matters — the benchmark is not flaky because the target apps are pinned and reproducible.

Idea 2 · Extensions

  • VisualWebArena — visually grounded tasks where success depends on interpreting images (screenshots as first-class observations).
  • TheAgentCompany (Dec 2024) — adds terminal + coding; more like a real remote-work environment.

Idea 3 · OSWorld (Xie et al., NeurIPS 2024)

  • 369 real computer tasks across Ubuntu, Windows, macOS.
  • Free-form keyboard and mouse control of real applications.
  • 1920×1080 screenshots as the observation.
  • At release: best model 12.24% vs human 72.36%.

Idea 4 · Primary failure modes

  1. GUI grounding. Pixel → element mapping. Models struggle to localize UI elements reliably in 1920×1080.
  2. Operational knowledge. Which menu has the setting, which keyboard shortcut, which preference pane. Knowledge tail that humans build over years.

Idea 5 · Follow-ups

  • OSWorld-G — 564-sample grounding suite + Jedi training set. Decomposes grounding from planning so you can measure them separately.
  • OSWorld-Human — manually curated gold action trajectories. Shows top agents use 1.4-2.7x more steps than necessary (the trajectory-efficiency gap).

Idea 6 · Why this matters

Claude computer use, OpenAI CUA, Gemini 2.5 Computer Use (Lesson 14.95) all train on workloads shaped by WebArena and OSWorld. The benchmarks are the target; the production models are the shipped answer.

Idea 7 · Where benchmarking goes wrong

  • Screenshot-only evals. OSWorld is screenshot-driven; evaluating an agent that uses DOM or accessibility APIs on OSWorld misses the grounding challenge.
  • Ignoring trajectory length. Scoring only success-rate misses the 1.4-2.7x step inefficiency OSWorld-Human surfaces.
  • Stale self-hosted apps. WebArena's apps pin specific versions; update without re-curation breaks comparability.

The same idea as a formula

Success is decided by a check on the final state sT​ of the environment, not on the agent's words: task i succeeds if checki​(sT​)=true, and the success rate is the mean over tasks.

Trajectory efficiency compares the agent's step count ki​ with a gold (human) trajectory of gi​ steps:

e=∑i​gi​∑i​ki​​.
OSWorld-Human reports e≈1.4 to 2.7 for top agents. Each extra step also costs time and is another chance to click the wrong thing: if each step goes wrong independently with probability q, a k-step run survives with probability (1−q)k.

Worked example
Two graders, one run
  • Task: buy the headphones. Gold trajectory: Add headphones, Checkout (2 steps).
  • The agent clicks Add headphones, Checkout, Checkout: 3 steps, e=1.5.
  • The order with exactly one pair of headphones exists, so the state check passes.
  • But the second Checkout replaced "Thank you! Order ord-001 placed." with "Your cart is empty", so a grader that reads the page message fails a task that was done.
  • With q=0.05 per step, a 2-step run survives with probability 0.952≈0.90 and an 8-step run with 0.958≈0.66: wasted steps cost success as well as time.
Check your mental model
  • ✗ "If the page says 'Thank you', the task succeeded."
    ✓ Only the application's state says that; messages can be stale or misleading either way.
  • ✗ "Success rate is the whole story."
    ✓ Steps over gold matter: extra steps cost time and add chances to break something.
  • ✗ "A web agent fails because it cannot find the button."
    ✓ Here it found the buttons easily and failed at knowing when to stop.
  • ✗ "Desktop benchmarks are solved."
    ✓ Short OSWorld tasks are near or above the human baseline; long workflows are not.

# A WebArena-style task in a real browser. The lesson's shopping app as a web page (Playwright + Chromium),
# three tasks, and Qwen2.5-0.5B-Instruct as the agent: each step it sees the page as text with numbered
# buttons and answers with one number to click, or DONE. Success is decided the WebArena way, by checking
# the app's state (the orders it placed), not by what the agent says. At most 8 steps per task.
import os, re, warnings
os.environ["HF_HUB_OFFLINE"] = "1"
warnings.filterwarnings("ignore")
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
from playwright.sync_api import sync_playwright
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct").eval()

SHOP = """<html><body><h1>Shop</h1><div id="items"></div><h2>Cart</h2><div id="cart"></div>
<button id="checkout">Checkout</button><p id="msg"></p><script>
const ITEMS = {"sku-001": ["headphones", 199], "sku-002": ["keyboard", 129], "sku-003": ["mouse", 59]};
window.shop = {cart: {}, orders: []};
function render() {
  document.getElementById("items").innerHTML = Object.entries(ITEMS).map(([s, [n, p]]) =>
    `<div>${n} $${p} <button id="add-${s}">Add ${n}</button></div>`).join("");
  document.getElementById("cart").innerHTML = Object.entries(shop.cart).map(([s, q]) =>
    `<div>${ITEMS[s][0]} x${q} <button id="rm-${s}">Remove ${ITEMS[s][0]}</button></div>`).join("") || "<div>(empty)</div>";
}
document.addEventListener("click", e => {
  const id = e.target.id, msg = document.getElementById("msg");
  if (id.startsWith("add-")) { const s = id.slice(4); shop.cart[s] = (shop.cart[s] || 0) + 1; msg.textContent = "Added " + ITEMS[s][0] + " to cart"; }
  else if (id.startsWith("rm-")) { delete shop.cart[id.slice(3)]; msg.textContent = "Removed from cart"; }
  else if (id === "checkout") {
    if (!Object.keys(shop.cart).length) { msg.textContent = "Your cart is empty"; return; }
    const oid = "ord-" + String(shop.orders.length + 1).padStart(3, "0");
    shop.orders.push({oid, items: {...shop.cart}}); shop.cart = {};
    msg.textContent = "Thank you! Order " + oid + " placed.";
  }
  render();
});
render();
</script></body></html>"""

TASKS = [  # (id, instruction, starting cart, gold UI steps, success check on the orders)
    ("buy_headphones", "Buy the headphones.", {}, 2,
     lambda o: any(x["items"] == {"sku-001": 1} for x in o)),
    ("buy_bundle", "Buy one keyboard and one mouse in a single order.", {}, 3,
     lambda o: any(x["items"] == {"sku-002": 1, "sku-003": 1} for x in o)),
    ("revised_order", "Your cart has headphones and a keyboard. Replace the keyboard with a mouse, then place the order.",
     {"sku-001": 1, "sku-002": 1}, 3,
     lambda o: any(x["items"] == {"sku-001": 1, "sku-003": 1} for x in o)),
]

def observe(page):
    """The page as the agent sees it: visible text plus numbered buttons."""
    buttons = page.query_selector_all("button")
    lines = [f"[{i}] {b.inner_text()}" for i, b in enumerate(buttons, 1)]
    cart = page.inner_text("#cart").replace("\n", "; ")
    return f"Cart: {cart}\nMessage: {page.inner_text('#msg') or '(none)'}\nButtons:\n" + "\n".join(lines), buttons

def ask(messages, max_new_tokens=8):
    ids = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=max_new_tokens, do_sample=False)
    return tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()

SYSTEM = ("You operate a web page. Each turn you see the page and numbered buttons. Reply with only the number "
          "of the button to click next, or DONE when the task is complete.")

def run(browser, task, system=SYSTEM, extra=None, max_steps=8):
    tid, instruction, start_cart, gold, ok = task
    page = browser.new_page()                                # a fresh page per task, like a reset environment
    page.set_content(SHOP)
    page.evaluate("c => { shop.cart = c; render(); }", start_cart)
    clicks = []
    for step in range(max_steps):
        obs, buttons = observe(page)
        msgs = [{"role": "system", "content": system}] + (extra or [])
        note = extra_note(clicks) if extra else ""
        msgs.append({"role": "user", "content": f"Task: {instruction}\n{obs}{note}\nNext:"})
        reply = ask(msgs)
        if "DONE" in reply.upper():
            break
        m = re.search(r"\d+", reply)
        if not m or not 1 <= int(m.group()) <= len(buttons):
            clicks.append(f"? {reply!r}"); continue
        b = buttons[int(m.group()) - 1]
        clicks.append(b.inner_text()); b.click()
    orders = page.evaluate("shop.orders")
    result = dict(tid=tid, clicks=clicks, steps=len(clicks), gold=gold, state_ok=ok(orders),
                  msg=page.inner_text("#msg"), orders=orders)
    page.close()
    return result

def extra_note(clicks):
    return ""

def report(results, label):
    print(label)
    for r in results:
        print(f"  {r['tid']:<15} state check: {'PASS' if r['state_ok'] else 'FAIL'}   steps {r['steps']} (gold {r['gold']})"
              f"   page says: {r['msg']!r}")
        print(f"  {'':<15} clicks: {', '.join(r['clicks']) or '(none)'}")
        print(f"  {'':<15} orders placed: {[o['items'] for o in r['orders']]}")
    ok = sum(r["state_ok"] for r in results)
    print(f"  success {ok}/{len(results)} by state check\n")

with sync_playwright() as p:
    browser = p.chromium.launch()
    results = [run(browser, t) for t in TASKS]
    report(results, "zero-shot agent")
    browser.close()

Reading this output

The agent can see and click; it cannot finish. Every task ran to the 8-step limit and no order was placed. It never clicked Checkout and never said DONE.

It loops. In buy_bundle it adds a keyboard, then clicks "Add mouse" seven times; in revised_order it removes the headphones the task said to keep and then adds mice. Finding the right button was not the problem: each click was a plausible button for the task. Knowing what has already been done, and when to stop, was.

That is WebArena's lesson in miniature. At release the best GPT-4 agent completed about 14% of tasks against 78% for people, and long-horizon failures like these, not misreading the page, were most of the gap.

The fixes help a little. With a worked example and a list of past clicks, the agent buys the headphones (1 of 3), in 3 steps against a gold of 2. It still undoes its own work in buy_bundle (adds and removes the mouse twice, never adds the keyboard) and keeps adding mice in revised_order.

Part 1 of 4 · ShoppingApp, Task, _agent_task_1, _agent_task_2

"""Toy web-agent harness with execution-based eval and trajectory efficiency.

Models a minimal shopping app; 3 tasks with gold trajectories; a scripted agent
attempts each task; we record success + steps-over-gold per OSWorld-Human.
"""

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, Callable


class ShoppingApp:
    def __init__(self) -> None:
        self.items = {
            "sku-001": {"name": "headphones", "price": 199},
            "sku-002": {"name": "keyboard", "price": 129},
            "sku-003": {"name": "mouse", "price": 59},
        }
        self.cart: dict[str, int] = {}
        self.orders: list[dict[str, Any]] = []

    def list_items(self) -> list[dict[str, Any]]:
        return [{"sku": sku, **meta} for sku, meta in self.items.items()]

    def add_to_cart(self, sku: str, qty: int = 1) -> str:
        if sku not in self.items:
            return "error: unknown sku"
        self.cart[sku] = self.cart.get(sku, 0) + qty
        return f"added {qty} x {sku}"

    def remove_from_cart(self, sku: str) -> str:
        if sku not in self.cart:
            return "error: not in cart"
        del self.cart[sku]
        return f"removed {sku}"

    def checkout(self) -> str:
        if not self.cart:
            return "error: empty cart"
        total = sum(self.items[sku]["price"] * qty
                    for sku, qty in self.cart.items())
        oid = f"ord-{len(self.orders) + 1:03d}"
        self.orders.append({"oid": oid, "items": dict(self.cart), "total": total})
        self.cart = {}
        return oid


@dataclass
class Task:
    tid: str
    description: str
    agent: Callable[[ShoppingApp], list[str]]
    gold_steps: int
    success: Callable[[ShoppingApp], bool]


def _agent_task_1(app: ShoppingApp) -> list[str]:
    trace: list[str] = []
    trace.append(f"list_items -> {len(app.list_items())} items")
    trace.append(f"add_to_cart sku-001 -> {app.add_to_cart('sku-001')}")
    trace.append(f"checkout -> {app.checkout()}")
    return trace


def _agent_task_2(app: ShoppingApp) -> list[str]:
    trace: list[str] = []
    trace.append(f"list_items")
    app.list_items()
    trace.append(f"add_to_cart sku-002 -> {app.add_to_cart('sku-002')}")
    trace.append(f"add_to_cart sku-003 -> {app.add_to_cart('sku-003')}")
    trace.append(f"checkout -> {app.checkout()}")
    return trace

Part 3 of 4 · setup

def main() -> None:
    print("=" * 70)
    print("WEBARENA/OSWORLD-STYLE HARNESS: Phase 14, Lesson 20")
    print("=" * 70)

    tasks = [
        Task(
            tid="buy_headphones",
            description="buy the headphones",
            agent=_agent_task_1,
            gold_steps=3,
            success=lambda app: any(
                o["items"].get("sku-001") == 1 for o in app.orders
            ),
        ),
        Task(
            tid="buy_bundle",
            description="buy keyboard + mouse as a bundle",
            agent=_agent_task_2,
            gold_steps=4,
            success=lambda app: any(
                o["items"].get("sku-002") == 1 and o["items"].get("sku-003") == 1
                for o in app.orders
            ),
        ),
        Task(
            tid="revised_order",
            description="swap keyboard for mouse mid-order",
            agent=_agent_task_3,
            gold_steps=5,
            success=lambda app: any(
                o["items"].get("sku-001") == 1 and
                o["items"].get("sku-003") == 1 and
                "sku-002" not in o["items"]
                for o in app.orders
            ),
        ),
    ]

    total_success = 0
    total_steps = 0
    total_gold = 0
    for task in tasks:
        app = ShoppingApp()
        trace = task.agent(app)
        ok = task.success(app)
        steps = len(trace)
        efficiency = steps / task.gold_steps
        print(f"\n[{task.tid}] {task.description}")
        print(f"  success: {ok}")
        print(f"  steps:   {steps}  (gold {task.gold_steps}, "
              f"efficiency {efficiency:.2f}x)")
        for line in trace:
            print(f"    - {line}")
        if ok:
            total_success += 1
        total_steps += steps
        total_gold += task.gold_steps

    print(f"\naggregate")
    print(f"  success rate:     {total_success}/{len(tasks)}")
    print(f"  step efficiency:  {total_steps / total_gold:.2f}x over gold")
    print()
    print("WebArena: execution-based, gym APIs, state check decides success.")
    print("OSWorld-Human: gold trajectories reveal 1.4-2.7x step inefficiency.")

Industry practice
What's current (2024–2026)
  • OSWorld-Verified, the cleaned-up version of OSWorld, is near saturation: self-reported top scores in late 2026 are about 83 to 86%, above the paper's 72.36% human baseline. None of these are independently verified.
  • OSWorld 2.0 (June 2026) moves to long-horizon workflows across self-hosted web apps and professional desktop software, with checkpoints for partial credit; scores depend strongly on the step budget (leaders reach roughly 46% at 150 steps and 78% at 500 on one tracked leaderboard).
  • WebArena-Verified (ServiceNow) re-checks WebArena's tasks and graders; VisualWebArena, TheAgentCompany and BrowseComp cover images, office work and hard web research.
  • Practice: product teams record gold trajectories for their own top flows and grade agents on the resulting state (database rows, API calls), with step counts and costs, rather than on screenshots or messages.
  • On your laptop: Playwright and Chromium run here in a few hundred MB. The real WebArena needs Docker images for its four apps (tens of GB); OSWorld needs a VM (VMware, VirtualBox or Docker with KVM) per environment.

Sources: WebArena (arXiv:2307.13854), OSWorld (arXiv:2404.07972), OSWorld-Human (arXiv:2506.16042), OSWorld-G (arXiv:2505.13227), OSWorld 2.0 (arXiv:2606.29537), OSWorld-Verified scores (llm-stats), OSWorld 2.0 leaderboard (Yutori), VisualWebArena (arXiv:2401.13649), TheAgentCompany (arXiv:2412.14161).

Recap
What to keep from this lesson
  • Grade agents on the state they leave behind, not on what they or the page say.
  • Count steps against a gold trajectory; extra steps cost time and success.
  • Small models find buttons but loop and fail to stop.
  • Examples and a memory of past actions help, but do not make a weak agent reliable.
  • Short desktop tasks are nearly solved on benchmarks; long workflows are the frontier.

Ship it

Given a target app (web or desktop) and a list of tasks with gold trajectories, build an eval harness.

Produce:

1. Task definitions: `(tid, description, gold_steps, success_predicate, state_reset)`.
2. Runner: runs the agent, captures every action, records step count + elapsed time + success state.
3. Trajectory-efficiency metric: `agent_steps / gold_steps`. Report per-task and aggregate.
4. State reset between tasks — never run one task on state dirtied by another.
5. Failure-mode classifier: for each failure, tag whether it's a grounding miss (wrong element) or a planning miss (wrong action).

Hard rejects:

- No state reset between tasks. Cross-task contamination invalidates all scores.
- Success-rate-only reporting. Trajectory efficiency is the 2026 standard.
- Screenshots-only harness without DOM parity. Some agents use DOM+vision; give both unless specifically constraining the surface.

Refusal rules:

- If the tasks have no gold trajectories, refuse. You cannot measure efficiency without them.
- If the app is not pinned to a specific version, refuse. Drift invalidates cross-run comparisons.
- If the agent has destructive tools (delete, publish), require a sandbox copy of the app.

Output: `tasks.py`, `runner.py`, `failure_classifier.py`, `report.py`, `README.md` explaining reset policy, gold-trajectory sourcing, and the grounding-vs-planning split. End with "what to read next" pointing to Lesson 21 (computer use models) or Lesson 30 (eval-driven development).

Exercises

  1. Extend the toy harness with a second app (a forum). Write 3 tasks plus gold trajectories.
  2. Add trajectory-efficiency reporting per task. On your toy, is the agent 1x, 2x, or 3x over gold?
  3. Implement a "distractor" tool — one the gold trajectory never uses. Does the scripted agent get tempted?
  4. Read OSWorld-G. How would you separate grounding failures from planning failures in your own evals?
  5. Read WebArena's apps README. What breaks when you upgrade one of the pinned app versions?

Solutions

SolutionP1 · None, by looping

None. The model reads the buttons well enough to click plausible ones, but it does not track what it has already done: it adds the same item again and again, removes items the task said to keep, and never reaches Checkout or says DONE within 8 steps. The failure is long-horizon control, not perception.

SolutionB1 · Grading the message, not the state

The evaluation grades the page, not the outcome. A message can say "thank you" when the order is wrong (wrong items, a duplicate order placed by a repeated click) and can say something else when the order is right, as when the agent's extra Checkout click replaced the confirmation with "Your cart is empty". A 92% pass rate on messages says little about orders.

Change it to execution-based checks: after each run, query the order system for the orders the agent created and compare them exactly with the expected items, quantities and addresses; fail on missing, extra or duplicate orders. Record steps against a gold trajectory and flag runs far above it, since repeated clicks are what create duplicates. Keep a few message checks only as a secondary signal.
