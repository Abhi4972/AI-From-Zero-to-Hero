Why this came about

Early statisticians noticed that a formula with enough adjustable numbers could fit any data perfectly, including pure noise, and still predict nothing. The mathematician John von Neumann reportedly joked, "With four parameters I can fit an elephant, and with five I can make him wiggle his trunk." The fix that machine learning settled on is simple and strict: judge a model only on data it did not learn from. Holding out data, cross-validation (developed by statisticians in the 1970s) and regularisation all follow from that one rule. It matters even more for large language models, whose billions of parameters could memorise a great deal.

In plain words first
Memorising the answers versus learning the subject

A student who memorises last year's exam answers can score 100% on last year's exam and fail this year's. A student who understood the subject does well on both. A model can do the same: with enough flexibility, it can memorise the training examples, noise and all, instead of learning the pattern behind them. You only find out by testing it on questions it has never seen. That is why data is split, and why the test questions must stay secret until the end.

Step 1 · See it happen

Below, 12 training points (filled) follow a gentle S-shaped pattern with some noise. Another 12 points from the same pattern (hollow) are kept aside as validation data. The model is a polynomial curve: degree 1 is a straight line, and each extra degree adds a parameter and lets the curve bend once more. Drag the degree up slowly.

The same experiment in code, with NumPy's polyfit (fit a polynomial of a given degree by least squares) and polyval (evaluate it):

import numpy as np

x_train = np.array([-0.943, -0.859, -0.743, -0.74, -0.704, -0.262, -0.001, 0.023, 0.203, 0.244, 0.856, 0.897])
y_train = np.array([-0.726, -0.953, -1.059, -0.908, -0.848, -0.602, -0.031, 0.176, 0.293, 0.258, 1.001, 0.775])
x_val   = np.array([-0.834, -0.742, -0.705, -0.529, -0.446, -0.293, -0.14, -0.066, 0.183, 0.604, 0.735, 0.792])
y_val   = np.array([-0.849, -0.803, -1.034, -1.081, -0.789, -0.579, -0.119, -0.382, 0.29, 0.829, 0.68, 0.994])

def mse(coefs, x, y):
    return np.mean((np.polyval(coefs, x) - y) ** 2)

for degree in [0, 1, 3, 4, 7, 9, 11]:
    coefs = np.polyfit(x_train, y_train, degree)
    print(f"degree {degree:>2}:  training error {mse(coefs, x_train, y_train):.4f}   validation error {mse(coefs, x_val, y_val):.4f}")
What you should see
degree  0:  training error 0.4730   validation error 0.5228
degree  1:  training error 0.0275   validation error 0.0494
degree  3:  training error 0.0095   validation error 0.0183
degree  4:  training error 0.0092   validation error 0.0172
degree  7:  training error 0.0027   validation error 0.0445
degree  9:  training error 0.0015   validation error 0.3070
degree 11:  training error 0.0000   validation error 288087.6743
Reading this output
  • Training error only ever goes down as the degree rises. At degree 11 (12 parameters for 12 points) it is 0.0000: the curve passes through every training point exactly.
  • Validation error goes down, then up. It is lowest around degree 3 to 4, and at degree 11 it explodes to about 288,000, because between and beyond the training points the curve swings wildly.
  • Degree 0 (a flat line) is underfitting: too simple, bad on both. Degrees 3 to 4 are a good fit. Degree 7 and above is overfitting: excellent on the data it memorised, poor on anything new.
  • The gap between training error and validation error is the warning sign. A small training error on its own tells you nothing.

Step 2 · Three splits, three jobs

  • Training set: the only data fit ever sees.
  • Validation set (or development set): used to compare models and choose settings, such as the polynomial degree above or the threshold in Lesson 2.25. You look at it many times.
  • Test set: used once, at the very end, to report how well the chosen model will do on new data.

Why a separate test set? Because every time you pick the model that scores best on validation data, you are fitting a little to the validation set's quirks. After many choices, its score becomes optimistic. The untouched test set gives an honest final number.

from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

# the 300 simulated deliveries from Lesson F3.3
rng = np.random.default_rng(1)
n = 300
dist = rng.uniform(1, 20, n).round(1)
rain = (rng.random(n) < 0.3).astype(float)
was_late = (rng.random(n) < sigmoid(-5 + 0.45 * dist + 2.0 * rain)).astype(int)
X = np.column_stack([dist, rain])

# first split off the test set (20%), then split the rest into training and validation
X_rest, X_test, late_rest, late_test = train_test_split(X, was_late, test_size=0.2, random_state=0)
X_train, X_val, late_train, late_val = train_test_split(X_rest, late_rest, test_size=0.25, random_state=0)
print("sizes:", len(X_train), len(X_val), len(X_test))

model = LogisticRegression().fit(X_train, late_train)
print(f"accuracy  train {model.score(X_train, late_train):.3f}   validation {model.score(X_val, late_val):.3f}   test {model.score(X_test, late_test):.3f}")
What you should see
sizes: 180 60 60
accuracy  train 0.767   validation 0.900   test 0.767
Reading this output
  • 25% of the remaining 240 is 60, so the split is 180 / 60 / 60.
  • random_state=0 fixes the shuffle so the split is the same every run. Change it and the numbers move.
  • Validation accuracy (0.90) is much higher than test accuracy (0.767) for the same model. Nothing is wrong: with only 60 examples, the score depends a lot on which 60 you happen to get. One lucky or unlucky split can mislead you, which is the problem Step 4 solves.
Tip
Split by time when the future matters

If the model will predict the future (next month's demand, tomorrow's fraud), do not shuffle: train on older data and test on newer data. Shuffling lets the model peek at the future and makes the test score too optimistic.

Step 3 · Fighting overfitting

There are four main remedies, and you will meet all of them again in deep learninglater · 3.15.

  1. A simpler model: fewer parameters, as when you chose degree 4 over degree 11.
  2. More data: with 1,000 training points instead of 12, even a degree-9 curve has nowhere to wiggle.
  3. Regularisation: keep the flexible model, but add a penalty to the loss for large weights, so the model only uses large weights when the data really demands it.
  4. Early stopping: in gradient descent, stop training when the validation error stops improving (Lesson 3.17).

Regularisation is worth seeing. Ridge regression adds alpha × (sum of squared weights) to the squared error. Here is the degree-9 polynomial with different penalty strengths:

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression, Ridge

X_tr, X_va = x_train.reshape(-1, 1), x_val.reshape(-1, 1)

def report(name, model):
    model.fit(X_tr, y_train)
    tr = np.mean((model.predict(X_tr) - y_train) ** 2)
    va = np.mean((model.predict(X_va) - y_val) ** 2)
    biggest = np.abs(model[-1].coef_).max()
    print(f"{name:<18} train {tr:.4f}   validation {va:.4f}   largest weight {biggest:7.2f}")

report("no penalty", make_pipeline(PolynomialFeatures(9), LinearRegression()))
for alpha in [0.0001, 0.01, 1, 10]:
    report(f"ridge alpha={alpha}", make_pipeline(PolynomialFeatures(9), Ridge(alpha=alpha)))
What you should see
no penalty         train 0.0015   validation 0.3070   largest weight  264.61
ridge alpha=0.0001 train 0.0037   validation 0.0247   largest weight    6.15
ridge alpha=0.01   train 0.0081   validation 0.0271   largest weight    1.57
ridge alpha=1      train 0.0444   validation 0.0950   largest weight    0.70
ridge alpha=10     train 0.1767   validation 0.2696   largest weight    0.27
Reading this output
  • PolynomialFeatures(9) turns each x into the columns x, x², …, x⁹ so that a linear model can fit a curve; make_pipeline chains it with the model, so fit and predict run both steps. model[-1] is the last step, the linear model, whose coef_ holds the weights.
  • No penalty: weights up to about 265, and a validation error of 0.31. Huge weights that nearly cancel each other are how a curve wiggles through every point.
  • A small penalty (0.0001 to 0.01) shrinks the weights to a few units and cuts the validation error more than tenfold, to about 0.025, not far from the best simple model's 0.017. The flexible model behaves like a simpler one.
  • Too strong a penalty (10) squashes the weights so much that the model underfits again. The penalty strength is itself a setting you choose on validation data.

Settings like alpha, the polynomial degree, or the learning rate are called hyperparameters: you choose them, training does not learn them. Choosing them is what the validation set is for.

Step 4 · Cross-validation: a steadier score from limited data

Step 2 showed that a single validation split of 60 examples can be noisy. Cross-validation reuses the data: split it into k parts (often 5), train k times with a different part held out each time, and average.

from sklearn.datasets import load_digits
from sklearn.model_selection import cross_val_score

digits = load_digits()                     # 1,797 small images of handwritten digits, 8 x 8 pixels each
print(digits.data.shape)

scores = cross_val_score(LogisticRegression(max_iter=2000), digits.data, digits.target, cv=5)
print("five scores:", scores.round(3))
print(f"mean {scores.mean():.3f}, spread (standard deviation) {scores.std():.3f}")
What you should see
(1797, 64)
five scores: [0.922 0.872 0.942 0.942 0.897]
mean 0.915, spread (standard deviation) 0.027

The five scores range from 0.872 to 0.942 depending on which fifth was held out. Reporting "0.915 ± 0.027" is far more honest than any single one of them. Cross-validation costs k times the training time, so it is common for small and medium datasets and rare for large neural networks, where one big held-out set is used instead.

Step 5 · Leakage: when the test is secretly easy

Data leakage means information that would not be available at prediction time slips into the features or into training. The model looks brilliant in testing and fails in real use. Here is a classic: the company sends an apology coupon after a late delivery, and someone includes "coupon sent" as a feature.

coupon_sent = was_late.copy()                 # only ever sent after a delivery turned out late
X_leaky = np.column_stack([dist, rain, coupon_sent])

Xa, Xb, ya, yb = train_test_split(X_leaky, was_late, test_size=0.2, random_state=0)
leaky = LogisticRegression().fit(Xa, ya)
print("test accuracy with the leaky feature:", leaky.score(Xb, yb))
print("weights (km, rain, coupon):", leaky.coef_.round(2))
What you should see
test accuracy with the leaky feature: 1.0
weights (km, rain, coupon): [[0.21 0.62 5.23]]

Perfect accuracy, and a huge weight on the coupon. But at the moment you need the prediction (before the delivery), no coupon exists yet. In real use this model is worthless. Ask of every feature: would I know this at the moment I make the prediction?

Other common leaks:

  • Preprocessing on all the data: computing the mean and standard deviation for scaling (Lesson 2.23) over training and test data. Fit every preprocessing step on the training set only; a sklearn pipeline does this for you.
  • Duplicates across splits: the same customer, document or near-identical image in both training and test sets. The model has seen the answer. Split by customer or by document, not by row.
  • The future in the past: shuffling time-ordered data (the tip above).
  • Benchmark contamination in language models: if a public test set's questions were on the internet, they may be in the model's training data, so a high benchmark score can partly be memory (Lesson 10.47).

Step 6 · Distribution shift: when the world moves

Even without leakage, a model only knows the world its training data came from. When the data it meets in use differs, called distribution shift, performance drops, often silently.

  • A delivery-time model trained in the dry season meets the monsoon.
  • A fraud model trained before a new payment method launched meets fraud patterns it has never seen.
  • A language model trained on text up to a knowledge cutoff date is asked about events after it, and may answer confidently and wrongly. This is one big reason for retrieval (the Retrieval (RAG) section): give the model current facts at question time instead of relying on its training.

The remedy is the "monitor" step of the workflow (Lesson 2.22): keep measuring the model on recent real data, and retrain when it drifts.

Watch out
You can overfit with prompts too

The same trap applies when you build with LLMs and never train anything. If you tweak a prompt fifty times until it scores perfectly on the same twenty test questions, you have fitted the prompt to those twenty questions. Keep a separate set of questions you only run at the end, exactly like a test set.

The same idea as a formula
  • ridge (L2) regularisation: loss = MSE + α Σⱼ wⱼ²
  • lasso (L1) regularisation: loss = MSE + α Σⱼ |wⱼ|, which pushes some weights to exactly 0
  • k-fold cross-validation score = (1/k) Σ score on fold i, after training on the other k − 1 folds
  • expected error on new data ≈ bias² (too simple) + variance (too sensitive to the particular sample) + irreducible noise
Check your mental model
  • ✗ "My training error is nearly zero, so the model is excellent."
    ✓ It may have memorised the data. Only error on held-out data tells you about new data.
  • ✗ "It is fine to look at the test set as long as I don't train on it."
    ✓ Choosing models or settings because of their test score leaks it into your decisions. Use validation data for choices, and the test set once.
  • ✗ "Bigger models always overfit more."
    ✓ Usually more flexible means more risk, but with enough data and regularisation, very large neural networks generalise well. Data size and regularisation matter as much as model size.

Exercises

Predict before you run

In Step 1, the degree-11 curve passes through all 12 training points. What would its training error be if you added a 13th training point that lies right on the S-shaped pattern? Would it still be 0? (Solution P1.)

Make it your own

In Step 2, change random_state=0 to 1, 2 and 3 in both splits, and note the validation and test accuracies each time. What does this tell you about trusting one split? (Solution M1.)

Debugging exercise

A teammate's churn model scores 0.99 AUC on the test set but performs no better than chance in its first week in production. One of the features is days_since_last_login, computed on the day the dataset was exported. What went wrong? (Solution D1.)

Solutions

SolutionP1 · One more point

No. A degree-11 polynomial has 12 parameters, so it can pass exactly through any 12 points, but generally not 13. With the 13th point added, least squares has to compromise and the training error becomes greater than 0. This is why, in general, the more data you have, the harder it is to overfit.

SolutionM1 · Different random splits

The validation accuracy ranges from 0.70 to 0.90 across these seeds, and the test accuracy from 0.75 to 0.78, with validation sometimes above test and sometimes below. With 60 examples, one example is 1.7 percentage points. Small evaluation setslater · 11.19 give noisy scores: report the spread (cross-validation), or get more evaluation data, before believing small differences between models.

SolutionD1 · Leakage through time

days_since_last_login was computed at export time, which for customers who had already left is after they left. Churned customers naturally show long gaps, so the feature encodes the answer. At prediction time, for a still-active customer, that information does not exist yet. Rebuild every feature as of the moment the prediction would have been made, and split by time.

Recap
  • Training error always falls as models get more flexible; validation error falls and then rises. The gap is the sign of overfitting.
  • Train on the training set, choose models and hyperparameters with the validation set, and report the test set once at the end.
  • Regularisation, simpler models, more data and early stopping all reduce overfitting.
  • Cross-validation averages several splits to give a steadier score and its spread.
  • Leakage (information unavailable at prediction time) and distribution shift (the world changing) are the commonest reasons good test scores fail in real use, for classic models and LLM systems alike.

Check your understanding

Q1Training error is 0.01 and validation error is 0.45. What is the most likely diagnosis?

A large gap between training and validation error means the model memorised the training data.

Q2What is the validation set for?

The test set is for the final score; the validation set is for choices.

Q3Which of these is data leakage?

The test data influenced a training step, so the test score is no longer independent.
