The problem

In plain words first

A classifier needs a fixed-length list of numbers for every document. Bag of words makes one by counting: give every word in the vocabulary a slot, and put in each slot how often that word appears. Word order is thrown away. TF-IDF then reweights the counts: words that appear in nearly every document ("the", "was") are turned down, and words that are frequent in this document but rare elsewhere are turned up. The result is simple, fast and explainable, and on many tasks still hard to beat; its blind spot is meaning, since "excellent" and "great" share no slot.

The model needs numbers. You have strings.

Every NLP pipeline has to answer the same question. How do we turn a variable-length stream of tokens into a fixed-size vector that a classifier can consume. The first answer the field landed on was the dumbest one that works. Count the words. Make a vector.

That vector has carried more production NLP than any embedding model. Spam filters, topic classifiers, log anomaly detection, search ranking (before BM25), the first wave of sentiment analysis, the first decade of academic NLP benchmarks. 2026 practitioners still reach for it first on narrow classification tasks. It is fast, interpretable, and often indistinguishable from a 400M-parameter embedding model on tasks where word presence is what matters.

This lesson builds bag of words, then TF-IDF, from scratch. Then shows scikit-learn doing the same in three lines. Then names the failure mode that makes you reach for embeddings.

The idea

Bag of Words (BoW) throws away order. For each document, count how many times each vocabulary word appears. Vector length is the vocabulary size. Position i is the count of word i.

TF-IDF reweights BoW. A word that appears in every document is uninformative, so scale it down. A word rare across the corpus but frequent in a single document is signal, so scale it up.

TF-IDF(w,d)​=TF(w,d)⋅IDF(w)=∣d∣count(w in d)​⋅logdf(w)N​​

Where TF is term frequency in the document, df is document frequency (how many docs contain the word), N is total documents. The log keeps the weight bounded for ubiquitous words.

Key property: both produce sparse vectors with interpretable axes. You can look at a trained classifier's weights and read which words push a document toward each class. You cannot do this with a 768-dimensional BERT embedding.

The same idea as a formula

Bag of words. With a vocabulary of V terms, document d becomes a vector of counts tf(t,d), one entry per term; word order is discarded. Across N documents this is an N×V matrix that is almost entirely zeros (a 200-word document touches perhaps 120 of 50,000 terms), so it is stored sparse.

Inverse document frequency. A term found in every document tells documents apart not at all; one in a few documents tells a lot. With df(t) the number of documents containing t:

idf(t)=lndf(t)N​,scikit-learn’s smoothed form: ln1+df(t)1+N​+1

and tfidf(t,d)=tf(t,d)⋅idf(t). The smoothed form never divides by zero and never gives a term weight 0.

Normalise, then compare. Dividing each row by its L2 norm makes long and short documents comparable; the similarity of two documents is then the dot product of their rows, which equals their cosine similarity:

cos(d1​,d2​)=∥xd1​​∥∥xd2​​∥xd1​​⋅xd2​​​

This is the scoring core of classic search engines (BM25 refines it with term-frequency saturation and document-length normalisation) and a strong baseline for text classification with a linear model.

Worked example
TF-IDF by hand

Step 3 uses the smoothed IDF that scikit-learn uses, IDF(w)=lndf(w)+1N+1​+1, rather than the plain log(N/df) above. For the three documents in Step 4 (the cat sat, the dog sat, the cat ran), N=3:

  • "the" is in all 3: ln(4/4)+1=1. Its TF in a 3-word document is 1/3, so TF-IDF =0.333.
  • "cat" is in 2: ln(4/3)+1=1.288, TF-IDF =1.288/3=0.429.
  • "dog" is in 1: ln(4/2)+1=1.693, TF-IDF =0.564.

Those are exactly the numbers Step 4 prints. With the plain formula, "the" would get ln(3/3)=0 and vanish completely; the +1 keeps it with a small, non-zero weight.

Step 1 · build the vocabulary

def build_vocab(docs):
    vocab = {}
    for doc in docs:
        for token in doc:
            if token not in vocab:
                vocab[token] = len(vocab)
    return vocab

Input: list of tokenized documents (any word-level tokenizer will do; the code/main.py in this lesson uses a simplified lowercase variant). Output: {word: index} dict. Stable insertion order means word index 0 is the first word seen in the first document. Convention varies; scikit-learn sorts alphabetically.

Step 2 · bag of words

def bag_of_words(docs, vocab):
    matrix = [[0] * len(vocab) for _ in docs]
    for i, doc in enumerate(docs):
        for token in doc:
            if token in vocab:
                matrix[i][vocab[token]] += 1
    return matrix

>>> docs = [["cat", "sat", "on", "mat"], ["cat", "cat", "ran"]]
>>> vocab = build_vocab(docs)
>>> bag_of_words(docs, vocab)

Rows are documents. Columns are vocabulary indices. Entry [i][j] is "how many times word j appears in document i." Doc 1 has cat twice because it did. Doc 0 has ran zero times because it did not.

Step 3 · term frequency and document frequency

import math


def term_frequency(doc_bow, doc_length):
    return [c / doc_length if doc_length else 0 for c in doc_bow]


def document_frequency(bow_matrix):
    df = [0] * len(bow_matrix[0])
    for row in bow_matrix:
        for j, count in enumerate(row):
            if count > 0:
                df[j] += 1
    return df


def inverse_document_frequency(df, n_docs):
    return [math.log((n_docs + 1) / (d + 1)) + 1 for d in df]

Two smoothing tricks worth naming. The (n+1)/(d+1) avoids log(x/0). The trailing +1 ensures a word in every document still has IDF 1 (not 0), matching scikit-learn's default. Other implementations use raw log(N/df). Both work; the smoothed version is friendlier.

Step 4 · TF-IDF

def tfidf(bow_matrix):
    n_docs = len(bow_matrix)
    df = document_frequency(bow_matrix)
    idf = inverse_document_frequency(df, n_docs)
    out = []
    for row in bow_matrix:
        length = sum(row)
        tf = term_frequency(row, length)
        out.append([tf_j * idf_j for tf_j, idf_j in zip(tf, idf)])
    return out

Three documents, five vocab words (the, cat, sat, dog, ran). the appears in all three, so its IDF is low. dog appears in one, so its IDF is high. With a real vocabulary of thousands of words, these vectors are sparse (most entries are zero). Even in this toy, the discriminative words pop.

Step 5 · L2-normalize rows

def l2_normalize(matrix):
    out = []
    for row in matrix:
        norm = math.sqrt(sum(x * x for x in row))
        out.append([x / norm if norm else 0 for x in row])
    return out

Without normalization, a longer document gets a larger vector and dominates similarity scores. L2 normalization puts every document on the unit hypersphere. Cosine similarity between rows is now just a dot product.

CountVectorizer does tokenization, vocabulary, and BoW in one call. TfidfVectorizer adds IDF weighting and L2 normalization. Both return sparse matrices. For 100k documents, the dense version does not fit in memory; stay sparse until the classifier demands dense.

Knobs that change everything:

Arg Effect
ngram_range=(1, 2) Include bigrams. Usually boosts classification.
min_df=2 Drop words in fewer than 2 docs. Trims vocabulary on noisy data.
max_df=0.95 Drop words in more than 95% of docs. Approximates stopword removal without a hardcoded list.
stop_words="english" scikit-learn's builtin stopword list. Task-dependent — sentiment analysis should not drop negations.
sublinear_tf=True Use 1 + log(tf) instead of raw tf. Helps when a term repeats many times in one doc.

When TF-IDF still wins (as of 2026)

  • Spam detection, topic labeling, log anomaly flagging. Word presence is what matters; semantic nuance does not.
  • Low-data regimes where no pretrained encoder fits your text (unusual jargon, codes, logs). On ordinary language, pretrained embeddings often win when labels are scarce; "Use it" measures it.
  • Anywhere latency matters. TF-IDF plus a linear model answers in microseconds. Embedding a document through even a small transformer costs milliseconds (about 4 ms per sentence, batched, for the CPU run under "Use it").
  • Systems that must explain their predictions. Inspect the classifier's coefficients. Top positive words are the reason.

When TF-IDF fails

The semantic blindness failure. Consider these two documents:

  • "The movie was not good at all."
  • "The movie was excellent."

One is a negative review. One is positive. Their TF-IDF overlap is exactly {the, movie, was}. A bag-of-words classifier has to memorize that the word not near good flips the label. It can learn this on enough data, but never as gracefully as a model that understands syntax.

The other failure: out-of-vocabulary words at inference. A BoW model trained on IMDb reviews has no idea what to do with Zoomer-approved if that token never appeared in training. Subword embeddings (lesson 04) handle this. TF-IDF cannot.

Hybrid: TF-IDF weighted embeddings

A common hybrid for medium-data classification: use TF-IDF weights as attention over word embeddings.

def tfidf_weighted_embedding(doc, tfidf_scores, embedding_table, dim):
    vec = [0.0] * dim
    total_weight = 0.0
    for token in doc:
        if token not in embedding_table or token not in tfidf_scores:
            continue
        weight = tfidf_scores[token]
        emb = embedding_table[token]
        for i in range(dim):
            vec[i] += weight * emb[i]
        total_weight += weight
    if total_weight == 0:
        return vec
    return [v / total_weight for v in vec]

You get semantic capacity from embeddings, and rare-word emphasis from TF-IDF. Classifier trains on the pooled vector. Whether this beats either part alone depends on the task and the data, so measure it; "Use it" tries a simpler combination (TF-IDF features next to sentence embeddings) on a real dataset.

import time
import numpy as np
import pyarrow.parquet as pq
import matplotlib.pyplot as plt
from scipy.sparse import hstack, csr_matrix
from huggingface_hub import hf_hub_download
from sklearn.linear_model import LogisticRegression
from sentence_transformers import SentenceTransformer

load = lambda split: pq.read_table(hf_hub_download("cornell-movie-review-data/rotten_tomatoes", f"{split}.parquet",
                                                   repo_type="dataset")).to_pydict()
train, test = load("train"), load("test")
y_train, y_test = np.array(train["label"]), np.array(test["label"])
print(f"{len(train['text'])} training sentences, {len(test['text'])} test; e.g. {train['text'][1][:70]!r} -> {train['label'][1]}")

start = time.time()
encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
emb_train = encoder.encode(train["text"], batch_size=64)
emb_test = encoder.encode(test["text"], batch_size=64)
print(f"embedded {len(train['text']) + len(test['text'])} sentences in {time.time() - start:.0f} s "
      f"({(time.time() - start) / (len(train['text']) + len(test['text'])) * 1000:.1f} ms each)")

sizes, results = (200, 1000, len(train["text"])), {"TF-IDF words": [], "TF-IDF words + bigrams": [], "MiniLM embeddings": [], "bigrams + MiniLM": []}
for n in sizes:
    idx = np.random.default_rng(0).permutation(len(train["text"]))[:n]
    texts = [train["text"][i] for i in idx]
    for name, vec in (("TF-IDF words", TfidfVectorizer()), ("TF-IDF words + bigrams", TfidfVectorizer(ngram_range=(1, 2), sublinear_tf=True))):
        vec.fit(texts)
        clf = LogisticRegression(max_iter=2000, C=4).fit(vec.transform(texts), y_train[idx])
        results[name].append(clf.score(vec.transform(test["text"]), y_test))
        if name.endswith("bigrams"):
            both_train = hstack([vec.transform(texts), csr_matrix(emb_train[idx])])
            both_test = hstack([vec.transform(test["text"]), csr_matrix(emb_test)])
            results["bigrams + MiniLM"].append(LogisticRegression(max_iter=3000, C=4).fit(both_train, y_train[idx]).score(both_test, y_test))
            bigram_vec, bigram_clf = vec, clf
    results["MiniLM embeddings"].append(LogisticRegression(max_iter=2000, C=4).fit(emb_train[idx], y_train[idx]).score(emb_test, y_test))
for name, accs in results.items():
    print(f"{name:24s} " + "   ".join(f"n={n}: {a:.1%}" for n, a in zip(sizes, accs)))

names = bigram_vec.get_feature_names_out()
order = np.argsort(bigram_clf.coef_[0])
print("\nmost negative features:", ", ".join(names[order[:8]]))
print("most positive features:", ", ".join(names[order[-8:][::-1]]))
for phrase in ["not good", "good", "excellent", "movie", "was"]:
    if phrase in bigram_vec.vocabulary_:
        print(f"weight of {phrase!r}: {bigram_clf.coef_[0][bigram_vec.vocabulary_[phrase]]:+.2f}")
for s in ["The movie was not good at all.", "The movie was excellent."]:
    print(f"{s!r}: P(positive) = {bigram_clf.predict_proba(bigram_vec.transform([s]))[0, 1]:.2f}")

fig, ax = plt.subplots(figsize=(6.5, 3.2))
for (name, accs), colour in zip(results.items(), ("#b7bfcb", "#474d9a", "#b24a1d", "#24753a")):
    ax.plot(sizes, accs, "o-", color=colour, lw=2, label=name)
ax.set_xscale("log"); ax.set_xlabel("training sentences"); ax.set_ylabel("test accuracy")
ax.legend(frameon=False, fontsize=8); ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout(); plt.show()

Reading this output

With only 200 labelled sentences the pretrained embeddings clearly win: MiniLM already knows that "dazzling" and "brilliant" are related, while TF-IDF has to learn every word from those 200 examples. With all 8,530 sentences, TF-IDF with bigrams catches up and slightly passes the small embedding model, and putting both feature sets side by side is best of all. The learned weights explain the bigram model completely: you can read the words and phrases that push a review negative or positive, including whether "not good" was frequent enough to earn its own negative weight. That readability is TF-IDF's lasting advantage; an embedding classifier's 384 weights mean nothing on their own. It also explains the strangest line: "The movie was excellent." comes out negative. The printed weights show why: in critics' one-line reviews, "movie" and "was" lean negative, and a single "excellent" cannot outvote them. Short inputs written in a different style from the training data are exactly where bag-of-words models fail, and reading the weights is how you find out.

Recap
What to keep from this lesson
  • Bag of words counts each vocabulary word per document; order is lost.
  • TF-IDF downweights words found in many documents; scikit-learn smooths the IDF and L2-normalises rows.
  • Sparse TF-IDF plus a linear model is fast, cheap and explainable; bigrams recover some word order such as "not good".
  • Pretrained embeddings win when labels are few; with enough labels, TF-IDF is often close, and combinations can beat both.
  • Fit the vocabulary and IDF on training data only.

Solutions

SolutionP1 · Embeddings early, TF-IDF late

At 200 and 1,000 sentences the MiniLM embeddings win by several points; at the full 8,530, TF-IDF with bigrams is slightly ahead, and the combination is best (the printed table). Pretrained knowledge matters most when labelled data is scarce; with enough labels, counting words that actually signal sentiment in this domain is competitive.

SolutionB1 · A leak through the vocabulary

Fitting on train plus test lets the test set decide the vocabulary and the IDF weights: words that only occur in test sentences get slots, and every IDF reflects test-set frequencies. The classifier is still trained on training labels only, so the effect is usually small, but the evaluation is no longer of a pipeline you could actually deploy, where future documents are unseen. Fit on training data, then only transform everything else.

Industry practice
What's current (2024–2026)
  • BM25 is the default keyword ranker. Elasticsearch, OpenSearch, Lucene and Solr rank with BM25, a refinement of TF-IDF, and it remains a strong retrieval baseline.
  • Hybrid search is standard. Production RAG systems combine BM25 with vector search and merge results with reciprocal rank fusion; Elasticsearch, OpenSearch, Weaviate, Vespa, pgvector setups and Snowflake Cortex Search all support it.
  • Learned sparse retrieval. Elastic's ELSER and OpenSearch's neural sparse models expand texts with related terms while keeping an inverted index.

Sources: Elasticsearch similarity (BM25), Elasticsearch RRF, ELSER, Cortex Search.
