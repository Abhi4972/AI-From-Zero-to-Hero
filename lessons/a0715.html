In plain words first
The idea in one line

Full attention is a circle. Every token sees every token, and memory pays the price. Three variants bend the shape of the circle and recover half the cost.

Terms you'll hear
Term What people say What it actually means
Sliding window attention (SWA) "Local attention" Each query attends to its last $W$ tokens; KV cache shrinks to $O(W)$.
Effective receptive field "How far back the model sees" In an $L$-layer SWA stack with window $W$, up to $L \times W$ tokens.
Longformer / BigBird "Local + global + random" Sparse patterns with a few always-attending global tokens; early long-context approach.
Native Sparse Attention "DeepSeek's kernel trick" Learn block-level sparsity; skip zero blocks at the kernel level while keeping quality.

Layer type mix "5:1 SWA-to-global" Interleave sparse and full attention layers in a stack to keep quality at lower memory.

The problem

In plain words first

In full attention every word looks at every earlier word, so the work and the memory for the cached keys and values grow with the length of the text. Three families of variants limit who looks at whom. Sliding-window attention lets each word see only the last few hundred or thousand words; models stay able to use the whole text by keeping some layers global. Sparse attention picks a pattern of pairs (nearby words plus some far ones, or blocks chosen by a learned scorer). Differential attention computes two attention patterns and subtracts one from the other to cancel noise. This lesson draws the masks with the lesson's code, then takes a real model, Gemma 3 270M, which mixes five sliding-window layers with one global layer, and shows that it finds a pass key 1,400 tokens back, keeps less than half the cache, and fails completely once every layer is made sliding. Nothing is trained.

Full attention costs O(N2) memory and O(N2) compute in sequence length. For a 128K-context Llama 3 70B that is 16 billion attention entries per layer, times 80 layers. Flash Attention (Lesson 7.12) hides the O(N2) activation memory but does not change the arithmetic cost — every token still attends to every other token.

Three classes of variants change the topology of the attention matrix itself:

  1. Sliding window attention (SWA). Each token attends to a fixed window of neighbors, not the full prefix (Gemma 2 and 3, Mistral 7B v0.1, gpt-oss). Memory and compute drop to O(N⋅W) where W is the window.
  2. Sparse / block attention. Only selected pairs (i, j) get scored; the rest are forced to zero weight. Longformer, BigBird, OpenAI sparse transformer.
  3. Differential attention. Compute two attention maps with separate Q/K projections, subtract one from the other. Kills the "attention sink" that bleeds weight into the first few tokens. Microsoft's DIFF Transformer (2024).

These coexist. 2025–2026 open models mix them: Gemma 3 uses five sliding-window layers (window 1,024) for every global layer, gpt-oss alternates 128-token windows with full attention, and DeepSeek-V3.2 adds a learned sparse selection on top of full attention. Differential attention is still a research result rather than a production default.

Idea 1 · Sliding Window Attention (SWA)

Each query at position i attends only to positions in [i−W,i] (causal SWA) or [i−W/2,i+W/2] (bidirectional). Tokens outside the window get −∞ in the score matrix.

full causal:           sliding window (W=4):
positions 0-7          positions 0-7, W=4
    0 1 2 3 4 5 6 7        0 1 2 3 4 5 6 7
0 | x                0 |  x
1 | x x              1 |  x x
2 | x x x            2 |  x x x
3 | x x x x          3 |  x x x x
4 | x x x x x        4 |    x x x x
5 | x x x x x x      5 |      x x x x
6 | x x x x x x x    6 |        x x x x
7 | x x x x x x x x  7 |          x x x x

For N=8192 and W=1024, the score matrix has 1024 × 8192 non-zero rows in expectation — an 8× reduction.

KV cache shrinks with SWA. Only the last W tokens of K and V need to be kept per layer. For a Gemma-3-ish config (1024 window, 128K context), KV cache drops 128×.

Quality cost. SWA-only transformers struggle with long-range retrieval. The fix: interleave SWA layers with full-attention layers. Gemma 3 uses 5:1 SWA:global. Mistral 7B used a causal-SWA stack where information "flows forward" through overlapping windows — each layer extends effective receptive field by W, and after L layers the model can attend L × W tokens back.

Idea 2 · Sparse / Block Attention

Pick an N × N sparsity pattern ahead of time. Three canonical shapes:

  • Local + strided (OpenAI sparse transformer). Attend to the last W tokens plus every stride-th token before that. Captures both local and long-range at O(N⋅N​) compute.
  • Longformer / BigBird. Local window + a small set of global tokens (e.g. [CLS]) that attend to everyone and are attended by everyone + random-sparse links. Empirical 2× context at matched quality.
  • Learned sparse attention (DeepSeek, 2025). Learn which blocks or tokens of (Q, K) matter and skip the rest at kernel level: Native Sparse Attention (research), and DeepSeek Sparse Attention in DeepSeek-V3.2, where a light "indexer" picks the tokens each query attends to.

Sparse attention is a kernel-engineering story. The math is simple (mask the score matrix); the win comes from never loading the zero entries into SRAM. FlashAttention-3 and the 2026 FlexAttention API make custom sparse patterns first-class in PyTorch.

Idea 3 · Differential Attention (DIFF Transformer, 2024)

Regular attention has an "attention sink" problem: softmax forces every row to sum to 1, so tokens that don't want to attend to anything in particular dump weight on the first token (or the first few). This steals capacity that should have gone to real content.

Differential attention fixes this by computing two attention maps and subtracting:

A1​A2​DiffAttn​=softmax(Q1​K1T​/d​)=softmax(Q2​K2T​/d​)=(A1​−λ⋅A2​)V​

where λ is a learned scalar (typically 0.5–0.8). A1 captures real content weights; A2 captures the sink. Subtraction cancels the sink, reallocates weight to relevant tokens.

Reported results (Microsoft, 2024): a DIFF Transformer matched a standard Transformer's language-modelling loss with about 65% of the parameters or training tokens, and retrieved key facts from long contexts more reliably. It has not yet been adopted by the major open model families.

The same idea as a formula

Every variant is the same attention with a different mask M added to the scores:

Attn(Q,K,V)=softmax(d​QK⊤​+M)V,Mij​={0−∞​(i,j) allowedotherwise​

Masks. Causal: j≤i. Sliding window W: i−W<j≤i. Local plus strided: i−W<j≤i or (j≤i and jmods=0).

Cost for n tokens: full causal attention scores n(n+1)/2 pairs; a window scores about nW, a fraction ≈2W/n of them; local plus strided about n(W+n/s), which is O(nn​) for W=s=n​.

Cache. A sliding layer keeps only the last W keys and values. With a fraction f of layers global, the cache relative to all-global layers is

Mfull​Mmixed​​=f+(1−f)nW​(n>W)

Reach. Information can travel W positions per sliding layer, so L stacked sliding layers can in principle connect tokens LW apart, but only through many hops; a single global layer connects any pair directly.

Differential attention. Two maps from separate query/key projections, subtracted:

DiffAttn(X)=(softmax(Q1​K1⊤​/d​)−λsoftmax(Q2​K2⊤​/d​))V

Noise that both maps share (for example weight parked on a sink token) cancels; the rows no longer sum to 1, and weights can be negative.

Worked example
Gemma 3's cache by hand

Gemma 3 27B: 62 layers, of which 10 are global and 52 sliding with W=1,024; context n=131,072.

  • Global fraction f=10/62=0.16.
  • Cache relative to all-global: 0.16+0.84×1024/131072=0.16+0.0066≈0.17, six times smaller.
  • Gemma 3 270M at the pass-key test below: 18 layers, 3 global, W=512, n=1,465 tokens: 3/18+(15/18)×511/1465≈0.17+0.29=0.46. At this short length the windows still hold a third of the text, so the saving is only about half; it grows with n.
  • Attention work at 128K for a sliding layer: nW/(n2/2)=2×1024/131072=1.6% of a full layer's.

Step 1 · full causal mask (baseline)

See code/main.py, or its Rust port code/main.rs. To run the Rust version: rustc --edition 2021 -O code/main.rs -o /tmp/lesson && /tmp/lesson. We implement a causal mask comparator that shows full, SWA, local+strided, and differential attention side by side on a toy sequence.

def causal_mask(n):
    return [[0.0 if j <= i else float("-inf") for j in range(n)] for i in range(n)]

Baseline from Lesson 07. Lower triangular; zero weight above the diagonal.

Step 2 · sliding window causal mask

def swa_mask(n, window):
    M = [[float("-inf")] * n for _ in range(n)]
    for i in range(n):
        lo = max(0, i - window + 1)
        for j in range(lo, i + 1):
            M[i][j] = 0.0
    return M

One parameter — window. For window >= n, you recover full causal attention. For window = 1, each token attends only to itself.

Step 3 · local + strided sparse mask

def strided_mask(n, window, stride):
    M = [[float("-inf")] * n for _ in range(n)]
    for i in range(n):
        lo = max(0, i - window + 1)
        for j in range(lo, i + 1):
            M[i][j] = 0.0
        for j in range(0, i + 1, stride):
            M[i][j] = 0.0
    return M

Dense local window plus every stride-th token back to the start of the sequence. Receptive field grows in log steps with additional layers.

Step 4 · differential attention

def diff_attention(Q1, K1, Q2, K2, V, lam):
    A1 = softmax_causal(Q1 @ K1.T / sqrt_d)
    A2 = softmax_causal(Q2 @ K2.T / sqrt_d)
    return (A1 - lam * A2) @ V

Two attention passes, subtract with a learned mixing coefficient. In the code we compare the attention-sink heatmap of single vs differential and watch the sink collapse.

Step 5 · KV cache sizes

Print the cache size per layer at N=131072 for each variant. SWA and sparse variants drop by 10–100×. Differential doubles. Pay your memory bill consciously.

Reading this output

The masks are the formula box's patterns: the sliding window keeps a band of width 4 under the diagonal, and the strided mask adds every second column back. The "attention sink" demo does not show a sink: position 0 gets only 0.018 of the weight, because queries and keys are random and sinks are something trained models learn (Lesson 7.2 measured 63–78% on the first token in GPT-2's later layers). The differential weights are simply about half the single ones, since with random maps A1​−0.5A2​ cancels nothing. In the cache table, the sliding and Gemma-mix rows follow the formula box (7.4 GB, 5.8 times smaller, for the 5:1 mix). The last row's "2×" assumes twice the key/value heads; the DIFF Transformer paper instead halves the number of heads to keep parameters equal, so its cache is about the same as a standard model's.

FlexAttention in PyTorch 2.5+ accepts a mask function:

import torch
from torch.nn.attention.flex_attention import flex_attention, create_block_mask

batch, heads, n, d = 1, 4, 4096, 64
q, k, v = (torch.randn(batch, heads, n, d) for _ in range(3))
def swa_pattern(b, h, q_idx, kv_idx):
    return (q_idx - kv_idx < 1024) & (q_idx >= kv_idx)
mask = create_block_mask(swa_pattern, B=batch, H=heads, Q_LEN=n, KV_LEN=n, device="cpu")
out = flex_attention(q, k, v, block_mask=mask)

# Check against ordinary attention with the same mask written out as a dense matrix.
i, j = torch.arange(n)[:, None], torch.arange(n)[None, :]
dense = torch.nn.functional.scaled_dot_product_attention(q, k, v, attn_mask=(i - j < 1024) & (i >= j))
print(out.shape, f"max difference from dense masked attention: {(out - dense).abs().max():.1e}")
print(f"blocks of 128 x 128 that the kernel can skip entirely: {mask.sparsity():.1f}%")

With torch.compile this becomes a custom fused kernel; the PyTorch team reports about 90% of FlashAttention-2's speed for common patterns, and the mask function is a plain Python callable. (Run as below, without compiling, it works on a CPU but unfused.)

When to pick each:

  • Pure full attention — every layer up to ~16K context, or when retrieval quality is paramount.
  • SWA + global mix — long context (>32K), training and inference memory-bound. The 2026 default above 32K.
  • Sparse block attention — custom kernel, custom pattern. Reserved for specialized workloads (retrieval, audio).
  • Differential attention — any workload where attention-sink contamination hurts (long-context RAG, needle-in-haystack).

A 5 : 1 sliding-window model, with and without its global layers

Gemma 3 270M answers a pass-key question 1,465 tokens long, for three different keys, as released and with every layer switched to its 512-token sliding window (only the configuration changes; the weights are the same). For the released model, the number of tokens each layer keeps in its cache.

import torch
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer

repo = "unsloth/gemma-3-270m"                      # Gemma 3 270M (an ungated copy): 18 layers, 5 sliding (window 512) : 1 global
tok = AutoTokenizer.from_pretrained(repo)
filler = " The grass is green. The sky is blue. The sun is yellow. Here we go. There and back again." * 60
def prompt(key):
    return f"The pass key is {key}. Remember it.{filler} What is the pass key? The pass key is"

def ask(model, key):
    ids = tok(prompt(key), return_tensors="pt").input_ids
    with torch.no_grad():
        out = model.generate(ids, max_new_tokens=6, do_sample=False, max_length=None)
    return ids.shape[1], tok.decode(out[0, ids.shape[1]:]).strip()

cfg = AutoConfig.from_pretrained(repo)
for label, layer_types in [("as released (5 sliding : 1 global)", cfg.layer_types),
                           ("every layer sliding (window 512)", ["sliding_attention"] * cfg.num_hidden_layers)]:
    cfg_v = AutoConfig.from_pretrained(repo); cfg_v.layer_types = layer_types
    model = AutoModelForCausalLM.from_pretrained(repo, config=cfg_v, dtype=torch.float32).eval()
    answers = [ask(model, k) for k in ("48213", "71956", "30587")]
    print(f"{label:36s} prompt {answers[0][0]} tokens; answers: " + " | ".join(a for _, a in answers))
    if label.startswith("as released"):
        with torch.no_grad():
            cache = model(tok(prompt("48213"), return_tensors="pt").input_ids, use_cache=True).past_key_values
        kept = [layer.keys.shape[-2] for layer in cache.layers]
        print(f"{'':36s} tokens kept in each layer's KV cache: {kept}")
        print(f"{'':36s} cache size: {sum(kept) / (len(kept) * kept[cfg.layer_types.index('full_attention')]):.0%} of keeping all tokens in every layer")

As released, Gemma 3 270M repeats all three pass keys correctly from 1,465 tokens away, almost three windows back. The cache line shows how: the 15 sliding layers keep only their last 511 tokens, the 3 global layers keep all 1,465, and together the cache is 46% of what all-global layers would hold, the formula box's f+(1−f)W/n. Switch every layer to sliding, with the same weights, and the model answers "the pass key. The pass…" for every key: the key is far outside every window, and passing it forward through 18 layers of 512-token windows does not work in practice, even though 18×512 would in principle reach that far. The few global layers are what carry long-range recall, which is why no production model drops them entirely.

Break it on purpose

In swa_mask, change lo = max(0, i - window + 1) to lo = i - window + 1 without the max. For rows with i < window - 1, lo is negative. What does Python's range(lo, i + 1) then do to the mask, and why would the bug go unnoticed on long sequences but corrupt the first tokens of every one? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Mixed local and global layers ship in open models. Gemma 3 (5 sliding to 1 global, window 1,024), gpt-oss (alternating 128-token windows and full attention) and Llama 4 (chunked local attention with interleaved global layers) cut long-context memory this way; transformers, vLLM and llama.cpp keep separate caches per layer type.
  • Learned sparsity in production. DeepSeek-V3.2 (2025) adds DeepSeek Sparse Attention, a lightweight indexer that selects which earlier tokens each query attends to, to cut long-context cost.
  • Masks as code. PyTorch's FlexAttention compiles mask functions (sliding windows, document masks for packed sequences, prefix-LM masks) into fused kernels, and is used in training stacks such as torchtitan.

Sources: Gemma 3 report, gpt-oss model card, Llama 4, DeepSeek-V3.2-Exp, FlexAttention.

Recap
What to keep from this lesson
  • Variants are masks: causal, sliding window, strided, learned block selection.
  • Sliding layers cut attention work to ≈2W/n and keep only W cached tokens; a few global layers preserve long-range recall.
  • Gemma 3 270M: global layers are what retrieve the pass key; all-sliding fails.
  • Differential attention cancels shared noise between two maps; it is promising but not yet standard.

# Attention Variant Picker

Help a developer choose and justify an attention topology for a new transformer, or for an existing one they're extending to longer context.

## Inputs to gather

1. **Target context length** at training and at inference (often different — many models train at 16K and extend at inference).
2. **Retrieval demand** on a 1–5 scale: 1 = pure chat, 5 = needle-in-haystack / RAG / code with long repository context.
3. **Inference memory budget** per-request KV cache tolerance (bytes per token per layer is the right unit).
4. **Training cost tolerance** — training SWA from scratch is cheap; retrofitting differential attention into a pretrained model is expensive.
5. **Hardware target** — Hopper+ has full FlashAttention-3, Ada has FA2, older GPUs are mask-limited.

## Decision rules

- **Context ≤ 16K and retrieval ≤ 3**: full attention with FlashAttention. Don't optimize prematurely.
- **Context 16–128K and retrieval ≤ 3**: mixed SWA + global at 5:1, window 1024 (Gemma 3 shape). Keeps retrieval workable while collapsing KV.
- **Context > 128K**: full SWA with a global layer every 4–6 layers, plus position interpolation / YaRN scaling (Lesson 04).
- **Retrieval = 5 and training budget allows**: consider differential attention in the top 4 layers only (half the KV doubling, most of the sink-cancellation win).
- **You're shipping a public API**: prefer stable patterns (full, SWA, Gemma-3 mix). Skip native-sparse / DIFF unless you have kernel engineers.
- **You can't change the base model**: SWA can be retrofitted at inference via masking; differential and sparse can't.

## Always flag

- Pure-SWA models below 7B often lose measurably on reasoning benchmarks. Recommend against.
- Window size < 512 is almost never right. Go bigger or use a different topology.
- Differential attention reports in the paper are on small models (3–7B). Scale-up evidence is thin as of early 2026.
- Every variant interacts with RoPE / YaRN scaling (Lesson 04). State the position scheme explicitly.

## Output format

Return:

1. **Recommendation** — a single named topology (e.g. "Gemma-3 mix, W=1024, 5:1 SWA:global").
2. **Justification** — map each input to the decision rule above.
3. **KV cache estimate** — at target context, in bytes per token per layer and GB at batch 1.
4. **Migration path** — if the base model is already trained, how to retrofit.
5. **Known risks** — which benchmarks / workloads might regress.

Exercises

  2. Medium. Implement causal SWA with window=1024 on top of the Lesson 7.7 capstone. Train for 1,000 steps on tinyshakespeare. How much does val loss regress vs full attention? How much does peak memory drop?

  4. Hard. Implement differential attention with a learned λ per head. Train on a synthetic retrieval task (one needle, 2,000 distractors). Measure retrieval accuracy vs a single-attention baseline at matched parameters.

Solutions

SolutionP1 · Only the released model

Only the released model. With its three global layers it returns 48213, 71956 and 30587 exactly; with every layer sliding it answers "the pass key. The pass…" each time. The key sits about 1,450 tokens before the question, nearly three 512-token windows back. In theory sliding layers can relay information forward window by window (18×512=9,216 tokens of reach), but the model was trained with global layers doing that job, and without them the information never arrives.

SolutionB1 · Negative starts allow the whole prefix

range(lo, i + 1) with a negative lo starts at a negative index, and M[i][j] with negative j addresses columns counted from the end of the row: for row 0 with window = 4, lo = -3, so the loop unmasks columns n−3,n−2,n−1 and 0. The first tokens would then attend to the last tokens of the sequence, future positions the causal mask must hide, and the model could read answers during training. On long sequences only the first window - 1 rows are affected, so aggregate metrics barely move and the bug hides, while every sequence gets a few positions that see the future.
