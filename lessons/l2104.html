Why this came about

Programs are rarely alone: they read data from files and talk to other programs over the internet. In the 2000s, web services settled on a simple convention: send an HTTP request to a URL and get JSON back, text that looks like Python dictionaries and lists. Every AI model provider (OpenAI, Anthropic, Google and the rest) works this way: your prompt goes out as JSON, the model's answer comes back as JSON. Understanding one request and response end to end makes every AI SDK much less mysterious.

In plain words first
Letters and replies

A file is a box on your disk with text (or other data) inside; your program can open it, read it and write to it. A web API is a program on another computer that answers requests. Calling one is like posting a letter with a precise address (the URL), a type of request on the envelope (the method: GET "please send me", POST "please do this"), sometimes a pass in the envelope (an API key) and a form inside (the body, usually JSON). The reply comes back with a number on the envelope saying how it went (the status code: 200 means fine, 404 means not found) and an answer inside.

Step 1 · Reading and writing text files

So far everything has vanished when the program ended. A file keeps data on disk. Python's pathlib module gives you a Path object that stands for a file's location and has methods to write text to it, read the text back and ask questions about it. This code writes a two-line file, reads it and inspects it:

from pathlib import Path

notes = Path("notes.txt")                       # a path: where the file is (or will be)
notes.write_text("Refunds take 5 to 7 days.\nUPI refunds take 2 days.\n", encoding="utf-8")
text = notes.read_text(encoding="utf-8")
print(repr(text))
print(text.splitlines())
print(notes.exists(), notes.suffix, notes.stat().st_size, "bytes")

with open("log.txt", "a", encoding="utf-8") as f:    # "a" appends; "w" would overwrite
    f.write("order SK-1042 viewed\n")
    f.write("order SK-1042 refunded\n")
with open("log.txt", encoding="utf-8") as f:
    for line in f:                              # read one line at a time
        print("LOG:", line.strip())
What you should see
'Refunds take 5 to 7 days.\nUPI refunds take 2 days.\n'
['Refunds take 5 to 7 days.', 'UPI refunds take 2 days.']
True .txt 51 bytes
LOG: order SK-1042 viewed
LOG: order SK-1042 refunded
Reading this output
  • repr(text) shows the string the way you would type it, so invisible characters become visible: \n is the newline character that ends each line.
  • .splitlines() cuts the text into a list of lines without the newlines.
  • notes.suffix is the file extension, .txt; st_size is the size in bytes.
  • with open(...) as f: opens a file and closes it automatically when the indented block ends, even if an error happens. Always open files this way. The second argument is the mode: "r" read (the default), "w" write (replaces the file), "a" append.
  • encoding="utf-8" tells Python how characters are stored as bytes. UTF-8later · 5.3 handles every language, including ₹ and Hindi text; say it explicitly, because some computers default to something else.

Step 2 · CSV: tables in a text file

CSV (comma-separated values) is the simplest table format: one row per line, columns separated by commas. Spreadsheets and databases export it.

import csv

rows = [
    {"order_id": "SK-1", "city": "Pune", "total": 540},
    {"order_id": "SK-2", "city": "Delhi", "total": 1299},
    {"order_id": "SK-3", "city": "Pune", "total": 89},
]
with open("orders.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["order_id", "city", "total"])
    writer.writeheader()
    writer.writerows(rows)

print(Path("orders.csv").read_text())
with open("orders.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["order_id"], row["city"], int(row["total"]) * 2)
What you should see
order_id,city,total
SK-1,Pune,540
SK-2,Delhi,1299
SK-3,Pune,89

SK-1 Pune 1080
SK-2 Delhi 2598
SK-3 Pune 178

Notice int(row["total"]): a CSV file is plain text, so every value comes back as a string, and you convert numbers yourself. (newline="" is a detail the csv module asks for, so that line endings are handled correctly on every operating system.) For real data work, pandas reads CSV in one line and guesses the types for you (Lesson 0.15).

Step 3 · JSON: the language of APIs

JSON (JavaScript Object Notation) is text that writes data as nested objects (like dictionaries) and arrays (like lists). It is the format of nearly every web API and of most AI configuration and output.

import json

raw = '{"id": "SK-1042", "paid": true, "items": [{"sku": "TEA-1", "qty": 3}, {"sku": "RICE-5", "qty": 1}], "coupon": null}'
order = json.loads(raw)                 # JSON text -> Python objects
print(type(order), order["paid"], order["coupon"])
print(order["items"][1]["sku"])         # second item, its "sku"
print(sum(item["qty"] for item in order["items"]), "units")

order["status"] = "delivered"
print(json.dumps(order))                # Python objects -> compact JSON text
print(json.dumps({"ok": True, "eta": None}, indent=2))   # indented: easier for people to read

Path("order.json").write_text(json.dumps(order), encoding="utf-8")
print(json.loads(Path("order.json").read_text(encoding="utf-8"))["status"])

To find a value deep in JSON, read the path one step at a time: order is a dict → ["items"] is a list → [1] is its second element, a dict → ["sku"] is a string. When a language model is asked for structured outputlater · 11.2 (Lesson 11.2), it replies with JSON text that your code turns into Python with json.loads.

Step 4 · How a web API call works

Part Example Meaning
URL https://api.shopkart.test/orders/SK-1042 Where to send the request: the server, then the path of the resource
Method GET, POST, PUT, DELETE What you want: read, create or act, replace, delete
Headers Authorization: Bearer <key>, Content-Type: application/json Extra information: who you are, what format the body is in
Body {"order_id": "SK-1042", "amount": 540} The data you send (usually JSON); GET requests normally have none
Status code 200, 201, 400, 401, 404, 429, 500 How it went (table below)
Response body {"refund_id": "RF-77"} The answer, usually JSON
Status codes Meaning What your code should do
200 to 299 Success (200 OK, 201 Created) Read the body
400 Bad request: your data was wrong Fix the request; retrying will not help
401, 403 Not authenticated, or not allowed Check the API key and permissions
404 Not found The URL or ID is wrong
429 Too many requests: you hit a rate limit Wait, then retry (Lesson 14.5)
500 to 599 The server failed Retry later, a limited number of times

Step 5 · Calling an API with requests

To keep this runnable without internet access or an account, the next chapter starts a tiny ShopKart API on your own computer in the background. You do not need to understand the server code; it is there so the call in the following block has something to talk to. 127.0.0.1 is the address that always means "this computer".

import threading
from http.server import BaseHTTPRequestHandler, HTTPServer

ORDERS = {"SK-1042": {"id": "SK-1042", "status": "shipped", "total": 540}}

class ShopKartAPI(BaseHTTPRequestHandler):
    def _send(self, status, body):
        data = json.dumps(body).encode()
        self.send_response(status)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)
    def do_GET(self):
        order_id = self.path.rsplit("/", 1)[-1]
        if self.path.startswith("/orders/") and order_id in ORDERS:
            self._send(200, ORDERS[order_id])
        else:
            self._send(404, {"error": f"no order {order_id}"})
    def do_POST(self):
        if self.headers.get("Authorization") != "Bearer test-key-123":
            return self._send(401, {"error": "missing or wrong API key"})
        body = json.loads(self.rfile.read(int(self.headers["Content-Length"])))
        self._send(201, {"refund_id": "RF-77", "order_id": body["order_id"], "status": "queued"})
    def log_message(self, *args):
        pass                                             # keep the output quiet

server = HTTPServer(("127.0.0.1", 0), ShopKartAPI)       # port 0: let the computer pick a free port
threading.Thread(target=server.serve_forever, daemon=True).start()
BASE = f"http://127.0.0.1:{server.server_port}"
print("local API running")
What you should see
local API running

Now the part that matters, the client. This is the same code you would write against any real API, with a different BASE:

import requests

r = requests.get(f"{BASE}/orders/SK-1042", timeout=5)
print(r.status_code, r.headers["Content-Type"])
print(r.json())                      # parse the JSON body into a dict
print(r.json()["status"])

r = requests.get(f"{BASE}/orders/SK-9999", timeout=5)
print(r.status_code, r.json())
What you should see

{'id': 'SK-1042', 'status': 'shipped', 'total': 540}

404 {'error': 'no order SK-9999'}

Sending data uses POST with a JSON body, and most APIs require a key in a header:

import os
os.environ["SHOPKART_API_KEY"] = "test-key-123"        # stands in for a key set outside the code (see below)

def request_refund(order_id, amount):
    key = os.environ.get("SHOPKART_API_KEY")
    if not key:
        raise RuntimeError("Set SHOPKART_API_KEY first")
    r = requests.post(f"{BASE}/refunds",
                      json={"order_id": order_id, "amount": amount},   # requests turns the dict into JSON
                      headers={"Authorization": f"Bearer {key}"},
                      timeout=10)
    r.raise_for_status()                                # turn 4xx and 5xx answers into a Python error
    return r.json()

print(request_refund("SK-1042", 540))
r = requests.post(f"{BASE}/refunds", json={"order_id": "SK-1042"}, timeout=10)   # no key
print(r.status_code, r.json())
try:
    r.raise_for_status()
except requests.HTTPError as e:
    print("HTTPError:", e.response.status_code, e.response.reason)
What you should see
{'refund_id': 'RF-77', 'order_id': 'SK-1042', 'status': 'queued'}
401 {'error': 'missing or wrong API key'}
HTTPError: 401 Unauthorized
Reading this output
  • json=... sends the dictionary as a JSON body and sets the Content-Type header for you.
  • headers={"Authorization": f"Bearer {key}"} is the common way to send an API key: the word Bearer, a space, then the key.
  • raise_for_status() does nothing on success and raises requests.HTTPError for any 4xx or 5xx status, so failures cannot slip by unnoticed.
  • timeout=10 gives up after 10 seconds. Without a timeout, a call to a server that never answers can hang your program forever. Every network call in this course sets one.
Watch out
Keep keys out of your code

The os.environ[...] = ... line above only stands in for a real key. In real projects never write a key in code: anyone who sees the file (or its history in git) can spend your money. Put keys in a .env file (Lesson 0.1), load them with python-dotenv, and read them with os.environ.get(...):

# uv add python-dotenv
from dotenv import load_dotenv
load_dotenv()                                # reads .env into the environment
key = os.environ.get("OPENAI_API_KEY")

Step 6 · What an AI SDK does for you

An SDK (software development kit) is a library that wraps an API in friendly Python functions. When the Talking to models: APIs, messages, prompts and context section calls a model with client.messages.create(...), the SDK builds the URL, adds your key as a header, turns your arguments into a JSON body, sends a POST request, checks the status code, retries on 429 and 5xx, and turns the JSON answer back into Python objects. Everything in Step 5, packaged. Knowing the layers underneath means that when something fails, an error such as 401 Unauthorized or 429 Too Many Requests tells you exactly what to check.

server.shutdown()                                       # stop our local test API
print("server stopped")
What you should see
server stopped
Check your mental model
  • ✗ "JSON is a Python feature."
    ✓ It is plain text that every language can read; Python converts it to dicts and lists with json.loads.
  • ✗ "Values read from a CSV file are already numbers."
    ✓ They are strings until you convert them.
  • ✗ "A 200 status means the answer is what I wanted."
    ✓ It means the request worked; still check the body (an empty result, a different shape).
  • ✗ "Timeouts are optional."
    ✓ Without one, a call to an unresponsive server can wait forever.

Exercises

Predict before you run

What does json.loads('[1, "two", true, null]') give back? Write the Python value, then check. (Solution P1.)

Debugging exercise

A script prints 401 {'error': 'missing or wrong API key'} when calling the refund endpoint, even though .env contains SHOPKART_API_KEY=test-key-123. List three likely causes. (Solution D1.)

Make it your own

Write a function order_status(order_id) that calls the local API, returns the status string on success, returns "unknown order" on 404, and raises an error for anything else. Test it with SK-1042 and SK-9999 (start the server block again if you stopped it). (Solution M1.)

Solutions

SolutionP1 · JSON array

[1, 'two', True, None]: a Python list with an int, a string, True (from true) and None (from null).

SolutionD1 · A key that is not arriving

(1) load_dotenv() was never called, so the .env file was not read; check with print(os.environ.get("SHOPKART_API_KEY")). (2) The script runs from a different folder than the one containing .env. (3) The header is malformed, for example "Bearer" + key without a space, or a different header name. Printing r.request.headers shows exactly what was sent (without sharing that output, since it contains the key).

SolutionM1 · A small client function
def order_status(order_id):
    r = requests.get(f"{BASE}/orders/{order_id}", timeout=5)
    if r.status_code == 404:
        return "unknown order"
    r.raise_for_status()
    return r.json()["status"]

print(order_status("SK-1042"), "|", order_status("SK-9999"))   # shipped | unknown order

Handling 404 deliberately and letting other errors raise is the same pattern good agent tools use in the Agents from first principles section: expected outcomes become answers, unexpected ones become visible errors.

Recap
  • Use pathlib.Path and with open(...) for files, and say encoding="utf-8".
  • CSV values arrive as strings; JSON maps to dicts and lists with json.loads and json.dumps.
  • An API call is a URL, a method, headers, an optional JSON body, and a response with a status code and a body.
  • With requests: pass json=, put the key in an Authorization header from an environment variable, call raise_for_status(), always set timeout=.
  • AI SDKs wrap exactly these steps.
