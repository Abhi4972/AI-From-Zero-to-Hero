In plain words first
The idea in one line

At 64k tokens, attention eats 70-80% of decode latency. Every open-model lab has a plan to fix it. DeepSeek's NSA (ACL 2025 best paper) is the one that stuck: three parallel attention branches — compressed coarse-grained tokens, selectively retained fine-grained tokens, and sliding windows for local context — combined through a learned gate. The problem

In plain words first

When a model writes the next token, every attention head reads the keys and values of every earlier token. At 64,000 tokens that reading dominates the time per token. Native Sparse Attention (NSA, DeepSeek, 2025) reads much less: a coarse summary of the whole context (one summary per small block of tokens), the full detail of only the few blocks the summaries say are relevant, and the most recent 512 tokens. A learned gate mixes the three. Because the model is trained with this pattern from the start, it learns to put information where the sparse reader will find it. This lesson runs the lesson's toy, counts exactly what the paper's settings read, tests when block summaries can find a single relevant token, and checks how much of a real dense model's attention an NSA-style selection would keep. No model is trained.

Full attention at sequence length N costs O(N^2) time and O(N) KV cache per layer. At 64k tokens, the compute and memory bandwidth numbers are catastrophic. Measured theoretical estimate from the NSA paper: attention accounts for 70-80% of total decode latency at 64k. Everything downstream — TTFT, tokens/sec, cost per million tokens — is dominated by attention cost.

Sparse attention is the obvious answer. Prior attempts fall into two buckets. Fixed-pattern sparsity (sliding-window, strided, block-local) throws information away and fails on long-range recall tasks. Inference-time sparsity (KV cache pruning, H2O, StreamingLLM) is applied to a model pre-trained on dense attention and recovers only a fraction of the potential speedup because the model was never asked to route information through the sparse pattern.

Native Sparse Attention (Yuan et al., DeepSeek + PKU + UW, ACL 2025 best paper, arXiv:2502.11089) does both: a sparsity pattern the model learns during pre-training, implemented as a kernel-aligned algorithm that actually delivers the compute savings at inference. Its production descendant, DeepSeek Sparse Attention (DSA), already runs in DeepSeek-V3.2.

Idea 1 · Three parallel branches

For each query, NSA runs attention three times, against three different views of the KV cache:

  1. Compressed branch. Tokens are grouped into blocks of length l = 32 that overlap with a stride of 16, so a new summary starts every 16 tokens. Each block is compressed into a single summary key and value by a small learned MLP with a position encoding inside the block. The query attends over these compressed tokens, getting a coarse-grained view of the whole sequence.

  2. Selected branch. Using attention scores from the compressed branch, the top-k blocks most relevant to the current query are identified. Fine-grained (uncompressed) tokens from those blocks are read and the query attends over all of them. Think of compressed-branch attention as the routing signal for the selection. The paper selects 16 blocks of 64 tokens, of which the first block and the 2 most recent blocks are always included, and all query heads of a GQA group share the same selection (their scores are summed) so the blocks are loaded once per group.

  3. Sliding-window branch. The query attends to the most recent W tokens (typically 512) for local context. This branch captures the structure-heavy short-range patterns (syntax, local coreference) that the other two might miss.

The three branch outputs are combined via a learned per-position gate:

out=gcmp​⋅outcmp​+gsel​⋅outsel​+gwin​⋅outwin​

g_cmp, g_sel, g_win are gate weights from a small MLP on the query. They do not have to sum to 1 — they can weight branches independently.

Idea 2 · Why this is "natively trainable"

The selection step (top-k blocks) is discrete. Discrete operations break gradient flow. Prior sparse-attention work either skipped backprop through selection (limiting training) or used continuous relaxations that did not give real sparsity at inference.

NSA sidesteps this: the compressed-branch attention IS a differentiable coarse-grained attention on the whole sequence. The top-k operation just reuses the top attention scores from the compressed branch to pick which fine-grained blocks to load. Gradients reach the compressed-branch scores through the compressed branch's own output, not through the choice of blocks. Inside the chosen blocks, attention over the selected keys and values is ordinary attention, so their contribution to the final output is differentiable too. The top_k index choice itself gets no gradient: it only controls which blocks get loaded from memory.

This is why NSA can be used in pre-training end to end. The model learns to route information through the three branches jointly, producing a sparse pattern that at inference actually delivers the promised speedup.

Idea 3 · Hardware-aligned kernel

NSA's kernel is designed for modern GPU memory hierarchies. The kernel loads queries by GQA groups (outer loop), fetches the corresponding sparse KV blocks per group (inner loop), and runs attention on SRAM. Because each query group sees the same selected blocks (selection is per-query-group, not per-query-head), the KV loads are amortized across the group. Arithmetic intensity stays high.

The paper reports Triton kernels up to 9.0× faster than FlashAttention-2 in the forward pass and 6.0× in the backward pass at 64K tokens, and an expected decoding speedup of up to 11.6× (5,632 instead of 65,536 tokens read per step), growing with sequence length.

Idea 4 · The compute budget

Let N be sequence length, l the compression block size, k the top-k selection count, w the sliding window, b the selected block size (typically equals l).

  • Compressed branch: O(N/l) keys per query, so O(N * N / l) total.
  • Selected branch: O(k * b) keys per query, so O(N * k * b).
  • Sliding branch: O(w) keys per query, so O(N * w).

Total: O(N * (N/l + k*b + w)).

With N = 64k, l = 64, k = 16, b = 64, w = 512: per-query cost is 1000 + 1024 + 512 = 2536 keys. Full attention is 64000 keys. 25x compute reduction.

With N = 128k, l = 64, k = 16, b = 64, w = 512: per-query cost is 2000 + 1024 + 512 = 3536 keys. Full attention is 128000 keys. 36x reduction. The benefit grows with sequence length, which is the whole point. (These counts use one summary per 64 tokens. With the paper's overlapping compression, one summary every 16 tokens, the compressed branch reads N/16 keys and the reduction at 64K is 11.6×; see the exact computation after Build it.)

Idea 5 · How does it compare

Method Differentiable Real inference speedup Long-range recall
Sliding window only yes yes fails
Strided / block-sparse yes yes partial
KV pruning (H2O, StreamingLLM) N/A (inference-time) yes partial
MoBA (Moonshot) partial yes good
NSA yes (natively) yes (up to 11.6× decode, 9× forward at 64k) matches full attention

MoBA (Moonshot, arXiv:2502.13189) was published the same week and is simpler: no compressed or sliding branch, just a parameter-free router that scores each block by its mean-pooled key and attends to the top-k blocks plus the current one, the MoE principle applied to attention blocks. Moonshot reports it serving Kimi's long-context requests.

The same idea as a formula

For query qt​, each branch c∈{cmp,sel,win} runs ordinary attention over its own keys and values K~tc​,V~tc​:

ot​=c∑​gtc​Attn(qt​,K~tc​,V~tc​),gtc​=σ(MLP(xt​))c​∈[0,1].

Compressed keys. With block length l and stride s: k~icmp​=φ(kis+1:is+l​), about t/s of them.

Selection. The compressed attention scores ptcmp​=softmax(qt⊤​K~tcmp​), summed over the heads of a GQA group, rank the selection blocks; the top n blocks of l′ tokens are read in full.

Tokens read per step: st​+nl′+w instead of t.

Why a block summary can miss a needle. If one token in a block of l has score m and the others have independent scores of standard deviation 1, the mean-pooled block score has mean m/l and noise 1/l​: a signal-to-noise ratio of m/l​.

Worked example
The paper's settings at 64K tokens

s=16, l′=64, n=16, w=512, t=65,536:

  • Compressed: 65,536/16=4,096 summaries.
  • Selected: 16×64=1,024 tokens.
  • Window: 512 tokens.
  • Total: 5,632 tokens read, against 65,536: 11.6× fewer, the paper's expected decoding speedup.

At 128K the compressed branch doubles to 8,192 while the other two stay fixed: 9,728 tokens, 13.5×. The compressed branch grows linearly, so the gain levels off.

Check your mental model
  • ✗ "NSA shrinks the KV cache."
    ✓ It reads less per step but stores every token (and the summaries on top): any block may be selected later.
  • ✗ "Top-k selection makes training impossible."
    ✓ The block choice gets no gradient, but everything it feeds is ordinary attention, and the compressed branch that ranks the blocks is trained through its own output.
  • ✗ "Mean-pooled summaries find any relevant token."
    ✓ A single token's score is diluted by the block length; small blocks, overlap and a learned compressor exist to counter that (the exact computation, part C).

Step 1 · compress tokens into blocks

code/main.py implements the three branches on a short synthetic sequence and shows:

  • The compression MLP (a simple mean-pool baseline is used for pedagogical clarity; the real NSA uses a learned MLP).
  • The top-k block selection driven by compressed-branch scores.
  • The sliding-window attention on the last w tokens.
  • The gated combination.
  • A compute-count printout comparing to full attention.
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out

Step 2 · compressed-branch attention

Run softmax attention of the query against the compressed keys. The compressed-branch scores double as the signal for top-k selection.

Step 3 · top-k block selection

Pick the indices of the k highest-scoring compressed blocks. Load the original uncompressed tokens from those blocks and run attention on them.

Step 4 · sliding-window attention

Take the last w tokens and run standard attention against them.

Step 5 · gate + combine

A small MLP on the query produces three gate weights. The final output is a weighted sum of the three branch outputs.

Step 6 · compute counting

Print the number of keys attended per query for each branch and the total. Compare to N (full attention). On a 1024-token synthetic with l = 32, k = 4, w = 128, NSA sees 32 + 128 + 128 = 288 keys per query versus 1024 for full attention — 3.5x fewer.

Reading this output

Step 1. The query reads 288 of 1,024 keys and the selection finds all three signal blocks (block 6 fills the fourth slot by chance). This is the easy case for block selection: in the synthetic sequence every token of a signal block carries the query's pattern, so averaging a block does not dilute the signal. A single relevant token among 31 others is much harder (the next run, part C). The gate weights come from a random matrix, so 0.34 / 0.36 / 0.46 only show the mechanics: independent sigmoids that need not sum to 1.

Step 2. The key counts use one summary per block of l tokens: 25.6× fewer keys at 64K and 36.6× at 128K. The paper's compression uses overlapping blocks with a stride of 16, which gives four times more summaries at the same settings and a reduction of 11.6× at 64K (next run, part A).

Step 3. With the selection block equal to the compression block, larger blocks shrink the compressed branch but enlarge every selected block, so the cost has a minimum (32× at l = 64 or 128 with k = 8). Cost is only half the trade: larger blocks also make each summary a blurrier average.

Reading this output

A. With the paper's settings, the selected blocks (1,024 tokens) and the window (512) are fixed, and the compressed branch grows as t/16. At 64K the total is 5,632 tokens, the 11.6× reduction the paper reports for decoding. At 8K the gain is only 4×, and beyond 128K it levels off near 15× because the compressed branch, still linear in t, dominates.

B. NSA does not save memory. All 128K tokens stay in the cache (40 GiB for this 70B-class configuration), plus 6% for the summaries, because any block might be selected by a later query. What it saves is the amount read per step: about 3 GiB instead of 40 GiB, which is what sets the speed of memory-bound decoding.

C. Selecting the 1,024 best single tokens always finds the needle. Selecting blocks by their mean-pooled key finds it far less reliably, and the larger the block the worse: with a logit margin of 8, 76% of the time with blocks of 16 but 30% with blocks of 128. The needle's margin is divided by the block length while the other tokens' noise only shrinks as the square root, so the block's signal-to-noise ratio is m/l​. This is why NSA uses small (32), overlapping compression blocks with a learned compressor, why the model must be trained with the sparsity so that it learns keys that stand out after compression, and why DeepSeek's later DSA scores single tokens.

Use it: the same idea with real libraries

No released model uses NSA itself. DeepSeek's production descendant is DeepSeek Sparse Attention (DSA) in DeepSeek-V3.2-Exp (September 2025) and DeepSeek-V3.2. DSA keeps NSA's idea of choosing what to read but works on single tokens instead of blocks: a small FP8 lightning indexer scores every earlier token, and each query attends to the top 2,048. It was added to an existing dense-attention model by continued training.

  • vLLM and SGLang: support DeepSeek-V3.2 with DSA (vLLM from launch day, 29 September 2025).
  • TensorRT-LLM: optimised DeepSeek-V3.2 kernels for Blackwell GPUs.
  • llama.cpp / CPU: not the target; sparse kernels pay off at long contexts on GPUs.

When to reach for NSA:

  • Pre-training or continued-training run targeting 64k-plus context with a serious compute budget.
  • Inference of DeepSeek-V3.2 checkpoints, whose sparse attention (DSA) is built in.

When not to:

  • Serving an existing dense-attention pre-trained model. You cannot retrofit NSA without continued training.
  • Context under 16k. The three-branch overhead dominates the savings.
  • Batch-1 interactive chat. Latency-sensitive decode benefits, but only at long contexts.

NSA-style selection applied to a real dense model

SmolLM2-360M at 4,095 tokens (Wikipedia text with a 4-digit code in the middle, as in Lesson 10.16). For the last token, in every one of the 160 GQA groups, keep the first block, the last 512 tokens and 13 more blocks of 64, chosen four ways: by the compressed (mean-pooled key) score as NSA does, by the true attention mass (the best possible), at random, or none. Reported: the share of each head's full attention that falls on the kept tokens. Inference only, about a minute.

import torch, transformers, datasets
import transformers.models.llama.modeling_llama as llama
from transformers import AutoTokenizer, AutoModelForCausalLM
transformers.logging.disable_progress_bar(); transformers.logging.set_verbosity_error(); datasets.disable_progress_bars()
name = "HuggingFaceTB/SmolLM2-360M"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, torch_dtype=torch.float32, attn_implementation="eager").eval()
cfg = model.config
H, G = cfg.num_attention_heads, cfg.num_key_value_heads

grab = []                                         # per layer: last query, keys (after RoPE), last attention row
orig = llama.eager_attention_forward
def spy(module, query, key, value, attention_mask, **kw):
    out, w = orig(module, query, key, value, attention_mask, **kw)
    grab.append((query[0, :, -1].clone(), key[0].clone(), w[0, :, -1].clone()))
    return out, None
llama.eager_attention_forward = spy

wiki = datasets.load_dataset("Salesforce/wikitext", "wikitext-2-raw-v1", split="test")
filler = tok(" ".join(t.strip() for t in wiki["text"][:600] if t.strip()))["input_ids"]
needle = tok(" The secret code for the vault is 7341.")["input_ids"]
question = tok(" Remember: the secret code for the vault is ")["input_ids"]
L, B, W, NSEL = 4096, 64, 512, 16                 # context, selection block, window, blocks (1 initial + 2 local + 13 chosen)
half = (L - len(needle) - len(question)) // 2
ids = (filler[:half] + needle + filler[half:2 * half] + question)[:L]
digits = [half + i for i, t in enumerate(needle) if tok.decode([t]) in "7341"]
with torch.no_grad():
    nxt = model(torch.tensor([ids])).logits[0, -1].argmax().item()
n = len(ids); nb = n // B
print(f"{name}: {cfg.num_hidden_layers} layers, {H} query heads in {G} GQA groups; context {n} tokens, next token {tok.decode([nxt])!r}")
print(f"NSA-style budget: first block + last {W} tokens + {NSEL - 3} more blocks of {B} = about "
      f"{B + W + (NSEL - 3) * B} of {n} tokens ({(B + W + (NSEL - 3) * B) / n:.0%})")

res = {"compressed score (NSA)": [], "best possible blocks": [], "random blocks": [], "window + first block only": []}
needle_hit, needle_heads = 0, 0
g = torch.Generator().manual_seed(0)
for q, k, w in grab:
    for grp in range(G):
        heads = range(grp * H // G, (grp + 1) * H // G)
        base = set(range(n - W, n)) | set(range(B))
        cand = [b for b in range(nb) if b != 0 and b * B < n - W]          # blocks outside window and first block
        kb = k[grp, :nb * B].reshape(nb, B, -1).mean(1)                      # mean-pooled block keys
        score = sum(torch.softmax(q[h] @ kb.T / q.shape[-1] ** 0.5, -1) for h in heads)   # summed over the group
        mass = sum(w[h, :nb * B].reshape(nb, B).sum(1) for h in heads)
        picks = {
            "compressed score (NSA)": sorted(cand, key=lambda b: -score[b])[:NSEL - 3],
            "best possible blocks": sorted(cand, key=lambda b: -mass[b])[:NSEL - 3],
            "random blocks": [cand[i] for i in torch.randperm(len(cand), generator=g)[:NSEL - 3]],
            "window + first block only": [],
        }
        for key, blocks in picks.items():
            keep = base | {t for b in blocks for t in range(b * B, b * B + B)}
            idx = torch.tensor(sorted(keep))
            for h in heads:
                res[key].append(w[h, idx].sum().item())
        for h in heads:                                                       # heads that look at the code
            if w[h, digits].sum() > 0.3:
                needle_heads += 1
                needle_hit += (digits[0] // B) in picks["compressed score (NSA)"]
print()
print(f"{'blocks chosen by':<27} {'median head keeps':>18} {'worst 10% of heads keep':>24}")
for key, v in res.items():
    v = torch.tensor(v)
    print(f"{key:<27} {v.median():>17.0%} {v.quantile(0.1):>24.0%}")
print(f"\nheads putting over 30% of attention on the code: {needle_heads}; the code's block selected for {needle_hit} of them")

Reading this output

Keeping 34% of the tokens, the median head keeps 94% of its attention when blocks are chosen from mean-pooled keys, against 99% for the best possible blocks and 86% for random ones; the first block and window alone already hold 82% (much of it the attention sink on token 0 and the recent text). The selection works for typical heads in a model that was never trained to be sparse.

It is the hard heads that suffer: for the worst 10% of heads only 64% survives (88% with the best blocks). Of the 16 heads that put more than 30% of their attention on the hidden code, the compressed score selected the code's block for 11, so 5 retrieval heads would have lost the code. The best-possible column shows that the right blocks exist; the mean-pooled keys of a dense model cannot always find them. Training with the sparsity in place (NSA) or continued training with a learned token indexer (DeepSeek-V3.2's DSA) closes this gap; bolting selection onto a dense model does not.

Break it on purpose

Drop the sliding-window branch and the two forced local blocks, keeping only compressed attention and top-k selection. What breaks first, and where would you see it? (Solution B1.)

Industry practice
What's current (2024–2026)
  • DeepSeek Sparse Attention (DSA) in DeepSeek-V3.2: a token-level lightning indexer picks the top 2,048 tokens per query; served by vLLM, SGLang and TensorRT-LLM.
  • MoBA (Moonshot): block top-k attention serving Kimi's long-context requests.
  • Hybrid local/global attention is the more common production answer to long-context cost: sliding-window layers interleaved with full-attention layers (Gemma 3, gpt-oss), or linear-attention layers mixed with full attention (Qwen3-Next, MiniMax).

Sources: NSA paper, DeepSeek-V3.2 report, vLLM: DeepSeek-V3.2-Exp, TensorRT-LLM: DeepSeek-V3.2 on Blackwell, MoBA, Gemma 3 report.

Recap
What to keep from this lesson
  • Three branches: compressed summaries, selected blocks in full, a sliding window; a sigmoid gate mixes them.
  • The compressed branch's scores choose the blocks, so selection needs no gradient of its own.
  • Paper settings read 5,632 of 65,536 tokens at 64K: 11.6× fewer.
  • NSA cuts reads, not storage.
  • Block summaries dilute single tokens by the block length; DSA selects single tokens instead.

Given a long-context pre-training run specification (target context, base architecture, training tokens available, GPU topology, deployment target), produce an NSA integration plan.

Produce:

1. Compression block size `l`. Pick 32, 64, or 128. Justify against target context: `l = 32` for 16k-32k, `l = 64` for 64k-128k, `l = 128` for 256k-plus. Larger `l` means fewer compressed keys but coarser routing signal.
2. Top-k selection count. Pick between 8 and 32. The paper's default is 16. Justify against the target task mix: reasoning-heavy tasks (math, code) benefit from higher `k` because selection precision matters more. Retrieval-heavy tasks work at lower `k`.
3. Sliding window `W`. Pick 256, 512, or 1024. Default 512. Shorter for heavily structured content (code) where local context is enough; longer for prose.
4. Gate MLP. Specify width and initialization. Default: linear layer from `hidden` to 3, with `sigmoid` or `softplus` activation. Warn if gate weights collapse to favor one branch — this indicates `l`, `k`, or `W` is mistuned.
5. Kernel choice. Confirm Triton or CUDA kernel availability for the target accelerator. Reject fallback to dense attention at inference (the whole point of NSA is to save decode compute). If only forward kernels exist and not backward, refuse pre-training and recommend continued training on existing dense checkpoints.

Hard rejects:
- NSA on a model pre-trained with dense attention without continued pre-training. Cannot be bolted on at inference.
- Target context under 16k. The three-branch overhead dominates.
- Inference-only deployments on stacks without NSA kernel support. Recommend MLA or sliding-window attention instead.

Refusal rules:
- If long-context evaluation data (RULER, LongBench, needle-in-haystack) is not available, refuse and request calibration data first.
- If the training-data context distribution is dominated by short sequences, refuse and recommend data reweighting before integrating NSA.
- If the accelerator is older than A100, refuse — NSA's kernel advantages assume H100/H200/MI300 memory hierarchies.

Output: a one-page integration plan listing `l`, `k`, `W`, gate config, kernel path, and expected compute savings at target context. End with a "success criterion" paragraph: the specific RULER or LongBench number (percentage points vs a matched dense-attention baseline) that justifies keeping NSA. Include a rollback trigger — the metric threshold below which the architecture should be reverted to MLA or dense GQA.

Solutions

SolutionP1 · About 94% for the median head

About 94%: the median head keeps 94% of its attention, and 82% is already in the first block and the last 512 tokens. Attention in a trained model is concentrated: on the first tokens (the attention sink), on the recent text, and on a few relevant spans, so a third of the context carries almost all of it. The tail is where it hurts: the worst 10% of heads keep only 64%, and 5 of the 16 heads that read the hidden code would lose it. Averages look fine; the heads that do long-range retrieval are the ones a poor selection breaks.

SolutionB1 · Local coherence and the newest tokens

Local text breaks first. Without the window, the newest tokens are only reachable through the selection, which must compete with every other block for a fixed number of slots, and through blurry summaries. The paper keeps both the window and two forced local blocks precisely so that grammar, word pieces and nearby references never depend on the selection. You would see it first in perplexity on ordinary text and in malformed output (wrong word endings, broken code syntax), long before any long-context benchmark moves. The paper also argues the window lets the other two branches specialise in long-range information instead of being dominated by easy local patterns during training.
