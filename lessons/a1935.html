In plain words first
The idea in one line

Twelve blocks stacked, a token embedding, a learned position embedding, a final LayerNorm, and a tied language model head. That is the entire 124 million parameter GPT model. This lesson assembles those pieces into a working class, counts the parameters to confirm the model matches the reference 124M shape, and generates text with multinomial sampling, temperature, and top-k.

Terms you'll hear
Term What people say What it actually means
Weight tying "Tied embeddings" The LM head and the token embedding share the same parameter tensor; saves vocab times d_model parameters and matches the GPT-2 reference
Position embedding "Learned positions" A separate table of shape (context length, d_model) added to token vectors; learned end to end
Sliding window context "Context cap" When the prompt plus generated tokens exceed the context length, drop the oldest tokens so the active window fits
Top-k sampling "K truncation" Keep the K logits with the highest values, mask the rest to negative infinity, softmax over the remainder
Temperature "Sampling temperature" Divide logits by T before softmax; T less than 1 sharpens, T equal to 1 keeps the natural distribution, T greater than 1 flattens

The problem

In plain words first

A GPT model is four steps around a stack of transformer blocks: look up a token embedding for each id, add a position embedding, run the vectors through the blocks, then apply a final LayerNorm and an LM head that turns each vector into a score (logit) for every word in the vocabulary. GPT-2 small uses 12 blocks of width 768, a 50,257-token vocabulary and 1,024 positions, about 124 million parameters. The LM head usually shares its weights with the token embedding (weight tying), saving 38.6 million parameters. Generation repeats one step: take the logits for the last position, divide by a temperature, optionally keep only the top-k candidates, sample one token, append it, and continue.

A transformer block does nothing on its own. You need to turn token ids into vectors, mix in positional information, run them through the stack, and project back to vocabulary logits. Forget any one of those four steps and the model either fails to forward, drifts in position information, or cannot speak.

The shape of the model also matters. The reference GPT-2 small is 124 million parameters at exactly the configuration above. The numbers are not magic. Vocab 50257 times embedding 768 is the token table. Position 1024 times 768 is the position table. Twelve blocks at roughly 7 million parameters each is 84 million. The final head reuses the token table by weight tying. Sum the pieces and you land on 124 million. Building a model whose parameter count does not match the reference is a sign you wired something wrong.

The idea

Token ids become token vectors. Position ids become position vectors. The two are added and sent through the stack. The final LayerNorm is the one piece outside the blocks that survives every modern variant. The LM head reuses the token embedding matrix, which is what weight tying means.

Idea 1 · Weight tying

The token embedding has shape (vocab, d_model). The language model head needs to project from d_model back to vocab. Those are transposes of each other. Tying the two means literally the same parameter tensor, used twice. At vocab 50257 and d_model 768, the matrix is 38 million parameters. Untied, you pay for it twice. Tied, you pay for it once and you also get a slightly cleaner gradient signal because the embedding and head update together.

Idea 2 · Position embedding is learned, not sinusoidal

GPT-2 ships a learned position embedding. The position table is one parameter tensor of shape (1024, 768). The model looks up position 0 through T-1 at every forward and adds the lookup to the token embedding. This is the simplest of the position schemes (RoPE, ALiBi, T5 relative bias are the alternatives) and it is what the 124M reference uses.

Idea 3 · Generation: temperature, top-k, multinomial

Generation is autoregressive. At every step, the model returns logits over the full vocabulary at every position. You take the last position only, divide by temperature, optionally mask all but the top k logits to negative infinity, softmax to get probabilities, and sample one token from the resulting distribution.

Three knobs, three different behaviors. Temperature near zero collapses to greedy. Temperature one matches the model's natural distribution. Top-k one is greedy. Top-k forty filters the long tail. The combinations matter; the next lesson on training uses generation as a qualitative eval signal.

import math
def probs(logits, temperature=1.0, top_k=None):
    scaled = [l / temperature for l in logits]
    if top_k:
        cutoff = sorted(scaled, reverse=True)[top_k - 1]
        scaled = [s if s >= cutoff else -math.inf for s in scaled]
    m = max(scaled); e = [math.exp(s - m) for s in scaled]; z = sum(e)
    return [round(x / z, 3) for x in e]

Production patterns in the wild

Three patterns make the difference between a model that runs and a model that ships.

Initialize the residual projections small. The output projection of attention and the second linear of the MLP both feed directly into a residual add. Initializing those with the same standard deviation as every other linear gives a residual stream that grows with depth and pushes the final LayerNorm into a hot regime. Scale the std by 1 / sqrt(2 * num_layers) for those two projections; the residual stream stays in a sane range through twelve layers.

Cache the position id tensor, do not recompute. torch.arange(T) allocates fresh memory at every forward. Allocate once in __init__ for the maximum context, slice the first T entries per call, and skip the allocator round trip.

Tie weights at parameter level, not just by copying. Setting lm_head.weight = token_embedding.weight shares the tensor; copying does not. The optimizer needs to update one parameter and the autograd graph needs one accumulation. If you copy, the head drifts away from the embedding and weight tying buys you nothing.

Use it: the same idea with real libraries

  • The model class in this lesson is the same shape as the one the next lesson trains.
  • Replacing the learned position embedding with RoPE gets you the LLaMA family without touching the block or the head.
  • Replacing the GELU with SiLU and the LayerNorm with RMSNorm gets you the rest of the LLaMA family changes.
  • The generation function works with any logits source, not only this model. You can pull logits from a pretrained GPT-2 file in lesson 37 and reuse the same generation loop.

Part 1 of 5 · GPTConfig, LayerNorm

"""Assemble the lesson 34 transformer block into a 124M parameter GPT model.

Twelve blocks, a token embedding, a learned position embedding, a final LayerNorm,
and a language model head that ties to the token embedding. Parameter count
lands on ~124M at the reference configuration. The demo also runs a tiny
configuration end to end and exercises generation with temperature, top-k, and
multinomial sampling under a sliding window context.

Run: python3 code/main.py
"""

from __future__ import annotations

import math
from dataclasses import dataclass

import torch
import torch.nn as nn
import torch.nn.functional as F


@dataclass
class GPTConfig:
    """Reference 124M configuration matches the GPT-2 small architecture."""

    vocab_size: int = 50257
    context_length: int = 1024
    d_model: int = 768
    num_heads: int = 12
    num_layers: int = 12
    mlp_expansion: int = 4
    dropout: float = 0.1
    use_bias: bool = True
    weight_tying: bool = True


class LayerNorm(nn.Module):
    def __init__(self, d_model: int, eps: float = 1e-5) -> None:
        super().__init__()
        self.eps = eps
        self.scale = nn.Parameter(torch.ones(d_model))
        self.shift = nn.Parameter(torch.zeros(d_model))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        mean = x.mean(dim=-1, keepdim=True)
        var = x.var(dim=-1, keepdim=True, unbiased=False)
        return self.scale * (x - mean) / torch.sqrt(var + self.eps) + self.shift

Part 2 of 5 · MultiHeadAttention, FeedForward

class MultiHeadAttention(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        if cfg.d_model % cfg.num_heads != 0:
            raise ValueError("d_model must be divisible by num_heads")
        self.d_model = cfg.d_model
        self.num_heads = cfg.num_heads
        self.head_dim = cfg.d_model // cfg.num_heads
        self.context_length = cfg.context_length

        self.qkv = nn.Linear(cfg.d_model, 3 * cfg.d_model, bias=cfg.use_bias)
        self.out_proj = nn.Linear(cfg.d_model, cfg.d_model, bias=cfg.use_bias)
        self.attn_dropout = nn.Dropout(cfg.dropout)
        self.resid_dropout = nn.Dropout(cfg.dropout)

        mask = torch.triu(
            torch.ones(cfg.context_length, cfg.context_length, dtype=torch.bool),
            diagonal=1,
        )
        self.register_buffer("causal_mask", mask, persistent=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        batch, seq, dim = x.shape
        if seq > self.context_length:
            raise ValueError(
                f"sequence length {seq} exceeds context length {self.context_length}"
            )
        qkv = self.qkv(x)
        q, k, v = qkv.split(self.d_model, dim=-1)
        q = q.view(batch, seq, self.num_heads, self.head_dim).transpose(1, 2)
        k = k.view(batch, seq, self.num_heads, self.head_dim).transpose(1, 2)
        v = v.view(batch, seq, self.num_heads, self.head_dim).transpose(1, 2)
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.head_dim)
        mask = self.causal_mask[:seq, :seq]
        scores = scores.masked_fill(mask, float("-inf"))
        attn = F.softmax(scores, dim=-1)
        attn = self.attn_dropout(attn)
        out = attn @ v
        out = out.transpose(1, 2).contiguous().view(batch, seq, dim)
        out = self.out_proj(out)
        out = self.resid_dropout(out)
        return out


class FeedForward(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        hidden = cfg.mlp_expansion * cfg.d_model
        self.fc1 = nn.Linear(cfg.d_model, hidden, bias=cfg.use_bias)
        self.act = nn.GELU(approximate="tanh")
        self.fc2 = nn.Linear(hidden, cfg.d_model, bias=cfg.use_bias)
        self.dropout = nn.Dropout(cfg.dropout)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.dropout(self.fc2(self.act(self.fc1(x))))

Part 3 of 5 · TransformerBlock, GPTModel

class TransformerBlock(nn.Module):
    """Pre-LN block. Lesson 34 explains both configurations; the GPT-2 reference is pre-LN."""

    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.ln1 = LayerNorm(cfg.d_model)
        self.attn = MultiHeadAttention(cfg)
        self.ln2 = LayerNorm(cfg.d_model)
        self.mlp = FeedForward(cfg)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x + self.attn(self.ln1(x))
        x = x + self.mlp(self.ln2(x))
        return x


class GPTModel(nn.Module):
    """A decoder only transformer language model with weight tied LM head."""

    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.cfg = cfg
        self.tok_embed = nn.Embedding(cfg.vocab_size, cfg.d_model)
        self.pos_embed = nn.Embedding(cfg.context_length, cfg.d_model)
        self.embed_dropout = nn.Dropout(cfg.dropout)
        self.blocks = nn.ModuleList([TransformerBlock(cfg) for _ in range(cfg.num_layers)])
        self.final_ln = LayerNorm(cfg.d_model)
        self.lm_head = nn.Linear(cfg.d_model, cfg.vocab_size, bias=False)

        if cfg.weight_tying:
            self.lm_head.weight = self.tok_embed.weight

        position_ids = torch.arange(cfg.context_length, dtype=torch.long)
        self.register_buffer("position_ids", position_ids, persistent=False)

        self.apply(self._init_weights)
        self._scale_residual_projections()

    def _init_weights(self, module: nn.Module) -> None:
        if isinstance(module, nn.Linear):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)
            if module.bias is not None:
                nn.init.zeros_(module.bias)
        elif isinstance(module, nn.Embedding):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def _scale_residual_projections(self) -> None:
        scale = 1.0 / math.sqrt(2 * self.cfg.num_layers)
        for block in self.blocks:
            block.attn.out_proj.weight.data.mul_(scale)
            block.mlp.fc2.weight.data.mul_(scale)

    def forward(self, tokens: torch.Tensor) -> torch.Tensor:
        batch, seq = tokens.shape
        if seq > self.cfg.context_length:
            raise ValueError(
                f"sequence length {seq} exceeds context length {self.cfg.context_length}"
            )
        tok = self.tok_embed(tokens)
        pos = self.pos_embed(self.position_ids[:seq])
        x = self.embed_dropout(tok + pos)
        for block in self.blocks:
            x = block(x)
        x = self.final_ln(x)
        logits = self.lm_head(x)
        return logits

Part 4 of 5 · count_parameters, top_k_filter, generate

def count_parameters(model: nn.Module) -> int:
    """Count unique parameters. Weight tied tensors are counted once."""
    seen: dict[int, int] = {}
    for param in model.parameters():
        seen[id(param)] = param.numel()
    return sum(seen.values())


def top_k_filter(logits: torch.Tensor, top_k: int) -> torch.Tensor:
    if top_k is None or top_k <= 0:
        return logits
    top_k = min(top_k, logits.size(-1))
    values, _ = torch.topk(logits, top_k, dim=-1)
    threshold = values[..., -1:]
    return torch.where(logits < threshold, torch.full_like(logits, float("-inf")), logits)


def generate(
    model: GPTModel,
    prompt: torch.Tensor,
    max_new_tokens: int,
    temperature: float = 1.0,
    top_k: int | None = None,
    seed: int | None = None,
) -> torch.Tensor:
    """Autoregressive generation with multinomial sampling, temperature, top-k.

    Holds the active window to model.cfg.context_length by sliding the oldest
    tokens out when the running sequence overflows.
    """
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    if seed is not None:
        torch.manual_seed(seed)

    was_training = model.training
    model.eval()
    tokens = prompt.clone()
    try:
        with torch.no_grad():
            for _ in range(max_new_tokens):
                window = tokens[:, -model.cfg.context_length:]
                logits = model(window)
                next_logits = logits[:, -1, :] / temperature
                next_logits = top_k_filter(next_logits, top_k)
                probs = F.softmax(next_logits, dim=-1)
                next_token = torch.multinomial(probs, num_samples=1)
                tokens = torch.cat([tokens, next_token], dim=1)
        return tokens
    finally:
        model.train(was_training)

def demo() -> None:
    torch.manual_seed(0)

    print("Building 124M reference GPT...")
    ref_cfg = GPTConfig()
    ref_model = GPTModel(ref_cfg)
    ref_params = count_parameters(ref_model)
    print(f"  reference params         : {ref_params:,}")
    print(f"  expected near 124M       : within 5% target {abs(ref_params - 124_000_000) / 124_000_000:.2%}")

    head_tied = ref_model.lm_head.weight.data_ptr() == ref_model.tok_embed.weight.data_ptr()
    print(f"  weight tying enforced    : {head_tied}")
    assert head_tied, "weight tying should share storage"

    print("\nUntying and re-counting to confirm the 38M delta...")
    untied_cfg = GPTConfig(weight_tying=False)
    untied_model = GPTModel(untied_cfg)
    untied_params = count_parameters(untied_model)
    delta = untied_params - ref_params
    expected_delta = ref_cfg.vocab_size * ref_cfg.d_model
    print(f"  untied params            : {untied_params:,}")
    print(f"  delta                    : {delta:,}")
    print(f"  expected (vocab*d_model) : {expected_delta:,}")
    assert delta == expected_delta

    print("\nSingle forward through 124M reference, batch 1, seq 32...")
    tokens = torch.randint(0, ref_cfg.vocab_size, (1, 32))
    with torch.no_grad():
        logits = ref_model(tokens)
    print(f"  logits shape             : {tuple(logits.shape)}")
    assert logits.shape == (1, 32, ref_cfg.vocab_size)

    print("\nGenerating with a tiny model end to end (faster demo)...")

        vocab_size=512,
        context_length=64,
        d_model=64,
        num_heads=4,

Break it on purpose

A developer unties the LM head to "give the model more capacity", but initializes the new head with zeros. The loss at step 0 is exactly ln(50,257) ≈ 10.8 and stays there for many steps. What happened? (Solution B1.)

Solutions

SolutionP1 · Untying and recounting

Give the head its own nn.Linear(768, 50257, bias=False) and recount: 163,037,184, an increase of 38,597,376, exactly vocabulary × width, which the demo confirms.

SolutionB1 · A zero head

With all-zero head weights, every logit is 0, so every token has probability 1/50,257 and the loss is ln(50,257). The gradient into earlier layers passes through the head's weights, which are zero, so the body learns nothing at first and progress is very slow. Initialize the head like other linear layers (small random values), or keep it tied.

Questions from real AI engineering interviews that this lesson prepares you for. Answer out loud first, then open the worked answer.

Read the codeA decode loop keeps keys and values in a preallocated cache and attends one query over the stored prefix. Generation always stops one token short of the configured context length, and the first tokens of a long prompt attend to extra zero rows. The cache code is: python class KVCache: def __init__(self, max_len, d_k, d_v): self.k = np.zeros((max_len, d_k)) self.v = np.zeros((max_len, d_v)) self.n = 0 def append(self, k, v): k = np.atleast_2d(k) v = np.atleast_2d(v) self.n += k.shape[0] if self.n >= self.k.shape[0]: raise ValueError("cache full") self.k[self.n - k.shape[0]:self.n] = k self.v[self.n - k.shape[0]:self.n] = v def keys(self): return self.k Explain the two symptoms from the code and fix them.

Level 3 of 4 · about 10 minutes to answer well.

Short answer. The capacity test rejects an append that ends exactly at the capacity, so the last slot is never used and generation stops one token early. The counter is also updated before the test, so a refused append leaves the length wrong. The accessor returns the whole buffer rather than the filled prefix, so attention sees the empty zero rows. Check that the length plus the new steps does not exceed the capacity before touching the counter, and return views of the first n rows.

Defect one: the boundary.

An append that fills the cache to its capacity is valid. The test must refuse only when the new length would exceed the capacity. With the strict comparison the last row is dead, and a generation loop that sizes the cache from the context length stops one token short.

Defect two: the counter.

Adding to the length before the check means a failed append leaves the cache claiming steps it never stored. The next call then writes past the real data or refuses a valid append. The rule from the practice is that a refused append changes nothing.

Defect three: the view.

keys() returns every row of the buffer, filled or not. The query then attends over zero rows that carry weight after the softmax, which dilutes the output for short prefixes. Return the first n rows only.

The corrected class.

    def append(self, k, v):
        k = np.atleast_2d(k)
        v = np.atleast_2d(v)
        if k.shape[0] != v.shape[0]:
            raise ValueError("keys and values differ in steps")
        if self.n + k.shape[0] > self.k.shape[0]:
            raise ValueError("cache full")
        self.k[self.n:self.n + k.shape[0]] = k
        self.v[self.n:self.n + k.shape[0]] = v
        self.n += k.shape[0]

    def keys(self):
        return self.k[:self.n]

    def values(self):
        return self.v[:self.n]

The copy into the buffer also protects the cache from later changes to the caller's arrays.

How this meets the generation loop.

The assembly lesson's generator keeps the active window inside the context length by dropping the oldest tokens when the prompt plus the generated tokens would exceed it. A cache with a fixed capacity needs the same rule one level down: either refuse the append and let the loop slide the window, or evict the oldest rows. The practice pins the refusing version so the boundary is explicit.

Plausible wrong answers.

  • "Use greater-or-equal so the cache never overflows." It also rejects the exact fill and wastes the last slot.
  • "Return the full buffer; the zero rows have no effect." Zero keys still get softmax weight and pull the output toward the zero values.
  • "Update the count first so the slice indices are simpler." A refused append then corrupts the length.

Follow-ups an interviewer may ask.

  • (level 3) What does the decode step do with the stored keys? Expected: it scores one query against every stored key, divides by the square root of the key size, takes a softmax and weights the stored values.
  • (level 3) A second bug writes every append at row zero. What is the symptom? Expected: new steps overwrite old ones, so attention only ever sees the latest append and the model loses its context.
  • (level 4) Where does a paged cache change this design? Expected: the capacity becomes a pool of fixed-size blocks shared by requests, so an append that needs a new block can wait or preempt instead of failing the request.

Where it is taught. The GPT assembly lesson bounds generation to the context length with a sliding window, and the KV cache practice pins the capacity rule and the filled-prefix views.

Read the codeThe assembly lesson says that swapping the activation and replacing LayerNorm with RMSNorm turns its model into the next open model family. A candidate submits this RMSNorm: python def rms_norm(x, weight, eps): mean = x.mean(axis=-1, keepdims=True) var = ((x - mean) ** 2).mean(axis=-1, keepdims=True) return weight * (x - mean) / np.sqrt(var) + eps What is wrong, and what does the correct function compute?

Level 3 of 4 · about 10 minutes to answer well.

Short answer. This is a LayerNorm without a shift, not an RMSNorm, and it adds epsilon after the square root instead of inside it. RMSNorm does not subtract the mean. It divides the input by the root of the mean of the squares over the last axis, with epsilon inside the root, and multiplies by a learned weight.

The two normalizations.

def layer_norm(x, gamma, beta, eps):
    mean = x.mean(axis=-1, keepdims=True)
    var = ((x - mean) ** 2).mean(axis=-1, keepdims=True)
    return gamma * (x - mean) / np.sqrt(var + eps) + beta


def rms_norm(x, weight, eps):
    ms = (x ** 2).mean(axis=-1, keepdims=True)
    return weight * x / np.sqrt(ms + eps)

LayerNorm centers and scales each token vector, then applies a learned scale and shift. RMSNorm keeps the direction of the vector and only fixes its magnitude. It has no mean subtraction and no shift, which saves one reduction per token and one parameter vector per layer.

The epsilon.

Epsilon exists to keep the division defined when the variance or the mean square is near zero. Inside the root it bounds the denominator from below. Outside the root it does nothing for a zero variance and shifts every output by a constant, which is wrong in both cases. The practice task has one mutant for each of these placements.

Over which axis.

Both normalizations reduce over the last axis, the feature axis, independently for every token in every batch element. Reducing over the batch axis turns the layer into a batch statistic, which changes with batch composition and breaks single-example inference.

Biased variance.

LayerNorm uses the biased variance, the mean of the squared deviations over the feature count. The unbiased estimate with one fewer in the denominator is a statistics convention that does not belong here and makes the output disagree with every standard library version by a factor that depends on the width.

Why the swap is safe in the assembly.

The final normalization sits between the last block and the tied head, and both functions take and return the same shape. Swap the class, drop the shift parameter, and the head, the embedding and the generation loop are untouched.

Plausible wrong answers.

  • "RMSNorm is LayerNorm with the shift removed." It also removes the mean subtraction; without that difference it would not be a different layer.
  • "Epsilon placement does not matter for normal inputs." It matters exactly for the inputs it exists for, the ones with near-zero variance.
  • "Use the unbiased variance, it is more correct." Standard library versions use the biased form; the choice is a contract, not a statistics question.

Follow-ups an interviewer may ask.

  • (level 3) What does the caller's epsilon argument control, and what happens if the function ignores it? Expected: the floor on the denominator; ignoring it and using a fixed constant makes a reference comparison fail when the caller passes a different value.
  • (level 3) Why does RMSNorm have no shift parameter? Expected: it does not center the input, so there is no mean to restore; the next linear layer's bias can absorb a shift if one is needed.
  • (level 4) A pretrained checkpoint has LayerNorm scales and shifts and you swap in RMSNorm. What breaks? Expected: the shift has nowhere to load and the scale was learned on centered inputs, so the loaded model no longer matches the trained function.

Where it is taught. The GPT assembly lesson places the final LayerNorm and names the RMSNorm swap, and the normalization practice checks both functions.

Take-homeThe reference small GPT configuration uses a learned position embedding of shape 1024 by 768. Replace it with a sinusoidal table computed at construction time, add it to a batch of token embeddings, and tell me by how much the parameter count changes and why the model still forwards.

Level 2 of 4 · about 20 minutes to answer well.

Short answer. Build a table with one row per position and one column per feature, where column 2i holds the sine and column 2i + 1 holds the cosine of the position divided by the base raised to 2i over the model width. Register it as a buffer, slice the first T rows at each forward and add them to the token embeddings without changing the caller's array. The table has the same shape as the learned one, so the forward pass is unchanged, and the count drops by 786,432 parameters because the table is no longer learned.

The table.

def sinusoidal_pe(max_len, d_model, base):
    pos = np.arange(max_len)[:, None]
    end = 2 * (d_model // 2)
    i = np.arange(0, end, 2)
    angle = pos / base ** (i / d_model)
    pe = np.zeros((max_len, d_model))
    pe[:, 0:end:2] = np.sin(angle)
    pe[:, 1:end:2] = np.cos(angle)
    return pe


class SinusoidalPositions(nn.Module):
    def __init__(self, max_len, d_model, base):
        super().__init__()
        table = torch.as_tensor(sinusoidal_pe(max_len, d_model, base)).float()
        self.register_buffer("pe", table)

    def forward(self, x):
        return x + self.pe[: x.shape[1]]

The exponent is 2i over the width, so the frequencies fall from one down to one over the base across the columns. The columns alternate between sine and cosine; putting all sines in the first half and all cosines in the second is a different layout and does not match the reference. Positions start at zero. An odd width has no pair for its last column, so that column stays zero. The table is built once with numpy and stored as a torch buffer, so it moves to the device of the model and the add sees two tensors on the same device.

Why the forward pass is unchanged.

The assembly adds a position vector to each token vector before the first block. Nothing downstream knows whether that vector came from a learned table or a fixed one. The shape contract is the same, so the blocks, the final LayerNorm and the tied head run unchanged.

The parameter count.

The learned table holds 1024 rows of 768 values each. Removing it from the parameter list drops the unique parameter count by 786,432. The parameter counter must count unique tensors, so that the tied language model head is not counted twice, and it must not count buffers.

Two mistakes to avoid.

  • Adding the table in place with += changes the caller's embeddings, which the training loop still holds.
  • Dividing the exponent by the width of the even part instead of the full width gives an odd width the frequencies of a narrower model.

Plausible wrong answers.

  • "Register the table as a parameter so the optimizer can refine it." Then it is a learned table again and the count does not drop.
  • "Start positions at one so the first row is not all zeros and ones." The reference starts at zero; row zero is the code of position zero.
  • "Use the same exponent for sine and cosine columns but a different base." Both columns of a pair share one angle; only the function differs.

Follow-ups an interviewer may ask.

  • (level 2) Why interleave sine and cosine rather than put them in two halves? Expected: a checkpoint trained with the interleaved layout expects each pair of neighbor columns to form one rotation, and the two layouts are not interchangeable.
  • (level 2) What does the base control? Expected: the lowest frequency, and so the longest position range before the slowest columns repeat.
  • (level 3) Which position scheme does the assembly lesson say turns this model into the next model family? Expected: a rotary scheme applied inside attention replaces the additive table and leaves the block and the head unchanged.
  • (level 3) A fixed table has no parameters; what does the model lose? Expected: the ability to learn position features from data, in exchange for a table that extends to any length at construction.

Where it is taught. The GPT assembly lesson sets this swap as an exercise and gives the parameter delta, and the sinusoidal encoding practice checks the interleaved layout.

Explain the mechanismWrite the one line that applies a sampling temperature to a vector of logits, then tell me what happens to the distribution as the temperature goes toward zero, equals one, and goes above one.

Level 1 of 4 · about 6 minutes to answer well.

Short answer. Divide the logits by the temperature before the softmax. Near zero the division stretches the gaps between logits, so the largest one takes almost all the mass and sampling becomes greedy. At one the model's own distribution is used, and above one the gaps shrink, the distribution flattens, and rare tokens are drawn more often.

The line.

probs = softmax(logits / temperature)

The order matters in a full sampler: the generation loop reads the final position's logits, divides by the temperature, applies any top-k or top-p filter, takes the softmax, and draws one token.

Three regimes.

Temperature Effect on the gaps between logits Behavior
Toward zero Gaps grow without bound Argmax; the same token every time
Equal to one Unchanged The model's natural distribution
Above one Gaps shrink Flatter distribution, more surprise, more errors

Why division and not multiplication.

Multiplying the logits by the temperature does the opposite of what people expect: a higher value sharpens the distribution. The practice lab has a mutant that makes this mistake, and the sign of the effect is the first thing its tests check.

Reading the effect.

Two measurements show what a temperature did: the probability of the top token, and the entropy of the distribution. As the temperature rises the top probability falls and the entropy rises. A sweep over temperatures on fixed logits makes both curves visible without a model in the loop.

Plausible wrong answers.

  • "Temperature scales the probabilities after the softmax." Scaling probabilities and renormalizing changes nothing; the division happens on the logits.
  • "A higher temperature makes the model smarter." It only flattens the distribution, which trades repetition for more mistakes.
  • "Temperature one means no sampling." It means sampling from the unchanged distribution; greedy is temperature zero or argmax.

Follow-ups an interviewer may ask.

  • (level 1) Why does temperature zero need a special case in code? Expected: division by zero; implement it as argmax rather than dividing.
  • (level 2) A product wants deterministic output. Is temperature zero enough? Expected: it removes sampling randomness, but ties and numeric differences across batches can still change the argmax.
  • (level 2) How does temperature interact with a top-p cutoff? Expected: the cutoff must run on the temperature-scaled probabilities, otherwise it cuts the distribution at temperature one and the setting does less than expected.

Where it is taught. The GPT assembly lesson describes the three temperature regimes in its generation loop, and the temperature lab sweeps them on fixed logits.

Take-homeGiven the logits of the last position, a temperature, a value of k and a seeded random generator, write the function that draws the next token. State the order of the operations, how ties are broken, and how the draw uses exactly one random number.

Level 2 of 4 · about 20 minutes to answer well.

Short answer. Divide the logits by the temperature, keep the k largest and set the rest to negative infinity, take the softmax, and draw one index from the result. Ties keep the lower index. The draw calls the generator once, takes the cumulative sum of the probabilities in vocabulary order, and returns the first index whose cumulative value exceeds the random number.

The code.

def top_k_filter(logits, k):
    if k >= logits.shape[0]:
        return logits.copy()
    order = np.argsort(-logits, kind="stable")
    keep = order[:k]
    out = np.full_like(logits, -np.inf)
    out[keep] = logits[keep]
    return out


def sample(logits, rng, temperature=1, top_k=None):
    z = logits / temperature
    if top_k is not None:
        z = top_k_filter(z, top_k)
    probs = softmax(z)
    u = rng.random()
    c = np.cumsum(probs)
    hits = np.nonzero(u < c)[0]
    if hits.size:
        return int(hits[0])
    return int(np.nonzero(probs > 0)[0][-1])

The order.

Temperature first, then the filter, then the softmax. The filter has to see the scaled logits, because the scale changes which tokens hold the mass when a top-p cutoff is added later. The softmax runs last so that a removed token has probability exactly zero and the kept ones renormalize.

Ties.

Sorting the negated logits with a stable sort keeps the lower index first among equal values. Sorting ascending and reversing the result flips that, so the higher index wins and the output differs from the reference on every tie.

One random number.

A seeded generator gives reproducible samples only if every call consumes the same number of draws. The function reads one uniform number, compares it with the cumulative sum, and returns the first crossing. Rounding can leave the last cumulative value a hair below one, so the fallback returns the last token with positive probability instead of failing.

Do not change the input.

The filter writes into a new array. Writing negative infinity into the caller's logits destroys the values that the next step, or a log, still needs.

Plausible wrong answers.

  • "Call the generator's choice function with the probabilities." It works, but it consumes draws differently across versions and breaks the one-draw contract that the tests pin.
  • "Apply the temperature after the filter." The filter then selects tokens at temperature one and the setting changes less than intended.
  • "Sort descending by reversing an ascending sort." Equal logits then keep the higher index, which contradicts the tie rule.

Follow-ups an interviewer may ask.

  • (level 2) What does top-k one produce? Expected: greedy decoding, the argmax every time.
  • (level 2) Why must the filter run before the softmax and not after? Expected: zeroing probabilities after the softmax leaves a distribution that does not sum to one unless it is renormalized; masking the logits does that for free.
  • (level 3) The assembly lesson keeps the context inside a fixed length during generation. How? Expected: when the prompt plus generated tokens exceed the context length, the oldest tokens are dropped so the active window fits.
  • (level 3) How do you make two runs with one seed produce the same text? Expected: the same generator, one draw per step, the same tie rule and the same temperature; any extra draw shifts every later token.

Where it is taught. The GPT assembly lesson describes the generation step as temperature, top-k mask, softmax and multinomial draw, and the sampling practice pins the order, the tie rule and the single draw.

Debug a failureA nucleus filter is reviewed because a product team says small values of p give an empty distribution on some prompts: python def top_p_filter(logits, p): probs = softmax(logits) c = np.cumsum(probs) out = np.where(c <= p, logits, -np.inf) return out Find the two bugs and explain how the filter must interact with the temperature in the full sampler.

Level 3 of 4 · about 10 minutes to answer well.

Short answer. The cumulative sum runs in vocabulary order instead of in order of decreasing probability, so the kept set is not the most probable prefix at all. The comparison also drops the token that makes the sum reach p, which for a small p leaves nothing and yields an empty distribution. Sort by probability first, keep the shortest prefix whose sum reaches p including the crossing token, and run the filter on the temperature-scaled logits.

Bug one: the order.

Nucleus sampling keeps the smallest set of most probable tokens whose mass reaches p. That requires sorting by probability, highest first, before the cumulative sum. In vocabulary order the sum crosses p at an arbitrary place and the kept set is a prefix of the vocabulary, not of the ranking.

Bug two: the crossing token.

The token whose addition makes the cumulative sum reach p is part of the nucleus. A strict comparison excludes it. When the top token alone carries more mass than p, nothing passes and the softmax of all negative infinities is NaN. Keep the prefix up to and including the first index where the sum is at least p, and if rounding keeps the sum from ever reaching p, keep every token.

The fix.

def top_p_filter(logits, p):
    probs = softmax(logits)
    order = np.argsort(-probs, kind="stable")
    c = np.cumsum(probs[order])
    cut = np.searchsorted(c, p, side="left")
    keep = order[: min(cut + 1, logits.shape[0])]
    out = np.full_like(logits, -np.inf)
    out[keep] = logits[keep]
    return out

The stable sort on the negated probabilities keeps the lower index first on ties.

Temperature comes first.

The full sampler divides by the temperature, applies top-k, applies top-p to that result, and takes the softmax last. If the temperature is applied after the filters, the nucleus is chosen at temperature one and a hot or cold setting changes less than the user asked for. The assembly lesson lists nucleus sampling as the extension of its top-k generation loop, with the check that the kept probabilities sum to at least p.

Plausible wrong answers.

  • "Use a strict comparison so you never exceed p." The definition is the smallest prefix that reaches p; excluding the crossing token breaks it and can leave an empty set.
  • "Take the cumulative sum in index order; the vocabulary is already sorted by frequency." Token ids are not sorted by probability for a given context.
  • "Apply the temperature after the filter so the nucleus is stable." The nucleus is then chosen at the wrong temperature and the knob loses most of its effect.

Follow-ups an interviewer may ask.

  • (level 3) Why does the filter return logits with negative infinity rather than probabilities? Expected: so the final softmax renormalizes the kept tokens and gives removed tokens exactly zero, and so top-k and top-p compose.
  • (level 3) What does p equal to one keep? Expected: every token, unless rounding leaves the sum short, in which case the rule to keep all tokens applies.
  • (level 4) Top-k and top-p are both set. Which one acts first and why does it matter? Expected: top-k first, then top-p on the survivors; the reverse order can keep a different set because the nucleus mass is computed over different candidates.

Where it is taught. The GPT assembly lesson adds nucleus sampling next to top-k in its exercises, and the sampling practice pins the crossing token and the order of operations.
