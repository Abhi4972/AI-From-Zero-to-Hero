In plain words first
The idea in one line

Discrete functional memory blocks the model can edit directly, and a sleep-time agent that consolidates memory asynchronously while the primary agent is idle. These two ideas are how you scale memory beyond one conversation.

The problem

In plain words first

Lesson 14.22 gave an agent memory tools. Two problems follow in real use. Memory grows messy: facts pile up, old ones contradict new ones ("lives in Berlin", later "moved to Lisbon"). And tidying memory takes time, which the user should not have to wait for. Letta's answer has two parts. Memory blocks are named, size-limited sections of the prompt (one about the user, one about the agent itself, others as needed), each with a description saying what belongs there. Sleep-time compute is a second agent that tidies those blocks in the background, between conversations, so the agent talking to the user never waits for it. This lesson builds both, then lets a real small model do the night shift and checks its work.

MemGPT (Lesson 14.22) solved the virtual-memory control flow. Three production problems emerged:

  1. Latency. Every memory operation sits on the critical path. If the agent has to prune, summarize, or reconcile while the user waits, tail latency blows up.
  2. Memory rot. Writes accumulate. Contradicted facts stay. Retrieval drowns in stale content.
  3. Structure loss. A flat archival store cannot express "the Human block is always in the prompt; the Persona block is always in the prompt; the Task block swaps per session."

Letta (letta.com) is the platform name the original MemGPT project adopted in 2024 — the paper's pattern keeps the MemGPT name — and the Letta V1 agent architecture (October 2025) is a later, separate step. Memory blocks make structure explicit; sleep-time compute moves consolidation off the critical path.

Idea 1 · Three tiers

Tier Scope Where it lives Written by
Core Always visible Inside the main prompt Agent tool call + sleep-time rewrites
Recall Conversation history Retrievable Automatic turn logging
Archival Arbitrary facts Vector + KV + graph Agent tool call + sleep-time ingest

Core is the MemGPT core. Recall is the conversation buffer with its evicted tail. Archival is the external store. The split cleans up MemGPT's two-tier overloading.

Idea 2 · Memory blocks

A block is a typed, persistent, editable section of the core tier. The original MemGPT paper defined two:

  • Human block — facts about the user (name, role, preferences, goals).
  • Persona block — the agent's self-concept (identity, tone, constraints).

Letta generalizes to arbitrary user-defined blocks: a Task block for the current goal, a Project block for codebase facts, a Safety block for hard constraints. Each block has an id, label, value, limit (character cap), description (so the model knows when to edit it).

In this lesson's code, blocks are edited through four tools (Letta's own memory tools differ in name and detail):

  • block_append(label, text)
  • block_replace(label, old, new)
  • block_read(label)
  • block_summarize(label) — condense a block that is near its limit.

Idea 3 · Sleep-time compute

The 2025 Letta addition: run a second agent in background, off the critical path. Sleep-time agents process conversation transcripts and codebase context, write learned_context into shared blocks, and consolidate or invalidate archival records.

Properties that fall out:

  • No latency cost. Primary responses do not wait for memory ops.
  • Stronger model allowed. The sleep-time agent can be a more expensive, slower model because it is not latency-constrained.
  • Natural consolidation window. Dedup, summarize, invalidate contradicted facts when the user is not waiting.

The shape matches how humans work: you do the task, you sleep on it, the long-term memory settles overnight.

Idea 4 · Native reasoning

Letta V1 (letta_v1_agent, October 2025) deprecates send_message/heartbeat and inline Thought: tokens in favor of native reasoning. The Responses API (OpenAI) and the Messages API with extended thinking (Anthropic) emit reasoning on a separate channel, passed through turns (encrypted across providers in production). The control loop is still ReAct. The thought trace is structural, not prompt-shaped.

Idea 5 · Where this pattern goes wrong

  • Block bloat. Infinite block_append hits the limit fast. Wire a block summarizer before the write that pushes over the cap.
  • Silent drift. Sleep-time agent rewrites a block and the primary agent never notices. Version blocks and surface diffs in the trace.
  • Poisoned consolidation. Sleep-time agent processes attacker-reachable content into core. Lesson 14.102 applies to the sleep-time surface too.

The same idea as a formula

Latency. If a turn costs treply​ and consolidation costs tcons​, doing both on the critical path gives the user

tinline​=tcons​+treply​,tsleep​=treply​,
and consolidation runs later, when nobody waits.

A block has a budget. With limit L characters and a near-limit threshold θ (0.8 in the lesson), consolidation is due when ∣v∣≥θL; a rewrite v′ should satisfy ∣v′∣≤L.

What a good rewrite keeps. With F the facts that are currently true and O the facts that later ones replaced:

retention=∣F∣∣F∩v′∣​,staleness=∣O∣∣O∩v′∣​.
A good consolidator has retention near 1 and staleness near 0.

Worked example
Scoring the two rewrites below
  • The week's appends hold 8 facts. Two are replaced by later ones (Berlin by Lisbon, "ML engineer" by "team lead"), so ∣O∣=2 and ∣F∣=6.
  • The lesson's _summarize keeps leading sentences up to half the limit: "Name is Ava. Works as an ML engineer at Northwind. Lives in Berlin." Retention 1/6, staleness 2/2. It keeps exactly the oldest facts, which is what goes stale first.
  • The model's rewrite keeps Ava, short answers, Lisbon, team lead and Miso but drops Python and keeps the old role: retention 5/6≈0.83, staleness 1/2.
  • Latency in the second block: about 10 s with inline consolidation against about 4 s without it, so the sleep-time design saves the user roughly the consolidation time, 5 s or so, on each consolidating turn here.
Check your mental model
  • ✗ "Sleep-time compute makes memory more accurate."
    ✓ It moves the work off the user's path; accuracy depends on the consolidator.
  • ✗ "Truncating a full block is a summary."
    ✓ Keeping the first sentences keeps the oldest facts and drops the newest.
  • ✗ "A rewrite that reads well is safe to apply."
    ✓ Check it: within the limit, no lost facts, no stale ones; keep versions and diffs.

# Sleep-time consolidation of a real-looking memory block. A week of fast appends (with two updates that
# contradict older facts) overflows the lesson's 'human' block. Two consolidators rewrite it: the lesson's
# _summarize (keep leading sentences) and a real model as the sleep-time agent (Qwen2.5-0.5B-Instruct).
import os, re, time, torch
os.environ.setdefault("HF_HUB_OFFLINE", "1")            # the model is already in the local cache
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
from main import BlockStore, _summarize
M = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(M); llm = AutoModelForCausalLM.from_pretrained(M).eval()
def chat(text, max_new=120):
    ids = tok.apply_chat_template([{"role": "user", "content": text}], add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=max_new, do_sample=False)
    return tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()
WEEK = ["Name is Ava.", "Works as an ML engineer at Northwind.", "Lives in Berlin.",
        "Prefers short answers with citations.", "Has a cat called Miso.", "Prefers Python over TypeScript.",
        "Moved from Berlin to Lisbon in May.", "Was promoted to team lead at Northwind."]
CURRENT = {"name Ava": ["ava"], "Lisbon": ["lisbon"], "team lead": ["team lead"], "short answers": ["short"],
           "cat Miso": ["miso"], "Python": ["python"]}
STALE = {"lives in Berlin": ["lives in berlin", "city: berlin", "located in berlin"], "ML engineer (old role)": ["ml engineer"]}
def score(text):
    t = text.lower()
    kept = [k for k, ws in CURRENT.items() if any(w in t for w in ws)]
    stale = [k for k, ws in STALE.items() if any(w in t for w in ws)]
    return kept, stale
store = BlockStore(); human = store.create("human", "Facts about the user. Newest fact wins.", limit=200)
for fact in WEEK:                                        # the primary agent's fast, unconsolidated writes
    human.append(fact)
print(f"after a week of appends: {len(human.value)}/{human.limit} chars, near limit: {human.near_limit()}")
print("  " + human.value)
lesson = _summarize(human.value, human.limit // 2)
SLEEP = ("You maintain a memory block about a user. Rewrite it as a short list of the facts that are true now. "
         "When a later fact updates an earlier one, keep only the later one. Keep every other fact. Use at most "
         "{limit} characters. Output only the rewritten block.\n\nBlock:\n{block}")
started = time.perf_counter()
model = chat(SLEEP.format(limit=human.limit // 2 + 40, block=human.value))
secs = time.perf_counter() - started
for name, text in (("lesson _summarize", lesson), ("Qwen 0.5B sleep-time agent", " ".join(model.split()))):
    kept, stale = score(text)
    print(f"\n== {name}: {len(text)} chars")
    print("  " + text)
    print(f"  current facts kept {len(kept)}/{len(CURRENT)}  missing {[k for k in CURRENT if k not in kept]}")
    print(f"  stale facts still present: {stale or 'none'}")
print(f"\nsleep-time rewrite took {secs:.1f} s (off the user's path)")

What the user waits for, and guarding the rewrite

This block continues from the one above. The same user turn is answered twice: after an inline consolidation, and directly with consolidation left for sleep time. Then the model's rewrite is proposed as a new block version: shown as a diff, checked by two cheap guards (the limit, and capitalised names that disappear), and applied only if both pass. # answered first with consolidation left for sleep time. (2) Silent drift: apply the model's rewrite as a
# new block version and surface what changed, with two cheap guards. Continues from the block above.

Part 1 of 5 · Block, BlockStore

"""Letta-shaped memory blocks with a sleep-time consolidation agent.

Primary agent writes raw facts during turns. Sleep-time agent runs between
turns, off the critical path, and consolidates blocks. Scripted so it runs
offline.
"""

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any


@dataclass
class Block:
    label: str
    value: str = ""
    limit: int = 300
    description: str = ""
    version: int = 0
    history: list[str] = field(default_factory=list)

    def append(self, text: str) -> str:
        old = self.value
        self.value = (self.value + " " + text).strip() if self.value else text
        self.version += 1
        self.history.append(old)
        return f"{self.label} v{self.version} ({len(self.value)}/{self.limit})"

    def replace(self, old: str, new: str) -> str:
        if old not in self.value:
            return f"error: {old!r} not in {self.label}"
        prev = self.value
        self.value = self.value.replace(old, new)
        self.version += 1
        self.history.append(prev)
        return f"{self.label} v{self.version} replaced"

    def rewrite(self, new: str) -> str:
        prev = self.value
        self.value = new
        self.version += 1
        self.history.append(prev)
        return f"{self.label} v{self.version} rewritten ({len(self.value)}/{self.limit})"

    def near_limit(self, threshold: float = 0.8) -> bool:
        return len(self.value) >= int(self.limit * threshold)


class BlockStore:
    def __init__(self) -> None:
        self._blocks: dict[str, Block] = {}

    def create(self, label: str, description: str, limit: int = 300) -> Block:
        block = Block(label=label, description=description, limit=limit)
        self._blocks[label] = block
        return block

    def get(self, label: str) -> Block | None:
        return self._blocks.get(label)

    def labels(self) -> list[str]:
        return sorted(self._blocks)

    def render(self) -> str:
        lines: list[str] = []
        for label in self.labels():
            block = self._blocks[label]
            lines.append(f"[{block.label} v{block.version} "
                         f"{len(block.value)}/{block.limit}]")
            lines.append(f"  {block.value}")
        return "\n".join(lines)

Part 2 of 5 · ArchivalRecord, Archival, PrimaryAgent

@dataclass
class ArchivalRecord:
    rid: str
    text: str
    valid: bool = True


class Archival:
    def __init__(self) -> None:
        self._records: list[ArchivalRecord] = []
        self._counter = 0

    def insert(self, text: str) -> str:
        self._counter += 1
        rid = f"a{self._counter:03d}"
        self._records.append(ArchivalRecord(rid=rid, text=text))
        return rid

    def invalidate(self, rid: str) -> bool:
        for record in self._records:
            if record.rid == rid:
                record.valid = False
                return True
        return False

    def valid_records(self) -> list[ArchivalRecord]:
        return [r for r in self._records if r.valid]

    def all_records(self) -> list[ArchivalRecord]:
        return list(self._records)


class PrimaryAgent:
    """Handles turns. Writes raw facts fast; never summarizes or consolidates."""

    def __init__(self, blocks: BlockStore, archival: Archival) -> None:
        self.blocks = blocks
        self.archival = archival
        self.trace: list[str] = []

    def turn(self, user_text: str, writes: list[tuple[str, str, str]]) -> str:
        self.trace.append(f"user: {user_text}")
        for kind, label_or_text, payload in writes:
            if kind == "block_append":
                block = self.blocks.get(label_or_text)
                if block is not None:
                    self.trace.append(f"  block_append -> {block.append(payload)}")
            elif kind == "archival_insert":
                rid = self.archival.insert(payload)
                self.trace.append(f"  archival_insert -> {rid}")
        response = f"response to: {user_text}"
        self.trace.append(f"assistant: {response}")
        return response

Part 3 of 5 · SleepTimeAgent, _summarize

class SleepTimeAgent:
    """Off the critical path. Summarizes near-limit blocks, invalidates
    contradicted archival records, no user latency cost.
    """

    def __init__(self, blocks: BlockStore, archival: Archival) -> None:
        self.blocks = blocks
        self.archival = archival
        self.trace: list[str] = []

    def run(self, contradictions: list[tuple[str, str]]) -> None:
        self.trace.append("sleep-time pass start")
        for label in self.blocks.labels():
            block = self.blocks.get(label)
            if block is None:
                continue
            if block.near_limit():
                summary = _summarize(block.value, block.limit // 2)
                result = block.rewrite(summary)
                self.trace.append(f"  consolidate {label}: {result}")
        for claim, reason in contradictions:
            for record in self.archival.all_records():
                if record.valid and claim.lower() in record.text.lower():
                    self.archival.invalidate(record.rid)
                    self.trace.append(
                        f"  invalidate {record.rid} ({reason}): {record.text[:50]}..."
                    )
        self.trace.append("sleep-time pass end")


def _summarize(text: str, target_len: int) -> str:
    sentences = [s.strip() for s in text.split(".") if s.strip()]
    if not sentences:
        return text[:target_len]
    picked: list[str] = []
    total = 0
    for sentence in sentences:
        if total + len(sentence) + 1 > target_len:
            break
        picked.append(sentence)
        total += len(sentence) + 2
    return ". ".join(picked) + "."

def main() -> None:
    print("=" * 70)
    print("LETTA MEMORY BLOCKS + SLEEP-TIME COMPUTE: Phase 14, Lesson 08")
    print("=" * 70)

    blocks = BlockStore()
    blocks.create("human", "facts about the user", limit=180)
    blocks.create("persona", "the agent's self-concept", limit=160)
    blocks.create("task", "the current task scope", limit=220)
    archival = Archival()

    primary = PrimaryAgent(blocks, archival)
    sleep = SleepTimeAgent(blocks, archival)

    primary.turn(
        "my name is ava, I ship agents for a living, I live in Berlin",
        [("block_append", "human", "name=ava role=ships_agents city=Berlin")],
    )
    primary.turn(
        "today help me plan a 30-lesson curriculum on agent engineering",
        [
            ("block_append", "task", "plan 30-lesson agent curriculum, target senior eng"),
            ("archival_insert", "",
             "ava prefers concise, citation-heavy writing over tutorial-style"),
        ],
    )
    primary.turn(
        "I moved to Lisbon last month; update your notes",
        [
            ("block_append", "human", "city=Lisbon (updated from Berlin)"),
            ("archival_insert", "",
             "ava lives in Berlin - old address, outdated"),
        ],
    )
    primary.turn(
        "also the curriculum target is senior and staff engineers, not junior",
        [("block_append", "task",
          "audience=senior+staff eng, cite arXiv and first-party framework docs")],
    )

    print("\nprimary turns (writes are fast and raw)")
    for line in primary.trace:
        print(f"  {line}")

    print("\nblocks after primary phase (pre-consolidation)")
    print(blocks.render())

    sleep.run(contradictions=[
        ("ava lives in Berlin",
         "human block updated city to Lisbon; Berlin archival claim is stale"),
    ])

    print("\nsleep-time trace")
    for line in sleep.trace:
        print(f"  {line}")

    print("\nblocks after sleep-time (consolidated)")
    print(blocks.render())

    print("\narchival state")
    for record in archival.all_records():
        status = "VALID  " if record.valid else "INVALID"
        print(f"  {record.rid} [{status}] {record.text}")

    print()
    print("key property: primary-turn latency is unchanged by consolidation.")
    print("sleep-time can run a stronger, slower model: it is off the path.")

Use it: the same idea with real libraries

  • Letta (letta.com) for the reference implementation. Self-host or managed cloud.
  • Claude Agent SDK skills as block-shaped knowledge — a skill is a named, versioned, retrievable block of instructions the agent loads on demand.
  • Custom builds for teams that want control over the storage backend. Use the Letta API contract so you can migrate later.
Break it on purpose

A teammate lets the sleep-time agent rewrite blocks directly, with no versioning, no guards and no review, "because it runs at night and nobody is waiting". It processes every transcript, including pasted web pages. What can go wrong over a month? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Letta runs memory blocks and sleep-time agents in production (self-hosted or Letta Cloud); its V1 agent architecture (October 2025) uses native reasoning instead of send_message and heartbeats.
  • Background memory work is a common pattern beyond Letta: LangMem's background memory manager, Mem0's asynchronous add, and the "dreaming" or consolidation jobs in assistant products all move consolidation off the request path.
  • File-shaped blocks. Coding agents keep block-like memory as files (CLAUDE.md, AGENTS.md, skills), edited by the agent or a person and versioned in git, which gives diffs and review for free.
  • On your laptop: a sleep-time job can use a slower, larger model than the chat model because nobody waits for it; on the RTX 4060 that might be a 7B to 8B model in 4-bit at night while a smaller model answers during the day.

Sources: Letta, sleep-time compute, Sleep-time Compute (arXiv:2504.13171), Letta, rearchitecting the agent loop (Oct 2025), Letta documentation, LangMem.

Recap
What to keep from this lesson
  • Blocks: named, size-limited, described sections of the prompt.
  • Sleep-time agents consolidate memory without making the user wait.
  • Truncation keeps old facts; consolidation must prefer the newest.
  • Version every rewrite, show the diff, and guard it before applying.
  • Background agents read untrusted content too; guard what they write.

Ship it

outputs/skill-memory-blocks.md generates a Letta-shaped block system with sleep-time hooks for any runtime, including safety rules and citation wiring.

outputs/skill-memory-blocks.md

---
name: memory-blocks
description: Generate a Letta-shaped three-tier memory system (core blocks, recall, archival) with a sleep-time consolidation agent off the critical path.
version: 1.0.0
phase: 14
lesson: 08
tags: [memory, letta, blocks, sleep-time, consolidation]
---

Given a target runtime, a primary model, and a (possibly stronger) sleep-time model, produce a three-tier memory system with explicit block types and async consolidation.

Produce:

1. `Block` type with `label`, `value`, `limit`, `description`, `version`, `history`. Every write bumps version and records the old value. Expose `near_limit(threshold=0.8)`.
2. A `BlockStore` with at minimum three default blocks: `human` (facts about the user), `persona` (agent self-concept), and `task` (current scope). Allow user-defined blocks.
3. A `Recall` store — turn log paginated by session. Auto-write every turn. Tail evicts on cap but remains retrievable.
4. An `Archival` store — at least two backends (vector, KV). Insert returns record id. Invalidate rather than delete on contradiction.
5. A `PrimaryAgent` that handles turns and only issues raw writes. No summarization on the critical path.
6. A `SleepTimeAgent` that runs between turns: summarize blocks over threshold, invalidate contradicted archival records, write `learned_context` into shared blocks.

Hard rejects:

- Any memory op that runs synchronously during a user-facing turn except a direct lookup. Summarization, consolidation, invalidation belong to the sleep-time pass.
- Deleting archival records on contradiction. Invalidate so history remains auditable.
- Writing to the Persona or Safety block without a review step. These blocks shape behavior globally; silent writes mask bugs.

Refusal rules:

- If the runtime cannot persist blocks across sessions, refuse to ship a product described as "memory." Downgrade the claim.
- If the sleep-time agent has no trace output, refuse. Silent consolidation is a debugging dead-zone.
- If the user asks for "no invalidation, always trust latest write," refuse for any domain where historical claims matter (compliance, medical, legal).

Output: one file per component plus a `README.md` that names the default blocks, the sleep-time cadence, and the contradiction resolution policy. End with "what to read next" pointing to Lesson 09 if the agent needs graph reasoning over memory, or Lesson 23 if the product needs OTel spans on memory ops.

Exercises

  1. Add a block_summarize tool that replaces the block value with a model-generated summary when near_limit returns true. Which trigger threshold minimizes both summarization calls and block overflow?
  2. Implement sleep-time dedup over archival: two records whose text has >90% token overlap collapse to one. Do it only in the sleep pass, never on the critical path.
  3. Version blocks. On every write record the old value and a diff. Expose block_history(label) so operators can debug "why did the agent forget X."
  4. Treat sleep-time agents as untrusted writers. When they touch the Persona or Safety block, require a second-agent review before committing.
  5. Port the example to use the Letta API (letta_v1_agent). What changes in the block schema, and how does native reasoning alter the trace shape?

Solutions

SolutionP1 · The oldest ones

The oldest. _summarize walks the sentences in order and stops once it has used half the limit, so it keeps "Name is Ava. Works as an ML engineer at Northwind. Lives in Berlin." Two of those three are no longer true, and every newer fact (Lisbon, team lead, preferences, cat) is gone. Order of writing is the opposite of what consolidation needs: the most recent statement of a fact should win.

SolutionB1 · Unwatched rewrites

Several slow failures, none of them visible at the time. A pasted page can carry text that the sleep-time agent turns into a standing "fact" or instruction in a core block, which then sits in every prompt (the poisoning from lesson 14.22, but now promoted into core memory). Small rewrites drift: each night's summary of a summary loses a detail, as "prefers Python" was lost here, until the block says something the user never said. Facts the user corrected can return when the agent re-reads old transcripts. And with no versions there is nothing to diff against and no way to roll back.

Keep the background agent, but treat its output like a pull request: version every block, store each rewrite with its diff and source transcripts, run guards (limit, lost names, new instructions, untrusted sources), apply automatically only small, guarded edits, and route the rest to review. Keep content from documents and tools out of core blocks unless a person confirms it.

Interview questions

Try answering out loud first, then open one answer at a time.

Questions from real AI engineering interviews that this lesson prepares you for. Answer out loud first, then open the worked answer.

Weigh a trade-offAn assistant's tail latency climbs because every turn also prunes, summarizes and reconciles its memory before it replies. A proposal moves that work to a second agent that runs while the user is idle. What does the split buy, what does it cost, and what new failure does it create?

Level 3 of 4 · about 10 minutes to answer well.

Short answer. The split takes the memory work off the critical path, so a reply never waits on consolidation, and the background agent can be a slower and stronger model because nobody is waiting on it. It costs a second agent, a shared block store and the coordination around them. The new failure is silent drift: the background agent rewrites a block and the primary agent never notices, so version the blocks, surface diffs in the trace, and treat the background writer as untrusted when it touches the persona or the safety block.

What the primary agent keeps.

Three tiers. Core memory is always in the prompt and is made of typed blocks, each with an id, a label, a value, a character limit and a description that tells the model when to edit it: a human block, a persona block, and user-defined blocks such as a task or a safety block. Recall is the conversation history. Archival is the external store. The primary agent serves turns and makes raw writes through block_append, block_replace, block_read and block_summarize.

What the background agent does.

It reads transcripts and context while the user is idle, writes learned context into shared blocks, deduplicates and summarizes, and invalidates contradicted facts. Three properties follow: no latency cost on the reply, a stronger model becomes affordable, and consolidation gets a natural window when nobody is waiting.

The three failures and their guards.

Failure Guard
Block bloat: appends hit the character limit run the summarizer before the write that would pass the cap
Silent drift: a block changes and the primary agent never notices version blocks, record old value and diff on every write, expose a history per block
Poisoned consolidation: content an attacker can reach lands in core treat the background agent as an untrusted writer; a change to the persona or the safety block needs a second-agent review before it commits

Keep the heavy work in the sleep pass.

Deduplication of records whose text overlaps by more than 90 percent belongs in the background pass and never on the critical path; the lesson's exercise is explicit about that.

Plausible wrong answers.

  • "Run the consolidation at the end of every turn, it is quick." It sits on the critical path and tail latency is the complaint; the point of the split is that the reply never waits.
  • "Use the cheapest model for the background agent to save money." It is the one place a stronger model is affordable, and its rewrites shape every later turn.
  • "Deduplicate on the critical path too, it is the same code." The lesson runs deduplication only in the sleep pass, never while the user waits.

Follow-ups an interviewer may ask.

  • (level 3) Why can the background agent use a more expensive model? Expected: it is not latency constrained, so a slower and stronger model is affordable.
  • (level 3) A block keeps growing toward its limit. What runs, and when? Expected: the block summarizer, before the write that would push the block over the cap; the trigger threshold trades summarization calls against overflow.
  • (level 4) How do you make a background rewrite visible? Expected: version every block, record the old value and a diff on each write, and expose a per-block history so an operator can see why the agent forgot something.
  • (level 4) The background agent reads attacker-reachable content. What is the control? Expected: treat it as an untrusted writer; a change to the persona or the safety block needs a second-agent review before it commits.

Where it is taught. The lesson memory blocks gives the three tiers, the block pattern, the background agent and its failure modes, and the lesson virtual context sets the two-tier pattern it extends.
