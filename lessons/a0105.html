Terms you'll hear
Term What people say What it actually means
Chain rule "Multiply the derivatives" The derivative of composed functions equals the product of each function's local derivative, evaluated at the right point
Computational graph "The network diagram" A directed acyclic graph where nodes are operations and edges carry values (forward) or gradients (backward)
Forward mode "Push derivatives forward" Autodiff that propagates derivatives from inputs to outputs. One pass per input variable.
Reverse mode "Backpropagation" Autodiff that propagates gradients from outputs to inputs. One pass per output variable.
Autograd "Automatic gradients" A system that records operations on values, builds a graph, and computes exact gradients via the chain rule
Dual numbers "Value plus derivative" Numbers of the form $a + b\epsilon$ ($\epsilon^2 = 0$) that carry derivative information through arithmetic
Topological sort "Dependency order" Ordering graph nodes so every node comes after all its dependencies. Required for correct gradient propagation.
Gradient accumulation "Add, don't replace" When a value feeds into multiple operations, its gradient is the sum of all incoming gradient contributions
Dynamic graph "Define by run" A computation graph rebuilt on every forward pass, allowing Python control flow inside models (PyTorch style)
Gradient checking "Numerical verification" Comparing autodiff gradients against numerical finite-difference gradients to verify correctness. Essential for debugging.
MLP "Multi-layer perceptron" A neural network with one or more hidden layers of neurons. Each neuron computes a weighted sum plus bias, then applies an activation function.
Neuron "Weighted sum + activation" The basic unit: $\text{output} = \text{activation}(w_1 x_1 + w_2 x_2 + \cdots + b)$. The weights and bias are learnable parameters.

The problem

In plain words first

Every number a network computes is built from a few simple operations: add, multiply, tanh. Each one knows its own small derivative. If every result remembers which numbers it came from, you can start at the loss and walk backwards through that record, multiplying the small derivatives together (the chain rule) and adding them up where paths meet. That walk is backpropagation, and a program that does it for you is an autograd engine. This lesson builds one in about 80 lines.

You can compute derivatives of simple functions. But a neural network is not a simple function. It is hundreds of functions composed together: matrix multiply, add bias, apply activation, matrix multiply again, softmax, cross-entropy loss. The output is a function of a function of a function.

To train the network, you need the gradient of the loss with respect to every single weight. Doing this by hand is impossible for millions of parameters. Doing it numerically (finite differences) is too slow.

The chain rule gives you the math. Automatic differentiation gives you the algorithm. Together they let you compute exact gradients through arbitrary compositions of functions in time proportional to a single forward pass.

This is how PyTorch, TensorFlow, and JAX work. You will build a miniature version from scratch.

Idea 1 · The Chain Rule

If y=f(g(x)), the derivative of y with respect to x is:

dxdy​=dgdy​⋅dxdg​=f′(g(x))⋅g′(x)

Multiply the derivatives along the chain. Each link contributes its local derivative.

Example: y=sin(x2)

g(x)f(g)dxdy​​=x2=sin(g)=cos(x2)⋅2x​g′(x)f′(g)​=2x=cos(g)​

For deeper compositions, the chain extends:

ydxdy​​=f(g(h(x)))=f′(g(h(x)))⋅g′(h(x))⋅h′(x)​

Every layer in a neural network is one link in this chain.

Idea 3 · Forward Mode vs Reverse Mode

There are two ways to apply the chain rule through a graph.

Forward mode starts at the inputs and pushes derivatives forward. It computes dx/dx=1 and propagates through each operation. Good when you have few inputs and many outputs.

Forward mode: seed dx/dx = 1, propagate forward

  x = 2       (dx/dx = 1)
  a = x^2     (da/dx = 2x = 4)
  y = sin(a)  (dy/dx = cos(a) * da/dx = cos(4) * 4 = -2.615)

Reverse mode starts at the output and pulls gradients backward. It computes dy/dy=1 and propagates through each operation in reverse. Good when you have many inputs and few outputs.

Reverse mode: seed dy/dy = 1, propagate backward

  y = sin(a)  (dy/dy = 1)
  a = x^2     (dy/da = cos(a) = cos(4) = -0.654)
  x = 2       (dy/dx = dy/da * da/dx = -0.654 * 4 = -2.615)

Neural networks have millions of inputs (weights) and one output (loss). Reverse mode computes all gradients in one backward pass. This is why backpropagation uses reverse mode.

Mode Seed Direction Best when
Forward dxi​/dxi​=1 Input to output Few inputs, many outputs
Reverse dy/dy=1 Output to input Many inputs, few outputs (neural nets)
Check your mental model
  • ✗ "Backpropagation is a different algorithm from the chain rule."
    ✓ It is the chain rule, applied in reverse order through a recorded graph so that one backward pass gives the gradient for every input at once.
  • ✗ "Forward mode and reverse mode give different gradients."
    ✓ They give the same numbers. They differ in cost: forward mode needs one pass per input, reverse mode one pass per output. A loss has one output and millions of inputs, so training uses reverse mode.
  • ✗ "self.grad += ... could just be =."
    ✓ When a value feeds two operations, its gradient is the sum of what comes back along both paths. With =, the second path overwrites the first. The broken exercise below shows it.

Idea 4 · Dual Numbers for Forward Mode

Forward mode can be implemented elegantly with dual numbers. A dual number has the form a+bϵ where ϵ2=0.

Dual number: (value, derivative)

(2, 1) means: value is 2, derivative w.r.t. x is 1

Arithmetic rules:
  (a, a') + (b, b') = (a+b, a'+b')
  (a, a') * (b, b') = (a*b, a'*b + a*b')
  sin(a, a')         = (sin(a), cos(a)*a')

Seed the input variable with derivative 1. The derivative propagates automatically through every operation.

Idea 5 · Building an Autograd Engine

An autograd engine needs three things:

  1. Value wrapping. Wrap every number in an object that stores its value and gradient.
  2. Graph recording. Every operation records its inputs and the local gradient function.
  3. Backward pass. Topological sort the graph, then walk it in reverse, applying the chain rule at each node.

This is exactly what PyTorch's autograd does. The torch.Tensor class wraps values, records operations when requires_grad=True, and computes gradients when you call .backward().

Idea 6 · How PyTorch Autograd Works Under the Hood

When you write PyTorch code:

import torch

x = torch.tensor(2.0, requires_grad=True)
y = x ** 2 + 3 * x + 1
y.backward()
print(x.grad)  # 7.0 = 2*x + 3 = 2*2 + 3
What you should see
tensor(7.)

PyTorch internally:

  1. Creates a Tensor node for x with requires_grad=True
  2. Every operation (**, *, +) creates a new node and records the backward function
  3. y.backward() triggers reverse-mode autodiff through the recorded graph
  4. Each node's grad_fn computes local gradients and passes them to parent nodes
  5. Gradients accumulate in .grad attributes via addition (not replacement)

The graph is dynamic (define-by-run). A new graph is built on every forward pass. This is why PyTorch supports control flow (if/else, loops) inside models.

The same idea as a formula

Local derivatives, multiplied along paths. Write a computation as a graph of simple operations vi​=gi​(parents). The derivative of the output L with respect to any node is the sum, over every path from that node to L, of the products of the local derivatives along the path.

Reverse mode (backpropagation) computes all of them in one backward sweep. Define the adjoint vˉi​=∂L/∂vi​, start with Lˉ=1, and visit nodes in reverse order:

vˉi​=j:vi​ is a parent of vj​∑​vˉj​∂vi​∂vj​​

The sum is why a value used twice must accumulate gradient (+=, never =). The cost is a small constant multiple of one forward pass, whatever the number of inputs: one backward pass gives the gradient of a loss with respect to every one of a billion parameters.

Forward mode carries derivatives along with values instead. Dual numbers do it: with ε2=0,

f(a+bε)=f(a)+f′(a)bε

so evaluating f(x+ε) gives f(x) and f′(x) at once. One forward pass yields the derivative with respect to one input direction, so n inputs need n passes: good for few inputs and many outputs, bad for training.

Worked example
Both modes by hand

f(x,y)=xy+sinx at x=2, y=3.

Forward pass. a=xy=6, b=sin2=0.9093, f=a+b=6.9093.

Reverse mode. fˉ​=1; aˉ=bˉ=1 (addition passes gradients through). x feeds both a and b, so its adjoint is a sum: xˉ=aˉ⋅y+bˉ⋅cos2=3−0.4161=2.5839. yˉ​=aˉ⋅x=2.

Forward mode with a dual number. Set x=2+ε, y=3: xy=6+3ε, sin(2+ε)=sin2+cos2ε, sum 6.9093+2.5839ε. The ε part is ∂f/∂x; a second pass with y=3+ε would give ∂f/∂y=2.

Step 1 · The Value class

class Value:
    def __init__(self, data, children=(), op=''):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None
        self._prev = set(children)
        self._op = op

    def __repr__(self):
        return f"Value(data={self.data:.4f}, grad={self.grad:.4f})"

Every Value stores its numeric data, its gradient (initially zero), a backward function, and pointers to child nodes that produced it.

Step 2 · Arithmetic operations with gradient tracking

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0, self.data), (self,), 'relu')
        def _backward():
            self.grad += (1.0 if out.data > 0 else 0.0) * out.grad
        out._backward = _backward
        return out

Each operation creates a closure that knows how to compute local gradients and multiply by the upstream gradient (out.grad). The += handles the case where a value is used in multiple operations.

Step 3 · The backward pass

    def backward(self):
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        self.grad = 1.0
        for v in reversed(topo):
            v._backward()

Topological sort ensures every node's gradient is fully computed before it propagates to its children. The seed gradient is 1.0 (dy/dy=1).

Step 4 · More operations for a complete engine

The basic Value class handles addition, multiplication, and relu. A real autograd engine needs more. Here are the operations you need to build neural networks:

    def __neg__(self):
        return self * -1

    def __sub__(self, other):
        return self + (-other)

    def __radd__(self, other):
        return self + other

    def __rmul__(self, other):
        return self * other

    def __rsub__(self, other):
        return other + (-self)

    def __pow__(self, n):
        out = Value(self.data ** n, (self,), f'**{n}')
        def _backward():
            self.grad += n * (self.data ** (n - 1)) * out.grad
        out._backward = _backward
        return out

    def __truediv__(self, other):
        return self * (other ** -1) if isinstance(other, Value) else self * (Value(other) ** -1)

    def exp(self):
        import math
        e = math.exp(self.data)
        out = Value(e, (self,), 'exp')
        def _backward():
            self.grad += e * out.grad
        out._backward = _backward
        return out

    def log(self):
        import math
        out = Value(math.log(self.data), (self,), 'log')
        def _backward():
            self.grad += (1.0 / self.data) * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        import math
        t = math.tanh(self.data)
        out = Value(t, (self,), 'tanh')
        def _backward():
            self.grad += (1 - t ** 2) * out.grad
        out._backward = _backward
        return out

Why each operation matters:

Operation Backward rule Used in
__sub__ Reuses add + neg Loss computation (pred - target)
__pow__ n⋅xn−1 Polynomial activations, MSE (error2)
__truediv__ Reuses mul + pow(-1) Normalization, learning rate scaling
exp exp(x)⋅upstream Softmax, log-likelihood
log (1/x)⋅upstream Cross-entropy loss, log probabilities
tanh (1−tanh2)⋅upstream Classic activation function

The clever part: __sub__ and __truediv__ are defined in terms of existing operations. They get correct gradients for free because the chain rule composes through the underlying add/mul/pow operations.

Step 5 · Mini MLP from scratch

With a complete Value class, you can build a neural network. No PyTorch. No NumPy. Just Values and the chain rule.

import random

class Neuron:
    def __init__(self, n_inputs):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(n_inputs)]
        self.b = Value(0.0)

    def __call__(self, x):
        act = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)
        return act.tanh()

    def parameters(self):
        return self.w + [self.b]

class Layer:
    def __init__(self, n_inputs, n_outputs):
        self.neurons = [Neuron(n_inputs) for _ in range(n_outputs)]

    def __call__(self, x):
        return [n(x) for n in self.neurons]

    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]

class MLP:
    def __init__(self, sizes):
        self.layers = [Layer(sizes[i], sizes[i+1]) for i in range(len(sizes)-1)]

    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x[0] if len(x) == 1 else x

    def parameters(self):
        return [p for layer in self.layers for p in layer.parameters()]

A Neuron computes tanh(w1*x1 + w2*x2 + ... + b). A Layer is a list of neurons. An MLP stacks layers. Every weight is a Value, so calling loss.backward() propagates gradients to every parameter.

Training on XOR:

random.seed(42)
model = MLP([2, 4, 1])  # 2 inputs, 4 hidden neurons, 1 output

xs = [[0, 0], [0, 1], [1, 0], [1, 1]]
ys = [-1, 1, 1, -1]  # XOR pattern (using -1/1 for tanh)

for step in range(100):
    preds = [model(x) for x in xs]
    loss = sum((p - y) ** 2 for p, y in zip(preds, ys))

    for p in model.parameters():
        p.grad = 0.0
    loss.backward()

    lr = 0.05
    for p in model.parameters():
        p.data -= lr * p.grad

    if step % 20 == 0:
        print(f"step {step:3d}  loss = {loss.data:.4f}")

print("\nPredictions after training:")
for x, y in zip(xs, ys):
    print(f"  input={x}  target={y:2d}  pred={model(x).data:6.3f}")
What you should see
step   0  loss = 4.1491
step  20  loss = 2.9166
step  40  loss = 1.4733
step  60  loss = 0.6011
step  80  loss = 0.2936

This is micrograd. A complete neural network training loop in pure Python with automatic differentiation. Every commercial deep learning framework does the same thing at massive scale.

Step 6 · Gradient checking

How do you know your autodiff is correct? Compare it against numerical derivatives. This is gradient checking.

def gradient_check(build_expr, x_val, h=1e-7):
    x = Value(x_val)
    y = build_expr(x)
    y.backward()
    autodiff_grad = x.grad

    y_plus = build_expr(Value(x_val + h)).data
    y_minus = build_expr(Value(x_val - h)).data
    numerical_grad = (y_plus - y_minus) / (2 * h)

    diff = abs(autodiff_grad - numerical_grad)
    return autodiff_grad, numerical_grad, diff

Test it on a complex expression:

def expr(x):
    return (x ** 3 + x * 2 + 1).tanh()

ad, num, diff = gradient_check(expr, 0.5)
print(f"Autodiff:  {ad:.8f}")
print(f"Numerical: {num:.8f}")
print(f"Difference: {diff:.2e}")
# Difference should be < 1e-5
What you should see
Autodiff:  0.15252426
Numerical: 0.15252426
Difference: 3.66e-10

Gradient checking is essential when implementing new operations. If your backward pass has a bug, the numerical check catches it. Every serious deep learning implementation runs gradient checks during development.

When to use gradient checking:

Situation Do gradient check?
Adding a new operation to your autograd Yes, always
Debugging a training loop that won't converge Yes, check gradients first
Production training No, too slow (2x forward passes per parameter)
Unit tests for autograd code Yes, automate it
Reading this output

The two gradients agree to all 8 printed decimals and differ by about 4e-10. That is the size of difference you should expect from a central difference with h = 1e-7: it comes from the approximation and rounding, not from the engine. A real bug shows up as a difference around 1e-2 or larger, or as a gradient with the wrong sign.

Recap
What to keep from this lesson
  • The chain rule multiplies local derivatives along a path and adds over paths.
  • An autograd engine wraps numbers, records each operation's inputs and local derivative, then walks the graph in reverse topological order.
  • Reverse mode gets every input's gradient from one backward pass, which is why it trains networks.
  • Gradients accumulate with +=; zero them before every step.
  • Check new operations against a central-difference derivative.

Solutions

SolutionP1 · One input, two paths

a + a gives a.grad = 2.0: the + sends gradient 1 back along each of its two inputs, and both are a, so the two 1s add. a * a gives 6.0: each input receives the other input's value times the upstream gradient, 3 + 3, which is the derivative of a² at 3. Both depend on the += in the backward functions.

SolutionB1 · Two backward passes

Your engine prints 7.0, then 28.0, not 14.0. The second pass resets only y.grad to 1; every intermediate node still holds its gradient from the first pass, so larger amounts flow down and are added to the 7 already in x.grad. PyTorch refuses instead: the second y.backward() raises RuntimeError: Trying to backward through the graph a second time, because it frees the graph after a backward pass. In both, a new forward pass without zeroing adds to the old gradient (PyTorch shows 14.), which is why every training loop calls zero_grad() first.

Industry practice
What's current (2024–2026)
  • Reverse-mode autodiff everywhere. PyTorch's autograd, JAX's grad and torch.compile (which traces the backward pass ahead of time with AOTAutograd) are all reverse-mode automatic differentiation, the method built in this lesson.
  • Trading compute for memory. Activation (gradient) checkpointing stores fewer intermediate values and recomputes them during the backward pass; it is a standard switch in Hugging Face transformers (gradient_checkpointing_enable()) and in large-scale training frameworks.

You are an expert in automatic differentiation and computational graph mechanics. You help engineers build, debug, and extend autograd systems.

When someone asks about gradients, backpropagation, or autodiff:

1. Draw the computational graph as ASCII. Label each node with its operation, forward value, and local gradient.
2. Walk the backward pass step by step. Show the chain rule multiplication at each node.
3. Identify common bugs:
   - Forgetting to zero gradients between backward passes (gradients accumulate by default)
   - Using in-place operations that break the graph
   - Detaching tensors from the graph unintentionally
   - Non-differentiable operations (argmax, integer indexing) silently returning zero gradients
4. When verifying gradients, compare against finite differences: `(f(x+h) - f(x-h)) / (2h)` with `h = 1e-5`.

Debugging checklist for wrong gradients:

- Is `requires_grad=True` set on the right tensors?
- Are gradients being zeroed before each backward pass?
- Is any operation breaking the graph (`.item()`, `.numpy()`, `.detach()`)?
- Are there any in-place operations (`+=`, `.zero_()`) on tensors that need gradients?
- Is the loss scalar? `.backward()` only works on scalar outputs without a `gradient` argument.
- For custom autograd functions, does the backward return the right number of gradients (one per input)?

Key relationships to always check:

- `d/dx(x^n) = n * x^(n-1)`
- `d/dx(relu(x)) = 1 if x > 0, 0 otherwise`
- `d/dx(sigmoid(x)) = sigmoid(x) * (1 - sigmoid(x))`
- `d/dx(tanh(x)) = 1 - tanh(x)^2`
- `d/dx(softmax)` produces a Jacobian matrix, not a simple vector
- For matrix multiply `Y = X @ W`, `dL/dX = dL/dY @ W^T` and `dL/dW = X^T @ dL/dY`

Read the codeThis is the multiply operation of a small autograd engine. python def __mul__(self, other): other = other if isinstance(other, Value) else Value(other) out = Value(self.data * other.data, (self, other), '*') def _backward(): self.grad += other.data * out.grad other.grad += self.data * out.grad out._backward = _backward return out A contributor replaces both += with =, with the comment that a gradient should be set, not added. The XOR training loop still runs and the loss still falls. What did the change break, and how do you prove it in one small test?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. A value that feeds two or more operations receives a gradient from each consumer, and the chain rule says those contributions add. With assignment, the last consumer to run overwrites the others, so every shared node gets a wrong gradient, including each weight that the summed loss uses once per sample. A numerical gradient check exposes the error in one call.

What the chain rule says about shared nodes.

When y depends on x through two paths, the derivative of y with respect to x is the sum of the derivatives along each path. In the engine, a node that is used twice has two closures that write to its grad. The topological order runs every consumer before the node passes its gradient to its own children, so both closures run, and the second must add to the first.

Why the loop still ran.

In the XOR loop the loss is the sum of four squared errors, one per sample, and every weight takes part in all four forward passes. With assignment, each weight keeps only the contribution of the sample that ran last. That is still a direction that often points downhill, so the loss moves. The gradient is wrong for every parameter even so.

The one-line test.

x = Value(3.0)
y = x * x
y.backward()

Here self and other are the same object. The correct gradient of x squared at 3 is 6.0. The two closures each add 3.0, which gives 6.0. With assignment the result is 3.0. The lesson's gradient_check does the same job for any expression: it compares the engine with a centered finite difference and reports the difference, which must be far below 1e-5.

The other side of the same rule.

Because gradients add, the training loop must set every grad back to 0.0 before each backward call. The lesson does this with a loop over the parameters. A framework does the same with a zero_grad call. Both habits come from the same fact: gradient storage is an accumulator.

Plausible wrong answers.

  • "Assignment is fine because each node has one parent." A node that feeds two operations has two consumers in the graph, and a weight in a summed loss has one consumer per sample.
  • "The loss still goes down, so the gradients are correct." A wrong gradient can still point partly downhill. Only a numerical check proves it.
  • "Use a running average instead of a sum." The chain rule sums the path contributions. An average divides the true gradient by the number of consumers.

Follow-ups an interviewer may ask.

  • (level 2) Why must the training loop set every gradient to zero before backward? Expected: gradients accumulate, so a second backward would stack onto the first; the loop sets each parameter's grad to 0.0.
  • (level 3) Write the smallest expression that fails with assignment. Expected: a value multiplied by itself; the gradient at 3 must be 6.0, and assignment gives 3.0.
  • (level 3) Why does the topological order matter for this bug? Expected: all consumers of a node must run before the node passes gradient on; with assignment the answer depends on which consumer ran last.
  • (level 4) Where does the same accumulation rule show up in a framework you use? Expected: a tensor's grad accumulates across uses and across backward calls, which is why the optimizer's zero_grad runs before each step.

Explain the mechanismAutomatic differentiation can push derivatives forward from the inputs or pull them backward from the output. Training frameworks pick the backward direction. Why, and in which situation would the forward direction be the better choice?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. A network has millions of parameters and one scalar loss. Reverse mode seeds the output with a gradient of 1 and gets the gradient of every parameter in one backward sweep. Forward mode needs one sweep for each input variable, so it wins only when the inputs are few and the outputs are many.

The two modes.

Both modes apply the chain rule at every node of the computation graph. They differ in where the seed goes.

Mode Seed Direction Best when
Forward the derivative of one input with respect to itself, set to 1 input to output few inputs, many outputs
Reverse the derivative of the output with respect to itself, set to 1 output to input many inputs, few outputs

Forward mode carries one derivative through the graph. To get the gradient of a loss with respect to a million weights, you would run it a million times. Reverse mode carries the gradient of the single loss back to every node, and each node multiplies by its local derivative and passes the result to its children.

What reverse mode costs.

The backward sweep visits each node once, so the time is proportional to one forward pass. The engine must order the nodes first. A topological sort guarantees that a node has received the gradient from every consumer before it passes gradient on. When a value feeds several operations, the contributions add.

When forward mode is the right choice.

Forward mode fits a function with one or two inputs and a large output, because one sweep gives the derivative of the whole output along one input direction. Dual numbers implement it with almost no code: a pair of value and derivative, with the rule that the square of the derivative part is zero, so the product rule falls out of the arithmetic.

Plausible wrong answers.

  • "Reverse mode is more accurate than forward mode." Both are exact up to floating point rounding. The difference is the cost, not the result.
  • "Forward mode cannot handle a composition of functions." Both modes apply the chain rule through every link. Forward mode pushes the derivative from the input side.
  • "Backpropagation is a different algorithm from reverse-mode autodiff." Backpropagation is reverse-mode autodiff applied to the network graph, with the loss as the single output.

Follow-ups an interviewer may ask.

  • (level 2) Why does the backward sweep need a topological order? Expected: a node must receive the full gradient from every consumer before it passes gradient to its children.
  • (level 3) How many forward-mode sweeps does a model with one million weights need for one gradient? Expected: one million, one per input variable, which is why nobody trains that way.
  • (level 3) What is a dual number and how does it carry a derivative? Expected: a pair of a value and a derivative, where the derivative part squares to zero, so each arithmetic rule carries the derivative along.
  • (level 4) Name a case in an ML system where you would pick forward mode. Expected: a function with one or two inputs and a large vector output, where one sweep gives the derivative of the whole output along one input direction.
