The problem

In plain words first

Sentiment analysis means deciding whether a piece of text is positive or negative. The classic recipe has two steps: turn the text into counts of its words, then let a simple model learn which words point which way ("loved" up, "boring" down). Naive Bayes does this by counting how often each word appears in positive and in negative examples; logistic regression learns one weight per word. Both are fast and surprisingly good. They also share blind spots: "not great" contains "great", sarcasm says the opposite of its words, and "great camera, terrible battery" is two opinions at once. This lesson builds both models, measures them on 10,000 real movie-review sentences, and checks those blind spots against a modern transformer.

"The food was not great." Positive or negative?

Sentiment sounds simple. A reviewer said they liked or did not like something. Label the sentence. The reason it became the canonical NLP task is that every easy-looking case hides a hard one. Negation flips meaning. Sarcasm inverts it. "Not bad at all" is positive despite two negative-coded words. Emojis carry more signal than surrounding text. Domain vocabulary matters (tight in music review versus tight in fashion review).

Sentiment is a working lab for classical NLP. If you understand why every naive baseline has a specific failure mode, you understand why every richer model was invented. This lesson builds a Naive Bayes baseline from scratch, adds logistic regression, and names the traps that make production sentiment a compliance-grade problem.

The idea

Classical sentiment is a two-step recipe.

  1. Represent. Turn the text into a feature vector. BoW, TF-IDF, or n-grams.
  2. Classify. Fit a linear model (Naive Bayes, logistic regression, SVM) on labeled examples.

Naive Bayes is the dumbest model that works. Assume every feature is independent given the label. Estimate P(word | positive) and P(word | negative) from counts. At inference, multiply the probabilities. The "naive" independence assumption is laughably wrong and yet the results are shockingly strong. The reason: with sparse text features and moderate data, the classifier cares about which side each word leans toward more than how much.

Logistic regression fixes the independence assumption. It learns a weight per feature, including negative weights. Give either model the bigram not good and both will learn that it is negative. The difference shows when features overlap: Naive Bayes counts "not", "good" and "not good" as three independent pieces of evidence, while logistic regression fits all the weights together, so it can learn how much the bigram should override the word "good".

The same idea as a formula
Naive Bayes, derived from Bayes' rule

We want the class c with the highest probability given the document d=(w1​,…,wn​). Bayes' rule turns that around:

P(c∣d)=P(d)P(d∣c)P(c)​⇒c^=argcmax​P(c)P(d∣c)

since P(d) is the same for every class. The "naive" step assumes each word is drawn independently given the class, so P(d∣c)=∏i​P(wi​∣c). Products of many small numbers underflow, so take logs:

c^=argcmax​[logP(c)+i=1∑n​logP(wi​∣c)],P(w∣c)=∑w′​count(w′,c)+α∣V∣count(w,c)+α​

That is exactly train_nb and predict_nb. For two classes the decision is a sum of per-word log-ratios logP(w∣−)P(w∣+)​, a linear classifier over word counts whose weights are set by counting rather than by optimisation. The independence assumption is false, which mostly makes the probabilities overconfident (correlated words such as "not", "good" and "not good" are counted as separate evidence), but the ranking of the two classes is often still right.

The same idea as a formula
Logistic regression: the loss and its gradient

Logistic regression models the probability directly: p=σ(w⊤x+b) with σ(z)=1/(1+e−z). For a label y∈{0,1}, maximising the likelihood is minimising the cross-entropy, plus an L2 penalty:

L=−N1​n=1∑N​[yn​logpn​+(1−yn​)log(1−pn​)]+2λ​∥w∥2

Because σ′(z)=σ(z)(1−σ(z)), the derivative collapses to the prediction error times the input:

∂w∂L​=N1​n∑​(pn​−yn​)xn​+λw,∂b∂L​=N1​n∑​(pn​−yn​)

These are the two lines grad_w = X.T @ err / len(y) + l2 * w and grad_b = err.mean() in train_lr. The loss is convex, so gradient descent finds the single best w; the L2 term keeps rare features, which can perfectly separate a few training sentences, from growing huge weights. Unlike Naive Bayes, the weights are fitted jointly, so a feature that only repeats another's evidence gets less weight.

The same idea as a formula
Precision, recall and F1

For one class, count true positives TP, false positives FP and false negatives FN:

precision=TP+FPTP​,recall=TP+FNTP​,F1​=P+R2PR​

F1​ is the harmonic mean, so it is low unless both are high. Macro-F1 averages F1​ over classes with equal weight; micro-F1 pools all counts first, which for single-label classification equals accuracy and is dominated by the majority class.

Step 2 · multinomial Naive Bayes from scratch

import math
from collections import Counter


def train_nb(docs_by_class, vocab, alpha=1.0):
    class_priors = {}
    class_word_probs = {}
    total_docs = sum(len(d) for d in docs_by_class.values())

    for cls, docs in docs_by_class.items():
        class_priors[cls] = len(docs) / total_docs
        counts = Counter()
        for doc in docs:
            for token in doc:
                counts[token] += 1
        total = sum(counts.values()) + alpha * len(vocab)
        class_word_probs[cls] = {
            w: (counts[w] + alpha) / total for w in vocab
        }
    return class_priors, class_word_probs


def predict_nb(doc, class_priors, class_word_probs):
    scores = {}
    for cls in class_priors:
        s = math.log(class_priors[cls])
        for token in doc:
            if token in class_word_probs[cls]:
                s += math.log(class_word_probs[cls][token])
        scores[cls] = s
    return max(scores, key=scores.get)

Additive smoothing (alpha=1.0) is Laplace smoothing. Without it, a word unseen in a class has probability zero and the log explodes. alpha=1.0 is also scikit-learn's default. Smaller values are sometimes better on large vocabularies, so treat it as a setting to tune (under "Use it", 0.1 does slightly worse on movie reviews).

Worked example
Naive Bayes by hand on "great story"

With the regex tokenizer used under "Use it", the five positive sentences hold 26 tokens, the negative ones 25, and the vocabulary has 44 distinct tokens (the comma counts as one).

  • Smoothed totals: positive 26+44=70, negative 25+44=69.
  • "great" appears once in positive text and never in negative: P(great∣+)=2/70=0.0286, P(great∣−)=1/69=0.0145. "story" has the same counts.
  • Scores (both priors are 0.5): positive ln0.5+2ln(2/70)=−7.80; negative ln0.5+2ln(1/69)=−9.16.

Positive wins by 1.36 in log space, a factor of e1.36≈3.9: each of the two words is about twice as likely under positive. A word seen once in each class, like "acting", is nearly neutral, and tilts very slightly negative only because the negative class has one token fewer.

Step 3 · logistic regression from scratch

import numpy as np


def sigmoid(x):
    return 1.0 / (1.0 + np.exp(-np.clip(x, -20, 20)))


def train_lr(X, y, epochs=500, lr=0.05, l2=0.01):
    n_features = X.shape[1]
    w = np.zeros(n_features)
    b = 0.0
    for _ in range(epochs):
        logits = X @ w + b
        preds = sigmoid(logits)
        err = preds - y
        grad_w = X.T @ err / len(y) + l2 * w
        grad_b = err.mean()
        w -= lr * grad_w
        b -= lr * grad_b
    return w, b


def predict_lr(X, w, b):
    return (sigmoid(X @ w + b) >= 0.5).astype(int)

L2 regularization matters here. Text features are sparse; without L2 the model memorizes training examples. Start near 0.01 and tune it: in the sweep under "Use it", 0.01 is already too strong for movie reviews and 0.001 does best.

Check your mental model
  • ✗ "Naive Bayes works because words really are independent."
    ✓ They are not. It works because classification only needs the right side of the decision boundary, not calibrated probabilities. The probabilities it prints are usually far too confident.
  • ✗ "More preprocessing always helps."
    ✓ Under "Use it", removing stop words costs up to three points and negation scoping slightly hurts Naive Bayes. Every step is a hypothesis to test.
  • ✗ "Stronger regularization is the safe default."
    ✓ Too much L2 underfits just as surely as none overfits; the sweep under "Use it" shows both ends.

Step 4 · handling negation (the failure mode)

Consider "not good" and "not bad". A BoW classifier sees {not, good} and {not, bad} and learns from whichever showed up more in training. A bigram classifier sees not_good and not_bad and learns them as distinct features. That is usually enough.

A cruder fix that works when you do not have bigrams: negation scoping. Prefix tokens following a negation word with NOT_ up to the next punctuation.

NEGATION_WORDS = {"not", "no", "never", "nor", "none", "nothing", "neither"}
NEGATION_TERMINATORS = {".", "!", "?", ",", ";"}


def apply_negation(tokens):
    out = []
    negate = False
    for token in tokens:
        if token in NEGATION_TERMINATORS:
            negate = False
            out.append(token)
            continue
        if token in NEGATION_WORDS:
            negate = True
            out.append(token)
            continue
        out.append(f"NOT_{token}" if negate else token)
    return out

>>> apply_negation(["not", "good", "at", "all", ".", "but", "funny"])
['not', 'NOT_good', 'NOT_at', 'NOT_all', '.', 'but', 'funny']

Now good and NOT_good are different features. The classifier can weight them opposite. It is a few lines of preprocessing and often helps on short, negation-heavy text, but measure it on your data: on the movie reviews under "Use it" it slightly hurts Naive Bayes, while plain bigrams help.

Step 5 · evaluation metrics that matter

Accuracy alone is misleading if classes are imbalanced. Benchmark sets such as IMDb and SST-2 are balanced by design, but real streams of text rarely are: product reviews skew heavily positive, support tickets heavily negative. On an 80-20 split, a classifier that always answers the majority class scores 80% accuracy and is worthless. Report every one of the following:

  • Per-class precision and recall. One pair per class. Macro-average them to get a single number that respects class balance.
  • Macro-F1 (primary metric for imbalanced data). Mean of per-class F1 scores, equally weighted. Use this instead of accuracy when classes are imbalanced.
  • Weighted-F1 (alternative). Same as macro but weighted by class frequency. Report alongside macro-F1 when the imbalance itself has business meaning.
  • Confusion matrix. Raw counts. Always inspect before trusting any scalar metric; it reveals which pair of classes the model confuses.
  • Per-class error samples. Pull 5 wrong predictions per class. Read them. Nothing replaces reading the actual errors.

For severely imbalanced data (> 95-5 ratio), report AUROC and AUPRC instead of accuracy. AUPRC is more sensitive to the minority class, which is what you usually care about (spam, fraud, rare sentiment).

Common bug to avoid. Reporting micro-F1 instead of macro-F1 on imbalanced data gives a number that looks high because it is dominated by the majority class. Macro-F1 forces you to see the minority-class performance.

def evaluate(y_true, y_pred):
    tp = sum(1 for t, p in zip(y_true, y_pred) if t == 1 and p == 1)
    fp = sum(1 for t, p in zip(y_true, y_pred) if t == 0 and p == 1)
    fn = sum(1 for t, p in zip(y_true, y_pred) if t == 1 and p == 0)
    tn = sum(1 for t, p in zip(y_true, y_pred) if t == 0 and p == 0)
    precision = tp / (tp + fp) if tp + fp else 0
    recall = tp / (tp + fn) if tp + fn else 0
    f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0
    return {"tp": tp, "fp": fp, "tn": tn, "fn": fn, "precision": precision, "recall": recall, "f1": f1}

Use it: the same idea with real libraries

scikit-learn does it in six lines, correctly.

import pyarrow.parquet as pq
from huggingface_hub import hf_hub_download
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

load = lambda split: pq.read_table(hf_hub_download("cornell-movie-review-data/rotten_tomatoes", f"{split}.parquet",
                                                   repo_type="dataset")).to_pydict()
X_train, y_train = load("train")["text"], load("train")["label"]      # 8,530 movie-review sentences
X_test, y_test = load("test")["text"], load("test")["label"]          # 1,066 held out

pipe = Pipeline([
    ("tfidf", TfidfVectorizer(ngram_range=(1, 2), min_df=2, sublinear_tf=True, stop_words=None)),
    ("clf", LogisticRegression(C=1.0, max_iter=1000)),
])
pipe.fit(X_train, y_train)
print(pipe.score(X_test, y_test))

Three things to notice. stop_words=None keeps negations. ngram_range=(1, 2) adds bigrams so not good becomes a feature (scikit-learn joins the two words with a space). sublinear_tf=True dampens repeated words. Measured on the movie reviews under "Use it", the gains are modest: bigrams, min_df=2 and sublinear scaling together add about half a point. The costly mistake is the opposite one, turning on English stop-word removal, which deletes "not", "no" and "never" along with "the" and costs up to three points.

import time
import matplotlib.pyplot as plt
from scipy.sparse import csr_matrix

train, test = load("train"), load("test")
y_tr, y_te = np.array(train["label"]), np.array(test["label"])
print(f"{len(y_tr):,} training sentences ({y_tr.mean():.0%} positive), {len(y_te):,} test ({y_te.mean():.0%} positive)")
print(f"   e.g. {train['text'][0][:80]!r}...")

def nb_run(prep, alpha=1.0):
    tr, te = [prep(tok(s)) for s in train["text"]], [prep(tok(s)) for s in test["text"]]
    vocab_rt = {w for d in tr for w in d}
    pri, pr = train_nb({1: [d for d, l in zip(tr, y_tr) if l == 1], 0: [d for d, l in zip(tr, y_tr) if l == 0]},
                       vocab_rt, alpha)
    pred = np.array([predict_nb(d, pri, pr) for d in te])
    return (pred == y_te).mean(), len(vocab_rt), pred

bigrams = lambda t: t + [a + "_" + b for a, b in zip(t, t[1:])]
print("\nNaive Bayes, test accuracy")
for name, prep, alpha in [("words", lambda t: t, 1.0), ("words, alpha=0.1", lambda t: t, 0.1),
                          ("words + NOT_ scoping", apply_negation, 1.0), ("words + bigrams", bigrams, 1.0)]:
    acc, n_feat, pred = nb_run(prep, alpha)
    print(f"   {name:22s} {acc:.1%}   ({n_feat:,} features)")
    if name == "words":
        nb_pred = pred

pos, neg = evaluate(y_te, nb_pred), evaluate(1 - y_te, 1 - nb_pred)
print(f"\nNaive Bayes (words): confusion  true pos -> {pos['tp']} pos / {pos['fn']} neg,  true neg -> {pos['fp']} pos / {pos['tn']} neg")
print(f"   positive class P {pos['precision']:.2f} R {pos['recall']:.2f} F1 {pos['f1']:.2f};  "
      f"negative class P {neg['precision']:.2f} R {neg['recall']:.2f} F1 {neg['f1']:.2f}")

rng = np.random.default_rng(0)
keep = np.r_[np.flatnonzero(y_te == 1), rng.choice(np.flatnonzero(y_te == 0), 133, replace=False)]
y_imb, always_pos = y_te[keep], np.ones(len(keep), dtype=int)

      f"macro-F1 {np.mean(f1s):.2f}  (F1 positive {f1s[0]:.2f}, negative {f1s[1]:.2f})")

word_index = {}
for s in train["text"]:
    for t in tok(s):
        word_index.setdefault(t, len(word_index))
def binary_bow(texts):
    rows, cols = [], []
    for i, s in enumerate(texts):
        for c in {word_index[t] for t in tok(s) if t in word_index}:
            rows.append(i); cols.append(c)
    return csr_matrix((np.ones(len(rows)), (rows, cols)), shape=(len(texts), len(word_index)))

Plain-word Naive Bayes gets about 78% on sentences it never saw, in about a second of counting. Of the three tweaks, only bigrams help (79.6%); a smaller alpha costs about two points and NOT_ scoping one (scoping runs to the next punctuation, which in long review sentences marks many words that are not really negated, and splits the counts of every word into two rarer features). The confusion counts and per-class scores are nearly symmetric, as they should be on balanced data. The 80/20 subset shows the trap Step 5 warned about: always answering "positive" scores 80% accuracy, while macro-F1 (about 0.44) exposes that it never finds a negative. The L2 sweep shows both failure modes: at 0.03 the weights are held so small that the model learns almost nothing, and at 0.01 even training accuracy is low; with no L2 the model fits 97% of training sentences and does slightly worse on the test set than at its best setting, 0.001. And Naive Bayes, with no tuning at all, beats every one of these logistic regressions (78.1% against 76.2%), a known result for short texts (Wang and Manning, 2012).

The transformer is about eleven points more accurate on the full test set, and it gets "Not bad at all" right, which the word-count model calls clearly negative (0.18). It is not a solved problem, though. The sarcastic sentence is read as positive, because its surface words ("great") win; the word-count model happens to get this one right, only just (0.46). "Camera great, battery terrible" gets one fully confident label from DistilBERT and a shrug (0.54) from TF-IDF, which is the wrong question for a two-opinion sentence. "I expected to hate it, and I did not" is called negative by both, DistilBERT with full confidence: the score next to each label is how sure the model is, not how often it is right. Those three failures are exactly the bullets below.

When to reach for a transformer

  • Sarcasm. Word-count models mostly fail here, and transformers only partly do better: the DistilBERT run under "Use it" reads an obviously sarcastic sentence as positive.
  • Long reviews where sentiment shifts mid-document.
  • Aspect-based sentiment. "Camera was great but battery was terrible." You need to attribute sentiment to aspects, which a single-label classifier cannot express: use an aspect-based model, or an LLM asked for structured output per aspect.
  • Non-English, low-resource languages. A multilingual model such as XLM-R, fine-tuned on English labels, transfers to other languages without labels in them (zero-shot cross-lingual transfer); a few hundred labels in the target language usually help a lot.

If you need any of the above, skip ahead to phase 7 (transformers deep dive). Otherwise, logistic regression or Naive Bayes on TF-IDF with bigrams is the strong, cheap baseline to beat first, and a fine-tuned small transformer is the usual next step when its accuracy is not enough.

Industry practice
What's current (2024–2026)
  • Encoders still do the volume work. For millions of texts a day, teams fine-tune a small encoder. ModernBERT (December 2024; 149M and 395M parameters, 8,192-token context, about twice as fast as DeBERTa-v3) is the usual modern starting point in place of the original BERT.
  • LLMs as zero-shot labellers. An LLM given the label definitions and a JSON schema classifies with no training data, and handles aspects ("camera: positive, battery: negative") naturally. It is slower and costlier per item, so a common pattern is to let the LLM label a few thousand examples, check a sample by hand, and train a small classifier on them.
  • Small zero-shot models on CPU. GLiNER2 (2025, about 205M parameters) does text classification with labels given at run time, alongside entity extraction, in about 0.1 to 0.2 seconds per text on a CPU.
  • Same rule as ever. Whatever the model, measure it on your own labelled sample with per-class scores, and keep the TF-IDF baseline as the number to beat.

Sources: ModernBERT, GLiNER2.

The reproducibility trap (again)

Retraining sentiment models is routine. Re-evaluating them is not. Accuracy numbers reported in papers use specific splits, specific preprocessing, specific tokenizers. If you compare your new model to a baseline without using the identical pipeline, you will get misleading deltas. Always regenerate the baseline on your pipeline, not the paper's number.

Recap
What to keep from this lesson
  • The recipe: represent (counts, TF-IDF, n-grams) then classify (Naive Bayes, logistic regression).
  • Naive Bayes is counting plus smoothing; without smoothing one unseen word breaks it.
  • Logistic regression needs its L2 strength tuned: too much underfits, none overfits.
  • Keep negation words: never remove stop words for sentiment. Bigrams help; test every other preprocessing step.
  • Report per-class precision, recall and macro-F1, not accuracy alone, and read the errors.
  • A fine-tuned transformer is about eleven points better here but still misses sarcasm and mixed opinions.

Solutions

SolutionP1 · It goes down slightly

Plain words score about 78%; with NOT_ scoping, about a point less. Scoping is a heuristic: in review sentences the next punctuation mark is often far away, so it marks words that are not really negated ("not only funny but moving"), and it splits each word's counts between word and NOT_word, making both rarer. Bigrams capture the useful part (not good) without that damage, and they do raise accuracy. Whether scoping helps depends on the data, which is why it has to be measured.

SolutionB1 · A math domain error

With alpha=0, a word that never appeared in, say, the negative class gets P(word∣−)=0, and predict_nb calls math.log(0), which raises ValueError: math domain error. Mathematically the score is −∞: one unseen word would veto the whole class however strong the rest of the evidence. Smoothing gives every word a small non-zero probability in every class, so a single word can only tilt the decision, never end it.
