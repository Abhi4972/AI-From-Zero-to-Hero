In plain words first
The idea in one line

Your model gets 99% on training data and 60% on test data. It memorized instead of learning. Regularization is the tax you impose on complexity to force generalization.

Terms you'll hear
Term What people say What it actually means
Overfitting "Model memorized the data" When a model's training performance significantly exceeds its test performance, indicating it learned noise rather than signal
Regularization "Preventing overfitting" Any technique that constrains model complexity to improve generalization: dropout, weight decay, normalization, augmentation
Dropout "Random neuron deletion" Zeroing random neurons during training with probability $p$, forcing redundant representations; equivalent to training an ensemble
Weight decay "L2 penalty" Shrinking all weights toward zero by subtracting $\lambda w$ at each step; penalizes complexity through weight magnitude
Batch normalization "Normalize per batch" Normalizing layer outputs across the batch dimension using batch statistics during training and running averages during inference
Layer normalization "Normalize per sample" Normalizing across features within each sample; batch-independent, used in transformers where batch size varies
RMSNorm "LayerNorm without the mean" Root mean square normalization; drops the mean subtraction from LayerNorm for 10% speedup with equal accuracy
Early stopping "Stop before overfit" Halting training when validation loss stops improving; the simplest regularizer, often used alongside others
Data augmentation "More data from less" Transforming training inputs (flip, crop, noise) to increase effective dataset size and force invariance learning
Generalization gap "Train-test split" The difference between training and test performance; regularization aims to minimize this gap

The problem

In plain words first

A big network can memorise its training set, noise included, and then do worse on new data. Regularisation makes memorising harder: dropout randomly switches neurons off during training so no single one can be relied on, weight decay keeps weights small, early stopping quits before the memorising starts, and data augmentation shows the model more varied examples. Normalisation layers (BatchNorm, LayerNorm, RMSNorm) mainly keep each layer's numbers in a steady range so training is stable, which also tends to help.

A neural network with enough parameters can memorize any dataset. This is not a hypothetical -- Zhang et al. (2017) showed it by training standard networks on ImageNet with random labels. The networks reached near-zero training loss on completely random label assignments. They memorized a million random input-output pairs with no pattern to learn. Training loss was perfect. Test accuracy was no better than chance.

This is the overfitting problem, and it gets worse as models get larger. GPT-3 has 175 billion parameters. The training set has about 500 billion tokens. With that many parameters, the model has enough capacity to memorize significant chunks of the training data verbatim. Without regularization, it would just regurgitate training examples instead of learning generalizable patterns.

The gap between training performance and test performance is the overfitting gap. Every technique in this lesson attacks that gap from a different angle. Dropout forces the network to not rely on any single neuron. Weight decay prevents any single weight from growing too large. Batch normalization smooths the loss landscape so the optimizer finds flatter, more generalizable minima. Layer normalization does the same thing but works where batch normalization fails (small batches, variable-length sequences). RMSNorm does it 10% faster by dropping the mean calculation. Each technique is simple. Together, they're the difference between a model that memorizes and one that generalizes.

Idea 1 · The Overfitting Spectrum

Every model sits somewhere on a spectrum from underfitting (too simple to capture the pattern) to overfitting (so complex it captures noise). The sweet spot is in between, and regularization pushes models toward it from the overfit side.

Idea 2 · Dropout

The simplest regularization technique with the most elegant interpretation. During training, randomly set each neuron's output to zero with probability p.

output=activation(z)⋅maskwhere mask[i]∼Bernoulli(1−p)

With p=0.5, half the neurons are zeroed on every forward pass. The network must learn redundant representations because it can't predict which neurons will be available. This prevents co-adaptation -- neurons learning to rely on specific other neurons being present.

The ensemble interpretation: a network with N neurons and dropout creates 2N possible subnetworks (every combination of which neurons are on or off). Training with dropout approximately trains all 2N subnetworks simultaneously, each on different mini-batches. At test time, you use all neurons (no dropout) and scale outputs by (1−p) to match the expected value during training. This is equivalent to averaging the predictions of 2N subnetworks -- a massive ensemble from a single model.

In practice, the scaling is applied during training instead of testing (inverted dropout):

During training:During testing:​output=activation(z)⋅mask/(1−p)output=activation(z)(no change needed)​

This is cleaner because test code doesn't need to know about dropout at all.

Default rates: p = 0.1 for transformers, p = 0.5 for MLPs, p = 0.2-0.3 for CNNs. Higher dropout = stronger regularization = more underfitting risk.

Worked example
Inverted dropout on eight numbers

Input (1,2,…,8), mean 4.5, with p=0.5. One training pass might keep positions 1, 2, 5 and 7 and scale them by 1/(1−0.5)=2: output (2,4,0,0,10,0,14,0), mean 3.75. Another pass keeps a different half. On average over many passes each value is kept half the time and doubled when kept, so the expected output equals the input, and at test time the layer can simply pass values through unchanged.

Check your mental model
  • ✗ "At test time dropout exactly averages all 2N sub-networks."
    ✓ Using all neurons with matched scaling is a cheap approximation of that average. It is exact only for a linear layer; with non-linear layers it is close, not equal.
  • ✗ "Training accuracy above test accuracy is always overfitting, and the reverse means a bug."
    ✓ With dropout, training accuracy is measured with neurons switched off, so it understates the model. Step 6's dropout run shows test accuracy above training accuracy for exactly this reason.
  • ✗ "BatchNorm works because it removes internal covariate shift."
    ✓ That was the original explanation; Santurkar et al. (2018) found the benefit comes mostly from a smoother loss landscape that tolerates larger learning rates.

Idea 3 · Weight Decay (L2 Regularization)

Add the squared magnitude of all weights to the loss:

total_loss=task_loss+2λ​i∑​wi2​

The gradient of the regularization term is λw. This means at every step, each weight is shrunk toward zero by a fraction proportional to its magnitude. Large weights get penalized more. The model is pushed toward solutions where no single weight dominates.

Why this helps generalization: overfit models tend to have large weights that amplify noise in the training data. Weight decay keeps weights small, which limits the model's effective capacity and forces it to rely on robust, generalizable features rather than memorized quirks.

The λ hyperparameter controls the strength. Typical values:

  • 0.01 for AdamW on transformers
  • 1e-4 for SGD on CNNs
  • 0.1 for heavily overfit models

As discussed in lesson 06: weight decay and L2 regularization are equivalent in SGD but not in Adam. Always use AdamW (decoupled weight decay) when training with Adam.

Idea 4 · Batch Normalization

Normalize the output of each layer across the mini-batch before passing it to the next layer.

For a mini-batch of activations at some layer:

μσ2x^y​=B1​i∑​xi​=B1​i∑​(xi​−μ)2=σ2+ϵ​xi​−μ​=γx^+β​​(batch mean)(batch variance)(normalize)(scale and shift)​

Gamma and beta are learnable parameters that let the network undo the normalization if that's optimal. Without them, you'd be forcing every layer's output to be zero-mean unit-variance, which might not be what the network wants.

Training vs inference split: During training, μ and σ come from the current mini-batch. During inference, you use running averages accumulated during training (exponential moving average with momentum = 0.1, meaning 90% old + 10% new).

Why BatchNorm works is still debated. The original paper claimed it reduces "internal covariate shift" (the distribution of layer inputs changing as earlier layers update). Santurkar et al. (2018) showed this explanation is wrong. The actual reason: BatchNorm makes the loss landscape smoother. The gradients are more predictive, the Lipschitz constants are smaller, and the optimizer can take larger steps safely. This is why BatchNorm lets you use higher learning rates and converge faster.

BatchNorm has a fundamental limitation: it depends on batch statistics. With batch size 1, the mean and variance are meaningless. With small batches (< 32), the statistics are noisy and hurt performance. This matters for tasks like object detection (where memory limits batch size) and language modeling (where sequence lengths vary).

Idea 5 · Layer Normalization

Normalize across features instead of across the batch. For a single sample:

μσ2x^y​=D1​j∑​xj​=D1​j∑​(xj​−μ)2=σ2+ϵ​xj​−μ​=γx^+β​​(feature mean)(feature variance)​

D is the feature dimension. Each sample is normalized independently -- no dependence on batch size. This is why transformers use LayerNorm instead of BatchNorm. Sequences have variable lengths, batch sizes are often small (or 1 during generation), and the computation is identical between training and inference.

LayerNorm in transformers is applied after each self-attention block and each feed-forward block (Post-LN), or before them (Pre-LN, which is more stable for training).

Idea 6 · RMSNorm

LayerNorm without the mean subtraction. Proposed by Zhang & Sennrich (2019).

rmsy​=D1​j∑​xj2​​=γ⋅rmsx​​

That's it. No mean computation, no beta parameter. The observation: the re-centering (mean subtraction) in LayerNorm contributes very little to the model's performance, but costs computation. Removing it gives the same accuracy with about 10% less overhead.

LLaMA, LLaMA 2, LLaMA 3, Mistral, and most modern LLMs use RMSNorm instead of LayerNorm. At the scale of billions of parameters and trillions of tokens, that 10% savings is significant.

Tip
How much faster?

The RMSNorm paper measured running-time reductions from 7 to 64 percent of the normalisation cost, depending on the model and hardware. Normalisation is a small part of a transformer's total compute, so the end-to-end saving is much smaller; treat "about 10 percent" as a rough figure, not a constant.

Idea 8 · Data Augmentation as Regularization

Not a model modification but a data modification. Transform training inputs while preserving labels:

  • Images: random crop, flip, rotation, color jitter, cutout
  • Text: synonym replacement, back-translation, random deletion
  • Audio: time stretch, pitch shift, noise addition

The effect is identical to regularization: it increases the effective size of the training set, making it harder for the model to memorize specific examples. A model that only sees each image once in its original form can memorize it. A model that sees 50 augmented versions of each image is forced to learn the invariant structure.

Idea 9 · Early Stopping

The simplest regularizer: stop training when validation loss starts increasing. The model hasn't overfit yet at that point. In practice, you track validation loss every epoch, save the best model, and continue training for a "patience" window (typically 5-20 epochs). If validation loss doesn't improve within the patience window, you stop and load the best saved model.

Idea 10 · When to Apply What

The same idea as a formula

Dropout. During training, each unit is kept with probability q and scaled: h~=qm⊙h​ with mi​∼Bernoulli(q). Then E[h~]=h, so at evaluation the layer simply passes h through unchanged ("inverted dropout"). Forgetting to switch to evaluation mode keeps the noise on at inference.

Weight decay. Adding 2λ​∥w∥2 to the loss adds λw to the gradient, so each SGD step multiplies the weights by 1−ηλ before the gradient step.

Normalisation layers. For a vector of activations x (over a batch for BatchNorm, over the features of one example for LayerNorm):

BN/LN(x)=γ⊙σ2+ϵ​x−μ​+β,RMSNorm(x)=γ⊙d1​∑i​xi2​+ϵ​x​

BatchNorm uses batch statistics in training and running averages at evaluation, so it depends on batch size; LayerNorm and RMSNorm use only the example itself, which is why transformers use them. RMSNorm drops the mean subtraction and β: fewer operations, and in practice the same quality (Llama, Qwen, Mistral, Gemma).

Early stopping keeps the checkpoint with the best validation loss; with gradient descent on a linear model it behaves much like an L2 penalty whose strength falls as training goes on.

Step 1 · Dropout (Train and Eval Mode)

import random
import math


class Dropout:
    def __init__(self, p=0.5):
        self.p = p
        self.training = True
        self.mask = None

    def forward(self, x):
        if not self.training:
            return list(x)
        self.mask = []
        output = []
        for val in x:
            if random.random() < self.p:
                self.mask.append(0)
                output.append(0.0)
            else:
                self.mask.append(1)
                output.append(val / (1 - self.p))
        return output

    def backward(self, grad_output):
        grads = []
        for g, m in zip(grad_output, self.mask):
            if m == 0:
                grads.append(0.0)
            else:
                grads.append(g / (1 - self.p))
        return grads

Step 2 · L2 Weight Decay

def l2_regularization(weights, lambda_reg):
    penalty = 0.0
    for w in weights:
        penalty += w * w
    return lambda_reg * 0.5 * penalty

def l2_gradient(weights, lambda_reg):
    return [lambda_reg * w for w in weights]

Step 3 · Batch Normalization

class BatchNorm:
    def __init__(self, num_features, momentum=0.1, eps=1e-5):
        self.gamma = [1.0] * num_features
        self.beta = [0.0] * num_features
        self.eps = eps
        self.momentum = momentum
        self.running_mean = [0.0] * num_features
        self.running_var = [1.0] * num_features
        self.training = True
        self.num_features = num_features

    def forward(self, batch):
        batch_size = len(batch)
        if self.training:
            mean = [0.0] * self.num_features
            for sample in batch:
                for j in range(self.num_features):
                    mean[j] += sample[j]
            mean = [m / batch_size for m in mean]

            var = [0.0] * self.num_features
            for sample in batch:
                for j in range(self.num_features):
                    var[j] += (sample[j] - mean[j]) ** 2
            var = [v / batch_size for v in var]

            for j in range(self.num_features):
                self.running_mean[j] = (1 - self.momentum) * self.running_mean[j] + self.momentum * mean[j]
                self.running_var[j] = (1 - self.momentum) * self.running_var[j] + self.momentum * var[j]
        else:
            mean = list(self.running_mean)
            var = list(self.running_var)

        self.x_hat = []
        output = []
        for sample in batch:
            normalized = []
            out_sample = []
            for j in range(self.num_features):
                x_h = (sample[j] - mean[j]) / math.sqrt(var[j] + self.eps)
                normalized.append(x_h)
                out_sample.append(self.gamma[j] * x_h + self.beta[j])
            self.x_hat.append(normalized)
            output.append(out_sample)
        return output

Step 4 · Layer Normalization

class LayerNorm:
    def __init__(self, num_features, eps=1e-5):
        self.gamma = [1.0] * num_features
        self.beta = [0.0] * num_features
        self.eps = eps
        self.num_features = num_features

    def forward(self, x):
        mean = sum(x) / len(x)
        var = sum((xi - mean) ** 2 for xi in x) / len(x)

        self.x_hat = []
        output = []
        for j in range(self.num_features):
            x_h = (x[j] - mean) / math.sqrt(var + self.eps)
            self.x_hat.append(x_h)
            output.append(self.gamma[j] * x_h + self.beta[j])
        return output

Step 5 · RMSNorm

class RMSNorm:
    def __init__(self, num_features, eps=1e-6):
        self.gamma = [1.0] * num_features
        self.eps = eps
        self.num_features = num_features

    def forward(self, x):
        rms = math.sqrt(sum(xi * xi for xi in x) / len(x) + self.eps)
        output = []
        for j in range(self.num_features):
            output.append(self.gamma[j] * x[j] / rms)
        return output

Step 6 · Training With and Without Regularization

def sigmoid(x):
    x = max(-500, min(500, x))
    return 1.0 / (1.0 + math.exp(-x))


def make_circle_data(n=200, seed=42):
    random.seed(seed)
    data = []
    for _ in range(n):
        x = random.uniform(-2, 2)
        y = random.uniform(-2, 2)
        label = 1.0 if x * x + y * y < 1.5 else 0.0
        data.append(([x, y], label))
    return data


class RegularizedNetwork:
    def __init__(self, hidden_size=16, lr=0.05, dropout_p=0.0, weight_decay=0.0):
        random.seed(0)
        self.hidden_size = hidden_size
        self.lr = lr
        self.dropout_p = dropout_p
        self.weight_decay = weight_decay
        self.dropout = Dropout(p=dropout_p) if dropout_p > 0 else None

        self.w1 = [[random.gauss(0, 0.5) for _ in range(2)] for _ in range(hidden_size)]
        self.b1 = [0.0] * hidden_size
        self.w2 = [random.gauss(0, 0.5) for _ in range(hidden_size)]
        self.b2 = 0.0

    def forward(self, x, training=True):
        self.x = x
        self.z1 = []
        self.h = []
        for i in range(self.hidden_size):
            z = self.w1[i][0] * x[0] + self.w1[i][1] * x[1] + self.b1[i]
            self.z1.append(z)
            self.h.append(max(0.0, z))

        if self.dropout and training:
            self.dropout.training = True
            self.h = self.dropout.forward(self.h)
        elif self.dropout:
            self.dropout.training = False
            self.h = self.dropout.forward(self.h)

        self.z2 = sum(self.w2[i] * self.h[i] for i in range(self.hidden_size)) + self.b2
        self.out = sigmoid(self.z2)
        return self.out

    def backward(self, target):
        eps = 1e-15
        p = max(eps, min(1 - eps, self.out))
        d_loss = -(target / p) + (1 - target) / (1 - p)
        d_sigmoid = self.out * (1 - self.out)
        d_out = d_loss * d_sigmoid

        for i in range(self.hidden_size):
            d_relu = 1.0 if self.z1[i] > 0 else 0.0
            d_h = d_out * self.w2[i] * d_relu
            self.w2[i] -= self.lr * (d_out * self.h[i] + self.weight_decay * self.w2[i])
            for j in range(2):
                self.w1[i][j] -= self.lr * (d_h * self.x[j] + self.weight_decay * self.w1[i][j])
            self.b1[i] -= self.lr * d_h
        self.b2 -= self.lr * d_out

    def evaluate(self, data):
        correct = 0
        total_loss = 0.0
        for x, y in data:
            pred = self.forward(x, training=False)
            eps = 1e-15
            p = max(eps, min(1 - eps, pred))
            total_loss += -(y * math.log(p) + (1 - y) * math.log(1 - p))
            if (pred >= 0.5) == (y >= 0.5):
                correct += 1
        return total_loss / len(data), correct / len(data) * 100

    def train_model(self, train_data, test_data, epochs=300):
        history = []
        for epoch in range(epochs):
            total_loss = 0.0
            correct = 0
            for x, y in train_data:
                pred = self.forward(x, training=True)
                self.backward(y)
                eps = 1e-15
                p = max(eps, min(1 - eps, pred))
                total_loss += -(y * math.log(p) + (1 - y) * math.log(1 - p))
                if (pred >= 0.5) == (y >= 0.5):
                    correct += 1
            train_loss = total_loss / len(train_data)
            train_acc = correct / len(train_data) * 100
            test_loss, test_acc = self.evaluate(test_data)
            history.append((train_loss, train_acc, test_loss, test_acc))
            if epoch % 75 == 0 or epoch == epochs - 1:
                gap = train_acc - test_acc
                print(f"    Epoch {epoch:3d}: train_acc={train_acc:.1f}%, test_acc={test_acc:.1f}%, gap={gap:.1f}%")
        return history

Recap
What to keep from this lesson
  • Overfitting shows as a gap between training and validation performance; measure it before regularising.
  • Dropout zeroes random neurons during training and rescales the rest; at test time it does nothing.
  • Weight decay shrinks weights each step; use AdamW's decoupled version with Adam.
  • BatchNorm normalises across the batch and keeps running statistics for eval; LayerNorm and RMSNorm normalise each sample and suit transformers.
  • Early stopping is often the strongest and cheapest regulariser on small data.

Solutions

SolutionP1 · Running statistics lag behind

The running mean ends near 2.2 to 2.4 in each feature, not 3.45: starting from 0, ten updates with momentum 0.1 cover only 1−0.910=65 percent of the way. In eval mode (5,5,5,5) is normalised with that low mean and comes out between about 2.6 and 3.0 per feature; with fully settled statistics it would be about 1.6.

SolutionB1 · BatchNorm needs more than one sample

ValueError: Expected more than 1 value per channel when training. In training mode BatchNorm normalises each feature across the batch, and one sample has no spread to divide by. In eval mode it uses the running mean and variance instead, so a single sample is fine. The same mismatch causes subtler bugs: forget model.eval() and predictions depend on whichever other samples share the batch.

Use it: the same idea with real libraries

PyTorch provides all normalization and regularization as modules:

import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(784, 256),
    nn.BatchNorm1d(256),
    nn.ReLU(),
    nn.Dropout(0.3),
    nn.Linear(256, 128),
    nn.BatchNorm1d(128),
    nn.ReLU(),
    nn.Dropout(0.3),
    nn.Linear(128, 10),
)

model.train()
out_train = model(torch.randn(32, 784))

model.eval()
out_test = model(torch.randn(1, 784))

The model.train() / model.eval() toggle is critical. It switches dropout on/off and tells BatchNorm to use batch statistics vs running statistics. Forgetting model.eval() before inference is one of the most common bugs in deep learning. Your test accuracy will fluctuate randomly because dropout is still active and BatchNorm is using mini-batch statistics.

For transformers, the pattern is different:

class TransformerBlock(nn.Module):
    def __init__(self, d_model=512, nhead=8, dropout=0.1):
        super().__init__()
        self.attention = nn.MultiheadAttention(d_model, nhead, dropout=dropout)
        self.norm1 = nn.LayerNorm(d_model)
        self.ff = nn.Sequential(
            nn.Linear(d_model, d_model * 4),
            nn.GELU(),
            nn.Linear(d_model * 4, d_model),
            nn.Dropout(dropout),
        )
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        attended, _ = self.attention(x, x, x)
        x = self.norm1(x + self.dropout(attended))
        x = self.norm2(x + self.ff(x))
        return x

LayerNorm, not BatchNorm. Dropout p=0.1, not p=0.5. These are the transformer defaults.

Industry practice
What's current (2024–2026)
  • LLM pretraining uses little dropout. Llama 3 and most modern LLM recipes set dropout to zero for pretraining and rely on weight decay (around 0.1 with AdamW) and huge, deduplicated data; dropout reappears in small-data fine-tuning.
  • Data augmentation in vision. RandAugment, MixUp and CutMix are standard in image classification training (timm, torchvision), as is label smoothing.
  • LoRA as regularisation. Low-rank fine-tuning (PEFT) changes far fewer parameters, which itself limits overfitting on small datasets.

Sources: Llama 3 paper, timm training scripts, torchvision v2 MixUp/CutMix, PEFT.

Batch normalization normalizes each feature over the examples of a mini-batch. Then it scales and shifts each feature with two learned vectors. In training, it uses the statistics of the batch and updates running averages. In inference, it uses only the running averages. You write the forward pass for both modes and the backward pass for training mode.

Task

Write two functions.

  1. batchnorm_forward(x, gamma, beta, running_mean, running_var, momentum=0.1, eps=1e-5, training=True) returns (out, cache, new_running_mean, new_running_var).
  2. batchnorm_backward(grad_output, cache) returns (dx, dgamma, dbeta).

In training mode, compute for each feature column j over the batch of N rows:

μj​=N1​i∑​xij​,σj2​=N1​i∑​(xij​−μj​)2

x^ij​=σj2​+ϵ​xij​−μj​​,outij​=γj​x^ij​+βj​

The variance is the biased variance. It divides by N, not by N−1. The running statistics also use this biased variance:

new mean=(1−m)⋅running mean+m⋅μ,new var=(1−m)⋅running var+m⋅σ2

Here m is momentum.

In inference mode (training=False), use running_mean and running_var in place of μ and σ2. Return copies of the running statistics without a change. The cache in inference mode can be None.

batchnorm_backward gets the gradient of the loss with respect to out and the cache from a training mode call. It returns the gradients of the loss with respect to x, gamma and beta. The gradient dx must include the effect of x on μ and on σ2.

The cache is your own choice. The checks pass the cache from your forward pass to your backward pass and do not read it.

  • batchnorm_backward returns a tuple (dx, dgamma, dbeta) with shapes (N, D), (D,) and (D,).

Reference solution and notes
import numpy as np


def batchnorm_forward(x, gamma, beta, running_mean, running_var, momentum=0.1, eps=1e-5, training=True):
    if not training:
        x_hat = (x - running_mean) / np.sqrt(running_var + eps)
        return gamma * x_hat + beta, None, running_mean.copy(), running_var.copy()
    mean = np.mean(x, axis=0)
    var = np.mean((x - mean) ** 2, axis=0)
    std_inv = 1.0 / np.sqrt(var + eps)
    x_hat = (x - mean) * std_inv
    out = gamma * x_hat + beta
    new_mean = (1 - momentum) * running_mean + momentum * mean
    new_var = (1 - momentum) * running_var + momentum * var
    cache = (x_hat, std_inv, gamma)
    return out, cache, new_mean, new_var


def batchnorm_backward(grad_output, cache):
    x_hat, std_inv, gamma = cache
    n = grad_output.shape[0]
    dgamma = np.sum(grad_output * x_hat, axis=0)
    dbeta = np.sum(grad_output, axis=0)
    dx_hat = grad_output * gamma
    dx = std_inv / n * (n * dx_hat - np.sum(dx_hat, axis=0) - x_hat * np.sum(dx_hat * x_hat, axis=0))
    return dx, dgamma, dbeta

Why dx has three terms

The first term is the direct path through x^. The second term removes the mean of g over the batch, because each xij​ also moves μj​. The third term removes the part of g along x^, because each xij​ also moves σj2​. For this reason, each column of dx sums to 0, and dx is orthogonal to x^ in each column.

Why eps goes inside the square root

σ2+ϵ​ is at least ϵ​, so the division is safe when a feature is constant. σ2​+ϵ also avoids a division by 0, but it gives a different output when the variance is close to ϵ. Frameworks use the first form.

Biased or unbiased variance

The lesson and this problem use the biased variance for the running statistics. Some frameworks store the unbiased variance, with N−1, in the running statistics. The normalization of the batch uses the biased variance in both cases. Check this detail when you load weights from another framework.

Training and inference

The forward pass depends on the mode. A model that stays in training mode at test time gives outputs that change with the other examples in the batch. This is a common bug. The model.train() and model.eval() calls in the lesson switch this mode.

Where this goes next

LayerNorm uses the same formula over the feature axis of each example. It needs no running statistics, so training and inference are the same. Transformers use LayerNorm or RMSNorm for this reason.

Dropout sets a random part of the activations to 0 during training. Inverted dropout also divides the kept activations by 1−p, so the expected value of each activation does not change. At inference time the layer then does nothing. You write the forward pass for both modes and the backward pass.

Task

Write two functions.

  1. dropout_forward(x, p, rng, training=True) returns (out, mask).
  2. dropout_backward(grad_output, mask, p) returns the gradient of the loss with respect to x.

In training mode, build the mask with exactly one call:

mask=(rng.random(x.shape)≥p)

True in the mask means kept. Each entry is dropped with probability p. The output is

out=x⋅mask/(1−p)

In inference mode (training=False), return a copy of x and a mask that is True everywhere. Do not draw from rng in inference mode.

The backward pass uses the mask from the forward pass: ∂L/∂x=grad_output⋅mask/(1−p).

Multiply x by the mask. numpy treats True as 1 and False as 0. Then divide by 1 - p, not by p.

Reference solution and notes
import numpy as np


def dropout_forward(x, p, rng, training=True):
    if not training:
        return x.copy(), np.ones(x.shape, dtype=bool)
    mask = rng.random(x.shape) >= p
    return x * mask / (1 - p), mask


def dropout_backward(grad_output, mask, p):
    return grad_output * mask / (1 - p)

Why divide by 1 - p

An entry is kept with probability 1−p. Without the scale, the expected value of the output is (1−p)x. The next layer then sees smaller activations in training than in inference. The division by 1−p makes the expected value x in training mode. Inference mode can then use the plain input.

The older form

The original form of dropout does not scale in training. It multiplies the activations by 1−p at inference time. Both forms give the same expected values. The inverted form puts all the work in training, so inference has no cost.

Why the mask is part of the output

The backward pass must use the same random draw as the forward pass. A layer object keeps the mask as state. A function returns it, as in this problem.

Where this goes next

Transformers use dropout with p=0.1 after attention and after the feed forward block. The model.eval() call in the lesson sets every dropout layer to inference mode. A model that stays in training mode gives a different result on each run.

Check your understanding

Q1What is overfitting in neural networks?

Overfitting occurs when a model achieves high training accuracy but poor test accuracy. It has memorized the training data's noise rather than learning the underlying patterns.

Q2How does dropout regularize a neural network?

During each forward pass, dropout randomly sets neuron outputs to zero with probability p. This prevents co-adaptation (neurons relying on specific others) and is equivalent to training an ensemble of 2^N subnetworks.

Q3Why do transformers use LayerNorm instead of BatchNorm?

BatchNorm depends on batch statistics, which are noisy with small batches and meaningless with batch size 1 (common during generation). LayerNorm normalizes across features within each sample, independent of batch size.

Q4What is the key difference between RMSNorm and LayerNorm?

RMSNorm removes the mean subtraction step from LayerNorm, which contributes little to accuracy but adds computation. LLaMA, Mistral, and most modern LLMs use RMSNorm for this efficiency gain.

Q5Why is it critical to call model.eval() before running inference in PyTorch?

Without model.eval(), dropout randomly zeroes neurons during inference (causing random output variation) and BatchNorm uses current-batch statistics instead of the stable running averages accumulated during training.
