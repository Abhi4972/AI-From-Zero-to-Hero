Why this came about

Writing backward passes by hand (Lesson 3.6) does not scale, so researchers built libraries that compute gradients automatically. Theano (2007) and TensorFlow (2015) asked you to define the whole computation graph first, then run it. PyTorch, released by Facebook's AI research lab in 2016, recorded the graph as ordinary Python code ran, exactly like your Value class, which made it far easier to write and debug. Researchers switched in large numbers, and today almost every open language model, including Llama, Mistral and Qwen, is trained and published with PyTorch. The Hugging Face transformers library you will use in the Transformers, step by step section is built on it.

In plain words first
NumPy with two superpowers

PyTorch's arrays, called tensors, behave almost exactly like NumPy arrays. They add two things. First, autograd: every operation is recorded, so calling .backward() on a result fills in gradients, just like your engine from Lesson 3.6, but for whole arrays and hundreds of operation types. Second, tensors can live on a GPUlater · 3.20, where the same code runs many times faster (Lesson 3.20). On top of that, PyTorch gives you ready-made layers, loss functions and optimizers, so a training loop becomes about ten lines.

Step 1 · Tensors

PyTorch's basic object is the tensor. It is the NumPy array from Lesson 0.14 with two additions that neural networks need: it can live on a graphics card, and it can keep track of gradients (Step 2). Creating and inspecting a tensor looks almost the same as with NumPy:

import numpy as np
import torch

t = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print(t)
print("shape:", t.shape, " dtype:", t.dtype)

print(torch.zeros(2, 3))
print(torch.arange(5))
print(torch.from_numpy(np.array([1.0, 2.0])))     # NumPy -> PyTorch
print(t.numpy())                                 # PyTorch -> NumPy

print(t @ t)                                     # matrix multiplication, as in NumPy
print(t.sum(), t.mean(dim=0))                    # dim=0 averages down the columns (NumPy calls it axis=0)

Reading this output
  • Shapes, indexing, broadcasting and @ work as in NumPy (Lesson 0.14). PyTorch says dim where NumPy says axis.
  • The default type for decimal numbers is float32 (4 bytes per number), half the size of NumPy's default float64. Neural networks rarely need more precision, and Lesson 3.20 goes lower still.
  • torch.from_numpy keeps NumPy's float64. Mixing float64 data with a float32 model gives an error, so convert data with dtype=torch.float32 (Step 4 does).
  • A one-number tensor prints as tensor(10.). Use .item() to get a plain Python number.

Step 2 · Autograd: the engine you already built

Mark the tensors you want gradients for with requires_grad=True. Here is the example from Lesson 3.6 again:

a = torch.tensor(3.0, requires_grad=True)
b = torch.tensor(-2.0, requires_grad=True)
L = (a * b + 4.0) * -3.0
L.backward()

print(L)
print("a.grad =", a.grad, "  b.grad =", b.grad)
What you should see
tensor(6., grad_fn=<MulBackward0>)
a.grad = tensor(6.)   b.grad = tensor(-9.)

The same 6 and −9 as your Value class. grad_fn=<MulBackward0> shows that L remembers the operation that made it, exactly like Value._backward. You will rarely set requires_grad yourself: a model's weights have it switched on automatically.

Step 3 · Layers, models and losses

nn.Linear(in_features, out_features) is the layer of Lesson 3.4: a weight matrix and a bias, created with sensible random starting values.

from torch import nn

torch.manual_seed(0)                              # same random starting weights every run
layer = nn.Linear(3, 2)
print("weight shape:", layer.weight.shape, " bias shape:", layer.bias.shape)
print(layer(torch.tensor([[7.5, 3.0, 1.0]])))     # one example with 3 features -> 2 outputs
What you should see
weight shape: torch.Size([2, 3])  bias shape: torch.Size([2])
tensor([[ 0.4101, -3.2412]], grad_fn=<AddmmBackward0>)

PyTorch stores the weight as (outputs × inputs), the transpose of the W you wrote in Lesson 3.4, and computes x @ W.T + b. You never need to care, except when reading shapes.

A model is a class that inherits from nn.Module. You create its layers in __init__ and say how data flows through them in forward. Here is a digit classifier: 64 pixel values in, a hidden layer of 128 ReLU neurons, 10 scores out (one per digit).

class DigitNet(nn.Module):
    def __init__(self, hidden=128):
        super().__init__()                         # always call this first in an nn.Module
        self.layer1 = nn.Linear(64, hidden)
        self.layer2 = nn.Linear(hidden, 10)

    def forward(self, x):
        h = torch.relu(self.layer1(x))
        return self.layer2(h)                      # raw scores (logits), no softmax

torch.manual_seed(0)
model = DigitNet()
print(model)
print("parameters:", sum(p.numel() for p in model.parameters()))
What you should see
DigitNet(
  (layer1): Linear(in_features=64, out_features=128, bias=True)
  (layer2): Linear(in_features=128, out_features=10, bias=True)
)
parameters: 9610

model(x) calls forward(x) for you. model.parameters() finds every weight and bias inside, which is how the optimizer knows what to update. 64 × 128 + 128 + 128 × 10 + 10 = 9,610.

The model returns logits, not probabilities. That is deliberate: nn.CrossEntropyLoss takes logits and applies softmax and the negative log itself (Lesson 2.6), in a numerically safer combined form:

loss_fn = nn.CrossEntropyLoss()
logits = torch.tensor([[2.0, 0.5, -1.0]])          # scores for 3 classes
target = torch.tensor([0])                         # the true class is 0
print(loss_fn(logits, target))
print(-torch.log_softmax(logits, dim=1)[0, 0])     # the same thing, spelled out: -log p(true class)
What you should see
tensor(0.2413)
tensor(0.2413)
Watch out
Do not apply softmax before CrossEntropyLoss

If your model ends with softmax and you also use CrossEntropyLoss, softmax is applied twice. Training still runs but learns slowly and badly, and nothing raises an error. Return logits from forward; apply softmax only when you want to show probabilities.

Step 4 · Data in mini-batches

The handwritten digits from Lesson 2.16: 1,797 images of 8 × 8 pixels with values from 0 to 16. Divide by 16 to put the pixels between 0 and 1 (feature scaling again, Lesson 2.4), split, and convert to tensors.

from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from torch.utils.data import TensorDataset, DataLoader

digits = load_digits()
X_train, X_val, y_train, y_val = train_test_split(digits.data / 16.0, digits.target, test_size=0.2, random_state=0)
X_train = torch.tensor(X_train, dtype=torch.float32)
X_val = torch.tensor(X_val, dtype=torch.float32)
y_train = torch.tensor(y_train)                    # class labels stay whole numbers (int64)
y_val = torch.tensor(y_val)
print(X_train.shape, y_train.shape, X_train.dtype, y_train.dtype)

loader = DataLoader(TensorDataset(X_train, y_train), batch_size=64, shuffle=True,
                    generator=torch.Generator().manual_seed(0))
xb, yb = next(iter(loader))                        # look at the first mini-batch
print("one batch:", xb.shape, " first labels:", yb[:10])
What you should see
torch.Size([1437, 64]) torch.Size([1437]) torch.float32 torch.int64
one batch: torch.Size([64, 64])  first labels: tensor([7, 1, 9, 0, 2, 6, 9, 9, 7, 6])

A DataLoader serves the training data in shuffled mini-batches of 64 examples. Each training step uses one batch: computing the gradient on 64 examples is much cheaper than on all 1,437, and the noise from random batches even helps training find good solutions. This is the stochastic gradient descent of Lesson 1.7. One pass through all the batches (23 of them here) is an epoch.

Step 5 · The training loop

Now the pieces meet. A training loop repeats four actions for every batch of data: run the model forward to get predictions, measure the loss, call backward() to compute gradients, and let the optimiser nudge the weights. One pass over all the training data is an epoch. After each epoch this loop also measures the loss on validation data the model never trains on, and keeps a copy of the weights from the best epoch.

import copy

torch.manual_seed(0)
model = DigitNet()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)    # Adam with weight decay; Lesson F4.4 explains it

best_loss, best_epoch, best_state = float("inf"), 0, None
for epoch in range(1, 31):
    model.train()                                  # training mode (matters for dropout, Lesson F4.4)
    for xb, yb in loader:
        logits = model(xb)                         # 1. forward
        loss = loss_fn(logits, yb)                 # 2. loss
        optimizer.zero_grad()                      # 3. reset old gradients
        loss.backward()                            # 4. backward: fill .grad for every parameter
        optimizer.step()                           # 5. update the parameters

    model.eval()                                   # evaluation mode
    with torch.no_grad():                          # no graph needed: faster, less memory
        val_logits = model(X_val)
        val_loss = loss_fn(val_logits, y_val).item()
        val_acc = (val_logits.argmax(dim=1) == y_val).float().mean().item()
    if val_loss < best_loss:                       # remember the best model so far
        best_loss, best_epoch, best_state = val_loss, epoch, copy.deepcopy(model.state_dict())
    if epoch in (1, 5, 10, 20, 30):
        print(f"epoch {epoch:>2}  validation loss {val_loss:.4f}  accuracy {val_acc:.3f}")

print(f"best validation loss {best_loss:.4f} at epoch {best_epoch}")
What you should see
epoch  1  validation loss 2.0229  accuracy 0.603
epoch  5  validation loss 0.6547  accuracy 0.897
epoch 10  validation loss 0.2999  accuracy 0.933
epoch 20  validation loss 0.1632  accuracy 0.961
epoch 30  validation loss 0.1301  accuracy 0.969

Reading this output
Reading this code
  • The five numbered lines are the five steps of your Value training loop in Lesson 3.6. optimizer.step() does p -= lr * p.grad for every parameter (plus Adam's refinements); optimizer.zero_grad() is your p.grad = 0.0.
  • model.train() and model.eval() switch layers that behave differently during training, such as dropoutlater · 3.12 (Lesson 3.12). Forgetting eval() gives noisy, wrong validation numbers for such models.
  • torch.no_grad() tells PyTorch not to record a graph, because you will not call backward() on validation results.
  • argmax(dim=1) picks the highest-scoring class for each image. Comparing with the labels gives True/False; .float().mean() turns that into accuracy.
  • state_dict() is a dictionary of every parameter tensor. copy.deepcopy stores a real copy; without it you would keep a reference that changes as training continues. Keeping the best validation checkpoint is early stopping in its simplest form (Lesson 2.16). Here validation loss was still improving at epoch 30, so the last epoch is also the best.

Step 6 · Save, load and use the model

A trained model is only its weights: a set of named tensors called the state dict. Saving the model means writing those to a file; loading means creating a fresh model of the same shape and copying them in. The code saves the best weights, restores them into a new model, checks that the two give identical predictions, and then uses the restored model on new images.

model.load_state_dict(best_state)
torch.save(model.state_dict(), "digits_net.pt")         # save the weights to a file

restored = DigitNet()                                   # a fresh model with random weights...
restored.load_state_dict(torch.load("digits_net.pt"))   # ...now holding the trained ones
restored.eval()
with torch.no_grad():
    print("same predictions:", torch.equal(restored(X_val), model(X_val)))

i = 5                                                   # look at one validation image
for row in X_val[i].reshape(8, 8):
    print("".join(" .:-=+*#%@"[int(v * 9)] * 2 for v in row))   # darker pixel -> denser character
with torch.no_grad():
    probs = torch.softmax(restored(X_val[i:i + 1]), dim=1)[0]
top = torch.topk(probs, 3)
print("top guesses:", [(int(k), round(float(p), 3)) for p, k in zip(top.values, top.indices)], " true label:", int(y_val[i]))

Model files you download later (the From language model to assistant section) work the same way: a configuration that describes the architecture, plus a file of weights, nowadays usually in the safer safetensors format.

Step 7 · Running on a GPU

If a GPU is available, move the model and each batch to it. Everything else stays the same:

device = "cuda" if torch.cuda.is_available() else "cpu"     # "mps" on Apple silicon Macs
model = DigitNet().to(device)
for xb, yb in loader:
    xb, yb = xb.to(device), yb.to(device)                   # data must be on the same device as the model
    ...

For this tiny model a CPU is fine. For the transformerlater · 7.8 you will train in Lesson 7.22, a CPU still works (slowly); for anything larger, a GPU makes the difference between minutes and days (Lesson 3.20). Free notebook services such as Google Colab provide one (Lesson 0.1).

Step 8 · The usual bugs

Symptom Likely cause Fix
Loss does not go down at all forgot optimizer.step(), or the optimizer was given the wrong parameters check the five lines of the loop
Loss falls, then jumps around or explodes forgot zero_grad() (gradients pile up), or learning rate too high reset gradients each step; lower the learning rate
Learns, but slowly and badly softmax before CrossEntropyLoss; unscaled inputs return logits; scale features
RuntimeError: mat1 and mat2 shapes cannot be multiplied layer sizes do not match the data print x.shape before each layer
expected scalar type Float but found Double data is float64 create tensors with dtype=torch.float32
Validation accuracy varies strangely between runs forgot model.eval() with dropout or batch norm call eval() before evaluating, train() after
Expected all tensors to be on the same device model on GPU, data on CPU (or the reverse) .to(device) for both

A useful habit from Andrej Karpathy's "recipe for training neural networks": before training on everything, check the model can overfit a single small batch (drive the loss near zero on, say, 10 examples). If it cannot, there is a bug, and more data will not fix it.

The same idea as a formula
  • mini-batch gradient: g = (1/|B|) Σ over examples in batch B of ∇ℓ(xᵢ, yᵢ; w)
  • update (plain SGD): w ← w − η g
  • nn.Linear: y = x Wᵀ + b, with W of shape (out, in)
  • CrossEntropyLoss(logits, k) = −log softmax(logits)ₖ
Check your mental model
  • ✗ "PyTorch is a different kind of maths from what I built by hand."
    ✓ It is the same forward pass, the same chain rule and the same update, done for whole tensors in fast compiled code.
  • ✗ "torch.no_grad() makes the model more accurate."
    ✓ It only skips recording the graph, saving time and memory. The predictions are identical.
  • ✗ "One epoch means one training step."
    ✓ One step uses one mini-batch; an epoch is one pass over all the batches (23 steps here).

Exercises

Predict before you run

If you change batch_size=64 to batch_size=1437 (the whole training set in one batch) and keep 30 epochs, will the model end better or worse than before, and why? (Solution P1.)

Make it your own

Add a second hidden layer of 64 neurons to DigitNet and train again. Count the parameters by hand first. Does validation accuracy improve? (Solution M1.)

Debugging exercise

A colleague's validation accuracy is stuck at about 10% (chance for 10 classes) while the training loss falls normally. Their evaluation code is acc = (model(X_val).argmax(dim=0) == y_val).float().mean(). What is wrong? (Solution D1.)

Solutions

SolutionP1 · One big batch

Worse after 30 epochs: about 78% instead of 97%. With one batch per epoch the model takes only 30 update steps in total, instead of 30 × 23 = 690. Each step uses a more exact gradient, but far fewer steps are taken. Mini-batches give many cheap, slightly noisy steps, which is usually a much better deal. With far more epochs (or a larger learning rate), the full-batch model would catch up.

SolutionM1 · A deeper network

Parameters: 64 × 128 + 128 + 128 × 64 + 64 + 64 × 10 + 10 = 8,320 + 8,256 + 650 = 17,226 (the same count as the digit classifier in Lesson 3.4). In __init__, add self.layer3 = nn.Linear(64, 10), change layer2 to nn.Linear(hidden, 64), and in forward apply ReLU after layer2. On this small, easy dataset the gain is small: validation accuracy goes from 96.9% to about 97.2%, a difference of one image out of 360. One hidden layer is already nearly enough; depth pays off on harder problems.

SolutionD1 · argmax along the wrong dimension

model(X_val) has shape (360, 10): one row per image, one column per class. argmax(dim=0) finds, for each class, which image has the highest score, giving 10 numbers that are compared with the labels by broadcasting accident. It should be argmax(dim=1): for each image, the highest-scoring class. When results look like chance, print the shapes.

Recap
  • Tensors are NumPy-like arrays that can record operations for autograd and live on a GPU; decimal tensors default to float32later · 3.20.
  • loss.backward() fills .grad for every parameter, exactly as the engine of Lesson 3.6 did.
  • A model is an nn.Module with layers in __init__ and the data flow in forward; it returns logits, and CrossEntropyLoss applies softmax and the log itself.
  • The training loop for each mini-batch: forward, loss, zero_grad, backward, step; after each epoch evaluate with eval() and no_grad(), and keep the best checkpoint.
  • Save weights with state_dict(); the architecture comes from your code or a configuration file.

Check your understanding

Q1What does optimizer.zero_grad() do?

Gradients accumulate with each backward() call, so they are reset every step.

Q2Your model ends with softmax and you train with nn.CrossEntropyLoss. What happens?

CrossEntropyLoss expects raw logits and applies log-softmax itself.

Q3With 1,437 training examples and batch_size=64, how many optimizer steps happen in one epoch?

1,437 / 64 = 22.5, rounded up because the last, smaller batch also counts.
