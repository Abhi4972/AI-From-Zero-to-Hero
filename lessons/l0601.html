Why this came about

By 2024, every team building agents was rewriting the same plumbing: loops, tool handling, state, persistence, streaming and approvals. Frameworks appeared to package it, and many competed. Knowing what you built by hand in Chapters 2 and 3 lets you judge what a framework actually saves you.

In plain words first
Hand tools first, then power tools

A framework packages the code every agent needs: the loop, tool plumbing, state, persistence, streaming, approvals, tracing. You wrote much of that by hand in Chapters 2 and 3, so you know what each piece does. A framework saves that work and adds tested features, at the cost of learning its abstractions and depending on its choices. Use one when its features match what you need; write plain code when they do not.

Four kinds of thing, all called "agent frameworks"

Vendors use the word "framework" for products that solve different problems. Sorting them first saves weeks of confused comparisons.

Category What it gives you Examples

The categories stack. A typical enterprise build is: an agent framework or harness for the agent logic, a runtime underneath when the process must be durable, and a managed platform (or your own Kubernetes) to host it. LangChainlater · 14.71's documentation uses the same three-way split of runtimes, frameworks and harnesses.

Do you need a framework at all?

Often not at first. Anthropic's Building effective agents advises starting with direct model API calls, because many patterns are a few lines of code, and frameworks can hide the prompts and responses you need to see when debugging. You built a complete agent in about 80 lines in Lesson 14.57.

Reach for a framework when you need what it does well and would otherwise rebuild: durable state, approval pauses, streaming to a UI, multi-agent routing, tracing, or integration with a cloud's managed services.

Industry practice
What the adoption data says

Datadog's State of AI Engineering report (April 2026) found that the share of organizations using an agent framework roughly doubled in a year, from about 9% to 18%, with LangChain, LangGraph, Pydantic AI and the Vercel AI SDK named most often. The same report warns that frameworks add operational complexity, and recommends using agent telemetry to find framework logic that a simpler custom workflow could replace. Two lessons: most teams still build without a framework, and the ones that adopt one should measure what it costs them.

In plain words first
The two names you will see most in this chapter

LangChain is an open-source library of building blocks for applications that use language models: one interface to many model providers, prompt templateslater · 14.72, tools, structured output and a ready-made agent loop. Lessons 14.71 to 14.77 teach it.

LangGraph is a second library from the same company, one level lower. It runs an agent as a graph: steps (nodes) connected by arrows (edges), with the state saved after every step so that a run can pause for a person, survive a crash and resume. LangChain's agent loop is itself built on LangGraph. Lessons 14.79 to 14.90 teach it.

You do not need either to build an agent, as Chapter 3 showed. They are taught in depth here because they are the most widely used, and because every idea in them (the loop, tools, state, checkpoints, approvals, streaming) is one you have already built by hand.

The lab rig: a scripted model server

To compare frameworks fairly and offline, every module in this part runs the same task, ShopKart order support, against the same "model": a small server that speaks the OpenAI-compatible Chat Completions API and answers with a few fixed rules. Almost every framework can talk to an OpenAI-compatible endpoint, so one server serves them all. Swapping in a real model is a one-line change, shown in each module.

Save this as mockllm.py in your project folder. It uses only the Python standard library.

# mockllm.py · A scripted, OpenAI-compatible model server for offline agent labs.
# It speaks the Chat Completions API (plain and streaming), so any framework that can
# talk to "an OpenAI-compatible endpoint" can run against it with no key and no cost.
import json, re, threading, time, uuid
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

ORDER_ID = re.compile(r"\b[A-Z]-\d{4}\b")


def _text(content) -> str:
    """Message content may be a string or a list of parts; return plain text."""
    if isinstance(content, str):
        return content
    return " ".join(p.get("text", "") for p in content or [] if isinstance(p, dict))


def _fill(schema: dict, hint: str):
    """Build a value that matches a JSON schema (enough for structured-output demos)."""
    t = schema.get("type")
    if "enum" in schema:
        return next((e for e in schema["enum"] if str(e).lower() in hint.lower()), schema["enum"][0])
    if "anyOf" in schema:
        return _fill(next(s for s in schema["anyOf"] if s.get("type") != "null"), hint)
    if t == "object":
        return {k: _fill(v, hint) for k, v in schema.get("properties", {}).items()}
    if t == "array":
        return [_fill(schema.get("items", {}), hint)]
    if t == "integer":
        return 3
    if t == "number":
        return 3.0
    if t == "boolean":
        return False
    return hint[:200]


def decide(messages: list, tools: list) -> dict:
    """The 'model': a few deterministic rules that imitate a tool-calling LLM."""
    names = {t["function"]["name"]: t["function"] for t in tools or [] if t.get("type") == "function"}
    last = messages[-1]
    tool_results = []
    for m in reversed(messages):                      # tool results since the last assistant turn
        if m["role"] != "tool":
            break
        result = _text(m.get("content"))
        try:                                          # some frameworks wrap results as {"result": ...}
            parsed = json.loads(result)
            if isinstance(parsed, dict) and len(parsed) == 1:
                result = str(next(iter(parsed.values())))
        except ValueError:
            pass
        tool_results.insert(0, result)
    if last["role"] == "user" and _text(last["content"]).startswith("Observation:"):   # smolagents style
        tool_results = [_text(last["content"])[len("Observation:"):].strip()]
        last = {"role": "tool"}
    user = next((_text(m["content"]) for m in reversed(messages)
                 if m["role"] == "user" and not _text(m["content"]).startswith("Observation:")), "")
    ids = ORDER_ID.findall(user)
    if "(Yes or No)" in user:                         # guardrail classifiers that ask "should this be blocked?"
        quoted = re.search(r'message[^"]*"(.*?)"', user, re.S)
        target = (quoted.group(1) if quoted else user).lower()
        risky = any(w in target for w in ("ignore previous", "ignore all", "system prompt", "other customer"))
        return {"text": "Yes" if risky else "No"}
    if last["role"] == "tool":
        asked = next((m for m in reversed(messages) if m["role"] == "assistant" and m.get("tool_calls")), {})
        called = [c["function"]["name"] for c in asked.get("tool_calls", [])]
        if called and called[0].startswith("transfer_to_"):          # just received a handoff
            return {"text": f"You are now with the {called[0][12:]} desk. How can I help?"}
        summary = "; ".join(tool_results)
        if "final_answer" in names:                   # frameworks that end a run through a final_answer tool
            return {"tool_calls": [("final_answer", {"answer": f"Here is what I found: {summary}"})]}
        if "final_result" in names:                   # frameworks that collect structured output via a tool
            args = _fill(names["final_result"].get("parameters", {}), summary + " " + user)
            return {"tool_calls": [("final_result", args)]}
        return {"text": f"Here is what I found: {summary}"}
    if "cancel" in user.lower() and "cancel_order" in names and ids:
        return {"tool_calls": [("cancel_order", {"order_id": ids[0]})]}
    if ids and "get_order_status" in names:           # one call per order ID, in parallel
        return {"tool_calls": [("get_order_status", {"order_id": i}) for i in ids]}
    handoff = next((n for n in names if n.startswith("transfer_to_") and n.split("_")[-1] in user.lower()), None)
    if handoff:
        return {"tool_calls": [(handoff, {})]}
    if "final_result" in names:
        return {"tool_calls": [("final_result", _fill(names["final_result"].get("parameters", {}), user))]}
    return {"text": "I can check order status and cancel orders. Please share your order ID, like A-1002."}


class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args):                     # keep the console quiet
        pass

    def do_GET(self):                                 # /v1/models, for clients that list models
        self._json({"object": "list", "data": [{"id": "mock-model", "object": "model"}]})

    def do_POST(self):
        body = json.loads(self.rfile.read(int(self.headers.get("Content-Length", 0))) or b"{}")
        out = decide(body.get("messages", []), body.get("tools", []))
        rf = body.get("response_format") or {}
        if "text" in out and rf.get("type") == "json_schema":     # structured output via response_format
            out["text"] = json.dumps(_fill(rf["json_schema"]["schema"], _text(body["messages"][-1]["content"])))
        forced = body.get("tool_choice")                          # the caller insists on a tool call
        if "text" in out and body.get("tools") and (forced == "required" or isinstance(forced, dict)):
            fn = next((t["function"] for t in body["tools"] if not isinstance(forced, dict)
                       or t["function"]["name"] == forced.get("function", {}).get("name")), body["tools"][0]["function"])
            user = " ".join(_text(m["content"]) for m in body["messages"] if m["role"] == "user")
            out = {"tool_calls": [(fn["name"], _fill(fn.get("parameters", {}), user))]}
        calls = [{"id": f"call_{uuid.uuid4().hex[:8]}", "type": "function",
                  "function": {"name": n, "arguments": json.dumps(a)}} for n, a in out.get("tool_calls", [])]
        usage = {"prompt_tokens": 50, "completion_tokens": 20, "total_tokens": 70}
        meta = {"id": f"chatcmpl-{uuid.uuid4().hex[:8]}", "created": int(time.time()), "model": body.get("model", "mock-model")}
        finish = "tool_calls" if calls else "stop"
        if not body.get("stream"):
            msg = {"role": "assistant", "content": out.get("text")}
            if calls:
                msg["tool_calls"] = calls
            return self._json({**meta, "object": "chat.completion", "usage": usage,
                               "choices": [{"index": 0, "message": msg, "finish_reason": finish}]})
        self.send_response(200)
        self.send_header("Content-Type", "text/event-stream")
        self.end_headers()
        def send(delta, reason=None, **extra):
            chunk = {**meta, "object": "chat.completion.chunk",
                     "choices": [{"index": 0, "delta": delta, "finish_reason": reason}], **extra}
            self.wfile.write(f"data: {json.dumps(chunk)}\n\n".encode())
        send({"role": "assistant", "content": ""})
        for word in (out.get("text") or "").split(" "):
            if word:
                send({"content": word + " "})
        for i, c in enumerate(calls):
            send({"tool_calls": [{"index": i, **c}]})
        send({}, finish)
        if (body.get("stream_options") or {}).get("include_usage"):
            self.wfile.write(f"data: {json.dumps({**meta, 'object': 'chat.completion.chunk', 'choices': [], 'usage': usage})}\n\n".encode())
        self.wfile.write(b"data: [DONE]\n\n")

    def _json(self, obj):
        data = json.dumps(obj).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)


def start(port: int = 0) -> str:
    """Start the server in a background thread (port 0 = any free port); return its base URL."""
    server = ThreadingHTTPServer(("127.0.0.1", port), Handler)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    return f"http://127.0.0.1:{server.server_address[1]}/v1"


if __name__ == "__main__":
    print("Mock model server at", start())
    threading.Event().wait()

from openai import OpenAI
from mockllm import start

client = OpenAI(base_url=start(), api_key="mock")                 # any key works
tools = [{"type": "function", "function": {"name": "get_order_status",
          "parameters": {"type": "object", "properties": {"order_id": {"type": "string"}}}}}]
r = client.chat.completions.create(model="mock-model", tools=tools,
                                   messages=[{"role": "user", "content": "Where are A-1001 and A-1002?"}])
print([(c.function.name, c.function.arguments) for c in r.choices[0].message.tool_calls])
What you should see
[('get_order_status', '{"order_id": "A-1001"}'), ('get_order_status', '{"order_id": "A-1002"}')]

Two parallel tool calls, exactly as a real model would return them. The rules are crude on purpose: the point is to exercise each framework's plumbing (tool calling, approvals, sessions, handoffs, structured output) without a key, a bill or randomness. It also answers the yes-or-no checks that guardraillater · 15.23 frameworks send (Lesson 15.23).

Industry practice
Test agents against a scripted model

Scripted or recorded models are standard practice for agent unit tests: they make tests fast, free and repeatable, and they let you trigger rare paths (a tool error, a handoff, a refusal) on demand. Real-model evals (Lesson 14.118) still decide quality. Keep both: scripted tests for the plumbing, evals for the behavior.

Solutions

SolutionP1 · Often no

Plain code or LCELlater · 14.72 (Lesson 14.72) is enough. Frameworks pay off with tool loops, state, approvals, streaming and multi-agent structure.

SolutionB1 · Framework sprawl

Three sets of abstractions, upgrades and debugging tools, with glue code between them. Choose one runtime and use others only through clear interfaces.

SolutionD1 · Pin and test

Pinned versions, wiring tests with fake models (Lesson 14.77) and evals that run on upgrades.

SolutionM1 · A decision process

Requirements (approvals, durability, streaming, providers), two or three candidates, a spike implementing the hardest path, and criteria including team familiarity and operations.

Check your understanding

Explain the mechanismWhat kinds of things are called agent frameworks?

Worked answer. Runtimes (durable executionlater · 14.115 of multi-step work, such as LangGraph), agent frameworks (abstractions for agents, tools and multi-agent patterns), harnesses (ready-made agents with tools and context management, such as the Claude Agent SDK), and managed platforms (hosting, identity, memory and observability). They solve different problems and can be combined.

A plausible wrong answer. "They are all the same." They operate at different layers.

Follow-ups. Which layer does your use case need?

Debug a failureAn agent built with a framework is hard to debug. What do you do?

Worked answer. Turn on its tracing, read the exact messages sent to the model, reproduce with a fake model, and remove abstractions in the failing path if needed.

A plausible wrong answer. "Drop the framework." First, use its debugging tools.

Follow-ups. What would you need to see in a trace?

Defend a designFramework or no framework?

Worked answer. No framework for simple, fixed pipelines; a framework when you need tool loops, state, approvals, streaming or multi-agent structure, because those are costly to build well. Keep business logic in plain functions so the framework stays replaceable.

A plausible wrong answer. "Frameworks are always bloat." Durable approvals and streaming are not trivial.

Follow-ups. What would make you switch frameworks?
