In plain words first
The idea in one line

Attention is a lookup table where every word asks "who matters to me?" - and learns the answer.

Terms you'll hear
Term What people say What it actually means
Query (Q) "The question vector" A learned projection of the input that represents what information this token is looking for
Key (K) "The label vector" A learned projection that represents what information this token contains, matched against queries
Value (V) "The content vector" A learned projection carrying the actual information that gets aggregated based on attention scores
Scaled dot-product attention "The attention formula" $\mathop{\mathrm{softmax}}(QK^T / \sqrt{d_k}) V$ - scaling prevents softmax saturation in high dimensions
Self-attention "The token looks at itself and others" Attention where Q, K, V all come from the same sequence, letting every position attend to every other position
Attention weights "How much focus" A probability distribution over positions, produced by softmax over scaled dot products
Multi-head attention "Parallel attention" Running multiple attention functions with different projections, then concatenating results for richer representations

The problem

In plain words first

Self-attention lets every word in a sentence build its new meaning from the other words. Each word makes three vectors from its embedding with three learned matrices: a query (what it is looking for), a key (how it describes itself to others) and a value (what it passes on if chosen). A word's query is compared with every key by a dot product, the scores become weights that add up to 1, and the word's output is the weighted average of the values. In a language model that writes left to right, a causal mask stops each word from looking at words that come after it. This lesson builds that from NumPy, then checks it against a real model: it rebuilds the attention weights of GPT-2's first layer from GPT-2's own weights with the lesson's functions, looks at what GPT-2's 144 heads actually attend to, and compares the code with PyTorch's fused attention kernel. Nothing is trained.

RNNs process sequences one token at a time. By the time you reach token 50, the information from token 1 has been squeezed through 50 compression steps. Long-range dependencies get crushed into a fixed-size hidden state - a bottleneck that no amount of LSTM gating fully solves.

The 2014 Bahdanau attention paper showed the fix: let the decoder look back at every encoder position and decide which ones matter for the current step. But it was still bolted onto an RNN. The 2017 "Attention Is All You Need" paper asked a sharper question: what if attention is the only mechanism? No recurrence. No convolution. Just attention.

Self-attention lets every position in a sequence attend to every other position in a single parallel step. That is what makes transformers fast, scalable, and dominant.

Idea 1 · The Database Lookup Analogy

Think of attention as a soft database lookup:

Traditional database:
  Query: "capital of France"  -->  exact match  -->  "Paris"

Attention:
  Query: "capital of France"  -->  similarity to ALL keys  -->  weighted blend of ALL values

Every token generates three vectors: - Query (Q): "What am I looking for?" - Key (K): "What do I contain?" - Value (V): "What information do I provide if selected?"

The dot product between a query and all keys produces attention scores. High score means "this key matches my query." Those scores weight the values. The output is a weighted sum of values.

Idea 2 · Q, K, V Computation

Each token embedding gets projected through three learned weight matrices:

Input embeddings (sequence of n tokens, each d-dimensional):

  X = [x1, x2, x3, ..., xn]       shape: (n, d)

Three weight matrices:

  Wq  shape: (d, dk)
  Wk  shape: (d, dk)
  Wv  shape: (d, dv)

Projections:

  Q = X @ Wq    shape: (n, dk)      each token's query
  K = X @ Wk    shape: (n, dk)      each token's key
  V = X @ Wv    shape: (n, dv)      each token's value

Visually, for one token:

             Wq
  x_i ------[*]------> q_i    "What am I looking for?"
       |
       |     Wk
       +----[*]------> k_i    "What do I contain?"
       |
       |     Wv
       +----[*]------> v_i    "What do I offer?"

Idea 3 · The Attention Matrix

Once you have Q, K, V for all tokens, attention scores form a matrix:

Scores = Q @ K^T    shape: (n, n)

              k1    k2    k3    k4    k5
        +-----+-----+-----+-----+-----+
   q1   | 2.1 | 0.3 | 0.1 | 0.8 | 0.2 |   <- how much q1 attends to each key
        +-----+-----+-----+-----+-----+
   q2   | 0.4 | 1.9 | 0.7 | 0.1 | 0.3 |
        +-----+-----+-----+-----+-----+
   q3   | 0.2 | 0.6 | 2.3 | 0.5 | 0.1 |
        +-----+-----+-----+-----+-----+
   q4   | 0.9 | 0.1 | 0.4 | 1.7 | 0.6 |
        +-----+-----+-----+-----+-----+
   q5   | 0.1 | 0.3 | 0.2 | 0.5 | 2.0 |
        +-----+-----+-----+-----+-----+

Each row: one token's attention over the entire sequence

Watch one query at a time sweep the keys: each row scores every token, softmax turns the scores into weights, and the context vector is the weighted blend of values.

Idea 4 · Why Scale?

The dot products grow with dimension dk​. If dk​=64, dot products can be in the range of tens, pushing softmax into regions where gradients vanish. The fix: divide by dk​​.

Scaled scores=dk​​QKT​

This keeps values in a range where softmax produces useful gradients.

Idea 5 · Softmax Turns Scores into Weights

Softmax converts raw scores into a probability distribution across each row:

Raw scores for q1:   [2.1, 0.3, 0.1, 0.8, 0.2]
                            |
                         softmax
                            |
Attention weights:   [0.580, 0.096, 0.079, 0.158, 0.087]   (sums to 1.0)

Now each token has a set of weights saying how much to attend to every other token.

Idea 6 · Weighted Sum of Values

The final output for each token is a weighted sum of all value vectors:

output_i = sum( attention_weight[i][j] * v_j  for all j )

For token 1:
  output_1 = 0.580 * v1 + 0.096 * v2 + 0.079 * v3 + 0.158 * v4 + 0.087 * v5

Idea 7 · Full Pipeline

Formula in one line:

Attention(Q,K,V)=softmax(dk​​QKT​)V

The same idea as a formula

For n tokens with embeddings stacked as rows of X∈Rn×d and learned WQ​,WK​∈Rd×dk​, WV​∈Rd×dv​:

Q=XWQ​,K=XWK​,V=XWV​,A=softmax(dk​​QK⊤​+M),out=AV

Softmax runs along each row, so row i of A is a probability distribution over positions and outi​=∑j​Aij​vj​.

The causal mask. For a left-to-right model, Mij​=0 if j≤i and −∞ if j>i. Since e−∞=0, token i gives zero weight to every later token, and A is lower-triangular.

Why divide by dk​​. If the entries of q and k are independent with mean 0 and variance 1, then q⋅k has variance dk​; dividing by dk​​ brings it back to 1, so softmax is not pushed into a near one-hot regime where its gradient vanishes (Lesson 5.10 measures this).

Shapes and cost. QK⊤ is n×n: O(n2dk​) time and O(n2) memory per head; the projections cost O(nddk​).

Multi-head. With h heads of size dk​=d/h, each head has its own WQ​,WK​,WV​; outputs are concatenated and multiplied by WO​ (Lesson 7.3). GPT-2 small: d=768, h=12, dk​=64.

Worked example
One row of attention by hand

Three tokens, dk​=2. Query of token 1: q1​=(1,0). Keys: k1​=(1,0), k2​=(0,1), k3​=(2,0). Values: v1​=(1,0), v2​=(0,1), v3​=(1,1).

  • Scores: q1​⋅kj​=(1,0,2), scaled by 1/2​: (0.707,0,1.414).
  • Softmax: e0.707=2.03, e0=1, e1.414=4.11; sum 7.14; weights (0.284,0.140,0.576).
  • Output: 0.284(1,0)+0.140(0,1)+0.576(1,1)=(0.860,0.716).
  • With a causal mask, token 1 can only see itself: weights (1,0,0) and output v1​=(1,0).

Step 1 · Softmax from scratch

Softmax converts raw logits into probabilities. Subtract the max for numerical stability.

import numpy as np

def softmax(x):
    shifted = x - np.max(x, axis=-1, keepdims=True)
    exp_x = np.exp(shifted)
    return exp_x / np.sum(exp_x, axis=-1, keepdims=True)

logits = np.array([2.0, 1.0, 0.1])
print(f"logits:  {logits}")
print(f"softmax: {softmax(logits)}")
print(f"sum:     {softmax(logits).sum():.4f}")

Step 2 · Scaled dot-product attention

The core function. Takes Q, K, V matrices and returns the attention output plus the weight matrix.

def scaled_dot_product_attention(Q, K, V):
    dk = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(dk)
    weights = softmax(scores)
    output = weights @ V
    return output, weights

Step 3 · Self-attention class with learned projections

A full self-attention module with Wq, Wk, Wv weight matrices initialized with Xavier-like scaling.

class SelfAttention:
    def __init__(self, d_model, dk, dv, seed=42):
        rng = np.random.default_rng(seed)
        scale = np.sqrt(2.0 / (d_model + dk))
        self.Wq = rng.normal(0, scale, (d_model, dk))
        self.Wk = rng.normal(0, scale, (d_model, dk))
        scale_v = np.sqrt(2.0 / (d_model + dv))
        self.Wv = rng.normal(0, scale_v, (d_model, dv))
        self.dk = dk

    def forward(self, X):
        Q = X @ self.Wq
        K = X @ self.Wk
        V = X @ self.Wv
        output, weights = scaled_dot_product_attention(Q, K, V)
        return output, weights

Use it: the same idea with real libraries

PyTorch's nn.MultiheadAttention does exactly what we built, plus multi-head splitting and output projection:

This lesson's code, inside GPT-2

GPT-2 small reads a sentence and reports its own attention weights. Then layer 0's weights for all 12 heads are rebuilt from GPT-2's weight matrix with the softmax from Step 1 and a causal mask.

import torch
from transformers import GPT2Tokenizer, GPT2Model

# GPT-2 small (124M parameters, 12 layers x 12 heads, width 768): load it and ask for its attention weights.
tok = GPT2Tokenizer.from_pretrained("openai-community/gpt2")
gpt2 = GPT2Model.from_pretrained("openai-community/gpt2", attn_implementation="eager").eval()
text = "The cat sat on the mat because it was tired, and then the cat fell asleep on the mat."
ids = tok(text, return_tensors="pt").input_ids
tokens = [tok.decode(i) for i in ids[0]]
with torch.no_grad():
    out = gpt2(ids, output_attentions=True, output_hidden_states=True)
n = ids.shape[1]
print(f"{n} tokens: {tokens[:8]} ...")

# Rebuild layer 0's attention with this lesson's own NumPy functions, from GPT-2's weights.
blk = gpt2.h[0]
with torch.no_grad():
    x = blk.ln_1(out.hidden_states[0])[0].numpy()                     # layer input after its LayerNorm
W, b = blk.attn.c_attn.weight.detach().numpy(), blk.attn.c_attn.bias.detach().numpy()   # (768, 2304): Wq | Wk | Wv
Q, K, V = np.split(x @ W + b, 3, axis=-1)
H, dh = 12, 64
causal = np.triu(np.full((n, n), -np.inf), k=1)                    # a token may not look at later tokens
max_err = 0.0
for h in range(H):
    sl = slice(h * dh, (h + 1) * dh)
    scores = Q[:, sl] @ K[:, sl].T / np.sqrt(dh) + causal
    w = softmax(scores)
    max_err = max(max_err, np.abs(w - out.attentions[0][0, h].numpy()).max())
print(f"layer 0, all 12 heads: largest difference between our weights and GPT-2's own: {max_err:.1e}")
_, w_nomask = scaled_dot_product_attention(Q[:, :dh], K[:, :dh], V[:, :dh])
print(f"without the causal mask, head 0 would put {w_nomask[0, 1:].sum():.0%} of the first token's attention on later tokens")

The same function, as production code calls it

This lesson's NumPy attention (8 causal heads, 1,024 tokens, head size 64) against torch.nn.functional.scaled_dot_product_attention, the fused kernel that PyTorch models call.

import time, torch, numpy as np
import torch.nn.functional as F
torch.manual_seed(0); torch.set_num_threads(2)
# Our NumPy attention against PyTorch's fused kernel (the call production code uses), causal, 8 heads.
H, N, dh = 8, 1024, 64
q, k, v = (torch.randn(1, H, N, dh) for _ in range(3))
mask = np.triu(np.full((N, N), -np.inf), k=1)
def ours():
    outs = []
    for h in range(H):
        Qh, Kh, Vh = q[0, h].numpy(), k[0, h].numpy(), v[0, h].numpy()
        w = softmax(Qh @ Kh.T / np.sqrt(dh) + mask)
        outs.append(w @ Vh)
    return np.stack(outs)
def fused():
    return F.scaled_dot_product_attention(q, k, v, is_causal=True)[0].numpy()
def best(f, reps=3):
    ts = []
    for _ in range(reps):
        t0 = time.perf_counter(); f(); ts.append(time.perf_counter() - t0)
    return min(ts)
t_ours, t_fused = best(ours), best(fused)
print(f"largest difference: {np.abs(ours() - fused()).max():.1e}")
print(f"NumPy, one head at a time: {1000 * t_ours:.1f} ms;  F.scaled_dot_product_attention: {1000 * t_fused:.1f} ms "
      f"({t_ours / t_fused:.1f}x)")
print(f"memory the NumPy version materialises: {H} x {N} x {N} scores = {H * N * N * 4 / 2**20:.0f} MiB in fp32")

The NumPy version and PyTorch's fused kernel agree to within 5×10−7. The fused call is about 15 times faster here and never stores the 32 MiB of scores that the NumPy version builds; on a GPU the same call dispatches to FlashAttention (Lesson 7.12).

Break it on purpose

Drop the causal mask when you rebuild GPT-2's layer 0 and compare the weights with GPT-2's again. The first run already shows one symptom: head 0 would put 80% of the first token's attention on later tokens. What goes wrong if a language model is trained without the mask, and why does its training loss look excellent? (Solution B1.)

Industry practice
What's current (2024–2026)
  • One function call in production. PyTorch's scaled_dot_product_attention dispatches to FlashAttention or memory-efficient kernels, and Hugging Face models select it by default (attn_implementation="sdpa"); serving engines (vLLM, SGLang, TensorRT-LLM) use FlashAttention and FlashInfer kernels with paged KV caches.
  • Custom masks without custom kernels. PyTorch's FlexAttention (2024) compiles mask and score modifications (sliding windows, document masks for packed sequences, ALiBi) into fused kernels, which training stacks use for packed pretraining batches.
  • Grouped-query attention is the default in open LLMs (Llama 3, Qwen3, Gemma 3, Mistral): several query heads share one key-value head to shrink the cache (Lesson 7.3).

Sources: scaled_dot_product_attention, Transformers attention backends, FlexAttention, FlashInfer, Llama 3 paper.

medium25 minimplement

Attention lets each query token collect information from a set of key and value tokens. Every transformer layer in the course uses this operation. A decoder adds a causal mask, so that a token cannot see the tokens that come after it.

Task

Write two functions.

  1. causal_mask(T) returns the causal mask for a sequence of T tokens.
  2. scaled_dot_product_attention(Q, K, V, mask=None) returns the attention output and the attention weights.

The scores are S=QKT/dk​​, where dk​ is the size of the last axis of Q. The weights are the softmax of each row of S, over the key axis. The output is the weights times V.

The mask is a boolean array. True means blocked. A blocked query and key pair gets a weight of exactly 0. The other weights in the row are a softmax over the allowed keys only, so each row of weights sums to 1.

The causal mask has True at row i and column j when j > i. Token i can see token i and every token before it.

Input and output

V float array (..., Tk, d_v) the values, with the same leading axes as Q

  • scaled_dot_product_attention returns a tuple (output, weights).
  • output is a float array of shape (..., Tq, d_v).
  • weights is a float array of shape (..., Tq, Tk).

  • 1 <= T, Tq, Tk <= 64 and 1 <= d_k, d_v <= 64.
  • Each row of the mask has at least one allowed key.
  • Scores can be larger than 1000. The output must stay finite.

  • Use numpy only.

Your code
Common mistakes the checks catch
  • Uses K.T, which reverses every axis of a batched K, not only the last two.
  • Builds the causal mask with k=0, so each token also blocks itself and the first row has no allowed key.
  • Sets the blocked weights to 0 after the softmax, so the rows do not sum to 1.
  • Calls np.exp on the raw scores, so large scores overflow to infinity.
  • Forgets to divide the scores by sqrt(d_k).
  • Divides the scores by d_k, not by sqrt(d_k).
Hint 1

Write a softmax over the last axis first. Use axis=-1 and keepdims=True, so that it works for any number of leading axes.

Hint 2

K.T reverses every axis of a 3D array. Use np.swapaxes(K, -1, -2) to transpose only the last two axes. The @ operator then treats the leading axes as a batch.

Hint 3

Apply the mask to the scores before the softmax. Put minus infinity at each blocked position with np.where. The exponential of minus infinity is exactly 0.

Hint 4

Subtract the maximum of each row before np.exp. Each row has at least one allowed key, so the maximum is finite. np.triu with k=1 gives the causal mask.

Reference solution and notes
import numpy as np


def softmax(x):
    shifted = x - np.max(x, axis=-1, keepdims=True)
    exp_x = np.exp(shifted)
    return exp_x / np.sum(exp_x, axis=-1, keepdims=True)


def causal_mask(T):
    return np.triu(np.ones((T, T), dtype=bool), k=1)


def scaled_dot_product_attention(Q, K, V, mask=None):
    dk = Q.shape[-1]
    scores = Q @ np.swapaxes(K, -1, -2) / np.sqrt(dk)
    if mask is not None:
        scores = np.where(mask, -np.inf, scores)
    weights = softmax(scores)
    output = weights @ V
    return output, weights

Why divide by the square root of d_k

Each score is a sum of dk​ products. When the entries of q and k have variance 1, the score has variance dk​. Large scores push the softmax toward a one-hot vector, and the gradient of a one-hot softmax is almost 0. Division by dk​​ sets the variance of the scores back to 1.

Why the mask goes before the softmax

The softmax divides by the sum over the row. When you set a weight to 0 after the softmax, the row sum is less than 1. When you put minus infinity in the score, the softmax gives that key a weight of exactly 0, and the other weights still sum to 1.

The numerical trap

Masked rows and large scores need the same fix: subtract the row maximum before np.exp. A row with no allowed key has a maximum of minus infinity, and the result is NaN. Real models avoid such rows. Some implementations use a large negative number such as -1e9 in place of minus infinity for this reason.

Where this goes next

Multi-head attention runs this function once for each head. The KV cache runs it for one new query at a time. In the lessons on BERT and GPT, the only difference between the two models is the mask.

Framework for explaining attention:

1. Start with traditional databases: a query matches a key exactly and returns one value.

2. Reframe attention as a soft database lookup:
   - Query (Q): what the current token is searching for
   - Key (K): what each token advertises about itself
   - Value (V): the actual content each token carries
   - Instead of exact match, compute similarity (dot product) between the query and ALL keys
   - Instead of returning one result, return a weighted blend of ALL values

3. Walk through the math step by step:
   - Q, K, V are learned linear projections of the input: Q = X @ Wq, K = X @ Wk, V = X @ Wv
   - Raw scores: Q @ K^T (dot product between every query-key pair)
   - Scaling: divide by sqrt(dk) to prevent softmax saturation
   - Softmax: convert raw scores to a probability distribution per row
   - Output: weighted sum of values using those probabilities

   - Show which tokens attend to which
   - Explain why "sat" might attend strongly to "cat" (subject-verb relationship)
   - Show the attention weight matrix as a grid

5. Connect to the bigger picture:
   - Self-attention: Q, K, V all come from the same sequence

   - Multi-head: multiple attention functions in parallel, each learning different relationship types
   - Causal masking: preventing tokens from attending to future positions (used in GPT-style models)

Solutions

SolutionP1 · More than half

More than half. In layers 5 to 10, 63–78% of all attention goes to the first token, and one head (layer 7, head 2) puts 96% there. This is the "attention sink": softmax must give each row weights that sum to 1, so a head with nothing useful to read parks the weight on a token every position can see. In a 21-token sentence part of the effect is that there are few tokens to choose from, but the same pattern appears in long texts, which is why streaming LLMs keep the first tokens in their cache.

SolutionB1 · It learns to copy the answer

Without the mask, position i can read token i+1, which is exactly the token it is trained to predict. The model learns to copy it from the input, so the training loss drops close to zero, but at generation time the next token does not exist yet and the model has learned nothing useful. Rebuilding GPT-2 without the mask also no longer matches GPT-2's weights: every row except the last changes, because the softmax now spreads over later positions too.

Read the codeA decoder's attention returns a zero vector in the first row of every sequence. The mask code is: python def causal_mask(T): return np.triu(np.ones((T, T), dtype=bool), k=0) weights = softmax(scores) weights[mask] = 0 out = weights @ V Two things are wrong. Find both and explain what each one does to the output.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. The mask uses a diagonal offset of zero, so every token blocks itself and the first token has no allowed key, which leaves an empty row. The mask is also applied after the softmax, so the rows no longer sum to one. Build the mask with an offset of one, and set the blocked scores to a very negative value before the softmax.

Bug one: the diagonal.

A causal mask lets position i see positions zero through i, itself included. np.triu with k=0 keeps the diagonal in the blocked set. For the first query every key is blocked, so this code sets the whole first row of weights to zero and the first output row is zero. If you only move the mask before the softmax and fill with negative infinity, that row has nothing to normalize and the division produces NaN. Use k=1 so the diagonal stays visible.

Bug two: masking after the softmax.

Setting weights to zero after normalization leaves each row summing to less than one, by exactly the mass that the future keys received. The output then shrinks and the model trains against a moving scale. The mask must act on the scores before the softmax, by setting blocked entries to a very negative value, so that their exponentials are zero and the remaining entries renormalize.

The corrected code.

def causal_mask(T):
    return np.triu(np.ones((T, T), dtype=bool), k=1)

scores = np.where(mask, -1e9, scores)
weights = softmax(scores)
out = weights @ V

Why both bugs can pass a shape test.

Neither bug changes a shape. Only a check of the weights, or a check that the first output row is not zero, exposes them. The practice task checks the causal weights against a reference and includes the first row.

Plausible wrong answers.

  • "Set the blocked weights to zero and renormalize the rows." It works numerically but doubles the work; masking the scores before the softmax does the renormalization for free.
  • "The first token should attend to nothing." The first token must attend to itself; an empty row has no valid distribution.
  • "Use a lower-triangular ones matrix as the mask." A ones matrix marks the allowed entries, so it must be inverted before it is used as a blocked-entry mask.

Follow-ups an interviewer may ask.

  • (level 2) Why a very negative number and not negative infinity? Expected: infinity works in most frameworks, but a fully masked row then produces NaN, while a finite value keeps the arithmetic defined.
  • (level 2) How does the mask interact with the batch dimension? Expected: the mask is tokens by tokens and broadcasts across batches and heads; it is built once per sequence length.
  • (level 3) The same model is used for prefill and then one token at a time. Does the mask change? Expected: at decode time the single query sees every cached key, so no mask is needed for that step; the causal rule was already applied when those keys were produced.
  • (level 3) A padding mask and a causal mask must both apply. How do you combine them? Expected: combine the boolean masks with a logical or before the scores are masked, so a padded key is blocked for every query.

Read the codeHere is an attention function from a take-home submission: python def attention(Q, K, V): scores = Q @ K.T / Q.shape[-1] return softmax(scores) @ V The tests for shape pass and the tests for the attention weights fail. Find the bug and explain what the correct factor protects against.

Level 1 of 4 · about 6 minutes to answer well.

Short answer. The scores are divided by the key dimension instead of its square root. Dot products of random vectors grow with the dimension, so without the square root the softmax input is either too large, which saturates it and kills the gradient, or too small, which flattens every row toward uniform. The correct line divides by the square root of the last dimension of the keys.

The fix.

def attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)
    return softmax(scores) @ V

Why the square root.

When the entries of a query and a key have unit variance, their dot product has a variance equal to the dimension. Its typical size is therefore the square root of the dimension. Dividing by that size brings the scores back to unit scale, where the softmax has useful gradients. Dividing by the dimension itself over-corrects and makes every row close to uniform, so the output is almost the mean of the values regardless of the query.

Two neighbors of this bug.

  • No scale at all: at a head size of 64 the raw scores reach the tens and the softmax saturates to one hot rows.
  • K.T on a batched tensor: .T reverses every axis, so a shape of batch by tokens by features becomes features by tokens by batch. With distinct sizes the matmul raises a shape error, and when the sizes happen to line up it mixes batches without an error. Swap only the last two axes.

How the practice checks it.

The practice task compares the weights, not only the output shape. A wrong scale changes every weight, so a reference weight matrix catches it at once.

Plausible wrong answers.

  • "Any constant works, the model learns around it." The learned projections can compensate in training, but the practice checks a fixed reference, and in a trained model the wrong factor changes every head.
  • "Divide by the sequence length." The growth comes from the feature dimension, not from the number of tokens.
  • "Scaling is only for numerical overflow." The max shift inside softmax handles overflow; the scale keeps the softmax out of its saturated and flat regions.

Follow-ups an interviewer may ask.

  • (level 1) What is the shape of the scores for one sequence? Expected: tokens by tokens, one row per query over all keys.
  • (level 2) Why do shape tests pass with the wrong factor? Expected: scaling does not change shapes; only the values move.
  • (level 2) How do you transpose the keys for a batched input? Expected: swap the last two axes only, for example with swapaxes(-1, -2).

Where it is taught. The self-attention lesson explains the square-root scale factor, and the attention practice checks the weights against a reference.

Read the codeA candidate writes this softmax for a batch of logits and the tests pass on small inputs but return NaN on a real attention row: python def softmax(x): e = np.exp(x) return e / e.sum(axis=-1, keepdims=True) What is wrong, how do you fix it, and why does the fix not change the result?

Level 1 of 4 · about 6 minutes to answer well.

Short answer. A large logit overflows the exponential to infinity, and infinity divided by infinity is NaN. Subtract the maximum of each row before the exponential. The softmax of a row is unchanged when the same constant is subtracted from every entry, because the constant cancels between the numerator and the denominator.

The failure.

Attention scores and language model logits can reach values in the tens or hundreds. The exponential of such a value does not fit in a float, so the row becomes infinite and the division gives NaN. Small test inputs never show it.

The fix.

def softmax(x):
    shifted = x - np.max(x, axis=-1, keepdims=True)
    e = np.exp(shifted)
    return e / e.sum(axis=-1, keepdims=True)

After the shift the largest entry of each row is zero, so the largest exponential is one and nothing overflows. Entries far below the maximum underflow to zero, which is the correct limit.

Why the result is the same.

Softmax of a row divides each exponential by the sum of all exponentials in that row. Subtracting a constant multiplies every exponential by the same factor, and that factor cancels in the ratio. The shift must be per row, over the last axis. A single maximum taken across the entire batch changes nothing about correctness but lets one hot row push every other row into underflow.

Two more details that bite.

  • Keep the dimension with keepdims=True so the subtraction broadcasts along the row and not along the batch.
  • Do not subtract in place when the caller still needs the logits.

Plausible wrong answers.

  • "Clip the logits to a safe range." Clipping changes the distribution; the shift does not.
  • "Use float64 and the problem goes away." It moves the threshold, and attention scores still overflow in long rows.
  • "Subtract the mean instead of the maximum." The mean does not bound the largest entry, so a row can still overflow.

Follow-ups an interviewer may ask.

  • (level 1) Where does this same shift appear inside attention? Expected: in the softmax over the scaled scores, which is why the attention lesson writes the shifted version first.
  • (level 2) Why is a global maximum over the whole batch a bug? Expected: one row with a very large logit shifts every other row far below zero, so those rows underflow to all zeros and divide by zero.
  • (level 2) The practice task also asks for the gradient of the mean cross-entropy. What is it? Expected: the softmax minus the one-hot target, divided by the batch size.

Where it is taught. The self-attention lesson builds the shifted softmax as its first step, and the softmax and cross-entropy practice checks it with large logits.

Debug a failureAn attention module between an encoder and a decoder runs without any exception, but the model's accuracy slowly falls behind the reference implementation. When you print the context tensor, its second dimension is the encoder length instead of the decoder length. Walk me through the diagnosis.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. A module that runs and still produces the wrong shape is a broadcast bug, and a silent broadcast is the worst attention bug because it degrades accuracy instead of crashing. Write the expected shapes first: scores and weights are batch by decoder length by encoder length, and the context is batch by decoder length by the encoder state width. Then find the matmul whose operands were swapped or not transposed, fix it with one transpose or reshape, and add asserts on the shapes and on the weights summing to one.

The shape table.

Tensor Shape
Encoder states H (T_enc, d_h); d_h is twice the hidden size for a bidirectional encoder
Decoder state s (d_s,)
Score for one encoder position scalar
Weights after the softmax (T_enc,) for one decoder step
Context vector (d_h,), the same shape as one encoder state

Batched over decoder steps, the weights are (batch, T_dec, T_enc) and the context is (batch, T_dec, d_h).

How the wrong shape appears.

The context is weights @ H. If the code built the scores as H @ H.T because the query tensor was replaced by the encoder states, the shapes still multiply and the result has the encoder length where the decoder length belongs. Nothing raises. Downstream layers broadcast or reshape the tensor and the loss keeps falling, just more slowly.

The diagnosis steps.

  1. Print the shape of every intermediate tensor and compare with the table.
  2. Check the score formula. For the additive form the projection vector collapses an attention-dimension vector to a scalar; for the dot form the query and the key must have the same width, and a bidirectional encoder doubles the key width, so the dot form fails unless a matrix W sits between them.
  3. Check which decoder state feeds the query. One classic formulation uses the state before the current step and the other uses the state after it. Mixing them gives subtly wrong gradients that are very hard to see.
  4. Fix with one transpose, reshape or projection. Refuse any fix that only silences the mismatch by broadcasting.

The regression test.

assert output.shape == (batch, T_dec, d_h)
assert weights.shape == (batch, T_dec, T_enc)
assert weights.sum(dim=-1) is close to 1

The third line catches a softmax taken over the wrong axis, which is the other silent bug in this layer.

Plausible wrong answers.

  • "Reshape the output to the expected shape and continue." The values inside are wrong; a reshape only hides the mismatch.
  • "Lower the learning rate; the model is just unstable." The run is not unstable; it is computing the wrong quantity.
  • "Add a mask to fix the shape." A mask changes which positions get weight, not the layout of the tensor.

Follow-ups an interviewer may ask.

  • (level 2) Which single test catches most attention bugs? Expected: the weights have shape batch by decoder length by encoder length and sum to one along the last axis.
  • (level 2) The score matrix comes out square in the encoder dimension. What happened? Expected: the keys were scored against themselves; the query tensor was replaced by the encoder states.
  • (level 3) Why does the plain dot score fail with a bidirectional encoder? Expected: the encoder state is twice the hidden width, so it no longer matches the decoder state; use the general form with a matrix between them.
  • (level 3) Why is the state convention a gradient problem and not a shape problem? Expected: both states have the same shape, so nothing fails; the gradient flows to the wrong step and the model learns a slightly wrong alignment.

Explain the mechanismA new teammate has read the word "attention" a hundred times and still cannot say what a query, a key or a value is. Explain the three to them in one minute. Then tell me what changed between the 2014 encoder-decoder version and the version inside a transformer.

Level 1 of 4 · about 6 minutes to answer well.

Short answer. Attention is a soft lookup. Each token produces a query that asks for information, a key that says what the token holds, and a value that the token hands over when it is picked. The query is scored against every key, the scores go through a softmax, and the output is the weighted sum of the values. In the 2014 version the query was the decoder state and the keys and the values were the same encoder states; a transformer takes all three from one sequence through three learned projections.

The three projections.

For a sequence X of n tokens with d dimensions each:

Q = X @ Wq    (n, dk)   what each token looks for
K = X @ Wk    (n, dk)   what each token contains
V = X @ Wv    (n, dv)   what each token returns when picked
scores = Q @ K.T        (n, n)

Row i of the score matrix is one token's view of the whole sequence. The softmax turns the row into weights that sum to one. The output for token i is the weighted sum of all value vectors.

The database picture.

A real database matches a query to one key and returns one value. Attention matches a query to every key with a similarity score and returns a blend of every value. The blend is what lets the model combine information from several positions in one step.

What the 2014 version had.

The encoder-decoder attention of 2014 used the previous decoder state as the query and scored it against every encoder hidden state. The context vector was the weighted average of those same encoder states. In that design the keys and the values were the same thing. Two score functions were common: an additive score that passes the pair through a tanh and a learned vector, and a multiplicative score that takes a dot product. The three-line fix broke the fixed-size bottleneck of the encoder-decoder.

What a transformer changed.

Self-attention queries a sequence against itself, and it separates keys from values with different learned projections. Multi-head attention runs several of these in parallel. The weighted sum of values is the same idea. The score function changes: the additive tanh score and the plain dot product give way to a dot product divided by the square root of the key width.

Plausible wrong answers.

  • "The key and the value must be the same vector." They were in the classic version, but a transformer learns separate projections for them.
  • "Attention picks the single best matching token." The softmax gives a weight to every position, and the output blends all of the values.
  • "The query comes from the encoder." In encoder-decoder attention the query comes from the decoder and the keys and the values come from the encoder.

Follow-ups an interviewer may ask.

  • (level 1) What shape does the output have for one token? Expected: the value dimension, because the output is a weighted sum of value vectors.
  • (level 2) Why give keys and values separate projections? Expected: a token can be matched on one kind of information and return another kind.
  • (level 2) Why does the plain dot-product score need the query and the key to have the same dimension? Expected: a dot product is only defined for vectors of equal length; the general form inserts a matrix W to remove that constraint.
  • (level 3) Name the convention trap between the two classic score functions. Expected: one uses the decoder state before the current step and the other uses the state after it; mixing them produces subtly wrong gradients.

Where it is taught. The attention mechanism lesson builds the classic version and the self-attention lesson builds the projections.

Explain the mechanismIn the attention formula the raw scores go through a division before the softmax. A new engineer calls the division a convention and removes it to save one multiply. What happens to training, and how would you show the effect in ten minutes?

Level 1 of 4 · about 6 minutes to answer well.

Short answer. A dot product of two vectors grows with their length, so without the division the scores grow with the key dimension. Large scores push the softmax into a region where one key takes almost all of the weight and the gradient to every other key is close to zero, so learning stalls. The division by sqrt(d_k) keeps the variance of the scores about constant for any head size. Show it with random Q and K at d_k = 64: print the score range and the softmax weights with and without the division.

The size of a score.

A score is the sum of d_k products. When the components of Q and K have unit variance, the sum has variance d_k, so a typical score is about sqrt(d_k) in size. At d_k = 64 the raw scores sit in the range of tens. A softmax over scores in the tens puts almost all of its mass on the largest entry.

Why the model stops learning.

The gradient of the softmax with respect to a score is small when one weight is near one and the others are near zero. The attention layer then behaves like a fixed lookup. The loss plateaus, and nothing fails loudly. The lesson calls this regime one where "one entry has almost all the mass and the others are vanishingly small".

The fix and its range.

Divide the scores by sqrt(d_k) before the softmax:

weights = softmax(Q @ K.T / sqrt(d_k))
output  = weights @ V

In multi-head attention the dimension under the root is the head width, d_head = d_model / n_heads, not the model width. Production models land d_head at 64 or 128. The scaling keeps the score variance constant at any width. The lesson's rule of thumb keeps heads at 32 or wider, because a narrower head sees too few dimensions, and below 256, because wider heads lose the benefit of many small specialists.

The ten-minute demonstration.

  1. Draw Q and K from a standard normal with d_k = 64.
  2. Print (Q @ K.T).max() with and without the division.
  3. Print the largest softmax weight in one row for both cases. Without the division it sits near one.

Plausible wrong answers.

  • "The division keeps the attention weights summing to one." The softmax normalizes any scores to sum to one; the division controls their spread, not their sum.
  • "A larger learning rate recovers the lost gradient." When the softmax is saturated the gradient carries almost no information about the other keys, and a larger step does not create information.
  • "Scale the values instead of the scores." The values are summed after the weights are fixed, so their scale does not touch the softmax.

Follow-ups an interviewer may ask.

  • (level 1) What is the shape of the score matrix for a sequence of n tokens? Expected: (n, n), one row per query and one column per key.
  • (level 2) Why does the missing division cause a silent failure instead of an exception? Expected: the softmax saturates, the gradients become tiny, and the loss plateaus with no error.
  • (level 2) Does the division change what the layer can represent? Expected: no, the projections can absorb a constant; it changes the scale of the scores at initialization, which is where training happens or stalls.
  • (level 3) With eight heads of width 64 in a model of width 512, which number goes under the root? Expected: 64, the head width, because each head computes its own softmax over its own scores.

Where it is taught. The self-attention lesson explains the saturation, the multi-head lesson gives the head widths, and the capstone attention block applies the scaling inside the batched block.
