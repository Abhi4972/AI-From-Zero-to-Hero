In plain words first
The idea in one line

Train an image encoder and a text encoder together so that matching (image, caption) pairs land at the same point in a shared space. That is the whole trick.

Terms you'll hear
Term What people say What it actually means
Two-tower "Dual encoder" Separate image and text encoders ending in a shared-dim projection head
Zero-shot "No task-specific training" Classify into classes described only by text at inference; no labels touched
Temperature / logit_scale "tau" Learned scalar that scales the similarity matrix before softmax
Prompt template "A photo of a {}" Natural-language wrapper around class names; averaging many templates boosts zero-shot accuracy
CLIP "Image+text model" The 2021 OpenAI model; vocabulary of the field in 2026
SigLIP "Sigmoid CLIP" Swaps softmax for per-pair sigmoid; trains better at small batches
OpenCLIP "Open reproduction" Community-trained CLIP variants on LAION; production default for open-source pipelines
VLM "Vision-language model" A CLIP-family encoder plus an LLM, trained to answer questions about images

The problem

In plain words first

CLIP learns from hundreds of millions of photos with their captions. It has two encoders, one for images and one for text, and trains them so that a photo and its own caption end up as nearby points in the same space, while mismatched pairs end up far apart. Afterwards you can classify an image into categories nobody trained it on: write each category as a sentence ("a photo of a parachute"), encode the sentences, and pick the one closest to the image. That is called zero-shot classification.

Traditional classifiers are closed-vocabulary: a 1000-class ImageNet model can only predict 1000 labels. Every new category requires labelled data and a retrained head.

CLIP (Radford et al., OpenAI 2021) showed that training on 400M (image, caption) pairs scraped from the web produces a model that can classify into any set of categories at inference, described purely in natural language. You give it a new class by writing a sentence.

That capability — zero-shot transfer — is why so many vision systems now start from a CLIP-family checkpoint. Detection (Grounding DINO, OWL-ViT), segmentation (CLIPSeg, SAM), retrieval, content moderation, VLMs, and text-to-image generation all build on CLIP-style joint embeddings.

Idea 1 · Two towers

Both encoders end with a linear projection to the same embedding dimension (512 for CLIP ViT-B/32, 768 for CLIP ViT-L/14). L2-normalise and compute cosine similarity.

Idea 2 · The objective

Given a batch of N (image, caption) pairs, build an N×N similarity matrix. Train both encoders so the diagonal (matching pairs) has high similarity and off-diagonals (non-matching) have low similarity.

sim_matrix = image_embeddings @ text_embeddings.T / tau

loss_i2t = cross_entropy(sim_matrix,       targets=arange(N))
loss_t2i = cross_entropy(sim_matrix.T,     targets=arange(N))
loss = (loss_i2t + loss_t2i) / 2

Symmetric because both image-to-text and text-to-image retrieval should work. tau (temperature) is typically learned as a scalar parameter, initialised to 0.07.

Worked example
One row of the matrix

A batch has 3 pairs. Image 1's cosine similarities with the three captions are 0.30,0.05,0.10; its own caption is the first. With CLIP's starting temperature, 1/τ=1/0.07≈14.3, the logits are 4.29,0.71,1.43.

p(caption 1)=e4.29+e0.71+e1.43e4.29​=73.0+2.0+4.273.0​=0.92

so this row's loss is −ln0.92=0.08. A cosine of only 0.30 is enough to be "clearly the match", because only the ranking within the batch matters. The text-to-image direction does the same for every column, and the two losses are averaged.

Idea 3 · SigLIP: a better loss

SigLIP (Zhai et al., 2023) replaced the softmax with per-pair sigmoid:

lossyij​​=pairsmean​log(1+exp(−yij​⋅simij​))={+1−1​if matchingotherwise​​

Per-pair loss removes the batch-level normalisation that CLIP requires. SigLIP trains better at small batch sizes and matches or exceeds CLIP at equal data.

Idea 4 · Zero-shot classification

Given a trained CLIP:

  1. For each class, compose a prompt: "a photo of a {class}".
  2. Encode all class prompts with the text encoder -> T shape (C, d).
  3. Encode the test image -> I shape (1, d).
  4. Similarity = I @ T.T shape (1, C).
  5. Argmax -> predicted class.

Prompt engineering matters. OpenAI published 80 prompt templates for ImageNet ("a photo of a {}", "a blurry photo of a {}", "a sketch of a {}", ...). Average the embeddings of all templates per class for an extra 1-3% top-1 accuracy.

Check your mental model
  • ✗ "Zero-shot means the model never saw that kind of image."
    ✓ It never saw labels for your classes. It almost certainly saw many web photos of dogs with captions saying so.
  • ✗ "The prompt wording does not matter; only the class name does."
    ✓ It can matter, mostly for ambiguous names on large class lists. On the 10 easy classes under "Use it" the three prompt styles score within half a point of each other, which is itself worth knowing.
  • ✗ "A cosine similarity of 0.3 is a weak match."
    ✓ Absolute CLIP similarities are small; what counts is which candidate is highest (see the worked example).

Idea 5 · Where CLIP-style models are used in 2026

  • Zero-shot classification — direct use.
  • Image retrieval — encode all images once, embed query at inference.
  • Text-conditioned detection — Grounding DINO, OWL-ViT wrap a CLIP text tower around a detector.
  • Text-conditioned segmentation — CLIPSeg; the original SAM paper explored text prompts through CLIP embeddings, and SAM 3 (Lesson 4.24) makes text prompts a core feature.
  • VLMs — LLaVA, Qwen-VL, InternVL wire a CLIP-family vision encoder into an LLM.
  • Text-to-image gen — Stable Diffusion 1.x and 2.x condition on CLIP text embeddings, and SDXL on two CLIP text encoders.

Once you have a shared embedding space, every vision+language task becomes a distance computation.

The same idea as a formula

Two towers, one space. An image encoder f and a text encoder g produce L2-normalised embeddings ui​=f(xi​) and vj​=g(tj​). For a batch of N matching pairs, the similarity matrix is

Sij​=τui​⋅vj​​

with a learned temperature τ. CLIP's loss is the average of two cross-entropies: each image must pick its own caption from the N in the row, and each caption its image from the column; the diagonal holds the correct pairs.

SigLIP replaces the softmax over the batch with an independent binary decision for every pair:

L=−N1​i,j∑​logσ(zij​(tui​⋅vj​+b)),zij​=+1 if i=j, −1 otherwise

with learned scale t and bias b. No normalisation across the batch is needed, so the loss works well at small batch sizes and is cheaper to distribute.

Zero-shot classification. Embed a prompt per class ("a photo of a dog") and predict argmaxc​u⋅vc​; averaging the embeddings of several prompt templates per class usually adds a few points of accuracy.

Retrieval is the same score used the other way: rank all images by ui​⋅v for a text query.

Step 1 · A tiny two-tower model

Real CLIP is ViT + transformer. For this lesson the towers are small MLPs over pre-extracted features so the training signal is visible on CPU.

import torch
import torch.nn as nn
import torch.nn.functional as F


class TwoTower(nn.Module):
    def __init__(self, img_in=128, txt_in=64, emb=64):
        super().__init__()
        self.image_proj = nn.Sequential(nn.Linear(img_in, 128), nn.ReLU(), nn.Linear(128, emb))
        self.text_proj = nn.Sequential(nn.Linear(txt_in, 128), nn.ReLU(), nn.Linear(128, emb))
        self.logit_scale = nn.Parameter(torch.ones([]) * 2.6592)  # ln(1/0.07)

    def forward(self, img_feats, txt_feats):
        i = F.normalize(self.image_proj(img_feats), dim=-1)
        t = F.normalize(self.text_proj(txt_feats), dim=-1)
        return i, t, self.logit_scale.exp()

Two projections, shared-dim output, learned temperature. Same shape as the real CLIP API.

Step 2 · Contrastive loss

def clip_loss(image_emb, text_emb, logit_scale):
    N = image_emb.size(0)
    sim = logit_scale * image_emb @ text_emb.T
    targets = torch.arange(N, device=sim.device)
    l_i = F.cross_entropy(sim, targets)
    l_t = F.cross_entropy(sim.T, targets)
    return (l_i + l_t) / 2

Symmetric. Higher logit_scale = sharper softmax = more confident but risk of instability.

Step 3 · Zero-shot classifier

@torch.no_grad()
def zero_shot_classify(model, image_feats, class_text_feats, class_names):
    """
    image_feats:      (N, img_in)
    class_text_feats: (C, txt_in)   one averaged embedding per class
    """
    i = F.normalize(model.image_proj(image_feats), dim=-1)
    t = F.normalize(model.text_proj(class_text_feats), dim=-1)
    sim = i @ t.T
    pred = sim.argmax(dim=-1)
    return [class_names[p] for p in pred.tolist()]

One line per step. This is the exact zero-shot procedure used with a production CLIP checkpoint.

Step 4 · Sanity check

torch.manual_seed(0)
model = TwoTower()

img = torch.randn(8, 128)
txt = torch.randn(8, 64)
i, t, scale = model(img, txt)
loss = clip_loss(i, t, scale)
print(f"batch size: {i.size(0)}   loss: {loss.item():.3f}")
What you should see
batch size: 8   loss: 3.167

With no structure learned you might expect log(N) = log(8) = 2.08, but the printed loss is higher (3.17). The reason is the starting logit_scale of 14.3: it magnifies the random cosine similarities between untrained embeddings into logits several units apart, so the softmax confidently picks the wrong pair. As in Lesson 4.17, log(N) is the value only when all similarities are near zero.

Predict before you run

Below, the lesson's TwoTower trains on synthetic "image" and "caption" features generated from 20 hidden concepts, but only pairs from 15 of them. Then it classifies examples of the 5 concepts it never trained on, given only their "captions". Above chance (20%)? (Solution P1.)

See zero-shot transfer happen

Each concept is a random 16-number vector. An "image" feature is a fixed random linear map of a noisy copy of it (128 numbers), a "caption" a different map of it (64 numbers). TwoTower and clip_loss learn from concepts 0 to 14 only.

import numpy as np
import matplotlib.pyplot as plt
torch.manual_seed(0)
NUM_CONCEPTS, LATENT = 20, 16
concepts = torch.randn(NUM_CONCEPTS, LATENT)
to_image, to_text = torch.randn(LATENT, 128), torch.randn(LATENT, 64)
def sample_pairs(concept_ids, n):
    c = concept_ids[torch.randint(len(concept_ids), (n,))]
    images = (concepts[c] + 0.3 * torch.randn(n, LATENT)) @ to_image + 0.5 * torch.randn(n, 128)
    captions = concepts[c] @ to_text + 0.5 * torch.randn(n, 64)
    return images, captions, c

seen, unseen = torch.arange(0, 15), torch.arange(15, 20)
two_tower = TwoTower()
opt = torch.optim.Adam(two_tower.parameters(), lr=1e-3)
losses = []
for step in range(1500):
    imgs, caps, _ = sample_pairs(seen, 128)
    loss = clip_loss(*two_tower(imgs, caps))
    opt.zero_grad(); loss.backward(); opt.step()
    losses.append(loss.item())

names = [f"concept {k}" for k in range(NUM_CONCEPTS)]
class_captions = concepts @ to_text                       # one clean "caption" per concept
for label, group in (("seen during training", seen), ("never seen", unseen)):
    imgs, _, truth = sample_pairs(group, 500)
    pred = zero_shot_classify(two_tower, imgs, class_captions[group], [names[k] for k in group])
    acc = sum(p == names[t] for p, t in zip(pred, truth.tolist())) / 500
    print(f"zero-shot accuracy on concepts {label}: {acc:.0%}  (chance {1 / len(group):.0%})")

fig, ax = plt.subplots(figsize=(6, 2.8))
ax.plot(losses, color="#474d9a", lw=1); ax.axhline(np.log(128), color="#b7bfcb", ls=":")
ax.set_xlabel("step"); ax.set_ylabel("clip_loss (batch 128)"); ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout(); plt.show()
What you should see
zero-shot accuracy on concepts seen during training: 100%  (chance 7%)
zero-shot accuracy on concepts never seen: 99%  (chance 20%)
Reading this output

The loss falls fast and then flattens around 2.2 rather than 0: with only 15 concepts in a batch of 128, many captions in a batch describe the same concept, so the model cannot tell "its" caption from another of the same concept. That floor is the price of duplicate pairs, which real web data has too. The important line is the second accuracy: the model classifies concepts it never trained on almost perfectly, given only their captions. It did not learn 15 classes; it learned to map both kinds of input into a shared space where meaning lines up. That is zero-shot transfer.

In clip_loss, return only l_i (image-to-text) instead of the average with l_t. Training still works and zero-shot classification by image still works. What capability quietly gets worse? (Solution B1.)

Use it: the same idea with real libraries

OpenCLIP is the most widely used open reproduction. Here it classifies a photo from ImageNet's validation set:

import io
import open_clip
import torch
import pyarrow.parquet as pq
from PIL import Image
from huggingface_hub import hf_hub_download

table = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
                                      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"),
                      columns=["image", "label"])
photo = Image.open(io.BytesIO(table.column("image")[2700].as_py()["bytes"])).convert("RGB")   # two puppies

model, _, preprocess = open_clip.create_model_and_transforms("ViT-B-32", pretrained="laion2b_s34b_b79k")
tokenizer = open_clip.get_tokenizer("ViT-B-32")
image = preprocess(photo).unsqueeze(0)
text = tokenizer(["a photo of a dog", "a photo of a cat", "a photo of a car"])
with torch.no_grad():
    image_features = model.encode_image(image)
    text_features = model.encode_text(text)
    image_features = image_features / image_features.norm(dim=-1, keepdim=True)
    text_features = text_features / text_features.norm(dim=-1, keepdim=True)
    probs = (100.0 * image_features @ text_features.T).softmax(dim=-1)
print(probs)

import numpy as np
import matplotlib.pyplot as plt
CLASSES = ["tench", "English springer", "cassette player", "chain saw", "church",
           "French horn", "garbage truck", "gas pump", "golf ball", "parachute"]
TEMPLATES = ["a photo of a {}.", "a blurry photo of a {}.", "a close-up photo of a {}.",
             "a photo of the large {}.", "a photo of the small {}.", "a bright photo of a {}."]

def class_embeddings(templates):
    with torch.no_grad():
        per_class = []
        for name in CLASSES:
            e = model.encode_text(tokenizer([t.format(name) for t in templates]))
            e = e / e.norm(dim=-1, keepdim=True)
            per_class.append(e.mean(0))
        e = torch.stack(per_class)
        return e / e.norm(dim=-1, keepdim=True)

labels_all = np.array(table.column("label").to_pylist())
rows = np.random.default_rng(0).choice(len(labels_all), 300, replace=False)
with torch.no_grad():
    feats = torch.cat([model.encode_image(torch.stack([preprocess(Image.open(io.BytesIO(table.column("image")[int(i)].as_py()["bytes"])).convert("RGB"))
                                                       for i in chunk])) for chunk in np.array_split(rows, 6)])
feats = feats / feats.norm(dim=-1, keepdim=True)
truth = torch.tensor(labels_all[rows])
for label, templates in (("bare class name", ["{}"]), ('"a photo of a {}."', TEMPLATES[:1]), ("6-template ensemble", TEMPLATES)):
    acc = ((feats @ class_embeddings(templates).T).argmax(1) == truth).float().mean().item()
    print(f"{label:22s} zero-shot accuracy {acc:.1%}")

probs_one = (100 * image_features @ class_embeddings(TEMPLATES).T).softmax(-1)[0]
fig, axes = plt.subplots(1, 2, figsize=(10, 3.4), gridspec_kw={"width_ratios": [1, 1.6]})
axes[0].imshow(photo); axes[0].axis("off")
axes[1].barh(CLASSES[::-1], probs_one.flip(0).numpy(), color="#474d9a")
axes[1].set_xlabel("probability"); axes[1].spines[["top", "right"]].set_visible(False)

Reading this output

Without a single training label CLIP sorts these photos into the 10 classes with high accuracy, and the puppies photo puts almost all its probability on "English springer". The three prompt styles all land at about 99% here, with the bare class name marginally ahead: these 10 classes are so distinct that wording barely matters. The gains from templates and ensembles that Idea 4 describes were measured on all 1,000 ImageNet classes, where many names are ambiguous ("crane" the bird or the machine); measure on your own class list before assuming either way. On harder or more specialised lists (medical scans, rare species) zero-shot accuracy drops a lot, and a linear probe or fine-tuning on a few labelled examples is the next step.

Recap
What to keep from this lesson
  • CLIP trains an image encoder and a text encoder so matching pairs are close in one shared space.
  • The loss is a symmetric cross-entropy over the batch similarity matrix; SigLIP uses a per-pair sigmoid instead.
  • Zero-shot classification: encode one prompt per class, pick the most similar to the image.
  • Prompt templates and ensembles help on large, ambiguous class lists; only relative similarity matters.
  • CLIP-family encoders power retrieval, open-vocabulary detection and segmentation, and vision-language models.

Solutions

SolutionP1 · Almost perfect on unseen concepts

Far above chance: nearly 100% on the five concepts never seen in training, about the same as on the seen ones. The towers learned a general mapping from both views into a shared space, not a lookup table of 15 classes, so a new concept's caption lands next to that concept's images automatically. Real CLIP works for the same reason, with language as the bridge.

SolutionB1 · Text-to-image retrieval

With only the image-to-text term, each image learns to pick its caption out of the batch, but nothing asks each caption to pick its image out of the batch. Zero-shot classification (image in, best caption out) barely notices. Search in the other direction, "find the images matching this text", is what weakens, because the text embeddings are never trained to rank images. The symmetric average keeps both directions useful.

Industry practice
What's current (2024–2026)

Practice problem · CLIP symmetric contrastive loss

From the source repository: write the function, then press "Run the checks". They run as real Python in your browser (the first run loads Python, about 10 MB) and tell you which part is wrong and why. Hints open one at a time; the reference solution opens when every check passes.

medium30 minresearch

CLIP trains an image encoder and a text encoder together. In a batch of N pairs, image i belongs with text i and with no other text. The loss pulls the matched pairs together and pushes the other N2−N pairs apart. Zero-shot classification and image search both use the embeddings that this loss trains.

Task

Write three functions.

  1. similarity_logits(image_emb, text_emb, temperature) returns the N×N logit matrix.
  2. symmetric_infonce(logits) returns the symmetric contrastive loss as a float.
  3. symmetric_infonce_grad(logits) returns the gradient of that loss with respect to the logits.

Logits. Divide each image row and each text row by its L2 norm. Call the results I^ and T^. The logits are

S=τI^T^⊤​

where τ is the temperature. Row i holds image i against every text. Column j holds text j against every image.

Loss. The target of row i and of column i is index i, the diagonal.

Limg​=−N1​i∑​log∑j​eSij​eSii​​,Ltxt​=−N1​j∑​log∑i​eSij​eSjj​​

L=2Limg​+Ltxt​​

Gradient. Return ∂L/∂S with the same shape as logits. Let R be the softmax of each row of S, and C the softmax of each column of S. The gradient of one cross-entropy is its softmax minus the one-hot target.

Input and output

Name Type Shape Meaning
image_emb float array (N, d) one image embedding in each row
text_emb float array (N, d) one text embedding in each row, row i matches image i
temperature float τ>0, the logits are divided by it
logits float array (N, N) a logit matrix, rows are images and columns are texts
  • similarity_logits returns a float array of shape (N, N).
  • symmetric_infonce returns a Python float.
  • symmetric_infonce_grad returns a float array of shape (N, N).

Constraints

  • 1 <= N <= 256 and 1 <= d <= 512.
  • No embedding row is all zeros.
  • 0.01 <= temperature <= 1.
  • symmetric_infonce and its gradient get any finite logits, with absolute values up to 1000. The results must stay finite.
  • Do not change the input arrays.
  • Use numpy only.

Your code
Common mistakes the checks catch
  • Adds the two gradient terms and divides by N, not by 2N.
  • Uses the row softmax for the text term of the gradient, not the column softmax.
  • Returns only the image to text cross-entropy and drops the text to image term.
  • Calls np.exp on the raw logits, so large logits overflow to infinity.
  • Skips the L2 normalization, so the logits depend on the length of each embedding.
  • Multiplies the similarities by the temperature instead of dividing by it.
Hint 1

np.linalg.norm(x, axis=-1, keepdims=True) gives the length of each row with shape (N, 1). Divide by it to get unit rows.

Hint 2

The text loss is the image loss applied to the transpose of the logits. Each column of S becomes a row of S⊤.

Hint 3

Write a log-softmax over the last axis that subtracts the row maximum first. The diagonal of the log-softmax gives the log probability of each correct match.

Hint 4

The gradient of the image term is (R−IN​)/N. The gradient of the text term is (C−IN​)/N, where C is the transpose of the row softmax of S⊤. The loss is the mean of the two terms, so add them and divide by 2.

Reference solution and notes
import numpy as np


def normalize(x):
    return x / np.linalg.norm(x, axis=-1, keepdims=True)


def log_softmax(x):
    shifted = x - np.max(x, axis=-1, keepdims=True)
    return shifted - np.log(np.sum(np.exp(shifted), axis=-1, keepdims=True))


def similarity_logits(image_emb, text_emb, temperature):
    i = normalize(image_emb)
    t = normalize(text_emb)
    return i @ t.T / temperature


def symmetric_infonce(logits):
    n = logits.shape[0]
    rows = np.arange(n)
    l_i = -np.mean(log_softmax(logits)[rows, rows])
    l_t = -np.mean(log_softmax(logits.T)[rows, rows])
    return float((l_i + l_t) / 2)


def symmetric_infonce_grad(logits):
    n = logits.shape[0]
    eye = np.eye(n)
    p_rows = np.exp(log_softmax(logits))
    p_cols = np.exp(log_softmax(logits.T)).T
    return ((p_rows - eye) + (p_cols - eye)) / (2 * n)

Why the loss is symmetric

The image term asks each image to find its text among N texts. The text term asks each text to find its image among N images. Both encoders get a gradient from both directions. The CLIP paper uses this mean of the two cross-entropies. A random model gives a loss near logN, because each softmax is close to uniform.

Why normalize and divide by a temperature

After normalization each entry of I^T^⊤ is a cosine similarity in [−1,1]. A softmax over values in that small range is almost flat. Division by a small τ, for example 0.07, makes the softmax sharp enough to learn from. CLIP learns log(1/τ) as a parameter and clips it so that 1/τ stays at 100 or less.

The numerical trap

The logits can be large when τ is small or when the code gets raw scores. Subtract the maximum before np.exp in both the row and the column softmax.

Where this goes next

Every off-diagonal entry is a negative example, so a larger batch gives more negatives for free. SigLIP replaces the two softmax terms with an independent sigmoid loss for each entry of S. The multimodal phase of the course uses this loss to pretrain a vision and language model.


### Domain-specific add-ons

- **natural_photos** — add 'blurry', 'cropped', 'black and white', 'close-up', 'low resolution' variants
- **medical** — 'a medical scan showing {}', 'an X-ray of {}', 'histology slide of {}'
- **satellite** — 'satellite imagery of {}', 'aerial photo of {}', 'remote sensing image of {}'
- **documents** — 'a scanned document of a {}', 'photograph of a {} document', 'OCR scan of a {}'
- **industrial** — 'industrial inspection image of a {}', 'defect image showing {}'
- **memes_social** — add 'a meme of a {}', 'internet image of a {}'

### Fine-grained templates (for hard classes)

- 'a photo of a {}, a type of <super-category>'
- 'a close-up photo of a {}'
- 'a photo showing the distinctive features of a {}'

## Output format

```
[classes]
  <list>

[templates used]
  <numbered list>

[per-class prompt counts]
  <class_1>: N prompts
  <class_2>: N prompts

[recommendation]
  - average embeddings across templates: yes
  - alpha-blend with super-category prompts: yes | no
```

## Operational Guidelines

- Always include the three base templates.
- For `expected_hardness == hard`, add the super-category templates; without them fine-grained classes collapse.
- Never use more than 100 templates per class; diminishing returns after about 80.
- Watch class-name casing: CLIP handles "dog" and "Dog" similarly but "DOG" (all caps) worse; normalise to lowercase unless the class name is a proper noun.

# Image-Text Retriever

Turn a folder of images into a searchable index using CLIP embeddings.

## When to use

- Building a zero-shot image search on an internal catalog.
- Deduplicating near-identical images by embedding distance.
- Building a quick "find similar" component without a labelled dataset.

## Inputs

- `image_folder`: directory of image files.
- `clip_model`: HuggingFace id like `openai/clip-vit-base-patch32` or `google/siglip-base-patch16-224`.
- `index_type`: flat | IVF | HNSW.
- `embedding_dim`: inferred from the model.

## Steps

1. Load the CLIP model and preprocessor.
2. Batch-encode every image in the folder. Save embeddings as (N, D) float32 + filename list.
3. Build a FAISS index over the embeddings. Use inner-product on L2-normalised vectors for cosine similarity.
4. Expose two query interfaces:
   - `search_by_text(text, k)` — embed the text, search.
   - `search_by_image(image_path, k)` — embed the image, search.

## Output template

```python
import os
import glob
import numpy as np
import torch
from PIL import Image
from transformers import CLIPModel, CLIPProcessor
import faiss


class ImageTextRetriever:
    def __init__(self, model_name="openai/clip-vit-base-patch32"):
        self.model = CLIPModel.from_pretrained(model_name).eval()
        self.processor = CLIPProcessor.from_pretrained(model_name)
        self.dim = self.model.config.projection_dim
        self.index = None
        self.filenames = []

    @torch.no_grad()
    def _encode_images(self, paths, batch=16):
        embs = []
        for i in range(0, len(paths), batch):
            imgs = [Image.open(p).convert("RGB") for p in paths[i:i + batch]]
            inputs = self.processor(images=imgs, return_tensors="pt")
            out = self.model.get_image_features(**inputs)
            out = out / out.norm(dim=-1, keepdim=True)
            embs.append(out.cpu().numpy())
        return np.concatenate(embs).astype(np.float32)

    @torch.no_grad()
    def _encode_text(self, texts):
        inputs = self.processor(text=texts, return_tensors="pt", padding=True)
        out = self.model.get_text_features(**inputs)
        out = out / out.norm(dim=-1, keepdim=True)
        return out.cpu().numpy().astype(np.float32)

    def build_index(self, folder, index_type="flat"):
        exts = ("*.jpg", "*.jpeg", "*.png", "*.webp", "*.bmp")
        files = []
        for ext in exts:
            files.extend(glob.glob(os.path.join(folder, ext)))
        self.filenames = sorted(files)
        embs = self._encode_images(self.filenames)
        if index_type == "IVF":
            quantizer = faiss.IndexFlatIP(self.dim)
            nlist = min(256, max(4, len(embs) // 32))
            self.index = faiss.IndexIVFFlat(quantizer, self.dim, nlist)
            self.index.train(embs)
        elif index_type == "HNSW":
            self.index = faiss.IndexHNSWFlat(self.dim, 32, faiss.METRIC_INNER_PRODUCT)
        else:
            self.index = faiss.IndexFlatIP(self.dim)
        self.index.add(embs)

    def search_by_text(self, text, k=5):
        q = self._encode_text([text])
        dist, idx = self.index.search(q, k)
        return [(self.filenames[i], float(d)) for d, i in zip(dist[0], idx[0])]

    def search_by_image(self, image_path, k=5):
        q = self._encode_images([image_path])
        dist, idx = self.index.search(q, k)
        return [(self.filenames[i], float(d)) for d, i in zip(dist[0], idx[0])]
```

## Report

```
[retriever]
  model:          <name>
  num_images:     <int>
  dim:            <int>
  index_type:     flat | IVF | HNSW
  index_size_mb:  <float>
```

## Rules

- Always L2-normalise embeddings before indexing; FAISS's inner product on normalised vectors equals cosine similarity.
- For < 100k images, `IndexFlatIP` (exact) is simplest and fastest.
- For 100k-10M, `IndexIVFFlat` is the standard trade-off.
- For > 10M, use HNSW or a product-quantised variant.
- Never rebuild the index on every query; embed once, search many times.
