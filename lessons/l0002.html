Why this came about

AI libraries change every few months, and lessons that call real paid APIs are slow, costly and give different answers each run. So this course pins its library versions and runs most examples against labeled stand-ins that behave the same every time, showing the real API alongside. This lesson sets that up once.

In plain words first
Setting up a workshop

Before cooking you need a kitchen: a stove, knives, a place to put things. Programming is the same. You need a terminal (a window where you type commands to your computer), a code editor (a text editor that understands code), Python (the program that runs Python code) and a project folder with its own set of add-on libraries. You do this once. If anything here feels unfamiliar, that is normal; every step says exactly what to type and what you should see.

Setup from zero: four tools, one project

If you have never programmed, follow this section step by step. If you already have Python 3.11 or newer and a code editor, skim it and continue at Setup below.

1. Open a terminal

A terminal (also called a command line or shell) is a text window where you type a command, press Enter, and the computer answers with text.

Your computer How to open a terminal
Windows 10 or 11 Press the Windows key, type PowerShell, press Enter
macOS Press Cmd+Space, type Terminal, press Enter
Linux Press Ctrl+Alt+T, or find Terminal in your applications

Type pwd (macOS, Linux) or Get-Location (Windows) and press Enter. The terminal prints the folder you are "standing in", for example /Users/asha or C:\Users\asha. Every command runs relative to that folder. Three commands are enough to move around:

Command What it does Example
cd <folder> Change directory: move into a folder (cd .. goes up one level) cd Documents
ls (macOS, Linux) or dir (Windows) List what is in the current folder ls
mkdir <name> Make a new folder mkdir ai-course

2. Install a code editor

Install Visual Studio Code (free, from code.visualstudio.com). Then, inside VS Code, open the Extensions panel (the four-squares icon on the left) and install Python and Jupyter, both published by Microsoft. VS Code also has a built-in terminal: menu Terminal → New Terminal. From now on you can use that one.

3. Install uv, which installs Python for you

uv is a small tool that installs Python and manages each project's libraries. In the terminal:

# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Close and reopen the terminal, then check it worked:

uv --version          # prints something like: uv 0.9.x
uv python install 3.12

4. Create the course project

Every lesson's code lives in one folder, called a project. These three commands make the folder, set it up for Python 3.12, and run the small test file that uv creates, so you know everything works before you write a line yourself. Type them in the terminal, one line at a time:

mkdir ai-course && cd ai-course
uv init --python 3.12           # creates pyproject.toml and a hello.py
uv run hello.py                 # runs it; prints: Hello from ai-course!

uv init created a project: a folder with a file called pyproject.toml that lists the libraries this project uses. The first time you run something, uv also creates a hidden folder .venv, a virtual environment: a private copy of Python plus this project's libraries, so different projects never break each other.

Add the libraries the foundation chapters (F1 to F7) use. PyTorchlater · F4.3 is large (about 200 MB); the extra flag fetches the smaller version that runs on an ordinary laptop processor (CPU):

uv add numpy pandas matplotlib scikit-learn tiktoken transformers requests
uv add torch --index https://download.pytorch.org/whl/cpu

The course was checked with Python 3.12, numpy 2.5, pandas 3.1, scikit-learn 1.9, torch 2.15 (CPU), transformers 5.22 and tiktoken 0.14. Newer versions almost always work; if an output differs slightly in the last decimal place, that is why.

5. Two ways to run code: scripts and notebooks

  • A script is a .py file you run from start to end: uv run my_script.py.
  • A notebook (.ipynb) is a document made of cells. You run one cell at a time and see its output right under it, which is ideal for experimenting. In VS Code: File → New File → Jupyter Notebook, then pick the .venv of your project as the kernel (top right). Every code block in this course can be pasted into a notebook cell.
Tip
No installation possible? Use Google Colab

If you cannot install software on your computer, open colab.research.google.com in a browser, create a new notebook, and run each code block in a cell. NumPylater · F1.6, pandas, scikit-learn, PyTorch and transformerslater · F6.3 are already installed there. To add a missing library, run !pip install tiktoken in a cell.

6. API keys, briefly

From Chapter 2 onwards some examples can call real AI models over the internet. Those services identify you with an API keylater · F1.4: a long secret string, like a password, that is billed to your account. Rules that matter from day one:

  • Never paste a key into code or a notebook you will share. Put it in a file called .env in your project folder (shown below) and add .env to .gitignore.
  • Ask your team lead which provider and account to use; most companies have an approved one.
  • You can do all of the foundation chapters and most of the course without any key: the examples run offline with labelled stand-ins (explained at the end of this lesson).

When something goes wrong

What you see What it usually means What to do
command not found: uv The terminal was opened before uv was installed Close the terminal and open a new one
ModuleNotFoundError: No module named 'numpy' The library is not installed in the environment you are using Run uv add numpy in the project folder, and in VS Code select the project's .venv as the interpreter
SyntaxError A typo in the code: a missing bracket, quote or colon Read the line number in the message; Lesson F1.3 teaches how to read errors
The notebook cannot find the kernel VS Code does not know which Python to use Click Select Kernel (top right) and choose .venv

Packages for the later blocks

The foundation blocks need only the packages installed above. When you reach Chapter 1, add the model and retrieval packages to the same project; later chapters name the extra packages they need.

# Install uv once (macOS / Linux). On Windows: powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
curl -LsSf https://astral.sh/uv/install.sh | sh

cd ai-course                       # the project you created in Setup from zero
uv add anthropic openai google-genai boto3 pydantic numpy scikit-learn rank-bm25

Keys go in a .env file that is never committed to git:

# .env  (add only the providers you use)
ANTHROPIC_API_KEY=...
OPENAI_API_KEY=...
GEMINI_API_KEY=...
AWS_PROFILE=...           # or AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY
AWS_REGION=ap-south-1

Watch out
Versions

This course was checked in late October 2026. These libraries change monthly. When an API here disagrees with the official docs, trust the docs, and check the version notes at the end of each framework module.

Stand-in models, test servers and real APIs

Most examples run offline, so you can run every block today and switch to live calls when you have keys. Three kinds of stand-in appear, and each lesson labels which one it uses:

Stand-in What it is Where
Scripted model A function that returns fixed replies in a provider's response shape. It is not a language model; it lets you trace mechanics with identical output on every run Lesson 3.1 (FakeAnthropic), Lesson 3.2 and most of Chapter 3
Mock model server A local server that speaks the OpenAI-compatible API, so real framework code runs unchanged against it Lesson 6.1 lists and explains it; Lesson 3.11 and Chapters 6 and 7 use it
Local test server for SDKs Returns responses in each API's documented format, so the real anthropic and openai SDK code can be checked end to end without a key Lesson 3.1, The real thing

What changes when you point the same code at a real model: wording varies between runs, the model sometimes calls tools you did not expect or skips ones you did, latency and cost become real, and evaluation has to run each case several times. Lessons that show real implementations say what changes in behavior, setup, evaluation and cost.
