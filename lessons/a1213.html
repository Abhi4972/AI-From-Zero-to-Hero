The problem

In plain words first

Chameleon and Emu3 turn images into discrete codes, and the codebook limits how good the images can be. Transfusion (Meta, August 2024) keeps images continuous. A pretrained autoencoder (VAE) compresses each image into a small grid of numbers, and one transformer reads text and image patches in the same sequence. It is trained with two losses at once: next-token prediction on the text, and a diffusion loss on the image patches. The diffusion loss means: add noise to the image, then learn to predict the noise. A special attention mask lets the patches of one image see each other in both directions, while text stays left-to-right. This lesson explains the mask, the two losses, the comparison with SD3's MMDiT and the measured advantage over Chameleon. It runs a miniature Transfusion forward pass with both losses and checks the diffusion arithmetic. No model is trained.

The discrete vs continuous image tokens debate is older than LLMs. Continuous representations (raw pixels, VAE latents) preserve detail. Discrete tokens (VQ indices) fit the transformer's native vocabulary but lose detail at the quantization step.

Chameleon / Emu3 went discrete: one loss, one architecture, but image fidelity capped by tokenizer quality.

Diffusion models went continuous: exceptional image quality, but a separate model from the LLM, complex noise-schedule engineering, and no clean integration with text generation.

Transfusion asks: can we have both? Keep images continuous, still train one model, use two losses stitched into one gradient step.

Idea 1 · The two-loss architecture

A single decoder-only transformer processes a sequence that contains:

  • Text tokens (discrete, from BPE vocab).
  • Image patches (continuous). Each image is first encoded by a pretrained VAE (86M parameters) into a latent grid: a 256x256 image becomes 32x32 latent positions with 8 channels. Groups of 2x2 latent positions (16x16 pixels) are embedded by a linear layer, or larger groups by U-Net down-blocks.
  • <image> and </image> tags marking where continuous patches live.

Forward pass runs once. The loss picks one of two heads per token:

  • For text tokens: standard cross-entropy on the vocab-logits head.
  • For image patches: diffusion loss on continuous patches — predict the noise that was added to each patch.

The gradient flows through the shared transformer body. Both losses improve the shared weights simultaneously.

Idea 2 · Attention mask: causal text + bidirectional image

Text tokens must be causal — you cannot let a text token attend to future text, or teacher forcing breaks. Image patches, however, represent one snapshot; they should attend to each other bidirectionally within the same image block.

The mask:

M[i, j] = 1 if:
  (i is text and j is text and j <= i)   # causal for text
  OR (i is image and j is image and same_image_block(i, j))   # bidirectional within image
  OR (i is text and j is image and j < i)   # text attends to images that closed before it
  OR (i is image and j is text and j < i_image_start)   # image attends to preceding text

Implemented as a block-triangular mask at training and inference.

Idea 3 · Diffusion loss inside the transformer

The diffusion loss is standard DDPM: add noise to the image latents and ask the model to predict that noise. Transfusion uses noise (ε) prediction with a cosine noise schedule over 1,000 timesteps. (Flow matching, which predicts a velocity from noise to data, is what SD3 and many later unified models use; the idea is the same.)

During training:

  1. For each image's latent x0​, sample a random timestep t.
  2. Sample noise ϵ and compute xt​=αˉt​​x0​+1−αˉt​​ϵ.
  3. The transformer predicts ϵθ​(xt​,t); lossDDPM​=MSE(ϵθ​(xt​,t),ϵ).
  4. Backprop alongside the text next-token loss from the same sequence: L=LLM​+λLDDPM​ with λ=5.

At inference, generation is: - Text tokens: standard autoregressive sampling. - Image patches: a diffusion sampling loop over all patches of the image at once (250 steps in the paper), conditioned on the prior text tokens.

The same idea as a formula

Forward noising with the cumulative schedule αˉt​ (cosine, t=1,…,1000):

xt​=αˉt​​x0​+1−αˉt​​ϵ,ϵ∼N(0,I).
If the model predicts ϵ exactly, the clean latent follows: x0​=(xt​−1−αˉt​​ϵ)/αˉt​​.

The combined loss over one interleaved sequence:

L=LLM​−i∈text∑​logpθ​(yi​∣y<i​)​​+λLDDPM​E∥ϵ−ϵθ​(xt​,t,context)∥2​​,λ=5.

Attention mask: Mij​=1 if j≤i (causal), or if i and j are patches of the same image (bidirectional inside the image).

Worked example
One 256×256 image in a caption-then-image sequence
  • VAE: 256/8=32, so a 32×32×8 latent. With 2×2 latent patches: 16×16=256 patches, each a vector of 2⋅2⋅8=32 numbers.
  • With U-Net down-blocks to 8×8 latent patches: 4×4=16 patches, 16 times fewer positions (the paper's "up to 64× cheaper serving").
  • Mask for 16 patches: causal attention alone allows 16⋅17/2=136 pairs inside the image; bidirectional allows 162=256, so 120 more (measured below).
  • At t=500 of 1,000, αˉ​≈0.70: the noisy latent still correlates about 0.7 with the clean one; at t=999 almost nothing is left.

A miniature Transfusion, one training step

A 2-layer transformer with a language head and a patch head, a 27-position sequence of text and 16 latent patches, Transfusion's mask, a cosine-schedule noisy latent at t = 0.6, and the combined loss with λ = 5. The run checks the mask and measures each loss's gradient on a shared weight. Random weights, nothing is trained. Instant.

import torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0)
# A miniature Transfusion: one transformer, text tokens with next-token loss, image patches with a diffusion loss.
# Sequence: 6 caption tokens, <image>, 16 latent patches, </image>, 3 more text tokens.
V, D, P = 1000, 64, 32                           # vocab, model width, numbers per latent patch (2x2 latent x 8 channels)
kinds = ["t"] * 6 + ["t"] + ["i"] * 16 + ["t"] + ["t"] * 3
n = len(kinds)
img = torch.tensor([k == "i" for k in kinds])
block = torch.cumsum(torch.tensor([k == "t" for k in kinds]), 0)   # image patches share a block id

causal = torch.tril(torch.ones(n, n, dtype=torch.bool))
same_image = img[:, None] & img[None, :] & (block[:, None] == block[None, :])
mask = causal | same_image                        # causal everywhere, bidirectional inside an image
print(f"sequence of {n} positions: {int((~img).sum())} text, {int(img.sum())} image patches")
print(f"allowed pairs: causal only {int(causal.sum())}, Transfusion mask {int(mask.sum())} "
      f"(+{int(mask.sum() - causal.sum())} = image patches seeing later patches of the same image)")
first, last = img.nonzero()[0].item(), img.nonzero()[-1].item()
print(f"first image patch sees the last one: {mask[first, last].item()}; "
      f"a caption token sees the image after it: {mask[2, first].item()}; "
      f"text after the image sees all its patches: {mask[last + 2, first:last + 1].all().item()}")

class Mini(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok = nn.Embedding(V, D); self.patch_in = nn.Linear(P, D); self.t_in = nn.Linear(1, D)
        self.body = nn.TransformerEncoder(nn.TransformerEncoderLayer(D, 4, 4 * D, batch_first=True), 2)
        self.lm_head = nn.Linear(D, V); self.patch_out = nn.Linear(D, P)
    def forward(self, ids, patches, t):
        h = self.tok(ids)
        h[:, img] = self.patch_in(patches) + self.t_in(t.view(1, 1, 1).expand(1, int(img.sum()), 1))
        h = self.body(h, mask=~mask)               # PyTorch masks True = blocked
        return self.lm_head(h), self.patch_out(h)

model = Mini()
ids = torch.randint(0, V, (1, n))
x0 = torch.randn(1, int(img.sum()), P)             # clean latent patches
t = torch.tensor(0.6)
alpha_bar = torch.cos(t * torch.pi / 2) ** 2       # cosine schedule
eps = torch.randn_like(x0)
xt = alpha_bar.sqrt() * x0 + (1 - alpha_bar).sqrt() * eps
logits, eps_hat = model(ids, xt, t)
text_pos = (~img).nonzero()[:, 0]
lm = F.cross_entropy(logits[0, text_pos[:-1]], ids[0, text_pos[1:]])   # next text token
ddpm = F.mse_loss(eps_hat[0, img], eps[0])
loss = lm + 5 * ddpm                               # Transfusion's balance: lambda = 5
w = model.body.layers[0].linear1.weight
g_lm, = torch.autograd.grad(lm, w, retain_graph=True)
g_dd, = torch.autograd.grad(ddpm, w, retain_graph=True)
print(f"\none forward pass: LM loss {lm:.3f} (ln {V} = {torch.log(torch.tensor(float(V))):.3f} at random), "
      f"diffusion loss {ddpm:.3f}, total {loss:.3f}")
print(f"gradient norm on a shared body weight from the text loss {g_lm.norm():.3f}, from the diffusion loss {g_dd.norm():.3f}: "
      f"both losses train the same weights")

Reading this output

The mask adds exactly the in-image pairs. A causal mask over 27 positions allows 378 pairs. Transfusion's mask allows 498, that is 120 more, and all of them let a patch see later patches of the same image (16² − 16·17/2 = 120). The first patch can see the last. A caption token before the image cannot see it, so text generation stays causal. The text after the image sees all 16 patches.

One pass, two losses. The language loss is 6.977, about ln 1000 = 6.908, which is what a random model scores on a 1,000-word vocabulary. The diffusion loss is 1.239, close to the MSE of guessing zero noise. With λ = 5 the total is 13.169. The weighting matters: here the image term contributes 6.2 of the 13.2.

Both losses train the same body. A weight inside the shared transformer receives a gradient from the text loss (norm 0.590) and from the diffusion loss (0.275). That is the design's whole point and its main difficulty: the two objectives compete for the same parameters, and λ decides how much say each gets.

The diffusion arithmetic and the sequence length

The cosine noise schedule over 1,000 steps is applied to a 256×256 image's latent (8 × 32 × 32): signal share, signal-to-noise ratio and correlation with the clean latent at five timesteps, plus exact recovery from a perfect noise prediction. Then the run counts patches per image for linear and U-Net patching. Instant.

import torch
torch.manual_seed(0)
# The DDPM arithmetic Transfusion uses for image latents, and what the latent patching does to sequence length
T = 1000
t = torch.arange(T + 1) / T
alpha_bar = torch.cos((t + 0.008) / 1.008 * torch.pi / 2) ** 2      # cosine schedule (Nichol and Dhariwal)
alpha_bar = alpha_bar / alpha_bar[0]
x0 = torch.randn(8, 32, 32)                                          # a 256x256 image's VAE latent: 8 channels, 32x32
print(f"{'step t':>7}{'signal share sqrt(abar)':>25}{'SNR (dB)':>10}{'corr(x_t, x_0)':>16}")
for step in [1, 250, 500, 750, 999]:
    ab = alpha_bar[step]
    eps = torch.randn_like(x0)
    xt = ab.sqrt() * x0 + (1 - ab).sqrt() * eps
    corr = torch.corrcoef(torch.stack([xt.flatten(), x0.flatten()]))[0, 1]
    print(f"{step:>7}{ab.sqrt():>25.3f}{10 * torch.log10(ab / (1 - ab)):>10.1f}{corr:>16.3f}")
    if step == 500:
        x0_back = (xt - (1 - ab).sqrt() * eps) / ab.sqrt()          # if the model predicts eps exactly
        print(f"{'':>7}(at t = 500, a perfect noise prediction recovers x_0 to {(x0_back - x0).abs().max():.1e})")

print("\nsequence length for one 256x256 image")
for name, patch in [("linear layer, 2x2 latent patches", 2), ("U-Net down blocks, 4x4", 4), ("U-Net down blocks, 8x8", 8)]:
    n = (32 // patch) ** 2
    print(f"  {name:<34} {n:>4} patches, each covering {patch * 8}x{patch * 8} pixels")
print(f"  Chameleon-style discrete tokens (16x16 px each) {(256 // 16) ** 2:>4} tokens, generated one at a time")
print(f"\nimage generation: 250 denoising steps over all patches at once, versus one step per token for discrete codes")

Reading this output

The schedule moves from image to noise. At step 1 the noisy latent is the clean latent (correlation 1.000). At step 250 it still holds 92% signal, at 500 the signal and noise are about equal (SNR −0.1 dB, correlation 0.70), at 750 it is mostly noise, and at 999 the image is gone (correlation 0.001). Training samples steps across this whole range, so the model learns to denoise from every level.

Predicting the noise is enough. At t = 500, subtracting the true noise and rescaling recovers the clean latent to within 4.8e-07, float rounding. A model that predicts ε well can therefore reconstruct the image, and sampling repeats that estimate over many steps.

Patch size sets the sequence length. With 2 × 2 latent patches a 256-px image is 256 positions. U-Net blocks with 4 × 4 or 8 × 8 patches bring it to 64 or 16. A Chameleon-style tokenizer at 16 px per code would also give 256 tokens, but generates them one at a time. Transfusion denoises all patches together, so it needs 250 parallel steps instead of 256 sequential ones (or 1,024 at 512 px).

Idea 4 · MMDiT: Stable Diffusion 3's variant

Stable Diffusion 3 (Esser et al., March 2024) shipped MMDiT (Multimodal Diffusion Transformer) around the same time as Transfusion. The architectures are siblings.

MMDiT's key differences:

  • Modality-specific weights per block. Each transformer block has separate Q, K, V, and MLP weights for text tokens vs image patches. Attention is joint (cross-modality); everything else is modality-specific.
  • Rectified flow training. A specific flow-matching variant with known sampling and simpler math than DDPM.
  • Scale. MMDiT is the backbone for SD3 (2B and 8B param variants). Transfusion's paper scales to 7B.

Both converge on the same core idea: one transformer runs NTP on text and diffusion on continuous image representations.

Idea 5 · Why this beats Chameleon-style

The quality gap between continuous diffusion and discrete next-token prediction is measurable. The Transfusion paper's controlled comparison against a Chameleon-style model trained on the same data reports:

  • FID parity with Chameleon at about 34 times less compute; at 7B, FID 16.8 against Chameleon's 29.6. It also reaches Chameleon's image-captioning quality with about a fifth of the compute.
  • No discrete tokenizer: images stay as continuous VAE latents, embedded by a linear layer or small U-Net blocks. With U-Net blocks an image can be compressed to just 16 patches with relatively small quality loss.
  • Inference can parallelize image patch denoising, unlike autoregressive image tokens.

Downside: Transfusion is a dual-loss model, making training dynamics trickier. Loss weights need tuning. Schedule mismatch between NTP and diffusion can cause one head to dominate.

Idea 6 · What sits downstream

Janus-Pro (Lesson 12.15) takes a different route: it decouples the vision encoder for understanding (SigLIP) from the one for generation (a VQ tokenizer) while sharing the transformer body, and generates images autoregressively. Show-o (Lesson 12.14) swaps diffusion for discrete diffusion (masked prediction). The unified-generation family branches rapidly after Transfusion.

Closed production models that emit images natively may use some descendant of this family, but their architectures are not published, so treat any such claim as a guess.

Use it: the same idea with real libraries

code/main.py builds a toy Transfusion on a tiny MNIST-like problem:

  • Images are 4x4 grids of bytes.

Industry practice
What's current (2024–2026)
  • Unified models mixing autoregression and diffusion: Transfusion's recipe and its descendants (Meta's Mixture-of-Transformers, ByteDance's BAGEL, Show-o2, InternVL-U's MMDiT head) dominate open unified image generation and understanding.
  • Flow matching replaced DDPM in most new image generators (SD3, FLUX), including diffusion heads on LLMs.
  • Few-step sampling: distillation and consistency methods cut 250 steps to a handful, which matters more for unified models than for text.
  • Laptop reality: these models are 7B and up; on an 8 GB GPU, run small diffusion models (SD 1.5/SDXL-class with optimisations) or quantized unified models, and expect seconds to minutes per image.

Given a multimodal training spec (two modalities, which gets NTP and which gets diffusion, target model scale, target sample length), design a working two-loss setup.

Produce:

1. Modality split. Which tokens are discrete (NTP) and which are continuous (diffusion). Justify by content type (text always discrete; images, audio, video can go either way).
2. Attention mask. Draw the block-triangular mask for an example sequence. Specify bidirectional regions and causal regions.
3. Loss weights. Starting weights for (text_loss, image_loss). Recommend tuning by target gradient-norm ratio. Cite Transfusion's ~0.1 default.
4. Flow-matching vs DDPM. Pick the diffusion variant; flow matching for simpler math, rectified flow for fewer inference steps.
5. Inference plan. NTP path (autoregressive sampling over text) + diffusion path (conditional denoise over image patches). Specify denoise steps (10-30).
6. MMDiT vs Transfusion split. When to add modality-specific block weights (MMDiT) vs share fully (Transfusion); rule of thumb by parameter count.

Hard rejects:
- Claiming one mask fits all sequences. Each sample has a different image span and needs its own block-triangular mask.
- Using DDPM without rectified flow or flow matching. Both need fewer inference steps and are simpler to tune.
- Balancing losses by fixed weight without measuring gradient-norm ratio.

Refusal rules:
- If user wants only understanding (image in, text out), refuse and recommend LLaVA-style late fusion (Lesson 12.05). Two-loss is for generation.
- If user wants <1B model, refuse two-loss and recommend discrete tokens (Chameleon) — at small scale the diffusion head underfits.
- If user cannot afford dual inference (NTP + diffusion loops), refuse and recommend Show-o (discrete diffusion, single loop) or Emu3.

Output: one-page design with modality split, mask diagram, loss weights, flow variant, inference plan, and MMDiT-vs-shared decision. End with arXiv 2408.11039 (Transfusion) and 2403.03206 (SD3) for canonical references.

Solutions

SolutionP1 · 120 extra pairs, all inside the image

120 extra pairs: 498 allowed against 378 for a causal mask. Every one of them is inside the image, a patch attending to a later patch of the same image (16 × 16 = 256 pairs instead of the causal 136). A caption token cannot see the image that follows it (False), so text generation stays causal. Tokens after the image see all its patches.

SolutionB1 · Images stop improving while text looks fine

With λ = 0.05 the diffusion term is 100 times weaker than in the paper. The image patches still flow through the model, but the shared weights are tuned almost entirely for text. Text perplexity looks healthy, perhaps slightly better. Image quality stalls: samples stay blurry or off-prompt, and FID barely moves as training continues. You would notice it in the loss curves: the diffusion loss flattens early while the LM loss keeps falling. A small image-generation evaluation on fixed prompts (FID or a CLIP score) shows no progress. Track both losses separately, scaled by λ, and run image evaluations from the first checkpoints. The paper's λ = 5 was chosen so neither objective drowns the other.
