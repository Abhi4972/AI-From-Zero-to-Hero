In plain words first
The idea in one line

3D vision comes in two flavours. Point clouds are the sensor's raw output. NeRFs are the learned volumetric field. Both answer "what is where in space."

Terms you'll hear
Term What people say What it actually means
Point cloud "3D points from LIDAR" Unordered set of (x, y, z) + optional features per point
PointNet "First neural net on point clouds" Shared MLP per point + symmetric (max) pool; permutation-invariant by construction
NeRF "MLP that is the scene" Network mapping (x, y, z, dir) to (density, colour); rendered by ray casting
Positional encoding "Fourier features" Encode each coordinate into sin/cos at multiple frequencies to overcome MLP low-frequency bias
Volumetric rendering "Ray integration" Composite samples along a ray into a single pixel using transmittance and alpha
Instant-NGP "Hash-grid NeRF" Replaces NeRF's coordinate MLP with a multi-resolution hash grid; 100-1000x faster
3D Gaussian splatting "Millions of Gaussians" Scene = collection of 3D Gaussians; renders in real time, trains in minutes
SDF "Signed distance field" Function returning signed distance to the nearest surface; another implicit representation

The problem

In plain words first

There are two common ways to hold a 3D scene in a computer. A point cloud is just a list of 3D points, the raw output of a LIDAR or depth camera; the list has no order, so a network must give the same answer however the points are shuffled. A NeRF stores the scene inside a small neural network: give it a position and a viewing direction, and it says how solid the space is there and what colour it looks. To render a picture you shoot a ray through each pixel, ask the network about points along the ray, and blend the answers. Train it on a few photos with known camera positions and it can render views no camera ever took.

A camera produces a 2D image. A LIDAR produces a set of 3D points with no ordering. A structure-from-motion pipeline produces a sparse cloud of 3D keypoints. A NeRF reconstructs an entire 3D scene from a handful of posed images. All of these are "vision" but none of them look like the dense tensor a CNN wants.

3D vision matters because almost every high-value robot task runs in 3D: grasping, obstacle avoidance, navigation, AR occlusion, 3D content capture. A vision engineer who only understands 2D images is locked out of the fastest-growing slice of the field (AR/VR content, robotics, autonomous driving stacks, NeRF-based 3D reconstruction for real-estate or construction).

The two representations dominate for different reasons. Point clouds are what sensors give you for free. NeRFs and their successors (3D Gaussian splatting, neural SDFs) are what you get when you ask a neural network to learn a scene.

Idea 1 · Point clouds

A point cloud is an unordered set of N points in R3, optionally each with features (colour, intensity, normal).

cloud = [
  (x1, y1, z1, r1, g1, b1),
  (x2, y2, z2, r2, g2, b2),
  ...
  (xN, yN, zN, rN, gN, bN),
]

No grid, no connectivity. Two properties make this hard for neural networks:

  • Permutation invariance — the output must not depend on point order.
  • Variable N — a single model must handle clouds of different sizes.

PointNet (Qi et al., 2017) solved both with one idea: apply a shared MLP to every point, then aggregate with a symmetric function (max pool). The result is a fixed-size vector that does not depend on order.

f(P)=p∈Pmax​MLP(p)

This is the entire core of PointNet. Deeper variants (PointNet++, Point Transformer) add hierarchical sampling and local aggregation but the symmetric-function trick is unchanged.

Worked example
Why max is order-proof

Three points pass through the shared MLP and come out as 2-number features: (1,5), (4,2), (3,3). Max-pooling each feature over the points gives (max(1,4,3),max(5,2,3))=(4,5). List the points in any of the 6 possible orders and you still get (4,5), because max, like sum and mean, ignores order. Flattening instead, (1,5,4,2,3,3), changes with every reordering, so a network built on it would give 6 different answers for the same object.

Idea 2 · The PointNet architecture

"Shared MLP" means the same MLP runs on every point independently. Implemented as a 1x1 conv over the point dimension for efficiency.

Idea 3 · Neural Radiance Fields (NeRFs)

NeRFs (Mildenhall et al., 2020) took the question "can we reconstruct a 3D scene from N photos?" and answered with a neural network that is the scene. The network maps (x, y, z, viewing_direction) to (density, colour). Rendering a new view is a ray-casting loop over this network.

NeRF MLP:  (x, y, z, theta, phi) -> (sigma, r, g, b)

To render a pixel (u, v) of a new view:
  1. Cast a ray from the camera through pixel (u, v)
  2. Sample points along the ray at distances t_1, t_2, ..., t_N
  3. Query the MLP at each point
  4. Composite the colours weighted by (1 - exp(-sigma * dt))
  5. The sum is the rendered pixel colour

A loss compares the rendered pixel to the ground-truth pixel in the training photos. Backprop through the rendering step updates the MLP. No 3D ground truth, no explicit geometry — the scene is stored in the MLP weights.

Idea 4 · Positional encoding in NeRF

A vanilla MLP on (x, y, z) cannot represent high-frequency details because MLPs are spectrally biased toward low frequencies. NeRF fixes this by encoding each coordinate into a Fourier feature vector before the MLP:

γ(p)=(sin(20πp),cos(20πp),sin(21πp),cos(21πp),…)

Up to L=10 frequency levels. This is the same trick transformers use for positions, and it appears again in diffusion time conditioning (Lesson 4.10). Without it, NeRFs look blurry.

Idea 5 · Volumetric rendering

C(r)Ti​δi​​=i∑​Ti​(1−exp(−σi​δi​))ci​=exp(−j<i∑​σj​δj​)=ti+1​−ti​​

T_i is transmittance — how much light survives to point i. (1 - exp(-sigma_i * delta_i)) is the opacity at point i. c_i is the colour. The final pixel is a weighted sum along the ray.

Worked example
One ray, two samples

A ray meets two samples δ=0.5 apart: first a thin red haze with σ1​=2, then a dense blue surface with σ2​=10.

  • Sample 1: opacity 1−e−2×0.5=0.632, transmittance T1​=1, weight 0.632.
  • Sample 2: opacity 1−e−10×0.5=0.993, transmittance T2​=e−1=0.368, weight 0.368×0.993=0.366.

The pixel is 0.632×red+0.366×blue: mostly red, because the haze in front absorbs 63% of the light before it reaches the blue surface. The weights sum to 0.998, so almost nothing of the background shows through.

Check your mental model
  • ✗ "A NeRF stores a 3D model, like a mesh, inside the network."
    ✓ It stores a function: density and colour at any point. Surfaces are only where density happens to be high.
  • ✗ "Training needs 3D ground truth."
    ✓ Only photos and their camera poses. The loss compares rendered pixels with real pixels; geometry appears because it is the only consistent explanation of every view.
  • ✗ "More view-direction detail is always better."
    ✓ With few views, a high-frequency direction encoding lets the network paint each training view separately and generalise badly (see "Try it yourself" under "Use it").

Idea 6 · What replaced NeRFs

Pure NeRFs are slow to train (hours) and slow to render (seconds per image). The lineage since:

  • Instant-NGP (2022) — hash-grid encoding replaces the MLP's position input; trains in seconds.
  • Mip-NeRF 360 — handles unbounded scenes and anti-aliasing.
  • 3D Gaussian Splatting (2023) — replaces the volumetric field with millions of 3D Gaussians; trains in minutes, renders in real time. Now the most widely used of these for real-time view synthesis.

Many products that started with NeRFs now use Gaussian splatting, which Lesson 4.22 covers. The volumetric rendering idea from NeRF carries over.

Idea 7 · Datasets and benchmarks

  • ShapeNet — classification and segmentation of 3D CAD models as point clouds.
  • ScanNet — real indoor scans for segmentation.
  • KITTI — outdoor LIDAR point clouds for autonomous driving.
  • NeRF Synthetic / Blended MVS — posed-image datasets for view synthesis.
  • Mip-NeRF 360 dataset — unbounded real scenes.

The same idea as a formula

Point clouds are sets. A cloud of n points has no natural order, so a classifier must give the same answer for any permutation. PointNet achieves it with a symmetric function:

f(x1​,…,xn​)=γ(i=1maxn​h(xi​))

a shared MLP h on every point, an element-wise max over points, and a final MLP γ. The max picks, for each feature, the most extreme point, so a few critical points determine the output.

Volume rendering (NeRF). A network maps a 3-D position and viewing direction to a density σ and a colour c. Along a camera ray, with samples i spaced δi​ apart,

C(r)=i∑​Ti​(1−e−σi​δi​)ci​,Ti​=exp(−j<i∑​σj​δj​)

1−e−σi​δi​ is the chance the ray stops in sample i, and Ti​ the chance it got that far. Everything is differentiable, so the network is trained by comparing rendered and real pixels.

Positional encoding. MLPs struggle to represent fine detail from raw coordinates, so each coordinate p is expanded to (sin(2kπp),cos(2kπp))k=0L−1​, with L=10 for positions in the original NeRF: 60 numbers per point instead of 3.

Cost. Rendering one 800×800 image with 192 samples per ray needs over 120 million network evaluations, which is why rasterised Gaussian splatting (Lesson 4.22) replaced NeRF for real-time use.

Step 1 · PointNet classifier

import torch
import torch.nn as nn

class PointNet(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.mlp1 = nn.Sequential(
            nn.Conv1d(3, 64, 1),    nn.BatchNorm1d(64),   nn.ReLU(inplace=True),
            nn.Conv1d(64, 64, 1),   nn.BatchNorm1d(64),   nn.ReLU(inplace=True),
        )
        self.mlp2 = nn.Sequential(
            nn.Conv1d(64, 128, 1),  nn.BatchNorm1d(128),  nn.ReLU(inplace=True),
            nn.Conv1d(128, 1024, 1), nn.BatchNorm1d(1024), nn.ReLU(inplace=True),
        )
        self.head = nn.Sequential(
            nn.Linear(1024, 512),   nn.BatchNorm1d(512),  nn.ReLU(inplace=True),
            nn.Dropout(0.3),
            nn.Linear(512, 256),    nn.BatchNorm1d(256),  nn.ReLU(inplace=True),
            nn.Dropout(0.3),
            nn.Linear(256, num_classes),
        )

    def forward(self, x):
        # x: (N, 3, num_points) — transposed for Conv1d
        x = self.mlp1(x)
        x = self.mlp2(x)
        x = torch.max(x, dim=-1)[0]       # (N, 1024)
        return self.head(x)

pts = torch.randn(4, 3, 1024)
net = PointNet(num_classes=10)
print(f"output: {net(pts).shape}")
print(f"params: {sum(p.numel() for p in net.parameters()):,}")
What you should see

    def __init__(self, num_points=1024, num_classes=10):
        super().__init__()
        self.per_point = nn.Sequential(nn.Conv1d(3, 8, 1), nn.ReLU())
        self.head = nn.Linear(8 * num_points, num_classes)

        return self.head(self.per_point(x).flatten(1))

Step 2 · Positional encoding

def positional_encoding(x, L=10):
    """
    x: (..., D) -> (..., D * 2 * L)
    """
    freqs = 2.0 ** torch.arange(L, dtype=x.dtype, device=x.device)
    args = x.unsqueeze(-1) * freqs * 3.141592653589793
    sinc = torch.cat([args.sin(), args.cos()], dim=-1)
    return sinc.reshape(*x.shape[:-1], -1)

x = torch.randn(5, 3)
y = positional_encoding(x, L=10)
print(f"input:  {x.shape}")
print(f"encoded: {y.shape}     # (5, 60)")

Step 3 · Tiny NeRF MLP

class TinyNeRF(nn.Module):
    def __init__(self, L_pos=10, L_dir=4, hidden=128):
        super().__init__()
        self.L_pos = L_pos
        self.L_dir = L_dir
        pos_dim = 3 * 2 * L_pos
        dir_dim = 3 * 2 * L_dir
        self.trunk = nn.Sequential(
            nn.Linear(pos_dim, hidden), nn.ReLU(inplace=True),
            nn.Linear(hidden, hidden),  nn.ReLU(inplace=True),
            nn.Linear(hidden, hidden),  nn.ReLU(inplace=True),
            nn.Linear(hidden, hidden),  nn.ReLU(inplace=True),
        )
        self.sigma = nn.Linear(hidden, 1)
        self.color = nn.Sequential(
            nn.Linear(hidden + dir_dim, hidden // 2), nn.ReLU(inplace=True),
            nn.Linear(hidden // 2, 3), nn.Sigmoid(),
        )

    def forward(self, x, d):
        x_enc = positional_encoding(x, self.L_pos)
        d_enc = positional_encoding(d, self.L_dir)
        h = self.trunk(x_enc)
        sigma = torch.relu(self.sigma(h)).squeeze(-1)
        rgb = self.color(torch.cat([h, d_enc], dim=-1))
        return sigma, rgb

nerf = TinyNeRF()
x = torch.randn(128, 3)
d = torch.randn(128, 3)
s, c = nerf(x, d)
print(f"sigma: {s.shape}   rgb: {c.shape}")
What you should see
sigma: torch.Size([128])   rgb: torch.Size([128, 3])

Step 4 · Volumetric rendering along a ray

def volumetric_render(sigma, rgb, t_vals):
    """
    sigma: (..., N_samples)
    rgb:   (..., N_samples, 3)
    t_vals: (N_samples,) distances along the ray
    """
    delta = torch.cat([t_vals[1:] - t_vals[:-1], torch.full_like(t_vals[:1], 1e10)])
    alpha = 1.0 - torch.exp(-sigma * delta)
    trans = torch.cumprod(torch.cat([torch.ones_like(alpha[..., :1]), 1.0 - alpha + 1e-10], dim=-1), dim=-1)[..., :-1]
    weights = alpha * trans
    rendered = (weights.unsqueeze(-1) * rgb).sum(dim=-2)
    depth = (weights * t_vals).sum(dim=-1)
    return rendered, depth, weights


N = 64
t_vals = torch.linspace(2.0, 6.0, N)
sigma = torch.rand(N) * 0.5
rgb = torch.rand(N, 3)
rendered, depth, weights = volumetric_render(sigma, rgb, t_vals)
print(f"rendered colour: {rendered.tolist()}")
print(f"depth:           {depth.item():.2f}")

import math, time
import torch.nn.functional as F
import matplotlib.pyplot as plt

H = W = 32
FOCAL = 40.0
SPHERES = [((-0.45, 0.0, 0.0), 0.55, (0.70, 0.29, 0.11)),     # centre, radius, colour
           ((0.5, 0.15, 0.2), 0.4, (0.28, 0.30, 0.60)),
           ((0.0, -0.55, -0.4), 0.3, (0.14, 0.46, 0.23))]

def camera_rays(angle, elevation, radius=4.0):
    eye = torch.tensor([radius * math.cos(elevation) * math.sin(angle), radius * math.sin(elevation),
                        radius * math.cos(elevation) * math.cos(angle)])
    forward = -eye / eye.norm()
    right = torch.linalg.cross(forward, torch.tensor([0.0, 1.0, 0.0])); right = right / right.norm()
    up = torch.linalg.cross(right, forward)
    row, col = torch.meshgrid(torch.arange(H, dtype=torch.float32), torch.arange(W, dtype=torch.float32), indexing="ij")
    d = ((col - W / 2 + 0.5) / FOCAL)[..., None] * right - ((row - H / 2 + 0.5) / FOCAL)[..., None] * up + forward
    return eye.expand(H, W, 3), d / d.norm(dim=-1, keepdim=True)

def ray_trace(origins, dirs):                      # ground truth: colour and depth of the nearest sphere hit
    nearest = torch.full(origins.shape[:-1], float("inf"))
    image = torch.ones(origins.shape)
    light = torch.tensor([0.5, 0.8, 0.6]) / torch.tensor([0.5, 0.8, 0.6]).norm()
    for centre, radius, colour in SPHERES:
        oc = origins - torch.tensor(centre)
        b = (oc * dirs).sum(-1)
        disc = b ** 2 - ((oc ** 2).sum(-1) - radius ** 2)
        t = -b - disc.clamp(min=0).sqrt()
        hit = (disc > 0) & (t > 0) & (t < nearest)
        normal = (origins + t[..., None] * dirs - torch.tensor(centre)) / radius
        shade = 0.35 + 0.65 * (normal * light).sum(-1).clamp(min=0)
        image[hit] = (torch.tensor(colour) * shade[..., None])[hit]
        nearest = torch.where(hit, t, nearest)
    return image, nearest

poses = [(2 * math.pi * k / 12 + (0.26 if e > 0.5 else 0.0), e) for k in range(12) for e in (0.15, 0.75)]
views = [camera_rays(a, e) for a, e in poses]
photos = [ray_trace(o, d)[0] for o, d in views]
rays_o = torch.cat([o.reshape(-1, 3) for o, _ in views])
rays_d = torch.cat([d.reshape(-1, 3) for _, d in views])
pixels = torch.cat([p.reshape(-1, 3) for p in photos])
test_o, test_d = camera_rays(math.pi / 12 + 0.13, 0.45)          # a viewpoint no training camera used
test_photo, test_depth = ray_trace(test_o, test_d)

class SoftplusNeRF(TinyNeRF):
    def forward(self, x, d):
        h = self.trunk(positional_encoding(x, self.L_pos))
        sigma = F.softplus(self.sigma(h)).squeeze(-1)                 # was torch.relu
        return sigma, self.color(torch.cat([h, positional_encoding(d, self.L_dir)], dim=-1))

N_SAMPLES, NEAR, FAR = 32, 2.5, 5.5
def render_rays(model, o, d, jitter=0.0):
    t_vals = torch.linspace(NEAR, FAR, N_SAMPLES) + jitter
    points = o[:, None] + t_vals[None, :, None] * d[:, None]
    sigma, rgb = model(points.reshape(-1, 3) / 1.5, d[:, None].expand(-1, N_SAMPLES, -1).reshape(-1, 3))
    return volumetric_render(sigma.view(-1, N_SAMPLES), rgb.view(-1, N_SAMPLES, 3), t_vals)

torch.manual_seed(0)
nerf = SoftplusNeRF(L_pos=6, L_dir=1, hidden=128)
opt = torch.optim.Adam(nerf.parameters(), lr=1e-3)
decay = torch.optim.lr_scheduler.CosineAnnealingLR(opt, 2500, eta_min=5e-5)
start = time.time()
for step in range(2500):
    batch = torch.randint(0, len(rays_o), (512,))
    jitter = (torch.rand(1).item() - 0.5) * (FAR - NEAR) / N_SAMPLES     # sample slightly different depths each step
    colour, _, _ = render_rays(nerf, rays_o[batch], rays_d[batch], jitter)
    loss = ((colour - pixels[batch]) ** 2).mean()
    opt.zero_grad(); loss.backward(); opt.step(); decay.step()
with torch.no_grad():
    colour, depth, _ = render_rays(nerf, test_o.reshape(-1, 3), test_d.reshape(-1, 3))
psnr = -10 * torch.log10(((colour.view(H, W, 3) - test_photo) ** 2).mean())
print(f"{len(views)} training views, {len(rays_o):,} rays, 2,500 steps in {time.time() - start:.0f} s; final batch loss {loss.item():.4f}")
on_sphere = torch.isfinite(test_depth)
depth_err = (depth.view(H, W) - test_depth)[on_sphere].abs().mean()
print(f"held-out view PSNR: {psnr:.1f} dB; mean depth error on sphere pixels: {depth_err:.2f} (camera is 4.0 from the centre)")

masked = lambda dep: torch.where(on_sphere, dep, torch.nan)
fig, axes = plt.subplots(1, 6, figsize=(12, 2.4))
for ax, (img, title) in zip(axes, [(photos[0], "training view 1"), (photos[13], "training view 14"),
                                   (test_photo, "held-out view (truth)"), (colour.view(H, W, 3).clamp(0, 1), "NeRF render"),
                                   (masked(test_depth), "true depth"), (masked(depth.view(H, W)), "NeRF depth")]):
    depth_panel = "depth" in title
    ax.imshow(img, cmap="magma" if depth_panel else None, vmin=3.0 if depth_panel else None, vmax=4.6 if depth_panel else None,
              interpolation="nearest")
    ax.set_title(title + (" (dark = near)" if depth_panel else ""), fontsize=8); ax.axis("off")
plt.tight_layout(); plt.show()

Make it your own
Try it yourself

Change L_dir=1 to L_dir=4, the lesson's default, and rerun. The training loss gets even lower but the held-out PSNR drops sharply (in our run, to about 16 dB, with washed-out colours): with high-frequency direction features and only two rings of cameras, the network paints each training direction separately instead of learning one colour per surface point. Recap
What to keep from this lesson
  • Point clouds are unordered sets; PointNet's shared MLP plus max pooling makes the output order-independent.
  • A NeRF maps position and view direction to density and colour; rendering integrates along camera rays.
  • Volumetric rendering weights each sample by its opacity times the light that survived to reach it.
  • Positional encoding lets an MLP represent fine detail; too much of it for view direction overfits.
  • Gaussian splatting is the faster successor; the volumetric idea carries over.

Solutions

SolutionP1 · Blurry but right, with real depth

The render is recognisable but soft (about 23 dB PSNR on the printed line), because 24 images of 32 × 32 pixels are very little data. The depth map matches the true depth closely (the printed error is about 0.12 units, with the camera 4 units away), even though no depth was ever given: the network found a 3D density that explains every photo, and depth falls out of it.

SolutionB1 · All density dies

At the start every sample has some density, so each ray is partly opaque and the render is far from the white background. The fastest way to reduce the loss is to push density down everywhere, and once relu receives a negative input its output and its gradient are exactly zero. When we trained the unmodified TinyNeRF this way, density went to zero everywhere within a few hundred steps and the network rendered a black image from then on, with no gradient to recover. softplus is never exactly zero and always has a gradient, which is why later NeRF variants such as mip-NeRF use it.

## Decision

### Classify / segment LIDAR points
-> **PointNet++** or **Point Transformer**. Use voxel-based **MinkowskiNet** if points exceed 50k per frame.

### 3D object detection on LIDAR
-> **PointPillars** (fast) or **CenterPoint** (accurate).

### Reconstruct a scene from posed RGB views
- Training time tolerable (hours), max quality -> **NeRF** (reference), **Mip-NeRF 360** (unbounded scenes).
- Training time tight, real-time rendering required -> **3D Gaussian Splatting**.
- Very few views (1-5) -> **InstantSplat** or **Gaussian Splatting from few views**.

### Render a novel view from a few posed images
-> same as reconstruction, but tune renderer for speed: Instant-NGP for MLP-backed, Gaussian Splatting for rasterised.

### Mesh extraction
-> Train a NeRF / Gaussian splat, run **marching cubes** on the density field to get a mesh.

### Physics simulation / robotics grasping
-> Convert to mesh or voxel; simulators prefer explicit geometry.

## Rules

- Never recommend NeRF for real-time rendering (`latency_budget_ms < 33` => >= 30 fps) on commodity GPUs; Gaussian Splatting is the answer.
- `latency_budget_ms < 100` — require Gaussian Splatting or Instant-NGP for rendering; plain NeRF will not meet the budget.
- `latency_budget_ms >= 1000` — plain NeRF and diffusion-based methods are acceptable; quality over speed.
- For edge / mobile, avoid any NeRF / Gaussian variant above 50MB model size; recommend mesh-based methods instead.
- If `input_modality == RGB_single`, route to a monocular depth estimator first (e.g. DepthAnythingV2) before any 3D task.
- Do not output SDF for tasks that need colour; SDFs encode geometry only.

# Point Cloud Loader

Turn a folder of 3D scan files into a ready-to-train PyTorch `Dataset`.

## When to use

- Starting a new point-cloud classification / segmentation project.
- Switching between `.ply`, `.pcd`, and `.xyz` formats.
- Debugging a model that trains without error but converges poorly; often the data loader normalisation is wrong.

## Inputs

- `data_root`: folder of point-cloud files and an optional CSV with labels.
- `file_format`: ply | pcd | xyz | npy.
- `num_points`: fixed sampling size, typically 1024 or 2048.
- `augmentation`: none | rotate | jitter | mixup.

## Normalisation policy

Every production point-cloud pipeline applies in order:

1. **Centre** the cloud: subtract the centroid.
2. **Scale** to unit sphere: divide by the max distance from centre.
3. **Sample** `num_points` points. If the cloud has more, use **farthest point sampling** (FPS) for faithful shape representation or random sampling for speed. If fewer, repeat points.
4. **Shuffle** point order (order should not matter for the model anyway, but shuffling breaks accidental order dependencies).

## Output template

```python
import numpy as np
import torch
from torch.utils.data import Dataset

try:
    import open3d as o3d
    HAS_O3D = True
except ImportError:
    HAS_O3D = False

def _read_ply(path):
    if HAS_O3D:
        pc = o3d.io.read_point_cloud(path)
        return np.asarray(pc.points, dtype=np.float32)
    # Fallback: minimal ascii-ply reader
    ...

def _fps(points, k):
    idx = np.zeros(k, dtype=np.int64)
    dist = np.full(len(points), np.inf)
    seed = np.random.randint(len(points))
    idx[0] = seed
    for i in range(1, k):
        dist = np.minimum(dist, ((points - points[idx[i-1]]) ** 2).sum(axis=1))
        idx[i] = int(np.argmax(dist))
    return idx

def normalise(points):
    centre = points.mean(axis=0)
    points = points - centre
    scale = np.max(np.linalg.norm(points, axis=1))
    return points / max(scale, 1e-8)

class PointCloudDataset(Dataset):
    def __init__(self, files, labels, num_points=1024, augment=False):
        self.files = files
        self.labels = labels
        self.num_points = num_points
        self.augment = augment

    def __len__(self):
        return len(self.files)

    def __getitem__(self, i):
        pts = _read_ply(self.files[i])
        pts = normalise(pts)
        if len(pts) >= self.num_points:
            idx = _fps(pts, self.num_points)
            pts = pts[idx]
        else:
            reps = int(np.ceil(self.num_points / len(pts)))
            pts = np.tile(pts, (reps, 1))[:self.num_points]
        # Shuffle point order to break any accidental dependencies (especially
        # important when tiling repeats points in deterministic order).
        np.random.shuffle(pts)
        if self.augment:
            theta = np.random.uniform(0, 2 * np.pi)
            R = np.array([[np.cos(theta), 0, np.sin(theta)],
                          [0, 1, 0],
                          [-np.sin(theta), 0, np.cos(theta)]], dtype=np.float32)
            pts = pts @ R
            pts = pts + np.random.normal(0, 0.02, pts.shape).astype(np.float32)
        pts = np.ascontiguousarray(pts, dtype=np.float32)
        return torch.from_numpy(pts).transpose(0, 1), int(self.labels[i])
```

## Report

```
[dataset]
  files:          <N>
  format:         <ply|pcd|xyz|npy>
  points_per_sample: <int>
  normalise:      centre + unit sphere
  sampling:       FPS | random
  augmentation:   <list>
```

## Rules

- Always centre before scaling; swapping the order changes the meaning of "unit sphere".
- Prefer FPS over random sampling for shape tasks; random is fine for segmentation where every point matters anyway.
- Never augment during evaluation; only during training.
- If point cloud files include colour or normals as extra channels, extend the Dataset to return a `(3 + C, num_points)` tensor, not just xyz.
