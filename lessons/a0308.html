Terms you'll hear
Term What people say What it actually means
Weight initialization "Set starting weights randomly" The strategy for choosing initial weight values that determines whether a network can train at all
Symmetry breaking "Make neurons different" Using random initialization to ensure neurons learn distinct features instead of computing identical functions
Fan-in "Number of inputs to a neuron" The number of incoming connections, which determines how input variance accumulates in the weighted sum
Fan-out "Number of outputs from a neuron" The number of outgoing connections, relevant for maintaining gradient variance during backpropagation
Xavier/Glorot init "The sigmoid initialization" $\mathrm{Var}(w) = 2/(\text{fan} {\text{in}} + \text{fan} )$, designed to preserve variance through sigmoid and tanh activations}
Kaiming/He init "The ReLU initialization" $\mathrm{Var}(w) = 2/\text{fan}_{\text{in}}$, accounts for ReLU zeroing half the activations
Variance propagation "How signals grow or shrink through layers" The mathematical analysis of how activation variance changes layer by layer based on weight scale
Residual scaling "GPT-2's init trick" Scaling residual connection weights by $1/\sqrt{2N}$ to prevent variance growth through $N$ transformer layers
Dead network "Nothing trains" A network where poor initialization causes all gradients to be zero or all activations to saturate
Exploding activations "Values go to infinity" When weight variance is too high, causing activation magnitudes to grow exponentially through layers

The problem

In plain words first

Before training, every weight needs a starting value. If they are all equal, every neuron in a layer stays identical forever. If they are random but too large, numbers grow by the same factor at every layer and explode; too small, and they shrink to nothing. Good initialisation picks the spread of the random weights from the number of inputs each neuron has, so that the signal keeps roughly the same size from the first layer to the last. Xavier does this for tanh-like activations, Kaiming (He) for ReLU.

Initialize all weights to zero. Nothing learns. Every neuron computes the same function, receives the same gradient, and updates identically. After 10,000 epochs, your 512-neuron hidden layer is still 512 copies of the same neuron. You paid for 512 parameters and got 1.

Initialize them too large. Activations explode through the network. By layer 10, values hit 1e15. By layer 20, they overflow to infinity. Gradients follow the same trajectory in reverse.

Initialize them randomly from a standard normal distribution. Works for 3 layers. At 50 layers, the signal collapses to zero or detonates to infinity depending on whether the random scale was slightly too small or slightly too large. The boundary between "works" and "broken" is razor-thin.

Weight initialization is the most underrated decision in deep learning. Architecture gets papers. Optimizers get blog posts. Initialization gets a footnote. But get it wrong and nothing else matters -- your network is dead before training begins.

Idea 1 · The Symmetry Problem

Every neuron in a layer has the same structure: multiply inputs by weights, add bias, apply activation. If all weights start at the same value (zero is the extreme case), every neuron computes the same output. During backpropagation, every neuron receives the same gradient. During the update step, every neuron changes by the same amount.

You're stuck. The network has hundreds of parameters, but they all move in lockstep. This is called symmetry, and random initialization is the brute-force way to break it. Each neuron starts at a different point in weight space, so each learns a different feature.

But "random" is not enough. The scale of the randomness determines whether the network trains.

Idea 2 · Variance Propagation Through Layers

Consider a single layer with fan_in inputs:

z=w1​x1​+w2​x2​+⋯+wn​xn​

If each weight wi​ is drawn from a distribution with variance Var(w) and each input xi​ has variance Var(x), the output variance is:

Var(z)=fanin​⋅Var(w)⋅Var(x)

If Var(w)=1 and fanin​=512, the output variance is 512x the input variance. After 10 layers: 51210=1.2×1027. Your signal has exploded.

If Var(w)=0.001, the output variance shrinks by 0.001⋅512=0.512 per layer. After 10 layers: 0.51210=0.00013. Your signal has vanished.

The goal: choose Var(w) so that Var(z)=Var(x). Signal magnitude stays constant across layers.

Worked example
Why N(0, 1) explodes by layer 10

Width 64, ReLU, weights drawn from N(0, 1). Each weighted sum adds 64 terms, so its variance is 64 times the variance of the inputs; ReLU then zeroes half of them, halving the mean square. Net effect: the mean square grows 32 times per layer, the typical size 32​≈5.7 times. From about 3.2 after layer 1, nine more layers multiply it by 5.79≈6×106: about 107 at layer 10, exactly what the experiment below reports. Kaiming sets Var(w)=2/64, so the factor becomes 64×2/64×21​=1.

Idea 3 · Xavier/Glorot Initialization

Glorot and Bengio (2010) derived the solution for sigmoid and tanh activations. To keep variance constant in both the forward and backward pass:

Var(w)=fanin​+fanout​2​

In practice, weights are drawn from:

w∼Uniform(−limit,limit)where limit=fanin​+fanout​6​​

or:

w∼Normal(0,fanin​+fanout​2​​)

This works because sigmoid and tanh are roughly linear near zero, where properly initialized activations live. The variance stays stable through dozens of layers.

Idea 4 · Kaiming/He Initialization

ReLU kills half the outputs (everything negative becomes zero). The effective fan_in is halved because on average half the inputs are zeroed. Xavier init doesn't account for this -- it underestimates the variance needed.

He et al. (2015) adjusted the formula:

Var(w)=fanin​2​

Weights are drawn from:

w∼Normal(0,fanin​2​​)

The factor of 2 compensates for ReLU zeroing half the activations. Without it, the signal shrinks by ~0.5x per layer. With 50 layers: 0.550=8.8×10−16. Kaiming init prevents this.

Idea 5 · Transformer Initialization

GPT-2 introduced a different pattern. Residual connections add the output of each sub-layer to its input:

x=x+sublayer(x)

Each addition increases variance. With N residual layers, variance grows proportionally to N. GPT-2 scales the weights of residual layers by 1/2N​, where N is the number of layers. This keeps the accumulated signal magnitude stable.

Very deep models such as Llama 3 405B (126 layers) face the same growth, and many implementations scale the residual output weights by depth in the same spirit. Without this scaling, the residual stream would grow unbounded through 126 layers of attention and feedforward blocks.

Idea 7 · Choosing the Right Init

The same idea as a formula

Variance through one layer. For z=∑i=1nin​​wi​xi​ with independent zero-mean weights and inputs,

Var(z)=nin​Var(w)E[x2]

After L layers the signal is scaled by about (nVar(w))L (with an activation factor): above 1 it explodes, below 1 it vanishes. The fix is to choose Var(w) to make the factor 1.

Xavier / Glorot (tanh, sigmoid, linear): balancing the forward and backward passes gives Var(w)=nin​+nout​2​, e.g. uniform on ±6/(nin​+nout​)​.

Kaiming / He (ReLU): ReLU zeroes half its inputs, so E[a2]=21​Var(z); keeping the second moment constant needs

Var(w)=nin​2​

Symmetry. If all weights start equal, every unit in a layer computes the same thing and receives the same gradient forever; random initialisation breaks the tie. Biases can start at 0.

Transformers. GPT-2 initialises weights with standard deviation 0.02 and scales the output projection of each residual branch by 1/2N​ for N layers, because 2N branches add into the residual stream and their variances add.

Step 1 · Initialization Strategies

Four ways to initialize a weight matrix. Each returns a list of lists (a 2D matrix) with fan_in columns and fan_out rows.

import math
import random


def zero_init(fan_in, fan_out):
    return [[0.0 for _ in range(fan_in)] for _ in range(fan_out)]


def random_init(fan_in, fan_out, scale=1.0):
    return [[random.gauss(0, scale) for _ in range(fan_in)] for _ in range(fan_out)]


def xavier_init(fan_in, fan_out):
    std = math.sqrt(2.0 / (fan_in + fan_out))
    return [[random.gauss(0, std) for _ in range(fan_in)] for _ in range(fan_out)]


def kaiming_init(fan_in, fan_out):
    std = math.sqrt(2.0 / fan_in)
    return [[random.gauss(0, std) for _ in range(fan_in)] for _ in range(fan_out)]

Step 2 · Activation Functions

We need sigmoid, tanh, and ReLU to test each init strategy with its intended activation.

def sigmoid(x):
    x = max(-500, min(500, x))
    return 1.0 / (1.0 + math.exp(-x))


def tanh_act(x):
    return math.tanh(x)


def relu(x):
    return max(0.0, x)

Step 3 · Forward Pass Through 50 Layers

Pass random data through a deep network and measure mean activation magnitude at each layer.

def forward_deep(init_fn, activation_fn, n_layers=50, width=64, n_samples=100):
    random.seed(42)
    layer_magnitudes = []

    inputs = [[random.gauss(0, 1) for _ in range(width)] for _ in range(n_samples)]

    for layer_idx in range(n_layers):
        weights = init_fn(width, width)
        biases = [0.0] * width

        new_inputs = []
        for sample in inputs:
            output = []
            for neuron_idx in range(width):
                z = sum(weights[neuron_idx][j] * sample[j] for j in range(width)) + biases[neuron_idx]
                output.append(activation_fn(z))
            new_inputs.append(output)
        inputs = new_inputs

        magnitudes = []
        for sample in inputs:
            magnitudes.append(sum(abs(v) for v in sample) / width)
        mean_mag = sum(magnitudes) / len(magnitudes)
        layer_magnitudes.append(mean_mag)

    return layer_magnitudes

Step 5 · Symmetry Demonstration

Show that zero init produces identical neurons.

def symmetry_demo():
    random.seed(42)
    weights = zero_init(2, 4)
    biases = [0.0] * 4

    inputs = [0.5, -0.3]
    outputs = []
    for neuron_idx in range(4):
        z = sum(weights[neuron_idx][j] * inputs[j] for j in range(2)) + biases[neuron_idx]
        outputs.append(sigmoid(z))

    print("\nSymmetry Demo (4 neurons, zero init):")
    for i, out in enumerate(outputs):
        print(f"  Neuron {i}: output = {out:.6f}")
    all_same = all(abs(outputs[i] - outputs[0]) < 1e-10 for i in range(len(outputs)))
    print(f"  All identical: {all_same}")
    print(f"  Effective parameters: 1 (not {len(weights) * len(weights[0])})")

import numpy as np
import matplotlib.pyplot as plt

def deep_stats(std_of_width, act, width=64, n=100, depth=50, seed=42):
    rng = np.random.RandomState(seed)
    x = rng.randn(n, width)
    size, spread = [], []
    for _ in range(depth):
        W = rng.randn(width, width) * std_of_width(width)
        with np.errstate(all="ignore"):
            x = act(x @ W.T)
        size.append(np.abs(x).mean()); spread.append(x.std(axis=0).mean())
    return np.array(size), np.array(spread)

np_sigmoid = lambda z: 1 / (1 + np.exp(-z))
np_relu = lambda z: np.maximum(0, z)

Reading this output

Two rows that look fine on the left are dead on the right. Zero init gives exactly 0.5 everywhere because every neuron computes sigmoid(0), so the spread is exactly zero from the first layer (too small to appear on the right panel at all; on the left its line hides under Xavier + sigmoid's). Xavier + sigmoid keeps an average of 0.5 too, but the spread between inputs collapses to about 10−16 by layer 25: sigmoid's slope of 0.25 shrinks differences at every layer, and the outputs no longer depend on the input. Kaiming + ReLU and Xavier + tanh keep a real spread. Kaiming's slow drift at width 64 (down to about 0.09 by layer 50) is a finite-width effect: at width 256 and 1,024 it holds near 0.4.

Break it on purpose

Run forward_deep(xavier_init, relu): Xavier's variance with a ReLU network. What happens to the average size by layer 50, and why? (Solution B1.)

Check your mental model
  • ✗ "If the activations keep a sensible size, the initialisation is fine."
    ✓ Size is not information. Zero init and Xavier + sigmoid both keep an average of 0.5, yet every input gives the same output. Check the spread between inputs too.
  • ✗ "Kaiming keeps the signal exactly constant."
    ✓ It keeps the expected mean square constant. In a finite-width network the actual size drifts like a random walk on a log scale; the narrower the layers, the larger the drift.
  • ✗ "PyTorch initialises nn.Linear with He initialisation."
    ✓ Its default variance is 1/(3fanin​), six times smaller than He's for ReLU (see the warning under "Use it").
Recap
What to keep from this lesson
  • Equal starting weights keep neurons identical; randomness breaks the symmetry.
  • A layer multiplies the signal's variance by fanin​⋅Var(w) times the activation's own factor; keep the product at 1.
  • Xavier: Var(w)=2/(fanin​+fanout​) for tanh. Kaiming: Var(w)=2/fanin​ for ReLU.
  • Judge an initialisation by whether different inputs still give different activations deep in the network.
  • Residual networks also scale the residual branches by depth to stop the stream from growing.

Solutions

SolutionP1 · Five verdicts and a trap

N(0,1) + ReLU explodes (about 107 by layer 10). N(0,0.01) + ReLU vanishes (below 10−6 by layer 5). Kaiming + ReLU and Xavier + tanh survive (still about 0.1 and 0.06 at layer 50). The trap is the two rows that print 0.5 at every layer: zero + sigmoid and Xavier + sigmoid. A sigmoid's output sits near 0.5 whether or not the network still carries information about the input, so the average size proves nothing; the picture under Step 6 shows both are dead.

SolutionB1 · Xavier under ReLU

The average size falls from 0.39 at layer 1 to about 1.6×10−2 at layer 10, 6×10−5 at layer 25 and 3×10−9 at layer 50: it vanishes. With fan_in = fan_out = 64, Xavier's variance is 1/64, so each layer multiplies the mean square by 64×1/64×21​=21​. Over 49 layers that alone shrinks the size by 2−24.5≈4×10−8; the finite-width drift seen under Step 6 accounts for the rest. Kaiming's extra factor of 2 exists precisely to cancel ReLU's halving.

Use it: the same idea with real libraries

PyTorch provides these as built-in functions:

import torch
import torch.nn as nn

layer = nn.Linear(512, 256)

nn.init.xavier_uniform_(layer.weight)
nn.init.xavier_normal_(layer.weight)

nn.init.kaiming_uniform_(layer.weight, nonlinearity='relu')
nn.init.kaiming_normal_(layer.weight, nonlinearity='relu')

nn.init.zeros_(layer.bias)
Watch out
PyTorch's default is not He initialisation

nn.Linear calls kaiming_uniform_ with a=math.sqrt(5), which works out to Uniform(−1/fanin​​, 1/fanin​​), a variance of 1/(3fanin​). For nn.Linear(512, 256) that is 0.00065, six times smaller than He's 2/512=0.0039:

check = nn.Linear(512, 256)
print(f"PyTorch default: weight variance {check.weight.var().item():.5f}, largest |w| {check.weight.abs().max().item():.4f}")
print(f"1/(3 x 512) = {1 / (3 * 512):.5f};  He for ReLU, 2/512 = {2 / 512:.5f}")

Shallow networks train fine with it, especially with normalisation layers. For a deep plain ReLU stack, initialise explicitly with nn.init.kaiming_normal_(layer.weight, nonlinearity="relu").

When you call nn.Linear(512, 256), PyTorch defaults to Kaiming uniform initialization. That's why most simple networks "just work" -- PyTorch's default is a safe, conservative choice for shallow networks (see the warning below). But when you build custom architectures or go deeper than 20 layers, you need to understand what's happening and potentially override the default.

For transformers, HuggingFace models typically handle initialization in their _init_weights method. GPT-2's implementation scales residual projections by 1/N​. If you're building a transformer from scratch, you need to add this yourself.

Industry practice
What's current (2024–2026)
  • Normalisation choices for stability. Modern LLMs use pre-norm RMSNorm; Gemma 3, Qwen3 and OLMo 2 add QK-norm (normalising queries and keys before attention) to prevent attention logits from blowing up, and Gemma 3 replaced Gemma 2's soft-capping with it.
  • Loss spikes are watched in production. Large runs log gradient norms and restart from checkpoints when the loss spikes; Kimi K2's MuonClip was designed to keep attention logits bounded and reported no loss spikes.
  • Initialisation still matters. Scaled initialisations for residual branches (dividing by the square root of depth) are standard in LLM code.

Sources: Gemma 3 report, OLMo 2 report, Kimi K2 report.

## Diagnostic Protocol

### 1. Gather Architecture Details

Before recommending initialization, determine:
- Layer types and sizes (Linear, Conv2d, Embedding, etc.)
- Activation functions used in hidden layers
- Whether residual connections exist
- Total depth (number of weight layers)
- Framework being used (PyTorch, TensorFlow, JAX)

### 2. Match Init to Architecture

Apply these rules:

**Sigmoid or Tanh activations:**
- Use Xavier/Glorot: `Var(w) = 2 / (fan_in + fan_out)`
- PyTorch: `nn.init.xavier_normal_(layer.weight)` or `nn.init.xavier_uniform_(layer.weight)`
- Bias: initialize to zero

**ReLU, Leaky ReLU, or GELU activations:**
- Use Kaiming/He: `Var(w) = 2 / fan_in`
- PyTorch: `nn.init.kaiming_normal_(layer.weight, nonlinearity='relu')`
- Bias: initialize to zero

**Transformer with residual connections:**
- Use Kaiming for attention and feedforward weights
- Scale residual projection weights by `1/sqrt(2*N)` where N = number of layers
- Embedding layers: `Normal(0, 0.02)` is the GPT convention

**Convolutional layers:**
- Same rules as linear: Kaiming for ReLU, Xavier for sigmoid/tanh
- fan_in = channels_in * kernel_height * kernel_width

**Batch/Layer normalization:**
- Weight (gamma): initialize to 1.0
- Bias (beta): initialize to 0.0

### 3. Diagnose Common Problems

**Symptoms of bad initialization:**

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| Loss stuck at random baseline from epoch 0 | Zero init or symmetric init | Use Xavier/Kaiming random init |
| Loss immediately NaN or Inf | Scale too large, activations overflow | Reduce init scale, use Kaiming |
| Loss decreases then plateaus early | Vanishing activations in deep layers | Switch from Xavier to Kaiming for ReLU |
| Some neurons always output zero | Dead neurons from ReLU + bad init | Use Kaiming, or switch to GELU |
| Gradient magnitudes vary 1000x across layers | Inconsistent init strategy | Apply same init scheme to all layers |

### 4. Verification Steps

After applying initialization, verify with:

```python
for name, param in model.named_parameters():
    if 'weight' in name:
        print(f"{name:40s} | mean: {param.data.mean():.4e} | std: {param.data.std():.4e}")
```

Then after one forward pass:
```python
hooks = []
for name, module in model.named_modules():
    if isinstance(module, nn.Linear):
        hooks.append(module.register_forward_hook(
            lambda m, i, o, n=name: print(f"{n:30s} | act mean: {o.abs().mean():.4f} | act std: {o.std():.4f}")
        ))
```

Healthy signs:
- Activation means between 0.1 and 2.0 across all layers
- No layer with all-zero activations
- Standard deviation roughly consistent across layers

Questions from real AI engineering interviews that this lesson prepares you for. Answer out loud first, then open the worked answer.

Explain the mechanismXavier initialization sets the weight variance to 2 over the sum of fan in and fan out. Kaiming initialization sets it to 2 over fan in. Both are called variance preserving. Explain what each one preserves, where the 2 in Kaiming comes from, and what happens to a 50 layer ReLU network that starts from a plain standard normal.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. A layer's pre-activation variance is fan in times the weight variance times the input variance, so a weight variance of 1 over fan in keeps the signal size constant through a linear layer. Xavier balances that condition between the forward and the backward pass, which gives 2 divided by the total of the two fan counts, and it suits sigmoid and tanh, which are near linear around zero. ReLU zeroes half of its inputs and halves the variance at each layer, so Kaiming doubles the variance of each weight to 2 over fan in to compensate. A standard normal with a fan in of 512 multiplies the variance by 512 at every layer, and the signal explodes within a few layers.

Variance through one layer.

For z equal to the sum of w_i x_i over fan in terms with independent weights and inputs:

Var(z) = fan_in * Var(w) * Var(x)

The lesson's two failures follow at once. With Var(w) equal to 1 and a fan in of 512, each layer multiplies the variance by 512, and after 10 layers the factor is 512 to the tenth, about 1.2 times 10 to the 27. With Var(w) equal to 0.001 the factor per layer is 0.512, and after 10 layers the signal is at 0.00013 of its size. The goal is Var(z) equal to Var(x).

Xavier.

Glorot and Bengio asked for constant variance in both directions: forward through fan in, backward through fan out. The compromise is Var(w) equal to 2 over (fan in plus fan out), drawn as a normal with that variance or as a uniform with limit the square root of 6 over the same sum. It holds for sigmoid and tanh because, at a well scaled initialization, their inputs sit in the near linear region around zero.

Kaiming.

ReLU sets every negative pre-activation to zero. On average half the units are off, so the variance that reaches the next layer is half of what the linear analysis predicts. He and colleagues doubled the weight variance to cancel that: Var(w) equal to 2 over fan in. Without the 2 the signal shrinks by about 0.5 per layer, and over 50 layers that is 0.5 to the 50, about 8.8 times 10 to the minus 16. GELU and Swish use the same rule. A framework's linear layer defaults to a Kaiming uniform draw, which is why shallow networks train with no thought given to it.

The check.

Push random inputs through the untrained network and log the mean activation magnitude at each layer. The lesson's experiment prints it at layers 1, 5, 10, 25 and 50: a standard normal explodes, a normal with standard deviation 0.01 vanishes, and both Xavier with sigmoid and Kaiming with ReLU hold near 1.0 through layer 50.

Plausible wrong answers.

  • "Random is random, the scale does not matter if it is small." Too small vanishes and too large explodes; the lesson shows both, and the margin is thin at 50 layers.
  • "Xavier works for ReLU too, the difference is minor." Xavier under-estimates the variance ReLU needs by a factor of 2, and over 50 layers the signal falls to about 8.8 times 10 to the minus 16.
  • "Kaiming's 2 stands for the forward and backward passes." That 2 compensates for ReLU zeroing half the activations; Xavier's 2 is the one that balances the two passes.

Follow-ups an interviewer may ask.

  • (level 2) Why does zero initialization fail even though its variance stays constant? Expected: every neuron computes the same function and receives the same gradient, so the layer has one effective neuron; random weights break the symmetry.
  • (level 3) Which initialization goes with GELU? Expected: Kaiming, as for ReLU.
  • (level 3) How do you verify an initialization without training? Expected: push random data through the network and log the mean activation magnitude per layer; it should stay in a band such as 0.5 to 2.0 at every depth.
  • (level 4) Why do residual networks need a further scale beyond Kaiming? Expected: each residual addition adds variance, so the stream grows with the layer count; the GPT-2 scheme scales residual weights by 1 over the square root of 2N.

Explain the mechanismA transformer with Kaiming-initialized weights trains without trouble at 20 layers and diverges at 126 layers with the same recipe. Nothing else changed. Explain why depth breaks it even with a variance preserving initialization, and what the GPT-2 style fix does.

Level 3 of 4 · about 12 minutes to answer well.

Short answer. Kaiming keeps the variance constant through each sub-layer, but a residual block adds the sub-layer's output back onto its input, and the variance of a sum of independent terms adds. With N residual additions the stream's variance grows in proportion to N, so a deeper stack carries a larger residual signal, and the attention logits and feed-forward activations built from it grow with it. The GPT-2 fix scales the weights of the layers that write into the residual stream by 1 over the square root of 2N, so the accumulated variance stays the same at any depth.

Two kinds of variance preservation.

Kaiming answers one question: how to draw weights so that a matrix multiply followed by a ReLU returns a signal with the same variance it received. It knows nothing about what happens next. In a residual block the next thing is an addition:

x = x + sublayer(x)

If the sub-layer output has about the same variance as x and is roughly independent of it, the sum has about twice the variance. Each block adds again. After N additions the stream has grown in proportion to N. The lesson states this directly: each addition increases variance, and with N residual layers the variance grows proportionally to N.

Why it shows up as depth.

At 20 layers the growth is a modest factor and the optimizer copes. At 126 layers, the depth the lesson cites for a 405B parameter model, the stream is large enough at initialization that the softmax inside attention and the activations in the feed-forward blocks run far from their intended range, and the first updates are oversized. Without a correction, the lesson says, the residual stream would grow without bound through the stack.

The fix.

GPT-2 scales the weights of the residual projections, the layers that write into the stream, by 1 over the square root of 2N, where N is the number of layers. The 2 counts the two writes per layer, one from attention and one from the feed-forward block. The sum of 2N contributions each scaled by that factor has the same variance as one, so the stream stays in range at any depth. The lesson notes that the 405B model uses a similar scheme and that a transformer built from scratch must add this scaling itself.

How to confirm before you change anything.

Push random tokens through the untrained model and log the residual stream magnitude at each layer. Growth with depth confirms the diagnosis. Run it again with the scaling and the curve should be flat. The lesson's exercise does exactly this over 50 layers.

Plausible wrong answers.

  • "Deeper models just need a smaller learning rate." A smaller rate slows the growth of the weights; it does nothing about the variance that accumulates in the forward pass at initialization.
  • "Kaiming is variance preserving, so depth cannot be the issue." It preserves variance through each sub-layer, not through the sum of a sub-layer and its input.
  • "Divide the residual stream by N at the output." The fix has to act where the variance accumulates; scaling the writers keeps every intermediate layer in range, not only the last one.

Follow-ups an interviewer may ask.

  • (level 3) Why does Kaiming not account for this? Expected: it preserves variance through a matrix multiply followed by ReLU; it knows nothing about the addition that follows.
  • (level 3) Why 2N and not N? Expected: each transformer layer writes into the stream twice, once from attention and once from the feed-forward block, so N layers make 2N additions.
  • (level 4) How would you confirm the diagnosis before changing the initialization? Expected: push random input through the untrained model and log the residual stream magnitude per layer; growth with depth confirms it, and the scaled version should be flat.
  • (level 4) Does a Pre-LN layout remove the need for the scaling? Expected: it normalizes what enters each sub-layer and helps stability, but the additions into the stream sit outside the norm, so the lesson still applies the scaling to the writers.

Explain the mechanismA network with a hidden layer of 512 units is initialized with every weight and every bias at zero. Training runs for thousands of epochs and the loss barely moves. Learning rate and data both check out. What is wrong, and why does a small random perturbation of each weight fix it?

Level 2 of 4 · about 6 minutes to answer well.

Short answer. Every neuron in the layer starts identical, so each computes the same output, receives the same gradient and takes the same update. They stay identical for the whole run: the layer holds the parameters of 512 neurons and the function of one. Random initialization gives each neuron its own starting point, so the gradients differ and the neurons learn different features. The scale of that randomness then decides whether the signal survives the depth.

The symmetry.

All neurons in a layer have the same structure: a weighted sum of the same inputs, a bias, an activation. Whatever makes them different must come from the weights. If the weights are equal, the outputs are equal. Backpropagation then hands each neuron the same gradient, because each contributed the same amount to the loss. The update is the same, and the weights are equal again. Nothing in gradient descent can split them. The lesson's demo builds four zero-initialized neurons, feeds one input, prints four identical outputs, and counts one effective parameter instead of the eight that were allocated.

Why zero is only the extreme case.

Any constant initialization has the same flaw. Setting every weight to 0.5 produces 512 copies of one neuron just as zero does. Random values are the brute force way to break the tie, and they are also why two runs with different seeds learn different features.

Biases can stay at zero.

The lesson's layers draw random weights and set the biases to 0.0. That is fine: the weights already differ across neurons, so the biases do not need to.

After the symmetry is gone.

Random is not enough on its own. The variance of the draw must match the activation: Xavier for sigmoid and tanh, Kaiming for ReLU and GELU. Too small a scale and the signal vanishes through the layers; too large and it explodes. A quick check is to push random inputs through the untrained network and log the activation magnitude at each layer.

Plausible wrong answers.

  • "The learning rate is too low." Each neuron moves, but all move together; no learning rate separates identical gradients.
  • "Add more neurons." They are all the same neuron; width adds nothing without symmetry breaking.
  • "Zero init is fine for the first layer because the inputs differ." The neurons in one layer share the same inputs; what differs across neurons has to be the weights.

Follow-ups an interviewer may ask.

  • (level 2) Is it fine to set the biases to zero? Expected: yes, when the weights are random; the lesson's layers do so.
  • (level 2) Would a nonzero constant for every weight fix it? Expected: no; the neurons are still identical and move in lockstep.
  • (level 3) After the fix, the loss moves but a deeper version trains badly. What do you check next? Expected: the scale of the random draw against the activation; Xavier for sigmoid and tanh, Kaiming for ReLU, verified by activation magnitudes per layer.
  • (level 3) How does the lesson show the symmetry in a few lines? Expected: four zero-initialized neurons on one input give four identical outputs, and it counts one effective parameter instead of eight.

Q1What happens if you initialize all weights in a neural network to zero?

With zero weights, every neuron in a layer computes the same function, receives the same gradient, and updates identically. This 'symmetry' means hundreds of parameters behave as one.

Q2Why does the scale of random weight initialization matter?

Each layer multiplies variance by fan_in * Var(w). If this product is > 1, signal explodes exponentially through layers. If < 1, it vanishes. Proper initialization keeps this product at exactly 1.

Q3What is the formula for Kaiming/He initialization variance?

Kaiming init uses Var(w) = 2/fan_in. The factor of 2 compensates for ReLU zeroing half the activations (negative values become 0), which effectively halves the fan_in.

Q4When should you use Xavier/Glorot initialization instead of Kaiming/He?

Xavier init uses Var(w) = 2/(fan_in + fan_out), designed for activations that are roughly linear near zero (sigmoid, tanh). Kaiming's extra factor of 2 compensates for ReLU's half-zeroing, which Xavier doesn't need.

Q5Why does GPT-2 scale residual layer weights by 1/sqrt(2N)?

Residual connections add sublayer output to the input: x = x + sublayer(x). Each addition increases variance. With N residual layers, variance grows proportionally to N. Scaling by 1/sqrt(2N) keeps the signal stable.
