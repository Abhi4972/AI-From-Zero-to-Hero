The problem

In plain words first

Part-of-speech (POS) tagging labels every word with its grammatical role: noun, verb, adjective, and so on. Parsing goes one step further and works out how the words connect: which word is the subject of which verb, which adjective describes which noun. Both matter because the same word can play different roles ("I saw a saw"), and many later steps, from finding a word's dictionary form to pulling facts out of text, need to know which role it plays here. This lesson builds the two classic taggers from counts (the simplest possible baseline, then a hidden Markov model), measures them on a million words of real English, and then uses spaCy's parser to draw sentence structure and extract information from it.

Lesson 5.1 promised that lemmatization needs a part-of-speech tag. Without knowing running is a verb, a lemmatizer cannot reduce it to run. Without knowing better is an adjective, it cannot reduce to good.

That promise hid a whole subfield. Part-of-speech tagging assigns grammatical categories. Syntactic parsing recovers the sentence's tree structure: which word modifies which, which verb governs which arguments. Classical NLP spent twenty years refining both. Then deep learning collapsed them into a token-classification task on top of a pretrained transformer, and the research community moved on.

Not the applied community. Tags and parses are still the cheap, deterministic layer under many pipelines: lemmatization, rule-based extraction ("which adjective describes which product"), query understanding, and annotation for the hundreds of languages that have treebanks but no large model of their own.

Worth knowing. This lesson introduces the tagsets, the baselines, and the point where you stop implementing from scratch and call spaCy.

The idea

POS tagging labels each token with a grammatical category. The Penn Treebank (PTB) tagset is the English default. 36 tags with distinctions the casual reader finds fussy: NN singular noun, NNS plural noun, NNP proper noun singular, VBD verb past tense, VBZ verb 3rd person singular present, and so on. The Universal Dependencies (UD) tagset is coarser (17 tags) and language-agnostic; it became the default for cross-lingual work.

The/DET cats/NOUN were/AUX running/VERB at/ADP 3pm/NOUN ./PUNCT

Syntactic parsing produces a tree. Two major styles:

  • Constituency parsing. Noun phrases, verb phrases, prepositional phrases nest inside each other. Output is a tree of non-terminal categories (NP, VP, PP) with words as leaves.
  • Dependency parsing. Each word has a single head word it depends on, labeled with a grammatical relation. Output is a tree where every edge is a (head, dependent, relation) triple.

Dependency parsing won in the 2010s because it generalizes cleanly across languages, especially free-word-order ones.

running is ROOT
cats is nsubj of running
were is aux of running
at is prep of running
3pm is pobj of at

Step 1 · most-frequent-tag baseline

The dumbest POS tagger that works. For each word, predict the tag it had most often in training.

from collections import Counter, defaultdict


def train_mft(train_examples):
    word_tag_counts = defaultdict(Counter)
    all_tags = Counter()
    for tokens, tags in train_examples:
        for token, tag in zip(tokens, tags):
            word_tag_counts[token.lower()][tag] += 1
            all_tags[tag] += 1
    word_best = {w: c.most_common(1)[0][0] for w, c in word_tag_counts.items()}
    default_tag = all_tags.most_common(1)[0][0]
    return word_best, default_tag


def predict_mft(tokens, word_best, default_tag):
    return [word_best.get(t.lower(), default_tag) for t in tokens]

On the Brown corpus it reaches about 90% with Brown's full set of 471 tags and about 95% with the 12 coarse universal tags (both measured under "Use it"). That sounds high, but the easy words ("the", "of", ".") make up much of every sentence; the baseline is the floor below which no serious model should fall.

Step 2 · bigram HMM tagger

Model the joint probability of the sequence:

P(tags,words)=i∏​P(tagi​∣tagi−1​)⋅P(wordi​∣tagi​)

Two tables: transition probabilities (tag given previous tag), emission probabilities (word given tag). Estimate both from counts with Laplace smoothing. Decode with Viterbi (dynamic programming over the tag lattice).

import math


def train_hmm(train_examples, alpha=0.01):
    transitions = defaultdict(Counter)
    emissions = defaultdict(Counter)
    tags = set()
    vocab = set()

    for tokens, ts in train_examples:
        prev = "<BOS>"
        for token, tag in zip(tokens, ts):
            transitions[prev][tag] += 1
            emissions[tag][token.lower()] += 1
            tags.add(tag)
            vocab.add(token.lower())
            prev = tag
        transitions[prev]["<EOS>"] += 1

    return transitions, emissions, tags, vocab


def log_prob(table, given, key, smooth_denom, alpha):
    return math.log((table[given].get(key, 0) + alpha) / smooth_denom)


def viterbi(tokens, transitions, emissions, tags, vocab, alpha=0.01):
    tags_list = list(tags)
    n = len(tokens)
    V = [[0.0] * len(tags_list) for _ in range(n)]
    back = [[0] * len(tags_list) for _ in range(n)]

    for j, tag in enumerate(tags_list):
        em_denom = sum(emissions[tag].values()) + alpha * (len(vocab) + 1)
        tr_denom = sum(transitions["<BOS>"].values()) + alpha * (len(tags_list) + 1)
        tr = log_prob(transitions, "<BOS>", tag, tr_denom, alpha)
        em = log_prob(emissions, tag, tokens[0].lower(), em_denom, alpha)
        V[0][j] = tr + em
        back[0][j] = 0

    for i in range(1, n):
        for j, tag in enumerate(tags_list):
            em_denom = sum(emissions[tag].values()) + alpha * (len(vocab) + 1)
            em = log_prob(emissions, tag, tokens[i].lower(), em_denom, alpha)
            best_prev = 0
            best_score = -1e30
            for k, prev_tag in enumerate(tags_list):
                tr_denom = sum(transitions[prev_tag].values()) + alpha * (len(tags_list) + 1)
                tr = log_prob(transitions, prev_tag, tag, tr_denom, alpha)
                score = V[i - 1][k] + tr + em
                if score > best_score:
                    best_score = score
                    best_prev = k
            V[i][j] = best_score
            back[i][j] = best_prev

    last_best = max(range(len(tags_list)), key=lambda j: V[n - 1][j])
    path = [last_best]
    for i in range(n - 1, 0, -1):
        path.append(back[i][path[-1]])
    return [tags_list[j] for j in reversed(path)]

With the 12 universal tags, the bigram HMM reaches about 96% under "Use it", a modest gain over the baseline that comes from transition probabilities: the model learns DET NOUN is common and NOUN DET is rare. The same run shows its weak spot, words it never saw in training.

Worked example
One Viterbi step by hand

Two tags, N (noun) and V (verb), and the sentence "can fish". Made-up probabilities:

start → → N → V P(can | tag) P(fish | tag)
N 0.6 0.3 0.7 0.1 0.4
V 0.4 0.8 0.2 0.3 0.2
  • Word 1, "can": N scores 0.6×0.1=0.06; V scores 0.4×0.3=0.12.
  • Word 2, "fish" as N: best previous is V, 0.12×0.8=0.096, times P(fish∣N)=0.4 gives 0.0384. (From N: 0.06×0.3=0.018, smaller.)
  • "fish" as V: best previous is N, 0.06×0.7=0.042, times 0.2 gives 0.0084.

The best final score is 0.0384, and following the back-pointer gives "can/V fish/N". Viterbi keeps only the best path into each tag at each word, so the work grows with (words × tags²), not with the number of possible tag sequences (tags^words). The lesson's code does the same with logarithms, so the products become sums and never underflow.

Check your mental model
  • ✗ "95% tagging accuracy means 1 word in 20 is hard."
    ✓ Most tokens are easy ("the", ".", "of"). The errors pile up on the hard part: ambiguous and unknown words, where accuracy is far lower.
  • ✗ "An HMM always beats the most-frequent-tag baseline."
    ✓ Overall it does, a little. On words never seen in training it does worse under "Use it", because its smoothing gives an unknown word the same tiny emission probability under every tag, which then favours rare tags.
  • ✗ "A POS tag is a property of the word."
    ✓ It is a property of the word in this sentence: "saw", "can", "fish" and "man" all change tag with context.

Break it on purpose

In viterbi, replace both emission lines with em = 0.0, so the words themselves are ignored and only the transition table is used. What tags come out for "I saw the movie yesterday ." and for "The quick brown fox jumps over the lazy dog ."? (Solution B1.)

The same idea as a formula
The Viterbi recursion

Let δt​(j) be the score of the best tag sequence for the first t words that ends in tag j. With transitions aij​=P(j∣i) and emissions bj​(w)=P(w∣j):

δ1​(j)=logaBOS,j​+logbj​(w1​),δt​(j)=imax​[δt−1​(i)+logaij​]+logbj​(wt​)

and the back-pointer ψt​(j)=argmaxi​[δt−1​(i)+logaij​] records which i won. The best final tag is argmaxj​δn​(j); following ψ backwards recovers the whole sequence. This works because the best path to tag j at word t must extend the best path to some tag at t−1 (an optimal path's prefixes are optimal), so only K partial paths survive per word. Cost: O(nK2) instead of Kn; for 12 tags and a 20-word sentence, 2,880 steps instead of 3.8×1021.

Step 3 · why modern taggers beat this

Transition + emission probabilities are local. They cannot capture that saw is a noun in "I bought a saw" but a verb in "I saw the movie." On the Penn Treebank's Wall Street Journal test set, a CRF or maximum-entropy tagger with rich features (suffix, word shape, neighbouring words) reaches about 97.3%, and BiLSTM or transformer taggers about 97.5 to 98%.

The ceiling on this task is set by annotator disagreement. Human annotators agree about 97% of the time on Penn Treebank. Scores much above that mostly mean a model has learned the quirks of one test set's annotators.

Step 4 · dependency parsing sketch

Full dependency parsing from scratch is out of scope; the canonical textbook treatment is in Jurafsky and Martin. Two classical families to know:

  • Transition-based parsers (arc-eager, arc-standard) act like a shift-reduce parser: they read tokens, shift them onto a stack, and apply reduce actions that create arcs. Greedy decoding is fast. Classic implementation is MaltParser. Modern neural version: Chen and Manning's transition-based parser.
  • Graph-based parsers (Eisner's algorithm, Dozat-Manning biaffine) score every possible head-dependent edge and pick the maximum spanning tree. Slower but more accurate.

Worked example
An arc-standard parse by hand

A transition-based parser keeps a stack, a buffer of unread words and a set of arcs, and applies one of three actions: SHIFT (move the next word to the stack), LEFT-ARC (the top word becomes head of the word below it, which is popped) and RIGHT-ARC (the word below becomes head of the top word, which is popped). For "cats chase mice":

Step Stack Buffer Action Arc added
1 [] cats chase mice SHIFT
2 [cats] chase mice SHIFT
3 [cats, chase] mice LEFT-ARC chase → cats (nsubj)
4 [chase] mice SHIFT
5 [chase, mice] RIGHT-ARC chase → mice (obj)
6 [chase] done: chase is the root

A sentence of n words always takes 2n−1 actions here (n shifts and n−1 arcs; parsers that start with a ROOT symbol on the stack add one more arc, for 2n), so parsing is linear time. The model's only job is to pick the next action from the current stack and buffer; Chen and Manning (2014) made that choice with a small neural network, which is close to what spaCy's parser does today.

Use it: the same idea with real libraries

Every production NLP library ships POS and dependency parsers as part of a standard pipeline.

  • spaCy (en_core_web_sm / md / lg / trf). Fast, accurate, integrated with tokenization + NER + lemmatization. token.tag_ (Penn), token.pos_ (UD), token.dep_ (dependency relation).
  • Stanford NLP (stanza). Stanford's successor to CoreNLP. State-of-the-art on 60+ languages.
  • trankit. Transformer-based, good UD accuracy.
  • NLTK. pos_tag. Usable, slow, older. Fine for teaching.

import time
import random
import nltk
import numpy as np
import matplotlib.pyplot as plt
from nltk.corpus import brown
nltk.download("brown", quiet=True); nltk.download("universal_tagset", quiet=True)

def split(sents):
    sents = [list(s) for s in sents]
    random.Random(0).shuffle(sents)
    return [([w for w, _ in s], [t for _, t in s]) for s in sents[500:]], [([w for w, _ in s], [t for _, t in s]) for s in sents[:500]]

train_u, test_u = split(brown.tagged_sents(tagset="universal"))
word_best, default_tag = train_mft(train_u)
transitions, emissions, tags, vocab = train_hmm(train_u)
print(f"{len(train_u):,} training sentences, {len(test_u)} test; tags: {' '.join(sorted(tags))}")

def accuracy(tagger, test):
    right = known_right = unk_right = unk = n = 0
    for toks, gold in test:
        for w, g, p in zip(toks, gold, tagger(toks)):
            n += 1; right += g == p
            if w.lower() in vocab:
                known_right += g == p
            else:
                unk += 1; unk_right += g == p
    return right / n, known_right / (n - unk), unk_right / unk, unk, n

start = time.time()
scores = {"most frequent tag": accuracy(lambda t: predict_mft(t, word_best, default_tag), test_u)}
scores["bigram HMM"] = accuracy(lambda t: viterbi(t, transitions, emissions, tags, vocab), test_u)
for name, (a, k, u, n_unk, n) in scores.items():
    print(f"   {name:18s} all {a:.1%}   known words {k:.1%}   unknown words {u:.1%}")
print(f"   ({n_unk} of {n:,} test words are unknown; Viterbi on 500 sentences took {time.time() - start:.0f} s)")

train_f, test_f = split(brown.tagged_sents())
wb_full, dt_full = train_mft(train_f)
full = sum(g == p for toks, gold in test_f for g, p in zip(gold, predict_mft(toks, wb_full, dt_full))) / sum(len(g) for _, g in test_f)
print(f"\nmost frequent tag with Brown's full tagset ({len({t for _, ts in train_f for t in ts})} tags): {full:.1%}")

print("\nambiguous words in context (HMM | most frequent tag):")
for s in ["I bought a saw at the store .", "I saw the movie yesterday .", "They can fish .", "The old man the boats ."]:
    t = s.split()
    print("  ", " ".join(f"{w}/{h}" for w, h in zip(t, viterbi(t, transitions, emissions, tags, vocab))),
          "|", " ".join(predict_mft(t, word_best, default_tag)))

In the arc diagram every word except the root has exactly one head: "camera" is the subject (nsubj) of "takes", "photos" its object, "sharp" modifies "photos", and "in low light" hangs off the verb. That single-head structure is what makes parses easy to query. The review sentence turns into aspect-opinion pairs with two rules over the parse, the start of aspect-based sentiment from Lesson 5.5. The query becomes structured constraints, each name attached to the verb that governs it, exactly the "query understanding" use listed below; check the printed pairs, because a small parser gets attachments in long phrases wrong now and then. The last two lines are Lesson 5.1's promise kept: without a POS tag the WordNet lemmatizer leaves "were", "hanging" and "ate" alone; with spaCy's tags it gives "be", "hang", "eat" and turns "better" into "good".

Industry practice
What's current (2024–2026)
  • Universal Dependencies keeps growing. Release 2.19 (November 2026) has over 200 treebanks in over 150 languages, all with the same 17 POS tags and relation labels, which is what makes cross-lingual tools like spaCy, Stanza and trankit possible.
  • Parsers next to LLMs. LLMs can tag and parse when asked, but a pipeline that needs the same structure millions of times a day, deterministically and in milliseconds, still runs a dedicated parser; the LLM handles the open-ended parts.
  • Transformer pipelines are the default. spaCy's *_trf and Stanza's models put a pretrained transformer under the tagger and parser; the small CNN-based *_sm pipeline used here trades a few points of accuracy for speed.

Source: Universal Dependencies.

Where this still matters in 2026

  • Lemmatization. Lesson 5.1 needs POS to lemmatize correctly. Always.
  • Structured extraction from LLM outputs. Validate that a generated sentence respects grammatical constraints (e.g., subject-verb agreement, required modifiers).
  • Aspect-based sentiment. Dependency parses tell you which adjective modifies which noun.
  • Query understanding. "movies directed by Wes Anderson starring Bill Murray" decomposes into structured constraints via the parse.
  • Cross-lingual transfer. UD tags and dependency relations are language-agnostic, enabling zero-shot structured analysis of new languages.
  • Low-compute pipelines. If you cannot ship a transformer, POS + dependency parse + gazetteer gets you surprisingly far.
Recap
What to keep from this lesson
  • POS tags label grammatical role in context; UD's 17 tags work across languages, Penn Treebank's 36 are English-specific.
  • The most-frequent-tag baseline is strong (about 95% on coarse tags); measure every tagger against it.
  • An HMM multiplies transition and emission probabilities and decodes with Viterbi in words × tags² time.
  • Unknown words and context-dependent ambiguity are where simple taggers fail; features (CRF) and context (transformers) fix them.
  • A dependency parse gives each word one head and a relation; simple rules over it extract aspects, query constraints and lemmas.

Solutions

SolutionP1 · The baseline wins on unknown words

The most-frequent-tag baseline is right on roughly 60% of unknown words, simply because most unknown words are nouns, while the HMM gets well under half of them. With add-alpha smoothing, an unseen word's emission probability is about alpha divided by the tag's total count, which is larger for rare tags, so the HMM drifts toward rare tags exactly when it knows least. Real HMM taggers fix this with a separate model for unknown words based on suffixes and capitalisation, the same trick as the shape feature in Lesson 5.6.

SolutionB1 · The same tags for every sentence of the same length

With no emission term, the words have no influence, and Viterbi returns the single most probable tag chain from the transition table: DET NOUN ADP DET NOUN … for any sentence of that length. "I saw the movie yesterday ." and "The quick brown fox jumps over the lazy dog ." come out as the same repeating pattern. The transition table only knows what tag sequences look like; the emissions are what tie the tags to the actual words.
