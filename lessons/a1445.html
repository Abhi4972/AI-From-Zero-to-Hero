The idea in one line

Parallel agents save wall time only when the work is independent. Otherwise they convert one clear task into a coordination problem with a faster failure rate.

The Parallelism Test

In plain words first

Delegation means handing parts of one change to separate workers, whether agents or people. It only saves time when the parts are truly independent: each worker owns files nobody else touches, has its own proof, and works to an interface fixed before anyone starts (the merge contract). An integrator then checks each handoff against its unit, merges in dependency order and runs the whole gate. Multi-agent systems and harnesses are covered in Lessons 14.12 and 14.70 (linked above). This lesson runs two model workers in two real git worktrees, with and without a merge contract.

Do not delegate because more agents are available. Delegate when at least one of these is true:

  • two investigations can answer different unknowns independently;
  • two implementations own disjoint files and contracts;
  • a reviewer can inspect a completed artifact without changing it;
  • a slow external check can run while local work continues.

Keep work serial when agents need the same files, the same unresolved decision, or the same mutable environment.

A Work Unit Is a Contract

Each delegated unit needs:

Field Meaning
Goal One observable result
Owner One accountable worker
Paths Exclusive write ownership
Dependencies Completed units required before starting
Proof Exact evidence returned to the integrator
Handoff Files changed, decisions made, remaining risk

“Handle the backend” is not a work unit. “Implement the duplicate check in app/accounts.py and prove it with the focused account test” is.

Isolation Has Three Layers

  1. Filesystem isolation: separate worktrees or sandboxes prevent accidental shared edits.
  2. Ownership isolation: contracts prevent two workers from intentionally editing the same path.
  3. State isolation: separate logs and outputs prevent one worker from overwriting another worker’s evidence.

Filesystem isolation does not solve ownership. Two clean worktrees can still produce conflicting designs. The merge contract must resolve shared interfaces before work begins.

The Integrator Does Not Rebuild the Work

The integrator should:

  1. confirm each handoff matches its assigned scope;
  2. read the proof output, not just the worker’s summary;
  3. combine changes in dependency order;
  4. run the full cross-unit gate;
  5. reject hidden scope expansion;
  6. record conflicts as new decisions, not silent edits.

If integration requires rewriting most of a worker’s result, the original decomposition was wrong.

Human and Agent Roles

Delegation does not remove human judgment. The human still owns choices that change public behavior, risk, authority, or irreversible cost. Agents can own bounded investigation, implementation, verification, and review.

This is calibrated autonomy: the system grants freedom where evidence and rollback are strong, and requires a checkpoint where consequence is high.

The same idea as a formula

Parallel speed-up is capped by what must stay serial. If a change takes T when done alone and a fraction s of it cannot be split, n workers give at best

Tn​=sT+n(1−s)T​+C(n),

where C(n) is the coordination cost: writing contracts, integrating, and redoing work that conflicts.

Ownership is a disjointness condition. Units U1​,…,Un​ with path sets P1​,…,Pn​ are safe to run together only if no path in one equals or contains a path in another:

∀i=j, ∀a∈Pi​, b∈Pj​: a⪯b and b⪯a,

where a⪯b means "a is b or a parent folder of b". That is the check paths_overlap() performs.

Worked example
Two units and an integrator
  • Say the change takes 30 minutes alone, a 5-minute contract must come first (s=1/6), and integration costs 5 minutes. With 2 workers: T2​=5+25/2+5=22.5 minutes.
  • With 8 workers: 5+25/8+C(8). If each extra worker adds 2 minutes of integration, C(8)=5+12=17, so T8​≈25 minutes. That is slower than 2.
  • Ownership: api owns app/accounts.py and tests/test_accounts.py; docs owns docs/api.md. Disjoint, so they share one wave.
  • Give docs app/ as well, and app/ is a parent of app/accounts.py, so the plan is blocked.
Check your mental model
  • ✗ "Separate worktrees make the work independent."
    ✓ They stop accidental edits. They do not stop two workers choosing different error codes.
  • ✗ "Each unit's proof passed, so the merge is fine."
    ✓ Both units passed and the cross-unit docs check still failed.
  • ✗ "The integrator should fix small mismatches itself."
    ✓ Send the unit back with the finding. If integration means rewriting, the split was wrong.
  • ✗ "More workers, more speed."
    ✓ The serial part and the coordination cost grow too.

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")

def chat(prompt, n=300, k=1):
    ids = tok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True)["input_ids"]
    torch.manual_seed(0)
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=n, do_sample=k > 1, temperature=0.8 if k > 1 else None,
                           top_p=0.95 if k > 1 else None, top_k=None, num_return_sequences=k)
    texts = [tok.decode(o[ids.shape[1]:], skip_special_tokens=True) for o in out]
    return texts if k > 1 else texts[0]

def sh(cmd, cwd):
    p = subprocess.run(cmd, cwd=cwd, shell=isinstance(cmd, str), capture_output=True, text=True, timeout=60)
    return p.returncode, (p.stdout + p.stderr).strip()

def make_repo():
    root = pathlib.Path(tempfile.mkdtemp()) / "main"
    for path, text in {"app/__init__.py": "", "app/accounts.py": ACCOUNTS, "tests/__init__.py": "", "tests/test_accounts.py": TESTS,
                       "docs/api.md": DOCS, "scripts/check_docs.py": CHECK_DOCS}.items():
        (root / path).parent.mkdir(parents=True, exist_ok=True); (root / path).write_text(text)
    for c in ("git init -q -b main", "git -c user.email=a@b -c user.name=lesson add -A",
              "git -c user.email=a@b -c user.name=lesson commit -qm base"):
        sh(c, root)
    return root

def worker_api(tree, contract):
    # the worker samples 4 candidates and keeps the first one its own proof accepts (up to 2 rounds)
    task = ("Make create_account refuse an email that already has an account (check `email in store.rows` after normalizing)" +
            (f": return {{\"status\": 409, \"error\": {{\"code\": \"email_taken\", \"message\": \"...\"}}}} instead of creating it."
             if contract else ". Return an error result instead of raising."))
    extra, log = "", []
    for round_ in range(1, 3):
        texts = chat(f"You own app/accounts.py:\n```python\n{ACCOUNTS}```\nTask: {task}\n{extra}"
                     "Return only the new create_account function in a ```python block.", k=4)
        for text in texts:
            m = re.search(r"```(?:python)?\n(.*?)(?:```|$)", text, re.S)
            fn = (m.group(1) if m else "").strip()
            if "def create_account" not in fn:
                log.append("no fn"); continue
            fn = fn[fn.find("def create_account"):].split("\ndef ", 1)[0].rstrip()
            (tree / "app/accounts.py").write_text(ACCOUNTS.split("def create_account")[0] + fn + "\n")
            rc, out = sh(UNITS[0].proof, tree)
            log.append(rc)
            if rc == 0:
                return log
        err = [l for l in out.splitlines() if re.match(r"^\w+(Error|Exception)\b", l)] if "out" in dir() else []
        extra = f"A previous version failed the test with: {(err or ['the test'])[-1][:150]}\nFix it. "
    return log

def worker_docs(tree, contract):
    ask = ("Write one sentence to add under '## POST /accounts' documenting what happens when the email already has an account"
           + (f": {contract}" if contract else "") + ". Mention the status code and the error code in backticks. "
           "Return only the sentence.")
    sentence = chat(f"docs/api.md:\n{DOCS}\n{ask}", n=80).strip().splitlines()[0]
    p = tree / "docs/api.md"
    p.write_text(p.read_text().replace("normalized email.\n", f"normalized email.\n\n{sentence}\n"))
    rc, out = sh(UNITS[1].proof, tree)
    return [rc], sentence

def changed(tree):
    return sh("git diff --name-only main", tree)[1].split()

# Lesson program for delegating work with isolated ownership boundaries.
# Read: phases/14-agent-engineering/45-delegate-with-isolation/docs/en.md
# Reference: Git worktree documentation, git-scm.com/docs/git-worktree.
# Reference: Lamport, Time, Clocks, and the Ordering of Events, 1978.
# Run this file to generate outputs/delegation-plan.json.
from __future__ import annotations

import json
from dataclasses import asdict, dataclass
from pathlib import Path, PurePosixPath


@dataclass(frozen=True)
class WorkUnit:
    id: str
    owner: str
    paths: tuple[str, ...]
    depends_on: tuple[str, ...]
    proof: str


def paths_overlap(left: str, right: str) -> bool:
    a = PurePosixPath(left)
    b = PurePosixPath(right)
    return a == b or a in b.parents or b in a.parents


def conflicts(units: list[WorkUnit]) -> list[str]:
    found: list[str] = []
    for index, left in enumerate(units):
        for right in units[index + 1:]:
            for left_path in left.paths:
                for right_path in right.paths:
                    if paths_overlap(left_path, right_path):
                        found.append(f"{left.id} and {right.id} overlap at {left_path} / {right_path}")
    return found


def waves(units: list[WorkUnit]) -> list[list[str]]:
    remaining = {unit.id: set(unit.depends_on) for unit in units}
    known = set(remaining)
    if any(not deps <= known for deps in remaining.values()):
        raise ValueError("unknown dependency")
    done: set[str] = set()
    result: list[list[str]] = []
    while remaining:
        ready = sorted(key for key, deps in remaining.items() if deps <= done)
        if not ready:
            raise ValueError("dependency cycle")
        result.append(ready)
        done.update(ready)
        for key in ready:
            del remaining[key]
    return result


def delegation_plan(units: list[WorkUnit]) -> dict:
    ids = [unit.id for unit in units]
    duplicate_ids = sorted({unit_id for unit_id in ids if ids.count(unit_id) > 1})
    overlap = conflicts(units)
    missing_proof = [unit.id for unit in units if not unit.proof.strip()]
    return {
        "status": "ready" if not duplicate_ids and not overlap and not missing_proof else "blocked",
        "duplicate_ids": duplicate_ids,
        "conflicts": overlap,
        "missing_proof": missing_proof,
        "waves": waves(units) if not duplicate_ids else [],
        "units": [asdict(unit) for unit in units],
    }

def example() -> list[WorkUnit]:
    return [
        WorkUnit("api", "worker-api", ("app/api", "tests/test_api.py"), (), "python3 -m unittest tests.test_api"),

def main() -> None:
    output = Path(__file__).resolve().parents[1] / "outputs" / "delegation-plan.json"

Exercises

  1. Decompose a real change into two independent work units and one integrator.
  2. Find a proposed parallel split that only looks independent. State the shared decision.
  3. Add a read-only research worker whose output is a fact table.
  4. Add a merge gate that checks the final changed-file set against all unit contracts.
  5. Define a cancellation rule for a worker whose dependency becomes invalid.

Solutions

SolutionP1 · Units pass, integration does not

With the contract, both unit proofs pass and the integration gate fails. The docs sentence never names email_taken, and the api worker added an internal_error code. Without the contract, the api unit fails its own proof on all 6 candidates, so the unit tests fail after the merge.

Neither run passes integration. Unit proofs check each worker's slice. Only the cross-unit gate checks that the slices agree.

SolutionB1 · No contract, shared files

The split looked parallel but shared two things: the error shape and types.ts. Before any agent starts, the plan needs a contract unit that fixes the response shape (for example {"error": {"code", "message"}}) and writes the shared type once. Every other unit depends on it.

types.ts gets one owner, or it becomes part of the contract unit, so that no two units can write it; paths_overlap() would have flagged the shared path. Each unit's proof should test against the contract's shape, and the integration gate should run the frontend against the real API response. Whatever extra shapes an agent adds go back to that agent as findings.

What You Keep

Keep outputs/delegation-plan.json. It records why the split is safe, who owns each path, and what proof integration must receive.

Break it on purpose

You launch four coding agents on one feature: API, frontend, docs and tests, each in its own worktree. All four report "done, tests pass". At integration the frontend expects errors[], the API returns error, the tests assert a third shape, and two agents edited the shared types.ts. Using this lesson, what went wrong before anyone wrote code? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Worktrees per agent. Claude Code documents parallel sessions in git worktrees (claude --worktree <name>). Cursor 2.0 (October 2025) runs up to eight agents on one prompt, each in its own worktree or on a remote machine.
  • Subagents for bounded work. Claude Code subagents run in their own context window with their own tools and permissions. Use them for research or review that returns a result, not for writes to shared files.
  • Cloud tasks in containers. Codex cloud tasks and similar background agents each run in a separate sandbox and return a branch or PR. The merge and its gate stay with you or CI.
  • On your laptop: worktrees are plain git. The 0.5B workers run on CPU one after the other, so the parallelism here is logical, not wall-clock.

Sources: Claude Code, Common workflows (worktrees), Claude Code, Subagents, Cursor 2.0 changelog, git worktree.

Recap
What to keep from this lesson
  • Delegate only independent work: disjoint paths, separate proofs, a fixed interface.
  • Write the merge contract before work starts: shapes, codes, names.
  • The integrator checks scope, merges in order and runs the cross-unit gate.
  • Send failing units back with the finding; don't rewrite them.
  • Anything a worker adds beyond the contract is a scope finding, even if it looks helpful.
