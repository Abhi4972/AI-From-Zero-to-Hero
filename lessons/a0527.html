The problem

In plain words first

Once a system writes free text, "is this answer right?" stops being a string comparison. A correct answer can share few words with the reference, and a wrong one can share almost all of them. This lesson builds the scores teams use instead. Faithfulness asks whether every claim in the answer is backed by the retrieved text. Answer relevance asks whether it answers the question asked. Context precision and recall ask whether retrieval found the right passages. An LLM-as-judge scores anything you can describe in a rubric. Each of these is itself a model that can be wrong, so the lesson also covers the step people skip: checking the judge against human ratings, measuring its biases, and deciding when a drop in a score is a real regression and when it is noise. All models here run locally and only for inference: a 0.5-billion-parameter instruction model plays the LLM and the judge.

Your RAG system answers: "June 29th, 2007." The gold reference is: "June 29, 2007." Exact Match scores 0. Token F1 scores 67%. A human would score 100%.

Now multiply by 10,000 test cases. Multiply again by every change to the retriever, chunking, prompt, or model. You need an evaluator that understands meaning, runs cheaply at scale, does not lie about regressions, and surfaces the right failure modes.

Three widely used tools address this problem: two libraries and one method.

  • RAGAS. Retrieval-Augmented Generation ASsessment. Four RAG metrics (faithfulness, answer-relevance, context-precision, context-recall) with NLI + LLM-judge backends. Research-backed, lightweight.
  • DeepEval. Pytest for LLMs. G-Eval, task-completion, hallucination, bias metrics. CI/CD-native.
  • G-Eval. A method (and a DeepEval metric): LLM-as-judge with chain-of-thought, custom criteria, 0-1 score.

All three lean on LLM-as-judge. This lesson builds intuition for the method and the trust layer around it.

Exact match and token F1 on answers a person would mark right or wrong

SQuAD's normalisation and scores from Lesson 5.19, against the reference "June 29, 2007."

import re, string
from collections import Counter

def normalize(s):                      # SQuAD's answer normalisation (Lesson 5.19)
    s = s.lower()
    s = "".join(ch for ch in s if ch not in set(string.punctuation))
    s = re.sub(r"\b(a|an|the)\b", " ", s)
    return " ".join(s.split())

def exact_match(pred, gold):
    return float(normalize(pred) == normalize(gold))

def token_f1(pred, gold):
    p, g = normalize(pred).split(), normalize(gold).split()
    common = sum((Counter(p) & Counter(g)).values())
    if common == 0:
        return 0.0
    prec, rec = common / len(p), common / len(g)
    return 2 * prec * rec / (prec + rec)

gold = "June 29, 2007."
for pred in ["June 29th, 2007.", "29 June 2007", "2007-06-29", "It came out on June 29, 2007.",
             "June 29, 2008.", "Not June 29, 2007."]:
    print(f"{pred:32s} EM {exact_match(pred, gold):.0f}   F1 {token_f1(pred, gold):.2f}")

The idea

LLM-as-judge. Replace a static metric with an LLM that scores outputs given a rubric. Given (query, context, answer), prompt a judge LLM: "Score 0-1 on faithfulness." Return the score.

Why it works: LLMs approximate human judgment at a tiny fraction of the cost. At, for example, 1 dollar per million input tokens and 5 dollars per million output tokens, a judge call with about 2,000 tokens in and 200 out costs $0.003 per scored case, so a 1,000-case regression run costs about 3 dollars, under $5.

Why it fails silently:

  1. Judge bias. Judges prefer longer answers, answers from their own model family, answers that match the prompt style.
  2. JSON parsing failures. Bad JSON → NaN score → silently excluded from the aggregate. RAGAS users know this pain. Gate with try/except + explicit failure mode.
  3. Drift over model versions. Upgrading the judge changes every metric. Freeze judge model + version.

The RAG four.

Metric Question Backend
Faithfulness Does each claim in the answer come from the retrieved context? An LLM splits the answer into claims and checks each against the context (an NLI-style verdict; RAGAS also offers Vectara's HHEM classifier for the check)
Answer relevance Does the answer address the question? Generate hypothetical questions from answer; compare to real question
Context precision Were the relevant chunks ranked near the top? LLM-judge per chunk, then a rank-weighted average
Context recall Did retrieval return everything needed? LLM-judge against gold answer

G-Eval. Define a custom criterion: "Did the answer cite the correct source?" The framework auto-expands into chain-of-thought evaluation steps, then scores 0-1. Good for domain-specific quality dimensions RAGAS does not cover.

Calibration. Never trust the raw judge score until you have a correlation against human labels. Run 100 hand-labeled examples. Plot judge vs human. Compute Spearman rho. Many teams treat rho of about 0.7 as a target, but know what is achievable: in the G-Eval paper, GPT-4 as judge reached an average rho of 0.514 with expert ratings on the SummEval summarisation benchmark, against 0.192 for ROUGE-1. Compare your judge with how well two humans agree, and report an interval, not just a number.

The same idea as a formula

Overlap scores. With normalised token multisets p (prediction) and g (gold), EM=[p=g] and

F1=P+R2PR​,P=∣p∣∣p∩g∣​,R=∣g∣∣p∩g∣​

Faithfulness. Split the answer into claims c1​,…,cm​ and ask whether the context C entails each:

Faith=m1​i=1∑m​[PNLI​(entail∣C,ci​)>0.5]

Answer relevance (RAGAS). Generate n questions q^​j​ that the answer would answer, embed them, and compare with the real question q: AR=n1​∑j​cos(E(q),E(q^​j​)).

Context precision@K (RAGAS) rewards relevant chunks ranked early. With vk​=1 if the chunk at rank k is relevant:

CP@K=∑k=1K​vk​∑k=1K​Precision@k⋅vk​​

Context recall = share of the reference answer's claims that can be attributed to the retrieved context.

G-Eval's score. Instead of the single score the judge writes, take the probability it gives each allowed score si​ (for example 1 to 5) and average:

score=i∑​p(si​)si​

This turns a coarse integer into a continuous value and breaks ties.

Calibration uses Spearman's rank correlation; without ties, with di​ the difference between item i's rank under the judge and under humans,

ρ=1−n(n2−1)6∑i​di2​​

Is a change real? A pass rate p^​ measured on n independent cases has standard error p^​(1−p^​)/n​; a 95% interval is about ±1.96 standard errors. For comparing two versions on the same cases, bootstrap the per-case differences, which is tighter because case difficulty cancels.

Worked example
F1, a rank correlation and a sample size by hand

Token F1. "June 29th, 2007." normalises to {june, 29th, 2007}; the gold to {june, 29, 2007}. Two tokens match: P=R=2/3, so F1=2/3=0.67. The lesson's original "~75%" was too generous.

Spearman. A judge scores five answers 0.9, 0.4, 0.8, 0.2, 0.7; humans gave 5, 2, 3, 1, 4. Judge ranks (1 = lowest): 5, 2, 4, 1, 3. Human ranks: 5, 2, 3, 1, 4. Differences: 0, 0, 1, 0, −1, so ∑d2=2 and ρ=1−6⋅2/(5⋅24)=1−0.1=0.9. One swapped pair costs 0.1 with five items; with only five items, though, ρ is very noisy.

How many test cases? A pass rate of 0.85 on n=100 cases has standard error 0.85×0.15/100​=0.036, so the 95% interval is about ±0.07: a drop from 0.85 to 0.82 is invisible. To get the interval down to ±0.03 you need n=1.962×0.1275/0.032≈544 cases, or a paired comparison on the same cases.

Judge cost. N cases × (input tokens × input price + output tokens × output price). For 1,000 cases of 2,000 input and 200 output tokens at 1 and 5 dollars per million tokens: 1000×(0.002+0.001)=3 dollars per run.

Check your mental model
  • ✗ "A judge score of 0.85 means 85% of answers are good."
    ✓ It means 0.85 on that judge's scale. Until it is calibrated against human labels, you do not know what it corresponds to.
  • ✗ "Faithful means correct."
    ✓ Faithful means supported by the retrieved context. If retrieval returned a wrong passage, a faithful answer repeats the error.
  • ✗ "The mean dropped from 0.86 to 0.84, so we regressed."
    ✓ Check the interval first. On 100 cases, that difference is usually noise.

Step 1 · faithfulness with NLI (RAGAS-style)

import re
from typing import Callable
import torch
from transformers import pipeline, AutoTokenizer, AutoModelForCausalLM

# The lesson's model, MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli, is a 1.7 GB download;
# this page uses the smaller NLI model from Lessons 5.30 and 5.26. The code is the same.
nli = pipeline("text-classification",
               model="MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7",
               top_k=None)

# `llm` is any callable: prompt str -> generated str.
# Example: llm = lambda p: client.messages.create(model="claude-haiku-4-5", ...).content[0].text
# Here: a 0.5B instruction-tuned model running locally, greedy decoding.
LLM = Callable[[str], str]
_qtok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
_qlm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct", dtype=torch.float32).eval()


def llm(prompt: str, max_new_tokens: int = 150) -> str:
    ids = _qtok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True,
                                    return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = _qlm.generate(ids, max_new_tokens=max_new_tokens, do_sample=False)
    return _qtok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()


def atomic_claims(answer: str, llm: LLM) -> list[str]:
    prompt = f"""Break this answer into simple factual claims (one per line):
{answer}
"""
    return [re.sub(r"^\s*(?:\d+[.)]|[-•*])\s*", "", c).strip() for c in llm(prompt).splitlines() if c.strip()]


def faithfulness(answer: str, context: str, llm: LLM) -> float:
    claims = atomic_claims(answer, llm)
    if not claims:
        return 0.0
    supported = 0
    for claim in claims:
        result = nli({"text": context, "text_pair": claim})   # top_k=None: one score per label
        entail = next((s for s in result if s["label"] == "entailment"), None)
        if entail and entail["score"] > 0.5:
            supported += 1
    return supported / len(claims)


context = "Apple released the first iPhone on June 29, 2007. The moon landing was in 1969."
for answer in ["The first iPhone was released on June 29, 2007.",
               "The first iPhone launched on June 29, 2006, shortly after the moon landing."]:
    print(answer)
    print("   claims:", atomic_claims(answer, llm))
    print("   faithfulness:", faithfulness(answer, context, llm))

Decompose the answer into atomic claims. NLI-check each claim against the retrieved context. Faithfulness = fraction supported.

Reading this output

The correct answer becomes one claim, entailed by the context: faithfulness 1.0. The wrong-year answer becomes two claims and neither is entailed: 0.0. Look at the second claim, though: "It followed the Moon Landing event of that year." The answer said "shortly after the moon landing"; "of that year" was added by the 0.5B model while splitting. Claim decomposition is itself generation, and a weak decomposer can invent content that the NLI step then rejects, lowering a score for something the answer never said. Production setups use a stronger model for this step and spot-check the claims. Two small fixes were needed for the code to run with current libraries: list markers ("1.", "-") are stripped from each claim, and the pipeline's result is used directly, because with top_k=None a single input now returns its list of label scores (indexing [0] would pick one label's dictionary).

Break it on purpose

Make the evaluator fail instead of the system: call faithfulness("The first iPhone was released on June 29, 2007.", context, lambda p: ""), an LLM that returns nothing. What score comes back, and how would it look inside an average over 1,000 cases? (Solution B1.)

Step 2 · answer relevance

import numpy as np
from sentence_transformers import SentenceTransformer

# encoder: any model implementing .encode(texts, normalize_embeddings=True) -> ndarray
# e.g., encoder = SentenceTransformer("BAAI/bge-small-en-v1.5")

def answer_relevance(question: str, answer: str, encoder, llm: LLM, n: int = 3) -> float:
    prompt = f"Write {n} questions this answer could be the answer to:\n{answer}"
    generated = [line for line in llm(prompt).splitlines() if line.strip()][:n]
    if not generated:
        return 0.0
    q_emb = np.asarray(encoder.encode([question], normalize_embeddings=True)[0])
    g_embs = np.asarray(encoder.encode(generated, normalize_embeddings=True))
    sims = [float(q_emb @ g_emb) for g_emb in g_embs]
    return sum(sims) / len(sims)

If the answer implies different questions than the one asked, relevance drops.

Calibration: three cheap scores against human ratings

SummEval (Fabbri et al., 2021) has expert ratings of summaries of CNN/DailyMail news articles, including consistency: is every fact in the summary supported by the article? This run takes 8 articles × 16 system summaries and asks how well three automatic scores rank them in the same order as the experts, with a 95% interval from resampling whole articles.

def rho_with_ci(scores, n_boot=1000, seed=0):
    """Spearman rho with humans, and a 95% interval from resampling whole articles."""
    rng = np.random.default_rng(seed)
    boot = []
    for _ in range(n_boot):
        pick = np.concatenate([np.where(art == d)[0] for d in rng.integers(0, 8, 8)])
        boot.append(spearmanr(scores[pick], human[pick]).statistic)
    return spearmanr(scores, human).statistic, np.nanpercentile(boot, [2.5, 97.5])

G-Eval from scratch, with and without probability weighting

The same consistency question as a G-Eval prompt (criterion plus three evaluation steps) to the 0.5B model. One forward pass per summary; the code reads the probabilities of the tokens "1" to "5" and computes both the most likely score and the probability-weighted score. First 4 articles (64 summaries), to keep the run short on a CPU.

STEPS = ("Evaluation steps:\n1. Read the news article and note its main facts.\n"
         "2. Read the summary and check each of its statements against the article.\n"
         "3. Give a consistency score from 1 (many statements not supported by the article) "
         "to 5 (every statement supported).")
score_ids = [_qtok.encode(str(s), add_special_tokens=False)[0] for s in range(1, 6)]

def g_eval(article, summary):
    prompt = (f"You will be given a news article and a summary of it. Rate the summary's factual consistency.\n\n{STEPS}\n\n"
              f"Article: {article[:1200]}\n\nSummary: {summary}\n\nAnswer with the score only (1-5).")
    ids = _qtok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True,
                                    return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        logits = _qlm(ids).logits[0, -1]
    p = torch.softmax(logits[score_ids], -1)               # probabilities of the five score tokens
    return float((p * torch.arange(1, 6)).sum()), int(p.argmax()) + 1

sub = [i for i, r in enumerate(rows) if r[0] < 4]        # the first 4 articles (64 summaries) keep this under 3 minutes on a CPU
t0 = time.time()
weighted, argmax = zip(*[g_eval(se[rows[i][0]]["text"], rows[i][1]) for i in sub])
weighted, argmax = np.array(weighted), np.array(argmax)
print(f"judged {len(sub)} summaries in {time.time() - t0:.0f} s; argmax scores used: {dict(sorted(Counter(argmax.tolist()).items()))}")
for name, s in [("lexical faithfulness (main.py)", judges["lexical faithfulness (main.py)"][sub]),
                ("0.5B judge, most likely score", argmax), ("0.5B judge, probability-weighted", weighted)]:
    print(f"{name:34s} Spearman rho with humans = {spearmanr(s, human[sub]).statistic:.2f}")

The judge almost never uses the middle of the scale (the most likely score is 1, 4 or 5), so many summaries tie. A regression gate that knows about noise

SummEval rated 16 systems on the same 100 articles; each column of the consistency table is one system. Treat one system as yesterday's build and another as today's, and decide with a paired bootstrap of the per-article differences and a check on the share of bad outputs.

# SummEval rated 16 summarisation systems on the same 100 articles. Treat two of them as
# "yesterday's build" and "today's build" and run a regression gate on the human scores.
C = np.array(se["consistency"])                 # shape (100 articles, 16 systems)
means = C.mean(0)
order = np.argsort(-means)
print("mean consistency per system, best first:", np.round(means[order], 2))

def gate(old, new, n_boot=2000, max_drop=0.05, seed=0):
    rng = np.random.default_rng(seed)
    diff = C[:, new] - C[:, old]                # paired: same articles, two systems
    boot = [diff[rng.integers(0, len(diff), len(diff))].mean() for _ in range(n_boot)]
    lo, hi = np.percentile(boot, [2.5, 97.5])
    bad_old, bad_new = (C[:, old] <= 2).mean(), (C[:, new] <= 2).mean()
    verdict = "FAIL" if hi < -max_drop or bad_new > bad_old + 0.02 else ("PASS" if lo > -max_drop else "INCONCLUSIVE")
    print(f"old system {old:2d} -> new {new:2d}: mean {C[:, old].mean():.2f} -> {C[:, new].mean():.2f}, "
          f"change 95% interval [{lo:+.2f}, {hi:+.2f}], share scored <=2: {bad_old:.0%} -> {bad_new:.0%}   {verdict}")

gate(order[0], order[1])          # two strong systems
gate(order[3], order[8])          # a middle-ranked replacement
gate(order[0], order[-1])         # the best replaced by the worst

def lexical_answer_relevance(question, answer):
    q_tokens, a_tokens = set(tokenize(question)), set(tokenize(answer))
    if not q_tokens or not a_tokens:
        return 0.0
    return len(q_tokens & a_tokens) / len(q_tokens | a_tokens)

Position and verbosity bias in a pairwise judge

Ten easy questions, each with a correct and a wrong answer. The judge sees both and must reply A or B; the code compares the probabilities of "A" and "B". Every pair is judged twice, once in each order, then again with the wrong answer padded with a confident-sounding sentence.

# Pairwise judging: the same two answers, shown in both orders.
pairs = [("What is the capital of Australia?", "Canberra.", "Sydney."),
         ("How many legs does a spider have?", "Eight.", "Six."),
         ("Who wrote Pride and Prejudice?", "Jane Austen.", "Charlotte Brontë."),
         ("What is the boiling point of water at sea level in Celsius?", "100 °C.", "90 °C."),
         ("Which gas do plants absorb for photosynthesis?", "Carbon dioxide.", "Oxygen."),
         ("What is 12 times 12?", "144.", "124."),
         ("Which planet is closest to the Sun?", "Mercury.", "Venus."),
         ("In which year did the Berlin Wall fall?", "1989.", "1991."),
         ("What is the largest ocean on Earth?", "The Pacific Ocean.", "The Atlantic Ocean."),
         ("What is the chemical symbol for gold?", "Au.", "Ag.")]
padding = " It is a well-known fact that is taught in schools around the world, and experts agree on it."

A_id = _qtok.encode("A", add_special_tokens=False)[0]
B_id = _qtok.encode("B", add_special_tokens=False)[0]

def prefer_first(question, first, second):
    prompt = (f"Question: {question}\n\nAnswer A: {first}\n\nAnswer B: {second}\n\n"
              "Which answer is correct? Reply with the single letter A or B.")
    ids = _qtok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True,
                                    return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        logits = _qlm(ids).logits[0, -1]
    return float(torch.softmax(logits[[A_id, B_id]], -1)[0])      # P(A) among {A, B}

for label, pad in [("short answers", ""), ("wrong answer padded with confident filler", padding)]:
    right_first = right_second = consistent = 0
    for q, good, bad in pairs:
        p1 = prefer_first(q, good, bad + pad)      # correct answer shown as A
        p2 = prefer_first(q, bad + pad, good)      # correct answer shown as B
        right_first += p1 > 0.5
        right_second += p2 < 0.5
        consistent += (p1 > 0.5) == (p2 < 0.5)
    print(f"{label}: correct picked when shown first {right_first}/10, when shown second {right_second}/10, "
          f"same verdict in both orders {consistent}/10")

Industry practice
What's current (2024–2026)
  • Library APIs keep moving. RAGAS's collections-based metrics (ragas.metrics.collections) replace the older imports, deprecated in 0.4 and due to be removed in 1.0, and RAGAS offers a faithfulness variant that uses Vectara's HHEM-2.1-Open classifier instead of an LLM call per claim. DeepEval's current docs build G-Eval with SingleTurnParams and accept either a criterion or evaluation steps, not both. Pin versions in CI.
  • Evaluation platforms in production. LangSmith, Langfuse, Braintrust, Arize Phoenix and MLflow 3's GenAI evaluation store datasets, run judges on every change and on samples of live traffic, and track scores per release.
  • Judge bias is measured, not assumed. Position bias and self-preference are routinely tested; the usual practice is to swap orders, mix judge families and report agreement with humans alongside every score.

Sources: RAGAS faithfulness docs, DeepEval G-Eval docs, MLflow 3, Langfuse evaluation, Judging LLM-as-a-Judge, SummEval.

Pitfalls

  • No calibration. A judge with 0.3 correlation to human labels is noise. Require a calibration run before shipping.
  • Self-evaluation. Judges tend to favour their own outputs. In Zheng et al. (2023), GPT-4 gave its own answers about a 10% higher win rate than humans did, and Claude-v1 about 25%, though the authors note their data was too limited to be sure; Panickssery et al. (2024) link this self-preference to models recognising their own text. Use a different model family for the judge.
  • Positional bias in pairwise judging. Judges prefer one position. In Zheng et al. (2023), GPT-4 gave the same verdict after the two answers were swapped in 65% of cases; the 0.5B judge below, in none. Always run both orders and count disagreement as a tie.
  • Raw aggregate hides failures. Mean score 0.85 often hides 5% catastrophic failures. Always inspect the bottom quantile.
  • Golden dataset rot. Unversioned eval sets that drift over time break longitudinal comparison. Tag the dataset with every change.
  • LLM cost. At scale, judge calls dominate cost. Use the cheapest model that meets the calibration threshold; the small, cheap tier of a major provider is usually the place to start.

Recap
What to keep from this lesson
  • Overlap scores (EM, F1) miss paraphrases and reward wrong answers that share words; use them only as a sanity check.
  • Faithfulness = share of the answer's claims entailed by the context; answer relevance compares the real question with questions the answer implies; context precision and recall score the retriever.
  • Every judge, including an LLM, is a model: calibrate it against human labels (Spearman ρ with an interval) before trusting it.
  • Run pairwise judgments in both orders; use a judge from a different family than the system under test.
  • Gate on intervals and on the share of bad outputs, not on raw means.

  2. Medium. Hand-label 50 QA answers 0-1 for correctness. Score with G-Eval. Measure Spearman rho between judge and human.

Solutions

SolutionP1 · Always "A"

It picks the correct answer only when it is shown first (10 of 10) and never when it is shown second, so it gives the same verdict in both orders 0 times out of 10. The 0.5B model answers "A" whatever the content. This is position bias in its purest form, and it is invisible unless you swap the order.

SolutionB1 · An evaluator failure that looks like a score

atomic_claims gets an empty reply and returns no claims, and faithfulness returns 0.0. Inside an average that is indistinguishable from "every claim was unsupported": ten such failures in 1,000 cases lower the mean by up to 0.01 and leave no trace, and a broken judge API would look like a collapse of the system. Return None (or raise) when the evaluator fails, count failures separately, and alert when their rate rises, as the lesson's JSON-parsing pitfall says.
