Why this came about

Through the 1990s and 2000s, networks deeper than a few layers would barely train, and the reason was found by Sepp Hochreiter in 1991: gradients shrink (or blow up) as they pass back through many layers. A series of practical fixes in the 2010s changed that. Xavier and He initialisation (2010, 2015) chose starting weights that keep signals a steady size; ReLU (popularised in 2011) avoided flat regions; batch normalisation (2015) and layer normalisation (2016) rescaled values inside the network; residual connections (ResNet, 2015) let a 152-layer network win the ImageNet competition; and the Adam optimiser (2014) gave every weight its own step size. A transformer block (Chapter F6) is these ideas assembled: LayerNorm, a residual connection, and training with AdamW and a warm-up schedule.

In plain words first
A message passed down a long line of people

Whisper a message down a line of twenty people. If each person speaks a little more quietly than they heard, the message fades to nothing; if each speaks a little louder, it ends as a shout. Training a deep network sends signals forwards (the predictions) and backwards (the gradients) through every layer, with the same problem. The fixes are: start everyone at the right volume (initialisation), have each person re-adjust the volume before passing it on (normalisation), and add a direct line that skips past everyone so the original message always gets through (residual connections).

Step 1 · Signals that vanish or explode

Push random data through 20 ReLU layers of 256 neurons each, with weights drawn at three different sizes, and watch the spread (standard deviation) of the values:

import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(size=(500, 256))               # 500 examples, 256 features, spread about 1

for name, scale in [("too large: weights ~ N(0, 1)", lambda n: 1.0),
                    ("too small: weights ~ N(0, 0.01)", lambda n: 0.01),
                    ("He init: weights ~ N(0, sqrt(2/n))", lambda n: np.sqrt(2 / n))]:
    h, spreads = x, []
    for layer in range(1, 21):
        W = rng.normal(0, scale(256), size=(256, 256))
        h = np.maximum(0, h @ W)              # a ReLU layer
        if layer in (1, 5, 10, 20):
            spreads.append(f"{h.std():.3g}")
    print(f"{name:<36} spread after layers 1, 5, 10, 20: {spreads}")
What you should see
too large: weights ~ N(0, 1)         spread after layers 1, 5, 10, 20: ['9.35', '1.69e+05', '3.45e+10', '1.3e+21']
too small: weights ~ N(0, 0.01)      spread after layers 1, 5, 10, 20: ['0.094', '1.55e-05', '3.28e-10', '1.04e-19']
He init: weights ~ N(0, sqrt(2/n))   spread after layers 1, 5, 10, 20: ['0.822', '0.771', '0.699', '0.514']
Reading this output
  • Too large: each layer multiplies the size by about 11, so after 20 layers the values reach 10²¹. Training would produce inf and nan at once.
  • Too small: each layer shrinks the values about tenfold, down to 10⁻¹⁹. The network's output ignores its input.
  • He initialisation (Kaiming He and colleagues, 2015) draws weights with spread √(2 / inputs). Each of 256 inputs adds a little to a neuron's sum, and ReLU zeroes about half; this size exactly balances both, so values stay around 0.5 to 0.8 even after 20 layers.
  • PyTorch's nn.Linear already uses an initialisation of this family, so you rarely set it by hand. But when a deep model's outputs are all the same or all nan, initialisation is a suspect.

Step 2 · Deep, plain networks do not train

Here is that measurement as code, then a real training run. Both networks have 20 hidden layers of 64 neurons:

import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

digits = load_digits()
X_train, X_val, y_train, y_val = train_test_split(digits.data / 16.0, digits.target, test_size=0.2, random_state=0)
X_train, X_val = torch.tensor(X_train, dtype=torch.float32), torch.tensor(X_val, dtype=torch.float32)
y_train, y_val = torch.tensor(y_train), torch.tensor(y_val)
loss_fn = nn.CrossEntropyLoss()

class PlainDeep(nn.Module):
    def __init__(self, depth=20, width=64):
        super().__init__()
        self.inp = nn.Linear(64, width)
        self.blocks = nn.ModuleList([nn.Linear(width, width) for _ in range(depth)])   # a list of layers
        self.out = nn.Linear(width, 10)
    def forward(self, x):
        h = torch.sigmoid(self.inp(x))
        for layer in self.blocks:
            h = torch.sigmoid(layer(h))
        return self.out(h)

def first_and_last_gradients(model):
    model.zero_grad()
    loss_fn(model(X_train[:256]), y_train[:256]).backward()
    return model.blocks[0].weight.grad.norm().item(), model.blocks[-1].weight.grad.norm().item()

def train(model, epochs=15):
    loader = DataLoader(TensorDataset(X_train, y_train), batch_size=64, shuffle=True,
                        generator=torch.Generator().manual_seed(0))
    opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
    for _ in range(epochs):
        model.train()
        for xb, yb in loader:
            opt.zero_grad()
            loss_fn(model(xb), yb).backward()
            opt.step()
    model.eval()
    with torch.no_grad():
        return (model(X_val).argmax(dim=1) == y_val).float().mean().item()

torch.manual_seed(0)
plain = PlainDeep()
first, last = first_and_last_gradients(plain)
print(f"plain: gradient at layer 1 {first:.2g}, at layer 20 {last:.2g}")
print(f"plain: validation accuracy after 15 epochs {train(plain):.3f}")
What you should see
plain: gradient at layer 1 2.7e-18, at layer 20 0.047
plain: validation accuracy after 15 epochs 0.075

The first layer receives a gradient of about 10⁻¹⁸, so it never changes; the network is stuck near chance (10% for ten digits), even though the same data gave 97% with a single hidden layer in Lesson F4.3. More layers made it worse, because the signal cannot get through. nn.ModuleList is a list that PyTorch knows contains layers, so their parameters are found and trained.

Step 3 · The fixes: normalisation and residual connections

Normalisation rescales values inside the network. Layer normalisation (LayerNorm) takes each example's vector of values, subtracts its mean and divides by its spread, then applies a learned scale and shift:

v = torch.tensor([[2.0, 4.0, 6.0, 100.0]])
ln = nn.LayerNorm(4)                          # learned scale starts at 1 and shift at 0
print(ln(v))
print("mean", ln(v).mean().item(), " spread", round(ln(v).std(unbiased=False).item(), 3))
What you should see
tensor([[-0.6251, -0.5770, -0.5289,  1.7310]],
       grad_fn=<NativeLayerNormBackward0>)
mean 0.0  spread 1.0

Whatever size the values arrive at, they leave with mean 0 and spread 1, so no layer can drift to huge or tiny values. Batch normalisation does the same across the examples of a batch instead of within each example; it is common in image networks, while transformers use LayerNorm or its simpler cousin RMSNormlater · F6.3.

A residual connection adds a layer's input back to its output: h = h + layer(h).

If the layer has nothing useful to add, it can output values near 0 and the block passes h through unchanged; so adding blocks can never make things much worse. On the way back, the + passes the gradient straight through to earlier layers, a "highway" around every layer. Put the two together:

class ResidualDeep(nn.Module):
    def __init__(self, depth=20, width=64):
        super().__init__()
        self.inp = nn.Linear(64, width)
        self.norms = nn.ModuleList([nn.LayerNorm(width) for _ in range(depth)])
        self.blocks = nn.ModuleList([nn.Linear(width, width) for _ in range(depth)])
        self.out = nn.Linear(width, 10)
    def forward(self, x):
        h = self.inp(x)
        for norm, layer in zip(self.norms, self.blocks):
            h = h + torch.relu(layer(norm(h)))     # normalise, transform, add back: a "pre-norm" residual block
        return self.out(h)

torch.manual_seed(0)
resnet = ResidualDeep()
first, last = first_and_last_gradients(resnet)
print(f"residual: gradient at layer 1 {first:.2g}, at layer 20 {last:.2g}")
print(f"residual: validation accuracy after 15 epochs {train(resnet):.3f}")
What you should see
residual: gradient at layer 1 4, at layer 20 1
residual: validation accuracy after 15 epochs 0.981

Same depth, same width, same data, same optimiser: 98% instead of chance. The gradient at layer 1 is now larger than at layer 20, because the residual paths deliver the signal to every layer. This "pre-normlater · F6.3 residual block" (normalise, transform, add back) is exactly the skeleton of a transformer block in Lesson F6.3; there, the transform is attention or a feed-forward networklater · F6.3.

Step 4 · Optimisers: better than plain gradient descent

Plain gradient descent uses one learning rate for every weight. Real loss landscapes are steep in some directions and shallow in others (Lesson F3.2's long thin valley), and a single rate is too big for one and too small for the other.

  • Momentum keeps a running average of recent gradients, so steps build up speed in directions that stay consistent and cancel out in directions that zig-zag.
  • Adam (2014) adds a running average of each weight's squared gradient and divides by its square root, giving every weight its own step size: weights with large, steady gradients take careful steps; weights with tiny gradients take relatively larger ones.
  • AdamW is Adam with weight decay (Step 6) applied separately. It is the default for training and fine-tuninglater · F7.2 transformers.
def grad(w):                                   # a stretched bowl: loss = 0.5 * (x² + 50 y²)
    return np.array([1.0, 50.0]) * w
def loss(w):
    return 0.5 * (w[0] ** 2 + 50 * w[1] ** 2)

def sgd(lr, steps=100, momentum=0.0):
    w, v = np.array([5.0, 1.0]), np.zeros(2)
    for _ in range(steps):
        v = momentum * v + grad(w)             # with momentum 0 this is plain gradient descent
        w = w - lr * v
    return loss(w)

def adam(lr, steps=100, b1=0.9, b2=0.999, eps=1e-8):
    w, m, v = np.array([5.0, 1.0]), np.zeros(2), np.zeros(2)
    for t in range(1, steps + 1):
        g = grad(w)
        m = b1 * m + (1 - b1) * g              # running average of the gradient (momentum)
        v = b2 * v + (1 - b2) * g ** 2         # running average of its square (per-weight scale)
        m_hat, v_hat = m / (1 - b1 ** t), v / (1 - b2 ** t)    # correct the start-up bias
        w = w - lr * m_hat / (np.sqrt(v_hat) + eps)
    return loss(w)

print(f"start loss               {loss(np.array([5.0, 1.0])):9.3f}")
print(f"SGD, lr 0.001            {sgd(0.001):9.3f}   (too small: crawls along the shallow direction)")
print(f"SGD, lr 0.039            {sgd(0.039):9.3f}   (just below the limit set by the steep direction)")
print(f"SGD, lr 0.041            {sgd(0.041):9.3g}   (just above it: diverges)")
print(f"SGD + momentum 0.9       {sgd(0.01, momentum=0.9):9.3f}")
print(f"Adam, lr 0.1             {adam(0.1):9.3f}")
What you should see
start loss                  37.500
SGD, lr 0.001               10.234   (too small: crawls along the shallow direction)
SGD, lr 0.039                0.005   (just below the limit set by the steep direction)
SGD, lr 0.041             4.32e+05   (just above it: diverges)
SGD + momentum 0.9           0.000
Adam, lr 0.1                 0.001

For plain gradient descent the steep direction (slope 50) sets the largest safe learning rate, 2 / 50 = 0.04, exactly as in Lesson F2.4. Just above it, it explodes; well below it, the shallow direction barely moves. Momentum and Adam both solve the problem.

Step 5 · Learning-rate schedules

The learning rate usually changes during training. Large models use a warm-up (rise from zero over the first steps, while Adam's running averages settle and the random starting weights get organised) and then decay slowly, often following a cosine curve, so the final steps are small and precise (Lesson F2.4's V-shaped valley showed why constant steps cannot settle).

import math

def lr_at(step, peak=3e-4, warmup=2000, total=100_000, floor=0.1):
    """Linear warm-up, then cosine decay to 10% of the peak: a common schedule for LLM training."""
    if step < warmup:
        return peak * step / warmup
    progress = (step - warmup) / (total - warmup)
    return peak * (floor + (1 - floor) * 0.5 * (1 + math.cos(math.pi * progress)))

for s in [0, 500, 2000, 25_000, 50_000, 75_000, 100_000]:
    print(f"step {s:>7,}  learning rate {lr_at(s):.2e}")
What you should see
step       0  learning rate 0.00e+00
step     500  learning rate 7.50e-05
step   2,000  learning rate 3.00e-04
step  25,000  learning rate 2.65e-04
step  50,000  learning rate 1.69e-04
step  75,000  learning rate 7.11e-05
step 100,000  learning rate 3.00e-05

In PyTorch, schedules live in torch.optim.lr_scheduler; you call scheduler.step() after each optimizer.step(). Fine-tuning (Lesson 11.10) uses the same shape over a shorter run, typically with a peak around 1e-4 to 2e-4 for LoRAlater · 11.6.

Step 6 · Regularisation and safety rails

Three more tools, each a line or two of PyTorch:

  • Weight decay: shrink every weight slightly at each step, the neural-network version of ridge regularisation (Lesson F3.5). In AdamW it is the weight_decay argument (often 0.01 to 0.1).
  • Dropout: during training, randomly set a fraction of a layer's outputs to zero, so the network cannot rely on any single neuron. At evaluation time it is switched off, which is why model.eval() matters.
  • Gradient clipping: if the gradient's overall size exceeds a limit, scale it down before the update, so one unusual batch cannot wreck training. Large models almost always clip, typically at a size of 1.0.
torch.manual_seed(0)
drop = nn.Dropout(p=0.5)
ones = torch.ones(1, 8)
drop.train()
print("training:  ", drop(ones))       # about half zeroed; survivors doubled so the average stays the same
drop.eval()
print("evaluation:", drop(ones))       # switched off

w = torch.tensor([3.0, 4.0], requires_grad=True)
(w * torch.tensor([30.0, 40.0])).sum().backward()          # a deliberately large gradient
print("gradient size before clipping:", w.grad.norm().item())
nn.utils.clip_grad_norm_([w], max_norm=1.0)                 # call between backward() and step()
print("after clipping:", w.grad, " size", round(w.grad.norm().item(), 4))
What you should see
training:   tensor([[0., 0., 2., 0., 0., 0., 2., 2.]])
evaluation: tensor([[1., 1., 1., 1., 1., 1., 1., 1.]])
gradient size before clipping: 50.0
after clipping: tensor([0.6000, 0.8000])  size 1.0

Clipping keeps the gradient's direction (30 : 40 stays 0.6 : 0.8) and caps only its size.

Step 7 · When training goes wrong: an order to try things

What you see First things to try
Loss is nan or explodes lower the learning rate; add gradient clipping; add warm-up; check inputs for huge values
Loss does not move at all check the loop (Lesson F4.3); raise the learning rate; check initialisation and that gradients are not 0
Deep model trains worse than a shallow one add residual connections and normalisation
Training loss falls, validation loss rises more data; weight decay; dropout; early stopping; a smaller model
Both losses high and flat a bigger model; train longer; better features or data

The standard advice (from Karpathy's recipe and every practitioner's experience): start from a known-good setup, change one thing at a time, and always watch both training and validation curves.

The same idea as a formula
  • He initialisation: W ~ N(0, 2 / n_in) for ReLU layers
  • LayerNorm: y = γ · (x − mean(x)) / √(var(x) + ε) + β, per example
  • pre-norm residual block: h ← h + F(LayerNorm(h))
  • momentum: v ← βv + g, w ← w − ηv
  • Adam: m ← β₁m + (1 − β₁)g, v ← β₂v + (1 − β₂)g², w ← w − η m̂ / (√v̂ + ε)
  • AdamW adds a separate decay: w ← w − ηλw

Exercises

Predict before you run

In the ResidualDeep class, what happens to accuracy if you remove the norm(...) call but keep the residual connection (h = h + torch.relu(layer(h)))? (Solution P1.)

Make it your own

Change PlainDeep to use ReLU instead of sigmoid (replace both torch.sigmoid calls with torch.relu) and train it. Does it do better than sigmoid? Then try a depth of 4. (Solution M1.)

Debugging exercise

A fine-tuning run's loss goes 2.1, 1.9, 1.8, then suddenly 9.7 and nan on one step, around step 400. The learning rate is constant at 5e-4 with no warm-up and no clipping. List two changes to try first. (Solution D1.)

Solutions

SolutionP1 · Residuals without normalisation

It still trains very well here: about 98.3%, the same as with LayerNorm. On this small problem the residual path alone keeps gradients flowing. Without normalisation, though, each block adds a ReLU output (never negative) to h, so the values in the residual streamlater · F6.3 tend to grow block after block. That matters more in wider and deeper networks trained for longer at higher learning rates, where it makes training unstable. That is why transformers use both.

SolutionM1 · ReLU, and fewer layers

At depth 20, ReLU does no better: about 8%, still chance, because gradients still shrink through 20 plain layers with PyTorch's default initialisation. At depth 4, ReLU reaches about 93% in 15 epochs, while sigmoid manages only about 19%: sigmoid's flat ends slow learning even in a fairly shallow network. That is one reason ReLU replaced sigmoid inside networks. Plain networks are fine at modest depth; residual connections are what make depth of 20, 100 or more practical.

SolutionD1 · A sudden spike

Add gradient clipping (clip_grad_norm_ with max_norm=1.0), so one unusual batch cannot produce a huge update; and lower the learning rate, ideally with a short warm-up and a decaying schedule. Also check the batch at that step for unusual data (very long or corrupted examples). Restarting from the last good checkpoint with these changes is standard practice.

Recap
  • In deep plain networks, signals and gradients shrink or blow up layer by layer; early layers stop learning.
  • Good initialisation (such as He) starts signals at a steady size; LayerNorm keeps them there throughout training.
  • Residual connections add each block's input to its output, giving gradients a highway; with LayerNorm they let very deep networks train.
  • Adam and AdamW give each weight its own step size; warm-up plus cosine decay is the common schedule.
  • Weight decay and dropout reduce overfitting, gradient clipping prevents blow-ups, and changing one thing at a time is how you debug training.
