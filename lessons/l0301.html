About the model on this page
The model on this page is a labeled stand-in

The examples run offline against FakeAnthropic, a rule-based stand-in with the same interface as anthropic.Anthropic(): client.messages.create(...) returns content blocks, a stop_reason and usage. It is not a language model. It picks replies with simple rules, so its wording is fixed and every run is identical. It does enforce the formatting rules the Claude API documents for tool results, so a malformed conversation fails here the way it fails there. Its code is in the appendix. The section The real thing runs the same function against the real Anthropic and OpenAI SDKs and lists what changes.

Why this came about

A model on its own can only produce text from what it learned. To let it look things up and act, OpenAI introduced function calling in June 2023, and other providers followed: the model returns a structured request to run a function, and your code runs it. This single capability is what turned chat models into the basis of agents.

The problem: the model cannot see your systems

A ShopKart customer writes: "Where is my order SK-1042? It was due yesterday." The answer lives in ShopKart's order service. A language model has never seen that service; it only knows what is in its training data and in the request you send. Start with the simplest thing: send the question with a good system prompt and nothing else.

That is the stand-in being honest. A real model usually is too ("I don't have access to your order details"), and sometimes it is worse: it guesses a plausible status. Either way the customer does not get an answer, and no amount of prompt wording fixes it, because the fact is not in the request. The model needs a way to ask your code for it. That is all a tool call is.

In plain words first
A manager who writes errand notes

A model cannot see your systems; it can only write text. Tool calling lets it write a very particular kind of text: a structured request ("run get_order_status with order_id A-1001"). Think of a manager who cannot leave the office and writes errand notes; your code is the assistant who runs each errand and brings back the result, matched to the note by its ID. The model never runs anything itself: every action passes through your code, which is where all the safety checks live.

Idea 1 · Describe the tool, keep the code

There are two things with the same name, and keeping them apart is most of the lesson. The function is ordinary Python that runs in your process. The tool definition is a JSON description you send to the API: a name, a description, and a JSON Schema for the arguments (input_schema). The model only ever sees the description.

import json

ORDERS = {   # ShopKart's order service, reduced to a dictionary
    "SK-1042": {"customer_id": "C-7", "status": "out for delivery", "eta": "today by 8 pm"},
    "SK-1077": {"customer_id": "C-7", "status": "delivered", "delivered_on": "2 November"},
    "SK-2001": {"customer_id": "C-9", "status": "processing", "eta": "6 November"},
}

def get_order_status(order_id: str) -> str:
    """The real function. The model never runs this; your code does."""
    order = ORDERS[order_id]
    return json.dumps({"order_id": order_id, **{k: v for k, v in order.items() if k != "customer_id"}})

ORDER_TOOL = {                                  # what the MODEL sees: a description, not the code
    "name": "get_order_status",
    "description": ("Look up the current delivery status of one ShopKart order. Use it whenever the customer "
                    "asks where an order is or when it will arrive. Order IDs look like SK-1042."),
    "input_schema": {
        "type": "object",
        "properties": {"order_id": {"type": "string", "description": "The order ID, for example SK-1042"}},
        "required": ["order_id"],
    },
}
print(get_order_status("SK-1042"))
What you should see
{"order_id": "SK-1042", "status": "out for delivery", "eta": "today by 8 pm"}

The function works on its own. The model will never see this code or this output unless your code sends the output back.

Three things about the definition matter more than they look:

  • The description is a prompt. The model decides whether and how to call a tool by reading it, so say what the tool does, when to use it, and what valid input looks like. "Order IDs look like SK-1042" will save you failed calls later.
  • The schema is a contract for the arguments, not a guarantee by default: the model fills it in, and it can get it wrong. You will see that happen below, and how to check.
  • It costs tokens on every request. The API turns your tool definitions into text the model reads, so every tool you send is paid for as input on every call, whether or not it is used.

The response is not an answer. The model cannot run anything: it produced text that your code is free to act on or ignore.

So your code acts. It needs a way to get from the name the model used to the function to call:

Python refresher
Python refresher: dispatch tables and `**` unpacking

A dispatch table is a dictionary from names to functions: TOOLS = {"get_order_status": get_order_status}. Then TOOLS["get_order_status"] is the function, and adding parentheses calls it. ** unpacks a dictionary into keyword arguments: if args = {"order_id": "SK-1042"}, then f(**args) is the same as f(order_id="SK-1042"). Together, TOOLS[block.name](**block.input) calls whichever function the model named, with the arguments it chose. That one line is why the tool's input_schema property names must match the function's parameter names.

TOOLS = {"get_order_status": get_order_status}  # name the model uses -> function your code calls

messages.append({"role": "assistant", "content": response.content})   # 1. keep the model's turn, tool_use included
results = []
for block in response.content:
    if block.type == "tool_use":
        output = TOOLS[block.name](**block.input)                     # 2. YOUR code runs the function
        results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
messages.append({"role": "user", "content": results})                # 3. results go back in a user turn
print(json.dumps(results, indent=1))

Three appends, in this order, and each one matters:

  1. The assistant turn goes back in whole, text and tool_use blocks together. The API checks that every result answers a request it can see in the previous message.
  2. Your code runs the function. This is the only line where anything happens in the world, and it is entirely under your control: you can refuse, ask a person first, or log it.
  3. The results go back as a user message of tool_result blocks, each carrying the tool_use_id of the request it answers. The content is a string here; it can also be a list of text, image or document blocks.

Idea 3 · Send the result back, get the answer

Your code has now run the function and appended the result to the list of messages. Send the whole list again. The model reads its own request, sees the result underneath it, and writes the answer in ordinary text. The small show function then prints the finished conversation exactly as the API sees it, so you can count the four messages of one round trip.

The whole round trip as one function

Now put the three steps in a function you can call for any question, with a trace line per request so you can see what happened. Two decisions are built in: a hard cap on requests (a model that keeps asking for tools must not run forever or bill forever), and a rule that every tool request gets a result, even when the function fails, because a request with no result is a conversation the API will reject.

def answer(question, tools=(ORDER_TOOL,), trace=True):
    """One complete round trip: ask, run any requested tools, send results, return the final text."""
    messages = [{"role": "user", "content": question}]
    tokens = 0
    for request_no in (1, 2, 3, 4):                              # at most four requests, then stop
        response = client.messages.create(model=MODEL, max_tokens=500, system=SYSTEM,
                                          tools=list(tools), messages=messages)
        tokens += response.usage.input_tokens + response.usage.output_tokens
        if trace:
            asked = [f"{b.name}({b.input})" for b in response.content if b.type == "tool_use"]
            print(f"  request {request_no}: stop_reason={response.stop_reason} {asked or ''}")
        if response.stop_reason != "tool_use":
            return response.content[-1].text, tokens
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": [run_tool(b) for b in response.content if b.type == "tool_use"]})
    return "Stopped: too many tool requests.", tokens

def run_tool(block):
    """Turn one tool_use block into one tool_result block. Every call gets a result, even a failed one."""
    try:
        output = TOOLS[block.name](**block.input)
        return {"type": "tool_result", "tool_use_id": block.id, "content": output}
    except Exception as e:
        return {"type": "tool_result", "tool_use_id": block.id, "content": f"{type(e).__name__}: {e}", "is_error": True}

text, tokens = answer("Where is my order SK-1042? It was due yesterday.")
print(text, f"(about {tokens} tokens)")

When tool calls go wrong

Bad arguments, and other customers' data

Fix both failures inside the tool, where they belong. The format check returns a message that tells the model how to fix its input. The ownership check uses the customer ID from your session, never from anything the model wrote, and it gives the same message for "does not exist" and "not yours", so the tool cannot be used to discover which order IDs exist.

import re
SESSION = {"customer_id": "C-7"}       # who is logged in comes from YOUR app, never from the model

def get_order_status(order_id: str) -> str:
    if not re.fullmatch(r"SK-\d{4}", order_id):
        raise ValueError(f"order_id must look like SK-1234, got {order_id!r}")   # tells the model how to fix it
    order = ORDERS.get(order_id)
    if order is None or order["customer_id"] != SESSION["customer_id"]:
        raise LookupError(f"no order {order_id} on this customer's account")       # same message: no leak
    return json.dumps({"order_id": order_id, **{k: v for k, v in order.items() if k != "customer_id"}})

Two lines from this section are worth memorizing. Schema validity is not business validity: even when the API guarantees that order_id is a string matching your schema, only your code can check that the order exists and belongs to this customer. And identity comes from the session, not the prompt: if the tool took a customer_id argument, a customer could simply ask the model to use someone else's.

Slow tools: put a deadline on every call

The carrier's tracking service is having a bad day and takes three seconds to answer. Without a deadline, your customer waits as long as the slowest dependency.

Python refresher
Python refresher: `concurrent.futures`

ThreadPoolExecutor runs functions in worker threads. pool.submit(fn, **kwargs) starts fn in a worker and returns a future, a handle to a result that is not ready yet. future.result(timeout=1.0) waits up to one second: it returns the value if the function finished, re-raises the function's exception if it failed, and raises TimeoutError if time ran out. That last case is what turns a hung dependency into an error you can handle.

import time
from concurrent.futures import ThreadPoolExecutor, TimeoutError as ToolTimeout

def get_order_status_slow(order_id: str) -> str:
    time.sleep(3)                                    # the carrier's tracking API is having a bad day
    return get_order_status(order_id)

POOL = ThreadPoolExecutor(max_workers=4)

def run_tool(block, timeout_s=1.0):
    """Same contract as before, plus a deadline: a slow tool becomes an error result, not a frozen app."""
    future = POOL.submit(TOOLS[block.name], **block.input)       # starts the call in a worker thread
    try:
        output = future.result(timeout=timeout_s)                  # wait at most timeout_s seconds
        return {"type": "tool_result", "tool_use_id": block.id, "content": output}
    except ToolTimeout:
        return {"type": "tool_result", "tool_use_id": block.id, "is_error": True,
                "content": f"order service timed out after {timeout_s:.0f} s; ask the customer to try again shortly"}
    except Exception as e:
        return {"type": "tool_result", "tool_use_id": block.id, "content": f"{type(e).__name__}: {e}", "is_error": True}

TOOLS["get_order_status"] = get_order_status_slow

What changes when the model is real:

  • Behavior. Wording varies from run to run. The model may answer without a tool, call one with a missing or invented ID, ask a clarifying question, or call two tools when you expected one. Your validation and every-request-gets-a-result rule are what keep those cases safe.
  • Setup. An API key in the environment, a pinned model ID, and SDK versions you control. On Claude, strict: true on a tool definition enables schema validation of tool inputs. On Claude Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1, forcing a tool with tool_choice any or tool returns a 400 error; the documented alternative is auto with strict tool use. On OpenAI, set strict explicitly; strict modelater · 14.58 requires additionalProperties: false.
  • Evaluation. Run each question several times and grade facts, not wording, exactly as run_eval does. A question that passes four times out of five is a reliability problem, not a pass (pass^k, Chapter 12).
  • Cost. Two or more requests per question, each re-sending the system prompt, the tool definitions and the growing history. Prompt caching cuts the repeated part; fewer, clearer tools cut the rest.

Explain the mechanismWalk me through exactly what happens when an LLM "calls a tool".

Worked answer. The application sends the conversation plus tool definitions: a name, a description and a JSON Schema for the arguments. The model reads the definitions as part of its input and, if it decides a tool is needed, returns a structured request instead of a final answer: on Claude a tool_use block with an id, name and input, and stop_reason: "tool_use". The application runs the matching function itself, then sends a new request containing the whole history plus a tool_result that references the request's id. The model reads the result and either answers or asks for another tool. The model never executes code; the API holds no state between requests unless you opt into a server-side feature; and every check lives in the application.

A plausible wrong answer. "The model calls the API or function directly." It sounds right because frameworks hide the loop, but it leads to the wrong security model: if you believe the model executes calls, you look for safety in the prompt instead of in the code that actually runs them.

Follow-ups. Why does the second request contain the first? What happens if a tool raises an exception? How does the model choose between two tools with similar descriptions? What does strict: true change, and what does it not?

Explain the mechanismWhat does tool_choice control, and what would you use on Claude Sonnet 5.5?

Worked answer. It controls whether and which tools the model must use: auto (the default when tools are given) lets it decide, any forces some tool, tool forces a named one, and none forbids tools. Forcing is useful for extraction, where you always want structured arguments. On Claude Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1, any and tool return a 400 error, so the documented approach is auto with strict tool use for schema-valid inputs, or structured outputs when you just need a fixed JSON shape. Parallel calls are limited with disable_parallel_tool_use inside the tool_choice object.

A plausible wrong answer. "Always force the tool so the model can't skip it." On the newest Claude models that request fails outright, and even where it works, forcing a tool skips the model's thinking and removes its ability to ask a clarifying question when the input is missing.

Follow-ups. When is structured output a better fit than a forced tool? How would you test that the model calls the tool when it should and not when it shouldn't?

The likely cause is a tool that trusts the model's arguments for identity, either by looking up any order ID or by taking a customer ID as a parameter. The fix belongs in the tool: take the customer from the authenticated session, check ownership on every call, and give the same response for missing and not-yours so IDs cannot be probed. A plausible wrong answer. "Add a line to the system prompt telling the model to only discuss the customer's own orders." Prompts are not a security boundary: a confused or manipulated model will still call the tool, and the tool will still answer.

Defend a designWhy write the round trip yourself instead of using the SDK's tool runner or a framework?

Worked answer. For learning and debugging, writing it once is the fastest way to understand what every framework does, and the code is about 30 lines. # fake_claude.py · A RULE-BASED STAND-IN (version 4, used from Lesson 2.1 to the end of Chapter 3) for the Claude Messages API. It is not a language model.
# It returns responses in the documented shape (content blocks, stop_reason, usage) and enforces the
# documented formatting rules for tool results, so your code succeeds and fails the way it would
# against the real API. Decisions come from simple rules, so its "wording" is fixed and predictable.
import json, re, time
from types import SimpleNamespace as NS

class BadRequestError(Exception):
    """Stands in for anthropic.BadRequestError (HTTP 400)."""

class OverloadedError(Exception):
    """Stands in for the error the SDK raises when the API is overloaded (HTTP 529), here part-way through a stream."""

class _Block(NS):
    def __repr__(self):
        name = {"text": "TextBlock", "tool_use": "ToolUseBlock"}.get(self.type, "Block")
        return f"{name}(" + ", ".join(f"{k}={v!r}" for k, v in vars(self).items()) + ")"

def _blocks(content):
    return [content] if isinstance(content, dict) else ([{"type": "text", "text": content}] if isinstance(content, str) else content)

def _get(b, k):
    return b.get(k) if isinstance(b, dict) else getattr(b, k, None)

def _check_rules(messages):
    for i, m in enumerate(messages):
        if m["role"] != "assistant":
            continue
        uses = [_get(b, "id") for b in _blocks(m["content"]) if _get(b, "type") == "tool_use"]
        if not uses or i + 1 >= len(messages):
            continue

        kinds = [_get(b, "type") for b in nxt]

        if i and messages[i - 1]["role"] == "assistant":
            prev_uses = {_get(b, "id") for b in _blocks(messages[i - 1]["content"]) if _get(b, "type") == "tool_use"}
        for b in _blocks(m["content"]) if m["role"] == "user" else []:

                raise BadRequestError(f"tool_result {_get(b, 'tool_use_id')} has no matching tool_use in the previous message")

    def _cache_usage(self, tools, system, messages, top):
        """Prompt caching: tools, then system, then messages form the prefix. Writes happen at a breakpoint."""
        pos = [("tools", json.dumps(tools))] if tools else []
        marks = []
        plain = lambda b: json.dumps({k: v for k, v in b.items() if k != "cache_control"} if isinstance(b, dict) else b, default=str)   # markers are not content
        for b in system:
            pos.append(("system", plain(b)))
            if _get(b, "cache_control"): marks.append(len(pos) - 1)
        for m in messages:
            for b in _blocks(m["content"]):
                pos.append((m["role"], plain(b)))
                if _get(b, "cache_control"): marks.append(len(pos) - 1)
        if top:
            marks.append(len(pos) - 1)                          # automatic caching: the last block
        if not marks:
            return None
        if len(marks) > 4:
            raise BadRequestError("a request may have at most 4 cache_control breakpoints")
        size = lambda k: sum(len(t) for _, t in pos[:k + 1]) // 4
        key = lambda k: hash(tuple(pos[:k + 1]))
        now, read, write = self.owner.clock, 0, 0
        for k in sorted(set(marks)):
            if size(k) < 512:                                   # below the minimum cacheable length: silently not cached
                continue
            hit = next((j for j in range(k, max(-1, k - 20), -1) if key(j) in self.cache and now - self.cache[key(j)] <= 300), None)
            if hit is not None:
                read = max(read, size(hit))
                self.cache[key(hit)] = now                      # a read refreshes the five-minute lifetime
            if hit != k:
                write = size(k) - max(read, 0)
                self.cache[key(k)] = now
        total = sum(len(t) for _, t in pos) // 4
        return {"input_tokens": total - read - write, "cache_creation_input_tokens": write, "cache_read_input_tokens": read}
    def parse(self, model, max_tokens, messages, output_format, **kw):
        schema = transform_schema(output_format.model_json_schema())
        r = self.create(model, max_tokens, messages, output_config={"format": {"type": "json_schema", "schema": schema}}, **kw)
        r.parsed_output = output_format.model_validate_json(r.content[0].text) if r.stop_reason == "end_turn" else None
        return r
    def stream(self, **kw):
        return _Stream(self.create(stream=True, **kw))

class _Stream:
    """Like the SDK's MessageStream: iterate over events, or read just the text with text_stream."""
    def __init__(self, events):
        self._events, self._final = events, None
    def __enter__(self): return self
    def __exit__(self, *exc): return False
    def __iter__(self):
        for e in self._events:
            if e.type == "message_start":
                self._final = e.message
            if e.type == "content_block_delta" and e.delta.type == "text_delta":
                self._final.content[e.index].text += e.delta.text
            if e.type == "message_delta":
                self._final.stop_reason, self._final.usage.output_tokens = e.delta.stop_reason, e.usage.output_tokens
            yield e
    @property
    def text_stream(self):
        return (e.delta.text for e in self if e.type == "content_block_delta" and e.delta.type == "text_delta")
    def get_final_message(self):
        for _ in self: pass
        return self._final

def _events(r, owner):
    """The documented server-sent event sequence for one response."""
    start = NS(content=[_Block(**{**vars(b), "text": ""}) if b.type == "text" else b for b in r.content], stop_reason=None,
               usage=NS(**{**vars(r.usage), "output_tokens": 1}))
    yield NS(type="message_start", message=start)
    sent = 0
    for i, b in enumerate(r.content):
        yield NS(type="content_block_start", index=i, content_block=start.content[i] if b.type == "text" else _Block(**{**vars(b), "input": {}}))
        raw = json.dumps(b.input) if b.type == "tool_use" else ""
        pieces = re.findall(r"\S+\s*\S*\s*", b.text) if b.type == "text" else [raw[k:k + 12] for k in range(0, len(raw), 12)]
        for piece in pieces:
            if owner.stream_fails_after is not None and sent >= owner.stream_fails_after:
                owner.stream_fails_after = None                  # the connection drops once; a retry works
                raise OverloadedError("Overloaded (529) part-way through the stream")
            time.sleep(owner.seconds_per_piece)
            yield NS(type="content_block_delta", index=i, delta=NS(type="text_delta", text=piece) if b.type == "text" else NS(type="input_json_delta", partial_json=piece))
            sent += 1
        yield NS(type="content_block_stop", index=i)
    yield NS(type="message_delta", delta=NS(stop_reason=r.stop_reason), usage=NS(output_tokens=r.usage.output_tokens))
    yield NS(type="message_stop")

UNSUPPORTED = ("minimum", "maximum", "exclusiveMinimum", "exclusiveMaximum", "multipleOf", "minLength", "maxLength")

def _check_schema(schema, path="schema"):
    """JSON outputs accept a documented subset of JSON Schema; anything else is a 400."""
    if isinstance(schema, dict):
        for k in UNSUPPORTED:
            if k in schema:
                raise BadRequestError(f"{path}: '{k}' is not supported in output_config.format schemas")
        if schema.get("type") == "object" and schema.get("additionalProperties", True) is not False:
            raise BadRequestError(f"{path}: objects must set additionalProperties to false")
        for k, v in schema.items():
            _check_schema(v, f"{path}.{k}")
    elif isinstance(schema, list):
        for v in schema:
            _check_schema(v, path)

def transform_schema(schema):
    """What the SDK helpers do before sending a schema: unsupported constraints move into the description."""
    if isinstance(schema, list):
        return [transform_schema(v) for v in schema]
    if not isinstance(schema, dict):
        return schema
    out, notes = {}, []
    for k, v in schema.items():
        if k in UNSUPPORTED or k == "default":
            notes.append(f"{k}: {v}")
        else:
            out[k] = transform_schema(v)
    if notes:
        out["description"] = (out.get("description", "") + "\n\n{" + ", ".join(notes) + "}").strip()
    if out.get("type") == "object":
        out["additionalProperties"] = False
    return out

SYNONYMS = {"delivery": "late delivered delivery yet still hasn't where", "late": "late yet still hasn't",
            "damaged": "broken damaged cracked smashed", "refund": "refund money back", "billing": "charged twice invoice payment billing",
            "technical": "app crash login error", "hinglish": "chahiye hai nahi kya", "hindi": "क्या है"}

def _words(t):
    return set(re.findall(r"[a-z']+", t.lower()))

def _fill(schema, question, name="", defs=None):
    """Build a value that matches the schema, using simple keyword rules on the question."""
    defs = defs or schema.get("$defs", {})
    if "$ref" in schema:
        return _fill(defs[schema["$ref"].split("/")[-1]], question, name, defs)
    if "anyOf" in schema:
        real = [s for s in schema["anyOf"] if s.get("type") != "null"]
        value = _fill(real[0], question, name, defs) if real else None
        return None if value in ("", "N/A") and len(real) < len(schema["anyOf"]) else value
    if "enum" in schema:
        words = _words(question)
        score = lambda v: len(words & (_words(str(v).replace("_", " ")) | set(" ".join(SYNONYMS.get(w, "") for w in _words(str(v).replace("_", " "))).split())))
        best = max(schema["enum"], key=score)
        return best if score(best) else ("other" if "other" in schema["enum"] else schema["enum"][0])
    kind = schema.get("type")
    if kind == "object":
        return {k: _fill(v, question, k, defs) for k, v in schema.get("properties", {}).items()}
    if kind == "array":
        return []
    if kind == "boolean":
        return bool(re.search(r"(?i)tomorrow|urgent|asap|now\b|!|today|wedding", question))
    if kind in ("integer", "number"):
        return 5 if re.search(r"(?i)tomorrow|urgent|asap|now\b|!|today|wedding", question) else 2
    if "order" in name:
        found = re.findall(r"\b[A-Z]{1,2}-?\d{4}\b", question)
        return found[0] if found else "N/A"
    first = re.split(r"(?<=[.!?])\s+", question.split(":", 1)[-1].strip())[0]
    return first[:60]

def _loose(name, question):
    """What a model writes when it is only asked nicely: plausible, but in its own words and format."""
    if "order" in name:
        found = re.findall(r"\b[A-Z]{1,2}-?\d{4}\b", question)
        return found[0] if found else None
    if "urgen" in name:
        return "High" if re.search(r"(?i)tomorrow|urgent|!|wedding", question) else "Normal"
    if "categ" in name:
        return "Delivery issue" if re.search(r"(?i)arrived|delivery|hasn't", question) else "Product issue"
    return question[:40]

def _summarise(text):
    try:
        d = json.loads(text)
    except (json.JSONDecodeError, TypeError):
        return text
    if d.get("refund_id"):
        return f"Refund {d['refund_id']} of INR {d['amount']:,} for order {d['order_id']}: {d['status']}."
    if d.get("return_id"):
        return f"Return {d['return_id']} for order {d['order_id']}: {d.get('status') or d.get('note')}."
    if d.get("delivered_on"):
        return f"Order {d['order_id']} was {d['status']} on {d['delivered_on']}."
    tail = f", expected {d['eta']}" if d.get("eta") else ""
    return f"Order {d['order_id']} is {d['status']}{tail}."
