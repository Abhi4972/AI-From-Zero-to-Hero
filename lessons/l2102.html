Why this came about

Real data comes in collections: the items in a cart, the words in a sentence, the fields of an order. Every programming language has ways to hold many values and to repeat a step for each one. Python's two workhorses, the list and the dictionary, matter even more in AI work because they map directly onto JSONlater · 0.19, the format in which every AI service sends and receives data. The messages you send to a language model in the Talking to models: APIs, messages, prompts and context section are literally a list of dictionaries.

In plain words first
Shopping lists and phone books

A list is like a shopping list: items in order, and you can add, remove or look at the third one. A dictionary is like a phone book: you look things up by a name (the key), not by position. A loop is "do this for every item on the list". A decision is "if the cart is over 499 rupees, delivery is free; otherwise, charge 40".

Step 1 · Lists: values in order

A list holds several values in order, inside square brackets. You can ask how long it is, read any position (positions start at 0, and -1 means the last), and add or remove items. A shopping cart is a natural list:

cart = ["tea", "rice", "soap"]
print(cart, len(cart))
print(cart[0], cart[-1])          # first and last
cart.append("pens")               # add at the end
cart.insert(1, "milk")            # add at position 1
print(cart)
cart.remove("soap")               # remove the first "soap"
last = cart.pop()                 # remove and give back the last item
print(cart, "| popped:", last)
print("tea" in cart, cart.index("rice"))
print(cart[1:3], cart[:2], cart[2:])
What you should see
['tea', 'rice', 'soap'] 3
tea soap
['tea', 'milk', 'rice', 'soap', 'pens']
['tea', 'milk', 'rice'] | popped: pens
True 2
['milk', 'rice'] ['tea', 'milk'] ['rice']

A list can hold any values, even a mix, and you can change it after creating it: lists are mutable. Slices work like they do for strings: cart[:2] means "from the start up to position 2", cart[2:] "from position 2 to the end".

Numbers in lists come with useful built-in functions:

prices = [249.5, 89, 35, 120]
print(sum(prices), min(prices), max(prices))
print(sorted(prices), sorted(prices, reverse=True))
prices.sort()                     # sorts the list itself, in place
print(prices)
What you should see
493.5 35 249.5
[35, 89, 120, 249.5] [249.5, 120, 89, 35]
[35, 89, 120, 249.5]

sorted(prices) gives back a new sorted list and leaves the original alone; prices.sort() changes the list itself and gives back nothing. Many Python libraries follow this split between functions that return a new value and methods that change an object in place.

Step 2 · Tuples and sets

Two more collections you will meet often:

point = (12.97, 77.59)            # a tuple: like a list, but it cannot be changed
lat, lon = point                  # "unpacking" a tuple into two variables
print(lat, lon)

tags = {"urgent", "refund", "urgent", "cod"}   # a set: no duplicates, no order
print(len(tags), "refund" in tags)
print(sorted(tags))
What you should see
12.97 77.59
3 True
['cod', 'refund', 'urgent']
Collection Written as Ordered Changeable Duplicates Typical use
list [1, 2, 3] yes yes yes Items you will add to or loop over
tuple (1, 2, 3) yes no yes A fixed group: a coordinate, a row, a pair returned from a function
set {1, 2, 3} no yes no Unique values, fast "is it in here?" checks
dict {"a": 1} keeps insertion order yes keys unique Looking things up by name

The duplicated "urgent" was stored once: sets keep only unique values. That is why len(tags) is 3.

Step 3 · Dictionaries: looking things up by key

A list finds things by position. A dictionary (dict) finds things by name: it stores pairs of a key and a value, inside curly brackets. Almost everything an AI model sends you arrives as dictionaries inside lists inside dictionaries, so this is worth practising. One order, as a dictionary:

order = {"id": "SK-1042", "status": "shipped", "items": ["tea", "rice"], "total": 540}
print(order["status"])
print(order["items"][0])           # a list inside a dict: index into it
order["status"] = "delivered"      # change a value
order["rating"] = 5                # add a new key
print(order)
print(order.get("phone"), order.get("phone", "not given"))
print(list(order.keys()))
print("total" in order)
What you should see
shipped
tea
{'id': 'SK-1042', 'status': 'delivered', 'items': ['tea', 'rice'], 'total': 540, 'rating': 5}
None not given
['id', 'status', 'items', 'total', 'rating']
True
Reading this output
  • order["status"] looks a value up by its key. If the key does not exist, order["phone"] stops the program with a KeyError.
  • order.get("phone") is the safe way: it gives None when the key is missing, or a default you choose as the second argument.
  • order.keys(), order.values() and order.items() give the keys, the values, and (key, value) pairs. Wrapping in list(...) shows them as a plain list.
  • "total" in order checks the keys, not the values.

Dictionaries can hold lists and other dictionaries, as deep as you like. This nesting is exactly what JSON looks like (Lesson 0.19), and it is how a chat with a language model is represented:

messages = [
    {"role": "system", "content": "You are ShopKart's support assistant."},
    {"role": "user", "content": "Where is my order SK-1042?"},
]
print(messages[1]["content"])
print(len(messages), "messages; roles:", [m["role"] for m in messages])
What you should see
Where is my order SK-1042?
2 messages; roles: ['system', 'user']

The last line uses a list comprehension, explained in Step 6. You will build lists like messages hundreds of times in the Talking to models: APIs, messages, prompts and context section.

Step 4 · Decisions with if, elif and else

Programs decide what to do by testing a condition. if runs its indented lines only when the condition is true; elif ("else if") is tried only when the ones above it were false; else catches everything left. The indentation is not decoration: it is how Python knows which lines belong to which branch. Here is a delivery fee that depends on the cart total:

cart_total = 420
if cart_total >= 499:
    delivery = 0
    print("Free delivery")
elif cart_total >= 300:
    delivery = 20
    print("Reduced delivery fee")
else:
    delivery = 40
    print("Standard delivery fee")
print("Pay:", cart_total + delivery)
What you should see
Reduced delivery fee
Pay: 440

Three rules make Python's decisions work:

  1. Each condition ends with a colon :.
  2. The lines that belong to it are indented (by convention, four spaces). Indentation is not decoration in Python: it is how Python knows which lines are inside the if. A line that is not indented, like the last print, runs whatever happened above.
  3. Python checks the conditions from the top and runs only the first one that is true. elif ("else if") is checked only when everything above it was false; else catches everything left.

A one-line version exists for simple choices: label = "free" if cart_total >= 499 else "paid".

Step 5 · Loops: repeating work

A for loop runs its indented lines once for every item in a collection:

cart = {"tea": 249.5, "rice": 89, "pens": 35}
total = 0
for item, price in cart.items():     # each pass gets one (key, value) pair
    print(f"{item:<6}{price:>8}")
    total += price
print(f"{'total':<6}{total:>8}")
What you should see
tea      249.5
rice        89
pens        35
total    373.5

Three helpers make loops easier to write:

for i in range(3):                    # 0, 1, 2: range stops before its end value
    print("attempt", i)
for i, word in enumerate(["red", "green"]):   # position and item together
    print(i, word)
names, cities = ["Asha", "Ravi"], ["Pune", "Goa"]
for name, city in zip(names, cities):          # walk two lists side by side
    print(name, "lives in", city)
What you should see
attempt 0
attempt 1
attempt 2
0 red
1 green
Asha lives in Pune
Ravi lives in Goa

Two keywords change a loop's flow: break stops the loop completely, continue skips to the next item. A while loop repeats as long as a condition stays true; use it when you do not know in advance how many passes you need:

stock = [5, 0, 3, 0, 8]
for qty in stock:
    if qty == 0:
        continue                       # skip empty shelves
    if qty > 6:
        print("found a full shelf:", qty)
        break                          # stop looking
    print("partial shelf:", qty)

balance, months = 10000, 0
while balance < 12000:                 # grow 2% a month until we reach 12000
    balance *= 1.02
    months += 1
print(months, "months, balance", round(balance, 2))
What you should see
partial shelf: 5
partial shelf: 3
found a full shelf: 8
10 months, balance 12189.94
Watch out
A while loop needs a way out

If the condition never becomes false, the loop runs forever and the program hangs. In a notebook, press the stop button; in a terminal, press Ctrl+C. The agent loops in the Agents from first principles section always carry a maximum number of steps for exactly this reason.

Step 6 · Comprehensions: building collections in one line

Building a new list from an old one is so common that Python has a short form for it, the list comprehension. These two snippets do the same thing:

prices = [249.5, 89, 35, 120]
with_tax = []
for p in prices:
    with_tax.append(round(p * 1.05, 2))
print(with_tax)

with_tax = [round(p * 1.05, 2) for p in prices]       # the same, in one line
cheap = [p for p in prices if p < 100]                 # with a filter
lengths = {word: len(word) for word in ["tea", "rice", "soap"]}   # a dictionary comprehension
print(with_tax, cheap, lengths)
What you should see
[261.98, 93.45, 36.75, 126.0]
[261.98, 93.45, 36.75, 126.0] [89, 35] {'tea': 3, 'rice': 4, 'soap': 4}

Read a comprehension from the middle: "for each p in prices (if p < 100), keep p". Use them for short transformations; when the logic needs several lines, a normal loop is easier to read.

Check your mental model
  • ✗ "range(3) gives 1, 2, 3."
    ✓ It gives 0, 1, 2: it starts at 0 and stops before the end value.
  • ✗ "Indentation is just style."
    ✓ In Python it decides which lines belong to an if, a loop or a function.
  • ✗ "x in my_dict searches the values."
    ✓ It checks the keys. Use x in my_dict.values() to search the values.
  • ✗ "sorted(lst) and lst.sort() are the same."
    ✓ sorted returns a new list; .sort() changes the list itself and returns None.

Exercises

Predict before you run

What does this print? nums = [3, 1, 2], then result = nums.sort(), then print(result, nums). (Solution P1.)

Break it on purpose

This code should print a delivery message, but it stops with an error. Find and fix the two problems.

order = {"id": "SK-7", "city": "Goa"}
if order["City"] == "Goa"
    print("Delivery in 4 to 7 days")

(Solution B1.)

Debugging exercise

A colleague's loop is meant to print the total of all orders over INR 500, but it prints 0. Why?

orders = [540, 120, 1299, 89]
total = 0
for amount in orders:
    if amount > 500:
        total + amount
print(total)

(Solution D1.)

Make it your own

Given orders = [{"id": "SK-1", "city": "Pune", "total": 540}, {"id": "SK-2", "city": "Delhi", "total": 1299}, {"id": "SK-3", "city": "Pune", "total": 89}], build a dictionary that maps each city to its total sales: {"Pune": 629, "Delhi": 1299}. (Solution M1.)

Solutions

SolutionP1 · Sort in place

It prints None [1, 2, 3]. .sort() changes nums itself and returns nothing (None), so result is None. Use result = sorted(nums) if you want a new sorted list.

SolutionB1 · Two small mistakes

The key is "city" (lowercase), so order["City"] raises KeyError: 'City'; keys are case-sensitive. The if line also needs a colon at the end. Fixed: if order["city"] == "Goa":. Python reports the missing colon first, as a SyntaxError, because it checks the whole file's grammar before running anything.

SolutionD1 · A calculation that goes nowhere

total + amount computes a value and throws it away. It needs to be stored: total += amount (or total = total + amount). With the fix, the loop prints 1839.

SolutionM1 · Totals by city
by_city = {}
for o in orders:
    by_city[o["city"]] = by_city.get(o["city"], 0) + o["total"]
print(by_city)     # {'Pune': 629, 'Delhi': 1299}

by_city.get(city, 0) starts each new city at 0. Lesson 0.22 does the same in one line with pandas: df.groupby("city")["total"].sum().

Recap
  • Lists hold ordered, changeable items; tuples are fixed; sets keep unique values; dictionaries map keys to values.
  • if / elif / else run the first true branch; indentation shows what belongs where.
  • for repeats for each item; range, enumerate and zip help; while repeats until a condition is false.
  • Comprehensions build a new list or dictionary from an old one in a single line.
  • Lists of dictionaries are the shape of JSON and of every chat sent to a language model.
