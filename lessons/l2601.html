Why this came about

In Lesson 5.36 the decoder used its hidden state as the query and the encoder's states as both keys and values. The 2017 transformerlater · 7.19 paper made two changes that turned this into a general building block. First, self-attention: every token of a sentence attends to the tokens of the same sentence, so each token's vector can absorb information from its context. Second, separate learned projections: each token's vector is multiplied by three different matrices to produce its query, key and value, so what a token looks for, how it is found, and what it passes on can all differ. Stack this with a few other parts (Lesson 7.19) and you have the architecture behind every modern language model.

In plain words first
A room full of people asking each other questions

Picture each word of a sentence as a person in a room. Each person holds up a card saying what they offer (a key: "I'm a noun, an object, something that can be big"), keeps a note of what they would tell others (a value), and asks a question of their own (a query: "I'm the word it; which earlier thing am I referring to?"). Every person compares their question with everyone's cards, listens mostly to the best matches, and updates their own understanding with what those people said. After one round, "it" knows a little about "parcel". A transformer runs dozens of such rounds in parallel, with different questions each time.

Step 1 · Queries, keys and values

For each token vector x (its embedding, Lesson 3.18), self-attention computes three new vectors with three learned matrices:

  • query q = x · W_Q: what this token is looking for;
  • key k = x · W_K: what this token offers to others looking;
  • value v = x · W_V: the information this token passes on if attended to.

Then each token's output is the weighted average of all the values, weighted by how well its query matches each key (dot product, then softmax), exactly as in Lesson 5.36.

Step 2 · By hand, for a four-token sentence

Four tokens, each with a made-up embedding of 4 numbers, and three small random matrices standing in for learned weights:

import math
import torch
import torch.nn.functional as F

tokens = ["the", "parcel", "was", "late"]
X = torch.tensor([[1.0, 0.0, 0.2, 0.1],     # one row per token: its embedding
                  [0.1, 1.0, 0.8, 0.0],
                  [0.0, 0.2, 0.1, 1.0],
                  [0.3, 0.1, 0.9, 0.6]])

torch.manual_seed(0)
d_k = 3                                      # size of each query, key and value
W_Q, W_K, W_V = torch.randn(4, d_k), torch.randn(4, d_k), torch.randn(4, d_k)

Q = X @ W_Q                                  # (4 tokens, 4) @ (4, 3) -> (4, 3): one query per token
K = X @ W_K
V = X @ W_V
print("Q, K, V shapes:", tuple(Q.shape), tuple(K.shape), tuple(V.shape))

scores = Q @ K.T / math.sqrt(d_k)            # (4, 3) @ (3, 4) -> (4, 4): every query against every key
print("scores (row = token looking, column = token looked at):")
print(scores.round(decimals=2))
What you should see
Q, K, V shapes: (4, 3) (4, 3) (4, 3)
scores (row = token looking, column = token looked at):
tensor([[ 0.3200, -1.1900,  0.0200, -0.7900],
        [ 0.4000, -0.6900, -0.4500, -0.6200],
        [-0.1600,  0.7400, -0.5700,  0.1900],
        [ 0.4800, -0.8700, -0.0900, -0.5200]])

Q @ K.T computes all 16 dot products at once: entry (i, j) is how well token i's query matches token j's key. Each row is then turned into weights with softmax, and the weights mix the values:

weights = F.softmax(scores, dim=-1)          # softmax along each row: each row adds up to 1
print("attention weights:")
for t, row in zip(tokens, weights):
    print(f"{t:>7}: " + "  ".join(f"{w:.2f}" for w in row))

out = weights @ V                            # (4, 4) @ (4, 3) -> (4, 3): one new vector per token
print("output shape:", tuple(out.shape))
print("output for 'parcel':", out[1].round(decimals=2))
What you should see
attention weights:
    the: 0.44  0.10  0.32  0.14
 parcel: 0.47  0.16  0.20  0.17
    was: 0.18  0.44  0.12  0.26
   late: 0.46  0.12  0.26  0.17
output shape: (4, 3)
output for 'parcel': tensor([ 0.3300, -0.6200, -0.6800])
Reading this output
  • Each row of weights is one token's attention: positive numbers adding up to 1. With random matrices the pattern means nothing; training shapes W_Q, W_K and W_V so that the patterns become useful (Step 5 shows trained ones).
  • The output has one vector per token, the same number of tokens as the input. Each token's new vector is a blend of the value vectors of the tokens it attended to: its embedding, updated with context.
  • dim=-1 means "along the last dimension", here along each row. Softmax along the wrong dimension is a classic bug: the columns would add to 1 instead of the rows.

Step 3 · Why divide by √d

The scores were divided by math.sqrt(d_k). Here is why. A dot product of two random vectors adds up d products, so it grows with the vector size:

torch.manual_seed(1)
for d in [4, 64, 512]:
    a, b = torch.randn(10_000, d), torch.randn(10_000, d)
    dots = (a * b).sum(dim=1)
    print(f"d = {d:>3}: spread of raw dot products {dots.std():6.2f}   after dividing by sqrt(d) {(dots / math.sqrt(d)).std():.2f}")

big = torch.tensor([8.0, 4.0, 2.0, 0.0]) * 4         # scores typical of large vectors
print("softmax of large scores:", F.softmax(big, dim=-1).round(decimals=3))
print("softmax of scaled scores:", F.softmax(big / 4, dim=-1).round(decimals=3))
What you should see
d =   4: spread of raw dot products   2.02   after dividing by sqrt(d) 1.01
d =  64: spread of raw dot products   8.14   after dividing by sqrt(d) 1.02
d = 512: spread of raw dot products  22.59   after dividing by sqrt(d) 1.00
softmax of large scores: tensor([1., 0., 0., 0.])
softmax of scaled scores: tensor([0.9790, 0.0180, 0.0020, 0.0000])

The spread of raw dot products grows like √d (2, 8, about 22.6). With large scores, softmax puts essentially all the weight on one token and its gradient nearly vanishes, so training stalls (Lesson 5.36's debugging exercise). Dividing by √d keeps the scores at a spread of about 1 whatever the size. That is the "scaled" in scaled dot-product attention.

Step 4 · The whole thing in one line

Attention(Q, K, V) = softmax(QKᵀ / √d_k) V

That formula is the core of the transformer. PyTorch has it built in, with fast implementations for GPUs:

built_in = F.scaled_dot_product_attention(Q.unsqueeze(0), K.unsqueeze(0), V.unsqueeze(0))[0]
print("same as our step-by-step result:", torch.allclose(built_in, out, atol=1e-6))
What you should see
same as our step-by-step result: True

unsqueeze(0) adds a batch dimension, because the built-in function expects (batch, tokens, size). On a GPU it uses FlashAttention-style kernels, which compute exactly the same result while avoiding writing the full score matrix to memory (Lesson 7.18).

Step 5 · Attention in a trained model

Now real weights. GPT-2 small has 12 layers, each with 12 attention heads (Lesson 7.18), 144 attention patterns in all. Here is one sentence, a classic test of whether a model can work out what "it" refers to:

from transformers import GPT2Model, GPT2TokenizerFast

tokenizer = GPT2TokenizerFast.from_pretrained("gpt2")
gpt2 = GPT2Model.from_pretrained("gpt2", attn_implementation="eager")   # "eager" so it can return attention weights
gpt2.eval()

sentence = "The trophy did not fit in the suitcase because it was too small."
ids = tokenizer(sentence, return_tensors="pt")
with torch.no_grad():
    result = gpt2(**ids, output_attentions=True)

toks = [tokenizer.decode([i]) for i in ids["input_ids"][0]]
attn = torch.stack(result.attentions)[:, 0]          # (12 layers, 12 heads, tokens, tokens)
print("attention tensor:", tuple(attn.shape))

it = toks.index(" it")
layer, head = 9, 0                                   # counting from 0: layer 10, head 1
row = attn[layer, head, it]
for t, w in sorted(zip(toks, row.tolist()), key=lambda p: -p[1])[:4]:
    print(f"   ' it' -> {t!r:<12} {w:.2f}")
What you should see
attention tensor: (12, 12, 14, 14)
   ' it' -> ' suitcase'  0.65
   ' it' -> 'The'        0.16
   ' it' -> ' trophy'    0.07
   ' it' -> ' fit'       0.03

In this head, "it" puts most of its attention on " suitcase", which happens to be the right answer here: the suitcase is what was too small. But be careful. GPT-2 reads left to right, so each token can only look at itself and earlier tokens (Lesson 7.18), and the word that decides the answer, "small", comes after "it". At the position of "it", the model cannot know yet; this head links "it" to a recent noun. Change "small" to "big" and this row of weights stays exactly the same (exercise M1). The decision has to be made at later positions, such as "small", which can look back at both nouns. Explore all 144 heads on three sentences:

What you will find
  • Many heads put most of their weight on the first token of the text when nothing else is relevant. It acts as a resting place, sometimes called an attention sink.
  • Some heads look at the previous token, or the token just before that; these help with word-level patterns.
  • A few heads in the middle and upper layers link pronouns to recent nouns, as above. Try layer 10, head 1 on all three sentences. In the "raining" sentence, where "it" refers to the weather, it still points at "parcel": a head is a learned pattern, not a reasoning step. Click later tokens such as " small" or " big" to see what they look back at.
  • Attention weights show where information flows, not why the model produces an answer. Treat them as clues, not explanations (Lesson 15.29 covers interpretability research).
The same idea as a formula
  • projections: Q = XW_Q, K = XW_K, V = XW_V, with X of shape (n, d_model) and each W of shape (d_model, d_k)
  • scores: S = QKᵀ / √d_k, shape (n, n)
  • weights: A = softmax(S) row by row; each row sums to 1
  • output: AV, shape (n, d_k); one updated vector per token
  • why √d_k: if the entries of q and k have variance 1, q · k has variance d_k
Check your mental model
  • ✗ "Attention gives each token a fixed importance."
    ✓ Weights are computed fresh for every pair of tokens from their queries and keys, so the same token can matter a lot to one word and not at all to another.
  • ✗ "Query, key and value are three different tokens."
    ✓ They are three different vectors computed from the same token, each with its own learned matrix.
  • ✗ "An attention head that links 'it' to the right noun means the model understood the sentence."
    ✓ It is a learned pattern that often matches the right referent, and sometimes does not. Behaviour is the sum of many heads and layers.

Exercises

Predict before you run

Make it your own

In Step 5, change the sentence to "The trophy did not fit in the suitcase because it was too big." and print layer 10, head 1 again. Where does " it" look now, and why? (Solution M1.)

Debugging exercise

A colleague writes weights = F.softmax(scores, dim=0). Their code runs, and the output has the right shape. What is wrong, and how could they detect it? (Solution D1.)

Solutions

SolutionP1 · Equal scores

Softmax of equal numbers gives equal weights: 0.25 for each of the 4 tokens. Every token's output would be the plain average of all four value vectors, so all four outputs would be identical. Attention only does something useful when the scores differ, which is what training arranges.

SolutionM1 · Big instead of small

The weights are exactly the same as before: " suitcase" 0.65, "The" 0.16, " trophy" 0.07. GPT-2 is a left-to-right (causal) model, so the token " it" cannot see "big" or "small", which come after it; its attention cannot depend on them. Any difference between the two sentences can only appear at later positions. Encoder models such as BERTlater · 7.22 (Lesson 7.22) let every token see the whole sentence in both directions, which suits tasks like this one.

SolutionD1 · Softmax along the wrong dimension

dim=0 normalises each column, so the weights a token gives to all other tokens no longer add up to 1; instead, each token's received attention does. The output shape is unchanged, so nothing crashes. Check with weights.sum(dim=-1): every row should be exactly 1. Asserting such invariants is a cheap way to catch silent bugs in model code.

Recap
  • Every token produces a query, a key and a value by multiplying its vector by three learned matrices.
  • Attention scores are dot products of queries with keys, divided by √d_k, turned into weights with softmax row by row.
  • Each token's output is the weighted average of the values: its vector updated with information from its context.
  • The whole operation is softmax(QKᵀ/√d_k)V, available in PyTorch as scaled_dot_product_attention.
  • Trained heads show patterns such as attending to the previous token, to the first token, or from pronouns to nouns; they are clues, not explanations.

Check your understanding

Q1In self-attention, what is compared to decide how much token A attends to token B?

The dot product of A's query and B's key, scaled and passed through softmax.

Q2Why are attention scores divided by √d_k?

Dot products grow with vector length; scaling keeps training stable.

Q3For 10 tokens and d_k = 64, what is the shape of the score matrix QKᵀ?

One score for every pair of tokens.
