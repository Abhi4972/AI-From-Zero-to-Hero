How to use these questions

These questions check whether the chapter's ideas have really landed. Read each question, then answer it in your own words (out loud, on paper, or to a colleague) before opening the model answer: a one-sentence definition, then how it works, then what it means in practice. Compare with the model answer and the plausible wrong answer, and note any follow-up you could not answer. If a question feels unfamiliar, go back to the lesson that teaches it. Teams can also use these as discussion prompts in a study group.

Graphs and AI search

JuniorWhen would you use a graph database instead of a vector database or SQL?

When the questions are about connections: paths of unknown length, dependencies, influence or communities. SQL is better for known joins and aggregates, vectors for similarity of meaning. Many systems use all three, and a graph is another system to secure and keep in sync, so it should be justified by graph-shaped questions (Lesson 14.146).

MidWalk me through building a knowledge graph from documents.

Competency questions first, then a schema of entity and relation types with allowed source and target types. Load structured sources with source IDs as the backbone. Extract from text with a model under the schema, with structured output and the source chunk kept on every fact. Validate against the schema, resolve entities (normalize, alias table, similarity within type, review queue), and load idempotently with MERGE and provenance. Measure precision and recall on a labeled sample and update incrementally by hashing chunks (Lesson 14.149).

MidWhich GraphRAG approach would you use for "What are the main themes across all our support tickets?"

A global question: community detection (Leiden) over the entity graph and map-reduce over community summaries, as in Microsoft GraphRAG's global search. If indexing cost or document churn is high, a lazy approach that defers summarization to query time, such as LazyGraphRAG. Plain vector RAG would retrieve a few similar tickets and generalize from them (Lesson 14.150).

SeniorHow do you let a model query a graph database safely?

Give it the schema and example queries; check the generated Cypher for write clauses, unknown labels and relations, unbounded variable-length paths, literals instead of parameters and a missing limit; run it as a read-only user restricted to the needed labels with a timeout; enforce tenant and role filters in the query layer; and log the query with the trace (Lesson 14.150, Lesson 14.157).

SeniorWhat is personalized PageRank and why does HippoRAG use it?

PageRank where random jumps return only to seed nodes, so scores measure closeness to the seeds. HippoRAG seeds it with the entities in the question over a graph extracted from the documents, then ranks passages by the scores of their entities, which handles multi-hop questions in one retrieval step (Lesson 14.155).

SeniorWhen is GraphRAG worth it?

When questions depend on relationships across many documents: "which suppliers of our top products had quality incidents?", or global summaries of a corpus. GraphRAG extracts entities and relations into a graph (and, in Microsoft's version, community summaries) and retrieves by traversal or summary. It costs a lot to build and keep current, and extraction errors propagate. Use it when you have relationship-heavy questions that hybrid search demonstrably fails on; otherwise a well-tuned hybrid retriever, or structured data in SQL, is cheaper.
