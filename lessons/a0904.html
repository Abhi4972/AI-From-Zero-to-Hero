In plain words first
The idea in one line

Monte Carlo waits until the episode ends. TD updates after every step by bootstrapping the next value estimate. Q-learning is off-policy and optimistic; SARSA is on-policy and cautious. Both are one line of code. Both underpin every deep-RL method in this phase.

The problem

In plain words first

Monte Carlo waits until an episode ends before learning anything. Temporal-difference (TD) learning updates after every single step: it compares its current guess for a state with a slightly better-informed guess, the reward just received plus its guess for the next state, and moves a little toward it. Learning from your own guesses is called bootstrapping; it introduces some bias but greatly reduces noise and works without episodes ever ending. Q-learning applies this to action values and always assumes the best action will be taken next; SARSA uses the action the agent actually takes next. That one difference decides whether the agent learns the bold path or the safe one. This lesson runs the lesson's tabular SARSA and Q-learning and checks them against exact values, then reproduces two textbook experiments in seconds: the cliff walk in Gymnasium, and the overestimation that double Q-learning fixes. Tables of numbers are updated; no neural network is trained.

Monte Carlo works but it has two expensive demands. It needs episodes that terminate, and it only updates after the final return is in. If your episode is 1,000 steps, MC waits 1,000 steps to update anything. It is high-variance, low-bias, and slow in practice.

Dynamic programming has the opposite profile — zero-variance bootstrapped backups — but requires a known model.

Temporal difference (TD) learning splits the difference. From a single transition (s,a,r,s′), form a one-step target r+γV(s′) and nudge V(s) toward it. No model. No complete episodes. Bias from using an approximate V on the RHS, but dramatically lower variance than MC and online updates from step one.

This is the pivot on which all of modern RL — DQN, A2C, PPO, SAC — turns. The rest of Phase 9 is layers of function approximation and tricks built on top of the one-step TD update you will write in this lesson.

The idea

The TD(0) update for V:

V(s)←V(s)+α[r+γV(s′)−V(s)]

The bracketed quantity is the TD error δ=r+γV(s′)−V(s). It is the online analogue of Gt​−V(st​) in MC. Convergence requires α satisfying Robbins-Monro (∑α=∞, ∑α2<∞) and all states visited infinitely often.

Q-learning. An off-policy TD method for control:

Q(s,a)←Q(s,a)+α[r+γa′max​Q(s′,a′)−Q(s,a)]

The max assumes the greedy policy will be followed from s′ onward, regardless of what action the agent actually takes. That decoupling makes Q-learning learn Q∗ while the agent explores via ε-greedy. Mnih et al. (2015) converted this into deep Q-learning on Atari (Lesson 9.5).

SARSA. An on-policy TD method:

Q(s,a)←Q(s,a)+α[r+γQ(s′,a′)−Q(s,a)]

The name is the tuple (s,a,r,s′,a′). SARSA uses the action a′ the agent actually takes next, not the greedy argmax. Converges to Qπ for whatever ε-greedy π is running, which in the limit ϵ→0 becomes Q∗.

The cliff-walking difference. On the classic cliff-walking task (fall-off-cliff = reward -100), Q-learning learns the optimal path along the cliff edge but occasionally takes the penalty during exploration. SARSA learns a safer path one step away from the cliff because it factors exploration noise into its Q-value. With training, both reach optimal at ϵ→0. In practice it matters: when exploration is actually happening at deployment, SARSA's behavior is more conservative.

Expected SARSA. Replace Q(s′,a′) with its expected value under π:

Q(s,a)←Q(s,a)+α[r+γa′∑​π(a′∣s′)Q(s′,a′)−Q(s,a)]

Lower variance than SARSA (no sample of a′), same on-policy target. Often the default in modern textbooks.

n-step TD and TD(λ). Interpolate between TD(0) and MC by waiting n steps before bootstrapping. n=1 is TD, n=∞ is MC. TD(λ) averages over all n with geometric weights (1−λ)λn−1. Most deep-RL uses n between 3 and 20.

The same idea as a formula

TD error. For a transition (s,a,r,s′): δ=r+γV(s′)−V(s), and TD(0) moves V(s)←V(s)+αδ. Compared with Monte Carlo's target Gt​, the target r+γV(s′) uses one real reward and one estimate: lower variance, some bias while V is wrong.

Three control targets for Q(s,a)←Q(s,a)+α(y−Q(s,a)):

ySARSA​=r+γQ(s′,a′),yExpected SARSA​=r+γa′∑​π(a′∣s′)Q(s′,a′),yQ​=r+γa′max​Q(s′,a′)

SARSA and Expected SARSA estimate the value of the policy being followed (with its exploration); Q-learning estimates Q∗ whatever the behaviour.

Maximisation bias. For noisy estimates Q^​=Q+noise, E[maxa​Q^​(a)]≥maxa​E[Q^​(a)]: the max of noisy numbers is biased upward. Double Q-learning keeps two tables and uses one to choose and the other to evaluate: y=r+γQ2​(s′,argmaxa′​Q1​(s′,a′)), which removes the bias from independent noise.

n-step returns interpolate: Gt(n)​=rt+1​+⋯+γn−1rt+n​+γnV(st+n​); n=1 is TD, n=∞ is Monte Carlo.

Convergence (tabular): with every pair visited infinitely often and step sizes with ∑α=∞, ∑α2<∞, Q-learning converges to Q∗.

Worked example
SARSA and Q-learning on the same step

α=0.5, γ=1, current Q(s,a)=−10. The step gives r=−1 and lands in s′ where Q(s′,safe)=−12 and Q(s′,edge)=−8; the ε-greedy agent happens to pick "safe" next.

  • SARSA: y=−1+Q(s′,safe)=−13; Q(s,a)←−10+0.5×(−13+10)=−11.5.
  • Q-learning: y=−1+max(−12,−8)=−9; Q(s,a)←−10+0.5×(−9+10)=−9.5.
  • Expected SARSA with ε=0.1 over two actions (greedy "edge" gets 0.95): y=−1+0.95×(−8)+0.05×(−12)=−9.2.

Maximisation bias by hand. Ten actions, each truly worth −0.1, estimates with independent noise of standard deviation 1: the expected maximum of ten standard normals is about 1.54, so maxa​Q^​≈−0.1+1.54=+1.44, a bad option made to look good.

Check your mental model
  • ✗ "Q-learning learns what the agent actually does."
    ✓ It learns the value of acting greedily afterwards, whatever the agent does while exploring; SARSA learns the value of the exploring policy itself.
  • ✗ "Bootstrapping is just a faster Monte Carlo."
    ✓ It updates from estimates, so early on it is biased; in return it learns online, without episode ends, with far less variance.
  • ✗ "Taking the max over noisy estimates is harmless."
    ✓ It systematically overestimates; with many similar actions the bias can make a bad option look best for hundreds of episodes (the run after the pitfalls).

Step 1 · SARSA on ε-greedy policy

def sarsa(env, episodes, alpha=0.1, gamma=0.99, epsilon=0.1):
    Q = defaultdict(lambda: {a: 0.0 for a in ACTIONS})

    def choose(s):
        if random() < epsilon:
            return choice(ACTIONS)
        return max(Q[s], key=Q[s].get)

    for _ in range(episodes):
        s = env.reset()
        a = choose(s)
        while True:
            s_next, r, done = env.step(s, a)
            a_next = choose(s_next) if not done else None
            target = r + (gamma * Q[s_next][a_next] if not done else 0.0)
            Q[s][a] += alpha * (target - Q[s][a])
            if done:
                break
            s, a = s_next, a_next
    return Q

Eight lines. The only difference from Q-learning is the target line.

Step 2 · Q-learning

def q_learning(env, episodes, alpha=0.1, gamma=0.99, epsilon=0.1):
    Q = defaultdict(lambda: {a: 0.0 for a in ACTIONS})
    for _ in range(episodes):
        s = env.reset()
        while True:
            a = choose(s, Q, epsilon)
            s_next, r, done = env.step(s, a)
            target = r + (gamma * max(Q[s_next].values()) if not done else 0.0)
            Q[s][a] += alpha * (target - Q[s][a])
            if done:
                break
            s = s_next
    return Q

The max decouples target from behavior. That one symbol is the difference between on-policy and off-policy.

Pitfalls

  • Initial Q values matter. Optimistic init (Q=0 for a negative-reward task) encourages exploration. Pessimistic init can trap a greedy policy forever.
  • α schedule. Constant α is fine for non-stationary problems. Decaying αn​=1/n gives convergence in theory but is too slow in practice — pin α in [0.05, 0.3] and monitor the learning curve.
  • ε schedule. Start high (ϵ=1.0), decay to ϵ=0.05. "GLIE" (greedy in the limit with infinite exploration) is the convergence condition.
  • Max bias in Q-learning. The max operator is biased upward when Q is noisy. Leads to overestimation — Hasselt's Double Q-learning (used by DDQN in Lesson 9.5) fixes this with two Q tables.
  • Non-terminating episodes. TD can learn without terminals, but you need to either cap steps or handle bootstrap correctly at the cap. Standard: treat cap as non-terminal, keep bootstrapping.
  • State hashing. If states are tuples/tensors, use a hashable key (tuple, not list; tuple of floats rounded, not raw).

Maximisation bias and double Q-learning

Sutton and Barto's example 6.7, averaged over 2,000 runs: from A, "left" leads to B, where ten actions end the episode with rewards drawn from N(−0.1,1); "right" ends it with 0. The share of runs choosing "left" at several episodes, for Q-learning and double Q-learning (ε=0.1, α=0.1).

import numpy as np

# Sutton & Barto's maximisation-bias example (6.7): from A, "right" ends the episode with 0; "left" goes to B,
# where any of 10 actions ends the episode with a reward drawn from N(-0.1, 1). Going left is a bad idea on average.
def run(double, episodes=300, alpha=0.1, eps=0.1, seed=0):
    rng = np.random.default_rng(seed)
    QA = np.zeros((2, 2)); QB = np.zeros((2, 10))          # table 1 (and table 2 for double Q-learning)
    QA2 = np.zeros((2, 2)); QB2 = np.zeros((2, 10))
    lefts = []
    for _ in range(episodes):
        qa = QA[0] + QA2[0] if double else QA[0]
        a = int(rng.integers(2)) if rng.random() < eps else int(rng.choice(np.flatnonzero(qa == qa.max())))
        lefts.append(a == 0)
        if a == 1:                                           # right: terminate, reward 0
            upd = rng.random() < 0.5 if double else True
            (QA if upd else QA2)[0, 1] += alpha * (0 - (QA if upd else QA2)[0, 1]); continue
        qb = QB[0] + QB2[0] if double else QB[0]
        b = int(rng.integers(10)) if rng.random() < eps else int(rng.choice(np.flatnonzero(qb == qb.max())))
        r = rng.normal(-0.1, 1.0)
        if not double:
            QA[0, 0] += alpha * (0 + QB[0].max() - QA[0, 0]); QB[0, b] += alpha * (r - QB[0, b])
        else:                                                # pick with one table, evaluate with the other
            if rng.random() < 0.5:
                QA[0, 0] += alpha * (QB2[0, int(QB[0].argmax())] - QA[0, 0]); QB[0, b] += alpha * (r - QB[0, b])
            else:
                QA2[0, 0] += alpha * (QB[0, int(QB2[0].argmax())] - QA2[0, 0]); QB2[0, b] += alpha * (r - QB2[0, b])
    return np.array(lefts)
for double in (False, True):
    L = np.mean([run(double, seed=s) for s in range(2000)], axis=0)
    print(f"{'double Q-learning' if double else 'Q-learning':<17}: share of episodes choosing 'left' at A: "
          + "  ".join(f"ep {e + 1}: {L[e]:.0%}" for e in (0, 10, 25, 50, 100, 299)) + "   (optimal: 5%, the exploration floor)")

Reading this output

Going left is a bad bet: every reward at B averages −0.1, while right gives 0, so the best behaviour picks left only as the 5% exploration floor (ε/2). Q-learning does the opposite at first: after 10 episodes 88% of runs choose left, and after 25 episodes 92%. The maximum over ten noisy estimates at B is optimistic, so A's "left" inherits an inflated value; the bias fades only after about 100 episodes (46%) and is still visible at 300 (12%). Double Q-learning, choosing with one table and evaluating with the other, never falls for it: 46% after 10 episodes and close to the 5% floor by 300. Deep RL inherits the same problem, which is why DQN uses Double-DQN targets and TD3 takes the minimum of two critics (Lessons 9.5 and 9.7).

The cliff walk in Gymnasium

CliffWalking-v1 (4 × 12, −1 per step, −100 and back to the start for stepping off the cliff), 500 episodes of SARSA and of Q-learning with α=0.5, ε=0.1, 20 runs each: reward collected while learning, and where each greedy path crosses the middle of the grid.

import numpy as np, gymnasium as gym

# Sutton & Barto's cliff walk (Example 6.6) in Gymnasium: 4 x 12 grid, -1 per step, -100 and back to start for the cliff.
env = gym.make("CliffWalking-v1")
def run(method, episodes=500, alpha=0.5, eps=0.1, seed=0):
    rng = np.random.default_rng(seed); Q = np.zeros((48, 4)); returns = []
    pick = lambda s: int(rng.integers(4)) if rng.random() < eps else int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    for ep in range(episodes):
        s, _ = env.reset(seed=seed * 10_000 + ep); a = pick(s); total = 0; done = False
        while not done:
            s2, r, term, trunc, _ = env.step(a); total += r; done = term or trunc
            a2 = pick(s2)
            if method == "sarsa":   target = r + (0 if term else Q[s2, a2])                     # the action actually taken
            else:                   target = r + (0 if term else Q[s2].max())                   # the best action
            Q[s, a] += alpha * (target - Q[s, a]); s, a = s2, a2
        returns.append(total)
    return Q, np.array(returns)
def greedy_path(Q):
    s, path = 36, {36}
    for _ in range(60):
        s = env.unwrapped.P[s][int(Q[s].argmax())][0][1]; path.add(s)
        if s == 47: break
    return path
for method in ("sarsa", "q-learning"):
    curves, paths = [], []
    for seed in range(20):
        Q, ret = run(method, seed=seed); curves.append(ret); paths.append(greedy_path(Q))
    curves = np.array(curves)
    mid_rows = [min([p // 12 for p in path if p % 12 == 6] or [-1]) for path in paths]          # the row the path uses at column 6
    common = max(set(mid_rows), key=mid_rows.count)
    print(f"{method:<10}: return per episode while learning (eps = 0.1), last 100 episodes {curves[:, -100:].mean():6.1f}; "

          f"(row 2 = right above the cliff, 0 = top); greedy path {np.mean([len(p) - 1 for p in paths]):.1f} steps")

The textbook result appears: Q-learning's greedy path runs right along the cliff edge (row 2 in all 20 runs, 13 steps), the true optimum. SARSA's goes the long way round, along the top row in 17 of 20 runs. Yet while learning, with 10% random moves, SARSA collects far more reward: −26.5 per episode against −50.5 for Q-learning over the last 100 episodes. On the edge, a single random step drops the agent off the cliff for −100, and Q-learning's values ignore that risk because its target assumes perfect greedy play. SARSA's target includes the exploratory moves it actually makes, so it learns that the edge is dangerous for an agent that explores. If exploration is switched off after training, Q-learning's path is better; if it continues, SARSA's is.

Break it on purpose

In q_learning, at a terminal transition, forget the special case and bootstrap anyway: target = r + gamma * max(Q[s_next].values()), where s_next is the terminal state. In the lesson's grid this happens to change nothing. Why, and in what kind of environment would the same bug silently corrupt every value? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Tabular TD as a test bed. Gymnasium's toy-text environments, rlberry and course code (CleanRL, Sutton and Barto exercises) keep tabular Q-learning and SARSA as the first sanity check before deep RL.
  • TD targets inside deep RL. DQN variants (Rainbow, the dopamine and CleanRL implementations), SAC and TD3 all learn a Q-network with one- or n-step TD targets and double-Q-style corrections.
  • Offline RL. IQL and CQL, implemented in libraries such as d3rlpy and CORL, are Q-learning with constraints that keep the max away from actions never seen in the data.

Sources: Gymnasium toy text, CleanRL, d3rlpy, Double Q-learning (van Hasselt, 2010), Sutton & Barto ch. 6.

Recap
What to keep from this lesson
  • TD learns online from δ=r+γV(s′)−V(s): lower variance than Monte Carlo, some bias.
  • SARSA's target uses the next action taken; Q-learning's uses the best; Expected SARSA averages.
  • Off-policy Q-learning finds bold optimal paths; on-policy SARSA accounts for its own exploration.
  • The max over noisy estimates overestimates; double Q-learning decouples choice and evaluation.
  • Every deep value-based method is this update with a network in place of the table.

easy15 minimplement

Tabular Q-learning and SARSA learn a table of action values from one transition at a time. Both move Q[s,a] toward a target. Q-learning uses the best next action in the target. SARSA uses the next action that the agent really takes. An epsilon-greedy policy picks the actions while the table learns.

Task

Write three functions.

  1. q_learning_update(Q, s, a, r, s_next, done, alpha=0.1, gamma=0.99) returns the table after one Q-learning update.
  2. sarsa_update(Q, s, a, r, s_next, a_next, done, alpha=0.1, gamma=0.99) returns the table after one SARSA update.
  3. epsilon_greedy(Q, s, epsilon, rng) returns the action for state s.

Both updates change only the entry Q[s,a]:

Q[s,a]←Q[s,a]+α(y−Q[s,a])

The target y for Q-learning is r+γmaxa′​Q[s′,a′]. The target for SARSA is r+γQ[s′,anext​]. When done is True, the target is r only, with no term for the next state. The target uses the values of Q before the update.

epsilon_greedy uses the generator rng in this exact order:

  1. Draw u = rng.random().
  2. If u < epsilon, draw and return rng.integers(n_actions).
  3. Else return the action with the largest Q[s]. On a tie, return the lowest index.

Input and output

Name Type Shape Meaning
Q float array (n_states, n_actions) the action values
s, s_next int the state and the next state
a, a_next int the action and the next action
r float the reward of the transition
done bool True when s_next is terminal
alpha float the step size, from 0 to 1
gamma float the discount, from 0 to 1

  • s_next can be equal to s.

  • Use numpy only.

Common mistakes the checks catch
  • Draws the random action before the coin on every call, so the rng gives a different sequence.
  • Adds gamma times the max of the next row also when done is True.
  • Uses np.asarray in Q-learning, so the update writes into the caller's table.
  • Uses the max over the next actions in SARSA, not the given next action.
  • Uses Q[s, a] minus the target in Q-learning, so the value moves away from the target.
  • Returns the highest index of the largest Q value on a tie.
Hint 1

Start each update with a copy of the table, for example with np.array(Q, dtype=float). Then change the copy and return it.

Hint 2

Compute the target before you change Q[s, a]. When s_next equals s, the target must read the old row.

Hint 3

At a terminal step the next state has no future reward. Use 0 in place of the next value, so that the target is r.

Hint 4

np.argmax returns the first index of the largest value, so it gives the lowest index on a tie. Draw rng.random() first, and call rng.integers only in the random branch.

Reference solution and notes
import numpy as np


def q_learning_update(Q, s, a, r, s_next, done, alpha=0.1, gamma=0.99):
    Q = np.array(Q, dtype=float)
    best_next = 0.0 if done else np.max(Q[s_next])
    target = r + gamma * best_next
    Q[s, a] += alpha * (target - Q[s, a])
    return Q


def sarsa_update(Q, s, a, r, s_next, a_next, done, alpha=0.1, gamma=0.99):
    Q = np.array(Q, dtype=float)
    next_q = 0.0 if done else Q[s_next, a_next]
    target = r + gamma * next_q
    Q[s, a] += alpha * (target - Q[s, a])
    return Q


def epsilon_greedy(Q, s, epsilon, rng):
    q = np.asarray(Q)[s]
    if rng.random() < epsilon:
        return int(rng.integers(q.shape[0]))
    return int(np.argmax(q))

Off policy and on policy

Q-learning uses the max over the next actions. So it learns the values of the greedy policy, while the agent explores with another policy. This is an off policy method. SARSA uses the next action of the policy that runs. So it learns the values of the epsilon-greedy policy itself. On cliff walking, SARSA learns a safer path because its values include the cost of the random steps.

Why the terminal rule matters

A terminal state has no future. If the target adds γmaxQ[s′] at a terminal step, the values near the goal take the values of a state that the agent never leaves. The values then grow or drift and the policy can loop.

Why the order of the random draws matters

A seeded run gives the same result only when every call uses the generator in the same order. A second draw in each call changes every later action. The checks compare your actions with the actions of the stated order.

Where this goes next

DQN replaces the table with a network and uses the same Q-learning target. It adds a target network and a replay buffer to keep the target stable.

Solutions

SolutionP1 · SARSA, by a wide margin

SARSA, by a wide margin: about −27 per episode against about −51 for Q-learning over the last 100 of 500 episodes, even though SARSA walks a longer path. Q-learning walks the edge of the cliff, and with ε=0.1 every step there has a 2.5% chance of a random move off the edge, costing 100 and a restart. Its target, r+γmaxa​Q, values the edge as if no random move would ever happen. SARSA's target uses the move actually taken, exploration included, so it learns that the edge is costly for this agent and keeps two rows away. Which is "right" depends on whether exploration continues in deployment.

SolutionB1 · Harmless here, poison elsewhere

In the lesson's grid every Q-value of the terminal state stays 0, because nothing ever updates it, so max(Q[terminal]) is 0 and the bootstrapped target equals the correct r. The bug is invisible. It becomes poison wherever the "terminal" state's values are not zero: when the end state is also visited as a normal state, when terminal and time-limit endings are confused (a time limit is not a real end, and there you should bootstrap), or in function approximation, where the network outputs some arbitrary value for terminal inputs. Then every value leading into the end inherits a phantom continuation. Gymnasium separates terminated from truncated for exactly this reason: bootstrap on truncation, never on termination.
