In plain words first
The idea in one line

A plain autoencoder compresses then reconstructs. It memorizes. It does not generate. Add one trick — force the code to look Gaussian — and you get a sampler. That single trick, the reparameterization of z=μ+σ⋅ϵ, is why every latent-diffusion and flow-matching image model you use in 2026 has a VAE at the input.

Terms you'll hear
Term What people say What it actually means
Autoencoder Encode-decode network $x \to z \to \hat{x}$, learn MSE. Not generative.
VAE AE with a sampler Encoder outputs a distribution, KL penalty shapes code space.
ELBO Evidence lower bound $\log p(x) \ge \text{recon} - \mathrm{KL}[q(z \mid x) \Vert p(z)]$; tight when $q = p(z \mid x)$.
Reparameterization $z = \mu + \sigma \cdot \epsilon$ Rewrites stochastic node as deterministic + pure noise. Enables backprop through sampling.

VQ-VAE Discrete latent Replace continuous $z$ with nearest codebook vector; enables transformer modelling.

The problem

In plain words first

An autoencoder squeezes an input, say a photo, into a short list of numbers (the "code" or "latent") and then rebuilds the input from that list. It is a compressor, not a generator: pick a random code and the decoder produces garbage, because nothing made the codes fill a simple, predictable region. A variational autoencoder (VAE) fixes this by making the encoder output a small cloud of possible codes instead of one point, and by charging a penalty whenever those clouds stray from a standard bell curve. Then random draws from the bell curve decode to plausible outputs. Today the VAE's main job is different again: it is the compressor in front of nearly every image and video diffusion model, which works on its compact latents instead of on pixels. This lesson checks the lesson's hand-written VAE maths without training it, then runs the real VAE from Stable Diffusion on photos: compression, reconstructions, what its latents look like, and why decoding them is the memory peak of an image server.

Compress a 784-pixel MNIST digit to a 16-number code, then reconstruct. A plain autoencoder will ace reconstruction MSE but the code space is a lumpy mess. Pick a random point in the code space, decode it, and you get noise. It has no sampler. It is a compression model dressed up.

What you actually want is: (a) the code space is a clean, smooth distribution you can sample from — say an isotropic Gaussian N(0,I), (b) decoding any sample produces a plausible digit, and (c) the encoder and decoder still compress well. Three goals, one architecture, one loss.

Kingma's 2013 VAE solves this by training the encoder to output a distribution q(z∣x)=N(μ(x),σ(x)2), pulling that distribution toward the prior N(0,I) via a KL penalty, and then sampling z from q(z∣x) before decoding. At inference time, drop the encoder, sample z∼N(0,I), decode. The KL penalty is what forces the code space to be structured.

VAEs rarely ship as standalone generators any more (diffusion beats them on image quality), but they are the compressor in front of almost every latent-diffusion model: Stable Diffusion 1.x to 3.5, FLUX.1 and FLUX.2, Stable Audio, and video models such as Wan. Learn the VAE and you learn the invisible first layer of every image pipeline you use.

The idea

Autoencoder. z=encoder(x), x^=decoder(z), loss = ∥x−x^∥2. Code space unstructured.

VAE encoder. Outputs two vectors: μ(x) and logσ2(x). These define q(z∣x)=N(μ,diag(σ2)).

Reparameterization trick. Sampling from q(z∣x) is not differentiable. Rewrite the sample as z=μ+σ⋅ϵ where ϵ∼N(0,I). Now z is a deterministic function of (μ,σ) plus a non-parameter noise — gradients flow through μ and σ.

Loss. Evidence Lower BOund (ELBO), two terms:

loss​=reconstruction+β⋅KL[q(z∣x)∥N(0,I)]=∥x−x^∥2+β⋅i∑​2σi2​+μi2​−logσi2​−1​​

Reconstruction pushes x^ toward x. KL pushes q(z∣x) toward the prior. They trade off. Small β (<1) = sharper samples, code space less Gaussian. Large β (>1) = cleaner code space, blurrier samples. β-VAE (Higgins 2017) made this knob famous and kicked off disentanglement research.

Sampling. At inference: draw z∼N(0,I), forward through decoder. One forward pass — no iterative sampling like diffusion.

The same idea as a formula

Where the ELBO comes from. For any distribution q(z∣x), Bayes' rule p(x)=p(x∣z)p(z)/p(z∣x) gives, after taking logs and averaging over z∼q,

logp(x)=ELBOEq​[logp(x∣z)]−DKL​(q(z∣x)∥p(z))​​+DKL​(q(z∣x)∥p(z∣x))

The last term is never negative, so the ELBO is a lower bound on logp(x), equal to it exactly when q is the true posterior. Training raises the bound by improving the decoder and by moving q toward the posterior.

Gaussian decoder = squared error. If p(x∣z)=N(x^(z),σx2​I), then logp(x∣z)=−∥x−x^∥2/(2σx2​)+const. The lesson's ∥x−x^∥2+βKL is this with the constant dropped and σx2​ folded into β.

KL between diagonal Gaussians. For q=N(μ,diag(σ2)) and p=N(0,I),

DKL​(q∥p)=21​i∑​(σi2​+μi2​−logσi2​−1)

zero only when every μi​=0 and σi​=1.

Reparameterisation. With z=μ+σ⊙ε, ε∼N(0,I):

∇μ​Eq​[f(z)]=Eε​[∇z​f(z)],∂logσi2​∂zi​​=21​σi​εi​

so the gradient of an expectation becomes the expectation of an ordinary gradient, estimated with one sample per step.

Worked example
A VAE's numbers by hand

KL for one code. μ=(1,0), σ2=(0.5,1):

  • Dimension 1: 0.5+1−ln0.5−1=0.5+0.693=1.193.
  • Dimension 2: 1+0−0−1=0.
  • KL =21​(1.193+0)=0.597 nats. Only the dimension that strays from N(0,1) costs anything.

Stable Diffusion's compression. A 256×256×3 image has 196,608 numbers; its latent is 32×32×4=4,096, 48 times fewer. At 512×512: 786,432 against 16,384, the same ratio.

The decoder's memory peak. The decoder's last stages run 256 then 128 channels at the full output size. One fp32 activation with 256 channels at 512×512 is 256×512×512×4 bytes =256 MiB. Decoding in 256×256 tiles cuts that one tensor to 256×256×256×4 bytes =64 MiB. (Both numbers appear in the run under the production note.)

Check your mental model
  • ✗ "A VAE's latents follow N(0,I)."
    ✓ Only if the KL weight is large enough. Stable Diffusion's VAE was trained with a tiny KL weight, so its latents have a standard deviation near 4.6 and decoding draws from N(0,I) gives texture, not pictures (the run under "Use it").
  • ✗ "The KL term is what makes the VAE a good compressor."
    ✓ The reconstruction term does that; the KL term trades compression quality for a latent space you can sample from. Diffusion models sample for themselves, so their VAEs need little KL.
  • ✗ "Walking in a straight line between two latents morphs one object into another."
    ✓ In a VAE trained for reconstruction, the midpoint decodes to roughly a cross-fade of the two images. Semantic morphs come from the generative model working on top of the latents.

Step 1 · encoder forward

code/main.py implements a tiny VAE without numpy or torch. Input is 8-dimensional synthetic data drawn from a 2-component Gaussian mixture in 8-D. Encoder and decoder are single hidden-layer MLPs. We implement tanh activation, forward pass, loss, and a hand-written backward pass. Not production — pedagogy.

def encode(x, enc):
    h = tanh(add(matmul(enc["W1"], x), enc["b1"]))
    mu = add(matmul(enc["W_mu"], h), enc["b_mu"])
    log_sigma2 = add(matmul(enc["W_sig"], h), enc["b_sig"])
    return mu, log_sigma2

logσ2 instead of σ so the network output is unconstrained (softplus of σ is a trap — gradients die at σ≈0).

Step 2 · reparameterize and decode

def reparameterize(mu, log_sigma2, rng):
    eps = [rng.gauss(0, 1) for _ in mu]
    sigma = [math.exp(0.5 * lv) for lv in log_sigma2]
    return [m + s * e for m, s, e in zip(mu, sigma, eps)]

def decode(z, dec):
    h = tanh(add(matmul(dec["W1"], z), dec["b1"]))
    return add(matmul(dec["W_out"], h), dec["b_out"])

Step 3 · the ELBO

def elbo(x, x_hat, mu, log_sigma2, beta=1.0):
    recon = sum((a - b) ** 2 for a, b in zip(x, x_hat))
    kl = 0.5 * sum(math.exp(lv) + m * m - lv - 1 for m, lv in zip(mu, log_sigma2))
    return recon + beta * kl, recon, kl

Exact closed-form KL because both distributions are Gaussian. A Monte Carlo estimate (sample $z$, average $\log q(z) - \log p(z)$) is correct on average but noisy; the run after Step 4 shows how many samples it needs.

Step 4 · generate

def sample(dec, z_dim, rng):
    z = [rng.gauss(0, 1) for _ in range(z_dim)]
    return decode(z, dec)

That is the generative model. Five lines.

The lesson's VAE maths, checked

main.py's functions on the untrained 8-to-2-dimensional VAE (its main() trains the model, which this page does not run): the hand-written backward pass against finite differences, the closed-form KL against Monte Carlo estimates, and the ELBO on a one-dimensional model where logp(x) is known exactly.

import math, random, runpy, time
m = runpy.run_path("main.py")            # the lesson's functions; main() is not run, because it trains

# 1. The hand-written backward pass against finite differences, on the untrained VAE.
rng = random.Random(7)
params = m["init_vae"](8, 10, 2, rng)
x = m["sample_mixture"](1, 8, rng)[0]
eps = [rng.gauss(0, 1) for _ in range(2)]
beta = 0.2
loss = lambda: m["loss_value"](x, m["forward"](x, params, eps), beta)[0]
grads = m["backward"](x, m["forward"](x, params, eps), params, beta)
print("gradient check, hand-written backward vs central differences (h = 1e-5):")
for part in ("enc", "dec"):
    for name, t in params[part].items():
        rows = t if isinstance(t[0], list) else [t]
        g = grads[part][name]; g = g if isinstance(g[0], list) else [g]
        worst = 0.0
        for i, row in enumerate(rows):
            for j in range(len(row)):
                old = row[j]
                row[j] = old + 1e-5; up = loss()
                row[j] = old - 1e-5; down = loss()
                row[j] = old
                worst = max(worst, abs((up - down) / 2e-5 - g[i][j]))
        print(f"  {part}.{name:<6} {sum(map(len, rows)):>3} numbers  max |difference| {worst:.1e}")

# 2. The closed-form KL against a Monte Carlo estimate of E_q[log q(z) - log p(z)].
fwd = m["forward"](x, params, eps)
mu, lv = fwd["mu"], fwd["log_sigma2"]
kl_exact = 0.5 * sum(math.exp(v) + u * u - v - 1 for u, v in zip(mu, lv))
def kl_mc(n, r):
    tot = 0.0
    for _ in range(n):
        for u, v in zip(mu, lv):
            e = r.gauss(0, 1); z = u + math.exp(0.5 * v) * e
            tot += (-0.5 * v - 0.5 * e * e) - (-0.5 * z * z)   # log q - log p; the 2*pi terms cancel
    return tot / n
print(f"\nKL(q(z|x) || N(0, I)) closed form: {kl_exact:.4f}")
r = random.Random(0)
for n in (1, 10, 100, 10_000):
    ests = [kl_mc(n, r) for _ in range(20)]
    mean = sum(ests) / 20; sd = (sum((e - mean) ** 2 for e in ests) / 19) ** 0.5
    print(f"  Monte Carlo with {n:>6,} samples: {mean:.4f} +/- {sd:.4f} (spread over 20 repeats)")

# 3. The ELBO is a lower bound, tight at the true posterior, on a model where log p(x) is known.
#    z ~ N(0, 1), x | z ~ N(a z, s^2)  =>  p(x) = N(0, a^2 + s^2), posterior N(a x / (a^2 + s^2), s^2 / (a^2 + s^2)).
a, s, xo = 2.0, 0.5, 1.3
log_px = -0.5 * math.log(2 * math.pi * (a * a + s * s)) - xo * xo / (2 * (a * a + s * s))
def elbo(mq, vq):
    rec = -0.5 * math.log(2 * math.pi * s * s) - ((xo - a * mq) ** 2 + a * a * vq) / (2 * s * s)
    kl = 0.5 * (vq + mq * mq - math.log(vq) - 1)
    return rec, kl, rec - kl
mt, vt = a * xo / (a * a + s * s), s * s / (a * a + s * s)
print(f"\nlog p(x) = {log_px:.4f} for x = {xo}")
for label, (mq, vq) in [("true posterior", (mt, vt)), ("mean off by 0.2", (mt + 0.2, vt)),
                        ("variance x 4", (mt, 4 * vt)), ("the prior N(0, 1)", (0.0, 1.0))]:
    rec, kl, e = elbo(mq, vq)
    print(f"  q = {label:<18} recon {rec:8.4f}  KL {kl:6.4f}  ELBO {e:8.4f}  gap {log_px - e:.4f}")

Reading this output

Every gradient of the hand-written backward pass, through the reparameterisation and both loss terms, matches a finite-difference estimate to about 10−10, so the derivatives in Step 2's comments are right. The closed-form KL is 0.0273; Monte Carlo estimates scatter around it, with a spread larger than the value itself at 1 or 10 samples and still about 8% at 10,000, which is why the formula is used. The last table is the formula box's identity: with the true posterior the ELBO equals logp(x) exactly; any other q leaves a gap, and the gap is the KL divergence from the true posterior. Using the prior as q makes the KL term zero but ruins the reconstruction term, the extreme of posterior collapse.

Pitfalls

  • Posterior collapse. KL term drives q(z∣x)→N(0,I) so aggressively that z carries no info about x. Fix: β-annealing (start β=0, ramp to 1), free bits, or skip the KL on inactive dimensions.
  • Blurry samples. The Gaussian decoder likelihood implies MSE reconstruction, which is Bayes-optimal for L2 (the mean) — the mean of a set of plausible digits is a fuzzy digit. Fix: discrete decoder (VQ-VAE, NVAE), or use the VAE only as an encoder and stack diffusion on the latents (this is what Stable Diffusion does).
  • β too large, too early. See posterior collapse. Start at β≈0.01 and ramp.
  • Latent too small. With too few latent numbers, reconstructions lose fine detail however long you train. Stable Diffusion's VAE compresses 512×512×3 → 64×64×4 (8x downsample per side, 64x in spatial area; channels go from 3 to 4, so about 48x fewer values overall). SD3 and FLUX.1 keep the 8x downsampling but use 16 channels, which preserves small text and faces much better.

Use it: the same idea with real libraries

The 2026 VAE stack:

Situation Pick
Image-latent encoder for diffusion The VAE the diffusion model was trained with: SD 1.x (sd-vae-ft-mse, run below), SDXL, SD3.5 or FLUX.1 (16 channels), FLUX.2 (its own new VAE). Latents are not interchangeable between them.
Audio-latent encoder Continuous latents: Stable Audio Open's VAE; discrete tokens: EnCodec, DAC, Mimi
Video latents Causal 3D VAEs that compress time as well as space: Wan-VAE, HunyuanVideo's VAE, LTX-Video's VAE
Disentangled representation learning β-VAE, FactorVAE, TCVAE
Discrete latents (for transformer modelling) VQ-VAE, RVQ (ResidualVQ)
Continuous latents for generation Plain VAE, then condition a flow/diffusion model in that latent space

A latent-diffusion model is a VAE with a diffusion model living between encoder and decoder. The VAE does coarse compression, the diffusion model does the heavy lifting. Same pattern for video (VAE + video-diffusion DiT) and audio (Encodec + MusicGen transformer).

import io, numpy as np, torch
import matplotlib.pyplot as plt
import pyarrow.parquet as pq
from PIL import Image
from huggingface_hub import hf_hub_download
from diffusers import AutoencoderKL

# Stable Diffusion's VAE (the fine-tuned "ft-mse" decoder): 256 x 256 x 3 images <-> 32 x 32 x 4 latents.
vae = AutoencoderKL.from_pretrained("stabilityai/sd-vae-ft-mse").eval()
table = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
                                      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"), columns=["image"])
def load(row, size=256):
    im = Image.open(io.BytesIO(table.column("image")[row].as_py()["bytes"])).convert("RGB")
    w, h = im.size; s = size / min(w, h)
    im = im.resize((round(w * s), round(h * s)), Image.BICUBIC)
    l, t = (im.width - size) // 2, (im.height - size) // 2
    return torch.tensor(np.asarray(im.crop((l, t, l + size, t + size))), dtype=torch.float32).permute(2, 0, 1) / 127.5 - 1

x = torch.stack([load(r) for r in (0, 1200, 3000)])
with torch.no_grad():
    post = vae.encode(x).latent_dist                       # q(z|x) = N(mu, sigma^2), one Gaussian per latent number
    z = post.sample(generator=torch.Generator().manual_seed(0))
    x_hat = vae.decode(z).sample.clamp(-1, 1)
mse = ((x_hat - x) / 2).pow(2).mean((1, 2, 3))
print(f"image {tuple(x.shape[1:])} = {x[0].numel():,} numbers -> latent {tuple(z.shape[1:])} = {z[0].numel():,} numbers "
      f"({x[0].numel() / z[0].numel():.0f}x fewer)")
print("reconstruction PSNR per image (dB):", ", ".join(f"{10 * torch.log10(1 / m):.1f}" for m in mse))
print(f"posterior: mean |mu| {post.mean.abs().mean():.2f}, mean sigma {post.std.mean():.4f}; "
      f"latent std {z.std():.2f} (Stable Diffusion rescales latents by {vae.config.scaling_factor} to make it about 1)")
kl = 0.5 * (post.mean ** 2 + post.var - 1 - post.logvar).sum((1, 2, 3))
print(f"KL(q(z|x) || N(0, I)) per image: {kl.mean():,.0f} nats, about {kl.mean() / z[0].numel():.1f} per latent number")

# Decoding samples from the prior N(0, I), and walking between two images' latents.
with torch.no_grad():
    prior = vae.decode(torch.randn(2, 4, 32, 32, generator=torch.Generator().manual_seed(1)) / vae.config.scaling_factor).sample.clamp(-1, 1)
    walk = vae.decode(torch.stack([(1 - a) * z[0] + a * z[2] for a in (0.0, 0.33, 0.67, 1.0)])).sample.clamp(-1, 1)
show = lambda t: ((t + 1) / 2).permute(1, 2, 0).numpy()
fig, axes = plt.subplots(3, 4, figsize=(9, 7))
for k in range(3):
    axes[0, k].imshow(show(x[k])); axes[1, k].imshow(show(x_hat[k]))
axes[0, 3].imshow(show(prior[0])); axes[1, 3].imshow(show(prior[1]))
for k in range(4): axes[2, k].imshow(show(walk[k]))
for a in axes.ravel(): a.axis("off")
axes[0, 0].set_title("originals", loc="left", fontsize=9); axes[1, 0].set_title("decoded from their latents", loc="left", fontsize=9)
axes[0, 3].set_title("decoded from N(0, I)", fontsize=9)
axes[2, 0].set_title("straight line between two latents", loc="left", fontsize=9)

Industry practice
What's current (2024–2026)
  • 16-channel image VAEs and beyond. FLUX.1 and Stable Diffusion 3.5 encode at 8× downsampling with 16 latent channels instead of 4, several open models reuse the FLUX.1 VAE, and FLUX.2 trained a new one (AutoencoderKLFlux2); they load in diffusers as AutoencoderKL.
  • Causal video VAEs. Wan 2.x, HunyuanVideo and LTX-Video compress time as well as space, so a few seconds of video become a small latent the diffusion transformer can afford; their decoders are run tiled in ComfyUI and diffusers to fit consumer GPUs.
  • Tiny preview decoders. TAESD and its SDXL, SD3 and FLUX variants decode latents to rough previews in milliseconds; ComfyUI and other front ends use them to show images forming during sampling.

Sources: diffusers AutoencoderKL, FLUX.2 in diffusers, Wan 2.1, LTX-Video, TAESD, SDXL fp16 fix.

Recap
What to keep from this lesson
  • The encoder outputs μ and logσ2; sample z=μ+σε; decode; loss = reconstruction + β⋅ KL.
  • logp(x)=ELBO+DKL​(q∥p(z∣x)): the ELBO is a bound, tight at the true posterior.
  • KL to N(0,I) in closed form: 21​∑(σ2+μ2−logσ2−1).
  • Latent-diffusion VAEs are compressors (48× for SD, 8× per side) with little KL; their latents are not N(0,I) and must be rescaled.
  • Decoding is the memory peak; tiling cuts it at some cost in time and quality.

Given a dataset profile (modality, resolution, dataset size) and the downstream use (reconstruction only, sampling, or input-encoder for a latent-diffusion or token-AR model), output:

1. Variant. Plain VAE, beta-VAE, VQ-VAE, RVQ (residual), or NVAE. One-sentence reason tied to modality and downstream use.
2. Architecture. Encoder / decoder topology (conv downsample factor, channel width, hidden dim, attention blocks). Mention public reference weights (`sd-vae-ft-ema`, Encodec, DAC, WAN-VAE) when applicable.
3. Latent dim. Spatial and channel dims. Total bits per sample. Compression ratio vs the raw data.
4. Beta schedule. Warmup ramp, final value, and free-bits threshold if used.
5. Eval plan. Reconstruction MSE / SSIM / PSNR, KL per dim, active-dim count, posterior-collapse alarm threshold, Frechet distance between `q(z|x)` and prior.

Refuse to ship a VAE with beta > 0.5 at training start (posterior collapse). Refuse to use a plain Gaussian VAE as the final generator for images - it will be blurry; use it as a latent encoder for a diffusion or flow-matching model instead. Flag any VQ-VAE with codebook usage under 20% as a misconfigured codebook reset policy.

Exercises

  1. Easy. Change β in code/main.py to 0.01, 0.1, 1.0, 5.0. Record the final reconstruction MSE and KL. Which β is Pareto-best for your synthetic data?
  2. Medium. Replace the Gaussian decoder likelihood with a Bernoulli likelihood (cross-entropy loss). Compare sample quality on a binarized version of the same synthetic data.
  3. Hard. Extend code/main.py into a mini VQ-VAE: replace the continuous z with a nearest-neighbour lookup in a codebook of K=32 entries. Compare reconstruction MSE and report how many codebook entries get used (codebook collapse is real).

Solutions

SolutionP1 · Not a photo at all

Not a photo at all: coloured, grainy texture (the right column of the first two rows). A VAE samples well only if its training pushed the latents toward N(0,I). Stable Diffusion's VAE was trained almost purely for reconstruction, so real latents have their own structure (standard deviation about 4.6 and strong correlations between neighbouring positions and channels), and independent Gaussian noise looks like none of them. Producing a latent that decodes to a photo is the job of the diffusion model trained on top (Lessons 8.6 and 8.7). A VAE trained with β=1 would give blurry but recognisable samples, the classic VAE trade-off.

SolutionB1 · The sampled and the charged distributions differ

The encoder's output is still called log_sigma2, and the KL term still charges for a Gaussian with variance elv, but samples are now drawn with standard deviation elv, that is, variance e2lv. The loss describes one distribution and the model samples from another, so the ELBO is no longer a bound on anything. Worse, backward still uses ∂z/∂lv=21​σε, which was the derivative for the old formula; the true derivative is now σε. The gradient check after Step 4 flags enc.W_sig and enc.b_sig at once, with differences many orders of magnitude above 10−10. A falling loss is not evidence that the gradients are right.

Production note: the VAE is the hottest path in a diffusion server

In a Stable Diffusion / Flux / SD3 pipeline the VAE is called twice per request — once to encode (if doing img2img / inpainting) and once to decode. At 1024² the decoder pass is often the single largest activation-memory peak in the whole pipeline because it upsamples 128×128×16 latents back to 1024×1024×3. Two practical consequences:

  • Slice or tile the decode. diffusers exposes pipe.vae.enable_slicing() and pipe.vae.enable_tiling(). Tiling trades a small seam artifact for O(tile2) memory instead of O(H⋅W). Essential for 1024²+ on consumer GPUs.
  • Watch the decoder's precision. The SDXL VAE overflows in fp16 and silently produces NaNs (black images). The community madebyollin/sdxl-vae-fp16-fix rescales its weights to stay in range, and diffusers upcasts the SDXL VAE to fp32 by default (force_upcast). bf16, which has fp32's exponent range, avoids the overflow.

Whole against tiled decoding

The same VAE decodes one 512×512 photo's latent in one piece and then with enable_tiling() (256×256 tiles that overlap and are blended), with the time and the largest single memory allocation of each.

import time, torch
from diffusers import AutoencoderKL
from torch.profiler import profile, ProfilerActivity

torch.manual_seed(0); torch.set_num_threads(2)
vae = AutoencoderKL.from_pretrained("stabilityai/sd-vae-ft-mse").eval()
import io, numpy as np, pyarrow.parquet as pq
from PIL import Image
from huggingface_hub import hf_hub_download
row = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"), columns=["image"]).column("image")[1200].as_py()
im = Image.open(io.BytesIO(row["bytes"])).convert("RGB").resize((512, 512), Image.BICUBIC)
x = torch.tensor(np.asarray(im), dtype=torch.float32).permute(2, 0, 1)[None] / 127.5 - 1
with torch.no_grad():
    z = vae.encode(x).latent_dist.mean    # the latent of one 512 x 512 photo: 4 x 64 x 64
print(f"decoder: {sum(p.numel() for p in vae.decoder.parameters()) / 1e6:.1f}M parameters; "
      f"encoder: {sum(p.numel() for p in vae.encoder.parameters()) / 1e6:.1f}M")
outs = {}
for mode in ("whole", "tiled"):
    vae.enable_tiling() if mode == "tiled" else vae.disable_tiling()
    with torch.no_grad(), profile(activities=[ProfilerActivity.CPU], profile_memory=True) as prof:
        t = time.perf_counter(); outs[mode] = vae.decode(z).sample; dt = time.perf_counter() - t
    biggest = max(e.cpu_memory_usage for e in prof.events())
    print(f"{mode:>5} decode of 64x64x4 -> {tuple(outs[mode].shape[1:])}: {dt:5.1f} s, "
          f"largest single allocation {biggest / 2**20:6.0f} MB")
d = (outs["whole"] - outs["tiled"]).abs()
print(f"tiled vs whole: mean |difference| {d.mean():.3f}, max {d.max():.2f} (pixel range -1..1)")
for mode in outs:
    mse = ((outs[mode].clamp(-1, 1) - x) / 2).pow(2).mean()
    print(f"  PSNR of the {mode} decode against the original photo: {10 * torch.log10(1 / mse):.1f} dB")

Reading this output

Decoding a 64×64×4 latent to a 512×512 photo takes about 13 seconds on this page's CPU, and its largest single allocation is 256 MB, exactly the worked example's 256-channel activation at full size. Tiling cuts that peak to 64 MB, a quarter, as predicted for 256×256 tiles, and the saving grows with the image: at 2048×2048 the untiled tensor would be 4 GiB while the tiled one stays at 64 MiB. It is not free: tiling took longer here, because overlapping tiles decode some pixels twice, and the result differs from the untiled decode, most at the image borders, lowering the PSNR against the original photo by about 4 dB. Each tile is decoded without seeing the rest of the image, and the decoder's normalisation layers compute their statistics per tile. That is why servers tile only above the size where memory forces it.
