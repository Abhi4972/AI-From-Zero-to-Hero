The problem

In plain words first

An audio-language model is a chat model that can listen. You give it a recording and a question in words ("Is anyone in danger?", "What instrument plays the melody?", "Summarise this meeting") and it answers in words, sometimes in speech. Almost all of them are built the same way: an audio encoder (often Whisper's) turns sound into vectors, a small projector translates those vectors into the "word vectors" a language model reads, and an ordinary LLM does the rest. Before such models existed, products chained separate parts instead: speech recognition and a sound tagger produce text, and a text-only LLM reasons over that text. This lesson builds both shapes from real parts on a CPU: Whisper's encoder feeding a projector into a small LLM's embedding space, to see the sizes and token counts involved, and a working cascade (Whisper + CLAP tags + a 0.5B LLM) to see what text throws away. The large models themselves are too big to run here, and nothing is trained.

You have 5 seconds of audio: dog barks, someone yells "stop!", then silence. Useful questions span multiple axes:

  • Transcription. "What was said?" — ASR territory.
  • Semantic reasoning. "Is the person in danger?" — requires joint understanding of the bark + yell + silence.
  • Music reasoning. "What instruments play the melody?"
  • Long-audio retrieval. "Where in this 90-minute lecture did the instructor explain gradient descent?"

A single model that answers all of these with one prompt is an audio-language model (LALM / ALM). Separate from pure ASR: LALMs produce free-form natural-language answers, not just transcripts.

The idea

The same idea as a formula

The pipeline. An encoder maps audio x to frame vectors H=Enc(x)∈RT×da​, optionally pooled in time; a projector g maps each to the LLM's width, A=g(H)∈RT′×d; the LLM reads a sequence that mixes text-token embeddings and the rows of A, and generates the answer:

P(y∣x,q)=u∏​PLLM​(yu​∣y<u​,[E(qpre​);A;E(qpost​)])

Training stages. Stage 1 trains only g (encoder and LLM frozen) with cross-entropy on paired text, usually transcripts or captions: L=−∑u​logP(yu​∣y<u​,A). Later stages fine-tune more of the network (often with LoRA) on instructions such as "answer the question about this clip".

Token budget. With an encoder at r frames per second and pooling by p, a clip of S seconds costs Sr/p tokens. Text is far denser: speech at about 2.5 words per second is roughly 3 text tokens per second.

Multiple-choice evaluation. With k options, chance is 1/k. With n questions, the standard error of an accuracy near a is a(1−a)/n​, so differences of a few points on a few hundred questions are noise.

Worked example
Token budgets and chance levels by hand

Whisper features. Whisper's encoder gives 50 frames per second; pooling by 2 (as Qwen2-Audio does) gives 25. A 12.5 s clip: 12.5×25=312 audio tokens, as the run under Step 2 finds. Its transcript is 33 text tokens, so the audio form is about 9.5 times longer.

An hour of audio. At 25 tokens per second, 3600×25=90,000 tokens; Google documents 32 tokens per second for Gemini, 115,200 tokens per hour. Long recordings fill context windows fast, which is one reason meeting tools transcribe and chunk first.

Chance. Four options: 25%. A model at 30% on 200 such questions has standard error 0.3×0.7/200​=3.2 points, so 30% is only about 1.5 standard errors above chance.

Check your mental model
  • ✗ "An audio-language model hears everything a person would."
    ✓ It hears what its encoder represents and what its training data asked about. Benchmarks find near-chance skills, such as comparing clips.
  • ✗ "Transcribe, then ask an LLM: same result."
    ✓ A transcript drops tone, speaker, background sounds and timing unless other tools add them as text, and errors in each step add up.
  • ✗ "The projector is where the intelligence lives."
    ✓ It is a small adapter (about 1.3M parameters in the run below); its job is to put audio features where the LLM can use them.

Idea 1 · The three-component template

Almost every LALM has the same skeleton:

  1. Audio encoder. Whisper encoder · BEATs · CLAP · WavLM · or a custom encoder per model.
  2. Projector. Linear or MLP bridging audio-encoder features into the LLM's token embedding space.
  3. LLM. Llama / Qwen / Gemma-based decoder. Takes interleaved text + audio tokens; generates text.

Training:

  • Stage 1. Freeze encoder + LLM; train projector only on ASR / captioning data.
  • Stage 2. Full / LoRA fine-tune on instruction-following audio tasks (QA, reasoning, music understanding).
  • Stage 3 (optional). Voice-in / voice-out adds a speech decoder. Qwen2.5-Omni and AF3-Chat do this.

Idea 4 · Where LALMs are useful in 2026

  • Compliance audit of call-center recordings. "Did the agent mention the required disclosure?"
  • Accessibility. Describe sound events to deaf users (not just transcription).
  • Content moderation. Detect violent language + threatening tone + background context.
  • Podcast / meeting chaptering. Semantic summary, not just speaker turns.
  • Music catalog analysis. "Find all tracks with a B-section key change."

Idea 5 · Where they are NOT (yet) useful

  • Fine-grained music theory (below chord-level).
  • Speaker-attributed reasoning over long conversations (it degrades as recordings get longer).
  • Comparing several clips, and other MMAU-Pro categories where models score near chance.
  • Real-time streaming reasoning (most are offline batch inference).

Step 2 · the projector pattern

import torch.nn as nn

class AudioProjector(nn.Module):
    def __init__(self, audio_dim=1280, llm_dim=4096):
        super().__init__()
        self.down = nn.Linear(audio_dim, llm_dim)
        self.act = nn.GELU()
        self.up = nn.Linear(llm_dim, llm_dim)

    def forward(self, audio_features):
        return self.up(self.act(self.down(audio_features)))

That's it. The projector is usually 1-3 linear layers. Training it on ASR pairs (audio → transcript) is the Stage-1 pretext task.

The three parts with real components

Whisper base.en's encoder on a 12.5 s LibriSpeech clip, 2× pooling, Step 2's projector (untrained) into the embedding space of Qwen2.5-0.5B-Instruct, and a comparison with the transcript's text tokens.

import io
import numpy as np, torch, soundfile as sf
from datasets import load_dataset, Audio
from transformers import WhisperProcessor, WhisperForConditionalGeneration, AutoTokenizer, AutoModelForCausalLM

libri = load_dataset("hf-internal-testing/librispeech_asr_dummy", "clean", split="validation").cast_column("audio", Audio(decode=False))
def clip(i):
    return sf.read(io.BytesIO(libri[i]["audio"]["bytes"]), dtype="float32")[0]

# The three parts, with real components: Whisper's encoder, a projector, and a small LLM's embedding space.
wproc = WhisperProcessor.from_pretrained("openai/whisper-base.en")
whisper = WhisperForConditionalGeneration.from_pretrained("openai/whisper-base.en").eval()
ltok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct", dtype=torch.float32).eval()

audio = clip(2)                                                    # a 12.5 s utterance
with torch.no_grad():
    feats = whisper.model.encoder(wproc(audio, sampling_rate=16000, return_tensors="pt").input_features).last_hidden_state
n_real = int(len(audio) / 16000 * 50)                              # encoder frames that cover real audio (50 per s)
feats = feats[:, :n_real]                                          # drop the padding up to 30 s
pooled = torch.nn.functional.avg_pool1d(feats.transpose(1, 2), 2).transpose(1, 2)   # 2x pooling, as Qwen2-Audio does
llm_dim = llm.config.hidden_size
proj = AudioProjector(audio_dim=feats.shape[-1], llm_dim=llm_dim)   # Step 2's class, untrained here
with torch.no_grad():
    audio_tokens = proj(pooled)
text = libri[2]["text"].lower()
text_ids = ltok(text)["input_ids"]
print(f"{len(audio) / 16000:.1f} s of speech -> Whisper encoder {tuple(feats.shape)} -> pooled {tuple(pooled.shape)} "
      f"-> projector -> {tuple(audio_tokens.shape)} in the LLM's {llm_dim}-dim embedding space")
print(f"projector parameters: {sum(p.numel() for p in proj.parameters()):,}; "
      f"LLM parameters: {sum(p.numel() for p in llm.parameters()) / 1e6:.0f}M")
print(f"the same content as text: {len(text_ids)} tokens; as audio: {audio_tokens.shape[1]} tokens "
      f"({audio_tokens.shape[1] / len(text_ids):.1f}x more)")
txt_emb = llm.get_input_embeddings()(torch.tensor(text_ids))
print(f"scale check: text embeddings have norm {txt_emb.norm(dim=-1).mean():.2f}, untrained projector outputs {audio_tokens.norm(dim=-1).mean():.2f}")
What you should see
12.5 s of speech -> Whisper encoder (1, 624, 512) -> pooled (1, 312, 512) -> projector -> (1, 312, 896) in the LLM's 896-dim embedding space
projector parameters: 1,263,360; LLM parameters: 494M

Reading this output

12.5 s of speech becomes 624 encoder frames of 512 numbers (the rest of Whisper's 30 s window is padding and is dropped), 312 after pooling, and 312 vectors of 896 numbers after the projector: the same width as the LLM's word embeddings. The projector has 1.3M parameters against the LLM's 494M, so Stage 1 training is cheap. The same content as text is 33 tokens, so the audio form costs 9.5 times as much context. The last line shows why training is still needed: the untrained projector's outputs have norm 7.6 where real token embeddings have 0.4, so the LLM would read them as noise. Stage 1 learns a mapping that lands audio where the LLM expects meaning.

The cascade: transcript and tags as text

Whisper base.en transcribes; CLAP (from Lesson 6.9) picks the top sound tags from six labels; Qwen2.5-0.5B-Instruct answers from that text. Three inputs: a reading, the reading with a synthetic siren behind it, the siren alone.

import librosa
from transformers import ClapModel, ClapProcessor

# The cascade most products start with: ASR + a sound tagger turn audio into text, then a text LLM reasons over it.
clap = ClapModel.from_pretrained("laion/clap-htsat-unfused").eval()
cproc = ClapProcessor.from_pretrained("laion/clap-htsat-unfused")
labels = ["people talking", "a siren", "a dog barking", "music", "drums", "silence"]
with torch.no_grad():
    t_emb = clap.get_text_features(**cproc(text=labels, return_tensors="pt", padding=True))
t_emb = torch.nn.functional.normalize(getattr(t_emb, "pooler_output", t_emb), dim=-1)

def tags(w):                                            # zero-shot sound tags from CLAP, at 48 kHz
    with torch.no_grad():
        a = clap.get_audio_features(**cproc(audio=[librosa.resample(w, orig_sr=16000, target_sr=48000)], sampling_rate=48000, return_tensors="pt"))
    a = torch.nn.functional.normalize(getattr(a, "pooler_output", a), dim=-1)
    p = torch.softmax(100 * a @ t_emb.T, -1)[0]          # CLAP's usual temperature
    return sorted(zip(labels, p.tolist()), key=lambda x: -x[1])[:3]

def transcribe(w):
    with torch.no_grad():
        return wproc.batch_decode(whisper.generate(wproc(w, sampling_rate=16000, return_tensors="pt").input_features),
                                  skip_special_tokens=True)[0].strip()

def ask(context, question):
    msgs = [{"role": "user", "content": f"{context}\n\nQuestion: {question} Answer in one sentence."}]
    ids = ltok.apply_chat_template(msgs, add_generation_prompt=True, return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=50, do_sample=False)
    return ltok.decode(out[0, ids.shape[1]:], skip_special_tokens=True).strip()

sr = 16000; t = np.arange(6 * sr) / sr
siren = 0.25 * np.sin(2 * np.pi * np.cumsum(900 + 300 * np.sin(2 * np.pi * 0.5 * t)) / sr)
speech = clip(1)[: 6 * sr]; speech = np.pad(speech, (0, 6 * sr - len(speech)))
cases = {"a LibriSpeech reading": speech, "the same reading with a siren behind it": (speech + siren).astype(np.float32),
         "the siren alone": siren.astype(np.float32)}
for name, w in cases.items():
    ctx = f"Transcript: \"{transcribe(w)}\"\nSound tags: " + ", ".join(f"{l} ({p:.2f})" for l, p in tags(w))
    print(f"--- {name}\n{ctx}\nLLM: {ask(ctx, 'What is happening, and is there any sign of an emergency?')}\n")

Reading this output

The tagger finds the siren in both siren clips. It also calls the clean reading "music" with full confidence: zero-shot tags over a short label list are brittle, and the softmax at CLAP's temperature makes every answer look certain. The transcript of the siren alone is "you", Whisper's familiar hallucination on non-speech (Lesson 6.4). The LLM then has the right evidence ("a siren (1.00)") and still answers "no immediate indication of an emergency", partly because a 0.5B model reasons weakly and partly because the cascade hands it a flat list of strings with no sense of loudness, timing or tone. End-to-end audio-language models exist to keep that information; the cascade is still the common first build because each part can be tested and swapped on its own.

Industry practice
What's current (2024–2026)
  • Open models in use. Qwen2.5-Omni and Qwen3-Omni (Apache-2.0, speech in and out), Mistral's Voxtral (Apache-2.0, speech understanding), and NVIDIA's Audio Flamingo 3 (non-commercial) are the commonly deployed open options.
  • APIs. Gemini 2.5 accepts long audio directly and is a frequent choice for meeting and call analysis; OpenAI's gpt-realtime serves low-latency voice agents (Lesson 6.15).
  • Evaluation. MMAU-Pro (5,305 instances, 49 skills) is the reference benchmark; its paper found leading models near chance in several categories, so test the skills your product needs.

Sources: MMAU-Pro paper, Qwen2.5-Omni-7B, Audio Flamingo 3, Voxtral, Gemini audio understanding docs.

Pitfalls

  • Over-trust on multi-audio. If your task needs "which clip has X," random-chance-level performance is real.
  • Long-audio degradation. On long recordings, speaker attribution breaks down. Diarize first (Lesson 6.6), then summarize.
  • Hallucinations on silence. Same Whisper-style issue inherited by LALMs that use Whisper encoder. VAD-gate.
  • Benchmark cherry-picking. Vendor blog posts highlight best-case categories. Run the MMAU-Pro categories that match your task yourself.
Recap
What to keep from this lesson
  • Audio encoder → projector → LLM; the projector is small and trained first, the LLM does the reasoning.
  • Audio costs many more tokens than its transcript (25–50 per second against about 3); long recordings need chunking or summaries.
  • Cascades (ASR + taggers + text LLM) are easy to build and test but lose tone, timing and background sound.
  • Benchmarks (MMAU-Pro) show strong speech skills and near-chance results in some categories; test your own task.
  • Zero-shot tags and transcripts can be confidently wrong; carry scores and VAD into the prompt.

  3. Hard. Build a minimal audio-captioning baseline: BEATs encoder + 2-layer projector + frozen Llama-3.2-1B. Fine-tune only the projector on AudioCaps. Compare to SALMONN on Clotho-AQA.

Solutions

SolutionP1 · Tags yes, reasoning no

CLAP tags the siren correctly in both siren clips (1.00), but the 0.5B LLM says there is no immediate emergency in all three cases, even when "a siren" is the top tag. The evidence reached the LLM as text; the conclusion did not follow. A larger LLM or an explicit rule ("siren or alarm tag above 0.8 → escalate") would do better.

SolutionB1 · Synonyms split the vote

With several near-synonyms, the softmax spreads probability across them, so no single label looks as certain, and the top tag may change between runs or clips ("police siren" vs "ambulance siren"). Sum the probabilities of labels that mean the same thing (or compare the raw cosine scores with a threshold) before deciding, and pass the grouped result to the LLM.
