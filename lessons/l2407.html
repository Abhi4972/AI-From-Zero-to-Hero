Why this came about

Early neural networks treated an image as one long list of pixels, with a separate weight from every pixel to every neuron. That wastes weights and has to relearn a pattern at every position where it might appear. In 1989 Yann LeCun trained a network for reading handwritten postcodes that instead slid small shared filters across the image: a convolutional neural network (CNN). It worked, banks used it to read cheques, and then the idea waited for data and computing power. In 2012 a larger CNN, AlexNet, trained on GPUs, won the ImageNet competition by a margin that surprised the whole field. That result started the deep learning era (Lesson 3.1). CNNs dominated computer vision for the next eight years, until transformerslater · 7.8 arrived there too.

In plain words first
A small stencil slid across the picture

Imagine checking a page for the letter "T" with a small cardboard stencil. You place the stencil on the top-left corner, see how well what is underneath matches, move it one step, and repeat until you have covered the page. You end up with a map of where the pattern appears. A convolutional layer does this with many stencils at once, and it learns what the stencils should look for. The first layer learns simple stencils such as edges; the next layer slides stencils over the first layer's maps and finds combinations such as corners and loops; and so on up to whole objects.

Step 1 · An image is a grid of numbers

A greyscale image is a table of brightness values. scikit-learn ships with 1,797 small handwritten digits, each 8 pixels by 8, with brightness from 0 (black) to 16 (white). A colour image is three such grids stacked (red, green, blue), called channels.

import numpy as np
from sklearn.datasets import load_digits

digits = load_digits()                                   # 1,797 handwritten digits, each an 8 x 8 grid of brightness values 0 to 16
image = digits.images[7]
print("label:", digits.target[7], "| shape:", image.shape)
for row in image:

Step 2 · Convolution by hand

A filter (or kernel) is a small grid of weights. To apply it, lay it over a 3 × 3 patch of the image, multiply each weight by the pixel under it, and add the nine products into one number. Then slide one pixel along and repeat. This filter has −1 on the left and +1 on the right, so it gives a large positive number wherever the image gets brighter from left to right: a vertical-edge detector.

edge = np.array([[-1, 0, 1],
                 [-1, 0, 1],
                 [-1, 0, 1]])                            # a 3 x 3 filter: bright on the right minus bright on the left

def convolve(img, kernel):
    """Slide the kernel over every 3 x 3 patch; at each position, multiply cell by cell and add up."""
    h, w = img.shape[0] - 2, img.shape[1] - 2
    out = np.zeros((h, w))
    for i in range(h):
        for j in range(w):
            out[i, j] = np.sum(img[i:i + 3, j:j + 3] * kernel)
    return out

response = convolve(image, edge)
print("output shape:", response.shape)
for row in response:
    print(" ".join(f"{int(v):4d}" for v in row))
What you should see

The output is 6 × 6 because a 3 × 3 window fits in 6 positions across an 8-pixel row. Large positive numbers mark places where the stroke of the 7 begins as you move right; large negative numbers mark where it ends. The output is called a feature map: a map of where the feature was found.

Reading this output
Four things to notice
  • The filter has 9 weights and they are reused at all 36 positions. A fully connected layer from 64 pixels to 36 outputs would need 2,304 weights. This is weight sharing.
  • Each output looks only at a small local patch. Nearby pixels matter to each other far more than distant ones, and convolution builds that assumption in.
  • If the digit moves two pixels right, the feature map moves two pixels right too, with the same values. This is translation equivariance: the network does not have to relearn the pattern at each position.
  • In a CNN nobody designs the filters. They start random and are learned by gradient descent, like every other weight (Lesson 3.6).

Step 3 · A fair test: digits that move

To see what convolution buys, set up an experiment. Put each digit on a larger 12 × 12 black canvas. Train on digits placed in the centre. Then test on digits moved a few pixels, which a person would find no harder.

import torch, torch.nn as nn
torch.manual_seed(0)

def on_canvas(images, shift=(0, 0)):
    """Place each 8 x 8 digit on a 12 x 12 black canvas, moved from the centre by `shift` pixels (down, right)."""
    canvas = np.zeros((len(images), 12, 12), dtype=np.float32)
    r, c = 2 + shift[0], 2 + shift[1]
    canvas[:, r:r + 8, c:c + 8] = images / 16.0
    return torch.tensor(canvas).unsqueeze(1)             # shape (N, 1, 12, 12): N images, 1 colour channel

rng = np.random.default_rng(0)
order = rng.permutation(len(digits.images))
train_idx, test_idx = order[:1400], order[1400:]
x_train, y_train = on_canvas(digits.images[train_idx]), torch.tensor(digits.target[train_idx])
y_test = torch.tensor(digits.target[test_idx])
print("training batch shape:", tuple(x_train.shape), "| test images:", len(test_idx))
What you should see
training batch shape: (1400, 1, 12, 12) | test images: 397

PyTorch expects images as (number of images, channels, height, width). There is one channel because the images are greyscale.

Step 4 · Two networks

The first model is the kind you built in Lesson 3.16: flatten the 144 pixels and pass them through fully connected layers (a multi-layer perceptron, MLP). The second is a small CNN.

mlp = nn.Sequential(nn.Flatten(), nn.Linear(144, 64), nn.ReLU(), nn.Linear(64, 10))

cnn = nn.Sequential(
    nn.Conv2d(1, 16, kernel_size=3, padding=1), nn.ReLU(),     # 16 different 3 x 3 filters, each slid over the whole image
    nn.MaxPool2d(2),                                           # keep the strongest response in each 2 x 2 block: 12 x 12 -> 6 x 6
    nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(),    # 32 filters that look for patterns in the first layer's outputs
    nn.AdaptiveMaxPool2d(1),                                   # for each of the 32 patterns: how strongly did it appear ANYWHERE?
    nn.Flatten(), nn.Linear(32, 10))

x = x_train[:1]
print(f"{'layer':<19}{'output shape':<18}{'parameters':>10}")
for layer in cnn:
    x = layer(x)
    print(f"{type(layer).__name__:<19}{str(tuple(x.shape)):<18}{sum(p.numel() for p in layer.parameters()):>10,}")
count = lambda m: sum(p.numel() for p in m.parameters())
print(f"\nCNN total: {count(cnn):,} parameters | MLP total: {count(mlp):,} parameters")

Follow the shape down the table. The first convolution turns 1 channel into 16 feature maps of the same size (padding=1 adds a border of zeros so the size is kept). Max pooling keeps the largest value in each 2 × 2 block, halving the grid: small shifts and details are thrown away, strong responses are kept. The second convolution builds 32 maps from the 16. The last pooling keeps one number per map: the strongest response anywhere. The CNN has about half as many parameters as the MLP.

Step 5 · Train both, then move the digits

The experiment that shows what convolution buys. Train the fully connected network (the MLP) and the convolutional network on the same centred digits, measure both, and then measure again after shifting every test digit a few pixels sideways. The digits have not changed; only their position has.

def fit(model, epochs=30):
    opt = torch.optim.Adam(model.parameters(), lr=0.01)
    for epoch in range(epochs):
        for i in range(0, len(x_train), 100):
            loss = nn.functional.cross_entropy(model(x_train[i:i + 100]), y_train[i:i + 100])
            opt.zero_grad(); loss.backward(); opt.step()
    return model

def accuracy(model, shift=(0, 0)):
    with torch.no_grad():
        return (model(on_canvas(digits.images[test_idx], shift)).argmax(1) == y_test).float().mean().item()

fit(mlp); fit(cnn)
print(f"{'test digits':<28}{'MLP':>8}{'CNN':>8}")
for name, shift in [("centred, as in training", (0, 0)), ("moved 1 pixel right", (0, 1)), ("moved 2 pixels right", (0, 2)), ("moved 2 down, 2 right", (2, 2))]:
    print(f"{name:<28}{accuracy(mlp, shift):>8.1%}{accuracy(cnn, shift):>8.1%}")
What you should see

On centred digits the two models are equally good. Move the digit and the MLP collapses: it learned "this pixel is usually bright for a 7", and now the 7 is somewhere else. The CNN, with half the parameters and no shifted examples in training, still reads most of them, because its filters respond to strokes wherever they are and the global pooling asks only whether each pattern appeared. (It does better on a 2-pixel shift than a 1-pixel shift because 2 pixels lines up exactly with the 2 × 2 pooling grid; real networks reduce this effect with more layers and with training on shifted, rotated and cropped copies, called data augmentation.)

These are less tidy than the hand-made filter of Step 2, but the pattern is the same: positive weights next to negative ones, so each filter responds to a change in brightness in some direction. Nobody told the network to look for edges and strokes; it found that they are useful. In networks trained on photographs the first-layer filters reliably become edge, colour and texture detectors, which is one of the most reproduced findings in deep learning.

From CNNs to today

Year Model What it added
1989–1998 LeNet Convolution and pooling, trained by backpropagation; read cheques and postcodes
2012 AlexNet A deep CNN on GPUs with ReLU and dropout; won ImageNet and started the deep learning boom
2014 VGG, GoogLeNet Much deeper stacks of small filters
2015 ResNet Residual connections (Lesson 3.12) made 100-layer networks trainable; still a standard backbone
2015 U-Net An encoder-decoderlater · 7.13 CNN for labelling every pixel; later the core of image diffusion modelslater · 10.34 (Lesson 10.34)

2020 Vision Transformer (ViT) Cuts the image into patches, treats each patch as a token, and applies a transformer (the Transformers, step by step section). No convolutions
2021 CLIPlater · 10.34 An image encoder and a text encoder trained so that a picture and its caption get similar vectors (Lesson 10.34)
2023 on Vision-language models An image encoder (usually a ViT) feeding a large language model

Two ideas from this history are used every day in the rest of this course. Transfer learning began here: take a network pretrained on ImageNet, keep its layers as a general feature extractor, and train only a new final layer on a few hundred of your own images. That is the same move as fine-tuninglater · 10.10 a language model (the Models: training, evaluation and fine-tuning section). And the patch-as-token idea of the ViT is how language models "see": Lesson 10.34 shows an image entering a language model as a row of patch vectors.

Do CNNs still matter?

Yes. Transformers win on very large datasets, but convolutions remain efficient and data-frugal. CNNs and hybrids run most on-device and real-time vision: phone cameras, factory inspection, medical imaging, number-plate and document readers. Convolution layers also sit inside speech models such as Whisper (to shorten the audio sequence) and inside image generators. When this course uses a vision model, it will be through an API or a pretrained model, and you now know the two kinds of machinery that can be inside.

Check your mental model
  • ✗ "A CNN is a different kind of learning."
    ✓ It is an ordinary neural network trained by backpropagation, with layers whose weights are shared across positions.
  • ✗ "Someone programs the filters to find edges."
    ✓ Filters start random and are learned. Edge detectors emerge because they are useful.
  • ✗ "Pooling loses information, so it must hurt."
    ✓ It deliberately discards exact positions, which makes the network tolerant of small shifts and cheaper to run.
  • ✗ "Vision transformers made convolution obsolete."
    ✓ Both are in wide use. Many strong models combine them.

The first convolution has 16 filters of 3 × 3 on 1 channel. If the input were a colour image with 3 channels, how many parameters would that layer have? What if the filters were 5 × 5 on 1 channel? (Solution P1.)

Practice
Apply it

Replace nn.AdaptiveMaxPool2d(1) with nn.MaxPool2d(2) followed by nn.Flatten() and a nn.Linear(32 * 3 * 3, 10) layer, retrain, and run the shift test again. Explain the result using the idea of "where" against "whether". (Solution X1.)

Solutions

SolutionP1 · Counting convolution weights

Each filter spans all input channels. With 3 channels: 16 × (3 × 3 × 3) + 16 = 448. With 5 × 5 on 1 channel: 16 × 25 + 16 = 416. The number of parameters does not depend on the size of the image at all, which is why CNNs scale to large pictures.

SolutionM1 · A horizontal-edge detector

np.array([[-1, -1, -1], [0, 0, 0], [1, 1, 1]]). Positive responses appear where the image gets brighter going down, such as the top edge of the bar across the 7 and the top of its long stroke; negative responses appear under the bar. Vertical and horizontal detectors together already describe much of a digit's shape, and the network learns 16 such detectors at many angles.

SolutionX1 · Where against whether

With a flatten-and-linear ending, the last layer has a separate weight for each of the 3 × 3 positions of each map, so it learns where each pattern usually is for centred digits. Accuracy on shifted digits drops sharply, closer to the MLP. Global pooling throws the position away and keeps only whether the pattern appeared, which is what makes the classifier tolerant of shifts. Many modern networks end with global pooling for this reason.

Recap
  • An image is a grid of numbers per colour channel. A convolution slides a small filter over it and produces a feature map of where the filter's pattern occurs.
  • Sharing the filter's weights across positions means few parameters and the same response wherever the pattern appears.
  • A CNN stacks convolution, ReLU and pooling; early layers learn edges, later layers combinations. Filters are learned.
  • On digits moved a few pixels, a small CNN kept working where a fully connected network failed.
  • AlexNet (2012) began the deep learning era. Vision transformers treat image patches as tokens, and image encoders now feed language models.

Check your understanding

Q1What does "weight sharing" mean in a convolutional layer?

One set of filter weights is reused across the whole image, so a pattern is detected wherever it appears.

Q2Why did the fully connected network fail on digits moved two pixels to the right?

With a separate weight per pixel, a shifted image is a different input as far as the network is concerned.

Q3How does a vision transformer turn an image into something a transformer can process?

Each patch becomes one vector, and attention then relates the patches to each other.
