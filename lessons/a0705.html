In plain words first
The idea in one line

Attention is the star. Everything else — residuals, normalization, feed-forward, cross-attention — is the scaffolding that lets you stack it deep.

Terms you'll hear
Term What people say What it actually means
Block "One transformer layer" Stack of norm + attention + norm + FFN, wrapped in residual connections.
Residual "Skip connection" x + f(x) output; enables gradient flow through deep stacks.
Pre-norm "Normalize before, not after" Modern: x + sublayer(LN(x)). Trains deeper without warmup gymnastics.
RMSNorm "LayerNorm without the mean" Divide by RMS; one less op, same empirical stability.
SwiGLU "The FFN everyone switched to" Swish(W1 x) ⊙ W3 x → W2. Beats ReLU/GELU on LM ppl.
Cross-attention "How the decoder sees the encoder" MHA with Q from decoder, K/V from encoder outputs.
FFN expansion "How wide the middle MLP is" Ratio of hidden-size to d_model, usually 4 (LayerNorm) or 2.6 (SwiGLU).
Bias-free "Drop the +b terms" Modern stacks omit biases in linear layers; slight ppl improvement, smaller model.

The problem

In plain words first

One attention layer only lets words look at each other. A model needs much more: it has to stack dozens of layers, and each layer also needs a step that works on every word separately. The transformer block packages this: attention (words exchange information), a small feed-forward network (each word's vector is transformed on its own), a residual connection around each (the input is added back to the output, so each step only adds a correction), and a normalisation in front of each so the numbers stay in range. An encoder stacks blocks that see the whole input; a decoder stacks blocks that see only earlier words and, in translation-style models, also read the encoder's output through cross-attention. This lesson builds both from the lesson's code, counts where the parameters of real models sit, shows what happens without residuals, and rebuilds all 30 blocks of a real model, SmolLM-135M, from its weights. Nothing is trained.

A single attention layer is a feature extractor, not a model. One matmul per layer is not enough capacity for language. You need depth — and depth breaks without the right plumbing.

The 2017 Vaswani paper packaged six design decisions that turned one attention layer into a stackable block. Every transformer since — encoder-only (BERT), decoder-only (GPT), encoder-decoder (T5) — inherits the same skeleton. In 2026 the blocks have been refined (RMSNorm, SwiGLU, pre-norm, RoPE) but the skeleton is identical.

This lesson is the skeleton. Next lessons specialize it — 06 for encoders, 07 for decoders, 08 for encoder-decoder.

The idea

Idea 1 · The six pieces

  1. Embedding + positional signal. Tokens → vectors. Position injected via RoPE (modern) or sinusoidal (classic).
  2. Self-attention. Every position attends to every other. Masked in decoders.
  3. Feed-forward network (FFN). Position-wise two-layer MLP: W_2 · activation(W_1 · x). Expansion ratio 4× by default.
  4. Residual connection. x + sublayer(x). Without this, gradients vanish past ~6 layers.
  5. Layer normalization. LayerNorm or RMSNorm (modern). Stabilizes the residual stream.
  6. Cross-attention (decoder only). Queries come from the decoder, keys and values from the encoder output.

Watch a vector flow through one block: attention mixes across positions, the residual carries it forward, the FFN transforms it, and norm keeps the stream stable.

Idea 2 · Encoder block (used by BERT, T5 encoder)

x → LN → MHA(self) → + → LN → FFN → + → out
                     ^              ^
                     |              |
                     └── residual ──┘

Encoder is bidirectional. No masking. All positions see all positions.

Idea 3 · Decoder block (used by GPT, T5 decoder)

x → LN → MHA(masked self) → + → LN → MHA(cross to encoder) → + → LN → FFN → + → out

Decoder has three sublayers per block. The middle one — cross-attention — is the only place information flows from encoder to decoder. In a pure decoder-only architecture (GPT), cross-attention is omitted and you just have masked self-attention + FFN.

Idea 4 · Pre-norm vs post-norm

Original paper: x + sublayer(LN(x)) vs LN(x + sublayer(x)). Post-norm lost favor around 2019 — it is harder to train deeply without careful warmup. Pre-norm (LN before sublayer) is the 2026 default: Llama, Qwen, GPT-3+, Mistral all use it.

Idea 5 · The 2026 modernized block

Vaswani 2017 shipped LayerNorm + ReLU. Modern stacks replaced both. What production blocks actually look like:

Component 2017 2026
Normalization LayerNorm RMSNorm
FFN activation ReLU SwiGLU
FFN expansion 4× about 2.7× (8/3) keeps SwiGLU's three matrices at the parameters of a 4× two-matrix FFN; real models use 2.7× to 5.4×
Position Sinusoidal absolute RoPE
Attention Full MHA GQA (or MLA)
Bias terms Yes No

RMSNorm drops the mean-centering of LayerNorm (one fewer subtraction), which saves compute and is empirically at least as stable. SwiGLU (Swish(W1 x) ⊙ W3 x) gave lower perplexity than ReLU and GELU feed-forward layers at the same parameter count in Shazeer's 2020 comparison, and PaLM, Llama and Qwen adopted it.

Idea 6 · Parameter count

For one block with d_model = d and FFN expansion r:

  • MHA: 4 · d² (Q, K, V, O projections)
  • FFN (SwiGLU): 3 · d · (r · d) ≈ 3rd²
  • Norms: negligible

At d = 4096, r = 2.6, layers = 32 (roughly Llama 3 8B), total: 32 · (4·4096² + 3·2.6·4096²) ≈ 32 · (67M + 131M) ≈ 32 · 198M ≈ 6.3B parameters in the blocks, plus about 1B for the embeddings and output head (128K vocab × 4096, untied). That lands near the published 8B. The real model uses GQA (smaller K and V projections) and a wider FFN (r = 3.5), which moves parameters from attention to the FFN but keeps the total close to 8B.

The same idea as a formula

One pre-norm block on a sequence of vectors X (one row per token):

X′=X+Attn(Norm(X)),X′′=X′+FFN(Norm(X′))

A decoder in an encoder–decoder model inserts a third step, X+CrossAttn(Norm(X),E), whose queries come from X and whose keys and values come from the encoder output E. Only attention moves information between positions; the norms and the FFN act on each row separately.

The two modern pieces.

RMSNorm(x)=g⊙d1​∑i​xi2​+ϵ​x​,SwiGLU(x)=(SiLU(xW1​)⊙xW3​)W2​

Why the residual matters. Unrolled over L blocks, XL​=X0​+∑l​Fl​(Xl​): the output is the input plus a sum of corrections, and ∂XL​/∂X0​ contains the identity, so gradients always have a direct path back to the first layer.

Parameters of a decoder-only model with L blocks, width d, key/value width dkv​ (smaller than d with grouped-query attention), FFN width dff​, vocabulary V, no biases:

N≈L(Q,O and K,V2d2+2ddkv​​​+SwiGLU3ddff​​​)+Vd×(1 if the output head is tied to the embeddings, else 2)

SwiGLU width. A classic FFN with width 4d has 2⋅d⋅4d=8d2 weights; SwiGLU's three matrices match that at dff​=8d/3≈2.67d.

Compute. A forward pass costs about 2N FLOPs per token for the matrix products, plus attention's ≈4Lnd for a context of n tokens.

Worked example
Counting Llama 3.1 8B by hand

Configuration: L=32, d=4096, 32 query heads and 8 key/value heads of size 128 (so dkv​=1024), dff​=14,336, vocabulary 128,256, untied output head.

  • Attention per block: $2 \times 4096^2 + 2 \times 4096 \times 1024 = 33.6\text{M} + 8.4\text{M} = 41.9$M.
  • SwiGLU per block: $3 \times 4096 \times 14{,}336 = 176.2$M, four times the attention.
  • One block: 218.1M; 32 blocks: 6.98 billion.
  • Embeddings and output head: 2×128,256×4096=1.05 billion.
  • Total: 8.03 billion, the published "8B". About 70% of it is feed-forward weights; only 17% is attention.
Check your mental model
  • ✗ "The feed-forward layer mixes information between tokens."
    ✓ It is applied to each position separately; only attention (self or cross) moves information between positions.
  • ✗ "Pre-norm keeps the residual stream normalised."
    ✓ Only the copy entering each sublayer is normalised; the stream itself grows freely (into the thousands in SmolLM, under "Use it"), and one final norm sits before the output head.
  • ✗ "Most of a large language model's parameters are in attention."
    ✓ In Llama 3.1 8B about 70% are in the feed-forward layers, 17% in attention, 13% in the embeddings and head.

Step 2 · wire a 2-layer encoder and a 2-layer decoder

Stack them. Pass the encoder output into every decoder cross-attention. Add a final LN before the output projection.

def encode(tokens, params):
    x = embed(tokens, params.emb) + sinusoidal(len(tokens), params.d)
    for block in params.encoder_blocks:
        x = encoder_block(x, block)
    return x

def decode(target_tokens, encoder_out, params):
    x = embed(target_tokens, params.emb) + sinusoidal(len(target_tokens), params.d)
    for block in params.decoder_blocks:
        x = decoder_block(x, encoder_out, block)
    return x

Reading this output

Changing the last target token changes only the last decoder row: the causal mask hides it from every earlier position, which is what lets a decoder be trained on all positions at once without seeing its answers. Changing one source token changes every encoder row (no mask) and, through cross-attention, every decoder row: cross-attention is the only route from source to target, and it is not masked, because the whole source is known before decoding starts.

Take the residuals away

48 pre-norm blocks (PyTorch attention and a GELU feed-forward, random initialisation) on 64 random token vectors, with and without the two residual connections in each block. After selected layers: the average cosine similarity between different tokens' vectors.

import torch, torch.nn as nn, torch.nn.functional as F

class Block(nn.Module):
    """One pre-norm transformer block; residual=False drops the two skip connections."""
    def __init__(self, d, heads, residual):
        super().__init__()
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = nn.MultiheadAttention(d, heads, batch_first=True)
        self.ffn = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
        self.residual = residual
    def forward(self, x):
        h = self.n1(x); a = self.attn(h, h, h, need_weights=False)[0]
        x = x + a if self.residual else a
        f = self.ffn(self.n2(x))
        return x + f if self.residual else f

def token_similarity(x):                      # mean cosine similarity between different positions
    z = F.normalize(x[0], dim=-1); s = z @ z.T
    n = s.shape[0]; return ((s.sum() - n) / (n * n - n)).item()

torch.manual_seed(0)
d, L = 256, 48
x0 = torch.randn(1, 64, d)
for residual in (True, False):
    torch.manual_seed(1)
    blocks = [Block(d, 4, residual) for _ in range(L)]
    x, sims = x0, []
    with torch.no_grad():
        for b in blocks:
            x = b(x); sims.append(token_similarity(x))
    label = "with residuals   " if residual else "without residuals"
    print(f"{label}  token similarity after layers 1, 2, 6, 24, 48: " + ", ".join(f"{sims[i]:.3f}" for i in (0, 1, 5, 23, 47)))
print(f"(the 64 input vectors are random: similarity {token_similarity(x0):.3f})")

Reading this output

Without residuals, the 64 random vectors are already strongly aligned after one block (0.76) and identical to three decimals after two. Each block's output is an attention average of its inputs, and repeated averaging pulls every row towards the same mixture; with nothing carrying the original signal forward, the differences between tokens are erased ("rank collapse"), and a deep network would see one token repeated 64 times. With residuals, each block only adds a correction to its input, so the tokens stay distinct: similarity creeps up to 0.5 after 48 random blocks, and trained models, with smaller residual updates at initialisation, keep their tokens apart through every layer.

Use it: the same idea with real libraries

The PyTorch/TF reference implementations: nn.TransformerEncoderLayer, nn.TransformerDecoderLayer. But most 2026 production code rolls its own block because:

  • Flash Attention is called inside attention, not via nn.MultiheadAttention.
  • GQA / MLA are not in the stdlib reference.
  • RoPE, RMSNorm, SwiGLU are not the PyTorch defaults.

HF transformers has clean reference blocks you should read: modeling_llama.py is the canonical 2026 decoder-only block. It's ~500 lines and worth walking through once.

Encoder vs decoder vs encoder-decoder — when to pick:

Need Pick Example
Classification, embeddings, QA over text Encoder-only BERT, DeBERTa, ModernBERT
Text generation, chat, code, reasoning Decoder-only GPT, Llama, Claude, Qwen
Structured input → structured output (translation, summarization) Encoder-decoder T5, BART, Whisper

Decoder-only won language because it scales cleanest and handles both comprehension and generation. Encoder-decoder is still best when the input has a clear "source sequence" identity (translation, speech recognition, structured tasks).

Where the parameters of real models are

Three models built from their configuration files on PyTorch's meta device (shapes only, nothing downloaded but config.json), every parameter counted by component, and the formula box's block count next to the real one.

import torch
from transformers import AutoConfig, AutoModelForCausalLM

# Build each model on PyTorch's "meta" device: shapes only, no memory, no download of weights.
def count(repo):
    cfg = AutoConfig.from_pretrained(repo)
    with torch.device("meta"):
        model = AutoModelForCausalLM.from_config(cfg)
    groups = {"embeddings": 0, "attention": 0, "feed-forward": 0, "norms": 0, "output head": 0}
    seen = set()
    for name, p in model.named_parameters():
        if id(p) in seen:
            continue
        seen.add(id(p))
        key = ("embeddings" if "embed" in name else "attention" if "self_attn" in name else
               "feed-forward" if "mlp" in name else "norms" if "norm" in name else "output head")
        groups[key] += p.numel()
    return cfg, groups

for repo in ["HuggingFaceTB/SmolLM-135M", "Qwen/Qwen2.5-0.5B", "unsloth/Meta-Llama-3.1-8B"]:

The formula box's block count matches the counted parameters exactly for SmolLM and Llama (6,979.3M); Qwen2.5 is 0.1M higher because it keeps biases on its query, key and value projections. The split shifts with size. In Llama 3.1 8B the feed-forward layers hold 70% of all weights and attention 17%; in the two small models the embedding table is a fifth to a quarter of the model, because a vocabulary of 49,152 or 151,936 tokens times the width is large next to a few hundred million block parameters, which is why small models tie their output head to the embeddings. The feed-forward widths also show that "2.6×" is not a rule: 2.67× (SmolLM), 3.5× (Llama), 5.43× (Qwen2.5-0.5B).

This lesson's block, inside a real model

All 30 blocks of SmolLM-135M (a Llama-architecture model) rebuilt in about 25 lines from its weights: RMSNorm, RoPE, grouped-query attention, SwiGLU and the two residual additions, then compared with transformers on a real sentence. The table follows the residual stream through the layers.

import torch, torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer

repo = "HuggingFaceTB/SmolLM-135M"                        # a Llama-architecture model, 30 blocks
tok = AutoTokenizer.from_pretrained(repo)
hf = AutoModelForCausalLM.from_pretrained(repo, dtype=torch.float32).eval()
cfg, W = hf.config, dict(hf.named_parameters())
ids = tok("The cat sat on the mat because it was tired, so the cat", return_tensors="pt").input_ids
n, d, H, KV = ids.shape[1], cfg.hidden_size, cfg.num_attention_heads, cfg.num_key_value_heads
dh = d // H

def rms_norm(x, w, eps=cfg.rms_norm_eps):
    return w * x / torch.sqrt(x.pow(2).mean(-1, keepdim=True) + eps)

theta = cfg.rope_parameters["rope_theta"]
inv_freq = 1.0 / theta ** (torch.arange(0, dh, 2).float() / dh)
ang = torch.outer(torch.arange(n).float(), inv_freq)            # (n, dh/2)
cos, sin = torch.cat([ang, ang], -1).cos(), torch.cat([ang, ang], -1).sin()
def rope(x):                                                    # Llama's layout: first half and second half form the pairs
    x1, x2 = x[..., : dh // 2], x[..., dh // 2 :]
    return x * cos + torch.cat([-x2, x1], -1) * sin

def block(x, i):
    p = f"model.layers.{i}."
    h = rms_norm(x, W[p + "input_layernorm.weight"])
    q = (h @ W[p + "self_attn.q_proj.weight"].T).view(n, H, dh).transpose(0, 1)
    k = (h @ W[p + "self_attn.k_proj.weight"].T).view(n, KV, dh).transpose(0, 1)
    v = (h @ W[p + "self_attn.v_proj.weight"].T).view(n, KV, dh).transpose(0, 1)
    q, k = rope(q), rope(k)
    k, v = k.repeat_interleave(H // KV, 0), v.repeat_interleave(H // KV, 0)       # grouped-query attention
    s = q @ k.transpose(-1, -2) / dh ** 0.5 + torch.triu(torch.full((n, n), float("-inf")), 1)
    a = (s.softmax(-1) @ v).transpose(0, 1).reshape(n, d) @ W[p + "self_attn.o_proj.weight"].T
    x = x + a                                                   # residual 1
    h = rms_norm(x, W[p + "post_attention_layernorm.weight"])
    f = (F.silu(h @ W[p + "mlp.gate_proj.weight"].T) * (h @ W[p + "mlp.up_proj.weight"].T)) @ W[p + "mlp.down_proj.weight"].T
    return x + f, a.norm(dim=-1).mean().item(), f.norm(dim=-1).mean().item()   # residual 2

with torch.no_grad():
    x = W["model.embed_tokens.weight"][ids[0]]
    rows = []
    for i in range(cfg.num_hidden_layers):
        x, an, fn = block(x, i)
        nrm = x.norm(dim=-1); rows.append((i, nrm[0].item(), nrm[1:].median().item(), an, fn))
    ours = rms_norm(x, W["model.norm.weight"]) @ W["model.embed_tokens.weight"].T     # tied output head
    ref = hf(ids).logits[0]
print(f"our 30 blocks vs transformers: max logit difference {(ours - ref).abs().max():.1e}; "
      f"same next token: {tok.decode(ours[-1].argmax())!r} = {tok.decode(ref[-1].argmax())!r}")
print("\n          residual-stream norm         mean size of the update added by")
print("layer   first token   other tokens   attention   feed-forward")
for i, s0, s, a, f in rows:

Industry practice
What's current (2024–2026)
  • The Llama-style block is the open-model standard. Pre-norm RMSNorm, RoPE, grouped-query attention, SwiGLU and no biases: Llama 3, Qwen2.5 and Qwen3, Mistral and SmolLM all follow it, and transformers, vLLM and llama.cpp share one implementation pattern for them.

easy15 minimplement

A transformer normalizes the vector of each token before attention and before the feed forward block. LayerNorm centers each vector and divides it by its standard deviation. RMSNorm skips the centering and divides by the root mean square. Modern LLMs use RMSNorm because it is cheaper and works as well.

Task

Write two functions.

  1. layer_norm(x, gamma, beta, eps=1e-5) returns LayerNorm of x over the last axis.
  2. rms_norm(x, weight, eps=1e-6) returns RMSNorm of x over the last axis.

For each vector x of length D along the last axis:

μ=D1​j∑​xj​,σ2=D1​j∑​(xj​−μ)2,LayerNorm(x)j​=γj​σ2+ϵ​xj​−μ​+βj​

RMSNorm(x)j​=wj​D1​∑k​xk2​+ϵ​xj​​

The variance is the biased variance. It divides by D, not by D−1. The eps goes inside the square root in both functions.

Common mistakes the checks catch
  • Uses a fixed eps of 1e-5 in LayerNorm and ignores the eps that the caller passes.
  • Takes the LayerNorm mean over axis 0, not over the last axis.
  • Adds eps after the square root in RMSNorm.
  • Uses the variance in RMSNorm, so it subtracts the mean as LayerNorm does.
  • Uses the unbiased variance with D - 1 in LayerNorm.
Hint 1

Use axis=-1 and keepdims=True for every mean. The statistics then have shape (..., 1) and broadcast against x for any number of leading axes.

Hint 2

gamma, beta and weight have shape (D,). numpy broadcasts them over the leading axes, so you can multiply and add them directly.

Hint 3

For LayerNorm, compute the mean, then the mean of the squared differences from it. Divide by np.sqrt(var + eps).

Hint 4

RMSNorm has no mean subtraction. The denominator is the square root of the mean of x * x plus eps. A row of zeros then gives 0/ϵ​=0.

Reference solution and notes
import numpy as np


def layer_norm(x, gamma, beta, eps=1e-5):
    mean = np.mean(x, axis=-1, keepdims=True)
    var = np.mean((x - mean) ** 2, axis=-1, keepdims=True)
    return (x - mean) / np.sqrt(var + eps) * gamma + beta


def rms_norm(x, weight, eps=1e-6):
    rms = np.sqrt(np.mean(x * x, axis=-1, keepdims=True) + eps)
    return x / rms * weight

What each norm removes

LayerNorm removes the mean and the scale of each vector. RMSNorm removes only the scale. The residual stream of a transformer has a mean close to 0 in practice, so the centering adds little. RMSNorm saves one reduction over the vector and one subtraction for each entry.

Why eps goes inside the square root

σ2+ϵ​ is at least ϵ​, so a constant vector does not cause a division by 0. LayerNorm of a constant vector gives β, and RMSNorm of a zero vector gives 0.

The difference from BatchNorm

BatchNorm normalizes each feature over the batch axis. LayerNorm and RMSNorm normalize each example over the feature axis. They do not need running statistics, and they act the same way in training and in inference. They also work for a batch of one token, which is the case during generation.

Given a transformer block source (PyTorch / JAX / numpy / pseudocode) and its intended role (encoder / decoder / encoder-decoder), output:

1. Wiring check. Pre-norm or post-norm. Residual connections around each sublayer. Flag post-norm as non-default for 2026 unless the author states why.
2. Normalization. LayerNorm vs RMSNorm. RMSNorm preferred. Flag if bias terms are present in Q/K/V/O projections — most 2026 models drop them.
3. Attention shape. MHA / GQA / MQA / MLA. For decoder blocks: confirm causal mask is applied. For cross-attention: confirm Q from decoder, K/V from encoder.
4. FFN. Activation (ReLU / GELU / SwiGLU / GeGLU). Expansion ratio. SwiGLU with ~2.67× is modern default; 4× ReLU/GELU is classic.
5. Positional signal. Confirm RoPE / ALiBi / absolute is applied where expected (typically Q,K projections for RoPE).

Refuse to sign off on a block that stacks more than 12 layers with post-norm and no warmup schedule — training will diverge. Refuse a decoder block without causal masking. Flag any block whose FFN expansion drops below 2× as likely under-capacity. Warn if the block hard-codes `d_model` without a config field for swap-in sizing.

Exercises

  1. Easy. Count the parameters in your encoder_block at d_model=512, n_heads=8, ffn_expansion=4, swiglu=True. Validate by implementing the block and using sum(p.numel() for p in block.parameters()).
  2. Medium. Switch from post-norm to pre-norm. Initialize both and measure the activation norm after 12 stacked layers on random input. Post-norm's activations should explode; pre-norm's should stay bounded.
  3. Hard. Implement a 4-layer encoder-decoder on a toy copy task (copy x reversed). Train 100 steps. Report loss. Swap in RMSNorm + SwiGLU + RoPE — does loss drop?

Solutions

SolutionP1 · Identical without residuals

With residuals, still mostly unrelated: similarity rises slowly, to about 0.2 after 24 blocks and 0.5 after 48. Without them, practically identical almost at once: 0.76 after one block and 1.000 from the second block on. Attention outputs are weighted averages of the inputs, and averaging again and again drives every row to the same vector. The residual connection adds each block's output to its input instead of replacing it, so the distinctive part of each token survives, and the gradient has the same direct path backwards.

SolutionB1 · No source, and a view of the future

First, the decoder no longer reads the encoder at all: its "cross-attention" attends over its own states, so the output cannot depend on the source sentence, and a translation model becomes a language model that ignores its input. Second, that attention call has no causal mask, so every target position can now see the later target tokens. During training with teacher forcing, the model can copy the next token from the input, so the loss falls quickly and looks excellent, while generation, where future tokens do not exist yet, fails. The test from Step 3 catches both at once: editing the last target token would now change every decoder row, and editing the source would change none.

Estimate itCount the parameters of a decoder stack with a model width of 4096, 32 layers and a SwiGLU feed-forward network at an expansion of 2.6. Then add an untied embedding and output head for a vocabulary of 128K. Where does the total land, and why is the published model of that size a little different?

Level 3 of 4 · about 10 minutes to answer well.

Short answer. Per block, attention takes 4 d^2 for the four projections and SwiGLU takes 3 d (r d), about 3 r d^2. At the given width and expansion that is about 67M plus 131M, about 198M per block, and 32 blocks give about 6.3B. The untied embedding and head add about 1B, so the stack lands near the published 8B. The real model uses grouped-query attention, which shrinks the key and value projections, and a wider FFN at an expansion of 3.5, which moves parameters from attention to the FFN while the total stays close.

The per-block arithmetic.

attention:  Q, K, V, O projections, each d x d        -> 4 d^2
FFN:        three matrices of d x (r d)               -> 3 r d^2
norms:      two vectors of length d                   -> negligible

With d = 4096 and r = 2.6:

4 * 4096^2        = about 67M
3 * 2.6 * 4096^2  = about 131M
per block         = about 198M
32 blocks         = about 6.3B

The embeddings.

An untied model has a token embedding of shape (vocab, d) and a separate head of the same size. At 128K by 4096 the pair adds about 1B. A tied model shares the matrix and saves half of that.

Why the published number differs.

Two architectural choices move the count without changing the total much:

  1. Grouped-query attention. The key and value projections map d to n_kv_heads * d_head instead of d to d, so attention holds fewer than 4 d^2 parameters.
  2. A wider FFN. The published model uses an expansion of about 3.5, so the FFN holds more than the 3 * 2.6 * d^2 counted above.

The total still lands near 8B. The FFN holds about two thirds of the block parameters in either version.

What the count is for.

Memory for the weights at a given data type, the bound on the cache budget that remains on the card, and a sanity check when a config file or a model card looks wrong.

Plausible wrong answers.

  • "The parameter count grows with the sequence length." No weight depends on the sequence; the length changes activation memory and compute, not parameters.
  • "The embedding is a rounding error." At 128K by 4096 it is about 1B, more than a tenth of the model.
  • "Attention is where most of the parameters are." The FFN holds about two thirds of each block.

Follow-ups an interviewer may ask.

  • (level 2) Why are the norms negligible? Expected: each norm is one or two vectors of length d, thousands of parameters against millions per matrix.
  • (level 3) How does grouped-query attention change the per-block count? Expected: the K and V projections shrink to d by n_kv_heads * d_head, so attention holds less than 4 d^2.
  • (level 3) Why does an expansion of 4 with two matrices equal an expansion of about 2.6 with three? Expected: 2 * 4 d^2 = 8 d^2 and 3 * 2.6 d^2 is about 8 d^2; the modern block kept the parameter budget and changed the activation.
  • (level 4) The team ties the embedding and the head. What changes in the count and what do you check? Expected: about half of the 1B disappears; check that the output logits still use the transpose of the embedding and that quality holds.

Defend a designYou inherit a decoder block written in the 2017 style: layer normalization after the residual add, a ReLU feed-forward network at four times the width, sinusoidal absolute positions summed into the input, bias terms on every linear layer, and full multi-head attention. Review it against what production decoders ship today and justify each change you ask for.

Level 3 of 4 · about 12 minutes to answer well.

Short answer. Move the normalization in front of each sublayer and switch it to RMSNorm; replace the ReLU network with SwiGLU at about 2.6 times the width so that its three matrices match the old parameter count; replace the sinusoid with rotation of the queries and keys; drop the biases; and use grouped-query attention to shrink the decode-time cache. Every change is one function substitution and the tensor shapes do not move. The evidence: pre-norm trains deep without warmup tricks, SwiGLU gains about half a point of perplexity in the published model papers, rotation gives relative position and a knob for long context, and grouped-query cuts cache memory by the ratio of query heads to key-value heads.

What stays.

The skeleton: embedding, a stack of blocks that each add attention and an FFN to the residual stream, a final norm and a head. The shift-by-one cross-entropy. The causal mask. The capstone architecture in the lesson is exactly this skeleton with the modern pieces plugged in, and its head is tied to the token embedding.

How to land the changes safely.

  1. Make each substitution behind a flag and confirm the output shape after every swap, the way the lesson's build step does.
  2. Train the old and the new block on a small copy task for a fixed number of steps and compare the loss; the lesson's exercise uses 100 steps of a toy task.
  3. Use the fused attention call from the framework so that a tiled kernel is dispatched when the inputs allow it.
  4. Keep a final norm before the head, which pre-norm requires and post-norm did not.

What needs a retrain.

All of these change the function the block computes, so a checkpoint trained with the old block cannot adopt them by editing code. Grouped-query is the exception the literature treats specially: a trained multi-head checkpoint can be converted and fine-tuned.

Plausible wrong answers.

  • "RMSNorm is a cheaper approximation that costs accuracy." The lesson records it as at least as stable with one fewer operation.
  • "SwiGLU doubles the feed-forward parameters." At about 2.6 times the width its three matrices match the old two-matrix count.
  • "Pre-norm removes the need for any final normalization." It adds the need: the residual stream is unnormalized, so the head needs a final norm.

Weigh a trade-offThree products land on your desk: a search ranking model over documents, a coding assistant that writes code, and a speech-to-text system. Which transformer shape do you pick for each, and what does the pretraining loss have to do with the choice?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. Encoder-only for ranking and embeddings, decoder-only for generation, and encoder-decoder when the input is a clear source sequence such as audio to transcribe. An encoder reads both sides of every position and trains on masked prediction, which gives strong representations and no way to generate. A decoder trains on next-token prediction behind a causal mask, so it can generate, and it scales cleanest, which is why it won language. The loss decides whether the model can produce text at all.

The three skeletons.

Need Shape Why
Classification, embeddings, question answering over text Encoder-only Bidirectional attention sees the whole input at once
Text generation, chat, code, reasoning Decoder-only Causal mask plus next-token loss; one pass of attention and FFN per layer
Structured input to structured output, translation, speech recognition Encoder-decoder The encoder owns the source; the decoder generates and reads it through cross-attention

The one line that separates them.

A decoder predicts each token's probability given the tokens before it. An encoder predicts a masked token given the unmasked ones. Same block, same attention, different mask and different target. Only the first loss produces a model that can continue a sequence.

Cross-attention.

A decoder block in an encoder-decoder model has three sublayers: masked self-attention, cross-attention and the FFN. In cross-attention the queries come from the decoder and the keys and values come from the encoder output. It is the only place where information flows from the source to the output. A pure decoder drops it.

Why decoder-only won language.

It handles comprehension and generation with one architecture, it scales cleanly, and in-context learning let one model follow examples without a new head per task. Encoder-decoder is still the best fit when the input has a strong source identity: a waveform, a sentence in another language, a table to summarize.

The three answers.

  1. Ranking: an encoder, or an embedding model built on one, because you need a representation of the whole document and no generation.
  2. Coding assistant: a decoder, because the product is generation and the causal loss is what makes generation possible.
  3. Speech-to-text: an encoder-decoder, because the audio is a source sequence of its own kind and the text is a different sequence.

Plausible wrong answers.

  • "A decoder-only model cannot classify." It can, by prompting or by adding a head; the point is that an encoder is often cheaper for that job.
  • "An encoder generates text one token at a time." It has no causal loss and predicts masked positions; it is not trained to continue a sequence.
  • "Every transformer block has cross-attention." Only the decoder blocks of an encoder-decoder model have it.

Follow-ups an interviewer may ask.

  • (level 2) Which sublayer exists only in the encoder-decoder shape? Expected: cross-attention, with queries from the decoder and keys and values from the encoder.
  • (level 3) Why can a decoder-only model also do comprehension tasks? Expected: the same next-token model answers a question by continuing a prompt, and in-context learning lets it follow examples without a task head.
  • (level 3) When would you still choose encoder-decoder for a text task? Expected: when the input is a clear source sequence that the output transforms, such as translation or summarization of a fixed document.
  • (level 4) The ranking team wants to reuse the decoder they already serve. How? Expected: prompt it and read the logits of a label token, or attach a head and fine-tune; weigh the cost against an encoder that scores documents in one pass.

Where it is taught. The full transformer lesson gives the three shapes and the picking table, and the causal language modeling lesson contrasts the two losses.

Weigh a trade-offThe 2017 paper placed the layer normalization after the residual add. Almost every model since about 2019 places it before the sublayer. What changed, how would you demonstrate the difference in one afternoon, and what does RMSNorm change on top of that?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. Post-norm sends the gradient of the skip path through a normalization at every layer, so at depth the gradient shrinks and the run needs a warmup schedule to survive. Pre-norm keeps the skip path unnormalized, so the gradient reaches the embeddings cleanly and a deep stack trains without warmup tricks. Demonstrate it by stacking twelve layers of each variant with the same initialization and printing the gradient norm at the embedding after one backward pass. RMSNorm then drops the mean subtraction, one fewer operation, with the same stability in practice.

The two placements.

pre-norm:   x + sublayer(LN(x))
post-norm:  LN(x + sublayer(x))

Same shapes, different training behavior. In the post-norm block the residual add is followed by the norm, so the signal that flows down the stack is normalized at each layer and the gradient that flows back must pass through every norm. At a depth of twelve and a learning rate of 3e-4 that gradient shrinks fast enough to need warmup. In the pre-norm block the norm sits inside the branch, before attention and before the MLP, and the skip path carries the raw signal.

The afternoon experiment.

  1. Build a six-layer or twelve-layer stack with a pre_ln flag.
  2. Feed the same random input to both variants with identical weights.
  3. Run one backward pass and print the gradient norm at the embedding.

The pre-norm stack shows an embedding gradient about an order of magnitude larger than the post-norm stack at the same learning rate.

What pre-norm needs that post-norm did not.

A final norm before the output head. The residual stream is unnormalized in a pre-norm model, so the head needs one normalization at the end.

RMSNorm.

LayerNorm subtracts the mean and divides by the standard deviation. RMSNorm divides by the root mean square and skips the mean subtraction. It is one operation cheaper and is empirically at least as stable, which is why the modern block uses it.

Where dropout goes.

After the attention softmax, on the attention output before the residual add, and after the second linear of the MLP. Never on the skip path itself, because that breaks the additive identity that lets the gradient flow at depth.

Plausible wrong answers.

  • "The two placements compute the same function in a different order." The composition differs: one normalizes the stream, the other normalizes only the branch input.
  • "Warmup is a learning-rate detail unrelated to the norm." The lesson ties the need for warmup directly to the post-norm gradient path.
  • "RMSNorm needs the mean to be stable." It omits the mean on purpose and matches LayerNorm in practice.

Follow-ups an interviewer may ask.

  • (level 2) Where exactly does the norm sit in a pre-norm block? Expected: inside each residual branch, before attention and before the MLP, plus one final norm before the head.
  • (level 3) Why does a pre-norm model need a final norm when a post-norm model does not? Expected: the pre-norm skip path is unnormalized, so the head would see an unbounded stream without it.
  • (level 3) Your six-layer post-norm model trains fine and the twenty-four-layer version diverges. Why? Expected: the skip-path gradient attenuates at every norm, and the effect compounds with depth; add warmup or switch to pre-norm.
  • (level 4) What would convince you to keep LayerNorm instead of RMSNorm? Expected: a measured quality or stability difference on your own run; the lesson's evidence is that RMSNorm matches it while being cheaper.

Explain the mechanismA transformer block has two skip paths, one around attention and one around the feed-forward network. What do they do for training, which of the two sublayers moves information between tokens, and why does a dropout layer placed on the skip path itself break something?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. The skip path makes the gradient additive across depth, so its norm stays in scale through a twelve-layer stack instead of shrinking at every layer, and it lets each block learn a small update to a running representation instead of a full replacement. Only attention mixes tokens; the MLP applies the same two layers to every position on its own. Dropout belongs after the attention softmax, on the attention output before the residual add, and after the second linear of the MLP; on the skip path it breaks the identity that carries the gradient, and early stacks that did this trained brittly.

The block as a function.

A decoder block takes a tensor of shape (batch, sequence, embedding) and returns the same shape. Inside, two sublayers do the work:

x = x + attention(norm(x))
x = x + mlp(norm(x))

Each line is an additive update to the stream that flows top to bottom through every block. The lesson calls that tensor the residual stream.

Why the additive path matters.

Without the skip path, gradients vanish past about six layers. With it, the gradient of the loss with respect to an early layer has a direct term that does not pass through the sublayers, so depth adds terms instead of multiplying attenuations. The second effect is representational: a block does not have to reproduce its input; it adds what it learned.

Who talks to whom.

Attention is the only place tokens exchange information. The MLP is position-wise: the same weights apply to every token independently, with a hidden width of four times the embedding width and a GELU in the classic block. The modern block uses SwiGLU, three matrices at about 2.6 times the width so that the parameter count matches the old four-times MLP, and it drops the bias terms.

Dropout on the branches, never on the identity.

Attention dropout after the softmax, residual dropout on the attention output, and residual dropout after the second linear of the MLP. Dropout applied to the identity term randomly removes part of it, and the gradient path that made depth tractable is no longer reliable.

Plausible wrong answers.

  • "The skip path exists to keep the output shape equal to the input shape." The shape would match anyway; the skip path is about gradient flow and additive updates.
  • "Dropout anywhere inside the block is equivalent." Dropout on the identity term damages the gradient path; dropout on the branch outputs does not.
  • "The feed-forward network mixes information between tokens." It applies the same MLP to each position alone; mixing happens only in attention.

Follow-ups an interviewer may ask.

  • (level 2) Which sublayer would you remove if the model only needed per-token transformations? Expected: attention; the MLP never looks across positions.
  • (level 3) Why does the modern FFN use an expansion of about 2.6 instead of 4? Expected: SwiGLU has three weight matrices, so 2.6 times the width matches the parameter count of the two-matrix MLP at 4 times.
  • (level 3) Why do modern stacks drop the bias terms in the linear layers? Expected: the lesson reports a slight perplexity improvement and a smaller model.
  • (level 4) A reviewer wants to regularize a small model by dropping out the identity term. Your answer? Expected: no; keep dropout on the branch outputs, because the additive identity is what lets the gradient reach early layers.
