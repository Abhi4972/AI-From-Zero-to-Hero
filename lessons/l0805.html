Protocols

MidWhat is MCP, and what problem does it solve?

The Model Context Protocol standardizes how agents discover and call tools, read resources and use prompts from servers. It turns an N-by-M integration problem (every agent times every tool) into N plus M. Servers expose tools over stdio or streamable HTTP; clients (agents, IDEs, chat apps) connect to them. The 2026 specification made it stateless, which helps scaling. Risks: tool poisoning, over-broad permissions and untrusted servers, so use allowlists, a gateway and least privilege.

MidMCP versus A2A?

MCP connects an agent to tools and data: the agent stays in control. A2A connects agents to other agents as peers that keep their own logic, state and tools, with agent cards for discovery and tasks for long-running work. Use MCP to give an agent capabilities, A2A to delegate to an agent owned by another team or vendor.

SeniorHow does MCP authorization work for a remote server?

The MCP server is an OAuth 2.1 resource server. A client that calls it without a token gets a 401 pointing to Protected Resource Metadata, which names the authorization server. The client registers, runs the authorization code flow with PKCE and requests a token whose audience is that specific server (resource indicators). The server validates issuer, audience, expiry and scopes on every call, and must not pass the user's token to downstream APIs; it obtains its own token for them, for example through token exchange.

MidWhat is AG-UI, and why does it exist?

AG-UI is an open event protocol between an agent back end and a user interface: streamed text, tool-call events, state snapshots and deltas, and human-in-the-loop prompts over SSE or WebSockets. It lets one front end (for example CopilotKit) work with agents built in different frameworks, the way MCP standardizes tools. It completes the stack: MCP for tools, A2A for agent-to-agent, AG-UI for agent-to-user.
