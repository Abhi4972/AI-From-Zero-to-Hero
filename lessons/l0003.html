Why this came about

Most people meet generative AI as a chat box that seems to understand them. That impression is useful for using it and useless for building with it: it hides the parts, so failures look mysterious. Teachers such as fast.ai found that showing the whole working system first, then opening it up, helps people learn faster than starting from theory. This lesson is that first look.

In plain words first
The words you will hear, in one breath

Artificial intelligence (AI) is any technique that makes a computer do something that seems to need intelligence. Machine learning is the part of AI where programs learn patterns from examples instead of following rules a person wrote. Deep learning is machine learning with large neural networks. Generative AI is deep learning that creates new content: text, images, sound, code. A large language model (LLM) is a generative model for text, trained to predict the next word. An agent is an LLM given tools it can ask to use, inside a loop that keeps going until a task is done.

Step 1 · A language model predicts the next piece of text

Here is a real language model at work. GPT-2 is a small, free model released by OpenAI in 2019; it is old and weak by today's standards, but it works exactly the way today's large models work, and it runs on a laptop. The code downloads it (about 500 MB, once), gives it the beginning of a sentence, and asks: what comes next?

from transformers import AutoTokenizer, AutoModelForCausalLM
from transformers.utils import logging
import torch
logging.set_verbosity_error()                     # hide download progress messages

tok = AutoTokenizer.from_pretrained("openai-community/gpt2")
model = AutoModelForCausalLM.from_pretrained("openai-community/gpt2")
model.eval()                                      # we are using the model, not training it

prompt = "The capital of France is"
ids = tok(prompt, return_tensors="pt").input_ids  # text -> token numbers
print("tokens:", tok.convert_ids_to_tokens(ids[0]))
print("ids:   ", ids[0].tolist())

with torch.no_grad():                             # no training, so no need to track gradients
    scores = model(ids).logits[0, -1]             # one score per word-piece in the vocabulary
probs = torch.softmax(scores, dim=-1)             # scores -> probabilities that add up to 1
print("vocabulary size:", len(probs))
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode(int(i))!r:12} {float(p):6.1%}")
What you should see
tokens: ['The', 'Ġcapital', 'Ġof', 'ĠFrance', 'Ġis']
ids:    [464, 3139, 286, 4881, 318]
vocabulary size: 50257
' the'         8.5%
' now'         4.8%
' a'           4.6%
' France'      3.2%
' Paris'       3.2%
Reading this output
  • tokens: the model does not see letters or whole words. A tokenizerlater · 5.31 cut the sentence into five pieces called tokens. Ġ is how GPT-2 writes "a space before this piece", so Ġcapital means " capital".
  • ids: each token is replaced by its number in the model's fixed list of pieces. Everything inside the model is arithmetic on numbers like these. Lesson 5.31 builds a tokenizer from scratch.
  • vocabulary size: 50257: GPT-2 knows 50,257 different pieces. For every one of them it produced a score.
  • the five lines: the scores turned into probabilities, highest first. The model thinks the most likely next piece is " the" (8.5%), and " Paris" gets only 3.2%.

Notice what the model is not doing. It is not looking up the capital of France. It learned, from millions of web pages, which pieces of text tend to follow which. "The capital of France is the city of..." is a perfectly common continuation, so " the" scores highest. Larger models put far more probability on " Paris", but the mechanism is identical: score every possible next token, turn the scores into probabilities. the Language as data: NLP foundations and Transformers, step by step sections show how the scores are computed; Lesson 1.25 explains the probabilities.

Step 2 · Generating text is choosing a token and repeating

A model only ever predicts one next token. To write a sentence, you pick a token, add it to the text, and ask again. Here the code always picks the single most likely piece (this is called greedy decoding):

text = prompt
for step in range(8):
    ids = tok(text, return_tensors="pt").input_ids
    with torch.no_grad():
        scores = model(ids).logits[0, -1]
    next_id = int(torch.argmax(scores))           # pick the single most likely next piece
    text += tok.decode(next_id)
    print(step + 1, repr(text))
What you should see
1 'The capital of France is the'
2 'The capital of France is the capital'
3 'The capital of France is the capital of'
4 'The capital of France is the capital of the'
5 'The capital of France is the capital of the French'
6 'The capital of France is the capital of the French Republic'
7 'The capital of France is the capital of the French Republic,'
8 'The capital of France is the capital of the French Republic, and'

The sentence grows one token at a time, and it is fluent but empty: "the capital of France is the capital of the French Republic". Always picking the top choice tends to produce safe, repetitive text. Real systems usually sample, picking tokens at random in proportion to their probabilities, with settings such as temperaturelater · 1.25 that you will drag with a slider in Lesson 7.21.

Step 3 · A model that predicts text is not yet an assistant

Ask GPT-2 to do something, and it does not do it. It continues the text in whatever way looks most like its training data:

request = "Write a polite two-line email declining a meeting on Friday.\n"
ids = tok(request, return_tensors="pt").input_ids
with torch.no_grad():
    out = model.generate(ids, max_new_tokens=30, do_sample=False, pad_token_id=tok.eos_token_id)
print(repr(tok.decode(out[0][ids.shape[1]:])))
What you should see
'\n"I\'m not going to be able to do that," he said. "I\'m not going to be able to do that. I\'m'

It wrote what looks like a line from a story. A model trained only to predict the next word on internet text is called a base model or pretrained model. The assistants you use (ChatGPT, Claude, Gemini, Copilot) are base models that were then trained further on examples of instructions and good answers, and on human feedback about which answers are better. That extra training, covered in Lesson 10.36, is what makes them follow requests. The mechanism underneath is still next-token prediction.

Step 4 · Retrieval: give the model your information

Even the best assistant does not know your company's refund policy or yesterday's orders: it only knows what was in its training data. The fix is simple to state: find the relevant documents yourself and paste them into the prompt. This is called retrieval-augmented generation (RAG). Here is the idea in plain Python, with no AI at all in the search step:

NOTES = {
    "refunds": "Refunds go back to the original payment method within 5 to 7 business days.",
    "delivery": "Metro cities get delivery in 2 to 3 days; other pin codes take 4 to 7 days.",
    "returns": "Most items can be returned within 7 days; damaged items within 30 days.",
}

def retrieve(question):
    """Pick the note that shares the most words with the question."""
    words = set(question.lower().replace("?", "").split())
    return max(NOTES.values(), key=lambda note: len(words & set(note.lower().split())))

question = "How long do refunds take to reach my payment method?"
prompt = f"Answer using only this note.\nNote: {retrieve(question)}\nQuestion: {question}"
print(prompt)
What you should see
Answer using only this note.
Note: Refunds go back to the original payment method within 5 to 7 business days.
Question: How long do refunds take to reach my payment method?

That prompt is what gets sent to the model. The model now answers from your note instead of guessing. Real retrieval replaces the word-matching with smarter search (the Retrieval (RAG) section builds it step by step), but the shape never changes: search, then put what you found in front of the model.

Step 5 · An agent: a model, some tools, and a loop

Some questions need an action: looking up an order, booking a slot, running a query. Modern models can reply with a structured request such as "please run lookup_order with SK-1042" instead of text. Your program runs the function and sends the result back; the model then answers or asks for another tool. Wrap that in a loop and you have an agent.

The "model" below is a stand-in written as a plain function, so you can see the loop without any AI service. In the Agents from first principles section the same loop runs with real models.

def stand_in_model(messages):
    """Stands in for an LLM: decides to use a tool, or to answer once it has the tool's result."""
    last = messages[-1]
    if last["role"] == "user":
        return {"tool": "lookup_order", "args": {"order_id": "SK-1042"}}
    return {"answer": f"Your order is {last['content']['status']}, expected {last['content']['eta']}."}

def lookup_order(order_id):
    """A real system would query the order database here."""
    return {"order_id": order_id, "status": "out for delivery", "eta": "today by 6 pm"}

TOOLS = {"lookup_order": lookup_order}
messages = [{"role": "user", "content": "Where is my order SK-1042?"}]

for step in range(5):                                        # a limit, so a confused agent cannot loop forever
    decision = stand_in_model(messages)
    if "answer" in decision:
        print("ANSWER:", decision["answer"])
        break
    result = TOOLS[decision["tool"]](**decision["args"])     # your code runs the tool, not the model
    print("TOOL CALL:", decision["tool"], decision["args"], "->", result)
    messages.append({"role": "tool", "content": result})
What you should see
TOOL CALL: lookup_order {'order_id': 'SK-1042'} -> {'order_id': 'SK-1042', 'status': 'out for delivery', 'eta': 'today by 6 pm'}
ANSWER: Your order is out for delivery, expected today by 6 pm.

Three things in those few lines are the heart of every agent you will build:

  1. The model decides, your code acts. The model never runs anything itself; it only asks. This is why agents can be made safe: your code chooses what tools exist, checks every request, and can ask a person for approval.
  2. The loop. The agent keeps going, one decision at a time, until it answers. Real tasks take several steps.
  3. A limit. range(5) stops a confused agent. Production agents have limits on steps, time and money.

Exercises

Predict before you run

Change the prompt in Step 1 to "The capital of Japan is". Before running, guess: will " Tokyo" be the top choice? Will " the" still be near the top? (Solution P1.)

Make it your own

In Step 4, add a fourth note about cash on delivery ("COD is available for orders up to INR 10,000") and ask "Can I pay cash on delivery for a 5,000 rupee order?". Does the word-matching retriever pick the right note? (Solution M1.)

Break it on purpose

In Step 5, change stand_in_model so that it always returns the tool request, never an answer. Run the loop. What stops it, and what would happen without range(5)? (Solution B1.)

Solutions

SolutionP1 · The capital of Japan

The run prints ' the' 9.4%, ' Tokyo' 6.7%, ' home' 6.4%, ' a' 4.2%, ' now' 3.8%. Tokyo is second, behind " the", because "is the..." is such a common pattern in web text. The lesson is not the exact numbers but the shape: a ranked list of likely continuations, not a looked-up fact.

SolutionM1 · A fourth note

Add "cod": "COD is available for orders up to INR 10,000 in most pin codes." to NOTES. The retriever returns the delivery note ("Metro cities get delivery in 2 to 3 days..."), not the COD note. The question says "cash on delivery", the note says "COD", so they share almost no words, while the delivery note shares "delivery". This is exactly the weakness of matching words that the Retrieval (RAG) section fixes with synonyms, embeddings and hybrid search.

SolutionB1 · A loop with no exit

The loop calls the tool five times and then stops because range(5) ends, without ever printing an answer. Without the limit it would call the tool forever (or until something crashed or the bill arrived). Every real agent needs a step limit, and a plan for what to tell the user when it is reached.

Recap
  • An LLM scores every possible next token and turns the scores into probabilities; generating text is picking one token and repeating.
  • A base model continues text; an assistant is a base model trained further to follow instructions.
  • RAG means: search your own documents, then put what you found in the prompt.
  • An agent is a model that can request tools, inside a loop with limits; your code runs the tools.
