Foundations and agent design

JuniorWhat is an AI agent, and how is it different from a chatbot?

An agent is a model running in a loop: it decides on an action (usually a tool call), observes the result, and repeats until the goal is met or a limit is reached. A chatbot answers one turn at a time without acting. The practical definition, from Anthropic and Simon Willison, is "an LLM running tools in a loop to achieve a goal". Agents add autonomy, so they also add cost, latency and risk.

JuniorExplain tool calling end to end.

You send the model a list of tools (name, description, JSON schema of parameters). The model returns a structured tool call instead of text. Your code validates the arguments, runs the tool, and sends the result back as a tool message. The model then answers or calls another tool. The model never runs anything itself; your code is the only executor, which is where permissions and checks live.

MidWhen would you use a workflow instead of an agent?

When the steps are known in advance: extraction pipelines, classification then routing, fixed approval flows. Workflows are cheaper, faster, testable step by step and predictable. Use an agent when the path depends on what the model finds (research, troubleshooting, open-ended support). Most production systems are workflows with an agentic step inside.

MidWhat is context engineering, and why did the term replace prompt engineering?

Prompt engineering is wording instructions. Context engineering is deciding everything that goes into the model's window at each step: instructions, tools, retrieved documents, memory, history and tool results, within a token budget. Agents run many steps, so what to select, compress, isolate or drop matters more than phrasing. Failure modes include context poisoning, distraction, confusion and clash.

SeniorSingle agent or multi-agent? Walk me through how you decide.

Start with one agent. Move to several only when (a) the work is broad and parallel, like research across many sources, (b) tool sets or permissions must be separated, or (c) context would overflow. Multi-agent systems cost much more (Anthropic measured about 15 times the tokens of chat) and lose context between agents (Cognition's argument). If you split, give each subagent a precise objective, output format and boundaries, and avoid splitting work whose parts must agree, such as one codebase change.

SeniorHow do you make a long-running agent reliable?

Externalize state: a progress file or task list, checkpoints after each step, durable executionlater · 14.140 so a crash resumes instead of restarting, idempotency keys on side effects, step and token budgets, and human approval for high-impact actions. Compact or summarize context periodically and keep the goal recited near the end. Treat the agent as a stateless reducer over an event log so pause and resume are simple.

JuniorWhat is the ReAct pattern?

ReAct (reason plus act) interleaves reasoning steps with tool calls: think about what to do, call a tool, read the observation, think again. It was introduced in a 2022 paper and is the basis of nearly every tool-calling agent loop. Native tool calling made the format implicit: the model's tool call is the "act", and the tool result is the "observation".

MidWhat kinds of memory does an agent have?

Short-term memory is the conversation and working state in the current context window or thread. Long-term memory persists across sessions and comes in three flavors borrowed from psychology: semantic (facts about the user or domain), episodic (past interactions and their outcomes, often used as examples) and procedural (learned instructions or rules, sometimes the agent's own updated prompt). Long-term memory needs extraction, deduplication, provenance, expiry and per-user isolation, and it is an attack surface (memory poisoning). Managed options include AgentCore Memory, Vertex AI Memory Banklater · 14.120, Foundry memory, LangGraphlater · 14.101 stores, Mem0 and Zep.

MidWhat are the common workflow patterns before you reach for an agent?

From Anthropic's "Building effective agents": prompt chaining (fixed sequence with checks between steps), routing (classify then dispatch), parallelization (sectioning or voting), orchestrator-workers (a model splits work dynamically) and evaluator-optimizer (generate, critique, revise). Each is easier to test and cheaper than a free agent. Good designs say which one fits the problem and why.

MidHow do you design good tools for an agent?

Few tools that match real tasks rather than one per API endpoint; clear names with namespaces; descriptions that say when to use the tool and when not to; typed, constrained parameters (enums, formats); compact, meaningful results (names, not opaque IDs); errors that tell the model what to do next; idempotency on write tools; and permissions enforced inside the tool. Then evaluate tool use on real tasks and refine descriptions from the failures.

SeniorWhat is a "deep agent" or agent harness, and how is it different from a ReAct loop?

A harness wraps the basic loop with what long tasks need: a planning tool (a to-do list the agent maintains), a file system for notes and artifacts, subagents with their own context for isolated subtasks, context compaction, and detailed system prompts. Claude Code, OpenAI's Codex, Deep Research and LangChainlater · 14.93's Deep Agentslater · 14.111 follow this shape. It lets agents work for hours on coding or research while keeping each model call's context focused.

SeniorHow do computer-use and browser agents work, and what are their risks?

The model receives screenshots (and sometimes the accessibility tree or DOM), and returns actions such as click, type and scroll, executed by a harness in a browser or virtual machine. They reach systems without APIs, but they are slower, costlier and less reliable than API tools, and every web page is untrusted input that can carry injected instructions. Run them in isolated sandboxeslater · 15.25 with no stored credentials beyond what the task needs, restrict domains, require confirmation for purchases, logins and sending, and prefer an API or MCPlater · 16.26 tool whenever one exists.

SeniorHow would you add human-in-the-loop to an agent without making it unusable?

Classify actions by risk: read-only runs freely, reversible low-impact actions run with notification, irreversible or high-value actions need approval. Show the reviewer the exact action and arguments plus the agent's reason, and let them edit, approve or reject. Implement the pause as durable state (an interrupt with a checkpointer or a durable waitlater · 14.140) so approvals can take hours. Track approval rates: actions approved 99% of the time are candidates for automation with monitoring, frequently rejected ones point to agent errors.

SeniorHow do structured outputs work, and can you rely on them?

Providers offer constrained decoding: the model can only produce tokens that keep the output valid against a JSON schema, so the result always parses. That guarantees syntax, not meaning: fields can still be wrong, so validate values (Pydantic, business rules) and retry with the error on failure. Without native support, ask for JSON, validate, and repair. Keep schemas small and descriptive; enums and field descriptions improve accuracy.

SeniorAn agent works in demos but picks the wrong tools and loops in production. What do you change first?

Read the failing traces before changing anything. Wrong tool choice usually means overlapping or vague tool descriptions, or too many tools in one agent: rewrite descriptions with when to use and when not to, merge overlaps, and split tools across specialists if the list is long. Loops usually mean no stop criteria and errors hidden from the model: add a step budget, explicit "after two failures, tell the user" instructions, repeated-call detection in code, and keep errors visible. Then move any fixed sequence into a workflow, enforce business rules in tools, and add the failing traces to the eval set so the fix is measured and stays fixed.
