In plain words first
The idea in one line

A Markov Decision Process is five things: states, actions, transitions, rewards, a discount. Everything in RL — Q-learning, PPO, DPO, GRPO — optimizes over this shape. Learn it once, read the rest of reinforcement learning for free.

Terms you'll hear
Term What people say What it actually means
MDP "Reinforcement learning setup" Tuple $(S, A, P, R, \gamma)$ satisfying the Markov property.
State "What the agent sees" Sufficient statistic for future dynamics under the chosen policy class.
Policy "Agent's behavior" Conditional distribution $\pi(a \mid s)$ or deterministic map $s \to a$.
Return "Total reward" Discounted sum $\sum \gamma^t r_t$ from the current step.
Value "How good a state is" Expected return under $\pi$ starting from $s$.
Q-value "How good an action is" Expected return under $\pi$ starting from $s$ with first action $a$.
Bellman equation "Dynamic programming recursion" Fixed-point decomposition of value / Q into one-step reward plus discounted successor value.
Discount $\gamma$ "Future vs present" Geometric weight on far-future reward; effective horizon $\approx 1/(1-\gamma)$.

The problem

In plain words first

Reinforcement learning is learning from consequences instead of from labelled answers. An agent looks at its situation (the state), picks an action, the world responds with a new situation and a number called the reward, and this repeats. The agent's goal is to choose actions that make the total reward large over time, not just right now. A Markov decision process (MDP) is the precise way to write such a problem down: the possible states, the possible actions, how actions change the state, what reward each step gives, and how much future rewards count compared with immediate ones. Every method in this phase, up to the reinforcement learning used to train chat models, works on this description. This lesson runs the lesson's grid world, solves its value equations exactly, and then reads the full rule book of a real environment from the Gymnasium library. Nothing is trained.

You are writing a chess bot. Or an inventory planner. Or a trading agent. Or the PPO loop that trains a reasoning model. Four different domains, one surprising fact: all four collapse to the same mathematical object.

Supervised learning gives you (x, y) pairs and asks you to fit a function. Reinforcement learning gives you no labels — only a stream of states, the actions you took, and a scalar reward. Did the move win the game? Did the restock decision save money? Did the trade make a profit? Did the token the LLM just produced lead to a higher reward from the judge?

You cannot learn from this stream until you formalize it. "What I saw," "what I did," "what happened next," "how good that was" — each has to become an object you can reason about. That formalization is a Markov Decision Process. Every RL algorithm in this phase, including the RLHF and GRPO loops at the end, optimizes over this shape.

The idea

The five objects.

  • States S. Everything the agent needs to decide. In GridWorld, the cell. In chess, the board. In an LLM, the context window plus any memory.
  • Actions A. The choices. Move up/down/left/right. Play a move. Emit a token.
  • Transitions P(s′∣s,a). Given state s and action a, the distribution over next state. Deterministic in chess, stochastic in inventory, almost-deterministic in LLM decoding.
  • Rewards R(s,a,s′). The scalar signal. Win = +1, loss = -1. Revenue minus cost. A verifier's pass/fail score on a language model's answer (GRPO).
  • Discount γ∈[0,1). How much future reward counts vs present. γ=0.99 buys a horizon of ~100 steps; γ=0.9 buys ~10.

The Markov property P(st+1​∣st​,at​)=P(st+1​∣s0​,a0​,…,st​,at​). The future depends only on the present state. If it does not, the state representation is incomplete — not a failure of the method, a failure of the state.

Policies and returns. A policy π(a∣s) maps states to action distributions. The return Gt​=rt​+γrt+1​+γ2rt+2​+… is the discounted sum of future rewards. The value Vπ(s)=E[Gt​∣st​=s] is the expected return starting from s under policy π. The Q-value Qπ(s,a)=E[Gt​∣st​=s,at​=a] is the expected return starting with a specific action. Every RL algorithm estimates one of these two, then improves π accordingly.

The Bellman equations. The fixed-point equations that everything in this phase uses:

Vπ(s)Qπ(s,a)​=a∑​π(a∣s)s′,r∑​P(s′,r∣s,a)[r+γVπ(s′)]=s′,r∑​P(s′,r∣s,a)[r+γa′∑​π(a′∣s′)Qπ(s′,a′)]​

These split expected return into "this step's reward" plus "discounted value of where you land." Recursive. Every algorithm in Phase 9 either iterates this equation to convergence (dynamic programming), samples from it (Monte Carlo), or bootstraps it one step (temporal difference).

The same idea as a formula

An MDP is (S,A,P,R,γ) with P(s′∣s,a) the transition probabilities, R the reward and γ∈[0,1] the discount.

Return and values under a policy π(a∣s):

Gt​=k=0∑∞​γkrt+k​,Vπ(s)=Eπ​[Gt​∣st​=s],Qπ(s,a)=Eπ​[Gt​∣st​=s,at​=a]

Bellman expectation equation in matrix form. Average the rewards and transitions over the policy: rπ(s)=∑a​π(a∣s)E[r∣s,a] and Pπ(s,s′)=∑a​π(a∣s)P(s′∣s,a). Then

Vπ=rπ+γPπVπ⟹Vπ=(I−γPπ)−1rπ

a linear system with one unknown per state. Iterative policy evaluation solves the same system by repeated substitution; it converges because each sweep shrinks errors by a factor γ (a contraction).

Effective horizon. A reward k steps away is weighted γk; the weights sum to 1/(1−γ), so γ=0.99 "sees" about 100 steps.

Undiscounted episodes. With γ=1 and −1 per step, Vπ(s) is minus the expected number of steps to finish; with reward 1 only at a goal, it is the probability of reaching it.

Worked example
A two-state chain by hand

States A and B; from A the agent moves to B with reward −1; from B it moves to the terminal state with reward −1; γ=0.9.

  • V(B)=−1+0.9×0=−1.
  • V(A)=−1+0.9×V(B)=−1−0.9=−1.9.
  • Undiscounted (γ=1): V(A)=−2, the number of steps.

Now make B slippery: with probability 0.5 the move from B fails and the agent stays in B. Then V(B)=−1+0.9(0.5V(B)+0.5×0), so 0.55V(B)=−1 and V(B)=−1.82. Solving one linear equation replaced an infinite sum over how many times the agent slips.

Discount weights. γ=0.9: a reward 10 steps away counts 0.910=0.35; 50 steps away, 0.005.

Check your mental model
  • ✗ "The value of a state is the reward you get there."
    ✓ It is the expected total discounted reward from that state onward, under a given policy; change the policy and the values change.
  • ✗ "The Markov property is a property of the world."
    ✓ It is a property of the state you chose; if decisions need history, put the history into the state.
  • ✗ "Evaluating a policy needs simulation."
    ✓ When the transitions are known, it is a linear system (the runs below solve it exactly); simulation is only needed when they are not.

Step 1 · a tiny deterministic MDP

A 4×4 GridWorld. Agent starts top-left, terminal at bottom-right, reward of -1 per step, actions {up, down, left, right}. See code/main.py.

GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL

Five lines. That is the entire environment. Deterministic transitions, constant step penalty, absorbing terminal state.

Step 2 · roll out a policy

A policy is a function from state to action distribution. The simplest: uniform random.

def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps

Run the random policy 5,000 times: the average return is about −59 on this 4×4 board (exactly −59.4, as the run after Step 4 shows). The optimal return is -6 (straight-line path down-right). Closing that gap is everything in Phase 9.

Step 3 · compute V^π exactly via the Bellman equation

For small MDPs the Bellman equation is a linear system. Enumerate states, apply the expectation, iterate until the values stop changing.

def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V

This is iterative policy evaluation. It is the first algorithm in Sutton & Barto and the theoretical foundation of every RL method that follows.

Step 4 · γ is a hyperparameter with physical meaning

Effective horizon is roughly 1/(1−γ). γ=0.9 → 10 steps. γ=0.99 → 100 steps. γ=0.999 → 1000 steps.

Too low and the agent acts myopically. Too high and credit assignment becomes noisy, because many early steps share responsibility for far-future reward. LLM RLHF typically uses γ=1 because episodes are short and bounded. Control tasks use 0.95–0.99. Long-horizon strategy games use 0.999.

See it drawn
The grid world, evaluated two ways

main.py's main() (5,000 rollouts per policy and iterative policy evaluation; no learning happens), then the same values from the linear system in the formula box, including the undiscounted case.

import numpy as np, runpy
m = runpy.run_path("main.py")
m["main"]()                                             # rollouts and iterative policy evaluation (no learning)

# The same Bellman equation solved in one shot as a linear system, V = r + gamma * P V  ->  (I - gamma P) V = r.
states = [s for s in m["all_states"]() if s != m["TERMINAL"]]
idx = {s: i for i, s in enumerate(states)}
def solve(policy, gamma):
    n = len(states); P = np.zeros((n, n)); r = np.zeros(n)
    for s in states:
        for a, pa in policy(s).items():
            s2, rew, _ = m["step"](s, a)
            r[idx[s]] += pa * rew
            if s2 != m["TERMINAL"]:
                P[idx[s], idx[s2]] += pa
    return np.linalg.solve(np.eye(n) - gamma * P, r)
print("\nexact V(start) from the linear system:")
for g in (0.5, 0.9, 0.99, 1.0):
    print(f"  gamma = {g:<4}: uniform policy {solve(m['uniform_policy'], g)[0]:8.2f} | "
          f"down/right policy {solve(m['greedy_policy'], g)[0]:6.2f}" + ("   <- undiscounted: minus the expected number of steps" if g == 1.0 else ""))
print("effective horizon 1/(1-gamma):", ", ".join(f"gamma {g} -> {1 / (1 - g):.0f} steps" for g in (0.5, 0.9, 0.99)))

Reading this output

The random policy averages −58.7 over 5,000 rollouts, against the optimal −6; the "greedy" policy, which picks down or right at random, averages −7.9, losing a couple of steps by bumping into walls. Policy evaluation fills each cell with its expected discounted return; with γ=0.5 every cell is about −2, because the discount hides anything beyond two steps, while with γ=0.99 the far corner is worth −39.4 and values rise steadily toward the goal. The linear system reproduces the iterative values to two decimals at every γ, and at γ=1 gives the exact expected episode length: −59.43 for the random policy, which the rollouts' −58.67 estimates (rollouts are also cut at 200 steps), and −7.88 for the down/right policy. The horizons, 2, 10 and 100 steps, explain why γ=0.5 sees no difference between cells.

Pitfalls

  • Non-Markovian state. If you need the last three observations to decide, the "state" is not just the current observation. Fix: stack frames (DQN on Atari stacks 4) or use a recurrent state (LSTM/GRU over observations).
  • Sparse rewards. Win-only rewards make learning nearly impossible in large state spaces. Shape rewards (intermediate signal) or bootstrap with imitation (Phase 9 · 09).
  • Reward hacking. Optimizing a proxy reward often produces pathological behavior. OpenAI's boat-racing agent spun in circles collecting powerups forever instead of finishing the race. Always define reward from the target outcome, not the proxy.
  • Discount mis-spec. γ=1 on an infinite-horizon task makes every value infinite. Always cap with either a finite horizon or γ<1.
  • Reward scale. Rewards of {+100, -100} vs {+1, -1} give identical optimal policies but vastly different gradient magnitudes. Normalize to [-1, 1]-ish before plugging into PPO/DQN.

Use it: the same idea with real libraries

The 2026 stack reduces every RL pipeline to an MDP before touching code:

Situation State Action Reward γ
Control (locomotion, manipulation) Joint angles + velocities Continuous torques Task-specific shaped 0.99
Games (chess, Go, poker) Board + history Legal move Win=+1 / loss=-1 1.0 (finite)
Inventory / pricing Stock + demand Order qty Revenue - cost 0.95
RLHF for LLMs Context tokens Next token Reward-model score at end 1.0 (episode ~200 tokens)
GRPO for reasoning Prompt + partial response Next token Verifier 0/1 at end 1.0

Write the five tuples before writing any training loop. Most "RL does not work" bug reports trace back to an MDP formulation that was broken on paper.

See it drawn
A real environment's MDP

Gymnasium's FrozenLake 4 × 4 (slippery ice, holes that end the episode, reward 1 only at the goal), whose full transition table is available as env.unwrapped.P: one transition, the exact value of the random policy, and 20,000 played episodes.

import numpy as np, gymnasium as gym

# FrozenLake 4x4 from Gymnasium: a real MDP whose full transition table is exposed as env.unwrapped.P.
env = gym.make("FrozenLake-v1", is_slippery=True)
P = env.unwrapped.P                                     # P[s][a] = [(prob, next_state, reward, done), ...]
nS, nA = env.observation_space.n, env.action_space.n
print("map:", " / ".join(r.decode() for r in env.unwrapped.desc.reshape(4, 4).astype(bytes).view("S4").ravel()),
      f"| {nS} states, {nA} actions (0 left, 1 down, 2 right, 3 up)")
print("from the start, action 'right' leads to:", [(round(p, 3), s2, r) for p, s2, r, _ in P[0][2]])

def evaluate(pi, gamma):                                 # exact V^pi by a linear solve over the 16 states
    T = np.zeros((nS, nS)); R = np.zeros(nS)
    for s in range(nS):
        for a in range(nA):
            for p, s2, r, done in P[s][a]:
                R[s] += pi[s, a] * p * r
                if not done: T[s, s2] += pi[s, a] * p
    return np.linalg.solve(np.eye(nS) - gamma * T, R)
uniform = np.full((nS, nA), 0.25)
V = evaluate(uniform, 1.0)
print(f"uniform policy, undiscounted: V(start) = {V[0]:.4f} = probability of reaching the goal")
print("V for every cell:\n" + "\n".join("   " + " ".join(f"{v:.3f}" for v in V[r * 4:(r + 1) * 4]) for r in range(4)))

rng = np.random.default_rng(0); wins = 0; N = 20_000
for ep in range(N):                                      # the same quantity estimated by actually playing
    s, _ = env.reset(seed=int(rng.integers(1e9)))
    done = False
    while not done:
        s, r, term, trunc, _ = env.step(int(rng.integers(4))); done = term or trunc
    wins += r
print(f"{N:,} random episodes in Gymnasium: success rate {wins / N:.4f} (episodes are cut at 100 steps)")

Break it on purpose

In policy_evaluation, set gamma = 1.0 and remove the terminal check, so the terminal state's value is also updated with its own transition (step returns the terminal again with reward 0). Industry practice
What's current (2024–2026)
  • Gymnasium is the standard environment API. The Farama Foundation's Gymnasium (successor to OpenAI Gym), with PettingZoo for multi-agent tasks and MuJoCo/Brax/MJX for physics, defines reset/step for most RL code; Stable-Baselines3, CleanRL and RLlib build on it.
  • MDPs inside LLM training. RL for language models (RLHF with PPO, GRPO for reasoning, used for DeepSeek-R1 and in libraries such as TRL, verl and OpenRLHF) treats the prompt plus generated text as the state, the next token as the action and a reward model or verifier as the reward, usually with γ=1.
  • Agentic RL environments. Training LLM agents on tool use and coding happens in sandboxed environments with programmatic rewards (tests passing, tasks completed), the same five-part MDP at a much larger scale.

Sources: Gymnasium, Stable-Baselines3, TRL, verl, DeepSeek-R1.

Recap
What to keep from this lesson
  • An MDP is states, actions, transitions, rewards and a discount; write all five before any training code.
  • Vπ and Qπ are expected discounted returns under a policy.
  • With known transitions, Vπ=(I−γPπ)−1rπ; iterative evaluation converges to the same answer.
  • γ sets an effective horizon of about 1/(1−γ) steps.
  • The Markov property belongs to the state representation; add history if it fails.

Solutions

SolutionP1 · About 60

About 60: the exact undiscounted value is −59.4, so the random walk takes almost ten times the shortest path's 6 steps. At each step only two of the four actions (down, right) move toward the goal, the other two move away or bump into a wall, and the walk keeps revisiting cells. The 5,000 rollouts in Step 2 estimate the same number as −58.7. A random policy is a terrible baseline in any but the smallest problems, which is why exploration strategies matter from Lesson 9.3 on.

SolutionB1 · Fine, then infinite

Without the terminal check but with a self-loop of reward 0, the terminal value stays 0 under γ=1 (it only ever adds zeros), so the first case still converges to the same values; the check was a shortcut, not a necessity. The second case breaks: in cells that can never reach the terminal, each sweep adds another −1 to the value, so with γ=1 the values head to −∞ and the loop runs until max_iter without converging. In matrix terms, I−Pπ is singular when some states never leave, so the linear system has no solution. That is why infinite-horizon tasks need γ<1 (the formula box's contraction) or a guaranteed way to terminate.
