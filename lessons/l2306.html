Why this came about

Logistic regression draws straight lines; real data often follows rules like "late if it is long and at rush hour". Researchers in the 1960s to 1980s (notably Leo Breiman and Ross Quinlan) built decision trees that learn such if-then rules directly. Single trees overfit, so Breiman's random forests (2001) averaged hundreds of them, and Jerome Friedman's gradient boosting (1999 to 2001) built trees that correct each other's errors. Boosted trees, in libraries like XGBoost (2014) and LightGBM (2017), still win most competitions on spreadsheet-style data today. Alongside these, methods for data without labels (clustering, compression) and for learning from rewards grew into fields of their own. This lesson is a guided tour, so you know what exists and when to reach for it.

In plain words first
A toolbox, not a ladder

It is tempting to think of AI methods as a ladder, with language models at the top making everything below obsolete. A better picture is a toolbox. A spreadsheet of past orders with a yes/no column to predict is a job for boosted trees: they train in seconds on a laptop and are often more accurate than anything else for that shape of data. Grouping customers with no labels is a job for clustering. Reading and writing language is the job for a language model. Knowing which tool fits is a large part of building good AI systems, including agents, which often call classic models as tools.

Step 1 · Decision trees: learned if-then rules

A decision tree asks a sequence of yes/no questions about the features. Training picks, at each step, the question that best separates the examples (for instance, the one that makes the groups below as close as possible to all-late or all-on-time), then repeats inside each group. Here are 600 simulated deliveries with three features:

import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text

rng = np.random.default_rng(3)
n = 600
dist = rng.uniform(1, 20, n).round(1)
raining = (rng.random(n) < 0.3).astype(int)
rush_hour = (rng.random(n) < 0.4).astype(int)
# hidden rule: short trips are late mainly in rain; long trips mainly at rush hour
p_late = np.where(dist <= 9, np.where(raining == 1, 0.65, 0.08), np.where(rush_hour == 1, 0.9, 0.35))
late = (rng.random(n) < p_late).astype(int)

X = np.column_stack([dist, raining, rush_hour])
X_train, X_test, y_train, y_test = train_test_split(X, late, test_size=0.25, random_state=0)

tree = DecisionTreeClassifier(max_depth=2, random_state=0).fit(X_train, y_train)
print(export_text(tree, feature_names=["km", "raining", "rush_hour"], show_weights=True))
print("test accuracy:", round(tree.score(X_test, y_test), 3))

|   |--- raining <= 0.50
|   |   |--- weights: [133.00, 11.00] class: 0
|   |--- raining >  0.50
|   |   |--- weights: [22.00, 37.00] class: 1
|--- km >  9.25
|   |--- rush_hour <= 0.50
|   |   |--- weights: [90.00, 52.00] class: 0
|   |--- rush_hour >  0.50

Reading this output
  • Each |--- line is a question; indentation shows which branch you are on. weights: [133.00, 11.00] means 133 on-time and 11 late training deliveries ended up in that leaf, so its prediction is class 0 (on time).
  • The tree found the hidden rule from data alone: first split on distance near 9 km, then ask about rain for short trips and rush hour for long ones. A linear model cannot express "rain matters for short trips but not long ones" without hand-made features; a tree learns it directly.
  • raining <= 0.50 is how the tree writes "not raining", because it only knows numbers (0 or 1).
  • You can read the whole model. That makes trees popular where decisions must be explained, such as credit and medicine.

Let the tree grow deeper and watch Lesson 2.26 happen again:

for depth in [1, 2, 3, 5, None]:                  # None means grow until every leaf is pure

    print(f"max_depth {str(depth):>4}:  train {t.score(X_train, y_train):.3f}   test {t.score(X_test, y_test):.3f}   leaves {t.get_n_leaves()}")

An unlimited tree carves the training data into 132 tiny leaves, many holding just one or two deliveries, and memorises the noise: training accuracy 0.95, test accuracy down to 0.68. max_depth is the tree's regularisation dial, chosen on validation data.

Step 2 · Many trees: forests and boosting

A single deep tree is unstable: change a few training examples and it can change completely. Combining many trees, called an ensemble, fixes this:

  • Random forest: train hundreds of trees, each on a random sample of the examples and considering a random subset of features at each question, then let them vote. Their individual mistakes are partly random, so they cancel out.
  • Gradient boosting: train small trees one after another; each new tree is fitted to the errors the trees so far still make. The prediction is the sum of all the trees' contributions. This is gradient descent again, but each "step" is a whole tree.

Both appear in the head-to-head comparison in Step 6. In practice, for data that fits in a spreadsheet (rows of customers, orders, transactions, sensor readings), gradient boosted trees are usually the strongest first choice, ahead of neural networks. scikit-learn's HistGradientBoostingClassifier and the separate libraries XGBoost, LightGBM and CatBoost implement it.

Step 3 · Nearest neighbours: "you are like the things you are close to"

The simplest classifier of all does no training. To label a new example, find the k labelled examples closest to it and take a vote: k-nearest neighbours (kNN). Here it is with the snack vectors of Lesson 1.23 ([sweet, salty]):

snacks = {
    "masala chips":  ([0.1, 0.9], "savoury"),
    "salted peanuts": ([0.0, 0.8], "savoury"),
    "namkeen mix":   ([0.2, 0.8], "savoury"),
    "chocolate":     ([0.9, 0.1], "sweet"),
    "gulab jamun":   ([1.0, 0.0], "sweet"),
    "jalebi":        ([0.95, 0.05], "sweet"),
}

def knn(query, k=3):
    q = np.array(query)
    dists = sorted((np.linalg.norm(np.array(vec) - q), name, label) for name, (vec, label) in snacks.items())
    nearest = dists[:k]
    for dist_, name, label in nearest:
        print(f"   {name:<14} distance {dist_:.2f}  ({label})")
    labels = [label for _, _, label in nearest]
    return max(set(labels), key=labels.count)            # the most common label

print("chikki [0.75, 0.3] ->", knn([0.75, 0.3]))
What you should see
   chocolate      distance 0.25  (sweet)
   jalebi         distance 0.32  (sweet)
   gulab jamun    distance 0.39  (sweet)
chikki [0.75, 0.3] -> sweet

np.linalg.norm(a - b) is the straight-line distance between two vectors. Chikki (peanut brittle) is closest to the sweet snacks, so it is classed as sweet.

This is the same operation as the vector searchlater · 14.71 at the heart of retrieval (Lesson 14.71): turn every document chunk into a vector (an embeddinglater · 3.19), turn the question into a vector, and fetch the nearest chunks. Real systems use cosine similarity rather than distance, and special indexes (Lesson 14.74) to search millions of vectors without comparing against every one.

Step 4 · Learning without labels: clusters and compression

k-means clustering groups examples into k clusters, with no labels at all. It starts with k random centres, then repeats two steps: assign each example to its nearest centre; move each centre to the average of its examples. Here are 150 customers described by orders per month and average basket value. We secretly made them as three kinds (40 occasional big spenders, 60 frequent small shoppers, 50 in between), but k-means is not told.

from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(5)
orders, basket = [], []
for mean_orders, mean_basket, count in [(2, 2500, 40), (12, 400, 60), (6, 1200, 50)]:
    orders += list(rng.normal(mean_orders, 1.2, count).clip(0.5).round(1))
    basket += list(rng.normal(mean_basket, mean_basket * 0.2, count).round(0))
customers = np.column_stack([orders, basket])

raw = KMeans(n_clusters=3, n_init=10, random_state=0).fit(customers)
print("raw features, cluster sizes:", np.bincount(raw.labels_))

scaler = StandardScaler().fit(customers)
scaled = KMeans(n_clusters=3, n_init=10, random_state=0).fit(scaler.transform(customers))
print("scaled features, cluster sizes:", np.bincount(scaled.labels_))
for o, b in scaler.inverse_transform(scaled.cluster_centers_):
    print(f"   centre: {o:4.1f} orders a month, average basket ₹{b:,.0f}")
What you should see
raw features, cluster sizes: [64 32 54]
scaled features, cluster sizes: [52 60 38]
   centre:  5.9 orders a month, average basket ₹1,204
   centre: 11.9 orders a month, average basket ₹407
   centre:  1.7 orders a month, average basket ₹2,545
Reading this output
  • On raw numbers, distances are dominated by the basket value (differences of hundreds of rupees) while order counts (differences of a few orders) barely count. The clusters come out the wrong sizes, cut by basket size alone.
  • After StandardScaler (the standardisation of Lesson 2.23) both features count equally, and the cluster sizes come close to the true 40, 60 and 50. The centres describe three customer types a marketing team can act on.
  • n_init=10 runs k-means ten times from different random starts and keeps the best, because a bad start can give poor clusters. inverse_transform turns the centres back into orders and rupees.
  • Distance-based methods (kNN, k-means) almost always need scaled features.

How do you choose k when you do not know it? A common check is the elbow: run k-means for several k and look at the total squared distance from points to their centres (called inertia), which always falls as k grows. Look for where it stops falling fast.

for k in range(1, 7):
    inertia = KMeans(n_clusters=k, n_init=10, random_state=0).fit(scaler.transform(customers)).inertia_
    print(k, round(inertia, 1))
What you should see
1 300.0
2 95.0
3 24.5
4 17.0
5 14.4
6 12.1

The big drops stop after 3 (95 to 24.5, then only to 17): three clusters is a sensible answer. Real data is rarely this clear, and the choice also depends on what is useful to the business.

PCA (principal component analysis) is the other classic unsupervised tool: it compresses many features into a few new ones, the directions in which the data varies most. It is used to visualise high-dimensional data and to remove redundant features.

from sklearn.datasets import load_digits
from sklearn.decomposition import PCA

digits = load_digits()                                 # 1,797 images, 64 pixel values each
pca2 = PCA(n_components=2).fit(digits.data)
print("variance kept by 2 components:", pca2.explained_variance_ratio_.round(3), "total", pca2.explained_variance_ratio_.sum().round(3))
print("variance kept by 10 components:", PCA(n_components=10).fit(digits.data).explained_variance_ratio_.sum().round(3))
print("first image (a 0) as 2 numbers:", pca2.transform(digits.data[:1]).round(1))
What you should see
variance kept by 2 components: [0.149 0.136] total 0.285
variance kept by 10 components: 0.738
first image (a 0) as 2 numbers: [[ -1.3 -21.3]]

Two numbers keep only 28.5% of the variation in 64 pixels, yet the picture already separates the digits quite well. Ten keep almost three-quarters. You will use PCA in Lesson 5.33 to draw word embeddings (hundreds of numbers each) on a flat page.

Step 5 · Learning from rewards

In reinforcement learning, nobody gives the right answers. An agent tries actions, receives rewards, and gradually prefers actions that pay off. It must balance exploring (trying options to learn about them) and exploiting (using the best option found so far). The smallest version is the multi-armed bandit: here, a dispatcher choosing among three delivery routes whose on-time rates it does not know.

rng = np.random.default_rng(0)
true_on_time = [0.55, 0.75, 0.60]           # hidden from the agent
estimate = np.zeros(3)                      # the agent's running estimate for each route
tries = np.zeros(3, dtype=int)
on_time = 0

for delivery in range(1000):
    if rng.random() < 0.1:                  # 10% of the time: explore a random route
        route = rng.integers(3)
    else:                                   # otherwise: exploit the best estimate so far
        route = int(np.argmax(estimate))
    reward = float(rng.random() < true_on_time[route])     # 1 if on time
    tries[route] += 1
    estimate[route] += (reward - estimate[route]) / tries[route]   # update the running average
    on_time += reward

print("estimates:", estimate.round(3))
print("times each route was used:", tries)
print("on time:", int(on_time), "of 1000")
What you should see
estimates: [0.5   0.758 0.592]
times each route was used: [ 42 855 103]
on time: 730 of 1000
Reading this output
  • The agent's estimates end close to the hidden rates for the routes it tried often, and it used the best route (index 1, 75%) for 855 of 1,000 deliveries, while still occasionally checking the others.
  • It achieved 730 on-time deliveries. Always using the best route would give about 750; picking at random about 633. The small gap to 750 is the cost of exploring.
  • estimate += (reward - estimate) / tries is a running average: it nudges the estimate towards each new reward by a shrinking amount. Notice the shape: "estimate plus step size times error", like a gradient descent step.

Full reinforcement learning adds situations (the best action depends on the state of the world) and delayed rewards (a chess move pays off twenty moves later). It mastered Go in 2016 (AlphaGo). For language models, it is how assistants are tuned to give answers people prefer (RLHFlater · 10.36), and how reasoning modelslater · 10.37 learn to work through problems, rewarded when their final answer is correct (Lessons 10.36 and 10.37).

Step 6 · Head to head on one dataset

Here is every classifier from this block on the handwritten digits, with the same training and test split:

from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier

X_train, X_test, y_train, y_test = train_test_split(digits.data, digits.target, test_size=0.25, random_state=0)
models = {
    "logistic regression": LogisticRegression(max_iter=3000),
    "3-nearest neighbours": KNeighborsClassifier(n_neighbors=3),
    "decision tree": DecisionTreeClassifier(random_state=0),
    "random forest": RandomForestClassifier(n_estimators=200, random_state=0),
    "gradient boosting": HistGradientBoostingClassifier(random_state=0),
}
for name, model in models.items():
    model.fit(X_train, y_train)
    print(f"{name:<22} test accuracy {model.score(X_test, y_test):.3f}")
What you should see
logistic regression    test accuracy 0.953
3-nearest neighbours   test accuracy 0.987
decision tree          test accuracy 0.838
random forest          test accuracy 0.982
gradient boosting      test accuracy 0.964
Reading this output
  • The same two lines (fit, then score or predict) work for every model. That shared interface is scikit-learn's great strength: trying five models costs five lines.
  • A single tree (0.838) is clearly the weakest; a forest of 200 trees (0.982) fixes most of its mistakes.
  • Nearest neighbours wins here (0.987), because images of the same digit really are close pixel by pixel. On another dataset the ranking would change. There is no best model in general, which is why you compare on validation data.
  • A small neural network (scikit-learn's MLPClassifier, one hidden layer of 64) gets about 0.976 on this split. Neural networks' real advantage shows on large, raw data such as photos, sound and text (the Neural networks and deep learning section).

Step 7 · Choosing the tool

Your problem Reach for Why
A table of rows and columns, predict a number or category gradient boosted trees; start with logistic or linear regression as a baseline fast, accurate, little tuning; linear models are easy to explain
You must explain every decision linear model or a shallow tree the whole model can be read
Group or explore data with no labels k-means (after scaling), PCA to visualise no labelling cost
Find similar items nearest neighbours on vectors (embeddings) the basis of search and recommendations (Lesson 14.71)
Images, audio, raw signals neural networks (the Neural networks and deep learning section) they learn their own features
Read, write or reason in language a language model (the sections from Language as data: NLP foundations to From language model to assistant, then the Talking to models: APIs, messages, prompts and context section onwards) the only tool that handles open-ended text
Learn a strategy from trial and reward reinforcement learning when the right answer is not known, only how good outcomes are
Tip
Classic models make excellent agent tools

A support agent built on a language model can call a gradient-boosted "will this order be late?" model as a tool (the Agents from first principles section), instead of asking the LLM to guess from text. The classic model is cheaper, faster, consistent, and measurable with the methods of Lesson 2.25.

Check your mental model
  • ✗ "Language models have replaced classic machine learning."
    ✓ For tabular prediction, boosted trees are usually more accurate and thousands of times cheaper. LLMs are for language.
  • ✗ "Unsupervised learning finds the true groups in the data."
    ✓ It finds groups according to the distance and features you chose. Unscaled features gave wrong groups above; different features give different groups.
  • ✗ "Random forests can't overfit because they average many trees."
    ✓ They resist overfitting well, but leakage and distribution shift (Lesson 2.26) hurt them like any model, and they still need honest test data.

Practice
Apply it

For each, name the tool from Step 7: (a) predict which of 50,000 customers will cancel next month from 30 columns of account data; (b) summarise customer complaints into themes in plain English; (c) find products similar to the one a shopper is viewing; (d) group 10,000 delivery addresses into 12 zones for planning. (Solution X1.)

Solutions

SolutionP1 · kNN with different k

With k = 3 the three nearest snacks are all savoury (namkeen mix, masala chips, salted peanuts), so the answer is savoury. With k = 6 every snack votes: three savoury, three sweet. That is a tie, and this simple code then returns whichever label max meets first in the set, which can even change from one run of Python to the next. Not a meaningful answer. In practice, use an odd k for two classes, or weight votes by closeness.

SolutionM1 · Never explore, explore a lot

With 0.0 the agent picks route 0 first (all estimates start at 0, and argmax takes the first). Its first delivery is on time, so route 0's estimate rises above the others' zeros and it never tries anything else: 1,000 deliveries on the worst route, 556 on time. With 0.5 it does find the best route but spends half its decisions on random routes: 685 on time, well below 730. Some exploration is essential, but not too much. Many real systems explore more at the start and less later.

SolutionX1 · Picking tools

(a) gradient boosted trees on the tabular data, with logistic regression as a baseline; (b) a language model, perhaps after clustering complaint embeddings to find the themes; (c) nearest neighbours on product embeddings (vector search); (d) k-means on the addresses' coordinates (latitude and longitude are already on similar scales, so this is one of the rare cases where scaling is less important).

Recap
  • Decision trees learn readable if-then rules but overfit when grown deep; max_depth controls them.
  • Random forests (voting trees) and gradient boosting (trees correcting each other) are the strongest tools for tabular data.
  • k-nearest neighbours labels by similarity, the same idea as vector search in RAGlater · 10.45.
  • k-means finds groups and PCA compresses features, both without labels; distance-based methods need scaled features.
  • Reinforcement learning learns from rewards by balancing exploration and exploitation; it is used to tune and train reasoning in modern assistants.
  • Choose the tool from the shape of the data and the job; language models are the right tool for language, not for everything.
