The problem

In plain words first

Translation turns a sequence into a different sequence, with a different length and in a different vocabulary. The sequence-to-sequence (seq2seq) design does it with two networks. An encoder reads the whole input and condenses it into a summary. A decoder writes the output one token at a time, each time looking at the summary and at what it has written so far. Training shows the decoder the correct previous word ("teacher forcing"). At use time it has to rely on its own guesses, which is a source of errors. Choosing the output is itself a search problem, because the best first word does not always lead to the best sentence. This lesson writes the equations behind all of that, works through greedy and beam search by hand, and runs a pretrained translation model to see where its decoder looks.

Classification maps a variable-length sequence to a single label. Translation maps a variable-length sequence to another variable-length sequence. The input and output live in different vocabularies, possibly different languages, with no guarantee of length parity.

The seq2seq architecture (Sutskever, Vinyals, Le, 2014) cracked this with a deliberately simple recipe. Two RNNs. One reads the source sentence and produces a fixed-size context vector. The other reads that vector and generates the target sentence token by token. Same code you wrote for lesson 08, glued together differently.

This is worth studying for two reasons. First, the context-vector bottleneck is the most pedagogically useful failure in NLP. It motivates everything attention and transformers are good at. Second, the training recipe (teacher forcing, scheduled sampling, beam search at inference) still applies to every modern generation system including LLMs.

The idea

Encoder. An RNN that reads the source sentence. Its final hidden state is the context vector — a fixed-size summary of the entire input. Lose nothing but the source, supposedly.

Decoder. Another RNN initialized from the context vector. At each step it takes the previously generated token as input and produces a distribution over the target vocabulary. Sample or argmax to pick the next token. Feed it back in. Repeat until an <EOS> token is produced or max length is hit.

Training: Cross-entropy loss at each decoder step, summed over the sequence. Standard backprop through time through both networks.

Teacher forcing. During training, the decoder's input at step t is the ground-truth token at position t-1, not the decoder's own previous prediction. This stabilizes training: without it, an untrained decoder's early mistakes become its next inputs, the targets no longer line up with what it is reading, and learning is slow and unstable. At inference, you have to use the model's own predictions, so there is always a train/inference distribution gap. That gap is called exposure bias.

The bottleneck. Everything the encoder learned about the source must be squeezed into that one context vector. Long sentences lose detail. Rare words get blurred. Reordering (chat noir vs. black cat) has to be memorized, not computed.

Attention (lesson 10) fixes this by letting the decoder look at every encoder hidden state, not just the last one. That is the whole pitch.

The same idea as a formula

What the model computes. For a source x=(x1​,…,xn​) and target y=(y1​,…,ym​) ending in <EOS>, the chain rule of probability gives

P(y∣x)=t=1∏m​P(yt​∣y1​,…,yt−1​,x)

The encoder turns x into a context c (here the last hidden state, c=hnenc​). The decoder keeps its own state st​=GRU(st−1​,embed(yt−1​)) with s0​=c, and predicts P(yt​∣y<t​,x)=softmax(Wst​+b).

Training. Maximise the log-likelihood of the reference translation, which is the same as minimising the summed cross-entropy:

L=−t=1∑m​logP(yt​∣y<t​,x)

With teacher forcing, the y<t​ fed to the decoder are the reference tokens, so every step's loss can be computed even when the model would have guessed wrong.

Exposure bias. At inference the condition becomes the model's own output, y^​<t​. The model was never trained on its own mistakes, so one wrong token can push it into states it has never seen. Scheduled sampling (Bengio et al., 2015) feeds the model's own predictions with a probability that grows during training.

Decoding is a search. We want y^​=argmaxy​logP(y∣x), but there are ∣V∣m candidate outputs. Greedy decoding takes the best token at each step; beam search keeps the k best partial outputs. Because every extra token multiplies in a probability below 1, raw scores favour short outputs; a length penalty divides the score, for example by ∣y∣α (GNMT used ((5+∣y∣)/6)α with α≈0.6 to 1).

The bottleneck. Whatever the source length, c has a fixed size (dh​ numbers, 256 or 512 in typical models). The information about a 40-word sentence must pass through the same few hundred numbers as a 5-word one.

Worked example
Greedy versus beam search by hand

A tiny made-up decoder. Each row gives the probability of the next token after the last one ("BOS" is the start):

after next-token probabilities
BOS the 0.45, a 0.40, EOS 0.15
the cat 0.30, dog 0.30, mat 0.25, EOS 0.15
a cat 0.90, EOS 0.10
cat, dog sat 0.60, EOS 0.40
sat down 0.50, on 0.30, EOS 0.20
down EOS 0.90, the 0.10
  • Greedy: "the" (0.45), then "cat" (0.30), "sat" (0.60), "down" (0.50), EOS (0.90). Total 0.45×0.30×0.60×0.50×0.90=0.036.
  • Beam, width 2: after step 1 keep "the" (0.45) and "a" (0.40). After step 2 the best two are "a cat" (0.40×0.90=0.36) and "the cat" (0.135): "a" lost at step 1 but leads by step 2. From there, stopping ("a cat EOS", 0.36×0.40=0.144) beats continuing to "a cat sat down EOS" (0.36×0.60×0.50×0.90=0.097) on raw probability, so the raw-score beam returns the shorter output, four times greedy's probability.
  • The short-output trap: "EOS" alone, the empty translation, has probability 0.15, higher than either. Exact search with raw probabilities returns nothing. Dividing logP by length fixes it: ln0.15/1=−1.90, while ln0.097/5=−0.47.

The experiment under "Use it" runs exactly this table through a beam search and an exhaustive search.

Check your mental model
  • ✗ "Greedy decoding finds the most likely output."
    ✓ It finds the output made of locally best choices. The worked example's greedy answer is three times less likely than beam search's.
  • ✗ "A wider beam is always better."
    ✓ Wider beams find higher-probability outputs, and the most probable output is not always the best one: for translation, very wide beams return shorter and blander outputs, and an exact search can even return an empty one (Stahlberg and Byrne, 2019).
  • ✗ "Teacher forcing is a trick for inference."
    ✓ It is a training-time choice. At inference there is no reference, so the decoder always reads its own outputs.

Step 1 · an encoder

import torch
import torch.nn as nn


class Encoder(nn.Module):
    def __init__(self, src_vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.embed = nn.Embedding(src_vocab_size, embed_dim, padding_idx=0)
        self.gru = nn.GRU(embed_dim, hidden_dim, batch_first=True)

    def forward(self, src):
        e = self.embed(src)
        outputs, hidden = self.gru(e)
        return outputs, hidden

outputs has shape [batch, seq_len, hidden_dim] — one hidden state per input position. hidden has shape [1, batch, hidden_dim] — the final step. Lesson 5.8 said "pool over outputs for classification." Here we keep the last hidden state as the context vector, and ignore the per-step outputs.

Step 2 · a decoder

class Decoder(nn.Module):
    def __init__(self, tgt_vocab_size, embed_dim, hidden_dim):
        super().__init__()
        self.embed = nn.Embedding(tgt_vocab_size, embed_dim, padding_idx=0)
        self.gru = nn.GRU(embed_dim, hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, tgt_vocab_size)

    def forward(self, token, hidden):
        e = self.embed(token)
        out, hidden = self.gru(e, hidden)
        logits = self.fc(out)
        return logits, hidden

Decoder is called one step at a time. Input: a batch of single tokens and the current hidden state. Output: vocabulary logits for the next token and the updated hidden state.

Step 3 · training loop with teacher forcing

def train_batch(encoder, decoder, src, tgt, bos_id, optimizer, teacher_forcing_ratio=0.9):
    optimizer.zero_grad()
    _, hidden = encoder(src)
    batch_size, tgt_len = tgt.shape
    input_token = torch.full((batch_size, 1), bos_id, dtype=torch.long)
    loss = 0.0
    loss_fn = nn.CrossEntropyLoss(ignore_index=0)

    for t in range(tgt_len):
        logits, hidden = decoder(input_token, hidden)
        step_loss = loss_fn(logits.squeeze(1), tgt[:, t])
        loss += step_loss
        use_teacher = torch.rand(1).item() < teacher_forcing_ratio
        if use_teacher:
            input_token = tgt[:, t].unsqueeze(1)
        else:
            input_token = logits.argmax(dim=-1)

    loss.backward()
    optimizer.step()
    return loss.item() / tgt_len

Two knobs worth naming. ignore_index=0 skips loss on padding tokens. teacher_forcing_ratio is the probability of using the true token vs. the model's prediction at each step. Start at 1.0 (full teacher forcing) and anneal down to ~0.5 over training to close the exposure-bias gap.

Step 4 · inference loop (greedy)

@torch.no_grad()
def greedy_decode(encoder, decoder, src, bos_id, eos_id, max_len=50):
    _, hidden = encoder(src)
    batch_size = src.shape[0]
    input_token = torch.full((batch_size, 1), bos_id, dtype=torch.long)
    output_ids = []
    for _ in range(max_len):
        logits, hidden = decoder(input_token, hidden)
        next_token = logits.argmax(dim=-1)
        output_ids.append(next_token)
        input_token = next_token
        if (next_token == eos_id).all():
            break
    return torch.cat(output_ids, dim=1)

Greedy decoding picks the highest-probability token at every step. It can wander off: once you commit to a token, you cannot unsay it. Beam search keeps the top-k partial sequences alive and picks the highest-scoring complete one at the end. Beam width 3-5 is standard, with a length penalty so the search does not prefer short outputs.

Step 5 · the bottleneck, demonstrated

The classic demonstration trains this model on a toy copy task: source [a, b, c, d, e], target [a, b, c, d, e], at increasing lengths. The numbers below show the typical pattern. They are illustrative and were not run on this page (this course does not train models here); exact values depend on the hidden size and training time, but the steep fall with length is robust.

seq_len=5   copy accuracy: 98%
seq_len=10  copy accuracy: 91%
seq_len=20  copy accuracy: 62%
seq_len=40  copy accuracy: 23%

A single GRU hidden state cannot losslessly memorize a 40-token input. The information is there at every encoder step, but the decoder only sees the last state. Attention fixes this directly.

Use it: the same idea with real libraries

PyTorch has nn.Transformer and nn.LSTM-based seq2seq templates. Hugging Face's transformers library ships full encoder-decoder models (BART, T5, mBART, NLLB) trained on billions of tokens.

import math
import itertools
import matplotlib.pyplot as plt

NEXT = {"BOS": {"the": .45, "a": .40, "EOS": .15}, "the": {"cat": .30, "dog": .30, "mat": .25, "EOS": .15},
        "a": {"cat": .90, "EOS": .10}, "cat": {"sat": .60, "EOS": .40}, "dog": {"sat": .60, "EOS": .40},
        "sat": {"down": .50, "on": .30, "EOS": .20}, "down": {"EOS": .90, "the": .10}, "on": {"the": .90, "EOS": .10},
        "mat": {"EOS": 1.0}}

def score(seq, logp, normalise):
    return logp / len(seq) if normalise else logp

def beam_search(k, normalise, max_len=6):
    beams, finished = [(["BOS"], 0.0)], []
    for _ in range(max_len):
        candidates = [(seq + [w], lp + math.log(p)) for seq, lp in beams for w, p in NEXT[seq[-1]].items()]
        candidates.sort(key=lambda c: -c[1])
        beams = []
        for seq, lp in candidates:
            (finished if seq[-1] == "EOS" else beams).append((seq, lp))
            if len(beams) == k:
                break
        if not beams:
            break
    best = max(finished, key=lambda c: score(c[0][1:], c[1], normalise))
    return " ".join(best[0][1:]), best[1]

def exhaustive(normalise, max_len=6):
    found = []
    def walk(seq, lp):
        if seq[-1] == "EOS":
            found.append((" ".join(seq[1:]), lp, score(seq[1:], lp, normalise))); return
        if len(seq) > max_len:
            return
        for w, p in NEXT[seq[-1]].items():
            walk(seq + [w], lp + math.log(p))
    walk(["BOS"], 0.0)
    return max(found, key=lambda f: f[2]), len(found)

for normalise in (False, True):
    print("length-normalised score" if normalise else "raw log-probability")
    for k in (1, 2, 3):
        out, lp = beam_search(k, normalise)
        print(f"   beam width {k}{' (greedy)' if k == 1 else '         '}  {out:28s} P = {math.exp(lp):.3f}")
    (out, lp, _), n = exhaustive(normalise)
    print(f"   exhaustive over {n} outputs  {out:28s} P = {math.exp(lp):.3f}")

outs = {}
def collect(seq, lp):
    if seq[-1] == "EOS":
        outs[" ".join(seq[1:])] = lp; return
    if len(seq) > 6:
        return
    for w, p in NEXT[seq[-1]].items():
        collect(seq + [w], lp + math.log(p))
collect(["BOS"], 0.0)
top = sorted(outs.items(), key=lambda kv: -kv[1])[:8]
fig, ax = plt.subplots(figsize=(6.5, 3.2))
ax.barh(range(len(top)), [math.exp(v) for _, v in top], color=["#b24a1d" if k == "EOS" else "#474d9a" for k, _ in top])
ax.set_yticks(range(len(top)), [k for k, _ in top], fontsize=8); ax.invert_yaxis()
ax.set_xlabel("probability of the whole output"); ax.grid(axis="x", alpha=0.3)
ax.set_title("The most probable output is the empty one", fontsize=9)

Greedy (width 1) commits to "the" and ends with a probability of 0.036. With raw probabilities, wider search keeps finding shorter outputs: width 2 returns "a cat" (0.144), width 3 and the exhaustive search return the empty output, just "EOS" (the red bar), the single most probable output in the whole space. With length-normalised scores, width 2 already finds "a cat sat down" (0.097), the best full sentence, and wider search agrees. This is not a bug in the search. The model really does assign that output the highest probability, because each extra word multiplies in another number below 1. Dividing by length changes what "best" means and brings back a full sentence. Real systems face the same problem at scale, which is why every translation and summarisation decoder has a length penalty.

Industry practice
What's current (2024–2026)
  • Decoder-only won for general LLMs. Most chat models generate from one stack that reads prompt and output together; the encoder-decoder split survives where inputs and outputs are clearly separate: speech recognition (Whisper, NVIDIA Canary), translation (NLLB, MADLAD-400, Marian models in on-device and offline translators) and some summarisation and search models.
  • The training recipe carried over. Teacher forcing is how every LLM is pretrained (predict token t from the true tokens before it), and exposure bias is one motivation for the reinforcement-learning stage after pretraining, which scores whole generated outputs.

Sources: Whisper, NLLB, MADLAD-400, Marian NMT.

When to still reach for RNN-based seq2seq

Almost never, for new projects. Specific exceptions:

  • Streaming translation where you consume input one token at a time with bounded memory.
  • On-device text generation where transformer memory cost is prohibitive.
  • Pedagogy. Understanding the encoder-decoder bottleneck is the fastest path to understanding why transformers won.

Exposure bias and its mitigations

  • Scheduled sampling. Anneal teacher forcing ratio during training so the model learns to recover from its own mistakes.
  • Minimum risk training. Train on sentence-level BLEU score instead of token-level cross-entropy. Closer to what you actually want.
  • Reinforcement learning fine-tuning. Reward the sequence generator with a metric. Used in modern LLM RLHF.

All three still apply to transformer-based generation.

Recap
What to keep from this lesson
  • Seq2seq factorises P(y∣x) token by token: an encoder summarises the source, a decoder generates conditioned on it.
  • Training maximises log-likelihood with teacher forcing; inference reads its own outputs, which creates exposure bias.
  • Decoding is a search: greedy takes local bests, beam search keeps k hypotheses, and a length penalty stops it preferring short outputs.
  • The fixed-size context vector is the bottleneck; attention lets the decoder look at every encoder state instead.
  • The same recipe, minus the separate encoder, is how decoder-only LLMs are trained and decoded.

hard45 minimplement

Greedy decoding picks the best token at each step and can never go back. Beam search keeps the beam_width best partial sequences at each step and picks the best finished one at the end. Translation and summarization models decode with beam search.

Task

Write beam_search(step_fn, bos_id, eos_id, beam_width, max_len, length_penalty=0.0).

A hypothesis is a tuple of token ids and a raw score. The search starts with one alive hypothesis: the tuple (bos_id,) with score 0. The raw score of a hypothesis is the sum of logp(ti​∣t<i​) over its generated tokens.

Repeat at most max_len times:

  1. For each alive hypothesis, call step_fn(tokens) once. It returns the log-probs of the next token, a float array of length V.
  2. Make one candidate for each alive hypothesis and each token id from 0 to V−1. The candidate score is the parent score plus the log-prob of the token.
  3. Sort all candidates by raw score, highest first. For equal scores, the smaller token tuple comes first, in Python tuple order. Keep the first beam_width candidates.
  4. A kept candidate that ends with eos_id is finished. The other kept candidates are the new alive hypotheses.
  5. Stop when no hypothesis is alive.

After the loop, the hypotheses that are still alive are also part of the result. Each hypothesis then gets its final score s/Lα, where s is the raw score, L is the number of generated tokens (BOS does not count, EOS counts) and α is length_penalty. With α=0 the final score is the raw score. The length penalty does not change the pruning in step 3.

Return every finished hypothesis as a list of (tokens, final_score) pairs. Sort the list by final score, highest first. For equal scores, the smaller token tuple comes first. The first pair is the answer of the search.

Input and output

Name Type Shape Meaning
step_fn function tuple of ints to float array (V,) the log-probs of the next token after a prefix
bos_id int scalar the first token of every sequence
eos_id int scalar the token that finishes a sequence, from 0 to V - 1
beam_width int scalar the number of candidates to keep at each step, >= 1
max_len int scalar the largest number of generated tokens, >= 1
length_penalty float scalar the exponent α of the length in the final score
  • Returns a list of (tokens, score) pairs. tokens is a tuple of ints that starts with bos_id. score is a float.

Constraints

  • 2 <= V <= 50 and max_len <= 20.
  • Never call step_fn on a prefix that ends with eos_id.
  • step_fn can return a new array on each call. Do not change the arrays that it returns.
  • Use Python and numpy only.

Common mistakes the checks catch
  • Forgets the alive hypotheses when the loop reaches max_len, so sequences without EOS are lost.
  • Never moves EOS candidates to the finished list, so the search extends sequences past EOS.
  • Counts BOS in the length of the length penalty.
  • Keeps the best beam_width tokens of each beam and never prunes over all candidates.
  • Sorts with reverse=True on (score, tokens), so equal scores put the higher token ids first.
  • Adds the alive hypotheses at max_len with their raw scores, so the length penalty skips them.
Hint 1

Keep two lists: alive and finished. Each item is a pair of a token tuple and a raw score. Start with alive = [((bos_id,), 0.0)].

Hint 2

At each step, build every candidate from every alive hypothesis first. Then sort the whole list once. Do not keep the best tokens of each beam on their own.

Hint 3

The sort key (-score, tokens) puts the highest score first. For equal scores, Python compares the tuples, so the lower token ids come first.

Hint 4

Move a kept candidate that ends with EOS to finished. When the loop ends, add the alive hypotheses to finished. Divide each raw score by (len(tokens) - 1) ** length_penalty only at the end, then sort again with the same key.

Reference solution and notes
import numpy as np


def final_score(tokens, score, length_penalty):
    return score / (len(tokens) - 1) ** length_penalty


def beam_search(step_fn, bos_id, eos_id, beam_width, max_len, length_penalty=0.0):
    alive = [((bos_id,), 0.0)]
    finished = []
    for _ in range(max_len):
        candidates = []
        for tokens, score in alive:
            log_probs = np.asarray(step_fn(tokens), dtype=float)
            for token in range(len(log_probs)):
                candidates.append((tokens + (token,), score + float(log_probs[token])))
        candidates.sort(key=lambda c: (-c[1], c[0]))
        alive = []
        for tokens, score in candidates[:beam_width]:
            if tokens[-1] == eos_id:
                finished.append((tokens, score))
            else:
                alive.append((tokens, score))
        if not alive:
            break
    finished.extend(alive)
    ranked = [(tokens, final_score(tokens, score, length_penalty)) for tokens, score in finished]
    ranked.sort(key=lambda c: (-c[1], c[0]))
    return ranked

Why beam search helps

Greedy decoding commits to the best token at each step. In the toy model, token 1 has the highest first probability, but every token after it is unlikely. Token 2 is a little worse at first, and EOS after it has probability 0.9. Width 2 keeps both paths alive long enough to see this.

What beam search does not promise

Beam search is a heuristic. A beam wide enough to keep every hypothesis is an exhaustive search, but any narrower beam can miss the best sequence. A wider beam often finds a better sequence, but this is not a theorem: a new candidate can push out a hypothesis that a narrower beam keeps and later extends to a better finish.

Length normalization

Each log-prob is 0 or less, so a raw score only goes down as a sequence grows. Without a correction, beam search prefers short outputs. Division by Lα removes part of that bias. Production decoders apply it when they rank finished hypotheses, as this problem does. The seq2seq lesson explains why beam width 3 to 5 is standard for translation.

Solutions

SolutionP1 · The empty output

"EOS" alone, with probability 0.15. Every real sentence multiplies several probabilities below 1: the best full sentence, "a cat sat down EOS", reaches only 0.097. With raw scores, more search makes this worse, not better: greedy never sees the empty output, but exact search finds it. Length normalisation (dividing the log-probability by the number of tokens) brings back "a cat sat down".

SolutionB1 · Learning stalls at the start

At the first step the decoder is untrained, so its predictions are close to random. With a ratio of 0, those random tokens become its next inputs, and the loss at step t asks it to produce the reference token yt​ after a prefix that has nothing to do with y<t​. The gradients are noisy and contradictory, so training is much slower and less stable; long targets suffer most. This is why the recipe starts at 1.0 (always the reference) and lowers the ratio only once the model's own predictions are mostly right.
