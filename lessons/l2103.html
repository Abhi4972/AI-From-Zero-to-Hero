Why this came about

As programs grow, repeating the same lines in many places becomes a source of bugs: fix one copy and forget the others. Functions let you write a piece of logic once, give it a name, and reuse it; modules let you organize functions into files and share them as libraries. Every AI library you will use (NumPylater · 0.14, PyTorchlater · 3.16, LangChainlater · 14.52) is a collection of modules full of functions and classes. And because things do go wrong, Python reports problems with detailed messages; learning to read them turns errors from roadblocks into directions.

In plain words first
A function is a recipe card

A function is a recipe card with a name. It lists what it needs (its parameters: flour, sugar), the steps, and what it hands back at the end (its return value: a cake). You write the card once; anyone can then "call" it with their own ingredients. A module is a recipe book: a file of functions you can bring into any program with import. An error message is the kitchen telling you exactly which step failed and why.

Step 1 · Defining and calling a function

A function is a named piece of code that you can run whenever you need it. def defines one: it has a name, parameters (the inputs, in brackets) and usually a return line that hands back the result. Defining a function runs nothing; calling it by name, with values for the parameters, does. Watch three ways of calling the same function:

def order_total(price, qty, discount=0):
    """Return the amount to pay for qty items at price each, minus a discount."""
    subtotal = price * qty
    return subtotal - discount

print(order_total(499, 2))                  # discount uses its default, 0
print(order_total(499, 2, 100))             # arguments by position
print(order_total(qty=3, price=89, discount=20))   # arguments by name, any order

898
247

The parts of a function definition:

Part In the example What it does
def and a name def order_total Starts a function definition and names it
Parameters (price, qty, discount=0) The inputs. discount=0 has a default, so callers may leave it out
Docstring """Return the amount...""" A description in triple quotes; editors and help(order_total) show it
Body the indented lines Runs each time the function is called
return return subtotal - discount Ends the function and hands one value back to the caller

Defining a function does not run it; calling order_total(...) does. Arguments can be passed by position (in the order of the parameters) or by name (qty=3), and named arguments make calls easy to read. AI libraries use named arguments everywhere, for example model.generate(ids, max_new_tokens=30, do_sample=False) in Lesson 0.2.

A function without return gives back None. A function can return several values as a tuple:

def split_bill(total, people):
    each = round(total / people, 2)
    remainder = round(total - each * people, 2)
    return each, remainder

each, left = split_bill(1000, 3)
print(each, left)
print(print("printing returns nothing"))      # print itself returns None

Step 2 · Variables inside functions are private

A variable created inside a function exists only while that function runs. Code outside cannot see it. This is called scope, and it is a good thing: two functions can both use a variable called total without disturbing each other. The code below proves it by trying to read an inside variable from outside, which fails:

rate = 0.05                     # a "global": defined outside any function

def add_tax(amount):
    tax = amount * rate         # functions can read globals...
    return amount + tax

print(add_tax(100))
try:
    print(tax)                  # ...but variables created inside a function vanish when it returns
except NameError as e:
    print("NameError:", e)
What you should see
105.0
NameError: name 'tax' is not defined

Variables created inside a function are local: they exist only while the function runs. This is a feature: functions cannot accidentally overwrite each other's variables. If a function needs a value, pass it in as a parameter; if the caller needs a result, return it. Functions that only use their parameters and return values are the easiest to test and reuse.

Step 3 · Functions are values too

A function's name refers to a value, just like a variable. You can store functions in dictionaries and pass them to other functions. This idea is everywhere in AI code: you hand a library your function to call later, such as a tool an agent may use (the Agents from first principles section) or a scoring rule for sorting.

orders = [("SK-3", 89), ("SK-1", 540), ("SK-2", 1299)]
print(sorted(orders))                                # sorts by the first item: the ID
print(sorted(orders, key=lambda o: o[1]))            # sort by amount instead
print(max(orders, key=lambda o: o[1]))

def shout(text): return text.upper() + "!"
def whisper(text): return text.lower() + "..."
STYLES = {"shout": shout, "whisper": whisper}         # a dictionary of functions
print(STYLES["shout"]("order shipped"))
What you should see
[('SK-1', 540), ('SK-2', 1299), ('SK-3', 89)]
[('SK-3', 89), ('SK-1', 540), ('SK-2', 1299)]
('SK-2', 1299)
ORDER SHIPPED!

lambda o: o[1] is a tiny unnamed function: "given o, return o[1]". The key= argument tells sorted and max what to compare. The STYLES dictionary is a dispatch table: look up a function by name, then call it. The agent in Lesson 0.2 used exactly this to find and run tools.

Step 4 · Modules and libraries

A module is a .py file of functions and variables. import brings one into your program. Python ships with a large standard library of modules; anything else you install with uv add (or pip install).

import math                       # standard library: always available
from statistics import mean       # import one name from a module
import random

print(math.sqrt(16), math.pi)
print(mean([4, 5, 9]))
random.seed(7)                    # fix the random sequence so the result repeats
print(random.choice(["tea", "rice", "soap"]), random.randint(1, 6))
What you should see
4.0 3.141592653589793
6
rice 2

You make your own module by saving functions in a file. Normally you would create shopkart_utils.py in your editor; here the code writes the file itself, so the example runs anywhere:

from pathlib import Path
Path("shopkart_utils.py").write_text('''
GST_RATE = 0.05

def with_gst(amount):
    """Add GST to an amount."""
    return round(amount * (1 + GST_RATE), 2)
''')

import shopkart_utils
print(shopkart_utils.with_gst(1000), shopkart_utils.GST_RATE)
What you should see
1050.0 0.05
You write What it means When to use it
import math Bring in the module; use names as math.sqrt The default: it is clear where each name came from
from math import sqrt Bring in one name; use it as sqrt When you use one or two names a lot
import numpy as np Bring in the module under a short alias For libraries with conventional aliases: np, pd, plt
from math import * Bring in every name Avoid: you cannot tell where names came from
Tip
Standard library or installed package?

If import something fails with ModuleNotFoundError, the package is not installed in the environment you are running. Standard modules (math, json, random, pathlib, datetime, csv) never need installing. Packages such as numpy, pandas, torch and requests do: uv add numpy in your project folder.

Step 5 · Reading error messages

Errors are normal: professional programmers see dozens a day. When Python cannot continue, it stops and prints a traceback: the chain of calls that led to the problem, ending with what went wrong.

Read it from the bottom up:

  1. The last line names the error type and gives a message: TypeError: unsupported operand type(s) for -: 'str' and 'int'. This is usually all you need.
  2. The line above it shows where: the file, the line number and the code. Go there first.
  3. The lines further up show how the program got there, from the outermost call down. In big programs most of these lines are inside libraries; look for the lowest one that is in your file.

Here the caller passed the text "499" instead of the number 499, so price * qty gave the string "499499", and subtracting a number from a string is impossible. The fix belongs at the caller, not inside order_total.

These ten errors cover most of what beginners meet:

Error Typical cause Example
SyntaxError Python cannot read the line: a missing colon, bracket or quote if x > 3 (no colon)
IndentationError Lines inside a block are not indented consistently a loop body not indented
NameError A name was used before it was defined, or misspelled prnt("hi")
TypeError An operation got the wrong type of value "Total: " + 998
ValueError Right type, unusable value int("forty")
KeyError A dictionary key does not exist order["phone"]
IndexError A list position does not exist cart[10] on a 3-item list

Step 6 · Handling errors with try and except

Some errors are expected: a user types letters where a number belongs, a file is missing, a web service is down. You can catch an error and decide what to do instead of crashing:

def parse_qty(text):
    try:
        qty = int(text)
    except ValueError:
        print(f"'{text}' is not a whole number; using 1")
        return 1
    if qty <= 0:
        raise ValueError(f"quantity must be positive, got {qty}")   # raise your own error
    return qty

print(parse_qty("3"))
print(parse_qty("three"))
try:
    parse_qty("-2")
except ValueError as e:
    print("Rejected:", e)
What you should see
3
'three' is not a whole number; using 1
1
Rejected: quantity must be positive, got -2
Keyword What it does
try: Run these lines and watch for errors
except SomeError: If that kind of error happens, run these lines instead of crashing. as e gives you the error object
else: (optional) Runs only if no error happened
finally: (optional) Runs whatever happened; used for clean-up such as closing a connection
raise Report an error yourself, with a clear message
Watch out
Catch specific errors, not everything

A bare except: (or except Exception:) catches every error, including your own typos, and hides real bugs. Catch the specific errors you expect and know how to handle, and let the rest surface. the Agents from first principles section applies the same rule to agent tools: a failed tool returns a clear error to the model, but a bug in your code should still be visible.

Check your mental model
  • ✗ "Defining a function runs it."
    ✓ def only creates it; the body runs each time you call it.
  • ✗ "print and return do the same thing."
    ✓ print shows a value on screen; return hands it back to the code that called the function, which can keep using it.
  • ✗ "Start reading a traceback at the top."
    ✓ Start at the last line (what went wrong), then the line above (where).
  • ✗ "Wrapping everything in try / except makes code safer."
    ✓ It hides bugs. Catch only the errors you expect and can handle.

Exercises

Predict before you run

What does def f(x): x * 2 followed by print(f(5)) print, and why? (Solution P1.)

Break it on purpose

Run this, read the traceback from the bottom up, and fix it at the right place.

def average(values):
    return sum(values) / len(values)

print(average([]))

(Solution B1.)

Make it your own

Write a function delivery_fee(total, city, express=False) that returns 0 for orders of INR 499 or more, otherwise 40; adds 99 if express is true; and raises a ValueError if total is negative. Call it four ways, including one call with named arguments. (Solution M1.)

Solutions

SolutionP1 · The missing return

It prints None. The function computes x * 2 but never returns it, so the caller gets the default return value, None. Fix: def f(x): return x * 2.

SolutionB1 · Average of nothing

The last line of the traceback is ZeroDivisionError: division by zero, and the line above it points at return sum(values) / len(values): len([]) is 0. The real question is what the average of no values should be. Either return a value that makes sense (return 0.0 if not values else ...) or raise a clear error (raise ValueError("cannot average an empty list")). Choosing deliberately is better than letting Python crash with a confusing message.

SolutionM1 · Delivery fee
def delivery_fee(total, city, express=False):
    """Delivery charge in INR for an order total in INR."""
    if total < 0:
        raise ValueError(f"total cannot be negative: {total}")
    fee = 0 if total >= 499 else 40
    if express:
        fee += 99
    return fee

print(delivery_fee(600, "Pune"), delivery_fee(300, "Goa"),
      delivery_fee(300, "Goa", True), delivery_fee(total=800, city="Delhi", express=True))
# 0 40 139 99

city is unused here; a later version might charge more for remote pin codes. Keeping it in the signature now means callers will not need changing then.

Recap
  • def name(params): defines a function; calling it runs the body; return hands back a value (or None).
  • Defaults and named arguments make calls flexible and readable; variables inside functions are local.
  • Functions are values: pass them to sorted(key=...) or store them in a dispatch table.
  • Modules are files of code; the standard library is built in, other packages are installed per project.
  • Read tracebacks from the bottom; catch only the errors you expect; raise your own with clear messages.
