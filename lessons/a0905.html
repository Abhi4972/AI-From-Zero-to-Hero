In plain words first
The idea in one line

2013: Mnih trained one Q-learning network on raw pixels, beat every classical RL agent on seven Atari games. 2015: extended to 49 games, published in Nature, sparked the deep-RL era. DQN is Q-learning plus three tricks that make function approximation stable.

Terms you'll hear
Term What people say What it actually means
DQN "Deep Q-learning" Q-learning with a neural Q-function, replay buffer, and target network.
Experience replay "Shuffled transitions" Ring buffer sampled uniformly each gradient step; decorrelates data.
Target network "Frozen bootstrap" Periodic copy of Q used in the Bellman target; stabilizes training.
Deadly triad "Why RL diverges" Function approximation + bootstrapping + off-policy = no convergence guarantee.
Double DQN "Fix for maximization bias" Online net selects action, target net evaluates it.
Dueling DQN "V and A heads" Decompose Q = V + A - mean(A); same output, better gradient flow.
Rainbow "All the tricks" DDQN + PER + dueling + n-step + noisy + distributional in one.
PER "Prioritized Replay" Sample transitions proportional to TD-error magnitude.

The problem

In plain words first

A Q-table needs one entry for every situation, which is hopeless when the situation is a video-game screen. Deep Q-learning (DQN) replaces the table with a neural network that takes the screen as input and outputs one value per action, trained with the same Q-learning target as Lesson 9.4. Done naively this falls apart: consecutive screens are almost identical, and the target the network chases moves every time the network changes. DQN's fixes are a memory of past experiences sampled at random (replay), and a frozen copy of the network used to compute targets (the target network). This lesson checks numerically why each fix is needed, and why one of them is not enough on its own, then plays a full game of Pong on this page's CPU with a DQN agent trained and published by the Stable-Baselines3 team, watching its Q-values as it plays. Nothing is trained here.

Tabular Q-learning needs a separate Q-value for every (state, action) pair. A chess board has ~10⁴³ states. An Atari frame is 210×160×3 = 100,800 features. Tabular RL dies at thousands of states, let alone billions.

The fix is obvious in hindsight: replace the Q-table with a neural network, Q(s,a;θ). But obvious-in-hindsight took decades. Naive function approximation with Q-learning diverges under the "deadly triad" — function approximation + bootstrapping + off-policy learning. Mnih et al. (2013, 2015) identified three engineering tricks that stabilize learning:

  1. Experience replay decorrelates transitions.
  2. Target network freezes the bootstrap target.
  3. Reward clipping normalizes gradient magnitudes.

DQN on Atari was the first time a single architecture with a single hyperparameter set solved dozens of control problems from raw pixels. Everything "deep-RL" built since — DDQN, Rainbow, Dueling, Distributional, R2D2, Agent57 — is stacked on top of this three-trick base.

The idea

The objective. DQN minimizes the one-step TD loss on a neural Q-function:

L(θ)=E(s,a,r,s′)∼D​[(r+γa′max​Q(s′,a′;θ−)−Q(s,a;θ))2]

θ = online network, updated every step by gradient descent. θ− = target network, periodically copied from θ (every ~10,000 steps). D = replay buffer of past transitions.

The three tricks, in order of importance:

Experience replay. A ring buffer of ~10⁶ transitions. Each training step samples a minibatch uniformly at random. This breaks temporal correlation (successive frames are nearly identical), lets the network learn from rare rewarding transitions many times, and decorrelates consecutive gradient updates. Without it, on-policy TD with a neural net diverges on Atari.

Target network. Using the same network Q(⋅;θ) on both sides of the Bellman equation makes the target move every update — "chasing your own tail." The fix: keep a second network Q(⋅;θ−) with frozen weights. Every C steps, copy θ→θ−. This stabilizes the regression target for thousands of gradient steps at a time. Soft updates θ−←τθ+(1−τ)θ− (used in DDPG, SAC) are a smoother variant.

Reward clipping. Atari reward magnitudes vary from 1 to 1000+. Clipping to {−1,0,+1} stops any single game from dominating the gradient. Wrong when reward magnitude matters; fine for Atari where only sign matters.

Double DQN. Hasselt (2016) fixes maximization bias: use the online net to select the action, the target net to evaluate it.

target=r+γQ(s′,arga′max​Q(s′,a′;θ);θ−)

Drop-in replacement, consistently better. Use it by default.

Other improvements (Rainbow, 2017): prioritized replay (sample high-TD-error transitions more), dueling architecture (separate V(s) and advantage heads), noisy networks (learned exploration), n-step returns, distributional Q (C51/QR-DQN), multi-step bootstrapping. Each adds a few percent; the gains are roughly additive.

The same idea as a formula

Loss. With online parameters θ, target parameters θ− and transitions drawn uniformly from the replay buffer D:

L(θ)=E(s,a,r,s′)∼D​[(r+γ(1−d)a′max​Q(s′,a′;θ−)−Q(s,a;θ))2]

with d=1 at a true episode end. In practice the Huber loss replaces the square to limit the gradient from large errors.

Gradient (semi-gradient: the target is treated as a constant):

∇θ​L=−2E[(y−Q(s,a;θ))∇θ​Q(s,a;θ)]

Double DQN target: y=r+γQ(s′,argmaxa′​Q(s′,a′;θ);θ−), choose with the online network, evaluate with the target network.

Dueling heads: Q(s,a)=V(s)+A(s,a)−∣A∣1​∑a′​A(s,a′), useful when many actions have nearly equal values.

The deadly triad. Function approximation + bootstrapping + off-policy data can make the updates diverge: the update is not the gradient of any fixed objective, and the data distribution need not match the states whose values the bootstrap uses. Replay and target networks reduce, but do not remove, this risk.

What Q means. With reward 1 per point and γ=0.99, a point expected k decisions away is worth 0.99k: 0.61 at 50 steps, 0.37 at 100.

Worked example
DQN's numbers by hand

One target. r=0, γ=0.99, target network's Q(s′,⋅)=(1.20,1.25,1.10): y=0+0.99×1.25=1.2375. If the online network says Q(s,a)=1.30, the TD error is −0.0625 and the update lowers Q(s,a).

Atari DQN's budget (Mnih et al., 2015). 50 million agent steps (200 million frames with a frame skip of 4); replay buffer of 1 million transitions; learning starts after 50,000; a minibatch of 32 every 4 steps, so about 12.5 million gradient updates; target network copied every 10,000 updates.

The Nature network. Input 4×84×84; convolutions of 32 (8×8, stride 4), 64 (4×4, stride 2), 64 (3×3, stride 1) channels; a 512-unit layer; one output per action. Parameters: about 1.69 million for Pong's 6 actions (the run under "Use it").

Overestimation by hand. Six actions, all truly worth 0, each estimate off by noise of standard deviation 0.5: the expected maximum of six standard normals is about 1.27, so maxQ^​≈0.63.

Check your mental model
  • ✗ "A target network is what makes DQN converge."
    ✓ It slows the feedback loop; with badly mismatched off-policy data the values can still blow up, only per sync instead of per step (the run after Step 4).
  • ✗ "Replay is just for data efficiency."
    ✓ It also breaks the strong correlation between consecutive states, which gradient descent assumes away.
  • ✗ "Q-values are probabilities of winning."
    ✓ They are expected discounted sums of clipped rewards; in Pong they rise as the next point approaches and fall right after it.

Step 1 · replay buffer

The code here is stdlib-only numpy-free — we use a hand-rolled single-hidden-layer MLP on a tiny continuous GridWorld, so every training step runs in microseconds. The algorithm is identical to Atari DQN at scale.

class ReplayBuffer:
    def __init__(self, capacity):
        self.buf = []
        self.capacity = capacity
    def push(self, s, a, r, s_next, done):
        if len(self.buf) == self.capacity:
            self.buf.pop(0)
        self.buf.append((s, a, r, s_next, done))
    def sample(self, batch, rng):
        return rng.sample(self.buf, batch)

~10⁶ capacity for Atari, as in the original DQN (it collects 50,000 transitions before learning starts); 5,000 suffices for our toy env.

Step 2 · a tiny Q-network (manual MLP)

class QNet:
    def __init__(self, n_in, n_hidden, n_actions, rng):
        self.W1 = [[rng.gauss(0, 0.3) for _ in range(n_in)] for _ in range(n_hidden)]
        self.b1 = [0.0] * n_hidden
        self.W2 = [[rng.gauss(0, 0.3) for _ in range(n_hidden)] for _ in range(n_actions)]
        self.b2 = [0.0] * n_actions
    def forward(self, x):
        h = [max(0.0, sum(w * xi for w, xi in zip(row, x)) + b) for row, b in zip(self.W1, self.b1)]
        q = [sum(w * hi for w, hi in zip(row, h)) + b for row, b in zip(self.W2, self.b2)]
        return q, h

Forward pass: linear → ReLU → linear. That is the entire net.

Step 3 · the DQN update

def train_step(online, target, batch, gamma, lr):
    grads = zeros_like(online)
    for s, a, r, s_next, done in batch:
        q, h = online.forward(s)
        if done:
            y = r
        else:
            q_next, _ = target.forward(s_next)
            y = r + gamma * max(q_next)
        td_error = q[a] - y
        accumulate_grads(grads, online, s, h, a, td_error)
    apply_sgd(online, grads, lr / len(batch))

The shape is Q-learning from Lesson 9.4 with two differences: (a) we backprop through a differentiable Q(⋅;θ) instead of indexing a table, (b) the target uses Q(⋅;θ−).

Step 4 · the outer loop

For each episode, act ε-greedy on Q(⋅;θ), push transitions into the buffer, sample a minibatch, take a gradient step, periodically sync θ−←θ. The pattern:

for episode in range(N):
    s = env.reset()
    while not done:
        a = epsilon_greedy(online, s, epsilon)
        s_next, r, done = env.step(s, a)
        buffer.push(s, a, r, s_next, done)
        if len(buffer) >= batch:
            train_step(online, target, buffer.sample(batch), gamma, lr)
        if steps % sync_every == 0:
            target = copy(online)
        s = s_next

On our tiny GridWorld with a 16-dim one-hot state, the agent learns a near-optimal policy in ~500 episodes. On Atari, scale this to 200M frames and add a CNN feature extractor.

Why each trick exists

No network is trained; three small computations. Correlation between consecutive CartPole states, against a shuffled replay sample. The classic two-state example of divergence (features 1 and 2, reward 0, only the first transition in the data), with plain TD, with a target network, and with the data the policy would actually produce. And the bias of the max in DQN's target against Double DQN's.

import numpy as np, gymnasium as gym

# 1. Why replay: consecutive transitions are nearly identical; a random minibatch from a buffer is not.
env = gym.make("CartPole-v1"); rng = np.random.default_rng(0); states = []
for ep in range(200):
    o, _ = env.reset(seed=ep); done = False
    while not done:
        states.append(o); o, r, te, tr, _ = env.step(int(rng.integers(2))); done = te or tr
S = np.array(states)
lag1 = np.mean([np.corrcoef(S[:-1, k], S[1:, k])[0, 1] for k in range(4)])
idx = rng.permutation(len(S)); shuffled = S[idx]
rand = np.mean([np.corrcoef(shuffled[:-1, k], shuffled[1:, k])[0, 1] for k in range(4)])
print(f"CartPole, {len(S):,} transitions from a random policy: correlation of each state with the next one "
      f"{lag1:.3f}; between neighbours in a shuffled replay sample {rand:+.3f}")

# 2. Why a target network is not magic: the classic two-state example with features x(s1) = 1, x(s2) = 2, V = w * x,
#    reward 0, and updates made only on the transition s1 -> s2 (off-policy data). True value: w = 0.
gamma, alpha = 0.9, 0.1
w = 1.0
for _ in range(100): w += alpha * (gamma * 2 * w - w) * 1           # semi-gradient TD on s1 -> s2
print(f"\nsemi-gradient TD, 100 updates: w = {w:.3g} (each update multiplies w by 1 + alpha(2 gamma - 1) = {1 + alpha * (2 * gamma - 1):.2f})")
w, w_target = 1.0, 1.0
for sync in range(10):
    for _ in range(100): w += alpha * (gamma * 2 * w_target - w)     # regress toward the frozen target
    w_target = w
print(f"with a target network synced every 100 updates, after 10 syncs: w = {w:.3g} (x{2 * gamma:.1f} per sync)")
w = 1.0
for _ in range(100):                                                 # on-policy data: s2 is updated too (s2 -> end, reward 0)
    w += alpha * (gamma * 2 * w - w) * 1; w += alpha * (0 - 2 * w) * 2
print(f"same updates plus the s2 -> end transition the policy also visits: w = {w:.2e} (converges to 0)")

# 3. Why Double DQN: the max over noisy estimates is biased upward; choosing with one estimate and scoring with another is not.
true_q = np.zeros(6); noise = 0.5
Q1 = true_q + rng.normal(0, noise, (100_000, 6)); Q2 = true_q + rng.normal(0, noise, (100_000, 6))
single = Q1.max(1).mean(); double = Q2[np.arange(len(Q1)), Q1.argmax(1)].mean()
print(f"\n6 actions all truly worth 0, estimates with noise 0.5: DQN target max Q = {single:+.3f}, Double-DQN target {double:+.3f}")

Reading this output

Consecutive CartPole states correlate at 0.87; neighbours in a shuffled replay sample at 0.01. Gradient descent assumes roughly independent samples, and replay provides them. The two-state example shows the deadly triad in its simplest form: with features 1 and 2 and updates only on the transition from the first state to the second, semi-gradient TD multiplies w by 1.08 per update and reaches 2,200 after 100 updates, although the true value is 0. A target network slows this to a factor of 2γ=1.8 per sync, still diverging (357 after 10 syncs). What fixes it is the data: if the second state's own transition (to the end, reward 0) is also updated, as it would be under the policy that visits it, w collapses to 0. Finally, the max in DQN's target overestimates six equal actions by +0.64 under noise of 0.5, while Double DQN's choose-with-one, evaluate-with-the-other target is unbiased (+0.001).

Pitfalls

  • Deadly triad. Function approximation + off-policy + bootstrapping can diverge. DQN mitigates with target net + replay; do not remove either.
  • Exploration. ε must decay, typically from 1.0 to 0.01 over the first ~10% of training. Without enough early exploration the Q-net converges to a local basin.
  • Overestimation. max over noisy Q is upward-biased. Always use Double DQN in production.
  • Reward scale. Clip or normalize rewards; the gradient magnitude is proportional to reward magnitude.
  • Replay buffer coldstart. Don't train until the buffer has a few thousand transitions. Early gradients on ~20 samples overfit.
  • Target sync frequency. Too frequent ≈ no target net; too infrequent ≈ stale targets. Atari DQN uses 10,000 env steps. Rule of thumb: sync every ~1/100 of training horizon.
  • Observation preprocessing. Atari DQN stacks 4 frames to make state Markov. Any env with velocity info needs frame-stacking or recurrent state.

Use it: the same idea with real libraries

In 2026, DQN is rarely state-of-the-art but remains the reference off-policy algorithm:

Task Method of choice Why not DQN?
Discrete-action Atari-like Rainbow DQN or Muesli Same framework, more tricks.
Continuous control SAC / TD3 (Phase 9 · 07) DQN has no policy network.
On-policy / high-throughput PPO (Phase 9 · 08) No replay buffer; easier to scale.
Offline RL CQL / IQL / Decision Transformer Conservative Q targets, no bootstrapping blowups.
Large discrete action spaces (recommender) DQN with action embedding, or IMPALA Fine; decoration matters.
LLM RL PPO / GRPO Sequence-level, not step-level; different loss.

The lessons still travel. Replay and target networks appear in SAC, TD3, DDPG, SAC-X, AlphaZero's self-play buffer, and every offline RL method. Reward clipping lives on as advantage normalization in PPO. The architecture is the blueprint.

import time, numpy as np, torch, gymnasium as gym, ale_py, matplotlib.pyplot as plt
from huggingface_hub import hf_hub_download
from stable_baselines3 import DQN
from stable_baselines3.common.env_util import make_atari_env
from stable_baselines3.common.vec_env import VecFrameStack, VecTransposeImage

gym.register_envs(ale_py); torch.set_num_threads(2)
# The RL Baselines3 Zoo's DQN for Pong: 84 x 84 grey frames, 4 stacked, Nature-DQN convolutional network.
env = VecTransposeImage(VecFrameStack(make_atari_env("PongNoFrameskip-v4", n_envs=1, seed=0), n_stack=4))
model = DQN.load(hf_hub_download("sb3/dqn-PongNoFrameskip-v4", "dqn-PongNoFrameskip-v4.zip"), device="cpu", buffer_size=1,
                 custom_objects={"learning_rate": 0.0, "lr_schedule": lambda _: 0.0, "exploration_schedule": lambda _: 0.0,
                                 "optimize_memory_usage": False,
                                 "observation_space": env.observation_space, "action_space": env.action_space})
q_net = model.policy.q_net
names = env.envs[0].unwrapped.get_action_meanings()
print(f"Q-network: {sum(p.numel() for p in q_net.parameters()):,} parameters; input {env.observation_space.shape} "
      f"(4 stacked frames); one Q-value per action: {names}")

obs = env.reset(); qmax, rewards, snaps = [], [], []
t0 = time.perf_counter()
while True:
    with torch.no_grad():
        q = q_net(torch.as_tensor(obs).float())[0].numpy()              # Q(s, .) for the current state
    qmax.append(q.max())
    if len(qmax) in (100, 400, 700): snaps.append((len(qmax), obs[0, -1].copy(), q.copy()))
    obs, r, done, _ = env.step(np.array([q.argmax()]))                 # act greedily (no exploration)
    rewards.append(r[0])
    if done[0]: break
rewards = np.array(rewards)
print(f"one full game, greedy: {int((rewards > 0).sum())} points won, {int((rewards < 0).sum())} lost, "
      f"{len(rewards):,} decisions (each repeated for 4 frames), {time.perf_counter() - t0:.1f} s on this CPU")
print(f"max-Q over the game: mean {np.mean(qmax):.2f}, range {np.min(qmax):.2f} to {np.max(qmax):.2f} "
      f"(rewards are +1 per point won, gamma = 0.99)")
for step, _, q in snaps:
    print(f"  decision {step}: " + "  ".join(f"{n} {v:+.2f}" for n, v in zip(names, q)))

fig = plt.figure(figsize=(9, 3.6)); gs = fig.add_gridspec(1, 4, width_ratios=[2.6, 1, 1, 1])
ax = fig.add_subplot(gs[0]); ax.plot(qmax, lw=0.8, color="#2b6cb0")
for i in np.flatnonzero(rewards > 0): ax.axvline(i, color="#38a169", lw=0.6, alpha=0.6)
ax.set_xlabel("decision", fontsize=8); ax.set_ylabel("max Q(s, a)", fontsize=8); ax.set_title("max Q; green = point won", fontsize=8)
ax.tick_params(labelsize=7)
for k, (step, frame, q) in enumerate(snaps):
    a = fig.add_subplot(gs[k + 1]); a.imshow(frame, cmap="gray"); a.axis("off")
    a.set_title(f"decision {step}: {names[int(q.argmax())]}", fontsize=8)
plt.tight_layout(); plt.savefig("v2.png", dpi=60); plt.show()

The network has 1.69 million parameters and sees four stacked 84×84 frames, so it can tell which way the ball is moving. Playing greedily it wins the game 21–0, in 1,626 decisions and a few seconds of CPU time: inference is cheap, the training was not (millions of steps on a GPU). The max-Q trace is a sawtooth: within each rally it climbs toward about 2 as the next point approaches, then drops right after the point (green lines) because the next reward is again far away, exactly γk discounting at work. Toward the end of the game the peaks fall to about 0.5: with few points left before the game ends, there is less future reward to expect, so the network has learned that the game is finite. The three snapshots show another lesson: all six actions have almost the same value (1.38 for each at decision 100). In most states the choice barely matters, which is the motivation for dueling networks that learn V(s) separately from small advantages.

Break it on purpose

In train_step, compute the target with the online network, q_next, _ = online.forward(s_next), and copy nothing to a target network. On the toy grid it may still learn. On Atari-scale problems, what feedback loop does this create, and what do the Q-values typically do? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Value-based deep RL lives on in libraries and benchmarks. Stable-Baselines3 and the RL Baselines3 Zoo, CleanRL, Dopamine and DeepMind's Acme ship DQN, Double/Dueling DQN, QR-DQN and Rainbow, with published Atari checkpoints such as the one run here.
  • Sample-efficient successors. BBF and other "Atari 100k" agents, and MuZero-style planners, push data efficiency far beyond DQN; PPO (Lesson 9.8) is the usual default when environment steps are cheap.
  • Replay and target networks everywhere. SAC and TD3 for continuous control, offline RL (CQL, IQL) and many robotics stacks keep DQN's two stabilisers.

Sources: Stable-Baselines3, RL Baselines3 Zoo, CleanRL, Mnih et al. 2015, BBF.

Recap
What to keep from this lesson
  • DQN = Q-learning's target with a neural network, trained by regression on replayed transitions.
  • Replay decorrelates data; the target network freezes the regression target between syncs.
  • Neither removes the deadly triad; on-policy-like data coverage matters.
  • Use Double DQN targets: choose with the online net, evaluate with the target net.
  • Q-values are discounted expected rewards; reading them explains what the agent anticipates.

  3. Hard. Add Double DQN: use the online net to pick argmax a', target net to evaluate. Compare bias of Q(s_0, best_a) vs true V∗(s0​) after 1,000 episodes with vs without Double DQN on a noisy-reward GridWorld.

Solutions

SolutionP1 · A sawtooth

A sawtooth: max Q rises during each rally toward about 2.0 and falls back to about 1.1 right after each point the agent wins, 21 teeth in all, and the peaks shrink at the end of the game. With γ=0.99 a point k decisions away is worth 0.99k, so the value climbs as the next point gets closer; the total includes later points too, discounted further, which is why it exceeds 1. Just after a point, the next one is a whole rally away, so the value drops. Near the end few points remain, and the expected future reward shrinks. The network learned all of this from reward signals alone.

SolutionB1 · Chasing its own tail

Every gradient step that raises Q(s,a) also tends to raise Q(s′,⋅), because neighbouring states share network weights, and with the online network in the target that immediately raises the target y that Q(s,a) is chasing. Errors feed back into their own targets within the same update cycle, and combined with the upward bias of the max, the values typically drift upward without bound or oscillate, the "divergence" curves in the DQN paper's ablations. The target network breaks the immediate loop: for thousands of steps the regression target is fixed, so the network solves an ordinary regression problem before the target moves. It is not a cure (the run after Step 4 shows growth per sync), but it turns a fast instability into a slow, usually manageable one.
