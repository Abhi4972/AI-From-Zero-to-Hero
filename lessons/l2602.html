Why this came about

A language model generates text left to right, so during training each position must predict its next token without seeing it. RNNs got this for free by reading in order. Transformerslater · 7.8 see the whole sequence at once, so the 2017 paper added a mask that hides future positions inside attention. The same paper split attention into several heads, because one weighted average can only follow one relationship at a time, while language has many at once: grammar, reference, topic. The price of letting every token look at every other token is a cost that grows with the square of the length, which is why "context length" became one of the most discussed numbers in AI, and why so much engineering since 2020 has gone into making attention cheaper.

In plain words first
No peeking, and several pairs of eyes

Imagine a quiz in which you see a sentence one word at a time and must guess the next word. If the whole sentence were printed on the page, you could just read the answer; so the later words are covered up. That cover is the causal mask. And instead of one reader looking for one kind of clue, picture twelve readers each watching for something different: one tracks the previous word, one tracks who is doing what, one tracks what "it" refers to. Their notes are combined at the end. Those readers are the heads.

Step 1 · The causal mask

Before softmax, the scores for future positions are replaced by minus infinity. Since e^(−∞) = 0, those positions get exactly zero weight:

import math
import torch
import torch.nn.functional as F

torch.manual_seed(0)
n = 5
scores = torch.randn(n, n)                                       # stand-in scores for 5 tokens

mask = torch.triu(torch.ones(n, n, dtype=torch.bool), diagonal=1)   # True above the diagonal = the future
print(mask.int())
masked = scores.masked_fill(mask, float("-inf"))
weights = F.softmax(masked, dim=-1)
print(weights.round(decimals=2))
print("each row still adds up to 1:", torch.allclose(weights.sum(dim=-1), torch.ones(n)))

Reading this output
  • torch.triu(..., diagonal=1) ("upper triangle") marks every position to the right of the diagonal: the future.
  • masked_fill replaces those scores with −∞; after softmax they are exactly 0. Row 1 can only attend to itself, so its weight is 1.0. Row 5 can attend to all five tokens.
  • This is what makes training efficient: a single forward pass over a sequence of 1,000 tokens produces 1,000 next-token predictions, each made without seeing its answer. An RNN needs 1,000 sequential steps for the same work (Lesson 5.13).

Models that use this mask are called decoder-onlylater · 7.13 or causal language models: GPT, Llama, Claude, Gemini and almost every chat model. Models without it, where every token sees the whole text in both directions, are encoders, such as BERTlater · 7.13 (Lesson 7.13).

Step 2 · Many heads

One attention operation produces one weighted average per token. Multi-head attention runs several in parallel. With a model width of 768 and 12 heads, each head works with queries, keys and values of 64 numbers; the 12 outputs are joined back to 768 numbers and mixed by a final matrix W_O. The total compute is about the same as one big head, but each head can learn a different pattern, as you saw in the GPT-2 viewer in Lesson 7.3.

Here is a complete causal multi-head self-attention layer, in the style of GPT-2 and Andrej Karpathy's nanoGPTlater · 7.22:

from torch import nn

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model=768, n_heads=12):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads, self.d_head = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)     # W_Q, W_K and W_V in one matrix
        self.proj = nn.Linear(d_model, d_model)        # W_O, mixes the heads back together

    def forward(self, x):                              # x: (batch, tokens, d_model)
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=-1)         # each (B, T, C)
        # split C into n_heads pieces and move heads next to batch: (B, n_heads, T, d_head)
        q = q.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        k = k.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        v = v.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d_head)       # (B, n_heads, T, T)
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=1)
        weights = F.softmax(scores.masked_fill(mask, float("-inf")), dim=-1)
        out = weights @ v                                              # (B, n_heads, T, d_head)
        out = out.transpose(1, 2).contiguous().view(B, T, C)           # join the heads: (B, T, C)
        return self.proj(out)

torch.manual_seed(0)
attn = CausalSelfAttention()
x = torch.randn(2, 10, 768)                            # 2 sequences of 10 tokens
y = attn(x)
print("in:", tuple(x.shape), " out:", tuple(y.shape))
print("parameters:", sum(p.numel() for p in attn.parameters()))

Reading this output
Reading this code
  • nn.Linear(d_model, 3 * d_model) computes queries, keys and values for all heads in one matrix multiplication, then split cuts the result into three. This is faster than three separate layers and gives the same result.
  • view(B, T, n_heads, d_head) reinterprets each 768-number vector as 12 pieces of 64; transpose(1, 2) moves the head dimension forward so each head becomes like a separate batch. The @ then runs all 12 heads at once.
  • contiguous().view(B, T, C) undoes that: the 12 head outputs are laid side by side into 768 numbers again.
  • The layer has 2,362,368 parameters: 768 × 2,304 + 2,304 for qkv and 768 × 768 + 768 for proj, about 4 × d_model². GPT-2 small has 12 of these layers.

A quick check that the hand-written layer is right: PyTorch's fused attention function with is_causal=True should give the same result from the same queries, keys and values.

with torch.no_grad():
    B, T, C = x.shape
    q, k, v = attn.qkv(x).split(C, dim=-1)
    q, k, v = [t.view(B, T, 12, 64).transpose(1, 2) for t in (q, k, v)]
    fused = F.scaled_dot_product_attention(q, k, v, is_causal=True)
    fused = attn.proj(fused.transpose(1, 2).contiguous().view(B, T, C))
    print("matches the built-in:", torch.allclose(fused, attn(x), atol=1e-5))

Step 3 · What a long context costs

Every token attends to every earlier token, so the score matrix has about n² entries per head per layer. Double the context and that part of the work quadruples:

def attention_cost(n, d_model=4096, n_layers=32, n_heads=32):
    """Rough cost of the attention scores for one sequence of n tokens, in a Llama-2-7B-sized model."""
    score_entries = n * n * n_heads * n_layers                 # one number per pair of tokens, per head and layer
    flops = 4 * n * n * d_model * n_layers                     # QK^T and weights @ V, 2 FLOPs per multiply-add
    return score_entries, flops

print(f"{'tokens':>9} {'score entries':>15} {'attention FLOPs':>16} {'if stored in bf16':>18}")
for n in [1_000, 8_000, 32_000, 128_000, 1_000_000]:
    entries, flops = attention_cost(n)
    print(f"{n:>9,} {entries:>15.2e} {flops:>16.2e} {entries * 2 / 1e9:>15,.0f} GB")

Reading this output
  • At 1,000 tokens, storing every score for every head and layer would take about 2 GB, which a GPU can hold. At 128,000 tokens it would be about 34,000 GB (34 terabytes), and at a million tokens about 2 petabytes, roughly 60 times more again. No GPU could hold that: a large one has about 80 to 200 GB of memory.
  • Models with million-token contexts exist, so they must avoid storing the matrix. FlashAttention (2022) computes exactly the same attention in small tiles, never writing the full matrix to memory; memory then grows only with n, though compute still grows with n².
  • The compute column still grows with n². For long documents, reading the whole context costs much more than the rest of the model, which is one reason long prompts cost more and respond slower (Lessons 10.3 and 11.21), and one reason retrieval (the Retrieval (RAG) section) remains useful even with huge context windowslater · 10.3.

The main ways engineers reduce the cost, all covered further in Lesson 7.17:

Technique What it changes
FlashAttention the same exact result, computed in tiles so the n × n matrix is never stored
Grouped-query attention (GQA) several query heads share one key/value head, shrinking the KV cachelater · 7.19 that generation keeps (Lesson 7.19)
Sliding-window attention each token attends only to the last few thousand tokens in some layers
Sparse or linear attention, state-space modelslater · 7.17 approximations or alternatives that grow more slowly than n²
The same idea as a formula
  • causal mask: Sᵢⱼ = −∞ for j > i, so Aᵢⱼ = 0 for every future position
  • head h: headₕ = softmax(Q_h K_hᵀ / √d_head + mask) V_h, with d_head = d_model / n_heads
  • multi-head output: concat(head₁, …, head_H) W_O
  • parameters: 3·d_model² + d_model² weights (plus biases) ≈ 4 d_model²
  • attention cost per layer: about 4n²·d_model FLOPs and n²·n_heads score entries
Check your mental model
  • ✗ "The causal mask is only used when generating text."
    ✓ It matters most in training, where every position predicts its own next token in a single pass and must not see the answer.
  • ✗ "Twelve heads cost twelve times as much as one."
    ✓ The model width is split between the heads, so the total work is about the same as one head of full width.
  • ✗ "A model with a 1-million-token context processes that context as cheaply as a short one."
    ✓ The attention part grows with the square of the length; long contexts cost real compute and time.

Practice
Apply it

Using attention_cost, by what factor does attention compute grow when the context goes from 8,000 to 32,000 tokens? And the rest of the model (which grows linearly with tokens)? (Solution X1.)

Solutions

SolutionP1 · Masking the diagonal too

With diagonal=0 the diagonal is masked as well, so the first token cannot attend to anything: its whole row is −∞, and softmax of all −∞ gives nan (0 divided by 0). The other rows can no longer attend to themselves. Every token must be allowed to see at least itself; that is why the mask starts one place above the diagonal.

SolutionM1 · A small layer

4 × 64² + 4 × 64 = 16,384 + 256 = 16,640. The qkv layer has 64 × 192 + 192 = 12,480 and proj 64 × 64 + 64 = 4,160, which add up to the same 16,640. The number of heads does not change the count: heads split the width, they do not add weights.

SolutionX1 · Four times the context

Attention compute grows by (32,000 / 8,000)² = 16 times. The rest of the model (embedding, feed-forward layers, the q, k and v projections) grows 4 times, in proportion to the number of tokens. As contexts get longer, attention becomes a larger share of the total cost.

Recap
  • The causal mask sets scores for future tokens to −∞, so each token sees only itself and earlier tokens; this lets training predict every position in one pass.
  • Multi-head attention splits the model width into several heads, each with its own queries, keys and values, then joins and mixes their outputs with W_O.
  • An attention layer has about 4·d_model² parameters, whatever the number of heads.
  • Attention's compute grows with the square of the context length; storing the full score matrix becomes impossible at long contexts.
  • FlashAttention avoids storing the matrix; grouped-query attention, sliding windows and other designs reduce cost further.
