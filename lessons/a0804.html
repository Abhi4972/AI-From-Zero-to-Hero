In plain words first
The idea in one line

The first big unlock of 2014-2017 was controlling what a GAN makes. Attach a label, or an image, or a sentence. Pix2Pix did the image version, and its recipe is still a strong, fast baseline for narrow image-to-image tasks with paired data.

Terms you'll hear
Term What people say What it actually means
Conditional GAN "GAN with labels" G(z, c), D(x, c). Both networks see the condition.
Pix2Pix "Image-to-image GAN" Paired cGAN with U-Net G and PatchGAN D + L1 loss.
U-Net "Encoder-decoder with skips" Symmetric conv network; skips preserve high-freq.
PatchGAN "Local-realism classifier" D outputs per-patch score instead of global score.
CycleGAN "Unpaired image translation" Two G's + cycle-consistency loss; no paired data.
SPADE "GauGAN" Normalizes intermediate activations with the semantic map; segmentation-to-image.
FiLM "Feature-wise linear modulation" Per-feature affine transform from the condition; cheap conditioning.

The problem

In plain words first

A conditional GAN is a GAN that takes instructions: besides random noise, both networks receive a condition, such as a class label or a whole input image. The generator must produce an output that fits the condition, and the discriminator judges the pair, "is this a plausible output for this input?". Pix2Pix applies this to image-to-image tasks with paired examples: sketch to photo, map to aerial view, black-and-white to colour. Its two tricks are an extra pixel-matching loss (L1) that keeps the output faithful to the target, and a discriminator that judges small patches rather than the whole image. This lesson shows numerically why the pixel loss alone gives blurry results, builds Pix2Pix's patch discriminator to measure exactly what it sees, and then runs Real-ESRGAN, an image-to-image GAN that upscales photos and is shipped in today's image tools. Nothing is trained.

An unconditional GAN samples arbitrary faces. Useful for a demo, useless in production. You want: map a sketch to a photo, map a map to an aerial photo, map a daytime scene to nighttime, colorize a grayscale image. In all of these, you are given an input image x and must output y with some semantic correspondence. There are many plausible y's per x. Mean-squared error flattens them into mush. An adversarial loss doesn't, because "looks real" is sharp.

Conditional GAN (Mirza & Osindero, 2014) adds a condition c as an input to both G and D. Pix2Pix (Isola et al., 2017) specialized this: condition is a full input image, generator is a U-Net, discriminator is a patch-based classifier (PatchGAN), and loss is adversarial + L1. That recipe is still hard to beat on narrow image-to-image tasks with plenty of paired examples, because it is trained on paired data: you have exactly the signal you need.

The idea

Conditional G. G(x,z)→y. In Pix2Pix, z is dropout inside G (no input noise — Isola found explicit noise got ignored).

Conditional D. D(x,y)→[0,1]. Input is the pair (condition, output). This is the key difference: D must judge whether y is consistent with x, not just whether y looks real.

U-Net generator. Encoder-decoder with skip connections across the bottleneck. Critical for tasks where input and output share low-level structure (edges, silhouette). Without the skips, high-frequency detail vanishes.

PatchGAN discriminator. Instead of outputting a single real/fake score, D outputs an N×N grid where each cell judges a receptive field of ~70×70 pixels. Averaged. This is a Markov random field assumption: realism is local. Much faster to train, fewer parameters, sharper output.

Loss.

lossG​lossD​​=−logD(x,G(x))+λ⋅∥y−G(x)∥1​=−logD(x,y)−log(1−D(x,G(x)))​

The L1 term stabilizes training and pushes G toward the known target. L1 gives sharper edges than L2 (medians, not means). λ=100 was the Pix2Pix default.

The same idea as a formula

Conditional GAN. Both networks see the condition c:

Gmin​Dmax​E(c,y)​[logD(c,y)]+Ec,z​[log(1−D(c,G(c,z)))]

At the optimum the generator matches p(y∣c) for every condition, not just the overall distribution of y.

Pix2Pix. With the input image x as the condition:

G∗=argGmin​Dmax​LcGAN​(G,D)+λEx,y​∥y−G(x)∥1​,λ=100

Why L2 blurs and L1 does not. If several targets y are plausible for the same input, the single output minimising expected squared error is their mean, argminy^​​E(y−y^​)2=E[y], which may look like none of them. Expected absolute error is minimised by the median, which is always one of the plausible values in each pixel when one outcome holds the majority. The adversarial term goes further: it rewards any output that looks like a real sample.

PatchGAN's receptive field. For a stack of convolutions with kernels kl​ and strides sl​, one output cell sees

r=1+l∑​(kl​−1)i<l∏​si​

input pixels along each side.

CycleGAN (no pairs): two generators G:X→Y, F:Y→X, two discriminators, and

Lcyc​=Ex​∥F(G(x))−x∥1​+Ey​∥G(F(y))−y∥1​

Worked example
The 70 × 70 patch by hand

Pix2Pix's discriminator: five 4×4 convolutions with strides 2, 2, 2, 1, 1.

  • Receptive field: r=1+3⋅1+3⋅2+3⋅4+3⋅8+3⋅8=1+3+6+12+24+24=70 pixels.
  • Output size for a 256×256 input (padding 1): 256→128→64→32→31→30, so a 30×30 grid of real/fake judgements, each about a 70×70 patch, overlapping heavily.
  • The loss averages the 900 cell losses: the discriminator rewards local realism (texture, edges) everywhere, and leaves global layout to the L1 term.

Mean against median. A pixel is 0 in 60% of plausible targets and 1 in 40%: the L2-best value is 0.6×0+0.4×1=0.4, a grey that appears in no target; the L1-best value is 0, the majority.

Check your mental model
  • ✗ "The discriminator only needs the generated image."
    ✓ It must see the input as well; otherwise any realistic image passes, whether or not it matches the input.
  • ✗ "With paired data, plain L1 or L2 training is enough."
    ✓ It gives faithful but blurry outputs whenever the target is uncertain (colours, textures, fine detail); the adversarial term restores sharpness.
  • ✗ "A sharper output is a more accurate one."
    ✓ A GAN invents plausible detail. It scores lower on pixel-accuracy metrics such as PSNR than a blurry output, even while looking better (the run under "Use it").

CycleGAN — when you don't have pairs

Pix2Pix needs paired (x,y) data. CycleGAN (Zhu et al., 2017) drops this requirement at the cost of an extra loss: the cycle consistency loss. Two generators G:X→Y and F:Y→X. Train them so F(G(x))≈x and G(F(y))≈y. This lets you translate horses to zebras, summer to winter, without paired examples.

Today most unpaired image-to-image work uses diffusion (ControlNet, IP-Adapter, instruction-following image editors) rather than CycleGAN, but cycle consistency remains a standard tool for unpaired domain adaptation.

Step 1 · append condition to both G and D inputs

code/main.py implements a tiny conditional GAN on 1-D data. The condition c is a class label (0 or 1). The task: produce a sample from the conditional distribution for the given class.

def G(z, c, params):
    return mlp(concat([z, one_hot(c)]), params)

def D(x, c, params):
    return mlp(concat([x, one_hot(c)]), params)

One-hot encoding is the simplest way. Larger models use learned embeddings, FiLM modulation, or cross-attention.

Step 2 · train conditional

for step in range(steps):
    x, c = sample_real_conditional()
    noise = sample_noise()
    update_D(x_real=x, x_fake=G(noise, c), c=c)
    update_G(noise, c)

The generator must match the real distribution for the given condition, not the marginal.

Step 3 · verify per-class output

import random, runpy
m = runpy.run_path("main.py")
rng = random.Random(5)
G = m["init_mlp"](4 + 2, 16, 1, rng)        # the generator as main() initialises it, before any training
real_mean = {0: -2.0, 1: 2.0}

for c in [0, 1]:
    samples = [m["g_forward"]([rng.gauss(0, 1) for _ in range(4)], c, G, 2)[0][0] for _ in range(500)]
    mean_c = sum(samples) / len(samples)
    ok = abs(mean_c - real_mean[c]) < 0.3
    print(f"class {c}: generated mean {mean_c:+.2f}, real mean {real_mean[c]:+.1f} -> {'ok' if ok else 'NOT matched'}")

Reading this output

The check is run on the untrained generator: both classes give means near 0, far from the real −2 and +2, so both fail, as they should before training. The one-hot class enters the generator as two extra inputs, and with small random weights it shifts the output only a little; training must make the generator rely on it. A conditional GAN that ignores its condition would pass a check on the overall distribution and fail this per-class one, which is why the lesson checks each class separately.

import torch, torch.nn as nn

# 1. Why L2 blurs and L1 does not. The input fixes "there is an edge here", but the target edge is at
#    position 10 in 60% of the training pairs and at position 14 in 40%. Which single output minimises each loss?
targets = torch.stack([(torch.arange(24) >= 10).float(), (torch.arange(24) >= 14).float()])
weights = torch.tensor([0.6, 0.4])
best_l2 = (weights[:, None] * targets).sum(0)                    # the weighted mean minimises squared error
best_l1 = (targets[0] if weights[0] > 0.5 else targets[1])       # the weighted median minimises absolute error
show = lambda v: "".join(" .:-=+*#%@"[min(9, int(round(float(t) * 9)))] for t in v)
print("target A (60%):  " + show(targets[0]))
print("target B (40%):  " + show(targets[1]))
print("best under L2:   " + show(best_l2) + "   values " + " ".join(f"{v:.1f}" for v in best_l2[9:15].tolist()))
print("best under L1:   " + show(best_l1))
for name, pred in (("L2-best", best_l2), ("L1-best", best_l1)):
    l2 = (weights[:, None] * (targets - pred) ** 2).sum(); l1 = (weights[:, None] * (targets - pred).abs()).sum()
    print(f"  {name}: expected L2 {l2:.2f}, expected L1 {l1:.2f}")

# 2. Pix2Pix's PatchGAN discriminator (the "70 x 70" one), untrained, on a (condition, output) pair.
def patchgan(in_ch=6, nf=64):
    layers, ch = [nn.Conv2d(in_ch, nf, 4, 2, 1), nn.LeakyReLU(0.2)], nf
    for mult, stride in ((2, 2), (4, 2), (8, 1)):
        layers += [nn.Conv2d(ch, nf * mult, 4, stride, 1), nn.BatchNorm2d(nf * mult), nn.LeakyReLU(0.2)]
        ch = nf * mult
    layers += [nn.Conv2d(ch, 1, 4, 1, 1)]                        # one logit per patch
    return nn.Sequential(*layers)
D = patchgan().eval()
x = torch.randn(1, 3, 256, 256); y = torch.randn(1, 3, 256, 256, requires_grad=True)
out = D(torch.cat([x, y], 1))                                     # D sees the condition AND the output
print(f"\nPatchGAN: {sum(p.numel() for p in D.parameters()) / 1e6:.2f}M parameters; "
      f"input 6 x 256 x 256 (condition + output) -> {out.shape[-2]} x {out.shape[-1]} grid of real/fake logits")
out[0, 0, 15, 15].backward()                                       # which input pixels can one cell see?
seen = (y.grad[0].abs().sum(0) > 0).nonzero()
h = seen[:, 0].max() - seen[:, 0].min() + 1; w = seen[:, 1].max() - seen[:, 1].min() + 1
print(f"one output cell depends on a {h} x {w} pixel patch of the input "
      f"(rows {seen[:, 0].min()}-{seen[:, 0].max()}, columns {seen[:, 1].min()}-{seen[:, 1].max()})")

Reading this output

The two possible targets are sharp edges at positions 10 and 14. The single output with the lowest expected squared error is their weighted average: 0 before position 10, 1 after 14, and 0.6 in between, a soft ramp that matches neither target. Its expected L2 (0.96) beats the sharp edge's (1.60), so an L2-trained network is pushed toward exactly this blur. Under L1 the best output is the majority target, a sharp edge at 10. The PatchGAN has 2.77M parameters and turns a 6-channel 256×256 input (condition and output stacked) into a 30×30 grid of logits. Backpropagating from one cell lights up exactly a 70×70 block of input pixels, the receptive field computed in the worked example: each judgement is about one local patch, never the whole image.

Pitfalls

  • Condition ignored. G learns to marginalize, D never penalizes because condition signal is weak. Fix: condition D more aggressively (early layer, not just late), use projection discriminator (Miyato & Koyama 2018).
  • L1 weight too low. G drifts to arbitrary real-looking outputs, not faithful ones. Start λ≈100 for Pix2Pix-style tasks.
  • L1 weight too high. G produces blurry outputs because L1 is still an Lp​ norm. Anneal down once training stabilizes.
  • Ground-truth leakage in D. Concatenate (x,y) as D input, not just y. Without this D cannot check consistency.
  • Mode collapse per class. Each class can collapse independently. Run class-conditional diversity checks.

2026 state of image-to-image tasks:

Task Best approach
Sketch → photo, same domain, paired data Pix2Pix / Pix2PixHD (still fast, still sharp)
Sketch → photo, unpaired ControlNet with a Scribble conditioning model

Pix2Pix remains the right tool when (a) you have thousands of paired examples, (b) the task is narrow and repeatable, and (c) you need fast inference. On generic open-domain tasks, diffusion wins.

import matplotlib.pyplot as plt, pyarrow.parquet as pq
from PIL import Image
from huggingface_hub import hf_hub_download
from spandrel import ModelLoader

torch.set_num_threads(2)
# Real-ESRGAN x4plus: an image-to-image GAN (generator trained with L1 + perceptual + adversarial losses),
# loaded the way ComfyUI loads upscalers, with spandrel.
sr = ModelLoader().load_from_file(hf_hub_download("Comfy-Org/Real-ESRGAN", "RealESRGAN_x4plus.safetensors")).eval()
print(f"{sr.architecture.name}: {sum(p.numel() for p in sr.model.parameters()) / 1e6:.1f}M parameters, scale x{sr.scale}")
table = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
                      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"), columns=["image"])
def crop(row, size=384):
    im = Image.open(io.BytesIO(table.column("image")[row].as_py()["bytes"])).convert("RGB")
    s = size / min(im.size); im = im.resize((round(im.width * s), round(im.height * s)), Image.BICUBIC)
    l, t = (im.width - size) // 2, (im.height - size) // 2
    return torch.tensor(np.asarray(im.crop((l, t, l + size, t + size))), dtype=torch.float32).permute(2, 0, 1)[None] / 255

psnr = lambda a, b: float(10 * torch.log10(1 / ((a.clamp(0, 1) - b) ** 2).mean()))
lap = torch.tensor([[0, 1, 0], [1, -4, 1], [0, 1, 0]], dtype=torch.float32).view(1, 1, 3, 3).repeat(3, 1, 1, 1)
detail = lambda a: float(F.conv2d(a.clamp(0, 1), lap, groups=3).pow(2).mean())   # energy of fine detail
rows = []
for r in (500, 2500):
    hr = crop(r)                                                     # the real 384 x 384 photo
    lr = F.interpolate(hr, scale_factor=0.25, mode="bicubic", antialias=True).clamp(0, 1)   # 96 x 96 input
    bic = F.interpolate(lr, scale_factor=4, mode="bicubic").clamp(0, 1)
    t = time.perf_counter()
    with torch.no_grad(): gan = sr(lr).clamp(0, 1)
    dt = time.perf_counter() - t
    print(f"photo {r}: 96x96 -> 384x384 in {dt:.1f} s | PSNR vs the real photo: bicubic {psnr(bic, hr):.1f} dB, "
          f"Real-ESRGAN {psnr(gan, hr):.1f} dB | fine-detail energy relative to the real photo: "
          f"bicubic {detail(bic) / detail(hr):.2f}, Real-ESRGAN {detail(gan) / detail(hr):.2f}")
    rows.append((lr, bic, gan, hr))

fig, axes = plt.subplots(2, 4, figsize=(9, 4.7))

Reading this output

Bicubic interpolation scores the higher PSNR, about 25.5 dB on both photos, against 24–25 dB for Real-ESRGAN, yet it keeps only 1–2% of the real photo's fine-detail energy: its output is smooth. Real-ESRGAN restores most of the detail energy on the first photo and a quarter on the second, and its output looks sharper: crisp edges on the hat, the fish and the dog's collar. Much of that detail is invented, not recovered: the dog's fur and the fish's skin are rendered smooth and painterly, plausible but not what the camera recorded. This is the perception–distortion trade-off: pixel-accuracy metrics favour the blurry average (the formula box's mean), while adversarial training favours a plausible sample, so GAN restorers are judged with perceptual metrics (LPIPS) and by eye. The model has 16.7M parameters and enlarges each image in one pass, seconds on this page's CPU and milliseconds on a GPU.

Industry practice
What's current (2024–2026)
  • GAN upscalers in image tools. Real-ESRGAN and its relatives (4x-UltraSharp and similar ESRGAN fine-tunes) are the standard upscale nodes in ComfyUI and Automatic1111, often followed by a low-strength diffusion pass to add detail.
  • Image-to-image by instruction. FLUX.2 and FLUX.1 Kontext, Qwen-Image-Edit, OpenAI's GPT Image models and Google's Nano Banana models handle many tasks that once needed a dedicated Pix2Pix model, with no task-specific training.
  • Structure-guided diffusion. ControlNet and T2I-Adapter (Lesson 8.8) cover sketch-, edge-, depth- and pose-to-image with a pretrained diffusion model.

Recap
What to keep from this lesson
  • Condition both networks: G(c,z) and D(c,y); the discriminator must see the pair.
  • Pix2Pix = U-Net generator + PatchGAN discriminator + λ=100 L1.
  • L2 predicts the mean (blur), L1 the median, the adversarial loss a plausible sample.
  • PatchGAN: a 30×30 grid of judgements over 70×70 patches for a 256×256 input.
  • GAN outputs look sharper and score lower on PSNR: judge them with perceptual metrics too.

Solutions

SolutionP1 · Bicubic wins PSNR, the GAN wins sharpness

Bicubic interpolation wins on PSNR, by about 1–2 dB, and Real-ESRGAN looks much sharper. PSNR measures squared pixel error, and when the fine detail of the original is unknowable from a 96×96 input, the safest guess is a smooth average, exactly what interpolation produces. Real-ESRGAN was trained with an adversarial loss to produce plausible sharp detail; where its invented detail differs from the real one, it is penalised twice by squared error (once for missing the true detail, once for adding a wrong one). That is why image-restoration papers report a perceptual metric such as LPIPS alongside PSNR.

SolutionB1 · Realistic but unrelated

Without the input, the discriminator judges only "is this a realistic image?" and cannot notice an output that is realistic but wrong for this input: the wrong colour of a car, a building where the map shows a road. With λ=100, the L1 term is the only thing tying the output to its input, so results remain roughly faithful but the adversarial term no longer pushes consistency in detail. With λ=0 as well, nothing ties output to input: the generator can learn to ignore x and produce any realistic image, often the same few for every input (mode collapse), and the discriminator has no reason to object. Isola et al. compared these variants and found the conditional discriminator plus L1 best.

Production note: Pix2Pix as a latency-bound baseline

When you have paired data and a narrow task (sketch → render, semantic map → photo, day → night), Pix2Pix's one-shot inference beats diffusion by an order of magnitude on latency. The production comparison is usually:

Path Steps Rough latency at 512² on a single L4 (order of magnitude; depends on model size)
Pix2Pix (U-Net forward) 1 ~30 ms
SD-Inpaint or SD-Img2Img 20 ~1.2 s
SDXL-Turbo Img2Img 1-4 ~0.15-0.35 s
ControlNet + SDXL base 20-30 ~3-5 s

Pix2Pix wins on throughput in static batches (every request is the same FLOPs). Diffusion wins on quality and generalization. The modern play is often to ship a Pix2Pix-style distilled model for the narrow task and a diffusion fallback for tail inputs.
