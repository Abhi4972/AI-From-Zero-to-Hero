The problem

In plain words first

Several AI reviewers on one pull request sounds like safety in numbers: if two of three agree, it must be real. Sometimes it is. Sometimes three reviewers share the same blind spot, and sometimes a quorum rule hides the one finding only a careful reviewer caught.

This project builds a review panel that measures instead of assuming. Every finding from every reviewer must point at a real line with an exact quote. Findings are grouped and votes counted, but single-reviewer findings stay visible as "needs review" and severity disagreements are flagged. Reviewer runs are bounded by cost and deadlines. And the panel is scored against a known answer key, reviewer by reviewer and as a consensus.

A review disagreement workbench that measures when quorum helps and when it hides findings.

Where it stops: Input files maps names to text or lines. Optional reviewers contain id,cost,findings recordings. Expected labels use {file,line,rule}; the report records the source fingerprint and per-reviewer versus consensus metrics.

Worked example
Votes on three findings
  1. eval(input); on line 2: broad, focused and eval-only all report it, at severity 3. Consensus, no disagreement.
  2. rejectUnauthorized: false on line 3: broad (severity 2) and focused (severity 3). Two votes reach the quorum, so it is consensus, but the severities differ, so the disagreement flag stays on.
  3. A comment on line 1 that merely mentions eval(input): only broad reports it. A single vote is not dropped; it is shown as needs-review.
  4. Votes are counted one per reviewer per group, so a reviewer repeating itself cannot outvote the others.
Check your mental model

Which statements are right?

  • ✓ Every finding must cite a file in the snapshot, a real line and an exact quote.
  • ✗ A finding reported by only one reviewer is noise and can be discarded. It stays visible as needs-review; it may be the one real catch.
  • ✓ Two reviewers built from the same model and prompt are not independent evidence.
  • ✗ Deduplication by file and line is enough. Groups are by file, line and rule; two different problems on one line stay separate.

      if (active && /\beval\s*\(/.test(quote))

          file,
          line: index + 1,

          rule: "dynamic-eval",

        /rejectUnauthorized\s*:\s*false/.test(quote)
      )
        rows.push({
          file,
          line: index + 1,
          quote,
          rule: "tls-disabled",
          severity: strategy === "broad" ? 2 : 3,
        });
      return rows;
    }),
  );

/*
 * Multi-Agent Code Review Panel reference implementation.
 * Follow stages in projects/multi-agent-code-review-panel/stages/.
 * The demo is deterministic and requires no provider credentials.
 * Protocol references are listed in the project README.
 */
import { pathToFileURL } from "node:url";
import path from "node:path";

export type Finding = {
  file: string;
  line: number;
  quote: string;
  rule: string;
  severity: number;
};
export type Review = { reviewer: string; findings: Finding[] };
export type Reviewer = {
  id: string;
  cost: number;
  run: (signal: AbortSignal) => Promise<Finding[]>;
};
export function validateFinding(
  raw: unknown,
  files: Record<string, string[]>,
): Finding | null {
  if (!raw || typeof raw !== "object") return null;
  const f = raw as Finding;
  if (
    typeof f.file !== "string" ||
    !Number.isInteger(f.line) ||
    f.line < 1 ||
    typeof f.quote !== "string" ||
    !f.quote.trim() ||
    typeof f.rule !== "string" ||
    !f.rule ||
    !Number.isInteger(f.severity) ||
    f.severity < 1 ||
    f.severity > 3
  )
    return null;
  const line = Object.hasOwn(files, f.file)
    ? files[f.file][f.line - 1]
    : undefined;
  return line !== undefined && line.includes(f.quote) ? f : null;
}
export function aggregate(
  reviews: Review[],
  files: Record<string, string[]>,
  quorum = 2,
) {
  if (!Number.isInteger(quorum) || quorum < 1)
    throw new Error("invalid quorum");
  const ids = new Set<string>();
  const groups = new Map<
    string,
    { finding: Finding; supporters: string[]; severities: number[] }
  >();
  let rejected = 0;
  for (const review of reviews) {
    if (ids.has(review.reviewer)) throw new Error("duplicate reviewer");
    ids.add(review.reviewer);
    const seen = new Set<string>();
    for (const raw of review.findings) {
      const f = validateFinding(raw, files);
      if (!f) {
        rejected++;
        continue;
      }
      const key = JSON.stringify([f.file, f.line, f.rule]);
      if (seen.has(key)) continue;
      seen.add(key);
      let g = groups.get(key);
      if (!g) {
        g = { finding: f, supporters: [], severities: [] };
        groups.set(key, g);
      }
      g.supporters.push(review.reviewer);
      g.severities.push(f.severity);
    }
  }
  return {
    findings: [...groups.values()]
      .map((g) => ({
        ...g,
        status: g.supporters.length >= quorum ? "consensus" : "needs-review",
        disagreement: new Set(g.severities).size > 1,
      }))
      .sort(
        (a, b) =>
          b.supporters.length - a.supporters.length ||
          a.finding.file.localeCompare(b.finding.file) ||
          a.finding.line - b.finding.line,
      ),
    rejected,
  };
}
export async function runPanel(
  reviewers: Reviewer[],
  budget: number,
  timeoutMs = 1000,
) {
  if (!Number.isFinite(budget) || budget < 0 || timeoutMs <= 0)
    throw new Error("invalid limits");
  if (new Set(reviewers.map((r) => r.id)).size !== reviewers.length)
    throw new Error("duplicate reviewer");
  if (reviewers.some((r) => !Number.isFinite(r.cost) || r.cost < 0))
    throw new Error("invalid cost");
  let spent = 0;
  const trace: { reviewer: string; status: string; cost: number }[] = [];
  const jobs: Promise<Review | null>[] = [];
  for (const r of reviewers) {
    if (spent + r.cost > budget) {
      trace.push({ reviewer: r.id, status: "budget-skipped", cost: 0 });
      continue;
    }
    spent += r.cost;
    const event = { reviewer: r.id, status: "running", cost: r.cost };
    trace.push(event);
    jobs.push(
      (async () => {
        const controller = new AbortController();
        let timer: ReturnType<typeof setTimeout> | undefined;
        try {
          const result = await Promise.race([
            r.run(controller.signal),
            new Promise<never>((_, reject) => {
              timer = setTimeout(() => {
                controller.abort();
                reject(new Error("deadline"));
              }, timeoutMs);
            }),
          ]);
          event.status = "complete";
          return { reviewer: r.id, findings: result };
        } catch (e) {
          event.status = controller.signal.aborted ? "timeout" : "failed";
          return null;
        } finally {
          clearTimeout(timer);
        }
      })(),
    );
  }
  const reviews = (await Promise.all(jobs)).filter(
    (r): r is Review => r !== null,
  );
  return { spent, trace, reviews };
}
export function evaluate(predicted: string[], expected: string[]) {
  const p = new Set(predicted),
    e = new Set(expected);
  const hits = [...p].filter((x) => e.has(x)).length;
  return {
    precision: p.size ? hits / p.size : 0,
    recall: e.size ? hits / e.size : 0,
    hits,
  };
}

Break it on purpose

A team runs three copies of the same model with the same prompt and reports "3 of 3 reviewers agree" as strong evidence. What is wrong with treating that as three votes? (Solution B1.)

Recap
What to keep from this project
  • Validate every reviewer's findings against the snapshot.
  • Count one vote per reviewer per finding group; keep singletons visible.
  • Flag severity disagreements even under consensus.
  • Bound reviewers by cost and deadline; keep failures in the trace.
  • Measure precision and recall per reviewer and for the consensus.

Exercises

Questions to test what you built. Try each one before you open the solutions.

  1. When can a quorum rule lower recall?
  2. Why reserve a reviewer's cost before launching it?
  3. How would you measure whether model reviewers are independent?

Solutions

Solution
  1. Quorum lowering recall

When only one reviewer is capable of spotting a kind of problem. Requiring two votes drops exactly those findings. Keeping singletons as needs-review avoids losing them.

Solution
  1. Reserving cost first

Several reviewers start in parallel; without reservations they could each see the full remaining budget and together overspend it. Reserving first, like the agent budget planner, makes the limit hold.

Solution
  1. Measuring independence

On a labelled set, check how often reviewers' errors coincide. If they miss the same findings far more often than chance would predict, their votes are correlated and agreement adds little.

SolutionB1 · Three copies, one opinion

Identical models with identical prompts share the same blind spots and mistakes, so their agreement is close to one vote repeated three times. Independence must be measured, not assumed.
