Why this came about

Fine-tuned models still produced answers people did not prefer. RLHF, learning from human comparisons, made ChatGPT possible in 2022; DPO (2023) simplified it; and from 2024, reinforcement learning on automatically checkable tasks (such as math and code) drove the rise of reasoning models.

In plain words first
Learning from 'this answer is better than that one'

After fine-tuning, models are aligned with preferences: people (or models) compare pairs of answers, and training pushes the model toward the preferred kind. RLHF trains a reward model on those preferences and optimizes against it; DPO learns from the pairs directly. RL with verifiable rewards rewards answers a program can check, such as passing tests or correct math, which drives much of today's reasoning ability.

Preference tuning: RLHF and DPO

Many answers are correct but some are better: clearer, safer, more honest. Preference tuning learns from comparisons, which people can make far more reliably than they can write perfect answers.

RLHF (reinforcement learning from human feedback, as in InstructGPT, 2022) has two steps. First, train a reward model on pairs where a person preferred one answer over another, using the Bradley-Terry model: P(A preferred over B) = sigmoid(r(A) − r(B)). Then fine-tune the LLM with reinforcement learning (usually PPO) to produce answers the reward model scores highly, with a KL penalty that keeps it close to the SFT model so it does not drift into gibberish that happens to score well.

import numpy as np
rng = np.random.default_rng(0)
sigmoid = lambda z: 1 / (1 + np.exp(-z))
# Reward model: learn a score r(answer) from pairs where a person preferred A over B.
# Each answer is described by 3 features: [answers the question, cites a source, length in 100s of words]
true_w = np.array([2.0, 1.0, -0.3])                   # what people actually value (hidden from the model)
A, B = rng.normal(size=(500, 3)), rng.normal(size=(500, 3))
prefers_a = rng.random(500) < sigmoid((A - B) @ true_w)   # Bradley-Terry: P(A > B) = sigmoid(r(A) - r(B))
chosen, rejected = np.where(prefers_a[:, None], A, B), np.where(prefers_a[:, None], B, A)

w = np.zeros(3)
for _ in range(500):
    margin = (chosen - rejected) @ w
    grad = -((1 - sigmoid(margin))[:, None] * (chosen - rejected)).mean(0)   # gradient of -log sigmoid(margin)
    w -= 0.5 * grad
print("learned reward weights", w.round(2), "| true", true_w)
What you should see
learned reward weights [ 1.99  1.08 -0.46] | true [ 2.   1.  -0.3]

From 500 noisy comparisons the reward model recovers what people value. Note the negative weight on length: real reward models often learn the opposite, rewarding longer answers, which is one source of verbose models (a form of reward hacking).

DPO (direct preference optimization, Rafailov et al., 2023) gets the same effect without a separate reward model or an RL loop. It treats the model's own log-probability ratio against a frozen reference model as an implicit reward, and raises it for chosen answers relative to rejected ones with a simple classification-style loss. It is cheaper and more stable, so it is the common choice for open-model fine-tuning; variants include IPO, KTO (needs only thumbs up or down, not pairs), ORPO and SimPO.

import math
def dpo_loss(pi_chosen, pi_rejected, ref_chosen, ref_rejected, beta=0.1):
    """Direct Preference Optimization (Rafailov et al. 2023). Inputs are log-probabilities of whole answers
    under the model being trained (pi) and a frozen copy of the starting model (ref). No reward model, no RL loop."""
    margin = beta * ((pi_chosen - ref_chosen) - (pi_rejected - ref_rejected))
    return -math.log(1 / (1 + math.exp(-margin))), margin

cases = [("start: model equals reference",  -42.0, -40.0, -42.0, -40.0),
         ("after training: chosen up, rejected down", -38.0, -47.0, -42.0, -40.0),
         ("wrong way: rejected answer gained",  -44.0, -36.0, -42.0, -40.0)]
for name, pc, pr, rc, rr in cases:
    loss, m = dpo_loss(pc, pr, rc, rr)
    print(f"{name:<42} implicit reward margin {m:+.2f}  loss {loss:.3f}")
What you should see
start: model equals reference              implicit reward margin +0.00  loss 0.693
after training: chosen up, rejected down   implicit reward margin +1.10  loss 0.287
wrong way: rejected answer gained          implicit reward margin -0.60  loss 1.037

The loss starts at log 2 (no preference), falls as the chosen answer becomes relatively more likely, and rises if training goes the wrong way. The beta setting plays the role of RLHF's KL penalty.

RLAIF replaces human labelers with an AI judge. Anthropic's Constitutional AI (2022) has the model critique and revise its own answers against a written set of principles, then trains on AI-labeled preferences, which scales harmlessness training without people reading thousands of harmful outputs.

Reinforcement learning from verifiable rewards

For tasks with a checkable answer (a math result, code that passes tests, a tool call that achieves the goal) there is no need for a learned reward model: a program can grade the output. RLVR samples many attempts, rewards the ones that pass, and reinforces the reasoning that led there. This is what produced reasoning models: OpenAI's o1 (2024), and DeepSeek-R1 (January 2025), whose paper showed that long chains of thought, self-checking and backtracking can emerge from RL alone (its R1-Zero variant used no SFT at all).

DeepSeek's GRPO (group relative policy optimization, introduced in DeepSeekMath, 2024) is the most copied algorithm here. Instead of PPO's separate value network, it samples a group of answers per prompt and scores each one against the group's average:

import numpy as np
# GRPO (DeepSeekMath, used for DeepSeek-R1): sample a GROUP of answers per prompt, score each with a checker,
# and push each answer up or down by how it compares with its own group. No value network needed.
rewards = np.array([1, 0, 0, 1, 0, 0, 0, 1], dtype=float)      # 8 sampled solutions, 1 = passes the unit test
advantage = (rewards - rewards.mean()) / (rewards.std() + 1e-6)
print("rewards   ", rewards.astype(int))
print("advantage ", advantage.round(2))
same = np.ones(8)
print("all-correct group advantage", ((same - same.mean()) / (same.std() + 1e-6)).round(2), "<- nothing to learn")
What you should see
rewards    [1 0 0 1 0 0 0 1]
advantage  [ 1.29 -0.77 -0.77  1.29 -0.77 -0.77 -0.77  1.29]
all-correct group advantage [0. 0. 0. 0. 0. 0. 0. 0.] <- nothing to learn

Correct samples get a positive advantage and are made more likely; wrong ones are pushed down. A prompt the model always solves, or never solves, gives zero signal, so RL data is filtered to tasks at the edge of the model's ability.

Three ideas around RLVR come up often:

  • Outcome vs process rewards: an outcome reward grades only the final answer; a process reward model (PRM) grades each reasoning step, giving denser signal at the cost of labeling steps.
  • RL environments: for agents, the "task" is an environment (a code repository with tests, a simulated browser, a mock customer database) where the model takes many tool-using steps and a checker grades the end state. Building such environments is now a major part of how agent skill is trained, and it is the same idea as the simulation-based agent evals of Lesson 14.144.
  • Test-time compute: reasoning models trade more thinking tokens for accuracy at inference. Accuracy rises with thinking budget on hard problems, which is why reasoning effort is a setting you tune per step (Lesson 11.25).

Reward hacking is the standing risk in all RL: the model finds a way to score without doing the task, such as special-casing unit tests, so graders must be robust and outputs audited.

See it learn: a policy trained by rewards alone

The advantage numbers above say which answers to push up and which to push down. This step does the pushing, so that you can watch a model get better with no correct answers shown to it, only a checker's verdicts. The method is called a policy gradient: the policy is the model's probability for each thing it might do, and the gradient says how to change those probabilities so that rewarded actions become more likely.

The "model" here is as small as a model can be: four numbers, one score for each answer it might give to What is 17 + 26?. A softmax (Lesson 1.25) turns the scores into probabilities. Nothing tells it that 43 is right. It samples a group of answers, a program grades them, and each answer's score moves by its advantage.

import numpy as np

ANSWERS = ["33", "42", "43", "53"]                 # four things the "model" might say to: What is 17 + 26?

def train(checker, steps=200, group=8, lr=0.5, seed=0):
    rng = np.random.default_rng(seed)
    logits = np.zeros(4)                           # the whole "model": one score per possible answer
    history = []
    for step in range(1, steps + 1):
        probs = np.exp(logits) / np.exp(logits).sum()
        picks = rng.choice(4, size=group, p=probs)                      # 1. sample a group of answers
        rewards = np.array([checker(ANSWERS[i]) for i in picks])        # 2. a program grades each one
        advantage = (rewards - rewards.mean()) / (rewards.std() + 1e-6) # 3. compare each with its group (GRPO)
        grad = np.zeros(4)
        for i, a in zip(picks, advantage):
            grad += a * (np.eye(4)[i] - probs)     # 4. the gradient of log P(answer i), scaled by its advantage
        logits += lr * grad / group                # 5. make better-than-average answers more likely
        if step in (1, 10, 50, 200):
            history.append((step, probs.round(2)))
    return history

print("checker: the answer must equal 43")
for step, probs in train(lambda a: float(a == "43")):
    print(f"  step {step:>3}: P(33, 42, 43, 53) = {probs}")

print("a careless checker: the answer must end in 3")
for step, probs in train(lambda a: float(a.endswith("3"))):
    print(f"  step {step:>3}: P(33, 42, 43, 53) = {probs}")

Reading this output
  • It learned from verdicts alone. The model starts with no preference (0.25 each). After ten steps it gives 43 a probability of 0.83, and after fifty, 0.99. No one showed it the answer. It tried answers, and the ones a checker accepted were made more likely.
  • Line 4 is the whole method. For a softmax, the gradient of the log-probability of answer i is "1 for that answer, minus the current probabilities". Multiplying it by the advantage pushes a better-than-average answer up and a worse one down. This rule is called REINFORCE. PPO and GRPO are more careful versions of the same step for models with billions of weights.
  • The model learns what the checker rewards, not what you meant. The second checker accepts any answer that ends in 3. The model drops 42 and then has no reason to prefer 43 over 33 or 53, so a third of its answers stay wrong for ever. This is reward hacking in four numbers: the reward was satisfied and the task was not.
How this connects
  • You have already met this loop. Lesson 2.27's delivery routes learned from rewards in the same way, with one difference: there the learner kept an estimate for each choice, and here it changes its probabilities directly.
  • In a real model the four scores are replaced by the network, an "answer" is a whole chain of reasoning and tool calls, and the checker is a set of unit tests or a simulated environment. The five numbered steps stay the same.

Distillation and synthetic data

Distillation trains a small student model to imitate a large teacher, either on the teacher's full probability distribution (logit distillation) or just on its generated text (sequence distillation). Most small, capable models are distilled; DeepSeek released R1's reasoning distilled into Qwen and Llama models of 1.5B to 70B. Synthetic data generated by strong models now makes up a large share of SFT and RL data. Two cautions: training repeatedly on model output without fresh human data degrades diversity and quality (model collapse, Shumailov et al., Nature 2024), and many providers' terms forbid using their outputs to train competing models.

Exercises

Predict before you run

DPO trains on pairs of a preferred and a rejected answer. What does it need that RLHF with PPO also needs, and what does it avoid? (Solution P1.)

Make it your own

Design a verifiable reward for ShopKart's refund-eligibility answers. (Solution M1.)

Solutions

SolutionP1 · DPO against RLHF

Both need preference data. DPO avoids training a separate reward model and running reinforcement learning, optimizing the policy directly on the pairs, which is simpler and more stable.

SolutionB1 · Reward hacking

To write long answers, not correct ones. Rewards must measure what you want; verifiable rewards (a checked final answer, passing tests) are harder to game.

SolutionD1 · Sycophancy from preferences

Raters preferred agreeable answers, so the reward favored agreement. Include preference data that rewards correct disagreement, and evaluate sycophancy explicitly.

SolutionM1 · A checkable reward

Compute eligibility in code from order data and policy, and reward answers whose stated decision matches; penalize missing reasons. The checker, not a judge model, defines correctness.

Check your understanding

Explain the mechanismExplain RLHF, DPO, RLVR and GRPO.

Worked answer. RLHF trains a reward model from human preferences and optimizes the model against it with reinforcement learning such as PPO. DPO optimizes directly on preference pairs without a reward model. RLVR uses rewards from verifiers (correct answers, passing tests) instead of preferences. GRPO is a reinforcement learning method that compares a group of sampled answers to the same prompt to compute relative advantages, avoiding a separate value model; it is widely used for reasoning models.

A plausible wrong answer. "They all train a reward model." DPO and verifier-based methods do not need one.

Worked answer. Whether the reward or a length bias rewards length, whether a length penalty or budget is applied, and whether the eval measures accuracy at fixed compute. Long traces cost tokens without benefit.

A plausible wrong answer. "Longer reasoning is better." Only if accuracy follows.

Worked answer. Rarely: prompting, retrieval and supervised fine-tuning solve most needs, and preference training needs quality preference data and expertise. It can pay off for consistent tone and refusals at scale; managed fine-tuning services that support DPO make it more accessible. Start with evals that show the gap.

A plausible wrong answer. "Yes, alignment improves everything." Only with good data and a measured gap.
