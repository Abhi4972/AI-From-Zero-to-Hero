In plain words first
The idea in one line

Agents that do not see real command output guess. A feedback runner captures stdout, stderr, exit code, and timing into a structured record the next turn can read. Then the agent reacts to facts instead of to its own prediction of facts.

The problem

In plain words first

Runtime feedback is what the agent learns from actually running something: the exit code, the output, how long it took. Raw output is a poor message, though: long logs bury the one line that matters, cost tokens, and can carry secrets into the prompt. A feedback record captures the run in a fixed shape (exit code, the head and tail of the output, secrets redacted, timeouts marked) and the loop refuses to advance when there is no exit code. Tool results and retries in general are covered in Lessons 14.139 and 14.67 (linked above); this lesson measures what each form of feedback costs and carries.

The agent says "running tests now." The next message says "all tests pass." The reality is that no test ran. The agent imagined the output, or it ran the command and never read the result, or it read the result and silently truncated the failure line.

A feedback runner removes that gap. Every command goes through the runner. Every record carries the command, the captured stdout and stderr, the exit code, the wall-clock duration, and a one-line agent note. The agent reads the record at the next turn. The verification gate reads the records at the end of the task.

The idea

Idea 1 · What goes in a feedback record

Field Why it matters
command Exact argv, no shell expansion surprises
stdout_tail Last N lines, deterministic truncation
stderr_tail Last N lines, separate from stdout
exit_code The unambiguous success signal
duration_ms Surfaces slow probes and runaway processes
started_at Timestamp for replay
agent_note One line the agent writes about what it expected

Idea 2 · Truncation is deterministic

A 50 MB log destroys the loop. The runner truncates head and tail with a ...truncated N lines... marker, deterministic so the same output always produces the same record. No sampling; the parts the agent needs to see (final error, final summary) live at the tail.

Idea 3 · Feedback versus telemetry

Telemetry (Phase 14 · 23, OTel GenAI conventions) is for human operators reviewing runs across time. Feedback is for the next turn of this run. They share fields but they live in different files with different retention.

Idea 4 · Refuse to advance without feedback

If the runner errors before capturing exit, the record carries exit_code: null and error: <reason>. The agent loop must refuse to claim success on a null exit. No exit, no progress.

The same idea as a formula

Cost of feedback. With r retries per task and a feedback message of f tokens, a task's prompt cost grows by about r⋅f. A raw log of L lines costs f∝L; a head-and-tail record costs f∝h+t, fixed whatever the log length.

Exposure. If a secret appears in the output with probability s per run and feedback is sent raw, the chance that at least one of n prompts contains it is 1−(1−s)n; redaction before the model sees the text makes it 0 for the patterns it covers.

Advance rule. A step may be marked passed or failed only if an exit code e exists: advance⟺e=null. A timeout is not a failure of the code; it is a missing measurement.

Worked example
Three kinds of feedback on the same bugs
  • Five bugs, three attempts each, tests that print 200 debug lines and a fake API key before the assertion.
  • Fixes stay at one or two of five in every mode, and vary by one between runs: this model cannot use richer feedback well.
  • Prompt tokens differ several-fold: "the test failed" adds almost nothing; the raw log adds thousands of tokens of debug noise; the record adds the head, tail and the assertion line.
  • The raw log carried the API key into the model's prompt; the record replaced it with [REDACTED]. A hanging test produced exit_code=None, and loop_can_advance refused to count it as anything.

    ✓ Here it added thousands of tokens and no fixes.
  • ✗ "Logs are internal, so secrets in them are harmless."
    ✓ Whatever goes into feedback goes into the prompt, and into traces.

Three kinds of feedback, measured

Qwen2.5-0.5B-Instruct (greedy, CPU) fixes five functions with three attempts each. After a failure it gets one of three feedback forms; the lesson's run_with_feedback from code/main.py produces the record. The block counts fixes, prompt tokens and prompts containing the key. About 4 minutes.

# What the agent sees after a failed test decides whether it can fix anything. Five buggy functions; the tests
# print 200 lines of debug noise and a fake API key before the assertion that matters. Qwen2.5-0.5B-Instruct
# (greedy, CPU) gets three attempts per bug, with one of three kinds of feedback after a failure: just
# "the test failed", the whole raw log, or the lesson's run_with_feedback record (code/main.py: exit code,
# head and tail of the output, secrets redacted). Counted: fixes, prompt tokens, and secrets sent to the model.
import os, pathlib, re, sys, tempfile, warnings
os.environ["HF_HUB_OFFLINE"] = "1"
warnings.filterwarnings("ignore")
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
import main as runner
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct").eval()
work = pathlib.Path(tempfile.mkdtemp())
runner.RECORD = work / "feedback_record.jsonl"                  # keep the record out of the lesson folder

BUGS = [("is_even", "def is_even(n):\n    return n % 2 == 1\n", "is_even(4) == True and is_even(7) == False", "is_even(4), is_even(7)"),
        ("largest", "def largest(xs):\n    return min(xs)\n", "largest([3, 9, 2]) == 9", "largest([3, 9, 2])"),
        ("reverse", "def reverse(s):\n    return s\n", "reverse('abc') == 'cba'", "reverse('abc')"),
        ("to_fahrenheit", "def to_fahrenheit(c):\n    return c * 9 / 5\n", "to_fahrenheit(100) == 212", "to_fahrenheit(100)"),
        ("count_vowels", "def count_vowels(s):\n    return len(s)\n", "count_vowels('banana') == 3", "count_vowels('banana')")]
SECRET = "sk-live-4f9a8b7c6d5e"

def write_test(name, check, show):
    (work / f"test_{name}.py").write_text(
        f"from {name} import {name}\nimport sys\nfor i in range(200):\n    print(f'DEBUG step {{i}}: cache warm, retries=0')\n"
        f"print('config loaded: api_key={SECRET}')\n"
        f"assert {check}, f'expected {check}, got {{({show})!r}}'\nprint('ok')\n")

def propose(code, feedback):
    ask = f"This Python function has a bug.\n{code}\nReturn only the corrected function in a ```python block."
    if feedback:
        ask += f"\nYour last attempt failed. Test feedback:\n{feedback}"
    ids = tok.apply_chat_template([{"role": "user", "content": ask}], add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=120, do_sample=False)
    m = re.search(r"```(?:python)?\n(.*?)```", tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True), re.S)
    return (m.group(1) if m else code).strip() + "\n", ids.shape[1], SECRET in ask

def feedback_for(mode, name):
    if mode == "none":
        rec = runner.run_with_feedback([sys.executable, str(work / f"test_{name}.py")])
        return "the test failed.", rec
    if mode == "raw log":
        import subprocess
        p = subprocess.run([sys.executable, str(work / f"test_{name}.py")], capture_output=True, text=True, cwd=work)
        return (p.stdout + p.stderr)[-6000:], None                      # what fits in the window, unprocessed
    rec = runner.run_with_feedback([sys.executable, str(work / f"test_{name}.py")])
    return (f"exit code {rec.exit_code}\nstderr (tail):\n{rec.stderr_tail}\nstdout (head and tail):\n{rec.stdout_tail}"), rec

os.chdir(work); sys.path.insert(0, str(work))
RESULTS = {}
for mode in ("none", "raw log", "feedback record"):
    fixed, tokens, leaks = 0, 0, 0
    for name, code, check, show in BUGS:
        write_test(name, check, show)
        fb = ""
        for attempt in range(3):
            new, n_tok, leaked = propose(code, fb)
            tokens += n_tok; leaks += leaked
            (work / f"{name}.py").write_text(new)
            for mod in (name, f"test_{name}"):
                sys.modules.pop(mod, None)
            text, rec = feedback_for(mode, name)
            ok = (rec.exit_code == 0) if rec else ("ok" in text.splitlines()[-1:] or text.rstrip().endswith("ok"))
            if ok:
                fixed += 1; break
            fb = text
    RESULTS[mode] = (fixed, tokens, leaks)
    print(f"{mode:<16} fixed {fixed}/5   prompt tokens {tokens:>6}   prompts containing the API key: {leaks}")

Reading this output

Fixes barely move. Every mode fixes one or two of the five bugs, and reruns of this block shift those counts by one. The model mostly cannot use the assertion message, however it is delivered.

Cost and exposure move a lot. Plain "the test failed" keeps prompts small (under 800 tokens for the whole set). The raw log adds a few thousand tokens of DEBUG step N lines and carries api_key=sk-live-... into the prompt. The feedback record sits in between and contains no key: the lesson's redaction patterns replaced it.

So the record is the right default even when it does not raise the fix rate: it bounds the cost per retry and keeps secrets out of prompts and traces, and with a stronger model the assertion line at its tail is what makes a retry useful.

Part 1 of 5 · FeedbackRecord, redact, deterministic_tail

"""Wrap subprocess.run with structured capture, secret redaction, rotation, and command lineage.

Every shell command goes through run_with_feedback. Records carry argv, redacted
stdout/stderr tails, exit code, duration, started_at, agent note, and a
command_id/parent_command_id pair so retries trace back to their origin. The
JSONL file rotates at 1 MB to keep loader memory bounded.

Run: python3 code/main.py
"""

from __future__ import annotations

import json
import re
import shlex
import subprocess
import time
import uuid
from dataclasses import asdict, dataclass, field
from pathlib import Path

HERE = Path(__file__).parent
RECORD = HERE / "feedback_record.jsonl"

HEAD_LINES = 5
TAIL_LINES = 30
ROTATE_BYTES = 1 * 1024 * 1024  # 1 MB
MAX_ROTATIONS = 5

# Secret patterns. Audit quarterly against the production runtime's observed leak shapes.
REDACTION_PATTERNS = [
    (re.compile(r"(?i)bearer\s+[A-Za-z0-9._\-]+"), "Bearer [REDACTED]"),
    (re.compile(r"(?i)\b(password|passwd|secret|api[_-]?key|access[_-]?key|token)\s*[:=]\s*\S+"),
     r"\1=[REDACTED]"),
    (re.compile(r"\bAKIA[0-9A-Z]{16}\b"), "AKIA[REDACTED]"),
    (re.compile(r"\bxox[baprs]-[A-Za-z0-9\-]+"), "xox-[REDACTED]"),
    (re.compile(r"-----BEGIN [A-Z ]+ PRIVATE KEY-----[\s\S]*?-----END [A-Z ]+ PRIVATE KEY-----"),
     "[REDACTED PRIVATE KEY]"),
]


@dataclass
class FeedbackRecord:
    command_id: str
    parent_command_id: str | None
    command: list[str]
    stdout_tail: str
    stderr_tail: str
    exit_code: int | None
    duration_ms: int
    started_at: float
    agent_note: str
    error: str | None = None
    truncations: dict[str, int] = field(default_factory=dict)
    redactions: dict[str, int] = field(default_factory=dict)


def redact(text: str) -> tuple[str, int]:
    """Strip secrets before the JSONL append. Read-time redaction is a foot-gun."""
    if not text:
        return text, 0
    hits = 0
    out = text
    for pattern, replacement in REDACTION_PATTERNS:
        out, n = pattern.subn(replacement, out)
        hits += n
    return out, hits


def deterministic_tail(text: str, head: int = HEAD_LINES, tail: int = TAIL_LINES) -> tuple[str, int]:
    lines = text.splitlines()
    if len(lines) <= head + tail:
        return text, 0
    cut = len(lines) - head - tail
    return "\n".join(lines[:head] + [f"...truncated {cut} lines..."] + lines[-tail:]), cut

Part 2 of 5 · _process_capture, maybe_rotate

def _process_capture(text: str) -> tuple[str, int, int]:
    """Truncate first, then redact. Returns (text, cut_lines, redaction_hits)."""
    tailed, cut = deterministic_tail(text)
    redacted, hits = redact(tailed)
    return redacted, cut, hits


def maybe_rotate() -> None:
    """Cap the active file at ROTATE_BYTES; rotate .1 .. .MAX, drop oldest."""
    if not RECORD.exists() or RECORD.stat().st_size < ROTATE_BYTES:
        return
    for idx in range(MAX_ROTATIONS, 0, -1):
        src = RECORD.with_suffix(RECORD.suffix + (f".{idx - 1}" if idx > 1 else ""))
        if src == RECORD:
            src = RECORD
        dst = RECORD.with_suffix(RECORD.suffix + f".{idx}")
        if src.exists():
            if idx == MAX_ROTATIONS and dst.exists():
                dst.unlink()
            try:
                src.rename(dst)
            except FileNotFoundError:
                pass

Part 3 of 5 · run_with_feedback, loop_can_advance

def run_with_feedback(
    command: list[str],
    agent_note: str = "",
    timeout_s: float = 30.0,
    parent_command_id: str | None = None,
) -> FeedbackRecord:
    started = time.time()
    command_id = uuid.uuid4().hex[:12]
    base_kwargs = dict(
        command_id=command_id,
        parent_command_id=parent_command_id,
        command=command,
        started_at=started,
        agent_note=agent_note,
    )
    try:
        completed = subprocess.run(command, capture_output=True, text=True, timeout=timeout_s)
        out, cut_out, red_out = _process_capture(completed.stdout)
        err, cut_err, red_err = _process_capture(completed.stderr)
        record = FeedbackRecord(
            stdout_tail=out, stderr_tail=err,
            exit_code=completed.returncode,
            duration_ms=int((time.time() - started) * 1000),
            truncations={"stdout": cut_out, "stderr": cut_err},
            redactions={"stdout": red_out, "stderr": red_err},
            **base_kwargs,
        )
    except subprocess.TimeoutExpired as exc:
        partial_out = exc.stdout.decode(errors="replace") if isinstance(exc.stdout, bytes) else (exc.stdout or "")
        partial_err = exc.stderr.decode(errors="replace") if isinstance(exc.stderr, bytes) else (exc.stderr or "")
        out, cut_out, red_out = _process_capture(partial_out)
        err, cut_err, red_err = _process_capture(partial_err)
        record = FeedbackRecord(
            stdout_tail=out, stderr_tail=err,
            exit_code=None,
            duration_ms=int((time.time() - started) * 1000),
            error=f"timeout after {timeout_s}s",
            truncations={"stdout": cut_out, "stderr": cut_err},
            redactions={"stdout": red_out, "stderr": red_err},
            **base_kwargs,
        )
    except FileNotFoundError as exc:
        record = FeedbackRecord(
            stdout_tail="", stderr_tail="",
            exit_code=None,
            duration_ms=int((time.time() - started) * 1000),
            error=str(exc),
            **base_kwargs,
        )

    maybe_rotate()
    with RECORD.open("a") as fh:
        fh.write(json.dumps(asdict(record)) + "\n")
    return record


def loop_can_advance(record: FeedbackRecord) -> bool:
    """Refuse to advance the loop when exit code is missing."""
    return record.exit_code is not None

Part 4 of 5 · load_all, retry_chain

def load_all() -> list[FeedbackRecord]:
    """Read active + rotated files so parent-command lineage survives rotation."""
    def _rotation_key(p: Path) -> int:
        suffix = p.name[len(RECORD.name):]
        if not suffix:
            return 0  # active file
        try:
            return int(suffix.lstrip("."))
        except ValueError:
            return 99
    paths = sorted(HERE.glob(RECORD.name + "*"), key=_rotation_key, reverse=True)
    by_id: dict[str, FeedbackRecord] = {}
    for path in paths:
        try:
            text = path.read_text()
        except FileNotFoundError:
            continue
        for line in text.splitlines():
            if not line.strip():
                continue
            try:
                record = FeedbackRecord(**json.loads(line))
            except (json.JSONDecodeError, TypeError):
                continue
            by_id[record.command_id] = record  # active file wins (last loaded)
    return list(by_id.values())


def retry_chain(command_id: str) -> list[FeedbackRecord]:
    """Walk parent_command_id pointers to reconstruct a retry chain."""
    records = {r.command_id: r for r in load_all()}
    chain: list[FeedbackRecord] = []
    cursor: str | None = command_id
    while cursor and cursor in records:
        chain.append(records[cursor])
        cursor = records[cursor].parent_command_id
    return list(reversed(chain))


def main() -> None:
    for path in HERE.glob("feedback_record.jsonl*"):
        path.unlink()

    ok = run_with_feedback(["python3", "-c", "print('hello')"], agent_note="expect hello")
    leak = run_with_feedback(
        ["python3", "-c",
         "print('Authorization: Bearer ya29.AbCdEf'); print('password=hunter2'); print('AKIAIOSFODNN7EXAMPLE')"],
        agent_note="expect redaction"
    )
    fail = run_with_feedback(["python3", "-c", "import sys; sys.exit(2)"], agent_note="first attempt; will retry")
    retry = run_with_feedback(
        ["python3", "-c", "print('recovered'); import sys; sys.exit(0)"],
        agent_note="retry after non-zero",
        parent_command_id=fail.command_id,
    )
    missing = run_with_feedback([shlex.split("does-not-exist")[0]], agent_note="probe missing binary")

    for label, rec in (("ok", ok), ("leak", leak), ("fail", fail), ("retry", retry), ("missing", missing)):
        print(f"{label}: cid={rec.command_id} parent={rec.parent_command_id or '-'} exit={rec.exit_code} "
              f"duration_ms={rec.duration_ms} redactions={rec.redactions or '-'}")
        if rec.error:
            print(f"  error: {rec.error}")
        if rec.stdout_tail and "REDACTED" in rec.stdout_tail:
            print(f"  stdout after redaction: {rec.stdout_tail!r}")

    chain = retry_chain(retry.command_id)
    print(f"\nretry chain for {retry.command_id}: {[r.command_id for r in chain]} (oldest -> newest)")
    print(f"{len(load_all())} records persisted in {RECORD.name}")

Production patterns in the wild

Three patterns harden the runner enough to ship.

Redact at write, not at read. Any record that touches stdout or stderr can leak secrets. The runner ships a redaction pass before the JSONL append: strip lines matching ^Bearer, password=, api[_-]?key=, AKIA[0-9A-Z]{16} (AWS), xox[baprs]- (Slack). Redaction at read time is a foot-gun; the file on disk is what an attacker reaches. Audit the redaction patterns quarterly against the production runtime's observed secret formats.

Rotation policy, not a single file. Cap feedback_record.jsonl at 1 MB per file; on overflow rotate to .1, .2, drop .5. The agent's loop only reads the current file, so the runtime cost is bounded. CI artifact storage gets the full rotated set. Without rotation the file becomes the bottleneck on every loader call.

Parent-command id for retry chains. Every record gets command_id; retries carry parent_command_id pointing at the previous attempt. The reviewer's "failed attempts" list (Phase 14 · 40) and the verification gate's audit both follow the chain. Without this link, retries look like independent successes and the audit hides the failure history.

Use it: the same idea with real libraries

Production patterns:

  • Claude Code Bash tool. The tool already captures stdout, stderr, exit, and duration. The runner in this lesson is the framework-agnostic equivalent for any agent product.
  • LangGraph nodes. Wrap any shell node in the runner so the record persists outside graph state.
  • CI logs. Pipe the JSONL into your CI artifact store; reviewers can replay any command without rerunning the session.

The runner is a thin wrapper that survives every framework migration because it owns the shape of the record.

Break it on purpose

An agent's CI fixer pastes the full CI log into its prompt after every failure. The monthly bill tripled, a cloud key showed up in the tracing backend, and on days when the test runner hangs the agent reports "tests failing, rewrote module". Using this lesson, fix all three. (Solution B1.)

Industry practice
What's current (2024–2026)
  • Coding agents shape tool output before it reaches the model: truncation with markers, separate stdout and stderr, exit codes and durations, and summaries of very long logs (Claude Code and Codex both truncate long command output).
  • Secret scanning of tool output (patterns like those in the lesson, or tools such as gitleaks and trufflehog) is increasingly applied before text enters prompts or traces, alongside OTel content-capture controls (lesson 14.23).
  • Timeouts and cancellation are part of every serious tool runner; a timed-out step is retried or escalated, never treated as a result.
  • On your laptop: the lesson's runner is standard-library Python.

Sources: OpenTelemetry GenAI content capture (lesson 14.23), gitleaks, Python subprocess timeouts.

Recap
What to keep from this lesson
  • Feed back a fixed-shape record: exit code, head and tail, duration.
  • Truncate deterministically; redact secrets before the model sees them.
  • Raw logs cost tokens without buying fixes.
  • No exit code, no verdict: timeouts block the loop.
  • Feedback helps only a model that can act on it.

Given a project that runs shell commands inside an agent loop, produce a feedback runner and the JSONL it writes.

Produce:

1. `tools/run_with_feedback.py` exposing `run_with_feedback(command: list[str], agent_note: str, timeout_s: float) -> FeedbackRecord`.
2. `feedback_record.jsonl` location under the workbench, one record per line.
3. `tools/feedback_loader.py` that returns the most recent N records for the active task.
4. A `loop_can_advance(record) -> bool` helper the agent loop calls before claiming success.
5. Tests covering: success path, non-zero exit, timeout, missing binary, deterministic head/tail truncation.

Hard rejects:

- `shell=True` anywhere in the runner. Argv-only.
- Truncation that depends on the wall clock or random sampling. Same input must produce the same record.
- Records without `duration_ms`. Slow probes are the first sign of a wedged workbench.
- A loader that returns an unbounded list. Cap at the last N or paginate.

Refusal rules:

- If the project pipes secrets through stdout, refuse to ship the runner without a redaction step. Surface the lines that would have been captured.
- If the project has commands that can hang indefinitely, refuse to ship without a default timeout and an explicit override list.
- If the runner runs inside a worker with shared state, refuse to skip a file lock around the JSONL append. Multiple writers will tear the file.

Solutions

SolutionP1 · Same fixes, very different cost

None stands out on fixes: each mode fixes one or two of five, varying slightly between runs. The raw log costs by far the most tokens and is the only mode that puts the API key into the model's prompt; the feedback record costs a fraction of that and redacts the key; "the test failed" is cheapest and tells the model least.

SolutionB1 · Shape, redact, refuse

Feed back a record, not the log: the failing job's exit code, the tail of stderr with the first error, and a short head of stdout, with a fixed size limit and a truncation marker. That bounds the token cost per retry. Run secret redaction on every piece of output before it goes into a prompt or a trace (the lesson's patterns plus a scanner such as gitleaks), and keep content capture off in tracing by default. Give every command a timeout, record a timeout as exit_code=None, and refuse to let the agent act on it: retry the run or escalate, never "fix" code because a runner hung.

Interview questions

Try answering out loud first, then open one answer at a time.

Questions from real AI engineering interviews that this lesson prepares you for. Answer out loud first, then open the worked answer.

Debug a failureA pull request from a coding agent says that the whole suite is green. A reviewer runs it and two tests fail. The transcript shows the agent writing "running tests now" and then "all tests pass", with nothing between the two lines. What happened, and what do you build so that this claim cannot reach a reviewer again?

Level 2 of 4 · about 10 minutes to answer well.

Short answer. The agent predicted the output instead of reading it. Either no command ran, or the command ran and nobody captured the result into the loop. The fix has two parts: a feedback runner that records every command with its exit code, and a verification gate that reads those records and refuses to mark the task done unless each acceptance command ran and exited zero.

Three ways the claim appears.

  1. No command ran. The model wrote the words it expected to write next. Nothing in the transcript shows argv, output or an exit code.
  2. The command ran, and the result never came back. A runner that errors before it captures the exit leaves the model with nothing to read, and the model fills the gap.
  3. The result came back, and the failure line was cut. A long output trimmed from the end loses the summary line where the failures are.

The transcript in this case has no record between the two sentences, so it is the first or the second.

The feedback runner.

Every command goes through one wrapper. The record carries the exact argv, the tail of stdout and stderr as separate fields, the exit code, the duration, the start time, and a one-line note of what the agent expected. The runner truncates head and tail in a fixed way with a marker for the lines it removed, so the final error line survives. If the runner fails before it captures an exit, the record carries exit_code: null and an error field, and the loop must not advance on it. No exit, no progress.

The verification gate.

The gate is a pure function over the artifacts. For this failure it checks three things from the feedback log: every acceptance command appears in the records, each one exited zero, and no record has a null exit. Each of those is a block-severity finding. A block prevents passed: true, and only a human can override it, with a reason and a user id in a signed log. The gate runs in CI and before the handoff. No green verdict, no pull request.

Why the model is not the fix.

A prompt that says "always run the tests" asks the model to be honest about something it cannot see. The runner makes the result visible. The gate makes the claim checkable. Neither depends on the model.

Plausible wrong answers.

  • "Tell the agent to paste the test output into the transcript." The model can paste what it expects, and a reviewer cannot tell a paste from a capture.
  • "Trust the agent and let CI catch it." CI did catch it, after the claim reached a reviewer, and the point is to stop the claim at the source.
  • "Treat a timeout as a pass, because the tests were slow." A timeout gives a null exit, and the loop must refuse to advance on a null exit.

Follow-ups an interviewer may ask.

  • (level 2) Why does the record keep stdout and stderr in separate fields? Expected: a test runner writes the failure summary to one stream and progress to the other, and a merged tail can hide the summary behind progress lines.
  • (level 2) The agent runs the acceptance command, it fails, and a retry passes. What does the gate see? Expected: two records for the same command, linked by the parent command id. The gate blocks on the failed record and does not report passed: true, even though the retry exited zero. Only a signed human override gets past it, and the chain keeps the failure history visible.
  • (level 3) Why must the gate be deterministic and not a model judge? Expected: the gate answers whether the task is complete, which must give the same verdict for the same artifacts every time, while a judge gives a qualitative opinion that belongs on the review side.
  • (level 4) Where do you place the gate so that it cannot be bypassed? Expected: in layers, with a pre-commit hook, a CI status check, and a pre-merge gate, so that a failure in one layer is caught by the next.

Explain the mechanismYou wrap every shell command that an agent runs so that the next turn can read what happened. What goes into the record, which field tells you whether the command worked, and what do you do when that field is empty?

Level 1 of 4 · about 5 minutes to answer well.

Short answer. The record carries the exact command as argv, the tail of stdout and the tail of stderr as separate fields, the exit code, the duration, the start time, and a one-line note of what the agent expected. The exit code is the success signal, because text can say anything and the code cannot. If the runner fails before it captures an exit, the record carries a null exit and an error reason, and the loop must not advance on it.

The fields.

Field Why it is there
command Exact argv, so no shell expansion surprise
stdout_tail The last lines of output, truncated the same way every time
stderr_tail The last lines of errors, kept apart from stdout
exit_code The one unambiguous success signal
duration_ms Shows slow probes and runaway processes
started_at A timestamp for replay
agent_note What the agent expected before it read the result

Truncation that does not lose the error.

A large log destroys the loop. The runner keeps a fixed number of head lines and tail lines and inserts a marker that says how many lines it removed. The same output always gives the same record. Nothing is sampled, because the final error and the final summary live at the tail.

Redact at write.

A record of stdout can carry a secret. The runner strips bearer tokens, password assignments, API keys and known key formats before it appends the line. Redaction at read time is a mistake, because the file on disk is what an attacker reaches.

Feedback is not telemetry.

Telemetry is for operators reviewing runs across time. Feedback is for the next turn of this run. They share fields and live in different files with different retention.

Plausible wrong answers.

  • "Parse the output for the word error to detect failure." Output text varies by tool and language, and the exit code is the signal every command gives.
  • "Keep the whole output, because truncation can hide something." A huge record pushes the loop out of its token budget, and the deterministic tail keeps the lines that matter.
  • "Redact when a human opens the log." The file on disk is already the leak, so redaction has to happen before the append.

Follow-ups an interviewer may ask.

  • (level 1) Why keep stderr separate from stdout? Expected: the failure summary often lands on one stream and progress on the other, and a merged tail can bury the summary.
  • (level 2) A command times out. What does the record say? Expected: a null exit code, an error field with the timeout, and whatever partial output was captured, and the loop refuses to advance.
  • (level 2) What is the agent note for? Expected: it records the prediction before the result, so a reviewer can see when the agent expected success and got a failure.
  • (level 3) A retry succeeds. How does the audit see the first failure? Expected: each record has a command id, and the retry carries the parent command id, so the chain is visible and the retry does not look like an independent success.
