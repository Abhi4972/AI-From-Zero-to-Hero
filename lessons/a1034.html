In plain words first
The idea in one line

Backprop keeps every intermediate activation. At 70B parameters and 128K context that is 3 TB of activations per rank. Checkpointing trades FLOPs for memory: recompute instead of save. The question is which segments to drop, and the answer is not "all of them."

Terms you'll hear
Term What people say What it actually means
Gradient checkpointing "Save memory by redoing forward" Store segment inputs only; recompute intermediates during backward to get gradient-support tensors
Activation recomputation "Same as checkpointing" The HPC-flavored name for the same technique
Segment size (k) "How many layers per checkpoint" Number of layers whose intermediates are dropped and rematerialized together
Selective checkpointing "Korthikanti's trick" Recompute only expensive-to-store activations (attention softmax); keep cheap ones
Full checkpointing "The naive version" Recompute every layer's intermediates in every segment
Block checkpointing "Coarse-grained" Checkpoint whole transformer blocks; largest granularity
FLOP overhead "The compute tax" Extra FLOPs per step = (recompute FLOPs) / (fwd + bwd FLOPs); 33% naive, 5% selective
Activation offload "Ship to CPU" Move activations to CPU RAM across forward->backward; alternative to recompute
sqrt-L rule "The classical optimum" For uniform-cost layers, optimal checkpoint spacing is $\sqrt{L}$ layers
Attention-softmax volume "The O(L^2) problem" $L^2 \cdot \text{heads} \cdot \text{batch}$ floats; dominates activation memory at long contexts

The problem

In plain words first

To compute gradients, backpropagation needs the intermediate results of the forward pass, so training normally keeps all of them in memory, and for long sequences that is far more than the model's own weights. Gradient checkpointing keeps only a few of them (say, each layer's input) and recomputes the rest during the backward pass when they are needed: more computation, much less memory, and exactly the same gradients. Selective checkpointing goes further by recomputing only what is cheap to recompute but expensive to store. This lesson runs the lesson's numpy version, computes the published memory formulas, and measures real checkpointing in PyTorch and Hugging Face on a real model. No model is trained.

Training a transformer stores, for each layer, the inputs to every op that is differentiated in backward: the attention inputs, the Q/K/V projections, the softmax output, the FFN inputs, the norm outputs, and the residual stream. For a layer with hidden size d, sequence length L, batch B, this is on the order of 12 * B * L * d floats per layer.

For d=8192, L=8192, B=1, that's about 805M values, or 1.6 GB/layer in BF16 by this rough count. Korthikanti et al.'s exact count is 34 bytes per element of B·L·d without the attention scores, 2.1 GiB per layer and about 136 GiB for 64 layers when FlashAttention avoids storing scores, plus 5·heads·L/d bytes per element (another 20 GiB per layer at this length) if the scores are kept. That is before you multiply by microbatch size or factor in tensor-parallel copies.

The two-sided bill: BF16 weights plus optimizer state might fit in 80GB, but activations push you past. Gradient checkpointing (aka activation recomputation) is the standard fix. Drop most activations; redo the forward during backward to get them back. Cost: extra FLOPs. Benefit: memory drops by the ratio of checkpoint segments to total layers.

Done naively, checkpointing costs roughly 33% more FLOPs per step: one extra forward pass. Done well — selective checkpointing per the "smart selection" of Korthikanti et al. — you save 5x memory for under 5% FLOP overhead. And with FP8 matmuls, FSDP offload, and expert-parallel MoE this really matters: you can't afford either the memory or the wasted compute.

Idea 1 · What Backward Actually Needs

output = layer(input). Backward wants grad_input and grad_params. To compute them it needs:

  • input (to compute grad_params = input.T @ grad_output for linear layers)
  • some activation derivative intermediates (the derivative of ReLU/GELU/softmax depends on the activation value)

The forward pass stores these automatically in the autograd graph. Every tensor.retain_grad() and every op that needs its input retains a reference.

Idea 2 · Naive Full Checkpointing

Split the network into N segments. During forward, store only the input to each segment. When backward needs intermediates, rerun the segment's forward pass to materialize them, then differentiate.

Example: 32-layer transformer split into 32 segments of 1 layer each.

  • Memory: 32 layer-inputs (small) vs 32 * (activation volume per layer) (huge).
  • Extra compute: 1 extra forward per segment, i.e., ~33% more forward FLOPs total (since backward is 2x forward, full step becomes 1 + 1 + 2 = 4 units instead of 1 + 2 = 3).

This is the original Chen et al. 2016 recipe: one checkpoint every sqrt(L) layers to balance memory and compute. For L=64, that's 8 checkpoints.

Idea 3 · Selective Checkpointing (Korthikanti 2022)

Not all activations cost the same. The attention softmax output is B*L*L*heads and grows quadratically with sequence length. The FFN hidden activation is B*L*4d and grows linearly. For long sequences the softmax dominates.

Selective checkpointing keeps the cheap-to-store activations (linear projections, residuals) and recomputes only the expensive ones (attention). You pay minimal FLOPs to recompute but save the O(L2) memory.

Megatron-Core implements this as "selective" activation recomputation. Used in most 2024+ frontier training runs.

Idea 4 · Offload

Alternative to recompute: ship activations to CPU RAM between forward and backward. Requires PCIe bandwidth; beneficial when idle bandwidth exceeds the cost of rematerialization. Mixed strategies are common: checkpoint some layers, offload others.

PyTorch offers activation offload as the context manager torch.autograd.graph.save_on_cpu(); FSDP2's CPUOffloadPolicy offloads parameters, gradients and optimizer state instead. Offload shines when GPU is bottlenecked on memory but CPU-GPU transfer has headroom.

Idea 5 · Recompute Cost Model

Per-step FLOPs with naive checkpointing every k layers out of L:

flops_fwd_normal = L * f_layer
flops_bwd_normal = 2 * L * f_layer
flops_total_normal = 3 * L * f_layer

flops_fwd_ckpt = L * f_layer
flops_recompute = L * f_layer  # one extra forward per layer in the segment
flops_bwd_ckpt = 2 * L * f_layer
flops_total_ckpt = 4 * L * f_layer
overhead = 4 / 3 - 1 = 0.33 = 33%

With selective checkpointing you recompute only the attention kernel, not the whole layer:

flops_recompute_selective = L * f_attention ~= L * f_layer * 0.15
overhead_selective = (3 + 0.15) / 3 - 1 = 0.05 = 5%

Idea 6 · Memory Savings Model

Activation volume per layer: A. For L layers, total activation memory: L * A.

Full checkpoint (segment size 1): store only L * input_volume (~L * 1/10 A for a standard transformer). Saves ~9 * L * A * 1/10.

Checkpoint every k layers: store L/k * A plus k-1 layers' worth within the active segment.

At k = sqrt(L), memory and recompute cost both scale with sqrt(L) — the optimal tradeoff for uniform-cost layers.

Idea 7 · When Not to Checkpoint

  • The innermost layers of a pipeline stage already in-flight. They have to finish anyway.
  • The first and last layers if they dominate the stage's compute (rare in transformers).
  • Attention kernels already using FlashAttention — Flash already recomputes the softmax fast, so additional layer-level checkpointing adds little on top.

Idea 8 · Implementation Patterns

  1. Function wrapper: wrap a segment in torch.utils.checkpoint.checkpoint(fn, input). PyTorch stores only input, recomputes everything else on backward.

  2. Decorator-based: label layers as checkpointable; the trainer decides at config time which segments get wrapped.

  3. Manual explicit recompute: write the backward pass yourself, calling a custom recompute_forward that duplicates the forward with the stored input.

All three give the same functional result. Wrappers are the standard idiom.

Idea 9 · Interaction with TP / PP / FP8

  • Tensor parallel: checkpoint inputs must be gathered or rescattered on recompute; handle the communication cost.
  • Pipeline parallel: typical pattern is to checkpoint each pipeline-stage's forward so reverse-order microbatches can reuse activation memory.
  • FP8 recompute: amax histories updated during recompute must match the original forward's, or the FP8 scale drifts. Most frameworks snapshot the scale.

The same idea as a formula

Activation memory per layer (Korthikanti et al., 16-bit, sequence s, batch b, hidden h, a heads, no tensor parallelism):

Mlayer​=sbh(34+h5as​) bytes.
The first term (projections, MLP, norms, dropout masks) grows linearly in s; the second (attention scores and softmax) quadratically. FlashAttention and selective recomputation both remove the second term.

Full checkpointing every k layers of L: keep ⌈L/k⌉ segment inputs (2sbh bytes each) and rebuild one segment at a time:

Mpeak​≈⌈kL​⌉⋅2sbh+k⋅Mlayer​,extra compute≈31​ of a step (one more forward).
With layer activations A times the input, the peak is smallest near k=L/A​; Chen et al.'s L​ assumes A≈1.

Selective recomputation of the attention core costs its share of FLOPs: 4s2h+24sh24s2h​ of a forward pass.

Worked example
64 layers, hidden 8,192, 64 heads, 8,192 tokens, batch 1
  • Linear term: 34×8,192×8,192=2.28 GB per layer, 136 GiB for 64 layers.
  • Score term: 5×64×8,192/8,192=320 bytes per element: 21.5 GB per layer, 1,280 GiB more. Removing it (FlashAttention, or selective recompute) is the single biggest saving.
  • Full checkpointing of every layer: 64 inputs of 2×8,192×8,192=134 MB, 8 GiB, plus one layer being rebuilt (2.1 GiB): about 10 GiB.
  • Price: one more forward pass, 31​ more step compute. Selective recomputation of the attention core costs 4.8% at this length.
Check your mental model
  • ✗ "Checkpointing changes the gradients a little."
    ✓ It recomputes the same operations; the gradients are identical (0 difference in the real runs below).
  • ✗ "More segments means more recompute."
    ✓ Full checkpointing recomputes the forward once whatever the segment size; the segment size trades stored inputs against the size of one rebuilt segment.
  • ✗ "Selective checkpointing is a different algorithm from FlashAttention."
    ✓ Both avoid storing the attention-score matrices; with FlashAttention the selective recompute of attention is already built in.

Step 1 · A Toy Model With Segments

import numpy as np


def linear_forward(x, w, b):
    return x @ w + b


def relu(x):
    return np.maximum(x, 0)


def layer_forward(x, w1, b1, w2, b2):
    h = relu(linear_forward(x, w1, b1))
    return linear_forward(h, w2, b2)


def model_forward(x, params):
    activations = [x]
    h = x
    for w1, b1, w2, b2 in params:
        h = layer_forward(h, w1, b1, w2, b2)
        activations.append(h)
    return h, activations

Step 2 · Naive Backward Needing All Activations

def model_backward(grad_output, activations, params):
    grads = [None] * len(params)
    g = grad_output
    for i in range(len(params) - 1, -1, -1):
        w1, b1, w2, b2 = params[i]
        x_in = activations[i]
        h_pre = linear_forward(x_in, w1, b1)
        h = relu(h_pre)
        gh = g @ w2.T
        gw2 = h.T @ g
        gb2 = g.sum(axis=0)
        g_pre = gh * (h_pre > 0)
        gx = g_pre @ w1.T
        gw1 = x_in.T @ g_pre
        gb1 = g_pre.sum(axis=0)
        grads[i] = (gw1, gb1, gw2, gb2)
        g = gx
    return g, grads

Step 3 · Checkpoint-Every-k Memory

def model_forward_checkpointed(x, params, k=4):
    saved_inputs = [x]
    h = x
    for i, (w1, b1, w2, b2) in enumerate(params):
        h = layer_forward(h, w1, b1, w2, b2)
        if (i + 1) % k == 0:
            saved_inputs.append(h)
    return h, saved_inputs


def model_backward_checkpointed(grad_output, saved_inputs, params, k=4):
    grads = [None] * len(params)
    g = grad_output
    segments = [(j * k, min((j + 1) * k, len(params))) for j in range(len(saved_inputs))]
    for seg_idx in range(len(saved_inputs) - 1, -1, -1):
        start, end = segments[seg_idx]
        if start >= end:
            continue
        x_in = saved_inputs[seg_idx]
        _, seg_acts = model_forward(x_in, params[start:end])
        g, seg_grads = model_backward(g, seg_acts, params[start:end])
        for j, gr in enumerate(seg_grads):
            grads[start + j] = gr
    return g, grads

Step 4 · Cost Model

def checkpoint_cost(n_layers, segment_size, flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }


def selective_checkpoint_cost(n_layers, attention_fraction=0.15,
                              flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * attention_fraction * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }

Step 5 · Memory Estimator

def activation_memory_mb(n_layers, hidden=8192, seq=8192,
                        batch=1, bytes_per_value=2):
    per_layer = 12 * batch * seq * hidden * bytes_per_value
    return n_layers * per_layer / 1e6


def memory_after_checkpoint(n_layers, segment_size, hidden=8192,
                           seq=8192, batch=1, bytes_per_value=2):
    n_seg = max(1, n_layers // segment_size)
    saved = (n_seg + segment_size) * 1 * batch * seq * hidden * bytes_per_value
    return saved / 1e6

Step 6 · Optimal Segment Size

def optimal_segment(n_layers):
    return int(round(np.sqrt(n_layers)))

Step 7 · Selective Checkpoint Decision

def should_recompute(layer_type, activation_bytes, recompute_flops_ratio):
    if layer_type == "attention" and activation_bytes > 100 * 1e6:
        return True
    if layer_type == "ffn" and activation_bytes > 500 * 1e6:
        return recompute_flops_ratio < 0.1
    return False

Equivalence. The checkpointed numpy backward produces exactly the same output and gradients (difference 0.0): recomputation repeats the same arithmetic.

Cost model. The script's formula charges (k−1)/k of a forward for recomputation, so segment size 1 shows 0% and 64 shows 33%. That contradicts the text above, where 32 segments of one layer each cost 33%: if only layer inputs are stored, every layer's internals must be recomputed, a full extra forward pass, whatever the segment size. Its "selective 5%" is an assumption (attention as 15% of a layer's FLOPs), not a measurement; the next run computes it.

Memory model. Activations without checkpointing come out at 103 GB using 12 values per s⋅b⋅h; the published count is 34 bytes (17 values), or far more if attention scores are kept (next run). For the checkpointed cases the script counts the stored inputs plus one input's worth per layer of the rebuilt segment, so k = 8 looks best (2.1 GB). Counting a rebuilt layer at its full size moves the optimum to much smaller segments.

Reading this output

A. For a 64-layer model with hidden size 8,192, keeping attention scores is what explodes memory: 1,416 GiB at 8,192 tokens and 21,024 GiB at 32,768. Without the score matrices (FlashAttention, or selective recomputation of attention) the same model needs 136 GiB at 8,192 tokens, and full checkpointing of every layer only 8 GiB of stored inputs. The lesson's rough count (12 values per element, 96 GiB at 8,192 tokens) is in the right range for the case without scores.

B. Full checkpointing always costs one extra forward (a third of a step), so the segment size only trades stored inputs against the one segment being rebuilt. When a layer's activations are 17 times its input, rebuilding big segments is expensive, and the peak is lowest at 1 or 2 layers per segment (81 and 66 units against 1,088 without checkpointing). Chen et al.'s L​ rule (8 layers for 64) assumes activations as small as the inputs; for transformers checkpointing every layer, as Hugging Face and Megatron do, is near optimal.

C. Recomputing only the attention core (QK⊤ and the weighted sum of values) costs 14% of a layer's forward FLOPs at 8,192 tokens and hidden 8,192: 4.8% more per training step, 1.3% at 2,048 tokens. That buys the removal of the quadratic score memory, which is why selective recomputation is so cheap for what it saves.

Use it: the same idea with real libraries

  • torch.utils.checkpoint: from torch.utils.checkpoint import checkpoint — the canonical wrapper in PyTorch. Wraps a function; stores only inputs, recomputes on backward.
  • Megatron-Core activation recomputation: supports selective, full, and block modes. Standard in 2024+ frontier training.
  • Activation offload in PyTorch: with torch.autograd.graph.save_on_cpu(pin_memory=True): around the forward pass moves saved activations to CPU memory and back during backward. (FSDP2's CPUOffloadPolicy offloads parameters, gradients and optimizer state, not activations.)
  • DeepSpeed: ZeRO-Offload moves optimizer states and gradients to the CPU; its activation-checkpointing settings can also keep checkpoints in CPU memory (cpu_checkpointing).
  • Selective checkpointing in PyTorch: torch.utils.checkpoint.checkpoint(..., context_fn=partial(create_selective_checkpoint_contexts, policy)) with a policy that marks ops as must-save or recompute (run after Use it).
  • Hugging Face: model.gradient_checkpointing_enable() checkpoints every decoder layer.

Real checkpointing, measured

Part 1: one training step of SmolLM2-135M (fp32, 2 × 512 tokens) with and without gradient_checkpointing_enable(), counting the bytes autograd keeps for backward (with saved_tensors_hooks) and checking the gradients. Part 2: twelve MLP blocks run without checkpointing, with PyTorch's selective checkpointing (a policy that saves matrix-multiply outputs and recomputes the rest) and with full checkpointing. No training; about 70 seconds on CPU.

import time, warnings, torch, torch.nn as nn, transformers
from torch.utils.checkpoint import checkpoint, create_selective_checkpoint_contexts, CheckpointPolicy
from functools import partial
from transformers import AutoModelForCausalLM
transformers.logging.set_verbosity_error()
torch.manual_seed(0); warnings.filterwarnings("ignore")

class Saved:                                   # count the bytes autograd keeps from the forward pass for backward
    def __init__(self): self.bytes, self.on = 0, True
    def pack(self, t):
        if self.on: self.bytes += t.numel() * t.element_size()
        return t
    def unpack(self, t): return t

def step(model, ids, ckpt):
    model.zero_grad()
    if ckpt: model.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})
    else: model.gradient_checkpointing_disable()
    s = Saved(); t = time.perf_counter()
    with torch.autograd.graph.saved_tensors_hooks(s.pack, s.unpack):
        loss = model(ids, labels=ids).loss
    s.on = False                               # recomputation during backward is not counted as stored
    loss.backward(); dt = time.perf_counter() - t
    return s.bytes, dt, loss.item(), torch.cat([p.grad.flatten() for p in model.parameters()])

print("1. Hugging Face gradient checkpointing on SmolLM2-135M (30 layers), batch 2 x 512 tokens, fp32, one step")
model = AutoModelForCausalLM.from_pretrained("HuggingFaceTB/SmolLM2-135M", dtype=torch.float32).train()
ids = torch.randint(0, 49152, (2, 512))
step(model, ids, False)                                                     # warm-up
b0, t0, l0, g0 = step(model, ids, False)
b1, t1, l1, g1 = step(model, ids, True)
print(f"  {'':<22} {'saved for backward':>19} {'time':>8}")
print(f"  {'no checkpointing':<22} {b0 / 2**20:>15.0f} MiB {t0:>7.2f}s")
print(f"  {'every layer':<22} {b1 / 2**20:>15.0f} MiB {t1:>7.2f}s")

class Block(nn.Module):
    def __init__(s, d=1024):
        super().__init__(); s.n = nn.LayerNorm(d); s.up = nn.Linear(d, 4 * d); s.down = nn.Linear(4 * d, d)
    def forward(s, x): return x + s.down(torch.nn.functional.gelu(s.up(s.n(x))))
blocks = nn.ModuleList(Block() for _ in range(12))
x0 = torch.randn(4, 1024, 1024, requires_grad=True)
sac_bytes = [0]                                                             # what the policy keeps (stored outside autograd's hooks)
def keep_matmuls(ctx, op, *args, **kw):                                     # save matmul outputs, recompute the rest
    if op in (torch.ops.aten.mm.default, torch.ops.aten.addmm.default):
        if not ctx.is_recompute:
            a, b = (args[0], args[1]) if op == torch.ops.aten.mm.default else (args[1], args[2])
            sac_bytes[0] += a.shape[0] * b.shape[1] * 4
        return CheckpointPolicy.MUST_SAVE
    return CheckpointPolicy.PREFER_RECOMPUTE
def run(mode):
    for b in blocks: b.zero_grad()
    sac_bytes[0] = 0; s = Saved(); t = time.perf_counter()
    with torch.autograd.graph.saved_tensors_hooks(s.pack, s.unpack):
        h = x0
        for b in blocks:
            if mode == "none": h = b(h)
            elif mode == "full": h = checkpoint(b, h, use_reentrant=False)
            else: h = checkpoint(b, h, use_reentrant=False, context_fn=partial(create_selective_checkpoint_contexts, keep_matmuls))
    s.on = False
    h.pow(2).mean().backward()
    return s.bytes + sac_bytes[0], time.perf_counter() - t, torch.cat([p.grad.flatten() for p in blocks.parameters()])
run("none")
rows = {m: run(m) for m in ["none", "selective", "full"]}
for m, (b, t, g) in rows.items():
    print(f"  {m:<10} saved {b / 2**20:7.0f} MiB  time {t:5.2f}s  gradient difference from none {(g - rows['none'][2]).abs().max():.1e}")

Reading this output

Part 1. Without checkpointing, autograd keeps 2,633 MiB for one step of SmolLM2-135M on 2 × 512 tokens, about five times the model's weights in fp32 (540 MB). With Hugging Face's gradient_checkpointing_enable() it keeps 569 MiB: the 30 layer inputs (68 MiB), plus what sits outside the checkpointed layers, mostly the logits (192 MiB) and the loss computation over a 49,152-token vocabulary. Loss and gradients are identical (difference 0.0). The step took about 5% longer here; on GPUs the cost of one more forward pass is closer to the theoretical third, because there the backward pass is not as dominant.

Part 2. For twelve MLP blocks, no checkpointing keeps 2,304 MiB, full checkpointing 192 MiB (just the block inputs) and selective checkpointing, which saves the outputs of the matrix multiplies and recomputes LayerNorm and GELU, 1,152 MiB. Selective cost no extra time (recomputing elementwise ops is cheap), full cost about 6% here. All three give identical gradients. Choosing what to save is a policy: save what is expensive to recompute (matrix multiplies), recompute what is cheap but large (elementwise results, attention scores).

Industry practice
What's current (2024–2026)
  • Selective activation recomputation (Megatron-Core's selective mode, PyTorch's selective activation checkpointing with policies) is the default in large-model training; full recompute is kept for the tightest memory budgets.
  • FlashAttention in every training stack removes the quadratic attention-score memory, the biggest single activation cost at long context.
  • Activation offload to CPU (PyTorch save_on_cpu, Megatron-Core fine-grained offloading) for long-context training where recompute is too slow.

Sources: Korthikanti et al., Chen et al., PyTorch checkpoint docs, Megatron Bridge activation recomputation, FlashAttention-2, PyTorch autograd saved tensors hooks.

Recap
What to keep from this lesson
  • Backward needs forward intermediates; storing all of them can dwarf the weights.
  • Checkpointing stores segment inputs and recomputes the rest: one more forward, identical gradients.
  • Per layer: 34·sbh bytes plus 5·a·s²·b for attention scores; FlashAttention removes the second.
  • Selective checkpointing keeps expensive-to-recompute tensors and recomputes cheap ones.
  • Offload trades memory for PCIe traffic instead of FLOPs.

Solutions

SolutionP1 · Not quite to 68 MiB, and only slightly slower

Not quite to 68 MiB: memory falls from 2,633 MiB to 569 MiB. The 30 layer inputs are indeed only 68 MiB, but the logits (2 × 512 × 49,152 numbers, 192 MiB) and the loss computation sit outside the checkpointed decoder layers and are still stored. With large vocabularies the output layer is a big part of what remains; chunked or fused cross-entropy losses exist for this reason. And the step was only about 5% slower on this CPU, with exactly the same gradients.

SolutionB1 · Different dropout masks, wrong gradients

The recomputed forward uses different dropout masks, so the activations rebuilt in backward differ from the ones that produced the loss, and the gradients are computed for a network that never ran: wrong, and differently wrong at every step. Training may still appear to work, just worse and less reproducibly. This is why torch.utils.checkpoint saves and restores the random number generator state by default (preserve_rng_state=True), and why Megatron tracks separate RNG states for tensor-parallel ranks. The same applies to any non-deterministic op, and FP8 scaling factors must be replayed for the same reason.
