In plain words first
The idea in one line

REINFORCE is noisy. Add a critic that learns V^(s), subtract it from the return, and you get an advantage that has the same expectation but far lower variance. That is actor-critic. A2C runs it synchronously; A3C runs it across threads. Both are the mental model for every modern deep-RL method.

Terms you'll hear
Term What people say What it actually means
Actor "The policy net" $\pi_\theta(a \mid s)$, updated by policy gradient.
Critic "The value net" $V_\phi(s)$, updated by MSE regression to returns / TD targets.
Advantage "How much better than average" $A(s, a) = Q(s, a) - V(s)$ or its estimators. Multiplier for $\nabla \log \pi$.
TD residual "δ" $\delta_t = r + \gamma V(s') - V(s)$; one-step advantage estimate.
GAE "The interpolation knob" Exponentially weighted sum of n-step advantages, parameterized by $\lambda$.
A2C "Synchronous actor-critic" Batched across envs; one gradient step per rollout.
A3C "Async actor-critic" Worker threads push gradients to a shared param server. Original paper; less common in 2026.
Bootstrap "Use V at the horizon" Truncate the rollout, add $\gamma^n V(s_{t+n})$ to close the sum.

The problem

In plain words first

REINFORCE judges each action by the total reward that followed it, which is very noisy. Actor-critic methods add a second learner, the critic, whose only job is to predict how good a situation is. The actor (the policy) is then judged by the advantage: how much better things went than the critic expected. If the critic is good, this comparison removes most of the noise; if it is wrong, it introduces bias. Generalised advantage estimation (GAE) is a dial between trusting the critic (low noise, possible bias) and trusting the actual rewards (no bias, high noise). This lesson runs the lesson's actor-critic on the grid world, turns the GAE dial with an exact and a deliberately wrong critic to measure bias and noise, and inspects the critic of a published A2C agent playing CartPole, which turns out to be wrong in a very specific, instructive way. No neural network is trained.

Vanilla REINFORCE works, but its variance is terrible. Monte Carlo returns Gt​ can swing over a factor of 10 between episodes. Multiplying that noise by ∇logπ and averaging produces a gradient estimator that takes thousands of episodes to move the policy the same distance you could move it with far fewer DQN updates.

The variance comes from using raw returns. If you subtract a baseline b(st​) — any function of state, including a learned value — the expectation is unchanged and the variance drops. The best tractable baseline is V^(st​). Now the quantity multiplying ∇logπ is the advantage:

A(s,a)=G−V^(s)

An action is good if it produced above-average return; bad if below. REINFORCE with a learned critic is actor-critic. The critic gives the actor a low-variance teacher. This is every deep-policy method after 2015 (A2C, A3C, PPO, SAC, IMPALA).

The idea

Two networks, one shared loss:

  • Actor πθ​(a∣s): the policy. Sampled to act. Trained with policy gradient.
  • Critic Vϕ​(s): estimates expected return from state. Trained to minimize (Vϕ​(s)−target)2.

The advantage. Two standard forms:

  • MC advantage: At​=Gt​−Vϕ​(st​). Unbiased, higher variance.
  • TD advantage: At​=rt+1​+γVϕ​(st+1​)−Vϕ​(st​). Biased (uses Vϕ​), far lower variance. Also called the TD residual δt​.

n-step advantage. Interpolate between the two:

At(n)​=rt+1​+γrt+2​+…+γn−1rt+n​+γnVϕ​(st+n​)−Vϕ​(st​)

n=1 is pure TD. n=∞ is MC. Most implementations use n=5 for Atari, n=2048 for PPO on MuJoCo.

Generalized Advantage Estimation (GAE). Schulman et al. (2016) proposed an exponentially weighted average over all n-step advantages:

AtGAE​=l=0∑∞​(γλ)lδt+l​

with λ∈[0,1]. λ=0 is TD (low variance, high bias). λ=1 is MC (high variance, unbiased). λ=0.95 is the 2026 default — tune until the bias/variance dial is where you want it.

A2C: synchronous advantage actor-critic. Collect T steps across N parallel environments. Compute advantages for each step. Update actor and critic on the combined batch. Repeat. The simpler, more-scalable sibling of A3C.

A3C: asynchronous advantage actor-critic. Mnih et al. (2016). Spawn N worker threads, each running an env. Each worker computes gradients locally on its own rollout, then asynchronously applies them to a shared parameter server. No replay buffer needed — workers decorrelate by running different trajectories. A3C proved you could train on CPUs at scale. In 2026, GPU-based A2C (batched parallel envs) dominates because GPUs want large batches.

The combined loss.

L(θ,ϕ)=−E[At​⋅logπθ​(at​∣st​)]+cv​⋅E[(Vϕ​(st​)−Gt​)2]−ce​⋅E[H(πθ​(⋅∣st​))]

Three terms: policy-gradient loss, value regression, entropy bonus. c_v ~ 0.5, c_e ~ 0.01 are canonical starting points.

The same idea as a formula

Advantage. Aπ(s,a)=Qπ(s,a)−Vπ(s); its expectation over a∼π is 0, so the policy gradient E[∇logπ(a∣s)Aπ(s,a)] pushes up better-than-average actions and down worse ones.

TD residual with a critic Vϕ​: δt​=rt+1​+γVϕ​(st+1​)−Vϕ​(st​). If Vϕ​=Vπ exactly, E[δt​∣st​,at​]=Aπ(st​,at​).

GAE. A^t(λ)​=∑l≥0​(γλ)lδt+l​, computed backwards as A^t​=δt​+γλA^t+1​.

  • λ=0: A^t​=δt​, one step of real reward, the rest from the critic: low variance, biased if the critic is wrong.
  • λ=1: A^t​=Gt​−Vϕ​(st​) (the sum telescopes): Monte Carlo with a baseline; any error in Vϕ​(st​) is only a baseline, so the gradient stays unbiased, but variance is high.

Combined loss (minimised): −E[A^t​logπθ​(at​∣st​)]+cv​E[(Vϕ​(st​)−R^t​)2]−ce​E[H(πθ​(⋅∣st​))] with critic targets R^t​=A^t​+Vϕ​(st​).

Bootstrapping at the end of a rollout. If an episode is cut by a time limit rather than ended, the last δ should use γVϕ​(sT​), not 0.

Worked example
GAE by hand

Rewards r1​=1, r2​=0, r3​=1 then the episode ends; critic values V(s0​)=0.5, V(s1​)=0.4, V(s2​)=0.3; γ=0.9, λ=0.8, so γλ=0.72.

  • δ2​=1+0−0.3=0.7 (terminal: no bootstrap).
  • δ1​=0+0.9×0.3−0.4=−0.13.
  • δ0​=1+0.9×0.4−0.5=0.86.
  • A^2​=0.7; A^1​=−0.13+0.72×0.7=0.374; A^0​=0.86+0.72×0.374=1.129.
  • Critic targets A^+V: 1.629, 0.774, 1.0 (the practice problem's numbers).
Check your mental model
  • ✗ "λ = 0.95 is always the right setting."
    ✓ It is a common default; the best value depends on how good the critic is (the run after Step 4 shows the trade-off exactly).
  • ✗ "The critic must be accurate for the gradient to be unbiased."
    ✓ With λ=1 the critic is only a baseline and any error leaves the gradient unbiased; bias enters through bootstrapping (λ<1).
  • ✗ "A well-trained critic knows the value of every state."
    ✓ It knows what its inputs can tell it; if the input omits time remaining, it cannot know an episode is about to be cut off (the run under "Use it").
Predict before you run

Under "Use it", a published A2C agent balances CartPole for the full 500 steps. Its critic predicts the discounted future reward (γ=0.99, +1 per step). Near step 490, ten steps before the time limit ends the episode, what will the critic predict: about 10, about 50, or about 95? (Solution P1.)

Step 1 · a critic

Linear critic Vϕ​(s)=w⋅features(s) updated with MSE:

def critic_update(w, x, target, lr):
    v_hat = dot(w, x)
    err = target - v_hat
    for j in range(len(w)):
        w[j] += lr * err * x[j]
    return v_hat

On a tabular env the critic converges in a few hundred episodes. On Atari, replace the linear critic with a shared CNN trunk + value head.

Step 2 · n-step advantage

Given a rollout of length T and a bootstrapped final V(sT​):

def compute_advantages(rewards, values, gamma=0.99, lam=0.95, last_value=0.0):
    advantages = [0.0] * len(rewards)
    gae = 0.0
    for t in reversed(range(len(rewards))):
        next_v = values[t + 1] if t + 1 < len(values) else last_value
        delta = rewards[t] + gamma * next_v - values[t]
        gae = delta + gamma * lam * gae
        advantages[t] = gae
    returns = [a + v for a, v in zip(advantages, values)]
    return advantages, returns

returns is the critic target. advantages is what multiplies ∇logπ.

Step 3 · combined update

for step_i, (x, a, _r, probs) in enumerate(traj):
    adv = advantages[step_i]
    target_v = returns[step_i]

    # critic
    critic_update(w, x, target_v, lr_v)

    # actor
    for i in range(N_ACTIONS):
        grad_logpi = (1.0 if i == a else 0.0) - probs[i]
        for j in range(N_FEAT):
            theta[i][j] += lr_a * adv * grad_logpi * x[j]

On-policy, one rollout per update, separate learning rates for actor and critic.

Step 4 · parallelization (A3C vs A2C)

  • A3C: spin up N threads. Each runs its own env and its own forward pass. Periodically push gradient updates to a shared master. No locks on the master — races are ok, they just add noise.
  • A2C: run N env instances in a single process, stack observations into a [N, obs_dim] batch, batched forward pass, batched backward pass. Higher GPU utilization, deterministic, easier to reason about. The default in 2026.

Our toy code is single-threaded for clarity; rewriting to batched A2C is three lines of numpy.

The GAE dial, measured exactly

For the uniform-random policy on the grid, the exact values (linear solve) give the exact advantage of "right" at the start. 3,000 episodes that begin with "right" then estimate it with main.py's gae_advantages() at five values of λ, once with the exact critic and once with a critic whose values are all 30% too small.

m = runpy.run_path("main.py")                          # the lesson's grid world and gae_advantages()
A, gamma = m["ACTIONS"], 0.99
cells = [(r, c) for r in range(4) for c in range(4) if (r, c) != m["TERMINAL"]]; ix = {s: i for i, s in enumerate(cells)}
# Exact values of the uniform-random policy (linear solve), and the exact advantage of 'right' at the start.
P = np.zeros((15, 15)); R = np.zeros(15)

Reading this output

With the exact critic every λ is unbiased (the small offsets at high λ are within sampling error), and the spread rises steeply: 0 at λ=0, where the one-step TD residual of a deterministic first move is exact, 0.8 at 0.5, 9 at 0.95 and 22 at λ=1, the full Monte Carlo return. With the critic 30% wrong, the picture flips: at λ=0 and 0.5 the estimate is off by about 11, the critic's error passed straight into the advantage; the bias shrinks as λ grows (9.1 at 0.9, 7.5 at 0.95) and disappears at λ=1, where the critic is only a baseline. That is the dial: λ near 1 when the critic is poor or early in training, lower when the critic is good and variance is the problem. The common 0.95 is a compromise.

Pitfalls

  • Critic bias before actor gradient. If the critic is random, its baseline is uninformative and you are training on pure noise. Warm up the critic for a few hundred steps before turning on the policy gradient, or use a slow actor learning rate.
  • Advantage normalization. Normalize advantages to zero-mean/unit-std per batch. Stabilizes training massively at near-zero cost.
  • Shared trunk. Use a shared feature extractor for actor and critic on image inputs. Separate heads. The shared features free-ride on both losses.
  • On-policy contract. A2C reuses data for exactly one update. More and your gradient is biased (importance-sampling correction is what PPO adds).
  • Entropy collapse. Without ce​>0, policy becomes near-deterministic in a few hundred updates and stops exploring.
  • Reward scale. Advantage magnitudes depend on reward scale. Normalize rewards (e.g., running-std dividing) for consistent gradient magnitudes across tasks.

Use it: the same idea with real libraries

A2C/A3C are rarely the final choice in 2026 but they are the architecture everything later refines:

Method Relation to A2C
PPO A2C + clipped importance ratio for multi-epoch updates

If you see "advantage" in a 2026 paper, think actor-critic.

A published A2C critic on CartPole

sb3/a2c-CartPole-v1 from the RL Baselines3 Zoo, loaded with Stable-Baselines3; five greedy episodes, with the critic's value V(s) compared against the discounted return that actually followed.

import numpy as np, torch, gymnasium as gym
from huggingface_hub import hf_hub_download
from stable_baselines3 import A2C

# The RL Baselines3 Zoo's A2C for CartPole: an actor head and a critic head on the same observation.
env = gym.make("CartPole-v1")
model = A2C.load(hf_hub_download("sb3/a2c-CartPole-v1", "a2c-CartPole-v1.zip"), device="cpu",
                 custom_objects={"learning_rate": 0.0, "lr_schedule": lambda _: 0.0,
                                 "observation_space": env.observation_space, "action_space": env.action_space})
gamma = model.gamma
print(f"A2C policy: {sum(p.numel() for p in model.policy.parameters()):,} parameters (actor and critic); gamma = {gamma}")
values, returns, lengths = [], [], []
for ep in range(5):
    obs, _ = env.reset(seed=ep); done = False; rew, vals = [], []
    while not done:
        t = torch.as_tensor(obs, dtype=torch.float32)[None]
        with torch.no_grad():
            vals.append(model.policy.predict_values(t).item())
        a, _ = model.predict(obs, deterministic=True)
        obs, r, term, trunc, _ = env.step(a); rew.append(r); done = term or trunc
    G = np.zeros(len(rew)); g = 0.0
    for k in reversed(range(len(rew))): g = rew[k] + gamma * g; G[k] = g
    values.append(np.array(vals)); returns.append(G); lengths.append(len(rew))
print(f"5 greedy episodes, lengths {lengths} (500 is CartPole's time limit)")
v, G = values[0], returns[0]
for t in (0, 100, 300, 450, 490, 499):
    print(f"  step {t:3d}: critic V(s) = {v[t]:6.1f}   actual discounted return from here = {G[t]:6.1f}")
print(f"an endless stream of +1 rewards is worth 1/(1 - gamma) = {1 / (1 - gamma):.0f}")

Reading this output

The agent balances the pole for the full 500 steps in all five episodes. Early on its critic is excellent: 99.9 predicted against 99.3 actually received at the start, close to the 100 that an endless stream of +1 rewards is worth with γ=0.99. Then the episodes are cut off by CartPole's 500-step time limit, and the critic does not see it coming: at step 450 it predicts 96 while only 39.5 will actually arrive, at step 490 it predicts 95 against 9.6, and at the last step 95 against 1. The observation (cart position and velocity, pole angle and angular velocity) contains no clock, so from the critic's point of view nothing distinguishes step 490 from step 90. This is correct behaviour, not a bug, provided training bootstrapped at the time limit instead of treating it as a failure: the end of the episode is an artefact of the environment, not of the agent's actions.

Break it on purpose

In gae_advantages, treat a time-limit cut-off like a real ending: next_v = 0.0 at the last step of every rollout, whether the episode terminated or was truncated. Rollouts in A2C are short (5 to 128 steps) and are cut far more often than episodes end. What does the critic learn, and how does that affect the actor? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Actor-critic is the default deep-RL family. PPO (A2C plus a clipped update, Lesson 9.8), SAC and TD3 are the standard algorithms in Stable-Baselines3, CleanRL, RLlib and robotics frameworks such as Isaac Lab; GAE with λ≈0.95 is the usual advantage estimator.
  • Critics in LLM training, and dropping them. RLHF with PPO trains a value model the size of the policy; GRPO, RLOO and REINFORCE++ remove it to save memory, estimating baselines from several samples per prompt instead (TRL, verl, OpenRLHF).
  • Time limits handled properly. Gymnasium's terminated/truncated split lets libraries bootstrap correctly at time limits; SB3 handles it in its rollout buffers.

Sources: GAE paper, Stable-Baselines3, Gymnasium terminated vs truncated, verl, Isaac Lab.

Recap
What to keep from this lesson
  • Actor: the policy; critic: a value estimate used as a learned baseline.
  • Advantage Q−V; estimated by TD residuals and GAE.
  • λ trades bias (from critic errors) against variance (from real returns).
  • Loss = policy term + value term − entropy bonus.
  • Bootstrap at truncations, not at true endings; critics only know what their inputs show.

medium25 minimplement

An actor critic needs an advantage for each step: how much better the action was than the critic expected. Generalized advantage estimation (GAE) mixes the one-step TD error with longer returns. The parameter λ controls the mix. A2C and PPO use GAE on every rollout.

Task

Write two functions.

  1. td_errors(rewards, values, dones, gamma) returns the TD error of each step: δt​=rt​+γ(1−dt​)Vt+1​−Vt​.
  2. gae(rewards, values, dones, gamma, lam) returns a tuple (advantages, returns).

The advantages follow the recursion from the last step to the first step:

AT−1​=δT−1​ and At​=δt​+γλ(1−dt​)At+1​ for t<T−1.

The returns are the targets for the critic: Rt​=At​+Vt​.

Here dt​ is 1 when dones[t] is True and 0 otherwise. A done flag at step t means that step t is the last step of its episode. The next value and the next advantage are then 0.

The array values has T+1 entries. values[t] is the critic value of the state at step t. values[T] is the bootstrap value: the critic value of the state after the last step. It is used only when the last step has no done flag.

Input and output

Name Type Shape Meaning
rewards float array (T,) the reward at each step
values float array (T + 1,) the critic value of each state, then the bootstrap value
dones bool array (T,) True at the last step of each episode
gamma float scalar the discount factor, from 0 to 1
lam float scalar the GAE parameter λ, from 0 to 1
  • td_errors returns a float array of shape (T,).
  • gae returns a tuple of two float arrays, each of shape (T,): the advantages, then the returns.

Constraints

  • 1 <= T <= 1000.
  • Do not normalize the advantages. Normalization is a separate step.
  • Do not change the input arrays.
  • Use numpy only.

Common mistakes the checks catch
  • Uses values[t + 1] as the next value also at a done step, so the next episode leaks into the TD error.
  • Uses 0 as the next value at the last step of the batch, so values[T] never enters.
  • Does not reset the running advantage at a done step, so the advantage sum crosses episodes.
  • Drops lam from the recursion, so every call computes lam = 1.
  • Adds values[t + 1] to the advantage for the return, not values[t].
  • td_errors ignores the done flags and always adds gamma * values[t + 1].
Hint 1

Compute the TD errors first. values[1:] holds the next value of each step, and values[:-1] holds the value of the step itself.

Hint 2

Multiply the next value by 1 - dones as floats. A done step has no next state, so its next value is 0.

Hint 3

The advantages need one pass from the last step to the first step. Keep a running value. At a done step, set the running value to 0 before you add the TD error of that step.

Hint 4

At each step the new running value is the TD error plus gamma * lam times the old running value. The returns are the advantages plus values[:T], not values[1:].

Reference solution and notes
import numpy as np


def td_errors(rewards, values, dones, gamma):
    rewards = np.asarray(rewards, dtype=float)
    values = np.asarray(values, dtype=float)
    not_done = 1.0 - np.asarray(dones, dtype=float)
    next_v = values[1:] * not_done
    return rewards + gamma * next_v - values[:-1]


def gae(rewards, values, dones, gamma, lam):
    rewards = np.asarray(rewards, dtype=float)
    values = np.asarray(values, dtype=float)
    dones = np.asarray(dones, dtype=bool)
    T = rewards.shape[0]
    advantages = np.zeros(T)
    gae_val = 0.0
    for t in reversed(range(T)):
        next_v = 0.0 if dones[t] else values[t + 1]
        delta = rewards[t] + gamma * next_v - values[t]
        if dones[t]:
            gae_val = 0.0
        gae_val = delta + gamma * lam * gae_val
        advantages[t] = gae_val
    returns = advantages + values[:T]
    return advantages, returns

Why GAE works

The TD error δt​ is an advantage estimate with low variance and a bias from the critic. The full discounted return minus Vt​ has no critic bias but high variance. GAE is the sum ∑l​(γλ)lδt+l​. The deltas telescope, so λ=1 gives the discounted return minus the value, and λ=0 gives the TD error. The lesson uses λ=0.95, the common default.

The two places where done acts

A done flag acts two times. It removes the next value from the TD error, because a finished episode has no next state. It also stops the recursion, because the advantage of the next episode does not belong to this one. The mutants bootstrap_through_done and no_cut_in_recursion each forget one of the two.

The bootstrap value

The lesson code uses 0 after the last step of the rollout. That is correct when the rollout ends at an episode end. When the rollout stops in the middle of an episode, the critic value of the next state fills in the missing future rewards. This problem passes that value as values[T]. The lesson version is the same code with values[T] = 0.

Where this goes next

PPO in the next lesson calls the same function on each rollout. It then normalizes the advantages per minibatch and uses the returns as targets for the value loss. The problem on the PPO clip loss takes these advantages as input.

Solutions

SolutionP1 · About 95

About 95: the critic predicts 95.2 at step 490, although only 9.6 of discounted reward actually follows before the time limit cuts the episode off. Its input is the cart's position and velocity and the pole's angle and angular velocity; nothing in it says how many steps remain, so it predicts what a balanced pole is worth in general, close to 1/(1−γ)=100. To value the remaining time correctly the time would have to be part of the state (time-aware critics add it as an input). For learning a good policy it does not matter, as long as the time limit is treated as a truncation and bootstrapped through.

SolutionB1 · A pessimistic critic, a misled actor

With next_v = 0 at every cut, the critic is taught that each rollout's last state is followed by nothing, although the episode actually continues. States that often fall at rollout boundaries get targets far too low, and because neural critics generalise, the whole value function drifts toward "the future is short". The advantages then reward actions that collect reward quickly and punish actions whose payoff comes after the next cut, a bias toward short-sighted behaviour, and on tasks like CartPole the critic underestimates by a large, rollout-length-dependent amount. The fix is the formula box's last line: bootstrap with γVϕ​(sT​) at truncations and use 0 only at true terminations.
