Leaderboard Aggregation

Lesson 19.7490 minBuildCompleted
Lesson goals
What you will be able to do
  • Aggregate per-task scores across multiple models and multiple tasks into a tidy per-model row.
  • Normalise heterogeneous scores so that pass rates and BLEU values do not over-influence the aggregate.
  • Rank models by mean and by win-rate, and explain when each is the right summary.
  • Compute bootstrap confidence intervals on the mean score per model and on pairwise differences.
  • Output the leaderboard as a JSON report and as a markdown table the runner in lesson 75 can paste into a CI comment.
Before you start
  • Needs: Phase 19 Track B foundations, lessons 70, 71, 73
  • Type: Build. Time: about 90 minutes.
In plain words first
The idea in one line

Per-task scores are easy. Per-model rankings across heterogeneous tasks are harder. Statistical significance on a thousand-prediction leaderboard is the part everyone skips. This lesson does not skip it.

The shape of input

In plain words first

Per-task scores are easy; ranking models across many different tasks honestly is harder. The leaderboard step first normalizes each task's scores to a common 0–1 scale, then computes each model's mean and win rate (the share of tasks on which it scores best). Then it asks whether differences are real. A bootstrap resamples the predictions with replacement many times and recomputes the mean each time; the middle 95% of those means is the confidence interval. For two models, a paired bootstrap resamples the same items for both and looks at the difference, which is far more sensitive. Results are rendered as a Markdown table with categories broken out.

The aggregator consumes a list of EvalRun records:

@dataclass
class EvalRun:
    model_id: str
    task_id: str
    metric_name: str
    score: float          # in [0, 1]
    category: str

The runner in lesson 75 emits one record per (model, task) pair. The aggregator does not care how the score was produced. It expects normalisation to already have happened: every score is in [0, 1].

The output

Three tables come out:

The leaderboard row contains: model_id, mean_score, mean_ci_lo, mean_ci_hi, win_rate, tasks_completed, and an optional categories map for per-category mean.

Normalisation

If one task scores in [0, 1] and another in [0, 100], the second silently dominates the mean. The aggregator validates that every input score sits in [0, 1] and refuses the run otherwise. The fix lives upstream: the metric should already return a fraction. Lessons 71 to 73 enforce that contract.

Mean and win-rate

The two ranking schemes serve different goals.

Mean score is the average of per-task scores for one model. It is the headline number leaderboards report. It is sensitive to outliers and to task imbalance.

Win-rate counts how often a model beats every other model on the same task. For each task, the model with the highest score wins (a tie gives a full win to every tied model). Win rate equals wins divided by the number of tasks where the model has a score. It is less sensitive to outliers and to scale differences but loses information.

def win_rate(model_id, runs_by_task, all_models):
    wins, total = 0, 0
    for task_id, runs in runs_by_task.items():
        scores = {r.model_id: r.score for r in runs if r.model_id in all_models}
        if model_id not in scores:
            continue
        total += 1
        best = max(scores.values())
        if scores[model_id] >= best:
            wins += 1
    return wins / total if total else 0.0

The harness reports both. The runner in lesson 75 ranks by mean by default; the markdown column for win-rate is right there in case the user prefers it.

Bootstrap confidence intervals

Per-model means come with a confidence interval estimated by bootstrap resampling over tasks. We resample task ids with replacement, compute the mean over the resampled set, repeat B times, and take the percentile interval at level alpha.

For pairwise comparisons we bootstrap the per-task difference score_A - score_B, take the percentile interval, and report it. The user reads off whether the interval excludes zero. If it does, the difference is significant at level alpha. If it does not, the leaderboard treats the models as tied.

The low-level helpers (bootstrap_mean_ci, bootstrap_pairwise_diff) default to B=1000; the public aggregators (aggregate, pairwise_diffs) default to b=500 so the demo and tests stay quick. The default alpha is 0.05. The lesson keeps the bootstrap pure numpy, no scipy.

Categories

If EvalRun.category is set, the aggregator also reports per-category mean. This is the column on every leaderboard that says math, reasoning, code, safety. It lets the runner spot whether a model is good overall but weak in code, which is information the headline mean hides.

Worked example
Reading overlapping intervals

Model A: mean 0.77, 95% interval 0.73–0.80. Model B: 0.70, interval 0.66–0.74.

  1. The intervals overlap (0.73–0.74), which tempts the conclusion "not significantly different".
  2. But both models answered the same items, and their errors are correlated: many items are easy for both, some hard for both.
  3. The paired bootstrap resamples items and computes A − B on each resample: the difference's interval is +0.026 to +0.102, entirely above zero.
  4. So A is reliably better. Overlapping individual intervals are not a test of a difference; the interval of the difference is.
Check your mental model

Which statements are right?

  • ✓ Bootstrap intervals come from resampling items with replacement.
  • ✗ If two models' confidence intervals overlap, their difference is not significant. For paired data, look at the interval of the difference.
  • ✓ Normalization puts tasks with different scales on equal footing.
  • ✗ Win rate and mean always rank models the same way. A model can win few tasks yet have a high mean, or the reverse.
Predict before you run

Before running the code below: two models are scored on 40 shared items. Model A is right on 30, model B on 26, and on 24 items both are right. Is A's lead significant by a paired bootstrap?

See it drawn
A paired bootstrap from scratch
import random
random.seed(0)
both, only_a, only_b, neither = 24, 6, 2, 8
items = [(1, 1)] * both + [(1, 0)] * only_a + [(0, 1)] * only_b + [(0, 0)] * neither
diffs = []
for _ in range(5000):
    sample = [random.choice(items) for _ in items]
    diffs.append(sum(a - b for a, b in sample) / len(sample))
diffs.sort()
lo, hi = diffs[int(0.025 * len(diffs))], diffs[int(0.975 * len(diffs))]
print(f"observed difference {(only_a - only_b) / len(items):+.3f}, 95% interval [{lo:+.3f}, {hi:+.3f}], significant: {lo > 0 or hi < 0}")
What you should see
observed difference +0.100, 95% interval [-0.025, +0.250], significant: False
Reading this output

A leads by 4 items out of 40 (+0.10), but only 8 items distinguish the models (6 favour A, 2 favour B), so the paired interval runs from about −0.03 to +0.25. It includes zero: not significant, despite a 4-point lead. The deciding quantity is the number of disagreements, not the total item count, which is why close models need large eval sets.

What this lesson does not do

It does not run models. It does not call the metric layer. It does not implement adaptive ECE or other calibration variants; those are lesson 73. It does not implement task weighting. Every task counts the same here. Production leaderboards weight tasks; we leave that hook open through the weight field but ignore it in the aggregator. Add weighting in a follow-up lesson if you need it.

How to read the code

main.py defines EvalRun, LeaderboardRow, aggregate, bootstrap_mean_ci, bootstrap_pairwise_diff, and render_markdown. Read main.py top to bottom. The data shape (EvalRun, LeaderboardRow) comes first, the aggregator next, the bootstrap third, the rendering last. Each function has a focused contract.

@dataclass
class PairwiseDiff:
    model_a: str
    model_b: str
    diff_mean: float
    ci_lo: float
    ci_hi: float
    significant: bool

    def to_dict(self) -> dict:
        return {
            "model_a": self.model_a,
            "model_b": self.model_b,
            "diff_mean": self.diff_mean,
            "ci_lo": self.ci_lo,
            "ci_hi": self.ci_hi,
            "significant": self.significant,
        }


def _validate_runs(runs: Sequence[EvalRun]) -> None:
    seen: set[tuple[str, str]] = set()
    for r in runs:
        if not (0.0 <= r.score <= 1.0):
            raise ValueError(f"score for {r.model_id}/{r.task_id} not in [0,1]: {r.score}")
        key = (r.model_id, r.task_id)
        if key in seen:
            raise ValueError(f"duplicate run for {r.model_id}/{r.task_id}")
        seen.add(key)


def _by_model(runs: Sequence[EvalRun]) -> dict[str, list[EvalRun]]:
    out: dict[str, list[EvalRun]] = defaultdict(list)
    for r in runs:
        out[r.model_id].append(r)
    return dict(out)


def _by_task(runs: Sequence[EvalRun]) -> dict[str, list[EvalRun]]:
    out: dict[str, list[EvalRun]] = defaultdict(list)
    for r in runs:
        out[r.task_id].append(r)
    return dict(out)

Part 3 of 6 · bootstrap_mean_ci, bootstrap_pairwise_diff

def bootstrap_mean_ci(
    scores: Sequence[float],
    b: int = 1000,
    alpha: float = 0.05,
    seed: int = 0,
) -> tuple[float, float]:
    if len(scores) == 0:
        return (0.0, 0.0)
    rng = np.random.default_rng(seed)
    arr = np.asarray(scores, dtype=np.float64)
    n = arr.size
    means = np.empty(b, dtype=np.float64)
    for i in range(b):
        idx = rng.integers(0, n, size=n)
        means[i] = float(arr[idx].mean())
    lo = float(np.percentile(means, 100.0 * (alpha / 2.0)))
    hi = float(np.percentile(means, 100.0 * (1.0 - alpha / 2.0)))
    return (lo, hi)


def bootstrap_pairwise_diff(
    paired_a: Sequence[float],
    paired_b: Sequence[float],
    b: int = 1000,
    alpha: float = 0.05,
    seed: int = 0,
) -> tuple[float, float, float]:
    if len(paired_a) != len(paired_b):
        raise ValueError("paired arrays must align")
    if len(paired_a) == 0:
        return (0.0, 0.0, 0.0)
    rng = np.random.default_rng(seed)
    a = np.asarray(paired_a, dtype=np.float64)
    b_arr = np.asarray(paired_b, dtype=np.float64)
    diffs = a - b_arr
    diff_mean = float(diffs.mean())
    n = diffs.size
    boots = np.empty(b, dtype=np.float64)
    for i in range(b):
        idx = rng.integers(0, n, size=n)
        boots[i] = float(diffs[idx].mean())
    lo = float(np.percentile(boots, 100.0 * (alpha / 2.0)))
    hi = float(np.percentile(boots, 100.0 * (1.0 - alpha / 2.0)))
    return (diff_mean, lo, hi)

Part 4 of 6 · _win_rate, _category_means, aggregate

def _win_rate(model_id: str, runs_by_task: dict[str, list[EvalRun]]) -> tuple[float, int]:
    wins = 0
    total = 0
    for task_id, runs in runs_by_task.items():
        scores = {r.model_id: r.score for r in runs}
        if model_id not in scores:
            continue
        total += 1
        best = max(scores.values())
        if math.isclose(scores[model_id], best, abs_tol=1e-12):
            wins += 1
    if total == 0:
        return (0.0, 0)
    return (wins / total, total)


def _category_means(runs: Sequence[EvalRun]) -> dict[str, float]:
    by_cat: dict[str, list[float]] = defaultdict(list)
    for r in runs:
        by_cat[r.category].append(r.score)
    return {cat: float(np.mean(scores)) for cat, scores in by_cat.items()}


def aggregate(
    runs: Sequence[EvalRun],
    b: int = 500,
    alpha: float = 0.05,
    seed: int = 0,
) -> list[LeaderboardRow]:
    if not runs:
        return []
    _validate_runs(runs)
    by_model = _by_model(runs)
    by_task = _by_task(runs)
    rows: list[LeaderboardRow] = []
    for model_id, model_runs in by_model.items():
        scores = [r.score for r in model_runs]
        mean_score = float(np.mean(scores))
        lo, hi = bootstrap_mean_ci(scores, b=b, alpha=alpha, seed=seed)
        wr, completed = _win_rate(model_id, by_task)
        cats = _category_means(model_runs)
        rows.append(
            LeaderboardRow(
                model_id=model_id,
                mean_score=mean_score,
                mean_ci_lo=lo,
                mean_ci_hi=hi,
                win_rate=wr,
                tasks_completed=completed if completed else len(scores),
                categories=cats,
            )
        )
    rows.sort(key=lambda r: r.mean_score, reverse=True)
    return rows

Part 5 of 6 · pairwise_diffs, render_markdown

def pairwise_diffs(
    runs: Sequence[EvalRun],
    b: int = 500,
    alpha: float = 0.05,
    seed: int = 0,
) -> list[PairwiseDiff]:
    if not runs:
        return []
    _validate_runs(runs)
    by_model = _by_model(runs)
    model_ids = sorted(by_model.keys())
    common_task_scores: dict[str, dict[str, float]] = defaultdict(dict)
    for r in runs:
        common_task_scores[r.task_id][r.model_id] = r.score
    out: list[PairwiseDiff] = []
    for i in range(len(model_ids)):
        for j in range(i + 1, len(model_ids)):
            a, b_id = model_ids[i], model_ids[j]
            paired_a = []
            paired_b = []
            for task_id, ms in common_task_scores.items():
                if a in ms and b_id in ms:
                    paired_a.append(ms[a])
                    paired_b.append(ms[b_id])
            if not paired_a:
                continue
            diff_mean, lo, hi = bootstrap_pairwise_diff(paired_a, paired_b, b=b, alpha=alpha, seed=seed + i + j)
            significant = lo > 0.0 or hi < 0.0
            out.append(PairwiseDiff(
                model_a=a,
                model_b=b_id,
                diff_mean=diff_mean,
                ci_lo=lo,
                ci_hi=hi,
                significant=significant,
            ))
    return out


def render_markdown(rows: Sequence[LeaderboardRow]) -> str:
    header = "| Rank | Model | Mean | 95% CI | Win rate | Tasks |"
    sep = "|------|-------|------|--------|----------|-------|"
    out_lines = [header, sep]
    for i, row in enumerate(rows, start=1):
        model_label = row.model_id[:20]
        ci = f"{row.mean_ci_lo:.2f}-{row.mean_ci_hi:.2f}"
        out_lines.append(
            f"| {i} | {model_label} | {row.mean_score:.2f} | {ci} | {row.win_rate:.2f} | {row.tasks_completed} |"
        )
    return "\n".join(out_lines)

Part 6 of 6 · render_json, _synthetic_runs, demo

def render_json(rows: Sequence[LeaderboardRow]) -> str:
    return json.dumps([r.to_dict() for r in rows], indent=2)


def _synthetic_runs(seed: int = 0) -> list[EvalRun]:
    rng = np.random.default_rng(seed)
    models = ["model_a", "model_b", "model_c"]
    categories = ["arithmetic", "mcq", "code_exec", "summary"]
    runs: list[EvalRun] = []
    means = {"model_a": 0.78, "model_b": 0.72, "model_c": 0.55}
    for cat in categories:
        for t in range(3):
            task_id = f"{cat}_{t:02d}"
            for m in models:
                base = means[m]
                if cat == "code_exec":
                    base -= 0.1
                if cat == "summary" and m == "model_c":
                    base += 0.15
                noise = rng.uniform(-0.1, 0.1)
                score = float(np.clip(base + noise, 0.0, 1.0))
                metric = {"arithmetic": "exact_match", "mcq": "accuracy", "code_exec": "code_exec", "summary": "rouge_l"}[cat]
                runs.append(EvalRun(model_id=m, task_id=task_id, metric_name=metric, score=score, category=cat))
    return runs


def demo() -> int:
    runs = _synthetic_runs(seed=42)
    rows = aggregate(runs, b=300, alpha=0.05, seed=11)
    diffs = pairwise_diffs(runs, b=300, alpha=0.05, seed=11)
    print(render_markdown(rows))
    print()
    print("Pairwise comparisons (paired bootstrap):")
    for d in diffs:
        sig = "yes" if d.significant else "no"
        print(f"  {d.model_a} vs {d.model_b}: diff={d.diff_mean:+.3f} ci=[{d.ci_lo:+.3f},{d.ci_hi:+.3f}] significant={sig}")
    if not rows:
        return 1
    if rows[0].mean_score < rows[-1].mean_score:
        return 1
    return 0
Reading this output

Model A leads on mean (0.77) and win rate (0.75 of 12 tasks), ahead of B (0.70) and C (0.57). The individual intervals of A and B overlap slightly, yet the paired bootstrap says A beats B (difference +0.064, interval +0.026 to +0.102), exactly the situation in the worked example. All three pairwise differences are significant on this fixture.

Break it on purpose

A leaderboard ranks 12 models by mean score on 200 items and highlights a 0.4-point lead as "best model". No intervals are shown. What should a reader ask for? (Solution B1.)

Recap
What to keep from this lesson
  • Normalize per task, then aggregate with mean and win rate.
  • Bootstrap items for confidence intervals.
  • Compare models with a paired bootstrap on the difference.
  • Overlapping individual intervals do not settle a comparison.
  • Render with categories and intervals, not just ranks.

Going further

The per-model intervals are unpaired, but model comparisons should be paired. If model A and B both ran the same hundred tasks, the appropriate test is the paired bootstrap on task-by-task differences, which bootstrap_pairwise_diff already implements. Beyond that, you want a hierarchical bootstrap that respects task families (math problems are not independent from each other; an arithmetic error pattern affects ten of them). That is a follow-up. The point of this lesson is to get the floor right so the eval reports a number you can defend.

Solutions

SolutionB1 · A lead without uncertainty

Ask for the paired-bootstrap interval of the difference between the top two models (and ideally adjacent pairs). On 200 items a 0.4-point lead is very likely inside the noise; the table should show intervals, and ties should be presented as ties.
