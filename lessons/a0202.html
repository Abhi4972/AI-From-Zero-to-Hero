In plain words first
The idea in one line

Linear regression draws the best straight line through your data. It is the "hello world" of machine learning.

Terms you'll hear
Term What people say What it actually means
Linear regression "Draw a line through data" Find weight $w$ and bias $b$ that minimize the sum of squared differences between $wx+b$ and actual $y$ values
Cost function "How bad the model is" A function that maps model parameters to a single number measuring prediction error, which optimization minimizes
Mean squared error "Average of squared errors" $\frac{1}{n} \sum (\text{predicted} - \text{actual})^2$, penalizing large errors disproportionately
Gradient descent "Walk downhill" Iteratively adjust parameters in the direction that reduces the cost function, using partial derivatives
Learning rate "Step size" A scalar that controls how much parameters change per gradient descent step
Normal equation "Solve it directly" The closed-form solution $w = (X^T X)^{-1} X^T y$ that gives optimal weights without iteration
R-squared "How good the fit is" The fraction of variance in $y$ explained by the model, ranging from negative infinity to 1.0
Feature scaling "Make features comparable" Transforming features to similar ranges (e.g., zero mean, unit variance) so gradient descent converges faster
Regularization "Penalize complexity" Adding a term to the cost function that shrinks weights, preventing overfitting
Ridge regression "L2 regularization" Linear regression with a penalty of $\lambda \sum w_i^2$ added to MSE
Polynomial regression "Fitting curves with linear math" Linear regression on polynomial features ($x, x^2, x^3, \ldots$), still linear in the weights
Overfitting "Memorizing training data" Using a model so complex that it fits noise in training data and fails on new data

The problem

In plain words first

Linear regression fits a straight line (or, with many inputs, a flat surface) through data so it can predict a number: prediction = w · x + b. "Best" means the line with the smallest mean squared error, the average of the squared gaps between predictions and true values. You can find it two ways: walk downhill on the error with gradient descent, or solve for it directly with the normal equation. Both should land in the same place.

You have data: house sizes and their sale prices. You want to predict the price of a new house given its size. You could eyeball it on a scatter plot, but you need a formula. You need a line that best fits the data so you can plug in any size and get a price prediction.

Linear regression gives you that line. More importantly, it introduces the entire ML training loop: define a model, define a cost function, optimize the parameters. Every ML algorithm follows this same pattern. Master it here with the simplest case, and you will recognize it everywhere.

This is not just for simple problems. Linear regression is used in production systems for demand forecasting, A/B test analysis, financial modeling, and as a baseline for every regression task.

Idea 1 · The Model

Linear regression assumes a linear relationship between input (x) and output (y):

y=wx+b

  • w (weight/slope): how much y changes when x increases by 1
  • b (bias/intercept): the value of y when x=0

For multiple inputs (features), this extends to:

y=w1​x1​+w2​x2​+⋯+wn​xn​+b

Or in vector form: y=wTx+b

The goal: find the values of w and b that make the predicted y as close as possible to the actual y across all training examples.

Idea 2 · The Cost Function (Mean Squared Error)

How do you measure "as close as possible"? You need a single number that captures how wrong your predictions are. The most common choice is Mean Squared Error (MSE):

MSE=n1​∑(ypredicted​−yactual​)2

Why squared? Two reasons. First, it penalizes large errors more than small errors (an error of 10 is 100x worse than an error of 1, not 10x). Second, the squared function is smooth and differentiable everywhere, which makes optimization straightforward.

The cost function creates a surface. For a single weight w and bias b, the MSE surface looks like a bowl (a convex paraboloid). The bottom of the bowl is where MSE is minimized. Training means finding that bottom.

Worked example
Worked by hand

Three points: (1, 5), (2, 7), (3, 12). Try the line y = 3x + 1: predictions 4, 7, 10, errors −1, 0, −2, squared 1, 0, 4, so MSE = 5/3 ≈ 1.67. Try y = 3.5x + 1: predictions 4.5, 8, 11.5, errors −0.5, 1, −0.5, squared 0.25, 1, 0.25, MSE = 1.5/3 = 0.5. The second line is better, and gradient descent finds the best one by repeatedly nudging w and b in the direction that lowers this number.

Idea 3 · Gradient Descent

Gradient descent finds the bottom of the bowl by taking steps downhill.

The gradients tell you two things: which direction to move each parameter, and how much to move.

For MSE with y^​=wx+b:

∂w∂MSE​∂b∂MSE​​=n2​∑(y^​−y)x=n2​∑(y^​−y)​

The update rule:

wb​=w−learning_rate⋅∂w∂MSE​=b−learning_rate⋅∂b∂MSE​​

The learning rate controls step size. Too large: you overshoot the minimum and diverge. Too small: training takes forever. Typical starting values: 0.01, 0.001, or 0.0001.

Idea 4 · The Normal Equation (Closed-Form Solution)

For linear regression specifically, there is a direct formula that gives the optimal weights without any iteration:

w=(XTX)−1XTy

This inverts a matrix to solve for w in one step. It works perfectly for small datasets. For large datasets (millions of rows or thousands of features), gradient descent is preferred because matrix inversion is O(n3) in the number of features.

Check your mental model
  • ✗ "Gradient descent and the normal equation can give different best lines."
    ✓ For linear regression the error surface is a single bowl, so they share one minimum. If they disagree, gradient descent has not finished: see the reading box in Step 2.
  • ✗ "Squared error is just a convention; absolute error would work the same."
    ✓ Squaring punishes big misses much more, makes the cost smooth (so gradients exist everywhere) and gives the closed-form solution. Absolute error is more robust to outliers but has neither of the last two properties.
  • ✗ "R² = 0.95 means 95 percent of predictions are correct."
    ✓ It means the model explains 95 percent of the variance of y around its mean. Predictions can still be off by a lot in absolute terms.

Idea 5 · Multiple Linear Regression

With multiple features, the model becomes:

y=w1​x1​+w2​x2​+⋯+wn​xn​+b

Everything works the same: MSE is the cost function, gradient descent updates all weights simultaneously. The only difference is that you are fitting a hyperplane instead of a line.

Feature scaling matters here. If one feature ranges from 0 to 1 and another ranges from 0 to 1,000,000, gradient descent will struggle because the cost surface becomes elongated. Standardize features (subtract mean, divide by standard deviation) before training.

Idea 6 · Polynomial Regression

What if the relationship is not linear? You can still use linear regression by creating polynomial features:

y=w1​x+w2​x2+w3​x3+b

This is still "linear" regression because the model is linear in the weights (w1​,w2​,w3​). You are just using nonlinear features of x.

Higher-degree polynomials can fit more complex curves but risk overfitting. A degree-10 polynomial will pass through every point in a 10-point dataset but predict poorly on new data.

Idea 7 · R-Squared Score

MSE tells you how wrong you are, but the number depends on the scale of y. R-squared (R2) gives a scale-independent measure:

R2​=1−sum of squared deviations from meansum of squared residuals​=1−SStot​SSres​​​

  • R2=1.0: perfect predictions
  • R2=0.0: the model is no better than predicting the mean every time
  • R2<0.0: the model is worse than predicting the mean

Idea 8 · Regularization Preview (Ridge Regression)

When you have many features, the model can overfit by assigning large weights. Ridge regression (L2 regularization) adds a penalty:

Cost=MSE+λ∑wi2​

The penalty term discourages large weights. The hyperparameter λ controls the tradeoff: higher λ means smaller weights and more regularization. This is covered in depth in a later lesson. For now, know that it exists and why it helps.

The same idea as a formula

Model and loss. y^​=Xw+b for n rows of d features; mean squared error J(w,b)=n1​∑i​(y^​i​−yi​)2.

Gradients. Differentiating the square,

∂w∂J​=n2​X⊤(y^​−y),∂b∂J​=n2​i∑​(y^​i​−yi​)

so gradient descent moves each weight against the correlation between its feature and the current errors.

Closed form. Folding b into w with a column of ones and setting the gradient to zero gives the normal equation

w∗=(X⊤X)−1X⊤y,ridge: w∗=(X⊤X+λI)−1X⊤y

It costs O(nd2+d3): instant for d in the hundreds, impossible for millions of features, where gradient descent takes over.

Fit quality. R2=1−∑(yi​−yˉ​)2∑(yi​−y^​i​)2​: 1 is perfect, 0 is no better than predicting the mean, and it can be negative on test data.

Polynomial regression is linear regression on features x,x2,…,xk: still linear in the weights, so the same formulas apply.

Step 2 · Linear regression from scratch with gradient descent

class LinearRegression:
    def __init__(self, learning_rate=0.01):
        self.w = 0.0
        self.b = 0.0
        self.lr = learning_rate
        self.cost_history = []

    def predict(self, X):
        return [self.w * x + self.b for x in X]

    def compute_cost(self, X, y):
        predictions = self.predict(X)
        n = len(y)
        cost = sum((pred - actual) ** 2 for pred, actual in zip(predictions, y)) / n
        return cost

    def compute_gradients(self, X, y):
        predictions = self.predict(X)
        n = len(y)
        dw = (2 / n) * sum((pred - actual) * x for pred, actual, x in zip(predictions, y, X))
        db = (2 / n) * sum(pred - actual for pred, actual in zip(predictions, y))
        return dw, db

    def fit(self, X, y, epochs=1000, print_every=200):
        for epoch in range(epochs):
            dw, db = self.compute_gradients(X, y)
            self.w -= self.lr * dw
            self.b -= self.lr * db
            cost = self.compute_cost(X, y)
            self.cost_history.append(cost)
            if epoch % print_every == 0:
                print(f"  Epoch {epoch:4d} | Cost: {cost:.4f} | w: {self.w:.4f} | b: {self.b:.4f}")
        return self

    def r_squared(self, X, y):
        predictions = self.predict(X)
        y_mean = sum(y) / len(y)
        ss_res = sum((actual - pred) ** 2 for actual, pred in zip(y, predictions))
        ss_tot = sum((actual - y_mean) ** 2 for actual in y)
        return 1 - (ss_res / ss_tot)

Step 3 · Normal equation (closed-form solution)

class LinearRegressionNormal:
    def __init__(self):
        self.w = 0.0
        self.b = 0.0

    def fit(self, X, y):
        n = len(X)
        x_mean = sum(X) / n
        y_mean = sum(y) / n
        numerator = sum((X[i] - x_mean) * (y[i] - y_mean) for i in range(n))
        denominator = sum((X[i] - x_mean) ** 2 for i in range(n))
        self.w = numerator / denominator
        self.b = y_mean - self.w * x_mean
        return self

    def predict(self, X):
        return [self.w * x + self.b for x in X]

    def r_squared(self, X, y):
        predictions = self.predict(X)
        y_mean = sum(y) / len(y)
        ss_res = sum((actual - pred) ** 2 for actual, pred in zip(y, predictions))
        ss_tot = sum((actual - y_mean) ** 2 for actual in y)
        return 1 - (ss_res / ss_tot)

Step 4 · Multiple linear regression

class MultipleLinearRegression:
    def __init__(self, n_features, learning_rate=0.01):
        self.weights = [0.0] * n_features
        self.bias = 0.0
        self.lr = learning_rate
        self.cost_history = []

    def predict_single(self, x):
        return sum(w * xi for w, xi in zip(self.weights, x)) + self.bias

    def predict(self, X):
        return [self.predict_single(x) for x in X]

    def compute_cost(self, X, y):
        predictions = self.predict(X)
        n = len(y)
        return sum((pred - actual) ** 2 for pred, actual in zip(predictions, y)) / n

    def fit(self, X, y, epochs=1000, print_every=200):
        n = len(y)
        n_features = len(X[0])
        for epoch in range(epochs):
            predictions = self.predict(X)
            errors = [pred - actual for pred, actual in zip(predictions, y)]
            for j in range(n_features):
                grad = (2 / n) * sum(errors[i] * X[i][j] for i in range(n))
                self.weights[j] -= self.lr * grad
            grad_b = (2 / n) * sum(errors)
            self.bias -= self.lr * grad_b
            cost = self.compute_cost(X, y)
            self.cost_history.append(cost)
            if epoch % print_every == 0:
                print(f"  Epoch {epoch:4d} | Cost: {cost:.4f}")
        return self

    def r_squared(self, X, y):
        predictions = self.predict(X)
        y_mean = sum(y) / len(y)
        ss_res = sum((actual - pred) ** 2 for actual, pred in zip(y, predictions))
        ss_tot = sum((actual - y_mean) ** 2 for actual in y)
        return 1 - (ss_res / ss_tot)

Step 5 · Polynomial regression

class PolynomialRegression:
    def __init__(self, degree, learning_rate=0.01):
        self.degree = degree
        self.weights = [0.0] * degree
        self.bias = 0.0
        self.lr = learning_rate

    def make_features(self, X):
        return [[x ** (d + 1) for d in range(self.degree)] for x in X]

    def predict(self, X):
        features = self.make_features(X)
        return [sum(w * f for w, f in zip(self.weights, row)) + self.bias for row in features]

    def fit(self, X, y, epochs=1000, print_every=200):
        features = self.make_features(X)
        n = len(y)
        for epoch in range(epochs):
            predictions = [sum(w * f for w, f in zip(self.weights, row)) + self.bias for row in features]
            errors = [pred - actual for pred, actual in zip(predictions, y)]
            for j in range(self.degree):
                grad = (2 / n) * sum(errors[i] * features[i][j] for i in range(n))
                self.weights[j] -= self.lr * grad
            grad_b = (2 / n) * sum(errors)
            self.bias -= self.lr * grad_b
            if epoch % print_every == 0:
                cost = sum(e ** 2 for e in errors) / n
                print(f"  Epoch {epoch:4d} | Cost: {cost:.6f}")
        return self

    def r_squared(self, X, y):
        predictions = self.predict(X)
        y_mean = sum(y) / len(y)
        ss_res = sum((actual - pred) ** 2 for actual, pred in zip(y, predictions))
        ss_tot = sum((actual - y_mean) ** 2 for actual in y)
        return 1 - (ss_res / ss_tot)

Step 6 · Ridge regression (L2 regularization)

class RidgeRegression:
    def __init__(self, n_features, learning_rate=0.01, alpha=1.0):
        self.weights = [0.0] * n_features
        self.bias = 0.0
        self.lr = learning_rate
        self.alpha = alpha

    def predict_single(self, x):
        return sum(w * xi for w, xi in zip(self.weights, x)) + self.bias

    def predict(self, X):
        return [self.predict_single(x) for x in X]

    def fit(self, X, y, epochs=1000, print_every=200):
        n = len(y)
        n_features = len(X[0])
        for epoch in range(epochs):
            predictions = self.predict(X)
            errors = [pred - actual for pred, actual in zip(predictions, y)]
            mse = sum(e ** 2 for e in errors) / n
            reg_term = self.alpha * sum(w ** 2 for w in self.weights)
            cost = mse + reg_term
            for j in range(n_features):
                grad = (2 / n) * sum(errors[i] * X[i][j] for i in range(n))
                grad += 2 * self.alpha * self.weights[j]
                self.weights[j] -= self.lr * grad
            grad_b = (2 / n) * sum(errors)
            self.bias -= self.lr * grad_b
            if epoch % print_every == 0:
                print(f"  Epoch {epoch:4d} | Cost: {cost:.4f} | L2 penalty: {reg_term:.4f}")
        return self


print("\n=== Ridge Regression (L2 Regularization) ===")
print("Same data as multiple regression, with alpha=0.1")
ridge = RidgeRegression(n_features=3, learning_rate=0.01, alpha=0.1)
ridge.fit(X_scaled, y_scaled, epochs=1000, print_every=200)
print(f"\nRidge weights: {[round(w, 4) for w in ridge.weights]}")
print(f"Plain weights: {[round(w, 4) for w in multi_model.weights]}")
print("Ridge weights are smaller (shrunk toward zero) due to the L2 penalty.")

Recap
What to keep from this lesson
  • Linear regression predicts w · x + b; training minimises mean squared error.
  • Gradient descent and the normal equation reach the same minimum; the normal equation is exact but needs a matrix solve, gradient descent scales to big data.
  • Feature scale controls how fast gradient descent converges and how large a learning rate it tolerates.
  • Polynomial features fit curves with the same machinery; more degree means more risk of overfitting.
  • Ridge adds an L2 penalty that shrinks weights and stabilises the solution.

Solutions

SolutionP1 · Just below the edge

0.03 converges (its cost first jumps to about 495, then falls steadily); 0.035 blows up. For mean squared error the steepest curvature is about 2 × mean(x²), around 63 here because x runs up to 10, and gradient descent is stable only when the learning rate is below 2 divided by that curvature, about 0.0316. Scale x to unit variance and the limit rises to about 1.

SolutionB1 · Divergence

The cost explodes: about 880, then 14,500, 242,000, 4 million, 67 million. Each step overshoots the minimum by more than it corrected, so the weights swing further out every epoch until they overflow. The cure is a smaller learning rate or, better, standardised inputs.

easy20 minimplement

Linear regression predicts a number as a weighted sum of the features plus a bias. Gradient descent finds the weights. It computes the gradient of the mean squared error and takes a small step against it, again and again. The same loop trains every model later in the course.

Task

Write four functions.

  1. predict(X, w, b) returns the prediction y^​=Xw+b for each row of X.
  2. compute_cost(X, y, w, b) returns the mean squared error J=n1​∑i​(y^​i​−yi​)2.
  3. compute_gradients(X, y, w, b) returns the pair (dw, db). Here dw=n2​X⊤(y^​−y) and db=n2​∑i​(y^​i​−yi​).
  4. fit(X, y, learning_rate, epochs) runs batch gradient descent and returns (w, b, cost_history).

The rules for fit:

  • Start with w as a vector of zeros and b = 0.0.
  • In each epoch, compute dw and db from the current w and b. Then update both: w←w−ηdw and b←b−ηdb, where η is learning_rate.
  • After the update, append the cost of the new w and b to cost_history.

Input and output

Name Type Shape Meaning
X float array (n, d) one row of d features for each of the n samples
y float array (n,) the target of each sample
w float array (d,) the weights
b float scalar the bias
learning_rate float scalar the step size η, 0 or more
epochs int scalar the number of updates, 0 or more
  • predict returns a float array of shape (n,).
  • compute_cost returns a Python float.
  • compute_gradients returns a tuple: a float array dw of shape (d,) and a float db.
  • fit returns a tuple: a float array w of shape (d,), a float b and a list of epochs floats.

Constraints

  • 1 <= n <= 1000 and 1 <= d <= 50.
  • 0 <= epochs <= 5000.
  • Do not change the input arrays.
  • Use numpy only. Do not use a closed form solution such as np.linalg.lstsq in fit.

Your code
Common mistakes the checks catch
  • Computes db but never updates the bias, so b stays at 0.
  • Uses target minus prediction as the error, so the gradients point uphill.
  • Appends the cost before the update, so the history is one step behind.
  • Drops the factor of 2 from both gradients, so they are half the true gradient.
  • Updates w first and then computes db at the new w, so the bias step uses the wrong point.
Hint 1

Compute the errors once: predict(X, w, b) - y. The cost and both gradients use this vector of shape (n,).

Hint 2

X.T @ errors gives one sum for each feature. Each sum is the error of a sample times the value of that feature, added over all samples. Multiply by 2 / n to get dw.

Hint 3

The bias acts like a feature that is always 1. So db is 2 / n times the plain sum of the errors.

Hint 4

In fit, compute both gradients before you change w or b. If you update w first and then compute db, the bias step uses the wrong point. Append the cost only after both updates.

Reference solution and notes
import numpy as np


def predict(X, w, b):
    return X @ w + b


def compute_cost(X, y, w, b):
    errors = predict(X, w, b) - y
    return float(np.mean(errors ** 2))


def compute_gradients(X, y, w, b):
    n = len(y)
    errors = predict(X, w, b) - y
    dw = (2 / n) * (X.T @ errors)
    db = (2 / n) * float(np.sum(errors))
    return dw, db


def fit(X, y, learning_rate, epochs):
    w = np.zeros(X.shape[1])
    b = 0.0
    cost_history = []
    for _ in range(epochs):
        dw, db = compute_gradients(X, y, w, b)
        w = w - learning_rate * dw
        b = b - learning_rate * db
        cost_history.append(compute_cost(X, y, w, b))
    return w, b, cost_history

Why the gradient has a factor of 2

The cost is a mean of squares. The derivative of (y^​i​−yi​)2 with respect to y^​i​ is 2(y^​i​−yi​). The chain rule then multiplies by xij​ for weight j and by 1 for the bias. Some texts define the cost with a factor of 21​ so that the 2 cancels. Both choices are correct, but the gradient must match the cost that you compute.

Why the update is simultaneous

Gradient descent takes one step from one point. Both gradients describe the slope at that point. If you update w and then compute db at the new w, you take a step from a mix of two points. The loop still often converges, but it is a different algorithm and its path is not the gradient path.

The learning rate

For this cost, the step is stable when η is less than 1/λmax​, where λmax​ is the largest eigenvalue of n1​X⊤X with a column of ones added. A larger step makes the cost grow at each epoch. Standardize the features first, as the lesson does, so that one learning rate works for all weights.

# Regression Strategy Guide

Regression predicts continuous values. The right approach depends on the relationship between features and target, the number of features, and the risk of overfitting.

## Decision Checklist

1. Is the relationship between features and target approximately linear?
   - Yes: start with ordinary linear regression
   - No: try polynomial features or a nonlinear model

2. How many features do you have relative to samples?
   - Few features, many samples: ordinary linear regression works fine
   - Many features, few samples: use regularization (Ridge or Lasso)
   - More features than samples: Lasso (L1) to select features, or Ridge (L2) to shrink all weights

3. Do you need interpretability?
   - Yes: linear regression with few features, or Lasso for automatic feature selection
   - No: polynomial features, or move to tree-based models or neural networks

4. Is your dataset small (under 10,000 rows)?
   - Use the normal equation (closed-form solution) for speed
   - Cross-validation is essential for reliable evaluation

5. Is your dataset large (millions of rows)?
   - Use stochastic gradient descent (SGD) or mini-batch gradient descent
   - The normal equation is too slow due to O(n^3) matrix inversion

## When to use each approach

**Ordinary Linear Regression**: baseline for any regression task. Start here. If R-squared is acceptable and the model is simple, stop here.

**Polynomial Regression**: the scatter plot shows a curve, not a line. Start with degree 2. Increase only if justified by validation performance. Degree > 5 almost always overfits.

**Ridge Regression (L2)**: many correlated features. All weights shrink toward zero but none become exactly zero. Good when you believe all features contribute.

**Lasso Regression (L1)**: many features and you suspect only a few matter. Lasso drives irrelevant feature weights to exactly zero, performing automatic feature selection.

**Elastic Net**: combines L1 and L2 penalties. Use when you have many correlated features and want some feature selection.

## Common mistakes

- Skipping feature scaling before gradient descent (convergence becomes extremely slow)
- Using test set performance to tune hyperparameters (use validation set or cross-validation)
- Fitting high-degree polynomials without checking validation error (training R^2 always increases with degree)
- Ignoring residual plots (R^2 can be misleading if residuals show patterns)
- Treating R^2 as the only metric (check residual distribution, MAE, and domain-specific thresholds)

## Quick reference

| Method | When to use | Regularization | Feature selection |
|--------|------------|---------------|-------------------|
| OLS | Baseline, few features | None | Manual |
| Ridge | Many features, all relevant | L2 (shrink) | No |
| Lasso | Many features, few relevant | L1 (zero out) | Automatic |
| Elastic Net | Many correlated features | L1 + L2 | Partial |
| Polynomial | Nonlinear relationship | Add Ridge/Lasso on top | Manual degree choice |

Explain the mechanismA regression report shows a negative R-squared on the test set. A teammate says the metric code must be broken, because R-squared lives between 0 and 1. How do you answer?

Level 1 of 4 · about 5 minutes to answer well.

Short answer. R-squared is one minus the ratio of the residual sum of squares to the total sum of squares around the mean. It is 1 for a perfect fit, 0 for a model that only predicts the mean, and below zero when the model does worse than that constant. A negative value is a real result, and it says the fitted model hurts on this data.

The formula.

R-squared = 1 - SS_res / SS_tot
SS_res = sum of (y_true - y_pred)^2
SS_tot = sum of (y_true - y_mean)^2

The total sum of squares is the error of the simplest model: predict the mean every time. When the model's residuals are larger than that, the ratio is above 1 and the metric goes negative. There is no lower bound.

How it happens on a test set.

The model was fit on the training set. On the test set, a model that overfit the training data, or data whose distribution moved, can give predictions that are further from the targets than the test mean. The evaluation lesson prints a mean baseline next to the model for this reason, and a model must beat it. That baseline uses the mean of the training targets. It scores near 0 only when the test mean is close to the training mean, and below 0 when the two means differ.

What to do with the number.

  1. Compare with the training R-squared. A high training value and a negative test value points at overfitting or a shift between the two sets.
  2. Check the split. A time series shuffled before the split, or a scaler fit on all the data, gives a very different pair of numbers.
  3. Report RMSE and MAE next to it. RMSE is in the units of the target. R-squared is a scale free fraction of the variance. Each answers a different question.

Plausible wrong answers.

  • "R-squared cannot be negative, so the code has a bug." The formula has no lower bound. A model that predicts worse than the mean gives a negative value.
  • "Negative means the slope is negative." R-squared compares residuals with the variance around the mean. It carries no sign of a slope.
  • "Clip it to zero in the report." That hides the fact that the mean would beat the model.

Follow-ups an interviewer may ask.

  • (level 1) What value does a model that predicts the training mean get on the test set? Expected: near 0 when the test mean is close to the training mean, because the residual and total sums are almost the same; below 0 when the two means differ.
  • (level 2) Training R-squared is high and the test value is negative. What does the gap say? Expected: the model fit the training data and does not transfer; suspect overfitting or a shift between the sets.
  • (level 2) Why report R-squared next to RMSE? Expected: RMSE is in the units of the target and shows the size of a typical error; R-squared is a fraction of variance and has no units.
  • (level 3) The target has a heavy tail. What else do you check? Expected: MAE next to MSE, because squared errors let a few outliers dominate both MSE and R-squared.

Check your understanding

Q1What does the learning rate control in gradient descent?

The learning rate is a scalar that controls how much weights change per gradient descent step. Too large causes divergence, too small causes slow convergence.

Q2What does R-squared = 0 mean for a regression model?

R-squared = 0 means the model explains none of the variance in the target. It performs exactly as well as simply predicting the mean every time.

Q3Why is feature scaling important for gradient descent in multiple linear regression?

When features have very different scales, the cost surface becomes elongated. Gradient descent takes many more steps to converge. Standardizing features makes the surface more spherical.

Q4The normal equation gives optimal weights directly. Why would you prefer gradient descent instead?

The normal equation requires inverting X^T * X, which is O(n^3) in the number of features. For large feature counts, gradient descent is more efficient.

Q5A degree-10 polynomial regression model fits training data perfectly (R^2 = 1.0) but has R^2 = 0.3 on test data. What should you do?

Perfect training fit with poor test fit is overfitting. The fix is to reduce complexity (lower polynomial degree) or add regularization to penalize large weights.
