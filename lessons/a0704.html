In plain words first
The idea in one line

Attention is permutation-invariant. "The cat sat on the mat" and "mat the on sat cat the" produce the same output without positional signal. Three algorithms fix it — each with a different bet on what "position" means.

Terms you'll hear
Term What people say What it actually means
Positional encoding "Tells attention about order" Any signal added to embeddings or attention that encodes position.
Sinusoidal "The original one" sin/cos at geometric frequencies added to embeddings; doesn't extrapolate.
RoPE "Rotary embeddings" Rotate Q, K by position-dependent angle; dot product encodes relative distance.
ALiBi "Linear bias trick" Add $-m \cdot \lvert i-j \rvert$ to attention scores; no embedding needed, great extrapolation.
base "RoPE's knob" The frequency scaler in RoPE; increase to extend context at inference.
NTK-aware "A RoPE scaling trick" Rescale base so high-frequency dims aren't squeezed when context expands.
YaRN "The fancy one" Per-dimension interpolation+extrapolation that preserves attention entropy.
Extrapolation "Works beyond trained length" Can the position scheme serve correct output past max_len seen in training?

The problem

In plain words first

Attention compares every word with every other word, but nothing in that comparison says which word came first, so "dog bites man" and "man bites dog" look alike to it. Position has to be added. The original transformer added a fixed pattern of sine waves to each word's vector. Almost every current open model instead uses RoPE: it turns each query and key by an angle that grows with the word's position, so that when two of them are compared, only the distance between them matters. A third method, ALiBi, simply subtracts a penalty that grows with distance. The choice decides how a model copes with texts longer than any it was trained on. This lesson shows that attention without positions really is order-blind, reads the real RoPE settings of Llama, Qwen, gpt-oss and DeepSeek from their configuration files, and runs a small RoPE model on text twice as long as its training length, with and without the stretching methods production models use. Nothing is trained.

Scaled dot-product attention is order-blind. The attention matrix softmax(Q K^T / √d) V is computed from pairwise similarities. Shuffle the rows of X, get the rows of the output shuffled the same way. Nothing inside attention cares about position.

That is not a bug in a bag-of-words model. For language, code, audio, video — anything where order carries meaning — it is fatal.

The fix is to inject position into the embeddings somehow. Three eras of answers:

  1. Absolute sinusoidal (Vaswani 2017). Add sin/cos of position to the embedding. Simple, learnable-free, extrapolates poorly beyond trained lengths.
  2. RoPE — Rotary Position Embeddings (Su 2021). Rotate Q and K vectors by an angle proportional to position. Encodes relative position directly in the dot product. Dominant in 2026.
  3. ALiBi — Attention with Linear Biases (Press 2022). Skip embeddings entirely; add a per-head linear penalty to attention scores based on distance. Excellent length extrapolation.

As of 2026, essentially every frontier open model uses RoPE: Llama 2/3/4, Qwen 2/3, Mistral, Mixtral, DeepSeek-V3, Kimi. A handful of long-context models use ALiBi or its modern variants. Absolute sinusoidal is historical.

Order-blindness, measured

A two-head attention layer with no positional information, given six random token vectors and the same vectors shuffled.

import torch
torch.manual_seed(0)
# Attention with no positional signal: shuffle the input rows, and the output rows are shuffled the same way.
n, d = 6, 16
x = torch.randn(1, n, d)
perm = torch.randperm(n)
mha = torch.nn.MultiheadAttention(d, 2, batch_first=True)
with torch.no_grad():
    y, _ = mha(x, x, x)
    y_perm, _ = mha(x[:, perm], x[:, perm], x[:, perm])
    print(f"bidirectional attention: output of shuffled input vs shuffled output, max difference {(y_perm - y[:, perm]).abs().max():.1e}")
    mask = torch.nn.Transformer.generate_square_subsequent_mask(n)
    y, _ = mha(x, x, x, attn_mask=mask)
    y_perm, _ = mha(x[:, perm], x[:, perm], x[:, perm], attn_mask=mask)
    print(f"causal attention:        same test, max difference {(y_perm - y[:, perm]).abs().max():.1e}")

Reading this output

Without a mask, shuffling the input just shuffles the output (difference 6×10−8, rounding error): attention cannot tell the orders apart. With a causal mask it can, because each token sees a different number of predecessors, so the output changes (difference 0.81). That is why decoder-only models trained with no positional encoding at all ("NoPE") still learn some sense of order; encoders get none without one.

The idea

Idea 1 · Absolute sinusoidal

Pre-compute a fixed matrix PE of shape (max_len, d_model):

PE(pos,2i)​PE(pos,2i+1)​​=sin(pos/100002i/dmodel​)=cos(pos/100002i/dmodel​)​

Then X' = X + PE[:N] before attention. Each dimension is a sinusoid at a different frequency. The model learns to read position from the phase pattern. Fails beyond max_len: nothing told the model what happens at position 2048 when it only saw positions 0–2047.

Idea 2 · RoPE

Rotate the Q and K vectors (not embeddings). For a pair of dimensions (2i,2i+1):

[q2i′​q2i+1′​​]=[cos(pos⋅θi​)sin(pos⋅θi​)​−sin(pos⋅θi​)cos(pos⋅θi​)​][q2i​q2i+1​​]θi​=base−2i/dhead​,base=10000 by default

Apply the same rotation to keys with position pos_k. The dot product qm′​⋅kn′​ becomes a function of (m−n) alone. That is: the attention score depends only on the relative distance, even though the rotation was keyed off absolute positions. Beautiful trick.

Extending RoPE: base can be scaled (NTK-aware, YaRN, LongRoPE) to extrapolate to longer contexts without retraining. Llama 3.1 extended its context from 8K to 128K with rescaled RoPE frequencies plus continued training on long documents.

Idea 3 · ALiBi

Skip the embedding trick. Bias the attention scores directly:

attn_score[i,j]=d​qi​⋅kj​​−mh​⋅∣i−j∣

Where mh​ is a head-specific slope (e.g. 1/28h/H). Closer tokens get boosted; far tokens get penalized. No training-time cost. The paper shows length extrapolation beats sinusoidal and matches RoPE on its original trained length.

Idea 4 · What to pick in 2026

Variant Extrapolation Training cost Used by
Absolute sinusoidal poor free original transformer, early BERT
Learned absolute none tiny GPT-2, GPT-3
RoPE good with scaling free Llama 2/3/4, Qwen 2/3, Mistral, DeepSeek-V3, Kimi
RoPE + YaRN excellent fine-tune stage DeepSeek-V3, gpt-oss, Qwen2.5 long-context models
RoPE + "llama3" scaling excellent fine-tune stage Llama 3.1, 3.2, 3.3 (128K)
ALiBi excellent free BLOOM, MPT, Baichuan

RoPE won because it slots into attention without changing the architecture, encodes relative position, and its base hyperparameter gives a clean knob for long-context fine-tuning.

The same idea as a formula

Sinusoidal. PEpos,2i​=sin(posωi​), PEpos,2i+1​=cos(posωi​) with ωi​=10000−2i/d, added to the embedding. Since sin and cos of (pos+k)ω are a fixed rotation of those at posω, a linear map can read relative offsets, but nothing forces the model to.

RoPE. Treat each pair of query coordinates as a complex number q(i)=q2i​+iq2i+1​ and rotate it: q~​m(i)​=q(i)eimθi​, likewise for keys at position n, with θi​=b−2i/d for base b. Then

Re[i∑​q~​m(i)​k~n(i)​​]=Re[i∑​q(i)k(i)ei(m−n)θi​]

depends on m and n only through m−n. Pair i turns once every 2π/θi​ tokens: the first pairs every few tokens (fine position), the last ones over hundreds of thousands (coarse position).

ALiBi. sij​=qi​⋅kj​/d​−mh​(i−j) for j≤i, with head slopes mh​=2−8h/H.

Extending RoPE. Position interpolation divides every angle by the factor s (positions are squeezed); NTK-aware scaling raises the base, b′=bsd/(d−2), which barely changes fast pairs and slows the slow ones; YaRN and Llama 3's scheme slow only the pairs whose wavelength exceeds the training length, leaving the fast pairs exactly as trained.

Worked example
RoPE angles by hand

Head size d=4, base 10,000: two pairs with θ0​=1 and θ1​=10000−1/2=0.01 radians per token.

  • At position 3, pair 0 turns by 3 rad (172°), pair 1 by 0.03 rad (1.7°).
  • Pair 0 completes a turn every 2π≈6.3 tokens, pair 1 every 628 tokens.
  • Query at 3 and key at 1 (gap 2): pair-0 contribution ∝cos(2); query at 103 and key at 101: the same cos(2).
  • A model trained only on 512-token texts has never seen pair 1 turn more than 0.81 of a circle; at position 2,000 it would see angles it never trained on, the failure the scaling methods fix.

Step 1 · sinusoidal encoding

See code/main.py. A 4-line computation:

def sinusoidal(N, d):
    pe = [[0.0] * d for _ in range(N)]
    for pos in range(N):
        for i in range(d // 2):
            theta = pos / (10000 ** (2 * i / d))
            pe[pos][2 * i]     = math.sin(theta)
            pe[pos][2 * i + 1] = math.cos(theta)
    return pe

Add this to the embedding matrix before the first attention layer.

Step 2 · RoPE applied to Q, K

RoPE operates in-place on Q and K. For each pair of dims:

def apply_rope(x, pos, base=10000):
    d = len(x)
    out = list(x)
    for i in range(d // 2):
        theta = pos / (base ** (2 * i / d))
        c, s = math.cos(theta), math.sin(theta)
        a, b = x[2 * i], x[2 * i + 1]
        out[2 * i]     = a * c - b * s
        out[2 * i + 1] = a * s + b * c
    return out

Crucial: apply the same function to Q at position m and K at position n. Their dot product picks up a cos((m−n)⋅θi​) factor on every coordinate pair. Attention learns relative position for free.

Step 3 · ALiBi slopes and bias

def alibi_bias(n_heads, seq_len):
    # slope_h = 2 ** (-8 * h / n_heads) for h = 1..n_heads
    slopes = [2 ** (-8 * (h + 1) / n_heads) for h in range(n_heads)]
    bias = []
    for m in slopes:
        row = [[-m * abs(i - j) for j in range(seq_len)] for i in range(seq_len)]
        bias.append(row)
    return bias  # add to attention scores before softmax

Add bias[h] to the (seq_len, seq_len) attention score matrix of head h, then softmax.

Step 4 · verify relative-distance property of RoPE

Pick two random vectors a, b. Rotate by (pos_a, pos_b). Then by (pos_a + k, pos_b + k). Both dot products must match within floating-point error. That property is the whole point of RoPE — it is invariant to the absolute offset, only the relative gap matters.

The RoPE table is the property of the formula box: four very different absolute positions, one gap of 2, identical scores to six decimals. Use it: the same idea with real libraries

PyTorch itself has no RoPE function; model code applies it (Hugging Face transformers implements every variant in modeling_rope_utils.py, and torchtune has a RotaryPositionalEmbeddings module), and serving engines such as vLLM fuse it into their kernels. Long-context tricks in 2026:

  • NTK-aware interpolation. Rescale base to base * (scale_factor)^(d/(d-2)) when extending from 4K to 16K+.
  • YaRN. Interpolates the slow dimensions, leaves the fast ones alone and rescales attention temperature. DeepSeek-V3 and gpt-oss use it; Llama 3.1 uses a related frequency-dependent scheme ("llama3").
  • LongRoPE. Microsoft's 2024 method that uses evolutionary search to pick per-dimension scale factors. Phi-3-Long uses it.
  • Position interpolation + fine-tuning. Just shrink positions by the extension factor and fine-tune for 1–5B tokens. Surprisingly effective.

Llama 3's real rotation speeds, and how it stretched them

The 64 dimension pairs of a Llama 3.2 head: their wavelengths with base 500,000, which of them never complete a turn within the 8,192-token training length, and the slow-down factors that Llama's "llama3" scaling (from transformers) applies to reach 131,072 tokens.

import numpy as np, torch
import matplotlib.pyplot as plt
from transformers import AutoConfig
from transformers.modeling_rope_utils import ROPE_INIT_FUNCTIONS
# Llama 3.2 3B's real RoPE settings: base 500,000, head size 128, trained at 8,192 tokens, extended to 131,072.
cfg = AutoConfig.from_pretrained("unsloth/Llama-3.2-3B")
d_head = cfg.hidden_size // cfg.num_attention_heads
theta = cfg.rope_parameters["rope_theta"]
base_freq = 1.0 / theta ** (np.arange(0, d_head, 2) / d_head)               # the 64 rotation speeds
scaled_freq, _ = ROPE_INIT_FUNCTIONS["llama3"](cfg, "cpu")                  # what Llama actually uses
wavelength = 2 * np.pi / base_freq
orig = cfg.rope_parameters["original_max_position_embeddings"]
print(f"head size {d_head}, base {theta:,.0f}: wavelengths from {wavelength.min():.1f} to {wavelength.max():,.0f} tokens")
print(f"{(wavelength > orig).sum()} of {len(wavelength)} pairs never complete one turn within the {orig:,} training tokens")
ratio = base_freq / scaled_freq.numpy()
print(f"llama3 scaling: {(ratio < 1.01).sum()} fast pairs unchanged, {(ratio > 31.9).sum()} slow pairs slowed 32x, "
      f"{((ratio >= 1.01) & (ratio <= 31.9)).sum()} in between")
fig, ax = plt.subplots(figsize=(7, 3.4))

ax.set_title("Llama 3's RoPE extension: only the slow pairs are stretched", fontsize=10); plt.tight_layout()
# The relative-distance property, on Llama's real frequencies: shifting both positions changes nothing.
rng = np.random.default_rng(0)
q, k = rng.normal(size=d_head), rng.normal(size=d_head)
def rope(x, pos, freq):
    a, b = x[0::2], x[1::2]; c, s = np.cos(pos * freq), np.sin(pos * freq)
    out = np.empty_like(x); out[0::2] = a * c - b * s; out[1::2] = a * s + b * c
    return out
f = scaled_freq.double().numpy()
s1 = rope(q, 1000, f) @ rope(k, 990, f); s2 = rope(q, 90_000, f) @ rope(k, 89_990, f)

Reading past the training length

SmolLM-135M (RoPE, base 10,000, trained on 2,048-token sequences) on 4,096 tokens of WikiText-103, with four position settings and no training: none, linear position interpolation, dynamic NTK and YaRN, each with factor 2.

from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, AutoConfig
torch.set_num_threads(2)
repo = "HuggingFaceTB/SmolLM-135M"                       # RoPE, trained with 2,048-token sequences
tok = AutoTokenizer.from_pretrained(repo)
wiki = load_dataset("Salesforce/wikitext", "wikitext-103-raw-v1", split="test")
text = "".join(wiki["text"][:3000])
ids = tok(text, return_tensors="pt").input_ids[:, :4096]
print(f"{ids.shape[1]} tokens of WikiText; trained context {AutoConfig.from_pretrained(repo).max_position_embeddings}")
def nll_by_position(rope_scaling):
    cfg = AutoConfig.from_pretrained(repo)
    cfg.rope_parameters = {"rope_theta": 10000.0, "rope_type": "default", **(rope_scaling or {})}
    m = AutoModelForCausalLM.from_pretrained(repo, config=cfg, dtype=torch.float32).eval()
    with torch.no_grad():
        logits = m(ids).logits[0, :-1]
    return torch.nn.functional.cross_entropy(logits, ids[0, 1:], reduction="none").numpy()

Reading this output

Unchanged, the model is fine up to its training length (2.50 nats per token) and falls apart after it (6.47): the plot shows the loss jumping at token 2,048, where the slow pairs reach angles never seen in training. Linear interpolation repairs the far half (3.50) but damages the near half (3.75), because every position, including the trained ones, is squeezed into unfamiliar angles; it needs fine-tuning to work well. Dynamic NTK and YaRN mostly stretch the slow pairs, so the first half is almost unchanged (2.60 and 2.53) and the second half reaches about 2.9 without any training. The remaining gap (2.9 against 2.5) is why production long-context releases also continue training on long documents.

Break it on purpose

In apply_rope, rotate the query by its position but forget to rotate the key (k_rot = k). The code still runs and scores still come out. What property is lost, and what would a trained model see? (Solution B1.)

Industry practice
What's current (2024–2026)
  • RoPE is the production default. Llama 3, Qwen2.5 and Qwen3, Mistral, Gemma 3, DeepSeek-V3, Kimi K2 and gpt-oss all use it, usually with a large base (500,000 for Llama 3, 1,000,000 for Qwen2.5) and a frequency-scaling scheme for 128K-plus contexts.
  • Scaling schemes in configs. YaRN (DeepSeek-V3, gpt-oss, Qwen's long-context releases) and Llama's "llama3" scaling are set in config.json and applied by transformers, vLLM and llama.cpp; serving a longer context than the release supports usually means setting rope_scaling explicitly.
  • Mixed layers. Some models leave RoPE out of a few layers (Llama 4's interleaved "NoPE" layers) or use different bases for local and global layers (Gemma 3), to help long-context recall.

Sources: RoFormer, YaRN, transformers RoPE utilities, Gemma 3 report, Llama 4 announcement, vLLM supported models.

Recap
What to keep from this lesson
  • Attention alone is order-blind (a causal mask leaks some order).
  • RoPE rotates queries and keys so scores depend only on distance; its pairs turn at speeds from a few tokens to millions.
  • Past the training length, unseen angles break the model; interpolation, NTK, YaRN and llama3 scaling stretch the slow pairs, and long-context releases also continue training.
  • The position scheme is part of the config: read it before serving a model.

medium25 minimplement

Rotary position embedding (RoPE) puts the position of a token into its query and key vectors. It turns each pair of coordinates by an angle that grows with the position. Then the attention score of a query and a key depends only on the distance between their positions. Most open language models use RoPE.

Task

Write two functions.

  1. rope_frequencies(d, base=10000.0) returns the frequency of each coordinate pair.
  2. apply_rope(x, positions, base=10000.0) returns a rotated copy of x.

The frequency of pair i is θi​=base−2i/d, for i=0,1,…,⌊d/2⌋−1.

Pair i is the two adjacent coordinates 2i and 2i + 1. For the token at position p, let a=x2i​, b=x2i+1​ and ϕ=pθi​. The output pair is:

a′=acosϕ−bsinϕ,b′=asinϕ+bcosϕ

When d is odd, the last coordinate has no partner. Copy it to the output without a change.

  • Do not change the input arrays.
  • Use numpy only.

Reference solution and notes
import numpy as np


def rope_frequencies(d, base=10000.0):
    i = np.arange(d // 2)
    return 1.0 / (base ** (2 * i / d))


def apply_rope(x, positions, base=10000.0):
    x = np.asarray(x, dtype=float)
    d = x.shape[-1]
    half = d // 2
    theta = np.asarray(positions, dtype=float)[:, None] * rope_frequencies(d, base)[None, :]
    c = np.cos(theta)
    s = np.sin(theta)
    a = x[..., 0:2 * half:2]
    b = x[..., 1:2 * half:2]
    out = x.copy()
    out[..., 0:2 * half:2] = a * c - b * s
    out[..., 1:2 * half:2] = a * s + b * c
    return out

Why the score depends on the gap only

Each pair is a point in a plane. RoPE turns the query pair by mθi​ and the key pair by nθi​. The dot product of two points in a plane depends on their lengths and on the angle between them. The angle between the turned points changes by (m−n)θi​. So the score sees only the gap m−n. The model gets relative positions, but each token needs only its own absolute position.

Why the norm stays the same

A rotation matrix is orthogonal. It keeps the length of every pair. So RoPE does not change the size of the scores. It changes only their direction.

The pairing convention

This lesson pairs adjacent coordinates (2i, 2i+1). Some libraries pair coordinate i with i + d/2. Both conventions give the relative property. But the weights of a trained model expect one convention. If you load weights with the other convention, the model gives wrong outputs and no error appears.

Where this goes next

The full transformer lesson applies RoPE to the queries and keys of each head before the attention scores. Long context methods change the base or scale the positions, so that the slow pairs do not wrap past a full turn.

Attention does not see the order of the tokens. The original transformer adds a fixed table of sines and cosines to the token embeddings. Each row of the table is the code of one position, and each pair of columns turns at its own frequency.

Task

Write two functions.

  1. sinusoidal_pe(max_len, d_model, base=10000.0) returns the table of shape (max_len, d_model).
  2. add_positional_encoding(x, base=10000.0) returns x plus the table for its sequence length.

For position p=0,1,…,max_len−1 and pair i=0,1,…,⌊d/2⌋−1, with d = d_model:

PE[p,2i]=sin(p/base2i/d),PE[p,2i+1]=cos(p/base2i/d)

The sin and the cos of one pair are in adjacent columns. When d_model is odd, the last column has no pair. It stays 0. The exponent still divides by d_model.

add_positional_encoding adds row t of the table to the vector of token t. The tokens are on the second to last axis of x. Every leading axis gets the same table.

Reference solution and notes
import numpy as np


def sinusoidal_pe(max_len, d_model, base=10000.0):
    pe = np.zeros((max_len, d_model))
    half = d_model // 2
    pos = np.arange(max_len)[:, None]
    i = np.arange(half)[None, :]
    theta = pos / (base ** (2 * i / d_model))
    pe[:, 0:2 * half:2] = np.sin(theta)
    pe[:, 1:2 * half:2] = np.cos(theta)
    return pe


def add_positional_encoding(x, base=10000.0):
    x = np.asarray(x, dtype=float)
    T, d = x.shape[-2], x.shape[-1]
    return x + sinusoidal_pe(T, d, base)

Why sines and cosines

Pair i is a point on the unit circle at the angle pωi​, with ωi​=base−2i/d. A shift of k positions turns each point by kωi​. This turn is the same for every p. So a linear map can move from the code of position p to the code of position p+k. The model can learn relative offsets from absolute codes.

Why many frequencies

The first pair turns once in about 6 positions. The last pairs turn very slowly. The fast pairs separate neighbours. The slow pairs separate positions that are far apart. Together the columns give each position a different code.

The limit

The table is fixed and the model sees only the positions of its training data. At a longer length the model sees codes that it did not learn. RoPE puts the same sines and cosines into a rotation of the queries and keys, and the score then depends only on the gap. Most current models use RoPE for this reason.

Where this goes next

The RoPE problem uses the same frequencies base−2i/d. The full transformer lesson adds this table to the embeddings before the first block.

Defend a designA model was trained with a context of 8K tokens. The product now needs 128K. You have a modest fine-tuning budget and no budget to pretrain again. Lay out the options by the way the model encodes position, and give me the plan you would run.

Level 3 of 4 · about 12 minutes to answer well.

Short answer. The answer depends on the positional scheme, so read the config first. A learned absolute table has no row past the trained length and cannot be extended without new parameters. With rotary embeddings you scale the base or interpolate the positions, with NTK-aware scaling, YaRN or LongRoPE, and fine-tune on long sequences; the lesson's reference is a model family that went from 8K to 128K this way. Linear-bias attention extrapolates by construction, but you cannot switch a trained model to it for free.

Option by scheme.

Scheme in the checkpoint Can it reach 128K? How
Learned absolute table Not without new rows Add rows and train them, or retrain
Fixed sinusoid The formula extends, the model does not The model never saw those phases; expect poor quality
Rotary Yes Scale the base or interpolate positions, then fine-tune
Linear bias Yes by design Already extrapolates; a training-time choice

The rotary toolbox.

  • Position interpolation plus fine-tuning. Shrink the positions by the extension factor so the angles stay inside the trained range, then fine-tune for 1 to 5B tokens. Simple and effective.
  • NTK-aware scaling. Rescale the base to base * scale_factor ** (d / (d - 2)) when going from 4K to 16K and beyond, so the high-frequency pairs are not squeezed.
  • YaRN. A per-dimension mix of interpolation and extrapolation that preserves the entropy of attention on long contexts; it needs a fine-tuning stage.
  • LongRoPE. A search over per-dimension scale factors; used for very long contexts.

The plan.

  1. Confirm the scheme from the model config and read the current rope scaling block.
  2. Pick YaRN or position interpolation, set the factor for 128K, and build a long-sequence fine-tuning set.
  3. Before training, measure perplexity on sequences longer than the trained length with and without the scaling, the way the lesson's exercise does at lengths 256 and 1024.
  4. Fine-tune, then measure again at the target length and at the original length, so that a win on long inputs does not hide a regression on short ones.
  5. Budget the memory. The cache of keys and values grows linearly with the context, and 128K is sixteen times 8K.

What to tell the product team.

The positional scheme is the gate. A rotary model gives you a clean knob and a short fine-tuning job. A model with a learned table or a sinusoid needs a retrain or a different model.

Plausible wrong answers.

  • "Set the maximum position in the config higher and ship." A learned table has no row for the new positions, and a rotary model needs its base scaled and a fine-tune.
  • "The sinusoid extends to any length, so the model works." The formula extends; the model was never trained to read those phases and its quality drops.
  • "Position interpolation needs no training." The lesson's recipe is to shrink the positions and then fine-tune for 1 to 5B tokens.

Follow-ups an interviewer may ask.

  • (level 3) Why does a rotary model fail when you just run it at 128K with no change? Expected: the fast-turning coordinate pairs reach angles the model never saw, so the scores at long distance are noise.
  • (level 3) What two measurements do you insist on before shipping? Expected: perplexity or task quality at the new length, and the same at the original length to catch a regression.
  • (level 4) The team proposes to switch the model to linear-bias attention because it extrapolates well. Your answer? Expected: that is a training-time choice; a checkpoint trained with rotation cannot be swapped to a score bias without retraining.
  • (level 4) What breaks on the serving side at 128K even if quality is fine? Expected: memory for each token's keys and values, which grows with the context; the attention stack needs grouped-query or latent attention and a tiled kernel.

Explain the mechanismTake a sentence and shuffle its words. Feed both versions through a self-attention layer that has no positional signal. How do the two outputs relate, and what are the three families of fixes you would name?

Level 1 of 4 · about 6 minutes to answer well.

Short answer. The output rows come back shuffled in the same way and nothing else changes, because attention only computes pairwise similarities between tokens. Order carries meaning in language and code, so the model needs a second signal. The three fixes are a position vector added to the embedding, a learned table or a fixed sinusoid, a rotation of the queries and keys by an angle that grows with position, and a distance penalty added to the scores.

Why the layer is blind.

The score matrix is softmax(Q K^T / sqrt(d)) V, built from dot products between pairs of tokens. Permute the rows of X and every dot product keeps its value; only its position in the matrix moves. The layer is permutation-equivariant by construction.

Fix one: add a position vector to the input.

A learned table has one row per position, so it adds max_context_length times D parameters and has no row for a position past the trained length. A fixed sinusoid uses the formula

angle = p / (10000 ** (2 * k / D))
emb[p, 2k]     = sin(angle)
emb[p, 2k + 1] = cos(angle)

with no parameters. The wavelength changes geometrically across dimensions. Low dimensions have the largest angle per position and the shortest wavelength, so they encode fine position; high dimensions have the longest wavelength and encode coarse position. The vector at position p plus k is a linear function of the vector at p, which gives attention an easy way to learn relative offsets. The position vector is summed with the token vector, not concatenated, so D stays constant and the model decides per feature how much position matters.

Fix two: rotate the queries and keys.

Rotary position embedding rotates each pair of coordinates in Q and K by pos * theta_i, with theta_i = base ** (-2i / d_head) and a default base of 10000. The dot product of a rotated query and a rotated key then depends only on their distance. This is the dominant choice in 2026.

Fix three: bias the scores.

Linear-bias attention adds -m_h * |i - j| to the score of query i and key j, with a slope per head. No table, no rotation, and strong extrapolation to longer inputs.

Where each one lives.

The first family changes the input to the first layer. The other two act inside attention, on the projections or the scores, so they follow the same shape contract as the embedding stage without touching the embedding.

Plausible wrong answers.

  • "The softmax makes attention order-aware." The softmax normalizes a row of similarities; it has no idea which column is first.
  • "Add the position as one extra number on the embedding." One scalar cannot give the dot products a usable signal; the schemes spread position across many dimensions or into the scores.
  • "Position only matters for long sequences." A two-word sentence already changes meaning when its words swap.

Follow-ups an interviewer may ask.

  • (level 1) Why add the two vectors instead of concatenating them? Expected: the sum keeps D constant through the network and lets the model weigh token and position per feature.
  • (level 2) What does a learned position table cost that a sinusoid does not? Expected: max_context_length times D parameters, and it cannot be indexed past the trained length.
  • (level 2) Why do the high dimensions of the sinusoid encode coarse position? Expected: their wavelength is longest, so they change slowly across positions.
  • (level 3) Where in the block does the rotation apply? Expected: to Q and K inside attention, after the projection and before the score matmul, never to V.

Explain the mechanismThe rotary scheme rotates every query and every key by an angle that is proportional to the token's absolute position. Yet everyone says it encodes relative position. Resolve the apparent contradiction, and tell me the one unit test you would write to prove the property.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. The rotation acts on pairs of coordinates with the angle pos * theta_i. When a query from position m meets a key from position n, the dot product on each pair picks up cos((m - n) * theta_i), so only the gap survives and the two absolute positions cancel. The test: rotate two random vectors at positions (a, b) and again at (a + k, b + k), then assert that the two dot products agree within floating-point error.

The rotation.

For each pair of dimensions (2i, 2i + 1) in a head of width d_head:

def apply_rope(x, pos, base=10000):
    d = len(x)
    out = list(x)
    for i in range(d // 2):
        theta = pos / (base ** (2 * i / d))
        c, s = math.cos(theta), math.sin(theta)
        a, b = x[2 * i], x[2 * i + 1]
        out[2 * i]     = a * c - b * s
        out[2 * i + 1] = a * s + b * c
    return out

Each pair is a point in a plane, and the rotation turns it by pos * theta_i. Low values of i turn fast and high values turn slowly, because theta_i = base ** (-2i / d_head).

Why the dot product only sees the gap.

A rotation by angle alpha followed by the dot product with a vector rotated by angle beta equals the dot product of the originals rotated by alpha - beta. Apply the same function to Q at position m and to K at position n, and every pair contributes a factor that depends on (m - n) * theta_i. The score depends on the distance even though the rotation was keyed off the absolute position. Attention gets relative position for free, with no table and no parameters.

Where it applies.

The rotation applies to Q and K after their projection and before the score matmul. It never touches V, because the values carry content that should not be rotated by position, and it never touches the input embedding.

Why it won.

It slots into attention without a change to the architecture. Its base is a clean knob: scale it and the model reaches longer contexts, which is how one model family reached a 128K context from 8K with scaling schemes such as NTK-aware interpolation and YaRN.

The unit test.

a, b = random vectors of width d_head
s1 = dot(apply_rope(a, pos_a), apply_rope(b, pos_b))
s2 = dot(apply_rope(a, pos_a + k), apply_rope(b, pos_b + k))
assert abs(s1 - s2) < tolerance

The property is the whole point of the method. If the test fails, the rotation was applied to only one side, or the two sides use different pairs or angles. A pass does not prove the pairing or the angles match the reference: a consistent wrong pairing passes too, so also compare one rotated vector with a value computed by hand.

Plausible wrong answers.

  • "RoPE adds a position vector to the embedding." It rotates the queries and the keys inside attention; the embedding is untouched.
  • "RoPE needs a table of size maximum length times width." The angles come from a formula; there is no table and no parameter.
  • "Rotate the keys only and save half the work." Then the score depends on the absolute position of the key, and the relative property is gone.

Follow-ups an interviewer may ask.

  • (level 2) Why rotate Q and K but not V? Expected: position should shape the match between tokens, not the content that is returned once a token is picked.
  • (level 3) What happens at a position the model never saw in training? Expected: the fast-turning pairs reach angles the model never learned to read; scaling the base or interpolating positions brings them back into the trained range.
  • (level 3) How does linear-bias attention get relative position without any rotation? Expected: it adds a penalty proportional to |i - j| to the scores, one slope per head.
  • (level 4) Why does increasing the base help a longer context? Expected: a larger base lowers every frequency except the first pair, which always turns at one radian per position, so the high-frequency pairs are not squeezed into unseen angles when the context grows; the NTK-aware rule rescales the base by the extension factor raised to d / (d - 2).
