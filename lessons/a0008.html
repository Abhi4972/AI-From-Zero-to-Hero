The problem

In plain words first

An editor does more than show text. Through a language server it reads your code as you type and reports mistakes before you run anything: a misspelt variable, a missing import, a string passed where a number was expected. A formatter rewrites layout on save so you never argue about spaces, and a linter flags code that is legal but almost certainly wrong.

You'll spend thousands of hours inside your editor writing Python, running notebooks, debugging training loops, and SSH-ing into GPU boxes. A misconfigured editor turns every session into friction: no autocomplete, no type hints, no inline errors, manual formatting, and a clunky terminal workflow.

The right setup takes 20 minutes. Skipping it costs you 20 minutes every day.

The same idea as a formula

A type checker such as Pylance (Pyright) treats a type as a set of values: int is all integers, str all strings, float | None all floats plus None. A value fits a parameter if it lies in the parameter's set, and a type A may be passed where B is expected if every A is a B (written A<:B, "A is a subtype of B"). By convention int is accepted where float is expected.

Containers that can be changed are stricter. A list[int] is not accepted where a list[float] is expected, even though every int is accepted as a float: a function given a list[float] may append 0.5 to it, which would break the caller's list of ints. Types like list are invariant; read-only ones such as Sequence[float] are covariant and accept a list[int].

The checker works on the code without running it, so it can only see what the annotations say: un-annotated code is mostly invisible to it.

Worked example
Checking two calls by hand
def mean(xs: list[float]) -> float: ...
def mean2(xs: Sequence[float]) -> float: ...
ints: list[int] = [1, 2, 3]
  • mean(ints): is list[int] a subtype of list[float]? No, lists are invariant. Pyright reports "list[int]" is not assignable to "list[float]" and suggests Sequence; mypy gives the same error.
  • mean2(ints): is list[int] a Sequence[float]? A list is a sequence, and int is accepted as float in a read-only container: yes, no error.
  • scale(3) with x: float: accepted, by the int-for-float convention.
Check your mental model
  • ✗ "Type hints make Python check types when the code runs."
    ✓ Python ignores them at run time. They are read by tools: your editor's type checker, Pydantic, LangChain. The demo below runs a badly typed call without complaint.
  • ✗ "The linter and the formatter do the same job."
    ✓ The formatter (Black, or ruff format) changes layout only. The linter (Ruff) finds problems such as unused imports and undefined names, and changes nothing unless you ask it to fix.
  • ✗ "Remote SSH copies my project to the GPU box."
    ✓ The files stay on the remote machine; VS Code runs a small server there and shows you the remote folder. Your code runs where the GPU is.

Step 1 · Install VS Code

VS Code is the recommended editor. It is free, runs on every OS, has first-class Jupyter notebook support, and the extension ecosystem covers everything you need for AI work.

Download it from code.visualstudio.com.

Verify from the terminal:

code --version

If code is not found on macOS, open VS Code, press Cmd+Shift+P, type "Shell Command", and select "Install 'code' command in PATH".

Step 2 · Install Essential Extensions

Open the integrated terminal in VS Code (Ctrl+` on every platform) and install the extensions that matter for AI work:

code --install-extension ms-python.python
code --install-extension ms-python.vscode-pylance
code --install-extension ms-toolsai.jupyter
code --install-extension eamodio.gitlens
code --install-extension ms-vscode-remote.remote-ssh
code --install-extension ms-python.debugpy
code --install-extension ms-python.black-formatter
code --install-extension charliermarsh.ruff

What each one does:

Extension Why
Python Language support, virtual env detection, run/debug
Pylance Fast type checking, autocomplete, import resolution
Jupyter Run notebooks inside VS Code, variable explorer
GitLens See who changed what, inline git blame
Remote SSH Open a folder on a remote GPU box as if it were local
Debugpy Step-through debugging for Python
Black Formatter Auto-format on save, consistent style
Ruff Fast linting, catches common mistakes

The file code/vscode/extensions.json in this lesson contains the full recommendations list. Copy it to .vscode/extensions.json in your project folder, and VS Code prompts you to install them when you open that folder.

Step 3 · Configure Settings

Copy the settings from code/vscode/settings.json in this lesson, or apply them manually through Settings > Open Settings (JSON).

The key settings for AI work:

{
    "python.analysis.typeCheckingMode": "basic",
    "editor.formatOnSave": true,
    "editor.rulers": [88, 120],
    "notebook.output.scrolling": true,
    "files.autoSave": "afterDelay"
}

Why these matter:

  • Type checking on basic: Catches wrong argument types before you run. Saves debugging time on tensor shape mismatches and wrong API parameters.
  • Format on save: Never think about formatting again. Black handles it.
  • Rulers at 88 and 120: Black wraps at 88. The 120 marker shows when docstrings and comments are getting too long.
  • Notebook output scrolling: Training loops print thousands of lines. Without scrolling, the output panel explodes.
  • Auto-save: You will forget to save. Your training script will run stale code. Auto-save prevents that.
Predict before you run

scale(x: float, factor: float) multiplies its two arguments. What does scale("3", 2) print, and would Pylance have warned you? (Solution P1.)

def scale(x: float, factor: float) -> float:
    return x * factor

print(scale(3, 2))
print(scale("3", 2))

What a linter catches

Ruff is the linter the lesson installs. Run on a small training file with an unused import and a typo in a variable name, it finds both without running the code:

import pathlib, subprocess, sys

pathlib.Path("train_demo.py").write_text(
    "import os\nimport numpy as np\n\n"
    "def loss(pred, target):\n    return ((pred - target) ** 2).mean()\n\n"
    "print(loss(preds, np.zeros(3)))\n")
r = subprocess.run([sys.executable, "-m", "ruff", "check", "--select", "F", "--output-format", "concise", "train_demo.py"],
                   capture_output=True, text=True)
print(r.stdout.strip())
What you should see
train_demo.py:1:8: F401 [*] `os` imported but unused
train_demo.py:7:12: F821 Undefined name `preds`
Found 2 errors.
[*] 1 fixable with `--fix`.

F821 Undefined name 'preds' would otherwise surface as a NameError at the end of a training run, possibly hours in.

Reading this output

Ruff reports two problems by rule code: F401 (os is imported but never used) and F821 (preds is used but never defined; the function's parameter is pred). Neither stops Python from starting the script; the NameError would come only when execution reaches the last line, possibly after a long training run. The editor shows the same codes as squiggles while you type.

Step 4 · Terminal Integration

VS Code's integrated terminal is where you run training scripts, monitor GPUs, and manage environments.

Set it up properly:

{
    "terminal.integrated.defaultProfile.osx": "zsh",
    "terminal.integrated.defaultProfile.linux": "bash",
    "terminal.integrated.fontSize": 13,
    "terminal.integrated.scrollback": 10000
}

Useful shortcuts:

Action macOS Linux/Windows
Toggle terminal Ctrl+` Ctrl+`
New terminal Ctrl+Shift+` Ctrl+Shift+`
Split terminal Cmd+\ Ctrl+Shift+5

Split terminals are useful: one for running your script, one for monitoring GPU with nvidia-smi -l 1 or watch -n 1 nvidia-smi.

Step 5 · Remote Development (SSH into GPU Boxes)

This is the most important extension for AI work. You will run training on remote machines (cloud VMs, lab servers, Lambda, Vast.ai). Remote SSH lets you open the remote filesystem, edit files, run terminals, and debug as if everything were local.

Setup:

  1. Install the Remote SSH extension (done in Step 2).
  2. Press Ctrl+Shift+P (or Cmd+Shift+P), type "Remote-SSH: Connect to Host".
  3. Enter user@your-gpu-box-ip.
  4. VS Code installs its server component on the remote machine automatically.

For passwordless access, set up SSH keys:

ssh-keygen -t ed25519 -C "your-email@example.com"
ssh-copy-id user@your-gpu-box-ip

Add the host to ~/.ssh/config for convenience:

Host gpu-box
    HostName 203.0.113.50
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519
    ForwardAgent yes

Now Remote-SSH: Connect to Host > gpu-box connects instantly.

Break it on purpose

Turn off files.autoSave, edit a training script so it prints something new, and run it from the integrated terminal without saving. What runs? Then save and run again. (Solution B1.)

Recap
What to keep from this lesson
  • VS Code plus the Python, Pylance, Jupyter, Ruff and Remote SSH extensions cover the whole course.
  • Type checking, linting and formatting catch mistakes before you run; type hints are not checked at run time.
  • Turn on format on save and auto-save so style and stale files never cost you a run.
  • Remote SSH lets you edit and run on a GPU box as if it were local; set up SSH keys and ~/.ssh/config once.

Alternatives

Cursor

cursor.com is a VS Code fork with built-in AI code generation. It uses the same extension ecosystem and settings format. If you use Cursor, everything in this lesson still applies. Import the same settings.json and extensions.json.

Windsurf

windsurf.com is another AI-first VS Code fork. Same story: same extensions, same settings format, same Remote SSH support.

Vim/Neovim

If you already use Vim or Neovim and are productive in it, stay there. The minimum setup for AI Python work:

  • pyright or pylsp for type checking (via Mason or manual install)
  • nvim-lspconfig for language server integration
  • jupyter-vim or molten-nvim for notebook-like execution
  • telescope.nvim for file/symbol search
  • none-ls.nvim with black and ruff for formatting/linting

If you do not already use Vim, do not start now. The learning curve will compete with learning AI engineering. Use VS Code.

Solutions

SolutionP1 · A string where a float was expected

scale(3, 2) prints 6, and scale("3", 2) prints 33: Python repeats the string twice, with no error, because type hints are not enforced. Pylance (with type checking on basic) underlines "3" with a warning like Argument of type "Literal['3']" cannot be assigned to parameter "x" of type "float". That warning is the whole point of the setting.

SolutionB1 · Running stale code

The terminal runs the file on disk, which is the last saved version, so the old output appears. The editor's unsaved buffer is invisible to Python. After saving, the new line prints. This is why the lesson turns auto-save on: a training run on stale code wastes the whole run.

Use it: the same idea with real libraries

With this setup, your daily workflow looks like:

  1. Open the project folder in VS Code (or connect via Remote SSH to a GPU box).
  2. Write Python in the editor with autocomplete, type hints, and inline errors.
  3. Run Jupyter notebooks inline with the Jupyter extension.
  4. Use the integrated terminal for training scripts, uv pip install, and GPU monitoring.
  5. Review changes with GitLens before committing.
Industry practice
What's current (2024–2026)
  • AI coding assistants are part of the editor. VS Code with GitHub Copilot (chat, edits and agent mode), Cursor, and JetBrains AI are the common setups; Claude Code and similar agents work from the terminal next to any editor.
  • Fast linting and type checking. Ruff replaces flake8, isort and Black in many projects; Pyright (Pylance in VS Code) or mypy check types; both run on save and in CI.
  • Remote development. VS Code Remote-SSH, Dev Containers and Codespaces let the editor run locally while code runs on a GPU machine.

Sources: Copilot in VS Code, Ruff, Pyright, VS Code Remote Development.
