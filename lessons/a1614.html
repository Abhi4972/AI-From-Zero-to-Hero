In plain words first
The idea in one line

Classical distributed-systems BFT meets stochastic LLMs. In 2025-2026 three research directions emerged: CP-WBFT (arXiv:2511.10400) weighs each vote by a confidence probe; DecentLLMs (arXiv:2507.14928) goes leaderless with parallel worker proposals and geometric-median aggregation; WBFT (arXiv:2505.05103) combines weighted voting with Hierarchical Secure Clustering to split Core and Edge nodes. The honest empirical result from "Can AI Agents Agree?" (arXiv:2603.01213) is that even scalar agreement is fragile today, and a separate study found that a single deceptive agent can drag down a Mixture-of-Agents. BFT is necessary but not sufficient. This lesson builds a minimal BFT protocol, injects three agent-specific attacks (byzantine lie, sycophantic conformity, correlated-error monoculture), and measures how each consensus variant copes.

Terms you'll hear

Problem

In plain words first

When several agents answer the same question, you need a rule for picking one answer. Majority vote counts heads. Byzantine fault tolerance (BFT) is the distributed-systems name for agreeing even when some participants lie or misbehave. With LLM agents there is an extra problem: agents built on the same model tend to make the same mistakes, so a majority can be confidently wrong. There is no Zero to Agents chapter on this; it builds on Lesson 16.7 (debate) and Lesson 16.13 (shared memory). This lesson tests the lesson's three aggregators on votes its scenarios do not try, and runs five copies of one small model as a real monoculture.

You have N LLM agents each producing an answer. They disagree. Majority vote picks the wrong one because two agents are correlated (same base model, same training data, same failure modes). A third agent happens to be wrong in a novel way — so the majority is a false majority.

Now add a deceptive agent: it lies on purpose. Or a sycophantic agent: it agrees with whoever spoke last. In classical BFT, the assumption is that Byzantine nodes are a fraction f < n/3 and behave arbitrarily. The 2026 reality is that LLM nodes are stochastic even when honest, correlated across models, and influenced by each other's outputs. You cannot treat them as independent Bernoulli voters.

Classical BFT (PBFT, 1999) is not wrong — it is incomplete. It handles arbitrary bit-flipping. It does not handle "three honest agents share a hallucination because they share training data." This lesson builds from PBFT's foundation and layers on three 2025-2026 adaptations.

Concept

What classical BFT gives you

Practical Byzantine Fault Tolerance (Castro & Liskov, OSDI 1999) tolerates f < n/3 Byzantine nodes. The protocol has three phases (pre-prepare, prepare, commit) and two primitives (signed messages, quorum certificates). Agreement on a single value among n >= 3f + 1 honest-or-malicious nodes.

The guarantees are strong but assume:

  1. Independent failures. The bound f < n/3 assumes replicas fail independently; Castro and Liskov suggest running different implementations so one bug cannot take out many nodes at once. The faulty nodes themselves may collude.
  2. Honest nodes are truly honest. Correctness of honest outputs is a non-issue; the protocol only aligns disagreement.
  3. The question has a ground-truth answer. Consensus on a wrong fact is still consensus.

LLM agents violate all three. Two agents running the same base model share faults. An "honest" LLM still hallucinates. And on ambiguous questions, the "truth" is what the agents decide — there is no external oracle.

The three LLM-specific attacks

Byzantine lie. One agent outputs a deliberately wrong answer. Classical BFT handles this if f < n/3.

Sycophantic conformity. One agent reads others' answers before voting and aligns with whoever spoke last. Not malicious, but correlates with the loudest voice. Classical BFT does not prevent this because the agent passes every signature check.

Correlated-error monoculture. Three agents share a base model. They hallucinate the same wrong answer. The majority is wrong. Classical BFT does not help because all three "honestly" agree.

The 2025-2026 responses

CP-WBFT (arXiv:2511.10400) — confidence-probe-based weighted BFT. Each voter's answer gets a confidence, either self-reported in the prompt or read by a probe trained on the model's hidden activations. Vote weights scale with confidence. With 6 of 7 agents Byzantine, the hidden-state probe raised final accuracy from 14.29% to 100% (+85.71%) on complete graphs; gains from self-reported confidence were smaller and on one task sometimes negative. Mitigation for: sycophantic conformity, on the assumption that conforming agents have low confidence in a position they did not derive.

DecentLLMs (arXiv:2507.14928) — leaderless. Worker agents propose answers in parallel, evaluator agents score every proposal, the scores are combined with the geometric median (Weiszfeld's algorithm), and the best-ranked answer wins. Robust while fewer than half the evaluators are Byzantine. Mitigation for: Byzantine lies (the geometric median ignores a minority of extreme scores); it does not fix errors that most agents share.

WBFT (arXiv:2505.05103) — weighted BFT with Hierarchical Secure Clustering, for a blockchain-style network of LLMs. A leader proposes a response, followers vote on whether theirs is better, and the response is accepted with two-thirds of the weighted vote. Each weight mixes a response-quality score and a trust value. Clustering on trust and latency picks high-trust Core nodes that vote, while Edge nodes receive the result by broadcast. Mitigation for: scalability (Core consensus is small and fast) and partially for monoculture (Core can be chosen for diversity).

Empirical: "Can AI Agents Agree?" (arXiv:2603.01213)

The paper (Berdoz, Rugli and Wattenhofer) runs LLM agents in a synchronous, all-to-all Byzantine consensus game over a scalar value, with no stake in which value wins, across hundreds of simulations that vary model size, group size and the number of Byzantine agents. The finding is uncomfortable:

  • Even with no adversaries, valid agreement is unreliable, and it gets worse as groups grow.
  • A few Byzantine agents lower the success rate further. Separately, Wolf et al. (arXiv:2503.05856) found that one deceptive agent among six cut a Mixture-of-Agents' AlpacaEval 2.0 length-controlled win rate from 49.2% to 37.9%.
  • Most failures are loss of liveness (timeouts and stalled convergence), not agreement on a wrong value.

The takeaway: BFT gives you machinery to align outputs, but it does not tell you whether the aligned output is right. Combine with verification (Phase 16 · 08 role specialization), diversity (Phase 16 · 15 debate variants), and evaluator agents (Phase 16 · 24 benchmarks).

The core protocol, stripped down

A minimal BFT round for LLM agents:

1. task arrives; each agent i produces answer a_i
2. each agent attaches confidence probe c_i in [0, 1]
3. aggregator collects (a_i, c_i) from all n agents
4. aggregator groups by semantic cluster (equivalent answers)
5. aggregator computes weight for each cluster C:
     w(C) = sum_{i in C} c_i
6. winner = cluster with max weight, if max > threshold * sum(c_i)
   else: retry or escalate
7. minority clusters logged with provenance for post-hoc audit

The semantic clustering step is the LLM-specific twist. Two answers "the study reports 4.2%" and "4.2% improvement" are the same cluster. A naive string-equality check would miss this. In production, use a cheap embedding model or explicit canonicalization.

Threshold tuning

The threshold parameter decides when to accept and when to retry. Too low: you accept weak majorities. Too high: you never accept anything. A reasonable starting point is 0.5-0.67 for n=5-7 agents, higher for smaller n; tune it on your own attack tests. Below a threshold, escalate to a human or to a different agent ensemble.

Where consensus does not help

  • Ambiguous questions. If the question has no ground truth, consensus is an opinion. Call it that.
  • Compound questions. "Write code and explain it" — two answers. Vote on each independently.
  • Adversarial multi-round. If agents can observe prior rounds and mimic (Du 2023 debate), they start agreeing with each other regardless of truth. Bound the rounds (2-3 typically).

The same idea as a formula

Majority of independent voters. With n voters each right with probability p, independently, a majority is right with probability

Pmaj​=k>n/2∑​(kn​)pk(1−p)n−k.
For n=5 and p=0.7 that is about 0.84, better than any one voter.

Correlated voters. If each voter copies one shared draw with probability ρ, and otherwise votes independently, the gain shrinks as ρ grows. At ρ=1 all five vote together and Pmaj​=p: five copies of one model are worth one.

Weighted vote. Cluster C gets weight w(C)=∑i∈C​ci​, and wins if w(C)/∑j​cj​≥τ. A liar who can set its own ci​ can always out-weigh an honest agent with lower confidence.

Worked example
Weighing the lesson's monoculture case
  • Three agents say 42% with confidence 0.70, 0.68 and 0.72, a weight of 2.10. Two say 4.2% with 0.85 and 0.82, a weight of 1.67.
  • The top share is 2.10/3.77=0.557.
  • With τ=0.5, CP-WBFT accepts 42%, which is wrong.
  • With τ=0.6, no cluster reaches the threshold, so the round is escalated. A higher threshold cannot pick the right answer here; it can only refuse to pick the wrong one.

Writing changes the count. canonical() only lowercases and strips punctuation, so "4.2%", "4.2 percent", "4.20%" and "0.042" became four clusters of one. With five single-vote clusters, plurality and DecentLLMs took the first vote, the liar's. CP-WBFT found no cluster above half and rejected the round, which is at least not wrong.

Self-reported confidence is the liar's to choose. Two liars at 1.0 outweighed three honest agents at 0.6, 2.0 against 1.8, and CP-WBFT returned 42%. Plurality got this one right.

The lesson's DecentLLMs is not a median. It scores a cluster by its size times one minus the spread of its confidences. Four honest agents with confidences from 0.3 to 0.95 scored 0, and one liar at a steady 0.8 scored 1 and won. A real median of the numbers is 4.2%, and stays right while fewer than half lie.

A threshold refuses; it does not rescue. On the monoculture case the top share was 0.557. At 0.5 the wrong answer was accepted; at 0.6 and above the round was escalated.

Correlation eats the majority's advantage. With independent voters right 70% of the time, five-way majority was right 83.8% of the time. As voters copied a shared draw more often, it fell to 69.7%, about one voter's accuracy.

# This block continues from the one above. Five "agents" that are all Qwen2.5-0.5B-Instruct, sampled at
# temperature 0.8 with different seeds: a real monoculture. Twenty two-digit multiplications; each agent replies
# with an answer and a self-reported confidence. We also record the probability the model gave its own answer
# tokens. Then: individual accuracy, how often the wrong answers coincide, and four ways to aggregate.
# About 2 minutes on CPU.
import os, re, random, warnings
from collections import Counter
os.environ["HF_HUB_OFFLINE"] = "1"
warnings.filterwarnings("ignore")
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct").eval()

rng = random.Random(3)
QS = [(rng.randint(12, 49), rng.randint(12, 49)) for _ in range(20)]
def ask(a, b, seed):
    p = (f"What is {a} times {b}? Reply in exactly this format:\nAnswer: <number>\n"
         "Confidence: <a number from 0 to 1>")
    ids = tok.apply_chat_template([{"role": "user", "content": p}], add_generation_prompt=True,
                                  return_tensors="pt", return_dict=True)["input_ids"]
    torch.manual_seed(seed)
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=24, do_sample=True, temperature=0.8, top_p=1.0, top_k=0,
                           output_scores=True, return_dict_in_generate=True)
    new = out.sequences[0, ids.shape[1]:]
    text = tok.decode(new, skip_special_tokens=True)
    m = re.search(r"Answer:\s*([\d,]+)", text); c = re.search(r"Confidence:\s*([01](?:\.\d+)?)", text)
    ans = int(m.group(1).replace(",", "")) if m else None
    # probability of the digits of the answer, from the scores at the steps that produced them
    lp, prefix = 0.0, ""
    for step, t in enumerate(new.tolist()):
        piece = tok.decode([t])
        if re.search(r"Answer:\s*[\d,]*$", prefix) and re.fullmatch(r"\s*[\d,]+", piece):
            lp += torch.log_softmax(out.scores[step][0], -1)[t].item()   # scores are already divided by temperature
        prefix += piece
    return ans, (float(c.group(1)) if c else 0.5), float(torch.tensor(lp).exp())

N = 5
rows = []
for a, b in QS:
    rows.append([ask(a, b, seed=100 * i + a) for i in range(N)])

truth = [a * b for a, b in QS]
indiv = sum(r[i][0] == t for r, t in zip(rows, truth) for i in range(N)) / (N * len(QS))
print(f"individual accuracy: {indiv:.2f} over {N * len(QS)} answers")
wrong_pairs = same_wrong = 0
for r, t in zip(rows, truth):
    ws = [x[0] for x in r if x[0] != t]
    for i in range(len(ws)):
        for j in range(i + 1, len(ws)):
            wrong_pairs += 1; same_wrong += ws[i] == ws[j]
print(f"when two agents are both wrong, they give the same wrong answer {same_wrong} of {wrong_pairs} times")
selfc = [x[1] for r in rows for x in r]
print(f"self-reported confidence: {len(set(selfc))} distinct values, mean {sum(selfc) / len(selfc):.2f}")
mean = lambda xs: sum(xs) / max(1, len(xs))
for k, name in ((1, "self-reported confidence"), (2, "answer probability")):
    r_ok = [x[k] for r, t in zip(rows, truth) for x in r if x[0] == t]
    r_no = [x[k] for r, t in zip(rows, truth) for x in r if x[0] != t]
    print(f"   mean {name:25s} when right {mean(r_ok):.2f}, when wrong {mean(r_no):.2f}")

def agg(r, weight):
    w = Counter()
    for ans, c, p in r:
        if ans is not None:
            w[ans] += weight(c, p)
    return w.most_common(1)[0][0] if w else None
methods = {"one agent (agent 0)": lambda r: r[0][0],
           "plurality": lambda r: agg(r, lambda c, p: 1),
           "weighted by self-reported confidence": lambda r: agg(r, lambda c, p: c),
           "weighted by answer probability": lambda r: agg(r, lambda c, p: p)}
print()
for name, f in methods.items():
    print(f"   {name:38s} {sum(f(r) == t for r, t in zip(rows, truth)):2d} / {len(QS)}")
oracle = sum(any(x[0] == t for x in r) for r, t in zip(rows, truth))
print(f"   {'any agent right (upper bound)':38s} {oracle:2d} / {len(QS)}")

Voting helped a lot here. Single answers were right 66% of the time, about 13 of 20 questions per agent (agent 0 got 10). Plurality got 17 of 20, as many as were possible: on the other 3 questions no agent was right.

The mistakes were correlated. When two agents were both wrong, they gave the same wrong answer 14 of 36 times, far more often than chance would give for four-digit numbers. That is the monoculture effect, and it is why some questions had no right answer to vote for.

Part 1 of 4 · Vote, plurality, cp_wbft, decentllms

"""Consensus and BFT for LLM agents, stdlib only.

Implements three aggregators (plurality, CP-WBFT, DecentLLMs) and three
attack patterns (byzantine, sycophancy, monoculture). Prints a table of
(attack, aggregator) -> final answer, highlighting correct decisions.
"""
from __future__ import annotations

from dataclasses import dataclass, field
from statistics import median
from typing import Callable


@dataclass
class Vote:
    agent: str
    answer: str
    confidence: float

    def canonical(self) -> str:
        """Rough semantic clustering: lowercase + strip whitespace/punct."""
        return "".join(c for c in self.answer.lower().strip() if c.isalnum() or c == "." or c == "%")


def plurality(votes: list[Vote]) -> tuple[str, dict[str, int]]:
    counts: dict[str, int] = {}
    rep: dict[str, str] = {}
    for v in votes:
        key = v.canonical()
        counts[key] = counts.get(key, 0) + 1
        rep.setdefault(key, v.answer)
    winner_key = max(counts, key=counts.get)
    return rep[winner_key], counts


def cp_wbft(votes: list[Vote], threshold: float = 0.5) -> tuple[str | None, dict[str, float]]:
    weights: dict[str, float] = {}
    rep: dict[str, str] = {}
    for v in votes:
        key = v.canonical()
        weights[key] = weights.get(key, 0.0) + v.confidence
        rep.setdefault(key, v.answer)
    total = sum(weights.values()) or 1.0
    winner_key = max(weights, key=weights.get)
    if weights[winner_key] / total < threshold:
        return None, weights
    return rep[winner_key], weights


def decentllms(votes: list[Vote]) -> tuple[str | None, dict[str, float]]:
    """Score proposals 0-1 via evaluator agents, pick geometric-median cluster.

    Simplified: evaluator is the aggregator itself, scoring = confidence. The
    'geometric median' selects the cluster whose members have min sum of
    pairwise distance-to-median in confidence space; tie-break by size.
    """
    clusters: dict[str, list[Vote]] = {}
    for v in votes:
        clusters.setdefault(v.canonical(), []).append(v)

    scores: dict[str, float] = {}
    for key, cluster in clusters.items():
        med = median([v.confidence for v in cluster])
        dist = sum(abs(v.confidence - med) for v in cluster)
        scores[key] = len(cluster) * max(0.0, 1.0 - dist)

    winner_key = max(scores, key=scores.get)
    rep = clusters[winner_key][0].answer
    return rep, scores

Break it on purpose

Your fraud team runs five agents on the same base model, each with a different prompt, and blocks a payment when CP-WBFT reaches 0.5 on "fraud". Agents attach self-reported confidence. A new merchant category appears; all five agents call its payments fraud at confidence 0.9, and the block rate triples overnight. Nothing in the consensus logs looks wrong. Using this lesson, what failed, and what would you change? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Confidence from inside the model. CP-WBFT's strongest results come from a probe trained on hidden activations, not from asking the model; with open-weight models, token probabilities are a cheap step in that direction.
  • Diversity over headcount. Mixtures of different model families and prompts are the main defence against correlated errors; five copies of one model share many mistakes.
  • Agreement is not reliable yet. Berdoz, Rugli and Wattenhofer (2026) found LLM groups often fail to reach valid agreement at all, mostly by stalling, so bound rounds and plan for no consensus.
  • On your laptop: sampling one small model several times and voting is the cheapest consensus there is. Here it took 13 of 20 average single-agent answers to 17 of 20, and it cannot fix questions where every sample is wrong.

Sources: CP-WBFT, arXiv:2511.10400, DecentLLMs, arXiv:2507.14928, WBFT, arXiv:2505.05103, Berdoz, Rugli and Wattenhofer, Can AI Agents Agree? (arXiv:2603.01213), Wolf, Yoon and Bogunovic, deception in Mixture of LLMs (arXiv:2503.05856), Castro and Liskov, PBFT.

Recap
What to keep from this lesson
  • Majority vote helps only as much as voters' errors are independent; copies of one model share mistakes.
  • Normalise answers before counting, or honest votes split and a liar wins the tie.
  • Self-reported confidence is the voter's to set; weight by signals the voter cannot choose.
  • A threshold can refuse a weak or wrong majority, but it cannot find the right answer; escalate.
  • Agreement is not correctness; send the consensus to an independent verifier.

Ship it

Before shipping any consensus mechanism:

  • Attack-test with at least the three patterns above. Your protocol should fail predictably, not silently.
  • Log every minority cluster with provenance. Minority clusters are your early-warning system for correlated errors.
  • Enforce bounded rounds. No "keep debating until agreement" — that rewards sycophancy.
  • Separate agreement from correctness. Consensus output goes to a verifier; verifier is independent of the ensemble.
  • Monitor the agreement rate. A sharp rise means conformity bias; a sharp fall means model drift.

Given an ensemble of N agents answering a common question, design a consensus protocol that is robust to the three canonical LLM-agent attacks: byzantine lie, sycophantic conformity, correlated-error monoculture.

Produce:

1. **Clustering strategy.** How are answers grouped? String canonicalization (lowercase + strip punct), embedding similarity with threshold, or explicit structural canonicalization (JSON schema). State the expected cluster-granularity error rate.
2. **Weighting strategy.** Plurality (counts), confidence-probe weighted (CP-WBFT), quality-plus-trust (WBFT), or score-based with geometric-median robustness (DecentLLMs). Justify the choice from the attack profile.
3. **Threshold.** What fraction of total weight triggers acceptance? What happens below threshold: retry, escalate, or abstain?
4. **Diversity requirement.** How many base models, prompt families, or temperature settings does the ensemble require? Monoculture is the attack plurality cannot recover from; diversity is the structural mitigation.
5. **Independent verifier.** Is there a read-only agent that fetches ground truth (when available) or applies a rubric? Where does the verifier's output go? It must not re-enter the voting pool.
6. **Round bounding.** Max rounds before escalating. Default 2-3 for most tasks. Longer rounds amplify sycophancy.
7. **Attack-test table.** For each of (byzantine, sycophancy, monoculture), show the expected protocol behavior and residual risk. If the protocol admits a known failure mode, state it in one sentence.

Hard rejects:

- Any design that does plurality-only on a single base model. Monoculture makes this fail silently.
- Any design with unbounded rounds or "keep debating until agreement." This rewards conformity.
- Any design where the verifier's output feeds back into the voting pool. That poisons the verifier.
- Claims that BFT "solves" disagreement. BFT aligns outputs; correctness is a separate problem.

Refusal rules:

- If the task has no ground truth (opinion, synthesis, creative), say so and recommend "consensus as advisory, human as decider."
- If fewer than 3 agents are available, consensus is not applicable; recommend single agent plus verifier instead.
- If all agents share a base model and the user cannot change this, flag the monoculture ceiling explicitly.

Output: a one-page design brief. Start with a single-sentence summary ("Confidence-weighted voting over 5 agents (3 base models), semantic-cluster threshold 0.55, independent verifier re-fetches sources, max 2 rounds."), then the seven sections above. End with the attack-test table.

Solutions

SolutionP1 · 42%, rejected, 42%

Plurality: 42%. canonical() keeps the four honest answers apart, so all five clusters have one vote, and max returns the first cluster it saw, the liar's.

CP-WBFT: rejected. The liar's 0.6 is the largest single weight, but it is only 0.6 of 3.8, under the 0.5 threshold, so no answer is returned.

DecentLLMs: 42%. Every cluster has one member and no spread, so all score 1, and the tie again goes to the first vote.

SolutionB1 · A monoculture with self-set weights

What failed. The five agents share a base model, so on an unfamiliar category they share the same mistake; different prompts do not make their errors independent. Their self-reported confidence was high and uniform, which CP-WBFT reads as strong agreement. The consensus worked exactly as designed and agreed on a wrong answer.

What to change: - Diversify the voters: use models from different families or training data, so errors are less likely to coincide. - Weight by signals the voters cannot set: token probabilities or a calibrated probe, checked against labelled outcomes per category. - Watch the agreement rate: a sudden jump to unanimity on a new segment is a warning, not reassurance; route it to review. - Verify independently: send blocks on new categories to a rule-based check or a human before acting, and track the block rate per category.

Say what the plurality returns, what the aggregator that weighs each vote by its confidence returns, and what the canonicalization does with the answer 4.2 percent. python @dataclass class Vote: agent: str answer: str confidence: float def canonical(self) -> str: return "".join(c for c in self.answer.lower().strip() if c.isalnum() or c == "." or c == "%") def plurality(votes: list[Vote]) -> tuple[str, dict[str, int]]: counts: dict[str, int] = {} rep: dict[str, str] = {} for v in votes: key = v.canonical() counts[key] = counts.get(key, 0) + 1 rep.setdefault(key, v.answer) winner_key = max(counts, key=counts.get) return rep[winner_key], counts

Level 3 of 4 · about 12 minutes to answer well.

Short answer. Plurality counts three votes for 42% and two for 4.2% and returns the wrong answer, because it counts heads and the wrong cluster has more heads. The confidence-weighted aggregator sums confidence per cluster and compares the top cluster's share with a threshold. The wrong cluster has the larger sum, so with a threshold of 0.5 it also returns 42%, and with a higher threshold it can return no winner. The canonicalization keeps letters, digits, dots and percent signs, so 4.2 percent becomes 4.2percent and lands in a different cluster from 4.2%, which splits the right answer's votes.

What the code does.

canonical lowercases the answer, strips the ends, and keeps alphanumerics, the dot and the percent sign. It is the lesson's rough semantic clustering. plurality builds a count per canonical key, keeps the first original answer per key as its representative, and returns the key with the most votes.

The monoculture case.

Aggregator Rule Result here
Plurality Most votes Wrong, because three correlated votes beat two
Confidence-weighted Sum of confidence per cluster, top cluster must pass a threshold share Wrong, because the three votes carry more total confidence, or none when the share is under the threshold
Geometric-median style Score each cluster by its size and how tight its confidences are Wrong, because the cluster of three is larger and its confidences are also tight

The lesson's own takeaway is the limit: no aggregator solves a wrong cluster that is both larger and more confident than the right one. That case needs diversity of models or verification, not a better vote.

The canonicalization blind spot.

Two agents that mean the same value can land in two clusters. 4.2% and 4.2 percent differ after canonicalization, and so would four point two percent. Every split in the right cluster helps the wrong one. In production, canonicalize numbers with their units into one form, or cluster by embedding similarity, and keep the canonical key next to the original answer in the log so a reviewer can see when a split happened.

Where the two percentages come from.

The values in the scenario are the memory-poisoning numbers from the shared-memory lesson: a page says 4.2 percent and a retrieval agent writes 42 percent. The consensus lesson reuses them so that the vote is over a claim with a known source, which is also what makes a verifier possible after the vote.

What the plurality code cannot see.

It has no idea which agents share a base model, no confidence, no source. It returns the answer with the most votes and does not check whether the voters are independent or accurate. Independence makes a right majority more likely but does not guarantee it, and the prompt's three agents share a base model, so their errors are correlated.

Plausible wrong answers.

  • "Plurality is fine as long as there are at least five agents." Three agents on one model are a majority at any size as long as they are over half, and the count never sees the correlation.
  • "The canonicalization is good enough because it handles case and spaces." It splits 4.2% from 4.2 percent, and every split in the right cluster is a vote for the wrong one.
  • "Higher confidence means a more correct answer, so weight by it and you are done." Weighting helps against low-confidence conformity and does nothing when the wrong cluster is also the confident one.

Follow-ups an interviewer may ask.

  • (level 3) Why does plurality keep rep? Expected: so that it can return the original answer text for the winning key, since the canonical key is a comparison form and not an answer to show.
  • (level 3) No cluster reaches the threshold share in the weighted vote. What is the result? Expected: no winner, with the weights, so the caller retries or escalates instead of accepting a weak majority.
  • (level 4) The sycophancy case: two agents copy the first answer they saw with low confidence. Which aggregator catches it and why? Expected: the confidence-weighted one, because the copiers carry little weight, while plurality counts them as full votes.
  • (level 4) How would you test a replacement for canonical? Expected: a table of answer pairs that must cluster together and pairs that must not, including unit variants and spelled-out numbers, run as a unit test.

Explain the mechanismFive agents answer the same factual question and vote. Three of them run the same base model and agree on a wrong answer, and the two others are right. Majority vote picks the wrong answer. A colleague says that classical fault-tolerant consensus solves this. Explain why it does not, which assumptions break, and what the recent agent-specific protocols change.

Level 4 of 4 · about 15 minutes to answer well.

Short answer. Classical consensus tolerates fewer than a third of nodes behaving arbitrarily, and it assumes that faults are independent, that honest nodes are correct, and that a ground truth exists. Three agents on a shared base model share their faults, an honest model still hallucinates, and on some questions the agents define the truth. The agent-specific variants weigh each vote by a confidence probe, aggregate leaderless proposals by a geometric median, or split agents into a core and an edge with learned trust weights. None of them makes agreement equal correctness, so the consensus output still goes to an independent verifier.

What the classical protocol gives and assumes.

The standard protocol reaches agreement on one value among n nodes when fewer than n divided by three are faulty, which needs n at least three f plus one. It runs three phases over signed messages and quorum certificates. Its three assumptions:

  1. Faults are independent, so faulty nodes do not coordinate.
  2. Honest nodes are correct, so the protocol only aligns disagreement.
  3. The question has a ground truth, so agreement on a wrong value is still agreement.

Model agents break all three. Agents on one base model share faults. An honest agent hallucinates. And on an ambiguous question the agents decide what is true.

Three attacks that pass the signature check.

Attack What happens Does the classical protocol handle it
A deliberate lie One agent outputs a wrong answer with high confidence Yes, while the liars are under a third
Sycophantic conformity One agent reads the others and aligns with whoever spoke last No, because the agent passes every check
Correlated monoculture Three agents on one model hallucinate the same answer No, because all three honestly agree

The prompt's case is the third.

The agent-specific responses.

  • Confidence-weighted voting. Each voter attaches a confidence, self-reported or read by a probe trained on the model's hidden activations, and the vote weight scales with it. The paper's large gain on fully connected graphs comes from the hidden-state probe. It helps most against conformity, because an agent that adopted a position it did not derive tends to report low confidence.
  • Leaderless aggregation by geometric median. Workers propose in parallel, evaluators score the proposals, and the answer is the geometric median of the scored positions. It is robust while the faulty fraction is under a half, and it resists outliers and pulls toward the dense cluster rather than the model-biased mean.
  • Weighted voting with a core and an edge. Weights come from a response-quality score and a trust value. A small core reaches agreement first and the edge follows, which bounds latency and lets the core be chosen for diversity.

The stripped-down round.

Each agent produces an answer and a confidence. The aggregator groups answers into semantic clusters, so that two phrasings of one value count together, sums the confidence per cluster, and accepts the top cluster only when its share passes a threshold. Below the threshold it retries or escalates. The lesson's working range for the threshold is 0.5 to 0.67 with five to seven agents. Minority clusters are logged with provenance, because they are the early warning for correlated errors.

The uncomfortable measurement.

The lesson cites a study of scalar agreement (Berdoz, Rugli and Wattenhofer): even with no adversary, groups of LLM agents often failed to reach valid agreement, more so as groups grew, and a few Byzantine agents made it worse. A separate study found one deceptive agent among six cut a Mixture-of-Agents' AlpacaEval win rate from 49.2% to 37.9%. Consensus machinery aligns outputs. It does not tell you whether the aligned output is right.

Plausible wrong answers.

  • "Use the classical protocol with a two-thirds quorum." Three honest agents that share a hallucination form the quorum, and the protocol agrees on the wrong value.
  • "Add more copies of the same model until the majority is right." More copies of one model add more correlated votes, and the wrong cluster grows with them.
  • "Consensus means the answer is correct." Agreement and correctness are different measurements, and the consensus output needs a verifier that is independent of the ensemble.

Follow-ups an interviewer may ask.

  • (level 3) Does the geometric median rescue this case? Expected: no. The median discounts outliers and moves toward the dense cluster, which helps only while the wrong cluster is under half. Here three of five votes are wrong, so the dense cluster is the wrong one and the median selects it.
  • (level 3) The three wrong agents are also the most confident. What now? Expected: no aggregator fixes a wrong cluster that is both larger and more confident, so the system needs diversity of base models or an independent verifier.
  • (level 4) Why bound the rounds at two or three? Expected: agents that observe earlier rounds start to mimic each other regardless of truth, so more rounds reward conformity.
  • (level 4) What do you monitor in production? Expected: the agreement rate, where a sharp rise means conformity and a sharp fall means model drift, and the minority clusters with their provenance.
