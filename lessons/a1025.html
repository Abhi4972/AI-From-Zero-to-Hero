In plain words first
The idea in one line

A frontier LLM generating one token requires a full forward pass over billions of parameters. That forward pass is massively over-provisioned: most of the time a much smaller model can guess the next 3-5 tokens correctly, and the big model only needs to verify the guess. When the guess is right you got 5 tokens for the price of one. Speculative decoding (Leviathan et al. 2023) made this exact, and EAGLE-3 (2025) pushed acceptance rates to ~4.5 tokens per verify — a 4-5x speedup at matched output distribution.

The problem

In plain words first

This lesson revisits speculative decoding (Lesson 10.22) from the builder's side, with the opposite letters: here p is the big target model and q the small draft. A draft guesses a few tokens, the target checks them all in one pass, and an accept/reject rule keeps the output exactly as if the target had written alone. The new piece is the tree: instead of one chain of guesses, the draft offers several alternatives at each step, and a special attention mask lets the target check every branch in the same single pass. This lesson runs the lesson's toy, computes exactness, chains against trees and the effect of temperature, and then runs real greedy tree speculation with two SmolLM2 models, checking the output is identical to the target's own. No model is trained.

Decode throughput for a 70B-class model on H100 is typically 40-80 tokens/second. Each token requires a full forward pass reading all model weights from HBM. You cannot make the model smaller without changing its output. You cannot increase batch size beyond memory. You're stuck — unless you can let the model output more than one token per forward pass.

Autoregressive generation looks inherently serial: x_{t+1} = sample(p(· | x_{1:t})). But there is a concurrency opportunity. If you had a cheap predictor that said "the next 4 tokens are probably [a, b, c, d]" you could verify all 5 positions in a single forward pass of the big model and accept the longest matching prefix.

Leviathan, Kalman, Matias (2023, "Fast Inference from Transformers via Speculative Decoding") made this exact via a clever accept/reject rule that preserves the target model's sampling distribution. The same output distribution, 2-4× faster.

Idea 1 · The Two-Model Setup

  • Target model M_p: the big, slow, high-quality model you actually want samples from. Distribution: p(x).
  • Draft model M_q: a small, fast, lower-quality model. Distribution: q(x). 5-30× smaller.

Per step:

  1. Draft model proposes K tokens autoregressively: x_1, x_2, ..., x_K ~ q.
  2. Target model runs ONE forward pass over all K+1 positions in parallel, producing p(x_k) for each proposed token.
  3. Accept/reject each token left-to-right via the modified rejection-sampling rule below. Accept the longest matching prefix.
  4. If any token is rejected, sample the replacement from the corrected distribution and stop. Otherwise sample one bonus token from p(· | x_1...x_K).

If the draft matches the target perfectly, you get K+1 tokens per target-forward. If the draft is wrong at position 1, you get only 1 token.

Idea 2 · The Exactness Rule

Speculative decoding is provably equivalent in distribution to sampling from p. The rejection rule:

For each drafted token x_t:
    r ~ Uniform(0, 1)
    if r < p(x_t) / q(x_t):
        accept x_t
    else:
        sample replacement from residual: (p - q)+ / ||(p - q)+||_1
        stop

where (p - q)+ denotes the positive part of the pointwise difference. When the draft and target agree (p ≈ q) acceptance is nearly 1. When they disagree, the residual distribution is constructed so that the overall sample is still exactly p.

Greedy case. For temperature=0 sampling just check argmax(p) == x_t. If yes, accept; if no, output argmax(p) and stop.

Idea 3 · Expected Speedup

If the draft model's token-level acceptance rate is α, the expected tokens produced per target-forward pass is:

E[tokens]=1−α1−αK+1​K=draft length, α∈[0,1]

At α = 0.8, K = 4: (1 - 0.8^5)/(1 - 0.8) = 3.36 tokens per forward. A single target forward costs roughly cost_q * K + cost_p (K draft steps plus one target verify). If cost_p >> cost_q * K the speedup ratio is 3.36× / 1 = 3.36× on throughput.

The only real parameter is α, which depends entirely on the draft-target alignment. A good draft is everything.

Idea 4 · Training the Draft: Distillation

A random small model makes a poor draft. The standard recipe is to distill from the target:

  1. Pick a small architecture (~1B for a 70B target, ~500M for a 7B target).
  2. Run the target model on a large text corpus; store its next-token distributions.
  3. Train the draft with KL divergence against the target's distribution (not against ground-truth tokens).

The result: α typically 0.6-0.8 on coding, 0.7-0.85 on natural-language chat. Speedups 2-3× in production.

Idea 5 · EAGLE: Tree Drafting + Feature Reuse

Li, Wei, Zhang, Zhang (2024, "EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty") observed two inefficiencies in standard speculative decoding:

  1. The draft does K serial steps, each full-stack. But the draft could reuse the target's features (hidden states) from the most recent verify — the target already computed rich representations that the draft is re-deriving from scratch.
  2. The draft outputs a linear chain. If the draft could output a tree of candidates (each node multiple guesses), the target's single forward pass could verify multiple candidate paths in parallel via a tree attention mask, and pick the longest accepted branch.

EAGLE-1 changes: - Draft input = target's final hidden state at position t, not raw tokens. - Draft architecture = 1 transformer decoder layer (not a separate small model). - Output = tree of K = 4-8 candidates per depth, depth 4-6.

EAGLE-2 (2024) adds dynamic tree topology: the tree grows wider where the draft is uncertain and stays narrow where it is confident. Raises α_effective without increasing verify cost.

EAGLE-3 (Li et al. 2025, "EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test") removes the fixed top-layer feature dependency and trains the draft with a new "test-time simulation" loss — the draft is trained on outputs that match the target's test-time distribution rather than teacher-forced training distribution. In the paper, the mean number of tokens accepted per verify for LLaMA-3.1-8B-Instruct at temperature 0 rises from 4.11 (EAGLE-2) to 6.23 (EAGLE-3). Acceptance depends on the model pair, the draft tree and the traffic: Phase 10 · 15 quotes 0.88 to 0.92 per accepted-path token on chat benchmarks, and Phase 17 · 05 plans with 0.6 to 0.8 on production general chat.

Idea 6 · Tree Attention Verification

When the draft outputs a tree, the target model verifies it in a single forward pass using a tree attention mask — a causal mask that encodes the tree topology rather than a pure line. Each token attends only to its ancestors in the tree. The verify pass is still one forward, one matmul; the topological mask costs only a few extra KV entries.

        root
       /    \
      a      b
     / \    / \
    c  d   e   f

If a, b are competing first-token candidates and c, d, e, f are second-token candidates, all six positions are verified in one forward pass. The output is the longest prefix along any accepted path.

Idea 7 · When It Wins, When It Doesn't

Wins: - Chat / completion with predictable text (code, common English, structured output). α is high. - Settings with unused GPU compute during decode (memory-bound phase). Tree drafting uses the available FLOPs.

Loses / no win: - Highly stochastic outputs (creative writing at high temperature) can lower α, though not toward 1/|vocab|: as the temperature rises both distributions flatten and their overlap grows (computed after Build it). Measure it on your own model pair. - Batch serving with very high concurrency — batching already fills the FLOPs, little room for tree verification. - Very small target models where the draft isn't much smaller.

Production shops typically report 2-3× wall-clock speedup on chat, 3-5× on code generation, and near-zero on creative writing.

The same idea as a formula

In this lesson's notation (target p, draft q), a drafted x∼q is accepted with probability min(1,p(x)/q(x)); otherwise the token is drawn from r=(p−q)+​/∥(p−q)+​∥1​:

P(output=x)=min(q(x),p(x))+(1−α)r(x)=p(x),α=x∑​min(p(x),q(x)).

Greedy (T=0): accept while the drafted token equals the target's argmax; the output equals plain greedy decoding.

Trees. If the draft offers its top bd​ tokens at depth d and the target's choice falls among them with probability ad​(bd​), independently per depth:

E[tokens per verify]=1+d=1∑D​j≤d∏​aj​(bj​),nodes to verify=d=1∑D​j≤d∏​bj​.

Tree mask. Node i attends to the prefix, its ancestors and itself; its position is P−1+depth(i).

Worked example
A tree versus a chain

The target picks the draft's 1st choice with probability 0.60, its 2nd with 0.15, its 3rd with 0.07.

  • Chain of 3: 1+0.6+0.36+0.216=2.18 tokens per verify, 3 nodes.
  • Tree 2×2×1: depth 1 and 2 accept with 0.75, depth 3 with 0.6: 1+0.75+0.5625+0.3375=2.65 tokens, for 2+4+4=10 nodes.
  • Each extra token costs more nodes: the tree spends the target's idle compute (decoding is memory-bound) to raise acceptance, which pays at small batch and stops paying when the GPU is busy.

code/main.py:

  • A reference speculative_decode(target, draft, prompt, K, temperature) that implements the exact rejection rule and verifies it preserves the target's distribution (empirical KL < 0.01 vs plain target sampling).
  • An EAGLE-style tree drafter that builds a depth-K tree with top-p branching.
  • A tree attention mask builder that produces the right causal pattern for a verifier.
  • An acceptance-rate harness on toy distributions over a 32-token vocabulary (the run after Use it measures real tree speculation between two real models).
def speculative_step(p_target, q_draft, K, temperature=1.0):
    """One round of speculative decoding. Returns list of accepted tokens."""
    # 1. Draft K tokens
    draft_tokens = []
    q_dists = []
    state = draft_state_init()
    for _ in range(K):
        probs = softmax(q_draft(state) / temperature)
        t = np.random.choice(len(probs), p=probs)
        draft_tokens.append(t)
        q_dists.append(probs)
        state = draft_step(state, t)

    # 2. Target computes p at every drafted position + 1 extra
    p_probs_all = target_forward_batched(p_target, draft_tokens, temperature)

    # 3. Accept/reject left-to-right
    accepted = []
    for k, tok in enumerate(draft_tokens):
        r = np.random.uniform()
        if r < p_probs_all[k][tok] / q_dists[k][tok]:
            accepted.append(tok)
        else:
            residual = np.maximum(p_probs_all[k] - q_dists[k], 0)
            residual /= residual.sum()
            accepted.append(np.random.choice(len(residual), p=residual))
            return accepted
    # 4. All K accepted → sample bonus token from target
    accepted.append(np.random.choice(len(p_probs_all[-1]), p=p_probs_all[-1]))
    return accepted

import numpy as np
rng = np.random.default_rng(0)

print("A. Exactness, computed: one speculative step with target p and draft q (this lesson's notation)")
V = 6
p = rng.dirichlet(np.ones(V)); q = rng.dirichlet(np.ones(V))
acc = np.minimum(1, p / q)                          # accept a drafted x with probability min(1, p(x)/q(x))
alpha = (q * acc).sum()
res = np.maximum(p - q, 0); res /= res.sum()
out = q * acc + (1 - alpha) * res
print(f"  p   = {np.round(p, 3)}\n  q   = {np.round(q, 3)}\n  out = {np.round(out, 3)}   largest |out - p| = {np.abs(out - p).max():.1e}, alpha = {alpha:.3f}")
print()

print("B. Chains against trees (greedy): the target's next token is the draft's top-1 with probability 0.60,")
print("   its 2nd choice with 0.15, its 3rd with 0.07 (independent at each depth)")
rank = [0.60, 0.15, 0.07]
def expected(branch):                               # tokens per verify = 1 + expected number of accepted depths
    e, prod = 1.0, 1.0
    for b in branch:
        prod *= sum(rank[:b]); e += prod
    return e
for label, branch in [("chain of 3", (1, 1, 1)), ("chain of 5", (1, 1, 1, 1, 1)), ("tree 2 x 2 x 1", (2, 2, 1)),
                      ("tree 3 x 2 x 1 x 1", (3, 2, 1, 1)), ("tree 3 x 3 x 3", (3, 3, 3))]:
    nodes = sum(int(np.prod(branch[:i + 1])) for i in range(len(branch)))

print("C. Temperature and acceptance: alpha = sum(min(p_T, q_T)) for two similar random models, vocabulary 1,000")
z = rng.normal(0, 3, 1000)
zt, zd = z + rng.normal(0, 1.0, 1000), z + rng.normal(0, 1.0, 1000)      # target and draft logits
sm = lambda v: np.exp(v - v.max()) / np.exp(v - v.max()).sum()
print(f"  greedy (argmax agreement): {float(zt.argmax() == zd.argmax()):.0f}")
for T in [0.3, 0.7, 1.0, 1.5, 3.0, 10.0]:
    print(f"  T = {T:>4}: alpha = {np.minimum(sm(zt / T), sm(zd / T)).sum():.3f}")

Reading this output

A. Even with a draft that puts almost no probability where the target does (α = 0.25), the computed output distribution equals the target's to 6×10−17. Here p is the target and q the draft, the reverse of Lesson 10.22's letters; the rule is the same.

B. If the target's next token is the draft's first guess 60% of the time, a chain of 3 gives 2.18 tokens per verify and a chain of 5 only 2.38: each extra drafted token is less likely to be reached. Offering the 2nd guess too at the first two depths (10 nodes) gives 2.65, and a 21-node tree 3.03. A 39-node tree adds almost nothing (3.04): beyond a point, nodes far down unlikely branches are rarely used. This is why EAGLE-2 grows trees dynamically, wide where the draft is unsure and narrow where it is confident.

C. For two similar models, acceptance rises with temperature, from 0.02 at T=0.3 to 0.94 at T=10: flatter distributions overlap more, and at very high temperature both approach uniform and α approaches 1, not 1/∣V∣. In practice speculative decoding at high temperature disappoints for other reasons: sampled text is less predictable, and a draft trained or tuned at low temperature may match the target worse there. Measure α on your own pair and settings.

Use it: the same idea with real libraries

  • vLLM and SGLang ship first-class speculative decoding. In vLLM, pass --speculative-config a JSON object with method, model, and num_speculative_tokens; EAGLE-3 is "method": "eagle3".
  • NVIDIA TensorRT-LLM supports Medusa and EAGLE trees natively.
  • Reference draft models: Qwen/Qwen3-0.6B (drafts for Qwen3-32B), meta-llama/Llama-3.2-1B-Instruct (drafts for Llama 3.x 70B).
  • Medusa heads (Cai et al. 2024, "Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads"): instead of a draft model, add K parallel prediction heads to the target itself. Simpler to deploy, slightly lower acceptance than EAGLE.

Tree speculation with real models

SmolLM2-135M-Instruct drafts for SmolLM2-360M-Instruct, greedy, 60 tokens. First the tree mask is checked: a node's logits in the tree pass against a plain forward pass along its path. Then chains and trees are verified with one target pass each (a 4D attention mask and per-node positions in Hugging Face), counting passes and checking the output against plain greedy decoding. About two minutes on CPU (the draft recomputes its context for every node; real systems reuse caches).

import torch, transformers
from transformers import AutoTokenizer, AutoModelForCausalLM
transformers.logging.disable_progress_bar(); transformers.logging.set_verbosity_error()
tok = AutoTokenizer.from_pretrained("HuggingFaceTB/SmolLM2-360M-Instruct")
target = AutoModelForCausalLM.from_pretrained("HuggingFaceTB/SmolLM2-360M-Instruct", dtype=torch.float32).eval()
draft = AutoModelForCausalLM.from_pretrained("HuggingFaceTB/SmolLM2-135M-Instruct", dtype=torch.float32).eval()

def tree_logits(model, prefix, nodes, parents):
    """One forward pass over prefix + all tree nodes; node i sees the prefix, its ancestors and itself."""
    P, n = len(prefix), len(nodes)
    allowed = torch.zeros(P + n, P + n, dtype=torch.bool)
    allowed[:P, :P] = torch.tril(torch.ones(P, P, dtype=torch.bool))
    depth = []
    for i in range(n):
        allowed[P + i, :P] = True
        j, d = i, 0
        while j != -1:
            allowed[P + i, P + j] = True; j = parents[j]; d += 1
        depth.append(d)
    mask = torch.zeros(1, 1, P + n, P + n).masked_fill(~allowed, float("-inf"))
    pos = torch.tensor([list(range(P)) + [P - 1 + d for d in depth]])
    with torch.no_grad():
        out = model(torch.tensor([prefix + nodes]), attention_mask=mask, position_ids=pos).logits[0]
    return out[P - 1], out[P:]                                  # logits after the prefix, and after each node

prompt = tok.apply_chat_template([{"role": "user", "content": "Explain in a few sentences why the sky is blue."}],
                                 add_generation_prompt=True, tokenize=False)
prefix = tok(prompt)["input_ids"]

# 1. The tree mask is exact: every node's logits equal a plain forward pass along its path
nodes, parents = [tok.encode(" The")[0], tok.encode(" Light")[0], tok.encode(" sky")[0], tok.encode(" is")[0]], [-1, -1, 0, 2]
_, lt = tree_logits(target, prefix, nodes, parents)
with torch.no_grad():
    plain = target(torch.tensor([prefix + [nodes[0], nodes[2], nodes[3]]])).logits[0, -1]
print(f"tree mask check: node ' is' (path ' The sky is') vs a plain forward pass: largest logit difference "
      f"{(lt[3] - plain).abs().max():.1e}")

def build_tree(prefix, branch):                                 # draft proposes its top-b tokens at each depth
    nodes, parents, frontier = [], [], [(-1, prefix)]
    for b in branch:
        new = []
        for par, seq in frontier:
            with torch.no_grad():
                top = draft(torch.tensor([seq])).logits[0, -1].topk(b).indices.tolist()
            for t in top:
                nodes.append(t); parents.append(par); new.append((len(nodes) - 1, seq + [t]))
        frontier = new
    return nodes, parents

def generate(prefix, branch, n_new=60):
    seq, verifies = list(prefix), 0
    while len(seq) - len(prefix) < n_new:
        nodes, parents = build_tree(seq, branch)
        root, lt = tree_logits(target, seq, nodes, parents)
        verifies += 1
        cur, want = -1, root.argmax().item()                     # target's greedy choice after the accepted part
        while True:
            kids = [i for i, p in enumerate(parents) if p == cur and nodes[i] == want]
            if not kids: break
            cur = kids[0]; seq.append(nodes[cur]); want = lt[cur].argmax().item()
        seq.append(want)                                         # the target's own next token (correction or bonus)
    return seq[len(prefix):len(prefix) + n_new], verifies

with torch.no_grad():
    ref = target.generate(torch.tensor([prefix]), max_new_tokens=60, do_sample=False, pad_token_id=tok.eos_token_id)[0, len(prefix):].tolist()
print(f"\ngreedy decoding of 60 tokens; target SmolLM2-360M-Instruct, draft SmolLM2-135M-Instruct")
print(f"{'draft shape':<28} {'tree nodes':>10} {'verify passes':>14} {'tokens per pass':>16} {'same as plain greedy':>21}")
for label, branch in [("chain of 3", (1, 1, 1)), ("chain of 5", (1, 1, 1, 1, 1)), ("tree 2 x 2 x 1", (2, 2, 1)), ("tree 3 x 2 x 1 x 1", (3, 2, 1, 1))]:
    out, v = generate(prefix, branch)
    n_nodes = sum(1 for _ in build_tree(prefix, branch)[0])
    print(f"{label:<28} {n_nodes:>10} {v:>14} {60 / v:>16.2f} {str(out == ref[:60]):>21}")
print("\ntarget's answer: " + tok.decode(ref).replace("\n", " ")[:160])

The mask is exact. The tree pass gives the node " is" (on the path " The sky is", with a sibling branch " Light" in the same pass) exactly the logits of a plain forward pass over that path: the mask hides the sibling completely and the positions follow depth.

Chains and trees. All four shapes produce exactly the target's own greedy output, 60 of 60 tokens, as exact verification guarantees. A chain of 3 needs 22 target passes (2.7 tokens per pass), a chain of 5 needs 16 (3.75), and the 21-node tree 15 (4.0); the 10-node 2×2×1 tree, at 3.33, beats the chain of 3 with the same depth but not the longer chain. Trees buy acceptance at each depth; depth buys more tokens when the draft is often right, as here, where the target's answer is a fluent, predictable explanation of Rayleigh scattering.

Whether fewer passes means less time depends on the hardware: each pass here verifies up to 21 extra positions, nearly free on a GPU in memory-bound decoding, not free on this CPU. The run counts passes, not seconds.

  • EAGLE-3 draft checkpoints exist for Llama 3.x, Qwen3 and DeepSeek models; SpecForge (SGLang) and NVIDIA's tooling train new ones.
  • Tree verification with dynamic trees (EAGLE-2/3) is the default shape for EAGLE drafts in these engines.

Recap
What to keep from this lesson
  • Accept with min(1, p/q), resample from (p − q)₊: the output is exactly p.
  • Greedy speculation reproduces greedy decoding token for token.
  • Trees verify several alternatives in one pass with an ancestor-only attention mask.
  • Trees raise tokens per pass at the cost of more nodes, which idle compute pays for at small batch.
  • Temperature changes α in model-dependent ways; measure it.

Given the target model (size, family, tokenizer), the workload telemetry (task mix, prompt-vs-decode token ratio, p50/p99 decode latency, accelerator and HBM headroom, average batch size, sampling temperature distribution), and the available draft checkpoints, output:

1. Draft choice. Pick from same-family small (Llama-3.2-1B for Llama-70B), a distilled draft trained on the target's outputs, Medusa heads bolted on the target, or "no spec decode" if no draft is closer than 30 percent FLOP cost ratio. Confirm tokenizer match against the target byte-for-byte; refuse a mismatched tokenizer.
2. Draft length K. Argmax of E[tokens] / (1 + K x c) where c is the draft-to-target cost ratio. Show the work for K in 2, 3, 4, 5, 6 using the measured alpha from a calibration run on 5_000 tokens of in-distribution data. Default K=4 for chat, K=6 for code, K=2 for high-temperature creative writing.
3. Temperature gate. Set a temperature threshold above which spec decode is disabled. Default 0.8; lower to 0.6 if the calibration shows alpha collapsing earlier. Reject any temperature gate that depends on per-request inspection that adds more than 50 microseconds.
4. Tree budget. If the serving stack supports tree drafting, pick a small fixed tree (depth 2, branch 3-2) for batch under 8; flat chain for batch over 32. State the verifier's KV scratch size in bytes and confirm it fits in HBM headroom.
5. Fallback policy. Name the metric (sliding-window measured alpha over the last 1_000 verifies) and the threshold (alpha under 0.4) at which the server drops back to plain autoregressive decode for that request stream. Include the per-request lifetime of the fallback decision.

Refuse spec decode at batch size above the point where the verifier is compute-bound. Above that point the unused FLOPs the speculator is meant to soak up no longer exist; throughput drops. Refuse spec decode for any task family with measured alpha under 0.4; the draft overhead dominates and wall-clock latency gets worse. Refuse a draft that has not been validated on a held-out 1_000-token sample against the target: an unvalidated draft is a silent KL drift.

Example input: "Llama-3.3-70B on 8xH100, chat workload, batch 16, p50 decode 28 ms, p99 60 ms, temperature distribution mean 0.4 / max 1.2, calibration shows alpha 0.78 on chat, 0.61 on code."

Example output:
- Draft: Llama-3.2-1B-Instruct. Same tokenizer, same family, ratio c approx 0.03.
- K: 4. E[tokens/verify] = 3.4 chat, 2.5 code. K=5 gains 0.1 token chat and pays 0.03 extra c; reject.
- Temperature gate: 0.8. Above 0.8 alpha drops below 0.45 on the calibration set.
- Tree budget: depth 2 branch (3, 2). KV scratch 480 MB at batch 16 fits.
- Fallback: sliding-window alpha over last 1_000 verifies under 0.40 disables spec decode for that stream for 30 s, then probes again.

Exercises

  1. Implement the exact rejection rule and empirically verify it. Run 10K samples via speculative_decode and via plain target sampling; compute TV distance between the two output distributions. Should be < 0.01.

  2. Compute the speedup formula. Given fixed α and K, plot expected tokens per target-forward. Find the optimal K for α∈{0.5,0.7,0.9}.

  3. Train a tiny draft. Take a 124M GPT-2 target and distill a 30M GPT-2 draft on 100M tokens with KL loss. Measure α on held-out text. Expected: 0.6-0.7.

  4. Implement EAGLE-style tree drafting. Instead of a chain, have the draft output top-3 branches at each depth. Build the tree attention mask. Verify the target accepts the longest correct branch.

  5. Measure failure modes. Run speculative decode at temperature=1.5 (high stochasticity). Show α collapses and the algorithm is slower than plain decode due to draft overhead.

Solutions

SolutionP1 · The tree, by a little; the output is unchanged

The 21-node tree, by a little: 15 target passes for 60 tokens (4.0 per pass) against 16 for the chain of 5 (3.75), and both are far better than a chain of 3 (22 passes). Neither changes the output: every configuration reproduces plain greedy decoding token for token, because a drafted token is kept only if it is exactly the target's own choice. The tree's advantage is small here because the small draft's first guess is usually right on this predictable text; branches help most where the draft is unsure.

SolutionB1 · Depth 1 survives, deeper nodes break

Only the first level stays correct. With RoPE, a node's position decides how its key and query are rotated, so the target computes each node's logits as if the node were the token at that position. Depth-1 nodes really are at "last prefix position + 1", so they are verified correctly. A depth-2 node given the same position would appear to sit at the same position as its parent, so its logits are computed for a malformed sequence: the target may reject correct drafts (losing speed) or, worse, accept tokens on the basis of wrong logits, and the output would no longer match plain decoding. This is why tree verification sets each node's position from its depth, P − 1 + depth, as the real run does.
