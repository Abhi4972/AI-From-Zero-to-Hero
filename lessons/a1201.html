In plain words first
The idea in one line

Before anything multimodal, an image has to become a sequence of tokens a transformer can eat. The 2020 ViT paper answered this with 16x16 pixel patches, a linear projection, and a position embedding. Six years later frontier models still begin this way: Claude, for example, reads and bills images as 28×28-pixel patches, up to 2,576 px on the long edge for Claude 4.7 and later. The encoders changed from the original ViT to CLIP, DINOv2, SigLIP 2 and DINOv3, and some added register tokens or 2D-RoPE, but the primitive held. This lesson reads the patch-token pipeline end to end and builds it in

Terms you'll hear
Term What people say What it actually means
Patch "16x16 pixel square" A fixed-size non-overlapping region of the input image; becomes one token
Patch embedding "Linear projection" A shared learned matrix (or Conv2d with stride=P) mapping flattened patch pixels to D-dim vectors
CLS token "Class token" Prepended learnable vector whose final hidden state represents the whole image; optional in 2026
Register token "Sink token" Extra learnable tokens that absorb the high-norm attention artifacts ViTs develop during pretraining
Position embedding "Positional info" Per-position vector or rotation making the sequence-order-aware; 2D-RoPE is the modern default

NaFlex "Native flexible resolution" SigLIP 2 feature: single model serves multiple aspect ratios and resolutions without retraining
Backbone "Vision tower" The pretrained image encoder whose patch-token outputs feed the LLM in a VLM
Pooling "Image-level summary" Strategy to turn patch tokens into one vector: CLS, mean, attention pool, or register-based
Patch 14 vs 16 "Finer vs coarser grid" Patch 14 produces more tokens per image, better fidelity for OCR, slower; patch 16 is the classic default

The problem

In plain words first

A transformer reads a sequence of vectors, but a photo is a grid of pixels. A Vision Transformer (ViT) cuts the image into small squares called patches, typically 14 or 16 pixels on a side. It turns each patch into one vector with a single shared linear map and adds a position signal, so the model knows where each patch came from. The image is now a sequence of "visual tokens", like words in a sentence. Almost every model that reads images starts this way, from CLIP to today's chat assistants. This lesson builds the patch pipeline, counts tokens, parameters and compute, then measures real vision towers from their published configurations. It also looks inside a real DINOv2 model to see why some ViTs now carry extra "register" tokens. No model is trained.

Transformers operate on sequences of vectors. Text is already a sequence (bytes or tokens). An image is a 2D grid of pixels with three color channels — not a sequence. If you flatten every pixel, a 224x224 RGB image becomes 150,528 tokens, and self-attention at that length is a non-starter (quadratic in sequence length).

Pre-2020 approaches bolted a CNN feature extractor onto the front: ResNet produces a 7x7 feature map of 2048-dim vectors, feed those 49 tokens to a transformer. This works but inherits the CNN's biases (translation equivariance, local receptive fields) and loses the transformer's appetite for scale.

Dosovitskiy et al. (2020) asked the blunt question: what if we skip the CNN? Split the image into fixed-size patches (say 16x16 pixels), linearly project each patch into a vector, add a positional embedding, and feed the sequence to a vanilla transformer. At the time this was heresy — vision without convolutions. With enough data (JFT-300M, then LAION) it beat ResNet on ImageNet and kept improving.

By 2026 the ViT primitive is the unquestioned foundation. Every open-weights VLM's vision tower is some descendant (DINOv2, SigLIP 2, CLIP, EVA, InternViT). The question is no longer "should we use patches?" but "what patch size, what resolution schedule, what pretraining objective, what positional encoding."

Idea 1 · Patches as tokens

Given an image x of shape (H, W, 3) and a patch size P, you carve the image into a grid of (H/P) x (W/P) non-overlapping patches. Each patch is a P x P x 3 cube of pixels. Flatten each cube to a 3 P^2 vector. Apply a shared linear projection W_E of shape (3 P^2, D) to map each patch into the model's hidden dimension D.

For the ViT-B/16 canonical config: - Resolution 224, patch size 16 → grid 14x14 → 196 patch tokens. - Each patch is 16 x 16 x 3 = 768 pixel values, projected to D = 768. - Add a learnable [CLS] token → sequence length 197.

The patch projection is mathematically identical to a 2D convolution with kernel size P, stride P, and D output channels. That is how production code actually implements it — nn.Conv2d(3, D, kernel_size=P, stride=P). The "linear projection" framing is conceptual; the kernel framing is efficient.

Idea 2 · Positional embeddings

Patches have no inherent order — the transformer sees them as a bag. Early ViTs added a learnable 1D positional embedding (one 768-dim vector per position, 197 of them). Works, but ties the model to the training resolution: at inference you have to interpolate the position table if you change the grid.

Many modern vision backbones use 2D-RoPE (the vision encoders of Qwen2-VL and later, DINOv3) or factorized 2D positions. SigLIP 2 keeps a learned position table and resizes it bilinearly to each image's grid (its NaFlex variant). 2D-RoPE rotates the query and key vectors based on the patch's (row, column) index, so the model infers relative 2D position from the rotation angle. No position table. The model handles arbitrary grid sizes at inference.

Idea 3 · CLS token, pooled output, and register tokens

What is the image-level representation? Three choices coexist:

  1. [CLS] token. Prepend a learnable vector to the patch sequence. After all transformer blocks, the CLS token's hidden state is the image representation. Inherited from BERT. Used by original ViT, CLIP.
  2. Pool the patches. Average the patch tokens' output hidden states, or let a small learned query attend over them (the "MAP head" attention pooling of SigLIP and SigLIP 2). DINOv2's linear probes use the CLS token together with the mean of the patch tokens.
  3. Register tokens. Darcet et al. (2023) observed that ViTs trained without an explicit sink token develop high-norm "artifact" patches that hijack self-attention. Adding 4–16 learnable register tokens absorbs this load and improves dense-prediction quality (segmentation, depth). DINOv2 has variants with 4 registers (measured below), and DINOv3 uses 4 registers from the start; SigLIP 2 does not use them.

The choice matters for downstream tasks. CLS is fine for classification. For VLMs that feed patch tokens into an LLM, you skip pooling entirely — every patch becomes an LLM input token. Registers get discarded before handoff (they are scaffolding, not content).

The same idea as a formula

Patching. An H×W image with patch size P gives

N=PH​⋅PW​ patch tokens,zi​=WE​vec(xi​)+b+pi​,WE​∈RD×3P2,
where xi​ is the i-th P×P×3 patch and pi​ its position embedding. This is exactly a convolution with kernel P and stride P (checked numerically below).

Size of one transformer block with width D and a 4× MLP: 4D2 (Q, K, V, O) + 8D2 (MLP) =12D2 weights, plus 13D biases and LayerNorm parameters.

Compute per image: about 2 FLOPs per weight per token, plus attention, which grows with N2:

FLOPs≈2Nparams​N+4LN2D.
Doubling the resolution multiplies N by 4 and the attention term by 16.

Worked example
ViT-B/16 at 224 and at 384
  • At 224 px: 14×14=196 patches. Each is 16⋅16⋅3=768 numbers, projected to D=768.
  • Parameters: $12 \times 12 \cdot 768^2 \approx 84.9$M in the blocks, plus 0.6M for the patch embedding and 0.15M for positions: about 86M.
  • Compute at 224: 2⋅86M⋅196≈33.7 GFLOPs, plus attention 4⋅12⋅1962⋅768≈1.4 GFLOPs: about 35 GFLOPs.
  • At 384 px: 24×24=576 patches (2.9× as many). Compute: 2⋅86M⋅576≈99 GFLOPs, plus attention ≈12.2: about 111 GFLOPs, 3.2× the cost. The attention share grows from 4% to 11%.
  • In a VLM, those 576 tokens also become 576 LLM input tokens per image.

Registers in a real ViT

DINOv2 ViT-B/14 without and with 4 register tokens on 8 photos from Imagenette (224 px crops, 256 patches). For each model: the norm of the patch tokens at the last block, the number of patches with a norm far above the rest, and where the [CLS] token's last-layer attention goes. Inference only. About half a minute on CPU.

import torch
from datasets import load_dataset
from transformers import AutoImageProcessor, AutoModel, logging
logging.set_verbosity_error()

# 8 real photos (Imagenette validation set); DINOv2 ViT-B/14 trained without and with 4 register tokens
imgs = [r["image"].convert("RGB") for r in load_dataset("Multimodal-Fatima/Imagenette_validation", split="validation").select(range(0, 800, 100))]
proc = AutoImageProcessor.from_pretrained("facebook/dinov2-base")
x = proc(images=imgs, return_tensors="pt").pixel_values             # 224x224 crops -> 16x16 = 256 patches of 14 px
print(f"{len(imgs)} photos, input {tuple(x.shape[1:])}, {(x.shape[-1] // 14) ** 2} patch tokens each\n")

for name, repo, n_reg in [("DINOv2-B, no registers", "facebook/dinov2-base", 0),
                          ("DINOv2-B, 4 registers", "facebook/dinov2-with-registers-base", 4)]:
    m = AutoModel.from_pretrained(repo, attn_implementation="eager").eval()
    with torch.no_grad():
        out = m(pixel_values=x, output_attentions=True, output_hidden_states=True)
    h = out.hidden_states[-1]                                         # last block's output before the final LayerNorm: [CLS] + registers + 256 patches
    patch = h[:, 1 + n_reg:]
    norms = patch.norm(dim=-1)
    med = norms.median(dim=1, keepdim=True).values
    outliers = (norms > 3 * med).sum(1)                               # "artifact" tokens: norm far above the rest
    cls_att = out.attentions[-1][:, :, 0].mean(1)                     # last layer, [CLS] attention, averaged over heads
    top = cls_att[:, 1 + n_reg:].topk(4, dim=1).values.sum(1)         # attention on the 4 most-attended patches
    reg = cls_att[:, 1:1 + n_reg].sum(1) if n_reg else torch.zeros(len(imgs))
    print(f"{name}")
    print(f"  patch-token norm: median {norms.median():.1f}, max {norms.max():.1f} ({norms.max() / norms.median():.1f}x the median)")
    print(f"  high-norm patches (> 3x the image's median) per photo: {outliers.tolist()}")
    print(f"  [CLS] attention on its 4 most-attended patches: {top.mean():.0%} (of 256 patches)")
    if n_reg: print(f"  [CLS] attention on the 4 registers: {reg.mean():.0%}")
    print()

Reading this output

Without registers, [CLS] stares at a few patches. In the last layer, 30% of the [CLS] token's attention lands on just 4 of the 256 patches. Those patches are not the important parts of the photo. Darcet et al. showed that such patches usually sit in plain background and stop carrying local information. The model has repurposed them as scratch space for global information. Their norms show it: the largest patch norm is 4.3 times the median, and two of the eight photos have a patch more than 3 times the median.

With registers, the sink moves to the registers. The variant trained with 4 extra learnable tokens sends 27% of [CLS] attention to the registers and only 8% to its top 4 patches. Patch norms are even: the largest is 1.3 times the median, and no patch stands out. The patch tokens are left to describe their own patch, which is what dense tasks (segmentation, depth) and VLMs that read every patch want.

A note on this measurement. Eight photos and one model size are a small sample; artifacts are stronger in larger models trained longer (the paper's ViT-L and ViT-g). The norms here are taken before the final LayerNorm, because the LayerNorm hides the outliers.

Idea 4 · Pretraining: supervised, contrastive, masked, self-distilled

The 2020 ViT was pretrained with supervised classification on JFT-300M. Quickly supplanted by:

  • CLIP (2021): contrastive image-text on 400M pairs. Lesson 12.02.
  • MAE (2021, He et al.): mask 75% of patches, reconstruct pixels. Self-supervised, works on pure images.
  • DINO (2021) / DINOv2 (2023): self-distillation with student-teacher, no labels, no captions. The 2023 DINOv2 ViT-g/14 is the strongest purely-visual backbone and the default for "dense features" use cases.
  • SigLIP / SigLIP 2 (2023, 2025): CLIP with a sigmoid loss and NaFlex for native aspect ratio. A common vision tower in open VLMs (Idefics2, LLaVA-OneVision, PaliGemma 2, Gemma 3); others, such as Qwen2.5-VL and InternVL, train their own ViTs.

Your choice of pretraining determines what the backbone is good for: CLIP/SigLIP for semantic matching with text, DINOv2 for dense visual features, MAE as a starting point for downstream finetuning.

Idea 5 · Scaling laws

ViT scaling (Zhai et al. 2022) established that a ViT's quality obeys predictable laws in model size, data size, and compute. At fixed compute: - Bigger model + more data → better quality. - Patch size is a lever on sequence length vs fidelity. Patch 14 (typical for DINOv2/SigLIP SO400m) gives more tokens per image than patch 16; better for OCR and dense tasks, worse for speed. - Resolution is the other big lever. Going from 224 to 384 to 512 almost always helps, at quadratic cost in FLOPs.

DINOv2 ViT-g/14 (1.1B parameters, 256 tokens at 224 px) is the strongest purely visual backbone of its family. SigLIP So400m/14 (about 430M parameters with its pooling head, 729 tokens at 384 px) is one of the most common towers in open VLMs. Both are measured below.

Idea 6 · Parameter count for a ViT

The full calculation lives in code/main.py. For ViT-B/16 at 224:

patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M

Ball-park every ViT this way before you load the checkpoint. The backbone size sets your VRAM floor in any downstream VLM.

Reading this output

The hand count is right. The lesson's formula gives 85.8M for ViT-B/16, and the real model, built from Google's configuration, has 86M. The small difference is the pooler layer that the transformers implementation adds. You can size any ViT this way before downloading a byte.

Patch size and resolution set the token count. ViT-B/16 at 224 px makes 196 tokens. CLIP ViT-L/14 at 336 px makes 576, and SigLIP So400m/14 at 384 px makes 729 (27 × 27; the last 6 pixels do not fill a patch). In a VLM each of those tokens becomes an LLM input token, so the vision tower's grid decides a large part of the prompt length.

Compute grows faster than parameters. DINOv2 ViT-g has 2.7 times SigLIP's parameters (1,136M against 428M) but needs less compute per image (598 against 690 GFLOPs), because it sees 256 tokens instead of 729. For a vision tower, resolution is usually the bigger cost lever.

SigLIP and SigLIP 2 have the same shape. Both So400m/14 towers have 27 layers of width 1,152 and 428M parameters. SigLIP 2 changed the training (extra captioning and self-distillation losses, more languages, NaFlex), not the architecture. So it can replace SigLIP in an existing VLM recipe.

The patch embedding is a convolution. Unfolding the image into 196 flat patches and multiplying by the convolution's weights gives the convolution's output to within 3e-06, which is float32 rounding.

Idea 7 · 2026 production config

A common encoder in open VLMs is SigLIP or SigLIP 2 So400m/14. It has: - About 400M parameters (428M in the transformers implementation, which counts the attention-pooling head). - Patch size 14. At 384 px the grid is 27 × 27 = 729 patch tokens (whole patches cover 378 px; the remaining 6 px are dropped). - Attention pooling (the MAP head) for one image-level embedding. For visual question answering, all 729 patch tokens flow into the LLM instead, usually through a projector that may merge neighbouring patches (Lesson 12.6). - No register tokens. - Learned position embeddings. The NaFlex variant resizes them to each image's own grid, so the aspect ratio is kept.

Hosted models follow the same arithmetic. Claude counts ⌈width / 28⌉ × ⌈height / 28⌉ visual tokens per image, so a 1920×1080 screenshot costs 2,691 input tokens on Claude 4.7 and later models.

Every decision in that config traces back to a paper you can read.

Industry practice
What's current (2024–2026)
  • SigLIP 2 (February 2025): sigmoid contrastive pretraining plus captioning and self-distillation losses, sizes from 86M to 1B, and a NaFlex variant for native aspect ratios. It is widely used as the vision tower of open VLMs.
  • DINOv3 (August 2025): self-supervised ViT-7B/16 with RoPE and 4 register tokens, plus distilled smaller models, for dense features.
  • Native-resolution encoders in VLMs: Qwen2.5-VL and later and InternVL train their own ViTs with 2D-RoPE, taking images at their own size and merging neighbouring patches before the LLM.
  • Hosted pricing follows patches: Claude counts 28×28-pixel visual tokens per image, with a higher resolution limit (2,576 px, 4,784 tokens) on Claude 4.7 and later.

Sources: SigLIP 2 (arXiv 2502.14786), DINOv3 ViT-7B model card, Vision Transformers Need Registers (arXiv 2309.16588), Claude vision documentation, Hugging Face SigLIP 2 documentation.

Recap
What to keep from this lesson
  • Patches of P × P pixels become tokens through one shared linear map (a strided convolution).
  • Tokens = (H/P)(W/P): resolution is the main cost lever, and attention grows faster still.
  • Position comes from learned tables (resized when the grid changes) or 2D-RoPE.
  • Image-level summaries: CLS, mean or attention pooling; VLMs pass all patch tokens on.
  • Registers absorb the attention sink that ViTs otherwise build out of a few patches.

Given a vision backbone config (patch size, resolution, hidden dim, depth, heads, optional registers), produce a geometry analysis that tells the caller how many tokens this encoder will emit, how much VRAM it costs to run, and whether it is the right pick for a downstream VLM or dense-prediction task.

Produce:

1. Patch grid and sequence length. Grid shape (H/P, W/P). Sequence length including CLS, registers, and any pooling token. Highlight multi-resolution support (NaFlex, AnyRes) when declared.
2. Parameter breakdown. Patch embed, position embed, transformer blocks (attention + MLP), final LN, totals in both exact counts and human-readable (e.g., 86.4M).
3. FLOPs per forward. Attention (4 N D^2 + 2 N^2 D per block) and MLP (16 N D^2 per block), summed across depth. Flag quadratic-in-N costs that will bite at high resolution.
4. VRAM estimate. Activation memory at inference for a single forward on one image, plus KV-equivalent cache if the encoder feeds a downstream LLM.
5. Pooling recommendation. CLS, mean patch, register-based, or skip-pooling-for-VLM, based on the declared downstream task.

Hard rejects:
- Any analysis that treats patch tokens as pixel-identical to the input. The projection is a learned linear map; patches are abstract vectors, not pixels.
- Claiming CLS is always the right pooling. Modern dense-feature and VLM paths skip CLS entirely.
- Treating 2D-RoPE and learned positional embeddings as interchangeable without noting NaFlex-style native-resolution flexibility.

Refusal rules:
- If the provided config declares a patch size that does not evenly divide the image size, refuse — this is not a NaFlex-compatible config without a declared padding scheme.
- If the caller asks for exact pretrained weight counts for proprietary models (Gemini, Claude, GPT-5), refuse — these are not published.
- If the target deployment VRAM is under 4GB for a ViT-g/14-class model, refuse and recommend a SigLIP SO400m/14 or smaller backbone.

Output: a one-page geometry analysis with token count, parameter breakdown, FLOPs estimate, VRAM budget, and a recommended pooling strategy. Solutions

SolutionP1 · About a third, and much less with registers

About 30%: without registers, the [CLS] token's last-layer attention puts 30% of its weight on 4 of the 256 patches, and the largest patch norm is 4.3 times the median. With 4 registers, the top 4 patches get only 8%, while the registers take 27%. The model still needs a place to store global information; registers give it one that is not a patch of the image.

SolutionB1 · The position table no longer fits

At 448 px the grid is 28 × 28 = 784 patches, plus [CLS] = 785 positions, but the learned table has 197 rows. Adding a 785-row sequence to a 197-row table is a shape error. Hugging Face's ViT raises one unless you pass interpolate_pos_encoding=True. The usual fix is that flag: treat the 14 × 14 table (without [CLS]) as a small image, resize it to 28 × 28 with bicubic interpolation, and use that. It works, but the model has never seen those interpolated positions, so quality usually drops a little until it is fine-tuned at the new resolution. This is why "train at low resolution, fine-tune briefly at high resolution" is standard. It is also why encoders built for many resolutions use 2D-RoPE, or resize the table on every input, as NaFlex does.
