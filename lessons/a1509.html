The idea in one line

SWE-bench Verified went from 4% to 80.9% in under three years. The same model can score very differently in different scaffolds — on Terminal Bench 2.0, harness changes alone took LangChain's agent from 52.8% to 66.5% with GPT-5.2-Codex — so the scaffolding around the model now matters as much as the model itself. OpenHands (formerly OpenDevin) is the most active MIT-licensed platform and its CodeAct loop executes Python actions directly in a sandbox instead of JSON tool calls. The headline numbers hide a methodological issue: Epoch AI rates 39% of SWE-bench Verified tasks as trivial changes (under 15 minutes for an engineer, about 5 changed lines on average), and on Scale's SWE-bench Pro (larger, multi-file changes) the same frontier models score far lower.

The problem

In plain words first

A coding agent is a model inside a scaffold: the loop that finds files, edits them, runs tests and feeds results back. The same model scores very differently in different scaffolds. Two designs dominate. With JSON tool calls the model asks for one action at a time and the host validates each one. With CodeAct the model writes a short program that runs in a sandbox, which can do much more in one step, good or bad. Specialized agents (coding, browser, research) and Deep Agents harnesses are covered in Lessons 14.14 and 14.70 (linked above). This lesson runs both scaffolds with a real small model on the lesson's three-bug repo, with real tests.

"Which coding agent is best" is the wrong question. The right question is: on a task distribution that matches my work, with the scaffolding I will run in production, what end-to-end reliability do I get?

Between 2022 and 2026 the field learned that scaffolding — the retrieval layer, the planner, the sandbox, the edit-verify loop, the feedback format — is load-bearing. On Terminal Bench 2.0, LangChain kept GPT-5.2-Codex fixed and changed only its harness, moving from 52.8% to 66.5% (February 2026). 13.7 absolute points of difference, same weights. The base model is a component; the loop is the product.

The companion problem is that benchmark saturation hides regressions. SWE-bench Verified is close to saturated, and the easy-task tail (Epoch AI rates 39% of tasks as trivial, under 15 minutes and about 5 changed lines) pulls top scores up. Real-world quality is better measured on distributions like SWE-bench Pro (10+ line changes), where the same leaders score far lower (about 23% at its September 2025 launch, around 40–60% on Scale's public set by late 2026).

Idea 1 · SWE-bench, one paragraph

SWE-bench (Jimenez et al.) takes real GitHub issues with ground-truth patches and asks an agent to produce a patch that makes the test suite pass. SWE-bench Verified (OpenAI, 2024) is a human-curated 500-task subset with the ambiguous and broken tasks removed. SWE-bench Pro is the harder successor — larger, multi-file changes from Scale AI, where frontier agents score well below their Verified numbers.

Idea 2 · What the 2022 → 2026 curve actually shows

  • 2022: research models at ~4% on raw SWE-bench.
  • 2024: GPT-4 + Devin-style scaffolding at ~14%; SWE-agent at ~12%.
  • 2025: Claude 3.5/3.7 Sonnet inside Aider and SWE-agent push into the 40–55% range.
  • 2026: Claude Sonnet 4.5 and frontier competitors at 70–80%+ on SWE-bench Verified. Epoch AI's leaderboard tracks this live.

The slope came from three compounding sources: better base models, better scaffolding (CodeAct, reflection, verifier loops), and better benchmarks (Verified removing noise).

Idea 3 · CodeAct vs JSON tool calls

OpenHands (All-Hands-AI, arXiv:2407.16741, formerly OpenDevin) took a specific architectural bet: instead of the model emitting JSON tool calls that a host decodes and executes, the model emits Python code and a Jupyter-style kernel runs it in a sandbox. The agent can loop over files, chain tools, and catch its own exceptions inside one action.

The trade-off:

  • JSON tool calls: every action is one turn; easy to audit; limited compositionality; safe by default because each call goes through an explicit validator.
  • CodeAct: one action can be a whole program; compositional; requires a hardened sandbox (OpenHands uses Docker isolation); failure modes include anything the sandbox runtime allows.

Both architectures are in production. CodeAct is dominant in open platforms (OpenHands, smolagents). JSON tool calls remain dominant in managed services (Anthropic Managed Agents, OpenAI Assistants) where the provider controls the executor.

Idea 5 · Why scaffolding dominates

A coding run is a long-horizon trajectory (Lesson 1). Reliability compounds across steps. Three places where scaffolding buys points:

  1. Retrieval: finding the right files to read is the silent bottleneck. SWE-agent's ACI, OpenHands' file-index, and Aider's repo-map all attack this.
  2. Verifier loop: running tests, reading stack traces, and re-attempting is a 10+ point delta on SWE-bench.
  3. Failure containment: a sandbox that rolls back on error prevents compounding damage. The same model with and without a verifier loop looks like two different products.

Idea 6 · Benchmark saturation and the real distribution

Epoch AI flags that SWE-bench Verified has an easy tail: it rates 39% of tasks as trivial changes, under 15 minutes for an engineer and about 5 changed lines on average. High scores are driven partly by this tail. SWE-bench Pro restricts to 10+ line changes and returns much lower scores even for frontier systems. Your production distribution is almost certainly closer to Pro than to Verified.

Implication for choosing an agent: run a Pro-like subset of your own bug backlog. The score that matters is the score on tasks representative of what you ship.

The same idea as a formula

Scaffold reliability compounds. If a scaffold needs N actions and each succeeds with probability p, the run succeeds with about pN (15.1). CodeAct lowers N by doing several edits per action; JSON tool calls keep each action small and checkable. Neither changes p by itself; feedback (test results, error messages) and guards change p.

Blast radius. For an action a, let R(a) be the set of files, processes and endpoints it can affect. A validated JSON call has ∣R(a)∣=1 by construction. A CodeAct snippet has R(a) = everything the sandbox allows, so the sandbox, not the model, sets the bound.

Benchmark mix. A reported score is S=∑b​wb​sb​ over task buckets b. If 39% of tasks are trivial and solved almost always, they lift S whatever happens on the hard buckets you care about. Report sb​ by bucket.

Worked example
One benchmark, two mixes
  • Say a model solves 95% of trivial tasks, 60% of medium ones and 20% of hard ones.
  • On a Verified-like mix (39% trivial, 53% medium, 8% hard): 0.39⋅0.95+0.53⋅0.60+0.08⋅0.20=0.71.
  • On a backlog that is 10% trivial, 50% medium and 40% hard: 0.095+0.30+0.08=0.48.
  • Same model, same scaffold: 71% against 48%. Only the task mix changed.
Check your mental model
  • ✗ "Pick the model with the best SWE-bench score."
    ✓ Pick the model and scaffold with the best score on tasks like yours.
  • ✗ "CodeAct is more capable, so it is better."
    ✓ It does more per action and can break more per action. The sandbox sets the limit.
  • ✗ "A sandbox is just for safety."
    ✓ It also shapes behaviour: Python's -I mode dropped the repo from sys.path and broke every import until the scaffold added it back.
  • ✗ "A better scaffold rescues any model."
    ✓ Below a capability floor nothing works: here all three scaffolds fixed 0 of 3 bugs, each failing differently.

JSON tool calls, for real

Qwen2.5-0.5B-Instruct (greedy, CPU) is forced to answer each turn with one tool call. The host validates it: only the three repository files can be read or written, and an identical repeated call is refused with a hint. Tests really run, in a sandbox. About 2 minutes.

# The lesson's three-bug repo with real tests and a real model. Scaffold 1, JSON tool calls: Qwen2.5-0.5B-Instruct
# (greedy, CPU) must reply with one tool call per turn (read_file, write_file, run_tests, done), forced by starting
# its reply inside a <tool_call> block. Each call is validated and executed by the host: only the three repo files
# may be read or written, and an identical repeated call is refused with a hint. Up to 12 turns. About 2 minutes.
import json, os, pathlib, re, subprocess, sys, tempfile, warnings
os.environ["HF_HUB_OFFLINE"] = "1"
warnings.filterwarnings("ignore")
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, logging as hf_logging
from main import INITIAL_REPO
hf_logging.set_verbosity_error(); hf_logging.disable_progress_bar()
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
llm = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct").eval()
TEST_SRC = ("import sys; sys.path.insert(0, '.')\nresults = []\n"
            "for name, expr in [('app.py', 'add(2, 3) == 5'), ('util.py', \"lower('AB') == 'ab'\"), ('cli.py', \"VERSION == 'v1.0'\")]:\n"
            "    ns = {}\n    try:\n        exec(open(name).read(), ns); results.append(bool(eval(expr, ns)))\n"
            "    except Exception:\n        results.append(False)\nprint(results)\n")
def make_repo():
    root = pathlib.Path(tempfile.mkdtemp())
    for p, s in INITIAL_REPO.items():
        (root / p).write_text(s)
    return root
def real_tests(root):
    p = subprocess.run(["unshare", "-n", sys.executable, "-I", "-c", TEST_SRC], cwd=root, capture_output=True, text=True, timeout=20)
    try:
        return json.loads(p.stdout.strip().lower())
    except json.JSONDecodeError:
        return [False, False, False]
def fn(name, desc, **params):
    return {"type": "function", "function": {"name": name, "description": desc, "parameters": {
        "type": "object", "properties": {k: {"type": "string", "description": v} for k, v in params.items()}, "required": list(params)}}}
TOOLS = [fn("read_file", "Read one repository file", path="app.py, util.py or cli.py"),
         fn("write_file", "Replace one repository file with new content", path="file name", content="the full new file"),
         fn("run_tests", "Run the test suite; returns pass/fail per file"),
         fn("done", "Finish when all tests pass")]
ALLOWED = set(INITIAL_REPO)
def step(messages):
    ids = tok.apply_chat_template(messages, tools=TOOLS, add_generation_prompt=True, return_tensors="pt", return_dict=True)["input_ids"]
    forced = '<tool_call>\n{"name": "'
    ids = torch.cat([ids, tok(forced, return_tensors="pt")["input_ids"]], dim=1)
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=120, do_sample=False)
    text = forced + tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True)
    m = re.search(r"<tool_call>\s*(\{.*?\})\s*(?:</tool_call>|$)", text, re.S)
    try:
        d = json.loads(m.group(1)); return d["name"], d.get("arguments", {}) or {}
    except (AttributeError, json.JSONDecodeError, KeyError):
        return "malformed", {}
root = make_repo()
messages = [{"role": "system", "content": "You fix bugs in a small repository. Tests: add(2, 3) == 5 in app.py; "
             "lower('AB') == 'ab' in util.py; VERSION == 'v1.0' in cli.py. Use the tools; call done when tests pass."},
            {"role": "user", "content": "Fix the repository so all three tests pass."}]
JSON_LOG = []
last = None
for turn in range(1, 13):
    name, args = step(messages)
    path = str(args.get("path", ""))
    if (name, json.dumps(args, sort_keys=True)) == last and name != "write_file":
        # scaffold rule: an identical repeat is refused with a hint, so the loop cannot stall on one call
        result = "refused: you just made this exact call. Read a file you have not read, or write a fix."
        JSON_LOG.append((turn, name, "repeat refused"))
        messages += [{"role": "assistant", "content": "", "tool_calls": [{"type": "function", "function": {"name": name, "arguments": args}}]},
                     {"role": "tool", "name": name, "content": result}]
        continue
    last = (name, json.dumps(args, sort_keys=True))
    if name == "read_file":
        result = (root / path).read_text() if path in ALLOWED else f"refused: {path!r} is not a repository file"
    elif name == "write_file":
        if path in ALLOWED and isinstance(args.get("content"), str):
            (root / path).write_text(args["content"]); result = f"wrote {path}"
        else:
            result = f"refused: write to {path!r}"
    elif name == "run_tests":
        result = str(real_tests(root))
    elif name == "done":
        JSON_LOG.append((turn, name, "")); break
    else:
        result = "refused: unknown or malformed tool call"
    JSON_LOG.append((turn, name, path or result[:30]))
    messages += [{"role": "assistant", "content": "", "tool_calls": [{"type": "function", "function": {"name": name, "arguments": args}}]},
                 {"role": "tool", "name": name, "content": result}]
print("JSON tool-call scaffold:")
for t, n, p in JSON_LOG:
    print(f"   turn {t:>2}  {n:<11} {p}")
JSON_RESULT = real_tests(root)
print(f"   tests passing at the end: {JSON_RESULT}   turns used: {len(JSON_LOG)}   files any one action could touch: 1")

The JSON scaffold stalls on its first call. The model calls run_tests on turn 1, sees three failures, and then asks for run_tests again on all 11 remaining turns. The repeat rule refuses each one and asks for a read or a write, but the model never changes action. No file is read or written.

CodeAct, in a sandbox

This block continues from the one above. The same model writes a Python snippet each turn, using read, write and run_tests helpers. The snippet runs in a fresh folder with no network, isolated Python and a 20-second limit, and a static check lists what it reaches beyond the helpers. About 2 minutes.

# This block continues from the one above. Scaffold 2, CodeAct: the same model writes one Python snippet per turn,
# with read(path), write(path, text) and run_tests() defined for it. Each snippet runs in a sandbox: a copy of
# the repo in a fresh folder, no network, isolated Python, 20 s limit. A static check records what each snippet
# could reach beyond the helpers (imports, open(), absolute paths). Up to 4 turns. Then a third, guided scaffold:
# the host picks the failing file and asks only for its fix. About 3 minutes.
import ast
HELPERS = ("import json, sys\nsys.path.insert(0, '.')\n"
           "def read(p):\n    return open(p).read()\n"
           "def write(p, s):\n    open(p, 'w').write(s); TOUCHED.add(p)\n"
           "TOUCHED = set()\n"
           "def run_tests():\n" + "".join("    " + l + "\n" for l in TEST_SRC.replace("print(results)", "return results").splitlines()))
def reach(code):
    """What a snippet can do beyond the helpers: the CodeAct blast radius, read statically."""
    try:
        tree = ast.parse(code)
    except SyntaxError:
        return ["does not parse"]
    found = []
    for n in ast.walk(tree):
        if isinstance(n, (ast.Import, ast.ImportFrom)):
            found.append("import " + ", ".join(a.name for a in n.names) if isinstance(n, ast.Import) else f"from {n.module} import")
        if isinstance(n, ast.Call) and getattr(n.func, "id", "") in ("open", "exec", "eval", "__import__"):
            found.append(f"{n.func.id}()")
        if isinstance(n, ast.Constant) and isinstance(n.value, str) and n.value.startswith("/"):
            found.append(f"path {n.value[:20]}")
    return found
print("CodeAct scaffold:")
root2 = make_repo()
history, CODEACT_LOG = "", []
for turn in range(1, 5):
    prompt = (f"Repository files:\n" + "\n".join(f"--- {p}\n{(root2 / p).read_text()}" for p in INITIAL_REPO) +
              "\nTests: add(2, 3) == 5 in app.py; lower('AB') == 'ab' in util.py; VERSION == 'v1.0' in cli.py.\n"
              "You can call read(path), write(path, text) and run_tests(), which returns a list of booleans.\n"
              f"{history}Write one Python snippet that fixes the bugs and then prints run_tests(). Return it in a ```python block.")
    ids = tok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True, return_tensors="pt", return_dict=True)["input_ids"]
    with torch.no_grad():
        out = llm.generate(ids, max_new_tokens=300, do_sample=False)
    text = tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True)
    m = re.search(r"```(?:python)?\n(.*?)(?:```|$)", text, re.S)
    code = m.group(1) if m else ""
    sandbox_dir = pathlib.Path(tempfile.mkdtemp())
    for p in INITIAL_REPO:
        (sandbox_dir / p).write_text((root2 / p).read_text())
    (sandbox_dir / "snippet.py").write_text(HELPERS + code + "\nprint('TOUCHED', sorted(TOUCHED))\n")
    try:
        p = subprocess.run(["unshare", "-n", sys.executable, "-I", "snippet.py"], cwd=sandbox_dir, capture_output=True, text=True, timeout=20)
        err = (p.stderr.strip().splitlines() or [""])[-1]
    except subprocess.TimeoutExpired:
        err = "timeout"
    touched = re.findall(r"TOUCHED \[(.*?)\]", p.stdout if err != "timeout" else "")
    for f in INITIAL_REPO:                        # keep the snippet's edits to repo files only
        (root2 / f).write_text((sandbox_dir / f).read_text())
    res = real_tests(root2)
    CODEACT_LOG.append((turn, touched[0] if touched else "-", reach(code), err[:50], res))
    print(f"   turn {turn}  files written: {touched[0] if touched else 'none':<28} reaches beyond helpers: {reach(code) or 'nothing'}")
    print(f"           error: {err[:60] or 'none'}   tests now: {res}")
    if all(res):
        break
    history = f"Your last snippet left the tests at {res}{' with error ' + err[:80] if err else ''}.\n"

print("\nguided scaffold: the host finds the failing test, shows only that file, asks for the fixed file, re-runs the tests")

for f in INITIAL_REPO:

Use it: the same idea with real libraries

code/main.py compares two toy agent scaffolds on a fixed mini-task distribution:

  1. A JSON tool-call scaffold that takes one action per turn.
  2. A CodeAct scaffold that can emit a small Python snippet per action.

Both use a stub "model" (deterministic rules) so the comparison isolates the scaffold from model quality. The output shows the CodeAct scaffold solves more tasks in fewer turns at the cost of a larger per-action blast radius.

The whole of code/main.py follows in parts. Each part runs on this page, in order, in one Python session; the last part does what python3 code/main.py does.

Part 1 of 4 · run_tests, _apply_fix

"""CodeAct vs JSON tool-call scaffold comparison — stdlib Python.

Both scaffolds use the same stub "model" (deterministic rules) so the
comparison isolates the scaffold from model quality. Metrics:
  - tasks solved
  - turns used
  - per-action blast radius (number of files an action can touch)

The point is pedagogical: scaffolding is load-bearing. OpenHands
(arXiv:2407.16741) made the CodeAct bet explicitly; JSON tool calls
dominate managed services where the provider controls the executor.
"""

from __future__ import annotations

import json
from dataclasses import dataclass, field


# ---------- Mini-world: a tiny in-memory "repo" ----------

INITIAL_REPO = {
    "app.py": "def add(a, b):\n    return a - b\n",
    "util.py": "def lower(s):\n    return s.upper()\n",
    "cli.py": "VERSION = 'v0.0'\n",
}

TESTS = [
    ("app.py", "add(2, 3) == 5"),
    ("util.py", "lower('AB') == 'ab'"),
    ("cli.py", "VERSION == 'v1.0'"),
]

# Per-path replacement the stub "model" applies when a test fails.
# Centralizing the table avoids duplicating the if/elif chain across
# both scaffolds and avoids UnboundLocalError if TESTS later grows.
FIXES: dict[str, tuple[str, str]] = {
    "app.py": ("a - b", "a + b"),
    "util.py": ("s.upper()", "s.lower()"),
    "cli.py": ("v0.0", "v1.0"),
}


def run_tests(repo: dict[str, str]) -> list[bool]:
    """Deterministic stub: simulate the test suite against the repo string."""
    results = []
    for path, _expr in TESTS:
        src = repo.get(path, "")
        passed = False
        if path == "app.py":
            passed = "return a + b" in src
        elif path == "util.py":
            passed = "return s.lower()" in src
        elif path == "cli.py":
            passed = "VERSION = 'v1.0'" in src
        results.append(passed)
    return results


def _apply_fix(repo: dict[str, str], path: str) -> bool:
    """Apply the per-path fix in place. Returns True iff a fix was applied."""
    rule = FIXES.get(path)
    if rule is None:
        return False
    old, new = rule
    repo[path] = repo[path].replace(old, new)
    return True

@dataclass
class JsonScaffold:
    repo: dict[str, str] = field(default_factory=lambda: dict(INITIAL_REPO))
    turns: int = 0

    def step(self) -> str:
        """Return one JSON action at a time, based on current failing test."""
        self.turns += 1
        results = run_tests(self.repo)
        for (path, _), ok in zip(TESTS, results, strict=True):
            if ok:
                continue
            if _apply_fix(self.repo, path):
                return json.dumps({"tool": "edit", "path": path})
        return json.dumps({"tool": "done"})

    def blast_radius(self) -> int:
        return 1  # each action touches exactly one file

    def run(self, max_turns: int = 10) -> tuple[int, int]:
        for _ in range(max_turns):
            action = self.step()
            if json.loads(action).get("tool") == "done":
                break
        passed = sum(run_tests(self.repo))
        return passed, self.turns


# ---------- CodeAct scaffold: one snippet may touch many files ----------

@dataclass
class CodeActScaffold:
    repo: dict[str, str] = field(default_factory=lambda: dict(INITIAL_REPO))
    turns: int = 0
    # Track the observed max number of files touched by a single action.
    # This is more honest than a static upper bound of len(repo) because
    # it would not silently inflate if someone adds an untested helper.
    worst_touched: int = 0

    def step(self) -> str:
        """Return one Python snippet that may edit multiple files in one go."""
        self.turns += 1
        # A single "snippet" action rewrites every failing file at once.
        snippet_lines = []
        results = run_tests(self.repo)
        for (path, _), ok in zip(TESTS, results, strict=True):
            if ok:
                continue
            if _apply_fix(self.repo, path):
                snippet_lines.append(f"fs.write('{path}', ...)")
        self.worst_touched = max(self.worst_touched, len(snippet_lines))
        if not snippet_lines:
            return "done()"
        return "; ".join(snippet_lines)

    def blast_radius(self) -> int:
        # observed worst-case: files touched by a single action.
        return self.worst_touched

    def run(self, max_turns: int = 10) -> tuple[int, int]:
        for _ in range(max_turns):
            action = self.step()
            if action == "done()":
                break
        passed = sum(run_tests(self.repo))
        return passed, self.turns


# ---------- Driver ----------

def report(name: str, passed: int, turns: int, blast: int) -> None:
    total = len(TESTS)
    print(f"  {name:<18}  passed {passed}/{total}  turns {turns:>2}  "
          f"blast-radius {blast}")

Break it on purpose

A team adopts the coding agent with the highest SWE-bench Verified score, wires it in with CodeAct over the developer's own shell, and points it at their monorepo. Industry practice
What's current (2024–2026)
  • Scaffolds matter as much as models. LangChain's Terminal Bench 2.0 result, 52.8% to 66.5% with the model fixed and only the harness changed, is the clearest public example. Vendors now report agent scores with their own scaffolds, which is why vendor and standardised numbers differ.
  • Benchmarks moved on. OpenAI stopped reporting SWE-bench Verified in February 2026, citing flawed tests and contamination. Scale's SWE-bench Pro, with larger multi-file tasks and a private commercial split, and Terminal Bench are now the common comparisons.
  • Both action styles ship. OpenHands and smolagents use CodeAct in containers. Claude Code, Codex and the managed agent services use structured tool calls with permission rules, and run code through a sandboxed shell tool.
  • On your laptop: both scaffolds run here with the 0.5B model on CPU. A 7B coding model in 4-bit fits the RTX 4060 for a fairer test of the same harness.

Sources: LangChain, Improving Deep Agents with harness engineering, Epoch AI, What skills does SWE-bench Verified evaluate?, Scale AI, SWE-Bench Pro, Wang et al., OpenHands (arXiv:2407.16741).

Recap
What to keep from this lesson
  • The scaffold (retrieval, edit, test, feedback loop, guards) is part of the product.
  • JSON tool calls: one checkable action at a time. CodeAct: a program per action, bounded only by the sandbox.
  • Report benchmark scores by task bucket, and test on tasks like yours.
  • Sandboxes shape behaviour as well as limit it; test the harness itself.
  • Compare scaffolds with a model above the capability floor; below it, only the failure modes differ.

outputs/skill-scaffold-audit.md helps you audit a proposed coding-agent scaffold before adoption: retrieval quality, verifier presence, sandbox isolation, and benchmark-to-distribution fit.

---
name: coding-scaffold-audit
description: Audit a proposed coding-agent scaffold (retrieval, verifier loop, sandbox, benchmark fit) before adopting it for production code changes.
version: 1.0.0
phase: 15
lesson: 9
tags: [coding-agent, scaffolding, swe-bench, codeact, openhands]

Given a proposed coding-agent scaffold (SWE-agent, OpenHands, Aider, Cline, Devin, Claude Code, or an in-house build), score it across four axes and flag where benchmark numbers will overstate production quality.

Produce:

1. **Retrieval.** Describe how the scaffold selects which files the agent reads before acting. Repo map, embedding search, explicit file list, or agent-driven `grep` calls. Quality of retrieval is the silent dominant reliability factor.
2. **Verifier loop.** Does the scaffold run tests, read the stack trace, and feed failure back into the next turn? If no verifier loop, flag as missing — this is usually a 10+ point absolute delta on SWE-bench-like tasks.
3. **Sandbox and blast radius.** Where do actions execute? Local file system, ephemeral container, managed VM. For CodeAct-style scaffolds, confirm the sandbox is hardened (no egress, no host mounts, time limit). For JSON tool-call scaffolds, confirm the tool validators reject every unintended side effect.
4. **Benchmark fit.** What distribution does the reported number (e.g., "80.9% on SWE-bench Verified") actually cover? Count the fraction of the benchmark made up of 1–2 line tasks; compare the reported score to SWE-bench Pro (10+ line tasks) for the same model. A scaffold whose headline number is driven by the easy tail is not a production signal.

Hard rejects:
- Any scaffold without a verifier loop used for tasks above trivial complexity.
- CodeAct scaffolds without sandbox isolation (no Docker, no rootless container, no VM) pointing at real repositories.
- Benchmark claims that do not disclose the distribution (easy-tail fraction, Pro-equivalent score).
- Tool-call scaffolds where a single tool can touch arbitrary paths with no validator (e.g., a raw `shell_exec` tool exposed to the model).

Refusal rules:
- If the user cannot produce the scaffold's test-suite pass-rate on a representative internal distribution, refuse and require a small-sample measurement first. Public benchmarks predict rank-order, not absolute quality.
- If the proposed scaffold would run against a production repository without a staging dry-run, refuse and require staging first. Coding agents rewrite files; coding agents with bad retrieval rewrite the wrong files.
- If the user plans to use benchmark scores alone (without their own evals) to make a go/no-go decision, refuse and require internal eval data.

Output format:

Return a scored memo with:
- **Retrieval score** (0–5 with mechanism described)
- **Verifier loop score** (0–5 with feedback format)
- **Sandbox score** (0–5 with isolation mechanism)
- **Benchmark fit score** (0–5 with internal distribution delta)
- **Deployment recommendation** (production / staging / research only)
- **One-line risk summary** (the most likely first production failure)

Solutions

SolutionP1 · What each scaffold managed

Neither, and neither does the guided third scaffold: all three end at 0 of 3. JSON tool calls stall on repeated run_tests. CodeAct snippets crash on imports of names that do not exist. The guided fix-one-file scaffold gets back confidently wrong code.

Each JSON action could touch at most one file. Each CodeAct snippet could do anything the sandbox allowed, which is why the sandbox, with no network, its own folder and a time limit, carries the safety. To compare scaffolds by score you need a model above the capability floor.

SolutionB1 · The wrong benchmark, the wrong sandbox

Choosing: SWE-bench Verified is dominated by small, single-file fixes, so a high score said little about cross-service changes in a monorepo. They should have built a small evaluation from their own backlog, split by task size, and compared candidate model-and-scaffold pairs on it.

Running: CodeAct over a developer's shell gives each action everything that shell can reach, including staging credentials. A test run became a migration because nothing separated "run tests" from "touch a database". Run CodeAct only in a sandbox with no credentials, no network except allowlisted hosts, and a disposable copy of the repo. Or use structured tool calls with permission rules, and deny database and deploy commands outright.
