The problem

In plain words first

A bag of words throws word order away, so "dog bites man" and "man bites dog" look identical. This lesson covers the two neural designs that first read words in order. A convolutional network (CNN) slides small learned windows over the sentence, each one acting as a pattern detector for a short phrase such as "not good at all". A recurrent network (RNN) reads one word at a time and carries a running memory forward; its improved versions, the LSTM and GRU, add learned gates that decide what to keep and what to forget, so the memory survives longer sentences. You will see the equations behind each, train both on real movie reviews, and measure the weakness that pushed the field to attention: a signal from early in a long sequence fades away as it travels.

TF-IDF and Word2Vec produced flat vectors that ignored word order. A classifier built on them could not tell dog bites man from man bites dog. Word order sometimes carries the signal.

Two families of architectures filled that gap before transformers arrived.

Convolutional nets for text (TextCNN). Apply 1D convolutions over sequences of word embeddings. A filter of width 3 is a learnable trigram detector: it spans three words and outputs a score. Stack different widths (2, 3, 4, 5) to detect multi-scale patterns. Max-pool to a fixed-size representation. Flat, parallel, fast.

Recurrent nets (RNN, LSTM, GRU). Process tokens one at a time, maintaining a hidden state that carries information forward. Sequential, memory-bearing, flexible input lengths. Dominated sequence modeling from 2014 to 2017, then attention happened.

This lesson builds both, then names the failure that motivated attention.

The idea

TextCNN (Kim, 2014). Tokens get embedded. A width-k 1D convolution slides a filter over consecutive k-grams of embeddings, producing a feature map. Global max-pooling over that map picks the strongest activation. Concatenate max-pooled outputs from several filter widths. Feed to a classifier head.

Why it works. A filter is a learnable n-gram. Max-pooling is position-invariant, so "not good" fires the same feature at the start or middle of a review. Three filter widths with 100 filters each gives you 300 learned n-gram detectors. Training is parallel; no sequential dependency.

RNN. At each time step t, the hidden state h_t = f(W * x_t + U * h_{t-1} + b). Share W, U, b across time. The hidden state at time T is a summary of the entire prefix. For classification, pool across h_1 ... h_T (max, mean, or last).

Plain RNNs suffer vanishing gradients. The LSTM adds gates that decide what to forget, what to store, and what to output, stabilizing gradients through long sequences. The GRU simplifies LSTM to two gates; performs similarly with fewer parameters.

Bidirectional RNNs run one RNN forward and another backward, concatenating hidden states. Every token's representation sees both left and right context. Essential for tagging tasks.

The same idea as a formula

Convolution over words. Stack the embeddings of a sentence into x1​,…,xn​∈Rd. A filter of width k has weights W∈Rk×d and a bias b. At each position i it scores the window xi​,…,xi+k−1​:

ci​=ReLU(j=0∑k−1​Wj​⋅xi+j​+b),c^=imax​ci​

One filter gives one number c^ per sentence, "how strongly does my phrase pattern appear anywhere". With 100 filters at each of 3 widths and d=100, the convolutions have 100⋅(3+4+5)⋅100+300=120,300 weights, independent of sentence length.

Plain RNN. ht​=tanh(Wxt​+Uht−1​+b). The same W,U,b are used at every step.

LSTM. Four gates computed from the same input, [ht−1​,xt​]:

ft​it​gt​ot​ct​​=σ(Wf​xt​+Uf​ht−1​+bf​)=σ(Wi​xt​+Ui​ht−1​+bi​)=tanh(Wg​xt​+Ug​ht−1​+bg​)=σ(Wo​xt​+Uo​ht−1​+bo​)=ft​⊙ct−1​+it​⊙gt​,ht​=ot​⊙tanh(ct​)​​forget: how much old memory to keepinput: how much new content to writecandidate contentoutput: how much memory to show​

The cell ct​ is updated by a sum, not squashed through a tanh at every step: that additive path is the "highway" Step 3 talks about. An LSTM layer has 4(dh​(dx​+dh​)+dh​) parameters, four times a plain RNN.

GRU. Two gates and no separate cell: update gate zt​=σ(Wz​xt​+Uz​ht−1​), reset gate rt​=σ(Wr​xt​+Ur​ht−1​), candidate h~t​=tanh(Wxt​+U(rt​⊙ht−1​)), and ht​=(1−zt​)⊙ht−1​+zt​⊙h~t​. Three blocks of weights instead of four.

Bidirectional. Run one RNN left to right and another right to left, and use [ht​;ht​], so each position sees the whole sentence.

Worked example
One LSTM step with one-dimensional numbers

Old cell ct−1​=2.0. Suppose the gates come out as ft​=0.9, it​=0.2, ot​=0.5, with candidate gt​=−1.0.

  • New cell: ct​=0.9×2.0+0.2×(−1.0)=1.8−0.2=1.6. Most of the old memory survives; a little new content is written.
  • Output: ht​=0.5×tanh(1.6)=0.5×0.922=0.461.
  • Gradient along the highway: ∂ct​/∂ct−1​=ft​=0.9 (holding the gates fixed). Over 50 steps with f=0.9 that is 0.950=0.005; with f=0.99 it is 0.9950=0.61.

The forget gate is a learned, input-dependent decay rate. When the network learns to hold ft​ near 1, information and gradients cross long distances; nothing forces it to, which is why an LSTM at initialisation forgets almost as fast as a plain RNN (measured under "Use it").

Step 1 · TextCNN in PyTorch

import torch
import torch.nn as nn
import torch.nn.functional as F


class TextCNN(nn.Module):
    def __init__(self, vocab_size, embed_dim, n_classes, filter_widths=(2, 3, 4), n_filters=64, dropout=0.3):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.convs = nn.ModuleList([
            nn.Conv1d(embed_dim, n_filters, kernel_size=k)
            for k in filter_widths
        ])
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(n_filters * len(filter_widths), n_classes)

    def forward(self, token_ids):
        x = self.embed(token_ids).transpose(1, 2)
        pooled = []
        for conv in self.convs:
            c = F.relu(conv(x))
            p = F.max_pool1d(c, c.size(2)).squeeze(2)
            pooled.append(p)
        h = torch.cat(pooled, dim=1)
        return self.fc(self.dropout(h))

The transpose(1, 2) reshapes [batch, seq_len, embed_dim] to [batch, embed_dim, seq_len] because nn.Conv1d treats the middle axis as channels. The pooled output is fixed-size regardless of input length.

Step 2 · LSTM classifier

class LSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, n_classes, bidirectional=True, dropout=0.3):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True, bidirectional=bidirectional)
        factor = 2 if bidirectional else 1
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(hidden_dim * factor, n_classes)

    def forward(self, token_ids):
        x = self.embed(token_ids)
        out, _ = self.lstm(x)
        pooled = out.max(dim=1).values
        return self.fc(self.dropout(pooled))

Max-pool over the sequence, not last-state pool. For classification, max-pooling usually beats taking the last hidden state because information at the end of a long sequence tends to dominate the last state.

Step 3 · the vanishing gradient demo (intuition)

A plain RNN without gating cannot learn long-range dependencies. Consider a toy task: predict whether token A appeared anywhere in a sequence. If A is at position 1 and the sequence is 100 tokens long, the gradient from the loss has to flow back through 99 multiplications of the recurrent weight. If the weight is less than 1, the gradient vanishes. If more than 1, it explodes.

def vanishing_gradient_sim(seq_len, recurrent_weight=0.9):
    import math
    return math.pow(recurrent_weight, seq_len)


# At weight=0.9 over 100 steps:
#   0.9 ^ 100 ≈ 2.7e-5
# The gradient from step 100 to step 1 is effectively zero.

LSTMs fix this with a cell state that runs through the network with only additive interactions (the forget gate scales it multiplicatively, but gradients still flow along the "highway"). GRUs do something similar with fewer parameters. Both make long-range learning possible: the gradient can survive 100+ steps when the forget (or update) gates learn to stay near 1. It is not automatic; under "Use it" an untrained LSTM loses its gradient almost as fast as a plain RNN.

The same idea as a formula
Why the gradient vanishes, in one line

Backpropagation through time multiplies one Jacobian per step. For ht​=tanh(Uht−1​+Wxt​),

∂ht​∂hT​​=s=t+1∏T​diag(1−hs2​)U,​∂ht​∂hT​​​≤(σmax​(U))T−t

because 1−hs2​≤1. If the largest singular value of U is below 1, the bound shrinks exponentially with distance: the lesson's 0.9 ** 100. If it is above 1, products can grow exponentially instead (exploding gradients, fixed in practice by clipping the gradient norm). The LSTM changes the product: along the cell, ∂cT​/∂ct​=∏s​diag(fs​) plus smaller terms, a product of gates the network controls rather than of a fixed matrix and saturating derivatives.

Check your mental model
  • ✗ "A CNN for text ignores word order, like a bag of words."
    ✓ Inside each window, order matters ("not good" and "good not" give different scores). Max-pooling then throws away where the pattern was.
  • ✗ "LSTMs solved vanishing gradients."
    ✓ They give the gradient a path that can survive; the gates still have to learn to use it, and very long dependencies remain hard.
  • ✗ "Bidirectional RNNs can be used to generate text."
    ✓ The backward direction reads the future, which a generator does not have yet. Bidirectional models are for tagging and classification of complete inputs.

Step 4 · why this still was not enough

Three problems persisted even with LSTMs.

  1. Sequential bottleneck. Training an RNN on a sequence of length 1000 requires 1000 serial forward/backward steps. Cannot parallelize across time.
  2. Fixed-size context vector in encoder-decoder setups. The decoder sees only the final hidden state of the encoder, compressed over the entire input. Long inputs lose detail. Lesson 5.9 covers this directly.
  3. Distant-dependency accuracy ceiling. LSTMs outperform plain RNNs but still struggle to propagate specific information across 200+ steps.

Attention solved the second and most of the third, and transformers dropped recurrence to solve the first: every position is processed in parallel during training. (Recurrence came back later in a new form; see "What's current" below.) Lesson 5.10 is the pivot.

Use it: the same idea with real libraries

PyTorch's nn.LSTM, nn.GRU, and nn.Conv1d are production-ready. Training code is standard.

Hugging Face ships pretrained embeddings you plug in as the input layer:

from transformers import AutoModel

encoder = AutoModel.from_pretrained("bert-base-uncased")
for param in encoder.parameters():
    param.requires_grad = False


class BertCNN(nn.Module):
    def __init__(self, n_classes, filter_widths=(2, 3, 4), n_filters=64):
        super().__init__()
        self.encoder = encoder
        self.convs = nn.ModuleList([nn.Conv1d(768, n_filters, kernel_size=k) for k in filter_widths])
        self.fc = nn.Linear(n_filters * len(filter_widths), n_classes)

    def forward(self, input_ids, attention_mask):
        with torch.no_grad():
            out = self.encoder(input_ids=input_ids, attention_mask=attention_mask).last_hidden_state
        x = out.transpose(1, 2)
        pooled = [F.max_pool1d(F.relu(conv(x)), kernel_size=conv(x).size(2)).squeeze(2) for conv in self.convs]
        return self.fc(torch.cat(pooled, dim=1))

Use-when-it-fits-the-constraint checklist.

  • Edge / on-device inference. A TextCNN or small LSTM has well under a million weights besides its embedding table; with a vocabulary trimmed to tens of thousands of words, the whole model is tens to hundreds of times smaller than BERT-base (110M parameters).
  • Streaming / online classification. An RNN updates a fixed-size state per token, so cost and memory per token stay constant however long the stream runs. A transformer can also stream with a key-value cache, but its memory grows with the length of the context. That constant-cost property is exactly why recurrent layers are back in 2025 hybrid models.
  • Tiny models for baselines. Fast iteration on a new task. Under "Use it", a TextCNN trains on 8,530 reviews in seconds per epoch on two CPU cores.
  • Sequence labeling with limited data. BiLSTM-CRF (lesson 06) is still a production-grade NER architecture for 1k-10k labeled sentences.

Everything else goes to a transformer.

import time
import re
import numpy as np
import pyarrow.parquet as pq
import matplotlib.pyplot as plt
from collections import Counter
from huggingface_hub import hf_hub_download
from gensim.models import KeyedVectors
torch.set_num_threads(2)

load = lambda split: pq.read_table(hf_hub_download("cornell-movie-review-data/rotten_tomatoes", f"{split}.parquet",
                                                   repo_type="dataset")).to_pydict()
tr, va, te = load("train"), load("validation"), load("test")
tok = lambda s: re.findall(r"[a-z0-9']+|[.!?,;]", s.lower())
counts = Counter(w for s in tr["text"] for w in tok(s))
itos = ["<pad>", "<unk>"] + [w for w, c in counts.items() if c >= 2]
stoi = {w: i for i, w in enumerate(itos)}
def encode(texts, L=50):
    X = np.zeros((len(texts), L), dtype=np.int64)
    for i, s in enumerate(texts):
        ids = [stoi.get(w, 1) for w in tok(s)][:L]; X[i, :len(ids)] = ids
    return torch.tensor(X)
(Xtr, ytr), (Xva, yva), (Xte, yte) = [(encode(d["text"]), torch.tensor(d["label"])) for d in (tr, va, te)]
lengths = (Xtr > 0).sum(1).float()
print(f"vocabulary {len(itos):,} words; review length: median {lengths.median():.0f} tokens, "
      f"{(lengths < 50).float().mean():.0%} shorter than 50")

hf_hub_download("fse/glove-wiki-gigaword-100", "glove-wiki-gigaword-100.model.vectors.npy")
glove = KeyedVectors.load(hf_hub_download("fse/glove-wiki-gigaword-100", "glove-wiki-gigaword-100.model"))
rng = np.random.default_rng(0)
G = torch.tensor(np.array([glove[w] if w in glove else rng.normal(0, 0.3, 100) for w in itos]), dtype=torch.float32)
G[0] = 0

def accuracy(model, X, y):
    model.eval()
    with torch.no_grad():
        return (model(X).argmax(1) == y).float().mean().item()

def fit(model, epochs=4, bs=64):
    opt = torch.optim.Adam(model.parameters(), lr=2e-3); best, start = (0, 0), time.time()
    for ep in range(epochs):
        model.train()
        for b in torch.randperm(len(Xtr)).split(bs):
            loss = F.cross_entropy(model(Xtr[b]), ytr[b]); opt.zero_grad(); loss.backward(); opt.step()
        v = accuracy(model, Xva, yva)
        if v > best[0]:
            best = (v, accuracy(model, Xte, yte))
    return best[1], (time.time() - start) / epochs

class LastStep(LSTMClassifier):          # same model, but reads only the final time step
    def forward(self, token_ids):
        out, _ = self.lstm(self.embed(token_ids))
        return self.fc(self.dropout(out[:, -1]))
class MeanPool(LSTMClassifier):
    def forward(self, token_ids):
        out, _ = self.lstm(self.embed(token_ids))
        mask = (token_ids > 0).unsqueeze(-1).float()
        return self.fc(self.dropout((out * mask).sum(1) / mask.sum(1).clamp(min=1)))

Random embeddings learned from 8,530 short reviews give the CNN only about 70%; starting from GloVe, which already knows that "superb" and "excellent" are close, lifts it to the TF-IDF baseline's level. The BiLSTM with max- or mean-pooling does a little better again, around 80%. import matplotlib.pyplot as plt
torch.manual_seed(0)
T = 100
x = torch.randn(32, T, 16)

def grad_profile(layer):
    xi = x.clone().requires_grad_(True)
    out, _ = layer(xi)
    out[:, -1].sum().backward()
    return xi.grad.norm(dim=(0, 2)).numpy()

lstm_fb = nn.LSTM(16, 64, batch_first=True)
with torch.no_grad():                               # PyTorch's gate order is input, forget, cell, output

Reading this output

All three standard layers lose the gradient exponentially: within 50 steps it falls by ten or more orders of magnitude, and at the first position it is effectively zero, for the LSTM as much as for the plain RNN. PyTorch initialises the forget-gate bias at zero, so ft​≈σ(0)=0.5 at the start, and 0.550 is tiny. Set the bias so that ft​≈0.95 and the LSTM's curve flattens dramatically: the additive cell path carries the gradient tens of steps further. That is the whole LSTM argument in one plot, and the reason many implementations start the forget bias at 1 or higher (Jozefowicz et al., 2015). Training can learn the same thing, but only if some gradient reaches the early steps to begin with.

Industry practice
What's current (2024–2026)

Recurrence is back in production models, in a form that also trains in parallel.

  • Hybrid production models. NVIDIA's Nemotron-H (2025) replaces most self-attention layers with Mamba-2 layers and reports up to three times the inference speed of similar-sized transformers; IBM's Granite 4.0 (October 2025) and AI21's Jamba are hybrid Mamba-transformer models offered commercially; Qwen3-Next (2025) mixes linear-attention Gated DeltaNet layers and standard attention 3:1, with over ten times the throughput of Qwen3-32B beyond 32K tokens of context.
  • Why it matters. A recurrent state costs the same per token however long the context grows, while attention's key-value cache keeps growing. The gating ideas in this lesson's LSTM equations are the ancestors of those layers' update rules.
  • LSTMs still ship in small on-device models (keyboard prediction, wake words, sensor streams), where their tiny state and low latency fit.

Sources: Nemotron-H, IBM Granite 4.0, Jamba, Qwen3-Next.

Recap
What to keep from this lesson
  • A text CNN filter is a learned n-gram detector; max-pooling makes it position-invariant and gives a fixed-size vector.
  • An RNN applies the same weights at every step; backpropagation through time multiplies one Jacobian per step, so gradients shrink or blow up exponentially.
  • The LSTM's additive cell and learned forget gate let gradients survive, if the gates learn to stay open; the GRU does the same with two gates.
  • Pretrained embeddings matter on small datasets; pool over all positions (max or mean) rather than reading a padded last step.
  • Recurrence is sequential to train, which is what transformers removed; its constant cost per token is why it returned in 2025 hybrids.

Solutions

SolutionP1 · About the same: both vanish

At initialisation the LSTM's gradient at the first position is as negligible as the plain RNN's (both around 10−20 or smaller in the run). The LSTM's advantage is not built in; it comes from forget gates near 1. PyTorch starts the forget bias at 0, so the gate starts at about 0.5 and the cell halves its contribution every step. With the forget bias set to 3 the curve flattens immediately. In training, gates learn to open, which is why trained LSTMs handle dependencies that plain RNNs cannot.

SolutionB1 · It reads padding, and accuracy collapses

Reviews are padded at the end with token 0, so for a 20-token review the last output comes after 30 padding steps. The padding embedding is zero, but the LSTM still updates its state at every step through its biases and recurrent weights, so the review's content must survive 30 extra multiplications to influence the output. Under "Use it" the last-step model ends far below the pooled ones. Fixes: pool over positions (max or mean with a mask), take the output at each review's true last token, or use nn.utils.rnn.pack_padded_sequence so the LSTM stops at each sequence's real length.
