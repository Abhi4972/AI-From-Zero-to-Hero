In plain words first
The idea in one line

BERT sees both sides. GPT sees only the past. The triangle mask is the most consequential single line of code in modern AI.

Terms you'll hear
Term What people say What it actually means
Causal mask "The triangle" Upper-triangular -inf matrix added to attention scores so position i only sees positions ≤ i.
Next-token prediction "The loss" Cross-entropy of the model's distribution against the true next token at every position.
Autoregressive "Generate one at a time" Feed output back as input; parallelism only during training, not during generation.
Logits "Pre-softmax scores" Raw output of the LM head before softmax; sampling happens on these.
Temperature "Creativity knob" Divide logits by $T$; $T \to 0$ = greedy, $T \to \infty$ = uniform.
Top-p "Nucleus sampling" Truncate distribution to smallest set summing to $\ge p$; sample from what remains.
Min-p "Better than top-p" Keep tokens where p ≥ min_p × max_p; adapts cutoff to sharpness of distribution.
Speculative decoding "Draft + verify" Cheap model proposes N tokens; big model verifies in parallel.
Teacher forcing "Training trick" During training, feed the true previous token, not the model's prediction. Standard for every seq2seq LM.

The problem

In plain words first

A GPT-style model does one thing: given the words so far, it gives a probability for every possible next word. To write text it picks one, appends it, and asks again. To train it, you show it real text and, at every position, score how much probability it gave to the word that actually came next. The trick that makes training fast is the causal mask: in attention, each position is forbidden to look at later positions, so one pass over a whole sentence produces an honest prediction at every position at once. This lesson builds the mask from a plain running average, checks with GPT-2 that one forward pass really gives a prediction per position, computes the training loss by hand and matches it to the library's, and compares greedy decoding, temperature, top-p and min-p on GPT-2's real next-word distribution. Nothing is trained.

A language model answers one question: given the first t-1 tokens, what is the probability distribution over token t? Train on that signal — next-token prediction — and you get a model that can generate arbitrary text one token at a time.

To train it end-to-end on a whole sequence in parallel, you need each position's prediction to depend only on earlier positions. Otherwise the model trivially cheats by looking at the answer.

The causal mask does this. It is a single upper-triangular matrix of -inf values added to attention scores before softmax. After softmax, those positions become 0. Each position can attend only to itself and earlier positions. And because you apply it once to the whole sequence, you get N parallel next-token predictions in one forward pass.

GPT-1 (2018), GPT-2 (2019), GPT-3 (2020), GPT-4 (2023), GPT-5 (2025), Claude, Llama, Qwen, Mistral, DeepSeek, Kimi — they are all decoder-only causal transformers with the same core loop. What separates them is data quality, scale and architectural refinements, and post-training (SFT, RLHF, DPO, and their successors).

The idea

Idea 1 · The mask

Given a sequence of length N, build an N×N matrix:

Mij​={0−∞​if j≤iif j>i​

Add M to the raw attention scores before softmax. exp(−∞)=0, so masked positions contribute zero weight. Each row of the attention matrix is a probability distribution over previous positions only.

Implementation cost: one torch.tril() call. Time to compute: nanoseconds. Impact on the field: everything.

Idea 2 · Where the triangle comes from

The mask is usually presented as a patch bolted onto attention. Run the derivation in the other direction and it stops being mysterious: attention is the third refinement of a prefix average, and the triangle is the loop bounds of that average, written as a matrix.

Stage 1 — prefix average. The dumbest causal summary of a sequence: position i becomes the mean of positions 0…i. As a loop, that is out[i] = X[:i+1].mean(0). The same computation is one matrix multiply. Take a lower-triangular matrix of ones, divide each row by its count, multiply:

import numpy as np

n, d = 5, 3
X = np.random.default_rng(0).standard_normal((n, d))   # five token vectors

A = np.tril(np.ones((n, n)))
A = A / A.sum(axis=1, keepdims=True)
out = A @ X
print(np.round(A, 3))
print("equal to a loop of prefix means:", np.allclose(out, [X[: i + 1].mean(0) for i in range(n)]))

Row i of A is [1/(i+1),…,1/(i+1),0,…,0]. The zeros above the diagonal are the causality. Nothing about the future was masked out; the future was never in the sum.

Stage 2 — learned weights. A uniform average treats every past token as equally relevant. Replace the ones with a learned score matrix S. Now rows no longer sum to one by construction, so normalize each row with softmax instead of dividing by the count. Softmax never outputs an exact zero, which breaks causality — unless the future scores go in as -inf, because exp(-inf) = 0:

def softmax(x, axis):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

S = np.random.default_rng(1).standard_normal((n, n))    # stands in for learned scores
S = S + np.triu(np.full((n, n), -np.inf), k=1)
A = softmax(S, axis=1)
out = A @ X
print(np.round(A, 3))
print("rows sum to", A.sum(axis=1))
What you should see
[[1.    0.    0.    0.    0.   ]
 [0.728 0.272 0.    0.    0.   ]
 [0.318 0.534 0.148 0.    0.   ]
 [0.448 0.256 0.184 0.113 0.   ]
 [0.123 0.092 0.444 0.333 0.008]]
rows sum to [1. 1. 1. 1. 1.]

Same triangle, same row-stochastic matrix, same one matmul. The -inf mask is not new machinery. It is stage 1's zero entries, translated into softmax's input domain.

Stage 3 — content-dependent weights. In stage 2, S is fixed after training: position 7 always weighs position 3 the same, whatever the tokens say. Let the scores depend on the tokens themselves: S = Q @ K.T / sqrt(d_k). Nothing else changes. Mask, softmax, matmul — identical.

Three stages, one invariant: a lower-triangular row-stochastic matrix times the sequence. Uniform average, learned static weights, content-dependent weights. The mask was never added to attention. It survived from the average.

Idea 3 · Parallel training, serial inference

Training: forward-pass the whole (N, d_model) sequence once, compute N cross-entropy losses (one per position), sum, backprop. Parallel along the sequence. This is why GPT training scales — you process 1M tokens in a batch in one GPU pass.

Inference: you generate token by token. Feed [t1, t2, t3], get t4. Feed [t1, t2, t3, t4], get t5. Feed [t1, t2, t3, t4, t5], get t6. The KV cache (Lesson 7.18) saves the hidden states of t1…tn so you don't recompute them each step. But serial depth at inference = output length. That is the autoregressive tax and why decoding is the latency bottleneck of every LLM.

Idea 4 · The loss — shift-by-one

Given tokens [t1, t2, t3, t4]:

  • Input: [t1, t2, t3]
  • Targets: [t2, t3, t4]

For every position i, compute -log P(target_i | inputs[:i+1]). Sum. This is the cross-entropy for the whole sequence.

Every transformer LM you've heard of trains on this loss. Pre-training, fine-tuning, SFT — same loss, different data.

Idea 5 · Decoding strategies

After training, sampling choices matter more than people think.

Method What it does When to use
Greedy Argmax every step Deterministic tasks, code completion
Temperature Divide logits by T, sample Creative tasks, higher T = more diversity
Top-k Sample from top-k tokens only Kills low-probability tails
Top-p (nucleus) Sample from smallest set with cumulative prob ≥ p 2020+ default; adapts to distribution shape
Min-p Keep tokens with p > min_p * max_p 2024+; better at rejecting long tails than top-p
Speculative decoding Draft model proposes N tokens, big model verifies 2–3× latency reduction at same quality

In 2026, temperature with top-p (or min-p, which vLLM, llama.cpp and transformers all support) is the usual setup for open-weights models, and the values on the model card are the best starting point. Speculative decoding is built into the main serving engines.

Idea 6 · What made the "GPT recipe" work

  1. Decoder-only. No encoder overhead. One pass of attention + FFN per layer.
  2. Scaling. 124M → 1.5B → 175B → trillions. Chinchilla scaling laws (Lesson 7.20) tell you how to spend compute.
  3. In-context learning. GPT-3 (175B) showed that examples placed in the prompt improve answers more and more as models grow, with no fine-tuning.
  4. RLHF. Post-training on human preferences converted raw pretrained text into chat assistants.
  5. Pre-norm + RoPE + SwiGLU. Stable training at scale.

The core architecture hasn't changed much since GPT-2. Everything interesting has happened in data, scale, and post-training.

The same idea as a formula

Factorise the probability of a text left to right (the chain rule of probability, exact for any distribution):

p(x1​,…,xn​)=t=1∏n​p(xt​∣x<t​)

A decoder computes all the factors at once: logits zt​=fθ​(x≤t​) at every position t, with the causal mask guaranteeing that zt​ cannot depend on x>t​.

The loss is the average negative log-probability of each actual next token, the shift-by-one cross-entropy:

L=−n−11​t=1∑n−1​logsoftmax(zt​)xt+1​​,perplexity=eL

A model that guesses uniformly over V tokens has L=lnV (10.8 nats for GPT-2's 50,257).

Decoding rules on the final logits z, with p=softmax(z/T):

  • Greedy: argmaxi​zi​. Temperature: T<1 sharpens, T>1 flattens; T→0 is greedy.
  • Top-k: keep the k most likely tokens. Top-p: keep the smallest set whose probabilities sum to at least p.
  • Min-p: keep tokens with pi​≥min_p⋅maxj​pj​, a cut-off that follows the model's confidence.

The kept probabilities are renormalised and one token is drawn.

Cost. Training scores n positions in one parallel pass; generating m tokens takes m sequential passes, which is why decoding speed, not training, sets an LLM's latency.

Sampling and loss by hand

Four candidate tokens with logits (2,1,0,−1).

  • T=1: e2,e1,e0,e−1=7.389,2.718,1,0.368, sum 11.475, so p=(0.644,0.237,0.087,0.032).
  • T=0.5 (logits doubled): p=(0.865,0.117,0.016,0.002); the top token goes from 64% to 87%.
  • Top-p=0.9 at T=1: 0.644+0.237=0.881 is short of 0.9, so the third token joins: 3 kept.
  • Min-p=0.1 at T=1: threshold 0.1×0.644=0.064 keeps 3 tokens; at T=0.5 the threshold is 0.087 and only 2 remain.
  • If the true next token is the second one, its loss is −ln0.237=1.44 nats; if it is the fourth, −ln0.032=3.44.
Check your mental model
  • ✗ "During training GPT generates text one token at a time."
    ✓ Training feeds the real text (teacher forcing) and scores every position in one pass; token-by-token generation happens only at inference.
  • ✗ "The mask removes future tokens from the input."
    ✓ They are in the input; their attention weights are forced to zero, so they cannot influence earlier positions. The run under "Use it" shows earlier logits are unchanged when the text is cut short.
  • ✗ "Greedy decoding gives the best text."
    ✓ It gives the most likely token at each step, which for open-ended text often falls into repetition loops; sampling with truncation reads better.

Step 1 · the causal mask

See code/main.py. A one-liner:

def causal_mask(n):
    return [[0.0 if j <= i else float("-inf") for j in range(n)] for i in range(n)]

Add it to attention scores before softmax. That's the entire mechanism.

Step 2 · a 2-layer GPT-ish model

Stack two decoder blocks (masked self-attention + FFN, no cross-attention). Add a token embedding, a positional encoding, and an unembedding (tied to the token embedding matrix — a standard trick since GPT-2).

Step 3 · next-token prediction, end-to-end

main.py computes the shift-by-one cross-entropy for a toy 10-word vocabulary (run below); under "Use it" the same loss is computed by hand from GPT-2's logits and matched to the library's. No gradient: these are forward-pass checks.

Step 4 · sampling

Implement greedy, temperature, top-k, top-p, min-p. Run each on a fixed prompt and compare outputs. A sampling function is 10 lines.

One pass, one prediction per position, one loss

GPT-2 reads a 19-token text once. The logits of the first 8 positions are compared with a run on the text cut after 8 tokens; the shift-by-one loss is computed by hand and compared with transformers; then every token's surprisal is listed.

import torch, torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer

tok = AutoTokenizer.from_pretrained("openai-community/gpt2")
gpt = AutoModelForCausalLM.from_pretrained("openai-community/gpt2").eval()
text = "The cat sat on the mat. The dog sat on the rug. The cat sat on the"
ids = tok(text, return_tensors="pt").input_ids
with torch.no_grad():
    full = gpt(ids).logits[0]                       # one pass: a prediction at every position
    part = gpt(ids[:, :8]).logits[0]                 # the same text cut after 8 tokens
    out = gpt(ids, labels=ids)
print(f"{ids.shape[1]} tokens in, {full.shape[0]} next-token distributions out, from one forward pass")
print(f"first 8 positions, full text vs text cut after token 8: max logit difference {(full[:8] - part).abs().max():.1e}")

# The shift-by-one loss by hand: position i predicts token i+1.
logp = F.log_softmax(full[:-1], -1)

Decoding rules on a real distribution

GPT-2's next-token distribution after a prompt: how many tokens each truncation rule keeps, then 40-token continuations with greedy decoding and three sampling set-ups (seed 0).

prompt = "The best thing about living in a small town is"
ids = tok(prompt, return_tensors="pt").input_ids
with torch.no_grad():
    logits = gpt(ids).logits[0, -1]

def kept(logits, T=1.0, top_k=None, top_p=None, min_p=None):
    p = (logits / T).softmax(-1)
    keep = torch.ones_like(p, dtype=torch.bool)
    if top_k: keep &= p >= p.topk(top_k).values[-1]
    if top_p:
        s, order = p.sort(descending=True)
        n = int((s.cumsum(0) < top_p).sum()) + 1            # smallest set reaching top_p
        keep &= torch.zeros_like(keep).scatter(0, order[:n], True)
    if min_p: keep &= p >= min_p * p.max()
    return int(keep.sum()), p[keep].sum().item()

p = logits.softmax(-1)
H = -(p * p.clamp_min(1e-12).log()).sum()
print(f"prompt: {prompt!r}\nnext-token entropy {H:.2f} nats; top token {tok.decode(p.argmax())!r} with p = {p.max():.3f}\n")
print(f"{'rule':24s} {'tokens kept':>11} {'their mass at T':>16}")
for name, kw in [("no truncation, T=1", {}), ("top-k = 50", {"top_k": 50}), ("top-p = 0.9", {"top_p": 0.9}),

After this prompt GPT-2 puts 48% on " that" and the entropy is 2.8 nats, about as uncertain as a uniform choice among 17 tokens. Truncation rules differ a lot here: top-k=50 keeps 50 tokens whatever the shape, top-p=0.9 keeps 36, min-p=0.1 only 3, and lowering the temperature to 0.7 shrinks top-p's set to 3 as well. In the continuations, greedy decoding locks into a loop ("You can live in it for a long time." four times): the most likely next token after a repeated phrase is the phrase again. For a 124M-parameter model this is as good as it gets; larger models need less truncation.

Break it on purpose

In causal_mask, change j <= i to j < i, so each position may attend only to strictly earlier positions. The code runs and the matrix still looks triangular. What happens to row 0, what would PyTorch's softmax return there, and what does every other position lose? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Decoder-only everywhere. Production chat and coding models (the GPT, Claude, Gemini, Llama, Qwen, Mistral and DeepSeek families) are causal decoders trained on next-token prediction, then post-trained with SFT and preference or reinforcement learning.
  • Sampling lives in the serving engine. vLLM, SGLang, TensorRT-LLM and llama.cpp implement temperature, top-k, top-p, min-p and repetition penalties per request; model cards (Qwen, Llama, Mistral) publish recommended values, and structured-output decoding (JSON schemas, grammars) masks logits the same way.
  • Speculative decoding (draft tokens checked by the large model in one pass) is built into these engines to cut latency without changing outputs (Lesson 7.24).

Sources: vLLM sampling parameters, transformers generation strategies, llama.cpp, Qwen2.5 model card.

Recap
What to keep from this lesson
  • A causal LM factorises text as ∏t​p(xt​∣x<t​); the mask makes position t blind to the future.
  • Training: one pass, a shift-by-one cross-entropy at every position. Generation: one pass per new token.
  • The mask is the prefix average's zeros, written as −∞ before softmax.
  • Greedy decoding loops on open-ended text; temperature with top-p or min-p is the usual setting.

A decoder turns the logits of the next token into a distribution and draws from it. Temperature changes how flat that distribution is. Top p then cuts off the tail. In this lab you sweep the temperature on fixed logits and measure the entropy, the top 1 probability and the number of tokens that top p keeps.

support.py gives the 10 token vocabulary and the logits from the GPT lesson demo, LOGITS = [3.2, 1.1, 2.8, 0.4, 0.9, 1.5, -0.2, 2.1, 0.7, 0.1]. It also gives the grid TEMPERATURES from 0.1 to 3.0 in steps of 0.1, TARGET_ENTROPY = 2.0 bits and TOP_P = 0.9.

Task

Write five helper functions and answers().

  1. softmax_t(logits, temperature) returns pi​=ezi​/T/∑j​ezj​/T. It must not overflow for large logits or a small T.
  2. entropy_bits(probs) returns H=−∑i​pi​log2​pi​ in bits. A zero probability adds 0.
  3. sweep_temperature(logits, temperatures) returns two float arrays of the length of temperatures: the entropy and the top 1 probability maxi​pi​ at each temperature.
  4. temperature_for_entropy(logits, target, lo=0.05, hi=10.0, iters=60) finds the temperature where the entropy equals target, by bisection. Do iters rounds. In each round, let m be the midpoint of lo and hi. If the entropy at m is below target, move lo to m. Else move hi to m. After the last round, return the midpoint of lo and hi.
  5. kept_count(probs, p) sorts the probabilities from high to low and returns the length of the shortest prefix whose cumulative sum is greater than or equal to p. If no prefix reaches p because of rounding, it returns the number of tokens.

Then do the experiment in answers().

  1. Set the temperature to 1.0. Report the entropy as entropy_t1.
  2. Set the temperature to 0.7. Report the top 1 probability as top1_t07.
  3. Change the temperature over TEMPERATURES. Measure the entropy at each one. Report the first grid temperature with an entropy greater than or equal to TARGET_ENTROPY as first_grid_temperature.
  4. Find the exact crossing with temperature_for_entropy(LOGITS, TARGET_ENTROPY). Report it as crossing_temperature.
  5. Apply top p with TOP_P at the temperatures 0.7, 1.0 and 1.5. Report the kept counts as kept_p09_t07, kept_p09_t10 and kept_p09_t15.

Common mistakes the checks catch
  • Moves hi up when the entropy is too low, so the bisection runs to the wrong end.
  • Takes log2 of every probability, so a zero probability gives NaN.
  • Multiplies the logits by the temperature, not divides, so a higher temperature makes the distribution sharper.
  • Uses the natural log, so the entropy is in nats, not in bits.
  • Calls np.exp on the scaled logits without the maximum shift, so large logits overflow.
  • Uses a strict greater than, so a cumulative sum equal to p does not stop the prefix.
Hint 1

Divide the logits by the temperature first. Then subtract the maximum of the scaled logits before np.exp. A small temperature makes the scaled logits large.

Hint 2

In entropy_bits, keep only the entries above 0 with probs[probs > 0]. Then np.log2 never sees a 0.

Hint 3

The entropy rises with the temperature. So when the entropy at mid is too low, the answer is above mid, and lo moves up.

Hint 4

For kept_count, use np.sort(probs)[::-1] and np.cumsum. The first index where the cumulative sum reaches p gives the count, plus 1.

Reference solution and notes
import numpy as np

from support import LOGITS, TARGET_ENTROPY, TEMPERATURES, TOP_P


def softmax_t(logits, temperature):
    scaled = np.asarray(logits, dtype=float) / temperature
    exps = np.exp(scaled - np.max(scaled))
    return exps / np.sum(exps)


def entropy_bits(probs):
    probs = np.asarray(probs, dtype=float)
    nonzero = probs[probs > 0]
    return float(-np.sum(nonzero * np.log2(nonzero)))


def sweep_temperature(logits, temperatures):
    entropies = []
    top1 = []
    for t in temperatures:
        probs = softmax_t(logits, t)
        entropies.append(entropy_bits(probs))
        top1.append(float(np.max(probs)))
    return np.array(entropies), np.array(top1)


def temperature_for_entropy(logits, target, lo=0.05, hi=10.0, iters=60):
    for _ in range(iters):
        mid = (lo + hi) / 2
        if entropy_bits(softmax_t(logits, mid)) < target:
            lo = mid
        else:
            hi = mid
    return (lo + hi) / 2


def kept_count(probs, p):
    ordered = np.sort(np.asarray(probs, dtype=float))[::-1]
    cum = np.cumsum(ordered)
    for i, c in enumerate(cum):
        if c >= p:
            return i + 1
    return len(ordered)


def answers():
    entropies, top1 = sweep_temperature(LOGITS, TEMPERATURES)
    first = next(t for t, h in zip(TEMPERATURES, entropies) if h >= TARGET_ENTROPY)
    return {
        "entropy_t1": entropy_bits(softmax_t(LOGITS, 1.0)),
        "top1_t07": float(np.max(softmax_t(LOGITS, 0.7))),
        "first_grid_temperature": float(first),
        "crossing_temperature": temperature_for_entropy(LOGITS, TARGET_ENTROPY),
        "kept_p09_t07": float(kept_count(softmax_t(LOGITS, 0.7), TOP_P)),
        "kept_p09_t10": float(kept_count(softmax_t(LOGITS, 1.0), TOP_P)),
        "kept_p09_t15": float(kept_count(softmax_t(LOGITS, 1.5), TOP_P)),
    }

What the sweep shows

At temperature 1.0 the distribution has 2.53 bits of entropy, about as much as a uniform choice among 5.8 tokens. At 0.7 the top token "the" has a probability of 0.497. The entropy crosses 2 bits at T=0.694, so the first grid temperature above the target is 0.7.

Top p with p=0.9 keeps 4 tokens at T=0.7, 6 at T=1.0 and 8 at T=1.5. Top p does not fix the number of tokens. It adapts to the shape that the temperature gives. A higher temperature flattens the distribution, so top p must keep more tokens to reach the same mass.

Why the entropy rises with the temperature

As T→0 the softmax puts all the mass on the largest logit and the entropy goes to 0. As T→∞ every logit divided by T goes to 0 and the distribution becomes uniform, with entropy log2​V. Between the two ends the entropy rises with T, so a bisection on T finds any target in between.

A language model gives one logit for each token of the vocabulary. The decoder must pick the next token from these logits. Temperature, top-k and top-p change the distribution before the draw. Every chat model in the course uses this sampling step.

Task

Write four functions. Each logits argument is a 1D float array of length V.

  1. top_k_filter(logits, k) keeps the k largest logits and sets every other entry to -np.inf. Sort by logit, highest first. When two logits are equal, the lower index comes first. If k >= V, keep every entry.
  2. top_p_filter(logits, p) computes softmax(z) and sorts the tokens by probability, highest first, with the same tie rule. It keeps the shortest prefix of the sorted tokens whose cumulative probability is ≥p. The token that makes the sum reach p is kept. If no prefix reaches p because of rounding, keep every token. Every other entry becomes -np.inf.
  3. sampling_probs(logits, temperature=1.0, top_k=None, top_p=None) returns the final distribution. Apply the steps in this order:
  4. Divide the logits by temperature.
  5. If top_k is not None, apply top_k_filter.
  6. If top_p is not None, apply top_p_filter to the result of step 2.
  7. Take the softmax. A removed token gets probability exactly 0.
  8. sample(logits, rng, temperature=1.0, top_k=None, top_p=None) draws one token index. Compute the probabilities with sampling_probs. Call u = rng.random() exactly once. Let c be the cumulative sum of the probabilities in vocabulary order. Return the smallest index i with u<ci​. If no index satisfies this because of rounding, return the largest index that has a probability above 0.

The softmax of z is ezi​/∑j​ezj​. Entries equal to -np.inf get probability 0.

Hint 2

np.argsort(-logits, kind="stable") gives the indices from the largest logit to the smallest. A stable sort keeps equal values in index order, so the lower index comes first.

Hint 3

For top-p, take the cumulative sum of the sorted probabilities. Find the first position where the sum is at least p. Keep the tokens up to and including that position.

Hint 4

Reference solution and notes
import numpy as np


def softmax(logits):
    shifted = logits - np.max(logits)
    exps = np.exp(shifted)
    return exps / np.sum(exps)


def top_k_filter(logits, k):
    order = np.argsort(-logits, kind="stable")
    keep = order[:k]
    out = np.full(logits.shape, -np.inf)
    out[keep] = logits[keep]
    return out


def top_p_filter(logits, p):
    probs = softmax(logits)
    order = np.argsort(-probs, kind="stable")
    cum = np.cumsum(probs[order])
    cutoff = len(order)
    for i in range(len(order)):
        if cum[i] >= p:
            cutoff = i + 1
            break
    keep = order[:cutoff]
    out = np.full(logits.shape, -np.inf)
    out[keep] = logits[keep]
    return out


def sampling_probs(logits, temperature=1.0, top_k=None, top_p=None):
    scaled = np.asarray(logits, dtype=float) / temperature
    if top_k is not None:
        scaled = top_k_filter(scaled, top_k)
    if top_p is not None:
        scaled = top_p_filter(scaled, top_p)
    return softmax(scaled)


def sample(logits, rng, temperature=1.0, top_k=None, top_p=None):
    probs = sampling_probs(logits, temperature, top_k, top_p)
    u = rng.random()
    cum = np.cumsum(probs)
    for i in range(len(cum)):
        if u < cum[i]:
            return i
    return int(np.nonzero(probs)[0][-1])

Why the order of the steps matters

Top-k does not change when you divide the logits by a positive temperature, because the order of the logits stays the same. Top-p does change. A high temperature makes the distribution flatter, so more tokens are necessary to reach the mass p. This is why the temperature step comes first. The lesson applies the temperature inside the softmax before the top-p cut for the same reason.

The token that crosses p

The rule "cumulative sum ≥p" keeps the token that makes the sum reach p. Without that token the kept mass is below p, and with a large first token the kept set can be empty. The lesson uses the same rule in sample_top_p.

Exact draws

rng.choice with probabilities gives the same distribution, but not the same draws for a fixed seed. The inverse CDF method with one rng.random() for each draw is simple to test, and the draws are the same on every machine.

Solutions

SolutionP1 · It loops

Something else: a loop. Greedy decoding produces " that you can live in it for a long time." and then repeats "You can live in it for a long time." until the 40 tokens run out. Once a phrase has appeared, the model's most likely continuation is to repeat it (the in-context copying the surprisal column shows), and greedy decoding always takes the most likely token, so it never escapes. Sampling with top-p or min-p breaks the loop because a less likely token is drawn sooner or later; serving engines also offer repetition and frequency penalties.

SolutionB1 · Row 0 has nothing to attend to

Row 0 is now all −∞. The lesson's apply_softmax_row returns a row of zeros, so position 0's attention output is silently the zero vector; PyTorch's softmax returns NaN for an all-−∞ row (e−∞/0), and the NaN spreads through every later layer and the loss. Every other position loses its own token from its attention: it can only gather information from the past, so its prediction must come entirely through the residual stream for the current token. Strictly-earlier masks are used on purpose only with an extra "start" position to attend to; the standard causal mask includes the diagonal.

Explain the mechanismA decoder must not read tokens that come after the current position. A teammate proposes to run the softmax first and then set the weights of later positions to zero. Why is that wrong, and where does the usual triangle of negative infinity really come from?

Level 2 of 4 · about 8 minutes to answer well.

Short answer. Zeroing weights after the softmax leaves rows that no longer sum to one, and the later tokens already shaped the normalization. The mask adds minus infinity to the scores before the softmax, so the exponential gives an exact zero there and each row is a distribution over the past alone. The triangle is not a patch on attention: a causal running average is a lower-triangular row-normalized matrix, and the mask is that same zero pattern written in the input domain of the softmax.

Three stages, one invariant.

Start with the simplest causal summary: position i becomes the mean of positions 0 to i. As a matrix:

A = np.tril(np.ones((n, n)))
A = A / A.sum(axis=1, keepdims=True)
out = A @ X

The zeros above the diagonal are the causality. Nothing was masked; the future was never in the sum.

Now replace the ones with learned scores S. The rows no longer sum to one, so normalize each row with a softmax. A softmax never outputs an exact zero, so the future entries must enter as minus infinity, because exp(-inf) = 0:

S = S + np.triu(np.full((n, n), -np.inf), k=1)
A = softmax(S, axis=1)

Finally let the scores depend on the tokens: S = Q @ K.T / sqrt(d_k). Mask, softmax, matmul. The mask survived from the average; it was never added to attention.

Why minus infinity and not zero.

A score of zero still gets a weight of exp(0) = 1 before normalization. Only minus infinity gives zero weight.

What it buys at training time.

With the mask in place one forward pass over a sequence of N tokens gives N next-token predictions, each of which saw only its past. That is why training is parallel along the sequence. Without the mask the model reads its own target and the loss collapses while the model learns nothing useful.

How a production block stores it.

Register the mask as a buffer at construction, sized to the maximum context, and slice the top-left (T, T) corner at forward time. It then lives on the same device as the weights and never enters the gradient graph. Rebuilding it on each call turns the mask into an allocator hot spot at long context.

Plausible wrong answers.

  • "Set the future scores to zero." Zero is a legal score and still earns weight after the exponential; only minus infinity gives a zero weight.
  • "The mask is a training-only trick, so serving can drop it." The prompt is processed in one pass at serving time, and without the mask the prompt tokens would read their own future.
  • "Encoders also need the triangle." The encoder sees both sides by design; the triangle is what makes a decoder a decoder.

Follow-ups an interviewer may ask.

  • (level 2) Why not multiply the future scores by zero? Expected: a zero score still receives weight exp(0) before normalization, so the future still contributes.
  • (level 2) Where does the mask live in a real block and why? Expected: a registered buffer at the maximum context length, sliced per forward pass, so it sits on the right device and is not allocated on every call.
  • (level 3) Does an encoder need this triangle? Expected: no, an encoder is bidirectional; it needs a padding mask, which also uses minus infinity but follows the batch, not the diagonal.
  • (level 3) What does the mask have to do with parallel training? Expected: it lets one pass produce every next-token prediction at once while each prediction sees only its past, so the N losses are valid together.

Where it is taught. The causal language modeling lesson derives the triangle from the prefix average, and the attention capstone and the block capstone register it as a buffer.

Debug a failureA new decoder-only language model on a vocabulary of 64 tokens reaches a training loss near zero after only some hundreds of steps, and the sampled text is nonsense. Name the two most likely causes and the check that tells them apart.

Level 2 of 4 · about 8 minutes to answer well.

Short answer. On real text, a loss far below the logarithm of the vocabulary size this early, with nonsense samples, most likely means the model can see its own target. Either the causal mask is missing, so position i reads the token at i plus one through attention, or the targets were never shifted, so the input and the target are the same sequence. Check the attention weights: if any mass sits above the diagonal the mask is gone; if the weights are triangular, print one batch and compare the input and target columns.

What a healthy run looks like.

At the first step the loss should sit near the logarithm of the vocabulary size, about 4.16 for 64 tokens. On the lesson's repeat task it falls to well under 1.0 over three epochs because the next token equals the previous one. A loss that reaches zero on real text is not learning; it is copying.

Cause one: the mask.

The mask replaces every entry above the diagonal of the score matrix with minus infinity before the softmax. Forget it and every position attends to the whole sequence, including the answer. The lesson's phrase: forget the mask and you train a model that cheats. Common ways to lose it: the mask buffer is built for the maximum context and never sliced to the current length, the mask is applied after the softmax, or the attention call takes a flag that defaults to non-causal.

Cause two: the shift.

Given tokens [t1, t2, t3, t4], the input is [t1, t2, t3] and the target is [t2, t3, t4]. If the data loader returns the same window twice, the model learns the identity. The loss collapses even with a perfect mask.

The checks.

  1. Causality test. Perturb a token at position j and assert that the outputs at positions before j do not change. The lesson's test suite pins this property.
  2. Triangle test. Return the attention weights for one head and confirm the upper triangle is exactly zero after the softmax.
  3. Batch inspection. Print one input and target pair and confirm the target is the input shifted left by one.
  4. Held-out check. Compute the loss on held-out text with the same pipeline. A model that memorized a small corpus has a high held-out loss and samples that copy the training text; a leak gives nonsense samples.

Why sampling exposes it.

During training the answer leaks through the input, so the loss is low. At sampling time the model has nothing to copy from, so it emits noise. A model that learned the real task is good at both.

Plausible wrong answers.

  • "The model is just learning fast." A loss near zero on natural text is not possible without seeing the target.
  • "Add dropout to regularize it." Dropout does not stop a leak; it only makes the copy slightly noisier.
  • "Lower the learning rate." The optimization is fine; the objective is broken.

Follow-ups an interviewer may ask.

  • (level 2) What loss do you expect at step zero, and why? Expected: about the logarithm of the vocabulary size, about 4.16 for 64, because a random model spreads probability evenly.
  • (level 2) How do you make the shift mistake impossible in the loader? Expected: slice one window of length T plus 1 and return window[:-1] and window[1:] from the same slice, with a test on one example.
  • (level 3) Write the causality unit test in one sentence. Expected: change the token at position j, run the block again, and assert that every output before j is unchanged.
  • (level 3) The mask and the shift are right, and the loss is still suspiciously low. What else leaks? Expected: a validation window that overlaps the training stream, or padding tokens counted as easy targets; check the split and the loss mask.

Where it is taught. The attention capstone and the block capstone build and test the mask, and the causal language modeling lesson defines the shift-by-one loss.
