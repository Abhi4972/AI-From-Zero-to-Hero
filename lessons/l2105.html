Why this came about

As programs grew in the 1970s and 1980s, keeping data and the functions that work on it in separate places became a source of bugs. Object-oriented programming bundled them together: a class describes a kind of thing (its data and its behaviour), and objects are the individual things. Python supports this style, and almost every library you will use is organised around it: a scikit-learn model is an object you .fit() and .predict() with, a PyTorchlater · 3.17 layer is an object you call, a LangChainlater · 14.93 chat model is an object you .invoke(). Reading library code is much easier once classes are familiar.

In plain words first
A blueprint and the houses built from it

A class is a blueprint: "a cart has a customer and a list of items, and you can add an item or ask for the total". An object (or instance) is one actual cart built from that blueprint: Asha's cart, Ravi's cart. Each has its own data, called attributes (customer, items); all of them share the same abilities, called methods (add, total). You already use objects all the time: a string is an object of class str, and .upper() is one of its methods.

Step 1 · You have been using objects all along

Every value in Python is an object: a bundle of data plus the actions that work on that data. The kind of object is its class. A string is an object of class str, a list of class list, and the methods you have been calling with a dot belong to those classes. The code asks a few values what they are:

name = "asha"
print(type(name), name.upper())          # an object of class str, and one of its methods
cart = ["tea"]
cart.append("rice")                       # a method of the list class
print(type(cart), cart)
print(isinstance(name, str), isinstance(cart, str))
What you should see
<class 'str'> ASHA
<class 'list'> ['tea', 'rice']
True False

Everything in Python is an object: numbers, strings, lists, functions, even modules. type(x) says which class an object belongs to; isinstance(x, SomeClass) checks it.

Step 2 · Writing your own class

You can define your own kind of object. A class is the blueprint; each object made from it is an instance. The special method __init__ runs when an instance is created and sets up its data, called attributes. self is the instance itself, so self.items means "this cart's items". Read the class first, then the lines below it that create two separate carts:

class Cart:
    """A shopping cart for one customer."""

    def __init__(self, customer):
        self.customer = customer          # attributes: data that belongs to this object
        self.items = []

    def add(self, name, price, qty=1):
        """Add a line to the cart."""
        self.items.append({"name": name, "price": price, "qty": qty})

    def total(self):
        """Sum of price times quantity over all lines."""
        return sum(line["price"] * line["qty"] for line in self.items)

cart_a = Cart("Asha")                     # create an object: calls __init__
cart_a.add("tea", 249.5, qty=2)
cart_a.add("rice", 89)
cart_b = Cart("Ravi")

print(cart_a.customer, len(cart_a.items), cart_a.total())
print(cart_b.customer, len(cart_b.items), cart_b.total())
What you should see
Asha 2 588.0
Ravi 0 0
Piece What it does
class Cart: Defines a new class called Cart. Class names use CapitalisedWords by convention
__init__(self, customer) The initialiser: runs automatically when you write Cart("Asha"), to set up the new object's attributes
self The object the method is working on. Python passes it in for you: cart_a.total() becomes Cart.total(cart_a)
self.items = [] Creates an attribute on this object; each cart gets its own list
def add(self, ...) A method: a function that belongs to the class and works on self

The key point is in the output: cart_a and cart_b are built from the same class but hold separate data. Adding to Asha's cart did not touch Ravi's.

Step 3 · A readable printout, and comparing objects

By default, printing an object shows something unhelpful like <__main__.Cart object at 0x7f...>. A method named __repr__ controls what is shown. Methods with double underscores, called special methods or "dunder" methods, let your objects work with Python's built-in operations:

class Cart:
    def __init__(self, customer):
        self.customer = customer
        self.items = []
    def add(self, name, price, qty=1):
        self.items.append({"name": name, "price": price, "qty": qty})
        return self                        # returning self lets calls be chained
    def total(self):
        return sum(line["price"] * line["qty"] for line in self.items)
    def __repr__(self):
        return f"Cart({self.customer!r}, {len(self.items)} lines, total={self.total()})"
    def __len__(self):
        return len(self.items)             # makes len(cart) work

cart = Cart("Asha").add("tea", 249.5, 2).add("rice", 89)
print(cart)
print(len(cart))
What you should see
Cart('Asha', 2 lines, total=588.0)
2

.add(...).add(...) works because add returns the cart itself, so the next .add is called on it. This method chaining style is common in data and AI libraries (pandas and LangChain both use it). {self.customer!r} inserts the repr of the value, which puts quotes around strings.

Step 4 · Inheritance: a specialised version

A class can inherit from another: it gets all the parent's attributes and methods, and can add or change some.

class PrimeCart(Cart):
    """A cart for Prime members: 10% off orders over 1000."""

    def total(self):
        base = super().total()             # super() calls the parent class's version
        return round(base * 0.9, 2) if base > 1000 else base

pc = PrimeCart("Meera").add("headphones", 1499)
print(pc, isinstance(pc, Cart), isinstance(pc, PrimeCart))
What you should see
Cart('Meera', 1 lines, total=1349.1) True True

PrimeCart reused __init__, add, __repr__ and __len__ from Cart and replaced only total. Notice that __repr__ printed the discounted total: it calls self.total(), and self is a PrimeCart, so Python uses the PrimeCart version. Libraries use inheritance heavily: in PyTorch you write your own network by inheriting from torch.nn.Module (Lesson 3.17), and in LangChain many components inherit from a common Runnable base class.

Step 5 · Exploring an unfamiliar object

When a library hands you an object, four tools tell you what it is and what it can do:

from datetime import date
d = date(2026, 11, 9)
print(type(d))
print(d.year, d.month, d.weekday())                # attributes and a method
print([name for name in dir(d) if not name.startswith("_")][:8])
print(d.isoformat(), (date(2026, 12, 25) - d).days, "days to go")
What you should see
<class 'datetime.date'>
2026 11 0
['ctime', 'day', 'fromisocalendar', 'fromisoformat', 'fromordinal', 'fromtimestamp', 'isocalendar', 'isoformat']
2026-11-09 46 days to go
Tool What it tells you
type(obj) The object's class
dir(obj) Every attribute and method name (skip the ones starting with _)
help(obj) or help(obj.method) The documentation written in the class's docstrings
Your editor Hover over a name in VS Code to see its signature and docstring; Ctrl+click (Cmd+click on a Mac) to jump to its source

Notice that subtracting two dates gave an object with a .days attribute: classes can define what - means for their objects, through special methods like the __len__ you wrote above.

Tip
Data-only classes: dataclasses and Pydantic

Many classes only hold data. Writing __init__ and __repr__ for them is repetitive, so Python offers @dataclass, which writes those methods for you, and the popular Pydanticlater · 0.23 library adds validation on top. Both appear everywhere in AI code (tool arguments, structured outputlater · 11.21) and are taught in Lesson 0.23.

Exercises

Predict before you run

After a = Cart("Asha"), b = a, b.add("tea", 100), what is len(a)? (Solution P1.)

Break it on purpose

Remove self from the method definition def total(self): (so it reads def total():) and call cart.total(). Read the error and explain it. (Solution B1.)

Make it your own

Write a class Order with attributes order_id, items (a list of (name, price) tuples) and status (starting at "placed"), and methods ship() (sets the status to "shipped", but raises a ValueError if the order is empty) and __repr__. (Solution M1.)

Solutions

SolutionP1 · Two names, one object

len(a) is 1. b = a does not copy the cart: it makes a second name for the same object (like the variable picture in Lesson 0.16). Changing it through b is visible through a. To make a separate cart you would create a new one or copy it.

SolutionB1 · Forgetting self

Python raises TypeError: Cart.total() takes 0 positional arguments but 1 was given. Calling cart.total() always passes the object as the first argument, so a method must accept it. The "1 was given" is self, the argument you did not type.

SolutionM1 · An order class
class Order:
    def __init__(self, order_id, items):
        self.order_id = order_id
        self.items = items
        self.status = "placed"
    def ship(self):
        if not self.items:
            raise ValueError(f"order {self.order_id} has no items")
        self.status = "shipped"
    def __repr__(self):
        return f"Order({self.order_id!r}, {len(self.items)} items, {self.status})"

o = Order("SK-7", [("tea", 249.5)])
o.ship()
print(o)        # Order('SK-7', 1 items, shipped)

Guarding the change (refusing to ship an empty order) inside the class means no caller can forget the check. Agent tools in the Agents from first principles section rely on the same idea: rules live in the code, not in the model's instructions.

Recap
  • A class bundles data (attributes) and behaviour (methods); objects are instances with their own data.
  • __init__ sets up a new object; self is the object a method works on; special methods such as __repr__ and __len__ plug into Python's built-ins.
  • Inheritance makes a specialised class that reuses and overrides a parent's methods.
  • Explore unfamiliar objects with type, dir, help and your editor.
