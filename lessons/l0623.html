This lesson is not new material: it is the imports, decision tables, error codes, common mistakes and migration notes from the LangChain and LangGraph section, gathered in one place. Look things up here when you build; go back to the lesson named in each row when you need the explanation.

Why this came about

LangChain and LangGraph changed quickly between 2022 and 2026, and old tutorials use names that no longer exist. This reference gathers the current imports, error codes and migration notes in one place.

Error codes

Code What it means Usual fix
GRAPH_RECURSION_LIMIT The run took more steps than recursion_limit Fix the loop's exit; set the limit from real run lengths; end gracefully with RemainingSteps (6.11, 6.18)
INVALID_CONCURRENT_GRAPH_UPDATE Two nodes in one step wrote a key that has no reducer Add a reducer with Annotated (6.10). The thread stays broken until you do: recompile with the reducer on the same checkpointer (6.24)
INVALID_GRAPH_NODE_RETURN_VALUE A node returned something other than a dict of state keys (or a Command) Return a partial state update
MULTIPLE_SUBGRAPHS One node called several subgraphs that use checkpointing in a way the runtime cannot track Give each subgraph its own node, or its own checkpoint namespace
INVALID_CHAT_HISTORY The messages break the tool-call rules, such as a tool call with no result Return a ToolMessage for every tool call, also from Command-returning tools (6.4, 6.19)

NodeTimeoutError (a node passed its timeout or idle_timeout, 6.18); GraphDrained (a run stopped for a drain and can be resumed, 6.18); AttributeError: ... _put_checkpoint_fut (you passed durability="sync" to a graph with no checkpointer, 6.24); ValueError: MCP target ... is not a valid URL (pass a Path for a local server, 6.19); ModuleNotFoundError: No module named 'mcp.server.fastmcp' (the mcp 2.x SDK renamed it; use the fastmcp package or mcp.server.mcpserver.MCPServer). Other errors you will meet: ValueError: Checkpointer requires ... thread_id (pass a thread ID, 6.5); RuntimeError: Cannot use Command(resume=...) without checkpointer (6.6); ValueError: No checkpointer set from get_state (6.12); NotImplementedError from GenericFakeChatModel.bind_tools (6.8); "Node timeouts are only supported for async nodes" (6.18).

Gotchas, all in one place

  • Resume reruns the node. Code before interrupt() runs again on resume; keep side effects out of it (6.13).
  • Input is not a resume. Sending input to a paused thread starts a new run; resume with Command(resume=...) (6.13, 6.17).
  • Return only what changed. A node that returns the whole list under an appending reducer duplicates it (6.10).
  • Declare router targets. A router without a Literal return type or path_map draws wrongly, and a misspelled target silently ends the run (6.11).
  • Thread IDs and namespaces carry the user. Build them from authentication, never from the URL or model arguments (6.14, 6.21).
  • Streaming filters. messages mode streams tokens from every model call, including internal ones; filter by langgraph_node (6.15).
  • Streaming usage behind a custom endpoint. ChatOpenAI with a base_url needs stream_usage=True (6.2).
  • Lambdas break streams. A RunnableLambda after the model collects the whole reply; use RunnableGenerator (6.3).
  • Trim at turn boundaries. trim_messages(..., start_on="human", include_system=True) (6.14).
  • Middleware order. The first middleware is outermost: its before-hooks run first and its after-hooks last (6.6).
  • Retry only transient errors, and in one layer only (6.18).
  • Permissions: first match wins in Deep Agents' file permissions (6.20).
  • Checkpoint compatibility. Renaming nodes or state keys can break resuming old threads; migrate in two releases (12.8).
  • Parallel writes merge in task-path order, not finish order (6.24).
  • A crash can rerun a node that already acted, in every durability mode; key the side effect (6.24).
  • Checkpoints hold the whole state every step; use DeltaChannel for long lists (6.24).
  • Tuples, Counters and time zones change on the way through a checkpoint (6.24).
  • Store searches match prefixes; build namespaces from the full user ID (6.25).
  • Batched approvals review a whole turn; prefer interrupt_mode="per_call" (6.6, 6.25).
  • AutoStrategy can pick different structured-output strategies on different providers; choose explicitly (6.4).
