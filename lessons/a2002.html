The idea in one line

Fix messy tables without losing the original cells.

The problem

In plain words first

A spreadsheet that people typed by hand has the same garden written three ways and dates in two orders. Cleaning it is easy. Cleaning it so that someone can trust the result is harder: every change has to be visible, every guess has to be refused, and the same recipe has to give the same table next month.

The project builds that in four steps: profile each column while keeping the original cells; write the fixes as an explicit, ordered recipe; preview every changed cell and park the ambiguous ones for a person; then replay the recipe and record each human decision in a ledger.

Help a spreadsheet owner repair inconsistent labels, dates and missing values through an explicit sequence of transformations. Preview every changed cell, keep ambiguous cases for review, and export a cleaned CSV with a reusable transformation recipe and HTML comparison.

The implementation uses Python 3.10+ and standard libraries. Samples are original teaching data. Read API.md for exact input, output and error contracts.

What you will build: cleaned.csv, recipe.json and a cell-level HTML before/after report

Worked example
Why `03/04/2026` waits for a person
  1. 14/03/2026 has a day of 14. No month is 14, so the only reading is 14 March: it becomes 2026-03-14 automatically.
  2. 03/04/2026 could be 3 April (day first) or 4 March (month first). Both are real dates, so the tool refuses to pick.
  3. 04/03/2026 has the same problem the other way round.
  4. 31/02/2026 is different: neither reading gives a real date, so it is invalid, not ambiguous, and it is reported as an error.

The preview carries a SHA-256 fingerprint of the input and the recipe. A person's decision is accepted only for the exact table and recipe they reviewed.

Check your mental model

Which statements are right?

  • ✓ Trimming before the alias lookup lets " North Garden " match the alias for North Garden.
  • ✗ The tool may map N. Garden to North Garden because they look alike. Only aliases you supply are applied; nothing is guessed from spelling.
  • ✓ A decision recorded for one input is rejected when the input changes, because the fingerprint no longer matches.
  • ✗ An empty volunteers cell should be filled with 0. A blank is "unknown", not zero; the tool counts it as missing and leaves it.

Step 4 of 4 · about 2 hours · Python

Replay the recipe and validate human cell decisions.

Build the mechanism. A decision for row 2 date=2026-04-03 is accepted only for the matching input and recipe fingerprint. Every accepted edit enters the change ledger.

Exact contract. The JSON input contains csv text, aliases and date_columns. Outputs are cleaned.csv, recipe.json, receipt.json and review.html. Download decisions.json from the HTML, add {row,column,value} entries to cells, and run the same command with --decisions decisions.json. Failure boundary and extension. Only slash dates and ISO dates are recognized. Reviews resolve pending date cells; no locale or semantic inference is claimed.

class StageTests(unittest.TestCase):
    def test_review(self):
        t = profile("d\n03/04/2026")
        p = propose(t, date_columns=["d"])
        r = preview(t, p)
        v = repair(
            t,
            p,
            {
                "fingerprint": r["fingerprint"],
                "cells": [{"row": 1, "column": "d", "value": "2026-04-03"}],
            },
        )
        self.assertFalse(v["pending"])
        self.assertIn("2026-04-03", v["csv"])

    def test_stale(self):
        t = profile("a\nx")
        with self.assertRaises(ValueError):
            repair(t, propose(t), {"fingerprint": "bad"})

    def test_roundtrip(self):
        t = profile('a,b\n"x,y",0')
        self.assertEqual(profile(repair(t, propose(t))["csv"])["rows"], t["rows"])

    def test_replay(self):
        t = profile("a\n x ")
        r = repair(t, propose(t))
        u = profile(r["csv"])
        self.assertFalse(repair(u, r["recipe"])["changes"])

    def test_nonpending(self):
        t = profile("a\nx")
        p = propose(t)
        r = preview(t, p)
        with self.assertRaises(ValueError):
            repair(
                t,
                p,
                {
                    "fingerprint": r["fingerprint"],
                    "cells": [{"row": 1, "column": "a", "value": "2026-01-01"}],
                },

import csv, io, datetime, copy, hashlib, json


def profile(text):
    """Parse CSV text into {columns, rows, profile}; profile maps each column to {missing, unique}. Reject empty/duplicate headers and ragged rows. Preserve cells exactly."""
    try:
        data = list(csv.reader(io.StringIO(text), strict=True))
    except csv.Error as error:
        raise ValueError("malformed CSV: " + str(error)) from error
    if (
        not data
        or not data[0]
        or any((not c.strip() for c in data[0]))
        or (len(set(data[0])) != len(data[0]))
    ):
        raise ValueError("unique nonempty headers required")
    cols = data[0]
    if any((len(r) != len(cols) for r in data[1:])):
        raise ValueError("ragged row")
    rows = [dict(zip(cols, r)) for r in data[1:]]
    return {
        "columns": cols,
        "rows": rows,
        "profile": {
            c: {
                "missing": sum((not r[c].strip() for r in rows)),
                "unique": len({r[c] for r in rows}),
            }
            for c in cols
        },
    }


def propose(table, aliases=None, date_columns=None):
    """Return schema_version=1 recipe with ordered trim, alias, date rules. aliases maps column to exact trimmed spelling->canonical spelling. Dates accept ISO or unambiguous DD/MM/YYYY; ambiguous dates await review."""
    aliases = aliases or {}
    date_columns = date_columns or []
    if any((c not in table["columns"] for c in [*aliases, *date_columns])):
        raise ValueError("unknown column")
    rules = []
    for c in table["columns"]:
        rules.append({"column": c, "operation": "trim"})
        if c in aliases:
            if not isinstance(aliases[c], dict) or any(
                (not isinstance(v, str) for v in aliases[c].values())
            ):
                raise ValueError("invalid alias map")
            rules.append({"column": c, "operation": "alias", "values": aliases[c]})
        if c in date_columns:
            rules.append({"column": c, "operation": "date"})
    return {"schema_version": 1, "rules": rules}


def preview(table, recipe):
    """Return {rows,changes,pending,fingerprint}; row numbers are CSV data rows starting at 1. Changes name row,column,before,after; ambiguous/invalid dates remain unchanged and appear in pending. Never mutate input."""
    if recipe.get("schema_version") != 1:
        raise ValueError("unsupported recipe")
    rows = copy.deepcopy(table["rows"])
    pending = []
    for rule in recipe["rules"]:
        col = rule.get("column")
        op = rule.get("operation")
        if col not in table["columns"] or op not in ("trim", "alias", "date"):
            raise ValueError("invalid rule")
        for n, row in enumerate(rows, 1):
            value = row[col]
            if op == "trim":
                row[col] = value.strip()
            elif op == "alias":
                row[col] = rule["values"].get(value, value)
            elif value:
                try:
                    if "/" in value:
                        a, b, y = map(int, value.split("/"))
                        if a <= 12 and b <= 12 and (a != b):
                            pending.append(
                                {
                                    "row": n,
                                    "column": col,
                                    "value": value,
                                    "reason": "ambiguous date",
                                }
                            )
                            continue
                        if a > 12:
                            parsed = datetime.date(y, b, a)
                        elif b > 12:
                            parsed = datetime.date(y, a, b)
                        else:
                            parsed = datetime.date(y, b, a)
                    else:
                        parsed = datetime.date.fromisoformat(value)
                    row[col] = parsed.isoformat()
                except (ValueError, TypeError):
                    pending.append(
                        {
                            "row": n,
                            "column": col,
                            "value": value,
                            "reason": "invalid date",
                        }
                    )
    changes = [
        {"row": n, "column": c, "before": old[c], "after": new[c]}
        for n, (old, new) in enumerate(zip(table["rows"], rows), 1)
        for c in table["columns"]
        if old[c] != new[c]
    ]
    digest = hashlib.sha256(
        json.dumps({"table": table, "recipe": recipe}, sort_keys=True).encode()
    ).hexdigest()
    return {"rows": rows, "changes": changes, "pending": pending, "fingerprint": digest}


def repair(table, recipe, decisions=None):
    """Return {csv,recipe,changes,pending,fingerprint}. Optional {fingerprint,cells:[{row,column,value}]} resolves pending cells only, rejecting stale fingerprints, duplicate edits and non-ISO replacement dates. Unresolved cells stay original."""
    result = preview(table, recipe)
    if decisions is not None:
        if decisions.get("fingerprint") != result["fingerprint"]:
            raise ValueError("stale review")
        allowed = {(p["row"], p["column"]) for p in result["pending"]}
        seen = set()
        for d in decisions.get("cells", []):
            key = (d["row"], d["column"])
            if key not in allowed or key in seen:
                raise ValueError("invalid review cell")
            datetime.date.fromisoformat(d["value"])
            seen.add(key)
            result["rows"][d["row"] - 1][d["column"]] = d["value"]
        result["pending"] = [
            p for p in result["pending"] if (p["row"], p["column"]) not in seen
        ]
        result["changes"] = [
            {"row": n, "column": c, "before": old[c], "after": new[c]}
            for n, (old, new) in enumerate(zip(table["rows"], result["rows"]), 1)
            for c in table["columns"]
            if old[c] != new[c]
        ]
    out = io.StringIO(newline="")
    writer = csv.DictWriter(out, fieldnames=table["columns"])
    writer.writeheader()
    writer.writerows(result["rows"])
    return {**result, "csv": out.getvalue(), "recipe": recipe}

Break it on purpose

A teammate "fixes" the pending queue by parsing every date day-first. The next file comes from a US office. What goes wrong, and how does this project's design prevent it? (Solution B1.)

Recap
What to keep from this project
  • Keep original cells and row numbers; never edit in place.
  • Write cleaning as an explicit, ordered recipe you can replay.
  • Apply only supplied aliases; refuse guesses.
  • Ambiguous is not invalid: queue the first, reject the second.
  • Bind human decisions to a fingerprint of the input and the recipe.

Solutions

Solution
  1. A split rule

Add it as a new rule type that runs after trimming and before aliases, so the alias lookup sees the cleaned name. The preview must show both new cells and the source cell for every row, and the receipt must list the rule, so replaying the recipe produces the same columns.

Solution
  1. A decision on a changed file

No. The fingerprint covers the whole input, so the decision is refused and the date goes back to pending. That is deliberate: the tool cannot know whether the new row changes what the reviewer meant. A per-row fingerprint would let unchanged rows keep their decisions, at the cost of more bookkeeping.

Solution
  1. A mostly blank column

Report the count and the share of missing cells in the profile, without filling anything. Whether to fill, drop or keep the column is a decision for the data owner, and it belongs in the recipe as an explicit rule if they choose one.

SolutionB1 · Day-first everywhere

03/04/2026 from a US office means 4 March (month first), so the date silently moves a month. The project prevents this by never choosing an order for ambiguous dates: they wait for a person, and the decision is tied to the exact file it was made for.
