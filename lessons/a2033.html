The problem

In plain words first

Automated code review, whether from a linter or a model, is only useful if each finding points at a real line that the change added, with the exact text as evidence. A reviewer that invents a line number, comments on deleted code, or flags a comment that merely mentions eval wastes everyone's time.

This project builds the plumbing that keeps review findings honest. It recovers the new-file line number of every added line from a unified diff, runs four narrow detectors on added lines only, verifies every candidate (from any reviewer) against the diff and merges duplicates, and publishes a local HTML report plus SARIF, the format CI systems use to show findings on pull requests.

A local patch-review artifact that preserves Git line evidence and can enter CI as SARIF.

Node 22.18+, Python 3 and Git only for --repo mode; unified diff counters, JSON, exact source quotes and HTML escaping. The core uses standard libraries. The grader checks your selected workspace; it never fills in missing behavior from the reference.

Where it stops: Use --diff - for stdin, --repo /path --base REF --head REF for a read-only Git diff, or --candidates recorded-findings.json to validate another reviewer's findings against the supplied patch.

Check your mental model

Which statements are right?

  • ✓ A finding whose quote is not in the added line at that location is rejected.
  • ✗ A detector match proves the code is exploitable. It is a review candidate; the report says the detectors are lexical, not semantic.
  • ✓ When two reviewers flag the same file, line and rule, the findings merge and keep the stronger severity.
  • ✗ Source text in the report can be shown as HTML because it comes from your own repository. A diff can contain HTML or script; the report escapes it.

        "diff",

"""Parse ordinary textual Git unified diffs; retain physical new-file line numbers."""

import ast
import json
import re
import sys


def decode_path(raw):
    if raw.startswith('"'):
        try:
            value = ast.literal_eval(raw)
            if not isinstance(value, str):
                raise ValueError("bad quoted path")
            if re.search(r"\\[0-7]{3}", raw):
                value = value.encode("latin1").decode("utf-8")
        except (ValueError, SyntaxError, UnicodeError) as error:
            raise ValueError("bad quoted path") from error
    else:
        value = raw.split("\t", 1)[0]
    if value == "/dev/null":
        return None
    if value.startswith("b/"):
        value = value[2:]
    if (
        not value
        or value.startswith("/")
        or ".." in value.split("/")
        or any(ord(c) < 32 for c in value)
    ):
        raise ValueError("unsafe file")
    return value


def parse(raw):
    out, file, line, old_left, new_left = [], None, 0, 0, 0
    for text in raw.splitlines():
        if old_left or new_left:
            if text.startswith("\\"):
                continue
            if text.startswith("+"):
                out.append({"file": file, "line": line, "text": text[1:]})
                line += 1
                new_left -= 1
            elif text.startswith("-"):
                old_left -= 1
            elif text.startswith(" "):
                line += 1
                old_left -= 1
                new_left -= 1
            else:
                raise ValueError("bad or truncated hunk")
            if min(old_left, new_left) < 0:
                raise ValueError("hunk count mismatch")
        elif text.startswith("diff --git "):
            file = None
        elif text.startswith("+++ "):
            file = decode_path(text[4:])
        elif text.startswith("@@ "):
            match = re.match(r"^@@ -(\d+)(?:,(\d+))? \+(\d+)(?:,(\d+))? @@", text)
            if not match or file is None:
                raise ValueError("bad hunk")
            old_left = int(match[2]) if match[2] is not None else 1
            line = int(match[3])
            new_left = int(match[4]) if match[4] is not None else 1
    if old_left or new_left:
        raise ValueError("truncated hunk")
    return out


if __name__ == "__main__":
    try:
        print(json.dumps(parse(sys.stdin.read())))
    except ValueError as error:
        print(str(error), file=sys.stderr)
        sys.exit(1)

export type AddedLine = { file: string; line: number; text: string };
export type Finding = {
  file: string;
  line: number;
  quote: string;
  rule: string;
  severity: "high" | "medium" | "low";
  message: string;

export function parseDiff(raw: string): AddedLine[] {
  return JSON.parse(
    execFileSync(
      "python3",
      [fileURLToPath(new URL("./diff_parser.py", import.meta.url))],
      { input: raw, encoding: "utf8", maxBuffer: 1_000_000 },
    ),
  );
}
export function inspect(lines: AddedLine[]): Finding[] {
  const rules: [RegExp, string, Finding["severity"], string][] = [
    [
      /\beval\s*\(/,
      "dynamic-eval",
      "high",
      "Untrusted input can execute code.",
    ],
    [
      /\bexec\s*\(/,
      "shell-exec",
      "high",
      "Use an argument array instead of shell interpolation.",
    ],
    [
      /rejectUnauthorized\s*:\s*false/,
      "tls-disabled",
      "high",
      "TLS certificate verification is disabled.",
    ],
    [
      /\.catch\s*\(\s*\(\)\s*=>\s*\{\s*\}/,
      "empty-catch",
      "medium",
      "An empty catch hides failures.",
    ],
  ];
  return lines.flatMap((line) =>
    rules
      .filter(
        ([pattern]) =>
          !/^\s*(?:\/\/|\*|#)/.test(line.text) && pattern.test(line.text),
      )
      .map(([, rule, severity, message]) => ({
        ...line,
        quote: line.text,
        rule,
        severity,
        message,
      })),
  );
}
export function verify(
  findings: unknown[],
  lines: AddedLine[],
): { accepted: Finding[]; rejected: unknown[] } {
  if (!Array.isArray(findings)) throw new Error("candidates must be an array");
  const accepted: Finding[] = [];
  const rejected: unknown[] = [];
  for (const candidate of findings) {
    if (!candidate || typeof candidate !== "object" || Array.isArray(candidate)) {
      rejected.push(candidate);
      continue;
    }
    const f = candidate as Finding;
    if (
      ![f.file, f.quote, f.rule, f.message].every((value) => typeof value === "string") ||
      !Number.isSafeInteger(f.line) || f.line < 1
    ) {
      rejected.push(candidate);
      continue;
    }
    const line = lines.find((l) => l.file === f.file && l.line === f.line);
    if (
      !line ||
      !f.quote.trim() ||
      !line.text.includes(f.quote) ||
      !["high", "medium", "low"].includes(f.severity) ||
      !f.rule.trim() ||
      !f.message.trim()
    )
      rejected.push(f);
    else accepted.push(f);
  }
  return { accepted, rejected };
}
export function merge(findings: Finding[]): Finding[] {
  const ranks = { high: 3, medium: 2, low: 1 };
  const unique = new Map<string, Finding>();
  for (const f of findings) {
    const key = JSON.stringify([f.file, f.line, f.rule]);
    const prev = unique.get(key);
    if (!prev || ranks[f.severity] > ranks[prev.severity]) unique.set(key, f);
  }
  return [...unique.values()].sort(
    (a, b) =>
      ranks[b.severity] - ranks[a.severity] ||
      a.file.localeCompare(b.file) ||
      a.line - b.line,
  );
}
export function escapeHTML(value: string): string {
  return value.replace(
    /[&<>"']/g,
    (c) =>
      ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" })[
        c
      ]!,
  );
}
export function render(findings: Finding[], rejected = 0): string {
  return (
    '<!doctype html><meta charset="utf-8"><title>PR Review</title><h1>Anchored review</h1><p>' +
    findings.length +
    " findings; " +
    rejected +
    " rejected</p><ol>" +
    findings
      .map(
        (f) =>
          `<li><strong>${escapeHTML(f.severity)} ${escapeHTML(f.file)}:${f.line}</strong><p>${escapeHTML(f.message)}</p><pre>${escapeHTML(f.quote)}</pre><small>${escapeHTML(f.rule)}</small></li>`,
      )
      .join("") +
    "</ol>"
  );
}

Recap
What to keep from this project
  • Recover new-file line numbers from hunk headers; only added lines are reviewable.
  • Detectors produce candidates, not proof.
  • Verify every finding's location and exact quote, from any reviewer.
  • Merge duplicates by file, line and rule.
  • Escape source text; publish locally and as SARIF.

Solutions

Solution
  1. Only added lines

The pull request is responsible for what it adds. Existing code is reviewed elsewhere, and a finding on an unchanged line cannot be fixed by this change, so it is noise here.

Solution
  1. A model reviewer

Treat its output exactly like the detectors': each finding must name a file, an added line, a rule id and an exact quote from that line. Run it through the same verification gate and record rejections, which tell you how often the model invents locations.

Solution
  1. SARIF

A standard machine format that CI systems and code hosts read, so findings appear as annotations on the exact lines of the pull request, and can be tracked across runs.

SolutionB1 · A finding outside the change

Line 40 is not an added line in the diff, so verification rejects the finding and lists it under rejected. Nothing is posted for it.
