In plain words first
The idea in one line

Every generative model leaderboard cites FID, CLIP score, and a win rate from a human-preference arena. Each number has a failure mode a determined researcher can game. If you do not know the failure modes, you cannot tell a real improvement from a gaming run.

The problem

In plain words first

How do you tell whether one image generator is better than another? You cannot compute the probability of an image, so evaluation compares collections: thousands of generated images against thousands of real ones, using the features of a pretrained vision network. FID measures how far apart the two clouds of feature vectors are. The CLIP score measures how well each image matches its prompt, using a model that embeds images and text in the same space. Human preference, collected as pairwise votes, is turned into a ranking. Each number is easy to fool if you do not know how it works. This lesson checks the lesson's FID code against the standard implementation and its Elo ratings against the exact formula, then computes real FID with Inception-v3 on real photos (where it shows a large bias even for identical distributions) and real CLIP scores (where it shows how easily the score is nudged). Nothing is trained.

A generative model is judged on sample quality and conditioning adherence. Neither has a closed-form measure. Your model has to render 10,000 images; something has to assign them numbers; you have to trust the numbers across model families, across resolutions, across architectures. Three metrics survived the 2014-2026 gauntlet:

  • FID (Fréchet Inception Distance). A distance between two distributions — real and generated — in an Inception network's feature space. Lower is better.
  • CLIP score. Cosine similarity between a generated image's CLIP-image embedding and a prompt's CLIP-text embedding. Higher is better. Measures prompt adherence.
  • Human preference. Pit two models head-to-head on the same prompt, have humans (or a GPT-4-class model) pick the better one, aggregate to an Elo score.

You will also see: IS (inception score, largely retired), KID, CMMD, ImageReward, PickScore, HPSv2, MJHQ-30k. Each corrects for one failure of the previous.

The idea

Idea 1 · FID — sample quality

Heusel et al. (2017). Steps:

  1. Extract Inception-v3 features (2048-D) for N real images and N generated.
  2. Fit a Gaussian to each pool: compute mean μr​,μg​ and covariance Σr​,Σg​.
  3. FID=∥μr​−μg​∥2+Tr(Σr​+Σg​−2⋅(Σr​⋅Σg​)0.5).

Interpretation: Fréchet distance between two multivariate Gaussians in feature space. Lower = more similar distributions.

Failure modes: - Biased on small N. FID is mean-squared over the feature distribution — small N under-estimates covariance, gives falsely low FID. Always use N≥10,000. - Inception-dependent. Inception-v3 was trained on ImageNet. Domains far from ImageNet (faces, art, text images) produce meaningless FID. Use a domain-specific feature extractor. - Gaming. Overfitting to the Inception prior gives low FID without visual quality improvement. Beat it with CMMD (below).

Idea 2 · CLIP score — prompt adherence

Radford et al. (2021). For a generated image + prompt:

clip_score = cos_sim( CLIP_image(x_gen), CLIP_text(prompt) )

Average across 30k generated images → a scalar comparable between models.

Failure modes: - CLIP's own blind spots. CLIP has weak compositional reasoning ("a red cube on a blue sphere" often fails). Models can rank well on CLIP score without really following complex prompts. - Short prompt bias. Short prompts have more CLIP-image matches in the wild. Longer prompts have lower CLIP scores mechanically. - Prompt gaming. Including "high quality, 4k, masterpiece" in the prompt inflates CLIP score without improving image-text binding.

CMMD (Jayasumana et al., 2024) fixes some of these: uses CLIP features instead of Inception, maximum-mean discrepancy instead of Fréchet. Better at detecting subtle quality differences.

Idea 3 · Human preference — the ground truth

Pick a pool of prompts. Generate with model A and model B. Show pairs to humans (or a strong LLM judge). Aggregate wins into an Elo or Bradley-Terry score. Benchmarks:

  • PartiPrompts (Google): 1,600 diverse prompts, 12 categories.
  • HPSv2: a CLIP model fine-tuned on Human Preference Dataset v2 (798k pairwise choices), widely used as an automated proxy.
  • ImageReward: a reward model trained on 137k expert comparisons of prompt-image pairs.
  • PickScore: a CLIP model trained on Pick-a-Pic, preferences collected from real users of a generation app.
  • Public arenas: LMArena's text-to-image and image-editing leaderboards and Artificial Analysis's image arena rank models from crowd votes.

Failure modes: - Judge variance. Non-experts have different preferences than experts. Use both. - Prompt distribution. Cherry-picked prompts favor one family. Always document. - LLM-judge reward hacking. GPT-4-judge gets fooled by pretty-but-wrong outputs. Triangulate with human.

Use together

A production eval report should include:

  1. FID on 10-30k samples against a held-out real distribution (sample quality).
  2. CLIP score / CMMD on the same samples vs their prompts (adherence).
  3. Win rate in a blinded arena vs the previous model (overall preference).
  4. Failure mode analysis: 50 randomly sampled outputs, flagged for known issues (hand anatomy, text rendering, consistent object count).

Any single metric is a lie. Three corroborating metrics + qualitative review are a claim.

The same idea as a formula

FID. Fit Gaussians N(μr​,Σr​) and N(μg​,Σg​) to the real and generated feature vectors. The Fréchet (Wasserstein-2) distance between them is

FID=∥μr​−μg​∥2+Tr(Σr​+Σg​−2(Σr​Σg​)1/2)

zero only if both means and covariances match.

Why small N inflates it. Means and covariances estimated from N samples are noisy, and every estimation error adds to the distance; for 2,048-dimensional features with N in the hundreds, the covariance estimates are not even full rank. The expected value behaves like FIDN​≈FID∞​+c/N, so FIDs are only comparable at the same N (or after extrapolating to N→∞).

KID and CMMD use the maximum mean discrepancy instead: MMD2=E[k(x,x′)]+E[k(y,y′)]−2E[k(x,y)], with an unbiased estimator and no Gaussian assumption (KID: polynomial kernel on Inception features; CMMD: Gaussian kernel on CLIP features).

CLIP score. CLIPScore(x,c)=w⋅max(cos(EI​(x),ET​(c)),0), with w=2.5 in the original paper and w=100 in common libraries.

Bradley–Terry / Elo. P(A beats B)=1+10(RB​−RA​)/4001​. Fitting ratings to all pairwise results by maximum likelihood gives stable rankings; online Elo updates (R←R+K(result−expected)) depend on the order of games.

Worked example
FID and Elo by hand

FID in one dimension. Real N(0,1), generated N(0.5,22): (0.5)2+(1+4−21⋅4​)=0.25+1=1.25. The mean shift contributes 0.25; the too-wide spread contributes 1.

What a covariance error costs. Generated features with the right mean but every variance halved (in d dimensions, diagonal covariances): each dimension adds 1+0.5−20.5​=0.086, so d=2,048 gives an FID of about 176, from spread alone.

Elo from a win rate. Model A wins 70% of comparisons: RA​−RB​=400log10​(0.7/0.3)=147. At 55%: 400log10​(0.55/0.45)=35, small gaps need many votes to establish.

Check your mental model
  • ✗ "FID is 0 for two samples of the same distribution."
    ✓ Only as N→∞; for 300 real photos against 300 others, Inception FID is far from 0 (the run under "Use it").
  • ✗ "A higher CLIP score means the image follows the prompt better."
    ✓ Only on average, and only for what CLIP can see; adding style words or reordering a compositional prompt changes the score without changing the image.
  • ✗ "The final Elo after a stream of games is the rating."
    ✓ Online Elo is noisy and order-dependent; leaderboards fit Bradley–Terry to all games and report confidence intervals.

Step 1 · FID in four lines

code/main.py implements FID, CLIP-score-like, and Elo aggregation on synthetic "feature vectors" (we use 4-D vectors as stand-ins for Inception features). You see:

  • FID computation on a small N and on a large N — the bias.
  • "CLIP score" as cosine similarity between feature pools.
  • Elo update rule from a synthetic preference stream.
def fid(real_features, gen_features):
    mu_r, cov_r = mean_and_cov(real_features)
    mu_g, cov_g = mean_and_cov(gen_features)
    mean_diff = sum((a - b) ** 2 for a, b in zip(mu_r, mu_g))
    trace_term = trace(cov_r) + trace(cov_g) - 2 * sqrt_cov_product(cov_r, cov_g)
    return mean_diff + trace_term

Step 2 · CLIP-style cosine-similarity

def clip_like(image_feat, text_feat):
    dot = sum(a * b for a, b in zip(image_feat, text_feat))
    norm = math.sqrt(dot_self(image_feat) * dot_self(text_feat))
    return dot / max(norm, 1e-8)

Step 3 · Elo aggregation

def elo_update(r_a, r_b, winner, k=32):
    expected_a = 1 / (1 + 10 ** ((r_b - r_a) / 400))
    actual_a = 1.0 if winner == "a" else 0.0
    r_a_new = r_a + k * (actual_a - expected_a)
    r_b_new = r_b - k * (actual_a - expected_a)
    return r_a_new, r_b_new

Reading this output

The lesson's demo shows the right trends on its four-dimensional features: FID between two samples of the same distribution falls from 0.043 at N=50 to 0.002 at N=1,000 (the small-N bias), and grows smoothly with a real shift (0.19, 1.15, 4.12). Its hand-written fid(), with a Denman–Beavers matrix square root, matches SciPy's to five decimals (0.35997). The Elo line is the one to distrust. After 200 games in which A wins 70%, the printed gap is only 28 points, while the Bradley–Terry formula says a 70% win rate means 147. Replaying the stream 200 times explains it: online Elo ends 163 points apart on average but with a spread of ±79, so any single run's final number is mostly noise, while fitting Bradley–Terry to the win count gives 152±28. Leaderboards fit all games at once for this reason.

Pitfalls

  • FID at N=1000. Heuristic is unreliable under N=10k. Papers reporting low-N FID are gaming.
  • Comparing FID across resolutions. Inception's 299×299 resize changes the feature distribution. Compare at matched resolution only.
  • Reporting one seed. Run 3 seeds minimum. Report std.
  • CLIP score inflation via negative prompts. Some pipelines boost CLIP by over-fitting the prompt. Check for visual saturation.
  • Elo bias from prompt overlap. If both models saw a benchmark prompt during training, Elo is meaningless. Use held-out prompt sets.
  • Human eval paid-crowd skew. Prolific, MTurk annotators skew younger / tech-friendly. Mix with recruited art/design experts.

FID with Inception-v3 on real photos

timm's Inception-v3 (torchvision's ImageNet weights), 2048-number pooled features, on Imagenette photos: real against real, against the same photos blurred, a mode-collapsed set of only two classes, and the effect of N.

import io, time, numpy as np, torch, timm, pyarrow.parquet as pq
from PIL import Image, ImageFilter
from huggingface_hub import hf_hub_download

torch.set_num_threads(2)
# Inception-v3 (torchvision's ImageNet weights, via timm): the 2048-number pooled features FID is defined on.
net = timm.create_model("inception_v3.tv_in1k", pretrained=True, num_classes=0).eval()
cfg = timm.data.resolve_data_config({}, model=net); prep = timm.data.create_transform(**cfg)
table = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
                      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"), columns=["image", "label"])
labels = np.array(table.column("label").to_pylist())
load = lambda r: Image.open(io.BytesIO(table.column("image")[int(r)].as_py()["bytes"])).convert("RGB")
def feats(rows, edit=lambda im: im):
    out = []
    with torch.no_grad():
        for i in range(0, len(rows), 50):
            out.append(net(torch.stack([prep(edit(load(r))) for r in rows[i:i + 50]])).numpy())
    return np.concatenate(out).astype(np.float64)
def fid(X, Y):
    """Exact FID. With N < 2048 samples, Tr((Sr Sg)^1/2) equals the sum of singular values of A^T B,
    where Sr = A A^T and Sg = B B^T (A, B: centred features / sqrt(N - 1)); an N x N problem instead of 2048 x 2048."""
    A = (X - X.mean(0)).T / np.sqrt(len(X) - 1); B = (Y - Y.mean(0)).T / np.sqrt(len(Y) - 1)
    tr_sqrt = np.linalg.svd(A.T @ B, compute_uv=False).sum()
    return float(((X.mean(0) - Y.mean(0)) ** 2).sum() + (A * A).sum() + (B * B).sum() - 2 * tr_sqrt)

perm = np.random.default_rng(0).permutation(len(labels))
ref_rows, test_rows = perm[:200], perm[200:400]                     # two disjoint random sets of real photos
t0 = time.perf_counter()
R = feats(ref_rows); T = feats(test_rows)
Tb = feats(test_rows, lambda im: im.filter(ImageFilter.GaussianBlur(3)))
print(f"Inception features for 600 photos: {time.perf_counter() - t0:.0f} s on this CPU; 2048 numbers each")
print(f"FID real vs real (200 vs 200, same distribution): {fid(R, T):6.1f}   <- not 0: small-N bias")
print(f"FID real vs the same 200 test photos blurred:     {fid(R, Tb):6.1f}")
two = np.flatnonzero(np.isin(labels[test_rows], [2, 8]))           # only cassette players and golf balls
rand = np.arange(len(two))
print(f"at N = {len(two)}: FID vs {len(two)} random test photos {fid(R, T[rand]):6.1f} | "
      f"vs {len(two)} photos of only 2 classes {fid(R, T[two]):6.1f}")
for n in (25, 50, 100, 200):
    print(f"  real vs real with N = {n:3d}: FID {fid(R[:n], T[:n]):6.1f}")

CLIP score with CLIP ViT-B/32

OpenAI's CLIP ViT-B/32 on 60 Imagenette photos: correct captions, wrong captions, wrong captions padded with "quality" words, and a compositional prompt with its words swapped.

import io, numpy as np, torch, pyarrow.parquet as pq
from PIL import Image
from huggingface_hub import hf_hub_download
from transformers import CLIPModel, CLIPProcessor

torch.set_num_threads(2)
model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32").eval()
proc = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")
names = ["tench", "English springer", "cassette player", "chain saw", "church", "French horn", "garbage truck",
         "gas pump", "golf ball", "parachute"]
table = pq.read_table(hf_hub_download("Multimodal-Fatima/Imagenette_validation",
                      "data/validation-00000-of-00001-b518380f1876c09a.parquet", repo_type="dataset"), columns=["image", "label"])
rows = np.random.default_rng(1).permutation(table.num_rows)[:60]
imgs = [Image.open(io.BytesIO(table.column("image")[int(r)].as_py()["bytes"])).convert("RGB") for r in rows]
lab = [table.column("label")[int(r)].as_py() for r in rows]

def clip_score(images, texts):                 # CLIPScore = 100 * max(cos(image, text), 0), per pair
    with torch.no_grad():
        i = model.get_image_features(**proc(images=images, return_tensors="pt"))
        t = model.get_text_features(**proc(text=texts, return_tensors="pt", padding=True))
        i, t = (x if torch.is_tensor(x) else x.pooler_output for x in (i, t))   # projected 512-number embeddings
    return (100 * torch.nn.functional.cosine_similarity(i, t).clamp(min=0)).numpy()

right = clip_score(imgs, [f"a photo of a {names[l]}" for l in lab])
wrong = clip_score(imgs, [f"a photo of a {names[(l + 5) % 10]}" for l in lab])
fluff_r = clip_score(imgs, [f"a photo of a {names[l]}, high quality, 4k, masterpiece" for l in lab])
fluff_w = clip_score(imgs, [f"a photo of a {names[(l + 5) % 10]}, high quality, 4k, masterpiece" for l in lab])
print(f"CLIP score, 60 photos: correct caption {right.mean():.1f} | wrong caption {wrong.mean():.1f}")
print(f"  with ', high quality, 4k, masterpiece' added: correct {fluff_r.mean():.1f} | wrong {fluff_w.mean():.1f}")
print(f"photos where the correct caption scores higher than the wrong one: {np.mean(right > wrong):.0%}")
print(f"spread of correct-caption scores: {right.min():.1f} to {right.max():.1f} (std {right.std():.1f})")
comp = clip_score([imgs[0]] * 2, ["a red cube on top of a blue sphere", "a blue sphere on top of a red cube"])
print(f"word order test on one photo: 'red cube on a blue sphere' {comp[0]:.2f} vs 'blue sphere on a red cube' {comp[1]:.2f}")

  with ', high quality, 4k, masterpiece' added: correct 26.9 | wrong 15.6

Reading this output

CLIP separates right from wrong captions perfectly on these 60 photos (29.5 against 17.4, correct higher every time), so as a relative measure it works. Absolute values say little: correct-caption scores range from 23.5 to 34.7 depending on the photo. Wording moves the score as much as content does: appending "high quality, 4k, masterpiece" to the caption lowers the correct-caption score from 29.5 to 26.9, because these photos are not glossy renders, so CLIP scores are comparable only with identical captions. The word-order test shows the compositional blind spot: "a red cube on a blue sphere" and "a blue sphere on a red cube" score 12.87 and 13.06, practically the same, since CLIP's embedding barely encodes which object is on top. Benchmarks for compositional prompt following therefore use VQA-style checks instead.

Break it on purpose

In fid, replace the matrix square root term with the plain product: trace(cov_r) + trace(cov_g) - 2 * trace(matmul(cov_r, cov_g)). For features whose variances are around 0.16 (the lesson's scale=0.4), what happens to FID for identical distributions, and what goes wrong at other scales? (Solution B1.)

Industry practice
What's current (2024–2026)
  • Arenas decide reputations. LMArena's text-to-image and image-editing leaderboards and Artificial Analysis's arena rank models by Bradley–Terry fits to crowd votes; vendors quote them at launch.
  • Learned scorers and VQA checks. HPSv2, ImageReward, PickScore and VQA-based checks (VQAScore, GenEval, DPG-Bench, GenAI-Bench) measure preference and compositional prompt following, where CLIP score is weak.
  • Better distribution metrics. FD with DINOv2 features and CMMD with CLIP features supplement or replace Inception FID; torchmetrics, clean-fid and torch-fidelity provide reference implementations with fixed preprocessing.

Sources: LMArena, Artificial Analysis image arena, HPSv2, clean-fid, CMMD, GenEval.

Recap
What to keep from this lesson
  • FID compares Gaussian fits of feature clouds: means plus covariances, with a matrix square root.
  • FID depends on N, the feature network and preprocessing; compare only like with like.
  • CLIP score measures text-image agreement as CLIP sees it; it is easy to nudge and weak on composition.
  • Preferences become ratings through Bradley–Terry; online Elo alone is noisy.
  • Report several metrics, at stated sample sizes, plus a look at the images.

Given a new generative-model checkpoint, a reference baseline, and a modality (image / video / audio / 3D), output a full eval plan:

1. Sample quality. FID / FD-DINO / CMMD on 10-30k samples vs held-out real set. Matched resolution. Report 3-seed mean +/- std.
2. Adherence. CLIP score / CMMD on prompt-image pairs. Include HPSv2 + ImageReward + PickScore for text-to-image. For video, add vision-language metrics (V-Eval). For audio, CLAP + MOS.
3. Pairwise preference. Blinded A/B on 200-2000 prompts vs baseline. Human + LLM-judge + PartiPrompts coverage.
4. Category breakdown. Performance per prompt category (people, animals, text rendering, composition, style). Flag regressions per category even if global metrics improve.
5. Safety / misuse. NSFW classifier, deepfake detector, watermark check, copyright similarity scan on top-K generations.
6. Sign-off. Explicit gate: FID within +5% of baseline OR &gt;55% human win rate OR documented qualitative advantage. No single-metric claims.

Refuse to report FID at N &lt; 5000. Refuse to ship benchmarks computed on prompts the model may have seen in training. Refuse to report only LLM-judge results without human cross-check. Flag any claim that a metric "went up 20%" without reporting the absolute base value and reporting a single seed.

Exercises

  1. Easy. Run code/main.py. Compare FID at N=100 vs N=1000 on the same synthetic distributions. Report bias magnitude.
  2. Medium. Implement CMMD from synthetic CLIP-style features (see Jayasumana et al., 2024 for the formula). Compare sensitivity to quality differences vs FID.
  3. Hard. Replicate the HPSv2 setup: take 1000 image-prompt pairs from a subset of Pick-a-Pic, fine-tune a small CLIP-based scorer on the preferences, and measure its agreement with a held-out set.

Solutions

SolutionP1 · Much larger

Much larger: about 92 for 200 photos against 200 others from the same dataset, and still 119 and 152 with 100 and 50. Nothing differs between the sets except chance; the whole number is estimation error, because 200 samples cannot pin down a 2,048-dimensional covariance. Published FIDs of 2–10 are computed with 10,000–50,000 samples, where this bias is small. Two consequences: never compare FIDs computed at different N, and treat any small-N FID as meaningful only relative to a real-against-real baseline at the same N.

SolutionB1 · A formula with the wrong units

Σr​Σg​ has squared units: for variances of 0.16 its trace is about 4×0.0256=0.10 in four dimensions, while (Σr​Σg​)1/2 has the same units as the variances, trace 0.64. With identical distributions the broken FID is 0.64+0.64−2×0.10≈1.08 instead of about 0: two identical distributions look far apart. At feature scale 1 the product and its square root happen to coincide and the bug hides; at larger scales the product term dominates and FID goes negative. Any formula whose value depends on the units of the features in this way is a sign of a missing square root. The standard implementation uses scipy.linalg.sqrtm, as the check after Step 3 does.

Production note: evaluation is an inference workload too

Running FID on 10k samples means generating 10k images. For a 50-step SDXL base at 1024² on a single L4, that is ~11 hours of single-request inference. Evaluation budgets are real, and the framing is exactly the offline-inference scenario (maximize throughput, ignore TTFT):

  • Batch hard, forget latency. Offline eval = static batching at the largest size that fits in memory. pipe(...).images with num_images_per_prompt=8 on an 80GB H100 runs 4-6× faster wall-clock than single-request.
  • Cache the real features. The Inception (FID) or CLIP (CLIP-score, CMMD) feature extraction over the real reference set is run once, stored as a .npz. Do not recompute per eval.

For CI / regression gates: run FID + CLIP score on a 500-sample subset per PR (~30 min); run full 10k FID + HPSv2 + Elo nightly.
