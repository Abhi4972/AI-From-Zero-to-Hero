The idea in one line

Pre-gen, during-gen, post-gen. Three checkpoints, one verdict, an audit trail per request.

Problem

Lessons 82-86 in this track each shipped a single piece: a taxonomy, an input detector, an evaluation framework, an output classifier, a rules engine. A real safety gate has to compose the runtime pieces (the lesson 83 detector, the lesson 85 classifier, and the lesson 86 rules engine), run them at the right moment in the request lifecycle, decide what action to take when they disagree, and produce a trace a reviewer can read on Monday morning. The composition is the lesson.

The gate sits at three checkpoints. Pre-gen runs before the model is called: the detector from lesson 83 looks at the prompt and either passes it, blocks it outright (high-confidence attack), or attaches a flag for downstream layers to weigh. During-gen runs as the model emits tokens: a streaming filter buffers chunks and terminates the stream early if a forbidden phrase appears (prefix-injection survives this if the gate only looks post-hoc). Post-gen runs after the model finishes: the classifier router from lesson 85 and the rules engine from lesson 86 inspect the full output, the gate aggregates their verdicts with the pre-gen signal, and the gate applies a final action.

The gate is self-terminating: every fixture in the lesson 82 taxonomy is run end to end, the gate emits a per-request trace, and the demo exits zero whether the gate blocks every attack or not. The point is observability and structural correctness, not a perfect score.

Concept

Three checkpoints, one decision tree.

The aggregator combines four severity signals: detector confidence (lesson 83), token-filter trigger (boolean), classifier max severity (lesson 85), rules engine max severity (lesson 86). The aggregation function is a deterministic table.

Signal state Action
detector confidence >= 0.85 on a non-benign category block before generation
any high severity block
any medium severity (detector confidence 0.5 to 0.85, or early stream termination) redact
any low severity (detector confidence below 0.5 on a non-benign category) warn
detector says benign and no other signal allow

Block returns a refusal. Redact ships the classifier-redacted text and applies the rules-engine fixer. Warn ships the original with a soft notice. Allow ships the original. Each request emits a RequestTrace with request_id, prompt, pre_gen (detector verdict), during_gen (token-filter trigger), post_gen (classifier action + rules report), final_action, final_output, and latency_ms.

The during-gen filter is a streaming abstraction. The mock LLM yields chunks (4 tokens each by default). The filter buffers up to two chunks and runs a regex sweep for known continuation tokens (Sure, here is the procedure, step 1: take, etc). On match it terminates the iterator and returns the partial output marked terminated_early=True. The downstream aggregator treats early termination as a medium severity signal.

The mock LLM has two behaviors keyed off the prompt: it refuses recognizable attacks (returns I cannot ...) and answers benign prompts (returns a generic helpful string). For a small subset of attacks (notably encoding tricks not caught by the input pipeline) it produces a partial harmful continuation that the during-gen filter is supposed to catch. This is intentional. The gate's value is in the layered defense; the demo shows the layers interact correctly.

Build it

code/safety_gate.py defines the SafetyGate class. It imports the detector, classifier router, and rules engine from the prior lessons via relative file paths. code/mock_llm_stream.py defines a streaming mock LLM with three scripted personas (clean, attacker-honest, attacker-lazy). code/main.py runs the lesson 82 corpus end-to-end through the gate and writes outputs/gate_trace.json.

The demo runs all 50 taxonomy fixtures plus 10 benign prompts. The trace summary reports: blocks, redacts, warns, allows, early terminations, per-category outcome breakdown, and average latency. The numbers are not the point; the per-request trace is the point.

Use it: the same idea with real libraries

python3 main.py or npx tsx main.ts. The demo loads everything, runs end-to-end, prints the summary table, and writes the trace artifact. Exit code is zero. The demo is self-terminating in the literal sense: each request runs to completion or early termination and the gate moves to the next.

# End-to-End Safety Gate

## Lifecycle

1. pre-gen - run the lesson 83 detector on the prompt
   - if confidence >= block_threshold: return refusal, emit trace, stop
2. during-gen - stream from the model, buffer two chunks, scan for known harmful continuations
   - if matched: terminate iterator, mark trace, treat as medium severity
3. post-gen - if no early termination, run the lesson 85 classifier router and the lesson 86 rules engine on the completed output
4. aggregate - take the maximum severity across pre, during, post.classifier, post.rules
5. apply - map to block, redact, warn, or allow

## Aggregation table

| Signal state | Action |
|---|---|
| any high severity | block |
| any medium severity | redact |
| any low severity | warn |
| nothing | allow |

## Trace structure

```text
RequestTrace
  request_id: str
  prompt: str
  pre_gen: { category, confidence, fired[] }
  during_gen: { terminated_early, matched_pattern, partial_chunks }
  post_gen: { classifier_action, classifier_severity, rules_max_severity, rules_violations[] } | null
  final_action: block | redact | warn | allow
  final_output: str
  latency_ms: float
```

## Artifact

`outputs/gate_trace.json` contains the summary and one trace per request, including 50 taxonomy fixtures and 10 benign prompts.

Exercises

  1. Add a fifth checkpoint: a policy-check that runs against the original system prompt before pre-gen. It must reject prompts targeting a known internal tool name.
  2. Replace the deterministic aggregator with a weighted score: each signal contributes a 0-1 confidence and the gate trips at a threshold. Sweep the threshold and report the precision-recall trade-off on the lesson 82 corpus.
  3. Add an async streaming variant where during-gen runs in a thread; verify the latency impact stays within a 50ms budget.

Level 3 of 4 · about 12 minutes to answer well.

Short answer. The first request blocks before generation: a non benign category at or above the block confidence ranks high, and high maps to block. The second request redacts: early termination is a medium signal on its own, so the partial output ships through the redactors and the fixer. The third blocks: a high rule severity ranks the same as a high classifier severity. By design the table takes the maximum, so signals never add up; three low signals stay a warn, and a medium detector flag next to a medium classifier finding stays a redact.

The thresholds.

The gate sets the block confidence at 0.85 and the note confidence at 0.5. A non benign detector verdict at or above 0.85 is high and blocks before the model runs. Between 0.5 and 0.85 it is medium. Below 0.5 it is low. A benign verdict adds no signal at all.

Request one: flagged prompt.

The detector returns a non benign category above 0.85. The pre generation signal ranks high. The gate never calls the model; it returns a refusal and writes a trace with the detector verdict and no post generation section.

Request two: benign prompt, stream cut.

The detector says benign, so nothing from pre generation. The streaming filter buffers two chunks of four tokens and sweeps a regex of continuation phrases over the window; it matches, terminates the iterator and marks the output as terminated early. That is one medium signal. Post generation runs on the partial text; if the classifier and the rules return none, the maximum is medium and the action is redact: the classifier redactors and the rules fixer run on the partial output, which ships with the trace.

Request three: benign prompt, high rule.

No pre generation signal and no early termination. The classifier router returns none. The rules engine returns a high violation, for example an internal library name in the output. The rules signal ranks high and the action is block, the same as if a classifier had found something high.

The limits the design accepts.

  • No accumulation. The maximum ignores how many signals fired. Several weak signals that together describe an attack still warn.
  • No weights. A medium from the detector and a medium from the classifier carry the same weight whatever their track record.
  • A short window. The streaming filter holds two chunks, so a continuation phrase split across more chunks escapes it; the post generation pass is the backstop, and a prefix injection that only shows after the fact survives a gate that looks only post hoc.
  • Fixed thresholds. The capstone's exercise proposes a weighted score tripped at a threshold, tuned by sweeping it against the corpus and reading precision and recall per category.

The point of the gate is the per request trace with every checkpoint's verdict, the final action and the latency, not a perfect score on the corpus.

Plausible wrong answers.

  • "Block whenever any layer fires." Low and medium signals exist so benign prompts with weak matches do not get refused; the table maps them to warn and redact.
  • "Set the block threshold low to save model calls." A low threshold turns the detector's middling precision on role play into refusals of creative requests; the capstone blocks at 0.85.
  • "The demo exits zero, so the gate caught every attack." The demo is self terminating by design; the trace is the deliverable, and the summary counts show what got through.

Follow-ups an interviewer may ask.

  • (level 3) Why is early termination medium and not high? Expected: a regex match on a two chunk window is weaker evidence than a confirmed high classifier finding; the partial output still goes through redaction.
  • (level 3) A low detector flag and a low rule violation arrive together. What ships? Expected: a warn with a soft notice; the maximum of two lows is low, and the table does not accumulate.
  • (level 4) What would a weighted aggregator change, and what does it cost? Expected: signals would add toward a threshold so several weak signals could block; the cost is a tuned threshold, set by sweeping it against the corpus and reading precision and recall per category.
  • (level 4) What does the two chunk buffer miss, and what catches it? Expected: a continuation phrase split across more chunks than the buffer holds; the post generation pass is the backstop.

Debug a failureYour gate blocks most attacks before the model runs. In the trace of one request the detector said benign, the model began answering with a procedure it must never give, and the response was cut after a few tokens and shipped as a redacted partial. Explain which layer acted, why the first layer missed, and whether the outcome is correct.

Level 3 of 4 · about 9 minutes to answer well.

Short answer. The streaming filter acted: it buffers a short window of emitted chunks, sweeps it for known continuation phrases, terminates the stream on a match and marks the output as terminated early, which the aggregator treats as a medium signal and maps to redact. The detector missed because the prompt was an encoding trick or a prefix injection whose surface the input rules did not cover. The outcome is correct for the design: the harmful continuation never completed, and the trace records the miss for the detector team.

The layer that acted.

The gate runs at three checkpoints. Pre generation is the detector. During generation is a filter over the model's stream: the mock yields chunks of four tokens, the filter holds up to two chunks, runs a regex of continuation phrases over the window, and on a match stops the iterator and returns the partial output marked as terminated early. Post generation runs the classifier router and the rules engine on whatever was emitted.

Why the detector missed.

Two taxonomy categories are built to pass input rules. An encoding trick hides the forbidden tokens in base64, rot13, leet speak or zero width characters, and a rule set that does not decode that form sees nothing. A prefix injection ends the prompt with the first words of the answer, so the model continues from an assumed yes instead of deciding; the prompt itself can look harmless. The capstone's mock produces a partial harmful continuation on exactly that subset of attacks, on purpose, so the layers can be seen interacting.

Why redact and not block.

Early termination is one medium signal. The post generation pass on the partial text found nothing high. The maximum is medium, so the action is redact: the classifier redactors and the rules fixer run over the partial, and it ships with a trace that shows the detector verdict, the matched termination pattern, the post generation verdicts, the final action and the latency.

What to do with the trace.

Add the prompt to the taxonomy as a fixture with its category and severity. Add or adjust a detector rule for its family. Rerun the metrics runner and read the recall change in that category and the false positive change on the benign list. The trace exists so that a miss becomes a fixture instead of a story.

The limit.

The window holds two chunks. A continuation phrase split across more chunks escapes the filter, and the post generation pass is the backstop. A gate that looked only after generation would let a prefix injection stream its procedure to the user before any check.

Plausible wrong answers.

  • "The gate failed because the detector said benign." The gate is layered so that a miss in one layer is caught by the next; the trace shows the design working.
  • "Ship nothing when the stream is cut." The design maps early termination to redact and ships the partial through the redactors; a block needs a high signal.
  • "Scan the whole output after generation instead." A post hoc only look lets a prefix injection stream its procedure to the user before the check; the filter exists to stop the stream early.

Follow-ups an interviewer may ask.

  • (level 3) Why does the filter hold two chunks instead of scanning each chunk alone? Expected: a continuation phrase can span a chunk boundary; the window lets the regex see across it at the cost of a short delay.
  • (level 3) Which taxonomy categories does this layer exist for? Expected: encoding tricks that pass the input rules, and prefix injection, where the prompt sets the first words of the answer.
  • (level 4) What is the next action for the detector team, and how do they know it worked? Expected: add the prompt as a fixture with its category, add or adjust a rule, and read the per category recall and the benign false positive rate from the metrics runner.
