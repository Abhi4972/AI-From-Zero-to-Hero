Why this came about

Google Cloud's data services (BigQuery and others) became AI platforms in their own right, and security tools such as Model Armor were added for AI-specific threats. Agents there combine all of these.

In plain words first
The rest of Google Cloud around the agent

Around the agent platform, Google Cloud offers Vertex AI for training and serving custom models, BigQuery for data and in-database AI, Document AI and speech services, Cloud Logging and Trace for observability, and IAM, VPC Service Controls and Model Armor for security. Production agents combine them.

import io, json
import httpx, requests, urllib3
import google.oauth2.credentials

class Recorded(requests.adapters.BaseAdapter):
    """Lab mode: answer HTTP calls from recorded JSON (same helper as Lesson 13.5)."""
    def __init__(self, routes: dict):
        super().__init__()
        self.routes = routes
    def send(self, request, **kwargs):
        answer = next(a for (m, frag), a in self.routes.items() if m == request.method and frag in request.url)
        raw = urllib3.HTTPResponse(body=io.BytesIO(json.dumps(answer).encode()),
                                   headers={"Content-Type": "application/json"}, status=200, preload_content=False)
        return requests.adapters.HTTPAdapter().build_response(request, raw)
    def close(self): pass

OFFLINE = google.oauth2.credentials.Credentials(token="offline")
PROJECT, LOCATION = "shopkart-prod", "asia-south1"

from google.cloud import dlp_v2

dlp = dlp_v2.DlpServiceClient(transport="rest", credentials=OFFLINE)
dlp._transport._session.mount("https://", Recorded({("POST", "/content:deidentify"): {
    "item": {"value": "Call me back on [PHONE_NUMBER] or [EMAIL_ADDRESS] about A-1001"}}}))

def redact(text: str) -> str:
    """Replace sensitive values with their type before logging or prompting (Lesson 10.1)."""
    out = dlp.deidentify_content(request={
        "parent": f"projects/{PROJECT}/locations/{LOCATION}",
        "inspect_config": {"info_types": [{"name": n} for n in
                           ("PHONE_NUMBER", "EMAIL_ADDRESS", "INDIA_AADHAAR_INDIVIDUAL", "INDIA_PAN_INDIVIDUAL")]},
        "deidentify_config": {"info_type_transformations": {"transformations": [
            {"primitive_transformation": {"replace_with_info_type_config": {}}}]}},
        "item": {"value": text}})
    return out.item.value

print(redact("Call me back on 9876543210 or ravi@example.com about A-1001"))
What you should see
Call me back on [PHONE_NUMBER] or [EMAIL_ADDRESS] about A-1001

AI inside the data platform

Much of Google's agent story runs through BigQuery: models are callable from SQL, so data teams can classify, extract and summarize millions of rows without moving data.

from google.cloud import bigquery

bq = bigquery.Client(project=PROJECT, credentials=OFFLINE, location=LOCATION)
bq._http.mount("https://", Recorded({("POST", "/queries"): {
    "kind": "bigquery#queryResponse", "jobComplete": True, "totalRows": "1",
    "jobReference": {"projectId": PROJECT, "jobId": "job_1", "location": LOCATION},
    "schema": {"fields": [{"name": "ticket_id", "type": "STRING"}, {"name": "category", "type": "STRING"}]},
    "rows": [{"f": [{"v": "T-981"}, {"v": "damaged_item"}]}]}}))

SQL = """
SELECT ticket_id,
       AI.GENERATE(('Classify this ShopKart ticket as late_delivery, damaged_item, refund or other. Ticket: ', body),
                   endpoint => 'gemini-3.8-flash').result AS category
FROM support.tickets
WHERE created_at > TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 1 DAY)"""
for row in bq.query_and_wait(SQL):
    print(row.ticket_id, row.category)
What you should see
T-981 damaged_item

Batch enrichment like this is often cheaper and simpler than an agent. An agent can also call this query as a tool.

BigQuery is also a vector store. Embeddings are generated in SQL, a vector index keeps search fast, and VECTOR_SEARCH returns the nearest chunks, so a retrieval tool for an agent can be one parameterized query over data that already lives in the warehouse:

-- once: embed the chunks and index them
CREATE OR REPLACE TABLE kb.policy_chunks AS
SELECT chunk_id, text, ml_generate_embedding_result AS embedding
FROM ML.GENERATE_EMBEDDING(MODEL kb.embedder, (SELECT chunk_id, text AS content, text FROM kb.raw_chunks));

CREATE VECTOR INDEX policy_idx ON kb.policy_chunks(embedding)
OPTIONS (index_type = 'IVF', distance_type = 'COSINE');

bq._http.mount("https://", Recorded({("POST", "/queries"): {
    "kind": "bigquery#queryResponse", "jobComplete": True, "totalRows": "2",
    "jobReference": {"projectId": PROJECT, "jobId": "job_2", "location": LOCATION},
    "schema": {"fields": [{"name": "chunk_id", "type": "STRING"}, {"name": "text", "type": "STRING"},
                          {"name": "distance", "type": "FLOAT"}]},
    "rows": [{"f": [{"v": "refunds#damaged"}, {"v": "Damaged items are refundable within 30 days."}, {"v": "0.18"}]},
             {"f": [{"v": "returns#window"}, {"v": "Unopened items can be returned within 7 days."}, {"v": "0.31"}]}]}}))

RETRIEVE = """
SELECT base.chunk_id, base.text, distance
FROM VECTOR_SEARCH(
  TABLE kb.policy_chunks, 'embedding',
  (SELECT ml_generate_embedding_result AS embedding
   FROM ML.GENERATE_EMBEDDING(MODEL kb.embedder, (SELECT @question AS content))),
  top_k => 2, distance_type => 'COSINE')
ORDER BY distance"""

def search_policies(question: str) -> list[dict]:
    """An agent tool: semantic search over policy chunks stored in BigQuery."""
    config = bigquery.QueryJobConfig(query_parameters=[bigquery.ScalarQueryParameter("question", "STRING", question)])
    return [dict(row) for row in bq.query_and_wait(RETRIEVE, job_config=config)]

for hit in search_policies("my mixer arrived broken"):
    print(f"{hit['distance']:.2f}  {hit['chunk_id']:16} {hit['text']}")
What you should see
0.18  refunds#damaged  Damaged items are refundable within 30 days.
0.31  returns#window   Unopened items can be returned within 7 days.

The question goes in as a query parameter, never pasted into the SQL string, which keeps user text from becoming SQL. Lower cosine distance means closer. For hybrid search, combine this with BigQuery's full-text SEARCH function and fuse the rankings (Lesson 5.38); for low-latency serving at high query rates, AlloyDB AI or Agent Platform Vector Search are the better fit.

Industry practice
A reference architecture Google Cloud teams converge on
  • Front door: Cloud Load Balancing with Cloud Armor, Identity-Aware Proxy or your IdP, then Agent Gateway for agent and tool traffic.
  • Agents: ADK on Agent Runtime (or Cloud Run), Gemini through regional or global endpoints, Model Armor floor settings for the organization.
  • Knowledge: Agent Search or RAG Engine for documents, BigQuery and AlloyDB for structured and vector data, grounding with Google Search where public facts matter.
  • State: Sessions and Memory Bank, Firestore or AlloyDB for business state, Workflows or Cloud Tasks for long processes.
  • Ops: Agent Observability and Cloud Trace, structured Cloud Logging with sinks to BigQuery, Gen AI evals in CI, billing export with labels.
  • Security: Agent Identity and least-privilege service accounts, VPC Service Controls perimeter, CMEK, Security Command Center AI Protection.
In production
Costs that surprise BigQuery AI users

AI functions in SQL call a model once per row, so a query over a large table is a large model bill. Develop on a LIMITed sample, check the estimated cost before running on full tables, and materialize results so the same rows are not processed twice. Label every job and endpoint by team and app so the billing export can attribute the spend.
