Why this came about

In 1948 Claude Shannon, founding information theory, generated English-like text by picking each letter according to the letters before it, using frequency tables from books. His "n-gram" approximations got more English-like as the context grew. From the 1980s to the 2010s, word n-gram models counted from huge text collections powered speech recognition, machine translation and phone keyboards; Google released counts of n-grams from a trillion words in 2006. They were finally overtaken by neural language models, but the task, the evaluation (perplexity) and the sampling procedure carried straight over to GPT.

In plain words first
Guess the next letter

Play a game: I show you "to be or not to b", and you guess the next letter. You would say "e" with confidence, because you have seen that phrase before. A language model plays exactly this game, but gives a probability for every possible next character (or token). The simplest way to get those probabilities is to count: in a big pile of text, after "to b", how often did each character come next? Then, to write text, repeatedly pick a next character according to those probabilities and add it on.

Step 2 · Counting what comes next

An n-gram model looks at the previous n − 1 characters (the context) and counts what followed them in the training text. A bigram model (n = 2) uses one character of context:

def count_ngrams(n):
    """For every context of n-1 characters, count which characters followed it."""
    counts = defaultdict(Counter)
    for i in range(len(train) - n + 1):
        context, nxt = train[i:i + n - 1], train[i + n - 1]
        counts[context][nxt] += 1
    return counts

bigrams = count_ngrams(2)
for ctx in ["q", "t", "."]:
    total = sum(bigrams[ctx].values())
    top = [(ch, round(c / total, 3)) for ch, c in bigrams[ctx].most_common(4)]
    print(f"after {ctx!r} ({total:,} times): {top}")
What you should see
after 'q' (563 times): [('u', 1.0)]
after 't' (60,384 times): [('h', 0.341), (' ', 0.246), ('o', 0.088), ('e', 0.065)]
after '.' (6,960 times): [('\n', 0.842), (' ', 0.148), ("'", 0.009), ('-', 0.001)]

defaultdict(Counter) creates an empty Counter the first time a new context appears. Dividing each count by the context's total turns counts into probabilities: P(next | context). After "q" comes "u" every time; after "t" the most common next character is "h"; after a full stop, a newline. That table is the model.

Step 3 · Writing text by sampling

To generate, start from a context, pick the next character at random in proportion to its probability, append it, slide the context along, and repeat. This is exactly how GPT generates text one token at a time (Lessons 0.15 and 7.21).

def sample(counts, n, length=200, seed=0, start="ROMEO:\n"):
    rng = np.random.default_rng(seed)
    out = start
    for _ in range(length):
        context = out[-(n - 1):] if n > 1 else ""
        options = counts.get(context) or bigrams[out[-1]]   # context never seen: fall back to the bigram table
        letters = list(options.keys())
        probs = np.array(list(options.values()), dtype=float)
        out += rng.choice(letters, p=probs / probs.sum())
    return out

print(sample(bigrams, 2))

Step 4 · Measuring a language model: loss and perplexity

How good is a model? Use the cross-entropy of Lesson 1.25 on held-out text: for each character of the validation text, ask the model what probability it gave to the character that really came next, take −log of it, and average. Lower is better.

The problem: if a context-and-character pair never occurred in training, its count is 0, its probability 0, and −log 0 is infinite. Smoothing fixes that by adding a small pretend count k to every possible character, so nothing has probability exactly 0:

def val_loss(counts, n, k=0.1):
    """Average -log P(true next character) over the validation text, with add-k smoothing."""
    totals = {ctx: sum(c.values()) for ctx, c in counts.items()}
    nll, m = 0.0, 0
    for i in range(n - 1, len(val)):
        ctx, nxt = val[i - n + 1:i], val[i]
        c = counts.get(ctx)
        count = c[nxt] if c else 0
        p = (count + k) / (totals.get(ctx, 0) + k * len(chars))
        nll -= math.log(p)
        m += 1
    return nll / m

loss = val_loss(bigrams, 2)
print(f"uniform guess (1/65 each): loss {math.log(len(chars)):.3f}, perplexity {len(chars)}")
print(f"bigram model:              loss {loss:.3f}, perplexity {math.exp(loss):.2f}")
What you should see
uniform guess (1/65 each): loss 4.174, perplexity 65
bigram model:              loss 2.484, perplexity 11.99
Reading this output
  • A model that knows nothing gives each of the 65 characters probability 1/65; its loss is log(65) = 4.17.
  • The bigram model's loss is 2.48. Perplexity is e^loss: about 12 here. It has a friendly meaning: the model is, on average, as uncertain as if it were choosing uniformly among about 12 characters, instead of 65.
  • Language model papers report exactly these two numbers (often per token instead of per character). Lower perplexity on held-out text means a better model, as long as the vocabularies are the same, because perplexities from different tokenisers cannot be compared directly.

Step 5 · Longer contexts, and where counting breaks

More context should help: after "to b", "e" is far more predictable than after just "b". Try n from 1 (no context at all, just letter frequencies) up to 7 (six characters of context):

models = {}
print(" n   contexts seen   validation loss   perplexity")
for n in range(1, 8):
    models[n] = count_ngrams(n)
    loss = val_loss(models[n], n)
    print(f"{n:>2}   {len(models[n]):>13,}   {loss:>15.3f}   {math.exp(loss):>10.2f}")
What you should see

 1               1             3.347        28.43
 2              65             2.484        11.99
 3           1,380             2.046         7.74
 4          11,228             1.784         5.95
 5          48,539             1.788         5.98
 6         133,293             2.051         7.78
 7         264,623             2.443        11.51
Reading this output
  • From n = 1 to n = 4 the loss falls fast: more context, better predictions.
  • At n = 5 it stops improving (1.788 against 1.784), and from n = 6 it gets clearly worse. The model that can see more is predicting worse on new text.
  • The reason is in the middle column. With 65 characters there are 65⁶ ≈ 75 billion possible 6-character contexts, but the training text contains only 264,623 different ones. In the validation text, many contexts were never seen, or seen once or twice, so their counts are mostly noise and smoothing. This is sparsity, the overfitting of counting models: Lesson 2.26's U-curve again.
  • Real n-gram systems used clever backoff (if "o not to b" was never seen, fall back to "not to b", then "to b") and huge corpora, but the wall remains: counting cannot generalise from "to be" to "to see" because it has no notion that contexts can be similar.

Step 6 · From counts to neural networks

Counting (n-grams) Neural language models (next lessons)
a table with one row per context seen a network with a fixed number of parameters
a context never seen gets no useful prediction similar contexts get similar predictions, because they are processed into similar vectors (Lesson 5.33)
table size explodes as the context grows context can grow without the parameters exploding
trained by counting trained by gradient descent on exactly this loss

The task stays exactly the same: predict the next character or token, measured by cross-entropy on held-out text, and generate by sampling. GPT-4 and its successors are trained on this task, with transformerslater · 7.19 in place of count tables and trillions of tokens in place of a million characters.

The same idea as a formula
  • a language model gives P(x_t | x_1, …, x_{t−1}); an n-gram model approximates it with P(x_t | x_{t−n+1}, …, x_{t−1})
  • counting estimate with add-k smoothing: P(c | ctx) = (count(ctx, c) + k) / (count(ctx) + kV), for a vocabulary of V symbols
  • cross-entropy loss on N held-out symbols: L = −(1/N) Σ log P(x_t | context)
  • perplexity = e^L; a uniform model over V symbols has perplexity V
Check your mental model
  • ✗ "A language model knows facts."
    ✓ It assigns probabilities to what comes next. Facts show up only to the extent that predicting text well requires them.
  • ✗ "Lower training loss means a better language model."
    ✓ Only held-out loss counts. The 7-gram model fits its training text better than any other and generalises worse.
  • ✗ "Sampling always picks the most likely next character."
    ✓ It picks at random in proportion to the probabilities. Always taking the most likely one is greedy decodinglater · 7.21, which tends to repeat itself (Lesson 7.21).

Solutions

SolutionP1 · No context at all

Characters drawn independently according to how common each one is in Shakespeare: lots of spaces and "e", "t", "o", some capitals and line breaks, but no word shapes at all, because the model has no memory of what came before. Each character is a random draw from the same distribution.

SolutionM1 · How much to smooth

For n = 5, k of 0.1 or 0.01 does much better than 1 (validation loss about 1.77 to 1.79 versus about 2.17). Longer contexts have small counts, so a pretend count of 1 for each of 65 characters (65 in total) swamps the real evidence. With short contexts, counts are large and the pretend counts hardly matter. Choosing k is a hyperparameter decision made on validation data.

SolutionD1 · Measuring on training data

On its own training text, a 7-gram model has seen almost every context and simply recalls what followed, so its training perplexity is very low. That measures memorisation, not prediction. On the validation text it is worse than the 4-gram and 5-gram models. Always evaluate language models on text they were not trained on, the rule from Lesson 2.26, which also makes benchmark contamination a real concern for large models (Lesson 10.47).

Recap
  • A language model gives a probability to every possible next token given the previous ones; generating means sampling from those probabilities again and again.
  • An n-gram model estimates them by counting what followed each context of n − 1 symbols in training text.
  • Models are measured by cross-entropy on held-out text; perplexity, e to the loss, is the effective number of equally likely choices.
  • Smoothing avoids zero probabilities for unseen events.
  • Longer contexts help until sparsity takes over: most long contexts were never seen, so counting models stop generalising, which neural language models fix.
