In plain words first
The idea in one line

Make a useful reading path from saved links.

The problem

In plain words first

A browser's bookmark export is a tree of folders, often years deep, with the same page saved twice under slightly different addresses. This project turns that pile into a reading path you can act on. It does four things in order: flattens the tree without forgetting which folders each link lived in; decides when two links are really the same page; ranks the pages against topics you name; and writes an HTML page plus a progress file you can edit and feed back in.

The habit it teaches: never throw information away while cleaning. The original URL, the folder path and the reason two links were merged all stay in the output, so a person can check every decision.

Help a reader recover a useful collection from an exported bookmark pile. Normalize URLs conservatively, merge exact duplicates, score user-defined topics from saved titles and notes, and export an editable reading path as HTML and JSON.

You build a standalone reading-path page and bookmarks.json with retained original URLs.

Step 1 · Import bookmarks with their original hierarchy

Step 1 of 4 · about 2 hours · TypeScript

What you build. Flatten a folder tree while keeping original URLs and every ancestor folder.

Public contract.

importBookmarks(input: unknown): Bookmark[]

Input is an array of folders {title,children} or bookmarks {id,title,url,notes?}. Return {id,title,url,notes,folders:string[]}. IDs must be unique; notes default to an empty string. Validate absolute HTTP(S) URLs without credentials. Limit folder nesting to 32. Stage 1 may validate URLs directly; normalizeURL is introduced in stage 2.

Worked example. A folder Maps / Basics containing bookmark a produces folders:["Maps","Basics"]; the original https://EXAMPLE.invalid/#intro remains verbatim. An empty input returns [].

Failure cases and hints. Reject duplicate IDs, missing titles, non-string notes and unsafe protocols. Recurse with a copied ancestor array, not one shared array.

Step 2 · Normalize links and explain duplicate groups

Step 2 of 4 · about 2 hours · TypeScript

What you build. Explain exactly why two saved links point at the same document.

Public contract.

normalizeURL(value: string): string; groupDuplicates(items: Bookmark[]): Group[]

Use the WHATWG URL representation: lowercase host, remove default port and remove fragment. Retain the query and its order, path case and trailing slash. Return groups {url,items,reason} in first-seen order with copied original records.

Worked example. https://EXAMPLE.invalid:443/maps#intro and https://example.invalid/maps#scale normalize to https://example.invalid/maps. ?view=print remains a separate group. The sample imports 12 saved records into 11 document groups.

Failure cases and hints. A tracking-looking query may change a page. Do not remove query parameters or merge HTTP with HTTPS. Reject credentials.

Worked example
Which links are the same page?
  1. https://EXAMPLE.invalid:443/maps#intro: the host is lower-cased to example.invalid, the default HTTPS port :443 is dropped, and the fragment #intro is removed (it only scrolls within the page). Result: https://example.invalid/maps.
  2. https://example.invalid/maps#scale normalizes to the same string, so the two bookmarks form one group, with the reason recorded.
  3. https://example.invalid/maps?view=print keeps its query: a query can change what the server returns, so it stays a separate document.
  4. http://example.invalid/maps stays separate too: a different scheme is a different request, and the project never guesses that they match.
Check your mental model

Which statements are right?

  • ✓ Removing the fragment is safe for "same document" because the server never sees it.
  • ✗ Dropping every query parameter is a safe way to merge tracking links. Some parameters change the page (?view=print, ?page=2); removing them silently merges different documents.
  • ✓ Each group keeps the original records, so the exported page can still show the address the user saved.
  • ✗ Scoring a duplicate group once per saved copy is fair because the user saved it twice. The project scores each keyword once per group, so duplicates do not push a page up the list.

Step 3 · Rank topics and assemble a reading path

Step 3 of 4 · about 2 hours · TypeScript

What you build. Rank a reading collection with visible keyword evidence.

Public contract.

readingPath(groups: Group[], topics: Record<string,string[]>): Reading[]

Match lowercase Unicode word tokens. Each unique keyword scores 3 if any group title contains it and 1 if any notes contain it; duplicate bookmarks do not multiply scores. Sum topic scores, sort descending then by id. Return {id,title,url,originals,folders,topics,score,evidence} using the first saved record as identity. Topic keywords must be nonempty strings and are intended as single tokens.

Worked example. For topic Mapping:["map"], title Map basics adds 3; notes Read this map first adds 1. Total is 4. A duplicate save of the same title contributes zero additional points. Mapping guide does not contain token map.

Failure cases and hints. Test a keyword in notes only and a word embedded inside another word. Preserve unmatched records at score zero.

Step 4 · Export an editable collection and progress file

Step 4 of 4 · about 2 hours · TypeScript

What you build. Carry reading order and completion between a browser review and the next command.

Public contract.

applyProgress(items: Reading[], value?: unknown): {items: Reading[]; progress: Progress}; renderCollection(items: Reading[], progress: Progress): string

Progress is {schemaVersion:1,order:string[],completed:string[]}. Order is a full permutation of current IDs; completed contains unique known IDs. The browser provides Move up/down, Read checkboxes and a JSON download. All visible text is escaped or assigned with textContent.

Worked example. If current IDs are ["a","b"], review {schemaVersion:1,order:["b","a"],completed:["a"]} renders b before a and checks a as read. ["a","a"] is not a permutation and must fail.

Failure cases and hints. Reject stale progress rather than silently dropping unknown IDs. Escape closing-script text in embedded JSON.

async function main() {
  const [input, output = "output", reviewFile] = process.argv.slice(2);
  if (!input || input === "--help") {
    console.log("node cli.ts INPUT.json [OUTPUT_DIRECTORY] [REVIEW.json]");
    return input ? 0 : 2;
  }
  const data = JSON.parse(await readFile(input, "utf8"));
  const review = reviewFile
    ? JSON.parse(await readFile(reviewFile, "utf8"))
    : undefined;
  await mkdir(output, { recursive: true });
  const save = async (name: string, value: any) =>
    writeFile(
      path.join(output, name),
      typeof value === "string" ? value : JSON.stringify(value, null, 2) + "\n",
    );

    groups = groupDuplicates(imported),
    ranked = readingPath(groups, data.topics);

    schemaVersion: 1,
    imported,
    groups,
    items: result.items,

    JSON.stringify(
      {
        imported: imported.length,
        documents: groups.length,
        duplicates: groups

          .map((x) => x.items.map((y) => y.id)),
        order: result.progress.order,
        output,
      },
      null,
      2,
    ),
  );
  return 0;

export type Bookmark = {
  id: string;
  title: string;
  url: string;
  notes: string;
  folders: string[];
};
export type Group = { url: string; items: Bookmark[]; reason: string };
export type Reading = {
  id: string;
  title: string;
  url: string;
  originals: string[];
  folders: string[][];
  topics: string[];
  score: number;
  evidence: string[];
};
export type Progress = {
  schemaVersion: 1;
  order: string[];
  completed: string[];
};

export function importBookmarks(input: unknown): Bookmark[] {
  const result: Bookmark[] = [];
  const ids = new Set<string>();
  function walk(nodes: unknown, folders: string[], depth: number) {
    if (depth > 32) throw new Error("Folder nesting exceeds 32");
    for (const node of array(nodes, "bookmarks")) {
      if (!node || typeof node !== "object")
        throw new Error("Bookmark must be an object");
      if ("children" in node) {
        walk(
          node.children,
          [...folders, nonempty(node.title, "folder title")],
          depth + 1,
        );
        continue;
      }
      const id = nonempty(node.id, "id"),
        title = nonempty(node.title, "title"),
        url = nonempty(node.url, "url");
      normalizeURL(url);
      if (ids.has(id)) throw new Error("Duplicate id " + id);
      ids.add(id);
      if (node.notes !== undefined && typeof node.notes !== "string")
        throw new Error("notes must be text");
      result.push({
        id,
        title,
        url,
        notes: node.notes ?? "",
        folders: [...folders],
      });
    }
  }
  walk(input, [], 0);
  return result;
}
export function normalizeURL(value: string): string {
  const u = new URL(nonempty(value, "url"));
  if (!["http:", "https:"].includes(u.protocol) || u.username || u.password)
    throw new Error("Only HTTP(S) URLs without credentials are supported");
  u.hash = "";
  return u.href;
}
export function groupDuplicates(items: Bookmark[]): Group[] {
  const groups = new Map<string, Bookmark[]>();
  for (const item of items) {
    const key = normalizeURL(item.url);
    groups.set(key, [...(groups.get(key) ?? []), structuredClone(item)]);
  }
  return [...groups].map(([url, items]) => ({
    url,
    items,
    reason:
      items.length > 1
        ? "Same WHATWG URL after removing the fragment; query parameters remain significant."
        : "Unique normalized document URL.",
  }));
}
export function readingPath(
  groups: Group[],
  topics: Record<string, string[]>,
): Reading[] {
  const entries = Object.entries(topics);
  for (const [name, words] of entries) {
    nonempty(name, "topic");
    if (
      !Array.isArray(words) ||
      !words.length ||
      words.some((w) => typeof w !== "string" || !w.trim())
    )
      throw new Error("Each topic needs nonempty keywords");
  }
  const tokens = (s: string) =>
    new Set(s.toLowerCase().match(/[\p{L}\p{N}]+/gu) ?? []);
  return groups
    .map((group) => {
      let score = 0;
      const matched: string[] = [],
        evidence: string[] = [];
      for (const [topic, words] of entries) {
        let local = 0;
        for (const word of [...new Set(words.map((w) => w.toLowerCase()))]) {
          const title = group.items.some((x) => tokens(x.title).has(word)),
            notes = group.items.some((x) => tokens(x.notes).has(word));
          local += (title ? 3 : 0) + (notes ? 1 : 0);
          if (title || notes)
            evidence.push(
              `${topic}: ${word} = ${title ? 3 : 0} title + ${notes ? 1 : 0} notes`,
            );
        }
        if (local) matched.push(topic);
        score += local;
      }
      return {
        id: group.items[0].id,
        title: group.items[0].title,
        url: group.url,
        originals: group.items.map((x) => x.url),
        folders: group.items.map((x) => x.folders),
        topics: matched,
        score,
        evidence,
      };
    })
    .sort((a, b) => b.score - a.score || a.id.localeCompare(b.id));
}
export function applyProgress(
  items: Reading[],
  value?: unknown,
): { items: Reading[]; progress: Progress } {
  const ids = items.map((x) => x.id);
  let order = ids,
    completed: string[] = [];
  if (value !== undefined) {
    const p = value as Progress;
    if (
      !p ||
      p.schemaVersion !== 1 ||
      !Array.isArray(p.order) ||
      p.order.length !== ids.length ||
      new Set(p.order).size !== ids.length ||
      p.order.some((x) => !ids.includes(x))
    )
      throw new Error(
        "Progress order must contain every current id exactly once",
      );
    if (
      !Array.isArray(p.completed) ||
      new Set(p.completed).size !== p.completed.length ||
      p.completed.some((x) => !ids.includes(x))
    )
      throw new Error("Unknown or duplicate completed id");
    order = p.order;
    completed = p.completed;
  }
  return {
    items: order.map((id) => structuredClone(items.find((x) => x.id === id)!)),
    progress: {
      schemaVersion: 1,
      order: [...order],
      completed: [...completed],
    },
  };
}

export function escapeHTML(value: unknown): string {
  return String(value).replace(
    /[&<>"']/g,
    (c) =>
      ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" })[
        c
      ]!,
  );
}
export function embedded(value: unknown): string {
  return JSON.stringify(value)
    .replace(/</g, "\\u003c")
    .replace(/\u2028/g, "\\u2028")
    .replace(/\u2029/g, "\\u2029");

Where the project stops

The importer consumes the documented JSON folder tree, not arbitrary browser HTML. URL equality is document-oriented because fragments are removed; query strings remain significant. Ranking uses lexical tokens, not a remote model. Links are never fetched.

Break it on purpose

A first version merges https://shop.invalid/item?id=7 and https://shop.invalid/item?id=9 into one group, and the reading path silently loses a page. Which normalization step went too far? (Solution B1.)

Recap
What to keep from this project
  • Flatten trees but keep every ancestor folder and the original URL.
  • Normalize conservatively: lower-case the host, drop default ports and fragments, keep the query.
  • Record why links were merged, so a person can audit the grouping.
  • Score each keyword once per group, and break ties by id for a stable order.
  • Round-trip state through a small, validated progress file.

Build it on your machine

Each step above is meant to be built, not only read. The source repository ships a starter and the checks for every step, and its test runner grades your own folder step by step:

git clone https://github.com/rohitg00/ai-engineering-from-scratch
cd ai-engineering-from-scratch
python3 scripts/project_test.py bookmark-path-organizer --init my-bookmark-path-organizer
python3 scripts/project_test.py bookmark-path-organizer --stage 1 --path my-bookmark-path-organizer

Write the step, run its checks, then move to the next step. The checks for each step are also shown above, under that step, so you can see what is expected before you start.

Exercises

  1. Add an import adapter for one browser export format while keeping this typed boundary. (step 1)
  2. Add an explicit user-approved tracking-parameter policy with its own receipt. (step 2)
  3. Support user-specified prerequisite edges before ranking independent topics. (step 3)
  4. Merge progress across revised collections with an explicit conflict report. (step 4)

Solutions

Solution
  1. A browser import adapter

Read the browser's own export (for example the Netscape bookmark HTML format) in a separate function that produces exactly the same folder tree the importer already accepts. Validation, URL checks and folder limits stay in one place, and the adapter can be tested on its own fixture.

Solution
  1. A tracking-parameter policy

Let the user list parameter names to drop (for example utm_source). Apply the list during normalization, and add a receipt to each group: "merged because utm_source was removed by your rule". Without the explicit list, keep today's behaviour.

Solution
  1. Prerequisite edges

Treat "read A before B" as a directed graph, check it has no cycles, then sort topologically. Among pages that are ready at the same time, keep the current score order. A cycle is an error that names the pages involved.

Solution
  1. Merging progress after the collection changes

Match old progress to new items by id. Ids that vanished go into a "removed" list, new ids are appended unread, and a completed item whose URL changed is reported as a conflict for the user to decide, never resolved silently.

SolutionB1 · Two products merged

The normalizer removed the query string. Queries can select different content, so they must stay part of the document identity; only the fragment, the default port and the host's case are safe to normalize.
