Platforms

IntermediateHow would you build a governed agent on AWS?

Strands or LangGraph hosted on AgentCore Runtime; models through Bedrock with a geographic inference profile and an enforced guardrail; tools through AgentCore Gateway with Policy rules and Identity-managed credentials; knowledge in Bedrock Knowledge Bases on S3 Vectors or OpenSearch; memory in AgentCore Memory; observability through ADOT into CloudWatch; online evaluations with AgentCore Evaluations; PrivateLink, least-privilege IAM and cost tags through application inference profiles.

IntermediateHow would you build an agent over warehouse data in Snowflake?

Define a semantic view (metrics, dimensions, synonyms, verified queries) for Cortex Analyst, a Cortex Search service over documents, and a Cortex Agent that orchestrates both plus procedures for actions, with orchestration budgets. Users reach it through CoWork or the Agent Run API; outside agents through the managed MCP server. Governance comes from roles, masking and row access policies, AI guardrails and model allowlists; quality from the agent's evaluations and AI Observability; cost from the account usage views and budgets.

AdvancedA client runs Microsoft 365, keeps data in Snowflake and serves customers on AWS. Design their agent landscape.

Put each agent where its data and users are. Data agents live in Snowflake (Cortex Agents over semantic views), exposed through the managed MCP server. The customer agent runs on AWS AgentCore and calls the Snowflake tools through the Gateway. Employees reach data agents in CoWork or through Copilot. One gateway policy governs model traffic, OpenTelemetry traces flow to one observability backend, identities are federated (Entra to AWS and Snowflake), and each agent has its own least-privileged role.

IntermediateHow would you build a governed agent on Azure?

A Foundry agent (prompt agent for simple cases, hosted agent built with Microsoft Agent Framework or LangGraph for code-heavy ones) using models deployed in Foundry; knowledge through Foundry IQ knowledge bases over Azure AI Search; tools through MCP and OpenAPI with Entra-managed identities (Entra Agent ID); Content Safety with Prompt Shields on inputs and documents; Azure API Management as the AI gateway for token limits and routing; Application Insights for OpenTelemetry traces and Foundry evaluations for quality; private networking and Purview for data governance.

IntermediateHow would you build a governed agent on Google Cloud?

ADK agents deployed to Agent Runtime (formerly Vertex AI Agent Engine) with Sessions and Memory Bank; Gemini models through Vertex AI; grounding with Agent Search or Google Search grounding; tools through MCP and Agent Gateway; Model Armor screening prompts and responses; Cloud Trace and Cloud Logging for telemetry; the Gen AI evaluation service for quality; VPC Service Controls around data; BigQuery for analytics over interaction logs.

IntermediateHow would you build an agent on Databricks?

Author it as an MLflow ResponsesAgent (with LangGraph, the OpenAI Agents SDK or plain Python inside), tools as Unity Catalog functions and managed MCP servers, retrieval through AI Search (formerly Vector Search), structured questions through a Genie space, models through the AI Gateway with usage tracking. Evaluate with mlflow.genai.evaluate and scorers, deploy with agents.deploy to Model Serving, and monitor with MLflow tracing and production scorers. Unity Catalog governs data, models, functions and lineage end to end. Agent Bricks offers higher-level, auto-optimized agents for common patterns.

AdvancedManaged agent runtime or your own containers?

Managed runtimes (AgentCore Runtime, Foundry Agent Service, Agent Runtime, Databricks Model Serving) give session isolation, identity, memory, observability and scaling out of the box, which shortens time to production and passes security review faster. Containers give full control over frameworks, networking, cost and portability. Choose managed when the platform matches where the data and users already are and its limits (session length, regions, supported frameworks) fit; choose containers for multi-cloud portability, unusual runtimes or very high steady volume. Either way, keep the agent code framework-thin so the choice can change.

AdvancedHow do you decide between Cortex Agents and building an agent with LangGraph on top of Snowflake?

Cortex Agents win when the work is mostly questions over governed Snowflake data and documents: Cortex Analyst and Search are built in, roles and policies apply automatically, data never leaves, and business users get it through CoWork or the API. LangGraph wins when you need custom control flow, long-running stateful workflows, many non-Snowflake tools, or a specific model outside Snowflake's catalog. A common hybrid: Cortex Agents as governed data tools (through the managed MCP server or the Agent Run API) inside a LangGraph orchestrator that handles the broader workflow.
