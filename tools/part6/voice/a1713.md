@@top The problem
:::plain In plain words first
**Observability** means being able to see what your system did and why. For an LLM feature that means recording, for every call, the prompt, the answer, the tokens, the latency, the cost and the model, and linking calls that belong to one user action into a **trace**. Tools split into two kinds. **Development platforms** (LangSmith, Langfuse, Opik) add evaluations, prompt versions and datasets, so you can test a new prompt against old cases. **Telemetry and gateway tools** (Helicone, Phoenix, SigNoz) focus on recording calls and dashboards. **OpenTelemetry** is the open standard for sending this data, and its **GenAI conventions** name the fields (`gen_ai.request.model`, `gen_ai.usage.input_tokens` and so on), so one instrumentation can feed several tools. Because traces are big, production systems keep only a **sample**, chosen so that errors and expensive calls are never thrown away.
:::
@@

@@end Idea 12 · Numbers you should remember
:::worked What a sampling policy keeps
A service handles 1,000,000 traces a day. 3% are errors and 1% are unusually expensive (over $0.10).

1. Keep everything: 1,000,000 traces.
2. Random 10%: 100,000 traces, but only about 3,000 of the 30,000 errors. Most failures you will need to debug are gone.
3. "5% of successes + all errors": 0.05 × 970,000 + 30,000 ≈ 78,500 traces, every error kept.
4. Add "all expensive calls": about 10,000 more, so about 88,000 traces, under 9% of the volume, with every error and every cost outlier.

Sample by *what you will ask later*, not uniformly.
:::

:::check
Which statements are right?

- ✓ Instrumenting at the SDK or HTTP layer keeps you portable between frameworks.
- ✗ Random sampling is fine because errors are rare.
  Rare is exactly why random sampling loses them; keep 100% of errors.
- ✓ OpenTelemetry's GenAI conventions let several tools read the same traces.
- ✗ LangSmith is the best choice for every stack.
  It is strongest on LangChain and LangGraph; elsewhere, other tools fit better.
:::

:::predict
Before running the code below: with errors at 3% of traffic, roughly what share of errors does a 10% random sample keep?
:::

:::visual Random sampling against a rule-based sample
```python run
import random
random.seed(5)
traces = [{"error": random.random() < 0.03, "cost": random.expovariate(1 / 0.02)} for _ in range(200_000)]
errors = sum(t["error"] for t in traces)

def keep_random(t):  return random.random() < 0.10
def keep_rules(t):   return t["error"] or t["cost"] > 0.10 or random.random() < 0.05

for name, rule in (("random 10%", keep_random), ("5% + errors + expensive", keep_rules)):
    kept = [t for t in traces if rule(t)]
    print(f"{name:24s} kept {len(kept) / len(traces):5.1%} of traces, {sum(t['error'] for t in kept) / errors:5.1%} of errors")
```
:::

:::read
Both policies keep roughly the same volume, under 10%, but random sampling keeps only about a tenth of the errors while the rule-based policy keeps all of them. The cost of the rule is a little more storage; the benefit is that every incident has its traces.
:::

@@before Ship it
:::broken
A team adds LangSmith tracing deep inside its LangGraph nodes. Six months later it moves half its agents to the OpenAI Agents SDK and loses all visibility into them. What should they have done from the start? (Solution B1.)

:::recap What to keep from this lesson
- Development platforms add evals and prompt management; telemetry tools record calls.
- Emit OpenTelemetry with GenAI conventions; send it to a gateway, an eval platform and an archive.
- Instrument at the SDK or HTTP layer, not inside one framework.
- Sample: all errors, all expensive calls, a few per cent of the rest.
- Pick by stack, licence, budget and whether you must self-host.

## Solutions

??? sol | P1 · Sampling cost in `code/main.py`
At 1M traces a day, keeping everything costs about $67.50 a day on a Datadog-class backend; "5% of successes + all errors + high-cost" costs about $5.30 and keeps the signal you debug with. On a data-lake pattern (Arize AX reading your own Parquet) even full retention costs well under a dollar a day, which is why large teams store everything there and sample only the expensive backend.
???

??? sol | B1 · Framework-coupled tracing
Instrument at the model-call layer, through OpenTelemetry with the GenAI conventions (OpenLLMetry or the gateway), so every framework's calls produce the same spans. Framework-specific traces can be added on top for detail, but the baseline must not depend on one framework.
