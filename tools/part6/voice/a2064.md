@@top The problem
:::plain In plain words first
Teams keep screenshots, photos of signs and diagrams, and later want to search them: "which sign says to return dry seeds?". A search that answers "image 7" is hard to trust. One that answers "image 7, this rectangle, which reads…" can be checked at a glance.

This project builds a visual evidence library around that idea. Each image has text regions with coordinates. Search ranks regions by how much of the query they cover and keeps the rectangle with every result. An optional vision model can propose text and labels, but proposals are kept separate from reviewed labels until a person accepts them. The export is an HTML gallery with the matching rectangle drawn on each image.
:::
@@

@@end Step 2 · Rank matches and preserve the rectangle
:::visual Query coverage per region
```python run
import re
words = lambda s: set(re.findall(r"\w+", s.lower()))
regions = [("seed-sign", "return", [45, 130, 510, 45], "Return dry seeds in paper envelopes."),
           ("tool-sign", "shelf", [45, 130, 455, 45], "Return tools to the blue shelf.")]
q = words("return dry seeds")
for img, rid, box, text in sorted(regions, key=lambda r: -len(q & words(r[3]))):
    cov = len(q & words(text)) / len(q)
    print(f"{img}/{rid}: {cov:.0%} coverage | box x,y,w,h = {box} | {text}")
```
:::

:::read
"Return dry seeds in paper envelopes." contains all three query words: 100 % coverage. The tool sign contains only "return": 33 %. Both results keep their rectangle (x, y, width, height), so the gallery can draw exactly where the text is. Coverage is a transparent score: you can see why each result ranked where it did, which a learned similarity score would not show.
:::

@@end Step 3 · Keep extraction proposals separate from labels
:::check
Which statements are right?

- ✓ Every region's rectangle is validated to lie inside its image.
- ✗ Text proposed by a vision model can be indexed directly.
  Proposals wait for review; only accepted labels are indexed.
- ✓ Recognized text and an image category ("sign", "diagram") are separate claims.
- ✗ A search result without a rectangle is still good evidence.
  The rectangle is what lets a person verify it quickly.
:::

@@end Exercises
1. Why index each region separately rather than all text of an image?
2. How would you review a vision model's proposals efficiently?
3. What should the gallery show when a region's rectangle is invalid?

## Solutions

??? sol | 1. Regions, not images
A query should point at the place in the image that answers it. Merging an image's text would match words from different signs in one photo and lose the rectangle.
???

??? sol | 2. Reviewing proposals
Show each proposed text with its rectangle drawn on the image and the model's name, and let the reviewer accept, edit or reject it in one click. Track the acceptance rate per model to see how far it can be trusted.
???

??? sol | 3. An invalid rectangle
Reject it at validation with the image id and reason, so it never reaches the index. A gallery that draws a box outside the image would mislead.
???

??? sol | B1 · Unreviewed OCR
Keeping model or OCR proposals separate until a person reviews them, with the rectangle shown, so "seats" is visibly wrong next to the photo and gets corrected before indexing.
???
