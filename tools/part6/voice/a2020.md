@@top The problem
:::plain In plain words first
Bad records get into training data in small ways: a negative token count, a split called "tset", the same id twice. Each one is easy to spot alone and easy to miss in a million rows. A data contract makes the rules explicit, and a gate enforces them before the data moves on.

This project builds that gate. It validates the contract itself, checks each record against it without quietly converting types, finds every row of a duplicate group (not just the second one), and splits the input into accepted and quarantined files, with a receipt saying why each rejected row was rejected.
:::
@@

@@end Step 2 · Check each record without coercion
:::visual Checking records against a contract
```python run
contract = {"id": {"type": str}, "tokens": {"type": int, "min": 0, "max": 8192},
            "split": {"type": str, "enum": ["train", "test"]}}
def issues(row):
    out = []
    for f, rule in contract.items():
        if f not in row: out.append((f, "required")); continue
        v = row[f]
        if not isinstance(v, rule["type"]) or isinstance(v, bool): out.append((f, "type")); continue
        if "min" in rule and v < rule["min"]: out.append((f, "min"))
        if "max" in rule and v > rule["max"]: out.append((f, "max"))
        if "enum" in rule and v not in rule["enum"]: out.append((f, "enum"))
    out += [(f, "extra") for f in row if f not in contract]
    return out
for row in [{"id": "a", "tokens": 31, "split": "train"}, {"id": "b", "tokens": -2, "split": "test"},
            {"id": "c", "tokens": "42", "split": "tset"}, {"id": "d", "tokens": True, "split": "test", "note": 1}]:
    print(row, "->", issues(row) or "ok")
```
:::

:::read
Row b breaks the minimum. Row c has two problems: `"42"` is a string, and the gate does not convert it to a number (coercion hides upstream bugs), and "tset" is not an allowed split. Row d shows Python's trap: `True` is an `int` subclass, so booleans are rejected explicitly, and the unknown field `note` is flagged as extra.
:::

@@end Step 3 · Find all rows in a duplicate group
:::check
Which statements are right?

- ✓ Every row of a duplicate group is quarantined, including the first one.
- ✗ Keeping the first duplicate and dropping the rest is the safe default.
  The gate cannot know which copy is right; it quarantines all and lets a person decide.
- ✓ A dataset with one quarantined row fails the gate.
- ✗ Converting `"42"` to 42 is harmless.
  It hides a producer that writes the wrong type; the gate reports it instead.
:::

@@before Build it on your machine
:::broken
A pipeline deduplicates by keeping the first occurrence of each id. `sample-c` in test survives and `sample-c` in train is dropped, so the same sample is now only in test, but its twin was used to tune a model last week. What would the gate have told you? (Solution B1.)
:::

:::recap What to keep from this project
- Validate the contract before the data.
- Check types exactly; never coerce.
- Report every member of a duplicate group.
- Quarantine with reasons; pass only when nothing is quarantined.
- Use exit codes so the gate can stop a pipeline.
:::

@@end Exercises
1. Why does the gate need a minimum row count?
2. A producer starts sending `tokens` as `31.0`. Should the contract accept it as an integer?
3. How would you let a team fix quarantined rows and resubmit them?

## Solutions

??? sol | 1. A minimum row count
An empty file has no invalid rows, so without `min_rows` it would pass. The rule turns "nothing arrived" into a dataset issue instead of a silent success.
???

??? sol | 2. 31.0 for an integer
No. JSON `31.0` is a number with a fraction part written out; accepting it as an integer is coercion. Either fix the producer or change the contract to `number` deliberately, with a version bump.
???

??? sol | 3. Fix and resubmit
Give each quarantined row its row number and issues (the gate already does), let the team edit `quarantine.jsonl`, and run the gate again on accepted plus corrected rows together, so duplicates across the two are still caught.
???

??? sol | B1 · Keep-first deduplication
That `sample-c` appears in both train and test (rows 3 and 4), with both rows quarantined. Keep-first hides exactly that cross-split duplicate, which is a leak.
???
