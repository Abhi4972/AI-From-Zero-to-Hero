@@top The situation
:::plain In plain words first
An agent printed its environment into a shared log, including something that looks like a key, and a reviewer files a ticket to rotate it. The value is a placeholder: the real secret never enters the sandbox; a proxy swaps it into requests to two approved hosts only. The case trains checking where a secret actually exists before treating a value as leaked.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A secret proxy keeps the real credential outside the sandbox.
- ✗ Any key-shaped value in a log is a leaked credential.
  Here it was a placeholder; the real value exists only in requests the proxy rewrites.
- ✓ Requests to unapproved hosts carry the placeholder or are blocked.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Find where the real secret lives before declaring a leak.
- Placeholders let agents work without holding credentials.
- Still avoid printing environments into shared logs.
- Check the receiving side to see where the real value appears.
:::
@@
