@@top The situation
:::plain In plain words first
A capacity report said one card could serve 16 requests per second because every run completed. A fixed-rate run always completes: the client stops sending and the server drains the queue. The first-token times showed the queue growing to 94 seconds. The case trains telling completion from steady state.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A growing first-token time across a run means the queue is growing.
- ✗ No failed requests means the card kept up.
  It finished by draining after arrivals stopped.
- ✓ Capacity is the rate at which latency stays flat over time.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Completion is not capacity.
- Look for steady latency over the run.
- Run long enough to see a trend.
- Size fleets on steady-state rates.
:::
@@
