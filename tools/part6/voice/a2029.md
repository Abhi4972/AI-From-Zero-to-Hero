@@top The problem
:::plain In plain words first
"The local model got 67 percent" is not an evaluation. Which model revision, which prompt, which hardware? Did it answer every question? When it was confident, was it right? How long did it take? This project builds a scorecard that answers those questions from recorded predictions, so the numbers can be reproduced and compared.

It validates each prediction record, measures exact-answer accuracy together with coverage, measures calibration (whether confidence matches correctness), and publishes accuracy beside latency percentiles, with a manifest of exactly what was measured.
:::
@@

@@end Step 3 · Measure confidence calibration
:::visual Expected calibration error by hand
```python run
preds = [("a", "yes", 0.8, "yes"), ("b", "yes", 0.9, "no"), ("c", "no", 0.6, "no")]   # id, answer, confidence, label
bins = {}
for _, ans, conf, label in preds:
    b = min(int(conf * 5), 4)                       # five bins of width 0.2
    bins.setdefault(b, []).append((conf, ans == label))
ece = 0
for b, items in sorted(bins.items()):
    c = sum(x for x, _ in items) / len(items); acc = sum(ok for _, ok in items) / len(items)
    print(f"bin {b}: n={len(items)} confidence {c:.2f} accuracy {acc:.2f} gap {abs(c - acc):.2f}")
    ece += len(items) / len(preds) * abs(c - acc)
print("ECE", round(ece, 4))
```
:::

:::read
Bin 3 (confidence 0.6 to 0.8) holds one prediction at 0.6 that was right: the model was under-confident by 0.4. Bin 4 holds two at 0.8 and 0.9 with one right: average confidence 0.85, accuracy 0.5, a gap of 0.35. Weighting each gap by its bin's size gives ECE = (1 × 0.4 + 2 × 0.35) / 3 ≈ 0.367. With three predictions, this number is a teaching example, not a measurement; ECE needs many predictions per bin to mean much.
:::

@@end Step 4 · Publish accuracy and latency together
:::check
Which statements are right?

- ✓ A missing prediction for a labelled item lowers coverage and must be visible.
- ✗ Removing punctuation before comparing answers is a harmless normalization.
  It can turn a wrong answer into a match; only case and whitespace are normalized.
- ✓ Nearest-rank percentiles give the same p95 every time on the same small sample.
- ✗ A NaN confidence can be ignored during calibration.
  The validator rejects it; NaN silently breaks comparisons.
:::

@@end Exercises
1. Why keep per-bin evidence instead of just the ECE number?
2. Two runs of the same model give 0.67 and 0.70 accuracy on 30 questions. Is that a difference?
3. How would you compare two models fairly on latency?

## Solutions

??? sol | 1. Per-bin evidence
One number hides where the problem is. A model can be well calibrated at low confidence and badly over-confident at 0.9, which is exactly where an automated router trusts it most. The bins show that.
???

??? sol | 2. A 3-point difference on 30 questions
Almost certainly not: one question is 3.3 points. Report counts (20/30 against 21/30) and treat differences of a few questions as noise unless you have many more items or repeated runs.
???

??? sol | 3. Fair latency comparison
Same hardware, same load, same prompts, warm-up excluded, and the same percentile definition. Report p50 and p95 for both, with the number of measured requests.
???

??? sol | B1 · Accuracy without coverage
Accuracy over all labelled items (0.91 × 0.85 ≈ 77 percent if unanswered count as wrong) and coverage 0.85 beside it. Scoring only answered items rewards a model for skipping hard questions.
???
