@@top The situation
:::plain In plain words first
An agent in a sandbox reports that "the network is down" and asks for a repair. The fetch was answered within a second: a policy proxy denied the request by default, because the host was not on the sandbox's allow list, and replied with a 403 and an explanation. The case trains distinguishing a refused request from a broken network, and reading a tool's message instead of the agent's summary of it.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A fast, explicit refusal is not an outage.
- ✗ If the agent says the network is down, the network is down.
  Agents summarize failures badly; the proxy's 403 said why the request was blocked.
- ✓ A sandbox-scoped allow rule turned the same request into a 200.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- A quick refusal and a timeout are different failures.
- Read the tool's own message, not the agent's summary.
- Default-deny is policy; allow hosts deliberately.
- Scope allow rules to the sandbox that needs them.
:::
@@
