@@top The problem
:::plain In plain words first
A RAG system can fail in two places, and they need different measurements. **Retrieval metrics** ask whether the right chunks came back and how high: **precision@k** (what share of the top k is relevant), **recall@k** (what share of the relevant chunks is in the top k), **MRR** (how high the first relevant chunk is, as 1/rank), and **nDCG@k** (a graded score that rewards relevant chunks near the top). **Answer metrics** ask whether the answer is supported by the retrieved text (**faithfulness**) and whether it addresses the question (**answer relevance**). Labelled **qrels** (which chunks are relevant to each query) make the retrieval metrics possible. Reading the two groups together tells you whether to fix the retriever or the generator.
:::
@@

@@end Idea 6 · Answer relevance
:::math nDCG@k
$$\text{DCG@}k=\sum_{i=1}^{k}\frac{\text{rel}_i}{\log_2(i+1)},\qquad \text{nDCG@}k=\frac{\text{DCG@}k}{\text{IDCG@}k}$$

$\text{rel}_i$ is the relevance of the result at rank $i$; IDCG is the DCG of the best possible ordering, so nDCG runs from 0 to 1.
:::

:::worked Diagnosing from the metrics
Two failing systems.

1. System A: recall@5 = 0.95, faithfulness = 0.55. The right chunks arrive, but the answers contain claims not in them: fix the generator (prompting, citations, a faithfulness check), not the retriever.
2. System B: recall@5 = 0.40, faithfulness = 0.95. Answers stick to what was retrieved, but what was retrieved is often wrong: fix retrieval (chunking, hybrid search, query rewriting).
3. System C: recall@5 high, precision@1 low, MRR low: the right chunk is usually present but not at the top; add or tune a re-ranker.
4. One combined score would hide all three diagnoses.
:::

:::check
Which statements are right?

- ✓ MRR uses only the rank of the first relevant result.
- ✗ High faithfulness means the answer is correct.
  It means the answer is supported by the retrieved text, which itself may be wrong.
- ✓ nDCG rewards relevant results more when they rank higher.
- ✓ With only one relevant chunk, precision@5 cannot exceed 0.2.
:::

:::predict
Before running the code below: a query has two relevant chunks, returned at ranks 1 and 4 out of 5. What are precision@5, recall@5, MRR and nDCG@5 (binary relevance)?
:::

:::visual Four retrieval metrics on one ranking
```python run
import math
ranking = ["a", "x", "y", "b", "z"]; relevant = {"a", "b"}
def precision(k): return sum(d in relevant for d in ranking[:k]) / k
def recall(k): return sum(d in relevant for d in ranking[:k]) / len(relevant)
mrr = next((1 / i for i, d in enumerate(ranking, 1) if d in relevant), 0)
dcg = sum((d in relevant) / math.log2(i + 1) for i, d in enumerate(ranking[:5], 1))
idcg = sum(1 / math.log2(i + 1) for i in range(1, len(relevant) + 1))
print(f"precision@5 {precision(5):.2f}  recall@5 {recall(5):.2f}  MRR {mrr:.2f}  nDCG@5 {dcg / idcg:.3f}")
print(f"precision@1 {precision(1):.2f}  recall@1 {recall(1):.2f}")
```
:::

:::read
Precision@5 is 0.40 (two of five relevant), recall@5 is 1.00 (both found), MRR is 1.00 (the first hit is at rank 1), and nDCG@5 is about 0.88: perfect would need the second relevant chunk at rank 2, not 4. Each number answers a different question about the same list, which is why the lesson reports all of them.
:::

@@takeaways
The problem | Retrieval and generation fail differently.
The idea | Measure both, read them together.
Idea 1 · Precision@k | Share of top k that is relevant.
Idea 2 · Recall@k | Share of relevant found in top k.
Idea 3 · MRR (Mean Reciprocal Rank) | How high the first hit is.
Idea 4 · nDCG@k | Graded, rank-discounted relevance.
Idea 5 · Faithfulness | Supported by retrieved text.
Idea 6 · Answer relevance | Addresses the question.
The fixture qrels | Labels for which chunks are relevant.
Build it | All six metrics in one evaluator.
Reading the metrics to diagnose failures | Fix the part that failed.
Failure modes the demo will hide | Small fixtures, binary labels.
