@@top The situation
:::plain In plain words first
Switching the KV cache to FP8 started fine after a backend flag, ran slightly faster and passed an accuracy check. The question nobody asked: where did the scaling factors for FP8 come from? For this model they defaulted to 1.0, which happened to be harmless; for the production model it may not be. The case trains asking what a precision change silently assumes, and checking it before rollout.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ FP8 caches need scaling factors; without them the default may be 1.0.
- ✗ Passing an accuracy check on one model proves the setting is safe for another.
  The production model needed its own proof: scale tensors present and no 1.0 warning.
- ✓ A startup warning about a default scale is evidence worth reading.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Ask what a precision change assumes.
- Check that calibration scales exist in the checkpoint.
- Read startup warnings, not just whether it started.
- Validate accuracy on the model you will ship.
:::
@@
