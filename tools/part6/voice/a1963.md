@@top The problem
:::plain In plain words first
A vision-language model needs measurements as much as training. This lesson builds three from scratch. **Retrieval**: given an image, is its caption among the top K of all captions by similarity (**Recall@K**), and the reverse for text to image. **Visual question answering**: does the model's answer exactly match the reference (**exact match**). **Captioning**: how many 1- to 4-word sequences of the generated caption appear in the reference (**BLEU-4**). Each has a **chance level**, and a result only means something compared with it: with 50 candidates, guessing gets Recall@10 right 20% of the time. The lesson measures before and after a short training run.
:::

@@end Idea 4 · Synthetic eval suite
:::worked Recall@K from a similarity matrix
Four images and four captions. Each image's row of similarities, with its own caption marked:

1. Image 1: [**0.9**, 0.3, 0.2, 0.1]: own caption ranks 1st, a hit at K = 1.
2. Image 2: [0.6, **0.5**, 0.7, 0.1]: own caption ranks 3rd, a miss at K = 1 and K = 2, a hit at K = 3.
3. Images 3 and 4 rank their captions 1st and 2nd.
4. Recall@1 = 2/4 = 0.5; Recall@3 = 4/4 = 1.0. With N candidates, random ranking gives Recall@K = K / N, the baseline every result is compared against.
:::

:::check
Which statements are right?

- ✓ Recall@K counts how often the correct item ranks in the top K.
- ✗ A Recall@10 of 0.26 over 50 candidates shows strong retrieval.
  Chance is 10 / 50 = 0.20; 0.26 is barely above it.
- ✓ BLEU-4 combines matches of 1- to 4-word sequences with a brevity penalty.
- ✗ Image-to-text and text-to-image recall are always equal.
  The same matrix is ranked by rows in one case and columns in the other.
:::

:::predict
Before running the code below: for 50 candidates, what Recall@1, @5 and @10 does random ranking give, and which of the lesson's after-training numbers are clearly above them?
:::

:::visual Results against chance
```python run
N = 50
after = {"R@1_i2t": 0.00, "R@1_t2i": 0.06, "R@5_i2t": 0.18, "R@5_t2i": 0.20, "R@10_i2t": 0.26, "R@10_t2i": 0.38}
import math
for name, value in after.items():
    k = int(name.split("@")[1].split("_")[0])
    chance = k / N
    se = math.sqrt(chance * (1 - chance) / N)            # spread of chance results over 50 queries
    print(f"{name:9s} {value:.2f}  chance {chance:.2f}  ({(value - chance) / se:+.1f} standard errors)")
```
:::

:::read
Text-to-image retrieval stands out: Recall@10 is 0.38 against 0.20 by chance (about 3 standard errors) and Recall@5 is 2.4 standard errors above chance. The image-to-text numbers are all within about 2 standard errors of guessing, and Recall@1 of 0 is not unusual when chance is 2%. With 50 queries the uncertainty is wide, so small differences between "before" and "after" may be noise. Always print chance levels next to retrieval numbers.
:::

@@before Tests
:::read
After 50 training steps, total loss falls from 8.39 to 6.08 and most retrieval numbers rise (text-to-image Recall@10 from 0.20 to 0.38), while image-to-text Recall@1 and VQA exact match drop to 0. BLEU-4 rises from 0.12 to 0.17. Read together with the visual, this is a tiny model just starting to align text to images: some metrics move clearly above chance, others are still indistinguishable from it.
:::

:::broken
A team reports Recall@1 of 0.92 on their retrieval benchmark. Their eval set has 10 captions per image query, and they did not mention it. What context is missing? (Solution B1.)
:::

:::recap What to keep from this lesson
- Recall@K from a similarity matrix, in both directions.
- Exact match for VQA; BLEU-4 for captions.
- Every metric has a chance level; report it.
- Small eval sets give wide uncertainty.
- Compare before and after on the same held-out suite.
:::

??? sol | P1 · Adding CIDEr
CIDEr weights each n-gram by TF-IDF across all reference captions, so rare, informative words ("giraffe") count more than common ones ("a", "the"), and averages cosine similarity of these weighted vectors for n = 1 to 4. Implement it alongside BLEU-4 and compare on captions that differ only in common or only in rare words.
???

??? sol | B1 · Recall without its pool size
Recall@1 depends heavily on how many candidates there are: with 10 candidates chance is 10%, with 5,000 it is 0.02%. The report needs the candidate pool size (and how many references per query), chance levels, and ideally results on a standard benchmark setup so others can compare.
