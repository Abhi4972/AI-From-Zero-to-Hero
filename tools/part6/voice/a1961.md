@@top The problem
:::plain In plain words first
A projection aligns one image vector with one caption. To describe an image word by word, each text token needs to look at the image's patches directly. **Cross-attention** does that: queries come from the text tokens, while keys and values come from the image tokens (the **memory**). A **fusion decoder** block has three parts: causal self-attention over the text (each word sees only earlier words), cross-attention into the image (each word may see *every* patch, since the whole image is given), and an MLP. During generation the image never changes, so its keys and values can be computed once and **cached**; the lesson checks that the cached path gives exactly the same output as recomputing.
:::
@@

@@end Idea 4 · Block composition
:::worked Mask shapes in one block
Text length 10, 197 image tokens.

1. Self-attention over text: scores are 10 × 10 with a causal mask, lower triangle allowed.
2. Cross-attention: scores are 10 × 197, one row per word, one column per image token, with no mask, because no image token is "in the future".
3. Caching: the image's keys and values (197 × head size per head) are computed once per image. Each new word adds one row to the self-attention cache but none to the image cache.
4. Masking the cross-attention causally (by mistake) would let word 1 see only image token 0 (the CLS token) and word 2 only tokens 0–1, discarding almost the whole image.
:::

:::check
Which statements are right?

- ✓ In cross-attention, queries come from text and keys and values from the image.
- ✗ Cross-attention needs a causal mask like self-attention.
  The whole image is available; every word may see every patch.
- ✓ The image's keys and values can be computed once and reused for every generated word.
- ✗ Caching changes the decoder's output slightly.
  Done correctly it gives exactly the same result.
:::

:::predict
Before running the code below: generating 50 words for one image with 197 image tokens and 4 decoder blocks, how many image key/value projections are computed per block with and without caching?
:::

:::visual What the image cache saves
```python run
image_tokens, blocks = 197, 4
for words in (10, 50, 200):
    uncached = words * image_tokens * blocks           # recompute image K and V at every generation step
    cached = image_tokens * blocks                     # compute once per image
    print(f"{words:3d} words: image K/V projections without cache {uncached:7,}, with cache {cached:,}  ({uncached // cached}x fewer)")
```
:::

:::read
Without a cache, every generated word recomputes keys and values for all 197 image tokens in every block; with a cache, they are computed once. The saving equals the number of words generated: 50 times fewer for a 50-word caption. Because the image does not change, the cached values are identical, which is why the lesson's drift check comes out at exactly zero.
:::

@@before Tests
:::read
The decoder (4.7 million parameters) maps 10 text tokens and 197 image tokens to logits of shape (2, 10, 1024), and the printed corner of the mask shows the lower-triangular pattern for text self-attention. The cached path matches the uncached one with a drift of exactly 0. The cross-attention output norms are similar at every text position, as expected from an untrained model whose attention is still spread evenly over the image.

## Solutions

??? sol | P1 · A tanh gate
Multiply the cross-attention output by tanh(g) with a learned scalar g initialized at 0. At the start tanh(0) = 0, so the block behaves exactly like the text-only model and training starts from a known state; as g grows, image information is let in gradually. Verify the loss at step 0 equals the text-only model's.
???

??? sol | B1 · A cache keyed by the wrong thing
Batch positions are reused for different requests from step to step, so a cache keyed by position can hand one request's image keys and values to another. Key the cache by a request or image id, and clear an entry when its request finishes.
