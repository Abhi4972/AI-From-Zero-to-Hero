@@top The situation
:::plain In plain words first
A planner trusted an agent card it fetched through someone else's caching proxy, and delegated a production deploy because the card said the agent could do that. The copy had been changed in transit. Cards are signed so that this can be detected, but the planner never verified the signature. The case trains verifying signed documents before reading any field that drives decisions.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A signature is useful only if the reader verifies it.
- ✗ A card fetched over HTTPS cannot have been modified.
  It passed through a proxy that could serve any bytes.
- ✓ Keys must come from a trusted store, with an allowed list of algorithms.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Verify signatures before reading fields that drive plans.
- Rebuild canonical bytes exactly as the specification says.
- Take keys from a trusted store; restrict algorithms.
- Reject and alert on documents that fail.
:::
@@
