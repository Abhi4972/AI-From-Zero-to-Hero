@@top The problem
:::plain In plain words first
A safety filter can only block what it recognizes. **Encoding attacks** hide a forbidden request in a form the filter does not read but the model still does. **ArtPrompt** (Jiang et al., 2024) is the clearest example: the one or two words that would trigger a refusal are drawn as **ASCII art**, letters built from `#` and spaces, and the model is asked to read them. A keyword filter sees only punctuation, and the model's own safety training, learned on ordinary text, often does not fire either. The same idea generalizes to other unusual structures (trees, nested JSON, encodings such as base64) in **StructuralSleight**. For defenders the point is that safety has to hold across every format the model can read, and that set keeps growing as models get more capable.
:::
@@

@@end Idea 6 · Where this fits in Phase 18
:::worked Which layer catches what
A deployment has three layers in front of the model. Check each encoding against each layer.

1. **Keyword filter on raw text.** Catches the plain word. Misses lookalike Unicode letters (homoglyphs), spaced-out letters, base64 and ASCII art.
2. **Normalization, then the keyword filter.** Unicode normalization and stripping separators recover homoglyphs and spacing; decoding obvious base64 recovers that too. ASCII art still slips through, because recovering it means *recognizing shapes*.
3. **A model-based classifier on the whole prompt and on the output.** Can recognize intent even when the word never appears, and the output check catches harm however the request was phrased.
4. Conclusion: cheap layers handle cheap encodings; only a layer that understands meaning, ideally checking the output too, handles encodings that rely on the model's own reading ability.
:::

```python run
import base64, re, unicodedata
BLOCK = {"forbidden"}
CONFUSABLES = str.maketrans({"о": "o", "е": "e", "і": "i", "ԁ": "d", "Ь": "b", "ɾ": "r"})   # a tiny confusables table

def raw_filter(text):
    return any(w in text.lower() for w in BLOCK)

def normalize(text):
    t = unicodedata.normalize("NFKC", text).translate(CONFUSABLES).lower()
    out = [t, re.sub(r"[^a-z]", "", t)]                      # also try with separators removed
    for chunk in re.findall(r"[A-Za-z0-9+/=]{8,}", text):     # decode anything that looks like base64
        try: out.append(base64.b64decode(chunk, validate=True).decode().lower())
        except Exception: pass
    return out

variants = {"plain": "a forbidden topic", "homoglyph": "a fоrbіdden topic",
            "spaced": "a f.o.r.b.i.d.d.e.n topic",
            "base64": "a " + base64.b64encode(b"forbidden").decode() + " topic"}
for name, text in variants.items():
    after = any(raw_filter(t) for t in normalize(text))
    print(f"{name:10s} raw filter: {'blocked' if raw_filter(text) else 'missed '}   after normalization: {'blocked' if after else 'missed'}")
```

That is why encoding defences end with a meaning-level classifier and an output check, not a longer keyword list.
