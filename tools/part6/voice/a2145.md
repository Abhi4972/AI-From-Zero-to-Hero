@@top The situation
:::plain In plain words first
A load sweep reported a faster first token at four times the load. Each run reused one seed on one server without flushing its prefix cache, so later runs found earlier prompts already cached. With fresh seeds the first token got slower with load, as queues predict. The case trains suspecting results that contradict how a system must behave.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Reusing a seed on a warm server lets the prefix cache serve repeated prompts.
- ✗ The server got faster under more load.
  Clean runs gave 209.98 ms at 8 and 416.37 ms at 32.
- ✓ The fix is a benchmark protocol: new seeds, flush or restart between runs.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Distrust results that defy queueing.
- Use different seeds and a cold cache per run.
- Write the protocol into the kit.
- Rerun before you publish.
:::
@@
