@@top The situation
:::plain In plain words first
A deeper speculative draft nearly halved time per token for one user, but at 32 users the server produced no more total output. Each draft guess costs work and memory, and under load that cost competes with real requests. The case trains measuring a setting at the load you serve and noticing what else it changes, such as the size of the cache pool.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A setting that helps one user can hurt total output at high load.
- ✗ Deeper drafts are always faster because they guess more tokens.
  Depth 3 gave 1.6 times the output at 32 users; depth 5 lost output.
- ✓ The draft model shrank the cache pool, which mattered under load.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Measure at the load you will serve.
- Count throughput as well as per-token time.
- Check what memory a feature takes.
- Lock clocks for fair comparisons.
:::
@@
