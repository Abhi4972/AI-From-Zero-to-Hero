@@top The situation
:::plain In plain words first
A long training run dies at night and is restarted from the newest checkpoint folder. In the morning the reward curve starts from the beginning again: the resume silently did not happen. The checkpoint was pointed at the wrong level of the folder tree, and the trainer starts fresh without a message when it finds nothing to load. The case trains checking that a resume really resumed, from the log, before walking away.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A trainer may start from step 0 without an error if it finds no step to load.
- ✗ Pointing at the newest `iter_` folder is the safest choice.
  The tracker file lives in the parent checkpoint folder; that is what `--load` needs.
- ✓ Writing the resumed run to a new log file keeps the old evidence intact.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Check the loaded step in the log before trusting a resume.
- Point resume options at the level the tool expects.
- Never overwrite the previous run's log.
- Silent fallbacks deserve explicit checks.
:::
@@
