@@top Problem
:::plain In plain words first
When a production service breaks at 3 a.m., an engineer reads alerts, metrics, logs and traces, works out which part of the system failed, and decides what to change. An **AI troubleshooting agent** does the first half: an alert arrives, the agent walks a **graph** of the cluster's objects (which pod belongs to which deployment, runs on which node, is watched by which metric), pulls the relevant telemetry, and proposes **ranked root-cause hypotheses**, each with **citations** to the evidence. The second half, changing anything, stays with people: the agent is **read-only by default**, and every remediation needs a human's approval. An **audit log** records not just what ran but everything the agent *considered*, so reviewers see the near-misses too. Product names in the brief are a 2026 snapshot.
:::

@@end Build it
:::worked Following an alert through the graph
Alert: error rate 14% on `Deployment/checkout-api`.

1. **Start node:** the deployment. Edges lead to its ReplicaSets, their Pods, the Nodes they run on, and the Service in front.
2. **Telemetry:** for each, pull the last 15 minutes. The newest ReplicaSet started 12 minutes ago with image `v2.41`; its pods fail the health check; the older ReplicaSet's pods are healthy.
3. **Hypotheses:** (a) bad rollout of `v2.41`, cited by the rollout time, the health-check failures and the error-rate jump; (b) DNS trouble, with no supporting evidence found.
4. **Proposal:** roll back to the previous image. The agent drafts the command and posts it for approval; it does not hold the credential to run it.
:::

Before running the code below: hypotheses are scored as recency × specificity × citation strength ÷ graph distance. What happens to a well-written hypothesis that cites no evidence at all?

:::visual Multiplicative evidence scoring
```python run
def score(h):
    citation_strength = min(1.0, h["citations"] / 3)          # three citations count as full support
    return h["recency"] * h["specificity"] * citation_strength / h["path_len"]

hyps = [
    {"title": "bad rollout of v2.41", "recency": 0.95, "specificity": 0.9, "citations": 3, "path_len": 1},
    {"title": "node memory pressure", "recency": 0.6, "specificity": 0.7, "citations": 2, "path_len": 2},
    {"title": "DNS flap in coredns", "recency": 0.8, "specificity": 0.8, "citations": 0, "path_len": 3},
]
for h in sorted(hyps, key=score, reverse=True):
    print(f"{score(h):.3f}  {h['title']}  (citations: {h['citations']})")
```
:::

:::read
With a multiplicative score, a hypothesis with no citations scores exactly zero, however recent and specific it sounds; one weak factor drags the whole score down. That is the intended behaviour for an incident brief: an engineer reading it at 3 a.m. should see first the explanations the telemetry supports. The cost is that a correct but unobserved cause also ranks zero, which is why the brief should list "no evidence found for" alongside the ranking.
:::

@@before Ship it
:::read
The agent ranks the bad rollout first (0.735, two telemetry citations) and DNS trouble a distant second with no citations. The remediation gate works as designed: the rollback is first **blocked** because nobody has approved it, then executed after a named engineer approves; the audit log keeps both entries, including the blocked attempt. Note that the toy's DNS hypothesis still scores 0.09 without any citations, so its formula is not purely multiplicative; decide deliberately whether uncited hypotheses should score above zero.

## Solutions

??? sol | P2 · Near-miss audit
For every command the agent proposed, classify it as read-only or destructive from the verb and resource, and record whether it ran. A near-miss is a destructive command proposed without an approval request attached. Count them per incident over a week; a rising rate means the agent is drifting toward acting, even though the gate is still stopping it.
???

??? sol | B1 · Policy in the prompt is not a permission
A prompt is not a security boundary: a mistaken plan or a prompt injection in a log line could still produce `kubectl delete`. Give the default server credentials whose RBAC role allows only get, list and describe, and put destructive verbs on a separate server whose credential is released only after human approval.
???
