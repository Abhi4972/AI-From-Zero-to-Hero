@@top The problem
:::plain In plain words first
**Red-teaming** means attacking your own system on purpose, before someone else does, to learn where its safety measures fail. Done by hand it does not scale: you need hundreds of tries to estimate a failure rate, and every model release changes the answer. **PAIR** (Chao et al., 2023) automates it with three models. An *attacker* model proposes a prompt, the *target* model answers, and a *judge* model scores whether the answer broke the target's rules; the attacker sees each result and refines its next try. The headline number is the **attack success rate (ASR)**: the share of goals where an attack succeeded within a fixed number of queries. This lesson treats PAIR as evaluation infrastructure: what it measures, how to compare results honestly, and what it says about defences.
:::

@@end Idea 6 · Where this fits in Phase 18
:::worked Comparing two red-team reports
Report A: "ASR 85% with attack X." Report B: "ASR 40% with attack Y." Before comparing, fill in the missing columns.

1. **Budget.** A allowed 200 queries per goal; B allowed 20. ASR always rises with budget, so these are not comparable yet.
2. **Judge.** A used a lenient keyword judge that counts any non-refusal as success; B used a strict judge that requires actually harmful content. Lenient judges inflate ASR.
3. **Behaviour set.** A tested 50 internal goals; B tested JailbreakBench's 100. Different goal sets have different difficulty.
4. **Sample size.** At 50 goals, an observed 85% has a 95% interval of roughly 73–93%; at 100 goals, 40% has roughly 31–50%.

Only after matching budget, judge and goal set does the comparison mean anything.
:::

:::visual ASR with an honest error bar
```python run
import math
def wilson(k, n, z=1.96):
    p = k / n; d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d; h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return c - h, c + h

for name, k, n in [("attack A", 12, 40), ("attack B", 20, 40), ("attack A, 400 goals", 120, 400), ("attack B, 400 goals", 200, 400)]:
    lo, hi = wilson(k, n)
    print(f"{name:20s} ASR {k / n:5.1%}   95% interval {lo:5.1%} – {hi:5.1%}")
```
:::

:::read
At 40 goals, 30% and 50% have overlapping intervals (about 18–45% and 35–65%), so the second attack is not clearly stronger. At 400 goals the intervals separate cleanly. Red-team reports with a few dozen goals can rank attacks only when the difference is large; small benchmarks need error bars before anyone writes "better".
:::
