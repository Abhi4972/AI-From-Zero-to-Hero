@@top The problem
:::plain In plain words first
"It works on staging but not in production." Often the code is the same and the configuration differs: a timeout set in a defaults file and overridden by an environment variable, or a secret that changed. Finding which layer won, and why, is tedious by hand.

This project explains configuration drift. It loads named layers in order (defaults, then files, then environment), resolves each key while keeping the full history of which layer set what, compares the expected values with what a running system actually reports, and exports a report that is safe to hand to a CI job or an AI assistant because secret values are redacted.
:::
@@

@@end Step 2 · Resolve precedence with provenance
:::worked Which layer won?
Layers in order: `defaults.json` sets `timeout: 30`, `api_token`, `region: local`; then `env:TIMEOUT` sets `timeout: 5`.

1. `timeout`: history `[(defaults.json, 30), (env:TIMEOUT, 5)]`. The later layer wins, so the expected value is 5.
2. `region`: set once, by defaults, expected `local`.
3. `api_token`: set once; the value is a secret, kept in memory for comparison only.
4. The observed system reports `timeout: 30`. Expected 5, observed 30: the environment variable never reached the running process.
:::

:::check
Which statements are right?

- ✓ A missing key and a key set to `null` are different results.
- ✗ Secrets can be redacted before comparing, since only the report is exported.
  Redacting first would make two different tokens look equal; compare first, then redact.
- ✓ Every shadowed value stays in the history, so you can see what was overridden.
- ✗ `--check` exits 1 when drift is found.
  It exits 2 for drift, 0 for none, and 1 for invalid input or I/O errors, so CI can tell them apart.
:::
@@

Expected: `timeout` 5 (from the environment), `region` local, and the default `api_token`. Observed: `timeout` 30, `region` local, and a different, live token. Which keys will be reported as changed, and what will the report show for the token?

@@end Run the finished project
:::read Reading this output
`drift: true`. `timeout` is `changed`: expected 5, observed 30, and the history shows both layers, so the cause is visible at once: the `env:TIMEOUT` override is not in effect. `region` is `equal`. `api_token` is `changed`, but both values appear as `[REDACTED]` and `redacted: true`: the tool compared the real values and then hid them, so the report proves the token differs without revealing either one.

@@before Build it on your machine
:::broken
A script prints `diff <(cat expected.env) <(env)` into a CI log to debug drift. The log is public. What leaked, and what does this project do instead? (Solution B1.)
:::

:::recap What to keep from this project
- Load named layers in a stated order; reject ambiguous input.
- Resolve with provenance: keep every value each layer set.
- Compare before redacting; missing, null and empty are different.
- Export only a redacted report; use distinct exit codes for drift and errors.
:::

@@end Exercises

## Solutions

??? sol | 1. A flattening adapter
Write it as a separate step that turns nested objects into dotted keys (`db.pool.size`) and treats arrays as single atomic values, so `["a","b"]` and `["b","a"]` count as different. Document the choice, because element-by-element comparison is a different policy.
???

??? sol | 2. Null, missing and empty
`null` means "explicitly unset", a missing key means "never configured", and `""` is a real value. Code often behaves differently for each (a default applies, an error is raised, an empty string is used), so the report keeps them apart.
???

??? sol | 3. A blocking allowlist
Add a list of keys whose drift should fail CI. The report still lists every change, but `--check` exits 2 only when an allowlisted key differs. Print the allowlist in the report so nobody wonders why a change did not block.
???

??? sol | 4. CI and an assistant
Run the binary in CI with `--check`, save the redacted JSON as a build artifact, and attach that file (not raw logs) when asking an assistant for help. Choose the sensitive keys deliberately: anything not listed will appear in plain text.
???

??? sol | B1 · A diff in a public log
Every environment variable on both sides, including tokens and passwords. This project keeps secret values in memory for the comparison and exports only `[REDACTED]` with a flag saying they differ.
???
