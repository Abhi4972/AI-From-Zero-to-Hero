@@top The situation
:::plain In plain words first
A new alert paged on-call nine times in an afternoon for a GPU driver line, and every server was healthy each time. The line is printed whenever a server allocates memory at start, so the rule paged on normal starts. The case trains designing alerts on symptoms users would feel (a server that does not become ready, a probe that fails) and keeping mechanism lines as diagnostics.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A log line that appears during normal work makes a noisy pager.
- ✗ Raising the threshold fixes the alert.
  It silences it without making it a signal.
- ✓ Health transitions are what on-call can act on.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Alert on symptoms users feel.
- Keep mechanism lines as diagnostic counters.
- Replay a rule against a known-good day first.
- Keep logs that let you match each firing to a cause.
:::
@@
