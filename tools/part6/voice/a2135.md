@@top The situation
:::plain In plain words first
A training run on a machine with unified memory (CPU and GPU share it) is stopped by Ray, not by a CUDA error, after the first rollout. Ray's memory monitor counts the whole node, and on unified memory that includes the GPU's allocations, so 95 percent really means the machine is nearly full. The case trains understanding what a watcher measures before deciding whether its alarm is real.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ On unified memory, node memory includes GPU allocations.
- ✗ No CUDA out-of-memory error means GPU memory was fine.
  The pressure showed up in the node total Ray watches.
- ✓ The fix is a smaller model or setting, not silencing the watcher.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Know what each monitor measures.
- On unified memory, CPU and GPU share one budget.
- Change the run, not the watcher.
- Test at the real answer length before scaling up.
:::
@@
