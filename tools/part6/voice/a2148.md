@@top The situation
:::plain In plain words first
Two evaluation runs at temperature 0 differed by a point. Temperature 0 picks the most likely token, but the numbers behind "most likely" change with the batch a request joins, with whether its prompt was cached, and with the number type. The case trains listing everything that has to be held fixed for an exact repeat.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Batching can change floating-point results, and so the chosen token.
- ✗ Different answers at temperature 0 mean the weights changed.
  Weights and tokenizer were fine; the cache, batch and dtype differed.
- ✓ Flushing the cache and fixing batch and dtype gives repeatable runs.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Temperature 0 is not the same as determinism.
- Hold cache, batch and dtype fixed.
- Test one prompt alone and in a batch.
- Write down the settings of each evaluation.
:::
