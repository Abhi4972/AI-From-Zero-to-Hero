@@top The situation
:::plain In plain words first
A conformance kit scored a server at 32 percent and a release was blocked. Most failures came from how the kit built a URL and how it counted skipped checks, not from broken requirements. One real defect remained. The case trains reading a score down to requirements: which MUSTs failed, which failures are the tool's, and what actually needs fixing.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A tool's score can measure the tool's own assumptions.
- ✗ 63 failing checks mean 63 things to fix.
  The server broke no MUST; one real defect was found.
- ✓ Release rules should be written in terms of requirements.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Read scores down to requirements.
- Separate tool artefacts from defects.
- Fix and verify the real defects.
- Write release rules on MUSTs, not percentages.
:::
@@
