@@top The problem
:::plain In plain words first
Gradients are not always well behaved. One bad batch can produce a gradient thousands of times larger than usual, and a single update that size can wreck a model. **Gradient clipping** limits the damage: compute the **global L2 norm** of all gradients together, and if it exceeds a threshold, scale every gradient down by the same factor. **Mixed precision** adds another hazard: computing in 16-bit floats is faster, but FP16 overflows easily, producing **Inf** or **NaN**. A **GradScaler** multiplies the loss by a large factor so small gradients do not vanish, divides it back out (**unscales**) before clipping, **skips** the update if any gradient is not finite, and lowers the factor when that happens. The order of these steps matters.
:::
@@

@@end Idea 4 · Scaling factor diagnostics
:::worked Clipping one update
Three parameter tensors have gradient norms 3, 4 and 12. Threshold 1.0.

1. Global norm: √(3² + 4² + 12²) = √169 = 13.
2. 13 > 1, so the clip factor is 1 / 13 ≈ 0.077.
3. Every gradient is multiplied by 0.077, so the new global norm is exactly 1, and the *direction* of the update is unchanged.
4. Clipping each tensor separately to norm 1 would instead give norms 1, 1, 1 (global √3 ≈ 1.73) and change the direction, over-weighting the small tensors. That is why clipping uses the global norm.
:::

:::check
Which statements are right?

- ✓ Global-norm clipping scales all gradients by the same factor.
- ✗ Gradients should be clipped before unscaling in mixed precision.
  Unscale first, or the threshold applies to artificially inflated values.
- ✓ A step with any non-finite gradient is skipped, and the scale is reduced.
- ✗ Clipping changes the direction of the update.
  Global clipping changes only its length.
:::

:::predict
Before running the code below: gradients with norms 0.3, 0.4 and 0 and a threshold of 1. Is anything clipped? What if one gradient is infinite?
:::

:::visual Global clipping and the skip rule
```python run
import math
def clip(grads, max_norm=1.0):
    norm = math.sqrt(sum(g * g for vec in grads for g in vec))
    if not math.isfinite(norm): return None, norm, "skip: non-finite gradient"
    factor = min(1.0, max_norm / (norm + 1e-6))
    return [[g * factor for g in vec] for vec in grads], norm, f"factor {factor:.3f}"

for grads in ([[3.0], [4.0], [12.0]], [[0.3], [0.4], [0.0]], [[1.0], [math.inf], [2.0]]):
    new, norm, note = clip(grads)
    after = None if new is None else math.sqrt(sum(g * g for v in new for g in v))
    print(f"global norm {norm:7.3f} -> {note}" + ("" if after is None else f", norm after {after:.3f}"))
```
:::

:::read
The first set is scaled by 1/13 to a norm of exactly 1. The second is below the threshold and passes untouched (factor 1). The third has an infinite component, so its norm is infinite and the update is skipped rather than clipped, because scaling infinity gives infinity or NaN, not a usable step.
:::

@@before Ship it
:::read
Twenty steps run; at step 0 the gradient norm (1.008) is just above the threshold and gets clipped to 1.0, and afterwards it stays below. At step 5 the demo injects an infinite gradient: the step is marked SKIP with reason `non_finite_grad`, the loss is unchanged at the next step, and training continues. Two details to read carefully: the scale stays at 1.0 throughout because this CPU run does not use FP16, so the scaler is inactive; and the summary reports `skip_count=1` but `final_skip_rate=0.0000`, which is a rate over a recent window that no longer contains step 5, not over the whole run.
:::

:::broken
A training script calls `torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)` right after `scaler.scale(loss).backward()`, then `scaler.step(optimizer)`. Clipping never seems to do anything. Why? (Solution B1.)
:::

:::recap What to keep from this lesson
- Clip by the global L2 norm; direction stays the same.
- In mixed precision: scale, backward, unscale, clip, step, update the scale.
- Skip steps with non-finite gradients and lower the scale.
- Log pre-clip norm, post-clip norm, scale and skips.
- BF16's wider range rarely needs loss scaling.
:::

## Solutions

??? sol | P2 · BF16 instead of FP16
BF16 keeps FP32's exponent range with fewer mantissa bits, so values that overflow FP16 do not overflow BF16. Switch autocast to `dtype=torch.bfloat16` and disable the scaler; on the same demo, non-finite gradients from overflow disappear (an injected Inf will still be skipped, since that is not an overflow).
???

??? sol | B1 · Clipping scaled gradients
After `scaler.scale(loss).backward()` the gradients are multiplied by the scale factor (often 65,536), so their norm is huge and clipping to 1.0 squashes them, then the scaler divides again, and the real update is tiny or erratic. Call `scaler.unscale_(optimizer)` before clipping, then `scaler.step(optimizer)` and `scaler.update()`.
???
