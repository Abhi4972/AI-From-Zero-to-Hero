@@top The situation
:::plain In plain words first
A chat service stalled at 64 users while the throughput chart looked fine. It was past its knee, the load where latency starts rising sharply, and a cap on running requests only moved the waiting elsewhere. The case trains finding the knee with clean measurements and treating overload as a capacity problem.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Total throughput can look healthy while each user's stream stalls.
- ✗ Lowering the cap on running requests fixes overload.
  It turned a capacity problem into a queue and made things worse.
- ✓ The knee on this card was between 8 and 16 users.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Watch per-user latency, not only total throughput.
- Find the knee with clean runs.
- Add capacity past the knee.
- Caps manage queues; they do not add capacity.
:::
@@
