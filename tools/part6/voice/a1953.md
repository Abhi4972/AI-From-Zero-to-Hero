@@top Why a paired test
:::plain In plain words first
After experiments run, the **evaluator** decides whether a candidate beat the baseline, made things worse, or changed nothing beyond noise. Because both were run with the **same seeds**, the comparison is **paired**: compute the difference for each seed, then ask whether the average difference is reliably non-zero with a **paired t-test**. Two more details: the metric's **direction** (lower perplexity is better, higher accuracy is better), and its **scale** (perplexity is compared on a log scale, so a drop from 40 to 30 counts the same as 400 to 300). The verdict, improved, regressed or no change, comes with a one-line rationale that names the size of the effect and the p-value.
:::
@@

@@end The Verdict shape
:::math Paired t statistic
For $n$ seeds with per-seed differences $d_i$ (candidate minus baseline, after any log transform), mean $\bar d$ and sample standard deviation $s_d$:

$$t=\frac{\bar d}{s_d/\sqrt{n}}\qquad\text{with } n-1 \text{ degrees of freedom.}$$
:::

:::worked Paired against unpaired
Perplexity over four seeds. Baseline: 30, 36, 28, 40. Candidate: 28, 34, 26, 37.

1. Differences: −2, −2, −2, −3. Every seed improved, by a similar amount.
2. Paired: mean difference −2.25, standard deviation 0.5, so $t = -2.25 / (0.5/2) = -9$: a clear improvement.
3. Unpaired: the two groups' spreads (seed-to-seed variation of about 5) swamp the 2-point shift, so a two-sample test would call it noise.
4. Pairing removes the variation that seeds introduce to *both* runs, which is why the runner must reuse seeds.
:::

:::check
Which statements are right?

- ✓ Pairing by seed removes variation shared by candidate and baseline.
- ✗ A lower number is always better.
  Direction depends on the metric; accuracy is higher-is-better.
- ✓ Perplexity is compared on a log scale.
- ✗ A p-value of exactly 0 is strong evidence.
  With real seeds it should never be exactly 0; it signals zero variance, often fake or deterministic data.
:::

:::visual Paired t statistic, including the degenerate case
```python run
import math, statistics as st
def paired_t(cand, base):
    d = [c - b for c, b in zip(cand, base)]
    sd = st.stdev(d)
    return (st.mean(d), sd, None if sd == 0 else st.mean(d) / (sd / math.sqrt(len(d))))

base = [30, 36, 28, 40]
for cand in ([28, 34, 26, 37], [28, 34, 26, 38]):
    mean, sd, t = paired_t(cand, base)
    print(f"diffs {[c - b for c, b in zip(cand, base)]}: mean {mean:+.2f}, sd {sd:.2f}, t = {'undefined (zero variance)' if t is None else f'{t:.1f}'}")
```
:::

:::read
The worked example gives t = −9. When every difference is identical, the standard deviation is zero and t is undefined (infinite); the lesson's code handles that case by returning p = 0 whenever the mean difference is non-zero. That convention is fine for a unit test, but in a real run zero variance across seeds is a warning sign that the "seeds" are not changing anything.
:::

:::recap What to keep from this lesson
- Run candidate and baseline on the same seeds; pair by seed.
- Respect each metric's direction; use log scale for perplexity.
- Require both a minimum effect size and significance.
- Treat zero variance and p = 0 as warning signs.
- Every verdict carries its rationale.

## Solutions

??? sol | B1 · Pairs that are not pairs
Pairing only removes shared variation when both members of a pair share the seed; seeds 1 and 6 share nothing, so the test's assumptions do not hold and its p-value is meaningless. Pair by the seed recorded in each result, raise an error when seeds do not match (as the lesson's `PairingError` does), or use an unpaired test if pairing is impossible.
???
