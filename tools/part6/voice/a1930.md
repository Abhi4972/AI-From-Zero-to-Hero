@@top The frame
:::plain In plain words first
A language model reads integers, not text; the **tokenizer** turns text into a list of integers and back. **Byte-pair encoding (BPE)** builds its vocabulary by repetition: start with the 256 possible bytes, find the pair of neighbouring symbols that occurs most often in a training corpus, **merge** it into a new symbol, and repeat until the vocabulary is the size you want. Encoding new text replays those merges in the order they were learned; decoding just concatenates the bytes back. Working on **bytes** rather than letters means any UTF-8 text can be encoded without an "unknown" token, and a correct tokenizer guarantees the **round trip**: decoding the ids gives back exactly the original bytes. **Special tokens** such as end-of-text are reserved ids that ordinary text can never produce.
:::

@@end Round-trip guarantee
:::worked Three merges by hand
Corpus: "low low lower", split into words first, so merges never cross a space: [l o w], [l o w], [l o w e r].

1. Pair counts: (l,o) 3, (o,w) 3, (w,e) 1, (e,r) 1. Tie between (l,o) and (o,w); take the first seen, (l,o) → "lo".
2. Now [lo w], [lo w], [lo w e r]. Counts: (lo,w) 3, (w,e) 1, (e,r) 1. Merge (lo,w) → "low".
3. Now [low], [low], [low e r]. Counts: (low,e) 1, (e,r) 1. Merge (low,e) → "lowe", then (lowe,r) → "lower".
4. Eleven characters became four tokens. Frequent words become single tokens quickly; rare words stay split into pieces until the vocabulary is large enough.
:::

:::check
Which statements are right?

- ✓ Encoding applies merges in the order they were learned.
- ✗ A byte-level BPE needs an unknown-token id for unusual characters.
  Every byte is in the base alphabet, so any text can be encoded.
- ✓ Decoding concatenates each token's bytes and decodes them as UTF-8.
- ✗ Special tokens can appear by chance inside normal text.
  They are reserved ids handled separately from the byte stream.

:::visual A BPE trainer in a dozen lines
```python run
from collections import Counter
def train(text, n_merges):
    words = [list(w.encode()) for w in text.split(" ")]
    vocab = {i: bytes([i]) for i in range(256)}
    merges = []
    for new_id in range(256, 256 + n_merges):
        pairs = Counter(p for w in words for p in zip(w, w[1:]))
        if not pairs: break
        best = max(pairs, key=pairs.get)
        merges.append(best); vocab[new_id] = vocab[best[0]] + vocab[best[1]]
        for w in words:
            i = 0
            while i < len(w) - 1:
                if (w[i], w[i + 1]) == best: w[i:i + 2] = [new_id]
                else: i += 1
    return merges, vocab

merges, vocab = train("low low lower newest widest", 6)
for rank, (a, b) in enumerate(merges):
    print(f"merge {rank}: {vocab[a]!r} + {vocab[b]!r} -> {vocab[256 + rank]!r}")
```
:::

:::read
The first merges join the most common neighbours, `l`+`o` and then `lo`+`w`, and soon `es`+`t` from "newest" and "widest". This trainer splits on spaces first (so merges never cross words, as in the lesson's version) and breaks ties by first occurrence. Real tokenizers also pre-split on punctuation and digits, and train on gigabytes, but the loop is the same.
:::

:::recap What to keep from this lesson
- Start from 256 bytes; repeatedly merge the most frequent neighbouring pair.
- The merge table, in order, is the tokenizer.
- Encode by replaying merges in rank order; decode by concatenating bytes.
- Byte-level means no unknown token, and an exact round trip.
- Special tokens are reserved ids outside the byte stream.
:::

## Solutions

??? sol | B1 · Same vocabulary, different tokenization
Longest-match produces valid ids that still decode correctly, but not the same ids the model saw in training for the same text, so the model receives unfamiliar token sequences and performs worse in ways tests on round-tripping will not catch. Encoding must reproduce training exactly: replay merges in rank order, and test encodings against a saved reference, not only round trips.

The frame | Text in, integers out, the same text back.
