@@top The problem
:::plain In plain words first
Product feedback arrives as interview notes and support tickets. Someone groups it into themes and reports "12 people asked for X". Often that number counts the same person three times, or the same ticket pasted twice, and the board shows counts without the quotes behind them.

This project builds a theme board that counts honestly. Each record keeps its id and its source. Phrases are matched on whole words, with the original quote and offsets kept. Duplicates are recorded rather than counted twice, and themes report distinct sources, not just records. The output is a board, a JSON summary and unsent investigation drafts.
:::
@@

@@end Step 3 · Count evidence without inflating source support
:::worked Records versus sources
Six records: f-1 and f-5 are the same text from `interview-a`; f-3 is another note from `interview-a`; f-2 from `support-b` and f-4 from `interview-c` mention old pages; f-6 is about keyboard focus.

1. Deduplicate: f-5 repeats f-1 from the same source, so it is recorded as a duplicate and counted once.
2. "First useful run" (setup guide, sample file) matches f-1 and f-3: **2 records, 1 distinct source**, because both are from `interview-a`.
3. "Stale search results" (old pages, update the docs) matches f-2 and f-4: 2 records from 2 sources.
4. "Search latency" (long time) matches f-4 only. One record can support two themes.
5. f-6 matches nothing and stays visible as unassigned.
:::

:::check
Which statements are right?

- ✓ Matching whole tokens keeps "slow" from matching inside "slowdown".
- ✗ Two records from the same source count as two supporters of a theme.
  They are two records but one source; the board reports both numbers.
- ✓ Unmatched feedback stays on the board as unassigned.
- ✗ The drafts are filed as issues automatically.
  They are local Markdown drafts; a person decides what to file.
:::

@@before Build it on your machine

:::recap What to keep from this project
- Records have ids; sources are what you count.
- Match whole tokens on normalized text, quote from the original.
- Record duplicates; count distinct sources per theme.
- Keep unmatched feedback visible.
- Drafts are proposals; people file issues.
:::

@@end Exercises

## Solutions

??? sol | 1. A CSV loader
Read the support export with a real CSV reader, map its columns to `{id, text, source}`, write one JSON object per line, and report the CSV row number for any row that cannot be mapped.
???

??? sol | 2. Negation
Flag a match when a negation word ("not", "never", "no longer") appears within a few tokens before the phrase, without changing the match itself. Measure it on labelled examples: count how often a flagged match was in fact a complaint (a false positive of the flag).
???

??? sol | 3. Comparing configurations
Run both theme files on the same records and list, for each record, the themes it joined or left. A change that moves many records is worth reviewing before the board is shared.
???

??? sol | 4. A prioritisation tool
Pass `board.json` with each theme's evidence (record ids, quotes, sources). Require the tool's output to keep those ids, so every priority can be traced back to what users actually said.
???

??? sol | B1 · Substring matching
Step 2 matches consecutive tokens. "slowdown" is one token, so the phrase "slow" does not match it.
???
