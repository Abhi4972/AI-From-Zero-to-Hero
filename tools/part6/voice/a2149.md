@@top The situation
:::plain In plain words first
A team tried to use two GPUs for more capacity. Tensor parallel refused to start because the second card was partly used by another team; data parallel started but gave that copy a tiny cache, then sent it half the traffic. One card beat the pair at every load. The case trains reading what a failure says about the environment, not just trying the next layout.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ The balance check stopped tensor parallel because the second card was shared.
- ✗ Data parallel worked, so the shared card did not matter.
  Its copy got a pool of 2,925 tokens and still received half the requests.
- ✓ The right next step was asking for a dedicated card.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Read what a refusal says about the environment.
- Check per-replica capacity before routing evenly.
- Compare against the single-card baseline.
- Fix the shared resource, not the layout.
:::
@@
