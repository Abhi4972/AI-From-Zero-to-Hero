@@top The situation
:::plain In plain words first
At 64 users the first token takes 18 seconds and the plan is to buy a second GPU. One scheduler line explains it: 38 requests running, the cache 99 percent full, 26 waiting. The wait was a full cache, not a slow GPU. Switching to FP8 weights and cache made it about six times larger on the same card, and the queue disappeared. The case trains reading the scheduler before buying hardware.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Requests waiting with a full cache means the cache size limits concurrency.
- ✗ Full GPU utilization proves the GPU needs more compute.
  Here the waiting time came from the cache running out of room.
- ✓ FP8 must still be checked for quality on the team's own prompts.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Read running, waiting and cache usage before buying hardware.
- Waiting time goes into time-to-first-token.
- Smaller number formats enlarge the cache on the same card.
- Check output quality after changing formats.
:::
@@
