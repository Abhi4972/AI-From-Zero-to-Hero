@@top The problem
:::plain In plain words first
If you run models on your own machines, you need a **serving engine**: the program that loads the model and answers requests. Five are common. **llama.cpp** runs models efficiently on CPUs and Apple chips. **Ollama** wraps llama.cpp in a one-command tool for laptops. **vLLM** is the general-purpose production server for GPUs. **SGLang** is a production server that excels when prompts share long prefixes, as in agents and RAG. **TGI** (Hugging Face's server) entered maintenance mode in December 2025, so new projects should avoid it. Choose in three steps: first by **hardware** (CPU, Apple, AMD, NVIDIA generation), then by **scale** (one developer or thousands of users), then by **workload** (chat, agents, RAG, long context).
:::
@@

@@end Idea 9 · Numbers you should remember
:::worked Three projects, three engines
1. A data scientist wants to try models on a MacBook. Hardware: Apple Silicon → llama.cpp (Metal). Scale: one user → **Ollama** on top of it.
2. A support bot for 2,000 staff on two H100s, mostly general chat. Hardware: NVIDIA Hopper → vLLM, SGLang or TRT-LLM. Scale: production → **vLLM** (broad default, good tooling).
3. An agent platform where every request reuses long tool schemas and a big system prompt. Workload: heavy prefix reuse → **SGLang** (RadixAttention).
4. Avoid in all three: starting a new deployment on TGI, now only receiving bug fixes.
:::

:::check
Which statements are right?

- ✓ On CPU-only machines llama.cpp is the competitive choice.
- ✗ Ollama is a good shared production server.
  It is built for single users; its concurrency handling and observability lag vLLM's.
- ✓ TensorRT-LLM is not an option on AMD GPUs.
- ✗ Moving from Ollama in development to vLLM in production needs no conversion.
  llama.cpp-family engines use GGUF; GPU engines use safetensors weights.
:::

:::visual The decision tree as code
```python run
def pick(hardware, scale, workload):
    if hardware in ("CPU", "Apple Silicon"):
        return "Ollama" if scale == "single user" else "llama.cpp"
    if scale == "single user":
        return "Ollama (or vLLM for GPU testing)"
    if workload in ("agentic multi-turn", "RAG, heavy prefix reuse"):
        return "SGLang"
    if hardware == "NVIDIA Blackwell" and workload == "general chat":
        return "TRT-LLM (or vLLM to stay portable)"
    return "vLLM"

for case in (("CPU", "single user", "chat"), ("NVIDIA Hopper", "production", "general chat"),
             ("AMD MI300X", "production", "agentic multi-turn"), ("NVIDIA Blackwell", "production", "general chat")):
    print(f"{' / '.join(case):55s} -> {pick(*case)}")
```
:::

:::read
The AMD agentic case lands on SGLang, which supports ROCm; TRT-LLM is never chosen off NVIDIA. Writing the tree as code makes the reasoning reviewable: when the facts change (a new engine release, TGI's maintenance mode), you change one branch and every team gets the same answer.
:::

- Decide by hardware first, then scale, then workload.
- llama.cpp for CPU and edge; Ollama for laptops; vLLM as the production default; SGLang for prefix-heavy agents and RAG.

- Plan the weight-format conversion between the llama.cpp family and GPU engines.

## Solutions
