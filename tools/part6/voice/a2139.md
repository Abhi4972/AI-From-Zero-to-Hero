@@top The situation
:::plain In plain words first
A check comparing an agent's newest session with the previous one gave three different results in a week, while the agent never changed. It compared the wrong things: a relative reference into a store shared with other agents, and a command form the parser rejected. The case trains asking what exactly a comparison compares before trusting its verdict.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A relative reference like "the previous session" depends on what else wrote to the store.
- ✗ A flaky check means the agent is non-deterministic.
  Here the operands were wrong; two replays of one recording matched on every turn.
- ✓ Pinning the model and comparing replays of one cassette gives an honest check.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Know exactly which two things a check compares.
- Avoid relative references into shared stores.
- Replay recordings to remove model randomness.
- Test the command form you rely on.
:::
@@
