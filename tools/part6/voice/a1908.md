@@top Problem
:::plain In plain words first
A **production RAG chatbot** answers questions from a fixed body of documents, here in a **regulated** field such as law, healthcare or insurance, where every answer must be traceable and some readers may only see some documents. The pipeline: parse documents carefully (including tables and scans), label each chunk with **who may see it** and **which jurisdiction** it belongs to, filter by those labels *before* searching, run hybrid search and re-ranking, and answer only with **citations**. Around it sit **guardrails** (checks on input and output), an **evaluation** on a hand-labelled golden set plus a red-team set, monitoring for drift when documents change, and **prompt caching**, which makes repeated context much cheaper if the prompt is built with a stable prefix. Product names are a 2026 snapshot.
:::
@@

@@end Build it
:::worked Why filtering comes before retrieval
An analyst in the EU asks about data deletion. The corpus holds GDPR documents and HIPAA documents meant for US counsel only.

1. **Filter after retrieval:** search everything, then drop chunks the analyst may not see. If the top 5 included three HIPAA chunks, the answer is built from only two chunks, and the HIPAA text was already inside the system, in logs and in the cache.
2. **Filter before retrieval:** restrict the search to chunks labelled for the analyst's role and jurisdiction. The top 5 are all usable, and restricted text never leaves its index.
3. The second is both safer and better quality, which is why labels are assigned at ingestion, not added later.
:::

:::check
Which statements are right?

- ✓ Role and jurisdiction labels are attached to chunks when documents are ingested.
- ✗ Prompt caching works whatever order the prompt parts are in.
  The cached part must be an identical prefix, so stable content goes first.
- ✓ A golden set with expert-labelled citations measures correctness; a red-team set measures safety.
- ✗ Once evaluated, a RAG system stays accurate.
  Documents change; retrieval quality needs monitoring for drift.
:::

:::predict
Before running the code below: cached input costs a tenth of normal input. A prompt has an 8,000-token stable prefix (system prompt and policies) and a 2,000-token variable part. How much cheaper is input at a 70% hit rate, and at 0%?
:::

:::visual Prompt-cache savings
```python run
PREFIX, VARIABLE = 8000, 2000          # tokens per query
CACHED_PRICE = 0.1                      # relative to normal input price
def relative_cost(hit_rate):
    cached = hit_rate * PREFIX * CACHED_PRICE + (1 - hit_rate) * PREFIX
    return (cached + VARIABLE) / (PREFIX + VARIABLE)

for hit in (0.0, 0.33, 0.7, 0.9):
    print(f"hit rate {hit:4.0%}  ->  input cost {relative_cost(hit):5.1%} of uncached")
```
:::

:::read
At a 70% hit rate, input costs about half of the uncached price, and at 90% about a third; at the toy's 33% the saving is modest. The variable part is never cached, so the larger the stable prefix relative to it, the bigger the win. That is why the brief puts the system prompt and policies first and the user's question last. (Cache writes can cost slightly more than normal input with some providers, which this sketch ignores.)
:::

:::read
The scaffold walks through the main behaviours. An EU analyst's GDPR question is answered from three cited sections; repeating the same query hits the cache; US counsel's HIPAA question draws only HIPAA-labelled sources; and an "ignore previous instructions" prompt is blocked at input. The cache hit rate is 33% because only one of three queries repeated a prefix; Exercise 2 asks you to find what breaks the prefix in real traffic.

:::broken
To personalize answers, a team starts every prompt with "You are helping {user_name} from {department} at {timestamp}", followed by the system prompt and policies. Their cache hit rate drops to almost zero. Why, and what is the fix? (Solution B1.)
:::

:::recap What to keep from this lesson
- Label chunks with role and jurisdiction at ingestion; filter before searching.
- Hybrid search, re-rank, answer with enforced citations.
- Guard input and output; red-team alongside the golden set.
- Build prompts with a stable prefix so caching pays off.
- Monitor retrieval and faithfulness for drift.
:::

## Solutions

??? sol | P1 · Cross-jurisdiction probe
Write 20 questions whose best answers live in the other jurisdiction's documents, and ask them as users of each role. With pre-retrieval filtering, no answer may cite a document outside the user's labels; count any that do as leaks. Also check logs and caches for restricted text, since a leak can happen without appearing in the answer.
???

??? sol | B1 · A changing first line
A cache matches an identical prefix, and the first line now changes with every user and every second, so nothing after it can be reused. Move the per-user details to the end of the prompt, after the system prompt, policies and retrieved context, and drop the timestamp or round it, so the long stable part comes first.
???
