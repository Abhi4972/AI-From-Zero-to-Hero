@@top The situation
:::plain In plain words first
Every deploy breaks the answers that were being streamed, and each stopped server logs a crash. The orchestrator sent one polite stop signal; a wrapper script forwarded it to every process in the group, killing the scheduler before the server could drain its requests. The case trains following a signal from the orchestrator to the process that should receive it.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A graceful stop needs the stop signal to reach the server's main process, which then drains.
- ✗ Forwarding the signal to the whole process group makes shutdown more reliable.
  It killed the child processes first, so the server could not finish its answers.
- ✓ `exec` in the wrapper makes the server the container's main process.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Follow a signal from the orchestrator to the process that should handle it.
- Make the server the main process (`exec`).
- Graceful shutdown means draining in-flight requests.
- A crash log can be a symptom of how the process was stopped.
:::
@@
