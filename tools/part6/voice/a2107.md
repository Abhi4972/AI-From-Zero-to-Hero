@@top The situation
:::plain In plain words first
An engineer sets the trainer's attention implementation to `triton` because the inference engine uses a backend of that name, hoping the two will produce matching numbers. The trainer refuses the name at once. The case trains the idea that two components using the same word do not mean the same thing: each validates settings against its own list, and the error that prints that list is the fastest documentation.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ The engine's backend names and the trainer's implementation names are separate lists.
- ✗ Using the same kernel name on both sides makes their log probabilities match.
  Matching numbers needs a specific supported pairing (here, only on Hopper GPUs), not matching names.
- ✓ An error message that lists valid values is the quickest reference.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- The same word can mean different things to different components.
- Read the valid values the error prints.
- Change one side at a time and measure the gap.
- Know which hardware a claimed property needs.
:::
@@
