@@top The problem
:::plain In plain words first
A transformer language model is one **block** repeated many times. Each block has two parts: **attention** (tokens gather information from earlier tokens) and an **MLP** (each token's vector is processed on its own, widened to four times the size and back). Around each part are a **residual connection**, which adds the part's output to its input so information and gradients can flow straight through the stack, and a **LayerNorm**, which keeps the numbers in a stable range. Where the LayerNorm goes matters a lot. **Post-LN** (the original 2017 design) normalizes after adding the residual; **pre-LN** (used by GPT-2 and most later models) normalizes inside the branch, before the sublayer, which keeps a clean residual path and trains far more stably in deep stacks.
:::
@@

@@end Idea 3 · Residual connections do two things
:::worked Parameters in one block
Width $D = 768$, MLP hidden size $4D = 3{,}072$, with biases.

1. Attention: the Q, K, V projection is $D \times 3D$ plus $3D$ biases = 1,771,776; the output projection $D \times D + D$ = 590,592.
2. MLP: $D \times 4D + 4D$ = 2,362,368; and $4D \times D + D$ = 2,360,064.
3. Two LayerNorms: $2 \times 2D$ = 3,072.
4. Total ≈ 7.09 million per block, so twelve blocks are about 85 million of GPT-2 small's 124 million; most of the rest is the token embedding. Roughly 12D² per block is the rule of thumb.
:::

:::check
Which statements are right?

- ✓ A block maps (B, T, D) to (B, T, D), so blocks can be stacked freely.
- ✗ Pre-LN and post-LN compute the same function in a different order.
  They are different functions with different training behaviour.
- ✓ The residual path lets gradients reach early layers without passing through every sublayer.
- ✗ The MLP mixes information between tokens.
  It acts on each position separately; attention does the mixing.
:::

:::predict
Before running the code below: how many parameters does a 768-wide block save if every linear layer drops its bias, as many modern models do?
:::

:::visual Counting a block's parameters
```python run
def block_params(D, bias=True, mlp_mult=4):
    lin = lambda i, o: i * o + (o if bias else 0)
    attn = lin(D, 3 * D) + lin(D, D)
    mlp = lin(D, mlp_mult * D) + lin(mlp_mult * D, D)
    norms = 2 * 2 * D
    return attn + mlp + norms

for D in (192, 768, 4096):
    with_b, without_b = block_params(D), block_params(D, bias=False)
    print(f"D={D:5d}: {with_b:>12,} params with biases, {without_b:>12,} without (saves {with_b - without_b:,})")
print(f"12 blocks at D=768 without biases save {12 * (block_params(768) - block_params(768, False)):,}")
```
:::

:::read
At D = 768 the linear-layer biases are only 6,912 parameters per block, about 0.1%, and 82,944 across twelve blocks. Dropping them is not about size; modern models drop biases mainly because they add little and complicate some optimizations. The block count also confirms the rule of thumb: parameters grow with the square of the width.
:::

@@before Exercises
:::read
Both variants produce the same (2, 32, 192) shape, but their gradients differ enormously: the gradient reaching the embedding is about 210 times larger with pre-LN than with post-LN. That is the lesson's point in one number. In post-LN, every block's normalization sits on the residual path and shrinks the signal flowing back; in pre-LN, the residual path is untouched and early layers keep learning. The four-block stack in the demo has about 2.7 million parameters.
:::

:::recap What to keep from this lesson
- Block = attention + MLP, each with a residual connection and a LayerNorm.
- Pre-LN normalizes inside the branch; post-LN after the add.
- Pre-LN keeps a clean residual path and trains stably without warmup tricks.
- About 12D² parameters per block.
- Shapes in and out are identical, so blocks stack.

## Solutions

??? sol | P1 · Dropping biases
Per block at D = 768, the linear biases are 3D + D in attention and 4D + D in the MLP: 9D = 6,912. Across 12 blocks that is 82,944 parameters, under 0.07% of 124 million (removing LayerNorm's shift terms as well would save another 2D per block).
???

??? sol | B1 · Deep post-LN without warmup
Switch to pre-LN, which keeps gradients healthy through deep stacks, and add a learning-rate warmup (a few hundred to a few thousand steps), which post-LN in particular needs. Gradient clipping helps contain early spikes as well.
