@@top The problem
:::plain In plain words first
Pulling fields out of a document (who asked, how many seats, which date) is a classic job for a model, and a classic source of silent errors. A model that finds "Seats: 18" and later "Seats: 24" will usually pick one without saying there were two.

This project builds the review desk that sits around any extractor, including a model. Each field is defined first. Every proposed value keeps the exact quote and its character position in the source. A person approves ambiguous fields, and the approval is bound to one exact version of the document. Only approved values are exported.
:::
@@

@@end Step 2 · Extract candidates without losing their evidence
:::visual A proposal carries its evidence
```python run
text = "Requester: Mira Chen\nSeats: 18\nDelivery: 2026-10-14\nFollow-up note:\nSeats: 24\n"
labels = {"requester": ["Requester"], "seats": ["Seats", "Attendees"], "delivery": ["Delivery"]}
cands = {f: [] for f in labels}
pos = 0
for line in text.splitlines(keepends=True):
    for f, labs in labels.items():
        for lab in labs:
            if line.startswith(lab + ": "):
                start = pos + len(lab) + 2; quote = line.rstrip("\n")[len(lab) + 2:]
                assert text[start:start + len(quote)] == quote      # the span really holds the quote
                cands[f].append((quote, start, start + len(quote)))
    pos += len(line)
for f, c in cands.items(): print(f, "->", c, "AMBIGUOUS" if len(c) > 1 else "")
```
:::

:::read
Each candidate carries its quote and a half-open span: `text[start:end]` is exactly the quote, which the assertion checks. Seats has two candidates, 18 and 24, so it is marked ambiguous rather than resolved by "last one wins". A model-based extractor would plug in at this point and would have to meet the same contract: a quote that really sits at the stated offsets.
:::
@@

@@end Step 3 · Bind approval to one document version
:::check
Which statements are right?

- ✓ A label may belong to only one field.
- ✗ If an extractor's quote is not found at its offsets, the desk should search for it nearby.
  A quote that is not where it claims to be is rejected; searching would accept fabricated evidence.
- ✓ An approval recorded for one version of the document does not apply to an edited version.
- ✗ Passing type validation (a real date, a finite number) means the value is right.
  It means the quote can be that type; whether it belongs in the field is a person's decision.
:::

@@before Build it on your machine
:::broken
An extraction service returns `{"seats": 24}` with no quote. The integration writes 24 into the order system. The follow-up note was later withdrawn. What did the missing evidence cost, and what would this desk have required? (Solution B1.)
:::

:::recap What to keep from this project
- Define fields, types and labels before extracting.
- Every candidate keeps its exact quote and span.
- Repeated labels make a field ambiguous, never "last one wins".
- Type checks, evidence checks and human approval are separate.
- Bind approvals to a document version; export only approved values.
:::

@@end Exercises

## Solutions

??? sol | 1. An optional contact field
Add `contact` with `required: false`. When the document has no contact line, the field reports "missing" but the status can still reach "approved" once the required fields are decided. Required-field completion must look only at required fields.
???

??? sol | 2. A fabricated quote
Feed a candidate whose quote does not appear at its offsets (or anywhere). The evidence check rejects it, and the desk shows the rejection beside the field so a reviewer sees that the extractor invented it.
???

??? sol | 3. Reviewer identity and time
Add `reviewer` and `decided_at` to each decision and show them in the export. Say plainly in the report that these are recorded claims, not signatures; real authentication needs a separate mechanism.
???

??? sol | 4. A consumer that refuses unreviewed reports
Read the report, and exit with an error unless `status` is `approved`; then use only `approvedValues`. The consumer never reads proposed values directly.
???

??? sol | B1 · A value without evidence
Without the quote and position, nobody could see that 24 came from a note "awaiting confirmation", or that a second value (18) existed. The desk would have marked seats ambiguous, shown both spans, and exported nothing until a person chose.
???
