@@top The problem
:::plain In plain words first
Language models **memorize** some of their training data and can repeat it, including personal details. **Differential privacy (DP)** is a mathematical guarantee against this: a training procedure is DP if its result would be almost the same whether or not any one person's data was included, so nothing reliable can be learned about that person from the model. The parameter **ε** (epsilon) measures "almost": smaller is more private. The standard method, **DP-SGD**, clips each example's gradient so no single example can push the model far, then adds random noise. Privacy costs accuracy and compute, so fine-tuning only a small adapter (LoRA) with DP-SGD is common. This lesson covers the guarantee, what ε values mean in practice, and why attacks that measure different things give different pictures of the risk.
:::
@@

@@end Idea 7 · Where this fits in Phase 18
:::worked What ε promises
DP bounds how much any attacker's beliefs can shift from seeing the model. Take the cleanest test: an attacker knows everything except whether Alice's record was in training (prior 50/50), and guesses from the model.

1. With δ = 0, the best possible guessing accuracy is $e^{\varepsilon}/(1+e^{\varepsilon})$.
2. ε = 0.1: at most 52.5%, barely better than a coin.
3. ε = 1: at most 73%.
4. ε = 8, common in published DP fine-tuning: at most 99.97%. The *worst-case* guarantee at that level is weak; real attacks usually do far worse than the bound, which is what privacy auditing measures.
:::

:::check
Which statements are right?

- ✓ DP-SGD clips each example's gradient before adding noise.
- ✗ Any ε below 10 makes membership inference impossible.

- ✓ Clipping bounds one example's influence, which is what lets noise hide it.
- ✗ LoRA with DP-SGD protects the pretraining data too.

:::

:::predict
Before running the code below: a counting query (how many records have property X) is released with Laplace noise of scale 1/ε. At ε = 1, how accurately can an attacker tell whether Alice's record (which has property X) was included?
:::

:::visual The best attacker against a noisy count
```python run
import math, random
random.seed(4)
def laplace(scale):
    u = random.random() - 0.5
    return -scale * math.copysign(1, u) * math.log(1 - 2 * abs(u))

def attack(eps, trials=100000, base=100):
    correct = 0
    for _ in range(trials):
        alice_in = random.random() < 0.5
        released = base + alice_in + laplace(1 / eps)
        guess = released > base + 0.5          # the best threshold for symmetric noise
        correct += guess == alice_in
    return correct / trials

for eps in (0.1, 0.5, 1.0, 2.0, 8.0):
    bound = math.exp(eps) / (1 + math.exp(eps))
    print(f"epsilon {eps:4.1f}   attacker accuracy {attack(eps):6.1%}   DP upper bound {bound:7.2%}")
```
:::

:::read
The simulated attacker always stays under the DP bound, and at small ε both are close to a coin flip. At ε = 1 the attacker reaches about 70% against a bound of 73%; at ε = 8 the bound allows near certainty and this simple attack is already above 95%. The bound is a guarantee for the worst case; how close real attacks on a trained LLM come to it is what DP audits such as arXiv:2503.06808 try to measure.
:::

??? sol | P3 · Extraction and moderate ε
The extraction papers attacked ordinary models without DP, so they do not show that extraction survives DP training. What they do show is that membership tests on typical examples understate risk for the most memorable data (repeated, unusual text). Moderate or large ε still bounds that worst case only weakly, so evaluations should target the most extractable data, which is what the new canary designs do.
???

??? sol | B1 · Two gaps
First, ε = 8 is a weak worst-case bound: an attacker could in principle infer membership with near certainty. Second, the guarantee covers each training *record*; if one customer appears in many logs, their combined data gets a much weaker guarantee unless privacy is accounted per user. The base model's pretraining data, and anything placed in prompts at inference time, are not covered at all.
