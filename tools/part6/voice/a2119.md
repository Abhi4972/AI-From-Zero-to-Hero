@@top The situation
:::plain In plain words first
To leave room for the trainer, someone set the inference engine's memory share to 0.02. The run still worked and the reward looked normal, but each step took six times longer. The tiny cache forced the engine to process answers in many more rounds. The case trains checking speed as well as correctness after a configuration change, and knowing what a memory share actually buys.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A correct result can hide a large slowdown.
- ✗ Giving the engine as little memory as possible is a safe way to avoid memory kills.
  Below a point the cache cannot hold enough work, and every step slows down.
- ✓ At 0.25 the rollout took 61 s against 386 s at 0.02.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Check step time as well as reward after changes.
- Know the cache size each memory share gives.
- Fix the memory fear with measurements, not extremes.
- Keep the default unless you know why not.
:::
@@
