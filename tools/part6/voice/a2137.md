@@top The situation
:::plain In plain words first
A training run sat idle for an hour while its log grew to 147 MB: the inference engine had died at startup, and the trainer kept sending requests, reading each 503 as "busy". The team's new watchdog then killed healthy runs too. The case trains two things: reading the first error above the noise, and tuning a watchdog against what healthy runs actually do.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A 503 from a dead engine looks the same to the client as a busy one.
- ✗ A watchdog that kills after a few failed checks is safe.
  Healthy runs reached 6 failed checks; the threshold needed to be above that.
- ✓ The assertion message named the attention backend to change.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Find the first error, above the flood that follows.
- Distinguish dead from busy explicitly.
- Tune watchdogs on healthy runs.
- Fix the cause the assertion names.
:::
@@
