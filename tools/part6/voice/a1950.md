@@top Why generate, then filter
:::plain In plain words first
This lesson starts a track that builds a small **research agent**. Its first component proposes **hypotheses**. Asking a model the same question repeatedly tends to produce the same idea, so the generator varies the **temperature** across passes (low for safe drafts, higher for adventurous ones), **parses** each draft into a structured hypothesis (text, variables, metric, baseline), and keeps it only if it is **novel**: far enough from every hypothesis already accepted, measured by cosine distance between simple word embeddings. Survivors are **ranked** by a weighted score for novelty, specificity (how many concrete variables) and testability (does it name a metric and a baseline?), and queued for later stages. The model here is a scripted mock, so the run is reproducible.
:::

@@end Output queue
:::worked Scoring one hypothesis
"Top-k sparse attention with k = 16 matches dense attention on perplexity at 12M parameters." Weights 0.4 novelty, 0.3 specificity, 0.3 testability.

1. Novelty: its smallest cosine distance to earlier survivors is 0.85.
2. Specificity: it names three variables (k, perplexity, parameter count) against a target of three, so 1.0.
3. Testability: it names a metric (perplexity) and a baseline (dense attention), so 1.0.
4. Rank score: 0.4 × 0.85 + 0.3 × 1.0 + 0.3 × 1.0 = 0.94. A vaguer draft with the same novelty but no baseline would score 0.4 × 0.85 + 0.3 × 0.67 + 0.3 × 0.5 ≈ 0.69.
:::

:::check
Which statements are right?

- ✓ Raising temperature across passes pushes later drafts toward different ideas.
- ✗ A hypothesis is novel if its text differs at all from earlier ones.
  It must be far enough in embedding space, above a distance threshold.
- ✓ Testability rewards naming both a metric and a baseline.
- ✗ Rank weights are fixed by the method.
  They live in the config so later stages can change them.
:::

:::visual A bag-of-words novelty filter
```python run
import math, re
from collections import Counter
def embed(text):
    c = Counter(re.findall(r"[a-z]+", text.lower()))
    n = math.sqrt(sum(v * v for v in c.values()))
    return {w: v / n for w, v in c.items()}
def distance(a, b): return 1 - sum(a[w] * b.get(w, 0) for w in a)

accepted = []
for draft in ("sparse attention improves perplexity",
              "sparse attention reduces perplexity",
              "a learned gate cuts attention flops",
              "block sparse attention lowers training time"):
    e = embed(draft)
    d = min((distance(e, a) for a in accepted), default=1.0)
    verdict = "accept" if d > 0.25 else "reject (too similar)"
    if d > 0.25: accepted.append(e)
    print(f"{draft:45s} min distance {d:.2f} -> {verdict}")
```
:::

:::read
The second draft shares three of its four words with the first, so its distance is 0.25, not above the threshold: rejected, although its claim points the other way ("reduces" against "improves"). That is the weakness of word-overlap novelty: it measures wording, not meaning. The other two drafts are far enough to pass. A sentence-embedding model would judge meaning better; the interface stays the same.
:::

- Parse drafts into structured hypotheses.
- Accept only drafts far enough from earlier survivors.
- Rank by novelty, specificity and testability with configurable weights.

## Solutions

??? sol | B1 · Twenty versions of one idea
At a low, fixed temperature most drafts repeat the same idea in slightly different words, and without a novelty filter each one becomes an experiment, so the budget buys the same result many times. Ramp the temperature, reject drafts within the novelty threshold of an accepted one, and cap the queue so only the top-ranked hypotheses reach the runner.
???
