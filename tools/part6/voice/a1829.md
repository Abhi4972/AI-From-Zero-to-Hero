@@top The problem
:::plain In plain words first
**Moderation** is the part of a product that checks text (and sometimes images) against a content policy and decides what to block, rewrite or send for human review. Three widely used checkers: the **OpenAI Moderation API**, which returns a score per category (harassment, hate, self-harm, sexual, violence, illicit) for text and images; **Llama Guard** (Lesson 16), an open classifier you can run yourself; and **Perspective API** from Google Jigsaw, an older toxicity scorer still used as a research baseline. Production systems layer them: check the **input** before the model runs, check the **output** before the user sees it, and add **custom rules** for the product's own policy. Each layer has its own blind spots, and every threshold trades missed harm against wrongly blocked users.
:::

@@end Idea 7 · Where this fits in Phase 18
:::worked A latency budget for three layers
A chat product targets a reply that starts within 1.5 seconds. Generation takes 1.0 s to the first useful chunk; each classifier takes 0.2–0.4 s.

1. **Sequential checks:** input moderation with two classifiers one after another (0.3 + 0.4 s), then generation (1.0 s): 1.7 s before anything can be shown. Over budget.
2. **Parallel within a layer:** run both input classifiers at once; the layer costs the slower one, 0.4 s. Total 1.4 s. Within budget.
3. **Output checks on a stream:** moderating every token is too slow, so systems check chunks (for example each sentence) as they are produced and stop the stream if one fails.
4. The layers stay in order (input before generation, output after), but nothing forces the classifiers inside a layer to wait for each other.
:::

:::check
Which statements are right?

- ✓ OpenAI's moderation endpoint returns per-category scores; the application sets thresholds.
- ✗ Input moderation alone is enough if the classifier is good.
  Encoded or indirect attacks can pass the input check, so the output needs checking too.
- ✓ Custom rules encode a product's own policy, such as how it handles financial questions.
- ✗ A stricter threshold is always safer for users.
  It also blocks more legitimate requests, which is a harm of its own.
:::

:::predict
Before running the code below: two input classifiers take 0.3 s and 0.4 s, generation takes 1.0 s, and the output check takes 0.3 s. What is the total time with sequential classifiers, and with parallel ones?
:::

:::visual Sequential against parallel classifiers
```python run
INPUT = [0.3, 0.4]           # two input classifiers, seconds
GENERATE, OUTPUT = 1.0, [0.3]

def total(parallel):
    layer = max if parallel else sum
    first_visible = layer(INPUT) + GENERATE          # when the reply could start showing
    complete = first_visible + layer(OUTPUT)        # when the whole reply has passed its check
    return first_visible, complete

for parallel in (False, True):
    fv, done = total(parallel)
    print(f"{'parallel ' if parallel else 'sequential'} classifiers: reply can start at {fv:.1f} s, fully checked at {done:.1f} s")
```
:::

:::read
Running the two input classifiers in parallel saves 0.3 s, enough to bring the first visible text from 1.7 s to 1.4 s. The output check still adds its time at the end unless the output is checked in chunks while streaming. Layering costs latency, and engineering it well is about putting independent checks side by side, never about dropping a layer.
:::

:::recap What to keep from this lesson
- OpenAI Moderation, Llama Guard and Perspective score content against categories.
- Layer input checks, output checks and custom rules.
- Run classifiers within a layer in parallel; keep layers in order.
- Thresholds trade missed harm against wrongly blocked users.
- Custom rules encode policy; refusing a whole topic is rarely the right policy.
:::

??? sol | B1 · Output-only moderation
Every input reaches the model, including injection attempts that can make it take actions through tools before any output is checked; for an agent, the harm may be the action, not the text. It also spends generation cost on requests that should have been refused, and a single output classifier can be evaded by encodings (Lesson 14). Add input moderation and limit what actions untrusted input can trigger.
