@@top The problem
:::plain In plain words first
Interface strings look easy to translate until a translation drops `{count}` and the app prints "You selected tools", or "Return" is translated as "go back" when the button returns a borrowed item. This project builds a review workbench for interface translations.

It reads each message with its key, its placeholders and a note on where it appears. It checks translation proposals (from any source, including a model) against that contract: the same placeholders must come back. It previews each string with real values so a reviewer sees what users will see. Only explicitly approved strings are exported; everything else goes to a queue of unresolved questions.
:::
@@

@@end Step 2 · Generate bounded translation proposals
:::visual Same placeholders in, same placeholders out
```python run
import re
from collections import Counter
ph = lambda s: Counter(re.findall(r"\{(\w+)\}", s))
pairs = {"borrow.count": ("You selected {count} tools", "Has seleccionado herramientas"),
         "borrow.hello": ("Hello, {name}", "Hola, {name}"),
         "dup": ("{a} and {a}", "{a} y {b}")}
for key, (src, tr) in pairs.items():
    print(f"{key:13}", "ok" if ph(src) == ph(tr) else f"placeholder multiset changed: {dict(ph(src))} -> {dict(ph(tr))}")
```
:::

:::read
The count message lost `{count}`: shipped, it would show "Has seleccionado herramientas" with no number. The greeting keeps `{name}`. The third case shows why the check compares a multiset (each name with its count), not just a set: `{a}` twice becoming `{a}` and `{b}` is a different contract even though both mention `a`.
:::
@@

@@end Step 3 · Preview strings with supplied interpolation values
:::check
Which statements are right?

- ✓ A message marked ambiguous needs the reviewer to acknowledge its context before approval.
- ✗ A missing placeholder value should render as an empty string in the preview.
  It stays visible as the placeholder, so the gap is obvious.
- ✓ Previews insert values as text, never as HTML.
- ✗ Strings without decisions are exported in the source language.
  They go to `unresolved-strings.json`; only approved strings enter the locale file.
:::

@@end Exercises

## Solutions

??? sol | 1. An ICU parser
ICU MessageFormat adds plural and select rules (`{count, plural, one {...} other {...}}`). Parse it with its own module and its own contract checks (every plural branch present for the target language), rather than stretching the simple placeholder rule.
???

??? sol | 2. A provider adapter
Call the provider only with explicit credentials, record its name and model version on each proposal, and send its output through the same placeholder checks and human approval. The adapter must have no path that writes the locale file.
???

??? sol | 3. Real overflow
Render the chosen component (for example the button) in a headless browser with each translation and measure its width against the design's limit. Character counts are a poor proxy across scripts and fonts.
???

??? sol | 4. Planning the next pass
Group the unresolved queue by reason: placeholder errors go back to the translator, ambiguous contexts to the product owner, and plain "awaiting review" to the reviewers, with counts so the work can be scheduled.
???

??? sol | B1 · A renamed placeholder
The placeholder multiset check: `{Name}` is a different placeholder from `{name}`, so the proposal is flagged before anyone reviews it.
???
