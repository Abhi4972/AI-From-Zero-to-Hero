@@top The problem
:::plain In plain words first
A study tool that generates quiz questions can quietly teach the wrong thing: a question whose "correct" answer is not what the reading says. This project builds practice cards that are tied to their source. Every card stores where its answer comes from (a source id and character offsets), grading is narrow and explained, attempts are stored as dated events, and the review schedule is recomputed from those events, so it can be checked and reproduced.

The result is a small offline practice page: type an answer, reveal the expected one with its supporting quote, and see when each card is due again.
:::
@@

@@end Step 3 · Replay attempts into a visible schedule
:::visual A schedule replayed from events
```python run
import datetime as dt
INTERVALS = [1, 1, 2, 4, 8]                               # days until due, by box (box 0 and box 2 as in the project)
events = [("e1", "storage", "2026-09-01", True), ("e2", "storage", "2026-09-02", True),
          ("e3", "year", "2026-09-02", False), ("e2", "storage", "2026-09-02", True)]   # e2 repeated
cards = {c: {"box": 0, "last": None, "n": 0} for c in ["storage", "year", "sort"]}
seen = set()
for eid, card, day, correct in sorted(events, key=lambda e: (e[2], e[0])):
    if eid in seen: continue                              # an exact duplicate does not count twice
    seen.add(eid); c = cards[card]
    c["box"] = c["box"] + 1 if correct else 0; c["last"] = day; c["n"] += 1
for name, c in cards.items():
    due = dt.date.fromisoformat(c["last"]) + dt.timedelta(days=INTERVALS[min(c["box"], 4)]) if c["last"] else "now"
    print(name, c, "due", due)
```
:::

:::read
Storage was answered correctly twice and sits in box 2; the duplicate `e2` did not move it a third time. Year was answered wrongly once and stays in box 0, due again tomorrow. Sort has never been attempted, so it is due now. The interval table is a policy choice; the principle is what matters: progress is a replay of events, so anyone can recompute it and get the same due dates.
:::

@@end Step 2 · Return feedback that shows its source
:::check
Which statements are right?

- ✓ Every card's quote must match the source text at its stored offsets.
- ✗ "Paper envelope" should be accepted for "paper envelopes" because it is close.
  Only normalized exact answers or author-approved variants pass; closeness is not a rule.
- ✓ Feedback shows the supporting passage whether the answer was right or wrong.
- ✗ Reusing an event id with a different answer is fine; the newer one wins.
  It is an error: one id must mean one event.
:::

:::recap What to keep from this project
- Every card stores its source id and exact quote offsets.
- Grade narrowly: normalized exact answers or approved variants.
- Always show the supporting passage.
- Store attempts as events; recompute the schedule from them.
- Duplicate events count once; reused ids with different contents are errors.
:::

@@end Exercises
1. Why recompute the schedule from events instead of storing the current box?
2. How would you let an author approve "seed envelopes" as a variant?
3. What should happen to cards when their source passage is deleted?

## Solutions

??? sol | 1. Events over state
Stored state can drift (a bug, a manual edit) and cannot explain itself. Events can be replayed to check the state, audited, and replayed again under a changed scheduling rule.
???

??? sol | 2. An approved variant
Add it to the card's list of accepted variants with the author's note, and show the method "author-approved variant" in the feedback when it matches, so learners know it was a deliberate choice.
???

??? sol | 3. A deleted passage
Mark the cards invalid and take them out of the queue until an author re-points them at a passage that exists. A card without a source should not be graded.
???

??? sol | B1 · A stale quote
Step 1's validation: the text at the stored offsets must equal the stored quote. After the edit it does not, so the card is reported as invalid instead of teaching from a source that no longer says it.
???
