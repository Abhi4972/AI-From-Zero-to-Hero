@@top The frame
:::plain In plain words first
This lesson starts a series that builds an agent **harness**, the program around a model, piece by piece. The first piece is the **loop contract**: the agent is written down as a **state machine** with six named states (idle, planning, executing, awaiting a tool, reflecting, done) and a fixed list of allowed moves between them. Around it are **hooks**, named moments (before a tool call, after a step, on error…) where operators attach safety checks and logging; **pull points**, where the loop pauses and hands control back to the caller (to fetch a tool result, or because the budget ran out); a **typed event stream** that dashboards can follow; and **budgets** on turns, tool calls and time. Once the contract is fixed, swapping the model, tools or policies is a registration, not a rewrite.
:::

@@end The budget envelope
:::worked Replaying a session from its event log
A session's events were: start, plan drafted, plan committed, step started, tool called, step ended, tool result, session complete.

1. Feed the same events to a fresh harness. Each event triggers one allowed transition: IDLE → PLANNING → EXECUTING → AWAITING_TOOL → REFLECTING → DONE.
2. Because every transition goes through one function and the rules are fixed, the replay ends in the same state, with the same hooks fired in the same order, without calling the model again.
3. That is what makes debugging possible: a failure at turn 37 of a long run can be reproduced from the log in milliseconds.
4. If the log contains an illegal move (say, EXECUTING straight to DONE without reflecting), the replay stops there, which points at the bug.
:::

:::check
Which statements are right?

- ✓ IDLE is the only entry state and DONE the only exit.
- ✗ Running out of budget crashes the loop.
  It fires a hook and yields at a pull point; the caller decides whether to extend or close.
- ✓ Hooks fire in registration order and may change the payload or abort the turn.
- ✗ Any state may jump to any other state.
  Only the transitions in the contract are legal.
:::

:::predict
Before running the code below: a log goes IDLE → PLANNING → EXECUTING → DONE. Is that a legal session under this contract?
:::

:::visual A transition table that rejects illegal moves
```python run
LEGAL = {("IDLE", "PLANNING"), ("PLANNING", "EXECUTING"), ("PLANNING", "DONE"),
         ("EXECUTING", "AWAITING_TOOL"), ("EXECUTING", "REFLECTING"), ("AWAITING_TOOL", "REFLECTING"),
         ("REFLECTING", "EXECUTING"), ("REFLECTING", "PLANNING"), ("REFLECTING", "DONE")}
def replay(states):
    for a, b in zip(states, states[1:]):
        if (a, b) not in LEGAL: return f"illegal move {a} -> {b}"
    return "legal" if states[0] == "IDLE" and states[-1] == "DONE" else "does not start at IDLE and end at DONE"

for log in (["IDLE", "PLANNING", "EXECUTING", "AWAITING_TOOL", "REFLECTING", "DONE"],
            ["IDLE", "PLANNING", "EXECUTING", "DONE"],
            ["IDLE", "PLANNING", "EXECUTING", "REFLECTING", "PLANNING", "EXECUTING", "REFLECTING", "DONE"]):
    print(" -> ".join(log), ":", replay(log))
```
:::

:::read
The first and third logs are legal; the third even includes a replan. The second is rejected: in this contract a step must pass through REFLECTING before the session can finish, so a jump from EXECUTING to DONE marks a bug. Keeping the legal moves in one table, checked in one place, is what makes the contract enforceable rather than a diagram in a document.
:::

@@before Going further
:::read
The demo runs a three-step plan in which two steps need a tool. The event stream and the hook list show the order precisely, and one detail is worth noticing: `step.end` (and the `after_step` hook) fires *before* `tool.result` (and `after_tool_call`). A step ends when the loop yields at the tool pull point, and the result arrives on resume. A logger that assumes "step end means tool done" will be wrong; subscribe to `tool.result` for that.
:::

:::broken
A teammate adds a shortcut: if the planner returns an empty plan, the code sets `self.state = "DONE"` directly instead of calling `_transition`. Tests still pass. What breaks? (Solution B1.)
:::

:::recap What to keep from this lesson
- The harness is a state machine with six states and fixed legal moves.
- Hooks are the operator's seams; pull points hand control to the caller.
- A typed event stream lets UIs and tracers follow without touching the loop.
- Budgets yield; they do not crash.
- One transition function keeps the invariants in one place and makes replay exact.
:::

## Solutions

??? sol | B1 · Bypassing the transition function
Setting the state directly skips everything `_transition` does: the legality check, the hooks (`on_complete` never fires), and the event (`session.complete` is never emitted). Subscribers think the session is still running, and replays of the log will not match. Route every state change, including the empty-plan case (PLANNING → DONE is legal), through the one function, and add a test for it.
???
