@@top Why a scheduler, not a worklist
:::plain In plain words first
A research agent has more ideas than budget, so it needs a **scheduler** that decides what to run next, not just a queue. Hypotheses are grouped into **branches** (lines of inquiry). After each experiment, the branch's **reward** is updated, and the scheduler picks the next hypothesis with **UCB1**: the branch's average reward plus an **exploration bonus** that is large for branches tried only a few times. That balances exploiting what works with exploring what has not been tested enough. Several experiments run at once in **parallel slots**, branches whose average stays very low are **pruned**, good results can **fan out** into follow-up hypotheses or trigger a paper, and budgets on experiments and time stop the loop.
:::
@@

@@end The Trace and final report
:::math UCB1
$$\text{UCB}(b)=\bar r_b + c\sqrt{\frac{\ln N}{n_b}}$$

$\bar r_b$ is branch $b$'s mean reward, $n_b$ how many times it ran, $N$ the total runs so far, and $c$ the exploration weight (here $\sqrt 2$). Untried branches score infinity, so each is tried at least once.
:::

:::worked Exploration bonus by hand
After 20 runs: branch A ran 17 times with mean 0.83; branch B ran once with mean 0.56. $c = \sqrt 2 ≈ 1.41$, $\ln 20 ≈ 3.0$.

1. A: 0.83 + 1.41 × √(3.0 / 17) ≈ 0.83 + 0.59 = 1.42.
2. B: 0.56 + 1.41 × √(3.0 / 1) ≈ 0.56 + 2.45 = 3.01.
3. UCB picks B next by a wide margin: one run is too little evidence to give up on it.
4. If B has nothing left in the queue, though, UCB cannot pick it. UCB ranks the work that exists; it does not create work for under-explored branches.
:::

:::check
Which statements are right?

- ✓ A branch tried only once gets a large exploration bonus.
- ✗ UCB always picks the branch with the highest mean.
  It adds a bonus that favours under-tried branches.
- ✓ Pruning removes branches whose mean stays below a floor after several runs.
- ✗ UCB guarantees every branch gets a fair share of runs.
  It can only choose among hypotheses actually waiting in the queue.
:::

:::predict
Before running the code below: three branches with true success rates 0.8, 0.5 and 0.2 and 60 runs. Roughly how many runs does UCB1 give the best branch?
:::

:::visual UCB1 on three branches
```python run
import math, random
random.seed(4)
true = {"A": 0.8, "B": 0.5, "C": 0.2}
runs = {b: 0 for b in true}; total = {b: 0.0 for b in true}
for n in range(1, 61):
    def ucb(b): return math.inf if runs[b] == 0 else total[b] / runs[b] + math.sqrt(2) * math.sqrt(math.log(n) / runs[b])
    b = max(true, key=ucb)
    runs[b] += 1; total[b] += random.random() < true[b]
for b in true: print(f"branch {b}: runs {runs[b]:2d}, observed mean {total[b] / runs[b]:.2f}")
```
:::

:::read
UCB gives most of the 60 runs to the best branch while still sampling the others several times, so their estimates are not based on a single lucky or unlucky run. Compare that with the lesson's run below, where the weaker branches got exactly one run each: there the limit was not UCB but an empty queue.
:::

@@before Going further
:::read
The run stops at its 20-experiment budget. Branch A received 17 runs (mean reward 0.83) and triggered a paper; branches B, C and D got one run each. As the worked example shows, UCB1 with $c = \sqrt 2$ would rate B far above A after these numbers, so the allocation did not come from UCB preferring A. It came from the queue: only branch A's successes spawned follow-up hypotheses, so after their first run the other branches had nothing left to schedule.
:::

:::broken
A team sets the exploration weight `c = 0` "to focus the budget". After the first round, one branch with a lucky first result gets every remaining run. Why, and what is a better way to focus? (Solution B1.)
:::

:::recap What to keep from this lesson
- Group hypotheses into branches; track mean reward per branch.
- UCB1: mean reward plus an exploration bonus for little-tried branches.
- UCB only chooses among queued work; follow-ups shape what exists.
- Prune persistently weak branches; cap experiments and time.
- Good results fan out into follow-ups or a paper.
:::

## Solutions

??? sol | B1 · No exploration
With `c = 0` the score is the observed mean, so a branch that got lucky once stays on top and the others are never tried again to correct their estimates. Keep a positive exploration weight (or lower it gradually), and focus the budget with pruning floors and per-branch caps instead.
???
