@@top What perplexity tells you
:::plain In plain words first
Two measurements complement accuracy. **Perplexity** says how well a model predicts text: the exponential of its average negative log-probability per token, roughly "how many choices it is hesitating between" at each step. **Calibration** asks whether the model's confidence means anything: of all answers given with 80% confidence, are about 80% right? **ECE** (expected calibration error) groups predictions into confidence **bins** and averages the gap between confidence and accuracy; the **Brier score** is the mean squared error between confidence and outcome, which also rewards being sharp and correct. A **reliability diagram** plots accuracy against confidence per bin; a calibrated model lies on the diagonal.
:::
@@

@@end Confidence sources
:::math ECE and Brier score
With predictions grouped into bins $B_m$ of $n$ predictions in total:

$$\text{ECE}=\sum_{m}\frac{|B_m|}{n}\,\big|\text{acc}(B_m)-\text{conf}(B_m)\big|,\qquad \text{Brier}=\frac1n\sum_{i}(p_i-y_i)^2$$

$p_i$ is the stated confidence and $y_i$ is 1 if the answer was right, 0 if not.
:::

:::worked An overconfident model
1,000 answers, all given with 90% confidence; 600 are right.

1. One populated bin: confidence 0.90, accuracy 0.60, so ECE = |0.60 − 0.90| = 0.30.
2. Brier: right answers contribute (0.9 − 1)² = 0.01, wrong ones (0.9 − 0)² = 0.81, so (600 × 0.01 + 400 × 0.81) / 1,000 = 0.33.
3. A model that said 60% on every answer would have ECE 0 and Brier 0.24: perfectly calibrated, but no help in telling right from wrong answers.
4. That is the gap Brier covers and ECE does not: ECE rewards honesty, Brier rewards honesty *and* discrimination.
:::

:::check
Which statements are right?

- ✓ Perplexity is the exponential of the average negative log-likelihood per token.
- ✗ A low ECE means the model is accurate.
  It means confidence matches accuracy, which can both be low.
- ✓ Brier score penalizes confident wrong answers heavily.
- ✗ ECE is reliable whatever the number of predictions per bin.
  Sparse bins give noisy estimates; report how many bins are populated.
:::

:::visual ECE and Brier from scratch
```python run
def ece_brier(preds, bins=10):
    groups = {}
    for p, y in preds: groups.setdefault(min(int(p * bins), bins - 1), []).append((p, y))
    n = len(preds)
    ece = sum(len(g) / n * abs(sum(y for _, y in g) / len(g) - sum(p for p, _ in g) / len(g)) for g in groups.values())
    brier = sum((p - y) ** 2 for p, y in preds) / n
    return ece, brier, len(groups)

overconfident = [(0.9, 1)] * 6 + [(0.9, 0)] * 4 + [(0.3, 1)] * 3 + [(0.3, 0)] * 7
calibrated = [(0.9, 1)] * 9 + [(0.9, 0)] * 1 + [(0.3, 1)] * 3 + [(0.3, 0)] * 7
for name, preds in (("overconfident at 0.9", overconfident), ("calibrated", calibrated)):
    e, b, k = ece_brier(preds)
    print(f"{name:22s} ECE {e:.3f}  Brier {b:.3f}  populated bins {k}")
```
:::

:::read
In the first set, the 0.3 bin is perfectly calibrated (3 of 10 right), but the 0.9 bin is right only 60% of the time, so ECE is 0.15 (half the predictions, each 0.30 off). When the 0.9 bin is right 9 times out of 10, ECE drops to 0 and Brier improves from 0.27 to 0.15. Only two bins are populated here; with so few, ECE says little about the rest of the confidence range.
:::

## Solutions

??? sol | B1 · Per-token with different tokens
No. Perplexity is per token, and the tokenizers split text differently: with larger tokens there are fewer predictions per sentence, each harder, so per-token perplexity is not comparable. Compare bits or nats per character (or per byte) on the same text, which normalizes by a unit both models share.
