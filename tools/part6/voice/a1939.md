@@top The problem
:::plain In plain words first
A base model continues text; it does not know that a question expects an answer. **Supervised fine-tuning (SFT)** teaches that format by training on examples written as one sequence: an instruction marker, the instruction, a response marker, the response. The key detail is the **loss mask**: the model should learn to produce the *response*, so positions inside the instruction get the label −100, which PyTorch's cross-entropy ignores. Without the mask, much of the training signal goes into predicting instructions the user will always supply. Answers are then **generated** after the response marker and scored by **exact match** against the reference. This lesson runs the whole loop on a deliberately tiny model, which, as the output shows, is not enough to learn the task.
:::
@@

@@end Why the mask matters
:::worked Where the gradient goes
An example has an 18-token instruction (with markers) and a 6-token response.

1. Without a mask, the loss averages over all 23 predictions (24 tokens, each predicting the next): 17 of them are instruction tokens.
2. About three quarters of the gradient teaches the model to predict instructions, which it will never have to write.
3. With the mask, only the 6 positions predicting response tokens count, so every update is about answering.
4. With short responses and long instructions, unmasked training can look like a falling loss while answer quality barely moves.
:::

:::check
Which statements are right?

- ✓ Labels of −100 are ignored by PyTorch's cross-entropy.
- ✗ The mask removes instruction tokens from the model's input.
  The model still reads them; they just do not contribute to the loss.
- ✓ The marker tokens tell the model where the response begins.
- ✗ A falling training loss guarantees better answers.
  Exact match on held-out instructions is the real check.
:::

:::predict
Before running the code below: three examples have (instruction, response) lengths of (18, 6), (10, 20) and (30, 3) tokens. What share of predicted positions count toward the loss with the mask?

:::visual How much of each example is trained
```python run
IGNORE = -100
def labels(n_inst, n_resp):
    ids = list(range(n_inst + n_resp))
    targets = ids[1:] + [IGNORE]                      # next-token targets
    return [IGNORE if i < n_inst - 1 else t for i, t in enumerate(targets)]   # mask predictions made inside the instruction

for n_inst, n_resp in ((18, 6), (10, 20), (30, 3)):
    lab = labels(n_inst, n_resp)
    counted = sum(1 for x in lab if x != IGNORE)
    print(f"instruction {n_inst:2d}, response {n_resp:2d}: {counted:2d} of {len(lab)} positions trained ({counted / len(lab):.0%})")
```
:::

:::read
With the mask, the trained share follows the response length: a quarter of the first example, two thirds of the second, a tenth of the third. Each counted position predicts one response token (the last one predicts the end of the sequence). Unmasked, all positions would count equally, and the long-instruction example would spend 90% of its signal on text the model is never asked to write.
:::

@@before Stretch goals
:::read
This run is an honest failure. Training loss falls steadily, from 3.30 to 1.99 over 20 epochs, but exact match on held-out instructions stays at 0.000 in every category, and the sample answers are fragments of characters. A tiny model trained for seconds learns some letter statistics, not the task. The lesson's mechanics (template, mask, generation, scoring) are all working; the model is simply far too small and briefly trained for SFT to show results, which is also why the loss alone would have been misleading.
:::

:::broken
A team masks the instruction correctly but forgets to put an end-of-response token in the training data. After SFT, the model answers correctly and then keeps writing new questions and answers until it hits the length limit. Why? (Solution B1.)
:::

:::recap What to keep from this lesson
- SFT trains on instruction–response pairs in a fixed template.
- Mask instruction positions with −100 so only responses are trained.
- Markers separate instruction from response.
- Score held-out generations with exact match, not training loss.
- Teach the model where a response ends.
:::

## Solutions

??? sol | B1 · No end token
The model learns to continue the pattern it saw: after a response comes another instruction marker and another pair, because nothing marked the response as finished. Append an end-of-sequence token to each response, include it in the trained (unmasked) labels, and stop generation when it is produced.
