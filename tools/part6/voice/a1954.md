@@top Why a skeleton first
:::plain In plain words first
The research agent's **paper writer** turns results into a LaTeX document, in a fixed order: first a **skeleton** (title, sections, figure slots, bibliography keys) that is guaranteed to compile, then content poured into it. The **render contract** says which fields each part needs and how text is **escaped**: characters such as `%`, `&`, `_` and `#` have special meanings in LaTeX and break compilation if left raw. **Figures** are injected from the experiments' outputs, so every plotted number traces back to a run. The prose generator here is a mock. **Validation gates** check before writing that every cited key exists in the bibliography and every figure file exists, and a **manifest** lists what was produced.
:::

@@end Validation gates
:::worked One unescaped character
A results sentence reads: "Accuracy rose 12% on task_3 & task_4."

1. In LaTeX, `%` starts a comment, so everything after "12" on that line disappears silently.
2. `_` outside math mode is an error ("Missing $ inserted"), and `&` outside a table is another error.
3. The document fails to compile, or worse, compiles with text missing.
4. Escaped, the sentence becomes `Accuracy rose 12\% on task\_3 \& task\_4.` The render contract escapes every piece of generated text before it enters the template, so a model's wording can never break the build.
:::

:::check
Which statements are right?

- ✓ Every citation key must exist in the bibliography.
- ✗ Figures can be drawn from numbers typed into the prose.

:::

:::visual Escaping text for LaTeX
```python run
SPECIAL = {"\\": r"\textbackslash{}", "&": r"\&", "%": r"\%", "$": r"\$", "#": r"\#",
           "_": r"\_", "{": r"\{", "}": r"\}", "~": r"\textasciitilde{}", "^": r"\textasciicircum{}"}
def escape(text):
    return "".join(SPECIAL.get(ch, ch) for ch in text)

for s in ("Accuracy rose 12% on task_3 & task_4.", "50% of runs_A & B cost $3 ~ fine", r"path C:\data {draft}"):
    print(escape(s))
```
:::

:::read
Each special character becomes its escaped form in one pass, including the backslash, which must be handled in the same pass (escaping it first and then the braces would double-escape the braces it produced). One character at a time through a lookup table is the simplest correct approach; regex chains are where escaping bugs usually live.
:::

@@before Going further
:::read
The demo writes a paper with 3 sections, 2 figures and 2 bibliography keys to a temporary folder and reports the path. It does not run a LaTeX compiler, so "compiles" here means "passes the validation gates"; a real pipeline would add a compile step in CI and treat any warning about undefined references as a failure.
:::

:::broken
A paper writer lets the language model write the full LaTeX document, including `\cite{}` commands. The PDF compiles, but three citations show as `[?]`. What went wrong, and which gate prevents it? (Solution B1.)
:::

:::recap What to keep from this lesson
- Build a compiling skeleton first, then fill it.
- Escape every piece of generated text.
- Inject figures from experiment outputs.
- Gate on missing citation keys and missing figure files.
- Write a manifest of everything produced.
:::

@@end Going further
## Solutions

??? sol | B1 · Invented citation keys
The model cited keys that are not in the bibliography (often plausible-looking inventions), and LaTeX prints `[?]` for undefined references instead of failing. Generate structured content, not raw LaTeX; let the renderer insert `\cite{}` only for keys the retrieval stage supplied; and run a gate that fails the build on any citation key missing from the bibliography.
