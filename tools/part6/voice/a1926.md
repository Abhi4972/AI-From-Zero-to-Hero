@@top The problem
:::plain In plain words first
After a gate allows a call, the **sandbox runner** controls what the command can actually do. Before spawning anything it checks four things: the **executable** against a denylist (`rm`, `sudo`, `curl`…); the **arguments** for tricks such as `python3 -c` or `bash -c`, which smuggle a whole shell command through an interpreter, and for shell symbols like `;` or `|`; every **path** argument, which must resolve inside the project folder (the **path jail**); and only then does it run the process with a **time limit**, a trimmed environment and **truncated output**. The result is structured (exit code, output, whether it was denied, timed out or truncated, and why), so later layers never parse error text. As the lesson stresses, this is a guardrail against mistakes, not an operating-system security boundary.
:::
@@

@@end Why this is not a real sandbox
:::worked Three ways to say `rm -rf`
The agent wants to clear a folder.

1. `rm -rf build/`: refused by name, `rm` is on the denylist.
2. `python3 -c "import shutil; shutil.rmtree('build')"`: refused by argument shape, an interpreter with `-c` is a shell call in disguise.
3. `find ../.. -delete`: `find` is not on the list, but the path argument `../..` resolves outside the project root, so the jail refuses it.
4. Three different checks catch three spellings of the same intent. A fourth spelling may slip through all three, which is why the lesson calls this a guardrail and why real isolation (containers, no network, a throwaway filesystem) still matters.
:::

:::check
Which statements are right?

- ✓ Path arguments are resolved with `realpath` before being compared with the project root.
- ✗ Denying `bash` by name is enough to stop shell commands.
  Interpreters such as python, node or perl with `-c` or `-e` do the same job.
- ✓ Output is truncated so one command cannot flood the agent's context.
- ✗ This runner is a security boundary against a determined attacker.
  It stops common mistakes; real isolation needs OS-level sandboxing.
:::

:::predict
Before running the code below: the project root is `/work/proj`. Which of `src/a.py`, `../proj/src/a.py`, `../proj-secrets/key`, and `/work/proj/../proj2/x` stay inside the jail?
:::

:::visual A path jail that compares components, not strings
```python run
import posixpath
ROOT = "/work/proj"
def inside(arg, root=ROOT):
    p = posixpath.normpath(posixpath.join(root, arg))
    return posixpath.commonpath([p, root]) == root

for arg in ("src/a.py", "../proj/src/a.py", "../proj-secrets/key", "/work/proj/../proj2/x", "/etc/passwd"):
    naive = posixpath.normpath(posixpath.join(ROOT, arg)).startswith(ROOT)
    print(f"{arg:24s} naive prefix check: {'in ' if naive else 'out'}   component check: {'in' if inside(arg) else 'out'}")
```
:::

:::read
Both checks agree on the obvious cases, but the naive string-prefix check lets `../proj-secrets/key` and `/work/proj/../proj2/x` through, because `/work/proj-secrets` and `/work/proj2` both start with the characters `/work/proj`. Comparing whole path components with `commonpath` gets it right. (The real runner also calls `realpath` to resolve symbolic links first; a link inside the project pointing outside it is another classic escape.)
:::

@@before How this composes with the rest of Track A
:::read
The demo walks every refusal axis. Ordinary commands run; `rm`, `sudo` and `curl` are refused by name; `python3 -c` and `bash -c` by argument shape; `echo a ; rm -rf` by the shell metacharacter; `../../etc/passwd` and `/etc/passwd` by the path jail; `sleep 5` is killed at the 2-second limit; and `yes` is cut off at the output cap. Every refusal comes with a one-line reason the agent can read.
:::

:::broken
The runner removes `HOME` and `PATH` from the environment but keeps everything else "to avoid breaking tools". The developer's shell exports `GITHUB_TOKEN` and `AWS_SECRET_ACCESS_KEY`. What can go wrong? (Solution B1.)
:::

:::recap What to keep from this lesson
- Check executable, arguments, paths and structure before spawning.
- Interpreters with `-c` or `-e` count as shell calls.
- Jail paths by resolved components, not string prefixes.
- Enforce a wall-clock limit and truncate output.
- Return structured results; remember this is a guardrail, not isolation.
:::

## Solutions

??? sol | B1 · Secrets in the environment
Any command the agent runs inherits those variables, so a script, a test or a tool that prints its environment can expose the tokens, and anything with network access could send them out. Start from an empty environment and add an allow-list of variables the tools need (for example `PATH` set to a fixed safe value, `LANG`), never pass credentials through, and give tools that need access their own narrowly scoped tokens.
