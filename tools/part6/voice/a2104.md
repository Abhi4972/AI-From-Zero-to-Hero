@@top The situation
:::plain In plain words first
A page works in the browser but a test harness on the same machine cannot connect, and the developer starts editing the server inside the sandbox. The cause sits outside it: the port was published on the IPv4 loopback only, and the harness tried the IPv6 one (`::1`). The case trains a quick, general check: compare the addresses each client used before touching the service.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ `localhost` can resolve to `127.0.0.1` or `::1`, depending on the client.
- ✗ If one client connects, the service must be listening on every address.
  A port mapping has its own address family; here it bound `tcp4` only.
- ✓ Fetching the same URL on both loopback addresses separates the two hypotheses in one minute.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- When one client works and another does not, compare the addresses they used.
- A port mapping has an address family; read it in the listing.
- Test both loopbacks before editing the service.
- Revert edits made on a wrong hypothesis.
:::
@@
