@@top The problem
:::plain In plain words first
The **training loop** repeats: take a batch, compute the model's predictions, measure the **cross-entropy loss** against the next tokens, compute gradients, **clip** them if they are too large, and let the **AdamW** optimizer update the weights. Two details matter. **Weight decay** (a pull of weights toward zero) is applied to the big matrices but not to biases or LayerNorm parameters. The **learning rate** starts small, **warms up** linearly, then decays along a **cosine** curve. A loop that only prints the training loss can fool you, so this one also measures loss on **held-out** data every few steps and prints a sample generation, writing everything to a log. The gap between training and held-out loss is how you see overfitting.
:::
@@

@@end Idea 5 · Qualitative sampling as an early signal
:::math Warmup then cosine
For step $s$, warmup length $W$, total steps $S$, peak rate $\eta_{\max}$ and floor $\eta_{\min}$:

$$\eta(s)=\begin{cases}\eta_{\max}\,\dfrac{s+1}{W} & s<W\\[1.5ex] \eta_{\min}+\tfrac12(\eta_{\max}-\eta_{\min})\left(1+\cos\!\left(\pi\,\dfrac{s-W}{S-W}\right)\right) & s\ge W\end{cases}$$
:::

:::worked Reading train against validation loss
Two runs, logged every 20 steps.

1. Run A: train 3.1 → 2.4 → 2.0; validation 3.2 → 2.6 → 2.3. Both fall together: the model is learning patterns that generalize.
2. Run B: train 3.0 → 1.1 → 0.9; validation 6.6 → 7.5 → 7.5. Training loss falls while validation rises: the model memorizes its training batches.
3. Run B's validation loss is even above the random-guess level of ln V, so the held-out data shares no learnable structure with the training data, or the model has overfit badly.
4. Without the validation column, run B looks like the better run. That is why the loop measures both.
:::

:::check
Which statements are right?

- ✓ Biases and LayerNorm weights are excluded from weight decay.
- ✗ Warmup is only needed for very large models.
  Early updates with a full learning rate can destabilize small models too.
- ✓ Gradient clipping caps the size of one update when gradients spike.
- ✗ A falling training loss shows the model is learning useful structure.
  Only held-out loss shows whether it generalizes.
:::

:::predict
Before running the code below: with 10 warmup steps, 80 total steps, a peak of 0.003 and a floor of 0, what is the learning rate at steps 4, 9, 45 and 79?
:::

:::visual The learning-rate schedule
```python run
import math
def lr(step, warmup=10, total=80, peak=3e-3, floor=0.0):
    if step < warmup: return peak * (step + 1) / warmup
    progress = (step - warmup) / (total - warmup)
    return floor + 0.5 * (peak - floor) * (1 + math.cos(math.pi * progress))

for s in (0, 4, 9, 10, 19, 39, 45, 59, 79):
    print(f"step {s:2d}: lr {lr(s):.5f}")
```
:::

:::read
The rate climbs linearly to its peak at step 9, starts the cosine at step 10, passes half the peak around step 45 and approaches zero at step 79. The lesson's log follows the same shape with slightly different settings (0.00289 at step 19, 0.00201 at step 39, 0.00086 at step 59, 0.00030 at step 79); its last value shows it keeps a small floor rather than decaying to zero. Exercise 3's floor simply lifts the end of the curve.
:::

- Loop: batch, forward, cross-entropy, backward, clip, AdamW step, schedule.
- Decay weights, not biases or norms.
- Warm up, then cosine decay.
- Log train loss every step, validation loss and a sample every K steps.
- Diverging train and validation loss means memorization.

## Solutions

??? sol | P3 · A learning-rate floor
Set `floor = 0.1 * peak` in the schedule. The warmup is unchanged and the cosine now ends at 10% of the peak instead of zero, so late training keeps making small updates. Re-plot to confirm the curve's last value equals the floor.
???

??? sol | B1 · Averaging away the sequence
Averaging logits over time throws away the per-position predictions, so the model is trained to predict one blurred distribution per sequence, not the next token at each position. Flatten instead: `F.cross_entropy(logits.view(-1, V), targets.view(-1))`, which treats every position as its own prediction.
???
