@@top The situation
:::plain In plain words first
A nightly job posted "no change" whenever a compare command exited 0, which it did whenever it ran at all. For three weeks it never read the result. The case trains reading a tool's actual status instead of its exit code, and treating "unknown" as not a pass.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Exit code 0 can mean the tool ran, not that the result is good.
- ✗ Three weeks of "no change" mean the binary did not change.
  The job never read the compare status.
- ✓ A result with unresolved records is not a pass.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Read the result, not the exit code.
- Treat unknown as not a pass.
- Name counts in the message.
- Compare like with like builds.
:::
@@
