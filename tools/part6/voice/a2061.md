@@top The problem
:::plain In plain words first
A support agent reads a customer's message, decides which team's knowledge applies, and answers or hands over to a person. Done carelessly, it copies an API key from the message into its logs, answers a billing question with access-control advice, or marks a ticket "resolved" that nobody answered.

This project builds the policy first, in plain Python: clean and validate the ticket (masking emails and keys) before any session starts, route by counting domain words and send ties or unknowns to a human, grant one read-only capability for that route, and keep the actual reply and its source with the ticket's state history. Only then does it run the same policy through real agents built with Google's Agent Development Kit (ADK).
:::
@@

@@end Step 2 · Route and authorize as separate decisions
:::visual Route only on a clear winner
```python run
import re
domains = {"billing": {"invoice", "charge", "refund", "membership"}, "access": {"login", "password", "locked"},
           "platform": {"error", "outage", "slow"}}
def route(text):
    words = set(re.findall(r"[a-z]+", text.lower()))
    scores = {d: len(words & kw) for d, kw in domains.items()}
    best = max(scores.values())
    winners = [d for d, s in scores.items() if s == best]
    return (winners[0] if best > 0 and len(winners) == 1 else "human"), scores
for t in ["Could you review the invoice reference for my workshop membership?",
          "My login fails and there is an error page", "The garden looks lovely today"]:
    print(route(t), "<-", t)
```
:::

:::read
The membership invoice question scores 2 for billing and 0 elsewhere: a unique winner, routed to billing. The login error scores 1 for access and 1 for platform: a tie, so it goes to a person instead of the first dictionary key. The garden remark matches nothing and also goes to a person. Routing decides *which* guidance applies; authorization (which tool the agent may call for that route) is a separate, second decision.
:::

@@end Exercises
1. Why separate routing from authorization?
2. How would you measure whether routing is good enough to automate more tickets?
3. Where should the ADK agent's model reply be checked against the source guidance?

## Solutions

??? sol | 1. Two decisions
Routing is a guess about the topic; authorization is a security decision. Keeping them apart means a wrong route can at worst read the wrong guidance, never call a tool it was not granted.
???

??? sol | 2. Measuring routing
Label a sample of past tickets with the correct team, run the router, and report accuracy and how many went to humans. Automate more only where the routed precision is high, and keep counting ties.
???

??? sol | 3. Checking the model's reply
Before the ticket moves to answered: the reply must cite the source id it used, and a check (lexical or a reviewer) must confirm it agrees with that guidance; otherwise escalate.
???

??? sol | B1 · Keys in the logs
Every pasted key, readable by anyone with access to the logs. Step 1 masks emails and keys before the ticket enters any session, so logs only ever see `[email]` and `[redacted]`.
???
