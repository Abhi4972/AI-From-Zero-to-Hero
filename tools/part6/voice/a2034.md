@@top The problem
:::plain In plain words first
A research agent takes a question, searches documents, and writes a report. The failure everyone has seen is a fluent report whose citations do not support its sentences. This project builds an agent where every sentence is checked.

It uses three languages, each for what it does well: a BM25 search engine in Rust, the pipeline in Python, and a report viewer in TypeScript. The pipeline splits the question into facets, extracts exact sentences as citable snippets, writes only from those snippets, has a critic check every sentence against its cited snippet and drop unsupported ones, and publishes a report with a machine-readable trace. A final step scores the agent on public test questions.
:::
@@

@@end Step 2 · Extract snippets you can cite
:::worked Citing a sentence, not a document
1. Search returns `07-secrets-proxy.md` as a top document for "How does a secrets proxy protect API keys?".
2. A citation to the whole file proves little: it is long and covers many claims.
3. The snippet extractor splits the file into sentences with `(start, end)` offsets and scores each against the query terms.
4. A sentence such as "The agent never sees the real key." (from that document) becomes a snippet, stored with its document and exact offsets, and gets a display id such as S1. Every later citation points at S1, which a reader (or the critic) can check.
:::
@@

@@end Step 5 · Verify every claim
:::check
Which statements are right?

- ✓ The writer may only arrange text from retrieved snippets.
- ✗ A sentence with a citation marker is supported.
  The critic checks that the cited snippet actually supports it, and drops the sentence if not.
- ✓ The planner works without a model and can use one when available.
- ✗ Display ids such as S1 are stable across runs.
  They are numbered per run; the trace links each to its document and offsets.
:::

`state completed`, 4 sections (one per facet), 10 sentences, none dropped: every sentence the writer produced passed the critic's support check, which is expected when the writer may only arrange snippet text. `out/report.html` is the readable report; `out/trace.json` records the plan, searches, snippets with offsets, and each verdict, so a reviewer can follow any sentence back to its source. @@before Build it on your machine
:::broken
A research agent's writer is a model that "uses the snippets as context" and writes freely. The report reads well and has a citation on every sentence. Half the citations point at snippets that say something else. Which step catches this? (Solution B1.)
:::

:::recap What to keep from this project
- Use the right language for each part, joined by clear JSON contracts.
- Cite exact sentences with offsets, not whole documents.
- Plan facets; the model is optional.
- Write only from evidence, then check every sentence against its citation.
- Publish a report for people and a trace for machines; score on fixtures.
:::

@@end Exercises

## Solutions

??? sol | 1. Term and document frequency
Term frequency counts occurrences inside one document, so repeats raise it. Document frequency counts how many documents contain the term at all; a document counts once however often the term appears in it.
???

??? sol | 2. An edited source
If text is inserted before the snippet's start offset, the stored offsets now point at the wrong characters. Store the document's hash with each snippet, and re-extract (or mark the snippet stale) when the hash changes.
???

??? sol | 3. A failed live model
The trace must say a live model was attempted and failed, and whether the run fell back to the offline planner. Labelling it "verified offline run" would misreport what actually produced the report.
???

??? sol | 4. Run-local ids
S1 is a display label assigned in order within one run. Another run with different search results assigns S1 to whatever snippet comes first. Compare runs by document and offsets, not by display id.
???

??? sol | 5. Before acting on a recommendation
An independent check outside the corpus: a test deployment, a second source, or a person with the domain knowledge. Lexical support shows the sentence matches its snippet, not that the snippet is right for your situation.
???

??? sol | 6. Changed claim or changed evidence
Compare both the sentence text and the cited snippet's hash between runs. Same words with a different snippet hash means the evidence changed under an unchanged claim, which needs a fresh look.
???

??? sol | 7. Generalizing beyond the fixtures
Held-out questions and documents the agent was never tuned on, scored with the same metrics, with enough items that a few questions do not decide the result.
???

??? sol | B1 · Citations that do not support
Step 5, the critic: it scores each sentence against its cited snippet and drops (and records) sentences without support. Step 4's rule, that the writer arranges only snippet text, prevents most of them in the first place.
???
