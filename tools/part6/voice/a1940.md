@@top The problem
:::plain In plain words first
**Direct Preference Optimization (DPO)** trains a model from pairs of answers to the same prompt where a person preferred one (**chosen**) over the other (**rejected**). Classic RLHF first trains a reward model and then optimizes against it with reinforcement learning; DPO skips both and uses one ordinary loss. It compares how much more likely the model makes the chosen answer than a frozen **reference** model does, against the same ratio for the rejected answer, and pushes the difference (the **margin**) up. The strength **β** controls how far the model may move from the reference. The model in this lesson is tiny and trains in seconds.
:::
@@

@@end Why DPO works
:::math The DPO loss
$$\mathcal{L}=-\log\sigma\!\Big(\beta\big[(\log\pi(y_w|x)-\log\pi_{\text{ref}}(y_w|x))-(\log\pi(y_l|x)-\log\pi_{\text{ref}}(y_l|x))\big]\Big)$$

$y_w$ is the chosen answer, $y_l$ the rejected one, $\pi$ the model being trained and $\pi_{\text{ref}}$ the frozen reference. The bracket is the margin; $\sigma$ is the logistic function.
:::

:::worked One pair by hand
$\beta = 0.2$. Log-probabilities of the chosen answer: policy −12, reference −14. Rejected answer: policy −15, reference −13.

1. Chosen improvement over the reference: −12 − (−14) = +2.
2. Rejected improvement: −15 − (−13) = −2.
3. Margin = 2 − (−2) = 4; times β = 0.8. Loss = −log σ(0.8) ≈ 0.37.
4. When the margin is large (say β × margin = 10), the loss is about 0.00005 and its gradient almost vanishes: the pair is already learned and stops contributing.
:::

:::check
Which statements are right?

- ✓ DPO needs a frozen reference model but no separate reward model.
- ✗ DPO maximizes the chosen answer's probability regardless of the reference.
  It rewards improvement relative to the reference, for chosen against rejected.
- ✓ Larger β makes the loss more sensitive to the margin.
- ✗ A loss of zero means the model has become better overall.
  It means these pairs are separated; check held-out quality and drift from the reference.
:::

Before running the code below: with β = 0.2, how large must the margin be for the loss to fall below 0.01?

:::visual How the DPO loss saturates
```python run
import math
def dpo_loss(margin, beta=0.2):
    return -math.log(1 / (1 + math.exp(-beta * margin)))

for margin in (-5, 0, 4, 10, 23, 50, 98):
    print(f"margin {margin:4d}: loss {dpo_loss(margin):.5f}")
```
:::

:::read
At margin 0 the loss is ln 2 ≈ 0.69; it falls below 0.01 at a margin of about 23 and is essentially zero by 50. Pairs separated that far stop producing gradient. Keep that in mind when reading the lesson's run: its margin starts at +257, so the loss is already near zero before preference training begins.
:::

@@before Stretch goals
:::read
Look at the first lines: after a short warm-up on the *chosen* completions, the initial chosen-minus-rejected margin is already +257, because the warm-up itself taught the model the chosen answers. DPO's loss is 0.07 in the first epoch and 0.0000 from the second on, and the margin settles near +98 (it moves down from the warm-up value as the reference comparison kicks in). The mechanics work, but the experiment has almost nothing left for DPO to learn. Warming up on both answers, or on separate data, would make the preference step visible.
:::

:::broken
A team runs DPO with the reference model *updated* alongside the policy at every step (they share weights by accident). The margin never grows and the loss stays at ln 2. Why? (Solution B1.)
:::

:::recap What to keep from this lesson
- DPO turns preference pairs into one supervised loss.
- The margin compares policy against reference for chosen and rejected answers.
- β controls how sharply the margin matters and how far the model moves.
- Large margins saturate the loss; those pairs stop teaching.
- Check held-out behaviour, not only the training loss.
:::

@@end Stretch goals
## Solutions

??? sol | B1 · A moving reference
If the reference shares weights with the policy, the policy-over-reference ratios are always 1 (log difference 0) for every answer, so the margin is always 0 and the loss stays at ln 2 with no useful gradient. Make the reference a separate, frozen copy (or precompute its log-probabilities once) before training.
???
