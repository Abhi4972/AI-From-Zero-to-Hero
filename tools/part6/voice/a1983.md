@@top Problem
:::plain In plain words first
A **prompt-injection detector** is a function: given a prompt, it returns a **confidence** that the prompt is an attack and the most likely **category** from the taxonomy. What makes it honest is measurement. Run it over a labelled set of attack and benign prompts and count, per category, **true positives**, **false positives** and **false negatives**, which give **precision** (of what it flagged, how much was really an attack) and **recall** (of the attacks, how many it caught). A single regex such as "ignore previous instructions" has high precision and terrible recall: the next paraphrase walks past it. Rules are added and judged by how they move these numbers.
:::
@@

@@end Concept
:::worked Precision and recall for one category
Context smuggling: 8 labelled attacks. The detector flags 3 of them and no benign prompts as this category.

1. True positives 3, false negatives 5, false positives 0.
2. Precision 3 / 3 = 1.00: everything it flags is right.
3. Recall 3 / 8 = 0.38: it misses most of them.
4. F1 = 2 × 1.00 × 0.38 / 1.38 ≈ 0.55. High precision with low recall is the signature of narrow rules, and context smuggling (instructions hidden in pasted data) is especially varied, so it is where this detector needs work first.
:::

:::check
Which statements are right?

- ✓ Precision asks: of what was flagged, how much was an attack?
- ✗ A detector with precision 1.0 is complete.
  It can still miss most attacks; check recall.
- ✓ Every benign prompt passing through is part of the evaluation.
- ✗ Adding a rule can only improve the detector.
  It can add false positives; measure before and after.
:::

:::predict
Before running the code below: a rule catches all 6 role-play attacks but also flags 4 of 25 benign prompts. What are its precision, recall and F1?
:::

:::visual Measuring a rule
```python run
def prf(tp, fp, fn):
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    return p, r, (2 * p * r / (p + r) if p + r else 0.0)

for name, tp, fp, fn in (("narrow regex", 2, 0, 4), ("broad rule", 6, 4, 0), ("balanced rule", 5, 1, 1)):
    p, r, f = prf(tp, fp, fn)
    print(f"{name:13s} precision {p:.2f}  recall {r:.2f}  F1 {f:.2f}")
```
:::

:::read
The broad rule catches everything (recall 1.0) but a third of its flags are benign (precision 0.60), so F1 is 0.75; the narrow regex is never wrong but misses two thirds; the balanced rule scores best on F1 (0.83). Which to prefer depends on the cost of each error: blocking a legitimate user against letting an attack through, a product decision the numbers inform but do not make.
:::

@@before Ship it
:::read
Over 50 attack fixtures the detector gets 31 right (accuracy 0.62) and lets all 25 benign prompts through. Precision is high in every category (0.75 to 1.00), recall is the weak side: context smuggling 0.38, multi-turn ramp 0.57, role-play 0.60. A detector tuned to never bother legitimate users, and missing a third or more of attacks in several categories, which is why it is one layer of a gate and not the whole gate.
:::

:::broken
A team reports "our injection detector is 98% accurate" on a test set that is 95% benign prompts. What should they report instead? (Solution B1.)
:::

:::recap What to keep from this lesson
- A detector returns a confidence and a category.
- Evaluate per category: precision, recall, F1.
- Include benign prompts; count false positives.
- Narrow rules give high precision and low recall.
- Judge every new rule by how it moves the numbers.
:::
