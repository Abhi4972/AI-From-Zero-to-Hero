@@top The problem
:::plain In plain words first
A beginner reading a lesson hits a word like "latitude" and leaves the page to look it up. Hover cards keep them on the page: the term becomes a small button, and its definition opens right there.

Doing it well is fiddly. Terms must be unique so a phrase means one thing. Matching must find whole words, prefer the longest phrase ("map scale" over "map"), and never touch code or links. The definitions must work with a keyboard, not only a mouse. And the published page should ship with the exact glossary that produced it, plus a report of which terms actually appeared.
:::
@@

@@end Step 2 · Match phrases inside eligible text nodes
:::visual Longest match at each word boundary
```python run
import re
terms = {"map scale": "map-scale", "map": "map", "legend": "legend"}
text = "Read the map scale before the legend on the map."

def match(text, terms):
    out, i, low = [], 0, text.lower()
    phrases = sorted(terms, key=len, reverse=True)          # longest first
    while i < len(text):
        if i == 0 or not text[i - 1].isalnum():               # only at a word start
            hit = next((p for p in phrases if low.startswith(p, i)
                        and (i + len(p) == len(text) or not text[i + len(p)].isalnum())), None)
            if hit:
                out.append((terms[hit], i, i + len(hit), text[i:i + len(hit)])); i += len(hit); continue
        i += 1
    return out

for m in match(text, terms): print(m)
```
:::

:::read
At position 9 both "map" and "map scale" fit; trying longest first takes "map scale", and the match consumes those characters so "map" is not matched inside it. Later, the lone "map" before the full stop is matched on its own. Offsets are zero-based with an exclusive end, so `text[9:18]` is exactly "map scale". The real project adds what this sketch skips: case-insensitive Unicode word rules, and never matching inside links or code.
:::

@@end Step 3 · Render accessible definitions in context
:::check
Which statements are right?

- ✓ A native `<button>` gives keyboard focus and Enter/Space activation for free.
- ✗ A `title` attribute tooltip is accessible enough.
  It does not open from the keyboard on most browsers and screen readers handle it inconsistently.
- ✓ Terms inside `<code>` and `<a>` are skipped, so code samples and links are left unchanged.
- ✗ Two terms may share an alias if their definitions agree.
  Aliases must be unique, or a phrase could open two different definitions.
:::

:::recap What to keep from this project
- Validate the glossary first: ids, non-empty text, unique phrases across terms and aliases.
- Match whole words, case-insensitively, longest phrase first, without overlaps.
- Skip links and code; annotate only eligible text.
- Use native buttons so definitions work by keyboard.
- Ship the glossary and a coverage report with the page.

@@end Exercises

## Solutions

??? sol | 1. Review timestamps
Add an optional `reviewed` date to each term and carry it into `glossary.json` and the page's data. Matching reads only the term and its aliases, so it is unaffected; a test should prove the same matches before and after.
???

??? sol | 2. Locale-aware word boundaries
Use a segmenter for the lesson's language (for example `Intl.Segmenter` with word granularity) instead of the letter/number rule, and report every place where a match changed between the two rules, so an editor can check them.
???

??? sol | 3. A real HTML parser
Parse with a maintained parser into a tree, walk only text nodes whose ancestors are not `a`, `pre` or `code`, and serialize back. Keep the existing tests and add pages outside the old subset.
???

??? sol | 4. A queue for unused terms
List terms with coverage 0 in the report and on the page's admin view. Each one is a question for an editor: is the term missing from the lesson, or should it leave the glossary?
???

??? sol | B1 · A button inside a link
Nested interactive elements are invalid HTML: focus order and activation become unpredictable, and Enter may follow the link instead of opening the definition. The rule "skip text inside `a`, `pre` and `code`" prevents it.
???
