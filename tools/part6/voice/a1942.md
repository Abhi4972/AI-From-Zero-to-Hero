@@top The problem
:::plain In plain words first
Before training, the corpus must be **downloaded** and **deduplicated**, and both steps must survive interruptions at scale. Resuming a download uses HTTP **Range** requests: ask the server for the bytes from the last verified offset onward, and keep that offset on disk so it outlives the process. Deduplication must catch **near-duplicates** (the same article with a different footer), which exact hashes miss. **MinHash** gives each document a short signature whose components agree with another document's in proportion to how many word **shingles** they share (their **Jaccard similarity**); **LSH** groups signature parts into bands so that similar documents land in the same bucket without comparing every pair. A **manifest** records each shard's hash and counts, so training can check exactly what it is reading.
:::
@@

@@end Idea 4 · Shard manifest as a contract
:::math The LSH S-curve
With a signature of $k = b \times r$ MinHash values split into $b$ bands of $r$ rows, two documents with Jaccard similarity $s$ share at least one whole band with probability

$$P(s)=1-\left(1-s^{r}\right)^{b}$$

which rises steeply around the threshold $s^{*}\approx(1/b)^{1/r}$.
:::

:::worked Choosing bands for a 0.8 threshold
$k = 128$ hash values.

1. $b = 32$, $r = 4$: threshold $(1/32)^{1/4} ≈ 0.42$. Pairs that share only half their shingles already collide often: too loose for "same document, different footer".
2. $b = 16$, $r = 8$: threshold ≈ 0.71.
3. $b = 8$, $r = 16$: threshold ≈ 0.88.
4. For a target around 0.8, pick between the last two and verify every candidate pair with an exact Jaccard computation, which is cheap because LSH has already narrowed the pairs to a handful.
:::

layouts = [(32, 4), (16, 8), (8, 16)]

With 32 bands of 4, a pair that shares only half its shingles collides 87% of the time, so it would be treated as a duplicate candidate. With 8 bands of 16, the same pair almost never collides, while pairs at 0.95 still collide 99% of the time. The band layout is the dial that sets what "duplicate" means; the lesson's corrected text above gives settings for a 0.8 target.

## Solutions

??? sol | P1 · Shingle width
Narrow shingles (3 words) make unrelated documents look similar through common phrases; wide ones (9 words) make a single edited word change many shingles, so near-duplicates look less similar. Measure on known duplicate and non-duplicate pairs at widths 3, 5 and 9, and pick the width that best separates the two groups, typically around 5 for prose.
???

??? sol | B1 · Trusting the file size
A crash can leave the last bytes on disk partially written or corrupted, so the file size overstates what was verified. Persist the verified offset (and a hash of the bytes up to it) after each flushed, checked block; on resume, truncate the file to that offset and continue from there.
???
