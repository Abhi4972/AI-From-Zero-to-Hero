@@top The situation
:::plain In plain words first
A small cache pool, sized to share a GPU, could not hold the sessions that came back for more turns, so from turn 4 the cache kept evicting what it would need next (thrashing), and first tokens slowed to 716 ms. Under that heavy eviction a crash path appeared too. The case trains separating two stacked problems and fixing the capacity one first.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Thrashing happens when the working set is larger than the pool.
- ✗ Changing the eviction policy is the main fix.
  Growing the pool to 16,384 tokens fixed the hit rate even with the default policy.
- ✓ The crash was a second problem that heavy eviction exposed.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Size the pool to the returning working set.
- Watch the hit rate by turn.
- Separate stacked failures; fix capacity first.
- Reproduce a crash path after the capacity fix.
:::
@@
