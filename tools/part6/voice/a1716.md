@@top The problem
:::plain In plain words first
**Model routing** sends each request to the cheapest model that can answer it well. Most traffic is easy (rephrase this, what time is it in Paris) and a small model handles it at a few per cent of a frontier model's price; the rest needs the big model. There are three patterns. A **pre-route** classifier looks at the request and picks a model before calling anything. A **cascade** tries the cheap model first and **escalates** to the expensive one when the answer looks weak: low confidence, a refusal, hedging. An **ensemble** runs both and picks the better answer, used only for tests. The risk is quiet: as users change what they ask, a router tuned on last quarter's traffic starts sending hard questions to the small model, and quality drops without an error anywhere.
:::
@@

@@end Idea 6 · Numbers you should remember
:::math
**Blended cost of routing.** If a fraction $s$ of traffic goes to the cheap model at cost $c$ per request and the rest to the frontier model at cost $F$, and a cascade escalates a fraction $e$ of the cheap requests (paying for both calls),

$$\text{cost per request} = s\,c + s\,e\,F + (1 - s)\,F$$

Pre-routing has $e = 0$ but depends on the classifier; a cascade pays $c$ on every escalated request as well.
:::

:::worked Routing 70% of an $80,000-a-month bill
1. All on the frontier model: $80,000.
2. Pre-route 70% to a model costing 3% as much: 0.7 × 0.03 × 80,000 + 0.3 × 80,000 = $1,680 + $24,000 = $25,680, a 68% saving.
3. Cascade instead, with 15% of the cheap requests escalating: add 0.7 × 0.15 × 80,000 = $8,400, so about $34,080, a 57% saving with a better quality floor.
4. If drift pushes escalation to 40%, the cascade costs $24,000 + $1,680 + $22,400 = $48,080 and saves only 40%: a rising escalation rate is your drift alarm.
:::

:::check
Which statements are right?

- ✓ A cascade adds latency only on the requests it escalates.
- ✗ A router trained once keeps working.
  Task mix drifts; gate routes on online quality, escalation and refusal rates.
- ✓ Prompt length is a cheap routing signal: very long prompts often need the frontier model.
- ✗ Pre-routing always beats a cascade on quality.
  Pre-routing is only as good as its classifier; a cascade checks the actual answer.
:::

:::visual Classifier accuracy against quality
```python run
import random
random.seed(11)
EASY_SHARE, CHEAP, FRONTIER = 0.7, 0.03, 1.0
for acc in (0.95, 0.90, 0.85, 0.80, 0.75):
    cost = ok = 0
    for _ in range(20000):
        hard = random.random() > EASY_SHARE
        says_hard = hard if random.random() < acc else not hard
        cost += FRONTIER if says_hard else CHEAP
        ok += (not hard) or says_hard          # hard questions fail on the cheap model
    print(f"classifier accuracy {acc:.0%}: quality {ok / 20000:6.2%}  cost {cost / 20000:5.1%} of all-frontier")
```
:::

:::read
Each lost point of classifier accuracy costs about 0.3 points of quality (hard questions now sent cheap) and, oddly, raises cost too, because easy questions get misread as hard and sent to the frontier model. A pre-router needs a well-measured classifier; when you cannot get one, a cascade, which checks the real answer, is the safer default.
:::

:::recap What to keep from this lesson
- Route easy requests to cheap models; most traffic is easy.
- Signals: task class, prompt length, similarity to known-hard requests, first-pass confidence.
- Pre-route is fastest; a cascade checks the answer; ensembles are for tests.
- Watch escalation, refusals and per-route quality; drift is the main risk.
- Gateways (LiteLLM, Portkey) and RouteLLM implement routing.

## Solutions

??? sol | P1 · When a cascade beats pre-routing
In the visual above, pre-route quality falls from about 98.4% to 92.4% as classifier accuracy drops from 95% to 75%, while a cascade's quality depends on its confidence check rather than a classifier. In `code/main.py`, with its accurate classifier, pre-routing gives higher quality and the cascade lower cost; once the classifier drops below roughly 90% accuracy, the cascade's quality floor is the better trade.
???

??? sol | B1 · Escalation creeping up
The task mix drifted: users ask longer, harder questions than the data the router was tuned on, so the cheap model fails more often and the cascade pays for both calls. Fixes: re-label recent traffic and retrain the router or threshold; route by prompt length or a hard-query set directly to the frontier model; and alert when escalation passes about 30%.
