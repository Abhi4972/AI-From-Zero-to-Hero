@@top The problem
:::plain In plain words first
A diagram shows everything at once, which is exactly what makes it hard for a newcomer: where do you start, and what does each box mean? A presenter solves this by walking through it one box at a time. This project builds that walkthrough as data: a graph of the diagram's nodes and edges, each with an explanation, checked against the real SVG; a reading order computed from the graph, with branches and cycles kept visible rather than flattened into a list; an author's review of that order; and a navigable page with Previous and Next buttons.
:::
@@

@@end Step 2 · Compute branches, cycles and candidate reading order
:::visual A reading order that keeps the branch
```python run
nodes = ["collect", "check", "share", "clarify"]
edges = [("collect", "check"), ("check", "share"), ("check", "clarify")]
indeg = {n: 0 for n in nodes}
for a, b in edges: indeg[b] += 1
order, seen = [], set()
def visit(n):
    if n in seen: return
    seen.add(n); order.append(n)
    for a, b in edges:
        if a == n: visit(b)
for n in [n for n in nodes if indeg[n] == 0] + nodes: visit(n)    # roots first, then anything left
branches = {n: [b for a, b in edges if a == n] for n in nodes if sum(a == n for a, _ in edges) > 1}
print("order:", order); print("branches:", branches)
```
:::

:::read
Depth-first from the only root gives collect → check → share → clarify. A plain list would suggest "clarify" comes after "share"; the branch record says otherwise: `check` leads to *either* share or clarify. That is why the analysis returns branches and cycles alongside the order, and why the walkthrough shows them.
:::
@@

@@end Step 3 · Review explanations and reading order
:::check
Which statements are right?

- ✓ Every graph node must exist as an element in the SVG.
- ✗ A cycle can be removed by deleting one edge to get a clean order.
  The cycle is part of what the diagram says; it is reported, not erased.
- ✓ An author's review must list each node exactly once.
- ✗ Nodes nobody can reach from a root are errors to delete.
  They are listed as unreachable and still get a place in the order.
:::

@@end Exercises

## Solutions

??? sol | 1. An author-side validator
Check the SVG and the graph together before saving: list SVG elements with no node, nodes with no element, nodes missing a label or explanation, and edges whose ends do not exist. Show them highlighted on the diagram.
???

??? sol | 2. Breadth-first as an alternative
Compute a breadth-first order as a second candidate and show both. The author picks one in the review, which records the choice; neither is silently the default.
???

??? sol | 3. An explanation change record
Store each edit as `{node, old, new, author, time}` beside the review, so collaborators can see what changed and why, and roll back a single change.
???

??? sol | 4. Read-aloud descriptions
Give each node button an accessible name (label) and description (explanation), and use the browser's speech synthesis on demand. Screen-reader users already get the text from the accessibility tree.
???

??? sol | B1 · A renamed box
Step 1's check that every node id exists in the SVG. `check` no longer exists, so loading fails with the missing id instead of publishing a stale explanation.
???
