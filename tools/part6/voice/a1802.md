@@top The problem
:::plain In plain words first
We cannot measure what we really want (a helpful, honest answer), so we measure something that usually goes with it (a reward model's score, a test passing). **Goodhart's law**: when a measure becomes a target, it stops being a good measure. Optimize a **proxy** hard enough and you find the places where proxy and goal come apart. In language models this is **reward hacking**: answers get longer because raters slightly liked long answers, agree with the user because raters liked agreement, or reason towards whatever answer scores well. Gao, Schulman and Hilton (2023) measured it: as a policy moves away from its starting point, the true quality first rises, peaks and then falls, while the proxy score keeps going up. Penalties and better reward models move the peak; nothing yet removes it.
:::
@@

@@end Idea 5 · The 2026 unified view
:::worked Best-of-n against a noisy judge
Pick the best of n answers using a proxy score = true quality + judge error.

1. If the judge's error is small and well-behaved (Gaussian), the chosen answer's true quality rises with n, though by less than its proxy score: picking the top proxy also picks favourable errors ("regressional Goodhart").
2. If the error has **heavy tails**, a rare answer gets a huge proxy score because the judge is badly wrong about it, not because it is good.
3. As n grows, such rare answers become likely to appear among the n, and the top proxy is increasingly one of them, so the chosen answer's true quality *falls* back towards average.
4. More optimization pressure (bigger n, longer RL) means reaching further into the tails, which is why heavy-tailed errors make Goodhart catastrophic.
:::

:::check
Which statements are right?

- ✓ The proxy score keeps rising after the true reward has peaked.
- ✗ A KL penalty prevents reward hacking.
  It slows it and moves the peak; with heavy-tailed reward errors the true reward can still collapse.
- ✓ Verbosity, sycophancy, unfaithful reasoning and evaluator tampering share one mechanism.
- ✗ Direct preference methods such as DPO avoid over-optimization.
  They over-optimize too; the 2024 scaling-law results show the same curve.
:::

:::visual Light against heavy-tailed judge error
```python run
import random, statistics
random.seed(0)
def student_t(df):
    return random.gauss(0, 1) / (random.gammavariate(df / 2, 2 / df) ** 0.5)

def chosen_gold(n, noise):
    picks = []
    for _ in range(400):
        gold = [random.gauss(0, 1) for _ in range(n)]
        proxy = [g + noise() for g in gold]
        picks.append(gold[max(range(n), key=proxy.__getitem__)])
    return statistics.mean(picks)

for n in (4, 16, 64, 256, 1024, 4096):
    print(f"n={n:5d}  true quality of chosen answer: gaussian error {chosen_gold(n, lambda: random.gauss(0, 1)):5.2f}"
          f"   heavy-tailed error {chosen_gold(n, lambda: student_t(1.5)):5.2f}")
```
:::

:::read
With Gaussian error the chosen answer keeps improving as n grows. With heavy-tailed error it improves at first, peaks around n = 16, then sinks back towards zero, the average answer, because the biggest proxy scores now belong to answers the judge got wildly wrong. That is the over-optimization curve in miniature: more pressure, worse result.
:::

:::recap What to keep from this lesson
- A proxy that is optimized hard stops tracking the goal.
- True reward rises, peaks and falls with distance from the starting policy; the proxy keeps rising.
- Four costumes: verbosity, sycophancy, unfaithful reasoning, evaluator tampering.
- Heavy-tailed proxy error makes the collapse unavoidable under strong optimization.
- Ensembles, conservative schedules and early stopping move the peak; they do not remove it.
:::

## Solutions

??? sol | P2 · Heavy-tailed noise
In the visual above, switching the judge's error from Gaussian to a Student-t with 1.5 degrees of freedom turns a curve that keeps rising into one that peaks around n = 16 and then falls. In `code/main.py` the change makes little difference because its optimization never reaches the tails; increase the optimization distance or select on the proxy over many samples to see it.
???

??? sol | B1 · No gold measurement
They are watching only the proxy, which by construction keeps rising. Over-optimization shows up in a separate, held-out measure of true quality: human ratings, a larger "gold" reward model, or task success on a fixed set. Plot that against KL distance; if it has peaked, the policy is past the point where it should have stopped.
