@@top The problem
:::plain In plain words first
A pretrained language model ends in a **head** that predicts the next token. To turn it into a **classifier** (spam or not spam), keep the **body**, which already encodes useful structure, and swap the head for a small linear layer that outputs one score per class. The body produces one vector per token, so first **pool** them into one vector per message: take the last real token's vector, or the mean over real tokens (ignoring padding). Then choose how much to train. **Head-only** training freezes the body and learns just the new layer: tiny, fast, and hard to overfit. **Full fine-tuning** updates everything: more capacity, more risk with little data. This lesson builds both on the same small dataset (training here is seconds on a tiny model).
:::
@@

@@end Why the comparison matters
:::worked Counting what you train
Body width $D = 64$, two classes.

1. Head-only: a linear layer from 64 to 2 has $64 \times 2 + 2 = 130$ parameters. That is the entire trainable set.
2. Full fine-tuning: the same 130 plus every body parameter, about 118,000 in this lesson's model.
3. With 640 training messages, 130 parameters cannot memorize much; 118,000 can, so full fine-tuning needs a validation set and early stopping to be trusted.
4. If both reach the same test score, the head-only result is the more informative: it shows the body's features already separate the classes.
:::

:::check
Which statements are right?

- ✓ Head-only training freezes the body and trains only the new layer.
- ✗ Mean pooling should include padding positions to keep shapes simple.
  Padding vectors carry no content; mask them out of the mean.
- ✓ The new head outputs one logit per class.
- ✗ Full fine-tuning always beats head-only training.
  With little data it can overfit; it wins only when the body's features are not enough.
:::

:::predict
Before running the code below: a message has 3 real tokens and 2 padding positions. What is the difference between a mean over all 5 positions and a mean over the real tokens only?

:::visual Masked mean pooling
```python run
vectors = [[1.0, 2.0], [3.0, 0.0], [2.0, 4.0], [0.0, 0.0], [0.0, 0.0]]   # last two are padding
mask = [1, 1, 1, 0, 0]
naive = [sum(v[d] for v in vectors) / len(vectors) for d in range(2)]
masked = [sum(v[d] * m for v, m in zip(vectors, mask)) / sum(mask) for d in range(2)]
last_real = vectors[max(i for i, m in enumerate(mask) if m)]
print("mean over all positions :", naive)
print("mean over real tokens   :", masked)
print("last real token         :", last_real)
```
:::

:::read
Including padding shrinks the pooled vector toward zero (here by 40%), and by an amount that depends on how much padding each message has, so short and long messages land in different regions for no reason related to their content. The masked mean and the last-real-token vector both ignore padding; which works better is the "pooling question" the lesson leaves you to test.
:::

@@before Stretch goals
:::read
Both approaches reach a perfect score on the 160 test messages: precision, recall and F1 all 1.0, with no errors in either confusion matrix. Head-only training gets there with 130 trainable parameters, full fine-tuning with 118,402. When the cheapest method is already perfect, the test set is too easy to tell the methods apart; that is the useful conclusion here, and a reason to build harder test cases before choosing.
:::

:::broken
A team fine-tunes the full model on 800 messages for 50 epochs, reports 100% training accuracy and ships. In production, accuracy is 71%. What did their process leave out? (Solution B1.)
:::

:::recap What to keep from this lesson
- Keep the pretrained body; replace the head with a small class layer.
- Pool token vectors into one, masking padding.
- Head-only: few parameters, fast, little overfitting.
- Full fine-tuning: more capacity, more need for validation.
- If the cheap method is perfect, the test set is too easy.
:::

## Solutions

??? sol | B1 · Training accuracy is not evidence
They measured only on the data they trained on, so 100% says the model memorized 800 messages, not that it generalizes. Hold out a validation set from the start, stop training when validation performance stops improving, compare against the head-only baseline, and test on messages from a different time or source to catch drift.
