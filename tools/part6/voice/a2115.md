@@top The situation
:::plain In plain words first
A training job ran for two hours, completed zero steps and was killed at its time limit. The custom reward function could not be imported by the worker processes, the first rollout failed, and the run never exited. The case trains two habits: test an import in the exact environment that will use it, and treat a job that hangs after an error as a separate problem from the error itself.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Code importable on the host may be invisible to worker processes in a container.
- ✗ A job that reaches its time limit was just slow.
  Zero completed steps after two hours points to a failure the job never exited from.
- ✓ A one-line import test in the container would have shown the problem in seconds.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Test imports in the environment that will run them.
- Set the module path for workers explicitly.
- Score a few known answers before a long run.
- A hang after an error needs its own fix.
:::
@@
