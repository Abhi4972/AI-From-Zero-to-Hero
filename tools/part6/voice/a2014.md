@@top The problem
:::plain In plain words first
"Find me two hours for deep work today" sounds simple. The calendar has overlapping meetings, you want a buffer around each one, and some tasks matter more than others. A planner that quietly squeezes everything in, or drops a task without saying so, is worse than none.

This project reads calendar events from an `.ics` file, merges overlaps to find the real free gaps, places tasks by priority into the earliest gap that fits, and says plainly which tasks did not fit and why. The result is a proposal you import yourself, never an automatic change to your calendar.
:::
@@

@@end Step 2 · Merge overlaps before finding gaps
:::worked The sample day, with a 10-minute buffer
Work window 09:00–17:00 (UTC). Events: Team sync 09:30–10:15, Office hours 10:00–11:00, Workshop 13:00–14:30.

1. Add 10 minutes on each side: 09:20–10:25, 09:50–11:10, 12:50–14:40.
2. The first two overlap, so they merge into one busy block, 09:20–11:10. Adding their lengths separately would double-count 35 minutes.
3. Busy: 09:20–11:10 and 12:50–14:40. Free gaps: 09:00–09:20 (20 min), 11:10–12:50 (100 min), 14:40–17:00 (140 min).
:::

:::visual Placing tasks by priority
```python run
gaps = [[9*60, 9*60+20], [11*60+10, 12*60+50], [14*60+40, 17*60]]   # minutes since midnight
tasks = [("lesson", 75, 5), ("review", 45, 4), ("record", 90, 3), ("deep", 120, 2)]
hm = lambda m: f"{m // 60:02d}:{m % 60:02d}"
for name, mins, pri in sorted(tasks, key=lambda t: (-t[2], t[0])):
    gap = next((g for g in gaps if g[1] - g[0] >= mins), None)
    if gap is None:
        print(f"{name:7} {mins:3} min  -> does not fit (longest gap left: {max(g[1]-g[0] for g in gaps)} min)"); continue
    print(f"{name:7} {mins:3} min  -> {hm(gap[0])}-{hm(gap[0] + mins)}"); gap[0] += mins
```
:::

:::read
The 75-minute lesson takes the start of the 100-minute gap (11:10–12:25). The review and the recording fill the afternoon gap back to back (14:40–15:25, then 15:25–16:55). The 120-minute task has nowhere to go: the gaps left are 20, 25 and 5 minutes, and the planner says so instead of splitting it.
:::

@@end Step 3 · Schedule priorities without pretending everything fits
:::check
Which statements are right?

- ✓ Overlapping events must be merged before gaps are computed.
- ✗ If a task does not fit, splitting it across gaps is an acceptable default.
  Splitting changes what the task is; the planner reports it as unscheduled and lets you decide.
- ✓ Cancelled and transparent events do not block focus time.
- ✗ The export writes the focus blocks into your calendar.
  It writes an `.ics` proposal that you import by hand.
:::

:::recap What to keep from this project
- Parse calendar text strictly; drop cancelled and transparent events.
- Buffer, clip, sort and merge busy intervals; free time is the complement.
- Place by priority into the earliest gap that fits, with a stable tie rule.
- Report what did not fit, with the reason.
- Export proposals with stable ids; a person imports them.
:::

## Solutions

??? sol | 1. An all-day event
An all-day event covers the whole work window once clipped, so the merged busy interval is 09:00–17:00 and the complement is empty. Every task is reported as not fitting, which is correct: the day is taken.
???

??? sol | 2. When the 75-minute task stops fitting
The middle gap is 13:00 − 11:00 − 2 × buffer, that is 120 − 2b minutes; the afternoon gap is 150 − b (14:30 + b to 17:00). The lesson task goes into the earliest gap of at least 75 minutes. The middle gap is at least 75 while 120 − 2b ≥ 75, so up to b = 22 minutes; above that it moves to the afternoon, which still fits up to b = 75. Check it by running the planner with buffers of 22 and 23.
???

??? sol | 3. Shortest-task-first
Shortest-first fits more tasks into small gaps but can push the most important long task out of the day. Earliest-fit by priority protects important work and may leave small gaps unused. Show both plans on the same tasks and say which one the user is choosing.
???

??? sol | 4. An adapter for another planner
Write a function that reads the other planner's proposals and returns validated `Task` records (id, title, minutes, priority), rejecting anything malformed. The scheduler stays unchanged and deterministic; the adapter is the only place that knows the other format.
???

??? sol | B1 · Summed meeting time
It ignored the overlap (the sync and office hours share 15 minutes) and, above all, that free time comes in separate gaps. A total of free minutes says nothing about a contiguous block. Here the longest gap is 140 minutes, but the higher-priority review and recording take 135 minutes of it first, so no 120-minute block is left.
???
