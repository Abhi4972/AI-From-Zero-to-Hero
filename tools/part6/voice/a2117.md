@@top The situation
:::plain In plain words first
A supervisor retries `CancelTask` all night for two tasks that keep answering with an error. Its rule, "an error means try again", treats a permanent state as a temporary one: the tasks had already finished, and a finished task cannot be cancelled. The case trains reading what an error means before deciding to retry, and checking the task's state instead of repeating the call.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ Cancelling a task that already completed is an error that will never go away.
- ✗ Retrying until success is a safe default for remote calls.
  It is only safe for transient errors; permanent states need a different branch.
- ✓ Calling `GetTask` once after the error shows the terminal state that closes the entry.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Classify errors as transient or permanent before retrying.
- After a failed cancel, read the task's state.
- Terminal states close the bookkeeping.
- Bound every retry loop.
:::
@@
