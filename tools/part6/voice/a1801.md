@@top The problem
:::plain In plain words first
A pre-trained language model has learned to continue text, not to help. **InstructGPT** (OpenAI, 2022) set out the three-stage recipe that turned such models into assistants, and that most later alignment work starts from. **Stage 1, supervised fine-tuning (SFT):** train on examples of good answers written by people. **Stage 2, a reward model (RM):** show people two answers to the same prompt, record which they prefer, and train a model to predict that preference as a score. **Stage 3, reinforcement learning (PPO):** let the model generate, score it with the RM, and push it towards higher scores, with a **KL penalty** that keeps it close to the SFT model so it cannot drift into strange outputs that merely fool the RM. Every later lesson in this phase criticizes one part of this recipe.
:::
@@

@@end Idea 6 · Why this is the reference point for Phase 18
:::math
**What the KL penalty does.** For one prompt, the best policy under $J(\pi) = \mathbb{E}[r] - \beta\,\mathrm{KL}(\pi \,\|\, \pi_{\text{SFT}})$ has a closed form:

$$\pi^{*}(y) \propto \pi_{\text{SFT}}(y)\, \exp\!\big(r(y) / \beta\big)$$

Large $\beta$ keeps $\pi^{*}$ close to the SFT model; as $\beta \to 0$, all probability moves to whichever answer the reward model scores highest, including one it scores highly by mistake.
:::

:::worked Three answers, one reward bug
The SFT model gives answers A, B, C probabilities 0.18, 0.63, 0.19. The reward model scores them −0.15, +0.72, −0.57, but has a bug: it adds +1.0 to A (say, A is long-winded, and the RM likes length).

1. With the bug, scores are +0.85, +0.72, −0.57. A is now the "best" answer.
2. β = 1: weights 0.18·e^0.85 = 0.42, 0.63·e^0.72 = 1.29, 0.19·e^−0.57 = 0.11. Normalized: A 23%, B 71%, C 6%. B still dominates; the bug moved A up a little.
3. β = 0.1: weights 0.18·e^8.5 ≈ 885, 0.63·e^7.2 ≈ 845, tiny for C. A becomes the top answer at about 51%.
4. β → 0: A takes everything. The smaller the penalty, the more completely the policy exploits the RM's mistake.
:::

:::check
Which statements are right?

- ✓ The reward model is trained on comparisons, not on absolute scores.
- ✗ RLHF can teach a model facts its base model never learned.
  The capability floor comes from pre-training; RLHF changes behaviour, not knowledge.
- ✓ β is the most important RLHF hyperparameter.
- ✗ A 1.3B InstructGPT beating 175B GPT-3 means it is more capable.
  It is more aligned with what labellers want; capability and alignment are different axes.
:::

:::predict
Before running the code below: with the buggy reward, at roughly what β does the bugged answer A overtake the correct answer B?

:::visual The KL-regularized optimum as β shrinks
```python run
import math
sft = {"A": 0.18, "B": 0.63, "C": 0.19}
reward = {"A": -0.15 + 1.0, "B": 0.72, "C": -0.57}      # +1.0 on A is the reward-model bug

for beta in (2.0, 1.0, 0.5, 0.2, 0.1, 0.05):
    w = {y: p * math.exp(reward[y] / beta) for y, p in sft.items()}
    z = sum(w.values())
    pi = {y: v / z for y, v in w.items()}
    kl = sum(pi[y] * math.log(pi[y] / sft[y]) for y in sft)
    print(f"beta={beta:4.2f}  A {pi['A']:5.1%}  B {pi['B']:5.1%}  C {pi['C']:5.1%}   KL from SFT {kl:4.2f} nats")
```
:::

:::read
At β = 2 the policy stays near the SFT model; around β = 0.1 the bugged answer A overtakes B; by β = 0.05 it holds almost 80%, and the KL from the SFT model keeps growing. The penalty does not fix a bad reward model; it limits how far the policy can go to exploit it. Pick β too small and you are optimizing the RM's mistakes.
:::

:::recap What to keep from this lesson
- SFT teaches the format; the reward model learns preferences from comparisons; PPO optimizes against it.
- The KL penalty keeps the policy near the SFT model: $\pi^{*} \propto \pi_{\text{SFT}} \exp(r / \beta)$.
- Too small a β exploits reward-model mistakes; too large a β changes nothing.
- PPO-ptx mixes in pre-training data to pay back the alignment tax.
- Alignment and capability are separate axes.
:::

## Solutions

??? sol | P2 · A reward bug for B
A +0.5 bias on B, which is already the highest-scoring answer, only strengthens what the policy does anyway, so no β "prevents" it. Exploitation becomes visible when the bug lifts a *worse* answer above the best one, as in the visual above, where the bugged answer wins once β falls to about 0.1.
???

??? sol | P4 · Hidden production prompts
Labellers wrote their own prompts, and the 175B base model can be coaxed into good answers on carefully written prompts. Real users write terse, ambiguous, instruction-shaped requests, which a base model handles badly and an instruction-tuned one handles well, so the preference gap widens.
???

??? sol | B1 · β too small
With a tiny KL penalty the policy moved far from the SFT model, into outputs the reward model overrates: length and confident tone that the RM learned as weak signals of quality. The proxy kept rising while real quality fell: reward hacking. Raise β, stop training at the point where held-out human (or gold) scores peak, and add a length control.
???
