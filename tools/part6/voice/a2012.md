@@top The problem
:::plain In plain words first
Autocomplete is the oldest language model there is: count which words follow which, and suggest the most common next word. Before neural networks, this was how phones predicted text. This project builds one you can fully inspect: it counts single words and one- or two-word histories from a small corpus, suggests completions for what you are typing, and shows for each suggestion how often it was seen and in which source text.

It is a good bridge to the n-gram lessons: the same counting, turned into a writing tool.
:::
@@

@@end Step 2 · Rank prefix and next-word candidates
:::visual Longest history wins
```python run
import re
from collections import Counter
corpus = ["Garden club grows native flowers. Garden club shares native seeds. Native seeds welcome bees.",
          "Garden club shares native seeds. Garden club grows leafy herbs. Leafy herbs need shade.",
          "Garden club shares tools. Garden club shares seeds. Native flowers welcome bees."]
uni, bi, tri = Counter(), Counter(), Counter()
for text in corpus:
    for sent in re.split(r"[.!?]", text.lower()):
        w = re.findall(r"\w+", sent)
        uni.update(w); bi.update(zip(w, w[1:])); tri.update(zip(w, w[1:], w[2:]))

def suggest(prefix, history):
    out = []
    for word in sorted(u for u in uni if u.startswith(prefix)):
        if len(history) >= 2 and tri[(*history[-2:], word)]: out.append((2, tri[(*history[-2:], word)], word))
        elif history and bi[(history[-1], word)]: out.append((1, bi[(history[-1], word)], word))
        else: out.append((0, uni[word], word))
    return sorted(out, key=lambda t: (-t[0], -t[1], t[2]))

print(suggest("sh", ["garden", "club"]))
```
:::

:::read
"shares" follows "garden club" four times in the corpus, so it is ranked on its two-word history (order 2, count 4). "shade" never follows "garden club" or "club", so it falls back to its plain word count (order 0, count 1). The order comes first in the sort, so a word seen after this exact history always beats a word that is merely common.
:::

@@end Step 3 · Accept suggestions in a writing pad
:::check
Which statements are right?

- ✓ Histories never cross a sentence boundary.
- ✗ After "Garden club sh", the history is `["club", "sh"]`.
  "sh" is the unfinished word, used as the prefix; the history is the completed words before it.
- ✓ Each suggestion lists the source texts it was learned from.
- ✗ Smoothing would make the raw counts unnecessary.
  Smoothing adjusts scores; the raw counts stay as evidence.
:::

`vocabulary: 14` distinct words. The history is `garden, club` and the prefix is `sh`. "shares" scores 2000004: order 2 (seen after the two-word history) is weighted far above any count, plus its count of 4, from the spring, summer and autumn texts. :::recap What to keep from this project
- Count words and one- and two-word histories inside sentences only.
- Rank by the longest history seen, then by count, then alphabetically.
- Keep sources with every count so suggestions explain themselves.
- Validate an imported model before using it.

@@end Exercises

## Solutions

??? sol | 1. Paragraph provenance
Store `(source id, paragraph index)` instead of just the source id in each count's source list, and update the import validation to accept the new shape with a schema version bump.
???

??? sol | 2. Smoothing without losing evidence
Compute a smoothed score (for example back-off weights or add-k) only for ranking, and keep the raw order and count in each suggestion. A reader can then see when smoothing promoted a word that was never seen in this context.
???

??? sol | 3. Editing at the caret
Take the text before the caret instead of the whole text, find the unfinished word and history there, and insert the accepted word at the caret, replacing only the prefix.
???

??? sol | 4. An editor plugin
Wrap `suggest` and `acceptSuggestion` behind the editor's completion interface, load the exported model once, and show the evidence (count and sources) in the completion detail.
???

??? sol | B1 · Pairs across texts
Tokenize each text and each sentence separately, and build histories inside a sentence only. Pairs that span a boundary are artifacts of concatenation, not language.
???
