@@top The situation
:::plain In plain words first
An overnight analysis wrapper restarted its engine eleven times, paying for a fresh import each time, and every retry failed the same way. Neither failure was the engine's fault: one was a tool provider that cannot run on that host, the other a wrong argument. The case trains classifying a failure before reacting, and using the category and retry hints the tool already returns.
:::
@@

@@before Walkthrough
:::check
Which statements are right?

- ✓ A failure caused by the input repeats no matter how often the engine restarts.
- ✗ Restarting the engine is a safe universal recovery.
  It cost an import each time and could not fix either cause.
- ✓ A wrong argument becomes retryable once the argument is changed.
:::
@@

@@end The lesson to carry
:::recap What to keep from this case
- Classify failures: engine, input or environment.
- Read the error's category and retry hint.
- Restart only for engine faults.
- Keep sessions alive when the engine is healthy.
:::
@@
