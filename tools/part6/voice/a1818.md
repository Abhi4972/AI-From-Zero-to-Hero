A safety case is a written argument that a deployment is acceptably safe under worst-case assumptions. The standard structure targets three pillars:

- **Monitoring.** Can we detect bad behaviour if it occurs?
- **Illegibility.** Does the model lack the ability to execute a coherent plan to cause harm?
- **Incapability.** Does the model lack the capability to cause the harm in question?

Different safety cases target different pillars. For an ASL-3 CBRN case, incapability (via unlearning) is the primary target. For deceptive alignment, monitoring and illegibility are targets. For cyber uplift, all three are relevant.
===
A safety case is a structured written argument, backed by evidence, that a specific deployment is acceptably safe. Clymer et al. (2024) group the arguments it can rest on into kinds, in rough order of how much they depend on trusting the model:

- **Inability.** The model cannot do the harmful thing at all, shown by capability evaluations (and, for CBRN, possibly unlearning).
- **Control.** The model might try, but the deployment would catch or block it (Lesson 10): monitoring, restricted permissions, audits.
- **Trustworthiness.** The model can and is not stopped, but would not try, shown by alignment evidence such as interpretability. This is the hardest to establish today (Lessons 7–9).

Real safety cases combine them. A CBRN case for today's models leans on inability plus deployment safeguards; a case about deceptive alignment cannot rest on behaviour tests alone and usually falls back on control.

@@top The problem
:::plain In plain words first
A **frontier safety framework** is a lab's own written rulebook for when a model has become dangerous enough to need stronger safeguards. Each one defines **capability thresholds** (for example, "could meaningfully help someone make a biological weapon"), the **evaluations** run to check whether a model has crossed one, and the **safeguards** required once it has, from tighter security around the model's weights to classifiers that block certain requests. Anthropic calls its version the Responsible Scaling Policy (with AI Safety Levels, ASLs), OpenAI the Preparedness Framework, and Google DeepMind the Frontier Safety Framework (with Critical Capability Levels, CCLs). They are voluntary and keep changing; this lesson compares their structure and the hardest question they share: what a lab should do if competitors move ahead without the same safeguards.
:::

@@end Idea 7 · Where this fits in Phase 18
:::worked Why frameworks evaluate before the threshold
A lab evaluates its models each time effective training compute grows 4×. Capability on a dangerous-skill evaluation rises by about 8 points per 4× step.

1. The threshold of concern is 70 points. The last evaluated model scored 64.
2. The next model, one 4× step later, will score about 72: past the threshold before anyone tested it.
3. So frameworks set an earlier **warning level** (a buffer). With a warning level at 60, the 64-point model already triggers preparation of the stronger safeguards before the next step.
4. The buffer must be at least one step's worth of capability growth (here 8 points), plus measurement error. Too small a buffer and thresholds are crossed between evaluations.
:::

Before running the code below: capability grows by 8 points per evaluation step, with measurement noise of about 3 points. If the warning level sits 4 points below the threshold, how often does a model cross the threshold without any warning first?

:::visual How big a buffer is enough
```python run
import random
random.seed(2)
def missed(buffer, step=8.0, noise=3.0, threshold=70.0, trials=20000):
    misses = 0
    for _ in range(trials):
        cap = random.uniform(threshold - 3 * step, threshold - step)
        while True:
            measured = cap + random.gauss(0, noise)
            if measured >= threshold - buffer:          # warning fired at this evaluation
                break
            cap += step
            if cap >= threshold:                        # the next model is past the threshold, untested
                misses += 1; break
    return misses / trials

for buffer in (0, 4, 8, 12):
    print(f"warning level {buffer:2d} points below threshold: crossed without warning {missed(buffer):6.1%}")
```
:::

:::read
With no buffer, most models (85%) cross the threshold between evaluations. A 4-point buffer still lets about half through, because it is smaller than one step of growth. At 8 points, one full step, misses fall to about one in seven, and a 12-point buffer that also covers measurement noise makes them rare (about 1%). The principle carries over to the real frameworks: warning levels and evaluation frequency have to be set together with the pace of capability growth.
:::
