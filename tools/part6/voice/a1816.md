@@top The problem
:::plain In plain words first
Knowing the attacks (Lessons 12–15) is not enough; a team needs tools that test a deployment again and again as models and prompts change. Three open tools cover different jobs. **Llama Guard** (Meta) is a *classifier*: a small model that reads a prompt or a response and says which hazard category, if any, it falls in, so it can sit in front of and behind the main model. **Garak** (NVIDIA) is a *scanner*: it fires thousands of known attack probes at a model and reports which ones got through, which makes it good for regression testing. **PyRIT** (Microsoft) is a *campaign orchestrator*: it runs deep multi-turn attacks, transforming a seed prompt step by step, to find failures a single probe would miss. None of them proves safety; together they make testing routine and repeatable.
:::

@@end Idea 6 · Where this fits in Phase 18
:::worked Choosing a classifier threshold
A deployment handles 1,000,000 requests a day, of which about 0.1% (1,000) are harmful. A classifier at threshold 0.5 catches 95% of harmful requests and flags 2% of benign ones.

1. Harmful caught: 0.95 × 1,000 = 950; missed: 50.
2. Benign flagged: 0.02 × 999,000 ≈ 19,980.
3. Of everything flagged (about 20,930), only 950, under 5%, is actually harmful. Users see about 20,000 wrong refusals a day.
4. Raising the threshold to cut benign flags to 0.2% (about 2,000) might drop recall to 85% (150 missed). Which is better depends on the harm of a miss against the cost of a wrong refusal, which is a decision for the deployment, not the classifier.
:::

:::visual Precision at a low base rate
```python run
def flags(n, base, recall, fpr):
    harmful = n * base; benign = n - harmful
    tp, fp = recall * harmful, fpr * benign
    return tp, fp, tp / (tp + fp)

N = 1_000_000
for base in (0.001, 0.01, 0.1):
    for recall, fpr in ((0.95, 0.02), (0.85, 0.002)):
        tp, fp, precision = flags(N, base, recall, fpr)
        print(f"harmful {base:5.1%}  recall {recall:.0%}  benign flagged {fpr:4.1%}  ->  flags {tp + fp:9,.0f}  of which harmful {precision:5.1%}")
```
:::

:::read
At a 0.1% base rate, the sensitive setting flags about 21,000 requests a day and fewer than 5% of them are harmful; the stricter setting flags far fewer, about a third of them harmful, at the price of missing more. As harmful traffic becomes more common, precision rises sharply for the same classifier. That is why the same tool needs a different threshold per deployment, set from that deployment's own traffic.
:::
